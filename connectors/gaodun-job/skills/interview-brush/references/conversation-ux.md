# 会话展示规范

## 总原则

- 每轮可见回复都按本规范组织；业务状态、计数和幂等语义仍以 session-protocol.md 为准。
- 每轮只通过宿主 Ask 展示当前真实可执行的 2～5 个操作。
- 开场渐进披露一级项目，不完整罗列岗位、题型和考核维度；不得把逐题动态返回的考核维度包装成固定数量或固定能力矩阵。
- 每条普通回复最多使用 2～3 种固定图标；题干用引用块；操作区置于末尾。
- 正文只承载题目、提示和状态说明；快捷操作必须调用宿主 Ask，禁止用反引号、Markdown 或纯文本模拟按钮。
- Ask 调用后立即结束当前轮，等待用户点击或输入；不得预设用户已选择默认项，也不得在同一轮继续提交、抽题或生成报告。
- 每个状态都先发送一条用户可见的普通回复，普通回复成功展示后，再发起 Ask。通常由普通回复承载业务正文。题目态中，正文区完整题目卡是主展示；Ask 内重复题干只能作为可见性兜底，不能替代正文区题目卡。整个作答期间当前题目必须持续可见，宿主的 Ask 编辑态若会遮挡或替换上一条普通回复，须在 Ask 内保留当前题干。
- 项目、行业、岗位和题型名称只来自 data、胶囊配置或当题响应，不编造选项。
- 产品入口仅支持公务员、事业单位、银行；原始字典中即使存在其他项目，也不得将其展示或解析为当前产品支持入口。

## 状态操作矩阵

| 状态 | 主引导 | 可用操作 |
|---|---|---|
| 目标未知 | 选择方向或请求推荐 | 一级项目、`帮我推荐` |
| 目标已定且尚未出题 | 确认模式并开始 | `开始练习`、`模拟面试`、`更换方向` |
| 题目已展示且草稿为空 | 输入并提交完整回答 | 不发起 Ask；操作以正文“温馨提示”纯文本列出：`💡 提示`、`⏭ 跳过此题`、`🎯 更换方向`、`⏹ 结束面试` |
| 已有回答草稿 | 输入补充内容或提交草稿 | `✅ 提交回答`、`💡 获取提示` |
| 已请求提示 | 输入并提交完整回答 | `⏭ 跳过此题`、`⏹ 结束面试` |
| 练习单题报告完成 | 选择后续动作 | `下一题`、`重答`、`更换方向`、`结束面试` |
| 模拟单题报告完成 | 自动推进下一题或整场总结 | 不要求额外操作 |
| 模拟达到计划题数 | 生成整场总结 | 不要求额外操作 |
| 整场总结完成 | 选择下一轮 | `🔁 再练一组`、`🎯 更换方向`、`⏹ 结束练习` |

草稿为空时不得展示 `提交回答`。模拟提交或跳过后的自动推进不是需要用户点击的操作。

## Ask 交互契约

本规范描述交互目的和状态语义，不绑定宿主的固定控件名称、输入框名称或未确认存在的参数。由宿主选择其支持的呈现方式，并根据当前状态解释返回内容。

Ask 是普通回复之后的操作面板。必须先把当前状态需要用户理解的内容作为普通回复真正发送出去，不能只在调用 Ask 前生成一段未展示的草稿。题目态必须先观察到正文题目卡已经展示；未观察到正文题目卡已经展示，不得发起 Ask。若 Ask 不遮挡普通回复，其 `question/prompt` 只写简短操作引导；若打开答案编辑区会遮挡或替换题目卡，则在 Ask 的标题、说明或编辑区上方重复当前题干，再给出简短操作引导。Ask 内重复题干只能作为可见性兜底，不能替代正文区题目卡；无需重复目标方向、考察重点等完整题目卡，也不得只显示作答提示或空白输入框。

题目态和提示态应在同一个 Ask 交互区域收集答案，并同时提供辅助操作；草稿态在该区域收集补充内容并提供提交操作。作答入口只用于打开或聚焦答案编辑区，不得把入口文案作为会话消息提交，也不得因点击入口就关闭 Ask；只有用户编辑并确认提交的文本才是答案。宿主若能直接呈现编辑区，可以省略作答入口。进入编辑态后，当前题干仍须与输入区同时可见。

只要宿主具备 Ask 能力，所有操作均通过 Ask 可点击。必须先查找并调用宿主 Ask 工具；宿主工具调用明确返回不可用后，才允许退化成自然语言指令。不得仅因工具未立即出现在列表中、一次搜索未命中或不确定工具名称就声称“当前环境无可点击交互”，也不得自行降级。

## 状态展示循环

- **开场态**：先显示欢迎语、支持范围、默认项或模式说明；没有题目。随后 Ask 展示方向、开始或更换方向等操作。
- **新题态**：抽题成功后，把完整题目卡作为独立的会话正文消息发送，题号、题型、目标方向、考察重点和题干展示完整后，在题目卡末尾以“温馨提示”纯文本列出可选操作（提示、跳过、换方向、结束），然后结束本轮，等待用户在会话中直接输入回答。**此状态不发起 Ask**：不弹操作窗、不开放可点击按钮，让用户专心作答；可选操作只作为文字提示存在。
- **草稿态**：收到首次回答后，只显示“回答已记录”和补充/提交说明；草稿态不重复题目。随后 Ask 允许直接自由输入补充，并提供提交回答、获取提示操作。
- **提示态**：先显示针对当前题目的提示正文，不重复完整题目；随后 Ask 允许直接自由输入回答，并提供跳过、结束操作。
- **报告态**：先显示单题报告或整场总结；练习模式随后 Ask 提供下一题、重答、换方向或结束等当前有效操作；模拟模式报告后自动推进，不发起 Ask。
- **空态与失败**：先显示失败原因或空态说明；随后 Ask 提供重试、放宽条件、换方向或结束等当前有效操作，不用纯文本模拟按钮。
- 提交或跳过需要推进时，先完成状态转换和抽题；下一题抽取成功后按新题态处理，即先显示新题目，再发起 Ask。不得在新题出现前先展示“输入回答”“跳过此题”等作答操作。
- `结束面试` / `结束练习` 始终作为 Ask 可点击操作；点击后直接结束，先为已作答但缺报告的题补跑单题报告，再按已固化的单题评价生成总结，不额外二次确认。结束操作按 session-protocol.md 幂等执行，重复事件不得重复补跑、总结或计数。

| 内部操作语义 | 展示文案 | Ask 行为 |
|---|---|---|
| `submit_answer` | 提交回答 | 提交当前草稿 |
| `get_hint` | 获取提示 | 保留草稿并生成提示 |
| `skip_question` | 跳过此题 | 执行当前模式的跳过语义 |
| `next_question` | 下一题 | 按当前状态推进 |
| `retry_answer` | 重答 | 回到当题作答 |
| `change_target` | 更换方向 | 进入目标选择 |
| `end_interview` | 结束面试 | 结束并总结 |

题目展示态与提示态中，用户编辑并确认提交的文本作为首次作答；草稿态中，该文本作为补充内容。不要假定宿主会返回稳定操作 ID：有明确操作标识时使用标识，否则结合当前状态和唯一的操作文案解释结果。任何仅用于展开、聚焦编辑区的入口都不是答案。

## 开场

### 目标未知

```markdown
### 👋 欢迎进行面试练习

支持方向：
**公务员 · 事业单位 · 银行**

还可以按 **细分方向、岗位、题型和年份** 精准选题。条件说得越具体，题目越贴近你的目标；暂时没有明确目标，也可以直接开始。

练习方式：

- **单题练习**：答完一题立即获得点评，适合专项提升。
- **模拟面试**：连续完成多道题，结束后查看整场总结。

每道题都会标明考察重点，并根据你的回答给出针对性反馈和改进建议。

你可以直接告诉我目标，例如：

> 模拟一场公务员面试
> 练习银行客户经理岗位
> 练习 2024 年公务员面试题

请选择一个方向，或让我帮你推荐。
```

正文后发起 Ask：`公务员`、`事业单位`、`银行`、`帮我推荐`。

选题条件不等于考核维度：对外将 `industryId` 统一表述为“细分方向”，进入具体项目后可按语境称为考试类型、地区或银行类型；`projectId`、`industryId`、`jobId`、`questionTag`、`batchYear` 可用于理解用户的精准选题目标，`excludeQuestionIds` 不作为用户能力介绍。开场只概述可筛选条件，不完整列出选项。

开场只说明有考察重点和针对性反馈，不展示固定数量的能力维度，不列维度名称或解释。考核维度仅在抽到题目后按当题真实响应展示。

### 目标已知

不重复介绍全部项目，只确认用户已经给出的目标、模式和计划题数，然后直接抽题。

### 仅指定“模拟面试”

不得直接抽题。先展示三个支持项目，明确默认公务员和 3 题，提供“开始答题”与“更换方向”；用户确认开始后才运行抽题脚本抽取第 1 题。

```markdown
已进入 **模拟面试**，共 3 题。

支持方向：
**公务员 · 事业单位 · 银行**

你尚未指定目标，本场暂按 **公务员** 方向出题。

```

正文后发起 Ask：`开始答题`、`🎯 更换方向`。

胶囊入口已经携带入口话术、目标和模式时，不重复开场或追问。

## 题目卡

题目卡依次展示题号、题型、目标方向、考察重点和题干：

```markdown
### 第 1 题 · 人际关系题

**目标方向**
公务员 · 国考 · 金管局

**考察重点**
人际交往意识与技巧

> 在工作中，如果你的想法和领导的意见不一致，你会怎么办？

请像正式面试一样直接作答。暂时没有思路，可以获取提示。

---
💡 温馨提示：直接回复即可作答；也可以回复「提示」「跳过此题」「更换方向」或「结束面试」。
```

把上面的完整题目卡（含末尾温馨提示）作为独立的会话正文消息发送后，本轮直接结束，等待用户自由输入。**不发起 Ask**：答题时不弹操作窗，可选操作只以温馨提示纯文本呈现，让用户专心作答。温馨提示只列操作名，不用反引号或 Markdown 模拟按钮。

题型或目标层级为空时省略空层级，不显示 `null`；维度为空时使用“综合素质”。不得用示例值覆盖当题真实数据。

## 回答草稿

首次实质回答后只确认记录，不自动提交，每题只追问一次：

```markdown
### ✅ 回答已记录

你可以继续补充，也可以提交当前回答。

```

正文后发起 Ask：交互目的是收集用户编辑并提交的补充内容，同时提供 `submit_answer`、`get_hint`。由宿主选择其支持的输入呈现方式；打开或聚焦编辑区的入口不能作为补充内容提交。

用户继续补充时合并内容，不重复展示同一次提交确认。

## 作答提示

```markdown
### 💡 作答提示

可以从以下角度思考：

1. 明确题目需要回应的核心问题。
2. 说明判断问题时要考虑的关键因素。
3. 给出与目标岗位相符的具体行动。

> 提示只帮助你搭建思路，请结合自己的理解作答。

```

正文后发起 Ask：交互目的是收集用户编辑并提交的回答，同时提供 `⏭ 跳过此题`、`⏹ 结束面试`。若宿主呈现“开始作答”入口，它只能打开或聚焦当前 Ask 内的编辑区，不能直接向会话提交该文案。

具体框架必须针对当题生成；这里只规定样式和下一步指引，不是固定答案。

## 提交与自动推进

模拟模式提交后，先输出当题完整单题报告（与练习一致，按 report-prompts.md），报告展示后给简短过渡并自动推进：

```markdown
### ✅ 第 1 题已完成

正在准备第 2 题……
```

过渡后立即按 session-protocol.md 抽题。最后一题完成后改为：

```markdown
### ✅ 本场题目已完成

3 道题已全部完成，正在整理本场表现总结……
```

随后直接生成整场总结。

## 跳过、换题和换方向

- 模拟跳过：回复“已将本题记为跳过，我们继续下一题。”，不展示范例并自动推进。
- 练习跳过：询问“想先看作答框架，还是直接进入下一题？”，展示 `查看框架` 与 `下一题`。
- 主动换题：确认当前题不计作已回答，再抽取新题。
- 更换方向默认回复“已记录新的练习方向，将从下一题开始生效。当前题目保持不变。”
- 用户明确要求立即更换时，先说明当前题不计入记录，再按新方向抽题。

## 总结收尾

整场总结的内容仍按 report-prompts.md 生成，末尾发起 Ask：`🔁 再练一组`、`🎯 更换方向`、`⏹ 结束练习`。

answeredCount=0 时不显示能力优劣结论，只给统计、无法评价说明和下一轮建议。

## 空态与失败

- 接口失败：说明可回复 `重试`，明确本场进度未丢失；如有 requestId，置于正文末尾。
- NO_QUESTION 放宽后仍为空：展示 `放宽题型`、`更换方向`、`结束练习`。
- EXHAUSTED：展示 `更换题型`、`调整岗位`、`重新开始`；未经同意不得重置排除集。

## 固定图标语义

- `💡`：提示
- `✅`：记录或提交
- `⏭`：跳过或推进
- `🎯`：目标方向
- `📋`：总结
- `⏹`：结束

同一操作在各状态使用同一名称。普通对话不使用大表格向用户展示，不为装饰而增加图标。
