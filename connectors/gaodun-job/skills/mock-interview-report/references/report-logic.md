# 报告生成与查询逻辑

本文件定义 skill 生成报告时必须严格遵守的行为契约：问答拼接格式、两类评估的参数与输出格式、每题分数/维度分/总分计算公式、排序规则，以及 skill 内的简化假设。所有格式与计算规则均与线上面试评估实现保持一致，不得自行发明。

## 一、单题处理流程

对每道已作答题目，依次做两件事（互相独立，一个失败不影响另一个）：

### 1. 拼接问答文本

按以下固定格式拼接，作为两次评估的 content（user message）：

```
问题:{题干}
回答:{用户回答}
```

若存在追问（probeQuestion 非空），追加：

```
追问:{追问问题}
回答:{追问回答}
```

（本 skill 抽题配置 isProbe=false，不模拟追问。）

### 2. 面试建议（type=「面试建议」）

参数（JSON）：

| 参数 | 拼接格式（代码来源） |
|---|---|
| target_job | 岗位名称（jobId 对应岗位；用户指定岗位名） |
| evaluation | 维度简介列表：`1.维度名:维度简介 2.维度名:维度简介 `（编号+`.`+维度名+`:`+简介，以空格分隔） |
| student_resume | 用户简历内容；未提供则为空 |
| question_refer | 参考回答逐条拼为 `参考范例1：xxx\n参考范例2：xxx\n`（末尾带换行） |
| structure | 题签回答结构规则（仅公考 2167 变体使用）；mock 置空 |
| skills / goals / rules | 全局技能配置，2169/2177 变体使用，内容见 `references/prompt-skill-map.md` |

prompt 变体按项目选择（见 `prompt-coaching-advice.md`）：100520929->2167，1000648/100534841->2169，100535479->2177；未指定项目默认 2169。

**输出契约**：

1. 输出 JSON（中文 key，亦可映射英文 key），prompt 实际输出中文 key：

```json
{"你的回答优点在于": "...", "不足之处及改进建议": "...", "作答范例": "..."}
```

（英文 key `answerStrengths`/`improvementSuggestion`/`answerByReference` 亦可映射。）

2. JSON 解析失败时按 `#` 切分为三段。skill 中 fallback：要求模型改按 `回答优点#改进建议#参考作答` 单行输出后按 `#` 切分。
3. 特殊文案：输出含「上下文超长」或「抱歉，你的回答与本题无关」时，三段均为该文案。
4. **展示前缀**（固定追加）：
   - answerStrengths -> `你的回答优点在于：`
   - improvementSuggestion -> `不足之处及改进建议：`
   - answerByReference -> `作答范例：`

### 3. 单题评分（type=「单题评分」）

参数（JSON）：

| 参数 | 拼接格式（代码来源） |
|---|---|
| target_job | 岗位名称 |
| assessment_latitude | 评分标准列表：`1.维度名(满分分)规则要求min-max分...`（编号+`.`+维度名+`(20分)`+各规则区间，无分隔符）；mock 无维度库时用 `1.维度名(20分)` |

prompt 变体按项目选择（见 `prompt-single-evaluation.md`）：100520929->893（GK 分支，变量为 `evaluation`=题签维度评分标准），1000648/100534841->585，100535479->1874；未指定项目默认 585。

**输出契约（注意：不是 `#` 切分）**：

每个考核维度输出一段，段与段之间用**空行**（`\n\n`）分隔，每段固定三行：

```
1、维度名：
分数：16分
建议：评语内容

2、逻辑思维：
分数：12分
建议：评语内容
```

解析规则（skill 解析模型输出时必须复刻）：

1. 先判特殊文案：含「你的回答与本题无关」-> 单条记录（维度名/建议为固定抱歉文案，分数 0）；含「上下文超长」-> 全字段为「上下文超长」，分数 0。
2. 按 `\n\n` 分段；仅处理**首字符为数字**的段；每段至少 3 行。
3. 第 1 行（titleLine）：维度名 = `[、.]` 之后到第一个 `：` 之间（trim）。
4. 第 2 行（scoreLine）：分数 = 第一个 `：` 之后到最后一个 `分` 之间（无「分」则取到行尾，trim）。
5. 第 3 行（suggestionLine）：建议 = 第一个 `：` 之后（trim）。
6. 分数转数字失败记 0。

**维度满分 20 分**（线上报告计算按 20 分制换算，见下）。

### 4. 本题分数

每题分数按维度加权换算为百分制：

```
本题分数 = Σ各维度 floor(维度分 / 20 × 权重)
```

- 权重等权分配：`floor(100 / 维度数)`，最后一个维度 = `100 - 其余之和`（保证合计恰为 100）。
- 每个维度**先单独 floor 再求和**。
- 未作答/跑题的题：各维度 0 分，本题 0 分。

## 二、报告聚合

### 1. 维度平均分与维度评价

- 跨题按维度合并：同维度多题分数取平均，保留 2 位小数、HALF_UP。
- 维度评价：各题该维度评语按 `第{中文数字}题：{评语}` 逐行拼接（行间 `\n`；题号为作答题序，一~十中文数字）。

### 2. 维度换算分与权重

- 参与聚合的维度 = 抽到题目的考核维度集合。
- 维度平均分先**截断取整**再换算：

```
维度换算分(百分制) = floor(维度平均分取整 / 20 × 归一化权重)
```

- 权重归一化：各 appraiseRate 按比例缩放为合计 100，逐项 floor，最后一项 = `100 - 其余之和`。无权重配置时等权分配（同上）。
- 报告展示的 dimensionScore 即该换算分；originScore/originTotalScore 对应换算前的平均分/满分（mock 中满分取 20）。

### 3. 总分

```
总分 = Σ权重列表内各维度换算分（未参与权重计算的维度不计入）
```

- 结果超过 100 按 100 封顶。
- 注意：总分是求和而非再平均--权重已在维度换算时归一化为合计 100。

### 4. 总评

- 公考（projectId=100520929）用 prompt 2147（见 `prompt-overall-evaluation.md`），其他项目按同一输入/输出契约直接生成。输入为**全部题目的问答内容**：每题 {题干, 回答, 考核维度名列表（维度名以中文逗号分隔）, 追问题干, 追问回答} + 岗位名。
- 输出 JSON `{"面试表现总评":"..."}`，取该文字作为总评（resp.getScore() 返回的是文字，不是分数）。skill 中基于全部问答生成，须引用具体题目表现，不得只复述分数。

### 5. 报告字段（HTML 报告需覆盖）

| 字段 | 说明 |
|---|---|
| interviewScore | 面试总分（上文计算，百分制，封顶 100） |
| interviewEvaluation | 面试总评（文字） |
| dimensionReports | 维度报告列表（见下），按得分比例**升序** |
| answerRecords | 回答记录列表（见下） |
| interviewType | 面试类型（REAL_QUESTION 等） |
| interviewForm | 面试形式（structure / semiStructure） |
| projectName / projectId | 项目信息（mock 场景可省略） |

维度报告项：

| 字段 | 说明 |
|---|---|
| dimensionId / dimensionName | 维度 id / 名称 |
| dimensionEvaluate | 维度评价（`第X题：评语` 逐行拼接） |
| dimensionScore | 展示用维度得分（换算后百分制） |
| originScore / originTotalScore | 换算前平均分 / 满分（mock 满分取 20） |
| appraiseRate | 考核比例（归一化后的权重） |

回答记录项：

| 字段 | 说明 |
|---|---|
| question | 题目题干 |
| questionType | 题型编码 |
| questionAnswer | 用户回答 |
| probeQuestion / probeQuestionAnswer | 追问及回答（本 skill 恒为空） |
| score | 本题分数（百分制） |
| coachSuggestion | 辅导建议（回答优点/改进建议/参考作答，展示时带线上前缀） |
| referenceAnswer | 参考回答 |

### 6. 排序

维度报告按 得分比例（`originScore / originTotalScore`）**升序**排列——得分最低的维度排在最前。HTML 报告必须按此顺序渲染维度行。

## 三、skill 内的简化假设

- 无真实 userId/interviewId/resumeId/botId，跳过用户上下文校验、简历附件读取与 bot 调度；评估由当前模型按线上 prompt 与输出契约直接执行。
- 维度信息由抽题工具 `draw_questions` 按维度配置真实拼接：`assessmentLatitude`（评分标准列表）、`evaluation`（维度简介列表）、维度名（可读名称）。dimensionScore 即维度满分（多为 20）。维度库未命中的 id 兜底为 `维度(id)(20分)`，该兜底**仅用于内部评估文本**（拼进 prompt 的 assessmentLatitude/evaluation）；用户可见的维度名一律用可读名称，若无可读名称用通用占位名（如「维度N」），**严禁把原始 id 带进用户可见内容或报告中**。下游评估直接取用抽题返回的同名字段，不得自行重拼。
- 无权重配置：维度权重按等权规则分配。
- 无追问流程（isProbe=false）；如需模拟，先基于用户回答生成一个追问，再按「追问:... 回答:...」格式拼入 content。
- 跳过的题不执行两个评估，各维度按 0 分参与聚合，辅导建议留空。
