# 任务查询与结果交付

已有任务查询、生成提交后的刷新和成品检查只读本文件，不加载模型推荐、参数模块或生成提交流程。`generationId` 必须来自真实任务；无法明确对应任务时先定位，不猜 ID、不重新生成。

`query_tasks` 使用真实任务编号；作品以原序号与 `contentType` 关联，临时 URL 不是永久标识。刷新链接、素材复用和明确查询均可调用原任务。没有任务编号且无实时任务列表/追踪能力时报告未知，不能仅凭 `taskTraceId` 查询或认定尚未创建。

## 状态刷新与回落

以宿主实际反馈判断 widget 是否已挂载并能刷新；仅有 UI 元数据不够。

| 场景 | 行为 |
| --- | --- |
| 已确认本次任务 widget 正常刷新 | 由组件查询并原位展示；模型不自动重复查询或创建第二张卡片 |
| 未挂载、挂载失败或组件不能刷新，用户要求生成作品 | 使用实时状态工具查询同一 `generationId`，直到终态或触发下述停止条件 |
| 用户明确单独查询进度 | 调用一次 `query_tasks` 返回当前快照，不开启查询循环；这是用户主动请求，不是 widget 自动刷新 |
| 用户明确展示已有结果 | 当前组件可用时沿用；否则实时存在 `query_result` 时调用一次，缺失时用 `query_tasks` 返回媒体或文本 |
| 已授权的多步骤任务需要前一步结果，但宿主不回传 widget 更新 | 可按下述规则查询原任务取得依赖结果，复用已有组件，不重复生成或展示 |
| 为后续生成取得源作品的当前 URL | 按源任务编号查询一次；这是素材准备，不重建结果卡片 |

需要查询时，按提供方允许的间隔继续到任务成功或失败。用户取消、当前轮次超时、宿主达到执行限制、限流或查询异常时停止，返回当前状态与任务编号；不重提生成。没有任务编号时按前述歧义规则处理。

widget 正常呈现时避免重复媒体和下载链接；用户明确索取链接或某个作品时按其请求提供。无 widget 时返回工具的可用媒体或主结果链接；用户要求多个作品时展示对应结果，不将批量结果强行限制为一项。

## 完成判定

- 状态按实时 schema/响应说明归一化。非终态只说“已提交”或“处理中”；任务失败时报告服务消息并保留 ID；消息若包含当前可用集合之外的模型名，概括失败原因，不原样透出隐藏型号。
- 任务终态成功，且至少有一个符合目标媒体类型的可用作品，才可宣称完成。作品级状态存在时必须为成功；缺失时依据任务终态和媒体。明确非成功的作品不能因含 URL 被当作成品。
- 主媒体优先使用提供方可用的 `urlWithoutWatermark`，其次 `url`；`coverUrl` 等只作封面，不能充当视频。结果包含多项时保留作品映射；部分成功如实说明。
- 终态成功却没有可用作品属于结果不一致，报告事实，不自动生成替代品。签名 URL 不写日志或当作永久资产 ID。

## 成品检查与迭代

任务成功只证明产出了文件，不证明符合创作要求。有宿主支持的查看/播放能力时，检查实际作品的用户必需项：图片的文字/身份/结构/裁切，视频的动作连续性和必要音轨；只有封面时不宣称运动或音频合格；不为质检提交额外生成，不为拿到同一结果重复创建卡片。无法检查时交付结果，并简短说明尚未做视觉或音频检查。

检查以用户的必需项为准：身份、产品结构、准确文字、动作/声音、规格与指定改动范围。发现明确偏差时返回现有结果并说明具体问题，不宣称“完全一致”或“可直接投放”；区分已观察到的问题与尚未检查的部分。

用户要求改进时，先区分局部编辑还是重新生成：保留其满意的内容，只修改针对问题的提示词、素材或参数，仍按一次已授权步骤提交。用户只问评价时提供改进建议；“质量欠佳”本身不授权自动重抽，也不构成删除原作品的理由。

## UI 与输出

只使用远端工具实际关联的 `_meta.ui.resourceUri`（兼容 `_meta["ui/resourceUri"]`）及 `text/html;profile=mcp-app` 资源。资源元数据存在不等于 widget 已挂载；不复制 HTML 或增设 MCP server。

结果字段以真实响应为准；下载优先可用的 `urlWithoutWatermark`，其次 `url`，封面不替代视频。错误消息中的凭据或当前账号不可见型号不原样透出。只凭工具调用成功不推断作品合格。

当前步骤完成后继续已授权且依赖满足的步骤。用户要求修改或重试才重新进入生成流程；质量欠佳、任务失败或链接过期都不构成自动重提授权。
