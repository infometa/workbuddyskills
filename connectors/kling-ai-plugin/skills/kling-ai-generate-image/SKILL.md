# Kling AI 图像生成

将创意需求转化为一条规格明确的 Kling 图像请求。使用本包 `mcp.json` 中 `kling-ai-plugin` 连接的实时工具与模型定义，不在 Skill 中另设端点。

## 使用约定

- 使用宿主管理的 OAuth。不索取或暴露 API key、token、cookie、授权头及上传票据。用户要求的作品预览/下载 URL 可以返回，但不写入日志或用作永久标识。
- 用户提出生成请求，即表示在补齐会实质影响结果的缺失输入后，授权提交一次任务。不要增加积分消耗警告或单独的确认步骤。
- 每个明确授权的生成步骤只提交一次；多个不同任务及跨媒体依赖按共享流程串行执行。绝不盲目重试结果不明确或失败的提交。
- 先发现实时模式定义，再选择工具、模型、输入名称或枚举值。实时提供方字段优先于本文示例。
- 需要时，使用远程上传工具上传附带的参考媒体，并原样复用返回的提供方引用。

使用主体库、动作库或本地素材上传时，先读[素材工作流](../kling-ai-plugin/references/asset-workflows.md)。

生成前按[能力发现](../kling-ai-plugin/references/capability-discovery.md)获取候选，遵守[账号可见性](../kling-ai-plugin/SKILL.md#模型可见性与灰度)。选定模型后读取[参数模块加载表](../kling-ai-plugin/references/model-parameters.md)，只加载满足触发条件的文件；提交时读[生成流程](../kling-ai-plugin/references/tool-workflows.md)。只查已有任务直接读[任务结果](../kling-ai-plugin/references/task-results.md)。

## 工作流程

只查已有任务时不执行以下生成步骤。

1. 根据下方模式表与用户素材确定候选入口，只发现相关模型；先检查用户必需能力，选定模型再构造参数。
2. 按参数模块加载表只读本次适用的规则；相关规格字段都只有唯一合法值时才跳过选档说明。发现要求不受支持时先处理限制，不加载不支持功能的详细写法。
3. 每次新建生成、编辑或变体都读[提示词构建](references/prompt-construction.md)，按本次用途选定一个质量画像，用它决定提示词写哪些可见事实和提交前检查什么；只有纯查询和已授权的原参数重试可免读。用途需要进一步场景决策时再加读[场景模式](references/scene-patterns.md)。不要因为“已有完整方案”跳过提示词构建。
4. 内部确定成品用途、必须保留的事实和允许创作的范围。关键身份/文案缺失或要求冲突时才补问；普通光线、背景和未指定的可选参数可合理选择。
5. 构建提示词并与所选模型参数及实际素材绑定对齐，按生成流程提交一次；返回任务后转任务结果流程，不在此重复定义查询与重试。

## 生成模式

| 用户意图 | 模式 | 必须采用的理解方式 |
| --- | --- | --- |
| 文生图 / text-to-image | 新建图像 | 不使用源图控制身份或构图，完全根据文字需求构建场景。 |
| 图生图 / image-to-image | 编辑或参考图引导的图像 | 至少一张图像用于控制内容、身份、产品结构、构图或风格。为每项输入明确指定角色。 |
| Element 参考主体 | 当前账号支持的图像入口 | 先读取 Element，再按 `who_am_i` 确认目标模型支持该主体类型与绑定参数，满足必填输入；不按入口名称预设允许或禁止。 |
| 变体 / restyle | 按指定范围修改的图生图 | 明确全部允许改动项，锁定其余事实；没有具体改动范围时才采用单维度变化。 |
| 查看 / 预览动作库 | 只读素材查询 | 用 `motion_library_list` 查询已保存动作，按[动作库流程](../kling-ai-plugin/references/asset-workflows.md#动作库与动作控制)展示真实结果与预览，不调用生成工具。 |
| 套用库中动作 / 参考视频动作 | 动作控制视频 | 转交[视频 Skill](../kling-ai-generate-video/SKILL.md) 使用 `motion_control`：主体图加动作库 `motionId` 或参考视频，动作来源二选一；模型与必填参数以 `who_am_i` 为准，不作为图生图提交。 |
| 查进度 / status | 只读 | 不调用生成工具；查询已有任务。 |

不要静默切换模式。附带图像不等于自动要求图生图：如果用户要求生成一张无关的新图像，只有在确认附件与请求无关后才能忽略它。反过来，在上传或模式定义校验失败后，也绝不能把明确的图生图请求降级为文生图。

调用工具前，在内部检查所选模式、宽高比、参考图角色和允许的改动。除非需要用户澄清缺失的创意要求，否则不要显示提交前的过程消息。

## 创作约束

规格取值由选定模型的参数模块处理，不从示例补字段或档位。新增文字仅在用户要求时生成；编辑时保留未指定修改的标签、标志和产品结构。变体明确全部允许改动项，其他事实保持一致；不虚构功效、认证、价格或统计数据。

## 质量门禁

提交前，将用户要求与提示词、模型参数、参考输入逐项对齐：改动范围、文案、比例和数量一致，视觉焦点清楚，构图与光线不互相冲突。不要为了填满提示词模板而增加无关细节。

生成后，宿主可查看原图时检查：身份与产品结构、标签/文字、数量与肢体、裁切和布局、明显畸变；按用户用途判断，不把低分辨率缩略图当作文字细节验收。发现问题按[成品检查与迭代](../kling-ai-plugin/references/task-results.md#成品检查与迭代)交付，不自动重新生成。

## 失败处理

- 授权失败：引导用户使用 WorkBuddy 原生 MCP 连接流程。
- 参数不受支持：刷新能力并准备修正方案；已提交的生成仍遵守共享流程，不因修正参数自动重提。
- 积分不足：告知用户充值并停止。不要自动重试。
- 响应丢失：按任务结果流程恢复或报告未知，不得盲目重放生成调用。
- 提供方失败：按共享流程概括原因、过滤敏感信息并保留任务 ID；不要自动重新提交。
