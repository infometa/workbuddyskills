# Kling AI 视频生成

将用户需求转化为连贯的 Kling 动态方案和一条已批准的远程生成请求。使用本包 `mcp.json` 中 `kling-ai-plugin` 连接的实时工具与模型定义，不在 Skill 中另设端点。

## 使用约定

- 使用宿主管理的 OAuth。不索取或暴露 API key、token、cookie、授权头及上传票据。用户要求的作品预览/下载 URL 可以返回，但不写入日志或用作永久标识。
- 用户提出生成请求，即表示在补齐会实质影响结果的缺失输入后，授权提交一次任务。不要增加积分消耗警告或单独的确认步骤；实时工具要求披露计费时，在提交前说明实际返回的计费范围，不猜单价或计费方式。
- 每个明确授权的生成步骤只提交一次；多个不同任务及跨媒体依赖按共享流程串行执行。绝不自动重试失败或结果不明确的生成。
- 在运行时发现实时工具和模式定义。不要根据示例硬编码模型名称、输入角色、时长值或多镜头字段。
- 需要时，通过远程上传工具上传附带媒体，并保留准确的返回引用。

使用主体库、动作库或本地素材上传时，先读[素材工作流](../kling-ai-plugin/references/asset-workflows.md)。

生成前按[能力发现](../kling-ai-plugin/references/capability-discovery.md)获取候选，遵守[账号可见性](../kling-ai-plugin/SKILL.md#模型可见性与灰度)。选定模型后读取[参数模块加载表](../kling-ai-plugin/references/model-parameters.md)，只加载满足触发条件的文件；提交时读[生成流程](../kling-ai-plugin/references/tool-workflows.md)。只查已有任务直接读[任务结果](../kling-ai-plugin/references/task-results.md)。

## 按能力加载推荐

只查已有任务时，直接进入任务结果流程，不加载生成推荐或创作参考。新生成先读取当前连接完整的 `tools/list`（有 `nextCursor` 时继续读取），再只读取下列一份文件：

| 工具发现结果 | 读取文件 |
| --- | --- |
| 没有 `omni_ref_video` | [基础视频推荐](references/standard-video.md) |
| 存在 `omni_ref_video` | [全能参考与新模型推荐](references/omni-video.md)；文件内继续按实际模型集合判断新旧分支 |

选定分支后按[视频候选入口](../kling-ai-plugin/references/capability-discovery.md#视频候选入口)查询模型：存在 `omni_ref_video` 时，普通文生/图生视频必须将它与原入口一起查询，再判断当前账号模型是否满足输入要求。推荐文件只负责选型，具体参数按模块加载表读取。不要同时预加载两份推荐，也不要按工具总数分流。发现失败不能当作“没有新工具”而走基础分支；说明无法读取能力并停止选型。切换账号、环境或重新连接后重新判断，失效的旧分支不再作为依据。

## 工作流程

1. 按推荐文件与实时响应确定“工具 + 模型”，用户指定且当前可用时优先。然后按参数模块加载表处理实际规格、必填/选用输入和声音需求，不提前加载不适用模块。
2. 每次新建生成、编辑或变体都读[运动与镜头规划](references/motion-and-shots.md)，按本次用途选定一个镜头画像，用它决定动作预算、镜头路径、连续性锚点和验收标准；只有纯查询和已授权的原参数重试可免读。产品展示、UGC、讲解、多镜头或社交格式需要进一步场景决策时再加读[场景模式](references/scene-patterns.md)。不要因为“已有完整方案”跳过运动与镜头规划。
3. 内部明确成品用途、必须保留的主体与目标动作。只询问会阻断执行或造成明显误解的素材、对白及冲突要求；普通运镜、光线和未指定的可选参数可合理选择，不要求用户逐项填写。
4. 构建以动态为中心的提示词，说明主体动作、镜头动作、环境运动、节奏、连续性和受保护元素。将抽象质量要求落实为光线、材质、景深和构图。
5. 按生成流程完成参数检查、余额查询与单次提交，受理后转任务结果流程。不要为了比较模型自动生成多份，也不在预览后未经请求再生成正式成片。

## 创作约束

参考角色、帧顺序、组合上限、声音控制与输出规格只按选定模型加载适用模块。未支持的输入不能静默丢弃或转成纯文本；不猜字段、型号或枚举，不切账号/端点试探。

提示词聚焦用户目标的动作与视觉，不添加未要求的旁白、画面文字、额外角色或功效。单镜头与多镜头依用户叙事需求选择，并与实际支持的参数一致；不为增加镜头自动拆成多个收费任务。

## 质量门禁

提交前，将提示词与实际参数对齐：时长、画幅、单/多镜头和声音开关一致；动作有起点、过程和落点，首尾帧之间可过渡，多镜头连续性明确。对于广告和讲解视频，确保每个镜头有清楚的传播目的。

生成后，宿主可检查视频时查看开头、关键动作、转场与结尾，检查身份漂移、产品变形、闪烁、动作突变和裁切；需要对白/声音时还要听取音轨，检查台词、口型与原声意图。只有封面或抽帧时，不据此声称运动或音频合格；检查与后续改进按[共享规则](../kling-ai-plugin/references/task-results.md#成品检查与迭代)执行。

## 失败处理

- 授权失败：引导用户使用 WorkBuddy 原生 MCP 连接流程。
- 参数或模型无效：刷新能力并准备修正方案；已提交的生成仍遵守共享流程，不因修正参数自动重提。
- 积分不足：告知用户充值并停止。不要自动重试。
- 响应丢失：按任务结果流程恢复或报告未知，不得盲目重放生成调用。
- 提供方失败：按共享流程概括原因、过滤敏感信息并保留任务 ID；不要自动重新提交。
