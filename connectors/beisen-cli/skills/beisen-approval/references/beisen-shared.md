# 北森 HR 共享规则

本 Skill 是所有 beisen-* 业务域 Skill 的公共基础设施。每个业务域 Skill 必须在其 SKILL.md 开头声明：

```markdown
**CRITICAL — 开始前 MUST 读取 [references/beisen-shared.md](references/beisen-shared.md)**
```

---

## 连接器与身份

- 全部能力通过北森连接器已注册的 MCP 工具提供；授权由连接器托管（OAuth），会话内**无需安装任何 CLI、无需收集账号密码或 API Key**。
- 执行身份 = 当前授权账号：用谁的账号完成授权，就以谁的身份查询和操作，无身份切换参数。
- 可查询的数据范围、是否具备管理权限，由北森后台对该账号的授权决定，而非工具参数控制。

## 连接器可用性前置校验（硬性门禁）

**任何 beisen-* Skill 在发起第一个 MCP 工具调用之前，必须先完成本校验。**

### 判定

在连接器当前已注册的工具清单中查找北森工具（名称含 `beisen` 前缀）。
- 找到 → 正常执行业务 Skill。
- **一个都没有 → 判定为「连接器未就绪」，立即按下方处置，不得继续任何业务步骤。**

判定只看工具清单本身是否为空，**不因以下任何迹象提前改判**：工具看似"应该存在"、历史会话用过、配置文件存在、连接器面板显示"已连接"、命令行工具可执行。

### 处置（连接器未就绪时）

1. 如实告知用户：北森 HR 能力当前不可用，需要重新授权连接器。
2. 明确给出恢复步骤：**断开北森连接器 → 重新授权 → 开一个新会话**。并说明原因：MCP 服务在会话启动时一次性初始化，失败的会话在本会话内不会自动重试，重新授权必须配合新会话才生效。
3. 交付后结束本轮，不进入任何业务步骤、不输出任何业务结论。

> **优先级例外**：静默执行与静默退出规则仅适用于"能力可用但无结果"的场景。连接器未就绪属于**能力不可用**，是静默规则的唯一例外——必须出声告知用户，不得静默退出、不得交由其他路由（菜单唤起、知识问答）兜底。

### 绝对禁止（连接器未就绪时，以下一律不得执行）

- ❌ **不得改用任何旁路（命令行工具、脚本、自行安装的任何客户端）替代已注册的 MCP 工具**——全部能力只由已注册的 MCP 工具提供，这是不可变通的边界，不是性能取舍。
- ❌ 不得自行安装、下载、初始化任何客户端或工具。
- ❌ 不得要求用户提供账号、密码、API Key 或任何凭据。
- ❌ 不得凭记忆、常识或历史数据推测并回答业务问题（宁可无数据，不可编造）。
- ❌ 不得在同一会话内反复重试；不得反复引导用户重连超过 1 次。
- ❌ 不得把"连接器未就绪"表述为"没有找到你想要的数据"或"换个描述试试"——那是数据层面的空结果，与能力不可用是两回事，混用会让用户误以为是自己表述有问题。

### 机制说明（供判断，不必转述给用户）

- MCP 服务器在会话启动时一次性初始化，失败后本会话内不会自动重挂载。
- 重新授权只刷新令牌，不会重新挂载服务器，因此**必须开新会话**。
- 连接器面板显示"已连接"不代表工具已注册成功，两者可能不一致。

## 能力级权限缺失（单类能力工具不在已注册清单中）

**与「连接器未就绪」是两回事，必须先分流再处置。** 连接器只挂载**当前授权账号有权限访问**的工具：清单里有其他北森工具、唯独缺当前 Skill 所需的某类能力工具时，**不是**连接器未就绪，而是该账号未开通这一项能力权限。

### 判定（先按连接器可用性前置校验确认"清单非空"，再走本节）

- 清单中**无任何**北森工具 → 属「连接器未就绪」，按上一节处置（不要套用本节）。
- 清单中**有其他**北森工具，但**缺当前 Skill 所需的某类能力工具** → 判定为「能力级权限缺失」，按下方处置。

> Skill 正文罗列的是产品的**全部能力面**；连接器返回的是**当前账号有权限的子集**。两者差额 = 未授权，不等于产品没有该功能，也不等于"工具不存在"。

### 处置（能力级权限缺失时）

1. 如实告知用户该能力**尚未对其账号开通**，用业务化的能力名称（取自当前 Skill 的业务域或用户所问能力），不使用任何工具名。
2. 固定话术：**"你的账号暂未开通「{能力名称}」权限，如需开通，请联系你的企业管理员。"**
3. 交付后结束本轮，不进入需要该能力的业务步骤，不输出任何依赖该能力的结论。

### 绝对禁止（能力级权限缺失时，以下一律不得执行）

- ❌ 不得表述为"工具不存在 / 没挂载 / 没注册 / 本会话没有该工具 / 没有挂载 XX 查询工具"——暴露内部机制，且把"未授权"错误暗示成"产品缺功能"。
- ❌ 不得把"能力级权限缺失"改判为"连接器未就绪"（后者是清单整体为空，处置是重新授权 + 新会话，二者话术不可混用）。
- ❌ 不得把"能力级权限缺失"表述为数据层的"没找到数据 / 换个描述试试"——用户没做错任何事，是权限未开通。
- ❌ 不得改用任何旁路（命令行工具、脚本、自行安装的客户端）绕过缺失的工具，也不得要求用户提供凭据。
- ❌ 不得凭记忆或常识推测该能力下的业务数据（宁可不出结果，不可编造）。

## 工具使用总原则（读取与加载机制）

- **工具发现**：在北森连接器当前已注册的工具清单中，按工具名与工具描述匹配用途相符的工具；工具清单是唯一事实源，不假设存在清单之外的工具。
- **参数构造**：完全依赖目标工具自身的 inputSchema（字段含义、必填项、类型、格式、枚举、默认值）构造参数；Skill 文件不复述接口字段细节。缺少关键参数时先追问用户，不猜测。
- **结果解读**：按工具的 outputSchema 与结构化结果说明解读返回，文本内容作为兜底；成功/失败判断与错误含义以工具返回的说明为准。
- Skill 文件只承载业务边界、流程编排、行为纪律与展示规则。

## 授权失效与错误处理

- 工具返回未登录、凭证过期或授权失效 → 提示用户重新授权北森连接器，完成后重试原请求；不在会话内反复重试未授权调用。
- 权限不足（**工具已调用、由工具返回权限错误**）→ 如实转述工具返回的原因，引导用户联系企业管理员开通对应权限或产品；不对权限错误反复重试。若某类能力工具在已注册清单中**本就缺失**（连接器已就绪但缺该类工具），不属于本条，按上方「能力级权限缺失」处置。
- 参数错误 → 对照该工具 inputSchema 修正，最多修正 1 次。
- 网络/超时 → 最多重试 2 次；超时不代表未执行，先查询结果再决定是否重试。
- 同一失败原因最多重试 1 次（网络重试除外），防止耗时失控。
- 报障时附上工具返回的请求标识（如 requestId）。

## 写操作门禁

当前能力以只读查询为主。一旦出现写操作类工具（录入、提交、修改、推进流程等），一律执行两段确认：

1. **先展示操作摘要**（操作类型、目标对象、影响范围、风险），完整复述给用户。
2. **用户明确回复确认后**才执行；用户拒绝 → 终止流程，不擅自改写参数或绕过确认。
3. 执行后读回结果交付。

补充约束：

- 单次批量写入/删除不超过 50 条；超过时拆批并逐批确认。
- 严禁以任何参数或方式跳过用户确认静默执行写操作。
- 薪酬查询、批量操作、数据导出，未获用户确认不得执行。

## 安全规则

### 绝对禁止

- ❌ 不要把任何凭据（token、密码、API Key）写入回答、文件或日志
- ❌ 不要编造员工、组织、审批、职位、任务等标识符；必须从工具返回中提取
- ❌ 不要将人力资源数据（薪酬、绩效、个人信息）发送到任何外部系统
- ❌ 不要在同一轮对话中展示敏感数据后紧跟着询问"是否要分享"
- ❌ 不要在 L3 机密数据场景中跳过二次身份验证

### 严格要求

- ✅ 工具返回的各类内部 ID 必须替换为可读名称后再展示给用户
- ✅ 涉及 L2/L3 敏感数据的查询结果，提取关键信息后摘要展示，不回显原始返回
- ✅ 查询他人数据时，先确认当前账号是否具备对应访问权限

## HR 数据分级展示策略

| 级别 | 分类 | 数据示例 | 展示规则 |
|:---:|------|---------|---------|
| L0 | 公开 | 组织架构、部门名称、公司公告 | 正常完整展示 |
| L1 | 内部 | 员工姓名、职位、工号、部门 | 正常展示，批量查询时默认摘要模式 |
| L2 | 敏感 | 考勤记录（他人）、绩效结果、晋升记录、候选人/求职者信息（招聘域） | 仅本人可查全部，他人查询时摘要展示；不回显原始返回 |
| L3 | 机密 | 薪酬、工资条、身份证号、合同附件 | 二次身份验证；脱敏展示；不回显原始返回；不写入任何持久化存储 |

**数据展示强制规则：**

- 查询 L2/L3 级别的他人数据时 → 必须先确认当前账号是否具备管理员访问权限
- L3 数据查询 → 二次身份验证（密码或短信验证码），验证失败直接终止
- 展示 L3 数据后 → 以"薪酬/个人信息已展示，请注意信息安全"作为收尾

## ID 引用规则

> 适用于所有 beisen-* Skill 的全部 MCP 工具调用。

1. **只复制真实值**：工具返回结果中的标识符（员工、组织、审批、职位、申请、任务、菜单、场景等 ID），只允许直接复制返回内容中真实存在的值。
2. **严禁编造 ID**：严禁编造、猜想、拼接任何 ID。下一步需要的 ID 不在最近工具返回中时，禁止调用工具，向用户说明缺少必要信息。
3. **精确匹配**：引用 ID 必须与工具返回中的字符完全一致，大小写、符号不得修改。
4. **就近取用**：不靠记忆记录 ID，所有参数值必须来源于最近一次工具返回的内容。
5. **空值阻断**：工具返回为空或缺少所需 ID 时，停止后续调用，如实告知用户无法继续。

## 回答语言

- 面向用户的回答只用业务语言：工具名、字段名、参数名、状态码与各类内部 ID 只用于理解工具，不出现在回答里。
- 空结果按工具返回的说明如实转述，不反推为"确实没有"或"没权限"（本条针对**数据层空结果**——工具已调用、返回为空；某类能力工具在清单中本就缺失属能力级未授权，按「能力级权限缺失」处置，不受本条约束）。
