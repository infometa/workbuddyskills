# 审批中心

**CRITICAL — 开始前 MUST 读取 [references/beisen-shared.md](references/beisen-shared.md)**

## 路由优先级

本 Skill 处理：审批流程状态、节点、审批人查询（本人待办 / 已办）

不归本 Skill 处理：
- 创建审批定义、审批同意/拒绝/转交/撤回 → 走后台管理界面

## 触发场景

当用户表达以下意图时触发：
- 查流程、查审批、流程进度、审批到哪了
- 我的流程状态、XX的审批进度
- 当前节点、审批人是谁
- 在途流程、进行中的流程、审批中的流程
- 已结束流程、已通过/已驳回的流程
- 某段时间内的流程、最近的流程

## 工具的读取与加载

- **工具发现**：在北森连接器当前已注册的工具清单中，按名称与描述匹配"查询本人待办审批""查询本人已办审批"类工具；工具清单是唯一事实源，本文件不枚举工具名与字段。
- **参数构造**：时间范围、流程状态、审批类型等筛选条件是否支持及其字段、枚举取值、日期格式，完全依赖该工具自身的 inputSchema；均为可选条件，用户未提及则不传。
- **流程状态语义**：业务上分为在途（审批中等进行中状态）与已结束（通过、不通过、已完成、已终止、已驳回、已撤回）；具体状态枚举值以 inputSchema 说明为准，用户说"在途/进行中"或"已结束/已通过/已驳回"时映射到对应状态集合筛选。
- **结果解读**：按工具 outputSchema 与返回说明解读；每条审批记录通常含流程标题、审批类型、流程状态、当前节点、当前审批人、发起时间、到达时间、详情页链接等业务信息，实际字段以返回为准。

## 工作流程

1. **查本人待办**：用户查询自己的待办时，调用待办查询工具；结果按到达时间降序组织，统计的数量必须与查询到的数量一致。
2. **查本人已办**：用户查询自己的已办时，调用已办查询工具；未指定时间时按工具自身默认口径（如默认近 30 天，以工具说明为准）；结果按发起时间降序组织，统计数量与查询到的数量一致。
3. **时间范围**：用户提到时间范围时，从原文提取开始/结束时间，按工具 inputSchema 声明的日期格式传入；只提到单边时间时按单边筛选处理。
4. **结果输出**：先总结，再以 Markdown 表格展示详细内容；若记录中返回了详情页链接，将链接作为流程标题的超链展示（链接必须来自工具返回，严禁编造）。

## 执行原则

- 待办/已办查询的是当前授权用户本人的审批数据；仅能查询自己发起或参与过的流程
- 审批列表属于 L1 内部数据，正常展示；批量结果较多时使用摘要模式，并提示还有更多记录可继续查看
- 审批对象、任务、审批人等内部 ID 只用于串联后续查询（如补查详情），必须从工具返回中提取，严禁编造，且不展示给用户
- 已拿到详情类标识后，不要重复查询列表
- 审批标题和审批人信息直接展示，无需额外转换

## 边界情况

- 查询结果为空时，说明"暂无相关审批流程"，不反推为"没权限"
- 结果较多时，提示"还有更多待办/已办，是否继续查看？"

## 不在本 Skill 范围

- 创建审批定义（走后台管理）
- 非审批类待办（如招聘待办 → [../beisen-recruiting-todo/SKILL.md](../beisen-recruiting-todo/SKILL.md)）
- 审批操作（同意/拒绝/转交/撤回）— 当前版本不支持
