# 员工数据查询

**CRITICAL — 开始前 MUST 读取 [beisen-shared.md](beisen-shared.md)**

**本 Skill 是北森连接器所有 read-only 数据查询场景的统一入口。** 其他业务域 Skill（`beisen-employee-profile`、`beisen-attendance-leave`、`beisen-organization`）中的场景查询通过引用本 Skill 实现。

## 任务目标

- 根据用户自然语言输入，识别数据查询意图，匹配查询场景，提取筛选参数，获取业务数据并智能总结为可读答案
- 能力包含：意图识别、场景匹配、参数提取、数据检索、智能总结、关联菜单展示
- 触发条件：用户询问个人/团队业务数据（如假期余额、考勤异常、下属信息、绩效情况等）

## 工具链的读取与加载（MCP 机制）

流水线需要五类工具，均在北森连接器当前已注册的工具清单中**按用途匹配**（工具名与工具描述是唯一事实源，本文件不枚举工具名与字段）：

| 流水线角色 | 用途 |
|---|---|
| 场景发现 | 获取租户已配置的查询场景列表（场景标识、场景名称、场景描述） |
| 场景说明 | 按场景标识获取该场景的输出要求与关联菜单 |
| 场景字段 | 按场景标识获取该场景支持的筛选字段（字段含义、类型、可选值） |
| 数据查询 | 按场景标识与筛选条件查询业务数据 |
| 菜单检索 | 按菜单标识或关键词获取菜单名称与链接 |

- 参数构造完全依赖各工具自身的 inputSchema；结果解读依赖 outputSchema 与返回说明。
- 场景标识、字段标识、菜单标识等一律从上一步工具返回中**原样透传**，严禁编造、修改或跨场景复用（见 beisen-shared ID 引用规则）。
- 工具清单中缺少某类工具时，按 beisen-shared「能力级权限缺失」处置（连接器已就绪、仅该类能力工具缺失 = 当前账号未开通该能力，给友好权限提示），不用其他工具硬凑、不暴露"工具/清单/没挂载"等内部机制。北森工具整体缺失时按 beisen-shared「连接器可用性前置校验」处置，优先级高于本条。

## 静默执行（硬性规则，适用于全部步骤）

**你输出的每个字用户都看得见，不存在"内部思考/过程说明"通道。**

- 意图判断、场景匹配、参数提取、数据查询、降级切换全部在内部静默完成，禁止写成任何文字。禁止示例："用户问XX，这是一个关于XX的查询，让我判断……""场景'XX'强命中""字段列表为空，说明……""按降级规则需静默退出……"
- 工具轮零文本：直接调用工具，调用前后不输出任何文字（"让我先读取相关技能指令并探测可用场景"等一律禁止）
- 面向用户的文字只允许出现在最终答案轮（或必要的追问/确认）

> **优先级例外**：静默执行与静默退出仅适用于"能力可用但无结果"的场景。连接器未就绪（工具清单中无任何北森工具）属于**能力不可用**，须按 beisen-shared「连接器可用性前置校验」出声告知用户并结束，不得静默退出、不得交由其他路由兜底。

## 操作步骤

### 步骤零：连接器可用性校验（所有步骤的前置门禁）

按 beisen-shared「连接器可用性前置校验」执行。
- 未通过（无任何北森工具）→ 立即按该节处置并结束本轮，不进入步骤一及后续任何步骤。
- 通过 → 进入步骤一。

### 步骤一：判断意图类型

根据用户输入判断是否为数据查询意图。**数据查询意图必须具备明确的数据询问结构**，即包含以下特征之一及以上：

- 疑问词/疑问句式（"多少""有没有""是否""哪些"）
- 数量/余额/记录类诉求（"还剩""余额""记录"）
- 时间范围 + 指标（"本月考勤""今年的绩效"）
- 明确主体 + 指标组合（"李白的任职信息""我团队的工时"）

**询问结构以整句为单位判定**：整句必须是向系统求取数据的疑问或请求表达；若整句是名词性短语、标题或描述性文案，即使内部嵌有形似"主体+指标"的片段或数量词字样，也不构成数据询问结构。

分类处理：

- **数据查询意图**（如"我还有多少年假"、"李白本月是否有考勤异常"）→ 进入步骤二
- **非数据查询意图**：以下情况均不走本流程，**静默退出**：
  - 用户询问企业政策、功能入口位置、操作导航
  - 输入为裸名词、功能名式短语或疑似某个功能/页面/菜单的名称或描述性文本（如"我的目标""日报"）——即使其中出现"查询""视图""权限""数据"等字样，只要整句不具备数据询问结构，就不是数据查询意图
- 多轮对话时，结合最近 10 条对话滚动判断意图，并将代词（他/她/那个人）和省略主语的表达替换为前文已出现的具体人名
- 静默退出时：不输出任何判断过程、解释说明或提示文案，交由 Agent 继续路由（菜单唤起或知识问答）

### 步骤二：匹配查询场景

1. 调用**场景发现**工具获取租户已配置的查询场景列表（场景标识、场景名称、场景描述）。
2. 结合用户问题和场景名称、描述判断是否命中。**命中标准为强命中，需同时满足两个条件**：
   - ① 用户问题具有数据询问结构（见步骤一）；
   - ② 该场景提供的数据能**直接回答**用户的问题。

   仅词面相似不构成命中，缺任一条件均视为无场景命中。匹配比对是内部过程，禁止在回答中输出场景清单、逐个排查分析或"让我看看"式推理文字。
3. 命中多个场景且无法确定唯一匹配 → 输出简短追问让用户确认（如"你是想查考勤记录还是假期余额？"），确认后再继续。
4. 仅命中 1 个场景 → 直接使用。
5. 无场景强命中 → **按"非数据查询意图"降级处理**：立即静默结束本流程，交由菜单唤起或知识问答处理。不输出任何文案，包括"暂不支持查询XX""没有找到数据"、场景分析过程或自行编造的查询建议。
6. 命中后，用场景标识调用**场景说明**工具，获取该场景的输出要求与关联菜单。

### 步骤三：获取可筛选字段并提取参数

1. **场景字段工具必须调用，严禁跳过**（真实事故：跳过本步骤、复用其他场景的字段导致查询返回错误数据）：用命中的场景标识调用**场景字段**工具，获取**本场景**支持筛选的字段清单（字段含义、类型、可选值）。字段清单每场景不同，严禁从记忆中复用其他场景的字段。
2. **组织能力前置检查**：检查字段清单中是否存在部门/组织范围类筛选字段——
   - **存在**：本场景支持组织范围查询，按 [business-rules.md](business-rules.md) "查询主体与组织范围判定"确定查询主体。
   - **不存在**：本场景仅支持查本人/权限范围/指定人。若用户问法属于组织范围查询（"XX负责的部门""XX部/中心"等），**一律静默退出**交由菜单唤起或知识问答处理，不输出任何文案、不降级为查指定人。
3. 根据字段清单和用户问题提取筛选参数：主体判定、日期行为、防误提取等业务规则见 [business-rules.md](business-rules.md) "参数提取规则"章节；**字段取值格式（日期形态、选项值、分页等）一律以该工具 inputSchema 与字段说明为准**。身份判定只依据用户原文的显性表达，禁止结合登录用户身份推断称谓指向。**用户原文无明确时间表达时，时间条件一律不传**，禁止自行默认任何范围。

### 步骤四：执行数据查询

将场景标识与提取的筛选条件传入**数据查询**工具：仅传有值的筛选字段；所有标识与字段取值原样透传自前序工具返回，禁止修改。

结果处理：

- 工具返回失败 → 输出固定文案（见 business-rules.md 固定文案表"查询失败"行），流程结束
- 返回记录为空 → 视为无数据（固定文案"无数据匹配"行）
- **返回记录数达到单次查询上限时（上限以工具返回或其说明为准）→ 视为"返回量触顶"**：实际数据可能多于已返回部分，此时**禁止**对全量数据下绝对结论（如"没有异常""全部正常""无请假记录"），必须按 business-rules.md "大数据量与返回边界提示"追加边界提示，并将结论限定为"已返回的记录中"。未触顶时不追加任何提示。
- 返回记录中的人员姓名通常已含消歧信息（如"姓名(部门)"），直接使用；记录字段为业务语义值，只取与用户问题相关的字段组织答案，空值字段省略。

### 步骤五：生成回答

**有数据时**：结合用户问题、返回的业务数据和场景的输出要求，组织为自然、可读的答案：

- 用户关心什么就重点展示什么，不关心的简洁带过
- **问题意图驱动的展示策略（禁止长表刷屏）**：异常判断型 → 有异常聚焦列异常明细、正常一笔带过；无异常直接给结论、不铺全部正常记录；整体概览型 → 按人分组概述、合并同类项；具体数值型 → 直接给值不展开整条记录。详见 business-rules.md "问题意图驱动的展示策略"。
- **数字零计算（硬约束）**：输出中每个数字都必须能在返回记录的字段值中逐字找到原文；需要数出来、加起来、求平均、求差才能得到的数字一律不输出；不得使用"共/合计/总计/累计/涉及N人/平均"等汇总性表述。详见 business-rules.md "计算与汇总规则"。
- 合理使用排版结构让信息层次清晰；输出原则与禁止事项详见 business-rules.md "输出核心思路"。
- **提交前自检（内部静默执行）**：按 business-rules.md "提交前自检"清单逐项核验，任一项不满足必须重写答案或重判优先级。

**无数据时**：输出固定文案（"无数据匹配"行），不返回关联菜单。

### 步骤六：展示关联菜单

检查步骤二获取的关联菜单：

- 有关联菜单 → 通过**菜单检索**工具获取每个菜单的名称和链接，在答案末尾追加"你可以在这里查看："，以 Markdown 链接列表输出：

  ```markdown
  - [菜单名称1](菜单链接1)
  - [菜单名称2](菜单链接2)
  ```

  链接文本使用菜单名称，URL 使用菜单链接；**链接必须从菜单检索工具返回中提取，严禁编造 URL**。
- 无关联菜单 → 仅展示答案文本。

## 使用示例

### 示例 1：查询本人假期余额

- 输入：用户问"我还有多少年假"
- 流程：场景发现命中"假期余额"场景 → 场景说明获取输出要求与关联菜单 → 场景字段返回员工、假期类型等筛选字段 → 提取：主体=本人、假期类型=年假（取值按字段说明） → 数据查询 → 回答"你当前年假余额为5天" → 展示关联菜单

### 示例 2：查询下属考勤异常

- 输入：用户问"李白本月是否有考勤异常"
- 流程：命中考勤场景 → 提取：主体=指定人"李白"、时间=本月（起止日期按 schema 格式） → 查询 → 有异常则聚焦列异常明细（"李白本月有考勤异常：8月5日迟到、8月12日早退，其余日期正常"），无异常直接给结论

### 示例 3：未提及日期，时间条件不传

- 输入：用户问"李白的任职信息" / "查询我的团队排班情况"
- 流程：用户原文无任何时间表达 → 时间条件一律不传，禁止自行默认本周/本月/近30天 → 正常查询并回答

### 示例 4：返回量触顶，不下绝对结论

- 输入：用户问"团队七月到八月有考勤异常情况吗"
- 处理：返回记录数达到单次查询上限 → 有异常则逐条列出明细（不计数、不汇总）并追加边界提示；全部正常则表述为"在已返回的记录中暂未发现考勤异常"，追加边界提示，建议缩小时间范围或前往菜单查看完整数据

### 示例 5：无场景强命中，静默降级

- 输入：用户问"考勤异常"，场景发现返回的列表中无可直接回答的场景
- 处理：静默结束本流程，交由菜单唤起或知识问答处理；不输出场景排查过程，不输出自行编造的说明

### 示例 6：按昵称查询他人（禁止身份推断）

- 输入：登录用户为"董纪辛"，用户问"小辛最新评定的职级是啥"
- 处理："小辛"是人名/昵称而非显性第一人称 → 按他人查询、原文透传。**禁止因登录用户姓名而推断"小辛"是用户自称**——系统中可能确有名为"小辛"的员工，一律以原文为准

### 示例 7：组织范围查询但场景不支持，静默退出

- 输入：用户问"麦店长负责的部门的休假情况"
- 处理：场景字段清单中无部门/组织范围类筛选字段 → 静默退出交由菜单唤起或知识问答处理；不调用数据查询，不降级为查麦店长个人数据，不输出任何文案

## 注意事项

- 数据查询意图优先级高于菜单唤起和知识问答；但该排他性仅在**场景强命中后**生效——意图不属于数据查询、或无场景强命中时，均静默降级
- 意图判断、场景匹配、参数提取均为内部过程，不得在回答中输出判断依据、排查过程或中间结论
- 身份判定只依据用户原文的显性表达：显性第一人称→本人、范围词→权限/负责范围、人名/昵称/称谓→他人；禁止用登录用户姓名推断称谓指向当前用户
- 不得跳过场景发现直接编造场景；不得跳过场景字段工具直接构造筛选条件；每次场景命中后必须重新获取本场景字段
- 不得修改工具返回的任何标识值；无数据命中时不输出菜单链接
- 回答中不得暴露任何内部机制（工具名、ID、"后端返回""系统查询"等表述），直接给出结论
- 不得建议员工联系 HR、直线经理或 SSC，你本身就是 HRSSC
- 只基于返回的实际数据回答，不得推测、编造或补充数据中未包含的信息
- **数字零计算（硬约束）**：禁止自行计数、求和、求平均、求差；用户问汇总也以逐条明细回答
- **日期不默认**：用户原文无明确时间表达时，时间条件一律不传；有明确表达时按 business-rules.md 转换为起止日期，**具体取值格式以工具 inputSchema 为准**
- **返回量触顶禁止绝对结论**：须追加边界提示并将结论限定为"已返回的记录中"
- 多个场景同时命中时，先追问确认再查询，不要自行猜测用户意图
- 菜单链接必须按步骤六的 Markdown 链接格式输出，链接必须来自菜单检索工具返回
