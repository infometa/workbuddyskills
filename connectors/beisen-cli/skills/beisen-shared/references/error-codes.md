# 错误码参考与排查流程

> 本文档是 beisen-shared 的子参考。

## 通用错误码

beisen-cli 错误分两类：调用级错误（CLI 自身失败，退出码非 0，stderr 输出文本）与业务级错误（退出码 0，业务信封内 `code != "200"`）。

### 调用级错误（退出码非 0）

| 现象 | 类型 | 处理 |
|------|------|------|
| `HTTP 401` + `error_code: "CLI_AUTH_005"` | 认证失效 | 触发响应式登录：执行 `beisen-cli auth login`，登录后重执行业务命令 |
| `--data` JSON 缺必填字段或格式不符 | 参数 | 查 `beisen-cli schema` 或业务域 references，最多修正 1 次 |
| 网络异常 / 超时 | 网络 | 最多重试 2 次，间隔递增 |

### 业务级错误（信封 code 非成功值）

| 信封字段 | 说明 |
|----------|------|
| `code` | **knowledge 命令**：`"0"` 成功，非 `"0"` 失败；**其他所有命令**：`"200"` 成功，非 `"200"` 失败 |
| `isSuccess` | 审批域专用，`false` 表示失败 |
| `message` | 失败原因，Agent 据此向用户解释 |
| `payload` / `data` | 失败时通常为空 |

> 业务信封层不返回 `missing_scope` 字段。权限不足时内层 `message` 会提示无权限，引导用户联系管理员开通账号访问权限。外层 `ok` 仅表示 CLI 调用成功，不代表业务成功。

## 排查流程

```
1. 命令返回
   ├── 退出码非 0（调用级错误）
   │   ├── HTTP 401 + CLI_AUTH_005 → 认证失效，触发响应式登录（auth login），登录后重执行业务命令
   │   ├── 参数错误 → 查 schema/references，最多修正 1 次
   │   └── 网络错误 → 最多重试 2 次
   ├── 退出码 0 但业务失败（knowledge: code != "0"；其他命令: code != "200"）
   │   ├── 权限不足 → 从 message 提取原因，引导联系管理员
   │   └── 业务逻辑错误 → 解释 message，给建议
   └── exit 10（写方法上线后，预留）→ 进入确认门禁流程
```

## 重试策略

- 网络/超时错误：最多 2 次，间隔递增
- 其他错误：最多 1 次
- 2 次重试仍失败：汇报错误、已尝试步骤和建议下一步
