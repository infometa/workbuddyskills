# 业务问数

**这是一张流程图，不是说明书。** 每个 `da_` 工具**单独**怎么用——参数怎么填、有哪些必须遵守的规矩——工具自己的说明里都写了，⛔ 本文一律不复述：同一件事写两份必然分家，而分家不报错。

本文只回答工具说明回答不了的那件事：**这一串调用整体上长什么样**，以及**答案交出去之前还欠什么**。工具说明是一个一个写的，谁也讲不了整串。

## 一、它是什么

按顾问**已发布的口径**出数：口径、时间基准、排除项都是配好的，你只是挑一条来用。

- ⛔ **不是 text2sql**：你写不了查询，指定不了表和列，⛔ 也不许自己造一个口径。
- ⛔ **口径没有就说没有**，绝不换一列算个近似的顶上——**数算对了、答的却是另一个问题**，这是这件事唯一真正致命的失败方式，而且它不会报错。

## 二、整体流程

1. **先认目录**。`da_list_objects` / `da_list_metrics` 看这个租户有哪些业务对象与已发布指标，再用 `da_describe_object` / `da_describe_metric` 看中意那一条的字段与口径。⚠️ 每个租户配的都不一样，标识只能从目录里**原样复制**，⛔ 不许按英文自己拼——多半不存在、白跑一轮，运气不好是撞上个近义的、算出一个真数字。

2. **人话先解析成标识**。指向某条记录或某个选项的值（人、网点、服务商、机型）先用 `da_resolve` 换成 id 或码值，再拿去当过滤条件。⛔ 数值、日期、布尔、普通字符串不要送来解析，直接写字面量。

3. **出数，⛔ 不许跳档**：
   - ① `da_compute_metric` —— 目录里有对应的已发布指标就**必须**走这一档。
   - ② `da_aggregate` —— 没有现成口径才现场聚合。⚠️ 那是**你自己算的**、没有口径背书，要把用户**原话**带上；响应里那句「没有口径」必须念出来。
   - ③ `da_query_records` / `da_get_record` —— 前两档都表达不了才拉明细。⛔ 它回的行数不是指标：没有时间基准、没有排除项。

4. **实体面是旁路，⛔ 不是第四档**。目录里一个能答的对象都没有时，才用 `da_list_entities` 直接问平台实体。判据**只有**这一个；⛔ 别因为前三档答得不好就转过去——那一面没有口径说明，一行代表什么、每个字段什么含义都没有经过业务确认。

## 三、什么时候必须回头问用户

- **`da_resolve` 给出的结论说这个值没定下来时**（认不出、或者有歧义），⛔ 不许自己挑一条接着往下算。把候选摆给用户，让用户认。⚠️ 该不该问以**响应里的结论**为准，⛔ 别拿「候选有几条」自己定——只回一条候选的也可能是待确认项。
- **要一条记录却回了多条时**，⛔ 别默认取第一条：先看是「标识不够精确」还是「问的粒度不对」。前者该要更精确的标识，后者该换一个对象——⚠️ 这两种处置相反，认错了会原地打转。

## 四、答案里必须讲什么

- **响应顶层 `mustSay` 里的每一句，逐条原样念给用户**，⛔ 不许省、不许改写、不许合并。⚠️ 漏念不会报错：缺披露的答案和完整答案，在用户眼里一模一样。
- **数怎么读，看同一层的 `valueState` / `valueNote` / `display`**，⛔ 别自己另作解释。⚠️ 数值为空有好几种不同的原因，它们各自代表什么由这几个字段说了算。
- **两件响应管不了、只能你说的**：
  - 指标的时间口径是**某一刻的快照**时，要讲成「截至那一刻的当前值」，⛔ 不是某段时间的统计。
  - 凡是**横向排名**（分组再比高低），一律带「未校正」声明交付——4 单全好评的网点会凭小样本占榜首，不声明就是在误导。

## 五、这条流程只有两个出口

**要么交付一个带口径的答案，要么如实说答不出来、并说清是谁要去做什么**（顾问改口径、管理员发布、运维建表、给这个用户加权限）。

⛔ 没有第三个出口：不许拿个近似的顶上，也不许把一次出错讲成「没有数据」——那两件事对用户的后续决定完全不同。

⚠️ 某一次错误该不该重来、要不要先等一等，**响应自己会讲**，照它说的做，⛔ 别在这儿另立一套。⚠️ 被拒绝的调用照样计入额度，⛔ 别原地反复重发。
