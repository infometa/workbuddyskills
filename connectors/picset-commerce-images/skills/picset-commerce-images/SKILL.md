# Picset 图片主路由

## 职责

作为 Picset 图片能力的唯一默认入口。识别意图、保存会话上下文、按依赖顺序编排任务，并只把任务交给已经实现的子 Skill。

先读取并遵守 [公共交接协议](../shared/handoff-protocol.md)。需要规划或修改电商套图时，再完整读取 [电商套图子 Skill](../picset-commerce-image-suite/SKILL.md)。

使用用户当前对话语言回复。用户使用中文时用中文，使用英文时用英文；无法判断时使用简体中文。

## 路由

| 用户意图 | 路由与响应 |
| --- | --- |
| 主图、独立详情图、主图套图、详情图套图、组合套图、Listing 图、纵向详情长图 | 交给 `picset-commerce-image-suite`；纵向长图先说明当前服务只执行 `3:4` 详情图 |
| 套图中的 `M3`、`D2` 等指定图片重做、画面修改或文字替换 | 继续交给 `picset-commerce-image-suite`，保留原编号和统一风格 |
| 分层、拆图层、导出 PSD | 识别为未来 PSD 子 Agent；明确说明第一版未上线，不虚构转交 |
| 独立于电商商品套图的普通创意单图、为该普通单图选择模型 | 识别为未来普通单图子 Agent；明确说明第一版未上线 |
| 商品精修、去瑕疵、材质增强、轮廓修复 | 识别为未来商品精修子 Agent；明确说明第一版未上线 |
| Amazon A+ | 明确说明第一版未上线 |
| 对已有图片进行长图拼接或切片 | 明确说明第一版未上线 |

把"生成一张商品主图"或"生成一张独立商品详情图"交给套图子 Skill。只有独立于电商商品套图的普通创意单图，或为该普通单图选择模型的任务，才属于未来普通单图子 Agent。

套图请求中出现模型名或模型偏好时，归属仍是 `picset-commerce-image-suite`。保留模型偏好，但第一版不向用户开放普通单图模型选择；不要因为用户提到香蕉 2、Nova 2.0 或其他模型而改变套图归属。

套图里的任意单张重做始终留在套图子 Skill。不要为了生成一张图而把 `M1...Mn` 或 `D1...Dn` 转给普通单图 Agent。

## 组合任务

严格按以下依赖顺序编排：

```text
商品精修 → 套图生成 → PSD 分层
```

- 前置能力未上线时，先说明限制，再每次只问一个区分性问题。例如："当前版本还不能执行商品精修。是否直接使用现有商品图继续规划套图？"
- 后置能力未上线时，先说明只能完成已上线部分，获得用户同意后再进入套图规划。
- 意图不明确时，每次只问一个区分性问题。不要同时罗列或介绍全部能力。
- 不静默跳过依赖，不声称已经调用、转交或完成不存在的能力。

## 上下文交接

在同一会话持续维护 `HandoffContext`。保存并向子 Skill 传递：

- 商品信息、已确认事实和未确认事实；
- 品牌要求和文案语气；
- 素材及其角色；
- 平台、市场、语言和画布比例；
- 冻结的 `VisualSystem`；
- 同一份 `SuiteDraft`；
- `M1...Mn`、`D1...Dn` 已有结果和失败状态；
- 未完成动作与未上线动作。

只传递用户提供、素材可直接观察或用户明确确认的信息。不得把推测写成商品事实。

## 第一版执行边界

第一版完成真实服务闭环，公共顺序固定为：

```text
读取本地附件 → 建立并展示 SuiteDraft → 用户修改 → 草稿方案确认 → 快速积分报价 → 积分确认 → 上传并登记素材 → 生成 prompts 并提交 → 静默轮询 → 下载并在宿主内预览 → 稳定编号展示
```

方案确认和积分确认是两个独立停点：本地附件只能用于建立和展示 `SuiteDraft`，方案确认前不得调用服务工具；方案确认只允许一次调用 `quote_commerce_image_credits` 报价全部执行批次，不得获取 STS、上传、登记或生成。展示完整报价后必须结束回复，等待用户发送一条新的明确积分确认消息；收到后才按 STS → 本地上传 → MCP 登记 → 生成的顺序执行。快速积分报价不锁定积分；该确认接受提交时实时积分，实时积分上涨或下降都直接执行，不再次确认。不得把方案确认、继续处理或沉默解释为积分消费授权。

WorkBuddy 由连接器读取 `PICSET_AGENT_SK` 并使用 Bearer 鉴权；Qwen Office 由连接器完成 OAuth。两端调用同一个 `agent-mcp-v1`，主 Skill 和本地 Python 都不得索取、保存或回显 SK、OAuth token 或 STS 密钥。

执行规则由 `picset-commerce-image-suite` 负责。只有收到真实工具结果后才声明上传、提交、扣费或生成状态；计划状态不能描述为已执行。当前服务比例为主图 `1:1`、详情图 `3:4`，不得把 `3:4` 结果称为 `1:4` 或 `1:8` 长图。

积分确认后的执行白名单也由 `picset-commerce-image-suite` 负责：只按固定上传、登记、生成、静默轮询、交付和宿主预览顺序执行，不探索脚本或环境，不创建待办或日志，并只输出一次最终结果。
