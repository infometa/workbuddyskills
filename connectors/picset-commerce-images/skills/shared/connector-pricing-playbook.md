# Picset 连接器充值面板共享手册

本手册定义 Picset MCP 连接器统一充值面板的标准操作。主 Skill、电商套图 Skill、单图文生图/图生图 Skill 与 Agent Canvas Skill 共用，不在各处重复实现。

**充值面板定位**：充值面板是对整个 MCP 连接器统一计费的独立支付入口，服务于电商套图、单图文生图/图生图、画布操作等所有消耗积分的功能。它与万能画布（Agent Canvas）在业务上没有依赖关系——充值面板不需要画布会话即可独立打开，画布也不依赖充值面板才能工作。两者仅在技术层面共享 skybridge 面板渲染框架。

调用 MCP 工具前，必须使用 `tool_search` 按工具名获取完整参数定义，再按取回的定义发起调用。禁止凭工具名猜测参数结构。

---

## 一、调用时机

以下场景调用充值面板：

1. **生成前余额不足**：费用授权完成后、上传登记或提交生成之前，`get_user_credits` 显示 `available_credits` 低于最新预估积分时，自动打开充值面板。
2. **提交/执行返回积分不足**：生成提交或任务执行返回 `INSUFFICIENT_CREDITS` 时，自动打开充值面板。
3. **用户主动要求充值**：用户明确说"充值""买积分""打开充值页面""看套餐"等时，打开充值面板。

---

## 二、工具：get_user_credits

### 用途

查询当前鉴权用户的可用积分余额。只读，不扣费、不锁定积分。

### 入参

无。空对象 `{}` 即可。

### 返回

```json
{
  "available_credits": 130,
  "subscription_credits": 100,
  "purchased_credits": 30
}
```

- `available_credits`：可用于支付生成费用的总余额（订阅 + 购买）。
- `subscription_credits` / `purchased_credits`：明细；比较是否足够时只用 `available_credits`。
- 查询失败时返回错误（如 `CREDIT_LOOKUP_FAILED`），不得把缺失当成余额为 0 或余额充足。

### 生成前余额校验（硬门禁）

费用授权完成后，**在任何上传登记或提交生成之前**必须执行：

1. 确认手头有本次有效的最新预估积分（电商用 `quote_commerce_image_credits` 的总计；单图/复刻用 `quote_image_credits` 的 `estimated_credits`）。局部返工若无本次报价，先做对应只读报价再校验；不编造预估。
2. 调用 `get_user_credits`，读取 `available_credits`。
3. **余额足够**（`available_credits >= 最新预估积分`）：继续上传登记与生成提交流程。
4. **余额不足**：立即停止，不上传、不登记、不提交生成、不轮询；调用 `open_agent_pricing`（传入 `conversation_id` 与 `scene`）；简要说明当前余额、预估所需积分、已打开充值面板，充值后可重试。
5. **余额查询失败**：停止后续上传/生成，如实报告查询失败，不打开充值面板，不把失败当成余额充足而继续。

该门禁适用于电商套图、单图文生图/图生图、风格复刻；自动确认偏好也不能跳过。提交后仍可能因实时计价或并发扣费返回 `INSUFFICIENT_CREDITS`，按第三节处理。

## 三、工具：open_agent_pricing

### 用途

在 MCP host 内打开 Picset 连接器统一充值套餐面板。

### 入参

```json
{
  "conversation_id": "<可选，当前对话 ID，便于宿主关联面板>",
  "scene": "<可选，充值场景标记>"
}
```

- `conversation_id`：可选，字符串。当前对话 ID，便于宿主关联面板。调用前按 [Agent Canvas 共享手册](./agent-canvas-playbook.md)「宿主 conversation_id 解析」尽量注入（`host-conversation-id` / `CODEBUDDY_CONVERSATION_REQUEST_ID`）；解析失败仍可打开面板，但可能无法绑定到正确对话。
- `scene`：可选，字符串。充值场景标记，用于区分不同入口的充值需求（如电商套图生成、单图生成等）。

### 行为

- 调用后由宿主在面板内渲染充值套餐页面，用户可在面板内完成查看套餐和支付。
- 支付完成后，积分自动到账，用户可返回对话继续之前的生成任务。

---

## 四、积分不足处理流程

当生成前校验不足，或生成提交/任务执行返回积分不足时：

1. **立即停止**：停止后续上传、生成提交和轮询，不重试、不新建任务。
2. **打开充值面板**：调用 `open_agent_pricing`，传入按手册解析的 `conversation_id`（如可用）和 `scene`（如适用）。
3. **告知用户**：简要说明积分不足、已打开充值面板、充值后可重试；生成前校验场景可附带当前余额与预估所需积分。
4. **保留状态**：生成前拦截时尚未创建任务；提交后不足则保留已生成的 `task_id`（套图）或 `request_id` + `job_id`（单图），用户充值后可凭原标识恢复或重试。

## 五、禁止事项

- **不得向用户展示充值 URL**：充值面板由宿主内渲染，不输出任何链接。
- **不得展示 ticket 或 functionsUrl**：这些是内部鉴权和端点信息，不暴露给用户。
- **不得编造套餐价目**：套餐内容由充值面板展示，skill 不硬编码价格。
- **不得在积分不足时继续上传、生成或轮询**：必须先停止，等用户充值后再继续。
- **不得跳过生成前余额校验**：费用授权后、上传/生成前必须调用 `get_user_credits` 并与最新预估比较。
- **不得将充值面板与画布混为一谈**：充值面板是连接器统一支付入口，不是画布的子功能；描述时使用"连接器充值面板"或"积分充值面板"，不使用"画布充值"。
- **不得在积分不足时仅以文字提示用户自行打开面板**：必须实际调用 `open_agent_pricing` 调起充值面板（传入 `conversation_id` 与 `scene`），再说明需充值后重试；禁止用"要我打开吗？"等询问代替实际调用。

## 六、工具速查

| 工具 | 用途 | 调用阶段 |
| --- | --- | --- |
| `get_user_credits` | 查询当前用户可用积分余额 | 生成前余额校验 |
| `open_agent_pricing` | 打开连接器统一充值套餐面板 | 积分不足 / 用户主动充值 |

> 注：`open_agent_pricing` 工具名中不含 "canvas"，因为充值面板与万能画布在业务上相互独立。服务端历史版本中曾使用 `open_agent_canvas_pricing`，已更名为 `open_agent_pricing`。
