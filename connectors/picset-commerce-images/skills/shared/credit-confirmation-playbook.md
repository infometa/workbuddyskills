# Picset 共享积分确认规则

电商、独立单图和风格复刻共用同一份用户授权。跳过的是重复询问，不是报价、费用展示或方案确认。此手册只管理确认规则，不改变各能力的报价工具和生成链路。

## 唯一偏好文件

沿用现有电商子 Skill 的 `user_preferences.json`，不移动、不复制、不按能力创建新文件：

- 从电商子 Skill 目录解析：`__SKILL_DIR__/user_preferences.json`。
- 从单图或复刻子 Skill 目录解析：`__SKILL_DIR__/../picset-commerce-image-suite/user_preferences.json`。
- 从本手册目录解析：`../picset-commerce-image-suite/user_preferences.json`。
- 主入口（包括宿主安装后位于包根的入口）先读取本手册，再以本手册的实际目录定位该文件，不从当前工作目录猜路径。

`__SKILL_DIR__` 表示当前业务子 Skill 的目录，不是主入口或本手册目录。以上路径必须解析到同一个文件；不得另建单图或复刻偏好。

## 确认决策

先让用户确认本次方案或生成意图，再按相应能力查询并展示最新报价。报价后、提交前读取共享偏好：

| 实际状态 | 下一步 |
| --- | --- |
| 用户曾明确授权，文件中 `confirm_credits` 为 JSON 布尔值 `false` | 展示最新报价后自动确认，无需等待重复回复 |
| 无偏好、文件不存在、解析失败、非对象、字段缺失或值不是布尔值 `false` | 等待用户针对本次最新报价明确确认；字符串 `"false"` 不代表授权 |
| 用户已明确确认本次最新报价，但未授权以后自动确认 | 仅提交本次请求，不写入自动确认偏好 |
| 用户要求恢复逐次确认 | 先恢复共享偏好，再按逐次确认处理后续所有能力 |

- 对电商和复刻工具：满足本次明确确认或有效自动确认授权时，才传 `confirmed: true`。
- 单图 `generate_agent_canvas_image` 没有 `confirmed` 参数：同样先完成授权判断，但不得传入该字段。
- 未获得授权不能将“用户想生成”推断成“用户接受尚未展示的费用”。不得预先写入 `false`。
- 自动确认仅覆盖图片生成费用，不授权其他购买、删除、权限变更等操作。
- 费用授权完成后、上传或提交生成前，必须按 [连接器充值手册](./connector-pricing-playbook.md) 调用 `get_user_credits`，用 `available_credits` 与最新预估积分比较；余额不足时打开充值面板并停止，不进入生成流程。
- 积分不足、余额查询失败、报价错误或报价规格不明确时，不自动提交。

## 展示与失效

- 展示数量、实际模型/分辨率/比例/速度和工具返回的预估积分；不硬编码单价。
- 说明最终按提交时实时积分扣除，可能与预估不同；自动确认模式也不隐藏此说明。
- 用户修改本次方案或生成规格后重新确认方案并重新报价；旧的单次费用确认失效，有效的跨能力自动确认偏好仍可使用。
- 提交结果不明时保存原任务状态；同一次幂等重放不当作新的扣费记录，不能累计重复费用。

## 设置与恢复

- 首次报价无偏好时，可询问：“以后电商、单图和复刻都自动确认积分吗？回复‘不用确认’可启用，随时可恢复。”不要求用户额外填写设置表。
- 用户明确说“不用确认”“以后不用问了”时，写入 `{"confirm_credits": false}`。此授权适用于三项能力，包括此前在电商流程中设置的同一偏好；本次仍须先展示报价。
- 用户只确认本次费用时，不创建自动确认偏好。
- 用户说“恢复积分确认”“以后都要确认”时，将唯一文件的 `confirm_credits` 改为 `true`（保留其他字段），或删除仅含该偏好的文件。告知三项能力已统一恢复。
- 若文件还有其他字段，设置自动确认时也保留其他字段；未知/损坏文件不得当成有效授权。
- 写入失败时如实说明偏好未保存，不宣称后续已自动确认；恢复写入失败时本轮及可恢复上下文中强制逐次确认，阻止旧 `false` 继续授权，并提示修复持久化后再跨会话使用。
- 偏好仅在本地保存，不上传；用户明确设置或恢复即授权相应本地写入，不额外要求第二次确认。
