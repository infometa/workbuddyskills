# MuseGate MCP 执行参考

仅在用户要实际生成或查询时使用。工具以宿主实时发现结果及 inputSchema 为准；未发现某项工具时，说明当前连接不支持，不伪造调用。不要自行请求后台私有接口或绕过 OAuth。

## 1. 授权、身份与费用

实际创作前调用 `musegate_account`，参数为空对象，确认当前账号；纯提示词与方案无需调用。身份由 OAuth 绑定决定，不能从聊天文字指定用户身份。授权过期时由宿主尝试刷新，失败则引导重新绑定；权限不足时说明限制，不切换身份绕过。

提交会按 MuseGate 当前规则消费 Muse 点，执行前简要告知并确认已有明确生成意图。充值使用账号工具实际返回的入口，在 MuseGate 完成；未返回入口时引导用户进入 MuseGate 平台，不拼造支付地址。不要索取支付信息，不自行报价或承诺免费。查询现有任务不应触发新的创作提交。

## 2. 准备参考图

本地素材需通过宿主文件能力读取 PNG/JPEG 文件，编码为**纯 base64**后调用 `musegate_upload_image`，唯一参数为 `base64`。不要传文件路径、data URL 前缀或浏览器 Blob 地址，也不要在聊天正文输出整段 base64。

当前上传限制：解码后单图不超过 1,048,576 字节，任意一边不超过 8192 像素，总像素不超过 16,777,216。超限时先告知需要压缩或调整尺寸，获得同意后处理副本，保留原文件；宿主不能读取或处理时，让用户提供符合限制的素材，不能假称上传成功。

使用上传工具实际返回的 HTTPS URL，并确保素材来自当前连接所对应的环境。任意公网 HTTPS 图片也不一定满足后端素材白名单。现有素材只有在确认满足当前服务要求时才可复用；不要把示例网址、其他环境地址或用户本地路径直接提交。

## 3. 图片创作

| 字段 | 规则 |
| --- | --- |
| requestId | 新任务生成新 UUID；允许8—80位英文字母、数字、下划线和连字符 |
| prompt | 非空，最多8000字符 |
| clarity | `1K`、`2K`、`4K` |
| imageRatio | `1:1`、`2:3`、`3:2`、`3:4`、`4:3`、`9:16`、`16:9` |
| batchCnt | 整数1—4，按用户意图选择 |
| images | 自由设计为0—8个 URL 字符串；自由换衣为1—8个 url/type 对象 |

以上字段均必填，不能附加未在 schema 定义的字段。自由换衣每个对象只含 `url` 与 `type`，type 为 `clothImage`、`modelImage`、`referenceImage` 或 `detailImage`。服装与模特的角色按用户意图设置；自由设计与视频的 images 则都是字符串数组，不能混用结构。

下面是可核对结构的**纯文字生图示例**，对应 `musegate_free_design`。示例 UUID 只用于文档；真实新任务需要重新生成，重试除外。

```json
{
  "requestId": "26fa95b3-e343-4885-87ce-0f6fa5130851",
  "prompt": "淘宝服装商品主图，一件黑色棉质圆领短袖T恤，正面平铺，完整展示领口、袖口和衣摆；浅灰纯净背景，左前方柔光，保留细织纹与自然褶皱，轮廓清晰，无文字、无Logo、无水印。",
  "images": [],
  "clarity": "1K",
  "imageRatio": "1:1",
  "batchCnt": 1
}
```

有参考图时，先上传素材，再用真实返回地址替换空数组；换衣需按上述对象结构组织。不要为凑示例编造素材 URL。

## 4. 视频创作

先调用 `musegate_video_models`，参数为空对象。核对模型产品代码、`modes`、`minImages`/`maxImages`、`resolutions`、`ratios`、`durationSeconds`。文生视频要求支持 `text_to_video`；图生要求 `image_to_video`。当前已知可灵支持两种模式，Seedance/MiniMax 为图生；实时目录可以变化，不能把这段说明当作永久配置。

`musegate_free_video` 必填 `requestId`、`prompt`、`images`、`model`、`resolution`、`ratio`、`durationSeconds`。images 是0—8个 URL 字符串，实际上下限遵从模型目录；时长为整数秒。分辨率区分大小写，例如 `720p` 与 `768P` 不可随意改写。模型代码使用目录的 model，不用展示名称。

以下**文生视频示例**只有在实时目录仍支持该组合、且用户要求实际生成时才可提交。它是概念商品视频；真实商品一致性需求优先用用户参考图。示例 UUID 需替换为本次新生成的值。

```json
{
  "requestId": "d7339d5b-07fd-4ef1-ab13-e398be0c2784",
  "prompt": "5秒竖屏服装概念展示视频：一件黑色圆领短袖T恤，模特自然站立后轻微转身，镜头缓慢推进展示领口和棉质织纹，浅灰背景与柔和侧光，单一连贯镜头，不加文字、配乐或转场，不出现服装突然变款。",
  "images": [],
  "model": "kling-v3",
  "resolution": "720p",
  "ratio": "9:16",
  "durationSeconds": 5
}
```

视频比例字段是 `ratio`，不是图片的 `imageRatio`。不要传图片的 batchCnt/clarity，也不要传内部渠道、供应商、计费、首尾帧、视频或音频参考等未开放字段。提示词可以描述镜头和节奏，不能据此虚构独立剪辑工具。

目录只提供规格时，不能根据 Mini/Fast 名称断言谁最便宜。用户要求低成本时，先按支持范围缩短时长、降低分辨率，不额外增加任务；无法比较实际费用时明确说明价格需在平台确认。用户有明确预算且无可核实价格时，先交付方案，待确认费用后再提交。

## 5. 提交、等待和结果

每次新创作记录真实工具名称、requestId、完整参数和返回的 batchId，保留在当前任务上下文。工具可能在 `content` 的文本块中返回 JSON，应先识别协议错误、`isError` 和业务状态；HTTP成功或出现一段文本并不等于任务完成。

图片用 `musegate_get_job`，视频用 `musegate_get_video_job`，唯一参数 `batchId` 为提交实际返回的正整数。只能查询当前授权操作者自己的任务；对话中没有编号时先问用户，不猜测或枚举编号。

宿主支持等待时，图片可依次间隔约3、5、10秒，视频约10、20、30秒；每轮最多查3次，或使用宿主支持的有界等待。宿主无法等待时先报告任务编号和已知状态，待后续继续查询，不进行密集循环。排队、处理中或状态不明时，不能说已生成。

图片需完成状态且 `resultImages` 非空；视频需 `FINISHED` 且 `resultVideos` 非空才可交付最终结果。展示真实图片或视频 URL；宿主支持时渲染预览，否则给可点击链接。空结果、失败或超时如实说明，并保留原任务编号。

## 6. 重试与异常

| 情况 | 处理 |
| --- | --- |
| 网络响应中断，不确定提交是否成功 | 幂等窗口24小时内只沿用原 requestId 与完全相同参数；有 batchId 优先查询 |
| submission_state_unknown | 停止自动创建；有 batchId 只查原任务，否则引导用户核对 MuseGate 历史记录；不换编号重建 |
| request_conflict | 同一 requestId 参数冲突，核对原请求，不自动换编号绕过 |
| 参数或模型规格不支持 | 查实时 schema/目录并解释；调整会影响用户方案时先确认，不盲目重试 |
| 401、授权失效 | 由宿主刷新，失败后重新绑定；不索取 Token |
| 无权限、无可用模型 | 告知当前账号限制，不伪装成系统已生成 |
| 余额不足 | 使用真实充值入口，充值后由用户决定后续创作 |
| 内部错误、任务失败 | 提供可操作说明和真实编号，不传播内部堆栈；不保证自动退款或自动补跑 |

超过24小时且原任务状态仍不明时，也不能直接换 requestId 重建；先核实记录与用户意图。用户明确要求“再生成一张”是新一轮付费创作，使用新 requestId；普通查询与网络重试不是新任务。
