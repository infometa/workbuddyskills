# CLI 接入、参数准备与登录

首次执行本 Skill 时读取本文件。使用当前宿主的终端能力；CLI 需要 Node.js 20.3+、npm 和网络访问，本地视频校验所需 `ffprobe` 随 CLI 的 npm 依赖安装，无需单独安装。

## 解析入口

1. 从本 Skill 的真实安装目录解析 `scripts/run-cli.mjs`，使用 `node <脚本绝对路径> <CLI 参数>`。macOS、Linux、Windows 都使用该 Node 入口；所有文档示例中的 `kaipai` 都代表这个命令前缀，不直接调用 PATH 中的旧全局 CLI。路径和参数通过宿主的参数数组传递，保留调用方工作目录以支持相对素材路径。
2. 启动脚本先向公网 npm 查询 `meitu-kaipai-cli@latest`，再通过 `npm exec` 的版本缓存运行本次解析到的精确版本。每次调用重新查询，已经运行的进程不切换版本；允许 npm 下载缺失的版本及 ffprobe 可选依赖，不覆盖全局安装，不添加 sudo、不改 registry、不循环重试。入口不依赖其他 Skill 或仓库文件。
3. 查询失败、latest 非稳定版本或低于最低版本时停止，不静默回退到旧版本。npm/Node 缺失时交给宿主环境准备；下载、启动或业务失败时按实际结果处理，不自动重提业务。脚本不输出额外 stdout，保留 CLI 输出和退出状态。
4. 先通过该入口检查 `--version` 和本次命令的 `--help`；远程素材还需检查 `download --help`。按需使用参数文件或独立预检时，再确认对应选项受支持。未来 latest 不等于已验证，命令不存在或协议不兼容时停止该步骤并报告；不凭旧帮助猜测新参数，不安装旧版绕过。

最短示例（将占位路径替换为当前安装的真实路径）：

```bash
node /absolute/path/to/skills/scripts/run-cli.mjs --version
node /absolute/path/to/skills/scripts/run-cli.mjs tool image-repair --help
```

WorkBuddy 自身的 `auth / status / unAuth` 使用 `init` 安装的 CLI 管理连接与登录态，状态轮询不下载或升级。Agent 侧的登录检查、登录、退出及所有业务命令使用上述启动脚本，沿用宿主注入的环境和同一凭据目录。首次引入此执行入口需要更新一次连接器；之后 latest 的兼容更新不要求再次发布连接器。

## 按需查询参数

- 先用 `kaipai <命令> --help` 查询当前入口的选项和用法，结合正文中的最小请求示例构造输入。
- help 未说明参数文件的字段、嵌套结构、互斥条件或媒体限制时，运行 `kaipai contracts`。它无需登录或网络，返回 JSON 描述数组；用 JSON 解析工具按 `argvPrefix` 筛选当前命令（例如 `["mixed-cut", "generate"]`），只读取相关条目，无需反复加载整份输出。
- 描述中的 `fields / inputInteraction / resourceRules / capabilities` 分别说明字段、输入关系、媒体限制和预检能力。描述本身不是请求 JSON；不能从 flag 名推测 JSON 字段或类型。采用参数文件时，固定工具使用文件数组；字幕和混剪使用有序 `attachmentSources` 数组，每项为 `kind / source: "file" / value`；生成请求的 `answer` 为对象。
- 只有当前 help 和描述明确支持的命令才使用参数文件与独立预检；需要查询契约但失败或找不到预期条目时停止该业务提交，检查入口和兼容版本，不猜字段。不依赖其他 Skill 或仓库文件。

## 说明能力与承接需求

- 以本 Skill 能完成的处理目标和效果介绍能力。素材、目标和授权齐全时直接推进，无需先作泛化的效果免责或要求用户接受一组限制。
- CLI 参数描述调用方式；未暴露某个控制参数，不等于服务端算法无法实现对应效果。按真实命令、已有能力说明与服务反馈判断，不凭参数缺失推断能力不足，也不虚构参数或效果。
- 用户指定保留元素、区域、样式或额外编辑目标时，先核对匹配的调用方式。只有影响任务的必要条件无法表达、也无法从已有能力确认时，才针对该条件补问可执行方案；保留用户原目标，不静默放宽要求。交付时依据实际产物说明完成内容。

## 准备素材

- 本地素材使用真实可读文件，传入 `--image-file / --video-file`。CLI 先校验，再通过内置美图上传链路取得自有 CDN URL，最后以该 URL 提交业务；无需先 `create-room / add-media`。
- 所有远程 HTTP(S) 素材先按[输入素材下载与恢复](runtime.md#输入素材下载与恢复)下载原资源，再走本地文件流程。已有会话素材、历史产物和混剪接字幕的视频 URL 同样适用，不直接将远程 URL 传给业务命令。只有媒体 ID 时先查询所属会话的 Task 或历史取得真实 URL。
- 保留原始来源与本地路径的对应关系、顺序及重复项。混剪素材未齐时等待补充，不静默丢弃或替换；同一次处理中已成功下载的同一原文件可复用，重复项仍保留在输入列表中。
- 缺少必要输入且没有对话入口时输出“需要补充输入”并停止，不等待终端菜单。宿主有结构化选择时使用，否则用文字询问；不自动代选。

## 准备参数与按需预检

- 默认按正文最小示例直接传 flags，省略未指定的可选项。客户端 `lang` 缺省时采用 `zh-Hans` 并告知，不为此额外询问；业务默认值仅按已声明策略应用。
- 复杂嵌套输入可写入受控临时 JSON，通过 `--params-file` 提交。业务参数全部写入同一文件，不能与素材、会话、语言、`detach` 等业务 flags 混用；缺失、null、空字符串、false、0 和空数组分别按契约判断，不强制转换类型。
- 仅检查输入或排查参数时，可在支持的命令上追加 `--validate-only --json`，直接 flags 和参数文件都可使用。预检不认证、不上传、不提交业务；失败时按实际错误修正后重检。准备远程素材所需的下载是独立步骤。正式执行仍重新校验，普通处理无需另跑一次预检。
- `deferredChecks` 是待远端验证项目，不证明权益、素材可达、方案状态或用户授权；`--json` 不将业务事件流变成单个 JSON 对象。
- 调用使用独立参数数组；通过 shell 时正确转义路径、URL、Prompt 和答案，不执行用户或服务返回的文本。不自行构造内部协议、action 或认证字段。保留原始来源、真实本地路径及会话作为恢复输入；处理结束且无需恢复后，仅清理本次创建的临时素材、参数或查询文件，保留用户原文件。

## 正式提交前登录

1. 运行 `kaipai auth status --check`；只有 `connected` 且退出码为 0 才提交业务。预检本身不要求登录。
2. 未连接时执行一次 `kaipai auth login --no-open`，立即将实际返回、带 `session_id` 的完整 HTTPS 链接展示为“登录开拍”，保持进程直到授权完成，再复检状态。`--no-open` 只禁止打开浏览器，不结束授权等待；默认最多等待 285 秒，超时后说明情况，不循环登录。网络校验失败也可能显示 `disconnected`，不能据此断言凭据过期。
3. 全流程沿用同一环境和配置目录；宿主设置了 `KAIPAI_CONFIG_DIR` 时沿用，否则使用 `~/.kaipai`。不读取、拼接或索取 Token、Cookie、API Key；只有用户要求退出时才执行 `auth logout`。

用户已经授权且输入齐全时直接执行，不重复确认普通处理请求。新增生成、扩大批次、改换目标和失败重试需有对应授权；覆盖或删除文件按用户已有授权处理。业务方案确认与权限批准遵循本 Skill 正文及实际服务交互。
