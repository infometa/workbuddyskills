# 快递100 通用问答资料

> ### 调用前置（强制执行）
> 1. **先加载，后回答**：回答下列任一领域的问题前，必须先读本文件与对应资料小节，**不得凭印象作答**。
> 2. **不确定就说不知道**：资料未覆盖的内容（含枚举、价格、政策）一律说明「需核实」，禁止用经验值填充。
> 3. **与 `expmgr-saas` 的分工**：本技能答**业务常识与界面操作**；问**业务数据**（多少件、多少钱）走那个技能。
> 4. **有图有视频就一起给**：资料中带图片或视频的内容，按原顺序随文字输出原始链接，见硬约束 6。

## 何时使用

提供四类问题的标准应答：

1. **寄件违禁品 / 限寄品判定** —— 用户给出具体物品，判断能否寄递。
2. **保价费率查询** —— 用户询问保价费用、费率、赔付口径。已收录 13 个品牌，一律由 `scripts/quote_insurance.py` 计算，不手算、不套用其他品牌费率。
3. **快递日常信息咨询** —— 时效、网点、运费、单号、签收、理赔、包装等常识类问题。
4. **产品操作答疑** —— 百递云·企业快递管理的地址簿、下单、审批、到件、云打印机、账户权限等「在哪里配置、为什么报错、怎么处理」。

**不在本技能范围：** 实时运价与时效数据、下单/改单/退单、理赔进度跟单、企业客户合同价。这类需求只给查询路径与判断口径，不代替系统查询。

## 一、硬约束（全部集中于此，其他章节不再重复）

| # | 约束 | 说明 |
|---|---|---|
| 1 | **不编造** | 时效、价格、政策条款，资料中没有权威值时直接说明「需核实」并给核实路径；保价费只以脚本输出为准 |
| 2 | **兜底语必带** | 结论为「可寄」且不属于明确列名允许的物品，必须附「最终是否可收寄，以取件员上门核实物品实际情况为准」 |
| 3 | **高危不给模糊空间** | 枪支弹药、爆炸物、毒品、放射性、腐蚀性剧毒、管制器具一律明确「禁止寄递」；禁止「应该可以」「少量没事」这类表述 |
| 4 | **未收录不猜测** | 资料未覆盖的物品，明确说「未在规则清单中列明」，按默认允许 + 兜底语处理，**不得臆造归类** |
| 5 | **输出** | 结论先行（能 / 不能 / 需核实）；只引规则要点，不整段粘贴原文；用户一次问多个物品时逐个判定并汇总成表 |
| 6 | **图文视频随文输出** | 答案涉及资料中的图片或视频时，**按资料内的原始顺序**在对应位置一并输出：图片用 Markdown 图片语法、视频直接给原始链接。**不得省略、改写、截断链接，也不得下载素材后重新组装**；资料里有的图/视频，对应段落必须带出来 |

## 二、违禁品判定流程

### 第 1 步：归类

把用户物品映射到 19 个类别中的一类或多类（清单见 `@//references/prohibited-items.md` 目录）。一个物品可能同时落入多类，例如「带酒精的香水」同时涉及易燃液体、液体类包装要求。

### 第 2 步：按四级命中顺序裁决

| 命中情况 | 结论 | 处理 |
|---|---|---|
| 命中该类**禁寄清单** | ⛔ 禁止寄递 | 引用类别与规则要点，说明原因。不提供规避建议 |
| 命中该类**允许清单** | ✅ 可以寄递 | 说明属于该类的哪种允许情形 |
| 未命中任何清单（默认） | ✅ 可以寄递 | **必须**带兜底语 |
| 规则本身标注「需核实」 | ⚠️ 需核实 | 说明核实方式，不代为拍板 |

### 第 3 步：冲突处理

字面命中禁寄词但实际是民用物品时（如「玩具枪」「菜刀」「道具刀剑」），按以下优先级裁决：

1. **具体列名优先于类目字面。** 物品在允许清单中被点名列出，即按允许处理。
2. **用途优先于字面。** 以日常用途、使用场景判定，而非名称中是否含敏感字。
3. **仍不能确定 → 给「需核实」**，并说明核实要点（尺寸、材质、是否含动力装置、是否含危险成分）。

### 第 4 步：叠加特殊限制

判定为可寄后，逐项检查是否触发下列附加约束：

| 物品 | 附加约束 |
|---|---|
| 酒类 | 酒精体积分数 **≤ 56 度** 方可寄递；推荐陆运渠道。未标注度数的散装酒、桶装酒按「需核实」处理 |
| 香烟 / 烟类 | 可寄，**单人单次不超过 2 条** |
| 含电池类（手机、充电宝等） | 部分快递公司列为限寄，需按实际承运方规则确认 |
| 活体动物 | 一律禁止（家禽类食品、羽毛除外） |
| 液体、易碎品 | 需符合包装要求，可能影响可寄性 |

### 第 5 步：按统一格式输出

```markdown
**结论：** ✅ 可以寄递 / ⛔ 禁止寄递 / ⚠️ 需核实
**归类：** <所属类别>
**依据：** <引用规则要点，一句话>
**注意：** <叠加限制，或兜底语>
```

示例：

```markdown
**结论：** ✅ 可以寄递
**归类：** 管制器具 —— 办公用品类小刀
**依据：** 美工刀、剪刀、指甲刀等办公用品类小刀属于允许寄递范围。
**注意：** 需妥善包装避免刀刃外露划伤包裹；最终是否可收寄，以取件员上门核实物品实际情况为准。
```

## 三、保价费率查询流程

已收录 **13 个品牌**：顺丰、京东、EMS、申通、圆通、极兔、菜鸟速递、德邦、德邦零担、京东重货、顺丰卡航、壹米滴答、中通快运。

### 第 1 步：补齐要素

1. **品牌** —— 快递100 平台可选多家，必须问清，**不可默认顺丰**。
2. **声明价值**
3. **重量** —— 仅京东重货、顺丰卡航需要，用于判定最低保费档位。
4. **是否易碎易损** —— 仅德邦需要，会触发 0.008 专用费率。

### 第 2 步：先判上限

部分品牌设单票保价上限（申通 10000 元、EMS 与圆通与极兔 30000 元、德邦 1000000 元）。声明价值超限时直接告知不可保价，不进入计算。

### 第 3 步：调脚本计算，不要手算

```bash
python scripts/quote_insurance.py --brand <品牌> --value <声明价值> [--weight <kg>] [--fragile] [--json]
python scripts/quote_insurance.py --list      # 列出已收录品牌
```

脚本已内置分段、最低保费、上限判定与取整规则，输出含适用档位与计算过程。**不要自行心算费率**，分段边界与最低保费容易出错。

返回值处理：

- `brand_not_found` → 该品牌未收录，按 `@//references/insurance-rates.md` 第六节模板处理，**禁止用相近品牌费率替代**。
- `over_cap` → 超单票上限，按超限话术回复。

### 第 4 步：按格式输出

```markdown
**品牌：** 顺丰
**声明价值：** 5000 元
**适用档位：** 1000 元以上，费率 0.5%
**保价费：** 25 元（5000 × 0.005）
**提示：** 实际以系统实收为准；保价金额是赔偿上限，并非保多少赔多少。
```

费率分段表、易错点与取整约定见 `@//references/insurance-rates.md`。

## 四、产品操作问题应答流程

### 第 1 步：先判属于哪个端

同一功能在不同端菜单名不同，**端判错则路径必错**：

| 端 | 侧边栏模块名 |
|---|---|
| 管理端 | 系统设置 / 增值服务 |
| 员工端 | 基础设置 |
| 前台（收发室）端 | 系统设置 |

用户只说「系统设置里找不到打印机」时，先确认是管理端还是前台端，再给路径。

### 第 2 步：按主题路由

| 问题域 | 参考文件 |
|---|---|
| 地址簿、下单看不到快递公司、钱包余额预警、系统管理员 | `@//references/product-ops-setup.md` |
| 寄件审批：飞书配置、钉钉配置、打开审批开关报错 | `@//references/product-ops-approval.md` |
| 到件异常、高拍仪出库、顺丰国际 ICRM | `@//references/product-ops-receipt-intl.md` |
| 云打印机添加、扫码打印、设备码、离线、卡纸、校正、重置、浓度、驱动下载 | `@//references/printer-ops-faq.md` |

### 第 3 步：按「定位 → 步骤 → 陷阱」输出

```markdown
**入口：** 员工端 → 基础设置 → 打印机设置 → 添加云打印机
**前置：** 打印机已连 WiFi 且在线
**步骤：** 1. … 2. … 3. …
**注意：** <易错点，如红灯=校正 / 蓝灯=重置>
```

### 第 4 步：陷阱必须前置提示

以下四条是高频踩坑点，答复中必须主动说明，不要等用户报错才讲：

1. 飞书 / 钉钉审批的「快递公司」条件分支必须选**包含任意**，选完全匹配会导致批量导入订单不触发审批。
2. OA 管理员默认同步系统管理员权限，**在系统内无法删除**，须去 OA 后台操作。
3. 云打印机**红灯闪 3 次是校正、蓝灯闪 3 次是恢复出厂**，两者极易混淆。
4. 到件异常的第四类原因是**隐私号尾号重复**，面单显示 `130****0000` 时要优先怀疑。

### 第 5 步：未收录不猜路径

问题不在两个 FAQ 文件中时，不得编造菜单路径。说明「该问题未收录」，按端给出可能入口，再引导至帮助中心或客服。

## 五、日常咨询应答流程

1. 先按 `@//references/daily-faq.md` 的问题分类表定位类型。
2. 该文件标注「可答」的，直接给结构化口径。
3. 标注「须查官方」的，只给查询路径与判断逻辑，不给具体数值。
4. 涉及用户自身订单（单号、进度、理赔）的，一律引导回官方渠道，本技能不查、不推断。
