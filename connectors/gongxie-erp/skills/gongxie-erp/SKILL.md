# 共鞋ERP

通过当前用户提供的 ERP MCP Token 调用共鞋ERP。Token绑定实际ERP账号；只能访问该账号已有角色权限、仓库范围和店铺范围内的数据。

## 使用顺序

1. 首次处理仓库、库存或单据任务时，先查询用户有权限的仓库；涉及店铺业务时先查询有权限的店铺。
2. 业务ID必须始终按字符串原样传递。不要使用 `Number`、`parseInt` 或任何浮点运算处理ID。
3. 查询分页时沿用返回的 `nextAfterId`。库存流水分页还要原样复用首次响应中的 `queryFrom` 和 `queryUntil`。
4. 查询结果不是一致性快照，也不能把库存流水事件直接当作当前库存合计。

## 查询能力

连接器会根据账号权限动态展示工具，可用于查询仓库、店铺、商品、货架、库存、入库单、出库单、订单明细、售后记录、库存流水及平台商品链接。普通列表查询可省略仓库或店铺范围；指定范围时必须使用查询结果返回的准确ID。

平台商品链接只代表ERP已记录的店铺商品映射，不代表平台全部在售商品或实时平台库存。无链接不等于无商品。

## 写入与确认

支持的写入仅限普通自建仓入库、指定库存直接出库、新增私有商品及空货架位。不得把直接出库描述为平台发货、移库或报损。

写入必须遵循以下流程：

1. 先调用对应的 `*_preview` 工具展示影响范围。
2. 向用户明确说明将创建或变更什么，并取得本次操作的明确确认。
3. 使用预览返回的 `confirmationToken`，生成稳定且唯一的 `requestKey`，再调用对应的 `*_create`。
4. 若请求超时或结果不确定，先使用原 `requestKey` 查询操作回执；重试时必须沿用原 `requestKey`，不得换键重复提交。

不要代替用户确认写入，不要批量批准后续操作。删除、覆盖商品、平台发货、移库、报损、Excel导入和权限变更不在连接器能力范围内。

## 错误处理

- 认证失效或Token无效：提示用户回到 ERP「个人信息 → MCP接入」重新生成或检查Token，然后重新连接。
- 权限不足：说明所需ERP权限或数据范围，不要建议改用管理员Token绕过限制。
- 限流或并发限制：稍后重试；写入重试仍沿用原 `requestKey`。
- 参数或范围错误：先重新查询可用仓库、店铺、货架或业务记录，使用返回的字符串ID修正请求。
- 写入结果不确定：查询操作回执；缺少回执本身不能证明操作失败。

严禁在对话、日志、示例或输出中回显完整Token。
