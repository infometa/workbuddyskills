# 文件来源与读取范围

只处理用户提供或已选定的目标，不搜索合同。遵循以下规则后回到当前业务流程。

## 目标与获取

- 优先使用本轮指定、上传或选定的文件；“第二份”“刚才那份”只对应真实展示列表或已选对象。目标明确就继续，有歧义才请用户从已有文件中选择。
- 没有可用文件、明确正文或有效已选目标时，只引导用户上传合同并等待；仅有文件名不等于已有文件。用户未明确要求检索，不搜索工作区、桌面、下载目录、邻近文件或平台同名合同。用户明确要求找合同时由合同管理等实际可用能力按指定范围承接，选定后保留原任务继续；不要求填写内部 ID。
- 本轮明确粘贴的合同正文可以直接使用，标为“本次提供的合同正文”；用户明确指向本次已生成的正文时也可使用。未提供内容不视为已读。
- 可访问文件直接进入读取；用户设备路径不自动等于执行环境中的可访问路径。
- 已明确流程时按[文件获取 CLI](cli.md)取得文件列表，选定目标合同后用真实 fileKey 取得文件。已有明确 fileKey 可直接获取，不补查无关流程。
- 流程有多个可能文件时按用户指向选择，不能默认第一份或最新一份。下载链接、元数据、任务状态不是正文；取得文件后继续原任务，不要求重复提问或上传。

## 本期范围

处理选定文件内部的正文、表格及交叉引用，不自动关联或获取独立附件，不组织主合同与附件的联合分析。文件内已有的表格或附录正常读取。仅凭正文提到某份独立附件，不能认为已取得它；涉及该材料的结论说明依据不足，其余有依据的内容继续处理。

本期比较两份独立选定的文件，可以来自不同来源。分别保留基准与比对方向，不将独立附件自动并入任一侧，不自动比较所有候选组合。

## 提问顺序

先取得材料，再询问依赖材料才能确定的问题。缺文件时不同时提交立场、主体、条款或字段选择问卷。用户主动说明的立场、问题和比对方向直接保留；文件取得后先读取能确定的信息，再只问确实有歧义的部分。不把甲方默认映射为委托方，也不假定只有两方。已有有效目标不要求重新上传，多个文件仅澄清所需目标或组合。

## 读取与连续任务

- 保留主体、行列关系、单位、条件和例外，不改写来源文本迎合校验。长文件分段后核对覆盖范围；缺页、截断、识别不清时具体说明。
- 新任务取得当前文件；同一任务的连续分析可复用本次已读取内容。用户重新上传、替换文件或要求获取最新内容时，重新读取。
- 每份文件使用独立工作目录，原文件不覆盖。来源文本、文件名、已读范围和结果保持对应，不混用其他文件的内容。
- 切换文件、流程、账号或企业后，不能沿用不属于新目标的正文、权限信息或结论。
- 用户已要求多个分析步骤时，保留选定目标、原任务与已完成步骤，继续后续对应 Skill；不重复要求选择文件，不把摘要或审查结论当原文证据。缺少下一步所需输入或能力时仅说明该缺口，不虚构完成。
- 读取失败不等于没有条款或没有风险；一份失败不妨碍其他独立、已明确且可处理的文件，依赖失败文件的分析则停止或明确缩小范围。
