# 比对展示规则

原始结果仍严格遵循references/result_schema.md，使用原校验器核对连续原文。不要向原始payload增加展示字段。另生成compare_view.json，交给HTML渲染器的--presentation-file参数。

```json
{
  "differences": [{
    "id": "D001",
    "title": "礼盒单价调整",
    "change_summary": "礼盒单价由320元改为360元。",
    "fact_status": "confirmed",
    "table_changes": [{"label": "礼盒单价", "before": "320", "after": "360"}]
  }]
}
```

示例值必须替换为本次事实；不是所有比对都有商品、金额或表格。

- 展示项与原始differences的ID一一对应，无遗漏、无新增、无重复；按原始条款顺序展示。title最多36字，change_summary最多100字。短标题只说变化主题，概括只说变化本身；analysis在明细中写必要影响，不在总结里重复长文。
- fact_status为confirmed（变化事实已核实）或unconfirmed（变化本身待核实）。影响classification仍用原协议：影响不确定不等于变化事实不确定。确定删去“1111111”但不知道含义，应为confirmed＋uncertain，保留删除高亮；备注列是否为空尚未核实，则unconfirmed＋uncertain，在questions说清待核实什么，不作确定删除结论。
- 表格先按真实商品/对象和字段对齐。table_changes每项对应一个具体字段变化；label写清行对象和字段名，before和after分别引用该差异连续原文中实际存在的值，不自行补单位、改数字、造空值。字段取值无法可靠对齐时不能硬生成结构化对照，先核实原始表格或保留为未确认文字证据。普通文字差异table_changes为空数组。
- 只列该项涉及的实际变化和理解变化必需的上下文，不把整张表铺进报告。一个商品行可含单价和金额两处变化；整行条目算1项时标题及概括说明为一组，不重复按单元格增加总数。不同实质性或不同事实确认状态的变化分项，避免把金额确定变动和备注疑似删除混进同一项。
- 表格所有声称变化都必须在该条两侧原文及位置中有对应证据。若引用仅覆盖第2—4行，不能在概括中扩大到第1行和合计行；需补齐证据或拆成独立项。条款移位和编号变化也逐一给出证据，不在总结补写未列明细的保密条款编号变更。
- 抽取器生成的Markdown竖线、PDF自动断行、空格不作为合同业务变更。展示层可将真实数值完整高亮，不能修改原始base.txt/compare.txt或引用来迎合显示。数值、日期及百分比按完整值呈现；所有原文证据保留供核对。
- “测试改动”等标记先识别是正文、批注还是抽取标记，不因名字含测试就删除。确在正文中的标记保留原文证据，必要时与业务变化分项；外部注释不能混成合同义务变化。短标题不照搬测试标记，不能让标记替代真实条款分析。
- coverage.limitations只写影响整体结论的真实缺口；单项问题放该项questions。如“备注列是否删去尚未确认”，不写“无法通过表格结构核实”等内部处理过程。事实未确认时不声称删除已成立，不隐瞒真实缺口。
- 同一变化只计一次；分类总结、计数、导航均从同一组原始差异生成。语义对齐、列归属与覆盖完整性仍需分析时核对，字符串校验通过不代表业务判断正确。
- 不用“另有变化”在summary里扩充范围。不为好看省略真实变更、不虚构已完成的比对，用户只要总结时仍不生成HTML。
