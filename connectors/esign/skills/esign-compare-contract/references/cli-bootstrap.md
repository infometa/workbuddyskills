# CLI 检测与安装

## 触发时机

实际需要执行 `esign` 命令时才检查。尚未取得必要文件或正在等待用户补充信息时，不提前安装。已有可用入口且本次环境已验证可执行时直接复用，不每一步重复检查或安装。

本规则只处理 CLI 缺失。本包其他规则中的“CLI 不可用时停止”指完成此处检测、必要安装及验证后仍不可用；其他运行依赖缺失不适用本安装分支。

## 检测

- 优先使用已有可用入口或已确认的安装路径。macOS / Linux 可用 `command -v esign`，Windows PowerShell 可用 `Get-Command esign -ErrorAction SilentlyContinue` 定位命令。
- 短命令不存在时，先检查已知安装路径：macOS / Linux 检查 `~/.esign/bin/esign`；Windows 使用已确认的安装路径，不猜目录、不扫描用户文件、不读取凭据。已有可执行文件时直接使用，不重复安装；验证命令为 `esign --version`，使用绝对路径时替换可执行入口。
- 只有确认 CLI 未安装，或系统明确返回 `command not found`、`esign: not found`、`'esign' 不是内部或外部命令` 等命令不存在错误且已有路径也不可用时，才进入安装。可执行文件存在但运行报错、权限拒绝或架构不兼容，不视为未安装，不自动覆盖重装。
- 登录失效、权限不足、余额不足、子命令不支持、参数错误、业务失败或超时，均不属于 CLI 未安装，不通过重新安装处理。

## 安装

如果本机没有 `esign` 命令，可先执行安装命令：

```bash
npm install -g @esign-ai/esign-cli
```

用户明确要求不安装或只提供命令时，遵循用户要求；否则实际执行安装，不仅回复“请先安装”。宿主限制执行安装或确需用户处理权限时，说明具体受阻事项，不绕过限制。不因下载失败换用未知来源，不自动安装其他依赖、不自动升级已有 CLI。

## 验证与继续

- 安装后执行 `esign --version` 验证可用性，不仅根据安装命令退出码或成功文字判断。若当前终端尚未更新 PATH，使用安装结果中确认的实际可执行路径；macOS / Linux 也可核对上述已知路径。后续命令沿用已验证入口，不要求用户先重启后再重新提供任务。
- 验证成功后继续原步骤；需要登录时按原有登录规则处理，安装成功不等于登录成功。不为纯本地处理强制登录，不切换账号、企业及环境。
- 仅当原命令尚未执行，或明确因命令不存在而未执行时，才恢复执行该命令。保留原参数、已选文件、草稿及当前任务上下文，不从头重建任务。
- 已经执行但超时或结果不明的业务操作，仍按原有恢复规则核查，不得因安装流程重复提交。安装不代表用户确认发送、审批或其他业务操作，不跳过原有授权和确认条件。
- 安装失败、缺少安装所需工具或验证仍不可用时，简短说明原因及需要用户处理的事项，保留任务上下文，停止受影响步骤，不反复安装。
- 对用户只说明必要的准备状态、受阻原因或下一步；不输出完整安装日志、内部检查过程或凭据信息。
