# 合同审查

对明确的合同文件进行条款风险分析，给出依据、影响和建议。开始时读取[文件来源规则](references/file-sources.md)与[通用依据规则](references/evidence-rules.md)，后续所有分支适用。

## 1. 确定文件与审查范围

使用本轮文件或有效已选目标；已明确流程时先取得目标文件，不搜索合同。一次审查一个明确的合同文件，多份可能目标时只澄清目标；用户明确要求多份时逐份独立处理，不混合风险与原文。

已有明确正文或本次刚起草的正文可以直接审查，不为分析改写条款或强制生成另一种格式。缺少文件或明确正文时，仅友好引导上传并结束本轮等待，不同时询问审查立场、条款重点或合同阶段；用户已明确流程目标时先取得所选文件，不重复要求上传。正文依赖未纳入的独立附件时，仅对受影响结论说明限制，不自动获取附件。

## 2. 读取并确认必要信息

- 读取选定文件内部的正文、表格及交叉引用，在内部记录实际覆盖。长合同分段读取并复核，不静默只审重点；真实缺页、截断或识别异常仅说明具体影响，不输出固定已读范围栏目。
- 先从正文识别真实主体，再保留用户已明确的立场和关注点。不明确代表哪方时只询问一次，选项使用本合同的真实角色及必要名称，并提供中立视角；不预设“甲方/委托方、乙方/相对方”，不假定只有两方。主体无法识别时开放询问，不编选项；能识别主体不等于知道用户代表谁，不从文件名、上传者或账号猜立场。用户已明确中立审查时直接继续；关注点未提供不追问。
- 只审合同正文、其中的表格和条款引用。不识别或审查签字、盖章及其有无、位置、真实性，不询问或查询实际签署阶段，不按未签/已签分支审查。正文中的生效、付款等约定仍可分析，但不据此判断现实中已签署或已生效。
- 文件整体不可读或不是可审查的合同内容时说明原因，不生成空报告。一个可读短协议不能仅因字数少就认定残缺。

## 3. 分析并复核

读取[审查规则](references/review-rules.md)，按合同交易结构核对适用的风险维度，不查询平台预设风险清单，不创建平台审查任务，不回写平台审查结果。

1. 先明确主体、交易与履行安排，再结合立场逐项核对条款、保护条件、例外及交叉引用。检查退款、解除、赔偿等已有补救安排后，具体说明剩余缺口；不能把保护不足说成完全没有，也不能因有一条保护就认定充分。
2. 只把有可靠依据的问题列为已识别风险。对缺失条款的判断先确认相关全文覆盖，内部保留查找依据；对外说清缺少什么及影响，不伪造引文、不固定展示范围。
3. 将识别不清、外部事实未知或材料不足列为待确认事项，说明影响和所需补充；不能与已确认风险重复计数。
4. 每项风险给出影响、真实位置和必要引文，以及可执行建议。重要修改示例仅作为建议，不覆盖原合同。
5. 自检事实与推断、等级及建议是否一致，合并重复风险，核对是否遗漏关键条件和有利保护条款。无风险不必强行生成风险项。

## 4. 输出与追问

按[结果组织规则](references/report-rules.md)组织分析，并读取本包[结果交付规则](references/result-delivery.md)决定交付方式，不自行生成当前包不支持的报告。结论在前，再列问题、依据与修改建议；无内容的模块不展示，不列合同阶段、已读范围、页数或技术过程。

用户要少量重点时优先呈现最重要的发现，不机械凑数或隐去已发现的重要问题，其余明细按本包结果交付规则展示，不因压缩会话而丢掉重要依据。区分“展示两条重点”和“只审两个事项”：后者只做指定分析，不能冒称全面审查；可简短引导全面审查，但不虚构其他风险，已经全面审查时不再询问是否重做。

同一任务的连续追问可沿用本次已读取的证据；文件被替换或用户要求获取最新内容时重新读取并重新核对，不能自动宣称旧风险已消除。切换主体或审查立场后重新评估受影响结论。用户取消时停止后续分析。

只处理合同正文审查，不发起高级审查，不处理购买或份数，不执行审批、签署、撤回等操作，不承诺报告已保存到平台。用户只问具体条款含义或要求摘要时由对应 Skill 承接。已明确要求多个连续步骤时，保留选定文件、原任务与已完成步骤继续处理，不要求重复选择；没有所需能力时说明缺口，不虚构完成。

## CLI 准备

首次需要执行 `esign` 命令时，先按[CLI 检测与安装](references/cli-bootstrap.md)确认命令可用；确认本机未安装时，完成安装并验证后继续原步骤。本包其他规则中的“CLI 不可用时停止”指完成该准备后仍不可用。只处理 CLI 缺失，不改变材料选择、业务处理、用户确认及结果展示规则。

## 平台文件访问规则

获取 e签宝平台文件，或抽取正文需要远端转换、OCR 时应用以下接入规则；粘贴正文和纯本地处理不强制连接。文件处理遵循下述正文读取规则。

- 已有有效连接和身份时直接执行，不重复引导安装或登录。
- 使用 CLI 自管登录态且状态未知时，可调用 `esign auth status`。需要登录或授权失效时，通过已有连接器或账号授权入口恢复，随后继续原任务。
- 缺少可用接入或授权入口时，说明平台文件暂不可访问；已有可用正文或明确可纯本地读取的文件仍可独立分析。不索取、读取或回显凭据，不绕过权限，不自动切换企业。

- 需要 CLI 处理文件或访问平台时，按[CLI 检测与安装](references/cli-bootstrap.md)解析可用入口；确认未安装时完成安装、验证后继续原步骤。不把其他 CLI 当成替代，不扫描用户文件或读取凭据，不自动升级已有 CLI；不得仅因命令缺失宣称业务不支持。

## 结构化提问节点

以下选择节点调用 `AskUserQuestion`，遵循[结构化提问规则](references/workbuddy-question-rules.md)：

- 当前已有多个真实文件候选而审查目标无法唯一对应时，仅选择审查文件；已有明确文件或有效序号直接沿用。
- 取得并读取合同、识别实际角色后，用户尚未明确审查立场时，用真实角色及必要名称作为选项，并提供“中立视角”。用户回答前不输出依赖立场的审查结论。已明确角色或中立立场时直接沿用，不再问。不预设甲方就是委托方，也不假定合同只有两方；无法识别角色时改为简短开放提问，不编造候选。
- 只有影响当前判断、尚未明确且存在真实有限候选的关键事实才可进一步选择；不把报告中的每项待确认事实都变成完成审查前的必答题。

未提供文件时只引导上传，不能同时提交角色或立场问题。不强制选择审查重点、签署阶段、报告格式或是否全面审查。保留用户已给出的关注点，报告及会话输出仍遵循结果交付规则。

## 正文读取入口

处理真实文件时统一使用 `esign document extract-contract-body`，按[文档处理规则](references/document-processing.md)选择真实本地路径或已选文件的真实 fileKey，并检查正文及覆盖情况。明确粘贴的正文直接使用；没有材料先按原流程引导提供，不运行抽取。

抽取并核对后才识别真实角色、询问必要立场并执行审查；不提前猜角色。表格或读取缺口按需核对，保留现有正文审查范围和HTML交付。
