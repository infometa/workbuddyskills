# 审查交付

默认生成独立HTML报告。会话只给一句总体结论，必要时增加少量一句话重点，紧接真实报告入口，不将完整风险分析、其他风险和待确认清单再复制一遍。用户追问某项时再直接展开，不机械重复生成报告。

## 生成数据

将本次抽取正文原样保存为UTF-8 `source.txt`。按以下字段组织`review_payload.json`，除下述可选字段外不增加字段；示意值必须换成本次事实：

```json
{
  "file_name": "真实合同文件名称.pdf",
  "perspective": "用户已明确的实际立场或中立",
  "conclusion": "基于本次分析的直接结论",
  "highlights": ["必要时的一句重点，最多3条"],
  "risks": [{
    "id": "R1", "level": "中", "title": "具体问题短标题",
    "location": "真实条款位置", "quote": "本次正文中的连续原文",
    "missing_basis": "", "impact": "有依据的可能影响",
    "suggestion": "对应原因的修改建议", "replacement": ""
  }],
  "wording": [], "questions": [], "limitations": []
}
```

- `conclusion`只写1—2句直接结论，最多180字；不在一段中堆保护条款、风险清单和缺材料说明。可选`highlights`最多3条、每条最多70字，不需要时为空。详细事实、依据及建议保留在问题项，不能为了压缩结论删去重大问题。风险数量由脚本统计，不在结论里重复手填。
- 每项`title`最多36字，使用可区分的短标题，如“付款起算早于续约期”；完整解释写进影响和建议。
- `risks`可为空，不凑风险。`level`为高／中／低；`quote`须匹配原文；缺失条款没有引文时`quote`为空，`missing_basis`写核对相关条款与交叉引用后的具体缺失依据，不编造“原文未约定”作引文。有引文时`missing_basis`为空。脚本不能证明缺失判断或法律结论正确，仍须按审查规则复核。
- `replacement`仅有必要时填写建议条款，不改源文件。
- `wording`每项为`location`、`quote`、`suggestion`，仅实际文字问题；`questions`每项为`question`、`impact`，仅影响判断的真实未知事实，不重复计入风险。与某项已识别问题相关时增加可选`risk_id`，取该问题的真实ID，提示随该问题展示且不在末尾重复。无法关联已识别问题时不填写`risk_id`，在末尾待确认事项中简短说明具体条款、影响与所需补充；不要为了挂提示而制造风险项。
- `limitations`保留为兼容字段，生成新数据时置空；材料模糊、缺页等具体影响写进`questions`并优先关联相关问题，不再在报告开头堆材料提示。不写固定范围、阶段、已读页数或技术说明。数量从实际条目算，不手填数量，不虚构原文位置。

```bash
python3 '<本技能目录>/scripts/render_contract_report.py' --kind review --input-file '<本轮review_payload.json>' --source-text '<本轮source.txt>' --output-dir '<本轮报告目录>'
```

命名自动为`合同审查报告-合同文件名称（去扩展名）-审查日期.html`，默认取本次本地日期；显式`--date`只能填真实审查日期YYYY-MM-DD。非法字符替换、超长文件名截短，同名同日新子目录保留原报告；原文件名在正文保留。仅退出成功且返回的`file`真实可访问才交付，用户看到的名称和实际文件名一致。

## 展示

报告顺序：标题 → 合同名称与实际审查立场 → 审查结论及实际风险数量 → 按需目录 → 问题与修改建议 → 文字问题（有才显示）→ 待确认事项（有才显示）→ 日期。合同名称、审查立场先于结论，但不增加合同阶段、已读范围等元信息。按风险重要性展示条款位置、原文依据、影响及建议，长文本自动换行。

目录按高／中／低风险分组，每项独立一行，使用“问题编号＋短标题”，点击定位正文；空风险分组不展示。文字问题和待确认事项只提供栏目入口，不把整段问题、材料说明或限制作为导航标题。目录不新增分析内容，也不叫“问题导航”。独立问题、文字问题和未关联待确认事项合计达到5项时显示，少于5项省略；关联问题下的补充提示不重复计数。

不设置“必要材料缺口”栏目。某处金额模糊等材料问题，只在相关问题旁说清无法判断什么、需要什么补充；不是合同缺少违约条款等审查问题。整个文件无法正常读取时先引导提供可读文件，不生成看似已完成的报告。局部不足不夸大为整体不可读，也不隐瞒影响关键结论的限制。

回复示意：“交付与付款安排存在需要调整的条款，主要涉及付款先后顺序和逾期责任。详见《实际报告名称》。”必须替换为实际有依据结论；不展开多屏分析、不固定加待确认问卷、已读范围或“两点提示”。真正阻止关键结论的缺失事实可简短指出。

HTML内嵌样式，无外部资源或公开上传。宿主支持预览则使用真实入口，否则给实际可打开／下载文件，不声称具备未验证的卡片内预览，不写上方／下方卡片。生成失败如实说明，保留已有分析，不伪造链接。
