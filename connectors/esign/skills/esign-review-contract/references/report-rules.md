# 审查报告与输出

## 交付边界

是否生成报告及对话展示方式，由[结果交付规则](result-delivery.md)决定。不得跨用其他平台的交付规则。共同要求是结论直接、依据充分、条款与建议可定位，不固定推荐其他任务，不输出技术过程或“安全可签”等无依据结论。

用户要少量重点时先列相关事项，不机械凑数，不隐藏其他重大问题。仅审指定事项不能冒称全面审查，可简短引导全面审查；已全面审查不再询问是否重做。未明确的外部事实与真实风险分开，不把所有未知都变成必答问卷。

## 完整结果组织

1. **结论**：直接说明主要发现。可用文件名及已明确立场帮助辨识，但不在结论前堆元信息，不展示合同阶段或已读范围。整体等级取有依据的风险最高等级；无明确风险就写未发现明确条款问题，不强行标低风险或承诺没有任何风险。
2. **问题与修改建议**：按重要程度排序。每项写清问题、等级、影响、真实条款位置及必要原文、可执行建议；需要时给条款示例。已有保护与剩余缺口结合分析，缺失条款不造引文。相同问题只计一次，不重复铺陈。
3. **文字问题**：仅有实际问题才列位置、原文和建议；已列为条款风险的问题不重复计数。没有内容，标题也不展示。
4. **待确认事项**：仅有影响结论的实际未知信息才展示，说明具体问题和所需信息，不计入已确认风险；没有内容则整块省略。

只审正文，不包含签字、盖章及实际签署阶段检查。读取完整性在内部核对；真实缺页或识别异常影响判断时在相关结论处简短说明，不隐瞒为完整完成，不把读取失败算一项风险。数量从最终明细核对，无内容分类不显示。

交付按本包规则进行，不创建平台审查记录，不声称结果已回写平台。生成文件的包只有在文件及入口实际可用后才交付链接；不支持报告的包直接给分析结果。
