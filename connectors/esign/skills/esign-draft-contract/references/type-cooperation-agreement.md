# 合作协议起草规则

信息收集遵循 [通用规则](intake-common.md)：下列字段为按场景选用的候选，不要求首稿前补齐；首轮询问缺失立场，回复仍未说明则直接中性起草。初稿后只引导补充 2～4 个真实缺失的重要变量，不足时不凑数，不默认列出全部。

## 适用场景

适用于双方或多方围绕项目、渠道、运营、市场、资源、品牌、客户等事项开展合作的协议。

不适用于单纯买卖、劳动、借款、租赁或明确服务采购关系。合作中包含具体服务或销售安排时，应在合作协议中拆分清楚。

## 角色与起草立场

合作协议角色通常不是固定甲乙强弱关系，应按投入、分工、收益和客户归属判断。

- 代表资源投入方：强化投入边界、成果归属、退出和补偿。
- 代表运营执行方：强化配合、费用结算、收益分配、责任边界。
- 代表渠道方：强化客户归属、结算周期、排他范围。

## 初稿与信息补充

合作模式不明确且会影响合同结构时，生成初稿前集中询问；其他信息不要求先补齐。合作目标、双方分工、投入资源、合作期限、收益分配或结算方式、费用承担等具体事实，缺失时先用原子化占位符生成完整初稿，初稿展示后按需补充。

对应场景已经出现时，初稿展示后还可补充客户归属、知识产权、排他合作、退出机制、项目管理、保密。

## 具体信息处理

| 变量 | 初稿缺失处理 |
|---|---|
| 合作事项/目标 | 使用原子化占位符，初稿展示后补充 |
| 双方分工 | 使用原子化占位符，初稿展示后补充 |
| 合作期限 | 使用原子化占位符，按需补充 |
| 收益分配/结算 | 使用原子化占位符，初稿展示后补充 |
| 费用承担 | 初稿先写中性机制，按需补充 |
| 起草立场 | 按通用首轮立场规则处理：用户首轮回复仍未说明立场时直接中性、均衡起草，不提示默认选择 |

## 可默认写入内容

- 双方按约投入资源并履行分工。
- 合作事项、费用和收益应定期对账确认。
- 未经同意不得擅自以对方名义对外承诺。
- 合作终止后进行结算、资料返还和保密。

## 条件触发变量

- 排他合作：补充排他范围、期限、地域、违约后果。
- 收入分成：补充计算口径、结算周期、扣除项、审计权。
- 渠道合作：补充客户报备、客户归属、撞单处理。
- 联合运营：补充账号、数据、内容、投放、客服分工。
- 品牌使用：补充授权范围、物料审核、停止使用。

## 标准章节结构

首部：标题后直接列明各方信息（不加小标题，不作为编号条款）。

1. 合作背景和目标
2. 合作内容
3. 双方分工和投入
4. 合作期限
5. 费用承担与收益分配
6. 项目管理和对账
7. 客户、数据和成果归属
8. 知识产权和品牌使用
9. 保密
10. 排他或限制性约定
11. 退出、解除和清算
12. 违约责任
13. 通知与送达
14. 争议解决
尾部：签署区（不作为编号章节）。

## 每章起草要求

- 合作内容：写明具体合作事项、目标、范围和不包含事项。
- 分工投入：列明各方资源、人员、渠道、费用、技术、品牌、运营职责。
- 收益分配：写明计算口径、结算周期、对账、发票、付款。
- 项目管理：写明负责人、会议、报表、确认机制。
- 归属：客户、数据、内容、知识产权、合作成果分别处理。
- 退出：写明退出条件、存量客户处理、未结算款项、资料返还。

## 输出前强制自检与自动补写

在通用合同质量框架基础上，逐项检查并自动补齐：合作目标与边界、各方投入和分工、决策/审批机制、费用承担、收入或成果分配、对账结算与审计、客户/品牌/数据/知识产权归属、对外责任、违约补救、合作退出与清算。不得只写“友好协商、共同推进、收益共享、风险共担”而没有可执行口径。

涉及分成时写明计算基数、扣除项目、结算周期、数据和凭证、异议及少付漏付处理；涉及长期合作时写明新增事项的确认方式、存量项目处理、资料返还、应收应付和退出与清算。

## 禁止写法

- 合作目标空泛，没有分工和收益机制。
- 只写"利润双方协商分配"。
- 排他合作没有范围和期限。
- 客户归属、数据归属、成果归属完全缺失。

## 生成前边界

生成草稿时应覆盖合作事项、分工、投入、收益、费用、期限、归属、退出、违约责任。正常规则适配不向用户说明，只有用户信息明显冲突时才简短提醒。

## 待补充信息规则

以下是内部核对用的字段候选，初稿后只挑实际缺失的 2～4 项友好引导：合作事项、分工清单、收益比例、结算周期、客户归属规则、合作期限。
