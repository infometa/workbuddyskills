# 委托合同起草规则

信息收集遵循 [通用规则](intake-common.md)：下列字段为按场景选用的候选，不要求首稿前补齐；首轮询问缺失立场，回复仍未说明则直接中性起草。初稿后只引导补充 2～4 个真实缺失的重要变量，不足时不凑数，不默认列出全部。

## 适用场景

适用于一方委托另一方处理事务、办理事项、提供代理性或事务性服务的合同，如代办手续、项目代理、事务处理、专项授权等。

不适用于劳动关系、长期顾问咨询、买卖、承揽或纯服务交付合同。涉及对外代理签署法律文件时，应补充授权范围和权限边界。

## 角色与起草立场

- 甲方通常为委托方。
- 乙方通常为受托方。
- 代表委托方：强化授权范围、报告义务、费用控制、资料返还、禁止转委托。
- 代表受托方：强化授权清晰、委托方配合、费用报销、责任边界。

## 初稿与信息补充

委托关系或权限模型不明确且会影响合同结构时，生成初稿前集中询问；其他信息不要求先补齐。委托事项、受托权限、委托期限、报酬或费用、成果/办理结果等具体事实，缺失时先用原子化占位符生成完整初稿，初稿展示后按需补充。

对应场景已经出现时，初稿展示后还可补充是否允许转委托、是否代收代付、费用承担、资料清单、对外沟通权限。

## 具体信息处理

| 变量 | 初稿缺失处理 |
|---|---|
| 委托事项 | 使用原子化占位符，初稿展示后补充 |
| 受托权限 | 影响权限模型时先确认，否则使用原子化占位符 |
| 委托期限 | 使用原子化占位符，按需补充 |
| 报酬/费用 | 使用原子化占位符，按需补充 |
| 成果或办理结果 | 初稿先写办理确认机制，按需补充 |
| 起草立场 | 按通用首轮立场规则处理：用户首轮回复仍未说明立场时直接中性、均衡起草，不提示默认选择 |

## 可默认写入内容

- 受托方应按委托范围勤勉、审慎处理委托事项。
- 受托方应及时报告办理进展和重要情况。
- 未经委托方书面同意不得超越权限或擅自转委托。
- 委托终止后返还资料、印章、证照、款项和成果。

## 条件触发变量

- 对外代理：补充授权文件、代理权限、签署边界。
- 代收代付：补充账户、资金归属、对账、返还。
- 转委托：补充允许条件、审批和责任承担。
- 政府/平台手续：补充资料真实性、审批不通过处理。

## 标准章节结构

首部：标题后直接列明各方信息（不加小标题，不作为编号条款）。

1. 委托事项
2. 委托权限
3. 委托期限
4. 报酬、费用与支付
5. 双方权利义务
6. 资料交付与保管
7. 报告与确认
8. 转委托
9. 合同解除与终止
10. 违约责任
11. 保密
12. 通知与送达
13. 争议解决
尾部：签署区（不作为编号章节）。

## 每章起草要求

- 委托事项：具体列明办理事项，不写"相关事宜"作为唯一描述。
- 权限：明确能做什么、不能做什么、是否可对外签署或收付款。
- 费用：区分服务报酬、代垫费用、第三方费用、报销凭证。
- 报告：写明重要事项报告、阶段确认、最终成果交付。
- 资料：写明资料清单、保管、返还、遗失责任。
- 解除：写明委托方解除、受托方无法继续办理、费用结算。
- 违约：超越权限、怠于办理、资料遗失、擅自转委托、逾期付款。

## 输出前强制自检与自动补写

在通用合同质量框架基础上，逐项检查并自动补齐：委托事项、权限边界、办理期限、委托人指示与配合、受托人报告、费用及必要垫付款、外部签约/收款/处分权限、资料和财物保管返还、转委托、终止后的在途事项和终止结算。涉及对外行为时必须区分“可代为办理”“可代为签署”“可代为收款或处分”，不得用“全权处理一切事项”替代具体授权。

无偿委托、行纪居间、诉讼代理、资产处分等存在专门规则的场景，应根据实质转用或补充相应规则；本 reference 不得默认赋予重大处分权限。

## 禁止写法

- 委托事项和权限不清。
- 受托方可无限代表委托方作决定。
- 费用承担和报销规则缺失。
- 对外代理但无授权边界。

## 生成前边界

生成草稿时应覆盖委托事项、权限、期限、费用、资料、报告、转委托、解除和违约责任。正常规则适配不向用户说明，只有用户信息明显冲突时才简短提醒。

## 待补充信息规则

以下是内部核对用的字段候选，初稿后只挑实际缺失的 2～4 项友好引导：委托事项、授权范围、委托期限、报酬金额、资料清单。联系人仅在委托执行机制明确需要时列入。
