# 借款合同起草规则

信息收集遵循 [通用规则](intake-common.md)：下列字段为按场景选用的候选，不要求首稿前补齐；首轮询问缺失立场，回复仍未说明则直接中性起草。初稿后只引导补充 2～4 个真实缺失的重要变量，不足时不凑数，不默认列出全部。

## 适用与分型

适用于自然人、企业之间的一次或分期借款。先区分自然人之间、企业之间/企业与个人，以及一次放款/循环或分期放款、一次还本/分期还款、有息/无息、有无担保。

不适用于金融机构标准贷款、融资租赁、股权投资或只起草独立担保文件的场景。名称为“借款”但实质是投资、保底回购或货款结算时，先确认真实交易关系。

## 角色与起草立场

- 甲方通常为出借人，乙方为借款人；底稿已有角色时沿用。
- 代表出借人：强化实际放款证据、用途、还款计划、资金回收、担保和提前到期。
- 代表借款人：强化足额按期放款、利率口径、费用透明、提前还款、宽限和责任边界。

## 初稿与信息补充

真实交易关系或借款模型不明确且会影响合同结构时，生成初稿前集中询问；其他信息不要求先补齐。双方主体、金额/币种、期限及起算、利率或明确无息、放款方式、还款方式、用途、用户代表哪一方等已有借据、转账凭证、还款表或底稿可供提取的，不重复询问。

缺失的具体事实先用原子化占位符生成完整初稿；初稿展示后，可按需补充分期计划、利息支付日、提前还款、担保方式与主体、收款账户、展期。邮箱、联系人、签署地点未提供时不问也不生成；签署区按全局规则只保留空白字段 `签署日期：`。

| 核心变量 | 初稿缺失处理 |
|---|---|
| 出借人和借款人 | 主体类型影响字段结构时先确认；名称可留占位符 |
| 本金金额和币种 | 使用原子化占位符，大小写一致 |
| 借期与起算方式 | 使用原子化占位符；自然人借款注意实际提供借款的事实 |
| 利率或明确无息 | 使用原子化占位符，不得自行填入利率 |
| 放款时间/方式 | 保留核心占位符，初稿展示后补充 |
| 还款方式/节点 | 保留核心占位符；分期时生成还款计划 |

## 起草质量闭环

### 本金、放款与证据

- 写明本金、币种、放款时间/条件、账户或其他方式，以及分期放款计划。
- 不得约定预先从本金扣除利息后仍按名义本金计息；实际到账金额、转账备注、收据/借据等证据安排应与正文一致。
- 自然人之间借款需区分合同签署与实际放款；不要把未发生的放款事实写成已经完成。

### 期限、利息与费用

- 期限可用明确起止日或“实际放款日起至某日/若干月”，但必须说明起算和到期。
- 利率写明年/月口径、单利或其他明确算法、计息本金、起止日和付息日；不同口径不得混用。
- 未约定利息不得擅自改成有息；自然人之间对利息约定不明时不要推定利息。
- 不硬编码可能变化的司法保护数字。用户给出的借期利率、逾期利率、违约金及其他费用合计明显可能超过现行保护上限时，只用一句话提醒需按合同成立时适用标准调整，并保留用户确认后的合法方案。

### 还款、抵扣与提前还款

- 一次还本付息要写明到期金额计算方式；分期还款用计划表列明日期、本金、利息和每期合计。
- 写明付款不足时的抵扣顺序，避免本金、利息、费用无法结算。
- 提前还款按用户要求写明通知、是否需同意、利息按实际占用期或其他合法约定计算；不得默认收取未发生期间的全部利息。

### 逾期、提前到期与担保

- 逾期责任写明起算、计算基数和与借期利率/违约金的关系，避免重复叠加后无上限。
- 提前到期事由应围绕未按约还款、用途违约、虚假信息、担保失效、明显影响偿债能力等可判断事件，并设置必要的通知或补救期。
- 有保证时写明保证人、方式、范围、期间及签署；信息不全不得默认“连带保证”。抵押/质押需提示另行完善标的、权属及登记/交付等生效或对抗手续。
- 用户未提出担保时，不生成“无担保”章节或担保人占位符。

## 条件模块

- 企业借款：授权、资金用途、财务资料、合规审批按场景加入。
- 多次放款：提款条件、额度、每笔借据、额度恢复与终止。
- 分期还款：计划表、提前清偿、部分逾期与全部提前到期的关系。
- 既有债务确认：区分借款合同、借据/欠条和还款协议，不把未核实的历史金额直接认定为本金。

## 必须覆盖的结构

首部当事人信息；金额和用途；期限；利率和计息；放款；还款；按需加入担保；权利义务；提前还款/展期；提前到期；违约；争议解决；按需加入通知送达；尾部签署区。

## 输出前强制自检与自动补写

先执行通用合同质量框架，再检查本节七项闭环。任何已触发节点缺失或仅有概括性一句话时，必须补写或重写后再向用户展示；不得用“借款事项另行协商”替代放款证据、计息口径、还款顺序、逾期救济和提前到期机制。

## 禁止写法与自检

- 不编造利率、账户、已放款事实或担保人。
- 不混用年利率、月利率和日利率，不让名义本金与实际本金矛盾。
- 不把借期利息、逾期利息、违约金和服务费无边界叠加。
- 不让还款计划合计与本金/利息算法不一致。
- 生成前检查“本金明确—放款可证明—期限有起算—利息可计算—还款可执行—逾期不重复—担保真实可落实”七项闭环。

## 待补充规则

内部核对以下核心字段，初稿后只挑实际缺失的 2～4 项友好引导：主体、本金/币种、借期/起算、利率或无息、放款、还款。担保、账户、展期等仅在场景已触发时列入；邮箱、联系人、签署地点不得因缺失列入。签署区只保留空白字段 `签署日期：`，不列入待补充项。
