# 买卖/采购合同起草规则

信息收集遵循 [通用规则](intake-common.md)：下列字段为按场景选用的候选，不要求首稿前补齐；首轮询问缺失立场，回复仍未说明则直接中性起草。初稿后只引导补充 2～4 个真实缺失的重要变量，不足时不凑数，不默认列出全部。

## 适用与分型

适用于货物、设备、物资和产品买卖。先区分现货/定制、一次/分批交付、普通货物/需安装调试设备、境内/跨境交易；不同分型决定交付、验收、质保和风险转移机制。

不适用于持续服务、租赁、技术研发或以加工成果为主的承揽关系。合同虽名为“采购”但核心是服务时，转服务合同规则。

## 角色与起草立场

- 甲方通常为买方/采购方，乙方为卖方/供应商；底稿角色相反时沿用底稿，不强制改名。
- 代表买方：强化技术规格、交付单证、分层验收、质保、替换/退货和付款前提。
- 代表卖方：强化明确订单、付款节点、验收异议期限、买方配合、风险转移和责任上限的合理边界。

## 初稿与信息补充

货物类别或交易模型不明确且会影响合同结构时，生成初稿前集中询问；其他信息不要求先补齐。货物名称及规格、数量、价款、交付时间/地点、付款节点、验收依据、用户代表哪一方等已能从清单、报价单、订单或底稿提取的，不得重复询问。

缺失的具体事实先用原子化占位符生成完整初稿；初稿展示后，可按需补充分批计划、运输/保险、安装调试、样品封存、质保、发票、定制图纸、进口单证。邮箱、联系人、签署地点未提供时不问也不生成；签署区按全局规则只保留空白字段 `签署日期：`。

| 核心变量 | 初稿缺失处理 |
|---|---|
| 货物名称、规格或可唯一识别的清单 | 使用原子化占位符；多项货物用正文内表格承载 |
| 数量及计量单位 | 使用原子化占位符，初稿展示后补充 |
| 单价/总价及含税口径 | 使用原子化占位符，不编造税率 |
| 交付时间、地点、方式 | 分别使用占位符；分批时对应到批次 |
| 付款节点 | 保留核心占位符，初稿展示后补充 |
| 验收依据和异议机制 | 标准可从用户资料提取；期限缺失时写合理机制但不编造具体天数 |

## 起草质量闭环

### 标的与价格

- 多项货物优先生成“货物清单”表格，至少包含名称、规格型号、数量、单位、单价、金额；技术参数较长时在当前正文内增设明细表。
- 写明总价是否含税、包装、运输、保险、安装调试等费用；用户未说明时不得推定具体税率或发票类型。
- 用户提供的当前底稿已有订单、报价单、技术协议引用时，保留明确引用及冲突顺序；未取得的内容不视为已读取，本期不另行获取或生成独立附件。

### 交付、所有权与风险

- 交付条款写明时间、地点、收货主体、运输方式、费用承担和随货单证。
- 所有权转移和毁损灭失风险转移分别约定，不得把“收货”“初验”“终验”“付款”混成同一时点。
- 分批交付时，每批数量、价款、验收和付款要能一一对应；延误一批是否影响后续批次应可判断。

### 分层验收与质量救济

- 区分到货时的数量/外观/包装核验与需要检测、安装或运行后才能完成的质量/性能验收。
- 写明验收依据、期限、异议载体、复检/第三方检测、整改或更换期限及复验；不得简单写“签收即视为质量合格”。
- 质量不合格的救济按场景覆盖修理、更换、补足、重作、退货、减价、解除和损失赔偿，并说明费用承担。
- 有质保时写明起算点、期限、响应、维修/更换、停机是否顺延质保；不得把验收通过等同于放弃隐蔽瑕疵或质保权利。

### 结算与违约

- 付款条件要与交付/验收节点对应；发票可作为结算材料，但不要在用户未要求时把开票设为所有付款义务的绝对前提。
- 分别处理逾期交付、逾期付款、数量短缺、质量不合格、拒收/不配合验收、知识产权侵权等责任。
- 违约金或责任上限未由用户提供时不编造具体比例；应保留可执行的损失赔偿、继续履行和解除路径。

## 条件模块

- 设备采购：安装调试、试运行、培训、备件、维保响应。
- 定制货物：图纸确认、变更单、模具/工装归属、取消订单后的已发生成本。
- 样品交易：样品编号、封存、批量一致性及样品与书面标准的优先级。
- 跨境交易：贸易术语及版本、报关、税费、保险、单证、币种与汇率风险；用户未提供时不得擅选贸易术语。
- 涉及品牌/软件/图纸：只转移货物不当然转移知识产权，按用户交易目的约定许可或权属。

## 必须覆盖的结构

首部当事人信息；标的与清单；质量/技术标准；价款与结算；包装运输与交付；验收与异议；所有权和风险转移；质保与售后；双方义务；违约与解除；不可抗力；争议解决；按需加入通知送达；尾部签署区。

## 输出前强制自检与自动补写

先执行通用合同质量框架，再检查本节六项闭环。任何已触发节点缺失或仅有概括性一句话时，必须补写或重写后再向用户展示；不得把付款安排、标的状态、费用承担、验收救济或风险转移整段留作待补充。

## 禁止写法与自检

- 不用“货物一批”“按行业标准”等无法识别或验收的表述替代核心内容。
- 不让签收、外观验收和最终质量验收相互冲突。
- 不遗漏不合格货物的处置、返运费用和复验路径。
- 不出现分项金额之和与总价不一致、批次时间与付款节点不对应、附件名称前后不一致。
- 生成前检查“标的可识别—价款可结算—交付可判断—验收可执行—风险有时点—违约有救济”六项闭环。

## 待补充规则

内部核对以下核心字段，初稿后只挑实际缺失的 2～4 项友好引导：货物/清单、规格、数量、价款、交付、付款、验收依据。运输、质保、发票、安装等仅在场景已触发时列入；邮箱、联系人、签署地点不得因缺失列入。签署区只保留空白字段 `签署日期：`，不列入待补充项。
