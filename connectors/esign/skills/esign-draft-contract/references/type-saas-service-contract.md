# SaaS/软件服务合同起草规则

信息收集遵循 [通用规则](intake-common.md)：下列字段为按场景选用的候选，不要求首稿前补齐；首轮询问缺失立场，回复仍未说明则直接中性起草。初稿后只引导补充 2～4 个真实缺失的重要变量，不足时不凑数，不默认列出全部。

## 适用场景

适用于云软件订阅、SaaS 平台服务、账号开通、在线系统使用、API 服务、软件运维服务等。

不适用于软件定制开发、软件著作权转让、单机软件买卖、劳动用工。

## 角色与起草立场

- 甲方通常为客户、订阅方、使用方。
- 乙方通常为服务商、平台方。
- 代表客户：强化服务范围、数据导出、安全、可用性、退款或解除。
- 代表服务商：强化使用限制、账号管理、暂停服务、费用支付、责任边界。

## 初稿与信息补充

服务模式不明确且会影响合同结构时，生成初稿前集中询问；其他信息不要求先补齐。服务名称、服务期限、账号/用户数量、费用、开通时间、服务范围、付款方式等具体事实，缺失时先用原子化占位符生成完整初稿，初稿展示后按需补充。

对应场景已经出现时，初稿展示后还可补充 SLA、数据导出、个人信息处理、API、私有化部署、续费、技术支持。

## 具体信息处理

| 变量 | 初稿缺失处理 |
|---|---|
| 服务名称/模块 | 使用原子化占位符，初稿展示后补充 |
| 服务期限 | 使用原子化占位符，初稿展示后补充 |
| 费用 | 使用原子化占位符，初稿展示后补充 |
| 账号或用量 | 使用原子化占位符，按需补充 |
| 开通时间 | 使用原子化占位符，按需补充 |
| 服务范围 | 初稿先写完整服务机制，具体范围按需补充 |

## 可默认写入内容

- 服务商按约开通账号和服务。
- 客户按约支付费用并按约使用账号。
- 客户负责账号权限管理和使用人员行为。
- 服务商采取合理安全措施保障系统运行和数据安全。
- 合同终止后按约处理数据导出、删除或保留。

## 条件触发变量

- API 服务：补充调用量、限流、密钥安全、接口变更。
- 个人信息处理：补充处理目的、范围、安全措施、委托处理。
- 私有化部署：转用技术开发/部署服务条款。
- SLA：补充可用性、维护窗口、故障响应、服务补偿。
- 定制功能：拆出开发内容、验收和知识产权。

## 标准章节结构

首部：标题后直接列明各方信息（不加小标题，不作为编号条款）。

1. 服务内容
2. 账号、权限和开通
3. 服务期限
4. 服务费用与支付
5. 服务支持和 SLA
6. 用户使用规范
7. 数据安全和个人信息保护
8. 知识产权
9. 服务变更、中断和暂停
10. 续费、终止和数据处理
11. 保密
12. 违约责任
13. 通知与送达
14. 争议解决
尾部：签署区（不作为编号章节）。

## 每章起草要求

- 服务内容：列明模块、功能、版本、账号数、用量限制。
- 开通：写明开通时间、管理员账号、权限配置。
- 费用：写明订阅费、增值服务费、超量费、付款和发票。
- SLA：写明支持时间、响应等级、维护窗口、不可用例外。
- 使用规范：禁止转售、攻击、爬取、违法内容、超授权使用。
- 数据：写明数据归属、备份、安全、导出、删除、委托处理。
- 暂停：写明欠费、违法使用、安全风险等暂停条件和恢复。

## 输出前强制自检与自动补写

在通用合同质量框架基础上，逐项检查并自动补齐：服务版本与功能范围、账号和使用限制、开通/续费/计费、可用性和计划维护、故障响应与服务补救、客户配合、数据权属与处理边界、安全措施、数据备份与数据导出、暂停/恢复、终止后的迁移/返还/删除。不得只写“提供软件服务”或“保障系统稳定”而没有服务边界和故障处理机制。

用户未提供具体 SLA 数值时，不编造可用率、响应时长或赔偿倍数；应写清故障申报、合理处理、计划维护通知和重大持续故障下的补救/解除路径。终止时必须说明数据导出窗口或双方确认的迁移安排，以及届满后的账号关闭和数据处理。

## 禁止写法

- 服务范围只写"提供系统使用"。
- 没有账号数量、服务期限或费用。
- 数据归属和终止后处理缺失。
- 服务商承诺绝对不中断。
- 客户无限制使用所有功能和接口。

## 生成前边界

生成草稿时应覆盖服务范围、账号、期限、费用、SLA、数据、安全、暂停终止、违约责任。正常规则适配不向用户说明，只有用户信息明显冲突时才简短提醒。

## 待补充信息规则

以下是内部核对用的字段候选，初稿后只挑实际缺失的 2～4 项友好引导：服务模块、账号数量、服务期限、费用、SLA、数据导出期限。技术支持联系人仅在用户要求约定支持对接机制时列入。
