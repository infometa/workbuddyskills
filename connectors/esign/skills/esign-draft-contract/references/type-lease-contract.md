# 租赁合同起草规则

信息收集遵循 [通用规则](intake-common.md)：下列字段为按场景选用的候选，不要求首稿前补齐；首轮询问缺失立场，回复仍未说明则直接中性起草。初稿后只引导补充 2～4 个真实缺失的重要变量，不足时不凑数，不默认列出全部。

## 适用与分型

适用于房屋、商铺/场地、设备、车辆等租赁。先识别租赁物类型；房屋租赁高频，但用户未说明时不得直接假定为房屋。

不适用于借用、融资租赁、住宿服务或以物业服务为核心的交易。商铺、设备、车辆不能机械套用住宅条款。

## 角色与起草立场

- 甲方通常为出租方，乙方为承租方；底稿已有角色时沿用。
- 代表出租方：强化租金、用途、合规使用、转租/装修限制、损坏赔偿和按期返还。
- 代表承租方：强化出租权属/权限、可正常使用、维修、安静使用、押金退还、提前解除和交付瑕疵救济。

## 初稿与信息补充

租赁物类型或交易模型不明确且会影响合同结构时，生成初稿前集中询问；其他信息不要求先补齐。租赁物可识别信息、用途、租期、租金、支付周期/节点、押金、交付时间、用户代表哪一方等已能从底稿或产权/设备清单提取的，不得重复询问。

缺失的具体事实先用原子化占位符生成完整初稿；初稿展示后，可按需补充附属设施/交付清单、物业水电、维修、转租、装修、免租期、保险、证照、续租。邮箱、联系人、签署地点未提供时不问也不生成；签署区按全局规则只保留空白字段 `签署日期：`。

| 核心变量 | 初稿缺失处理 |
|---|---|
| 租赁物及定位信息 | 使用原子化占位符；房屋写地址，设备/车辆写型号和编号 |
| 用途 | 影响使用限制或许可时，可在初稿前确认 |
| 租期及起算 | 分别使用占位符，并与交付日区分 |
| 租金、周期和付款节点 | 分别使用占位符，初稿展示后补充 |
| 押金 | 用户未采用押金时不强行添加；已采用则在初稿展示后补充金额 |
| 交付及返还状态 | 可依据清单/照片/底稿形成机制 |

## 起草质量闭环

### 租赁物与出租权限

- 房屋写明地址、用途、面积口径及附属设施；设备/车辆写名称、品牌型号、序列号/车牌号、数量和现状。
- 写明出租方有权出租并配合提供必要权属或授权材料；存在共有、转租、抵押等情况时按用户资料处理，不编造权属状态。
- 清单、照片、表计读数、钥匙/配件作为交付附件时写明附件名称和确认方式。

### 租期、交付与计租

- 区分合同期限、交付日、租金起算日、免租期和到期返还日，避免同一日期承担多个未说明的含义。
- 交付应有现状确认和异议处理；无法正常使用时写明维修、延后计租、减租或解除等与场景相符的救济。
- 续租优先权或协商续租只有用户要求时写入，并明确通知窗口；不自动生成具体通知天数。

### 租金、押金与费用

- 写明租金金额、周期、付款节点、支付方式以及含税/开票口径；不编造税率。
- 押金不得默认抵作最后一期租金；写明可扣项目、证据、结算期限和余额退还条件，不得使用“出租方可任意扣除”。
- 物业、水电、燃气、网络、停车、税费、维修、保险等按租赁物类型分配，并写明抄表/账单和结算方式；未触发的费用不堆砌。

### 使用、维修与风险

- 区分自然损耗、主体/基础故障、日常耗材和承租方不当使用造成的损坏。
- 维修条款写明报修、响应、紧急处置、费用和因维修影响使用的处理。
- 转租、装修、改造、用途变更按场景设置书面同意、审批、成果归属和恢复原状；未触发时可简写或省略。
- 设备/车辆补充操作规范、保养、故障停租、事故、保险、灭失及替代设备机制。

### 解除、返还与结算

- 分别约定逾期租金、擅自转租/改变用途、长期无法使用、权属瑕疵、提前退租等解除条件及催告机制。
- 返还条款写明时间、地点、状态、合理损耗、物品清单、费用结清、验收异议和逾期占用责任。
- 押金退还与返还验收、费用结算相衔接，但不得让无期限的“全部结清后”阻断退还。

## 条件模块

- 住宅：居住人员、物业规则、家具家电、养宠/扰民等仅按用户需求加入。
- 商铺/场地：经营用途、证照、消防、物业、招牌、装修、免租期、停业风险。
- 设备：安装、调试、操作、维护、停机、保险、替代设备。
- 车辆：驾驶资格、里程、油电、违章、事故、保险、维修、跨区域使用。

## 必须覆盖的结构

首部当事人信息；租赁物与用途；租期/交付/计租；租金押金和费用；交付验收；使用维修；按需加入装修/转租；解除；返还与结算；违约；不可抗力；争议解决；按需加入通知送达；尾部签署区。

## 输出前强制自检与自动补写

先执行通用合同质量框架，再检查本节七项闭环。任何已触发节点缺失或仅有概括性一句话时，必须补写或重写后再向用户展示；设备、车辆等租赁不得遗漏交接确认、维修停机、替换/解除、事故损害、返还和最终结算等已触发机制。

## 禁止写法与自检

- 不把租期、交付日、计租日和返还日混用。
- 不写押金可由一方“自行认定并任意扣除”。
- 不把全部维修责任无条件推给一方，不区分原因。
- 不遗漏返还标准、合理损耗、费用结清和押金退还的衔接。
- 生成前检查“租赁物可识别—有权出租—计租清楚—费用可结算—维修有分工—返还有标准—押金可退”七项闭环。

## 待补充规则

内部核对以下核心字段，初稿后只挑实际缺失的 2～4 项友好引导：租赁物、用途、租期/起算、租金、支付、交付/返还。押金、费用、装修、转租等仅在场景已触发时列入；邮箱、联系人、签署地点不得因缺失列入。签署区只保留空白字段 `签署日期：`，不列入待补充项。
