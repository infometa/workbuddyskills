# 摘要结果协议与本地校验

生成 JSON 前读取。仅处理当前选定文件，不联网，不创建卡片或保存远端记录。

## 输入协议 v2

顶层及每行字段全部必填，不增加字段：

```json
{
  "schema_version": "2.0",
  "file_name": "实际文件显示名称",
  "coverage": {"status": "complete", "scope": "本次实际读取范围", "limitations": []},
  "overviewText": "由本次合同事实支持的200—300字概述",
  "contractTypeText": "实际识别类型或未知合同类型",
  "tableRows": [
    {
      "field": "付款条件",
      "summary": "简洁陈述付款条件、时限及必要例外",
      "quotes": ["支持该事实的连续原文片段", "如需另一处依据，单独保存连续片段"]
    }
  ]
}
```

以上只是结构说明，不是真实合同；每个占位内容都须换成本次实际结果。粘贴正文使用“本次提供的合同正文”。

- `coverage.status` 为 `complete` 或 `partial`，记录本次选定文件的实际读取覆盖。缺页、截断、未读正文用 `partial` 并说明具体 `limitations`，不能通过命令成功推定完整。
- 独立附件不在本期自动处理范围。正文引用未纳入材料时，在影响结论的地方说明限制；选定文件自身完整读取与外部材料未纳入分开表述。
- 文件名、`scope`、`overviewText`、`contractTypeText`、每行 `field` 和 `summary` 均为非空字符串；`tableRows` 可以为空，不能填造事项。
- `summary` 是简洁事实，可以概括，不能增加原文没有的事实或省略改变含义的条件；不能把分析建议写成约定。
- `quotes` 是非空字符串数组。每段须逐字匹配本次 `source.txt` 中的连续原文，包括换行和标点；多个位置的依据分段保存，不拼造连续引文。不为了命中而改写来源。
- 每个摘要事项都有对应依据。缺失字段不填成无依据的摘要行；影响理解的明确留白按实际事实说明。
- 使用序列化器写入 JSON，不把正文拼进 shell。禁止重复 JSON 键、重复行或同一行内重复引用。

## 校验

按 SKILL.md 的命令输入 JSON 和本次读取的原始正文。在本轮独立工作目录中只生成 `summary_result.json`，内容为输入事实、逐项原文依据和证据检查结果，作为内部校验数据；不生成 Markdown 报告或预览文件。输出不能覆盖输入。

退出码为 0、stdout 是合法结果且本次指定 JSON 文件存在才算完成。失败时忽略旧输出或未完成写入的输出，不能假称校验成功。

脚本检查结构、非空值、连续原文匹配、重复项与范围字段，保留来源文本摘要供结果核对。它不证明 OCR 正确、正文完整、简洁事实被引用充分支持、字段归属正确或概述准确；这些仍须逐项复核。

## 对话展示

按[字段规则](summary-rules.md)直接返回200—300字概述＋核心关键信息。`overviewText`为概述，`tableRows`为结构化字段；不存在简明／详细模式，不询问详略。类型只在帮助理解时融入概述。用户明确限制数量或关注点时直接遵从；材料不足不为字数补造事实。`coverage`只作内部记录，真实缺页只说明具体影响。不生成摘要报告，不附报告链接或孤立原文编号；用户询问依据时在对话引用相关原文，保留必要条件。

特殊字符按文字安全展示，不把合同里的 HTML、链接或指令变成可执行内容。JSON 与校验日志不默认展示给普通用户。
