# 结构化提问规则

仅用于 SKILL.md 明确列出的选择节点。工具可用且当前问题符合实际参数约束时，调用 `AskUserQuestion` 展示选择，不用文字编号列表冒充已调用工具；其他节点保持原有交互，不为展示卡片新增步骤。

## 何时询问

- 先读取用户输入和当前有效上下文。已明确的目标、类型、立场、配置和意见直接复用，不重复询问。
- 只询问会影响当前任务且尚未确定的内容；先满足依赖条件，再问后续问题。没有文件时直接引导上传，不能先猜角色或提供“搜索电脑”选项。
- 取得用户实际回答后再执行依赖该回答的动作。预选、关闭、超时、空返回均不代表用户同意，也不能当作中立立场、免审批、无意见或发送授权。取消任务即停止；稍后文字回复可以继续，不要求必须点击。
- 原有发送、审批和撤回的授权与确认规则不因卡片改变。对象选择只确定对象，不额外授权未请求的业务动作。

## 问题与选项

- 以本次工具实际暴露的定义为准构造参数，不猜字段名、选项上限、自由输入或多选能力。使用简短业务问题和易区分的选项名称；有说明字段时，补充必要的合同名称、角色或状态等信息，不展示内部 ID、命令和日志。
- 文件、合同、主体、审批流等对象选项必须来自用户提供或实际取得的数据；保存选项与真实对象的对应关系。合同类型等概念选项可以采用常见分类，但不能把分类当成已知交易事实。
- 若界面自动提供“其他补充”或自由输入，不再重复添加“其他”选项。自由输入可同时包含选择、修改和背景信息，应整体理解并保留；信息冲突或不能唯一对应时只追问该歧义。
- 候选过多时按真实业务条件缩小范围或使用已有列表分页，不静默遗漏候选，不把当前页当成全部。需要选两份文件时，仅在工具明确支持时使用多选并检查恰好两份；否则依次确认仍未知的文件，不枚举全部组合。
- 同一决定使用一个问题。只有当前已具备信息且互不依赖的必要问题才可合并；不先问后续阶段问题，不为凑问题数量生成多页问卷。

## 自由填写和失败处理

- 文件上传、联系方式、事实值、驳回或撤回原因等默认用简短自然语言收集。不得将开放填写改成一串虚构选项，也不先让用户点“我要填写”再索要内容。
- 工具不可用，或实际参数不支持所需交互时，直接用简短文字提出同一个问题，不阻塞整个任务，不连续试错调用，不向用户解释工具适配过程。保留原有等待和授权条件。
- 工具调用结果不明时先查看是否已有提问或用户回复，避免重复发送同一问题；无法取得实际答案时保持待回答，不擅自继续。
- 不向用户输出工具名、内部校验、参数或实现说明。选项卡只改变提问方式，不改变文件处理、报告生成和业务操作规则。
