# 合同流程管理

执行对应业务前读取本文件和[参数说明](parameters.md)，同时遵循 SKILL.md 的对象绑定及结果规则。

**流程列表查询**
1. 执行 `esign sign process list`，根据用户条件追加列表查询参数。常用参数：`--doc-query-type`、`--process-status-list`、`--title`、`--contract-no`、`--page-num`、`--page-size`。补充筛选参数：`--process-biz-type-list`、`--time-range-type`、`--begin-time-in-mill-sec`、`--end-time-in-mill-sec`、`--account`、`--person-name`、`--subject-name`、`--initiator-name`、`--initiator-subject-name`。
2. 按结果规则展示总数、清晰序号及名称、状态等可读信息，内部 processId 和操作编码只保存在上下文，不展示给普通用户；成功空结果用文字说明，当前页为空但 `total>0` 时提示调整页码。
3. 保留 `processId`、`processName`、`processStatus`、`processStatusDesc`、`operations`、`dedicatedCloudId`，供后续操作使用。
4. 结果过多时最多展示 100 条并提示缩小范围。
5. “待我签署”使用 `--doc-query-type 5 --process-status-list 2`；“我发起的”使用 `--doc-query-type 1`。CLI 默认范围不能冒充用户要求的“全部”，明确查全部时使用 `--doc-query-type 0`。

**单流程访问链接 / 单流程签署**
1. 获取 `processId`；用户说"第 N 条"时使用最近一次有效合同列表中的第 N 条。
2. 凡是单个流程的打开、查看、填写、签署诉求，都使用 URL 工作流，不进入 batch 工作流。多合同签署不得拆成多次本流程调用；仅在用户明确要求或同意逐份签署时，才分别取得单份入口。
3. 执行 `esign sign process url --process-id '<processId>'`。
4. 返回实际 URL；若未获取到 URL，返回流程名称或可识别的业务编号并提示用户到系统内打开，不展示内部流程 ID，不自行拼造链接。

**撤回流程**
1. 获取目标流程；缺少流程信息时先执行列表查询。
2. 用户请求的必须是撤回，不能将作废替换为撤回试探。当前能力不支持用户所需动作时直接友好说明暂不支持。仅当流程状态为 `填写中`/`签署中`/`合同审批中` 且 `operations` 包含 `revoke` 时才允许撤回，否则说明该流程当前不支持撤回并中断，不发送撤回命令验证。
3. 缺少已明确绑定当前目标的撤回原因时，必须纯文本收集（必填），提示 `请填写撤回原因（必填）`；原因必须与当前 `processId` 绑定，换流程需重新收集。
4. 按已确认的字符限制核对原因或意见；明确不支持的字符提示用户修改，不静默删改。没有精确限制时，不因字符少见或自行推测而拦截；服务端返回字符错误时，说明受影响字段和可读原因后请用户修改。
5. 撤回原因校验通过后，直接执行 `esign sign process revoke --process-id '<processId>' --revoke-reason '<撤回原因>'`。

**下载流程文件**
1. 获取下载范围；缺少流程信息时先执行列表查询。
2. 每个流程必须在实际返回的 `operations` 中包含 `download`，否则提示不支持下载并中断。
3. 批量下载必须校验 `dedicatedCloudId`：全部为空/缺失，或全部相同且非空才允许；公有云与专属云混合或多个专属云混合时中断。
4. 执行 `esign sign process download --process-id '<processId>'`；批量下载时多个流程 ID 用英文逗号拼成同一个参数：`esign sign process download --process-id '<processId1>,<processId2>'`。不要使用 `--process-ids`，该参数属于批量签署，不属于下载。
5. 命令通常直接输出 `下载地址：<URL>`；返回该 URL。若返回 `goToJobCenter`/任务中心地址，提示前往任务中心；若返回 `failReason`，说明失败原因。

**批量签署入口**
1. 本分支获取真实批量签署入口，由用户打开页面完成签署，不要求WorkBuddy具有批量签章或平台专用卡片能力。不能因无法代签而拒绝获取入口，也不能只解释方法。
2. 查合同后用户说“这几份一起签”“把这些都签了”“签第1和第3份”等，不要求出现“批量”二字，直接复用有效列表的真实processId。范围不明确才澄清，已明确不重复确认。用户要求全部时核对筛选范围和分页，不把当前页当全部。
3. 多流程使用batch；明确只选一份时使用单流程URL。不能自行剔除对象后将单份入口当作原批次成功。
4. 核对真实流程状态、待当前用户签署范围及操作项。存在明确非签署中或不可签对象时，指出具体合同并让用户调整范围；信息缺失或过期则先只读补查，不把字段未返回直接当成无权限。可查看不等于可签，不能让用户口头确认代替权限。
5. 范围和条件齐备后执行 `esign sign process batch --process-ids '<processId1>' --process-ids '<processId2>'`，完整选中范围放在同一次调用中，每个ID一个参数；禁止逐份调用process url，也禁止按单个ID循环调用process batch。不改用单份URL集合代替批量入口。
6. 命令成功且返回真实redirectUrl时，仅给本次完整选中范围对应的一个可点击批量入口，合同名称另作简短列表或明确范围，提示“打开批量签署页面完成签署”。取得链接不代表已签署，卡片不可用但有真实URL时仍可交付。
7. 当前环境明确拒绝批量能力时停止重复尝试；旧评测的沙箱失败、缺卡片、临时超时或字段缺失不能推断所有WorkBuddy环境不支持。不自动切生产或换企业试探。未获有效URL不拼链接、不谎称已生成。
8. 未取得有效批量入口时，简短说明“未生成批量签署入口”及实际原因；结果不明就说明暂未取得有效入口，不猜测能力不支持。不自动调用单份链接命令，也不展示已缓存的多个单份链接作为替代。只有用户明确要求或同意改为逐份签署后，才分别核对可签条件并取得真实单份入口，清楚标明是逐份签署；不替用户签署。用户后续询问完成情况时只读查询实际状态，不根据打开链接推断完成。
