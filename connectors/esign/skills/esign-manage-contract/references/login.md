# 登录与恢复

仅用于访问 e签宝平台前的账号准备和登录失效恢复，不改变业务操作授权、意见收集或意愿认证规则。

1. 先按[CLI 检测与安装](cli-bootstrap.md)保证命令可用。已有本次有效连接、身份和环境时直接继续业务；登录状态未知或业务明确返回未登录／过期时执行 `esign auth status`。状态查询自身失败或信息不明时说明实际受阻原因，不推断成未登录，不循环发起登录。
2. 确认未登录或过期后，执行 `esign auth login`，让 CLI 打开浏览器并由用户完成授权，不仅回复“请先登录”。沿用已确认的环境；当前明确为 e签宝沙箱或用户明确要求沙箱时，登录命令加 `--sandbox`。WorkBuddy 的运行沙箱或审核沙箱不等于 e签宝沙箱，不能因此添加该参数；已有环境不能自动切换。
3. 浏览器无法打开时才执行 `esign auth login url --no-browser`，将返回的真实授权链接交给用户。若该分步流程要求授权码，仅使用用户为本次登录明确提供的授权码执行 `esign auth login code --code '<本次授权码>'`；沙箱登录的两步均带 `--sandbox`。授权码仅用于本次兑换，不回显、不写入报告或日志；不索取密码、访问令牌或读取凭据文件。未完成授权、用户取消或宿主禁止执行时保留原请求，说明需要完成的步骤，不虚构登录成功。
4. 登录完成后用 `esign auth status` 确认可用身份和环境。若 CLI 返回未完成实名及真实认证链接，提供链接等待用户处理，不把实名当作登录失败而反复授权。用户完成实名后先执行 `esign auth tenant list`，按用户已明确的企业或引导其从真实候选中选择，再用 `esign auth tenant set '<tenant-id>'` 完成企业设置；不得替用户选择企业。只有该查询明确返回未登录或过期，才重新登录。账号、企业或环境实际变化时按主流程清理旧对象上下文并重新查询。
5. 恢复成功后继续原请求，不要求用户重新描述。查询可以重试；写操作仅在尚未调用，或已明确未提交／未执行时继续。先前写操作超时、断连或结果不明时，先按[恢复规则](recovery.md)只读核实，不能因登录恢复而重复审批或撤回。不要将账号登录成功视为审批意愿认证完成。

普通回复只提供授权／实名入口、当前受阻事项或业务结果，不展示内部检查步骤与原始返回。无权限、业务校验失败和意愿认证要求分别走对应规则，不通过反复登录解决。
