# 错误处理与恢复

1. 按实际失败类型处理，不统一以“无法执行”结束：
   - CLI 缺失先按[CLI 检测与安装](cli-bootstrap.md)恢复；登录未知、未登录、身份失效按[登录与恢复](login.md)检测和授权。恢复成功后继续尚未执行的原步骤；已调用的写操作按第4条先核实结果，不因重新登录而直接重放。
   - 实名限制提供 CLI 返回的真实实名入口，完成后按登录恢复规则核对身份和企业；无权限不改成重新登录，不自动换账号、企业或环境。
   - 查询明确成功且数据为空，按实际范围报告无记录；查询失败、超时或数据无法判断时不能报无记录。对象已处理、操作不可用或其他明确业务失败时停止依赖该条件的步骤，仅给实际可行的恢复路径。
   - 确认当前能力不支持时说明暂不支持，不反复调用，不用另一业务操作替代试探。审批识别为个人空间或返回个人空间限制时，提示 `个人空间不支持审批管理，请切换到企业空间后重试` 并中断；不能自行选择企业。
2. 缺少 `approval-code`、`task-id` 或批量任务数据时，先查询或询问，不同意/拒绝；`--operate-data` 为空数组或格式错误时停止并修正任务数据。
3. 审批不以意愿认证查询作为统一前置，具体分支见[审批流程](approval.md)。当前任务已明确需要认证时，停止无认证提交并提供真实审批入口；查询认证返回空数据不等于需要认证或免认证，也不单独阻止已授权且信息齐备的首次审批提交。不得让用户口头指定免认证。审批写操作失败、超时或结果不明时先核对实际结果，不用认证查询空结果作为重放理由；审批访问地址只提供页面处理入口，不证明认证或审批完成。
4. 同意、拒绝、批量审批或撤回返回结果不明/连接中断时，不盲目重放写命令。可查询对应列表核对状态；列表不足以证明本次批量结果时说明无法确认，并使用 CLI 已返回的任务详情/系统入口核查。不编造独立的批量结果查询命令。
5. 用户追问本次批量成功/失败数量时读取已保存结果；没有可验证结果时明确说明。CLI 已在内部轮询，Agent 不通过重复 batch-agree/batch-refuse 进行轮询。
6. 列表时间优先使用 CLI 返回的展示字段；原始毫秒时间戳只用于排序、筛选和追溯，不自行转换展示。自然语言筛选日期使用用户明确时区或宿主已知时区；未知时先确认，不能猜测。
7. 下载明确报 `unknown flag: --process-ids` 时，改成 `esign sign process download --process-id '<processId或逗号分隔的ID>'` 后重试；不得用于重放其他结果不明的写操作。
8. 审批列表模板错误提示即使误写 `esign sign process list --help`，仍使用 `esign sign approval list --help` 核对审批参数。
9. 卡片展示失败与业务失败分别处理。已成功的操作仅重试展示或降级文本；无有效 URL 时返回对象的可读名称或业务编号和系统内打开建议，不展示内部标识，不构造链接。

10. 服务端明确当前环境不支持批量签署时不重复尝试；不能把历史环境报错、卡片工具不可用、字段缺失或单次超时泛化为WorkBuddy不支持批量入口；未取得有效批量入口时，说明“未生成批量签署入口”及实际可读原因，不自动获取或展示多个单份链接。仅在用户明确要求或同意改为逐份签署后才提供真实可签的单份入口；不把可查看说成可签，不悄悄排除不可签对象执行剩余项。已有真实批量URL但卡片展示失败时，直接以可点击链接交付同一批量URL，不拆分为单份链接。暂时超时与明确不支持分开处理，结果不明先只读核查。
11. 下载明确失败后，原请求已授权的逐份导出可作为合理替代，逐份核对下载权限、状态和实际结果；这不授权重放签署、审批或撤回。
