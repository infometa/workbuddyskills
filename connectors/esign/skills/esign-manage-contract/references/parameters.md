# 业务参数

来自现有管理与审批命令约定；仅给支持的命令传参，不给所有命令追加同一种输出选项。参数值使用真实上下文和返回结果，不照抄示例 ID。

## 合同管理参数
* `--doc-query-type`：`0` 全部，`1` 我发起的，`2` 我收到的，`3` 抄送我的，`5` 待我操作，`6` 待他人操作，`7` 已完成。
* `--process-status-list`：`1` 填写中，`2` 签署中，`3` 合同审批中，`4` 已撤回，`5` 已拒绝，`6` 已过期，`8` 已完成，`9` 合同审批驳回，`10` 合同审批撤回。
* `--process-biz-type-list`：流程业务类型列表，可重复传入数字类型值；仅当用户明确指定业务类型时使用。
* `--time-range-type`：时间范围类型，`1` 发起时间，`2` 完成时间，`3` 签署截止时间；配合 `--begin-time-in-mill-sec` 和 `--end-time-in-mill-sec` 使用。
* `--begin-time-in-mill-sec`、`--end-time-in-mill-sec`：开始/结束时间，毫秒时间戳。用户只给自然语言日期时先换算为毫秒时间戳再传入。
* `--title`：流程标题/合同名称，列表查询参数；用户说合同名称、流程标题、processName 或 title 时使用本参数。
* `--contract-no`：合同编号，列表查询参数；用户提供合同编号、contractNo 或 contract-no 时使用。
* `--account`：账号标识；用户按账号、手机号、邮箱等账号标识筛选时使用。
* `--person-name`：账号名称，列表查询参数。
* `--subject-name`：主体名称，列表查询参数。
* `--initiator-name`：发起人姓名，列表查询参数。
* `--initiator-subject-name`：发起主体名称，列表查询参数。
* `--page-num`、`--page-size`：列表查询分页参数，`page-size` 最大 100。
* `--process-id`：单流程访问链接、撤回、下载必填；下载多个流程时使用逗号分隔的单个 `--process-id` 值。单流程签署也走这个参数。
* `--process-ids`：仅用于多流程批量签署，可重复传入；不要用于下载，也不要用于单流程签署。
* `--revoke-reason`：撤回原因；不得使用 CLI 默认值，必须使用用户已明确提供或补充的当前目标原因。

## 审批参数
* `--query-type`：`0` 企业全部审批，`1` 我收到的，`2` 我发起的，`3` 待我审批，`4` 我已审批。
* `--approval-type`：`1` 用印审批，`2` 合同审批。
* `--approval-name`：审批名称，列表查询参数。
* `--approval-codes`：审批编码列表，可重复传入；用户提供多个审批编号/approvalCode 且用于列表筛选时使用。
* `--approval-status-list`：审批状态列表，可重复传入：`1` 审批中，`2` 审批通过，`3` 审批拒绝，`4` 审批撤回，`5` 审批终止。
* `--contract-no`：合同编号，列表查询参数。
* `--initiator-name`：发起人名称，列表查询参数。
* `--initiator-subject-name`：发起人主体名称，列表查询参数。
* `--participant-name`：参与人名称，列表查询参数。
* `--participant-subject-name`：参与人主体名称，列表查询参数。
* `--min-create-time`、`--max-create-time`：创建时间下限/上限，毫秒时间戳。用户只给自然语言日期时先换算为毫秒时间戳再传入。
* `--min-operate-time`、`--max-operate-time`：操作时间下限/上限，毫秒时间戳。用户只给自然语言日期时先换算为毫秒时间戳再传入。
* `--process-id`：流程ID，列表查询参数。
* `--page-num`、`--page-size`：列表查询分页参数，`page-size` 最大 100。
* `--approval-code`：审批编号；访问地址、同意、拒绝必填。
* `--task-id`：审批任务ID；同意、拒绝、意愿认证必填。
* `--reason`：审批意见/拒绝原因；同意审批只在尚无当前目标绑定的意见时提示，用户明确表示“不填写”“无”“无意见”“没意见”“空着”时传 `--reason '无'`，不省略、不传空值；未回答时先询问；拒绝审批必填明确原因。不得使用 CLI 默认值冒充用户输入。
* `--approval-tasks`：意愿认证任务 JSON，可重复传入，格式为 `{"approvalCode":"审批编号","taskId":"审批任务ID"}`。
* `--will-auth-id`、`--will-auth-type`：仅在意愿认证返回需要认证且用户完成认证后传入同意/拒绝/批量命令。
* `--operate-data`：批量同意/拒绝时的审批任务 JSON 数组，格式 `[{"approvalCode":"xxx","taskId":"xxx"}]`（必填）。
* `--remark`：批量同意/拒绝时的审批意见/驳回原因；批量同意只在尚无当前任务集合绑定的意见时提示，用户明确表示“不填写”“无”“无意见”“没意见”“空着”时传 `--remark '无'`，不省略、不传空值；未回答时先询问；批量拒绝必填明确原因。
