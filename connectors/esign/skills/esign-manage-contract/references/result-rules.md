# 查询与操作结果规则

所有管理与审批分支均适用。

## 列表与空结果

- 先核对命令和业务执行成功，再处理数据。失败、无权限、字段缺失与成功空结果区分。
- 展示实际总数、当前筛选范围、清晰序号及名称、状态、发起人、业务时间等必要信息。首次列表保持简洁，可分页展开；最多展示 100 条时说明未展示范围，不能声称已经列出全部。
- 普通用户无需看到 processId、taskId、内部审批编码或操作编码，保存在执行上下文即可。业务合同编号可用于辨识，不能把所有编号一概隐藏。
- 区分个人已办、企业可见记录与完整流程历史；个人查询无记录不能说整份流程没有历史。总数、当前页条数和分类数量使用同一口径，需要不同口径时明确说明。
- 总数为 0 才按实际查询范围说明空结果；总数大于 0 但当前页为空应提示分页问题。只回显实际使用的筛选条件。
- 文件事实依据正文；流程、任务和状态依据本次实际返回信息。状态时间仅在真实返回时引用，不把获取时间当成更新时间。

## 操作状态

| 实际取得的结果 | 可以向用户表达 |
| --- | --- |
| 访问或签署 URL | 已取得查看、填写或签署入口；不说已经签署 |
| 下载 URL 或任务中心入口 | 已取得下载入口；未实际保存不说已下载到电脑 |
| 意愿认证链接 | 请完成本次任务所需认证；不说审批已通过 |
| 处理中、提交成功但无最终结果 | 已提交或处理中，结果尚未确认 |
| 明确操作成功或最终失败 | 按真实目标与动作报告成功或失败 |
| 批量部分成功 | 分别列实际成功、失败、未知及原因；未返回的数量不猜 |

成功后直接说清处理对象和实际结果，必要时给下一步；批量分清成功、失败和未知，不重复执行来补回复。

实际下载文件后才说明页数、文件变化或签署显示情况；从文件元数据、实际页面及必要的签名数据核实，不凭链接名称或流程状态编造签署信息页。阅读器显示不一致时先核对实际文件和版本，不直接认为用户看错；不通过重新发起合同修复展示。保留原流程、文件与版本关联。此为文件交付核验，不扩成合同签字盖章的风险审查。

具体展示方式按入口的执行规则处理。仅卡片发布成功不代表业务成功；展示失败也不能推断业务失败。

不把技术日志和原始 JSON 展示给普通用户，不输出凭据或内部服务地址。返回的用户访问链接可以展示，但不能根据 ID 自行拼造链接。
