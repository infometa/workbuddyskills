# 教案生成技能（lesson-plan）

把「教师要一份教案」或「备课修订案已定稿」变成「拿到一份可直接用的教案文档」（Word 文档，唯一交付格式）。两部分能力：

1. **教学设计**（我来写）：按新课标核心素养导向，产出目标—活动—评价一致的教学设计（教案的内容层）。
2. **文档渲染**（工具干）：`render_lesson` 工具把结构化 JSON 渲染成中文排版精良的 Word 文档（.docx，唯一交付格式，返回 24 小时有效的免登录下载链接）；PDF 不再提供（用户要 PDF 时如实告知）。

## 两种输入源（先判断走哪条）

- **输入源 A · 直接生成**：用户只给课题 → 走下面「第零步 → 第三步」全流程。
- **输入源 B · 承接备课技能产物**：个人备课已有产物（`./K12/备课/{book_code}/{课文名}/` 下的 00/01/02/04 号文件；04 为修订案，旧目录的 04-共案同构兼容）→ **跳过追问与图谱预检**（数据已在 01-课时图谱档案里），直接解析 Markdown 产物 → 映射成教案 JSON → 渲染教案文档（默认 Word）。映射契约与补齐规则见 **`references/from-lesson-prep.md`**（承接模式必读）。触发话术：「修订案转教案/转 Word」「共案转教案」「把初备/共案/修订案渲染成教案」「把刚才的备课成果出成文档/Word」。

## 第零步：图谱预检（k12-kg 连接器，输入源 A 必做）

1. 调 `kg_health` 确认连接器可用。**不可用 → 跳过本步**，完整走原路径（追问 + 不编造 + 标注「待核对」），并在留痕块注明未连图谱。
2. 可用则 `locate_lesson(keyword=课文名, subject, grade_term)` 定位课时：唯一命中→直接取档案；多命中→列出候选（课文名+册+单元路径）让用户选；无命中（版本/学科不在库）→ 降级原路径。
3. `lesson_context(lesson_id)` 拿课时档案；`kg_ability_profile(knowledge_ids)` 拿素养上溯；`kg_anchor_exercises(unit_id)` 拿单元习题与分布。
4. 图谱已确认的信息（册次/版本/单元/生字表/课标锚）**不再追问、不再凭印象写**——这是本技能最大的质量来源。

工具用法、板块数据映射、降级决策树、校验与留痕的完整约定见 **`references/kg-integration.md`**（动手前必读）。

## 第一步：先追问，别猜

课题信息不全时**必须先问清**，问齐后再动手。缺信息硬写就是编造教材内容。**但图谱已给出的事实不算「缺信息」**：把图谱结论（册/单元/课时建议）给用户确认即可，只追问图谱给不了的。

必问清单（能推断的可以自己定，但要**明说假设**；✅=图谱可直取，免问）：

| 项 | 说明 |
|---|---|
| 学科 + 学段 ✅ | 小学/初中/高中 + 年级——locate_lesson 命中即确认 |
| **册次** ✅ | 「一年级上册」还是「下册」——图谱路径直接给出 |
| 教材版本 ✅ | 统编/人教/湘少/译林/湘教在库；苏教版/北师大版等不在库 → 降级追问 |
| 课时数 | 1 课时 / 2 课时——图谱给建议值（知识点量+课型），**仍由教师确认** |
| 单课时长度 | 默认 40 分钟；有的学校 35 或 45，影响时间分配 |
| 课型 ✅ | lesson_type 直取（课文/略读/习作…），特殊课型（复习/项目式）仍需问 |
| 输出格式 | **Word 文档 .docx（唯一格式**，可直接二次编辑）/ 先看大纲；用户要 PDF 时如实告知不再提供 |

**重要**：「人教版小学语文第一课」这种说法是不完整的——各年级第一课完全不同（一年级《天地人》、三年级《大青树下的小学》、五年级《白鹭》、六年级《草原》）。**不要猜年级**，直接列出来让用户选。

## 第二步：写教学设计

按下面的骨架产出，**结构固定，颗粒度自适应**（要大纲给框架，要完整教案给细节）：

```
教材分析 · 学情分析        ← 有图谱档案时从 lesson_context 直取（映射见 kg-integration.md §2）
教学目标（核心素养四维 × 认知层级，双轴标注）  ← 维度依据 kg_ability_profile 真实素养名；每条目标标主层级〔记忆/理解/运用/分析/评价/创造〕，动词取自 references/bloom.md 对应层级动词库，一课一主层级＋低层铺垫
教学重难点                 ← importance/knowledge_type 佐证
教学准备
教学过程（分钟级时间轴，每环节含：教师操作 · 提问话术 · 设计意图）
板书设计                   ← 生字板书用 board 板块的 spec.blocks（char 逐字，见 schema.md）
作业设计（分层：基础/提升/拓展）  ← kg_anchor_exercises 按难度 1-2/3/4-5 对齐
评价量规（rubric）
教学反思提示
```

写作原则（详见 `references/design-principles.md`）：

- **以生为本**：不写"教师讲解…"这种填鸭式描述，优先设计**启发式提问、探究任务、同伴互动**。
- **目标标认知层级**：每条目标标〔记忆/理解/运用/分析/评价/创造〕之一，动词从对应层级动词库选、活动从该层级教师行为清单选 2–4 条，评价方式与层级匹配（速查 `references/bloom.md`）。
- **提问话术要具体**：写"「这个小朋友他的头顶上是——？」"而不是"引导学生观察"。
- **每个环节标注设计意图**：说明这个活动达成了哪条目标（目标—活动—评价一致性）。
- **环节时间加总要 ≈ 课时长度**：40 分钟课，各段之和必须是 40。

图谱数据纪律（有档案时）：
- 生字表、页码、课标锚**逐字直取**，不凭印象；课标原文以 `kg_std_items` 的 text 为准。
- node_id / 课标 code 留在留痕块，不进教案正文（详见 kg-integration.md §2 末）。
- 图谱查不到的事实 → 标注「待核对」，不混用模型印象与图谱数据。

**出稿前校验**：教学设计写完、渲染前，把课时切分翻译成 plan 结构调 `check_lesson_plan(lesson_id, plan)`——duration_mismatch 与 foreign_* 警告必须修，info 级标注归属即可（plan 结构与判读见 kg-integration.md §4）。图谱降级时此步跳过，手工加总时间轴。

## 第三步：渲染教案文档（仅 Word）

把教学设计写成教案 JSON，可先落盘 plan.json 留档（结构见 `references/schema.md`，完整范例见 `assets/example-tiandiren.json`）。

**渲染主路径——`render_lesson` 工具**（k12-kg MCP 服务端渲染，不依赖本机 Python）：

- `render_lesson(plan_json=<教案 JSON>)`：渲染 Word 文档（docx，教师可直接二次编辑），工具仅支持 docx——2026-10-16 起 PDF 支持移除，用户要 PDF 时如实告知，不要手写 PDF 替代；
- 返回 **24 小时有效的免登录下载链接**：先下载落盘到产物目录（或把链接直接给用户），链接时效要告知用户。

**渲染失败的处理**（服务不可达 / 工具报错）：把教案 JSON 落盘到产物目录留档（留档的 plan.json 就是重渲染的输入），告知用户服务恢复后说一声即可用同一 JSON 重试；不要现场手写文档替代。

渲染完成后，用 `present_files` 把文档呈现给用户。

**留痕（默认带）**：sections 末尾加一个 `text` 块「数据来源与 AI 辅助」——图谱查询统计 + AI 起草范围 + 待教师核对项；格式与降级写法见 kg-integration.md §5。教研合规要求，不是可选项。承接模式（输入源 B）的留痕改为引用修订案三件套，见 from-lesson-prep.md §4。

## 承接流程（输入源 B：备课技能产物 → 教案文档）

1. **定位产物**：用户给路径直接用；没给则在 `./K12/备课/` 下按课文名找目录，缺什么列什么让用户确认。
2. **读产物**：`04-修订案-第N课时.md`（首选；旧目录的 `04-共案-…` 同构兼容；无修订案用 `02-初备教案-第N课时.md`）+ `01-课时图谱档案.md`（生字表/知识点/前序的追溯源）+ `00-课时规划.md`（总课时数与切分）+ `03-研讨-意见卡片.md`（附录一原文源）+ 全部 `05-二次备课-NN.md`（涉及目标/过程修订的并入最新状态，迭代记录为附录二原文源）。04 内的「## 目标↔知识点映射表」（修订案独有，标题是机读契约）为**附录三原文源**。缺 03/05 时如实跳过对应附录并留痕注明，不编造；02 初备退用时无映射表，附录三同样跳过注明。
3. **映射 JSON**：按 from-lesson-prep.md §2 映射表把用纸结构翻成教案 JSON——共用板块（教材分析/学情分析）进 meta，每课时一个 `band` + `phases`。
4. **补两块**：用纸没有的**板书设计**（生字取自 01 档案 characters）与**评价量规**（取自修订案「目标↔知识点映射表」的评价点列）——补齐属设计判断，留痕注明。
5. **附录留痕（默认带，教研合规）**：03/05 记录与映射表原文照录进教案——**附录一「AI 研讨记录」**（03 全部意见卡片逐条：编号/提出人/针对板块/建议/依据类型/图谱佐证/采纳状态，含教师回应纪要）、**附录二「二次备课推演记录」**（05 逐轮迭代，教师反馈条目保留来源标注）、**附录三「目标↔知识点映射表」**（04 各课时映射表全表转录，含 node_id 与能力上溯列——附录属教研留痕域，不受「ID 不进正文」纪律约束）。置于全文末尾、数据来源留痕块之前；多课时合并时附录只出现一次。用户明确说不要附录时可省略，留痕块注明「应用户要求未附」。
6. **不重复校验**：04 修订案已含 check_lesson_plan 覆盖检查结论，直接引用进留痕块；仅当用户要求复核时才重调 `check_lesson_plan`。
7. 渲染与呈现同第三步。

## ⚠️ 关键坑（务必遵守）

**中文引号必须用直角引号「」『』，严禁弯引号 “ ”**

原因：写入含中文的 Python / JSON 文件时，弯引号会被转码成 ASCII 直引号 `"`，直接截断字符串 → 语法错误或 JSON 解析失败。

- 表示"小于/大于/与"用全角 `＜ ＞ ·`，不要用半角 `< > &`。
- 需要嵌套引用时用 `「外层『内层』」`。
- **不要用手写脚本批量替换引号**——会误伤代码里的字符串定界符。写的时候就写对。

其它约定：
- JSON 里的换行用 `<br />`（HTML 标签，渲染引擎识别）。
- 加粗用 `<b>`。

## 与备课技能的上下游关系

备课技能（目录 `lesson-prep`，上游）= 个人备课全流程：课时规划→初备→AI 研讨（大模型作研讨伙伴提意见/引导）→修订案→二次备课（大模型自主迭代），产物为 `./K12/备课/` 下的 Markdown 修订案（教研留痕导向）。**本技能（下游）= 教案文档生成（默认 Word）**：既承接修订案渲染课堂用教案（输入源 B），也可从课题直接生成（输入源 A——「要一份教案/教学设计」走本技能）。用户说「备课/带研讨的深度备课/走备课全流程」找备课技能；说「出教案/写教案/转 Word/转 PDF」找本技能（PDF 请求如实告知不再提供）。两者共用 k12-kg 图谱数据底座。

## 边界

- 产出的是**设计草稿**，是否符合本校/本班实际需教师审核确认。
- **不编造课标原文、教材页码、单元名称**——图谱在库的版本（统编语文/历史、人教数学/英语/物理/化学/生物、湘少/译林英语、湘教地理）一律以图谱为准；不在库的走人工核对路径，不确定就留空或标注「待核对」。
- 图谱只读：发现缺漏 `report_gap` 登记，不为出教案改图。
- 不生成脱离真实教学场景的空泛口号式内容。
- 不替代教师完成课堂教学本身。
