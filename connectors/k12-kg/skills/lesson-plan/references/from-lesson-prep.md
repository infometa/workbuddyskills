# 承接备课技能（lesson-prep）产物：修订案 → 教案文档（输入源 B，仅 Word）

> 本文件是 SKILL.md「承接流程」的展开。前提：备课技能已按 `templates/统一备课用纸.md`
> 产出产物，**标题层级与命名是机读契约**（下游按标题解析，改名=解析失败）。
> 兼容口径：2026-10-12 起产物为备课技能（个人形态）产物（03-研讨-意见卡片 / 04-修订案）；旧目录的
> 集体备课形态（03-研讨实录-结构化 / 04-共案）结构同构，直接兼容读取，不必要求用户重跑。

## 1. 产物发现与选取

产物目录：`./K12/备课/{book_code}/{课文名}/`

| 文件 | 角色 | 选取规则 |
|---|---|---|
| `04-修订案-第N课时.md`（旧：`04-共案-…`） | **主输入** | 首选；每个课时一份。无修订案时退用 `02-初备教案-第N课时.md`（并在留痕注明「未经研讨」） |
| `01-课时图谱档案.md` | 事实追溯源 | 生字表/知识点 ID/前序链从这里直取，**不从修订案正文复述**（修订案可能已简化） |
| `00-课时规划.md` | 总框架 | 总课时数、每课时目标骨架；校验各 04 是否齐套 |
| `03-研讨-意见卡片.md`（旧：`03-研讨实录-结构化.md`） | 附录一素材＋留痕 | 采纳状态汇总进留痕块；全部意见卡片**原文照录**为教案附录一（见 §3） |
| `05-二次备课-NN.md` | 修订叠加＋附录二素材 | 存在且涉及目标/教学过程时，**并入最新状态**再渲染；只改评价/反思的可不并入。全部迭代记录**原文照录**为教案附录二（见 §3） |

缺文件不要硬猜：列出目录现状，让用户确认用哪份。

## 2. 用纸结构 → 教案 JSON 映射表

| 统一备课用纸板块 | → 教案 JSON（`render_lesson`） | 说明 |
|---|---|---|
| 课题/总课时/备课时间（表格头） | `meta.title` / `meta.subtitle` / `meta.info` | 标题加「（修订案）」；「（待填）」占位原样保留，不编造 |
| 本课时教学目标 | `info` 教学目标 | 目标后挂的 `→ node_id` 锚点**移到留痕块**，不进正文；行内〔认知层级〕标注保留在正文（教研可读，判据 `bloom.md`） |
| 教学重难点 | `info` 教学重难点 | 直取 |
| 教材分析及学情分析 | `meta.info` 长行（同 example-tiandiren） | 与 01 档案对账：生字表/前序以档案为准 |
| 教学过程设计 `### 一、{板块}（{X} 分钟）` | `band`（第 N 课时）+ `phases.rows[]` | time=`X′`、name=板块名；活动要点/逐字稿进 items；时长和必须=课时长度（修订案已过 check，引用结论即可） |
| 课后作业 | `info` 作业设计（基础/提升/拓展三层） | 修订案 exe 编号保留在留痕；正文写题目内容 |
| 目标↔知识点映射表（修订案独有） | `rubric` 评价量规 ＋ **附录三全表照录** ＋ 留痕块 | 评价点列→rubric 的 ★达成列（见 §3）；全表（含 node_id 与能力上溯列）另原文照录为**附录三**（见 §3 附录转录）；认知层级列并入 rubric 维度名或目标行内标注，并据此核对评价点层级匹配 |
| 03-研讨-意见卡片（附录一） | `band`＋`info`（每卡一行） | 原文照录：卡片编号/提出人/针对板块作标签列，建议＋依据类型＋图谱佐证＋采纳状态＋教师回应作内容列，一字不改 |
| 05-二次备课-NN（附录二） | `band`＋`text`（每轮一块） | 原文照录逐轮（改了什么/依据哪条推演发现）；教师反馈条目保留（AI 推演/教师反馈）来源标注 |
| 覆盖检查结论 / 采纳留痕 / AI 辅助清单 | `text` 留痕块 | 见 §4 |

**多课时合并**：一份文档装全课（同 example-tiandiren 两课时）——共用板块（教材分析/学情分析/重难点）只出现一次，每课时一个 `band` 分隔，课时之间加 `pagebreak`。

## 2A. 问题化产物承接映射（问题化模式，2026-11 起）

备课技能以问题化模式产出时，除 §2 全表外按下表**增换**板块（新板块契约见 `schema.md` §9/§10）：

| 问题化产物板块 | → 教案 JSON | 说明 |
| --- | --- | --- |
| `00-单元问题系统.md`（单元规划） | `band`（单元标题）＋`text`（单元学科学习重点）＋`rubric`（内容目标 4 列：核心素养/学习内容/目标描述/学习水平）＋`rubric`（问题化能力目标 4 列：目标/描述/编号/水平）＋**`qsystem(variant="unit")`**（单元核心问题＋课时分配链）＋`text`（单元长作业指向） | 单元规划整体置于文档头部、第一课时 band 之前；编号/水平列原样保留（教研留痕域） |
| `## 三位一体问题` | `info`（三行：学生问题/学科问题/教师问题） | 学科/教师问题行内的 node_id/回应标注原样保留在内容中 |
| `## 课时问题系统` | **`qsystem(variant="lesson")`**（核心问题＋子问题链） | 每课时一个，紧随三位一体 info 之后；chain 项 node_id 必填（缺则回备课技能补锚，不在渲染层造） |
| `### {板块}（{X} 分钟）　解决问题：Q{n}` ＋ `#### 互动解问` 三件套 ＋ 五力标注 | **`qactivity`**（每板块一行：name/goal/steps；solve.text＋chain_idx=Q{n}−1；interaction 三件套；powers） | 替代 §2 的 `phases` 行——问题化课时过程表整体走 qactivity，不与 phases 混用 |
| 映射表扩展两列（问题（类别）/回应的预设） | 附录三 `rubric` head 动态 7 列 | head/rows 按修订案表头原样（rubric 已泛化 2–8 列），node_id/code/素养列不删 |

承接纪律：`solve.chain_idx` 必须指向本 plan 内 lesson 变体 qsystem 的 chain 序号——
组装 plan 时先立 qsystem 再写 qactivity，发送前预检会对账（链上孤儿/越界序号都会被拦）。
五力的水平级与匹配素养直取修订案标注（备课侧已回溯 question-powers.md 与能力上溯），渲染层不复核也不改写。

## 3. 补齐两块（用纸没有、教案文档需要）＋附录转录（默认带）

| 板块 | 补齐来源 | 纪律 |
|---|---|---|
| **板书设计**（`board`） | 生字板书：01 档案 `characters.会写` 清单；非识字课：课题结构 + 核心知识点名（01 档案 knowledge） | 素材取自档案；布局是设计判断，留痕注明「板书为 AI 补排」 |
| **评价量规**（`rubric`） | 修订案「目标↔知识点映射表」的**评价点列** → rubric ★达成列；☆☆待加强列按设计原则 §7 补写 | 维度与目标一一对应，3～4 维；维度名可带认知层级（取自映射表层级列，如「表达运用（理解）」），★达成描述的检验方式须与该层级匹配（判据 `bloom.md`——用默写检验创造层目标即断链） |

**附录转录（教研合规，默认带）**：附录一「AI 研讨记录」（03 全部意见卡片，含教师回应纪要）、附录二「二次备课推演记录」（05 全部迭代轮次）与附录三「目标↔知识点映射表」（04 各课时的映射表**全表转录**）**原文照录**——不摘编、不删卡、不改写措辞（编号/提出人/采纳状态/来源标注一字不动），教研合规优先于篇幅。置于全文末尾、数据来源留痕块之前；多课时合并时附录只出现一次（换附录处用 `pagebreak` 分隔）。缺对应产物时如实跳过并留痕注明（02 初备退用场景无映射表，附录三同样跳过注明）；用户明确说不要附录时可省略，留痕注明「应用户要求未附」。

附录三用 `band` 分隔＋每课时一个 `rubric` 板块承载（head＝原表五列，rows 逐行原样；**附录属教研留痕域，node_id 与能力上溯列原样保留**，不受「ID 不进正文」纪律约束——该纪律只约束教学过程正文等教师誊用板块）：

```json
{ "type": "band", "text": "附录三　目标↔知识点映射表（原文照录）" }
{ "type": "rubric", "title": "第 N 课时",
  "head": ["教学目标", "认知层级", "承载知识点（node_id）", "能力上溯", "评价点（维度④锚）"],
  "rows": [["（目标原文）", "（记忆/理解/…）", "cpt…", "abl…", "（评价方式原文）"]] }
```

修订案正文一般没有【设计意图】条目——可按映射表给关键板块补一句（目标—活动—评价一致性），**必须在留痕注明哪些意图是渲染时补写的**，不得冒充修订案原文。

## 4. 留痕块（承接模式专用格式）

留痕块是一个 `text` section，**`title` / `text` 都必填**（title 固定「数据来源与 AI 辅助」；缺 title 会被 `render_lesson` 预检拒绝）：

```json
{ "type": "text", "title": "数据来源与 AI 辅助", "text": "本教案由备课技能修订案渲染——……<br />……【待教师核对】……" }
```

正文内容按下式组织（换行用 `<br />`）：

```
数据来源与 AI 辅助：本教案由备课技能修订案渲染——04-修订案-第N课时（共 N 份）
+ 01-课时图谱档案（图谱取数：N 个知识点/M 条前序/K 道习题，ID 未改动）；
覆盖检查结论（引用修订案：X 错误/Y 警告/Z 提示）；研讨采纳 W 条（详见 03/04 产物，
AI 研讨伙伴意见 N 条/教师意见 M 条）。
附录留痕：AI 研讨记录 N 条＋二次备课 N 轮＋目标↔知识点映射表 N 份已按原文附录（或：产物缺失未附/应用户要求未附）。
AI 补写：板书布局、评价量规待加强列、【设计意图】N 处。
【待教师核对】班级/授课时间等待填项；补写内容是否符合本班学情。
```

## 5. 边界

- **不改修订案结论**：渲染只做结构映射与排版，目标/板块/时长以修订案为准；发现修订案本身有问题（如时长和不对）→ 告知用户回备课技能修订，不在渲染层偷改。
- 修订案与 01 档案冲突（如生字表不一致）→ 以档案为准并向用户指出。
- 02 初备渲染的文档标题注明「初备稿」，与「修订案」区分。
