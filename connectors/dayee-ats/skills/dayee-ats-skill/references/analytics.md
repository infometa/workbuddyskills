# 分析与人才洞察

## 招聘报表

职位进展用 get_report_post，候选人明细用 get_report_details，其他聚合用 get_report_result。用户要查找已保存的报表才用 report_search；它返回元信息，没有私有模板不等于基础统计不可用。

指标、维度或筛选含义不明确时，用 get_report_fields 取得目标报表字段。metadataCode、groupColumn、columnCode、状态与时间字段以实际定义为准，不能跨报表套编码。定义不足时说明缺哪些字段，不能大量遍历原始简历来弥补缺失聚合。

复用用户日期、招聘类型、职位、机构和负责人范围。“本周”默认周一至今天，“上周”为上一自然周；相对日期用宿主当前日期和用户时区计算，展示明确起止日期。个人报表限定当前授权账号对应范围，不能把租户全量称为个人成绩。

| 分析目标 | 必须核对的口径 |
| --- | --- |
| Pipeline / 完成率 | 同职位范围的已入职/HC；HC 为 0 或缺失不计算，合计行不重复相加。预测须明确假设与证据，不编造历史转化率 |
| 渠道效果 | 同时期比较数量与推进/录用结果，分清行动次数、人头和库存；无费用不算成本/ROI。深挖已出报告时优先复用同口径数据 |
| 招聘漏斗 | 同一投递人群及去重口径；当前状态库存或独立操作次数不能直接除成转化率，重叠阶段不能无依据相减 |
| 个人/团队周报 | 区分本期新增、推进、存量及面试待办；工作记录和统计分开，不编造完成动作 |
| 学历、年限、地区等结构 | 明确分母和未知类别；样本量与覆盖范围同时报告，不冒充全库普查 |
| 面试官负荷 | 安排、完成、待反馈及逾期分别统计；缺时间不算逾期，不用少量样本评价绩效 |

同名日期字段可能分别指投递、操作、面试或入职时间，先确认可比再计算。列式结果按实际列元数据映射；分页核验与合计去重后再汇总。字段缺失、0、空数据和查询失败分别报告；Exception:null 只说明本次异常，不代表全部报表不支持。

先给结论，再附时间/范围、关键表格、指标定义、样本缺口与建议；相关性不写成因果。仅交付真实报告资源，无文件则用 Markdown。

## 人才库与群体画像

先分清库存、已有画像和新建画像任务；不要因用户说“画像”就创建任务。简历上传见 [候选人与简历](candidates.md)。

| 需求 | 工具与执行规则 |
| --- | --- |
| 核心规模与基础结构 | talent_claw_main_data：库存与期间活跃量不相除为招聘转化 |
| 查已有画像 | group_portrait_search：核对人群定义与时间，有可复用结果直接查询 |
| 创建前获取合法条件 | get_group_portrait_filter_options：使用当前租户的职位、机构、项目与招聘类型选项 |
| 新建目标/对比画像 | create_group_portrait：先查重，具体两组范围获授权后创建；缺组别先补，不默认选全库 |
| 异步进度 | task_status_query：任务提交不等于分析完成，保留任务标识 |
| 已完成画像的特征差异 | get_group_portrait_tgi：TGI 是相对差异，不是人数、录用概率或因果关系 |

按服务端建议间隔查询，单轮至多查 3 次状态；需等待超过 60 秒或仍在运行时交付任务标识、状态及继续查询方式。除非用户要求且有调度能力，不承诺后台追踪。失败或未知结果不通过再创建任务重试。

## 公司人才地图与外部情报

按 [候选人检索](candidates.md) 取得目标公司/岗位的有界样本，只对必要人选补详情。人才地图整理部门、岗位、地域分布，背景画像归纳经历结构；离职候选人样本不代表公司当前组织全貌。

- 部门优先用履历明确字段，职责推断标“推测”，不明则未分类，不绘成官方组织架构。
- 流向依据工作时间与公司顺序；时间重叠或“至今”不明时标待核实，不编造跳槽链。
- 单人只展示岗位相关信息，群体报告用脱敏样本，不公开联系方式或简历全文。
- ATS 样本、公开资料和分析推断分别注明来源。新闻、财务、组织公告等只取宿主实际可用的公开搜索/浏览结果；无外网能力则说明只完成内部样本分析。
- 外部搜索仅用公司、岗位、行业等公共关键词，不传候选人身份、简历或内部报表。引用注明链接与日期，区分历史任职和现任人员。
- 不用少量样本计算企业真实流失率或全行业人才浓度。结论附可执行建议及证据限制；联系、流转或新建画像建议不等于已执行。
