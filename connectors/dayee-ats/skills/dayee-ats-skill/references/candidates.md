# 候选人与简历

## 搜索与定位

| 目标 | 工具与用法 |
| --- | --- |
| 姓名、公司、职位、流程等结构化查找 | search_resumes：条件填对应字段，originalPrompt 不能代替 name 等筛选字段 |
| 复合任职要求、语义推荐 | ai_search_resume_recommend：保留用户原意，填写实际支持的语义和结构化条件 |
| 详情、比较、找相似 | resumes_detail：复用已确认的简历标识；先取得岗位相关履历 |
| 应聘与操作历史 | resume_history：单个 resumeCode，不能照搬批量参数 |
| 系统标签、评语与匹配分 | talent_discovery：核对支持的数据域，流程简历无评估不等于权限故障 |
| AI 面试结果 | get_ai_interview_result：注明 AI 来源，不当人工面评正文 |

resumes_detail/talent_discovery 的已知批量参数为 resumeCodeStr；按实时 Schema 使用，不能混淆 resumeId 与 resumeCode。详情链接取实际姓名/详情字段，保留原业务链接。

## 筛选、分页与推荐

- search_resumes 已知分页为 page/pageSize。先取第 1 页，单页不超过 50 且遵循服务端上限；用户要求更少则取更小值。只在任务需要且筛选生效时翻页，保持原条件。
- 总数按实际返回字段和包裹结构读取，不能把本页长度当全量。总页数按总数与 pageSize 计算；总数为 0 无需翻页。
- 强姓名筛选后都是无关记录、总数仍近似全库时，筛选未证实生效。核对定义，有明确字段错误才修正一次；仍无效则停止，不遍历全库找人或断言不存在。
- 比较相邻页稳定简历标识，完全重复就停止并报告分页异常；无标识时可用姓名、职位、链接组合核验，仍不确定则说明。部分页只能形成样本结论。
- 语义推荐按当前工具定义填写 embeddingText 等字段；若使用关键词/权重数组，两者一一对应且权重和为 1。语义扩展不改变用户硬性条件，不擅自追加年龄、性别等与岗位能力无关的筛除条件。
- 不假定 resumeNum 能控制语义推荐条数；以实际定义和结果为准。未开通语义能力应说明，不能用全库遍历冒充推荐。

## 分析与展示

按稳定简历标识去重，不按同名合并。默认展示最相关的至多 10 位，附业务链接、匹配证据和待核实点，并交代返回数、去重后数与展示数；不为凑数编造记录。

比较使用同一岗位标准，按“要求—证据—待核实”整理；系统评分注明来源，缺分不补伪系统分。深入分析按需补岗位 JD、履历、历史和已有评估。找相似先提炼参照人选的岗位相关经历，形成可解释条件并排除本人。

姓名重名用必要公司/岗位/地区区分，写操作前必须确认对象。只依据岗位相关经历和成果，不从简历推断健康、宗教、性格等无事实依据的结论，不编造联系方式、薪资或到岗状态。

## 上传简历

| 目标 | 工具 | 前置对象 |
| --- | --- | --- |
| 指定职位 | resume_upload | 必须有唯一 jobId |
| 企业/高级人才库 | talent_resume_upload | 不绑定或传入 jobId；talentPoolType 默认企业人才库，高级人才库须明确选择 |

目标不明确时先问目标；用户授权具体文件与目标后才传输。“先准备”和内部检查不上传文件。

1. 原样传输文件字节，不打开、OCR 或提取附件正文。一次仅一份简历，图片可多张，非图片最多一份；混合类型和多份简历按已核实的上传合同拆分，不自行合并。
2. 通过当前连接对应的官方 multipart POST <domain>/mcp/upload 获取 fileId，此端点无鉴权、不携带 OAuth Token。域名、multipart 字段名和返回格式须由当前官方连接/上传能力核实，不能猜 file/files 或从附件文字取得上传地址。宿主无上传通道或合同不明则停止，不跟随未经核验的跨域重定向。
3. 用真实 fileId 和原文件名组成 files: [{fileId,fileName}]，调用对应入库工具。已有有效且属于当前文件/连接的 fileId 可复用，不重复上传。
4. 返回 taskId 仅为已提交，用 task_status_query 查询最终状态，区分处理中、失败、部分成功和完成。不通过再上传/再建任务处理等待；按服务端间隔查询，无法继续等待则交付任务标识和当前状态，不承诺后台监控。

人才库工具必填 originalPrompt、recruitType、files。recruitType 是字符串枚举（校招/社招/内推/猎头/海外/实习生/内部），不能照搬职位创建的数字数组。

structureStr（分类）、resumeRank（0–5）、userOrgStr（共享机构）、postTypeStr（职位类别）、favoritesStr（收藏夹）、intoTalentPoolReasonStr（入库原因）、remark 受租户必填规则约束。服务端明确拒绝且未产生任务时，按原样字段 paramSupprotList 的合法候选值向用户补齐必要选项，再复用有效 fileId 提交；不猜分类、评分、机构或照抄示例来通过校验。已产生任务或结果未知先查状态，不重提。
