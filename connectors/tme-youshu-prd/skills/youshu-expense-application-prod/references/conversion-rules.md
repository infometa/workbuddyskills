# 可复用转换经验

只保留由需求或成功转换确认的结构规则。新规则写清来源列的语义、匹配条件、输出字段和需要追问的边界；不保存任何实际个人信息、文档链接、租户/账号标识或原始数据行。

| 适用范围 | 结构规则 | 需要追问的边界 |
| --- | --- | --- |
| 宣推费对私 | 宣推轮次、中央曲库歌曲 ID 可能在标题或表头，而非每条明细 | 标题没有信息，或多首歌无法确定行归属 |
| 宣推费对私 | “视频链接”“链接”可作为视频字段候选 | 多列候选、列含义不清；允许无链接时用户明确提供文字用途 |
| 四类费用 | “价格”“金额”“费用”可作为申请金额字段候选 | 多个候选、币种或元/分单位不明确；“合计”不能当明细金额 |
| 宣推费对私 | “云账户信息”可能混合姓名、证件号、收款账号和联系电话，可按明确标签拆分 | 标签缺失、多个号码用途不明、联系电话是否也是支付宝账号未确认 |
| 宣推费对私 | “开户银行”整列原文传 `payee.bankName`，可含支行；不拆分、不强制匹配标准字典 | 仅缺少银行卡收款必需的开户银行原文时补问，不要求新增支行列 |
| 制作费、报销、银行收款备用金 | 银行列用 `queryFeeBanks(level=1, keyword=银行关键词)` 核实，选定完整bankName后按需用 `level=2, bankName, keyword=支行关键词` 查支行；两级关键词均必填，使用对应银行下的真实支行，`key` 只用于识别候选 | 简称、多义、银行与支行不对应或字典未命中时核对，不能默认首项；支付宝不适用 |
| 宣推费对私 | 用户未指定付款主体时省略 `ourSubjectId`，由后端按发行厂牌关联的我方公司主体补全，不从歌曲展示字段猜 ID | 多厂牌或无法匹配有效主体时先按后端错误核对结果，再查询候选让用户补选；用户已指定时核实并显式传入 |
| 制作费 | 同一歌曲可对应多笔独立费用行，不合并金额和收款信息 | 歌曲分组、子类或收款信息互相冲突 |

后续成功案例只追加脱敏模式，例如“某来源列标题 A 在该模板版本中表示开户支行”，不复制示例账户或真实费用数据。规则冲突时保留条件或修订旧规则，不能靠新增一条无条件覆盖旧规则。
