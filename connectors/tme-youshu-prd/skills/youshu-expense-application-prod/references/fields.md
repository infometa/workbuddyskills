# 字段与模板

下面是用户材料中的业务要求。调用时仍以已发现工具的 schema 和查询结果为准，前端显示名不能代替接口标识。

四类费用的付款主体按 [付款主体取值](api.md#付款主体取值)处理：用户指定时保留并以 `queryFeePaymentSubjects` 核实真实 ID；宣推对私未指定时可省略，由后端尝试厂牌关联的我方公司主体补全，失败后再补选，不能由模型猜 ID。其他类型沿用各自接口要求。

## 宣推费对私

[填写模板](https://drive.weixin.qq.com/s?k=AJEAIQdfAAomz0EvptAdsAnQZrADY)；[原子接口表所附清单模板](https://drive.weixin.qq.com/s?k=AJEAIQdfAAoAT0YPsq)。两份链接均由需求提供，不能仅凭链接推断已下载或已校验其最新内容。

每行一笔费用。模板字段：宣推轮次、歌曲 ID、歌曲名、达人名（抖音昵称或视频号达人名）、推广平台、视频链接、点赞量、金额、收款人姓名、收款人身份证号、收款账户类型、收款账户、开户银行、联系电话、备注。

| 字段 | 业务要求 |
| --- | --- |
| 宣推轮次 | 必填；先查标题、表头，再询问用户 |
| 歌曲 ID | 必填，中央曲库 ID；每首歌分别确定 |
| 付款主体 | 整单主体；`ourSubjectId` 可省略，未指定时先由后端按发行厂牌关联自动补全，无法匹配时再从候选补选；用户已指定时核实并显式传入 |
| 推广平台 | 必填；使用查询/工具允许值，不从账号格式猜测 |
| 视频链接或用途 | 必填；模板明确允许无链接时填写文字用途，不伪造 URL |
| 金额 | 必填，正数，按接口契约换算金额单位 |
| 收款人姓名、身份证号、联系电话 | 必填；可从云账户混合文本中拆出 |
| 收款账户类型与账号 | 必填；明确银行卡号及开户银行时选择银行卡；明确支付宝邮箱或手机账号时选择支付宝；仅有联系手机号不足以确认支付宝收款 |
| 开户银行 | 银行卡收款必填；完整原文（可含支行）传 `bankName`，不拆分或强制匹配字典，不额外要求支行 |
| 歌曲名、达人名、点赞量、备注 | 模板可选字段；来源未提供时按工具空语义处理 |

## 宣推费备用金

第一步查询已开通的备用金账号。用户尚未选定且需要选择时，优先通过原生提问弹窗按“平台-账号名”展示真实候选；已明确的账号核实后复用，不重复询问。没有目标账号时说明需要联系财务同事先注册，不自行创建平台账户。

| 字段 | 业务要求 |
| --- | --- |
| 备用金账号 | 必填，使用查询返回的真实标识 |
| 付款主体 | 接口必填，以付款主体候选核实用户指定值；未指定时再补齐 |
| 申请金额 | 必填，正数 |
| 收款方式 | 必填：平台账号或银行账户；前者由财务充值到选择的平台账号，后者打款后用户自行充值 |
| 银行账户收款的收款户名 | 必填，收款类型默认自然人 |
| 银行账户收款的证件类型 | 必填：身份证、香港身份证、澳门身份证、台湾身份证、回乡证，映射工具语义枚举 |
| 银行账户收款的证件号、手机号 | 必填 |
| 银行卡号、支付宝账号 | 银行账户收款时二选一，不能同时填；提供银行资料时按 `queryFeeBanks` 核实名称及支行，支付宝不查银行 |
| 充值证明附件 | 非 `GE_DAN` 歌单平台沿用原业务校验必填；先通过通用上传流程完成上传 |

选择平台账号收款时不要要求补齐无关的私人收款资料。

## 制作费

[填写模板](https://drive.weixin.qq.com/s?k=AJEAIQdfAAojLQ1wASAdsAnQZrADY)；[原子接口表所附版权费用申请模板](https://drive.weixin.qq.com/s?k=AJEAIQdfAAoqB3c5PV)。模板支持一首歌多笔费用、多首歌一起申请。

歌曲有中央曲库 ID 时用 ID 查询并核实基本信息；用户已指定付款主体时仍显式填写该歌曲的 `ourSubjectId`。没有 ID 时必须收集歌曲名、付款主体、歌手、词作者、曲作者；主体从付款主体候选核实，不能改用歌曲发行主体。不能为了通过校验编造歌曲 ID。

每笔费用必填费用子类、金额及下方收款资料，备注可选。费用子类从“制作费费用子类”查询结果选择，不复用报销子类。相同歌曲的多笔款项保持独立，不按歌曲把金额合并。

模板列：歌曲 ID、歌曲名、付款主体、歌手、词作者、曲作者、费用子类、金额、收款户名、收款类型、证件类型、证件号、手机号、银行卡号、开户银行、开户支行、支付宝账号、备注。模板中的明确示例行（含“示例备注：删除本行”）不导入。

## 费用报销

一单只选一个费用子类，使用“费用报销费用子类”查询。整单共用收款资料、付款主体、发票和可选备注；每条明细包含歌曲 ID、金额和可选说明。一笔费用对应一首歌，可以有多笔明细。

歌曲 ID 必填；用户只有歌名、歌手时先查询歌曲基本信息，多个候选需选择。付款主体必须通过付款主体候选核实并保留用户指定值。发票必填，支持 PDF 或图片；仅有未上传的本地路径、发票号或 OCR 文本不等于发票文件已上传。跨费用子类、付款主体或整单收款人冲突时说明需要拆单并询问如何拆分，不擅自把所有行归到首个子类、主体或收款人。

## 共用收款资料（制作费、费用报销）

| 字段 | 自然人 | 法人 |
| --- | --- | --- |
| 收款户名 | 必填 | 必填 |
| 收款类型 | 自然人 | 法人 |
| 证件类型 | 身份证、香港身份证、澳门身份证、台湾身份证、回乡证之一 | 固定为企业信用代码 |
| 证件号 | 必填 | 必填 |
| 手机号 | 必填 | 选填 |
| 银行卡号 / 支付宝账号 | 二选一 | 银行卡号必填，不可填支付宝 |
| 开户银行、开户支行 | 按接口要求提供，提供时查询银行字典；只填银行时不强制增加支行 | 均必填，使用同一银行字典项的名称 |

银行/支行选择使用 `queryFeeBanks` 分级查询的真实候选及名称：两级keyword均必填，一级选定bankName后再按需查二级支行；不提交字典 `key`，不默认首条，详情见 [银行与支行选择](api.md#银行与支行选择)。本节共用字典规则不用于强制校验宣推对私开户银行原文。

## 弹窗追问示例

遵循 [弹窗优先规则](../SKILL.md#提问与候选选择弹窗优先)。下面是问题内容和选项设计示例，不是固定工具参数；真实调用按当前原生提问工具 Schema 构造。

| 场景 | 问题与交互 |
| --- | --- |
| 费用类型尚不明确 | “这笔费用属于哪一类？”；按当前已知用途展示适用的费用类型单选，已明确类型时跳过 |
| 付款主体需要用户选择 | “这次申请由哪个主体付款？”；单选展示 `queryFeePaymentSubjects` 的真实主体名称及必要 ID，用户已经指定且唯一匹配时直接复用 |
| 歌曲同名或版本不唯一 | “第 5 行对应哪首歌曲？”；单选展示查询返回的歌名、歌手、版本及中央曲库 ID，不默认第一首 |
| 多列可映射同一字段 | “第 3、7 行同时有‘视频链接’和‘投放链接’，这次采用哪一列？”；以这两个真实列名为单选项 |
| 收款方式不明确 | “该收款人使用哪种方式收款？”；按该费用及收款人类型允许的方式展示银行卡/支付宝单选，选定后仅补充对应方式仍缺失的资料，不能把联系电话自动当支付宝账号 |
| 其他费用开户支行不明确 | 银行字典返回多个匹配项时，询问“这笔费用对应哪个开户支行？”；展示相关银行/支行组合供选择，已唯一匹配时直接复用，不默认第一条；宣推对私不增加此项追问 |
| 缺少轮次和歌曲 ID | “标题未找到宣推轮次和中央曲库歌曲 ID，请补充轮次及各歌曲的中央曲库 ID。”；按工具支持的自填能力合并收集，只有歌名/歌手时先查询候选 |
| 无 ID 的制作费歌曲资料不足 | “制作费第 5 行缺少歌曲资料，请补充尚未提供的歌曲名、付款主体、歌手、词作者或曲作者。”；原生输入能力可用时分组收集，已有字段无需重填 |

引用行号只用于定位当次资料，不写入长期经验。弹窗内外均不回显完整证件或银行账号；工具不可用或不支持所需输入时，再用简短文字集中追问。
