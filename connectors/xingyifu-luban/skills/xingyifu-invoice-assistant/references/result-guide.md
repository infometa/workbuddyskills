# 开票交互与结果指南

指导AI将工具结果组织为可选择、可确认、可下载的交互界面；字段表用于说明数据来源，不要求照着渲染成Markdown表格。调用步骤和异常处理见 [技能正文](../SKILL.md)，参数以工具 `inputSchema` 为准。以下示例数据均为虚构。

## 交互要求

优先使用可交互列表、卡片和表单；无对应能力时使用文本。下方表格是字段与内容示例，不限定UI布局。

| 环节 | 展示与操作 |
| --- | --- |
| 选商户 | 先展示当前页商户名称、商户号，再询问选择；提供下一页 |
| 选订单 | 先展示当前页订单号、完整交易时间、实付金额、支付方式和开票状态，再询问选择；提供下一页 |
| 填资料 | 个人或单位、抬头、税号及选填资料 |
| 确认申请 | 分组预览订单与购买方资料，提供确认提交、修改、取消 |
| 查结果 | 展示中文状态及所需详情 |
| 取文件 | 下载后通过文件卡片或附件交付 |

选择商户或订单不等于确认提交；预览修改后须重新确认。文件链接约30秒有效，用户请求下载时再获取并立即保存，不将短期链接预先绑定到下载按钮。

## 商户列表

来源：`list_invoice_merchants`。

| 返回字段 | 含义 |
| --- | --- |
| `data[]` | 本页商户 |
| `data[].custId` | 商户号 |
| `data[].busName` | 商户名称 |
| `pager` | 业务返回的分页信息，字段以实际结果为准 |

选择映射到 `custId`；页码仅展示接口实际返回的信息。

文本回退示例：

| 序号 | 商户名称 | 商户号 |
| --- | --- | --- |
| 1 | 示例餐饮有限公司 | 600000000001 |

第1页 · 本页1条。请回复序号或商户号选择商户。

## 订单列表

来源：`search_trade_orders`。

| 返回字段 | 含义 |
| --- | --- |
| `orders[]` | 本页经筛选后的候选订单 |
| `orders[].custId`、`orders[].orderNo` | 商户号、系统订单号 |
| `orders[].amount`、`orders[].orderTime` | 实付金额、交易时间 |
| `orders[].mercRefName` | 商户名称，可选 |
| `orders[].payWayName` | 支付方式展示文案；缺失时不猜测 |
| `orders[].invoiceStatus`、`orders[].invoiceStatusDesc` | 开票状态枚举及中文文案，见状态表 |
| `orderTimeBegin`、`orderTimeEnd`、`timezone` | 本次查询时间范围和时区 |
| `currentPage`、`pageSize` | 原始流水的当前页码和每页条数 |
| `hasMore`、`nextPage` | 是否可继续查询原始流水页、下一页码；没有后续页时不返回 `nextPage` |
| `uninvoicedOnly` | 是否只保留未开票订单 |
| `notice` | 本次结果的提示文案 |

`hasMore` 针对原始流水分页，不表示下一页一定有匹配订单；筛选后的 `orders=[]` 仅说明本页没有候选，不代表整个范围没有订单。

列表只展示订单信息和开票状态，不追加发票号、失败原因或文件列。

列表顶部显示商户、查询范围和筛选条件，金额突出、状态使用中文标签。选择映射到 `custId`、`orderNo`；“下一页”保留条件，使用返回的 `nextPage`，不要求先取全量。

文本回退示例：

商户：示例餐饮有限公司（600000000001）
查询范围：2026-09-01 00:00:00 ～ 2026-09-30 23:59:59（上海时区）
筛选：仅未开票

| 序号 | 订单号 | 交易时间 | 实付金额 | 支付方式 | 开票状态 |
| --- | --- | --- | ---: | --- | --- |
| 1 | DEMO-ORDER-001 | 2026-09-29 15:02:30 | ¥100.00 | 微信 | 未开票 |

第1页 · 本页1条 · 还有更多，可回复“下一页”。请回复序号选择订单。

## 交易核对与开票预览

交易字段来自 `get_trade_order_detail` 的 `data` 对象；购买方资料来自用户。

| 返回字段 | 含义 |
| --- | --- |
| `custId`、`orderNo`、`busName` | 商户号、系统订单号、商户名称 |
| `amount`、`orderTime`、`payWayName` | 实付金额、交易时间、支付方式文案 |
| `orderStatus`、`orderStatusDesc` | 交易状态枚举及中文文案，见状态表 |
| `showInvoiceEntry` | 业务返回的开票入口展示标记，按上游标量值透传；不作为开票状态判断依据 |

详情用于核对选定订单；开票进度来自订单搜索或开票结果中的 `invoiceStatus`。

### 提交前预览

使用摘要卡片分组展示订单信息和购买方资料；末尾提供“确认提交”“修改资料”“取消”。修改操作回到资料编辑，取消操作结束本次申请。

**订单实付金额不等于最终开票金额**，后者由业务后端确定。文本回退示例：

| 订单信息 | 内容 |
| --- | --- |
| 商户 | 示例餐饮有限公司（600000000001） |
| 订单号 | DEMO-ORDER-001 |
| 交易时间 | 2026-09-29 15:02:30 |
| 支付方式 | 微信 |
| 订单实付金额 | ¥100.00 |
| 交易状态 | 交易成功 |

| 购买方资料 | 内容 |
| --- | --- |
| 类型 | 单位 |
| 抬头 | 示例购买方有限公司 |
| 纳税人识别号 | DEMO-TAXPAYER-ID |
| 备注 | 未填写 |
| 手机号 / 邮箱 | 未填写 |

最终开票金额由业务后端确定。请确认是否提交；需要修改时直接说明字段和值。

## 提交反馈

来源：`submit_invoice`。

| 返回字段 | 含义 |
| --- | --- |
| `data.applyId` | 业务申请标识，有值时返回 |
| `data.orderNo` | 系统订单号，有值时返回 |

提交成功时反馈“申请已受理，正在查询开票结果”。`applyId` 是申请标识，不是发票号；受理成功不能展示为开票成功。

## 开票结果与文件交付

来源：`get_invoice_result`。

| 返回字段 | 含义 |
| --- | --- |
| `data[]` | 本次返回的订单开票结果 |
| `data[].orderNo` | 系统订单号，按它匹配请求，不依赖数组顺序 |
| `data[].invoiceStatus`、`data[].invoiceStatusDesc` | 开票状态枚举及中文文案 |
| `data[].applyId` | 业务申请标识，可选 |
| `data[].invoiceNum` | 发票号码，可选 |
| `data[].invoiceFileUrl` | 文件下载链接，可选，约30秒有效；它是下载来源，不是本地保存路径 |
| `data[].failReason` | 失败原因，有值时返回 |

请求中某笔订单没有返回记录时，标明“未返回记录，状态未确认”，不能解释为未开票。开票成功但缺少链接时，说明暂未取得文件。

### 查询进度或失败原因

只展示本次查询的状态与详情，不默认添加文件列：

| 订单号 | 开票状态 | 发票号 | 失败原因 |
| --- | --- | --- | --- |
| DEMO-ORDER-001 | 开票成功 | DEMO-INVOICE-001 | 不适用 |
| DEMO-ORDER-002 | 开票中 | 未返回 | 不适用 |
| DEMO-ORDER-003 | 开票失败 | 未返回 | 示例：抬头校验失败 |

单笔使用状态卡片或简短文字，批量使用状态列表；上表是文本回退示例。全部订单均无发票号或失败原因时，可省略相应列；失败状态未返回原因时标“未返回”。

### 文件交付

下载完成后优先通过宿主附件或文件卡片交付，标明对应订单号、发票号；不支持时提供可点击文件或真实绝对路径。只有确认保存成功，才写“已保存”。

- 只查进度：反馈“开票成功”，不声称文件已下载。
- 下载完成：反馈“发票已保存”，附实际文件或绝对路径。
- 下载失败：反馈“开票成功，文件下载失败”，不改为“开票失败”。
- 成功但无下载链接：反馈“开票成功，暂未取得文件链接”。

## 状态映射

### 交易状态：`orderStatus`

| 枚举 | 中文含义 |
| --- | --- |
| `SUCCESS` | 交易成功 |
| `PENDING` | 待处理 |
| `FAILED` | 交易失败 |
| `CLOSED` | 已关闭 |
| `REFUNDED` | 已退款 |
| `UNKNOWN` | 未知状态 |

### 开票状态：`invoiceStatus`

| 枚举 | 中文含义 |
| --- | --- |
| `UNINVOICED` | 未开票 |
| `PROCESSING` | 开票中 |
| `SUCCESS` | 开票成功 |
| `FAILED` | 开票失败 |

两套状态属于不同业务对象：交易成功不等于开票成功。界面使用中文文案，流程判断使用对应枚举。

## 字段格式

- 商户号、订单号、发票号保留完整字符串；金额以人民币元展示两位小数，时间保留完整日期与时分秒。
- 业务未返回的字段标“未返回”，用户未填的选填项标“未填写”。
- 除订单搜索外，其余工具可返回 `code`、`traceId`。`code="000000"` 表示接口成功；`traceId` 供排查，不作为主要展示信息。
