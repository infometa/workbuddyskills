## 公共搜索参数

七个资源搜索工具沿用以下公共字段；分类与场景的按工具差异，见 [调用速查](quickref.md#直接调用示例)。

> **编号速查**：年级（12 个）、资料类型（26 个）、学段（4 个）、学科（10 个）、省级地区（35 个）的固定值见 [基础字典](dictionary.md)，能直接查到就不必调 `searchMetadata`。**教材版本、教材、章节**必须实时查，不要凭记忆猜；地市级地区需要 `areaId`，也要查。

| 字段                              | 用法                                                                                                                                                                |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `keywords`                      | 标题关键词，可选；服务允许关键词和结构化条件都省略，不等于能搜索全文。**只放资料主题词，不放完整问句**（服务按标题硬匹配、不做分词）——详见下方注意                                                                                     |
| `size`                          | MCP 资源搜索单次最多 20 条，超过 20 会返回参数错误。Skill 未获数量要求时传 5；用户指定 1～20 条时按要求传入，超过时说明限制并先查最多 20 条。服务对省略、0 或负数仍默认 10。实际数量取决于命中数 |
| `page`                          | 页码，从 1 开始，省略为 1。**要更多结果时递增 page 而不是加大 size**（size 上限 20）。实测 page=1/2/3 返回三批完全不同数据，无重叠 |
| `year`                          | 资料年份，四位整数（如 2022）。用户限定年份时传这里，**不要拼进 keywords**。未匹配时不会自动换年份；各年覆盖率因类型而异（中考真题 2023 年后收录锐减但仍有真实数据，全库课件 2027 仍有零星数据），详见 [年份](dictionary.md#年份) |
| `area` / `areaId`               | 地区名称或编号。`area="长沙市"` 精确匹配该市，**不自动扩大到全省**；重名（如北京市 110000/110100）必须用 `areaId` 指定。不是所有地区都有数据，0 条属覆盖问题不是参数错误 |
| `grade` / `gradeId`             | 年级名称或真实编号（12 个固定值见 [基础字典](dictionary.md#年级)）；同一个年级 ID 可以在多个学段候选中出现                                                                                                                                   |
| `textbookVersion` / `versionId` | 教材版本名称或真实编号；同名时结合年级、课程等确认                                                                                                                                         |
| `textbook` / `textbookId`       | 教材或册次名称、真实编号；必须能唯一确定                                                                                                                                              |
| `chapter` / `catalogId`         | 章节名称或目录编号；**必须同时传 `textbookId`**，单传会报错「查询章节前请提供教材、教材 ID…」；只查当前章节节点，不自动包含下级 |
| `courseId` / `subjectId` / `stageId` | **接口查不到，只能查 [字典](dictionary.md#学段与学科)**。`subjectId` 跨学段统一（语文1/数学2/英语3/物理4/化学5/生物6/道法思政7/历史8/地理9/科学10）；`courseId` 按学段分组（数学：小学2/初中11/高中27）；`stageId` 小学2/初中3/高中4/中职6。**`courseId` 与 `stageId` 必须配套，配错返回 0 条且不报错**；**`subjectId` 不传 `stageId` 时不限学段（小学/初中/高中会一起返回）** |
| `gradeId` + `subjectId`         | **年级必须配学科**。只传 `gradeId` 时学科条件不生效，会混入其他科目：实测 `keywords="期末"` 只传 `gradeId=9` 得 3167 条（语文/物理/道法/非学科混杂），加 `subjectId=2` 后 794 条全是初中数学。三字段同时传不冲突，建议 `gradeId` + `subjectId` 至少都传，跨年级检索再加 `stageId` |
| `knowledgePointId`              | 筛包含该知识点的整份资源，不查询单题                                                                                                                                                |
| `typeId`                        | 字符串，必须使用真实分类（26 个固定编号见 [基础字典](dictionary.md#资料类型)）。专项工具不能改变固定范围；`resource` 可指定分类，省略时不限制资料类型                                                                                                             |
| `includeSubtypes`               | 通常省略。`resource` 设为真时必须提供 `typeId`，查询该分类及全部子类；试卷、课件工具设为真时必须同时提供允许的父分类；学案、作业工具始终包含全部子类                                                                              |
| `hasAnswer` / `hasExplanation`  | 只在用户明确要求有无答案、解析时传入；只是筛选标记，不返回正文                                                                                                                                   |
| `scenario`                      | 课件：1 课件、2 教案、3 两者；试卷、真题、模拟卷：1 中考、2 高考、3 两者。学案、作业、通用检索不使用该字段。**`courseware` 必须传**——省略时服务不附加类型条件，会返回题集、同步练、单元卷等无关类型（实测 15 个关键词里 14 个都混入非课件类型，详见下方） |

### `courseware` 省略 scenario 会返回错误类型

这不是理论风险，是实测结果。用 **15 个不同关键词**各查 20 条，
**14 个都混入了非课件类型**，只有 1 个（「现在完成时」）是纯课件。

| 关键词 | 混入比例 | 返回了什么 |
| --- | --- | --- |
| `勾股定理` | **100%** | 同步练12 / 题集4 / 单元卷2 / 试题汇编1 / 专项训练1 |
| `期末 数学` | **100%** | 试卷 20 条（全是试卷，一条课件都没有） |
| `中考` | **100%** | 试卷19 / 试题汇编1 |
| `牛顿第一定律` | 90% | 同步练8 / 讲义7 / 课件2 |
| `浮力` | 85% | 题集9 / 专项训练4 / 教案3 / 试题汇编2 |
| `一元二次方程` | 80% | 视频8 / 课件4 / 单元卷3 / 导学案2 |
| `集合` | 80% | 试卷8 / 题集5 / 课件4 |
| `化学方程式` | 65% | 课件6 / 同步练6 / 题集4 / 讲义2 |
| `岳阳楼记` | 55% | 教案6 / 课件3 / 学案3 / 题集3 / 音频2 |
| `细胞分裂` | 40% | 课件9 / 教案3 / 学案2 / 同步练2 / 作业2 |
| `光合作用` | 35% | 课件11 / 题集3 / 教案2 |
| `等高线` | 30% | 课件13 / 题集2 / 教案1 |
| `秦统一` | 15% | 课件17 / 题集1 / 学案1 |
| `圆明园的毁灭` | 5% | 课件12 / 教案7 / 同步练1 |
| `现在完成时` | 0% | 纯课件 ✓ |

**最坏的例子**：查「期末 数学」的课件，返回的是 20 条**试卷**——一条课件都没有，
但标题里都有「期末」「数学」，用户很难一眼看出错。

用户问「找一份勾股定理的课件」，如果不传 `scenario`，可能拿到一份「第17章 勾股定理
期末综合复习提升训练」（题集）或「17.1勾股定理 课后同步练习」（同步练）——
**标题里有"勾股定理"，但根本不是课件**。

服务端工具描述写的是「省略时不通过场景附加类型条件」，这个说法字面没错，
但后果是**类型完全不限**。所以：

> **`courseware` 必须显式传 `scenario`：查课件传 `1`，查教案传 `2`，两类都要传 `3`。**
> 任何情况下都不要省略。

同理，`pastExamPaper` / `modelExamPaper` 也必须传 `scenario`（`1` 中考 / `2` 高考 / `3` 两者），
省略会导致中考高考混在一起。

### 地区与年份：不要塞进 keywords

这两个是**独立字段**，塞进 `keywords` 会当标题词匹配，命中率大幅下降。

**但「中考」「高考」这类场景词不能留在 `keywords` 里，哪怕和地区分开也不行。**

#### 「中考」+ area 会把结果清零

`keywords` 里带「中考」并同时传 `area` 时，结果**几乎必然为 0**。这不是库里没数据——
同一批数据换 `keywords="数学"` 就能查到，且查出来的标题全都带「中考」。

实测（`pastExamPaper`，`scenario=1`，`area="长沙市"`）：

| `keywords` | total | 说明 |
| --- | --- | --- |
| `"中考数学"` | **0** | 带「中考」→ 清零 |
| `"中考"` | **0** | 同上 |
| `"数学"` | 13 | ✅ 正常返回 |

再对比同一地区下「数学」的命中量，可见库里数据充足：

| `area` | `keywords="数学"` | `keywords="中考"` |
| --- | --- | --- |
| 长沙市 | 2995 | **0** |
| 湖南省 | 3921 | **0** |
| 湖北省 | 4120 | **0** |
| 广东省 | 6642 | **0** |
| 江苏省 | 13063 | **0** |
| 河南省 | 6695 | 65（少数例外） |

「高考」**没有这个现象**（加 `area` 后各省仍有 14～70 条），只有「中考」会踩。

#### 正确写法：把场景交给 `scenario`，`keywords` 只留学科

| 用户说 | ❌ 不要这样 | ✅ 这样写 |
| --- | --- | --- |
| 「长沙中考数学真题」 | `keywords="中考数学"` + `area="长沙市"` → 0 条 | `keywords="数学"` + `scenario=1` + `area="长沙市"` → 13 条 |
| 「2022年河南中考数学」 | `keywords="中考 数学"` + `year=2022` + `area="河南省"` → 5 条 | `keywords="数学"` + `year=2022` + `area="河南省"` → 1423 条 |
| 「北京中考数学真题」 | `keywords="中考 数学"` + `areaId=110000` → 0 条 | `keywords="数学"` + `areaId=110000` → 7600 条 |

**规则**：用户说的「中考」「高考」属于**考试场景**，由 `scenario`（`1` 中考 / `2` 高考）表达；
`keywords` 只放**学科和主题**。两者不要重复表达同一件事。

#### 地区重名怎么处理

传 `area="北京市"` 会报

```
地区有多个候选，请使用地区 ID：北京市（110000）、北京市（110100）
```

这时用 `areaId` 明确指定即可（省级 110000 / 地市级 110100）。**不要反复重试同一个名称。**

#### 0 条时怎么判断原因

0 条有三种原因，**不要一律说成「库里没有」**：

1. **`keywords` 里带了「中考」+ 传了 `area`** → 去掉「中考」，改用 `scenario`，重查一次
2. **该地区确实没收录** → 换上级地区（`长沙市` → `湖南省`）或去掉地区再确认
3. **年份超出收录范围** → 去掉 `year` 看最新到哪一年

第 1 种是参数写法问题，**必须先排除**，不能直接告诉用户「没有这份资料」。

#### year 只放 `year` 字段

年份不要写进 `keywords`。`keywords` 是标题匹配，写 `"2022 数学"` 会同时要求标题含「2022」，
把 2021、2023 年的同类资料一并排除，命中量白白减少。

实测：

| 写法 | total |
| --- | --- |
| `keywords="数学"` + `year=2022` | 162819 |
| `keywords="2022 数学"` + `year=2022` | 158061 |
| `keywords="数学"` + `year=2021` | 157584 |
| `keywords="2022 数学"` + `year=2021` | 47843 ← 标题年份和 `year` 打架，剩下不到三成 |

最后一行说明了问题：`year=2021` 要 2021 年的资料，`keywords` 又要求标题含「2022」，
两个条件互相收缩。年份只放 `year`，`keywords` 只留学科和主题。

---

名称和对应 ID 同时传入时，服务会校验一致性。不能把用户明确的年级、版本、章节限定只写在关键词中，也不能在出错后静默去掉这些限定。

### keywords 怎么填

服务对 `keywords` 做标题匹配，**有一定容错但不是分词语义理解**。简单口语能过，复杂句子会整串匹配导致 0 条。

| 写法 | 示例 | 实测 total |
| --- | --- | --- |
| ✅ 主题词 | `勾股定理` | 3900 |
| ✅ 主题 + 类型 | `勾股定理课件` | 2723743 |
| ✅ 简单口语 | `帮我找一份八年级数学勾股定理的课件` | 3005 |
| ❌ 复杂口语（多层修饰） | `我想要一些适合初二学生的一元二次方程练习题` | **0** |
| ❌ 复杂口语（带顿号描述） | `有没有那种讲浮力的、比较生动的课件` | **0** |

**判断标准**：句子里除了主题词，还有多少「非主题的修饰」？超过一两个就该拆。

- 「帮我找一份八年级数学勾股定理的课件」——修饰只有句式框架，主题词清晰 → 能过
- 「我想要一些适合初二学生的一元二次方程练习题」——夹了「适合初二学生」这种主观修饰 → 挂

**别赌句式能不能过**，按主题词写最稳，还能提高命中量：

- `keywords` 只写**资料主题**（知识点、章节名、专题名），如 `勾股定理`、`一元二次方程`、`浮力`。
- 年级、教材版本、教材、章节、资料类型等条件，改用 `grade`/`gradeId`、`versionId`、`textbookId`、`catalogId`、`typeId` 等独立字段传。
- 用户原话里有「帮我找」「有没有」「我想要」这类**疑问或祈使句**、有「适合初二学生」「比较生动」这类**主观修饰**、有顿号或逗号分隔多个描述时，先剥掉再传。

## 筛选候选：searchMetadata

建议开放，用于查真实年级、版本、教材、章节或分类编号。它是辅助工具，不是每次搜索的必经步骤；简单关键词搜索或已知真实 ID 时直接调用搜索工具即可。完整名称能够唯一匹配时，也可以直接使用搜索工具的名称字段。

需要精确选教材或章节、名称有歧义、服务提示候选不唯一时再调用。`kind` 可为 `年级`、`教材版本`、`教材`、`章节`、`资料类型`、`综合`（`综合` 或 `all` 会跨类别返回，唯一确定教材时还带章节树）；**不支持 `学段`、`学科`、`课程`**，这三个查不到，只能查 [基础字典](dictionary.md#学段与学科)。`name` 是包含匹配，不能把任一同名候选直接当作唯一选择。

| kind | 其他可用条件                                                         |
| ---- | -------------------------------------------------------------- |
| 年级   | `gradeId`                                                      |
| 教材版本 | `gradeId`、`courseId`、`versionId`、`textbookId`                  |
| 教材   | `gradeId`、`courseId`、`versionId`、`textbookId`                  |
| 章节   | `textbookId` 必填，可加 `gradeId`、`courseId`、`versionId`、`parentId` |
| 资料类型 | `courseId`、`parentId`                                          |

所有候选查询支持 `name`、`page`、`size`。`page` 默认 1，`size` 默认 20、范围 1 到 100。章节不传 `parentId` 时查教材全部目录节点，传入后只查直接子节点。资料类型查询用于核对分类和选择通用检索的 `typeId`；有分类候选不代表该分类一定有资源命中。

**`kind=综合` 匹配到多本教材时是中间态**：返回 `resolution.status="需选择教材"`、`isError=false`、没有业务 `code`，教材候选在顶层 `items` 里（不在 `resolution.candidates`），且**尚未查询章节目录**。此时要按 `items[].id` 取 `textbookId`，带上它再查章节，不能把这一层候选当成章节或资源结果展示给用户。

### 结构化查询示例

用户要求八年级、华东师大版、“浮力”章节的课件，先确定年级、版本和教材。已有真实候选时复用，不重复查询。以下编号取自真实返回值（八年级·华东师大版·浮力），可直接运行验证；换学科或教材时须用 `searchMetadata` 重新取真实编号。

```json
{"name":"searchMetadata","arguments":{"requestDto":{"kind":"年级","name":"八年级"}}}
```

确认年级后查版本；仍有多个学科或版本候选时结合用户已知条件继续确定，不默认选第一项：

```json
{"name":"searchMetadata","arguments":{"requestDto":{"kind":"教材版本","name":"华东师大版","gradeId":8}}}
```

```json
{"name":"searchMetadata","arguments":{"requestDto":{"kind":"教材","name":"八年级上册","gradeId":8,"versionId":303}}}
```

确认教材后查章节：

```json
{"name":"searchMetadata","arguments":{"requestDto":{"kind":"章节","name":"浮力","textbookId":2369}}}
```

选定章节后调用课件工具：

```json
{"name":"courseware","arguments":{"requestDto":{"keywords":"浮力","scenario":1,"gradeId":8,"versionId":303,"textbookId":2369,"catalogId":45070,"size":5}}}
```

候选业务结果示例：

```json
{"kind":"章节","page":1,"size":20,"total":1,"hasMore":false,"items":[{"id":"45070","name":"第三章  浮力","parentId":"0","textbookId":2369,"versionId":303,"gradeId":8,"courseId":19}]}
```

这个对象没有 `code`、`data` 外层。`hasMore=true` 时按需继续翻页，不能认定当前页已覆盖全部候选。`items[].id` 是字符串，填入 `gradeId`、`versionId`、`textbookId`、`catalogId` 时转换为数值；资源分类 `typeId` 保留字符串。

候选中的 `description`、`versionName`、`gradeName` 等可帮助识别教材，仅使用实际返回字段。年级可能跨学段重复，但相同 `gradeId` 是同一个年级筛选值。**学科、课程编号接口查不到，查 [基础字典](dictionary.md#学段与学科)**；知识点没有字典，只能用返回结果里的 `knowledgePointIds`，不根据名字编造编号。

## 学案和作业分类边界

原备份中记录的分类如下，实际归属和适用课程以实时 `searchMetadata` 为准：

| 分类        | 已知子类                                                     | 本次查询方式                                                |
| --------- | -------------------------------------------------------- | ----------------------------------------------------- |
| 学案 `4103` | 导学案 `410301`、学习任务单 `410302`、知识清单 `410303`、实验报告单 `410304` | `studyGuide` 查整个分支；`resource` 精确查指定子类                 |
| 作业 `4104` | 同步练 `410401`、单元卷 `410402`                                | `assignment` 查整个分支；`resource` 精确查指定子类                 |
| 题集 `4106` | 试题汇编 `410601`、专项训练 `410602`、综合训练 `410603`                | `resource` 查指定子类，或用父类编号及 `includeSubtypes=true` 查整个分支 |

可查询学案的直接子类来了解分类：

```json
{"name":"searchMetadata","arguments":{"requestDto":{"kind":"资料类型","parentId":"4103","size":100}}}
```

这不会使 `studyGuide` 支持子类 ID 精确筛选。只要学习任务单等某个子类时，将确认的分类编号传给 `resource`，按实际返回核对 `typeIdV4`。实验报告单等分类可能有课程限制，查看候选 `courseIds`，不假定所有课程可用。

`assignment` 不包含题集三类。用户明确要求覆盖产品所说的全部五种作业内容时，分别调用 `assignment` 和 `resource`（`typeId="4106"`、`includeSubtypes=true`），保持相同的关键词、年级等条件，再按 `documentId` 去重。不能把题集归属改成作业，也不能声称单个 `assignment` 已覆盖全部。
