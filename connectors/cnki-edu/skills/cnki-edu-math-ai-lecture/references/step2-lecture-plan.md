# 三大核心教学理念

1. **数学是"思考"而非"复制"** —— 讲题必须制造认知冲突。
2. **教育是"唤醒"而非"填鸭"** —— 老师的任务是"引疑"而非"灌答"。
3. **学习是"迁移"而非"累积"** —— 每一问都要提炼通法。

# 讲题语言的"四大功能定位"

| 功能类型 | 作用 | 语音特征 | 示例 |
|----------|------|----------|------|
| **指令性语言** | 告诉学生"我们现在要做什么" | 简洁、明确；语速正常 | "来，我们连接OB，构造辅助线。" |
| **启发性语言** | 把"怎么做"转化为"怎么想" | 语速稍慢，语调上扬，尾音拖长 | "直接算很复杂，能不能换个角度看？" |
| **确认性/纠错性语言** | 评价学生思路，只解剖思维不批评人格 | 先扬后抑，语气诚恳；关键词用降调重音 | "思路非常漂亮！但问题出在哪？" |
| **升华性语言** | 把通法提炼成口诀 | 高浓缩、口诀化；语速平缓，最后一句铿锵有力 | "留在你脑海里的还剩什么？四个字——旋转造相等。" |

**铁律**：每一句 `voiceText` 必须至少明确属于以上一种功能类型，并在开头标注（如 `[指令性]`、`[启发性]`、`[确认性]`、`[升华性]`）。

> ★ **关于方括号标记**：`[指令性]` / `[启发性]` / `[确认性]` / `[升华性]` / `[pause Xs]` / `[转折]` / `[冲突]` / `[激励]` 等标记 **必须保留在 `voiceText` 里**。它们是给渲染引擎用的**控制标记**（控制停顿、情绪、语速）。第四步的 `cleanVoiceText` 会在**播放前自动清洗掉**，用户**听不到**。**不要手动删除它们**。

# 工作流程（按顺序严格执行）

## 第零步：学习四份方法论材料（不可跳过）

完整学习《心法》《操作手册》《实战范例库》《声图联动体系》四份材料，内化"四环三阶"讲题体系与"声图联动"同步规则后，再进入下一步。

## 第一步：深入分析试题原图

### 1.1 识别图形类型

| 类型 | 特征 | 对讲题设计的影响 |
|------|------|-----------------|
| 几何图形 | 三角形、圆、四边形、组合图形 | 破冰需设计辅助线；建模需标注角度/线段 |
| 函数图像 | 坐标系、抛物线、直线 | 破冰需建立函数模型；建模需标记顶点/交点 |
| 几何+函数混合 | 坐标系中的几何图形 | 同时处理几何关系和坐标计算 |
| 纯文字/表格 | 无图形 | 减少图形描述，侧重文字条件分析 |

### 1.2 提取图形关键信息

- 所有标注点（A、B、C、O、D、E、F 等）的位置关系
- 关键线段（实线、虚线、辅助线）的连接关系
- 角度信息（标注角度值、直角符号、等角标记）
- 位置关系（平行、垂直、相切、共线、中点）
- 数值标注（线段长度、角度值、半径等）
- 图形特征（圆、直径、切线、对称性等）

### 1.3 识别"天然卡点"和"认知冲突点"

- 从原图中找到最容易出错的地方 → 决定破冰环节的避坑/纠错内容
- 找到思维最容易卡住的地方 → 决定 `voiceText` 中"障碍前置"话术的位置
- 找到题目的核心转化步骤 → 决定破冰环节"启发式语言"的位置

### 1.4 读取 Markdown 数据辅助理解

从 `Content` 字段提取题干文字并与图片交叉验证；从 `Analyse`/`Method` 字段了解分析与解答；从 `Discuss` 字段了解重难点；从 `Points`/`Topics` 字段确定题目类型。**如有图片与 Markdown 不一致，以原图为准。**

## 第二步：识别小问结构

1. 从题干中识别本题包含**几个小问**，通常以"（1）（2）（3）"或"①②③"标记。
2. 若题目只有一问，视为"单个小问"处理（仍按四环展开）。
3. 为每个小问明确其**目标**，并判断难度与所需讲法侧重。

## 第三步：为每个小问设计"四环"讲题方案

| 环节 | 核心任务 | 教师角色 | 话术节点 | 说明 |
|------|----------|----------|----------|------|
| **审题定向** | 把文字条件翻译成数学符号/图形语言，明确"去哪里" | 导游 | 审题转译 | 逐句翻译，问"这意味着什么" |
| **破冰搭桥** | 制造认知冲突，堵死错误路径，引出思路 | 陪练 | 障碍前置 + 纠错归因 | 先堵路后开路，展示典型错误 |
| **规范建模** | 按逻辑链分步书写过程，强调采分点 | 教练 | 分步板演旁白 | **细分为多个小步骤** |
| **独立总结** | 剥离数据，提炼通法与"四字真言" | 教练 | 脱模升华 | 纯文字总结，无卡片 |

**注意：每个小问不设"交互反馈"环节。**

## 第四步：规范建模环节的细分（核心改动）

规范建模环节**必须**按逻辑顺序拆解为若干个子步骤，每一步都对应"**画布更新 + 解题步骤累加展示 + 语音讲解**"三联动。

### 4.1 子步骤拆解四原则

| 拆解原则 | 具体说明 |
|----------|----------|
| **逻辑递进** | 每一步必须是上一步的直接推论，或需要引入的新条件。**不可跳步，不可并列** |
| **可动量化** | 每一步都要能对应到画布上的一个"变化" |
| **语音独立** | 每一步都有完整的一句话讲解 |
| **步数控制** | **证明题 4~8 步，计算题 3~6 步** |

### 4.2 子步骤的逻辑类型

| 逻辑类型 | 说明 | 示例 |
|----------|------|------|
| **A 型：条件转译** | 把已知条件转化为数学符号 | "旋转性质→CA=CD" |
| **B 型：中间推导** | 由已得结论推出新结论 | "CA=CD 且 CB=CE→CB/CA=CE/CD" |
| **C 型：判定应用** | 用判定定理得出结论 | "两边成比例且夹角相等→SAS相似" |
| **D 型：结论确认** | 写出最终结论并标注依据 | "∴△BCE∽△ACD（SAS）" |

**拆解检查**：相邻两步之间必须有明确的"因此"关系。

### 4.3 每步只展示一条新结论

一步只对应一条新的解题结论（一行 `solutionLine`）。

### 4.4 强制留白的"微停顿"

- **每完成一个子步骤后**：停顿 1.5~2 秒（`[pause 2s]`）
- **全部子步骤完成后**：停顿 10 秒（`[pause 10s]`）

### 4.5 步骤增量展示（累加式板演）

第 1 步只展示第 1 行；第 2 步在第 1 步基础上**追加**第 2 行；以此类推，**绝不允许整体替换**。

# ★ voiceText 符号转文字规范（必读，违反将导致 TTS 读错）

**核心铁律**：`voiceText` 中**禁止出现任何数学符号**——它们在播放时会被 TTS 读错或读不出。所有符号必须**写成中文**。

> **为什么**：TTS 引擎（Web Speech API）只识汉字和字母，遇到 `△`、`∠`、`⊥`、`∽` 等符号时，可能读成奇怪音、可能跳过、可能读成英文符号名（如 "triangle"）。这会破坏语音体验。

## 符号 → 中文 对照表（必须遵守）

|---|---|
| `△ABC` | 三角形 ABC |
| `∠ABC` | 角 ABC |
| `⊥` | 垂直于（或"垂直"） |
| `∥` | 平行于（或"平行"） |
| `∽` | 相似于（或"相似"） |
| `≌` | 全等于（或"全等"） |
| `°` | 度 |
| `√` | 根号 |
| `π` | 派 |
| `²`（上标 2） | 的平方 |
| `³`（上标 3） | 的立方 |
| `²` 在单位后（如 `cm²`） | 平方厘米 |
| `±` | 正负 |
| `≠` | 不等于 |
| `≥` | 大于等于 |
| `≤` | 小于等于 |
| `∴` | 所以 |
| `∵` | 因为 |
| `∈` | 属于 |
| `∪` | 并集 |

| `AB²` | AB 的平方 |

| "BC=√5" | "BC 等于根号 5" |

## 数学公式的边界处理

- **`$...$` 包裹的 LaTeX 公式**：第四步的 `latexToSpeech` 函数会**自动转为口语**（`\frac{1}{2}`→"二分之一"）。**voiceText 里可以写 $...$**，但为了保险，**建议也直接写成中文**。（**这条例外已被第 3.5 步 §0.10.1 同步承认**——第 3.5 步按符号搜索时会跳过 `$...$` 内部内容，不会因此打回本步。）
- **单纯字母组合（如 `AB`、`CE`、`SAS`）**：TTS 读字母一般没问题，**不需要改写**。
- **中文与字母混排**：写成 `三角形BCE`（无空格）或 `三角形 BCE`（有空格）都可以，TTS 读起来差别不大。**推荐无空格**，更紧凑。
- **数字**：`30`、`90`、`2` 等阿拉伯数字 TTS 能读，不需要改成"三十"、"九十"。但**符号必须在数字之后**（`90°` → `90 度`）。
- **第四步的兜底**：第四步模板的 `cleanVoiceText` 会做一层"符号转中文"兜底替换——但它**只覆盖约 20 个纯数学符号**（`△` `∠` `⊥` `∥` `∽` `≌` `⊙` `°` `√` `π` `²` `³` `×` `÷` `±` `≠` `≥` `≤` `∴` `∵` `∈` `∪` `∩`）。**`=` `/` `+` `-` `(` `)` 等不在第四步兜底范围**——**必须由你在本步改好**。

## 检查方法

写完 `voiceText` 后，**逐条搜以下字符**：
- `△` `∠` `⊥` `∥` `∽` `≌` `°` `√` `π` `⊙` `±` `≠` `≥` `≤` `∴` `∵` `∈`
- 上标：`²` `³` `⁴`
- 其他：`×` `÷` `→` `←` `⇌` `=` `/` `+` `-`

**命中即违规**，必须改为对应的中文。**唯一例外**：`$...$` 包裹的 LaTeX 公式——它会被第四步的 `latexToSpeech` / `cleanVoiceText` 自动转成口语。**这条例外已在第 3.5 步 §0.10.1 同步登记**，第 3.5 步搜 `=` `/` `+` `-` 时会排除 `$...$` 内部，不会因此把你打回。

# 声图联动同步规则

**核心原则：声音到哪、画面变到哪、步骤写到哪——三者必须同步。**

## 规范建模子步骤的"三联动"标准结构

```
子步骤 N
├── 🖼️ 画布变化：图形上的高亮/标注/新元素
├── 📝 解题步骤（累加展示）：
│       Step 1：……（已有）
│       Step N：……（新增，在本步骤末尾追加）
└── 🔊 语音脚本（≤50字，不超过3句）
```

## 声图同步的三要素对应关系

| 语音中的元素 | 画布上应发生的视觉变化 | 步骤区应发生的变化 |
|--------------|------------------------|-------------------|
| 讲到某个条件/点/线/角 | 该元素**高亮/变色/描边** | 步骤区高亮对应解题行 |
| 讲"连接OB构造辅助线" | **动画绘制**辅助线 | 出现/更新对应解题行 |
| 讲到"旋转"、"平移"等变换 | **动画演示**变换过程 | 出现/更新对应解题行 |
| `[pause Xs]` 停顿 | 画面**保持静止**或做缓慢脉动 | 不变化 |
| 讲到采分点/易错点 | 该处**闪烁/圈出/放大** | 对应解题行**加粗/标记** |
| 讲到"做减法"、"无用条件" | 无用元素**淡化/置灰** | 无 |

## 每个环节的声图联动要求

| 环节 | 声图联动要求 |
|------|--------------|
| 审题定向 | 语音翻译到哪个条件，画布上就高亮哪个条件 |
| 破冰搭桥 | 讲"堵路"时画面保持现状；讲"开路/转化"时画布**动画演示**转化路径 |
| 规范建模（每个小步骤） | 语音讲解 `solutionLine` 的推理，画布同步**渐进绘制**该步骤的几何变化，步骤区**追加**该行 |
| 独立总结 | 讲"擦掉数据"时画布数据**渐隐**；讲"四字真言"时核心图形**高亮定格** |

## 声图联动的量化标准

| 指标 | 标准 |
|------|------|
| 子步骤数量 | **证明题 4~8 步，计算题 3~6 步** |
| 每步时长 | 约 40~60 秒 |
| 语音字数 | **每步 ≤50 字，不超过 3 句话** |
| 停顿（每步后） | 1.5~2 秒，用 `[pause 2s]` 标记 |
| 停顿（全部完成后） | 10 秒，用 `[pause 10s]` 标记 |
| 画布变化 | **每步至少 1 个新高亮/新元素** |
| 步骤展示 | **累加式** |
| 语音与画面时间对齐 | 语音讲到元素名时，该元素必须**同时**完成高亮/绘制 |

## 口述讲解的"五维标准"

| 维度 | 执行标准 | 量化控制 |
|------|----------|----------|
| **语言精准度** | 术语规范，搭配"生活化"解释 | 专业词与生活词比例 **3:7** |
| **逻辑脚手架** | 每讲完一个推理步骤，用一句**小结句**收束 | 每 40~60 秒一次 |
| **语音表现力** | 重音敲黑板，停顿给思考 | 关键词重读（音量提升百分之三十），提问后停顿 1.5~2 秒 |
| **启发式提问** | 少用陈述句，多用反问句和追问句 | 每阶段至少 1 个反问句 |
| **情绪正向性** | 在卡点处给予心理锚定 | "这个地方当年我也卡过，很正常。" |

## 手机端"渐进式交互"适配原则

| 限制 | 对策 | 原则 |
|------|------|------|
| 屏幕小 | 渐进式滚屏 | 每一步只显示一个核心信息块 |
| 缺乏教师体态语 | 语音 + 光标引导动画 | Canvas 动画 + Web Speech API |
| 无法实时观察学情 | 点击解锁 | 新内容必须点击"下一步"才显示 |

**核心原则：一次只吐一个核心信息。**

## canvasChange 的写法规范

`canvasChange` 必须包含三要素：

1. **对象**：画面中哪个元素（点/线/角/图形）
2. **动作**：怎么变（高亮/新增/变色/动画/渐隐/闪烁）
3. **时机**：与语音的哪一句对应

### ★ v3 新增：canvasChange 的「层级后缀」

每条 `canvasChange` **末尾必须用括号标注层级**——`（持久）` 或 `（临时）`。这是给 Step 3 的持久/临时分离机制提供**最直接的判定依据**：标了 `（持久）` 的元素会逐帧累积保留；标了 `（临时）` 的元素只在当帧显示、讲完即撤。

**这是本步最重要的规范之一**——不标或标错，Step 3 会把"讲完该撤的强调"当"永久累积"，导致后续帧画面越来越脏。

#### 层级判定标准

| 层级 | 该标的典型情况 | 例 |
|------|-----------------|-----|
| **（持久）** | ① 新画的辅助线（如 AP、AQ）<br>② 新加的**题目条件**的角弧（题面给定角，如 30°、α）<br>③ 直角符号 / 等长标记 / 平行标记<br>④ 最终结论的 ✓ 符号<br>⑤ 题面明确给出、构成图形一部分的线段 | "从 A 向 BM 动画绘制红色虚线 AP（持久）" |
| **（临时）** | ① 对**已有元素**的高亮强调（叠色/变色）<br>② **当前步骤正在证明的角弧**（非最终结论角）<br>③ 破冰时的引导射线、指向箭头<br>④ 填充强调（相似/全等三角形的填充）<br>⑤ 整体闪烁 / 呼应<br>⑥ "做减法"时对无用元素的淡化 | "高亮已有的 AD、AP 两条线段，闪烁一次（临时）" |

#### 口诀（三条）

1. **"擦掉它，图形还完整吗？完整 → 持久；不完整（说明它是强调） → 临时。"**
2. **"这一步讲完，它还有必要显示吗？有必要 → 持久；没有必要 → 临时。"**
3. **"闪烁/高亮 → 临时；画线/画弧/画标记 → 持久。"**

#### 示例对照

| ❌ 未标后缀 | ✅ 已标后缀 |
|---|---|
| "伴随语音'过A作AP⊥BM'：从A向BM动画绘制红色虚线AP，垂足P处绘制直角符号。" | "伴随语音'过A作AP⊥BM'：从A向BM动画绘制红色虚线AP，垂足P处绘制直角符号（持久）。" |
| "伴随语音'∠DAM等于∠PAM'：用高亮色叠画已有的 AD、AP 两条线段，闪烁一次。" | "伴随语音'∠DAM等于∠PAM'：用高亮色叠画已有的 AD、AP 两条线段，闪烁一次（临时）。" |
| "伴随语音'四边形AFEC是平行四边形'：高亮整个四边形 AFEC，最后整体闪烁一次确认。" | "伴随语音'四边形AFEC是平行四边形'：高亮整个四边形 AFEC，最后整体闪烁一次确认（临时）。" |

#### 特殊情形

- **题面给定角的角弧 → 持久**。如 "标出 ∠BAC = 30° 的角弧（持久）"。
- **当前步骤正在证明的角弧 → 临时**。
- **相似/全等三角形的填充 → 临时**。
- **破冰时的引导射线 → 临时**。
- **"做减法"时对无用元素的淡化 → 临时**。

### 画布上标注数值/函数式的规则

- 画布**默认不显示**线段长度、角度值、坐标、函数表达式等数值文字。
- **只有当你认为某个数值/函数式对讲题必不可少、必须让学生看到时**，才在 `canvasChange` 中**明确写出"标注…"**，Step 3 才会以 ≤11px 纯数学文本绘制。
- 不要写"显示'相等'"这类中文描述。

**无图题/纯代数题的特殊规则：**
- 若本题是**纯代数计算题**且原图无几何图形，则**每个 `canvasChange` 一律写空字符串 `""`**。
- 纯文字推理全部由"解题步骤累加区"承担，画布保持空白。

**好的写法**：
```
canvasChange: "伴随语音'连接OB'：从O到B动画绘制红色虚线辅助线OB，绘制完成后高亮闪烁一次（持久）"
```

**差的写法**：
```
canvasChange: "辅助线OB"   ❌
canvasChange: "从O到B动画绘制红色虚线辅助线OB"   ❌（缺层级后缀）
```

# 各字段详细编写规范

## 1. 顶层字段

| 字段             | 必填 | 说明                                 |
| -------------- | -- | ---------------------------------- |
| `questionType` | ✓  | 题型：几何证明 / 函数综合 / 实际应用 / 基础计算 / 新定义 |
| `totalIntro`   | 可选 | 整题总起。多小问建议包含；单小问可省略                |
| `subQuestions` | ✓  | 小问数组，**必须至少 1 项**                  |
| `finalSummary` | 可选 | 整题终局总结。多小问建议包含；单小问可省略              |

## 2. 小问对象（subQuestions[i]）

| 字段       | 说明                                      |
| -------- | --------------------------------------- |
| `index`  | 小问序号（从 1 开始）                            |
| `label`  | 小问标号，如 `（1）`、`（2）`                      |
| `goal`   | 本小问的求证/求解目标（一句话）                        |
| `stages` | 四环数组，**顺序固定**：审题定向 → 破冰搭桥 → 规范建模 → 独立总结 |

## 3. 单环节对象（审题定向 / 破冰搭桥 / 独立总结）

| 字段               | 说明                                                             |
| ---------------- | -------------------------------------------------------------- |
| `stage`          | 环节名：`审题定向` / `破冰搭桥` / `独立总结`                                   |
| `title`          | 步骤标题，格式 `环节名 · 具体任务`                                           |
| `description`    | HTML 格式，支持 `<br>` 换行和 `<span class='math'>` 标记数学式；**必须基于原图**描述 |
| `voiceText`      | 语音讲解文本，**必须**遵循"四环话术标准"；**禁止**直接复制 `description`；**★ 禁止含数学符号**（见上「voiceText 符号转文字规范」） |
| `showPitfall`    | 是否显示避坑弹窗。**仅破冰搭桥环节可设为 true**                                   |
| `pitfallContent` | 避坑内容 `{ wrong, right }`，`showPitfall=true` 时必填                 |
| `voiceDuration`  | 语音时长（秒），含 `[pause Xs]` 停顿时间                                    |

> ⚠️ **字符串引号铁律（必读，违反将导致 HTML 整页空白）**
>
> 上面所有字符串字段的值都用**英文双引号 `"` 包裹**。因此字段内容中**绝不能出现未被转义的英文双引号 `"`**，否则 JS 语法解析失败，整页白屏。
>
> **处理规则：**
> 1. 字段内容中需要"引用"或"强调"某个短语时，**一律使用中文引号 `「」` 或 `''`**，不要用英文 `"`。
>    - ❌ `description: "指出"够不够凑齐相似判定"的冲突点"` ← 中间两个 `"` 会切断字符串
>    - ✅ `description: "指出「够不够凑齐相似判定」的冲突点"`
> 2. HTML 属性值（如 `<span class='math'>`）**一律使用英文单引号 `'`**。
> 3. 确实必须使用英文双引号时，写成转义形式 `\"`。
> 4. 输出前逐行自检：**每个字段行内，非转义的英文双引号必须恰好 2 个**。

> ⚠️ **`description` 与 `pitfallContent` 是"画布外文字"，可以含符号**。因为它们显示在 HTML 区域（步骤卡片、避坑弹窗），不经过 TTS。**唯一要遵守符号转文字规则的是 `voiceText`**。

## 4. 规范建模的小步骤对象（subSteps[i]）

| 字段              | 说明                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------- |
| `subIndex`      | 小步骤序号（从 1 开始）                                                                                |
| `logicType`     | 本步的逻辑类型：`A`（条件转译）/ `B`（中间推导）/ `C`（判定应用）/ `D`（结论确认）                                      |
| `stepTitle`     | 本小步的标题                                                                       |
| `solutionLine`  | **本小步新增的一行解题过程**；**每步只展示 1 条新结论**；**这是步骤卡片文字，可以含符号**                                        |
| `voiceText`     | 本小步的讲解语音；**≤50 字，不超过 3 句**；**★ 禁止含数学符号**（见上「voiceText 符号转文字规范」）                                                    |
| `canvasChange`  | 本小步画布上的**新增/变化内容**（对象+动作+时机+**层级后缀**）——**末尾必须标 `（持久）` 或 `（临时）`** |
| `voiceDuration` | 语音时长（秒），每步约 40~60 秒                                                               |

> ⚠️ **`solutionLine` 与 `voiceText` 的区别**：
> - `solutionLine` 是**画面上显示的解题步骤文字**（步骤卡片里），**可以含符号**（如 `△BCE ∽ △ACD`）。
> - `voiceText` 是**播放的语音**，**禁止含符号**（必须改写为 `三角形 BCE 相似于三角形 ACD`）。
> - 两者虽然描述的是同一步推理，但**书写形式不同**。

**关键约束：**

- `solutionLine` 必须按"因为→所以"的逻辑顺序排列，**逻辑链不能断、不能跳步**。
- 相邻两步之间必须有明确的"因此"关系，逻辑类型按 A→B→C→D 递进。
- 每个小步骤的 `voiceText` 必须**恰好讲解对应那一条 `solutionLine`**（口语化版本）。
- 每个小步骤的 `canvasChange` 必须描述**画布本次的可视变化**（对象+动作+时机+**层级后缀**）。
- **★ v3 铁律**：`canvasChange` 末尾**必须**标 `（持久）` 或 `（临时）`；两者必居其一。
- **声图联动铁律**：三者一一对应，画布变化与步骤展示必须**同时发生**。

- ~~`hasBlank` / `blankConfig`~~ —— 填空交互已删除
- ~~`isSummary`~~ —— 总结卡片已删除
- ~~`hasVariant` / `variantConfig`~~ —— 交互反馈已删除
- ~~`hasErrorDiagnosis`~~ —— 交互反馈已删除

## 6. voiceDuration 时长建议

- 规范建模小步骤：**约 40~60 秒**
- 单环节（审题/破冰/独立总结）：建议 **20~40 秒**
- 整题总起 / 终局总结：建议 **15~30 秒**
- `[pause Xs]` 标记的停顿时间也要计入总时长
