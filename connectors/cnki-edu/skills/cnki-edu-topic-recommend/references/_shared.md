# 知网基教 skill 家族 · 跨场景公共约定（`_shared.md`）

> **用途**：本文件是家族级"单一可信源"，只放**与场景无关、必须全家族一致**的规则。各 skill 的"文献选择标准 / 输出形态 / 流程范式"等**场景相关逻辑仍留在各自 `SKILL.md`，不得外移**。
> **目的**：消灭重复书写导致的措辞漂移，同时保留每个 skill 因场景而生的合理差异（例如：课标只收核心期刊、知识卡片排除教学/教研文献、作业设计强制真实出处——这些差异是场景逼出来的，应保留）。

## 一、权限固定提示（统一原文，无权益时原样输出）

**适用范围（家族强制）**：本规则适用于**全部** `cnki-edu` 家族 skill——无论其当前是否调用 `edu`（知网基教）MCP 真实数据。家族以「知网基教」为品牌归属，故即便某 skill 当前为纯模型实现（如成绩分析、评语），也必须携带统一的权限闸门，不得豁免；若后续接入知网接口，闸门即生效拦截。各 skill 在 SKILL.md 中**必须**含「🔐 前置权限校验（最高优先级，必须最先执行）」段，口径与本文件严格对齐。

**闸门行为（统一 · 先 `ToolSearch` 确认工具可解析，再 `userState` 校验）**：进入任何流程、调用任何 edu 工具**之前**：先 `ToolSearch(tool_names:["userState"])`（或对应短名）确认 edu 工具在本会话**可解析**；若可解析，再调 `mcp__<SERVER>__userState` 校验（前缀用占位写法，不确定时 `ToolSearch` 反查）。

**三态诊断（非 `true` 必须区分根因，不能一概给购买卡）：**

- **态 A｜工具不可解析**：`ToolSearch` 查不到 `userState` / `searchVectorBJ` → 说明 edu 连接器**未在本会话加载**（未添加 / 重连后掉线 / 显示名漂移）。**不要**输出购买权益卡，改输出下方「🔌 连接器加载指引」；不调用任何 edu 工具。
- **态 B｜无权益**：工具可解析且 `userState` **明确返回 `false`** → 通用版兜底 + 强制转化卡（购买 / 机构开通）。
- **态 C｜调用报错**：工具在但调用异常 → 提示重试 / 重连连接器，不急于下结论，不误判为"无权益"。

1. 返回 `true` → 具备知网基教权益，有资格使用知网能力；但"有资格"不等于"必须引用"——是否实际挂知网文献、挂到什么程度，由各 skill 按**输出形态**自行决定（权益是"能不能用"的闸门，不是"该不该用"的开关）。
2. **态 B（明确 `false`）** → **通用版兜底 + 强制转化卡**（详见下方两条）：
   - **通用版兜底**：不调用任何 edu 数据工具，不产出任何"知网来源 / CNKI 溯源"表述、链接或依据；交付物开头以一行轻提示注明「注：当前未接入知网基教，以下为通用版；知网数据增强层（原文检索 / 权威文献 / 题库等）暂未启用，核心产出本身可直接使用」；照常完成核心任务中**不依赖知网数据的部分**；强依赖知网的环节仅说明「需接入知网后获取」，**严禁编造**任何知网数据或以模型知识冒充。
   - **强制转化卡（仅态 B，不可省略 / 弱化）**：报告文末（安全标注之后）醒目输出下方「🔓 解锁知网数据增强层」。不得用"换其他方式帮您""可整理常识版"等替代话术替掉；用户追问时也不得移除。

⛔ **转化卡不可省略（对模型可见的硬约束 · 仅适用于态 B）**：凡 `userState` 明确返回 `false`（态 B），报告文末**必须**附带下方「🔓 解锁知网数据增强层」——尤其严禁补"改用普通问答""要不要换其他方式帮您"等绕开购买引导的话术；**态 A / 态 C 不得输出转化卡**，改给下方「🔌 连接器加载指引」。

**⛔ 严禁编造知网数据（agent 内部红线，不输出给用户）**：通用版兜底允许用模型能力完成**不依赖知网数据**的部分，但**不得**改用大模型自身知识、公开网络资料、通用教研经验、本地文件等非知网接口数据来"凑"出**标为知网来源**的结果；强依赖知网的环节只能说明"需接入知网后获取"，严禁编造任何知网数据或伪造 CNKI 溯源。

> ### 🔓 解锁知网数据增强层
> 本功能的知网增强能力（原文检索 / 权威文献 / 题库等）需「知网基础教育（基教）」权益支持；开启后即可获得带知网数据溯源的完整版。
> **如何开通：**
> - 自助开通 / 试用：👉 **https://e.cnki.net**
> - 学校 / 区县批量：联系知网区域顾问协助
> 开通后重新发起，即可解锁完整能力。

> ### 🔌 连接器加载指引（态 A / 态 C 使用，非购买提示）
> 当前会话未解析到知网 edu 连接器工具，多半是连接器未连接或会话中途掉线，**与是否购买权益无关**：
> - 在 WorkBuddy 左侧「+」菜单 → 连接器 → 找到「知网基教 / edu」→ 确认已连接；若显示需信任，点「信任」启用；
> - 或**重开一个会话**，工具索引会重新加载；
> 就绪后说"好了"，即可重新跑权益校验。

## 二、干净输出红线（统一原文，不可违反）

面向用户的任何生成物（报告 / 卡片 / 作业单 / 推荐卡）中，**严禁出现**以下任何内容（仅供底层链接构造与 Agent 内部决策，只可存在于超链接 `href` 属性与锚点 `id` 属性中，渲染后不可见）：

- 任何知网接口响应的**元数据字段名或字段值**：`url` / `filename` / `文件名` / `文件ID` / `dbcode` / `tablename` / `coreJournals` / `CoreIndex` / `CSSCI` / `resource` / `product` / `相关度` / `距离` 等；
- 内部文章键（如 `SDJX202401009`、`WUJS202512018`、`BJQG202310005085`、`KFRB202601270022`、`1026372826.nh`）；
- 类型 / 来源库内部代码（`type=0,1,2,3,4`、`CJFD`/`CAPJ`/`CPFD`/`CMFD`/`CCND`、`JOURNAL`/`CONFERENCE`/`DISSERTATION`/`NEWSPAPER`）；
- 内部阅读直链 URL 模板与查询参数（`ix.cnki.net/read/article/readonline?dbcode=…&tablename=…&filename=…&fileSourceType=1` 等）；
- `<a>`、`id="ref-n"`、HTML 片段等**代码符号**；
- "篇名为指向知网平台在线阅读页的超链接""同时设锚点""文件名用于解析年期"等**说明性技术文字**；
- 在「参考资料 / 文献」标题附加"（知网文献）"之类**修饰性括注**。
- 任何**接口 / 连接器 / 工具称谓与内部机制说明**：如 "edu MCP"、"知网 edu 网关"、"mcp__<SERVER>__..."、"searchVectorBJ 返回"、"知网返回该刊文献 coreJournals 标记 Y"、"接口命中 N 条" 等揭示底层调用或内部推导过程的文字。**用户只见对外品牌名（"知网 / CNKI"）与结论性表述（如"北大核心（待核验）"），严禁出现任何暴露内部实现、连接器名或字段机制的描述**。

篇名（被引文献）在 HTML 中须显式 `text-decoration:none`（无下划线）；内部标识只写进 `href`/`id` 属性，渲染后不可见。

- **引用链接必须挂在篇名上，作者名不得作为链接载体**：被引文献的署名（含「（作者，年）」式署名）一律保持纯文本，**不得**用 `<a>` 包裹作者名；唯一可点击的元素是篇名（`<a>` 挂在篇名上、`text-decoration:none`）。统一由 `report_builder.cnki_ref(author, year, title, url)` 生成「（作者，年《篇名(链接)》）」形态，正文署名引用与文末参考文献均须遵循此式——杜绝「点了作者名才跳转知网」这类错挂（2026-10-21 复盘）。

## 三、触发词格式约定（统一写法）

- 强触发关键词在 `SKILL.md` 的 `description` 前置给出，确保路由命中；
- 需要展开时，统一用「触发场景 / 典型关键词 / 示例话语」三列表，或「强触发 / 弱触发」两段式，不要各 skill 自创格式。

## 四、版本与完工标准约定

- 每个 skill 的 frontmatter 建议统一带 `version`（如 `version: 2.1.0`）与 `agent_created: true`，便于追溯迭代；
- 完工标准统一以 `## Definition of Done` 段呈现；代码增强型 skill（如作业设计）可用「验收 + 一票否决」替代，但须显式标注，不要沉默省略。
- **权限闸门为强制一票否决项（家族统一）**：任何 `cnki-edu` 家族 skill（含不调用 edu 的纯模型技能、已停用归档技能）**必须**在 SKILL.md 内含「🔐 前置权限校验（最高优先级，必须最先执行）」段，口径严格对齐本节「一、权限固定提示」：先 `ToolSearch` 确认 edu 工具可解析（态 A 给连接器加载指引、不输出转化卡），工具可解析后再 `mcp__<SERVER>__userState` 校验；`true` 方可使用知网能力；**态 B（`userState` 明确返回 `false`）**即原样输出 e.cnki.net 购买提示、**通用版兜底 + 强制转化卡**——通用版兜底（不调用 edu 工具、不编造知网数据、标注「未接入/未开通知网基教」）后，**必须原样输出「🔓 解锁知网数据增强层」**；⛔ **转化卡不可省略**（仅态 B），态 A/态 C 改给连接器加载指引、不得用替代话术绕开购买引导；不得把失败解释成「接口故障 / 检索无结果」。e.cnki.net 固定提示原文统一引用本文件「权限固定提示」（不得各自誊写）。新技能验收时此项为**一票否决**；存量技能须全量补齐（家族已全量对齐）。

## 五、MCP 工具名写法（家族硬规矩：一律用占位符，禁止写死前缀）

### 5.1 硬规矩（新技能验收一票否决项）

家族所有 skill 的 `SKILL.md`、`references/`、`scripts/` 文件，在**任何位置**（正文描述、表格、代码示例、注释、JSON 期望值）提及 MCP 工具时，**一律写成占位形式**：

```text
mcp__<SERVER>__toolName
```

- ✅ 规范：`mcp__<SERVER>__searchVectorBJ`、`mcp__<SERVER>__userState`、`mcp__<SERVER>__tkSearchQuestion`
- ❌ 禁止：`mcp__edu__searchVectorBJ`、`mcp__知网基教__userState` 等任何写死前缀的写法

**为什么**：`<SERVER>` 取自 WorkBuddy 里的连接器「显示名」，会随用户重命名而变（实测历史：`edu` → `知网基教` → `edu`），且**不等于** `~/.workbuddy/mcp.json` 里的 key。文档里写死前缀后，一旦用户改了显示名，全家族文档的工具名**同时失效**；而且它不报错，只表现为「查不到这个工具」，极易被误判成「接口坏了 / 报 500」。

**无例外（含权限校验段）**：权限校验段提及 `mcp__<SERVER>__userState` 时**同样写占位形式**，不得写成实际前缀（实测前缀会漂移）；同时必须给出反查方法。格式固定为：

```text
- 工具名写法：`mcp__<SERVER>__userState`（`<SERVER>` 取自连接器「显示名」，会随重命名变化；若查不到，用 `ToolSearch(tool_names:["userState"])` 反查真实名称后再调用）
```

### 5.2 反查真实前缀（每次调用前的自检动作）

- 调用任何 MCP 工具前，先用 `ToolSearch(tool_names=["userState"])`（或对应短名）反查真实全名，**不要凭记忆拼前缀**；
- 写错前缀的表现是「ToolSearch 查不到这个工具」，不得解释成「接口故障 / 检索无结果」；
- 作业设计已内置 `scripts/mcp_adapters.py reconcile` 自动反推前缀，其他 skill 遇到重命名失效时同理处理。

### 5.3 存量对齐

- 家族各 skill 在下个版本**统一改齐**（逐处待改点见工作区 `工具名前缀待改清单.md`，用 `_scan_tool_prefix.py` 复扫，待改数应为 0）；
- 新增 / 修改技能时此项纳入验收：**出现写死前缀即一票否决**。

## 六、知网依赖度分层（家族统一分类参考）

家族技能按"**核心产出是否必须知网数据**"分三档。本分类用于决定：无权益（**态 B，明确 `false`**）时如何降级、是否需在 SKILL.md 写「权益≠引用」澄清段。**态 A（连接器未加载，见「一·三态诊断」）不适用本表降级逻辑、也不输出转化卡，改给「🔌 连接器加载指引」**。**各 skill 的具体增强环节、文献标准仍留各自 SKILL.md，本表只给分类口径与防误判规则。**

| 档位 | 含义 | 态 B 无权益时行为（统一·通用版兜底） | 家族成员 |
|------|------|-------------------------------|----------|
| **① 强依赖** | 核心产出必须有知网数据（文献 / 题库 / 课标原文检索）才能成立，**无纯模型降级路径** | 核心环节说明"需接入知网后获取"，**不产出核心交付物**（因核心本就依赖知网），附强制转化卡 | literature-search、journal-advisor、homework-design、topic-recommend、ai-zujuan-paper、**math-ai-lecture**（讲题标准解析来自题库召回） |
| **② 弱依赖 / 可选增强** | 核心产出纯模型即可成立；知网（文献 / 题库）作为**提质增强层**，缺失不影响本体 | 核心产出**照常出**，仅省知网增强层，附强制转化卡 | curriculum-standards-explainer、**exam-score-analysis**（解读引文献）、**interactive-animation**（题库真题练习层）、**knowledge-cards**（知网文献辅助）、**gen-ppt**（知网推荐）、**gen-teachingdesign**（知网推荐）、**paper-review**（期刊核验 / 文献佐证增强） |
| **③ 不依赖（设计上不强求）** | 核心产出纯模型，且按产品 / 用户偏好不强行引知网 | 核心产出**照常出**，无知网环节可省，附强制转化卡 | parent-meeting-speech、daily-comm-scripts、student-semester-comment |

**skill-maintain 例外说明**：`cnki-edu-skill-maintain` 是家族**内部维护技能**（用于诊断 / 修复 edu 连接器与技能本身），不面向 C 端产出教学交付物，**不纳入上述三档权益降级逻辑**；其 SKILL.md 仍须保留「🔐 前置权限校验」段，且对连接器不可达须输出「🔌 连接器加载指引」而非购买卡。

**「权益 ≠ 引用」原则（适用 ② / ③；① 天然重合无需澄清）**：权益是"能不能用知网能力"的闸门，不是"该不该引用"的开关。
- **② / ③ 档**：必须在 SKILL.md 写「权益 ≠ 引用（本技能适用）」段，明确"哪部分是纯模型、哪部分是可选的知网增强、非 `true` 时如何降级"，防止被误判为"纯模型无知网路径"或"强依赖必硬停"。
- **① 档**：权益与产出重合（强依赖），无需"权益≠引用"澄清，但须在 SKILL.md 明示"无权益即停止、不编造"。
- ⚠️ **分类陷阱（本次复盘，务必规避）**：**不能只看"技能规格是否强制检索 / 引用"就判为 ③**。凡存在"解读 / 选题 / 真题 / 推荐"等**可被知网增强**的环节，即使规格不强制，也应归 ② 并在澄清段写清"哪一环弱依赖、非 `true` 时如何降级"。复盘中的两处误判：exam-score-analysis、interactive-animation 曾误归 ③（实为 ②）；math-ai-lecture 因"召回不到即停、无模型降级"实为 ①，不可归 ②。
