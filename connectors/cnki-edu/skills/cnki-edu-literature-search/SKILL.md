# cnki-edu-literature-search · 知网 edu 文献检索

> 面向所有人可安装的**通用** skill：通过**知网 edu（研学 / 基教）MCP** 的文献检索能力获取结果。
> 不依赖任何私有桥接、本地脚本或宿主专属工具——只要连接了知网 edu MCP 即可使用。

## 前置条件（安装者必读）

- 在 WorkBuddy 中**连接「知网 edu」（研学 / 基教）MCP 连接器**。
- 连接后，文献检索工具会以 `mcp__<SERVER>__searchVectorBJ` 的形式出现在可用工具列表中，
  其**叶子名为 `mcp__<SERVER>__searchVectorBJ`**。
- 本 skill **不绑定具体连接器显示名**：Agent 直接调用已连接的 `mcp__<SERVER>__searchVectorBJ` 即可；如需显式写全名，
  把下列说明中的 `<SERVER>` 替换为你的连接器显示名。
- 无需任何本地脚本、私有工具或端口。

## 触发场景

当用户说出以下意图之一时触发本 skill（自然语言判断，无需正则匹配）：

- 查找 / 搜索某主题、关键词、作者、机构、来源、基金、时间范围内的文献或论文
- 「……有哪些文献」「关于……的论文」「……相关的研究」
- 泛指「文献检索」「查论文」
- 带年份 / 时间范围约束的检索，如「2024 年之后的」「近三年的」「2020 年以来的」
- 用户给出**一整句 / 诗句 / 名言 / 段落**并想找"包含这句话的文献" → 走「段落检索模式」（`mcp__<SERVER>__searchVectorBJPara`，列表格式输出，见「段落检索输出格式」）
- **用户明确要「文献片段 / 原文 / 摘录 / 段落素材」用于出题、摘录、阅读理解或阅读素材，但「未提供任何具体句子」** → 仍走「段落检索模式」（`mcp__<SERVER>__searchVectorBJPara`），但改用**主题发散检索**（`query_type=1`，不要求命中某句原文），返回与主题相关的原文片段列表。这是为"想要可直接引用的原文，但不给具体句子"的场景兜底——区别于纯关键词列表诉求，此时用户要的是片段本身而非文献目录。

## 调用方式

调用已连接的**知网 edu MCP** 中的文献检索工具 `mcp__<SERVER>__searchVectorBJ`，传入用户原始检索词：

```json
{
  "text": "$QUERY"
}
```

- 完整工具名形如 `mcp__<SERVER>__searchVectorBJ`；`<SERVER>` 为你的连接器显示名，可省略，由 Agent 按可用工具自行匹配。
- `$QUERY`：用户原始检索词，**一字不改，原样传入**，严禁二次理解、拆分或编辑。
- **严禁**对 `$QUERY` 做任何改写、翻译、扩写或拆词。
- 可选参数（非必填）：`query_type`（0 篇名 / 1 摘要 / 2 小标题 / 3 主题，发散检索用 3）、`maxRecallNumber`（默认 20）、`type`（0 期刊 / 1 硕士 / 2 博士 / 3 会议 / 4 报纸，逗号分隔）、`nprobe`。

### 文献检索

当用户给出主题、关键词、研究方向、作者、机构、来源、基金、时间范围或其他检索条件时，
调用 `mcp__<SERVER>__searchVectorBJ`，参数如下：

## 段落检索模式（按句子 / 整句找文献）

当用户给出**一段完整的句子、诗句、名言或段落**，希望找到**包含该句（或语义相近段落）的文献**时，不走文档级 `mcp__<SERVER>__searchVectorBJ`，改走段落级 `mcp__<SERVER>__searchVectorBJPara`，并改用「段落列表」格式输出（见下文「段落检索输出格式」）。

### 何时走段落模式
- 用户直接粘贴/引用一整句（如诗句、文言句、政策原文、定义句）来"找包含它的文献"。
- 用户说"用这句去搜""按这句话找文献""哪篇文献里有这句"。
- 与文档模式区分：文档模式（`mcp__<SERVER>__searchVectorBJ`）回答"关于某主题的文献有哪些"；段落模式回答"这句话出现在哪些文献的哪个位置"。
- **用户要"文献片段 / 原文 / 摘录"用于出题、摘录、阅读素材，但未提供具体句子**：此时没有"原句"可定位，但仍属段落模式——调用 `mcp__<SERVER>__searchVectorBJPara` 时务必用 `query_type=1`（段落主题发散），以主题词检索并返回相关的原文片段，而不是只回目录列表。这是本 skill 对"关键词触发 → 却要片段"这一常见诉求的兜底分支。

### 调用方式
调用 `mcp__<SERVER>__searchVectorBJPara`，参数：

```json
{
  "text": "$QUERY",
  "query_type": 1,
  "maxRecallNumber": 20
}
```

- `text`：用户原始句子，**一字不改，原样传入**（必填，参数名 `text`）。
- `query_type`：0 篇名小标题 / 1 段落主题（默认 1，发散找段落用 1）。
- `maxRecallNumber`：最多返回数，默认 20；段落模式**默认展示前 10 条**（见输出格式，可调）。

### 字段映射（mcp__<SERVER>__searchVectorBJPara 返回结构）
`mcp__<SERVER>__searchVectorBJPara` 实际返回（关键字段）：`Title`(篇名) / `Author`(作者) / `Source`(来源) / `JournalName`(期刊名) / `Year`(年份) / `PubDate`(发表日期) / `当前小标题`(所在章节小标题) / `章节序号` / `PhysicalPage`(物理页) / `JournalPage`(期刊页) / `正文`(命中段落全文) / `url`(官方阅读链接) / `相关度`。

映射到段落列表的 7 项：

| 输出项 | 来源字段 | 说明 |
|---|---|---|
| 文献标题 | `Title` | 直接取 |
| 作者 | `Author` | 去结尾多余分号 `;` |
| 来源 | `JournalName` 优先，否则 `Source` | 同文档模式 |
| 发表时间 | `PubDate` 优先，否则 `Year` | 同文档模式 |
| 段落位置 | `当前小标题` | 命中段落所在章节小标题；可附 `章节序号` / 页码(`PhysicalPage`/`JournalPage`)增强定位；报纸无小标题时填「报纸全文」 |
| 段落内容 | `正文` | 接口返回的命中段落全文（可能较长，建议截断到 ≤200 字，超出加"…"） |
| 阅读地址 | `url` | 即用户模板中的 `CnkiRefMarker`，渲染为 `[阅读](url)` |

### 段落排序（默认规则）
与文档模式一致（见「结果排序」）：先按**期刊优先**分组（`type_rank`），组内按**发表时间倒序**（新在前），同年按**质量分 `CitedTimes×1.0 + DownloadedTimes×0.02` 倒序**；同时参考接口 `相关度`（距离越小越相关）辅助判断。段落模式尤其建议优先展示**真正包含原句**且相关度最高者。

## 出题素材表（段落检索的增值整理，按需启用）

当用户在段落检索结果基础上，明确要求「整理成出题素材表」「做成 Word/Markdown 素材表」「方便存档 / 下发」时，在已返回的段落片段之上做**增值整理**——输出一张四列 Markdown 表格，而非仅展示原始段落列表。

> 注意：本表是段落检索结果的再加工，必须**基于 `mcp__<SERVER>__searchVectorBJPara` 真实返回的字段**生成，不得编造出处、片段、题型或考点；「适用题型 / 建议考点」为 AI 依片段内容推断的辅助信息，须在表头或单元格中注明"建议"。

### 四列结构

| 输出列 | 来源 / 生成方式 | 说明 |
|---|---|---|
| 出处 | `Title`+`Author`+`Source`+`PubDate`+`url` | 文献标题、作者、来源、发表时间合并为「出处」单元格，并附 `[阅读](url)`；与段落检索字段一一对应 |
| 原文片段 | `正文`（命中段落全文） | 取自接口 `正文`，保留原句；过长可截断到 ≤200 字并加"…"，但不得改写语义 |
| 适用题型（建议） | AI 依片段内容推断 | 如：选择题 / 填空题 / 判断题 / 简答题 / 生活实践题；可多选 |
| 建议考点 | AI 依片段内容推断 | 片段可考察的知识点，如"磷酸铁锂 vs 三元锂特性对比""电池成本结构占比"等 |

### 成功表格结构要求

- 表头固定为：`| 序号 | 出处 | 原文片段 | 适用题型（建议） | 建议考点 |`
- 分隔线：`| --- | --- | --- | --- | --- |`
- 每条数据行完整独占一行，行首行尾均有 `|`；`出处` 单元格内可含 `[阅读](url)` 链接（url 中 `&` 无需转义）
- 单元格内若出现 `|`、换行等破坏表格的字符，替换为 `、`、`／` 或空格
- 默认展示前 10 条（对应段落检索默认展示数）；用户要求"全部"时可放宽，但以可读性为先
- 表前加一行说明，如：「以下基于上文段落检索结果整理为出题素材表（题型 / 考点为建议项）」

### 适用场景示例

- "把这几段整理成出题素材表"
- "做成 Word/Markdown 素材表，含出处、片段、题型、考点"
- "方便我直接下发，给个四列表格"

## 字段映射说明（mcp__<SERVER>__searchVectorBJ 返回结构）

> 以下字段为**接口实测已返回**的真实字段（2026-10 之后版本）。接口升级后，作者 / 来源 / 年份 / 被引 / 下载 / 摘要 / 官方阅读链接**均直接返回**，无需再靠文件名推断或自行拼链接。

`mcp__<SERVER>__searchVectorBJ` 实际返回（节选关键字段）：`Title`(篇名) / `Author`(作者) / `Source`(来源) / `JournalName`(来源·期刊名) / `Year`(年份) / `PubDate`(发表日期) / `CitedTimes`(被引) / `DownloadedTimes`(下载) / `Summary`(标准摘要) / `Keyword`(关键词) / `AuthorAffiliation`(单位) / `Page`(页码) / `Issue`(期) / `DOI` / `url`(官方在线阅读链接) / `product`(产品库) / `resource` / `ResourceType`(资源类型中文) / `TableName`(数据表名) / `文件名`(文件编码) 等。

据此映射到 9 列输出：

| 输出列 | 来源字段 | 说明 |
|---|---|---|
| 文献标题 | `Title` / `篇名` | 直接取 |
| 作者 | `Author` | 直接取；**去掉结尾多余的分号 `;`**（如 `言咏;` → `言咏`，`李昶洁;张海蓉;` → `李昶洁;张海蓉`） |
| 来源 | `JournalName` 优先，否则 `Source` | 期刊取 `JournalName`，报纸 / 会议取 `Source`；接口已返回，直接取 |
| 发表时间 | `PubDate` 优先，否则 `Year` | `PubDate` 形如 `2026-04-15`（含月日）；无月日时退回 `Year`(如 `2026`) |
| 文献类型 | `ResourceType` / `product` | `ResourceType` 直接为中文（期刊 / 报纸 / 硕士 / 会议）；亦可据 `product` 映射：CJFD=期刊、CCND=报纸、CMFD=硕士、CPFD=会议、CDMD=博士（`product` 为知网内部产品库代码，仅 agent 侧解析映射用，不展示给用户） |
| 被引 / 下载 | `CitedTimes` + `DownloadedTimes` | 合并为一列，形如 `0/340`（被引/下载）；缺项用 `-` |
| 摘要要点 | `Summary` 优先，否则 `正文` / `小标题` | `Summary` 为接口标准摘要，最干净；报纸等无 `Summary` 时可回退 `正文`/`小标题`，仍无则填 `-` |
| 阅读地址 | `url` | 接口直接返回官方在线阅读链接（形如 `https://xfat.cnki.net/read/article/readonline?dbcode=...&filename=...`），**直接渲染为可点击链接**：`[阅读](url)` |

### 年份筛选（按接口 `Year` / `PubDate` 字段）

- 接口已直接返回年份：`Year`(如 `2026`) 或 `PubDate`(如 `2026-04-15`)。
- 支持按年份 / 时间范围筛选：**从 `Year`（或 `PubDate` 前 4 位）取值**，过滤满足条件的条目。
  - 「2024 年之后」→ 保留 `Year >= 2024`
  - 「近三年」→ 保留 `Year >= 当前年 - 3 + 1`（如 2026 年检索则 `Year >= 2024`）
  - 「2020 年以来」→ 保留 `Year >= 2020`
- **不再依赖文件名编码推断年份**（接口升级后年份字段已可靠）。仅在极端情况下 `Year`/`PubDate` 同时缺失时，才回退到 `文件名` 编码的 4 位年份兜底。

> 原则上接口已返回的字段（作者 / 来源 / 年份 / 被引 / 下载 / 摘要 / 链接）**如实取数、不得编造**；仅当个别字段确实缺失时，使用 `-` 占位。

## 结果排序（默认规则）

用户对检索结果的核心诉求是「质量好、时间新」——把**最新发表、且学术质量高**的文献排在最前；同时默认**期刊优先于其他文献类型**（期刊排在前面，硕士 / 博士 / 会议 / 报纸等其余类型也完整保留、紧随其后）。

接口默认按相关度返回，未必满足该诉求，因此**输出表格前必须按以下规则重排**：

0. **类型优先级（最前置键）：期刊置顶，其余其后**
   - 判定：`resource` / `ResourceType` 为「期刊」（或 `product` = `CJFD`）→ 排第一组（最前）；硕士 / 博士 / 会议 / 报纸 → 排第二组（其后）。即 `type_rank = 0 if 期刊 else 1`，先按 `type_rank` 升序分两大组。
   - **调用时不限制 `type`**（保持默认 `0,1,2,3,4` 全类型检索），通过排序把期刊顶到最前，其余类型仍完整保留——满足「期刊优先、其他的也得有」。
   - 仅当用户明确说「只要期刊」「别给我报纸」时，才在调用层用 `type` 参数收窄；否则不收窄。
1. **主排序键：发表时间倒序**（最新在前）
   - 取值自 `PubDate`（如 `2026-04-15`）或 `Year`（如 `2026`）；日期 / 年份较大者在前。在「期刊组」与「其余组」内分别生效。
2. **次排序键：质量分倒序**（同组内同年份比质量）
   - `质量分 = CitedTimes × 1.0 + DownloadedTimes × 0.02`
   - 被引权重最高（代表学术认可度）；下载量通常比被引大 1–2 个数量级，故缩权 `×0.02` 避免淹没被引。
   - `CitedTimes` / `DownloadedTimes` 缺项按 `0` 计。
3. **带时间窗口的检索**（如「近三年」「2024 之后」）：先按年份过滤，再套 0–2 排序。窗口已保证「新」，可在窗口内直接按质量分倒序突出质量最佳者。
4. **学科 / 学段相关性：仅作结果标注，不强制过滤**
   - 用户未明确指定学科时，**不做学科过滤**，所有命中文献均按 0–2 排序展示。
   - 仅当用户明确说「语文学科相关」「只要语文的」等时，才在结果中**优先展示学科相关项并加学科标注**，但不删除其他命中（除非用户说"只要"）。
5. **覆盖规则**：用户明确要求「按被引排序」「按时间排序」「只要期刊」等时，以用户指令为准，覆盖本默认。

> 为什么「期刊优先」作为最前置键：教育 / 教研场景下期刊（尤其核心 / 普教类刊）时效性与可引用性最佳，用户通常想先看到期刊。其余类型（博硕 / 会议 / 报纸）仍保留在期刊之后，满足"其他的也得有"。
> 为什么不用纯「被引」排序：新文献尚未积累被引，纯被引排序会把陈旧经典顶到最前，与「时间新」诉求冲突。故采用「期刊优先 + 年份优先 + 同年比质量」的写法。

## 输出格式（文档级 · `mcp__<SERVER>__searchVectorBJ`）

> 本节为**文档级**检索（`mcp__<SERVER>__searchVectorBJ`）的表格输出规范。若用户按"整句 / 诗句 / 段落"检索，请改用上方的「段落检索输出格式」。

返回结果必须使用 Markdown 表格展示原始检索结果。

要求：

- 必须基于知网 edu MCP（`mcp__<SERVER>__searchVectorBJ`）返回结果展示
- `$QUERY` 必须使用用户原始输入文本，一字不改，严禁二次理解、拆分、编辑用户输入文本
- 返回结果必须使用 Markdown 表格展示检索结果，严禁只输出对检索结果的二次整理和总结
- 若用户给定年份 / 时间范围约束（如「2024 年之后」「近三年」），**先从每条的 `Year`（或 `PubDate` 前 4 位）取值，仅保留满足条件的文献**，再输出表格；不满足条件的一律不展示
- 不允许原样输出 JSON
- 不允许原样输出接口响应
- 不允许模型自行补充、扩展、编造或从其他来源追加文献。**用户明确授权的例外**：用户在当前对话中明确要求「用你已有的知识 / 不依赖检索」给出文献时，可按通用版列出模型知识中的文献，但清单开头必须标注「以下为通用知识整理，非知网检索结果」，不得附知网链接、不得标 CNKI 溯源；未获明确授权仍严格执行本条
- 不允许再次调用其他检索工具
- 不允许伪造文献标题、作者、来源、时间、摘要或链接
- 如果字段缺失，使用 `-` 占位（99% 字段接口已返回，仅极个别缺失时用）
- 只展示接口返回结果中的前 20 条文献。如果返回结果超过 20 条，也只取前 20 条。严禁在返回结果大于等于 20 条的情况下展示少于 20 条数据
- 成功返回的说明区必须严格分行输出：第一行 `检索词：[用户查询词]`，第二行 `共找到 [总数] 条结果，当前展示前 [展示数量] 条。`，第三行为空行，然后再输出表格；`展示数量` 为实际输出条数，最多 20
- 表格中的每个单元格都必须保持单行，不得插入换行、项目符号或代码块
- `摘要要点` 基于接口返回的 `Summary`（或 `正文`/`小标题`）输出一句话，建议控制在 20-40 个汉字，超过 60 字必须省略，禁止输出摘要全文
- `阅读地址` 单元格渲染为 Markdown 链接 `[阅读](url)`，整条 `url` 放在括号内，url 中的 `&` 无需转义
- 标题、作者、来源、摘要要点都要尽量短，避免占用过多宽度
- 如果字段中出现 `|`、换行或其他会破坏表格的字符，必须替换为 `、`、`／` 或空格
- 不要使用代码块包裹最终回答

### 成功表格结构要求

- 成功返回时只允许输出一张 9 列 Markdown 表格，不要输出第二套表头或第二种表格格式
- 9 列顺序必须固定为：`序号`、`文献标题`、`作者`、`来源`、`发表时间`、`文献类型`、`被引/下载`、`摘要要点`、`阅读地址`
- 表头必须完整独占一行，且严格使用：`| 序号 | 文献标题 | 作者 | 来源 | 发表时间 | 文献类型 | 被引/下载 | 摘要要点 | 阅读地址 |`
- 分隔线必须完整独占一行，且严格使用：`| --- | --- | --- | --- | --- | --- | --- | --- | --- |`
- 每条数据行必须完整独占一行，行首和行尾都必须有 `|`，去掉行首行尾 `|` 后必须正好有 9 个单元格
- `阅读地址` 单元格渲染为 `[阅读](url)` 形式的可点击链接（url 为接口返回的官方链接）；未返回则填 `-`
- 作者列需去掉字段结尾多余的分号（`;`）

### 流式输出稳定性要求

- 生成表格时，必须按“表头行 → 分隔线行 → 数据行”的顺序连续输出，不要在中间插入空行
- 每条数据行应一次性生成完整行，禁止将同一行拆分为多段补写
- 表头、分隔线、数据行前后都必须有换行；禁止把分隔线接在表头同一行
- 禁止拆分任何表头字段，尤其 `阅读地址` 必须保持在同一个单元格、同一行
- 如果当前条目内容过长，优先截断 `摘要要点`，不要让表格结构断裂
- 输出表格前先自检：表头 9 列、分隔线 9 列、每条数据 9 列、无单元格换行、无第二套表头、无代码块包裹

### 文件导出 / 存档清单规范（链接一律可点击，不展示裸地址）

当用户要求把检索结果**生成独立文件**（Markdown / Word / Excel 等）用于存档、引用或下发时，除遵守上方表格格式外，额外遵守：

- **CNKI 链接列**：所有指向 `https://...cnki.net/read/...` 的官方阅读链接，**必须以 Markdown 可点击超链接形式呈现**（如 `[在线阅读](url)` 或 `[阅读](url)`）；**严禁以裸 URL 文本展示完整地址**——界面 / 文档中只显示可点击文字，地址仅作为链接 target 存在于源码，不向用户复述。
- 表头中「阅读地址」「CNKI 链接」等列名，建议统一改为中性可点击列名（如「在线阅读」）。
- 本规则同样覆盖对话内直接给出的表格：任何出现 CNKI 链接的地方，都只呈现可点击链接、不暴露长地址。
- 生成文件后，向用户说明"链接已设为可点击超链接，点击即可打开"，无需再列出完整 URL。
