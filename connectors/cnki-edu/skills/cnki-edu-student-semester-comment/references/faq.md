# 常见问题全集（按需加载）

> 本文件是 `SKILL.md` 「常见问题」一节的完整版，仅在高频疑问出现时查阅，不在主文件展开。

## 常见问题

- **用户要求把具体分数/名次写进评语（与现行口径冲突）**：**按原规则写，但不说破**——
  分数一律转化为程度描述（"往上走了一个台阶""跨度很大"），
  **不要在回复里讲"这与 skill 口径冲突""脚本会预警""规则不允许"**，也不请示是否放宽。
  规则照守、话术照常；只有当"不写分数就没法成文"（材料只有分数一个信息点）时，
  才去问**材料**（平时怎么学的、有什么习惯细节），而不是问能不能写分数。详见 SKILL.md 工作流程 Step 7
- **写几个人、交付形态怎么定**：**默认按人数自动分流，不用问用户**——**1~3 人**直接在页面
  输出「人名（有就写、没有就不写）+ 评语正文」，**不出表、不落盘**；**4 人及以上**才出 xlsx。
  边界 3 人算在文字侧（"多于 3 人"＝4 人起）。详见 SKILL.md 工作流程 Step 7
- **用户说「只要评语正文，其他不输出」/「直接给文字就行」**：走 Step 7 的「只要正文」模式——
  回复体里只有评语本身，不发文件、不落盘、不讲小贴士、不附质检结论，**且优先于人数分流**
  （哪怕 10 人也只输出正文）。**写作口径一条不松**（语气基调、五条硬规则、机检照跑），
  只是不外露执行痕迹。这是输出层的裁剪，不是降级；用户没说就按人数分流
- **用户只粘贴了一段表格文本**：先整理成 xlsx/csv 再走 Step 2，列名以用户原表为准
- **用户直接发来图片（截图 / 照片 / 手机拍的奖状）**：**先读图转写成标准表**，再走 Step 2——
  图片只是录入通道，转写完之后与原链路完全一致。三条硬口径：**回读确认**（姓名/数字/级别
  列成清单让用户核对）、**读不出就留空绝不猜**、**图上没标注的数字不当分数用**。
  脚本不吃图（传 `.png/.jpg` 会被友好拒绝）。详见 `references/image-intake.md`
- **用户发来的是一张"成绩趋势图"（柱状/折线），不是成绩表**：只能得出**趋势**
  （"一次比一次稳"），不能得出分数——除非图上直接标了数值标签，那时才可以转写，且仍要回读确认
- **用户给的奖状照片里没有学号**：正常，奖状本来就没有学号。只有姓名列即可；
  重名或姓名写法不一致时脚本会进「疑似同一人 / 姓名冲突」，**必须问用户**，不要自己认
- **评语里想写竞赛获奖 / 担任职务**：只有 `荣誉奖项` 或教师描述里有出处才能写
  （`--awards` 就是为此而生）；没有材料就是虚构，`award_flags()` 会预警。
  写了就**必须忠于原文**——校级不写成市级、三等奖不写成一等奖
- **输入是多工作表成绩册**（全科汇总 + 单科表 + 统计表 + 小题得分明细）：先跑一次适配，抽出
  「学号/姓名/班级 + 各科 + 总分/排名」的标准宽表再进 Step 2。可参考 `scripts/adapt_exam_workbook.py`
- **只有成绩、没有作业/课堂/教师描述**：仍可做，但「具体细节」要换证据源——用**逐题得分与知识点得失**
  顶上（"圆锥曲线那道大题一步没漏""英语作文写满拿满分"都是真实材料细节，不是虚构）。
  此时评语里绝不能出现作业提交率、课堂发言、纪律这类没有材料支撑的表述。
  `export_comments.py` 会把整体缺失的材料类型写进表下「小贴士」，交付时照读给用户。
  **有往年评语时它也能顶一部分**——但只能写"稳定的特点"与延续性，不要当成本学期的观察
- **只有成绩没有期中对比**：`roster.json` 的排名变化为空，分层里的「C 波动待稳」无法判定，
  不要硬凑 C 层，在最终回复里讲清楚
- **用户要「核心印象标签 / 分层 / 证据来源」这些内部字段**：交付表里默认不出现，直接从
  `comments.json` 取给他，或临时加列另存一份，不要因此改掉标准交付形态
- **用户嫌小贴士里的某条没必要**（如只做期末存档、不参评三好）：出表时加 `--skip-tips 5,6`
  按**固定编号**跳过即可（1教师描述/2课堂/3作业/4上次对比/5分科逐题/6体质劳动），
  也可以用负数从末尾倒数（`--skip-tips -1`），**不用改脚本源码**
- **成绩表列名是「期末语文」「语文(150分)」这类写法**：直接跑，识别规则是「列名含学科名就算」，
  不再因为列名里有「期末」就整列丢；含「期中/上次」的列会作为历史列另作提示，
  某科只有历史列、没有当前列时会退回当本次用，不会整科丢失
- **同一门课用了简写（「道法」＝「道德与法治」）**：词表与归一规则在 `scripts/subjects.py`，
  常见简写已内置。三种情况都已覆盖：① 表里只写「道法」→ 正常识别；
  ② 「道法」与「道德与法治」两列并存 → 只取前一处并提示，不会把同一门课算两次
  （否则班均与学科偏差会整体失真）；③ 「道法」＋「期中道德与法治」并存 → 历史列**不会**被误救成新学科。
  用 `--subjects` 传简写、表里写全称（或反之）也能对上，并会提示已按同学科写法匹配
- **`--subjects` 传了却报「列找不到」**：旧版把参数字符串按「字符」遍历，
  「语文,数学」会被拆成「语」「文」「,」「数」「学」。已在 `prepare_roster.py` 修掉
- **列名里有学科词但整列是等级**（如「语文等级」A/B/C）：脚本会按「整列是文本等级、解析不出分数」
  判掉并提示，不会把全班误判成缺考
- **选考 / 走班科目**（新中考选物理/历史二选一、某科只有一半人考）：**已支持**。脚本不再把
  「有分数的人不足一半」当成等级列丢掉，而是保留该科并标进 `meta.选考科目`；
  未选考的同学不计该科缺考、该科也不计入总分（否则总分不可比）。**旧的"整科消失 + 全班被判缺考"
  已修掉**，评语里对未选考的同学不要写该科
- **成绩表底部有「班级平均」「年级最高」这类统计行**：脚本按「学号空 + 姓名含统计词」自动剔除，
  不会变成一个要写评语的"学生"（旧版会让它进名单，然后报「漏写」）
- **表里同时有「班级排名」和「年级排名」**：排名类字段一律以**班级排名**为准，年级排名只做提示；
  如果**只有年级排名**，本次就不做排名分位与排名变化（年级排名的位次基数不同，直接当班级排名用
  会让整班分层错位）
- **成绩表有同名学生**：不同学号同名正常处理，脚本会点名列出，优先靠学号匹配；
  **没有学号**且同名 → 按出现顺序编「张三1号」「张三2号」（不再报错停止，但会要求人工核对）；
  同一学号重复出现 → 直接报错，必须先修表
- **成绩表没有学号列 / 有列但整列为空**：不报错。脚本忽略学号、以姓名为主键，
  `roster.json` 里每生的「学号」字段就是姓名（重名者带 1号/2号后缀），
  `comments.json` 直接抄这个字段即可与名单对上；`meta.主键` 会注明本次用的是哪种。
  **但有学号列、却只有部分行填了学号时不放过**：直接报错中止——一次对齐里混用
  「学号 / 姓名」两种主键会让附表匹配口径漂移。请补齐学号，或把学号整列删掉
- **表格第一行是标题、第二行才是表头**（或有多行合并表头 / 多个工作表）：**已支持**，
  直接喂 `--scores` 即可。脚本会跳过标题行、拼出「第1次-数学」这类列名，
  多工作表时按考试先后自动选本次/上次/平时（`scripts/read_workbook.py`）。
  唯一要人工介入的情况：两张成绩表名字看不出先后 → 报错并请你用 `--scores-sheet` 指定
- **期末、期中、平时是三个独立文件**（每个文件里工作表名还都叫「Sheet1」）：**已支持**，
  **一起传给 `--scores`** 就行（`--scores 期末.xlsx 期中.xlsx 平时.xlsx`，
  路径也可以是逗号分隔的一个参数；只传一个文件的行为完全不变）。
  脚本按**文件名**给通用表名贴标签（「初一3班期末考试成绩」），再按同一套规则分流成
  本次/上次/平时，不需要用户先手工合成一个工作簿。
  ⚠ **只传一个文件的代价是静默的**：少了期中表就没有「总分变化/排名变化」，
  少了平时表就丢掉「学习习惯」维度唯一的证据源——**两者都不会报错**。
  因此只传一个成绩文件时，脚本会在控制台打 `[重要提示]`，点名同目录下还有哪些
  文件名带「期中/期末/平时/成绩」的表，**这条必须原样读给用户**，让他决定要不要一起传。
  文件名看不出先后（「表一」「表二」）时仍**报错**，用 `--scores-sheet` 指定；
  传多个文件时标签就是文件名（如 `--scores-sheet 初一3班期中考试成绩`）。
  另外：成绩分散成「一人一行一科」的长表仍要先转宽表，多文件帮不上这个忙
- **用户上传了往年（上学期）学生评语**：走 `--past-comments`（技术上也认 `--notes`，
  但那会把往年与本学期混在一个字段里，不推荐）→ 落进 `roster.json` 的 `往年评语`，
  当"教师对学生的个性化描述"用，但**只作参考**：找这个人身上稳定的特点、保持与过去期待的连贯。
  **不得照搬去年措辞**（`similarity_check.py --past` 专门查这个），
  其中的事实须以本学期材料为准；往年评语里若含分数/名次，不得转述
- **往年评语里的旧结论与今年材料冲突**（去年"上课不发言"，今年课堂发言 15 次）：
  **以本学期材料为准**——写"这学期你开始举手了"，不写"你一直不太爱说话"。
  参考材料越位，比没有材料更糟
- **只有往年评语、没有本学期材料**：仍可写，但只能写"延续性"评语（去年那个特点 + 去年提过的期待），
  表下小贴士会提示补一份**本学期的**教师描述；不要拿往年事实当今年事实写
- **只有教师描述，没有统计表**：`--scores` 是必填主表，此时用教师描述表自己当主表
  （`--scores 教师描述.xlsx --notes 教师描述.xlsx`）——它没有分数列，脚本会按「没有成绩数据」处理
  并在控制台提示，评语中不得出现任何数字。**这条降级路径已跑通**（工作簿里可以有多张表，
  只要其中恰好一张是名单/描述表就会被自动选中；若有多张这种表则报错请你指定）
- **学生数少于 10 人（小样本）**：分位类规则整体失效（3 人时 D 层规则会把每个人都判成「需重点帮扶」），
  脚本已自动把「分层建议」标为「待人工确认」，必须人工分层并在交付说明里写明「已人工分层」
- **学生数超过 60 人**：分批写（每批 20 人），每批之间跑一次自检。注意**自检只查批内**，
  跨批的同骨架句式查不出来——每批换一个起手式基调，收尾句跨批也不许重复；
  **全部批次写完后，把所有批的 `comments` 合并成一个 json 再跑一次 `similarity_check.py`**，
  这才是唯一能查跨批句式复用的办法（脚本接受任意条数，60 条实测 0.5 秒）
- **某张表是长表**（每生每学科一行，含 6 次平时 + 期中 + 期末）：这种"一人一行一科"的结构仍需先转成
  宽表（一科一列）再喂 `--scores`。但如果只是**列的方向变宽**（表头是「第1次…第6次」横向跨各科），
  现在**不用手工转**——脚本会拼出「第1次-数学」，把 6 次整理成 `平时趋势`
- **6 次平时成绩怎么用**：脚本按用户口径**保留逐次序列、不取均值**。成文时**一律用标准式**
  引用序列：**「学科 + 第X次平时成绩 + NN分」**，例如
  「语文从第一次平时成绩74分提升到第六次平时成绩的87分」——哪一科、第几次、是平时成绩，一次说清。
  **不要**写「第1次的 74 一直涨到第6次的 87」「那条平时线」「六次记录」这类省略式/自造指代，
  也不要自己把 `逐次` 平均一下再写（均值抹掉的正是趋势，脚本也不产出均值字段）。
  没有作业表、也没有教师描述时，这条序列就是双证据原则里那个「具体/量化事实」的最佳替代，不算虚构。
  注意：跨期对比时，**本次总分/排名的列名要用「总分」「期末总分」「班级排名」「期末排名」**，
  上次的用「期中总分」「期中排名」——两者必须是**不同的列**。表里只有一列「期中总分」而没有
  本次总分列时，本次总分由各科求和得出，与上次不同源，脚本会**不产出「总分变化」**并说明原因
  （不再像旧版那样拿期中总分当本次总分、算出一个恒为 0 的"变化"）
- **用户要求"活泼一点/严肃一点"**：改的是语气层，不动结构和证据要求；**也不动「语气基调」**——
  优点照样要写足写具体，缺点照样只能给可执行的下一步（改完重跑 `similarity_check.py`）
- **用户要求"存档版/第三人称"**：只把第二人称"你"换成"该生"（全篇统一），
  基调与证据要求一条不动；不要顺手把语气写成"该生表现良好"的公文体
- **用户对某条评语不满意**：读 `roster.json` 该生的证据点，换一个切入点重写，不要在同一切入点上改词
- **用户嫌表扬不够/建议太软**：先确认是不是踩了"虽然…但是…"（优点被一句带过）；
  表扬不足补的是**材料里的具体事**，不是形容词；建议太软改的是**动作够不够具体**（时间+数量+动作），
  不是把话说重
- **评语里要不要写缺点**：要写，但必须是"可执行的下一步"，不是"你哪里不行"
- **学生个人信息（必读）**：输入的成绩、作业、课堂、教师描述都是**未成年人个人信息**；
  用户发来的**图片（成绩截图、奖状照片）里还可能有姓名、学校、照片、身份证号后四位**。
  只在本机处理；`roster.json` / `comments.json` 以及读图转写出的中间表属过程留档，
  交付完提醒用户自行删除或妥存，不要把原始表/图片/留档上传到任何在线文档、
  也不要在最终回复里附学生成绩明细（读图回读清单只列姓名与要点，不照抄整张成绩表）。
  **交付的 xlsx 连「文件属性」也要干净**：不出现作者=openpyxl、不出现生成库与版本号
  （脚本已自动清，见 Step 6「文件属性也不带生成侧元数据」）。
