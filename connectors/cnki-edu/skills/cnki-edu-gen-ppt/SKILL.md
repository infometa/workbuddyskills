# cnki-edu-gen-ppt · PPT 生成三步工作流

## 🔐 前置权限校验（最高优先级，必须最先执行）

> 权限校验的「三态诊断 / 通用版兜底 / 强制转化卡 / 连接器加载指引」统一见本技能 `references/_shared.md`「一、权限固定提示」，本章节仅保留本技能专属说明，不重复展开。

> **权益 ≠ 引用（本技能适用）**：PPT 正文（WebSearch 联网取真实内容 + ImageGen 生图）与总结文字**纯模型生成、不依赖知网**；「知网推荐」才是依赖 `mcp__<SERVER>__searchVectorBJ` 的增强层，缺失不影响 PPT 本体。权益是"能不能用知网推荐"的闸门，不是"该不该生成 PPT"的开关（无权益时 PPT 照出、仅省知网推荐）。

## 概述

本技能面向"从一句话需求到一份完整 PPTX"的场景，将生成过程拆解为三个步骤：**步骤 1（基础信息）与步骤 2（大纲）需逐级确认**，步骤 3（资料检索 + 配图 + 生成）直接执行。最终产出依次交付：

1. **完整 `.pptx` 演示文稿**：由**封面、目录页、过渡页、内容页、尾页（即总结页）**五类页面构成；以**内容页为主体**；根据主题**自动匹配风格与版式组合**（详见 `references/types-and-styles.md` 的"主题→模板映射"），内容页支持**图文 / 双栏 / 卡片 / 时间轴 / 对比 / 数据大字 / 表格 / 引言**等多种版式，避免千篇一律；
2. **PPT 内容总结文字**（一段话 ≤120 字，含页数/风格/内容概要，加前后衔接语）；
3. **知网推荐**（列表逐条、非表格，≤6 篇），**紧接 PPT 卡片下方直接展示**，**不进入 PPT 文件**：每条**只展示「文献名 / 作者 / 来源」三项**；**严禁以任何方式暴露知网的任何元数据**（发表时间、卷期页码、doi、数据库名、来源链路、检索语句、内部 id、链接地址等一律不可见）；**点击文献名一次直达**该文献在**知网研学平台的研读页面**（已登录且有阅读权限时直接在线阅读全文；未登录时弹出登录框，登录后自动校验阅读权限）；**《文献名》带跳转链接**（**不附带悬停提示**；跳转地址只作「文献名」的跳转目标，不以明文出现在可见文案里）。

**生成方式（重要）**：步骤 3 的 PPT 产出由本技能内置的 **PPT 渲染工作流**（SlideDSL + `slidep` 工具链）完成，详见 `references/generate-pptx-tencent.md`。本技能负责"需求确认 + 大纲 + 资料 + 配图规划"，渲染工作流负责"按设计稿逐页渲染成 .pptx"。

**配图方式（重要）**：配图统一由 **ImageGen 生图**提供（PPT 渲染工作流明确要求取消"搜图"、配图只能来自 ImageGen 或 SVG），按 **L1/L2/L3 三级**分级，并采用"**配图前置**"（写每页前先生成该页所需图、核对后再写页面）。详见 `references/research-image-guide.md`。

核心原则：**先确认（仅步骤1/2），再执行（步骤3一次跑完）；主题自动配模板、版式多样；配图用 ImageGen 生图前置（禁止搜图、禁止确认、绝不中断）；PPT 末尾带总结页；步骤 3 执行期间**同时展示「生成过程」（阶段进度）与「思考过程」（决策随想）**（轻松口吻、用户视角、无技术细节、无负面词）；最终在**左侧以卡片形式交付 .pptx（主交付物）、并打开右侧预览/编辑面板（可下载导出）**，并在 **PPT 卡片下方直接展示**「知网推荐」（仅展示文献名/作者/来源三项，禁止暴露任何元数据，点击文献名**一次直达知网研学平台的研读页面**（已登录且有权限即可**直接在线阅读全文**；未登录时**弹出登录框**，登录后**自动校验阅读权限**），且**《文献名》带跳转链接**）。**

## 触发关键词（结构化 · 含命中规则）

### 一、关键词矩阵（按语义维度）

| 维度 | 关键词 / 短语示例 | 触发强度 |
|---|---|---|
| 产物类（要的物件） | PPT、ppt、演示文稿、幻灯片、slides、课件、教案课件、汇报、汇报稿、演讲稿、宣讲材料、分享材料、班会、说课、答辩 | 强（单独出现即触发） |
| 动作类（生成意图） | 生成、做、写、制作、输出、出一份、弄一份、帮我做、帮我生成、来一份、整一份、整一个 | 中（需配合产物/场景） |
| 场景类（上下文意图） | 备课、上课、授课、培训、述职、周报/月报/季报/年报、教研、公开课、德育、主题活动、活动策划、产品介绍、项目宣讲、路演、总结、结业/毕业 | 中（需配合动作） |
| 口语/同义 | "做个PPT""来个课件""给我整一份汇报""把这段内容做成演示""帮我出个说课稿的幻灯片" | 强（整体即触发） |

### 二、触发判定规则

- **强触发**：产物类关键词**单独出现**（如"帮我做个PPT""来份课件""出个班会"）→ 直接触发，进入步骤 0。
- **组合触发**：动作类 + 场景类**同时出现**（如"帮我写一份述职汇报""生成教学课件"）→ 触发。
- **弱触发 / 待确认**：仅有动作类或模糊表述（"做个东西""帮我整理一下"）→ 结合上下文判断是否为 PPT 类需求，**疑似则触发**，否则不触发。
- **排除项**：明确指向非 PPT 产物（如"写篇论文""做个 Excel 表格""出张海报"）不触发。

> 命中任意触发条件即进入步骤 0 解析；无需用户显式说"用某个技能"。

## 适用场景（结构化 · 生成 PPT 的对应场景）

不同需求对应不同 PPT 类型与模板风格，结构化映射如下（详细类型/页数/版式见 `references/types-and-styles.md`）：

| 生成场景 | 典型需求描述 | 推荐 PPT 类型 | 推荐风格 |
|---|---|---|---|
| 备课授课 | 中小学/培训课堂要一份可讲的课件 | 教学课件 | 清新绿 |
| 工作述职 | 周/月/季/年度汇报、述职报告 | 工作汇报 | 商务蓝 |
| 教研交流 | 教研组/公开课经验分享、课题汇报 | 教研分享 | 科技紫 |
| 德育班会 | 班级主题活动、德育/心理班会 | 班会主题 | 中国风 / 卡通风 |
| 活动方案 | 校园/机构活动策划与执行方案 | 活动策划 | 商务蓝 / 清新绿 |
| 产品宣讲 | 产品/项目介绍、路演、招生宣讲 | 产品介绍 | 科技紫 |
| 自定义主题 | 其它任意主题（用户自拟或指定） | 其它 | 简约白 / 按主题自拟 |

> 类型识别不明确时，按"适用场景"给 2–4 个候选类型供选择，不默认假设。

## 全局规则

1. **两级确认门（仅 Gate 1 / Gate 2）**：基础信息（步骤1）与两级大纲（步骤2）产出后，用简洁确认卡片（交互式确认卡片，如 AskUserQuestion）向用户展示关键信息，待用户确认后再进入下一步；**步骤 3 一次性执行（资料检索+配图+生成脚本），不再中途询问**。用户未确认前不得推进步骤 2。
   - ⚠️ 确认卡片**只呈现用户需要决策的信息**（类型/风格/页数/语言/特殊要求/大纲的确认与修改项），**不得出现**"知网推荐""文献推荐""是否生图""生成图片""配图确认""第三步无需确认""无需确认"等内部流程或配图相关提示文字。
   - ⚠️ **确认卡片禁止"跳过"（修复"已确认却显示跳过"）**：确认卡片**只设「确认」与「修改」两类操作**，**严禁出现"跳过/略过/默认跳过"等选项或文案**；用户点击「确认」后必须**立即推进对应 Gate**，并将卡片状态明确标记为「**已确认**」——**绝不允许把已确认的结果渲染、表述或展示为"跳过"**。若所用确认机制带有默认"跳过"入口，不要使用它，必须等待用户显式「确认」或「修改」后再继续。
2. **沟通术语**：对用户统一使用「页 / 封面 / 目录 / 这一页」，不暴露 slidep、SlideDSL、.slide、project_dir 等内部实现。
3. **风格与配色**：默认低饱和度、简洁统一；分类标识用 tag/badge 样式而非 button/chip 样式（遵循产品既有规范）。低饱和配色预设见 `references/types-and-styles.md`，并作为 `PPT 渲染工作流` 的 `DESIGN.md` 色彩池输入。
4. **页面构成与页数控制**：默认页数由类型决定（见 `references/types-and-styles.md`），用户可覆盖。一份完整 PPT 由五类页面构成——**封面、目录页、过渡页、内容页、尾页（即总结页）**；以**内容页为主体**合理分配篇幅，**过渡页可按需自动生成**（章节较多时插入分隔，章节少时可省）；尾页固定为总结页。文献推荐不进入 PPT，不计入页数。
5. **资料真实性（防源数据外显）**：第三步文字内容须来自联网检索；不编造数据、作者、期刊。**来源标注一律只写"机构/平台/期刊名称"，且仅在对话正文出现——严禁把 URL、域名、检索语句、网页地址写进幻灯片或任何用户可见文案**；中间产物（STORY/DESIGN 等）同样不得残留链接地址。
6. **主题自动匹配模板（自动生成对应模板）**：依据 PPT 主题/类型，**自动选定风格预设与版式组合**，无需用户额外设计；版式按内容语义多样化排布（映射与版式清单见 `references/types-and-styles.md`）。自动生成的模板须排版合理、留白克制、视觉统一美观。该风格/版式结论将作为 `PPT 渲染工作流` 生成阶段的 `DESIGN.md` 输入。
7. **配图策略（ImageGen 生图前置 · 禁止搜图 · 禁止确认 · 绝不中断）**：
   - **来源唯一**：配图只来自 **ImageGen 生图**或 SVG（结构化的流程图/时间轴/图表等低语义元素）。**禁止联网搜图**、禁止引用在线图片 URL 或 `image://` 占位符。用户明确提供的材料图/品牌图可复制到 `assets/` 后使用。
   - **分级 L1/L2/L3**：L1 主视觉（占内容区 ≥40%，封面/章节过渡/左右图文主图）、L2 支撑图（≥280×180，段落旁/卡片头）、L3 母版徽标（≤64×64，全篇位置固定）。详见 `references/research-image-guide.md`。
   - **配图前置（强制）**：写每一页前，先生成**该页**所需图片 → Read 核对（内容/比例/清晰/风格统一）→ 重命名落入 `assets/` → 再写该页 SlideDSL。**严禁先写占位后补图。**
   - **严禁向用户确认**：直接调用 ImageGen 生成即可，不得就此询问用户、不得在确认卡片出现生图字样。
   - **绝不中断生成**：无论 ImageGen 成功/失败（最多重试 2 次仍不合格则 SVG 兜底并记原因），都**不得中断或回退** PPT 生成；缺图时该页退化为纯文字/SVG 版式，流程继续直至产出 `.pptx`。
   - **配图密度**：默认每内容页 ≥1 张图（L1/L2），封面/过渡/总结页可配主题图；全篇同一视觉类型（插画/3D/摄影）统一，禁止混用。
8. **生成方式与交付形态（内置 PPT 渲染工作流）**：步骤 3 按**本技能内置的 PPT 渲染工作流**（slidep SlideDSL）产出标准 `.pptx` 文件。完成后用 `present_files` 在**左侧以卡片形式展示最终交付的 `.pptx` 文件（主交付物）**，并**打开右侧预览/编辑面板**，用户可在此**预览效果、在线编辑、下载/导出**（编辑由平台本地 Office 编辑能力提供；导出即下载文件本体）。本技能的大纲（Gate 2 产物）即 `STORY.md` 输入，风格映射（types-and-styles）即 `DESIGN.md` 输入；具体工作流与版式→SlideDSL 映射见 `references/generate-pptx-tencent.md`。
9. **内容丰富、形式多样化**：每页内容须真实充实、信息量足；内容页版式应在多种类型间轮换使用（见规则 6），避免整篇"要点罗列"的同质化排版。
10. **知网推荐（edu MCP + 文献名带链接一次点击直达知网研学研读页面 + 零元数据暴露）**：知网推荐必须**调用名称为 `edu` 的 MCP 中的文献检索接口**（工具全名 `mcp__<SERVER>__searchVectorBJ`；若实际名称不同，以 edu MCP 暴露的检索接口为准）检索，最多 **6 篇**。
    - **位置**：**紧接 PPT 卡片下方直接展示**（PPT 总结文字之后，中间不插入任何其它区块），不折叠、不分页。
    - **展示内容（三项，且仅三项）**：每条**只显示文字**「**文献名 / 作者 / 来源**」。
    - **禁止暴露任何元数据（强约束）**：**严禁以任何方式展示、复述、暗示来自知网/检索接口的任何元数据**，包括但不限于——**发表时间**、卷期、页码、**doi**、数据库名、来源链路、检索语句、**内部 id**、`filePath`、**链接地址（URL/域名）**、被引量、关键词、摘要、分类编号等。接口返回的原始元数据只用于内部取用，**一概不得外显**。**唯一例外**：跳转链接作为「文献名」的 `href` 跳转目标存在——**不得以明文形式出现在可见文案中**（条目文本、列表、卡片、幻灯片里都不允许出现 URL / 域名 / "点击查看原文""链接："一类提示语）。
    - **点击行为（跳转目标=知网研学「研读页面」· 一次点击直达）**：**仅「文献名」为可点击锚文本**，点击后**一次即落在该文献在知网研学平台的研读页面**（在线阅读全文；详见 `references/cnki-guide.md` 第三节）：
      - **取址方式（唯一）**：**直接取用检索接口返回的 `url` 字段**——该字段即该篇在知网研学平台的**研读页地址**，形如 `https://ix.cnki.net/read/article/readonline?dbcode=…&tablename=…&filename=…&fileSourceType=1`；**原样使用——不改写、不精简参数、不替换字段值、不自行拼接、不解析**。
      - ⚠️ **跳转目标固定为「研学研读页面」**：**不得**改用知网官网检索页（`kns.cnki.net/kns8s/...`）、知网节 / 文献详情页（`kcms/detail/detail.aspx?...`、`kcms2/article/abstract?v=...`）等其它地址，**也不得自行拼接任何地址**（篇名不是文件标识，不得拿篇名去拼）。
      - ⚠️ **不得用非浏览器请求抓取该地址**：本流程**只取接口返回值**，**不发起任何网络请求**。
      - **取址失败降级**：某篇若**未返回 `url`**，该篇**不挂链接、退为无链接纯文本**（此时无跳转目标，只写《文献名》），**流程继续**，不臆造地址、不中断知网推荐产出。
      - 作者、来源**一律为纯文本、不可点击**。
    - **登录与阅读权限处理（由研学平台自动接管 · 强约束）**：点击后进入知网研学研读页——**已登录且具备阅读权益**（关联机构授权、个人／团队会员、文献流量包等）时**直接在线阅读全文**；**未登录时由研学平台弹出登录框**（支持账号登录、扫码、微信/QQ 等方式），**登录完成后平台自动校验该篇的阅读权限**——有权限即展示全文，无权限则给出平台自身的获取指引。以上均为**平台侧正常流程**，**属预期行为**——**链接照挂：不预先拦截、不改写、不删除、不降级为纯文本**。**不得**在可见文案中出现任何登录网址、接口名、服务名或域名；**列表下方统一附一句**中立文案「**点击文献名可在线阅读全文；未登录时登录知网账号后即可查看**」。
    - **文献名带跳转链接（强约束 · 链接写法 · 不要求悬停提示）**：**《文献名》必须带跳转链接**，**点击一次即直达该篇在知网研学平台的研读页面**。写法按渲染环境自适应——① **默认首选**：**Markdown 链接** `[《文献名》](<接口返回的研读页地址>)`（兼容性最好）；② **内联 HTML 锚点**（`<a href="研读页地址">《文献名》</a>`）**仅在确知渲染环境会执行内联 HTML 时使用**——**实测（2026-10-13）：对话/卡片类渲染环境会剥离内联锚点，落地后表现为"纯文本、点不动"，届时立即改回写法①**；③ **仅在链接完全无法渲染时**，才退为**无链接纯文本**（只写《文献名》）。**不附加悬停提示**——**一律不写 `title` / 链接标题**（对话渲染环境不呈现该提示，写了也无效）；**需求口径 = 保点击跳转、放弃悬停提示**。**可见文案中一律不得出现 URL / 域名明文**——地址只作为「文献名」的跳转目标存在。
    - **保密**：检索过程与工具返回的原始数据严禁暴露；仅输出整理好的「知网推荐」列表。
11. **PPT 文件以卡片形式在左侧呈现（适中宽度）**：最终交付的 `.pptx` 作为主交付物，在**左侧**通过 `present_files` 以**卡片形式**展示，宽度取**适中值（不拉伸至整屏宽度、不强制铺满）**，聚焦内容即可；**右侧同步打开预览/编辑面板**（预览、在线编辑、下载/导出）；附属信息（知网推荐等）置于该卡片**下方**，不与 PPT 卡片并排拉长。
12. **仅暴露最终交付物与必要生成过程（强约束）**：用户**只应看到三类最终交付物**——① PPT 文档（.pptx 卡片）、② PPT 内容总结、③ 知网推荐（**仅展示文献名、作者、来源三项**；**严禁暴露知网任何元数据**——发表时间、卷期、doi、数据库名、检索语句、内部 id、链接地址等一律不展示，仅文献名可点击**一次直达知网研学平台的研读页面（直接取用检索接口返回的链接）**，**《文献名》带跳转链接**、**不附带悬停提示**）——以及**必要的生成过程展示（见规则 13：含「生成过程·阶段进度」与「思考过程·决策随想」，均为用户视角、不含技术细节）**。**除此之外的所有内容严禁暴露**，包括但不限于：内部工具/技能名（slidep、SlideDSL、.slide、project_dir、ImageGen、PPT 渲染工作流、edu MCP 等）、联网检索的原始数据与查询语句、STORY/DESIGN 等中间产物原文、配图生成的具体过程与"是否生图"类确认、附件解析/复制的原始细节、任何文件路径与系统信息。
13. **生成过程与思考过程展示（阶段进度 + 决策随想 · 趣味轻松 · 禁负面词 · 禁技术细节）**：步骤 3 执行期间，向用户**实时展示"在做什么"与"为什么这么做"**——既要呈现高层级阶段进度（生成过程），也要同步流露关键设计/内容决策背后的思考（思考过程），以轻松有趣的口吻展开，避免沉默或冷冰冰的"处理中"。要点：
    - **① 生成过程（阶段进度）**：按实际流程推进、完成即标记 ✓ 的五个阶段——**① 解析需求与大纲 → ② 检索资料 → ③ 生成配图 → ④ 渲染 PPT → ⑤ 生成知网推荐**。可呈现为步骤进度条/清单，已完成项打勾。
    - **② 思考过程（决策随想）**：在阶段推进的同时，以**简短（1–2 行）、轻松、用户视角**的方式，自然流露关键决策背后的考虑，让用户"看见你的思路"。典型可流露的内容：
      - 类型与风格判定（"主题偏科普，我选了清新绿，读起来更轻松"）；
      - 章节合并/拆分逻辑（"两章内容相近，我合并成一章，避免碎片化"）；
      - 某页版式取舍（"这页概念有点抽象，加一张示意图帮理解"）；
      - 检索到的亮点素材（"找到个近年的教学案例，补进活动页"）。
      - ⚠️ **思考随想随阶段自然出现、不必每步都有**，重在"流露思路"而非"逐步汇报"；它讲的是"为什么这么选"，不是"用了什么工具"。
    - **口径**：轻松、有趣、贴合 PPT 主题调性；**严禁出现"排队""等待""处理中""加载中"等负面/枯燥措辞**（遵循产品"趣味、轻松"的等待态文案规范）。
    - **分阶段文案示例**（纯文字、不配 emoji，可结合主题变量替换）：
      - 进入检索：「先去查点真实可信的资料，把内容夯实」
      - 配图阶段：「资料已就位，正在为你绘制配图」
      - 渲染阶段：「内容已排好，正在为它们搭配合适的版式」
      - 收尾：「最后一步，正在生成知网推荐与总结」
    - **思考随想示例**（轻松、用户视角、不提工具）：
      - 「主题偏科普，我选了清新绿，读起来更轻松」
      - 「两章内容相近，合并成一章，结构更顺」
      - 「这页概念有点抽象，加张示意图帮理解」
    - **严禁暴露技术细节**：无论是阶段进度还是思考随想，都只讲"在做什么 / 为什么这么选"（用户视角），**不得出现工具名/技能名（slidep、ImageGen、PPT 渲染工作流、edu MCP 等）、文件路径、中间文件名、原始数据**；生成完成即收尾，不再追加提示。

## 步骤 0：接收需求（不确认，仅解析）

读取用户输入，提取可识别的初始信号：主题、隐含类型、任何已提及的风格/页数/要求；**重点检测是否携带附件**，若有则按下方「附件处理（两种模式）」判定模式并提取素材。若信息缺失，**不要一次性抛出所有问题**，进入步骤 1 的确认门补齐。

## 附件处理（两种模式）

当用户上传附件时，先判定属于哪种模式，再决定后续流程；判定依据 = **文件扩展名 + 用户表述**。

| 模式 | 适用附件 | 判定信号 | 处理方式 |
|---|---|---|---|
| **A · 内容生成** | doc/docx/pdf/txt/md/图片/网页等**内容型**素材 | "根据这份资料/文档生成""用这个内容做个PPT"、非 PPT 格式 | 以附件内容为素材，走标准流程（提取要点 → 大纲 → 配图 → 生成）；附件即内容来源，可不另设主题 |
| **B · 模板制作** | .ppt/.pptx **模板文件** | "按这个模板做""用这个课件改""套用这个版式"、PPT 格式 | **先解析模板，再将生成内容套进模板**：① 解析模板（提取配色/字体/母版版式/已有页面结构/占位符/品牌元素）；② 套入内容（将大纲与生成的文字、配图按模板版式逐页填入，保留模板视觉基因，缺失页按同风格补齐并适度扩充优化），而非从空白新建或简单套用 |

- 若用户**同时给内容附件 + 模板附件**：默认**内容为主、模板为样式基底**——用模板风格承载内容、并做扩充优化。
- 内容型附件：先复制到工作区并读取/解析（图片用读取/OCR、网页用 WebFetch），再进入步骤 1。
- 模板型附件（B 模式）处理流程：① **解析模板**：用平台本地 Office 编辑能力打开模板，提取其配色方案、字体、母版/版式、已有页面结构与占位符、品牌元素；② **套入内容**：将步骤 2 大纲与步骤 3 生成的文字/配图，按模板版式逐页填入（保留模板视觉基因），模板缺失的页面按同风格补齐、并做适度扩充优化；③ 校验整体风格统一后输出。
- 附件处理属内部流程，**对用户仅说明"已基于附件生成 / 已套用模板"，不暴露解析、复制、工具名等细节**。

## 步骤 1：类型识别 + 基础信息收集 → Gate 1

1. 依据 `references/types-and-styles.md` 的类型清单，判断 PPT 类型（教学课件 / 工作汇报 / 教研分享 / 班会主题 / 其它）。如用户未指明，给出 2–4 个候选类型供选择。
2. **自动匹配模板**：依据主题/类型，参照"主题→模板映射"**自动选定风格预设与一个版式组合建议**（如教学课件→清新绿+图文/卡片/时间轴；工作汇报→商务蓝+数据大字/对比/图表）。该匹配可在确认卡片中以"推荐风格/版式倾向"形式呈现，但**不暴露内部实现名词**。
3. 收集基础信息字段（风格、页数、语言、特殊要求）。字段模板见 `references/types-and-styles.md` 的「基础信息收集卡」。
4. 用**一张确认卡片**汇总：`类型 + 风格 + 页数 + 语言 + 特殊要求 + 推荐版式倾向`，并说明默认假设，请用户确认或修改。可在卡片中以**一句话轻量附上「推荐理由」**（如"主题偏科普，清新绿读起来更轻松"），让用户理解你的判断——但**只讲用户视角的取舍，不暴露工具/流程细节**。

**Gate 1**：用户确认类型与基础信息后，方可进入步骤 2。若用户修改，就地更新卡片再次确认。

## 步骤 2：两级大纲生成（三字段表格 · 强制表格化 · 相同内容只写一次、延续行留空） → Gate 2

1. 仅生成**两级大纲**：一级为章节/模块（一级标题），二级为每章下的要点页（二级标题）。**先合并相同内容**——内容相同或高度重合的一级标题归并为一章（如多个"知识讲解""原理分析"合成一章），相邻重复的二级标题、内容摘要一并合并，杜绝章节碎片化、同名重复与"同一内容出现两次"；**一级标题、二级标题均不超过 20 个汉字**（标点、阿拉伯数字、英文单词不计入汉字计数，但整体仍须精炼），超长须压缩或拆分，不得用"……"等截断占位。
2. **优化扩展标题内容**：为每章/每页撰写**经优化与适度扩展**的一级、二级标题，表述完整、有信息量（避免"讲授""说明"等干瘪短语），但仍**控制在 20 个汉字以内**；并为**每个二级要点**撰写一句内容摘要（15–40 字，说明该页讲什么、放什么），摘要末用括号轻量标注建议版式（（图文）/（卡片）/（时间轴）/（对比）/（数据大字）/（表格）/（引言）/（双栏）），供步骤 3 生成参考。
3. **大纲强制以表格形式呈现（唯一形态）**：**严禁改用非表格形态**（层级分组式、缩进列表、要点清单等一律不得作为大纲呈现方式）；**顶部为横跨三列的 PPT 名称行**（HTML 表内用 `colspan="3"`；非 HTML 环境则在表格正上方单独一行、全宽呈现，其下仍必须接表格）；列固定为三个字段：`一级标题 | 二级标题 | 内容摘要`。**合并只在"内容层"做，单元格一律不做合并**：① **内容合并**——内容相同/高度重合的一级标题归并为一章（如多个"知识讲解""原理分析"合成一章），相邻重复的二级标题、摘要先合并；**相同内容只写一次，绝不重复填写**；② **单元格保持不合并，延续行留空即可**——同一章节首行正常填写一级标题，其**后续行该列留为一个空白单元格**（表示"同上"，与上一行相同）；**不使用 `rowspan` 做跨行合并，也不要求填「〃」等占位符号**。⚠️ 此处**留空 = 有意表示延续上一行**，属**预期形态**（不等于漏填）；但**不允许为了填满表格而把相同内容重复写一遍**。规范、模板与示例见 `references/outline-guide.md` 第三、四节。
4. 大纲末尾固定追加一章（用于内容页，不含文献推荐行）：
   - `总结`：二级标题 = "本PPT核心结论与要点回顾"（内容由步骤 3 填充）。

**Gate 2**：在**消息正文**展示完整大纲（**强制以表格形式呈现**——顶部 PPT 名称行 + 三字段表格；**相同内容已合并**：相同内容只写一次，同一章节延续行的对应单元格**留空**表示同上，**不做单元格合并**；不得改用非表格的层级分组/缩进列表形态）。确认章节结构、页数分配是否合理。⚠️ **大纲正文不放进确认卡片的选项里**（表格在卡片选项内无法正常渲染），卡片只承载「确认 / 修改」操作。可附一句轻量「结构考量」，说明章节合并/拆分与版式分配的取舍逻辑（用户视角，不暴露内部流程）。用户确认后进入步骤 3；可要求增删章节或调整页数。

## 步骤 3：资料检索 + 配图 + 生成 PPT（一次性执行）

1. **无中途确认**：步骤 2 确认后直接进入本步骤，按下方计划一次跑完，**不向用户询问任一环节**（尤其**不得确认是否生图**）。本步骤全程按**规则 13 实时展示「生成过程（阶段进度）」与「思考过程（决策随想）」**——进度让用户看见"做到哪了"，思考随想让用户看见"为什么这么选"（如某页版式取舍、章节合并逻辑、检索到的亮点素材）；思考随想随阶段自然流露，不每步必写。
2. 执行（详细工作流见 `references/generate-pptx-tencent.md`）：
   - **模板与版式 → DESIGN.md**：把步骤 1 自动匹配的"风格+版式组合"与 `references/types-and-styles.md` 的低饱和配色，落为 `PPT 渲染工作流` 的 `DESIGN.md`（色彩池、字号阶梯、版式映射表、配图 L1/L2/L3 清单）。
   - **大纲 → STORY.md**：把 Gate 2 确认的两级大纲落为 `STORY.md`（叙事逻辑、章节、每页要点与建议版式）。
   - **文字资料**：联网检索（WebSearch / WebFetch）补充每页真实内容，标注来源。
   - **配图（ImageGen 生图前置）**：按 `references/research-image-guide.md` 执行——写每页前先生成该页 ImageGen 图，核对后落入 `assets/`；L1/L2/L3 分级；**严禁搜图、严禁确认、绝不中断**。
   - **生成（内置 PPT 渲染工作流）**：按本技能 `references/generate-pptx-tencent.md` 的流程执行，即 `slidep create` → 逐页 `.slide`（写前配图前置、写完用 `slidep lint "<pptx路径>" --dsl-file "slides/{NN}.slide"` 校验、通过后 `slidep upsert-dsl` 写入）→ 完成。务必把"总结页"作为末页生成；内容页按语义在多种版式间轮换，保证**丰富、多样、美观**。过渡页按章节数自动决定是否插入。**若为模板型附件（B 模式），先按「附件处理」解析模板得到版式基因，再将内容套入模板版式生成，而非从空白新建。**
3. 生成完成后，校验末页"总结页"存在且内容完整，各页版式落实、无空白占位（缺图页已退化为文字/SVG 版式）；计算**从步骤 3 开始到产出 `.pptx` 的总时长**（建议以"约 X 分钟"呈现，不足 1 分钟时显示"约 X 秒"），将其显示在 PPT 文档**上方**；再用 `present_files` 在**左侧以卡片形式（适中宽度，不拉伸至整屏）展示最终交付的 `.pptx`**，并**打开右侧预览/编辑面板**（可预览、在线编辑、下载/导出）。

若用户对成片不满意，进入编辑（交由平台本地 Office 编辑能力）。

## 最终交付（依次：PPT 文件 → PPT 总结 → 知网推荐；知网推荐紧接 PPT 卡片下方）

1. **PPT 文件（文档上方显示生成总时长 · 卡片呈现于左侧 · 右侧预览/编辑/下载导出）**：先在 PPT 文档**上方**以一行醒目文字显示**「PPT 生成总时长：约 X 分钟」**（不足 1 分钟显示"约 X 秒"）；随后通过 `present_files` 在**左侧以卡片形式（适中宽度，不拉伸至整屏）展示最终交付的 `.pptx`**，并**打开右侧预览/编辑面板**，用户可在此**预览效果、在线编辑、下载或导出**该 `.pptx`（编辑经平台本地 Office 编辑能力；导出即下载文件本体）。
2. **PPT 总结文字**：在对话中附上 **PPT 内容总结**：用**一段话（不超过 120 字）**概述，须包含三要素——【页数】【风格】【内容概要】，并加**前后衔接语**（开场一句引入背景/意图，收尾一句点题或过渡），与末尾总结页一致。
3. **知网推荐（紧接 PPT 卡片下方 · 仅三项 · 零元数据 · 文献名带链接一次点击直达知网研学研读页面）**：调用 `edu` MCP 检索后，**紧接 PPT 卡片下方直接展示**文献列表（PPT 总结文字之后，中间不插入其它区块），**最多 6 篇**。
   - **每条只展示三段文字**：`《文献名》，作者，来源`（作者多人用"等"或逗号分隔）。
   - **零元数据暴露**：**不得出现发表时间、卷期页码、doi、数据库名、检索语句、内部 id、URL/域名等任何元数据字样**；接口返回的原始元数据只作内部取用；跳转地址只作为「文献名」的 `href` 跳转目标存在，**不得以明文出现在条目文本里**。
   - **文献名带跳转链接（硬约束 · 不要求悬停提示）**：**《文献名》必须带跳转链接**，**点击一次即直达该篇在知网研学平台的研读页面**。默认用 **Markdown 链接**：`[《文献名》](<接口返回的研读页地址>)`；**内联 HTML 锚点仅在确知渲染环境会执行 HTML 时使用**（对话/卡片类环境会剥离内联锚点 → 表现为纯文本、点不动，届时立即改回 Markdown 写法）；**仅在链接完全无法渲染时**才退为**无链接纯文本**。**不写 `title` / 链接标题**（悬停提示在对话渲染环境中不呈现，需求口径为"保点击跳转、放弃悬停提示"）。
   - **仅「文献名」可点击**，**点击一次即直达该篇在知网研学平台的研读页面**——跳转目标**直接取用检索接口返回的 `url` 字段**（该字段即该篇研读页地址）；**原样使用——不改写、不精简参数、不替换字段值、不自行拼接、不解析**；**不得**改用知网官网检索页 / 知网节 / 详情页等其它地址，**也不得把篇名当作 `filename` 自行拼接**。作者、来源为**纯文本、不可点击**。
   - **未登录 / 无权益（点击后登录即可）**：点击后进入知网研学研读页——**已登录且有阅读权益时直接在线阅读全文**；**未登录时由平台弹出登录框，登录完成后自动校验该篇阅读权限**（有权限即展示全文，无权限给出平台自身的获取指引）。以上均为**正常现象**，**保留链接、不做拦截**；**列表下方统一附一句**中立文案「**点击文献名可在线阅读全文；未登录时登录知网账号后即可查看**」，**不得出现任何登录网址 / 接口名 / 服务名 / 域名**。
   - **不进入 PPT 文件；检索原始数据与过程严禁暴露。**
