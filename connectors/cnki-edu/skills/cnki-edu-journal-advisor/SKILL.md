# cnki-edu-journal-advisor（中小学教师教研论文投稿选刊版 WorkBuddy 版）

> **⚠️ 前置依赖（MCP server 注册）**
> 本技能仅依赖 **`edu`（公共知网 edu 网关，已注册、可用）**：文献检索，步骤 3 走 `mcp__<SERVER>__searchVectorBJ`。该工具为**语义文献检索**（按文本向量返回主题相关文献，非按刊名过滤），实测返回字段含 `JournalName`(刊名)/`Source`(来源刊)/`JournalName_EN`/`Author`/`PubDate`/`CitedTimes`/`DownloadedTimes`/`Keyword`/`相关度`/`coreJournals`(偶发"Y")/`url`(知网阅读链接)/正文摘要等——**不含 `PinyinName`(拼音刊号)**，故**无法从检索结果直接拼出知网出版物检索详情页 `navUrl`**。注意：① 检索为语义匹配，**不是"按刊名过滤"**，返回文献 `JournalName` 多为同主题其他刊物，命中目标刊自身文献才实证其知网收录，未命中**不等于未收录**；② `coreJournals` 偶发返回"Y"可作核心旁证，但核心状态仍以**知网「出版物检索」详情页徽标**（`北大核心(20XX版)`）为准。这是本技能唯一的数据源，无需任何额外配置即可正常工作。
>
> **文件解析说明**：WorkBuddy 的 Read 工具已内置 PDF/DOCX 文本抽取，步骤 1 直接用 Read 读上传文件即可，无需脚本转换。

## 概述

面向**中小学教师**，帮助其把写好的教研论文（学科教学、作业设计、班级管理、德育、课题研究、课标落地等）投到**合适的「基础教育 / G4 教育类」期刊**。

区别于高校科研选刊工具，本版**不以影响因子 / CSSCI / SSCI 为核心指标**，而是围绕教师最关心的三件事做推荐与提示：

1. **投得对**——是不是基础教育 / 教育类刊物，主题是否契合；
2. **投得安全**——期刊是否正规、是否被三大网（知网 / 万方 / 维普）收录、会不会踩到假刊套刊；
3. **投得及**——版面费是否在合理区间、审稿出刊周期能否赶上评职称截止日期。

> **本技能不编造数据**：知网 `mcp__<SERVER>__searchVectorBJ` 只返回「刊名 + 主题相关发文 + 被引/下载等文献元数据」，**不返回收录信号判定、不返回版面费、不返回省级/国家级定性结论、不返回审稿周期天数**。核心/收录状态须查知网出版物检索详情页。这些字段本技能一律标注「需自行核实」，绝不凭空填写。

## 任务分支与意图识别

本技能支持三类任务，**先判定意图再走对应流程**，避免把"查某刊定位"误套成"推刊"模板：

| 分支 | 意图 | 用户输入特征 | 走哪条流程 |
|------|------|--------------|------------|
| **A 选刊推荐** | 有论文，求"投哪个刊" | 上传/粘贴论文，或描述主题+学段 | 步骤 1–4 全流程（含步骤 2 确认节点） |
| **B 查刊定位** | 指定刊名，求"这刊是什么定位" | "查一下《XX》这本刊"、"《XX》定位如何" | 见文末「分支 B：查刊定位」独立模板（**无步骤 2 确认节点**） |
| **C 核验避坑** | 指定刊名/可疑刊，求"这刊靠不靠谱" | "这刊是真的吗"、"版面费多少"、"是不是套刊" | 见文末「分支 C：核验避坑」独立模板（**无步骤 2 确认节点**） |

> 以下步骤 1–4 为**分支 A（选刊推荐）**默认流程。

## 工作流程

整体流程分为 4 个步骤，从用户输入到最终推荐展示，形成完整闭环：

```
步骤 1 → 步骤 2 → 步骤 3 → 步骤 4
输入      确认      检索      推荐
解析      解析      聚合      展示
                   (候选)   +核验清单
```

> **单一「主题启发式模式」**：本技能完全基于 `edu` 的 `mcp__<SERVER>__searchVectorBJ` 返回的真实文献元数据（刊名 + 主题相关发文频次 + 被引/下载等）做推荐，**不接入任何用户行为 / 轨迹画像**，不声称个性化分析。不存在"精准 / 启发式"双档位，所有推荐均为同一模式。

### 步骤 1：用户输入分析与内容解析

分析用户输入的内容或上传的文档，统一使用 **Prompt 1：论文核心信息提取提示词**（`references/prompts.md`）通过大模型提取论文标题、摘要、关键词。

**方式 ① — 用户上传论文文件：**

在 WorkBuddy 中直接用 **Read 工具** 读取用户上传的 PDF / DOC / DOCX 文件，提取文章全文文本（Read 已内置 PDF/DOCX 文本抽取，无需脚本转换）。

> **数据映射：** 将 Read 工具抽取出的全文作为 **Prompt 1**（`references/prompts.md`）中的 `{full_text}` 占位符传入。

**方式 ② — 用户直接输入文字内容：**

直接调用 **Prompt 1** 通过大模型从用户输入的文字中提取标题、摘要、关键词。

> **数据映射：** 将用户输入的文字内容作为 **Prompt 1**（`references/prompts.md`）中的 `{full_text}` 占位符传入。

**Prompt 1 提取字段：**

| 字段 | 类型 | 说明 | 去往步骤 |
|---|---|---|---|
| 标题 | string | 论文完整标题 | 步骤 2 确认 |
| 摘要 | string | 论文摘要全文 | 步骤 2 确认 |
| 关键词 | string[] | 4～6 个关键词 | 步骤 2 确认 |

---

### 步骤 2：解析结果确认（⛔ 确认节点）

> ⛔⛔⛔ **最高优先级流程控制 — 绝对不可跳过**
>
> 展示完下面的**解析结果确认卡片**后：
> 1. **立即停止输出** — 你的回复到此为止，不要有任何多余文字
> 2. **绝对禁止**调用任何 MCP 工具
> 3. **绝对禁止**进入步骤 3 及之后的任何步骤
> 4. **唯一允许的动作**：等待用户在聊天框中输入回复
>
> 只有当用户回复 **1/确认/正确/没问题** 后，下一轮对话才能进入步骤 3。

将步骤 1 提取的标题、摘要、关键词展示给用户确认。

**展示卡片（本轮输出的全部内容，输出后即停止）：**

```
论文解析完成，请确认以下信息：

📝 **【标题】** {从论文中提取的完整标题}


📋 **【摘要】** {摘要}


🔑 **【关键词】** {关键词1}、{关键词2}、{关键词3}、{关键词4}、{关键词5}


---

信息无误请确认，如有偏差可手动修改。

请回复：
- 输入 **1** 或"确认" → 开始推荐
- 输入 **2** 或"修改" → 手动修改信息
```

**用户回应处理（仅在用户回复后触发）：**

| 用户回应 | 处理方式 |
|---|---|
| 回复 **1** / "确认" / "正确" / "没问题" | → 进入步骤 3 |
| 回复 **2** / "修改" / 指出某字段有误 | 引导用户逐字段修正（标题/摘要/关键词），更新后再次展示确认卡片 |
| 用户直接输入修正内容（如"关键词改成 A、B、C"） | 解析修正内容，更新对应字段，重新展示确认卡片 |

### 步骤 3：相似文献检索与候选聚合（知网 edu 网关，主路径）

调用 `mcp__<SERVER>__searchVectorBJ` 工具（公共知网 edu MCP，server 名 `edu`，已在 WorkBuddy 注册）按文本向量检索相关文献，作为每条推荐期刊的"内容相关文献"来源，**并直接聚合出候选期刊**。

**调用参数：**

```json
{
  "text": "{步骤1提取的论文标题 + 关键词，以逗号或空格拼接}",
  "query_type": 3,
  "type": "0",
  "maxRecallNumber": 5
}
```

**参数说明：**
| 参数 | 必填 | 说明 |
|---|---|---|
| text | 是 | 检索文本，建议用论文标题 + 关键词拼接，体现主题 |
| query_type | 否 | 0 篇名 / 1 摘要 / 2 小标题 / 3 主题，默认 0；推荐用 3（主题）召回相关文献 |
| type | 否 | 文献类型：0 期刊 / 1 硕士 / 2 博士 / 3 会议 / 4 报纸，多值逗号隔开，默认 0（期刊） |
| maxRecallNumber | 否 | 最大返回条数，默认 20；此处取 5 |

> 注：`mcp__<SERVER>__searchVectorBJ` 为**语义文献检索**（非按刊名过滤）。实测每条结果含 `JournalName`(刊名)/`Source`/`Author`/`PubDate`/`DownloadedTimes`/`CitedTimes`/`Keyword`/`相关度`/`coreJournals`(偶发"Y")/`url` 等，**不含 `PinyinName`**——无法据此拼 `navUrl`。`coreJournals` 偶发返回"Y"可作核心旁证，但核心状态仍须查知网「出版物检索」详情页徽标核验。`readUrl` 直接用返回结果的 `url` 字段（无需自行拼接）。

#### 3.1 候选期刊的聚合方法（直接用真实返回字段，不反推文件名）

`mcp__<SERVER>__searchVectorBJ` **直接返回**每条文献的 `JournalName`(刊名)，无需从 `文件名` 反推。候选期刊的算法如下：

1. 对步骤 3 返回的每条文献，取 `JournalName` 作为候选刊名。**注意：检索结果为同主题多刊物文献，聚合出的是"同类主题都发在哪些刊"，并非目标刊专属；该刊是否在知网收录，须以其自身文献被命中为准。** `PinyinName`(拼音刊号) **不在返回字段中**，故**无法自动拼出 `navUrl = https://navi.cnki.net/knavi/journals/{PinyinName}/detail`**；核验详情页时须引导用户去 `navi.cnki.net` 手动搜刊名查看。
2. 按 `JournalName` 聚合，统计出现频次（即"该刊发表了多少篇相关主题文献"），频次越高越值得作为候选。
3. 极少数 `JournalName` 缺失时，回退用 `文件名` 前 4 位作兜底展示（仅兜底，不依赖）。

> 这是"同类主题都发在哪些刊"的启发式信号，**非精确匹配**，且**不保证该刊为正规基础教育刊**——必须在步骤 4.2 的「📋 投稿前核验清单」中逐刊核验正规性。

---

### 步骤 4：推荐结果展示与反馈闭环

#### 4.1 推荐理由生成（Prompt 2）

对每条候选期刊，调用 **Prompt 2：推荐理由生成提示词**（`references/prompts.md`），输入候选聚合信息（主题相关发文频次 + 期刊客观字段） + 相似文献数据，生成面向教师的推荐理由，并**固定附带期刊资质核验提醒**（见 4.2）。不依赖任何用户轨迹数据。

#### 4.1.5 🔒 数据源透明度铁律（输出前必检，最高优先级）

> 本技能只有**知网**一个数据源（`searchVectorBJ` 只查知网文献库）。任何超出知网实证范围的表述都必须标注来源，严禁混淆"出版方自述"与"知网实证"：

- **知网实证（两处来源，勿混淆）**：① `searchVectorBJ` 文献命中即实证**该刊知网可检索**，并带回刊名 / 主题相关发文频次 / 被引下载等文献元数据；② **知网「出版物检索」详情页**（`navi.cnki.net/knavi/journals/{PinyinName}/detail`）带回主办单位 / CN·ISSN 号 / 出版周期 / 分版 / 影响因子 / 北大核心徽标，均属实证。**⚠️ 主办单位与 CN 号来自详情页，并非 searchVectorBJ 单篇载荷字段。**
- **能力边界（外部源不可机检）**：本技能**不能**自动查询总署 / 万方 / 维普；这些来源的相关核验项一律标「待核验（总署官网 / 官网）」并提示用户人工自查。输出中**严禁**出现"已为您在总署/万方核实"等暗示自动核验的表述。
- **出版方自述（非实证）**：返回记录**正文 / 摘要**里出现的"万方 / 维普收录""北大核心""全国中文核心期刊"等，一律视为**出版方自述**。禁止用 ✅ / 实证 / 已验证 等措辞；必须标注「（出版方自述，待核验）」。**本技能对万方、维普无任何接口，无法验证其收录。**
- **北大核心核验（严谨做法）**：北大核心由北京大学图书馆《中文核心期刊要目总览》评定，须查**知网「出版物检索」详情页徽标**（显示 `北大核心(20XX版)`）或北大图书馆要目总览最新版。`searchVectorBJ` 偶发返回 `coreJournals:"Y"` 可作核心旁证，但**核心状态仍以详情页徽标为准**；**文章正文里的自述不算知网实证**，不得仅凭字段或自述下"是核心"结论。
- **内部字段严禁外显（最高优先级）**：`coreJournals:"Y"` 等 `searchVectorBJ` 返回字段属**模型内部推导依据**，仅用于内部判断是否在卡片标注"北大核心（待核验）"，**严禁写入面向用户的卡片文本**。用户可见输出只应呈现"北大核心（待核验，以知网出版物检索详情页 `北大核心(20XX版)` 徽标为准）"类干净结论；任何"知网返回 coreJournals 标记 Y""searchVectorBJ 标记""接口返回字段"等机理性/接口级描述均不得出现在用户可见内容中（含 级别、数据溯源、推荐理由等任意字段）。
- **每张期刊卡片必须含「数据溯源」行**，逐字段标注：知网实证 / 出版方自述 / 需自行核验。

## 分支 B：查刊定位（指定刊名，求"这刊是什么定位"）

> **适用场景**：用户输入一个具体刊名，想了解"这本刊是干什么的 / 定位如何 / 适不适合我投"。
> **与分支 A 的核心区别**：分支 A 是"有论文推刊"，分支 B 是"有刊名查定位"——**没有用户论文，因此不计算契合度% / 适配评分**，只做期刊客观定位 + 知网实证核验。
> **无步骤 2 确认节点**：分支 B 直接走"权限校验 → 检索 → 定位卡"，不需要用户确认论文解析（因为没有解析论文）。

> 📌 **能力边界（务必牢记）**：本技能**唯一能机检的只有「知网收录」**（`searchVectorBJ` 实证）。**总署 CN 号核对、万方/维普收录、版面费、出刊周期均无法由本技能自动获取**，只能作为「待核验」清单项提示用户人工去总署官网（nppa.gov.cn）及期刊官网自查。**严禁在本技能输出中出现"已为您在总署/万方核实"等暗示自动核验的表述。**

### B.1 流程

1. **权限校验**（同全局 🔐 块）：先 `ToolSearch(tool_names:["userState","searchVectorBJ"])` 确认 edu 工具可解析 → 调 `userState`；非 `true` 按态 A/B/C 处理（态 A 给连接器加载指引，态 B 通用版兜底 + 转化卡）。
2. **检索该刊**：调用 `mcp__<SERVER>__searchVectorBJ`，以**刊名**作为检索文本，拉取该刊在知网的相关文献记录。
   ```json
   {
     "text": "{刊名，如：中学语文教学参考}",
     "query_type": 3,
     "type": "0",
     "maxRecallNumber": 10
   }
   ```
   - 返回为空 → 本工具**未能在知网确认该刊收录**（语义检索未命中，可能未上知网 / 刊名有误 / 仅上其他库 / 主题词不匹配），如实说明"知网未检索到"，提示核对刊名与总署 CN 号，并给核验清单，**不编造**、不下"未收录/假刊"结论。
   - 返回有记录 → 检查返回文献中是否有 `JournalName` 等于目标刊名者：**有则该刊知网实证可检索**；若返回均为同主题其他刊物（本工具为语义检索，非按刊名过滤），则仅说明主题相关文献存在，**不能确认目标刊收录**，须引导总署/详情页核验。同时观察活跃度（被引/下载）。

## 分支 C：核验避坑（指定刊名/可疑刊，求"这刊靠不靠谱"）

> **适用场景**：用户给出某刊名（或收到某刊投稿邀请），想确认"这刊是真的吗 / 版面费多少 / 是不是套刊假刊"。
> **与分支 A / B 的区别**：A 是"有论文推刊"，B 是"有刊名查定位"，C 是"有刊名核验风险"——聚焦**正规性 + 三大网收录 + 假刊套刊识别 + 版面费警戒**，是安全闸的放大版。
> **无步骤 2 确认节点**：直接走"权限校验 → 检索核验 → 核验卡 + 假刊识别要点"。

> 📌 **能力边界（务必牢记）**：本技能**唯一能机检的只有「知网收录」**（`searchVectorBJ` 实证）。**总署 CN 号核对、万方/维普收录、版面费、出刊周期均无法由本技能自动获取**，只能作为「待核验」清单项提示用户人工去总署官网（nppa.gov.cn）及期刊官网自查。**严禁在本技能输出中出现"已为您在总署/万方核实"等暗示自动核验的表述。**

### C.3 假刊 / 套刊 / 水刊 识别要点（C 分支重点放大）

- **克隆刊（同名不同 CN）**：盗用正刊刊名，但 CN 号对不上或根本查不到；务必以总署官网 CN 号为准，不凭刊名判断。
- **套刊（借正刊 CN 另立分册）**：用正刊的 CN 号另出"XX 版/下半月"，不在正刊目录、三大网查不到该分册正文；正刊详情页无此分版即存疑。
- **水刊（只收钱不审稿）**：录用极快、来稿必录、先交高额版面费才给录用通知、无审稿意见；三大网查不到或收录极少。
- **山寨网站 / 钓鱼邮箱**：投稿链接非期刊官网（多为仿冒域名）、邮箱非官方域名；以详情页/官网公示的投稿方式为准。
- **预警名单**：关注中科院《国际期刊预警名单》及学校/省份不认可期刊目录，列入者慎投。
