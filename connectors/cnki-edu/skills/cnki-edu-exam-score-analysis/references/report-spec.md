# 报告格式与交付物规范

## 文件命名（三件套同源）

```
{考试名称}_{学科范围}_成绩分析报告.html     ← 主报告（默认第一交付物）
{考试名称}_{学科范围}_成绩分析报告.pdf      ← 打印版（同源，可直接发家长/教研组）
{考试名称}_{学科范围}_成绩分析结果册.xlsx   ← 数据版（6–10 个工作表，看数据齐不齐）
```

- 单科示例：`高二期中考试_英语_成绩分析报告.pdf`
- 多科示例：`高二期中考试_数语物化政_成绩分析报告.pdf`（学科范围可用简称连写）
- Excel 由 `report_builder.py --excel`（默认开启）自动派生：把 HTML 文件名中的
  「成绩分析报告」替换为「成绩分析结果册」并改扩展名为 `.xlsx`；用 `--excel-out` 可覆盖
- 三者必须写在**同一个输出目录**，避免用户拿到"一份 HTML 找不到对应 Excel"

## HTML（默认格式）

单文件自包含：CSS 内联、图表全部内联 SVG，无外链资源。
- 可直接在浏览器打开，可"打印 → 另存为 PDF"
- 响应式排版，手机/电脑都能看
- 每学科章节带锚点，目录可跳转
- 打印样式已内置：`@page A4`、页边距 2cm、章节分页（`page-break-before`）、表格与图表不跨页断裂

## PDF

两种产生方式：
1. `report_builder.py --pdf`：自动调用本机 Edge/Chrome 无头打印（Windows 常见路径已内置探测）
2. 失败时：浏览器打开 HTML → Ctrl+P → 另存为 PDF（A4，边距 2cm，勾选"背景图形"）

**页眉页脚必须关掉**（用户要求 2026-10-11）：脚本同时给 `--print-to-pdf-no-header`（老版本认）与
`--no-pdf-header-footer`（Chrome/Edge 120+ 认）。否则每页页脚都会印出 `file:///C:/…` 的本地路径与打印时间——
交付给老师/家长的 PDF 不能带这些。手工另存时也要在打印对话框里取消"页眉和页脚"。
**PDF 与 HTML 同源**：报告正文改了什么，PDF 必须跟着重跑一次 `--pdf`，不要只重出 HTML。

**PDF 属性里的生成侧元数据要抹掉**（用户要求 2026-10-12）：无头 Edge/Chrome 会把浏览器 UA 与渲染引擎
版本写进 PDF 的 Info 字典（`/Creator` 里带 `Mozilla/5.0 … HeadlessChrome/…`，`/Producer` 是
`Skia/PDF m…`），这些在「文档属性」里可见，属于内部信息。`report_builder.py` 在生成后调用
`scrub_pdf_metadata()` 处理：**逐字节等长替换**（内容换成同长度空格），因此 xref 偏移全部保持有效、
PDF 结构不受影响；只动 Info 里那几个键，`/Title` 与生成时间保留。
清理后回读校验（`pdf_metadata_leaks()`），有残留会打 `[警告]`。
Excel 侧同理：`build_excel.py` 把工作簿的 `creator` / `lastModifiedBy` 等属性清空，
否则老师在「文件 → 信息 → 属性」里会看到库名 `openpyxl`。

## Excel 结果册（默认交付，6–10 个工作表）

由 `scripts/build_excel.py` 生成，**只依赖 `analysis.json`**（学生成绩从各科
`individuals.ranking` 还原，不需要原始成绩表）。风格：表头深蓝底白字、冻结首行、列宽自适应、
等级/预警单元格按统一配色填充、低于及格线的单科成绩标红加粗。

**缺数据的表直接不生成**：没有逐题得分数据时不生成「04 逐题得分率」；没有知识点数据时不生成
「05 知识点优先级」；单班样本不生成「09 年级班级排名」；无历次成绩不生成「10 历次成绩对比」；
逐题表没有「学号」列时 04 照常生成、只是末尾没有各班得分率列；
部分学科缺数据时，只跳过该学科的行（不写"数据缺失"占位行）。
**逐题数据里没有知识点归属时，「04 逐题得分率」照常生成，但不保留空白的「知识点」列**——
空列本身也是一种占位，「04」的表格会随之少一列。
「01 阅读说明」的导航只列实际生成的表（**不写"哪张表没生成、为什么"**——那属于内部交代，
只在对话交付说明里讲）。

**结果册不承载「数据说明」**（用户要求 2026-10-08）：`data_notes`、满分设定、分数线设定、数据来源
一律不写进工作表。这些内容留在 `analysis.json` 与命令行输出里，交付时在对话中复述；
满分与三条分数线已逐列写在「02 学科总览」，不需要在「01」再复述一遍。

**narrative.json 读不出来或字段类型写错时**（可选话术文件），只打印警告并降级为「无话术」继续生成，
不得让 HTML/PDF/Excel 一条都产不出来。结果册与 narrative 已解耦（不再吃 `--narrative`）。

| # | 工作表 | 内容与设计要点 |
|---|--------|---------------|
| 01 | 阅读说明 | 考试名/班级/样本人数/分析学科、合计总分概览、学生名单范围、生成时间、工作表导航（只列实际生成的表）、**「⚠️ 待确认的满分」置顶点名**（`meta.full_to_confirm` 非空时）、**「未纳入统计的学生」逐科剔除名单**（缺考/空值/超满分/负分，逐个点名）。**不再有**：满分设定、分数线设定、数据来源、`data_notes`、未生成的工作表、主表工作表、统计范围 |
| 02 | 学科总览 | 各科满分/分数线/人数/均分/中位数/极差/标准差/得分率/**四率（优秀/良好/合格/不合格）**/及格率（累计）/低分率/**相对学科均值**/分数形态；标准差≥16% 标橙、≥20% 标红，及格率<90% 标橙、<80% 标红，形态"尾部沉重"标红。**多班样本分三段**：学科行（本册主范围）→「各班层（逐个班级 · 各学科）」每班一行、第一列写「班级 · 学科」→「全年级层（全部样本）」。相对学科均值 = (本学科得分率 − 各科得分率均值) ÷ 该均值 ×100% |
| 03 | 分数段分布 | 长表：学科 × 「范围」× 5 个分数段。**「分数段（分数）」是主列**（按各科满分换算成实际分数区间，如「0 – 90 分」「135 – 150 分」——末档按 `min(hi, 1)` 收成满分，绝不能拼成「满分 分」；**与报告侧 `band_range()` 同一写法**），**「分段（占满分比例）」是辅助列**（不及格 <60%、60–70%、70–80%、80–90%、优秀 ≥90%，放在分数列之后），再跟人数/占比/累计占比；不及格段红底、优秀段蓝底。**多班样本：「范围」列先列本班，再逐个班列出各班，最后列「全年级（全部样本）」**（用户要求 2026-10-11） |
| 04 | 逐题得分率 | **班级层 / 年级层双栏并排**（用户要求 2026-10-10）：学科/题号/知识点/满分 + **本班**均分·得分率·判定·讲评优先级·作答人数 + **年级**均分·得分率·判定·作答人数；各科内按**题号升序**（用户要求 2026-10-11），「讲评优先级」另按本班得分率升序标注。两层范围相同时退回单栏（平均得分/得分率/判定等级/P 序/作答人数）。**全部学科都没有逐题数据的整张表不生成**；个别学科没有则该学科不列行（不写"数据缺失"占位）。**逐题数据没有知识点归属时不保留「知识点」列**（空列也是占位） |
| 05 | 知识点优先级 | 学科/优先级 P1…/知识点/得分率/掌握等级/涉及题目/题数，按得分率升序。**只要输入里没有知识点数据，整张表就不生成**（不摆空表、不写「数据缺失」占位，也不进「01 阅读说明」的工作表导航）：逐题表没有「知识点」列、该列整列为空、或只填了 `-`「/」「—」「N/A」「无」「未标注」这类**占位符**，都算「没有知识点数据」；引擎绝不编造「未标注」这类知识点。表的存在与否**只看引擎有没有聚合出知识点**，与报告侧维度 4 同一判据 |
| 06 | 学生成绩与排名 | 标题带范围标注（「高二(3)班 ·」或「全部样本 ·」）。总分排名/**学号**/姓名/班级/各科成绩/**总分**/总分得分率/**与该范围均分差**/有效科数；单科低于及格线红底红字；末行"本班均"或"样本均"；「有效科数」<科目数 提示缺考。**「学号」列只在数据里有真学号时出现**（`meta.has_student_id` 为假时整列不生成，不用 `#N` 冒充）。**合计列称谓随统计范围变**：全部学科 → 「全科总分」；只分析部分学科 → 「所选学科总分」（`meta.total_label`），避免被当成学校层面的整份总分 |
| 07 | 临界生与分层名单 | 学科 × (尖子生/临界优秀/临界及格/学困生/学科排名前 20)，含"距优秀线/及格线 N–M 分"；有历次成绩时，末尾附一次「进步榜 / 需关注名单」（基于历次总分与名次变化，名次 +N = 前进 N 名）。**分层名单的范围与「06」标题范围一致** |
| 08 | 学生学科均衡性 | **学号（有真学号时才出）**/姓名/总分/排名/各科得分率/强弱极差/最弱学科/最强学科，按极差降序；极差≥15% 标橙、≥20% 标红 |
| 09 | 年级班级排名 | 班级总分排名（按总分平均）+ 各学科班级排名（按该科得分率）+ 全年级各学科四率。**多班样本才生成** |
| 10 | 历次成绩对比 | 历次年级总分与各科四率 + 历次各班总分与各科。**有历次表才生成**；历次表只有总分时只给总分层面对比 |

设计原则：**Excel 只承载数字与名单（可排序、可筛选、可二次加工），可视化一律交给 HTML/PDF**，
避免两套图表维护不一致；若要 Excel 原生图表，在对应 Sheet 追加 `openpyxl.chart` 对象。

**单元格是纯文本，不写 Markdown**（用户要求 2026-10-11）：表注里的 `**加粗**` 在 Excel 里不会渲染，
只会显示成字面星号——`build_excel.py` 的 `plain()` 已在入库前统一剥掉，新增表注不必再手动处理。
**同一处内容在报告与结果册必须表述一致**：报告里改了什么（题号升序、学号列、分数段用具体分数…），
结果册要同步改并重出，别只重出 HTML。

单独重出 Excel：

```bash
PY="$HOME/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
"$PY" scripts/build_excel.py --analysis analysis.json \
  --out "高二期中考试_数语物_成绩分析结果册.xlsx"
```

缺 openpyxl 时脚本会打印「用哪个解释器装」的指引并以退出码 2 结束；不要用全局 pip 装。

## Word（.docx，备选，非默认交付）

**本 skill 没有现成的 Word 脚本**，用户明确要 Word 时才按下面的方式临时实现：
- 含自动目录（多科模式必须）
- 每科一章，章节分页；图表建议"先出 PDF 再转 Word"或把 SVG 截图后插入，不要指望在正文里现画 PNG
  （本机不保证有 matplotlib / cairosvg）
- 中文正文宋体/微软雅黑 10–11 号，标题加粗，页边距 2cm

## 报告结构（固定顺序）

**标题序号体系（用户要求 2026-10-11，全报告统一）**：
`h2` 一级「一、二、…」→ `h3` 二级「（一）（二）…」→ `h4` 三级「1. 2. …」
→（更深层备用「（1）（2）…」「a. b. …」）。
序号由 `report_builder.renumber_headings()` 在渲染收尾时**按实际出现的标题**统一生成，
连续编号、**缺章节不跳号**；`h2` 的号在 `build_html` 里写死，**目录与正文同源**。
**「目录」标题与「核心结论摘要」本身不编号**（目录里列出的章名照常带「一、二、…」）。
**目录用 `<ul>` + `list-style:none`，不出现 `<ol>` 自动生成的 1./2./3.**（用户要求 2026-10-11）
——条目里已有「一、二、…」，再加一层阿拉伯数字是重复编号。
各学科章节内的维度小节**不再重复写「维度 N ·」**（与新序号功能重复、维度缺失时会错位成
「（四）维度 5」），只写小节名，如「（三）逐题得分率」「（四）对比分析」。

**题号与学号的两条硬规则（用户要求 2026-10-11）**：
- **含题号的列一律按题号升序**：班级层 / 年级层逐题表、各班逐题矩阵、知识点表「涉及题目」、
  Excel「04 逐题得分率」。讲评优先级 `P1…Pn` **另按得分率升序单独算**，行序不再是得分率序。
  例外：`得分最低 / 得分最高的试题清单`按**得分率**取前 5（语义如此），清单项**不套 `<b>`、也不自带 `<li>`**，
  直接写「第6题（共性错题）：得分率 …」。
- ⚠️ **清单项是纯文本，标签由渲染层统一加**（用户要求 2026-10-11：「`<li>` 这个符号去掉，HTML 和 PDF 都改」）：
  `ulist()` 会给每一项包 `<li>` 并先 `esc()`，所以传给它的字符串**不能自己拼 `<li>` / `<b>` 等标签**，
  也不能自己 `esc()`（用户数据交给 `inline_md()` 统一转义，两次转义会把知识点名里的 `&` 变成 `&amp;amp;`）。
  自带标签会被转义成**字面文本印在页面上**（曾经每份报告印出 50 处 `&lt;li&gt;…&lt;/li&gt;`）。
  想加粗只写 `**…**`，由 `inline_md()` 转成 `<b>`。
- **姓名与学号各占一列**：学生排名表、历次追踪表（报告）与 06/08 表（结果册）都是学号一列 + 姓名一列；
  `meta.has_student_id` 为假时**「学号」列整列不出现**，不用 `#N` 兜底编号冒充学号。
- 报告里**不指向「随附的结果册」**：只写「本表仅展示前 N 名，共 M 人」（PDF 单独一份，手上不一定有 xlsx）。

1. **封面**：考试名称、分析学科范围、班级、样本人数、涉及班级、任课教师、考试时间、生成时间
   （**不列**「满分设定」「统计范围」「数据来源」这类内部/来源字段 —— 用户要求 2026-10-08）
2. **目录**（多科模式必须；单科可省）——章节名按实际可用维度写，不虚报"完整 6 维度"
3. **核心结论摘要**：3–5 条最重要发现（单科聚焦该科；多科为跨学科视角）
   - `meta.history_order_source == "unknown"`（历次顺序判不出）时，摘要里必须加一条 ⚠️
4. **年级层 · 班级排名与全年级指标**（用户要求 2026-10-11；**仅多班样本生成**）：
   （一）班级总分排名（全部学科合计，按总分平均）→（二）各学科 · 班级整体排名（格内为该科**平均分** + 名次，
   末列平均名次；名次按**得分率**排定，因各科满分不同、平均分不可跨科横比）→（三）全年级各学科四率
   →（四）全年级各学科分数段分布（**按学科分别成表**，每科一张表、**表正上方用小标题写出学科名称**
   如「【数学】分数段分布（全年级 · 满分 150 分 · 135 人）」；表内「分数段」列写成**实际分数区间**
   如「0 – 90 分」「135 – 150 分」，列为 分数段 / 人数 / 占比 / 累计占比，**不用百分数**）
5. **各学科章节**（多科模式每科一章、章间分页）：维度 1→6 依次展开，每节含 表格 + 图表 + 解读；
   维度 3/4 开头必须有小字标注统计范围
   - **维度 2 分数段分布**：本班表的「分数段」列**直接显示具体分数区间**（按该科满分换算，
     如「0 – 90 分」「135 – 150 分」），不再单列「对应分区间」（用户要求 2026-10-11）
   - **维度 3 固定四块**（用户要求 2026-10-10 / 11）：`班级层 · 逐题得分率`（本班，含讲评优先级）
     → `年级层 · 逐题得分率`（全部样本）
     → `各班 · 逐题得分率`（行=题号、列=各班 + 全年级）
     → `得分最低 / 得分最高的试题清单`。小题分**不下到每个学生**。
     前两块与矩阵**都按题号升序**（纯数字按数值排如 1 → 2 → 10）；
     两层范围相同时只呈现一套；逐题表没有「学号」列时不摆「各班·逐题得分率」矩阵（无班可分）
   - **维度 5 对比分析**：逐班分数段表（标题「XX班 分数段分布」）的「分数段」列同样显示**具体分数区间**
   - **维度 3/4 缺数据时整节不生成**（标题、表格、图表全部不出现），**并且不再写「本节未生成」这类
     章首小字**（用户要求 2026-10-11）：缺失原因属于内部交代，只在**对话交付说明**里讲，
     报告正文保持干净。同时章节名从「完整 6 维度分析」改成「N 个维度：…」。
     **不要摆"数据缺失"空板块，也不要写任何占位文字**
   - 各科满分来源非 `user` 时，章首满分小字要标「（由成绩分布推断，待确认）」或「（按常规 100 分制默认，待确认）」
     —— 这是报告里**唯一**的满分待确认提示（「数据说明」章节已取消）
   - 维度 6 用的是历次成绩、且顺序由名称序号推出（`meta.history_order_source == "natural"`）时，
     附一行小字提醒顺序可复核（用 `--history-order` 指定后重跑）
   - `meta.history_order_source == "unknown"`（顺序判不出）时，**报告照常出但必须显著警示**：
     「核心结论摘要」加一条 ⚠️、维度 6 表格上方用一个 `note red` 区块说明
     「趋势判定与进步榜可能整体反向」，并给出补「序号」/`--history-order` 的补救方式。
     **不要把顺序存疑做成静默**，也不要因为它阻断整份报告
6. **历次成绩对比（年级 / 班级）**（用户要求 2026-10-11；**仅当历次表可用时生成**）：

7. **跨学科横向对比**（仅多科模式）

8. **教学改进建议**：共性问题（整体形态）→ 薄弱点讲评优先级（按学科分列）→ 重点学生（进步榜/需关注/临界生，按学科分列）→ 行动清单
   - 这一块的**标题与数据源随数据变**（用户要求 2026-10-11）：有知识点 →
     「（二）知识点薄弱点（讲评优先级）」+ 知识点清单；**只有逐题、没有知识点 →
     「（二）薄弱题讲评优先级（按小题得分率）」**，按每题得分率升序列出最薄弱的题（题号/等级/得分率/满分）；
     逐题与知识点都没有 → **整块不出现**，不写占位文字

## 知网文献引用规范（链接挂在篇名，不在作者）

权益 `true` 时，教学解读 / 改进建议可引知网实证文献提质（详见 SKILL.md「权益 ≠ 引用」段）。引用渲染**只有一种标准形态**，由 `report_builder.cnki_ref(author, year, title, url)` 统一产出，禁止手写拼接：

```
（作者，年《篇名(可点击)》）
```

- **可点击元素只能是篇名**：`<a href="…ix.cnki.net…" target="_blank" rel="noopener" style="text-decoration:none;color:#1F3864">篇名</a>`；
- **作者名与「（作者，年）」署名一律纯文本、不可点**，绝不能用 `<a>` 包裹作者名（2026-10-21 复盘：曾误把作者名染成链接，现已在 `_shared.md` 干净输出红线与 `selftest` 中锁死）；
- 正文署名引用、文末「参考文献（知网基教溯源）」列表都用同一函数，形态一致；
- 文末每条参考文献须带**来源**（`narrative.references[].source`，如「西南大学（硕士学位论文）」「《天府数学》（期刊）」），渲染为「篇名 —— 作者，年。来源：xxx。」；来源取自接口 `Source`/`JournalName`（CMFD 取授予单位、CJFD 取刊名、CAPJ 取资源库名），缺失时不显示该字段；
- 直链 URL（含 `filename=…nh`、`dbcode=…`）只进 `href`，渲染后不可见（见 `_shared.md` 干净输出红线，不得出现在可见文本里）；
- 权益非 `true`（态 B）时**不产出任何知网来源表述与链接**，照常走通用版兜底。
