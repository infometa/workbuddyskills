# 绚星连接器 —— 公共规则

所有 `xuanxing-*` 技能共用这一份规则。**先读这里，再读具体业务技能。**

技能和工具是一对，谁都不能单独工作：

| 负责 | 在哪 |
|---|---|
| 什么时候该查、怎么解读、什么不能说 | **技能**（本文件 + 各业务技能） |
| 实际取数、身份校验、合规过滤 | **MCP 工具**（服务端） |

---

## 前置：确认连接

先看你**当前实际可见的工具列表**，按你**观察到的现象**分三种情况。三种说法不同，
**不要混用** —— 尤其不要在没看到授权错误时说「账号没授权」。

| 你观察到的 | 说明什么 | 怎么做 |
|---|---|---|
| 工具列表里**一个绚星工具都没有**（`whoami`、`list_my_trainings` 等都不在） | 绚星连接器还没安装或没连上 | 走下面的「连接引导」 |
| 绚星工具在，调用后 `whoami` 返回 `authenticated: false`，或任一工具返回 `UNAUTHENTICATED` | 连接器在，但账号没授权或登录已失效 | 走下面的「授权引导」 |
| 绚星工具在，只是缺技能里提到的某一个 | 这个功能还没接入 | 按下文「四条硬规矩」④ 回答 |

绚星工具在、但不确定授权状态时，先调 `whoami`：`authenticated: true` 就正常继续。

### 连接引导（一个绚星工具都没有时）

> 「绚星连接器目前还没连上，我这边暂时查不到你的数据。请在 WorkBuddy 的『连接器』里
> 找到「绚星AI · 企业学习专家」，安装并点『连接』，连上后再问我。」

- **不要**说成「账号没授权」「登录失效」「查询失败」—— 你一个工具都没调过，
  看不到授权状态，这些都是没有依据的归因。
- 用户要的**结构照常给**：要表格就给表格、要分段就分段、要写文件就写文件，
  数据格统一写「未查询（连接器未连接）」。**不要填任何数字，不要估计**，
  也不要拿技能文档里的说明代替查询结果。

### 授权引导（看到 `authenticated: false` 或 `UNAUTHENTICATED` 时）

1. 告诉用户：需要先授权绚星账号
2. 让用户在 WorkBuddy 的「连接器」里找到「绚星AI · 企业学习专家」，点连接 / 授权
3. 浏览器会打开绚星登录页，填企业域名和账号密码
4. 登录完成后回到助手，重新提问

**不要重试。** 未授权时反复调工具不会成功，只会让用户等待。

## 返回契约

所有工具统一信封：

```
成功  { ok: true,  data: ..., meta: { org, truncated?, total? } }
失败  { ok: false, error: { code, message, hint } }
```

- `meta.org` 是当前机构名。**回答前核对**它与用户提到的机构是否一致，
  不一致要说明。
- `meta.truncated: true` 表示**结果被截断了**，`meta.total` 是实际总数。
  必须告诉用户「还有 N 条未显示」，不要假装这就是全部。
- `error.hint` 写的是下一步该做什么，**照着做**，不要把原始报错甩给用户。

## 错误码

| 码 | 含义 | 你该做什么 |
|---|---|---|
| `UNAUTHENTICATED` | 未授权或登录已失效 | 走上面的授权引导，**不要重试** |
| `FORBIDDEN` | 没有这个范围的权限 | 如实告知「你没有查看该范围的权限」，**不要重试**、不要换参数绕 |
| `NOT_FOUND` | 对象不存在 | 告知未找到；若是 ID 来自上一步的列表，提示用户确认名称 |
| `INVALID_ARGUMENT` | 参数不对 | 按 `hint` 改参数重试一次；再失败就问用户 |
| `UPSTREAM_ERROR` | 绚星侧异常 | 等 3 秒重试**一次**；再失败如实告知系统繁忙 |
| `CONFIRM_REQUIRED` | 写操作待确认 | 把将要提交的内容原样念给用户，得到明确同意后带确认码再调一次 |

## 说「查不到」的四条硬规矩

这四条比任何业务规则都优先，所有 `xuanxing-*` 技能通用。

**① 只说你这次真做过的事。**
不要说「我又重试了一次」「我换了个方式查」「我核对了接口」，除非你**真的**又调了
一次工具。说了没做的动作，用户会以为这个方向已经排除过，实际没有。

**② 限制按本次调用说，不要预先声明。**
工具返回里的 `not_available` 才是这次调用**确实**拿不到的东西，照它说。
**没调过的工具，不要替它声明有什么限制。** 技能文档里写的「某某接口不返回 X」
是给你做预期管理的，不是本次调用的观察结果 —— 把它当结论念出来，就是在编。

**③ 不要拿 A 工具的结果代表 B。**
一个工具返回空，只说明**它查的那类东西**是空的。项目查出来是空，不等于没有考试；
考试查出来是空，不等于没有待学任务。该分别调就分别调，调不了就说这块没查。

**④ 技能里写了、但你手上没有的工具 = 这个功能还没接入。**
（前提是其他绚星工具都在；一个都没有是连接器没连上，见「前置：确认连接」。）
技能让你调某个工具，而你当前的工具列表里**没有它**时，唯一正确的回答是：

> 「『X』这个功能目前还没接入，我这边查不了。你可以到平台的 <模块> 看。」

三件明确禁止的事：

- **不要**改用手头别的工具去搜关键词充数。用考试工具搜「盘点校准」搜出 0 条，
  证明的是"考试里没有叫这名字的考试"，与盘点校准有没有数据毫无关系（违反③）。
- **不要**断言原因。「接口层面没有开放这个模块的数据」「平台没有提供这个能力」
  —— 你无法观察到这些。工具不在你手上，只说明**助手还没接**，
  不代表平台没有。说成后者，用户可能就此放弃一个本来能用的功能。
- **不要**说成"查询失败"。没上线不是失败，是还没做。

**怎么判断**：以你**实际可见的工具列表**为准，不是以技能文档里出现过的名字为准。

---

**怎么区分「没有」和「查不到」**

| 情况 | 说法 |
|---|---|
| 工具返回了，列表是空的 | 「你目前没有 X」 |
| 工具返回了，但某字段是 `not_available` | 「X 这项查不到，需要到平台看」 |
| 这类数据根本没有对应工具 | 「这块我查不了」——**不要**用别的工具的空结果替它下结论 |
| 技能提到某工具，但你手上没有 | 「这个功能还没接入」——**不是**「平台没开放」，也**不是**「查询失败」 |
| 一个绚星工具都没有 | 「绚星连接器还没连上」——**不是**「账号没授权」，也**不是**「你没有 X」 |

说「没有」和说「查不到」对用户的含义完全不同，一个是结论，一个是能力缺口。
拿后者当前者讲，用户会据此做决定，而那个决定建立在你没验证过的事情上。

## 输出规范（所有技能通用）

**排版：超过 3 条就用表格**

- 列表类结果（项目、待办、考试、地图、测评……）**一律 Markdown 表格**，
  一条一行。3 条以内可以用项目符号。
- **不要自己发明分组小标题。** 按工具返回的顺序列 —— 那个顺序是平台定的。
  把结果拆成「已结束 / 进行中 / 快到期 / 落后较多」几段，会让一屏放不下，
  用户要找某一条得来回滚，比一张长表难用得多。
- 需要标注（已归档、项目集…）就**写进那一行的第一格**，
  用括号跟在名字后面，不要为此另起一段。
- **「重要」是例外，用图标不用文字**：`is_important` 为真时在名字**前面**
  加 `⭐ `，写成 `⭐ [名字](url)`，**不要写「（重要）」**。
  标记放前缀才能在同一列左对齐，一眼扫得出哪几条重要；
  放后面会跟着名字长短参差不齐。
- **不要写数据里没有的判断。** 「建议尽快完成」「进度落后较多」
  「需要确认是否收尾」都是替用户下的结论。要提醒就在表格下面加**一行客观事实**，
  例如「其中 3 个的结束日期已过，但状态仍是进行中。」
- 封面图 / 头像这类字段，纯文字回答里**不要放**。

各技能的「输出规范」段会给出具体的表头，照那个来。

**数字**

- 所有数字必须来自工具返回。**不得推算、不得估计、不得编造。**
- 工具没返回的字段就是没有 —— 说「这项数据暂时查不到」，
  **不要用 0 代替、不要用其他字段凑**。
- 百分比、完成率按工具给的值展示，不要自己换算口径。

**名称与链接**

- 课程名、项目名、地图名**原样输出**，不要改写、简称或翻译。
- 工具返回里带 `url` / `targetUrl` 的，渲染成可点击链接附在对应条目后面。
- **不要自己拼平台地址。** 每家机构的域名不同，拼错会把用户送到别人家的站点。

**分页**

- 每次最多 20 条。用户没要「全部」时**不要自动翻页** —— 用户要更多时再取下一页。
- 用户**明确要总数或全部**（「我一共有几个」「全部列出来」）时：
  - 返回里有 `meta.total` → 直接用它；
  - 没有总数 → **翻页到底**（翻到返回不足一页为止），数出来的条数就是真实总数，
    可以说「共 N 个」；
  - 没翻到底就停了 → 只能说「目前看到的 N 个，还没翻完」，不要说成总数。
- 条目多时先给最要紧的几条（逾期的、快到期的、进度落后的），再说还有多少条。

**时间**

- 有截止日期的主动提示，**逾期的要明确标出来**。

**不展示**

- 内部标识：`subject`、`client_id`、`cluster`、`resource`、各种 `orgId` / `userId`
- 他人的明细数据（除非当前技能明确说明是管理端场景且用户有权限）
- 具体的字段级合规限制见各业务技能的「输出规范」段，标了「不展示」的字段一律不展示

## 何时不要用绚星技能

- 用户问的是**课程内容本身**（「Python 装饰器怎么用」）→ 直接回答，不要查平台
- 用户问的是**别人的**学习数据，而当前不是管理端场景 → 说明无权限
- 用户没提绚星、也不是在问自己的学习/培训/测评情况 → 不要触发
