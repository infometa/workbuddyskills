# 批阅与鉴定待办（教学端）

## 前置

先读 `xuanxing-shared`，确认连接与授权。

## 何时使用

- 「我还有哪些待批阅的考试 / 作业」
- 「我有多少要批的」「我要批改什么」
- 「我还有哪些待鉴定的任务」
- 「有什么等我审核的」—— **目前查不了**，见下方「已知限制」，照那里说

## 何时不要使用

| 用户想问 | 用哪个 |
|---|---|
| **我自己**要考的考试 | `xuanxing-study-todo` |
| **我自己**的作业要交什么 | `xuanxing-study-todo` |
| 项目整体进度、谁没完成 | `xuanxing-training-admin` |

⚠️ **最容易串台的一组**：「我还有哪些考试」有两种意思 ——
「我要**考**的」（`xuanxing-study-todo`）和「我要**批**的」（本技能）。
用户说「批阅」「批改」「待批」「鉴定」「审核」才是本技能。
不确定时**问一句**，不要猜。

## 调用流程

每一类数据在**不同的地方**，按用户问的是哪一类选工具：

| 用户问 | 调用 |
|---|---|
| 待批阅的**作业** | `list_my_homework_markings`（默认就是待批阅） |
| 已批阅的作业 | `list_my_homework_markings`，`status` 传 `done` |
| 待批阅的**考试** | `list_my_exam_markings` |
| 待**鉴定**的任务 | `list_my_appraisals`（默认就是待鉴定） |
| 已鉴定的 | `list_my_appraisals`，`status` 传 `done` |
| 笼统地问「我要批改什么」 | 作业、考试、鉴定三个都调，分三段讲 |
| 等我**审核**的 | **不调工具**，按「已知限制」照实说 |

用户要按学员找，`keyword` 传学员姓名或账号；按作业找，`homework_name` 传作业名；
按鉴定名称找，`appraisal_name` 传鉴定名（鉴定的 `keyword` 和 `appraisal_name` 只能传一个）。

### ⚠️ 考试批阅的日期筛的是「考试发布时间」，不是「交卷时间」

`list_my_exam_markings` 的 `start_date` / `end_date` 对的是**考试发布日期**。

- 用户问「**9 月发布**的考试还有哪些没批」→ 可以筛，正常答。
- 用户问「**上个月交上来**的卷子还有多少没批」「最早提交的是哪份」
  → **这个口径查不了**。照实说只能按考试发布时间筛，
  **不要**把发布时间筛出来的结果当成交卷时间的结果讲。
- 两个日期**必须一起传**（只传一个工具会直接拒，不会静默返回全部）。
  用户只说了一头（「9 月以后」）就把另一头补成今天或该月末。

## 输出规范

用户只是想知道「我还有多少要批」时，先给各类总数，不要一上来铺一长串明细。

### 跳转链接：每一行都要带

三个工具返回的 `review_url` 是**带机构域名的完整地址**（形如
`https://<机构域名>/ote/#/stu/mark`），**每一行**的名称都做成指向它的链接，
**不能只在结尾放一个** —— 表格一长，结尾那一个用户就看不到了。

- 地址**原样用 `review_url` 的值**，不要改写，**不要只写 `ote/#/stu/mark` 这种不带域名的路径**，
  也不要自己拼域名（每家机构不一样）。
- 返回里没有 `review_url` 时只写名称，**不要编链接**。
- 结尾仍然再给一次 `review_url`，作为「去 XX 页批阅」的入口。

### 待批阅的作业（`list_my_homework_markings`）

跟平台批阅中心的列表一个样子，每条给：

- **学员姓名**（`student`）+ 部门（`department`）+ 来源标签（`source`，如「培训项目」）
- **作业名称**（`homework_name`），写成 `[作业名称](这一条的 review_url)`——
  **不是**结尾那个顶层 `review_url`。`homeworks[]` 每条自带 `review_url`，
  点开直接是这一份提交的批阅详情页（不用先进批阅中心列表页再找）。
  某条的 `review_url` 是 `null`（缺拼链接必需的字段，极少见）才退回去只写
  名称，不编链接。
- 所属项目：`project_name`
- 提交时间：`submitted_at`

开头先说总数「你有 N 份作业待批阅」（取 `meta.total`），每条用上面的逐条
`review_url` 链到具体这一份；结尾再给一次顶层 `review_url`，作为「去批阅
中心看全部」的入口（这是列表页，不是某一条的直达链接）。总数多时先列前几条，
告诉用户还有多少。

- `is_group_work` 为 true 时 `student` 是**小组名**，要说「XX 小组提交的」，不要当成人名。
- 一条 = 一份提交，同一个学员可能有多条。说「N 份」，**不要说「N 个人」**。
- 用户问「最早是什么时候提交的」用 `earliest_submitted_at`（已经是全量里的真实最小值）。
- 「谁有几份待批」用 `by_student`；「每项待批份数 + 所属项目」用 `by_homework`——
  两个都是全量统计字段（不受 `homeworks` 展示截断影响），已按份数从多到少排好。
  `by_homework` 每项是 `{homework_name, project_name, count}`，`project_name`
  就是「所属项目/任务」，直接用它答，不要只从 `homeworks` 最新几条里找所属项目。
- 「每个作业还有几份没批」用 `by_homework` 回答，**不要**说查不了。
  ⚠️ 全量聚合有取数上限（见 `not_available`，机构待批数超过上限时会写明），
  超过上限时 `by_student`/`by_homework` 只覆盖取到的那部分，**不是**精确
  全量——按 `not_available` 里的话说清楚覆盖范围，不要当成精确全量讲，更
  不要据此下"积压更集中在某些学员/作业上"这类全量性结论。用户没问的归纳
  不要主动给。

⛔⛔ **追问后重新取到更完整的数据时，正文里的数字要用新数据重算，不许沿用
上一轮的旧数字。** 常见错误：追问时已经把全量数据取回来核对过，但回答正文里
各作业、各学员的份数还是首轮只看了部分数据时算出来的旧数。
同一轮对话里，后面的回答只要用到了更完整的数据，就要把前面说过的统计数字
重新算一遍，不能因为"前面已经说过"就照抄。

### 待批阅的考试（`list_my_exam_markings`）

跟平台考试批阅页一个样子，**一条 = 一场考试安排**（不是一份卷子），每条给：

- **考试名称**（`name`），写成 `[考试名称](review_url)`
- 参与人数：`participant_count` · 待批阅数：`pending_count` · 发布时间：`published_at`（只说日期）· 来源：`source`

开头先说「你有 N 场考试待批阅」（取 `meta.total`），结尾给 `review_url`
作为「去考试批阅页批阅」的链接。表格形如：

| 考试名称 | 来源 | 发布时间 | 参与人数 | 待批阅数 |
|---|---|---|---|---|
| [示例考试](https://<机构域名>/ote/#/stu/mark) | 项目安排 | yyyy-MM-dd | 2 | 1 |

- N 是**场次**，不是卷子份数；要说总共几份卷子，直接用 `page_pending_total`
  （工具已经把本页 `pending_count` 加好了），**不要自己手动相加** —— 心算
  加总很容易差一两份，逐场数字都对、合计却错。`page_pending_total` 只是
  **本页**的合计，说清楚「这是前 X 场的合计」，没列全时不要说成全部场次的合计。
- 用户要按**时间段**统计（如「去年及以前有多少场/多少份」），**不要**从
  已经展示的（可能被截断的）列表里手动数或加总——按该时间段重新传
  `start_date` / `end_date` 调一次，用返回的 `meta.total` 和新一批
  `page_pending_total` 作为这个时间段的权威数字。
- 用户想知道「哪场最该优先批」「按等待时间排」时，传 `sort_by="longest_wait"`
  重新调一次（默认 `published_desc` 是发布时间从新到旧，与平台页一致）。

### 待鉴定的任务（`list_my_appraisals`）

跟平台「我的鉴定」页一个样子，每条给：

- **学员姓名**（`student`）+ 部门（`department`）+ 来源标签（`source`，如「培训项目」）
- **鉴定名称**（`appraisal_name`），写成 `[鉴定名称](review_url)`
- 所属项目：`project_name`
- 提交时间：`submitted_at`

开头先说「你有 N 条鉴定待处理」（取 `meta.total`），结尾给 `review_url`
作为「去我的鉴定页鉴定」的链接。

- 一条 = 一个学员的一次鉴定申请，同一个学员可能有多条。**不要说「N 个人」**。
- `meta.distinct_students_in_page` 只是**本页**学员明细去重后的人数，口径窄，
  一般不用它回答「涉及多少学员」。

### 按任务统计（`list_my_appraisals` 返回里的 `tasks`）

对应平台「我的鉴定」页的「项目」「认证项目」两个页签——与上面
按学员一条一条列的 `appraisals` 是**不同粒度**的同一份数据，`tasks` 是按「项目/
认证项目」聚合出来的任务清单，**不受** `keyword`/`appraisal_name` 筛选。

- 用户问「**按任务**算涉及多少学员」「这个任务有多少人没鉴定」，用
  `tasks[].student_count`——这是平台原样给的数，**不是**按 `appraisals`
  明细数出来的。
  ⚠️ 它与 `appraisals` 明细的条数（`meta.total`）**不保证相等**：有的机构
  几乎一致，有的机构 `student_count` 略大，不能假设固定会差一截，也不能假设
  一定对得上。它的口径可能比「已提交申请、正等你处理的学员」（`appraisals`
  这份明细）更宽。回答时把 `student_count` 讲成「平台给出的待鉴定学员数」，
  **不要**说成「这些人都已经提交了申请在等你处理」——那是混淆了两个不同口径
  的数据。
- 鉴定**截止时间 / 是否逾期**：`tasks[].project_end_time` + `project_overdue`——
  **培训项目、人才发展、认证项目都可能有值**，不是只有认证项目类才有。
  单个任务没配起止时间时这两个字段可能是 `null`，这时如实说
  「这个任务没配起止时间」，**不要**说成「这类任务平台不给」。
- `project_overdue` 为 `null` 时不代表「没逾期」，代表这个任务没配起止时间
  或是周期/相对时间模式——照字段说明讲，不要把 `null` 当 `false` 用。
- 任务名称 `tasks[].name`：认证项目类、培训项目类、人才发展类都会给名称；
  单条没有名称时如实说「这个任务的名称这次查不到」，**不要**拿
  `appraisals` 明细里的 `project_name` 去顶替——那是学员申请所属的项目名，
  字段来源不同，可能对不上。

### 已知限制（照实说，不要编）

| 用户可能会问 | 现状 | 你该怎么回答 |
|---|---|---|
| 有什么**等我审核**的 | **没有工具能查** | 说「审核类待办我这边暂时查不了，请到平台的待办里查看」。**不要**说「你没有待审核的」，也不要拿作业 / 鉴定的数据凑 |
| 作业 / 鉴定按**等了最久**的排 | 固定按提交时间**从新到旧**（与考试不同——考试支持 `sort_by=longest_wait`，这两个工具没有这个参数） | 照返回顺序讲并说明「按提交时间从新到旧排列」；等得最久的在最后几页 |
| 考试按**等了最久 / 待批时长**的排 | `list_my_exam_markings` 支持 `sort_by="longest_wait"`（发布时间从旧到新，越早发布等越久） | 用户问"哪场最该优先批"类问题时传这个参数，**不要**用默认的 `published_desc` 再自己猜顺序 |
| 直接打开某一场考试 / 某一条鉴定 | 考试和鉴定的 `review_url` 是**列表页**，每行的链接指向的是同一个列表页（作业不同：`homeworks[].review_url` 是这一份的批阅详情页，见上） | 给链接并说「在页面里找到它」，不要说是直达链接 |
| 来源 `source` 为「未知」 | 码值不认识 | 说「来源未知」，不要猜 |
| 已鉴定的**鉴定结论**（通过没通过） | 返回里没有结论字段 | 说「结论要到我的鉴定页查看」，不要猜 |
| 鉴定**截止时间 / 是否逾期** | 按学员一条条列的 `appraisals` 这层没有；按任务看的 `tasks[].project_end_time`/`project_overdue` 有，培训项目/人才发展/认证项目都可能有值 | 用 `tasks`（见上方「按任务统计」）回答；单个任务没配起止时间时如实说「这个任务没配起止时间」，不要说成「这类任务平台不给」 |
| 作业**最早提交时间** | `list_my_homework_markings` 的 `earliest_submitted_at` 是另外查的真实全量最小值 | 直接用这个字段回答，**不要**自己从本页列出来的几条里找最小值当"最早" |
| 积压里**新单子多还是老单子多**（作业/鉴定/考试都一样） | 本工具只给分页抽样，没有按时间分布的统计 | 只核对过的那几条如实说，**不要**凭小样本下"大部分是老的/新的"这类构成性结论 |

## 错误处理

按 `xuanxing-shared` 的错误码表。

- 某一类返回空列表 —— 说「你目前没有待批阅的作业」（或考试 / 鉴定），
  只说**那一类**，不要推成「你什么都不用批」。
- `FORBIDDEN` 说明用户没有教学管理权限，如实告知，不要重试。
