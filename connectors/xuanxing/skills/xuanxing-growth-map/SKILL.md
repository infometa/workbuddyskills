# 成长地图与认证

## 前置

先读 `xuanxing-shared`，确认连接与授权。

## 何时使用

- 「我的岗位地图走到哪了」「我在哪个阶段」
- 「我的层级地图闯到第几关」「下一关是什么」
- 「我的认证项目过了吗」「认证拿了多少分」

## 何时不要使用

| 用户想问 | 用哪个 |
|---|---|
| 普通培训项目的进度 | `xuanxing-study-progress` |
| 测评、发展计划（IDP）、盘点校准 | `xuanxing-assessment-idp` |
| 待学任务 | `xuanxing-study-todo` |

⚠️ 「地图」在绚星有两种：**岗位地图**（按岗位的培养方案）和
**层级地图**（闯关式）。用户只说「地图」时，`list_my_growth_maps` 两种都会返回，
用返回里的类型字段区分着讲，**不要替用户假定是哪一种**。

## 调用流程

1. 先调 `list_my_growth_maps`，不传参数 —— 岗位地图、层级地图**全部**一起返回
   （不分页、不截断，也不给总数/截断字段），直接按列表展示。

   用户点名问某一张地图时，可以带 `keyword`（地图名关键字）或 `map_id` 缩小范围，
   也可以直接在全部列表里找。

   ⛔ **`keyword` 只按地图名称模糊匹配，不是"按类型筛"——没有 `map_type`
   这个入参。** 常见错误：用户问「我的层级地图」（泛指这一**类**地图，
   不是某一张具体的图），被当成 `keyword="层级"` 去匹配地图名称，结果只有
   名字恰好带"层级"两个字的地图被搜到，名字不含这两个字的层级地图全部漏掉。
   **问某一类地图（"我的层级地图/岗位地图"）时不要传 keyword**，直接调用拿到全部地图，再用返回里
   每条的 `map_type` 字段分组/筛选——`keyword` 只在用户报出具体地图**名字**
   时才用。

   ⚠️ 带了 `keyword` 没找到时，只能说「按这个名字没找到」，先去掉 `keyword`
   再调一次在全部列表里核对，**不要**直接说「你没有参与这张地图」。
   返回里 `failed` 不为空时，表示那一类地图**这次没查成**（不是 0 张），照实说。

2. 用户问某一张地图的细节（第几关、还差什么）：
   - 从第 1 步的返回里拿这张地图的标识，**两种地图要的 ID 不一样**：

   | 地图类型 | `map_type` | 还要传 | 从哪来 |
   |---|---|---|---|
   | 岗位地图 | `position` | `series_id` | 该地图 `series[]` 里某一项的 `series_id` |
   | 层级地图 | `level` | `stage_id` | 该地图的 `stage_id` |

   > 列表返回的 `map_type` 是中文（「岗位地图」「层级地图」），**原样传回去也行**
   > （工具两种写法都收），不必自己转成英文。

   - 调 `get_growth_map_detail`
   - 名字匹配到多张地图时**问用户**是哪一张
   - 岗位地图下有多个序列时**也要问用户**看哪个序列，不要挑第一个
   - 少传 `series_id` / `stage_id` 会拿到 `INVALID_ARGUMENT`，
     按提示补参数重试一次即可，**不要**换成别的工具
   - 拿到「这张层级地图还没有发布」时如实说，**不要重试**
   - 岗位地图的 `detail_available` 为 false 时**不要调** `get_growth_map_detail`
     —— 这张地图没有已发布的培养方案，查不了明细（`map_id`/`series` 都是空的），
     直接说「能看到这张岗位地图，进度 X%，但这边查不到明细」
3. 问认证 → `get_my_certification`，它自己会把认证项目清单和我的结果取齐。

## 输出规范

- 地图讲清三件事：**这是哪张地图、我现在在哪、下一步是什么**。
  只报一个百分比用户没有体感。
- 层级地图要说当前关卡名称和状态；有下一关名称时一并给出。
  ⚠️ **`stage_status`（未开始/进行中/已完成）是真实值**，
  直接用，不要只给进度百分比而不说状态。为 `null` 且 `stage_id` 也是 `null`
  时，说「这张地图还没有建关卡」，不是「状态不明」。
- 认证要说清是否通过；有申诉记录时提一句。
  「是否通过」看 `level`（就是平台报告页的「认证结果」，如通过 / 不通过，**原样说**），
  得分看 `score`。`level` 为 `null` 且 `score_hidden` 不是 `true` = 这个项目
  **还没有认证结果**，此时 `score` 通常也是 `null`，说「还没出结果」，**不要**说成
  「得了 0 分」或「没通过」；`score_hidden` 为 `true` 是机构隐藏了得分，说「得分未公开」；
  `result_query_failed` 为 `true` 才是「这一项没查到」。
  ⛔ **不要**因为多数项目 `level` 是 `null` 就对整个清单说「没有任何项目出结论」——
  逐个项目看，有结果的都要说，否则会漏掉那些已经有通过 / 不通过结论的项目。
  没有 `report_url` 只表示平台没给这个项目报告入口（完成率未到 100%），**不代表没有结果**。
  ⛔ **每个认证项目都要带上起止时间**（`start_time`/`end_time`），
  `relative_schedule=true` 时才说「相对时间模式，没有固定起止日期」；
  为 `false` 时 start_time/end_time **就是实际有值的日期**，要逐条写出来。
  常见错误：起止时间明明有值，回答里却一个都没提。
- 认证项目返回里有 `report_url` 时，把「查看认证报告」做成指向它的链接直接给用户。
  **没有这个字段**表示平台没给这个项目报告入口（任务完成率还不到 100%）—— 照实说，
  但结果（`level` / `score`）有就照样说；**不要自己按模板拼一个报告链接**。
- 每张地图 / 认证项目附上可点击的进入链接，**不是只在结尾放一个列表页链接**：
  - 认证项目：每条都有 `project_url`（不论完没完成），把项目名称做成指向它的链接；
    `report_url` 是另一个链接（只在 100% 时有），两个都给、不要只给一个。
  - 岗位地图：`detail_available=true` 时 `series[]` 里每个序列自带 `url`，
    按序列给链接（多个序列就给多个，不用猜用户要哪个）；`detail_available=false`
    时没有链接，照实说「这张地图看得到，但这边没法给跳转链接」。
  - 层级地图：每张都有 `url`（已按 mapId 拼好），把地图名称做成指向它的链接；
    `get_growth_map_detail` 查单张层级地图时返回里也带同一个 `url`，回答明细时也要给。

### 合规限制（硬性）

- **进度可能被机构隐藏。** 工具在这种情况下不会返回进度值 ——
  此时说「你所在机构未开放学习进度展示」，
  **绝不要**用其他字段推算进度、也不要说「查询失败」。
- **认证结果可能被机构隐藏。** 同理，此时不给得分与分层结果，
  只说「认证结果未公开」。

这两条都由服务端强制执行。你看不到值就是不该看到，不要绕。

⛔⛔ **`score`/`level` 为 null 时，先看 `score_hidden` 再开口，这两种原因
不许混。** 常见错误：返回是 `score_hidden: false`、`score: null`，
回答却编出了「得分被机构隐藏」——数据本身没错，是编错了原因。

| 字段 | 含义 | 怎么说 |
|---|---|---|
| `score_hidden: true` | 机构设置了隐藏得分 | 「认证结果未公开」 |
| `score_hidden: false` 且 `score`/`level` 为 null | 还没出结果（评定/批阅尚未完成） | 「结果还没出来」 |

两种都**不许**说成「通过了」或凭空编一个「隐藏」的理由——`score_hidden` 的
真实值就在返回里，照它说，不要自己判断「大概率是隐藏了」。

**`progress` 为 null 有两种原因，说法不同，先看字段再开口：**

| 字段 | 含义 | 怎么说 |
|---|---|---|
| `progress_hidden: true` | 机构设置了不展示进度 | 「你所在机构未开放学习进度展示」 |
| `progress_query_failed: true` | 没取到进度值（接口没查成，或上游没给这一关的值） | 「这张地图的进度我这次没查到」 |

两种都**不许**说成「进度是 0」或「还没开始学」—— 把没查到当成 0 报给用户，
而平台上那一关可能实际已经完成了。

⚠️ **`progress` 是 0 和是 null，是两句话。** 0 是上游给了值、确实没开始；
null 看上面两个标志。两个标志都 false 而 progress 仍是 null 时，当作
「没查到」说，**不要**自己补成 0。

### 已知限制（照实说，不要编）

> ⚠️ 本表是**预期管理**，不是本次调用的观察结果。
> 照实回答要以工具返回的 `not_available` 为准（见 `xuanxing-shared` 的硬规矩）。
> **没调过的工具，不要替它声明限制。**

| 用户可能会问 | 现状 | 你该怎么回答 |
|---|---|---|
| 我的**评估部分**完成了多少、**培训部分**完成了多少 | 返回里可能只有「是否完成」的布尔值 | 有完成率就给完成率，只有布尔值就说是否完成，**不要把布尔值说成百分比** |
| 给我认证**报告**的链接 | 看本次返回里有没有 `report_url` | 有就给（就是平台「查看认证报告」打开的地址）；没有就说这个项目暂时没有报告入口、需到平台看，**不要自己拼报告链接** |
| 学习报告链接 | 看本次返回里有没有 | 工具返回了就给，没返回就说暂无 |

## 错误处理

按 `xuanxing-shared` 的错误码表。

- 用户没有参与任何地图时返回空列表 —— 说「你目前没有参与中的地图」，
  **不要说查询失败**。
