# 学习待办

## 前置

先读 `xuanxing-shared`，确认连接与授权。

## 何时使用

- 「我这周有什么要学的」「我还有什么没学完」
- 「XX 项目下导师给我派了什么任务」
- 「我还有哪些考试没考 / 没通过」
- 「有什么快到期了」「我有逾期的吗」

## 何时不要使用

| 用户想问 | 用哪个 |
|---|---|
| 想找新课程学、想报名新项目 | `xuanxing-catalog-discovery` |
| 某个项目**完成了多少**、拿了多少学时学分 | `xuanxing-study-progress` |
| 待**批阅**的考试 / 作业（我是老师） | `xuanxing-teaching-todo` |
| 岗位地图、层级地图、认证项目 | `xuanxing-growth-map` |

⚠️ 注意区分「我还有哪些考试**没考**」（本技能）和「我还有哪些考试**待批阅**」
（`xuanxing-teaching-todo`，那是老师视角）。

## 调用流程

### ★ 先分清：三个来源是三件事，问什么调什么

| 用户问的 | 调哪个 | 它是什么 |
|---|---|---|
| 「我有哪些培训」「我的培训项目」 | `list_my_trainings` | o2o 的培训项目，**带跳转链接** |
| 「我有什么待办」「我这周要学什么」 | `list_my_study_todo` | 平台待办中心（含**外派培训**） |
| 「我有哪些考试」 | `list_my_exams` | 测练中心的考试 |

⚠️⚠️ **这三个来源是三份不同的数据，一个为空不代表另外两个也为空。**

- 只调了培训 → **不能**说「你没有待办」
- 只调了待办 → **不能**说「你没有培训」
- 哪个没调，就别替它下结论；需要就再调一次

问法含糊时（比如只说「我要学什么」），**两个都调，分开讲**，不要合并计数。

列培训项目时有两条必须自检的规矩：

⛔⛔ **每个项目名都必须做成指向 `url` 的链接，一个都不许漏。** 数据里每条都带着
`url`，不给链接就是漏答。回答前自检：列了几个项目名，就要有几个 `[name](url)`，
数不上就是漏了，补全再发出去。

⛔⛔ **返回几条就要列几条，一条都不许漏。** `trainings` 返回里带着
`data.completeness_check`，写明了这次要列几条 —— 回答前数一遍表格行数对不对得上，
对不上就是漏了，找回来补上再发。**不要因为某条 `task_total` 是 0、看着像空项目
就跳过它**（全是选修任务的项目 `task_total` 就是 0）；有没有任务看
`progress_basis`，不看 `task_total`（见下）。

1. 问**我有哪些培训**：调 `list_my_trainings`。

   | 用户想看 | 传什么 |
   |---|---|
   | 我有哪些培训（默认） | 不传，默认 `status="ongoing"` 进行中 |
   | 还没开始的 | `status="upcoming"` |
   | 已经结束的 | `status="ended"` |
   | 归档的 | `status="archived"` |
   | 全部 | `status="all"` |
   | 用户**明确说**要看项目集 | `collection=True`（默认只查普通项目） |
   | 只看没做完的 | `show_unfinished=True` |
   | 按名字找 | `keyword="..."` |
   | 看下一页 | `offset` 往后翻，`limit` 默认 16、最大 20 |

1b. 问**我有什么待办**：调 `list_my_study_todo`。
   只有 `overdue_only` / `offset` / `limit` 三个参数。
   它的 `meta.total` 是**真实总数**，可以说「共 N 条待办」。
2. 问**考试**（没考的、快到期的）：调 `list_my_exams`，`status="pending"`。
   其余取值：`marking` 批阅中、`done` 已完成、`absent` 未参与、`all` 全部。

   ⛔ **每场考试的名称都做成指向 `url` 的链接**（工具已按考试类型拼好：循环考试
   进循环考试列表页，其他进考试入口页）。`url` 为 null 时只写名称，
   **不要自己拼链接**，也不要说「平台不提供考试链接」。

   **「我一共几场没通过」怎么答**：

   ```
   list_my_exams(status="all", passed=False)    → meta.total 就是总数
   ```

   - ✅ **可以**直接说「你一共 N 场没通过」——`meta.total` 是平台筛好的真实总数，
     不受分页限制。
   - ⚠️ **必须用 `status="all"`**。`passed` 和 `status` 是**两个轴**：
     没通过的考试会分散在已完成、未参与、待考（例如主考没过、补考还没开始）
     等各档里。只用 `status="done"` 会漏掉未参与那一档。
   - 想看具体是哪几场，就翻页读 `exams`；`passed=True` 则是只看通过了的。

   **逐条看通过与否**（每条考试都带 `passed` / `score`）：

   - 用 `status="done"`（已完成）查，再挑 **`passed` 为 `false`** 的那几条。
   - ⛔ **`passed` 为 `null` 绝不能说成「没通过」。** null 的意思是
     **还没考完**（未开始 / 考试中 / 批阅中都是 null）。
     平台对还没考的考试同样返回 0 分、未通过，工具已经把这些挡成 null 了 ——
     **只认 `passed` 这个字段**，不要自己去看分数或状态推。
   - ⛔ 仍然**不许**拿 `status="done"` 本身当成「通过」——"考完了"和"通过了"是两回事。
   - ⚠️ 这样逐条挑只覆盖**取到的这一页**，`meta.truncated` 为 true 时
     **不要**拿它说总数 —— 要总数就用上面的 `passed=False`。
   - `score` 为 0 分**是正常的**，0 分不等于没查到。
   - 出现 `result_query_failed` 时，`passed` 的 null 是**没查到**不是没考完，照实说。

   ⚠️ **`round_count` 非空的那几条：这是循环考试，平台给了多轮记录。**
   工具**不替你挑一轮** —— 只有恰好一轮考完时才给 `passed` / `score`，否则它们是
   `null`。这时说「这场是循环考试，有 N 轮记录」，**不要**把某一轮的分数说成
   「你这场的成绩」。

   ⚠️ **`has_resit` 为 true 的那几条：一行说的是两场考试。**
   `passed` / `score` 是**主考**的（通常没通过，所以才派了补考），
   `my_status`（形如「补考未开始」）说的是**补考**。它出现在待考里，欠的是补考那场。

   - ✅ 「这场主考你没通过，有一场补考还没开始」
   - ⛔ 不要说「这场你还没考」—— 主考考过了
   - ⛔ 不要说「你没通过且没有补考机会」—— 正好相反

   **「还能考几次」**：用户问起时传 `with_remaining_attempts=True`
   （按条逐个查配置，较慢，默认关，用户真问这个才开）：

   | `can_retake` | `remaining_attempts` | 怎么说 |
   |---|---|---|
   | `false`（不可重考） | 精确值（已算好） | 直接报数，如「你还能考 1 次」 |
   | `true`（可重考） | 固定是 `null` | 「这场可以重考，但具体还能考几次这边读不到」——**不要**编数字，也**不要**说成「不限次数」（没有字面证据） |
   | `null` | `null` | 这场是循环考试（`is_recurring=true`），「再来一轮」是另一套机制，这个问法不适用 |

   不传 `with_remaining_attempts` 时这两个字段也会出现在返回里但恒为 `null`，
   同时 `not_available.remaining_attempts` 会说明"没查"不是"查不到"。

   ⛔ **`my_status_conflict` 非空的那几条：三个字段都别用。**
   平台两个接口对这场考试的说法不一致（一个说你没开始，一个说你考完了），
   工具已经把 `my_status` / `passed` / `score` 全部置空。这时：

   - ✅ 「这场考试平台上两处状态对不上，建议你到「我的考试」页看一眼」
   - ⛔ 不说「你没通过」，也不说「你还没考」—— 两句都可能是错的。
   - ⚠️ 它**仍然是一条欠着的考试**，数「还有几场没考」时不要把它悄悄丢掉；
     `meta.status_conflict_count` 是本页这种条数，必要时说「其中 N 场状态待确认」。

   ⚠️ **`absent` 对的是平台的「未参与」，不是「缺考」判定。**
   这一档里每条的 `my_status` 仍可能显示「未开始」「考试中」——
   那是平台两个口径不一致，不是数据错。讲的时候说「这些你还没参加」，
   不要逐条念 `my_status`，也不要断言「你缺考了」。

   ⚠️ **排序只在本页内。** `meta.sorted_within_page_only` 为 true 时，
   全量里更急的那场可能在后面的页上，这时只能说「我看到的这些里最急的是 X」，
   **不要**说「你最急的是 X」。已过期的考试一律排在最后
   （`meta.expired_count` 是本页过期条数）。
3. 用户限定了时间（「这周」「这个月」）→ 传对应的时间范围。
4. 用户问**某个具体项目下**导师派了什么：
   - **先**调 `list_my_trainings(keyword="项目名")` 找到它，拿 `project_id`
   - **再**调 `list_my_mentor_tasks(project_id)`
   - 名字匹配到多个项目时**问用户**是哪一个，不要猜
   - 一个都没匹配上，如实说没找到，不要拿别的项目顶替

### 导师任务怎么展示（`list_my_mentor_tasks` 的结果）

⛔⛔ **任务数不许凭印象编。** `data.completeness_check` 把 `stages[].tasks` 的
真实总数算好摆在旁边了——回答前按这个数核对，不要自己数 `stages` 嵌套数组
时数错或编一个整数。按阶段列任务，`is_mentor_task` 为 false 的是项目里的
普通任务，不要跟导师派的混在一起算进「导师任务」的条数里。

## 输出规范

**列表一律用 Markdown 表格**，不要用多级小标题 + 嵌套项目符号 ——
那种排版一屏放不下，用户要找某一条得来回滚。

### 学习待办怎么展示（`list_my_study_todo` 的结果）

```markdown
| 待办 | 分类 | 时间 |
|---|---|---|
| ⭐ [管理技能外派培训](短链) | 外派培训 | 10-01 ~ 10-05 |
| [新员工入职引导](短链) | 在线课程 | 10-08 ~ 10-20 |
```

- 标题做成指向 `target_url` 的链接（是完整地址，可直接用）
- `category` 为 null 时写 `category_code_raw` 的原值，**不要猜它是什么**
- `is_important` 为真 → 标题**前**加 `⭐ `（一个星号 + 一个空格），
  **不要写「（重要）」**。链接外面加，形如 `⭐ [标题](短链)`
- **逾期的排最前**，并在表格前说明有几条逾期（看 `meta.overdue`）
- `meta.total` 是真实总数，可以说「共 N 条待办，这是第 1 页 10 条」

### 培训项目列表怎么展示（`list_my_trainings` 的结果）

**一张 Markdown 表格，不要别的。** 列固定为这四列，顺序不变：

```markdown
| 培训项目 | 进度 | 任务 | 结束时间 |
|---|---|---|---|
| ⭐ [新员工入职培训](https://…) | 44% | 11/25 | 2026-08-07 |
| [销售技能提升营](https://…) | 33% | 1/3 | 2027-01-09 |
| ⭐ [管理者领导力项目](https://…) | 0% | 0/5 | — |
| [客服带教项目](https://…) | 0% | 0/2（任务） | 2024-12-13 |
```

填表规则：

| 列 | 取值 | 没有时 |
|---|---|---|
| 培训项目 | `[name](url)` | `url` 为 null 就只写 `name`，**不要编链接** |
| 进度 | `progress_percent` + `%` | 写 `0%` |
| 任务 | `progress_basis` 的 `done/total`（与「进度」**同一个**分子分母，见下） | `progress_basis` 为 null 写 `—` |
| 结束时间 | `end_time` 的**日期部分**（`2026-08-07`） | 写 `—` |

⚠️ **「任务」列必须用 `progress_basis`，绝不能用 `task_done`/`task_total`。** 后者永远只统计
**必修**任务，项目完成标准不是「完成全部必修任务」时两者会对不上——例如某全选修项目
`task_total=0`（必修为 0 个），但平台页面写「0/2 个任务」，`progress_basis` 才是
`{done:0, total:2, unit:"任务"}`；用 `task_total` 就会答成「0/0」。
`progress_basis.unit` 不是「必修任务」时（如「学分」「阶段」），
在数字后加括号注明，如 `0/5（学分）`；是「必修任务」时按惯例不用特别标注。

⚠️ **不要自己分组、不要加小标题。** 平台按创建时间倒序返回，**照原顺序列**。
把「已结束」「进度落后」「快到期」拆成几段小标题会让一屏放不下，用户反而
找不到东西 —— 一张表从头看到尾最快。

⚠️ **不要写数据里没有的判断。** 比如「建议确认是否需要收尾」「进度落后较多」
都是你替用户下的结论，不是平台给的。要提醒只能提一句客观事实，例如
表格下面加一行：「其中 3 个的结束日期已过，但状态仍是进行中。」

需要标注时**写进项目名那一格**，不要另起一段：

- `is_important` 为真 → 名字**前**加 `⭐ `（一个星号 + 一个空格），
  **不要写「（重要）」**。链接外面加，形如 `⭐ [名字](url)`。
  前缀能让所有重要项的标记在同一列左对齐，扫一眼就知道是哪几条；
  跟在名字后面会随名字长短参差不齐。
- `is_collection` 为真 → 名字后加 `（项目集）`，并说明它是装项目的容器
  （只在显式传 `collection=True` 时会出现在 `trainings` 里，见下）
- `status` 与请求的状态不一致时（比如查进行中却返回已归档）→ 加 `（已归档）`

### 项目集（`data.collections`）—— 不要漏掉这部分

`collection` 参数没有显式传 `True` 时，`data.collections` 是**同一个 status 下的
项目集**，平台「我的培训」同一页签里会看到，但本来就不在 `trainings` 表格里
（项目集没有进度概念，混进同一张表会让"进度/任务"两列失去意义）。

⚠️ **回答「我有哪些培训」时，`collections` 非空就必须提一句**，否则平台上看得到的
项目，用户问了却得不到。不需要展开成完整表格，紧跟在主表格后面补一段即可：

```markdown
另外还有 N 个项目集（不计进度）：[年度重点项目集](url)、[新员工项目集](url)……
```

- `collections` 为空数组：这个 status 下确实没有项目集，不用提这段。
- `collections` 为 `null`：本次调用本身就是在查项目集（`collection=True`），
  `trainings` 已经是项目集列表了，不要再找 `collections`。

其他约定：

- `progress_percent` **已经是百分数**（44.0 就是 44%），不要再乘 100
- `task_done` / `task_total` 永远只统计**必修**任务，**不是**「任务」列该用的字段（见上，
  那里用 `progress_basis`）——只有完成标准正好是「完成全部必修任务」时两者才凑巧相等。
  它仅作旁证：单独确认「必修任务做完没有」时才用，不含选修，别说成「全部任务」
- `cover_url` 是封面图，**纯文字回答里不要放**（贴一堆图会把回答撑爆）
- 表格前最多一句话交代范围，例如「进行中的培训，第 1 页 16 条：」

### 「我一共在几个培训项目里」：翻完再数

`list_my_trainings` 一次调用只给一页，**返回里没有总数**。所以：

- 用户只问「我有哪些培训」→ 列这一页，说「这是进行中的前 N 个」；
  `meta.maybe_more` 为真时补一句「后面可能还有」。
- 用户**明确要总数**（「我一共在几个培训项目里」「全部有几个」）→ 用同一个 `status`
  把 `offset` 往后翻，**翻到返回不足一页为止**，各页条数加起来就是真实总数，
  可以直接说「你一共有 N 个培训项目」。同时说清口径：默认 `status="ongoing"` 是
  进行中的；问「一共参加过几个」就用 `status="all"`。项目集（`collections`）另算，
  有的话单独说一句。
- 没翻到底就停了 → 只能说「目前看到 N 个，还没翻完」，**不要**把它说成总数。
- ❌ 不要拿 `list_my_study_todo` 的 `meta.total`、考试条数或别的工具的数字
  当培训项目总数 —— 那是另外的东西。

`meta.maybe_more` 为真只说明**这一页装满了、后面可能还有**，这是推断不是事实。

### 关于「查不到」的三条硬规矩

**① 只说你这次真做过的事。**
不要说「我又重试了一次」「我换了个方式查」，除非你真的又调了一次工具。
说了没做的动作，用户会以为已经排除过，实际没有。

**② 限制要按**本次调用**说，不要套用。**
工具返回里带 `not_available` 的，才是这次调用确实拿不到的字段，照它说。
**没调过的工具，不要替它声明有什么限制** —— 比如没查考试就不要说
「考试接口不返回剩余次数」，那是另一次调用的事。

**③ 不要拿 A 的结果代表 B。**
`list_my_trainings` 查培训项目、`list_my_study_todo` 查待办中心、
`list_my_exams` 查考试 —— **三个来源互不重合**，任一个返回空都**不等于**
另外两个也空。要分别调、分别说。

### 已知限制（照实说，不要编）

| 用户可能会问 | 现状 | 你该怎么回答 |
|---|---|---|
| 我的导师是谁 | `data.mentors` 是数组，每项有 `name` | 为空数组时说「这个项目没有给你配导师」，**不要**从任务里推断导师是谁；非空时报 `name`，缺字段时用 `raw` 里能认出的信息 |

考试相关的限制以 `list_my_exams` 返回的 `not_available` 为准，不要预先声明。
出师状态（是否已出师）可以答 —— 它来自项目统计，`data.graduation_status` 直接给出中文结论；
遇到「未知状态」原样转述，不要编一个听着像的说法。

## 错误处理

按 `xuanxing-shared` 的错误码表。特别注意：

- `list_my_mentor_tasks` 返回 `NOT_FOUND`：多半是 `project_id` 取错了，
  回到第 1 步重新确认项目，不要反复重试。
- 该项目没有带教任务时返回空列表，这是正常的 —— 说「这个项目下导师没有安排
  带教任务」，**不要说查询失败**。
