# 信息展示规范

## crud_get_yidea_table_def — 表单定义展示

用 Markdown 表格展示字段列表，格式：

| # | 字段名称 | 模型名 (model) | 类型 | 必填 | i18n/Options/备注 |

- 子表单独立成表，标题 `### 【子表单：名称】(ID: xxx)`
- 多选字段在必填列标注 `(可多选)`

## crud_yidea_table_search — 查询结果展示

根据记录数量选择模式：

- **≤ 3 条 → 卡片模式**：每条独立区块，含头部（`## 📄 SN: [serialNo]`）、主表概要行（流水号、名称、创建时间、状态）、子表 Markdown 表格
- **> 3 条 → 简表模式**：统一表格，列：`# | 订单号/流水号 | 名称 | 关键信息 | 状态`，不展开子表

卡片间用 `---` 分隔，记录数 > 3 时先在开头显示 `total` 总数。

## crud_yidea_table_add / crud_yidea_table_update / crud_yidea_table_delete — 增改删结果展示

操作成功后的返回值 `data` 字段**必须完整展示给客户**，不得只报"提交成功"而遗漏 `data` 信息。

### 示例（新增 AI采购申请）

```json
{
  "isSuccess": true,
  "message": "提交成功",
  "data": "单号为： SQ20260629016"
}
```

展示给客户的信息应包含：

> ✅ **AI采购申请提交成功！**
> **申请单号：SQ20260629016**

| 返回字段 | 展示方式 |
|:---|:---|
| `isSuccess` | ✅ 标记操作成功 |
| `message` | 提示语，如"提交成功" |
| `data` | **核心信息，必须原样展示**，如"单号为：XXX" |

### 📌 行为规则

1. `data` 字段禁止过滤或简化，**必须完整呈现给客户**
2. 即使 `message` 仅告知"提交成功"，`data` 中可能包含系统自动生成的编号（如单号、流水号、ID 等），客户需要它进行后续查询或关联操作
3. 在展示时，推荐以 `✅ **操作成功！**` 开头，再以原文或结构化方式展示 `data` 内容
4. 若 `data` 包含单号信息，应额外在摘要中高亮单号（如加粗或独立一行），方便客户识别
