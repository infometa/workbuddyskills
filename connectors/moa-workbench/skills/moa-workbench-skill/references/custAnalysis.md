# 客户分析场景

用于销售在跟进前/中分析目标客户：读取**口袋资料**（客户属性、标签及其变更时间、跟进记录、商机/订单/合同/回款、回访提醒）并结合**用户指定的微信聊天等外部信息**，形成有证据的**客户画像、成交阻力与下一步建议**；用户确认后**创建一条跟进记录**并**设置回访提醒**，创建人取当前口袋授权账号。

## 场景工具

参数结构以工具 schema 为准，本文档不写死字段。

| 工具 | 用途 |
|---|---|
| searchCustomer | 按客户名称或联系人（姓名/手机号/微信）搜索客户并返回客户资料/联系人/跟进人/标签（含选中与变更时间）/自定义属性 |
| getCustomerFollowRecords | 按客户 ID 查跟进记录（沟通/通话+外勤两类合并，时间倒序，支持按跟进记录时间范围过滤） |
| getCustomerSalesChances | 按客户 ID 查商机列表（阶段历史/金额/跟进人/赢单输单状态） |
| getCustomerOrders | 按客户 ID 查销售订单列表（状态/金额/回款退款汇总，权限范围内） |
| getOrderReceivePayments | 按订单 ID 查回款与退款明细列表（金额/回款方式/状态/退款原因/图片附件） |
| getOrderContracts | 按订单 ID 查合同列表（标题/编号/起止时间/自定义属性/图片附件） |
| getCustomerReminds | 按客户 ID 查回访提醒（未完成/已失效两组，未完成含逾期标记） |
| createCustomerFollowRecord | 创建客户跟进记录（会话沟通），创建人自动为当前登录账号（需【创建跟进记录】权限） |
| createRemind | 创建回访提醒（关联客户，指定提醒时间与重复规则） |
| whoami | 查询当前登录用户的简要信息（pid/did/姓名），用于确认当前登录身份 |

## 工作流

### 1. 确认身份与定位客户

先调用 whoami 确认当前授权账号（后续写入的创建人即该账号，不得冒用客户原跟进人），再调用 searchCustomer 定位客户：

- name 与联系人条件（contactName/mobile/wechat）至少提供一个，且联系人条件至多提供一个（底层同为联系人搜索字段）。
- 最多返回前 100 条，无分页；**命中多条时必须向用户展示候选并确认唯一客户后再继续**。
- 返回的 labels 为已选中标签树（最多三层），各层含 on（选中）与 updateTime（标签变更时间，GMT 毫秒，0/缺失表示未知），用于判断客户关注点的变化时间。
- 用户可能提供该客户的微信聊天记录等**外部信息**：接收后与口袋数据一并纳入分析，但外部信息仅用于分析整合，不作为口袋写入内容的出处依据。

### 2. 查询客户全景并汇报

定位到唯一客户后，按用户关注的分析目标与时间范围调用对应查询工具（均传 custmid）：

- **getCustomerFollowRecords**：返回该客户跟进记录（沟通/通话记录与外勤记录两类合并，时间倒序，合计取前 9999 条）；支持 timeStart/timeEnd（GMT 毫秒时间戳）按跟进记录时间范围过滤，不传则不限；source=talk 
  为沟通/通话记录，crdid 非零为电销通话记录（含通话状态/方向与内容，关联商机见 scid），source=legwork 为外勤记录（含签到/签退位置与目标地址距离）；跟进内容在 content（纯语音外勤为占位文本）；图片在 pictures、附件在 atts、语音在 
  voices（均带下载链接，获取失败时为空不影响主体数据）；自定义表单在 forms（value 已解析，选项类已映射为选项文本；值为空的表单项整项不返回）。
- **getCustomerSalesChances**：返回该客户全部商机（内部自动分批拉全）；列表含当前阶段编号与阶段历史（名称/占比/进出时间）；阶段 5=赢单、6=输单，其余为自定义阶段（名称见 stepInfos）。
- **getCustomerOrders**：返回该客户全部订单（内部自动分批拉全）；订单状态含语义描述（statusDesc）；回款/退款为汇总金额与笔数；商品明细在 products；订单属性在 myProps（value 已解析为可读值）；附件在 atts（带下载链接）。
- **getOrderReceivePayments**：关注回款/退款明细时先用 getCustomerOrders 拿到订单再按 orderId 查（orderId 取自 getCustomerOrders 返回，不要臆造）；返回该订单全部回款与退款（内部自动分批拉全）；状态含语义描述（statusDesc：待确认/已确认/已驳回/已作废/未设置审批人）。
- **getOrderContracts**：关注合同信息时按 orderId 查；返回该订单全部合同（create_time 倒序）；开启的自定义属性在 properties（value 已解析为可读值）。
- **getCustomerReminds**：返回该客户全部提醒（内部自动分批拉全）；reminds 为未完成提醒（overdue=true 表示已逾期），invalidReminds 为已失效提醒。
- 客户 ID（custmid）与订单 ID（orderId）一律取自工具返回，不要臆造；无数据时返回空列表属正常。
- 汇报内容根据用户关注点裁剪，不要把全部字段罗列给用户。

### 3. 生成分析（画像、阻力与建议）

基于上述数据与外部信息，按以下口径输出分析结论，**每条结论必须给出证据**（引用跟进记录/表单/聊天原文要点及时间；标签类证据可用标签名称与 updateTime）：

- **客户画像**：只包含有记录或原文支持的**需求、关注点、决策因素**；无证据的内容不要写入画像。
- **成交阻力**：至少对应一条证据；无证据的阻力只能标为"待验证假设"，不得作为结论陈述。
- **下一步建议**：每条建议必须对应一个阻力，并明确**沟通主题、材料、渠道、时间**。

输出后请用户确认或调整；分析结论以用户最终确认为准。

### 4. 写入跟进记录（经确认）

调用 createCustomerFollowRecord：

- 入参：customerId（取自 searchCustomer 返回，不要臆造）、content（用户确认的分析结论文本）。
- 工具会回传 tkid（跟进记录 ID）与 publishTime（发布时间，GMT 毫秒）：**发布时间为服务端当前时间，不可自定义**；创建人自动为当前登录账号（不可指定他人）。
- 写入前先与用户确认写入内容原文。

### 5. 创建回访提醒（经确认）

调用 createRemind：

- 关联 customerIds（取自 searchCustomer 返回的 custmid，不要臆造）；awokePids/awokeGids 不指定时默认提醒当前登录用户。
- 创建前先查 getCustomerReminds，避免与既有未完成提醒重复；提醒内容、提醒时间（remindTime，GMT 毫秒时间戳）必须来自用户；重复规则未指定时默认"不重复"（repeatType=1）。
- 成功响应含提醒 id 与 nextScheduleTime，单独回报给用户。

## 常见异常

| 现象 | 处理方式 |
|---|---|
| 401 / 未授权 | 提示用户重新发起扫码授权（AGENT 会自动打开授权页） |
| 搜索命中多条客户 | 展示候选列表让用户确认唯一客户，不要自行猜测 |
| 创建跟进记录报错 | 核对 customerId 是否为搜索返回的真实客户；content 不得为空 |
| 创建跟进记录报权限错误 | 需【创建跟进记录】权限，提示用户联系管理员在权限组中分配 |

## 注意事项

- 一切客户 ID（custmid）来自工具返回，不要臆造。
- 标签变更时间 updateTime 为 0（返回中缺失）表示该标签从未记录过变更时间（历史数据），不要臆断为"最近变更为 0 点"。
- 写入操作（创建跟进记录、创建提醒）必须先经用户确认，不得擅自写入。
