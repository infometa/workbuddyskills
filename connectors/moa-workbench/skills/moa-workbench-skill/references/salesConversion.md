# 销售转化场景

用于销售经理查看某员工在指定时间段内的完整销售转化漏斗：先拉取该时间段内**被分配的客户列表**，再按用户确认的维度（跟进阶段/客户标签/商机阶段）分组统计，得到各阶段的客户数量和转化率，识别转化瓶颈并给出改进建议。

典型问题示例：
- "看招生老师小王本月的完整转化：分配线索、实际联系、加微信、邀约、到店、报名各有多少？"
- "查看销售团队上个月新分配客户的转化情况"

## 场景工具

参数结构以工具 schema 为准，本文档不写死字段。

| 工具 | 用途 |
|---|---|
| whoami | 查询当前登录用户的简要信息（pid/did/姓名），用于确认当前登录身份 |
| findPersons / getAllPerson | 按姓名批量查找成员 / 获取部门（含子部门）或全公司成员，解析员工范围 |
| getCustomerFollowLevel | 获取公司配置的跟进阶段列表（过程阶段/结果阶段/售后阶段） |
| getCustomerLabels | 获取公司配置的客户标签树（多级标签） |
| getAssignedCustomerList | 按分配时间范围获取客户列表（含跟进阶段、标签、分配时间、成交状态），一次返回全部结果 |
| getCustomerFollowRecords | 按客户 ID 查跟进记录（支持时间范围过滤），用于瓶颈阶段下钻分析 |
| getCustomerSalesChances | 按客户 ID 查商机列表（阶段历史/金额/跟进人/赢单输单状态） |
| getCustomerOrders | 按客户 ID 查销售订单列表（状态/金额/回款退款汇总，权限范围内） |
| getOrderReceivePayments | 按订单 ID 查回款与退款明细列表，辅助分析 |

## 工作流

### 1. 确认身份与选择员工

先调用 whoami 确认当前授权账号：

- 用户指定了员工姓名时，用 findPersons 解析为 pid（followerPids）；用户指定部门/团队时，用 getAllPerson 解析成员范围。
- 用户未指定员工时，默认当前用户（用 whoami 返回的 pid）。

### 2. 确认漏斗指标维度（必须询问用户）

用户提到的阶段名称（如"加微信""邀约""到店"）可能来自不同维度，无法自动判断时，**必须向用户确认**按哪个维度计算漏斗。先调用 getCustomerFollowLevel 与 getCustomerLabels 获取公司配置：

| 维度 | 数据来源 | 适用场景 |
|---|---|---|
| 客户跟进阶段 | 客户的 followLevel 字段 | 用户提到的阶段名与公司配置的跟进阶段一致（如"初步沟通""方案报价""赢单"） |
| 客户标签（某个一级标签） | 客户的 labels 字段中某个一级标签下的值 | 用户提到的阶段名是公司配置的某个标签值（如"加微信""邀约""到店""报名"） |
| 客户商机阶段 | 逐客户调用 getCustomerSalesChances 取当前阶段 scstep | 用户提到的阶段名与商机阶段一致 |

确认流程：
1. 先调用上述两工具获取公司配置；
2. 将配置展示给用户，询问："您提到的阶段对应的是哪个维度？"（标签维度需让用户选择按哪个一级标签分组）；
3. 用户确认后，记住分组维度，进入下一步。

### 3. 拉取分配客户列表

调用 getAssignedCustomerList：

- 入参：obtainTimeStart/obtainTimeEnd（用户指定的时间范围，GMT 毫秒时间戳，左闭右开）、followerPids（步骤 1 解析）、size/skip（分页，默认 50，上限 200）。
- **循环拉取**：若 ended=false，用 skip 续拉，直到 ended=true，否则统计不完整。
- 返回的每条客户含 followLevel、labels、obtainTime、transStatus 等字段。
- **若维度为商机阶段**：需对每个客户调用 getCustomerSalesChances 获取当前商机阶段（注意 RPC 量 = 客户数）。

### 4. 按维度分组统计并输出漏斗

根据步骤 2 用户确认的维度，对步骤 3 的客户列表本地分组计数：

- 按跟进阶段（followLevel）分组：统计每个跟进阶段的客户数（一个客户只有一个 followLevel，不重复计数）。
- 按标签分组：统计某个一级标签下各标签值的客户数（一个客户可能有多个标签，同一客户可出现在多个值中）。
- 按商机阶段分组：统计每个商机阶段的客户数（需步骤 3 中逐客户拉取商机）。

计算转化率并输出漏斗表：

```
阶段        客户数   占分配总数   递进转化率
分配线索      50      100%        -
实际联系      42       84%        84%
加微信        30       60%        71%
邀约          18       36%        60%
到店          10       20%        56%
报名           5       10%        50%
```

- 分配总数 = 步骤 3 拉取的客户总数（分母）。
- 阶段转化率 = 该阶段客户数 / 分配总数；递进转化率 = 下一阶段客户数 / 上一阶段客户数。

### 5. 瓶颈分析与建议（可选）

- **识别瓶颈**：转化率最低或客户流失最多的阶段。
- **下钻分析**：对瓶颈阶段的客户调用 getCustomerFollowRecords（可带 timeStart/timeEnd）查看跟进记录内容，按需调用 getCustomerOrders / getCustomerSalesChances / getOrderReceivePayments 辅助分析。
- **生成建议**（引用证据）：哪个阶段流失最严重、该阶段客户的跟进记录共性（跟进间隔过长、内容空泛、缺少关键动作等）、如何改进（缩短跟进间隔、增加特定动作、调整话术等）。

## 常见异常

| 现象 | 处理方式 |
|---|---|
| 401 / 未授权 | 提示用户重新发起扫码授权（AGENT 会自动打开授权页） |
| getAssignedCustomerList 返回空列表 | 输出"该时间范围内无分配客户" |
| 阶段/标签配置为空 | 提示"公司未配置跟进阶段/标签，无法分组统计" |
| 客户的 followLevel 为空 | 该客户未设置跟进阶段，归入"未设置"分组 |
| 客户无相关标签 | 该客户无该一级标签，归入"无标签"分组 |
| 维度为商机阶段但客户无商机 | 该客户无商机，归入"无商机"分组 |

## 注意事项

- **必须先问用户确认维度**：用户提到的阶段名称可能对应跟进阶段、标签或商机阶段，无法自动判断时，必须展示配置后让用户选择，不要自行推断。
- **阶段定义因公司而异**：不同公司配置的跟进阶段和标签完全不同，不要预设阶段名称，始终以 getCustomerFollowLevel 和 getCustomerLabels 返回的配置为准。
- **无需手动分页**：getAssignedCustomerList 内部自动分批拉取，一次返回全部结果。
- **标签可多选、跟进阶段单选**：一个客户可能同时有多个标签（如"加微信"+"邀约"），按标签分组时同一客户可出现在多个值中；followLevel 同一时间只有一个，不会重复计数。
- **下钻按需调用**：getCustomerFollowRecords/getCustomerSalesChances 等按客户逐个查询，量大时 RPC 较多，仅在分析瓶颈阶段时按需调用。
