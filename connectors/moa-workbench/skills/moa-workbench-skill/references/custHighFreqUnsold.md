# 高频未成交场景

用于销售经理筛选最近 N 天内有跟进但未成交的客户，分析"投入多却没结果"的原因并给出分类建议（重点推进/调整方式/降低优先级），为每个客户写入一条分析结论作为新的跟进记录。

## 场景工具

参数结构以工具 schema 为准，本文档不写死字段。

| 工具 | 用途 |
|---|---|
| whoami | 查询当前登录用户的简要信息（pid/did/姓名），用于确认当前登录身份 |
| findPersons / getAllPerson | 按姓名批量查找成员 / 获取部门（含子部门）或全公司成员，解析员工范围 |
| getLfCustomerList | 按最后跟进时间获取客户列表，支持多条件过滤，一次返回全部符合条件的客户 |
| getCustomersByIds | 批量获取客户详情（标签/成交状态等），用于写入前校验客户存在性 |
| getCustomerFollowRecords | 按客户 ID 查跟进记录（支持时间范围过滤），用于统计每个客户的跟进次数 |
| getCustomerOrders | 按客户 ID 查销售订单列表，确认是否成交（status=2/8） |
| getCustomerSalesChances | 按客户 ID 查商机列表，分析商机阶段 |
| getOrderReceivePayments | 按订单 ID 查回款与退款明细，辅助分析 |
| getOrderContracts | 按订单 ID 查合同列表，辅助分析 |
| batchCreateCustomerFollowRecords | 批量创建客户跟进记录（全部成功或全部失败；需【创建跟进记录】权限） |

## 工作流

### 1. 确认身份与解析范围

先调用 whoami 确认当前授权账号：

- 用户指定了员工姓名时，用 findPersons 解析为 pid（followerPids）；用户指定部门/团队时，用 getAllPerson 解析成员范围。
- 用户未指定范围时，默认当前用户（用 whoami 返回的 pid）。

### 2. 获取未成交客户列表

调用 getLfCustomerList：

- 入参：followerPids/followerGids（步骤 1 解析）、lftimeStart（近 N 天起始时间戳，N 由用户指定）、transStatus=1（未成交）。
- 工具内部自动分批拉取，一次返回全部结果，无需手动翻页。
- 返回空列表时，输出“该范围/时间窗内无符合条件的客户”。

### 3. 逐客户统计跟进次数并筛选高频

对步骤 2 返回的每个客户调用 getCustomerFollowRecords（入参 customerId、timeStart 近 N 天起始时间戳）：

- **统计跟进次数**：返回的 records 数组长度即为跟进次数。
- **筛选**：跟进次数 ≥ 用户阈值（如 5 次）的客户；用户未指定阈值时先询问。

### 4. 分析原因并生成建议

- **按需调用辅助分析**（仅在证据不足时）：getCustomerOrders（按客户）确认订单状态；getCustomerSalesChances（按客户）分析商机阶段；getOrderReceivePayments（按订单）分析回款情况；getOrderContracts（按订单）分析合同状态。
- **分类建议口径**（每条建议必须引用具体跟进记录作为证据，含时间+对象+内容摘要）：
  - **重点推进**：有明确需求、方案已报价、阶段为"方案报价"或"合同谈判"、近期有跟进计划；
  - **调整方式**：跟进内容空泛（"已联系""继续跟进"）、无明确需求、阶段停滞（如 30 天仍在"初步接触"）；
  - **降低优先级**：多次联系无响应（如 5 次以上无内容记录）、客户明确拒绝、阶段为"初步接触"但时间跨度 >60 天。
- **证据不足处理**：若跟进记录内容空泛，输出"证据不足，建议补充跟进内容后再分析"，不可臆断。

### 5. 批量写入分析结论（经确认）

调用 batchCreateCustomerFollowRecords：

- 写入前先与用户确认写入内容原文。
- 入参：records: [{customerId, content}, ...]（每个高频未成交客户一条，customerId 取自步骤 2/3 返回，不要臆造）。
- **全部成功或全部失败**：服务端批量接口不支持部分成功；若某个客户无效（已删除/无权限），整个请求失败。
- **前置校验**：调用前用 getCustomersByIds 确认客户存在性，过滤无效客户。
- **失败处理**：若返回错误，输出错误信息，建议用户检查客户状态后重试。

## 关键口径

### 筛选口径

- **最后跟进时间**：lftimeStart/lftimeEnd 过滤，精确到毫秒。
- **成交状态**：transStatus 过滤，1=未成交，2=已成交（含成交 1 单和多单）。
- **跟进人**：followerPids/followerGids 过滤，支持按部门递归展开。

### 成交口径

- **有效成交订单**：status=2（ORDER_CONFIRMED）或 status=8（ORDER_HAVE_BEEN_OUTSTORAGE）。
- **未成交**：无订单 或 所有订单 status 非 2/8（含 status=1 待确认、3 已拒绝、4 已取消等）。

## 常见异常

| 现象 | 处理方式 |
|---|---|
| 401 / 未授权 | 提示用户重新发起扫码授权（AGENT 会自动打开授权页） |
| getLfCustomerList 返回空列表 | 输出"该范围/时间窗内无符合条件的客户" |
| getCustomerOrders 返回空 | 视为"未成交"（无订单） |
| batchCreateCustomerFollowRecords 失败 | 输出错误信息，建议检查客户状态后重试 |
| 批量写入报权限错误 | 需【创建跟进记录】权限，提示用户联系管理员在权限组中分配 |

## 注意事项

- **批量写入不支持部分成功**：若某个客户无效（已删除/无权限），整个请求失败。写入前需前置校验客户存在性。
- **合同/回款 RPC 量大**：按订单逐次查询，50 客户 × 3 订单 = 150 次 RPC。按需调用，非必须全量拉取。
- **证据引用必须具体**：每条建议必须引用具体跟进记录（时间+对象+内容摘要），不可泛泛而谈。
- **证据不足时降级**：若跟进记录内容空泛，输出"证据不足，建议补充跟进内容后再分析"，不可臆断。
- **写入操作必须先经用户确认**，不得擅自写入。
