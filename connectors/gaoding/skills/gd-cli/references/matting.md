# 抠图与透明结果

抠图前先区分“保留原图可见像素”与“重新绘制完整主体”。白底图、带棋盘格的图片和真正有透明通道的文件是不同交付物。

## 选择处理方式

| 用户目标 | 处理流程 | 交付边界 |
| --- | --- | --- |
| 主体完整，只去背景；保留商品结构、文字、人脸或纹理 | 标准抠图：从原图分离前景，保留可见主体 | 不补出原图看不到的部位；细边、毛发、半透明材质和遮挡需复查 |
| 提取被遮挡的物品，并补全被挡部分；从复杂画面中重新呈现指定主体 | 用户允许重建时，先用参考图重绘主体，再对重绘图做标准抠图 | 补全内容是生成推测，可能改变结构和纹理；不能称为原物的精确恢复 |

仅有背景复杂并不等于必须重绘。用户要求保真、不能重绘时，优先标准抠图；效果不足就说明限制或请求更完整的原图，不能自行改为 AI 重建。用户明确要补全被挡主体时，可按其要求执行重建。

## 发现能力与执行

1. 按 [创作](creation.md) 发现当前 Tool 和 Model，读取相关 `--help`、公开 Schema 和选定 Model detail。确认该能力交付透明图，还是只交付中间重绘图；模型标题中的“抠图”不能替代输出契约。模型、参数与费用以当前地区和组织的查询结果为准。
2. 标准抠图与已包含重绘/分割的智能抠图都可作为原子 [Tool](tool.md)；用户需要业务规划、多步骤编排或多产物时再选 [Agent](agent.md)。有 mask 时先按 [选区复核](media-tools.md#提交前复核-mask) 查看原图、mask 及叠加预览。不能把未公开的算法接口、编辑器入口或历史测试套件名称当成 CLI Model。
3. 输入必须使用本次指定的原图。AI 重建时明确主体、需要补全部位、必须保留的结构与比例；若选定的智能抠图已承诺交付透明 PNG，直接验收最终文件，避免再调用一次标准抠图。仅在模型只交付重绘图时才另做分割。不要继续对原始遮挡图做第二步，也不要使用上一次结果的尺寸代替当前图片尺寸。
4. 当前 CLI 没有可发现的透明抠图能力时，明确说明缺口。不要用“生成透明背景”的提示词、白底图或棋盘格图替代用户要求，也不要调用内部接口绕过产品权益结算。已完成的重绘图可作为中间产物交付，但必须说明透明步骤未完成。

重建提示词的结构可以是：“以参考图中的〔指定主体〕为依据，补全〔被遮挡部位〕，保持〔可见结构、纹理、比例〕。主体完整、边缘清楚，置于易分离的纯色背景，不画棋盘格、不添加文字或其他物品。”具体约束来自用户；提示词本身不会产生真正的 alpha 通道。

## 验收与交付

- 由调用 Agent 或用户下载实际输出，查看真实格式、尺寸和透明区域；扩展名、MIME 声明和模型文字说明不能证明抠图效果。透明背景与有效主体都要结合画面判断，不能只检查“存在 alpha”。alpha 最大值不必等于 255；毛发、玻璃和阴影可合理半透明，不按最大值设通过阈值或自动拉满透明度。
- 在明暗两种底色上检查边缘、孔洞、毛发与半透明区域，确认没有烘焙棋盘格、明显背景残留或误删主体。保持原尺寸或裁到主体边缘按用户要求处理。
- AI 重建另外对比商品结构、标识、人物身份和可见细节；说明哪些部位是生成补全，不能承诺像素级一致。
- 使用结果文件或已授权下载链接交付。只完成重绘或拿到蒙版时，不宣布透明抠图完成；保留可用中间结果和未完成步骤。
- 多阶段生成按各次真实用量解释费用，估算不当实扣。任务已受理后中断、超时或后处理失败时，先按 [错误处理](errors.md) 查询原任务，不能为拿到透明图而盲目重做已完成的收费生成。
