# reference/markdown.md —— Markdown 文字版报告的单一来源

## 一、定位与边界

- 本文件只管 **md 文字版怎么写**；html 版的工程约束见 `reference/html.md`（本 skill 自包含）。

## 二、数据-SQL 一一对应规范（重要）

每段数据紧跟其对应的 SQL：md 版用 `<details>` 折叠块承载 SQL；正文引用数据时标注来源编号
`[📊 SQL-N]`，使每个数字都可溯源。这是报告可信度的核心，**不要**把所有 SQL 集中堆在文末附录。

## 三、标准模板（按骨架填入，用用户的原始语言）

```markdown

> 仅 `full` 形态出本节；`lite` 跳过。结论先行（BLUF），3~5 条要点，让读者 30 秒抓住全局。

- **关键发现**：{2~3 条最重要的发现，每条 1 句 + 数据引用 [📊 SQL-N]}

## 四、写作要求

- **摘要前置（仅 full）**：`full` 报告**必须**以「## 0. 摘要」开篇——结论先行，3~5 条要点浓缩核心结论 + 首要建议，每条带 `[📊 SQL-N]`。它是末尾「## 5. 结论与建议」的前置精简版，**不替代**末尾完整版；两处结论/建议必须一致、不打架。`lite`/`chart`/`dashboard` 不出本节。
- **结论先行**：每个发现先给一句话结论，再用数据支撑。
- **数字可溯源**：正文每个关键数字都带 `[📊 SQL-N]`，对应一个 `<details>` SQL 折叠块。
- **多角度**：每个发现至少 2~3 个分析角度（量级 / 占比 / 趋势 / 对比 / 异常），不要只复述单个数字。
- **页脚联动**：结尾必须带 html 报告路径与"按 SQL 编号迭代 / 按章节修改 / 导出 PDF"三条引导。
- **语言**：跟随用户的原始提问语言；不要把"{...}"占位符遗留到产物里。

## 五、与现状的一致性（回归基线）

若有场景特有的小节 （如"异常清单"、"预测区间"），在「## 4. 详细分析」下增设子节即可， 不改动整体骨架。
