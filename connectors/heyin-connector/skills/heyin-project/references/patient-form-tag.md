# 研究参与者表单标记使用说明

本说明处理已实例化 EDC 数据的六类状态标记，并说明研究者数据签名状态的读取。请求可以按研究参与者、事件、表单或字段选择作用范围；上级范围会向下覆盖其包含的数据，但平台仍按每个对象的现状决定实际更新、部分更新或跳过。

## 功能总览

| 标记 | 可用范围 | 主要限制 |
| --- | --- | --- |
| 数据锁定 | 研究参与者、事件、表单 | 加锁只处理已提交表单；未关闭质疑会阻止相应层级完全锁定 |
| 数据冻结 | 研究参与者、事件、表单、字段 | 加冻结只处理已提交表单；已锁定表单不能冻结或取消冻结 |
| SDV | 研究参与者、事件、表单、字段 | 加标记只处理已提交表单 |
| 数据管理审核 | 研究参与者、事件、表单、字段 | 加标记只处理已提交表单 |
| 医学审核 | 研究参与者、事件、表单、字段 | 加标记只处理已提交表单 |
| 安全审核 | 研究参与者、事件、表单、字段 | 加标记只处理已提交表单 |

六类标记都可以取消；取消方向不要求表单已提交。

## 调用平台

按 [项目使用指南](../SKILL.md) 选择目标项目和角色凭证，通过 `heyincli req` 调用以下接口。参数直接放入表中指定的 `--query` 或 `--body` JSON 对象，项目由凭证确定，不传 `project_id`；请求环境由 `--test-env` 选择。

- 数据锁定与取消锁定需要 `PRJ_FORM_DATA_LOCK` 权限，并依赖 `PRJ_FORM_DATA_LOCK_ACCESS`；不支持中心级写权限。
- 数据冻结与取消冻结需要 `PRJ_FORM_DATA_FROZEN` 权限，并依赖 `PRJ_FORM_DATA_FROZEN_ACCESS`；不支持中心级写权限。
- SDV 与取消 SDV 需要 `PRJ_FORM_DATA_SDV` 或目标中心范围内的 `SITE_FORM_DATA_SDV` 权限，分别依赖 `PRJ_FORM_DATA_SDV_ACCESS` 或 `SITE_FORM_DATA_SDV_ACCESS`。
- 数据管理审核、医学审核和安全审核分别需要 `PRJ_FORM_DATA_DM_REVIEWED`、`PRJ_FORM_DATA_MM_REVIEWED`、`PRJ_FORM_DATA_SAFETY_REVIEWED` 权限，并依赖各自对应的 `*_ACCESS` 权限；这三类操作不支持中心级写权限。

## 接口一览

所有接口均为 `POST`，范围数组直接放入 `--body`。各范围数组均可省略，但每次请求至少一个非空；数组中的 ID 必须是正整数且不重复。

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 标记数据锁定 | `POST` | `/api/project/patient/tag_data_lock/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids` |
| 取消数据锁定 | `POST` | `/api/project/patient/untag_data_lock/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids` |
| 标记数据冻结 | `POST` | `/api/project/patient/tag_frozen/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 取消数据冻结 | `POST` | `/api/project/patient/untag_frozen/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 标记 SDV | `POST` | `/api/project/patient/tag_sdv/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 取消 SDV | `POST` | `/api/project/patient/untag_sdv/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 标记数据管理审核 | `POST` | `/api/project/patient/tag_dm_reviewed/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 取消数据管理审核 | `POST` | `/api/project/patient/untag_dm_reviewed/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 标记医学审核 | `POST` | `/api/project/patient/tag_mm_reviewed/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 取消医学审核 | `POST` | `/api/project/patient/untag_mm_reviewed/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 标记安全审核 | `POST` | `/api/project/patient/tag_safety_reviewed/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |
| 取消安全审核 | `POST` | `/api/project/patient/untag_safety_reviewed/` | `--body`：`patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` |

不同层级数组可以组合，但只有在每组 ID 都已通过当前项目的最新读取结果独立解析、且对象归属关系清楚时才可组合。若同一对象同时被上级和下级范围覆盖，先去除不必要的重叠目标，避免影响说明和写后核验重复计数。

## 共同写入语义

- 所有目标必须属于当前项目、当前环境和当前角色可写的中心范围。目标跨项目、跨生产与测试环境、不可写或不存在时，平台会拒绝请求；不能删减失败目标后自动重试。
- 标记操作会写入状态，并同步记录操作者和操作时间；取消标记会清除相应操作者和时间。审核人信息属于敏感投影，默认只反馈状态和必要的业务对象名称。
- 数据锁定以外的五类“加标记”只处理所属表单 `is_committed=true` 的数据。按事件或研究参与者下发时，已提交的下级照常处理，未提交的下级静默跳过；只因未提交而跳过的对象不会出现在部分更新或未更新结果中。
- 取消标记不受“表单必须已提交”限制，以便解除历史存量标记。
- 数据锁定只允许研究参与者、事件和表单范围，不接受字段 ID。
- 上级聚合状态来自下级数据的派生计算，可能异步刷新。写接口成功不表示聚合值已立即稳定，必须回读实际状态。

## 数据锁定与冻结限制

数据锁定只锁已提交表单。按事件或研究参与者锁定时：

- 其下存在未提交表单时，该事件或研究参与者自身不会被锁定，但符合条件的已提交下级仍可能被锁定。
- 存在未关闭质疑时，相应层级可能部分锁定或完全不锁定；平台会在 `partial_update_data` 或 `not_update_data` 中列出可识别的参与者编号、事件名称或表单路径。
- 只因未提交表单导致的跳过不会进入上述两个结果，因此不能把空结果解释为所有目标均已锁定。

冻结与锁定互斥：已锁定表单内的数据不能新增冻结，也不能取消冻结。按上级范围操作时，已锁定的下级会产生部分更新或未更新结果。数据锁定不阻止 SDV、数据管理审核、医学审核或安全审核；不要因表单已锁定而跳过这些审核类操作。

## 返回内容

| 操作 | 业务返回内容 |
| --- | --- |
| 数据锁定、取消数据锁定、数据冻结、取消数据冻结 | `partial_update_data` 与 `not_update_data`；可包含 `patient_list`、`event_data_list`、`form_data_list` |
| SDV、数据管理审核、医学审核、安全审核及其取消操作 | 无，输出 `null` |

两个结果字段及其下的列表均为可选，列表项是用于说明范围的字符串，不是对象 ID 结构。字段缺失时保留缺失语义。

`partial_update_data` 表示所选上级范围内只有部分合规下级完成更新；`not_update_data` 表示相应对象未完成更新。它们不包含只因表单未提交而静默跳过的目标，也不是完整的逐字段变更清单。对无业务返回的接口更不能仅凭成功响应推断所有目标均已改变。

## 项目与中心状态写入限制

数据锁定标记只作用于表单、事件或参与者数据，与项目和中心的生命周期 `LOCKED` 是两层不同的状态。平台对所有研究参与者数据写入执行同一组状态校验，覆盖本说明的加标记和取消标记、研究者数据签名、表单录入与提交，以及质疑的创建、回复、取消、关闭和重开。目标涉及的任一参与者、中心或项目不满足以下条件时，整批请求失败：

| 层级 | 拒绝写入的状态 | 平台错误码 |
| --- | --- | --- |
| 项目 | 已禁用；已锁定（`LOCKED`）；已结束（`TERMINATED`）；已暂停（`SUSPENDED`）；生产环境在项目准备中（`IN_PREPARATION`） | `4004010001`、`4004010005`、`4004010006`、`4004010007`、`4004010002` |
| 中心 | 已禁用；已锁定（`LOCKED`）；已暂停（`SUSPENDED`）；已关闭（`CLOSED`） | `4004020002`、`4004020003`、`4004020004`、`4004020189` |
| 研究参与者 | 正在方案升级 | `4004020177` |

- 中心或项目锁定后，表单级解锁（取消数据锁定）、取消冻结和取消审核标记同样会被拒绝。锁库后需要更正时，必须先恢复中心或项目的可写状态：中心按 `heyin-project-settings` 的“中心设置”解锁；项目的锁定与解锁需要二次认证，只能在平台受控界面完成，CLI 不收集认证材料。更正完成后重新标记并回读，再按同样途径恢复中心或项目的锁定。
- 方案升级校验以整批为单位：批次中任一参与者正在升级，整次请求即失败，其他参与者也不会更新。需要继续处理时，先按[研究参与者方案升级](participant-upgrade.md)确认升级完成，或拆出不在升级中的参与者另行提交。
- 写前读取项目状态（[项目通用查询](common.md)）、目标中心状态与参与者升级标记。遇到上述错误码时报告实际状态和错误码，不改用其他角色、环境或目标绕过限制，也不自动发起中心或项目状态变更。

## 操作前置

执行任何标记前必须：

1. 使用已授权的研究参与者、事件、表单或字段读取能力，获取最新状态并唯一解析目标；ID 不得根据名称、排序或相邻记录猜测。
2. 按 `patient_ids`、`event_data_ids`、`form_data_ids`、`field_data_ids` 分别列出目标数量和可核对的 ID 或研究参与者编号，说明上级范围会影响其合规下级。
3. 对加标记说明未提交表单会被静默跳过；对锁定和冻结额外说明质疑、既有锁定可能导致部分或未更新；确认项目、中心和参与者满足“项目与中心状态写入限制”。
4. 取得用户对最终标记方向和完整范围的明确同意后，只发送一次写请求。查询、解释现状或核验请求不得自动升级成标记操作。

使用[参与者读取](patient-read.md)和[事件与表单读取](patient-form-read.md)核对归属与范围；无法确认时不调用写接口。

## 结果核验

写后使用[事件与表单](patient-form.md)或[参与者管理](patient-common.md)中的读取方法核验相同对象的实际锁定、冻结、SDV 或审核状态。核验上级范围时应读取足够的下级状态，区分：

- 已更新：目标和需要核验的下级均显示预期状态。
- 部分更新：响应或回读显示只有部分下级改变。
- 未更新：响应明确列出，或回读仍为原状态。
- 无法确认：未授权对应读取能力、派生状态尚未刷新、响应缺失或回读失败。

请求成功但未完成回读时，只报告“请求已受理，结果尚未核验”。不要把 `partial_update_data`、`not_update_data` 为空，或无业务返回，写成“全部成功”。

多个对象发生变化时使用 Markdown 批量变更表格。第一列固定为“变更类型”，填写“变更”；后续列至少包含对象层级、对象 ID 或编号、标记类型和写后状态。原状态紧跟新状态并使用删除线；未核验的状态写“未知”，不补造结果。

## 研究者数据签名

研究者签名表示研究者对所签数据的确认，属于电子签名（参照 21 CFR Part 11），平台要求签名人本人输入登录密码或完成本机身份认证。签名和撤销签名都由研究者本人在平台页面完成；本技能不调用签名或撤销签名接口，不索取、传递密码。

本技能只读取签名状态：事件、表单数据返回的签名状态及签名人、时间字段可用于数据管理和监查核对锁库准备情况，按最小必要原则展示。签名只处理已提交表单，未关闭质疑可能导致部分数据未签。

## 敏感数据与失败边界

只输出完成任务所需的研究参与者编号、事件或表单名称、对象 ID 和状态。不得输出研究参与者身份信息、字段值、表单内容、账号、审核人用户名、认证材料、内部路径或无关上游数据。

平台失败、权限不足、对象不存在、目标范围不一致、结果不完整或回读不一致时，如实保留失败语义并停止。不得切换标记类型、反转标记方向、更换 ID、删除失败对象或盲目重试来制造成功。
