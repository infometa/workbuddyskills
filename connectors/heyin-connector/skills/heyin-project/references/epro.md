# 项目 ePRO 使用说明

本说明用于查询当前生产或测试环境中的 ePRO 问卷数据，回答研究参与者的计划问卷、填写状态、访视窗、提交时间和提交人摘要。它只有读取能力，不修改问卷、表单或研究参与者数据。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 分页查询问卷数据 | 按当前项目和权限范围查询问卷数据 | 否 |
| 按中心筛选 | 查询一个当前环境、当前权限范围内的中心 | 否 |
| 按研究参与者编号筛选 | 使用关键词匹配研究参与者编号 | 否 |
| 按状态筛选 | 查询未开始、进行中、已填写、逾期已填写或逾期未填写数据 | 否 |

## 调用平台

按 [项目使用指南](../SKILL.md) 选择目标项目和角色凭证，通过 `heyincli req` 调用以下接口。参数直接放入表中指定的 `--query` 或 `--body` JSON 对象，项目由凭证确定，不传 `project_id`；请求环境由 `--test-env` 选择。

- 查询 ePRO 问卷数据需要 `PRJ_EPRO_ACCESS` 权限，或相应中心的 `SITE_EPRO_ACCESS` 权限。
- 本说明没有写接口，不需要 EDIT 权限，也不能把查询请求升级为填写或状态修改。

## 查询 ePRO 问卷数据（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| ePRO 问卷数据列表 | `GET` | `/api/project/epro/list_questionnaire_data/` | `--query`：`site_id` = 当前项目可见中心 ID（可选，非负整数；大于 0 时按该中心筛选，0 等同未指定）；<br>`status` = `NOT_STARTED`、`IN_PROGRESS`、`FILLED`、`OVERDUE_FILLED` 或 `OVERDUE_MISSED`（可选）；<br>`keyword` = 研究参与者编号关键词（可选）；<br>`limit` = 10–100（必填）；<br>`offset` = 非负分页偏移（可选） |

没有用户指定页大小时使用 10。用户需要完整结果、总体统计或跨页查找时，根据 `total` 以递增 `offset` 持续分页，直到收集全部匹配记录；不能把单页或空页当作完整数据集。

### 返回内容

成功返回 `list`（`EproQuestionnaireDataItem[]`）和 `total`。列表按 `plan_date` 升序、相同计划时间按记录 ID 升序；`total` 是全部匹配记录数，不是当前页数量。

每条记录的核心属性如下：

| 属性 | 定义 |
| --- | --- |
| `id`、`epro_questionnaire_id` | ePRO 问卷数据 ID 和问卷配置 ID。 |
| `site_id`、`patient_id`、`patient_sn` | 中心、研究参与者 ID 和编号；默认只向用户反馈完成问题所需的最少标识。 |
| `patient_is_mdv_upgrading` | 研究参与者是否处于方案版本升级中；只反映当前平台值。 |
| `event_def_id`、`event_def_name` | 访视事件定义及名称。 |
| `form_def_id`、`form_def_name`、`form_data_id` | 表单定义与当前匹配的最新表单数据 ID；0 表示本次没有关联值，不能补造。 |
| `plan_date`、`window_start_date`、`window_end_date`、`time_unit` | 计划时间、访视窗和平台时间粒度。 |
| `status` | `NOT_STARTED` 未开始、`IN_PROGRESS` 进行中、`FILLED` 已填写、`OVERDUE_FILLED` 逾期已填写、`OVERDUE_MISSED` 逾期未填写。 |
| `is_required_must_fill`、`is_overdue_fillable` | 是否严格必填、是否允许研究参与者逾期自填；后者不限制研究者通过 EDC 表单代填。 |
| `opened_at`、`submitted_at`、`duration`、`is_self_filled` | 打开和提交时间、填写耗时秒数、是否由研究参与者自填。空值保持未知。 |
| `submit_role_id`、`submit_role_code`、`submit_role_name`、`submit_role_scope` | 提交时的生效角色快照；角色级别为 `PROJECT` 或 `SITE`，不代表当前角色分配。 |
| `submit_user_id`、`submit_username`、`submit_name` | 提交人摘要，属于人员敏感信息，仅在用户明确需要时最小化输出。 |

## 查询范围与解释规则

- 平台首先校验项目级或中心级 ePRO 查看权限。项目级权限可覆盖当前环境的项目数据；只有中心级权限时，未指定中心也只返回其权限范围内中心的数据，权限范围为空时必须保持空结果，不能退化为全项目查询。
- 显式 `site_id` 必须属于当前项目、当前生产或测试环境，并位于当前角色权限范围内。名称无法唯一对应中心时先让用户确认，不能猜测中心 ID。
- 项目必须已开启 ePRO。关闭 ePRO、中心不属于当前环境、状态非法、权限不足或项目不存在时保留平台错误，不移除筛选条件或切换环境重试。
- `keyword` 实际匹配研究参与者编号，不是问卷名、事件名、表单名或提交人姓名。用户使用其他语义搜索时，应说明此限制并使用可支持的筛选，而不能暗示平台完成了不支持的全文检索。
- 各状态是问卷记录状态，不是研究参与者、事件或整个表单的聚合状态。缺失字段、空时间或未加载后续页不得解释为未开始、未填写或没有提交人。

研究者按[表单写入说明](patient-form-write.md)中的“表单全量提交”提交关联 EDC 表单时，平台会同步尚未处于 `FILLED`、`OVERDUE_FILLED` 终态的对应 ePRO 记录，按提交时间与访视窗确定填写状态，记录提交时间、代填人员及角色，并将 `is_self_filled` 设为 `false`。`is_overdue_fillable=false` 不阻止这种同步；逾期代填仍可变为 `OVERDUE_FILLED`。查询时须区分参与者自填与研究者代填，不得仅凭该开关认定问卷不能补录。本说明仍只负责读取，实际写入须遵循表单写入说明并获得相应授权。

## 敏感数据与输出边界

ePRO 结果包含研究参与者编号、内部 ID、填写时间和提交人员信息。默认使用中心、问卷/事件/表单名称、状态和必要时间回答问题；只有在用户任务确实需要定位个体记录时才返回研究参与者编号或记录 ID，不输出无关内部 ID、提交人账号或完整数据集。

不要将 `patient_is_mdv_upgrading`、`is_self_filled` 或提交人字段用于推断身份、医学结论、依从性原因或责任归属。未知、空值和部分分页结果按实际情况说明，不补造默认值。

## 结果核验

少量记录可使用“中心 / 研究参与者 / 问卷或表单 / 计划时间 / 状态 / 提交时间”表格；仅包含回答问题所需列。汇总时必须说明筛选条件和已遍历的数据范围，并按平台状态计数，不把 `FILLED` 与 `OVERDUE_FILLED` 合并，除非用户明确要求合并口径。
