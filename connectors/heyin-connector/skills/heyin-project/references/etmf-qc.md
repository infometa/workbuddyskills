# eTMF 质量控制使用说明

本说明处理 eTMF 质量控制视角下的里程碑、文件列表和状态流转。普通文件库结构、文件项与文件信息维护由 [etmf 使用说明](etmf.md) 处理；本说明不读取文件内容；质控前需要核对正文时，按 [etmf 使用说明](etmf.md) 的“文件正文受控读取”下载已授权文件（`PRJ_TMF_QC_ACCESS` 也可使用该入口）。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询质控里程碑 | 获取当前环境的里程碑分组、里程碑与统计 | 否 |
| 查询质控文件 | 按分区、级别、中心、里程碑、状态和文件名分页查询 | 否 |
| 归档文件 | 将待质控或已驳回文件归档 | 是 |
| 驳回文件 | 将待质控或已归档文件驳回并记录原因 | 是 |

## 调用平台

按 [项目使用指南](../SKILL.md) 选择目标项目和角色凭证，通过 `heyincli req` 调用以下接口。参数直接放入表中指定的 `--query` 或 `--body` JSON 对象，项目由凭证确定，不传 `project_id`；请求环境由 `--test-env` 选择。

- 查询质控里程碑和文件需要 `PRJ_TMF_QC_ACCESS` 权限。
- 归档或驳回文件需要 `PRJ_TMF_QC_EDIT` 权限。

## 查询质控数据（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取质控里程碑结构 | `GET` | `/api/project/etmf/qc/get_milestone_structure/` | 无 |
| 获取质控文件列表 | `GET` | `/api/project/etmf/qc/list_files/` | `--query`：`section_id`、`milestone_id` = 正整数（可选）；<br>`level` = `PROJECT` 或 `SITE`（可选）；<br>`site_id` = 正整数（仅中心级筛选时生效，可选）；<br>`status` = `PENDING`、`REJECTED` 或 `ARCHIVED`（可选）；<br>`keyword` = 文件名关键词（可选，最长 200）；<br>`limit` = 10–100（必填）；<br>`offset` = 非负偏移（可选） |

### 返回内容

| 接口 | 业务返回内容 | 定义 |
| --- | --- | --- |
| 获取质控里程碑结构 | `EtmfMilestoneStructure` | 根级统计和 `groups`（分组 > 里程碑）结构；生产环境使用已发布快照，测试环境使用草稿轨。 |
| 获取质控文件列表 | `list`（`EtmfFile[]`）和 `total` | 按文件 ID 倒序的分页结果及全部命中数。当前页为空不表示项目内没有质控文件。 |

里程碑结构包含分组与里程碑的 ID、名称、排序、关联文件项数，以及文件总数、大小、各状态数量、必备与缺失槽位、完整度等统计。只解释平台实际返回的节点与统计；筛选或权限导致节点缺失时不得补造。

`EtmfFile` 的核心属性如下：

| 属性 | 定义 |
| --- | --- |
| `id`、`artifact_id`、`sub_artifact` | 文件 ID、所属文件项 ID 和子文件项；文件 ID 是归档或驳回的唯一依据。 |
| `level`、`sites` | `PROJECT` 表示项目级；`SITE` 表示中心级，并返回当前可见的关联中心摘要。 |
| `milestone_id`、`milestone_name` | 按文件级别对应的里程碑；ID 为 0 表示没有里程碑。 |
| `name`、`original_name`、`version`、`file_date`、`size` | 文件展示信息、版本、日期和大小。 |
| `status`、`reject_reason`、`rejected_at`、`archived_at` | `PENDING`、`REJECTED` 或 `ARCHIVED` 及相应质控信息。 |
| `creator_*`、`qc_*` | 上传人与质控人员摘要，属于人员敏感信息，仅在用户问题需要时最小化反馈。 |
| `is_accessible`、`path` | 是否允许查看或下载；质控列表中的 `path` 始终为空，不代表文件不存在。 |

质控查看权限是项目级权限；中心级筛选仍必须指向当前项目和当前环境。双盲项目中，无盲态访问权限且尚未完全揭盲时，文件元数据仍可能返回，但 `is_accessible=false`；不得据此尝试其他接口、角色或中心绕过限制。

## 归档与驳回（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 | 允许的变更前状态 | 目标状态 | 业务返回内容 |
| --- | --- | --- | --- | --- | --- | --- |
| 归档文件 | `POST` | `/api/project/etmf/qc/archive_file/` | `--body`：`file_id` = 最新质控列表唯一定位的文件 ID | `PENDING`、`REJECTED` | `ARCHIVED` | 无 |
| 驳回文件 | `POST` | `/api/project/etmf/qc/reject_file/` | `--body`：`file_id` = 最新质控列表唯一定位的文件 ID；`reject_reason` = 用户确认的具体原因（1–200 字符） | `PENDING`、`ARCHIVED` | `REJECTED` | 无 |

两个写接口的 `file_id` 为必填整数；驳回还要求必填字符串 `reject_reason`，长度为 1–200。

### 状态与副作用

- 归档会记录当前质控人员和归档时间，清空驳回原因与驳回时间，并向上传人发送归档通知。
- 驳回会记录完整驳回原因、当前质控人员和驳回时间，清空归档时间，并向上传人发送驳回通知。
- 已归档文件可以被驳回，已驳回文件也可以被归档；平台会在写入时重新校验目标状态和当前生产/测试环境。
- 两个写接口都要求项目处于可写状态且已开启 eTMF。权限、状态或环境不满足时保留平台错误，不更换目标或改写原因后盲目重试。

执行前先用最新质控列表唯一定位目标，向用户展示文件安全摘要、ID、当前状态、预期状态；驳回还必须展示完整最终原因。既有授权已覆盖目标和归档/驳回影响时继续；状态、目标或原因不明确时先澄清，不得猜测。

执行后按相同环境和足够精确的筛选重新查询，核验目标状态、驳回原因及相应时间。写接口返回成功但回读未更新时，只能报告“请求已受理，变更未确认生效”，不能将其视为最终完成。

## 敏感数据与输出边界

质控结果可能包含文件名、原始文件名、中心、上传人、质控人和驳回原因。只返回完成用户问题所需的最少字段，不输出无关人员账号、对象存储路径、签名地址、认证材料或未知上游字段。

列表不会下发文件内容或签名地址；正文只经“文件正文受控读取”按文件获取，下载会记录访问日志。`is_accessible=false`、空 `path`、缺失质控人或空时间必须按原值说明，不能推断文件损坏、未上传或从未质控。

## 结果核验

使用写前与写后两次读取的实际值反馈结果。单文件可使用“属性 / 变更前 / 变更后 / 结果”表格；至少包含文件 ID、名称、状态、驳回原因以及归档或驳回时间。若目标消失、回读失败或状态不符合预期，明确标为“变更未确认生效”。
