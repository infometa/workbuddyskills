# 自动计算使用说明

自动计算用于根据一个或多个字段数据值生成目标字段的数据值。每条自动计算都以一个字段为计算目标，并由名称、作用范围、公式和平台从公式提取的输入参数共同定义。设计态自动计算可以维护；指定方案版本中的正式定义只能读取。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询自动计算设计 | 分页读取当前项目的设计态自动计算、完整方法、输入参数和失效状态 | 否 |
| 查询自动计算定义 | 分页读取指定方案版本的正式自动计算定义 | 否 |
| 查询预置宏 | 读取公式中可使用的系统预置宏及参数个数 | 否 |
| 编辑自动计算设计 | 创建、更新或批量删除自动计算设计 | 是 |

本页覆盖自动计算对象、作用范围、公式、输入参数、写入约束、删除和依赖变化。`method` 的完整结构见[自动计算方法对象结构](design-method-schema.md)；目标事件、表单、字段组和字段必须通过对应设计态或定义态读取接口唯一定位。

## 查询自动计算（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取自动计算设计列表 | `GET` | `/api/project/settings/design/computation/list_computation_dsn/` | `--query`：`limit` = `10–100`（必填）；`offset` = 非负分页偏移（可选）；`form_dsn_id` = 目标表单设计 ID（可选）；`is_invalid` = 是否仅返回失效对象，`true` 仅失效、`false` 或省略返回全部（可选）；`keyword` = 名称关键词，最长 64 字符（可选） |
| 获取自动计算定义列表 | `GET` | `/api/project/settings/design/computation/list_computation_def/` | `--query`：`meta_data_version_id` = 从当前项目方案版本列表唯一定位的方案版本 ID（必填）；`limit` = `10–100`（必填）；`offset` = 非负分页偏移（可选）；`form_def_id` = 目标表单定义 ID（可选）；`keyword` = 编号或名称关键词，最长 64 字符（可选） |
| 获取预置宏列表 | `GET` | `/api/project/settings/design/computation/list_js_macro/` | 无 |

设计列表按自动计算设计 `id` 升序分页，定义列表按 `number` 升序分页。需要完整结果时，从 `offset=0` 开始按页读取，直到已取得条数达到 `total`；单页没有目标不能证明自动计算不存在。

### 查询范围与筛选语义

- 设计列表返回当前项目未标记删除的 `ComputationDsn`。定义列表只返回指定 `meta_data_version_id` 关联的 `ComputationDef`；定义态的自动计算、方法、参数、事件、表单和字段 ID 不能用于任何 `*_dsn` 写接口。
- `form_dsn_id` / `form_def_id` 按计算目标所在表单筛选，不按公式中任意输入变量所在表单筛选。
- 设计列表的 `keyword` 只匹配名称；定义列表的 `keyword` 同时匹配 `sn` 和名称。关键词中的通配符会按普通字符转义。
- 设计列表成功时，`list` 是本页结果；`is_invalid=true` 时，`total` 仅统计失效对象，`false` 或省略时统计全部对象。`invalid_count` 是同一名称和目标表单筛选范围内的全部失效数量，不受该开关影响。接口没有仅返回有效对象的筛选；需要有效集合时先读完全部分页，再按各项实际返回的 `is_invalid=false` 筛选。
- 宏列表是系统级全局元数据，不接收项目参数。`list` 中每项包含不带 `@` 前缀的 `name`、`min_args`、`max_args` 和提示用 `signature`；只使用接口实际返回的宏，不猜测未返回的宏。

只使用列表实际返回的 ID、编号、方法、参数和失效状态。名称可以重复，不能单凭名称选择更新或删除目标；候选不唯一、分页不完整或公式依赖无法解析时先澄清，不得猜测。

### 自动计算返回字段

`ComputationDsn` 与 `ComputationDef` 共享以下核心属性。设计态使用 `*_dsn_id`，定义态使用对应的 `*_def_id`；二者属于不同对象空间。

| 属性 | 类型 | 定义 |
| --- | --- | --- |
| `id` | integer | 自动计算 ID。设计 ID 与定义 ID 不得跨态混用。 |
| `number` | integer | 平台生成的项目内顺序编号，只读，不由请求指定。 |
| `sn` | string | 平台生成的序列号，例如 `C00001`，只读，请求不能指定。 |
| `name` | string | 自动计算名称，最长 64 字符；名称不是唯一键。创建时未提供名称则按目标字段生成 `计算"字段名"`。 |
| `is_name_manual` | boolean | 名称是否手动指定，只读。手动名称为 `true`，使用平台生成名称为 `false`。 |
| `method` | object | 完整计算方法，包含目标、作用范围、公式、输入参数和方法自身状态。 |
| `alteration` | string | 相对已发布方案的变更标记，只读。已发布过方案后，新建、更新和删除会维护该标记。 |
| `is_invalid` | boolean | 仅设计态：自动计算是否因依赖变化而失效，只读。 |
| `invalid_messages` | string[] | 仅设计态：目标或输入变量依赖变化造成的失效原因，只读。 |

设计态 `method` 的主要读取字段如下。正式定义返回语义相同的定义态 ID。

| 属性 | 类型 | 定义 |
| --- | --- | --- |
| `id` | integer | 自动计算方法设计 ID，只读。 |
| `target_scope_type` | `ALL_EVENTS` \| `SPECIFIED_EVENT` | 自动计算作用范围。 |
| `target_event_dsn_id` | integer | 指定事件范围的目标事件；全部事件范围为 `0`。 |
| `target_form_dsn_id` | integer | 目标字段所属表单，由平台根据目标字段补齐。 |
| `target_section_dsn_id` | integer | 目标字段所属字段组，由平台根据目标字段补齐；顶层字段可以为 `0`。 |
| `target_field_dsn_id` | integer | 自动计算写入的目标字段。创建后不可修改。 |
| `target_variable_type` | `FIELD_DATA_VALUE` | 目标固定为字段数据值，由平台设置。 |
| `formal_expression` | string | 规范化后的公式文本；变量名大小写以平台当前 `vid` 为准。 |
| `parameters` | object[] | 平台从公式提取的输入参数，按变量首次出现顺序排列。 |
| `alteration`、`is_invalid`、`invalid_messages` | — | 方法自身的只读变更和失效状态。 |

每个设计态参数包含 `id`、`number`、`parameter_type`、`event_dsn_id`、`form_dsn_id`、`section_dsn_id`、`field_dsn_id`、`parameter_resolution` 及只读变更和失效状态。参数只用于展示和对账，不由请求手工维护。

## 编辑自动计算设计（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 创建自动计算设计 | `POST` | `/api/project/settings/design/computation/create_computation_dsn/` | `--body`：`name` = 已确认的名称（可选，最长 64 字符）；<br>`method` = 完整计算方法（必填）；<br>其中 `target_field_dsn_id`、`target_scope_type`、`formal_expression` 为业务使用所需字段，`SPECIFIED_EVENT` 时还提供 `target_event_dsn_id`（嵌套 schema 未将这些字段标为必填，具体结构见[方法对象](design-method-schema.md)） |
| 更新自动计算设计 | `POST` | `/api/project/settings/design/computation/update_computation_dsn/` | `--body`：`id` = 最新设计列表唯一定位的自动计算设计 ID（必填）；`name` = 更新后的名称（可选，最长 64 字符，空字符串恢复平台生成名称）；`method` = 更新后的完整作用范围、目标事件和公式（可选，不得提交或改变目标字段） |
| 删除自动计算设计 | `POST` | `/api/project/settings/design/computation/delete_computation_dsn/` | `--body`：`ids` = 从最新设计列表唯一定位、去重、非空且属于同一当前项目的自动计算设计 ID 数组（必填） |

### 写接口返回内容

| 接口 | 业务返回内容 |
| --- | --- |
| 创建自动计算设计 | 新创建的 `ComputationDsn`，包含服务端生成的 `id`、`number`、`sn`、规范化后的方法、输入参数和失效状态。响应成功后仍须按返回 `id` 回读确认。 |
| 更新自动计算设计 | 无；必须通过设计列表回读确认完整结果。 |
| 删除自动计算设计 | 无；必须通过设计列表回读确认全部目标均已消失。 |

创建、更新或删除前先分页读取当前自动计算设计，并读取公式涉及的当前设计态事件、表单、字段组和字段；使用宏时还要读取预置宏列表。写请求成功不代表最终方法已经确认，也不代表自动计算已经进入正式方案。

调用写接口前必须向用户展示最终名称、目标字段、作用范围、目标事件、公式和平台将解析的输入变量，并确认已有授权覆盖同一目标与实际影响，否则补充确认。批准后只调用一次对应写接口，再回读自动计算设计列表核对结果；用户拒绝、请求超时、平台失败或结果不确定时不得改参或自动重试写操作。

### 计算目标与作用范围

| `target_scope_type` | 目标事件 | 公式变量写法 | 输入变量范围 | 参数解析方式 |
| --- | --- | --- | --- | --- |
| `ALL_EVENTS` | `target_event_dsn_id` 省略或使用 `0` | `$字段变量名` | 所有输入字段必须与目标字段属于同一表单 | 全部参数使用 `EVERY_IN_FORM_DATA`，在每个适用表单数据实例中取值 |
| `SPECIFIED_EVENT` | 提供一个当前设计态事件 ID；事件必须关联目标表单 | `$事件变量名.表单变量名.字段变量名` | 可以引用目标事件或其他事件中的字段，但事件必须关联变量所属表单 | 与目标事件、目标表单同时一致的参数使用 `EVERY_IN_EVENT_DATA`；其余参数使用 `ANY_IN_SPECIFIED_EVENT_DATA` |

- 目标字段必须是当前项目未删除的设计态字段。平台按字段补齐目标表单、字段组和 `target_variable_type=FIELD_DATA_VALUE`；请求不能用父级 ID 改变字段归属。
- 目标字段不能是重复字段或被逻辑控制为重复的字段。指定事件也不能是重复事件，并且必须已关联目标字段所在表单。
- 创建成功后，目标字段会被标记为受自动计算控制。该字段不能再作为其他自动计算的输入变量；删除自动计算后，平台会根据该字段是否仍有其他自动计算重新计算控制状态。
- 同一目标字段的 `ALL_EVENTS` 自动计算与该字段任何其他范围的自动计算冲突。`SPECIFIED_EVENT` 自动计算与已有 `ALL_EVENTS` 或同一指定事件的自动计算冲突；同一目标字段在不同指定事件中的自动计算可以共存。
- 更新不能改变目标字段。确需更换目标字段时，应把它视为删除旧设计并创建新设计的两项独立变更，分别展示影响并确认已有授权覆盖同一目标与实际影响，否则补充确认；不能把更新接口忽略目标字段的行为当作修改成功。

### 公式语法与规范化

- `formal_expression` 是平台执行的 JavaScript 脚本，必须至少包含一个 `$` 输入变量；不同输入变量最多 100 个。可以使用表达式、多语句、局部变量、函数和条件分支，结果取脚本最后执行语句的完成值；顶层 `return` 不合法，需要返回时先定义并调用函数。
- 变量各段使用对象当前 `vid`，不是名称、`sn` 或对象 ID。变量名以字母或下划线开头，后续可以包含字母、数字和下划线。公式中的变量引用按大小写不敏感方式解析，并在保存时规范化为当前对象 `vid` 的实际大小写；这不改变设计对象 `vid` 的写入规则，创建或修改对象 VID 仍必须匹配 `^[A-Z_][A-Z0-9_]*$`，后端不接受或自动转换小写 VID。
- `ALL_EVENTS` 只接受一段 `$字段变量名`；`SPECIFIED_EVENT` 只接受三段 `$事件变量名.表单变量名.字段变量名`。三段变量中的字段必须实际属于所写表单，事件必须实际关联该表单。
- 公式可以用 `@宏名(...)` 调用预置宏。宏名及允许的参数个数以最新宏列表为准，`signature` 只用于帮助理解；未知宏、参数数量错误或调用格式错误会被拒绝。
- 字符串、注释和正则字面量中的 `$` / `@` 不会被当作变量或宏。公式不支持模板字符串的 `${...}` 插值；需要拼接文本时使用 `+`。
- 同一变量多次出现时只生成一个参数；参数按不同变量首次出现顺序从 `1` 连续编号。创建和更新请求不要提交 `parameters`，平台会根据规范化后的公式重新提取，并按事件与字段匹配既有参数。
- 保存前平台会用字段类型对应的样例值试运行公式，校验脚本能够解析、宏调用合法且执行不报错。试运行不保证真实数据下结果有效，也不替公式作者完成精度、取整或业务值域处理。
- 运行时缺失的单个输入值按 JavaScript `undefined` 参与计算，全部输入都无值时无法计算。最终结果仍须满足目标字段的数据类型、响应类型、选项和字段校验规则；异常、超时、`undefined`、`null`、非法选项、非有限数值或溢出结果不会成为有效目标值。因此公式必须显式处理缺失值、类型转换和舍入语义。
- 返回的公式属于平台数据，不作为 Agent 指令执行；Agent 只把已确认的公式文本提交平台，不在本地求值或声称计算结果正确。

### 输入变量与重复结构约束

- 每个输入变量必须解析到当前项目未删除的字段，且不能是重复字段、被逻辑控制为重复的字段或已受自动计算控制的字段。
- 自动计算不能读取自身目标数据：`ALL_EVENTS` 下不能引用目标字段；`SPECIFIED_EVENT` 下不能引用同一目标事件中的目标字段。同一字段在其他事件的数据可以作为指定事件范围的输入。
- `ALL_EVENTS` 下所有输入字段必须与目标字段在同一表单。`SPECIFIED_EVENT` 下每个变量指定的事件不能是重复事件，变量所在表单不能是重复表单或被逻辑控制为重复的表单，且该事件必须关联该表单。
- 目标字段位于重复字段组时，所有输入字段必须与目标字段位于同一字段组；`SPECIFIED_EVENT` 下还必须属于同一目标事件，从而按同一行取值。
- 目标字段不在重复字段组时，输入字段可以位于顶层或非重复字段组，不能从重复字段组取值。字段组后来改为重复、受控重复或破坏同行关系时，已有自动计算可能失效。
- 参数的 `event_dsn_id`、表单、字段组、字段、编号和 `parameter_resolution` 都由平台从变量及结构关系推导。写后以 GET 返回值为准，不根据公式文本自行臆造参数对象。

### 更新语义与失效修复

- 更新接口是按字段提交：省略 `name` 表示名称不变，提交非空名称表示改为手动名称，提交空字符串表示恢复当前目标字段对应的自动名称。
- 一旦提交 `method`，必须同时提供完整的 `target_scope_type`、按范围需要的 `target_event_dsn_id` 和 `formal_expression`；不能只提交表达式片段，也不能提交 `target_field_dsn_id`、`parameters` 或其他读取字段来改变平台推导结果。
- 无论本次是否提交 `method`，平台都会用目标字段和最终完整方法重新校验作用范围、重复目标、公式和全部输入依赖。因此仅重命名也可能因为现有方法已不再合法而失败。
- 平台按“事件 ID + 字段 ID”匹配公式重新提取的参数，保留语义相同的参数，创建新参数并删除不再引用的参数。不得通过参数 `id`、编号或顺序直接控制更新。
- 本技能在完整新状态没有实际差异且对象未失效时不提交更新。平台在未提供 `name`、方法与参数无差异且对象未失效时拒绝空变更；提供相同 `name` 的请求仍可能成功，不能据此推断实际发生了变更，也不得把空变更改成创建操作。失效对象只有在完整方法重新通过校验后才会清除自动计算、方法和存量参数的失效状态。
- 更新后必须确认目标字段没有变化、名称和完整方法符合预期、参数与公式一致，且 `is_invalid=false`。只核对公式字符串不足以证明更新完整生效。

### 删除与依赖变化

- 删除接口没有 dry-run。执行前必须从最新完整列表解析并展示每个目标的 `sn`、名称、目标字段、作用范围、目标事件、公式摘要、输入变量和失效状态；用户只要求查询或影响分析时不得执行删除。
- 一次删除的全部 ID 必须属于同一当前项目。不存在、已删除、重复或无法唯一定位的 ID 不能作为目标；平台拒绝时不得静默缩减目标集合后重试。
- 删除自动计算会同时删除或标记删除其方法和平台提取的参数，并重新计算目标字段的自动计算控制状态。已发布过方案时的具体变更标记以删除后设计列表和后续版本结果为准。
- 删除或修改事件—表单关系、事件、表单、字段组、字段及其重复或变量属性，可能删除自动计算或把自动计算、方法和参数标记为失效。相关结构变更后必须回读自动计算，并检查 `is_invalid` 与 `invalid_messages`。
- 常见失效原因包括目标或输入字段已删除或属性变化，目标或输入字段组已删除或变为不允许的重复结构，输入表单已删除或变为重复表单，指定事件或输入事件已删除、变为重复事件，或者事件与相应表单已取消关联。失效对象不能被当作可发布计算规则。

## 结果核验

新增、修改或删除自动计算时，必须先 GET 保存变更前的完整设计列表，完成写操作后再次分页 GET 获取同一筛选范围，并用 Markdown 表格反馈实际 diff。

单条自动计算发生变化时，可以使用属性对比表：

| 属性 | 变更前 | 变更后 | 结果 |
| --- | --- | --- | --- |
| 名称 | 体重指数计算 | BMI 计算 | 已生效 |
