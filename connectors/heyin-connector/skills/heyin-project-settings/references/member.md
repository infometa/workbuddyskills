# 项目成员配置使用说明

项目成员配置用于维护当前项目中的成员身份及其项目级、中心级角色，处理被移除成员的恢复，以及管理加入申请和成员邀请。成员身份与角色分配相互独立：成员可以暂时没有角色，同一成员也可以持有多个项目级和中心级角色。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询成员配置 | 获取成员、角色名称、中心名称和待处理通知数量 | 否 |
| 编辑成员与角色 | 覆盖成员角色分配、移除成员、按回收站快照恢复成员 | 是 |
| 管理加入申请 | 查询申请并批准或拒绝待处理申请 | 是 |
| 管理成员邀请 | 查询、创建、变更或撤销邀请，按手机号精确搜索用户 | 是 |
| 批量邀请 | 实时生成邀请模板并导入已上传的 Excel 文件 | 是 |

## 权限与调用方式

按 [项目设置使用指南](../SKILL.md) 核对项目及凭证，通过 `heyincli req` 调用本文接口。GET 参数放入 `--query`，POST 参数放入 `--body`；所列字段直接放入对应 JSON 对象，不额外嵌套 `query` 或 `body`。业务返回内容均位于接口响应封装的 `data` 中。

本文用于管理指定项目的成员、审核他人的加入申请及发出或维护成员邀请。查看本人申请、申请加入项目或回复本人收到的邀请，使用合因命令行指南中的 `project application`、`project invitation` 指令。

从成员角度整体替换某些成员的角色时使用本文；从角色角度增删成员或调整生效中心时阅读 [角色与权限](role.md)。两者的字段和更新语义不同，不得混用。

- 获取通知数量、角色名称、中心名称、成员、可恢复成员、申请和邀请列表需要 `PRJ_SETTINGS_MEMBER_ACCESS` 权限。
- 搜索用户、下载邀请模板，以及全部成员、申请和邀请写操作需要 `PRJ_SETTINGS_MEMBER_EDIT` 权限。

## 查询成员、申请与邀请（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取通知数量 | `GET` | `/api/project/settings/member/badge_number/` | 无 |
| 获取项目内角色名称列表 | `GET` | `/api/project/settings/member/list_role_name/` | `--query`：`scope` = `PROJECT` 或 `SITE`（必填） |
| 获取中心名称列表 | `GET` | `/api/project/settings/member/list_site_name/` | `--query`：`status`、`special`、`keyword` = 中心状态、生产/测试类型和编号或名称关键词筛选（可选，关键词最长 32） |
| 获取成员列表 | `GET` | `/api/project/settings/member/list_member/` | `--query`：`limit` = 10–100（必填）；`offset` = 非负分页偏移（可选）；`keyword` = 匹配姓名或用户名的关键词（可选，最长 16）；`role_id`、`site_id` = 角色或中心筛选（可选） |
| 获取可恢复成员列表 | `GET` | `/api/project/settings/member/list_restore_member/` | `--query`：`limit` = 10–100（必填）；`offset` = 非负分页偏移（可选）；`keyword` = 匹配姓名或用户名的关键词（可选，最长 16） |
| 获取加入项目申请列表 | `GET` | `/api/project/settings/member/list_application/` | `--query`：`limit` = 10–100（必填）；`offset` = 非负分页偏移（可选）；`keyword` = 申请人姓名关键词（可选，最长 16）；`result` = 审核结果筛选（可选） |
| 获取邀请加入项目列表 | `GET` | `/api/project/settings/member/list_invitation/` | `--query`：`limit` = 10–100（必填）；`offset` = 非负分页偏移（可选）；`keyword` = 受邀人姓名关键词（可选，最长 16）；`result` = 邀请结果筛选（可选） |
| 搜索用户 | `GET` | `/api/project/settings/member/search_user/` | `--query`：`phone` = 用户明确提供的完整手机号（必填） |
| 下载批量邀请模板 | `GET` | `/api/project/settings/member/download_invite_template/` | 无 |

中心名称查询中，省略 `special` 表示全部可见中心类型，显式传 `special=""` 只查询生产中心，传 `special="TEST"` 只查询测试中心；`status` 省略或留空表示全部状态。项目未开启测试环境时不返回测试中心。成员、可恢复成员、申请和邀请列表使用 `--query` 内的 `limit`、`offset` 分页，其余查询按接口表所列参数调用。

中心筛选字段均为字符串：`keyword` 最长 32；`status` 可取空字符串、`STARTED`、`ENROLLING`、`FINISH_ENROLLMENT`、`LOCKED`、`CLOSED` 或 `SUSPENDED`。角色作用域使用项目业务允许的 `PROJECT` 或 `SITE`，不因共用枚举还包含系统、组织作用域就扩展本接口的使用范围。

### 只读接口返回内容

| 接口 | 业务返回内容 | 定义 |
| --- | --- | --- |
| 获取通知数量 | `application_pending_number`、`invitation_pending_number`（integer，必填） | 当前项目待处理申请数和待回复邀请数。 |
| 获取项目内角色名称列表 | 必填的 `list`（`RoleName[]`） | 指定级别的角色简表，按角色 ID 升序返回。 |
| 获取中心名称列表 | 必填的 `list`（`SiteName[]`） | 当前项目可选中心；项目未开启测试环境时不返回测试中心。 |
| 获取成员列表 | 必填的 `list`（`ProjectMember[]`）和 `total`（integer） | 当前成员及其当前可见的项目级、中心级角色分配；项目未开启测试环境时，测试中心角色不会展示。 |
| 获取可恢复成员列表 | 必填的 `list`（`ProjectMember[]`）和 `total`（integer） | 回收站成员及其当前可见的角色分配快照；项目未开启测试环境时，测试中心角色不会展示。 |
| 获取加入项目申请列表 | 必填的 `list`（`ProjectApplication[]`）和 `total`（integer） | 当前项目未撤销的加入申请；撤销申请不在列表中。 |
| 获取邀请加入项目列表 | 必填的 `list`（`ProjectInvitation[]`）和 `total`（integer） | 当前项目邀请及其聚合后的角色、中心和脱敏手机号。 |
| 搜索用户 | `UserBrief` | 按完整手机号精确命中的账号摘要；姓名经过掩码处理。 |
| 下载批量邀请模板 | `file_path`（string，必填） | 实时生成的签名下载地址；仅用于本次下载，不在聊天中展示或虚构。 |

`ProjectMember` 的核心属性如下：

| 属性 | 类型 | 定义 |
| --- | --- | --- |
| `user_id` | integer | 用户 ID，是成员写操作的唯一定位依据。 |
| `name` | string | 成员姓名。 |
| `project_roles` | `RoleRef[]` | 成员持有的全部项目级角色；一个成员可以持有多个。 |
| `site_roles` | `RaRS[]` | 成员持有的中心级角色；同一角色只返回一条，多个生效中心合并在该条目的 `sites` 中。 |

`RoleName` 包含 `id`、`name`、`code`、`scope` 和 `role_tpl_id`。`RoleRef` 包含角色 `id`、`code`、`name` 和 `scope`。`RaRS` 在 `RoleRef` 基础上包含完整 `sites`；每个中心包含 `id`、`sn`、`name` 和 `special`，其中 `special=TEST` 表示测试中心。

项目未开启测试环境时，成员列表和可恢复成员列表都会过滤测试中心角色。这只表示当前管理界面不可见，不等于底层一定不存在相关分配或回收站快照；恢复成员时隐藏的测试中心快照仍可能触发整批拒绝。

申请与邀请状态如下：

| 对象 | 状态 | 定义 |
| --- | --- | --- |
| 加入申请 | `PENDING`、`APPROVE`、`REJECT`、`REVOKED` | 待审核、已批准、已拒绝或申请人已撤销；成员设置列表不返回 `REVOKED`。 |
| 成员邀请 | `PENDING`、`ACCEPT`、`REJECT`、`REVOKED` | 待回复、已接受、已拒绝或邀请已撤销。 |

邀请中的 `roles` 按角色聚合。项目级角色的 `sites` 为空数组；中心级角色可包含一个或多个中心。角色和中心名称是邀请建立时的业务快照，已删除中心的编号可能为空，不能据此补造当前对象。

只使用平台实际返回的成员、角色、中心、申请和邀请 ID。空列表或计数为零只表示本次读取结果；缺失、部分响应或请求失败不能补造为零或默认对象。

## 编辑成员、申请与邀请（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 更改角色分配 | `POST` | `/api/project/settings/member/update_role_assignment/` | `--body`：`user_ids` = 最新成员列表唯一定位、去重且非空的用户 ID 数组（必填）；`project_role_ids` = 更新后的完整项目级角色 ID 集合（可选）；`site_roles` = 更新后的完整中心—角色分配集合（可选，每项包含 `site_id`、`role_id`） |
| 删除项目成员 | `POST` | `/api/project/settings/member/delete_member/` | `--body`：`user_ids` = 最新成员列表唯一定位、去重且非空的用户 ID 数组（必填） |
| 批量恢复项目成员 | `POST` | `/api/project/settings/member/batch_restore_member/` | `--body`：`user_ids` = 最新可恢复成员列表唯一定位、去重且非空的用户 ID 数组（必填） |
| 回复加入项目申请 | `POST` | `/api/project/settings/member/reply_application/` | `--body`：`application_id` = 最新申请列表返回的待处理申请 ID（必填）；`result` = `APPROVE` 或 `REJECT`（必填）；`project_role_ids`、`site_roles` = 批准后授予的项目级角色和中心—角色集合（可选）；`auditor_comment` = 审核备注（可选，最长 255；拒绝时必填） |
| 邀请加入项目 | `POST` | `/api/project/settings/member/invite/` | `--body`：`phone` = 用户明确提供的完整手机号（必填）；`roles` = 1–50 条完整邀请角色集合（必填，每项包含 `role_id` 和 `site_id`）；`inviter_comment` = 邀请备注（可选，最长 255） |
| 批量邀请加入项目 | `POST` | `/api/project/settings/member/import_invite/` | `--body`：`file_path` = 当前用户本次上传并明确选定的 `.xlsx` 文件对象路径（必填） |
| 变更成员邀请 | `POST` | `/api/project/settings/member/update_invitation/` | `--body`：`id` = 最新邀请列表返回的待回复邀请 ID（必填）；`roles` = 变更后的 1–50 条完整邀请角色集合（必填）；`inviter_comment` = 变更后的邀请备注（可选，最长 255；不传按空字符串处理） |
| 撤销邀请成员 | `POST` | `/api/project/settings/member/revoke_invitation/` | `--body`：`invitation_id` = 最新邀请列表返回的待回复邀请 ID（必填） |

| 接口 | 业务返回内容 |
| --- | --- |
| 更改角色分配 | 无 |
| 删除项目成员 | 无 |
| 批量恢复项目成员 | 无 |
| 回复加入项目申请 | 无 |
| 邀请加入项目 | 新创建的 `ProjectInvitation`，其中手机号已脱敏，角色按角色聚合。 |
| 批量邀请加入项目 | `import_id`、总行数、成功行数、失败行数和是否全部成功；失败数据可能附带签名下载地址，不在聊天中展示。 |

### 成员角色分配

- `project_role_ids` 与 `site_roles` 都是完整集合，不是增量，提交前必须分别去重；省略其中一类不表示保留该类旧分配，必须提交本次完整目标集合。平台会先删除每个目标成员在当前项目中的全部项目级和中心级角色分配，再把同一套目标集合分配给 `user_ids` 中的每名成员；空的两类集合表示成员保留项目身份但不持有角色。
- 项目级角色只能出现在 `project_role_ids`；`site_roles` 中每项必须是中心级角色和正整数中心 ID。角色、中心与成员必须属于当前项目，项目关闭测试环境时不能分配测试中心。
- 项目关闭测试环境时，成员列表隐藏既有测试中心角色，但覆盖更新仍会先删除这些隐藏分配，且请求不能把测试中心角色加回。执行前必须向用户说明既有隐藏测试中心分配可能被移除，不能把当前可见列表当成完整的变更前角色全集。
- 项目管理员至少保留一名。若更新后的结果会使当前项目无人持有项目根角色，平台会拒绝整次变更。
- 角色变更可能使相关 API 令牌 的角色或数据域绑定失效并触发吊销；写入后角色上下文会立即失效。

### 移除与恢复成员

- 删除项目成员会移除其成员身份及全部角色分配，并把本次角色分配保存为回收站快照。删除不会删除平台账号；项目管理员至少保留一名，不能移除全部项目管理员。
- 删除时会覆盖该成员此前的旧快照，确保后续只恢复最近一次移除时的角色状态。成员身份或角色绑定失效时，相关 API 令牌 可能被吊销。
- 恢复只使用可恢复成员列表实际返回的用户 ID，并按回收站快照恢复成员身份和角色。恢复期间已经删除的角色或中心会被跳过；过滤后无有效角色仍可恢复为无角色成员。
- 项目未开启测试环境且有效快照仍包含测试中心分配时，包含该成员的整批恢复会被拒绝，不会静默丢弃测试中心角色。已经是项目成员的用户不能恢复；请求中的每个用户都必须从本次完整回读的可恢复成员列表唯一定位。当前服务端在整批没有匹配回收站记录时不能保证拒绝，不能依赖错误响应代替这项核对，也不得用裸用户 ID 探测或补建成员。

### 审核加入申请

- 只能回复 `PENDING` 申请，`result` 只能是 `APPROVE` 或 `REJECT`。已撤销、已批准或已拒绝的申请不能再次处理。
- 批准时，`project_role_ids` 和 `site_roles` 表示本次要追加授予申请人的角色集合；平台会先确保申请人成为项目成员，再直接创建这些角色分配，不会先清空既有角色。若申请人在申请待处理期间已通过其他途径进入项目，批准前必须读取最新成员列表，避免把其已持有的同一角色再次提交。角色级别、中心归属和测试环境限制与成员角色分配相同。
- 拒绝时 `auditor_comment` 必填，只更新申请审核结果，不删除申请人可能通过其他途径获得的成员身份或角色分配。

### 创建、变更与撤销邀请

- 搜索用户只允许使用用户为本次成员配置任务明确提供的完整手机号进行精确查找，不能用部分号码枚举账号。未找到既有账号不阻止邀请；正式邀请时平台会为该手机号创建未激活账号。
- 邀请角色按 `(role_id, site_id)` 去重。项目级角色的 `site_id` 必须为 0，中心级角色的 `site_id` 必须为当前项目正整数中心 ID；项目关闭测试环境时不能邀请测试中心角色。
- 已经是项目成员的用户不能重复邀请。已有待回复或已接受邀请，或者已有待处理或已批准申请时，也不能创建新邀请。
- 变更邀请使用覆盖语义，完整替换角色明细与备注；只能变更 `PENDING` 邀请。撤销同样只适用于 `PENDING` 邀请，不能撤销已接受、已拒绝或已撤销的邀请。

### 批量邀请

`req` 的 `--body` 只提交 JSON，不能把本地 Excel 文件直接上传。`file_path` 必须是当前用户已经上传且本次明确选定的文件对象路径，不是本地路径或签名下载 URL。尚未取得有效上传路径时，先通过平台受控页面完成上传或批量邀请，不假定存在上传命令，也不编造文件路径。

- 邀请模板按当前项目的角色和中心实时生成，不复用旧模板。只在用户明确要求模板时获取；仅使用本次响应提供的下载地址，不猜测或虚构，不在聊天中展示签名地址。该接口返回下载地址，调用本身不代表文件已经下载。
- 批量邀请只接受当前用户上传路径下的 `.xlsx` 文件；模板表头必须匹配，非空数据行最多 1000 行。格式、表头、空文件或超限问题会使整份文件在处理前失败。
- 导入会逐行校验手机号、角色、中心、测试环境和备注；成功行会在同一次调用中直接创建邀请，失败行不会回滚成功行。调用前必须明确说明部分成功语义，写操作只执行一次。
- 结果必须按平台返回的总数、成功数、失败数和 `is_succeed` 报告。失败文件可能附带签名下载地址，不记录或复述到聊天中。

## 写操作前置与失败边界

所有写操作都要求当前项目处于平台允许修改的状态，最终以平台校验为准。

写操作前必须读取最新成员、回收站、申请或邀请现状，并通过角色名称和中心名称列表唯一解析所有业务 ID。向用户复述目标成员、申请或邀请 ID、本次可见的角色与中心范围及主要影响；项目未开启测试环境时，还要说明列表不会展示测试中心角色，恢复成员时隐藏测试中心快照仍可能导致整批拒绝。无法唯一匹配时先澄清。不得把查询请求自动升级成写操作。

权限不足、项目不可写、参数冲突、对象不存在、结果不明或平台失败时，保留实际错误并停止。不得更换用户、角色、中心、申请或邀请 ID，不得删减影响范围，也不得盲目重试来绕过拒绝。

## 敏感数据与输出边界

平台结果可能包含 `username`、申请人或审核人账号、邀请人或受邀人账号、手机号和签名下载字段。只使用完成当前任务所需的非敏感字段，不得恢复、推断或输出用户名、认证材料、签名下载字段或无关上游字段。

手机号只在用户明确要求的精确查找、邀请或批量邀请任务中作为输入使用。回复默认不复述完整手机号，只展示平台返回的掩码值；缺失姓名、手机号或其他字段保持“未知”，不能根据账号或其他字段反推。

## 结果核验

- 更改角色分配前后分别获取成员列表；以每名成员为单位比较当前可见的 `project_roles` 和 `site_roles`。项目未开启测试环境时，不把列表中看不见的测试中心角色当成已不存在。
- 移除成员前获取成员列表，写后同时获取成员列表和可恢复成员列表；成员从前者消失且出现在后者才确认移除生效。
- 恢复成员前获取可恢复成员列表，写后同时获取成员列表和可恢复成员列表；成员出现在前者且从后者消失才确认恢复生效。
- 审核申请、变更或撤销邀请前后分别获取对应列表；创建单人邀请后按返回 ID 回读邀请列表。批量邀请以导入统计为本次直接结果，需要展示新增邀请明细时再读取邀请列表。

成员、回收站、申请和邀请列表都是分页接口。用于唯一定位或写后确认时，必须使用能够唯一收窄目标的筛选条件，或持续分页直到覆盖目标或遍历全部结果；不能因目标不在当前页就推断其不存在或变更已生效。

一次操作包含多个成员、角色、中心、申请或邀请变化时，使用 Markdown 批量变更表格。第一列固定为变更类型，只填写“新增”“变更”或“删除”；后续列展示变更后的值，原值紧跟其后并使用删除线标记。新增条目的原值留空，删除条目的变更后值留空并只保留删除线原值；未变化的属性留空。

成员角色变更示例：

| 变更类型 | 成员 ID | 成员姓名 | 项目级角色 | 中心级角色与生效中心 |
| --- | --- | --- | --- | --- |
| 变更 | 203 | 王某 | 数据管理员、项目管理员<br>~~数据管理员~~ | 临床监查员：S01、S02<br>~~临床监查员：S01~~ |
| 删除 | 207 | ~~李某~~ | ~~研究者~~ | ~~研究者：S03~~ |

表格中的 ID、名称、角色、中心和状态必须来自前后两次读取。若回读失败、对象未出现、已删除对象仍存在、回收站状态不一致或角色集合与预期不符，应报告“变更未确认生效”，不得仅依据写接口返回成功得出已生效结论。
