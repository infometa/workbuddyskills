# 表单设计使用说明

表单是 eCRF 方案中的采集单元，用于组织字段组、字段以及围绕表单配置的范围检查、自动计算、逻辑控制和逻辑核查。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询表单设计与定义 | 获取当前项目的设计态表单，或指定方案版本的正式表单定义 | 否 |
| 查询表单模板 | 读取系统表单模板库，作为新建表单的结构参考 | 否 |
| 编辑表单设计 | 创建、变更、排序、删除（含演练）表单设计 | 是 |

本页只覆盖表单对象本身以及定义态、设计态的读取与表单级写操作。字段组、字段和文本校验规则见[字段组与字段设计使用说明](design-form-item.md)。

## 查询表单设计与定义（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取当前表单设计列表 | `GET` | `/api/project/settings/design/form/list_form_dsn/` | `--query`：`keyword` = 名称、描述或备注关键词，最长 16 字符（可选） |
| 获取完整表单设计 | `GET` | `/api/project/settings/design/form/get_form_dsn/` | `--query`：`id` = 从当前表单设计列表唯一定位的表单设计 ID（必填） |
| 获取已发布表单定义列表 | `GET` | `/api/project/settings/design/form/list_form_def/` | `--query`：`meta_data_version_id` = 从当前项目方案版本列表唯一定位的方案版本 ID（必填）；`keyword` = 名称、描述或备注关键词，最长 16 字符（可选） |
| 获取完整表单定义 | `GET` | `/api/project/settings/design/form/get_form_def/` | `--query`：`id` = 从指定方案版本的表单定义列表唯一定位的表单定义 ID（必填） |
| 获取所有表单定义及所有字段名称 | `GET` | `/api/project/settings/design/list_form_def_name_with_subs/` | `--query`：`meta_data_version_id` = 从当前项目方案版本列表唯一定位的方案版本 ID（必填） |
| 获取所有表单设计及所有字段名称 | `GET` | `/api/project/settings/design/list_form_dsn_name_with_subs/` | 无 |

`keyword` 的查询只检索名称、描述和备注，不检索 `vid`。需要按 `vid` 或下级结构定位时，读取未过滤列表或完整对象后再匹配；匹配不唯一或没有匹配项时先澄清，不得猜测 ID。

### 只读接口返回内容

| 接口 | 业务返回内容 | 定义 |
| --- | --- | --- |
| 获取当前表单设计列表 | `list: FormDsn[]` | 当前项目按 `ranking` 升序排列且未标记删除的设计态表单列表，是表单级写操作定位 `id` 和写后回读的依据。列表用于候选定位；需要下级完整结构时继续调用完整表单设计接口。 |
| 获取完整表单设计 | `data: FormDsn` | 单个设计态表单的完整结构，包含表单属性、字段组、字段、自动计算、逻辑控制和逻辑核查。 |
| 获取已发布表单定义列表 | `list: FormDef[]` | 指定方案版本按 `ranking` 升序排列的正式表单定义列表，只读；其中的定义 ID 不能作为设计态写操作的表单 ID。 |
| 获取完整表单定义 | `data: FormDef` | 单个正式表单定义的完整结构，只用于查看、比对或下游只读选择。 |
| 获取所有表单定义及所有字段名称 | `list: FormDef[]` | 指定方案版本的定义态表单及下级字段结构，按表单 `ranking` 升序返回；用于一次读取名称和层级候选，定义态 ID 仍然只读。 |
| 获取所有表单设计及所有字段名称 | `list: FormDsnName[]` | 当前项目的设计态表单及下级字段名称结构，按表单 `ranking` 升序返回；省略完整表单中的描述、备注、规则和计算详情。 |

只使用平台实际返回的表单 ID、排序和状态。空列表只表示本次读取没有对应候选；缺失、空列表或部分响应不得被补造为默认表单，也不得把其他方案版本或项目的对象补入当前结果。

### 表单级返回字段

`FormDsn` 和 `FormDef` 的表单级属性如下。“是”表示对象必定包含该属性，“否”表示属性可能不返回，“不适用”表示该对象没有此属性。

| 属性 | 类型 | `FormDsn` 必填 | `FormDef` 必填 | 定义 |
| --- | --- | --- | --- | --- |
| `id` | integer | 是 | 是 | 表单 ID。设计 ID 和定义 ID 属于不同对象空间，不得跨态混用。 |
| `project_id` | integer | 是 | 是 | 表单所属项目 ID；必须与当前项目一致。 |
| `vid` | string | 是 | 是 | 表单变量名。设计写入时长度为 1–32，须匹配 `^[A-Z_][A-Z0-9_]*$`（大写字母或下划线开头，后续仅大写字母、数字或下划线；不接受小写，后端不自动转换），并在当前项目的未删除表单设计中大小写不敏感唯一。变更设计态 `vid` 会使引用该表单的自动计算失效。 |
| `name` | string | 是 | 是 | 表单名称；设计写入时长度为 1–256。名称不作为唯一键，同名候选仍须结合 `id`、`vid` 和结构唯一定位。 |
| `description` | string | 否 | 否 | 表单描述；设计写入时最长 256 字符。 |
| `comment` | string | 否 | 否 | 表单备注；设计写入时最长 256 字符。 |
| `ranking` | integer | 是 | 是 | 表单排序。新建表单追加到当前列表末尾；排序目标超过当前最大位置时，服务端归一到最大可用位置。 |
| `is_optional` | boolean | 是 | 是 | 是否为选填表单。 |
| `has_change_info` | boolean | 是 | 是 | 表单数据发生变更时是否要求提交变更原因。 |
| `is_repeating` | boolean | 是 | 是 | 是否允许重复填写。RTSM 关联表单不能从不重复改为重复。重复属性变化可能使逻辑核查、自动计算和随访通知规则失效。 |
| `repeating_limit` | integer | 否 | 否 | 重复次数限制，非负；只在 `is_repeating=true` 时生效，`0` 表示不限制次数。 |
| `is_hidden` | boolean | 是 | 是 | 是否隐藏；当前表单级创建和更新接口不接受该字段，按平台返回值只读。 |
| `style` | object | 否 | 否 | 表单样式；当前表单级创建和更新接口不接受该字段。 |
| `is_display_controlled` | boolean | 是 | 是 | 是否被逻辑控制配置为受控展示，服务端计算，只读。 |
| `is_repeating_controlled` | boolean | 是 | 是 | 是否被逻辑控制配置为受控重复，服务端计算，只读。 |
| `count_rated_total_field` | integer | 是 | 是 | 额定字段总数，服务端计算，只读。 |
| `count_required_field` | integer | 是 | 是 | 必填字段总数，服务端计算，只读。 |
| `alteration` | string | 否 | 否 | 相对已发布方案的变更标记，只读；空字符串表示无变更，`ADDED` 表示新增，`EDITED` 表示变更，`MOVED` 表示移位，`DELETED` 表示删除。列表接口不返回已标记删除的设计。 |
| `is_invalid` | boolean | 否 | 不适用 | 设计态表单是否失效，服务端计算，只读。 |
| `invalid_messages` | string[] | 否 | 不适用 | 设计态表单失效原因列表，只读。 |
| `is_rtsm_related` | boolean | 是 | 是 | 是否与 RTSM 关联，只读。RTSM 关联表单不能删除，也不能从不重复改为重复。 |
| `is_epro_related` | boolean | 是 | 是 | 是否与 ePRO 关联，只读。ePRO 关联表单不能删除。 |
| `subs` | array | 是 | 是 | 下级字段组和字段树；字段组与字段的具体结构见[字段组与字段设计使用说明](design-form-item.md)。 |
| `edit_checks` | array | 是 | 是 | 关联的逻辑核查列表。 |
| `logics` | array | 是 | 是 | 关联的逻辑控制列表。 |
| `computations` | array | 是 | 是 | 关联的自动计算列表。 |

### 对象与 ID 边界

- 正式定义 `*_def` 绑定指定 `meta_data_version_id`，只能读取；定义 ID 不能传给任何 `*_dsn` 写接口。
- 草稿设计 `*_dsn` 是当前项目表单级写操作的唯一目标。表单、字段组和字段 ID 都必须从当前项目设计态结果唯一解析。
- 名称清单用于快速取得表单与字段层级候选，不能替代完整表单读取。执行会受下级结构或关联规则影响的操作前，必须读取完整表单。

## 查询表单模板（只读）

系统表单模板库提供可参考的完整表单结构（字段组、字段、自动计算、逻辑控制和逻辑核查）。两个接口都要求当前角色具备 `PRJ_SETTINGS_DESIGN_EDIT`，且项目方案处于设计中；只读，不会把模板写入项目。

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取表单模板列表 | `GET` | `/api/project/settings/design/form/list_form_tpl/` | `--query`：`keyword` = 名称、描述或备注关键词，最长 16 字符（可选）；`limit` = 1–100（可选，省略或 0 时平台按 10 处理）；`offset` ≥ 0（可选） |
| 获取完整表单模板 | `GET` | `/api/project/settings/design/form/get_form_tpl/` | `--query`：`id` = 模板列表唯一定位的表单模板 ID（必填） |

列表返回 `list`（`FormTpl[]`）和 `total`，按模板全局排序；完整模板返回 `FormTpl`，含 `vid`、`name`、表单属性、`subs` 下级结构及 `computations`、`logics`、`edit_checks`。分页按 `total` 读完再判断模板是否存在。

模板只是参考结构，没有“从模板创建”的接口。模板 ID 与项目内表单设计 ID 不可混用。

需要沿用模板时，先与用户提供的 CRF 和方案逐项比对，建立 CRF 原文映射：记录文档版本、来源位置、原文和目标表单／字段，保留原题号、完整题干、选项及编码、单位和说明，逐项说明模板与原文的差异及取舍依据。不能自行增删问题或改写采集语义；资料不明确或存在冲突时，仅暂停受影响项并向用户澄清。再用本页和[字段组与字段设计使用说明](design-form-item.md)中的创建接口逐项写入；模板的 `vid`、选项编码、单位和核查规则不能未经确认直接套用，也不能因模板含有某字段就替用户新增采集项。写后回读实际配置，与同一份原文映射逐项核验。

## 编辑表单设计（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 创建表单设计 | `POST` | `/api/project/settings/design/form/create_form_dsn/` | `--body`：`vid` = 已确认且在当前项目唯一的表单 VID（必填）；`name` = 已确认的表单名称（必填）；`description`、`comment`、`is_optional`、`has_change_info`、`is_repeating`、`repeating_limit` = 已确认的表单属性（可选）；`default_sdtm_domain_id` = 默认 SDTM 数据域 ID，`0` 为不设置（可选，只作为该表单之后新建字段的初始数据域） |
| 变更表单设计 | `POST` | `/api/project/settings/design/form/update_form_dsn/` | `--body`：`id` = 最新表单设计列表返回的表单设计 ID（必填）；`vid`、`name`、`description`、`comment`、`is_optional`、`has_change_info`、`is_repeating`、`repeating_limit`、`default_sdtm_domain_id` = 已确认且实际变化的字段（可选；省略的字段保持原值） |
| 排序表单设计 | `POST` | `/api/project/settings/design/form/rank_form_dsn/` | `--body`：`id` = 最新表单设计列表返回的表单设计 ID（必填）；`ranking` = 根据当前完整表单列表确认的目标正整数顺序（必填） |
| 删除表单设计演练 | `POST` | `/api/project/settings/design/form/delete_form_dsn_dry_run/` | `--body`：`ids` = 从最新表单设计列表唯一定位、去重且非空的表单设计 ID 数组（必填） |
| 删除表单设计 | `POST` | `/api/project/settings/design/form/delete_form_dsn/` | `--body`：`ids` = 与最近一次成功删除演练完全相同的表单设计 ID 数组（必填，不得新增、删减、替换或重排） |

`default_sdtm_domain_id` 必须是当前项目 SDTM 数据域候选中实际返回的 ID，按[数据字典与 SDTM 数据域使用说明](design-data-dictionary.md)读取；修改默认数据域不改变已有字段的数据域关联。

### 写接口返回内容

| 接口 | 业务返回内容 |
| --- | --- |
| 创建表单设计 | 新创建的 `FormDsn`。服务端将其追加到当前表单列表末尾；响应成功后仍须按返回 `id` 回读确认。 |
| 变更表单设计 | 无 |
| 排序表单设计 | 无 |
| 删除表单设计演练 | 必填的 `will_affect_patient_count`（integer）：正式删除预计影响的研究参与者数量；必填的 `will_delete_form_data_count`（integer）：正式删除预计删除的表单数据数量。两个计数都只是影响预览，不是已删除结果。 |
| 删除表单设计 | 无 |

变更、排序和删除接口响应成功后仍必须回读当前表单设计列表或同一完整表单，不得仅凭写请求成功推断最终状态。

### 表单属性与重复采集

- `vid` 在当前项目的未删除表单设计中大小写不敏感唯一。创建或更新发生冲突时保留平台错误，不得自动改名、改 `vid` 或重复提交。
- `name` 可以重复，不能单凭名称选择写入目标；同名时必须结合 `vid`、`id` 和完整结构唯一定位。
- `repeating_limit` 只在 `is_repeating=true` 时生效，`0` 表示不限次数；接口不会因为 `is_repeating=false` 自动拒绝非零限制，因此不能把该组合解释为生效的重复上限。
- RTSM 关联表单不能从 `is_repeating=false` 改为 `true`。任何重复属性变化都可能使引用该表单的逻辑核查失效；改为重复还会使不允许重复表单的自动计算失效，并触发随访通知规则有效性重算。
- 更新接口只提交实际要修改的字段。省略字段表示保持不变，不能用空字符串、`false` 或 `0` 代替“未修改”。

### 删除和联动限制

- 删除多个表单时，所有 ID 必须属于同一当前项目；不存在、已删除、重复或无法唯一定位的表单不能作为目标。
- 删除前必须先调用删除演练接口，读取 `will_affect_patient_count` 和 `will_delete_form_data_count`。任一影响计数大于 0 时，向用户说明预计影响；仅当已有授权覆盖同一目标及这些实际影响时正式删除，否则先补充确认；两个计数都为 0 时，无需展示零值影响，也不再追加一次影响确认，可按用户已经明确的删除意图继续。用户只要求查询影响时，返回演练结果后停止。
- 正式删除必须使用与最近一次成功演练完全相同且顺序一致的 `ids`；目标增删、替换或重排后都必须重新演练。
- RTSM 关联表单和 ePRO 关联表单不能删除。
- 已发布过方案时，删除通常将既有 DSN 标记为 `DELETED`，本轮新增对象可直接移除；从未发布过方案时可直接删除设计记录。两种情况都会从后续表单设计列表中移除目标。
- 删除表单会删除事件与表单的关联，并使引用被删表单的范围检查、逻辑核查、逻辑控制、自动计算及其条件、参数或目标失效；同时会重新计算关联随访通知规则的有效性。

### 结果核验

新增、修改、排序或删除表单时，必须先 GET 获取变更前表单列表，完成写操作后再次 GET 获取变更后列表，并用 Markdown 表格向用户反馈实际 diff。删除演练只返回影响，不算正式变更。

单个表单属性发生变化时，可以使用属性对比表：

| 属性 | 变更前 | 变更后 | 结果 |
| --- | --- | --- | --- |
| 表单名称 | 生命体征表 | 生命体征表（修订） | 已生效 |
| `is_repeating` | `false` | `true` | 已生效 |
| `repeating_limit` | `0` | `3` | 已生效 |
| 表单排序 | `3` | `2` | 已生效 |

当一次操作包含多个表单或多个变更条目时，必须使用批量变更表格：每行表示一个表单条目，第一列固定为变更类型，只能填写“新增”“变更”“删除”或“排序”；后续各列按表单属性展开，例如 `vid`、名称、是否重复、是否选填和排序。表格展示变更后的值，原值紧随其后并使用删除线标记。新增条目的原值留空，删除条目的变更后值留空并只保留删除线原值。

| 变更类型 | `vid` | 表单名称（`name`） | 是否重复（`is_repeating`） | 排序（`ranking`） |
| --- | --- | --- | --- | --- |
| 新增 | AE_FORM | 不良事件表 | 否 | 5 |
| 变更 | VS_FORM | 生命体征表（修订）<br>~~生命体征表~~ | 是<br>~~否~~ | |
| 删除 | ~~LAB_FORM~~ | ~~实验室检查表~~ | | |
| 排序 | | | | 2<br>~~3~~ |

如果用户要求展示全量结果，表格仍需逐行展示所有表单；没有发生变化的属性留空，不要用“无变化”填充。批量变更表格可在全量结果之前作为变更摘要。

表格中的值必须来自前后两次 GET 响应。如果 GET 失败、表单未出现、删除后仍存在，或属性与预期不一致，应报告“变更未确认生效”，不得仅依据写接口成功响应作出结论。
