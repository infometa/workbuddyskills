# 分组设计使用说明

分组用于组织研究参与者所属的方案组别，并通过分组—事件矩阵决定各组适用的事件。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询分组设计与定义 | 获取当前项目设计态分组，或指定方案版本的正式分组定义 | 否 |
| 编辑分组设计 | 创建（含演练）、变更、排序、删除（含演练）分组设计 | 是 |

## 查询分组设计与定义（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取当前分组设计 | `GET` | `/api/project/settings/design/arm/list_arm_dsn/` | 无 |
| 获取已发布分组定义 | `GET` | `/api/project/settings/design/arm/list_arm_def/` | `--query`：`meta_data_version_id` = 先从当前项目方案版本列表唯一定位的方案版本 ID（必填） |

### 只读接口返回内容

两个只读接口成功时的业务返回内容都是包含必填 `list` 属性的对象：

| 接口 | `list` 类型 | 定义 |
| --- | --- | --- |
| 获取当前分组设计 | `ArmDsnName[]` | 当前项目按 `ranking` 升序排列的设计态分组列表，是后续设计写操作定位 `id` 和写后回读的唯一依据。 |
| 获取已发布分组定义 | `ArmDefName[]` | 指定方案版本按 `ranking` 升序排列的正式分组定义列表，只读；其中的定义 ID 不能作为设计态写操作的分组 ID。 |

`ArmDsnName` 与 `ArmDefName` 的属性定义如下；表中适用于对应对象的属性均为必填：

| 属性 | 类型 | `ArmDsnName` | `ArmDefName` | 定义 |
| --- | --- | --- | --- | --- |
| `id` | integer | 是 | 是 | 分组 ID，正整数。设计 ID 与正式定义 ID 不可混用于设计写操作。 |
| `name` | string | 是 | 是 | 分组名称；设计写入时长度为 1–16。名称不要求唯一，定位目标时必须结合 `vid` 和上下文。 |
| `vid` | string | 是 | 是 | 分组变量名；设计写入时长度为 1–32，须匹配 `^[A-Z_][A-Z0-9_]*$`（大写字母或下划线开头，后续仅大写字母、数字或下划线；不接受小写，后端不自动转换），并在同一项目内大小写不敏感唯一。 |
| `ranking` | integer | 是 | 是 | 分组排序位置，正整数。创建时追加到末尾；排序目标超过最大位置时归一到最大可用位置。 |
| `alteration` | string | 是 | 是 | 设计变更标记，只读：空字符串表示无变更，`ADDED`、`EDITED`、`MOVED`、`DELETED` 分别表示新增、变更、移位、删除。 |
| `is_invalid` | boolean | 是 | 不适用 | 分组设计是否失效，服务端只读计算值。 |
| `invalid_message` | string | 是 | 不适用 | 分组设计的失效原因；没有失效原因时为空字符串。 |
| `is_rtsm_related` | boolean | 是 | 不适用 | 分组是否被 RTSM 关联使用，只读；为 `true` 时不能删除。 |

只使用平台实际返回的分组 ID 与状态。空列表只表示本次读取没有对应分组；缺失、空列表或部分响应不得被补造为默认分组。

## 编辑分组设计（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 创建分组设计演练 | `POST` | `/api/project/settings/design/arm/create_arm_dsn_dry_run/` | 无（省略 `--body`） |
| 创建分组设计 | `POST` | `/api/project/settings/design/arm/create_arm_dsn/` | `--body`：`vid` = 紧邻的创建演练返回的候选 `vid`（必填）；`name` = 已确认的分组名称（必填） |
| 变更分组设计 | `POST` | `/api/project/settings/design/arm/update_arm_dsn/` | `--body`：`id` = 最新分组设计列表返回的分组设计 ID（必填）；`name`、`vid` = 已确认且实际发生变化的字段（可选，至少提供一个） |
| 排序分组设计 | `POST` | `/api/project/settings/design/arm/rank_arm_dsn/` | `--body`：`id` = 最新分组设计列表返回的分组设计 ID（必填）；`ranking` = 根据当前完整分组列表确认的目标顺序（必填，正整数） |
| 删除分组设计演练 | `POST` | `/api/project/settings/design/arm/delete_arm_dsn_dry_run/` | `--body`：`ids` = 从最新分组设计列表唯一定位、去重且非空的分组设计 ID 数组（必填） |
| 删除分组设计 | `POST` | `/api/project/settings/design/arm/delete_arm_dsn/` | `--body`：`ids` = 与最近一次删除演练完全相同的分组设计 ID 数组（必填，不得新增、删减或替换） |

### 写接口返回内容

| 接口 | 业务返回内容 |
| --- | --- |
| 创建分组设计演练 | `vid`（string）：平台预生成的分组变量名，只作为本次正式创建的候选值；演练成功不表示分组已创建。 |
| 创建分组设计 | 新创建的设计态分组，字段见上文；响应成功后仍须按返回 `id` 回读确认。 |
| 变更分组设计 | 无 |
| 排序分组设计 | 无 |
| 删除分组设计演练 | `will_affect_patient_count`（integer）：预计影响的生产研究参与者数量；`will_delete_event_data_count`（integer）：预计影响的研究参与者在分组相关事件中的事件数据数量。两个计数都只是影响预览。 |
| 删除分组设计 | 无 |

变更、排序和删除接口响应成功后仍必须回读分组设计列表，不得仅凭写请求成功推断最终状态。

### 创建、变更与排序约束

- 创建前先执行创建演练，并使用紧邻演练返回的 `vid`；`vid` 必须匹配 `^[A-Z_][A-Z0-9_]*$`，小写不会被后端自动转为大写，且与当前项目未删除分组的 `vid` 大小写不敏感唯一。
- 分组名称和 `vid` 的写入长度分别为 1–16 和 1–32。名称可以重复，因此不能只按名称猜测分组 ID。
- 创建分组后，服务端会自动建立该分组与当前项目全部未删除事件的关联；后续差异化关系由分组—事件矩阵维护。
- 变更只接受实际变化的 `name` 或 `vid`；没有实际变化时平台拒绝请求。排序必须基于完整列表；目标顺序超过最大排序时会归一到最大位置，并同步调整途经分组。

### 删除和影响限制

- 删除多个分组时，所有 ID 必须属于同一项目；不存在或已删除的分组不能作为目标。
- 删除前必须调用删除演练。方案未启用“按分组配置不同事件”时，两个影响计数均为 0；启用时，平台统计所选分组下生产研究参与者数量，以及这些参与者在分组相关事件中的事件数据数量。
- 任一影响计数大于 0 时，向用户说明预计影响；仅当已有授权覆盖同一目标及这些实际影响时正式删除，否则先补充确认；两个计数都等于 0 时，无需展示零值影响，也不再提示用户确认，可按用户已明确的删除意图继续正式删除。用户只要求查询影响时，返回演练结果后停止。
- 正式删除的 `ids` 必须与最近一次演练完全一致。RTSM 关联分组不能删除；即使演练成功，正式删除仍会执行该关联校验。
- 已发布过方案时，目标分组会标记为已删除；尚未正式发布过方案时会直接删除记录。删除后服务端会把剩余分组重新排为连续顺序。

### 结果核验

新增、修改、排序或删除分组时，必须先 GET 获取变更前分组列表，完成写操作后再次 GET 获取变更后列表，并用 Markdown 表格向用户反馈实际差异。删除演练只返回影响，不算正式变更。

一次操作包含多个条目时，每行表示一个分组，第一列只能填写“新增”“变更”“删除”或“排序”；后续按 `vid`、名称、排序等属性展开。展示变更后的值，原值紧随其后并用删除线标记；新增的原值留空，删除只保留删除线原值，没有变化的属性留空。

| 变更类型 | `vid` | 分组名称（`name`） | 排序（`ranking`） |
| --- | --- | --- | --- |
| 新增 | ARM03 | 第三组 | 3 |
| 变更 | ARM02 | 试验组（修订）<br>~~试验组~~ | |
| 删除 | ~~ARM01~~ | ~~对照组~~ | |
| 排序 | | | 1<br>~~2~~ |

表格值必须来自前后两次 GET 响应；如果 GET 失败、分组未出现、删除后仍存在或属性与预期不一致，应报告“变更未确认生效”，不得仅依据写接口返回成功得出结论。
