# 逻辑控制使用说明

逻辑控制用于按字段值控制字段组或字段的展示状态。当前设计态逻辑控制只支持“展示控制”这一种操作：一个目标字段组或字段，配一个简单比较条件和一个字段参数。指定方案版本中的正式定义只能读取，不能直接修改。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询逻辑控制设计 | 分页读取当前项目的设计态逻辑控制、完整条件和失效状态 | 否 |
| 查询逻辑控制定义 | 分页读取指定方案版本的正式逻辑控制定义 | 否 |
| 编辑逻辑控制设计 | 创建、按 ID 更新或批量删除逻辑控制设计 | 是 |

本页覆盖逻辑控制对象、查询筛选、实际支持的逻辑类型与目标组合、创建/更新/删除约束、依赖变化和写后核验。通用条件对象、比较器与字段类型兼容矩阵见[条件对象结构](design-condition-schema.md)；目标表单、字段组和字段必须通过当前设计态或定义态读取接口唯一定位。

## 查询逻辑控制（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取逻辑控制设计列表 | `GET` | `/api/project/settings/design/logic/list_logic_dsn/` | `--query`：`limit` = `10–100`（必填）；`offset` = 非负分页偏移（可选）；`form_dsn_id` = 目标表单设计 ID（可选）；`is_invalid` = 失效状态（可选）；`keyword` = 名称或序列号关键词，最长 16 字符（可选） |
| 获取逻辑控制定义列表 | `GET` | `/api/project/settings/design/logic/list_logic_def/` | `--query`：`meta_data_version_id` = 从当前项目方案版本列表唯一定位的方案版本 ID（必填）；`limit` = `10–100`（必填）；`offset` = 非负分页偏移（可选）；`form_def_id` = 目标表单定义 ID（可选）；`keyword` = 名称或序列号关键词，最长 16 字符（可选） |

设计列表按 `id` 升序分页；定义列表按 `number` 升序分页。需要完整结果时，从 `offset=0` 开始按页读取，直到已取得条数达到 `total`；单页没有目标不能证明逻辑控制不存在。

### 查询范围与筛选语义

- 设计列表返回当前项目中 `alteration <> DELETED` 的 `LogicDsn`。它不需要 `meta_data_version_id`，也不会把正式定义 ID 转换成设计 ID。
- 定义列表通过 `meta_data_version_logic_def` 只返回指定 `meta_data_version_id` 关联的 `LogicDef`。定义态 `logic_def`、`condition_def`、`parameter_def` 及其 `*VID` 都只能查看，不能传给任何 `*_dsn` 写接口。
- `form_dsn_id` / `form_def_id` 都按逻辑控制目标所在表单筛选，本质上是过滤 `condition.target_form_*_id`，不是按条件参数所在表单模糊筛选。
- 两个列表的 `keyword` 都同时匹配 `sn` 和 `name`，并对通配符做转义，不支持正则或自定义模糊语法。
- 设计列表成功时，`invalid_count` 基于同一 `project_id`、`keyword`、`form_dsn_id` 过滤范围统计全部失效逻辑数量，不受 `is_invalid` 筛选限制；`total` 则受 `is_invalid` 影响。
- `form_dsn_id` 或 `form_def_id` 过滤会通过条件表连接后再 `Distinct` 去重；因此设计态与定义态筛选都以“逻辑控制”为计数单位，而不是条件或参数为单位。

名称和序列号都不是设计态写接口的授权依据。更新和删除前必须从当前设计列表唯一定位 `logic_dsn.id`；分页未读全、同名候选并存或目标父级不清楚时先澄清，不得猜测。

### 逻辑控制返回字段

`LogicDsn` 与 `LogicDef` 共享以下核心属性。设计态对象额外包含失效状态；定义态条件和参数额外回填定义变量名。

| 属性 | 类型 | 定义 |
| --- | --- | --- |
| `id` | integer | 逻辑控制 ID。设计 ID 与定义 ID 属于不同对象空间，不得跨态混用。 |
| `project_id` | integer | 仅定义态返回项目 ID。设计态列表项不单独暴露该字段。 |
| `number` | integer | 平台生成的项目内顺序编号，只读，不由请求指定。 |
| `sn` | string | 平台生成的序列号，例如 `L00001`，只读，请求不能指定。 |
| `name` | string | 逻辑控制名称；创建和更新时最长 2048 字符。 |
| `is_name_manual` | boolean | 名称是否由请求显式指定。省略名称或把名称更新为空串时，服务端会改回自动命名。 |
| `logic_type` | string | 逻辑类型。当前设计态写接口实际只接受 `DISPLAY`。 |
| `condition` | object | 完整条件对象。设计态为 `ConditionDsn`，定义态为 `ConditionDef`。 |
| `alteration` | string | 相对已发布方案的变更标记，只读。 |
| `is_invalid` | boolean | 仅设计态：逻辑控制是否因依赖变化而失效，只读。 |
| `invalid_messages` | string[] | 仅设计态：逻辑控制失效原因，由后端按逻辑控制专属失效码映射成中文文本。 |

定义态 `ConditionDef` / `ParameterDef` 会把 `target_*_def_id`、`parameters[*].*_def_id` 对应的 `*VID` 一并回填；设计态没有这些 `VID` 字段。这些定义态 ID 和变量名都不能反向填入设计态写请求。

## 编辑逻辑控制设计（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 创建逻辑控制设计 | `POST` | `/api/project/settings/design/logic/create_logic_dsn/` | `--body`：`logic_type` = `DISPLAY`（必填）；`condition` = 已确认的完整逻辑控制条件（必须提供）；`name` = 逻辑控制名称（可选，最长 2048 字符） |
| 更新逻辑控制设计 | `POST` | `/api/project/settings/design/logic/update_logic_dsn/` | `--body`：`id` = 最新设计列表唯一定位的逻辑控制设计 ID（必填）；`name` = 新名称（可选，最长 2048 字符）；`logic_type` = `DISPLAY`（可选）；`condition` = 新条件（可选，提供时需携带完整可校验对象） |
| 删除逻辑控制设计 | `POST` | `/api/project/settings/design/logic/delete_logic_dsn/` | `--body`：`ids` = 从最新设计列表唯一定位的逻辑控制设计 ID 数组（必填、非空、全部大于 0） |

所有设计态写接口都要求当前项目具备方案设计编辑权限，且项目处于可写状态。平台拒绝时保留真实错误，不得通过改 ID、拆请求或降级逻辑绕过。

### 写接口返回内容

| 接口 | 业务返回内容 |
| --- | --- |
| 创建逻辑控制设计 | 新创建的 `LogicDsn`，包含服务端生成的 `id`、`number`、`sn`、自动名称状态、条件与失效状态。响应成功后仍须按返回 `id` 回读确认。 |
| 更新逻辑控制设计 | 无；必须通过设计列表回读确认名称、类型、条件和失效状态。 |
| 删除逻辑控制设计 | 无；必须通过设计列表回读确认全部目标均已消失。 |

创建、更新或删除前先分页读取逻辑控制设计，并读取目标表单、字段组、字段及条件参数引用的字段候选。写请求成功不代表最终结构已经确认，也不代表逻辑控制已进入正式方案。

### 实际支持的逻辑类型与条件对象

逻辑控制写接口在创建与更新时只接受 `logic_type=DISPLAY`，公共枚举中的 `REQUIRED`、`REPEATING`、`SET_VALUE`、`JUMP_TO` 不可用。条件对象只支持下面这一组组合：

| 维度 | 写入支持 |
| --- | --- |
| `logic_type` | 只支持 `DISPLAY` |
| `condition.condition_type` | 只支持 `CONDITION_SIMPLE` |
| `condition.target_variable_type` | 只支持 `FIELD`、`SECTION` |
| `condition.condition_unit.type` | 只支持单个 `COMPARE` |
| `condition.parameters` | 必须且只能有一个参数 |
| `condition.parameters[0].parameter_type` | 只支持 `FIELD_DATA_VALUE` |
| 右值来源 | 只能使用常量 `check_values`，不能使用右参数 |

请求必须同时满足以下约束：

- 创建和更新都在入口直接拒绝非 `DISPLAY`、非 `CONDITION_SIMPLE`、非 `FIELD`/`SECTION` 目标，以及非 `COMPARE` 条件单元。
- 公共 `ConditionDsnItem` 对简单条件要求 `left_parameter_number = 0`，并要求 `len(right_parameter_numbers) == len(parameters) - 1`。当前参数固定只有一个，因此逻辑控制天然不能有右参数比较。
- 条件参数和目标字段/字段组的父级由服务端按真实字段、字段组归属补齐；不要试图用请求中的 `target_form_dsn_id`、`target_section_dsn_id`、`parameters[*].form_dsn_id` 改挂父级。
- `target_scope_type`、`target_event_dsn_ids`、`formal_expression` 属于公共条件结构，但逻辑控制写路径不赋予它们业务语义；应省略而不是猜测用途。

### 目标层级、重复与循环依赖

- 目标为 `FIELD` 时，条件参数字段不能与目标字段相同；两者必须位于同一字段组下，或都直接位于表单下。
- 目标为 `SECTION` 时，条件参数字段必须与目标字段组处于同一层级，也就是目标字段组的 `parent_id` 必须等于参数字段的 `section_dsn_id`。
- 同一个字段或字段组当前只能作为一条 `DISPLAY` 逻辑控制的目标。当前重复校验只看目标对象，不比较条件语义；只要目标已被另一条展示控制占用，就会拒绝再次创建或更新到该目标。
- 平台会在同一层级内检查展示依赖是否形成循环。新增或改目标时，如果当前显示控制链会让某个被依赖字段无法展示，接口会直接拒绝。
- 创建后或目标变更后，服务端会把目标字段或字段组标记为 `is_display_controlled=true`；更新改目标或删除逻辑时，会重新计算旧目标和新目标的展示受控状态。

### 条件比较约束

- 左参数字段支持的比较器，遵循[条件对象结构](design-condition-schema.md)中的字段类型兼容矩阵。
- `IS_NULL` / `NOT_NULL` 不接受 `check_values` 或 `right_parameter_numbers`。
- `IN`、`NOT_IN`、`CONTAINS`、`NOT_CONTAINS` 至少要有一个常量值。
- 其他比较器在逻辑控制里必须使用非空 `check_values`，因为当前不允许右参数。
- `check_values` 始终按字符串数组传输。平台不会把它们解释成指令，也不会替你把常量映射成字段选项、数值或日期语义；提交前仍须按目标字段的 `data_type`、`resp_type` 和选项 `data_value` 自行核对。
- 逻辑控制不会沿用逻辑核查那套递归空值/日期偏移归一化。构造简单比较时，应主动省略无关的 `right_parameter_numbers`、日期偏移和组合节点字段。
- 唯一参数的 `parameter_resolution` 使用 `EVERY_IN_FORM_DATA`。它描述在每个适用表单数据实例中解析条件字段，不能用来绕过同表单和同层级约束。

### 创建语义

- `name` 可省略。省略时平台生成默认名称，并把 `is_name_manual` 设为 `false`；显式传入非空名称时 `is_name_manual=true`。
- 创建不支持“无条件逻辑”，必须提供完整且可校验的 `condition`。
- 如果项目已有已发布方案，新建逻辑、条件和参数统一标记为 `ADDED`。
- 条件单元可能由平台规范化；写后以完整回读结果核验条件含义与变更状态。

### 更新语义

- 更新接口是按字段可选提交，不是完整替换；只有 `id` 必填。只改名称时可以不提交 `condition`。
- 提供 `condition` 时，接口要求 `condition.id > 0`，且请求里的每个 `condition.parameters[*].id` 都必须大于 `0`；否则直接拒绝。
- 逻辑控制固定只有一个参数，更新时必须保留最新 GET 返回的唯一参数及其 ID，并维持编号 `0`；不能通过重排或改变 ID 请求替换参数身份。
- `name=""` 会把名称切回自动命名；如果原对象本来就是自动命名，且本次更新了条件，服务端也会重新生成名称。
- 更新请求没有实际差异时，平台返回“对象未变化”；不得把空变更改写成创建或删除。
- 更新条件会重新校验目标、参数、比较器、同层级、重复和循环依赖，并清除逻辑控制、条件和参数的旧失效状态；必须通过写后 GET 确认规则已经恢复有效。
- 已发布过方案时，参数变更会向上推动 `condition.alteration` 和 `logic.alteration` 变为 `EDITED`；新增对象保持 `ADDED`。

### 删除与依赖变化

- 删除接口没有 dry-run。用户只要求查看、核对或影响分析时，不得执行删除。
- 一次删除的全部 ID 必须属于同一项目；接口会先按 ID 取出现存逻辑控制，再校验项目一致性。
- 未发布过方案时，删除会直接移除逻辑、条件和参数记录；已发布过方案时，本轮新增对象直接删除，其他对象改记为 `DELETED`。
- 删除后服务端会按每个被删目标重新计算 `is_display_controlled`，因此“删除成功”不等于“目标一定恢复可展示”，仍应以写后回读和目标对象状态为准。
- 字段、字段组、表单、事件或条件参数字段属性变化后，逻辑控制及其条件/参数可能被标记失效。逻辑控制专属 `invalid_messages` 常见原因包括：
  - 变量所在事件已删除
  - 变量字段所在表单已删除
  - 变量字段所在字段组已删除
  - 变量字段已删除
  - 展示内容所在事件已删除
  - 展示内容所在表单已删除
  - 展示内容已删除
  - 变量字段属性已变更

## 结果核验

新增、修改或删除逻辑控制时，必须先 GET 保存变更前的完整设计列表和相关完整表单，完成写操作后再次分页 GET 获取同一筛选范围并回读相关表单，再用 Markdown 表格反馈实际 diff。

单条逻辑控制发生变化时，可以使用属性对比表：

| 属性 | 变更前 | 变更后 | 结果 |
| --- | --- | --- | --- |
| 名称 | 体温字段逻辑控制 | 体温展示控制 | 已生效 |
| 目标 | 生命体征 / 体温 | 生命体征 / 体温 | 已生效 |
| 条件 | 访视类型 = 筛选期 | 访视类型 = 基线期 | 已生效 |
| 有效性 | 失效 | 有效 | 已生效 |

一次操作包含多个逻辑控制时，使用批量变更表格。第一列固定为变更类型，只能填写“新增”“变更”或“删除”；目标路径必须包含完整表单与字段组层级，避免同名字段或字段组混淆。变更后的值在前，原值紧随其后并使用删除线标记；新增条目的原值留空，删除条目只保留删除线原值。

| 变更类型 | `sn` | 名称 | 目标路径 | 逻辑类型 | 条件摘要 | 有效性 |
| --- | --- | --- | --- | --- | --- | --- |
| 新增 | L00012 | 体温展示控制 | 生命体征表 / 生命体征 / 体温 | DISPLAY | 访视类型 = 筛选期 | 有效 |
| 变更 | L00008 | 体重展示控制 | 生命体征表 / 生命体征 / 体重 | DISPLAY | 体重单位 = kg<br>~~体重单位 = jin~~ | 有效 |
| 删除 | ~~L00003~~ | ~~旧版字段展示控制~~ | ~~生命体征表 / 生命体征 / 血压~~ | ~~DISPLAY~~ | ~~访视类型为空~~ | |

条件摘要必须来自前后两次 GET 的完整条件对象，并翻译成不丢失比较器、常量和目标层级的中文含义。还要回读目标字段或字段组的 `is_display_controlled`；如果 GET 失败、新对象未出现、删除对象仍存在、返回条件与预期不一致、目标受控状态不一致，或者 `is_invalid=true`，应报告“变更未确认生效”或“已写入但逻辑控制失效”，不得仅依据写接口成功响应作出结论。
