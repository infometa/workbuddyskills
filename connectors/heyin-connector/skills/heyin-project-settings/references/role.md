# 角色与权限配置使用说明

角色用于定义项目成员在当前项目中的操作权限和数据作用范围。项目级角色作用于整个项目，中心级角色只作用于明确分配的中心；同一成员可以持有多个角色。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询角色与权限 | 按级别获取角色列表、权限目录或角色模板权限编码集 | 否 |
| 查询角色成员与中心 | 获取角色当前成员、可添加成员及中心级角色可选的生效中心 | 否 |
| 编辑角色 | 创建角色，更新角色名称或完整权限集合，删除自定义角色 | 是 |
| 编辑成员分配 | 添加或移除角色成员，调整中心级角色成员的生效中心 | 是 |

## 权限要求

按 [项目设置使用指南](../SKILL.md) 选择项目凭证，通过 `heyincli req` 调用下列接口。项目、角色、角色模板、成员和中心 ID 必须来自实际查询结果，不能互换。角色分配中的中心集合按本接口规则选择，不套用中心配置批量操作必须同类型的限制。

- 查询角色列表、权限列表和角色模板权限编码集需要 `PRJ_SETTINGS_ROLE_ACCESS` 权限；创建、更新和删除角色需要 `PRJ_SETTINGS_ROLE_EDIT` 权限。
- 查询角色分配、可添加成员和可选生效中心需要 `PRJ_SETTINGS_MEMBER_ACCESS` 权限；分配成员、取消成员分配和调整生效中心需要 `PRJ_SETTINGS_MEMBER_EDIT` 权限。

## 查询角色与权限（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取角色列表 | `GET` | `/api/project/settings/role/list_role/` | `--query`：`scope` = `PROJECT` 或 `SITE`（必填）；`keyword` = 匹配角色名称或编码的关键词（可选，最长 32） |
| 获取权限列表 | `GET` | `/api/project/settings/role/list_permission/` | `--query`：`scope` = `PROJECT` 或 `SITE`（必填） |
| 按角色模板获取权限编码集 | `GET` | `/api/project/settings/role/list_permission_by_role_tpl/` | `--query`：`role_tpl_id` = 角色列表实际返回的项目级或中心级模板 ID（必填） |
| 获取角色分配列表 | `GET` | `/api/project/settings/role/list_role_assignment/` | `--query`：`role_id` = 角色列表实际返回的角色 ID（必填） |
| 获取可添加成员列表 | `GET` | `/api/project/settings/role/list_member_user/` | `--query`：`role_id` = 角色列表实际返回的角色 ID（必填）；`limit` = 10–100（必填）；`offset` = 非负分页偏移（可选）；`keyword` = 匹配姓名或用户名的关键词（可选，最长 16） |
| 获取可选生效中心列表 | `GET` | `/api/project/settings/role/list_site/` | `--query`：`status`、`special`、`keyword` = 中心状态、生产/测试类型和编号或名称关键词筛选（可选） |

只有可添加成员列表使用 `limit`、`offset` 分页，通过 `--query` JSON 传递；按返回的 `total` 继续获取，直到覆盖目标。角色列表虽然返回 `list` 和 `total`，其接口不接收分页参数。项目级和中心级角色分别使用 `scope=PROJECT` 与 `scope=SITE` 查询。

角色的可选生效中心接口中，省略 `special` 表示全部可见中心类型，显式传 `special=""` 只查询生产中心，传 `special="TEST"` 只查询测试中心；`status` 省略或留空表示全部状态。项目未开启测试环境时不返回测试中心。此处不沿用中心配置列表省略 `special` 时仅查询生产中心的规则。

中心筛选字段均为字符串：`keyword` 最长 32；`status` 可取空字符串、`STARTED`、`ENROLLING`、`FINISH_ENROLLMENT`、`LOCKED`、`CLOSED` 或 `SUSPENDED`。角色作用域使用项目业务允许的 `PROJECT` 或 `SITE`，不因共用枚举还包含系统、组织作用域就扩展本接口的使用范围。

### 只读接口返回内容

| 接口 | 业务返回内容 | 定义 |
| --- | --- | --- |
| 获取角色列表 | 必填的 `list`（`RoleWithCount[]`）和 `total`（integer） | `scope` 指定级别的角色列表及筛选结果总数；角色按 ID 升序返回。 |
| 获取权限列表 | 必填的 `list`（`PermissionCategory[]`） | 对应级别的权限目录，按“分类 / 模块 / 权限”三层组织；目录顺序即平台定义的展示顺序。 |
| 按角色模板获取权限编码集 | 必填的 `codes`（string[]） | 模板权限编码集合，只用于恢复内置权限或复制权限的候选值，不直接修改角色。 |
| 获取角色分配列表 | 必填的 `members`（`RaMS[]`） | 指定角色的当前成员；一个成员一条，中心级角色的多个生效中心合并在 `sites` 中。 |
| 获取可添加成员列表 | 必填的 `list`（`MemberWithRoles[]`）和 `total`（integer） | 当前项目中尚未持有指定角色的候选成员及分页总数。 |
| 获取可选生效中心列表 | 必填的 `list`（`SiteName[]`） | 当前项目中可用于中心级角色分配的中心；项目未开启测试环境时不返回测试中心。 |

角色列表中的 `RoleWithCount` 具有以下核心属性：

| 属性 | 类型 | 定义 |
| --- | --- | --- |
| `id` | integer | 当前项目角色 ID，是角色写操作和成员分配的唯一定位依据。 |
| `scope` | string | 角色级别：`PROJECT` 或 `SITE`；创建后不可修改。 |
| `code` | string | 角色编码；创建后不可修改。 |
| `name` | string | 角色名称。 |
| `role_tpl_id` | integer，可选 | 派生模板 ID；大于 0 表示内置角色。 |
| `role_tpl_name` | string，可选 | 派生模板名称。 |
| `role_tpl_is_root` | boolean，可选 | 是否为项目根角色；项目根角色名称不可修改。 |
| `permissions` | `Permission[]`，可选 | 当前角色的权限项。权限项中的 `is_required=true` 表示内置角色必须保留该权限。 |
| `member_count` | integer | 持有该角色的项目成员数；同一成员在多个中心持有该中心级角色时只计一次。 |

权限项包含 `category`、`module`、`scope`、`code`、`kind`、`depends_on`、`name`，以及在角色模板上下文中可能出现的 `is_required`。`kind=READ` 表示查看权，`kind=WRITE` 表示操作权；`depends_on` 声明操作权依赖的查看权。只能使用对应级别权限列表实际返回的编码，并保持平台要求的依赖闭包，不能根据名称猜测编码。

角色成员、候选成员与中心对象的核心属性如下：

| 对象 | 核心属性 | 定义 |
| --- | --- | --- |
| `RaMS` | `user_id`、`user_name`、`user_is_activated`、`sites`、`other_roles` | 已持有目标角色的成员。项目级角色的 `sites` 为空数组；中心级角色的 `sites` 是该成员在本角色下的完整生效中心集合。`other_roles` 不包含当前角色。 |
| `MemberWithRoles` | `user_id`、`user_name`、`user_is_activated`、`roles` | 尚未持有目标角色的项目成员；`roles` 是该成员在当前项目已有的其他项目级和中心级角色。 |
| `SiteName` | `id`、`sn`、`name`、`special`、`status` 等 | 可选中心。`special` 为空字符串表示生产中心，`TEST` 表示测试中心。 |

平台响应可能包含 `user_username` 等字段。只使用完成任务所需的非敏感字段，不得恢复、推断或向用户输出 `username`、认证材料或无关上游字段。缺失值保持“未知”，不能根据其他字段反推。

只使用平台实际返回的角色、成员、模板、权限和中心 ID。空列表只表示本次读取没有匹配项；缺失、空列表、部分响应或请求失败不得被补造为默认角色、成员、权限或中心。

## 角色级别与权限

| 角色级别 | 接口值 | 权限范围 | 成员作用范围 |
| --- | --- | --- | --- |
| 项目级 | `PROJECT` | 只能配置项目级权限编码 | 对整个项目生效，成员分配时不能提交中心 ID |
| 中心级 | `SITE` | 只能配置中心级权限编码 | 只对明确分配的一个或多个中心生效，成员分配时必须提交中心 ID |

角色在创建时确定 `scope` 和 `code`，后续只能修改名称和权限集合。项目级与中心级权限目录互不通用；创建或更新角色前必须按角色自身 `scope` 读取最新权限列表。权限列表为空、缺失或请求失败时停止角色写操作，不沿用旧权限编码。

按角色模板获取权限编码集只返回模板的内置权限候选值，不会直接修改角色。恢复内置权限时使用目标角色自己的 `role_tpl_id`；复制内置角色权限时使用来源内置角色的 `role_tpl_id`。获取编码后仍须按目标角色的级别校验，并通过更新角色信息保存完整权限集合。

### 权限配置原则

权限按职责最小授予，配置或分配前对照项目的职责授权表核对：

- **盲态隔离**：`PRJ_BLIND_DATA_ACCESS`、`PRJ_RTSM_UNBLIND` 只授予按方案应知晓分组的非盲角色（如独立统计师、非盲药师）；紧急破盲权限 `PRJ_RTSM_EMERGENCY_UNBLIND`／`SITE_RTSM_EMERGENCY_UNBLIND` 只授予方案规定的研究者。盲态角色与非盲角色分开设置，同一成员需要两类身份时分配不同角色，不把非盲权限加到盲态角色上。
- **职责分离**：数据签名权限（`PRJ_FORM_DATA_SIGNATURE`、`SITE_FORM_DATA_SIGNATURE`、SD 签名）只授予研究者；数据冻结、锁定授予数据管理角色，不授予数据录入角色；SDV 授予监查角色。
- **变更留痕**：角色权限和成员分配的变更由平台记录操作日志；人员离岗、调岗或职责变化时及时取消分配或收缩中心，并提醒用户同步更新线下职责授权表。

用户要求的配置违背上述原则时，说明风险并请用户确认依据，不自行调整为其他方案。

## 编辑角色与成员分配（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 创建角色 | `POST` | `/api/project/settings/role/create_role/` | `--body`：`scope` = `PROJECT` 或 `SITE`（必填）；`code` = 已确认的不可变角色编码（必填）；`name` = 角色名称（必填）；`codes` = 完整权限编码集合（可选，不传表示创建无权限角色） |
| 更新角色信息 | `POST` | `/api/project/settings/role/update_role/` | `--body`：`id` = 最新角色列表返回的角色 ID（必填）；`name` = 新名称（可选）；`codes` = 更新后的完整权限编码集合（可选；不传表示不修改权限，空数组表示请求清空全部权限，内置必留权限不可删除） |
| 删除角色 | `POST` | `/api/project/settings/role/delete_role/` | `--body`：`id` = 最新角色列表返回的自定义角色 ID（必填） |
| 分配角色成员 | `POST` | `/api/project/settings/role/assign_member/` | `--body`：`role_id` = 最新角色列表返回的角色 ID（必填）；`user_ids` = 可添加成员列表唯一定位、去重且非空的用户 ID 数组（必填）；`site_ids` = 中心级角色的生效中心 ID 数组（中心级必填，项目级必须留空） |
| 取消角色成员分配 | `POST` | `/api/project/settings/role/unassign_member/` | `--body`：`role_id` = 最新角色列表返回的角色 ID（必填）；`user_ids` = 当前角色分配列表唯一定位、去重且非空的用户 ID 数组（必填） |
| 更改角色成员的生效中心 | `POST` | `/api/project/settings/role/update_member_site/` | `--body`：`role_id` = 中心级角色 ID（必填）；`user_ids` = 已持有该角色的成员 ID 数组（必填，非空）；`site_ids` = 参与集合运算的中心 ID 数组（必填，非空）；`action` = `ADD`、`REMOVE` 或 `SET`（必填） |

### 写接口返回内容

| 接口 | 业务返回内容 |
| --- | --- |
| 创建角色 | 新创建的角色对象，包含角色 ID、级别、编码、名称、模板信息和权限等投影字段。 |
| 更新角色信息 | 无 |
| 删除角色 | 无 |
| 分配角色成员 | 无 |
| 取消角色成员分配 | 无 |
| 更改角色成员的生效中心 | 无 |

写接口返回成功后仍必须通过相应只读接口回读确认，不得仅凭空响应或请求成功推断最终状态。

### 创建与更新限制

- 创建角色的 `code` 长度为 1–32，必须以字母或下划线开头，且只包含字母、数字或下划线；`name` 长度为 1–16。`code` 和 `scope` 创建后不可修改。`code` 在同一项目、同一级别内大小写不敏感唯一；项目级和中心级可以各自存在相同 `code`。
- 创建时 `codes` 不传表示创建无权限角色；提交 `codes` 时，它表示创建时的完整权限集合。
- 更新时 `codes` 不传表示本次不修改权限，空数组表示请求清空全部权限。不得把增删差异当成 `codes` 提交；必须根据最新权限和用户意图构造更新后的完整集合。
- 权限编码必须全部属于角色自身级别，并满足权限依赖闭包。内置角色中 `is_required=true` 的权限不可删除，即使提交空数组也不能绕过。
- 项目根角色的名称不可修改。没有实际名称或权限变化的更新会被平台拒绝，不能用无变化写请求探测状态。

### 成员与生效中心限制

- 角色、成员和中心必须属于同一当前项目；成员必须是当前项目成员，中心必须是当前项目可选中心。项目未开启测试环境时不能分配测试中心。
- 分配项目级角色时 `site_ids` 必须留空；分配中心级角色时 `site_ids` 必须非空。中心级分配按去重后的成员与中心做笛卡尔积，即每个成员在每个目标中心都获得该角色。
- 分配角色成员具有幂等性：已存在的同一成员—角色—中心分配会被跳过。成功响应不能解释为重复创建了分配，也不能用重复提交代替写后回读。
- 取消成员分配会移除该成员在目标角色下的全部分配。对中心级角色而言，会同时移除该成员在此角色下的所有生效中心，但不影响该成员的其他角色。
- 项目管理员至少保留一名。移除项目根角色成员时，若操作会使项目管理员人数变为零，平台会拒绝。
- 更改生效中心只适用于已经持有目标中心级角色的成员，不能借此接口添加新成员。`ADD` 在当前集合上追加，`REMOVE` 从当前集合移除，`SET` 将完整集合置为本次提交的非空 `site_ids`。
- `REMOVE` 摘掉某成员最后一个生效中心时，该成员也会从此角色移除。调用前必须逐个成员计算并说明操作后的完整中心集合及是否会失去该角色。
- 取消成员分配、删除角色，或把成员的中心级生效中心收缩到不再满足绑定条件时，相关 API 令牌 可能因角色绑定失效而被自动吊销。

### 删除限制与影响

- 只有当前项目的自定义角色可以删除；`role_tpl_id > 0` 的内置角色不能删除。
- 删除前必须通过最新角色列表唯一定位目标，并读取角色分配列表。向用户说明角色名称、ID、级别、权限和受影响成员；不能仅凭名称猜测 ID。
- 删除角色会同时删除其权限配置、全部成员分配及待回复邀请中引用该角色的明细；已接受或已拒绝邀请保留为历史记录。因角色绑定失效而不再满足约束的 API 令牌 可能被吊销。
- 平台没有角色删除演练接口。用户只要求查询删除影响时，返回角色和分配现状后停止，不执行删除。

## 操作限制

按主指南完成写前目标与授权核对。所有写操作要求项目允许修改；权限不足、参数冲突、对象不存在或结果不明时停止，不更换角色、成员或中心，不删减权限或影响范围来绕过拒绝。

角色删除没有演练接口。删除前查询角色及成员分配，展示影响；已有明确授权覆盖同一角色及实际影响时继续，否则先取得确认。修改当前调用凭证绑定的角色或成员分配，可能导致该凭证失效；回读失败时报告未确认，不自动切换身份或重复写入。

## 结果核验

创建、更新或删除角色时，必须在写前和写后分别获取对应级别的角色列表；成员分配、取消分配或生效中心调整时，必须在写前和写后分别获取角色分配列表。用前后两次读取的实际结果向用户反馈变更，不得只复述请求参数。

单个对象的少量属性变化可使用“属性 / 变更前 / 变更后 / 结果”表格。一次操作包含多个角色、成员、权限或中心变化时，使用批量变更表格：第一列固定为变更类型，只填写“新增”“变更”或“删除”；后续列展示变更后的值，原值紧跟其后并使用删除线标记。新增条目的原值留空，删除条目的变更后值留空并只保留删除线原值。未变化的属性留空，不用“无变化”填充。

角色变更示例：

| 变更类型 | 角色 ID | 角色名称 | 级别 | 权限编码 |
| --- | --- | --- | --- | --- |
| 变更 | 18 | 数据审核员（修订）<br>~~数据审核员~~ |  | `PRJ_A`、`PRJ_B`<br>~~`PRJ_A`~~ |

成员与中心变更示例：

| 变更类型 | 成员 ID | 成员姓名 | 角色 | 生效中心 |
| --- | --- | --- | --- | --- |
| 新增 | 203 | 王某 | 中心监查员 | S01、S02 |
| 变更 | 207 | 李某 | 中心监查员 | S02、S03<br>~~S01、S02~~ |
| 删除 | 211 | ~~赵某~~ | ~~中心监查员~~ | ~~S03~~ |

表格中的 ID、名称、权限和中心必须来自前后两次读取。若回读失败、对象未出现、删除后仍存在、成员或中心集合与预期不一致，应报告“变更未确认生效”，不得仅依据写接口返回成功得出已生效结论。
