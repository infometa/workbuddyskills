# RTSM 配置使用说明

使用 `heyincli req` 查询和维护当前项目随机化、盲法及药物供应配置。共用的项目凭证、GET/POST 参数、响应和授权规则见 [项目设置使用指南](../SKILL.md)。本技能不执行研究参与者随机化、揭盲、发药、转运、隔离、失效或恢复等业务操作，也不代替随机化、盲法或药物供应方法学判断。

## 选择领域

| 目标 | 使用说明 |
| --- | --- |
| 随机化开关、静态随机方案、分层因素、分组设计关联、结果回填、随机号、导入和删除 | [随机方案与随机号](rtsm-randomization.md) |
| 盲法和揭盲方式、项目级盲态角色、随机化与 eTMF 关联影响 | [盲法配置](rtsm-blinding.md) |
| 药物供应开关、中央库、药物类型、预警阈值、有效期、发药事件、导入与库存删除 | [药物供应](rtsm-drug-supply.md) |

## 权限与状态

随机化读取需要 `PRJ_SETTINGS_RTSM_ACCESS`，写入需要 `PRJ_SETTINGS_RTSM_EDIT`；分组设计候选由平台按任一项目设置权限校验。盲法读取需要 `PRJ_SETTINGS_BLINDING_ACCESS`，保存需要 `PRJ_SETTINGS_BLINDING_EDIT`，只能在项目准备中保存。

药物供应读取需要 `PRJ_SETTINGS_DRUG_SUPPLY_ACCESS`，写入需要 `PRJ_SETTINGS_DRUG_SUPPLY_EDIT`。随机化与药物供应开关只允许准备期变更；项目启动后药物供应已有配置仅允许有限字段更新。具体状态、许可、生产数据使用约束和级联影响按领域说明核对，不自动切换功能、角色或项目绕过拒绝。

## 环境、导入与盲态

随机号、药物列表及导入、删除接口中的 `is_test_env` 是业务参数，必须在 `--query` 或 `--body` 中显式传 `true` 或 `false`。`req --test-env` 选择请求环境，不能替代接口要求的 JSON 参数；按同一目标环境核对请求和数据，不复用另一环境的 ID、附件、统计或回读结果。

导入 `file_path` 只能使用已上传且平台认可的对象路径，不是本地文件路径，也不是模板或错误报告签名地址。`req` 不提供文件上传；没有有效上传结果时先通过平台上传流程获取，不能凭文件名猜测路径。随机表支持 `.xlsx` 和 `.xls`，药物导入只支持 `.xlsx`。只有 `is_succeed=true` 且同环境回读一致，才报告导入成功，失败记录或 HTTP 成功不能替代业务结果。

双盲项目的编码与名称可能受角色权限及各环境独立揭盲状态影响。遮罩值保持原样，不能通过方案、药物配置、其他环境、导入文件或历史响应反推。药物列表只用于库存配置判断，不输出、关联或补全 `patient_id`、`patient_sn`。不展示上传路径、模板签名地址、错误报告签名或认证材料。

## 写入与回读

先读取状态、完整配置与必要库存，展示完整目标与级联影响。关闭模块、方案核心变更、药物类型变化或有效期提高的影响按具体说明逐项展示，不能只笼统提示“可能清空数据”。这些写操作没有演练接口，不将读取结果描述为正式演练。

仅在授权覆盖相同目标与实际影响后提交；结果未知时先回读，不重复写入。每次变更后核对开关、完整配置及相关环境列表，模块关闭后不可读的数据不能作为逐项物理删除证据。部分核验或缺失数据如实报告，不扩大目标或权限。
