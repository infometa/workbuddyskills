# 逻辑核查使用说明

逻辑核查用于在字段数据满足条件时产生核查提示。每条逻辑核查都以一个字段数据值为核查目标，并由作用范围、条件参数、条件树和提示信息共同定义。设计态逻辑核查可以维护；指定方案版本中的正式定义只能读取或导出。

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询逻辑核查设计 | 分页读取当前项目的设计态逻辑核查、完整条件和失效状态 | 否 |
| 查询逻辑核查定义 | 分页读取指定方案版本的正式逻辑核查定义 | 否 |
| 编辑逻辑核查设计 | 创建、完整更新或批量删除逻辑核查设计 | 是 |
| 导出逻辑核查 | 为指定方案版本生成或复用逻辑核查工作簿 | 否 |

本页覆盖逻辑核查对象、作用范围、写入约束、删除和导出。通用条件对象、参数和条件树字段见[条件对象结构](design-condition-schema.md)，目标事件、表单、字段组和字段必须通过对应设计态或定义态读取接口唯一定位。

## 查询逻辑核查（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取逻辑核查设计列表 | `GET` | `/api/project/settings/design/edit_check/list_edit_check_dsn/` | `--query`：`meta_data_version_id` = 从当前项目方案版本列表唯一定位的方案版本 ID（必填）；`limit` = `10–100`（必填）；`offset` = 非负分页偏移（可选）；`form_dsn_id` = 目标表单设计 ID（可选）；`target_field_dsn_id` = 目标字段设计 ID（可选）；`is_invalid` = 失效状态（可选）；`keyword` = 名称关键词，最长 64 字符（可选） |
| 获取逻辑核查定义列表 | `GET` | `/api/project/settings/design/edit_check/list_edit_check_def/` | `--query`：`meta_data_version_id` = 从当前项目方案版本列表唯一定位的方案版本 ID（必填）；<br>`limit` = `10–100`（必填）；<br>`offset` = 非负分页偏移（可选）；<br>`form_def_id` = 目标表单定义 ID（可选）；<br>`target_field_def_id` = 目标字段定义 ID（可选）；<br>`keyword` = 编号或名称关键词，最长 64 字符（可选） |

两个列表都按逻辑核查的 `number` 升序分页。需要完整结果时，从 `offset=0` 开始按页读取，直到已取得条数达到 `total`；单页没有目标不能证明逻辑核查不存在。

### 查询范围与筛选语义

- 设计列表返回当前项目未标记删除的 `EditCheckDsn`。`meta_data_version_id` 用于解析并校验当前项目及读取权限，不把正式定义 ID 转换为设计 ID。
- 定义列表只返回指定 `meta_data_version_id` 关联的 `EditCheckDef`。定义态的逻辑核查、条件、参数、事件、表单和字段 ID 不能用于任何 `*_dsn` 写接口。
- `form_dsn_id` / `form_def_id` 按核查目标表单筛选，`target_field_dsn_id` / `target_field_def_id` 按核查目标字段筛选；它们不是按条件中任意引用字段筛选。
- 设计列表的 `keyword` 只匹配名称；定义列表的 `keyword` 同时匹配 `sn` 和名称。关键词中的通配符会按普通字符转义。
- 设计列表成功时，`list` 是本页结果，`total` 是应用 `is_invalid` 后的结果总数；`invalid_count` 是同一关键词、目标表单和目标字段筛选范围内的全部失效数量，不受 `is_invalid` 筛选限制。

只使用列表实际返回的 ID、编号、条件和失效状态。名称可以重复，不能单凭名称选择更新或删除目标；候选不唯一、分页不完整或条件引用无法解析时先澄清，不得猜测。

### 逻辑核查返回字段

`EditCheckDsn` 与 `EditCheckDef` 共享以下核心属性。设计态对象额外返回失效状态；定义态对象属于指定方案版本，只读。

| 属性 | 类型 | 定义 |
| --- | --- | --- |
| `id` | integer | 逻辑核查 ID。设计 ID 与定义 ID 属于不同对象空间，不得跨态混用。 |
| `number` | integer | 平台生成的项目内顺序编号，只读，不由请求指定。 |
| `sn` | string | 平台生成的序列号，例如 `E00001`，只读，请求不能指定。 |
| `name` | string | 逻辑核查名称；设计写入时长度为 1–64。名称不是唯一键。 |
| `is_name_manual` | boolean | 名称是否手动指定。创建和更新设计时由服务端设为 `true`，请求不能指定。 |
| `message` | string | 条件命中时的核查提示；设计写入时长度为 1–256。 |
| `condition` | object | 完整条件对象，包含目标、作用范围、参数和条件树。 |
| `alteration` | string | 相对已发布方案的变更标记，只读。已发布过方案后，新建、更新和删除会维护该标记。 |
| `is_invalid` | boolean | 仅设计态：逻辑核查是否因依赖变化而失效，只读。 |
| `invalid_messages` | string[] | 仅设计态：字段、字段组、表单、事件或字段属性变化造成的失效原因，只读。 |

## 编辑逻辑核查设计（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 创建逻辑核查设计 | `POST` | `/api/project/settings/design/edit_check/create_edit_check_dsn/` | `--body`：`name` = 已确认的名称（必填，1–64 字符）；`message` = 已确认的核查提示（必填，1–256 字符）；`condition` = 已确认的完整逻辑核查条件（必填） |
| 更新逻辑核查设计 | `POST` | `/api/project/settings/design/edit_check/update_edit_check_dsn/` | `--body`：`id` = 最新设计列表唯一定位的逻辑核查设计 ID（必填）；`name`、`message`、`condition` = 更新后的完整逻辑核查状态（全部必填） |
| 删除逻辑核查设计 | `POST` | `/api/project/settings/design/edit_check/delete_edit_check_dsn/` | `--body`：`ids` = 从最新设计列表唯一定位、去重、非空且属于同一当前项目的逻辑核查设计 ID 数组（必填） |

### 写接口返回内容

| 接口 | 业务返回内容 |
| --- | --- |
| 创建逻辑核查设计 | 新创建的 `EditCheckDsn`，包含服务端生成的 `id`、`number`、`sn`、归一化后的条件和失效状态。响应成功后仍须按返回 `id` 回读确认。 |
| 更新逻辑核查设计 | 无；必须通过设计列表回读确认完整结果。 |
| 删除逻辑核查设计 | 无；必须通过设计列表回读确认全部目标均已消失。 |

创建、更新或删除前先分页读取逻辑核查设计，并读取条件涉及的当前设计态事件、表单、字段组和字段。写请求成功不代表最终结构已经确认，也不代表逻辑核查已经进入正式方案。

### 核查目标与条件对象

- 逻辑核查的目标固定为字段数据值。请求中的 `condition.target_variable_type` 最终由服务端设为 `FIELD_DATA_VALUE`；必须提供可解析的 `target_field_dsn_id`，服务端按该字段补齐 `target_form_dsn_id` 和 `target_section_dsn_id`。
- `condition.condition_type` 当前只支持 `CONDITION_COMPLEX`。不要提交 `CONDITION_SIMPLE`、`CONDITION_EXPRESSION`，也不要依赖 `formal_expression` 执行逻辑。
- `condition.parameters` 的 `number` 必须从 `0` 开始连续且不能重复。条件树中的 `left_parameter_number` 和 `right_parameter_numbers` 必须引用这些编号。
- 目标字段必须作为参数存在，并且至少在一个 `COMPARE` 节点中作为左参数参与判断。只把目标字段放在参数列表、右参数或目标属性中都不满足该约束。
- 字段型参数使用 `parameter_type=FIELD_DATA_VALUE` 和当前设计态 `field_dsn_id`。服务端按字段补齐所属 `form_dsn_id`、`section_dsn_id`；不能用请求中的父级 ID 把字段改挂到其他结构。
- `parameter_resolution` 由服务端根据作用范围、目标和参数事件推导，创建或更新时不要自行决定；写后以 GET 返回值为准。
- `id`、`alteration`、`is_invalid`、`invalid_messages` 属于读取或更新对账信息。创建时不要臆造；更新参数时只保留最新 GET 中确实属于本条件的参数 `id`。

### 作用范围与参数解析

| `target_scope_type` | 目标事件 | 参数限制 | 服务端解析方式 |
| --- | --- | --- | --- |
| `ALL_EVENTS` | `target_event_dsn_ids` 使用空数组 | 所有字段参数必须与目标字段属于同一表单，不允许跨表单引用；字段参数的 `event_dsn_id` 使用 `0` | 参数按 `EVERY_IN_FORM_DATA` 解析，在每个适用表单数据实例中评估 |
| `SPECIFIED_EVENT` | `target_event_dsn_ids` 提供且只提供一个当前设计态事件 ID；该事件必须关联目标表单 | 每个参数都必须提供正整数 `event_dsn_id`，且该事件必须关联参数所属表单；允许引用同事件其他表单或其他事件中的字段 | 目标事件、目标表单、目标字段三者一致的目标参数使用 `EVERY_IN_EVENT_DATA`；目标事件中的其他参数使用 `ANY_IN_EVENT_DATA`；其他事件参数使用 `ANY_IN_SPECIFIED_EVENT_DATA` |

指定事件范围实际以 `target_event_dsn_ids[0]` 作为目标事件。为避免未使用的多余事件产生歧义，只提交一个事件 ID。目标表单可能关联多个事件，因此指定事件范围下，仅字段 ID 相同还不足以证明它是目标参数；目标字段参数的事件、表单和字段必须同时匹配目标。

### 条件树和比较约束

- `condition_unit.type=COMPARE` 表示叶子比较；每个 `COMBINATION` 节点只能选择一个非空的 `and` 或 `or` 数组，所选数组至少包含两个子节点，另一个省略或为空数组。混合 AND / OR 必须通过嵌套组合节点表达；同节点同时填写两类子节点即使保存成功，执行时也会优先 `and` 并忽略 `or`。具体字段和比较器见[条件对象结构](design-condition-schema.md)。
- `IS_NULL` 和 `NOT_NULL` 不接受常量或右参数；服务端会递归清空其 `check_values`、`right_parameter_numbers` 和日期偏移。
- `IN`、`NOT_IN`、`CONTAINS`、`NOT_CONTAINS` 至少需要一个常量值或右参数；其他有右值的比较器必须在“一个右参数”和“一个或多个常量值”之间二选一。
- 左参数允许的比较器取决于字段的 `data_type` 与 `resp_type`。平台拒绝不支持的组合；不要通过更换比较器或字段 ID 自动重试。
- 右值使用变量时，左字段只支持数值输入框、日期、时间或日期时间类型。左右字段须具有相同数据类型与响应类型；数值输入框的 `INTEGER`、`FLOAT`、`DOUBLE` 可以互相比较，`DATE` 与 `DATETIME` 可以互相比较且执行时按日期比较。其他类型使用常量值。
- 日期偏移只在右值是 `DATE` 或 `DATETIME` 字段变量时保留；其他右值的 `right_date_offset_type` 和 `right_date_offset_days` 会被服务端清空。
- `check_values` 是字符串数组。接口不会完整预检所有常量与字段选项、数据类型和运行态值域的关系；提交前仍须按目标字段配置核对常量含义。

### 重复判定与完整更新

- 同一项目内，如果作用范围、指定事件、目标字段以及条件树的业务语义都相同，平台判定为重复逻辑核查并拒绝创建或更新。名称、提示和参数编号顺序不同不会使重复条件变成新条件。
- 重复判定会把参数编号解析为实际事件、表单、字段组、字段和定义，并对 `AND` / `OR` 子树做顺序无关的语义比较。不得通过交换参数编号或条件顺序绕过重复校验。
- 更新接口不是部分补丁：`name`、`message` 和完整 `condition` 都必须提交。先保存最新 GET 返回的完整对象，在副本上形成新状态，再移除只读字段并提交。
- 更新条件参数时，保留的既有参数必须携带该条件最新 GET 返回的参数 `id`；没有 `id` 的参数会新建，GET 中存在但请求中遗漏的参数会删除。未知或重复的参数 `id` 可能被服务端当作新参数，因此提交前必须校验归属并去重。
- 更新会重新验证完整条件，并清除已修复对象的旧失效状态。完整新状态与当前状态没有实际差异时，平台拒绝空变更；不得把空变更改成创建操作。

### 删除与依赖变化

- 删除接口没有 dry-run。执行前必须从最新完整列表解析并展示每个目标的 `sn`、名称、目标字段、作用范围、条件摘要和提示信息；用户只要求查询或影响分析时不得执行删除。
- 一次删除的全部 ID 必须属于同一当前项目。不存在、已删除、重复或无法唯一定位的 ID 不能作为目标；平台拒绝时不得静默缩减目标集合后重试。
- 删除逻辑核查会同时处理其条件和参数。已发布过方案时，本轮新增对象直接移除，其他对象标记为 `DELETED`；从未发布过方案时直接删除设计记录。两种情况都应从后续设计列表中消失。
- 删除或修改事件—表单关系、表单、字段组、字段及字段属性，可能删除逻辑核查或把逻辑核查、条件和参数标记为失效。相关结构变更后必须回读逻辑核查，并检查 `is_invalid` 与 `invalid_messages`。
- 常见失效原因包括条件字段所在事件、表单、字段组或字段已删除，目标作用范围事件已删除，目标字段所在表单已删除，以及条件字段属性已变化。失效对象不能被当作可发布规则。

## 导出逻辑核查（只读产物）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 导出逻辑核查 | `POST` | `/api/project/settings/design/edit_check/export_edit_check/` | `--body`：`meta_data_version_id` = 从当前项目方案版本列表唯一定位的方案版本 ID（必填） |

导出要求方案设计访问权限，不要求项目处于“设计中”。未发布版本按当前内容生成工作簿；已发布版本可能复用该版本已有的导出文件，不能把再次调用理解为强制重新生成。请求成功时平台原始 `file_path` 是短期下载授权材料，`req` 仅返回响应，不下载工作簿。响应缺失时不能猜测或恢复；不在对话中公开该地址。仅在实际取得并核验文件后报告已下载。超时或结果不确定时不得自动重复导出。

## 结果核验

新增、修改或删除逻辑核查时，必须先 GET 保存变更前的完整设计列表，完成写操作后再次分页 GET 获取同一筛选范围，并用 Markdown 表格反馈实际 diff。

单条逻辑核查发生变化时，可以使用属性对比表：

| 属性 | 变更前 | 变更后 | 结果 |
| --- | --- | --- | --- |
| 名称 | 收缩压范围核查 | 收缩压高值核查 | 已生效 |
| 作用范围 | 全部事件 | 筛选期 | 已生效 |
| 条件 | 收缩压 > 180 | 收缩压 ≥ 180 | 已生效 |
| 核查提示 | 收缩压超出范围 | 请核对收缩压高值 | 已生效 |

一次操作包含多个逻辑核查时，使用批量变更表格。第一列固定为变更类型，只能填写“新增”“变更”或“删除”；目标字段必须包含完整表单与字段组路径，避免同名字段混淆。变更后的值在前，原值紧随其后并使用删除线标记；新增条目的原值留空，删除条目只保留删除线原值。

| 变更类型 | `sn` | 名称 | 目标字段路径 | 作用范围 | 条件摘要 | 核查提示 | 有效性 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 新增 | E00012 | 收缩压高值核查 | 生命体征表 / 生命体征 / 收缩压 | 全部事件 | 收缩压 ≥ 180 | 请核对收缩压高值 | 有效 |
| 变更 | E00008 | 体温核查 | 生命体征表 / 生命体征 / 体温 | 筛选期<br>~~全部事件~~ | 体温 > 38<br>~~体温 ≥ 38~~ | 请核对体温 | 有效 |
| 删除 | ~~E00003~~ | ~~旧版体重核查~~ | ~~生命体征表 / 生命体征 / 体重~~ | ~~全部事件~~ | ~~体重为空~~ | ~~请填写体重~~ | |

条件摘要必须来自前后两次 GET 的完整条件对象，并翻译成不丢失 `AND` / `OR` 分组、比较器、常量、右参数和日期偏移的中文含义。如果 GET 失败、新对象未出现、删除对象仍存在、完整条件与预期不一致，或者 `is_invalid=true`，应报告“变更未确认生效”或“已写入但逻辑核查失效”，不得仅依据写接口成功响应作出结论。
