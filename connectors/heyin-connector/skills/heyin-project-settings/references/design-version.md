# 方案版本与生命周期使用说明

## 功能总览

| 功能 | 说明 | 可修改 |
| --- | --- | --- |
| 查询方案版本 | 获取项目方案版本列表 | 否 |
| 版本基础维护 | 创建方案版本、更改版本名称、撤销方案版本（含演练） | 是 |
| 生命周期管理 | 发布方案版本（含演练）、进入设计中、正式发布方案版本 | 是 |
| CRF 下载 | 按方案版本导出空白 CRF、注释 CRF 和 CRF 填写指南，支持 DOCX／PDF | 是 |

## 方案版本生命周期

项目字段 `mdv_status` 表示当前方案设计阶段，使用[基础配置](general.md)中的项目查询接口读取当前值。版本列表的响应是 `list`，其中每条 `MetaDataVersion` 包含 `mdv_status`、`is_published`、`is_draft`；该接口没有独立的 `mdv_status`。版本记录用于定位和核验，空列表或缺失字段不能替代当前项目状态，不得按用户表述、前端展示或历史调用结果推断。

| 状态 | 枚举值 | 含义 | 设计数据可编辑性 |
| --- | --- | --- | --- |
| 未创建 | `EMPTY`，实际值为空字符串 `""` | 从未创建方案版本，DSN 为空 | 可通过创建方案进入设计 |
| 设计中 | `DESIGNING` | 当前存在正在设计的方案，DSN 可编辑 | 可编辑 |
| 草稿 | `DRAFT` | 草稿已发布，测试中心可使用草稿 | DSN 只读；可正式发布或重新进入设计 |
| 已正式发布 | `PUBLISHED` | 已存在正式发布版本，生产中心可使用 | DSN 只读；可创建下一轮设计 |

"设计中"不是从 MDV 记录简单推导出的状态，而是在创建新版本或从草稿重新进入设计时显式设置。其他稳定状态由剩余 MDV 记录推导：存在晚于最新正式版本的当前草稿时为"草稿"，否则存在正式版本时为"已正式发布"，否则为"未创建"。

### 状态跳转控制

状态跳转约束：

- **创建方案版本**：仅"未创建"或"已正式发布"状态允许；项目处于"设计中"或"草稿"时不允许重复创建进行中的设计或草稿。创建后项目进入"设计中"并解锁 DSN 编辑。
- **发布草稿**：仅"设计中"状态允许，发布前必须通过发布演练校验；发布后项目进入"草稿"，测试中心可绑定该草稿，生产中心不会因草稿发布而切换。
- **正式发布**：仅"草稿"状态且存在当前草稿时允许，需用户明确"正式发布"意图；正式发布推进 DSN 正式基线并按参数分配生产中心，项目进入"已正式发布"。
- **进入设计**：仅"草稿"状态允许；项目回到"设计中"，保留草稿 MDV 和测试中心绑定、恢复 DSN 编辑，此时不能再次创建新方案版本。
- **撤销**：仅"设计中"或"草稿"状态允许，撤销前必须通过依赖检查（ePRO、RTSM、SD 关联）；撤销后根据是否存在正式版本推导为"已正式发布"或"未创建"。

### MDV 记录状态组合

版本列表返回的 `is_published` 和 `is_draft` 描述单条 MDV 记录：

| 记录类型 | `is_published` | `is_draft` | 说明 |
| --- | --- | --- | --- |
| 设计中版本 | `false` | `false` | 每次创建方案版本都会生成的未发布设计记录，包括正式发布后创建的下一版本 |
| 草稿版本 | `true` | `true` | 草稿发布后的版本；测试中心可使用 |
| 正式版本 | `true` | `false` | 正式发布后的生产版本；正式基线永久保留 |

从草稿重新进入设计时保留原草稿，不另建未发布设计记录。早于最新正式版本的旧草稿不参与状态推导、前端列表和对外名称唯一性校验；列表接口展示未发布设计记录、所有正式版本和最新当前草稿。

## 查询方案版本（只读）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 获取项目方案版本列表 | `GET` | `/api/project/settings/design/list_meta_data_version/` | 无 |

### 返回说明

- **版本列表**：`list` 为 `MetaDataVersion[]`，每项包含整数 `id`、`project_id`，字符串 `name`、`created_at`，布尔值 `is_published`、`is_draft`，枚举 `mdv_status`，以及版本内容、变更、失效和应用情况的整数计数；`published_at` 为可选字符串。只使用平台实际返回的版本 ID 与状态，缺失、空列表或部分响应不得被补造为默认设计中、草稿或正式版本。当前项目状态仍按上文读取。

## 版本基础维护（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 创建项目方案版本 | `POST` | `/api/project/settings/design/create_meta_data_version/` | `--body`：`name` = 已确认的新版本名称（必填） |
| 更改项目方案版本名称 | `POST` | `/api/project/settings/design/update_meta_data_version/` | `--body`：`id` = 版本列表返回的方案版本 ID（必填）；`name` = 已确认的新名称（必填） |
| 撤销方案版本演练 | `POST` | `/api/project/settings/design/revoke_meta_data_version_dry_run/` | 无（省略 `--body`） |
| 撤销方案版本 | `POST` | `/api/project/settings/design/revoke_meta_data_version/` | 无（省略 `--body`） |

### 使用要点

版本创建、更名、草稿发布和正式发布请求中的 `name` 均为字符串，提供时长度为 1–16；创建、更名必填，草稿发布和正式发布可选。创建成功的 `data` 为新建 `MetaDataVersion`；更名和撤销未声明具体业务返回结构，完成后须回读。

- **创建版本**：用户明确要求新增草稿版本且名称已确认时使用；仅"未创建"或"已正式发布"状态允许创建，创建前先查询版本列表确认状态与名称，避免目标状态冲突。
- **重命名版本**：已唯一定位版本 ID 并确认新名称时使用；更新前先读取当前名称与状态，重名或 ID 无法唯一定位时先澄清。
- **撤销**：仅"设计中"或"草稿"状态允许。撤销前必须先执行撤销演练，演练响应声明了可选布尔字段 `is_epro_related`、`is_rtsm_related` 和 `is_sd_related`；需取得完整关联结果再决定后续操作，不能把缺失字段当作 `false`，向用户说明方案与 ePRO、RTSM、SD 的关联情况；关联结果必须按平台原值陈述。演练按已有授权执行；演练授权不等于正式操作授权；演练成功不代表撤销完成。演练完成且用户明确表达"撤销"意图、批准后正式撤销；若演练后状态变化则重新演练。`revoke_meta_data_version` 不能从"修改""重做""回退看看"等模糊表达推断意图。
- 写操作前须完成目标、状态和名称核验；正式写入成功后，使用版本列表读取接口回读并核验目标对象，请求成功不等于最终状态已核验。

## 生命周期管理（写）

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 发布项目方案版本演练 | `POST` | `/api/project/settings/design/publish_meta_data_version_dry_run/` | 无（省略 `--body`） |
| 发布项目方案版本 | `POST` | `/api/project/settings/design/publish_meta_data_version/` | `--body`：`name` = 新草稿名称（可选）；`test_site_ids` = 当前项目测试中心 ID 数组（可选） |
| 进入设计中 | `POST` | `/api/project/settings/design/update_meta_data_version_dsn/` | 无（省略 `--body`） |
| 正式发布方案版本 | `POST` | `/api/project/settings/design/release_meta_data_version/` | `--body`：`is_apply_to_all_sites` = 是否应用到运行中的生产中心（可选布尔值，调用时显式固定）：`true` 时覆盖状态为 `STARTED`、`ENROLLING` 或 `FINISH_ENROLLMENT` 且当前版本不同于本次正式版本的生产中心，包括已分配旧版本的中心；`false` 或省略时仅分配 `STARTED` 且 `meta_data_version_id=0` 的生产中心；`name` = 正式发布后的版本名称（可选） |

### 发布闭环

1. **演练**：正式调用发布接口前先执行发布演练；演练响应应包含 `invalid_computation_count`、`invalid_edit_check_count`、`invalid_event_count` 和 `invalid_logic_count`，向用户说明无效计算、核查、事件与逻辑数量。演练按已有授权执行；演练授权不等于正式操作授权；演练成功不代表发布完成。
2. **发布**：仅"设计中"状态允许，演练完成、参数未变化且用户批准后发布方案版本。`name` 为发布后新草稿方案版本名称，`test_site_ids` 为显式指定的测试中心 ID 列表，必须由当前项目读取结果解析。发布还会自动绑定已启动且尚未分配版本的测试中心；再次发布会把持有旧草稿的测试中心切换到新草稿，并同步尝试升级旧草稿的测试研究参与者，最后重建统计。因此影响范围不限于 `test_site_ids`，省略该数组也可能发生这些变更。发布前展示完整影响范围；若演练后项目状态、名称或受影响中心及研究参与者范围变化，重新核验，不复用过期结论。
3. **正式发布**：仅"草稿"状态且存在当前草稿时允许，且仅在用户明确表达"正式发布"意图后使用。正式发布使方案在生产中心生效，前提是该版本已在测试环境完成用户验收测试（UAT）并取得上线批准；方案修订版本还须已获伦理批准。核对本次版本的 UAT 范围、结果及未决问题、上线批准和适用的伦理批准依据，记录对应版本与来源位置，不以接口成功或无失效项代替验收。用户无法提供这些依据时，说明缺失项及风险并请用户确认，不得声称已完成验收或取得批准。执行前读取版本列表，并按[中心设置](site.md)分页读取完整生产中心列表，固定本次草稿 ID 和显式布尔参数。`is_apply_to_all_sites=true` 时，筛选状态为 `STARTED`、`ENROLLING` 或 `FINISH_ENROLLMENT` 且 `meta_data_version_id` 不同于本次版本 ID 的生产中心；`false` 时仅筛选 `STARTED` 且 `meta_data_version_id=0` 的生产中心。展示实际受影响中心的 ID、名称、状态和“当前版本 → 本次版本”，不能只用“全部中心”或“已启动中心”概括。正式发布没有独立的中心分配演练接口，这份清单是根据当前读取结果预览；执行前范围或版本变化时重新核对。确认已有授权覆盖同一目标与实际影响，否则补充确认。该操作更新中心的方案绑定，不升级已有生产研究参与者的方案版本。
4. **回读核验**：发布或正式发布成功后，回读项目方案状态、版本列表及受影响中心的版本绑定；正式发布还须重新读取完整生产中心列表，逐项核验预览清单中的绑定并报告其他实际变化，不能据此声称已有生产研究参与者已升级。再次发布草稿还应核验受影响测试研究参与者的版本。单个研究参与者升级失败不会使草稿发布整体失败，不能凭发布成功宣称全部升级完成。未核验最终状态时只陈述请求结果，不得宣称最终完成。

"发布项目方案版本"与"正式发布方案版本"是不同操作，不能互换；`release_meta_data_version` 只有用户明确表达"正式发布"意图时才可调用。

### 进入设计中

仅"草稿"状态允许调用，用户明确要求当前项目回到设计中状态时使用；项目回到"设计中"，保留草稿 MDV 和测试中心绑定、恢复 DSN 编辑，此时不能再次创建新方案版本。执行前读取当前方案版本状态并说明目标变化；该接口只是切换设计中状态，不得当作撤销或新建版本的替代操作。成功执行后回读版本列表核验。

## CRF 下载（写）

该功能按指定方案版本同步生成空白 CRF、注释 CRF 和 CRF 填写指南，可多选。先从当前项目版本列表唯一定位方案版本 ID，再按用户要求确定文件类型、表单组织方式、格式及注释 CRF 是否标注 SDTM 数据域。

### 接口一览

| 用途 | 方法 | 路径 | 请求参数 |
| --- | --- | --- | --- |
| 下载 CRF | `POST` | `/api/project/settings/design/export_crf/` | `--body`：`meta_data_version_id` = 版本列表返回的方案版本 ID（必填）；`has_blank_crf`、`has_annotated_crf`、`has_guide_crf` = 是否包含空白 CRF、注释 CRF、CRF 填写指南（布尔值，至少一项为 `true`）；`form_organization` = `COMPLETE`（完整）或 `UNIQUE`（不重复）（必填）；`format` = `DOCX` 或 `PDF`（必填）；`has_sdtm_domain` = 注释 CRF 是否标注数据域（布尔值，可选，仅含注释 CRF 时生效） |

### 返回说明

- 需要项目级 `PRJ_SETTINGS_DESIGN_ACCESS` 权限。方案版本必须属于凭证绑定的项目，且包含表单；`has_sdtm_domain=true` 时版本中至少一个字段须已关联 SDTM 数据域，否则平台拒绝。本操作不导出研究参与者数据。
- 三个类型布尔值逐一显式提交；只选一种时生成单个文件，多选时打包为 zip。用户未指定组织方式或格式时先询问，不按默认值推断。
- 平台同步生成文件，PDF 可能耗时数十秒；已发布正式版本相同选项组合会复用缓存。成功响应的 `file_path` 是短期签名下载地址；`req` 仅返回响应，不下载文件。只有实际取得并核验文件后才能报告已下载，不能把导出请求成功视为文件已保存；不在对话中公开签名地址，响应缺失时不猜测或恢复。
- 导出会记录操作日志，属于写操作：调用前展示方案版本、文件类型、组织方式、格式和数据域选项，并确认已有授权覆盖同一目标与实际影响，否则补充确认；批准后只调用一次。请求超时或结果不确定时不得自动重试。
