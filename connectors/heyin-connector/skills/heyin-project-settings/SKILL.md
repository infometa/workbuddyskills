# 项目设置使用指南

使用 `heyincli req` 和目标项目对应的凭证完成项目设置操作。Windows 使用 `heyincli.cmd`。根据用户目标阅读对应参考文件，不必一次加载全部内容。

## 确认项目与凭证

1. 按 `heyin-project` 技能的“获取与使用项目 API 令牌”查询目标项目和角色，选择或创建匹配的本地凭证；同一项目操作沿用已确认的角色凭证，不擅自切换身份。
2. `--token-id` 是本地凭证 ID，不是项目 ID、中心 ID 或令牌原文。项目由凭证确定，请求不传 `project_id`；中心、方案、模板、角色和成员 ID 必须来自该项目的实际查询结果。角色 ID 与角色模板 ID 不可互换。
3. 多个候选仍无法唯一匹配时，请用户明确目标。不同项目分别选择凭证，不跨项目复用中心集合或配置候选。
4. 区分生产与测试中心，按具体接口填写 `special`。中心配置接口省略类型时按生产中心处理，其批量操作必须属于同一项目、同一类型；知情同意的中心查询省略 `special` 时，在测试环境开启的项目中会同时返回生产与测试中心，查询生产中心须显式传空字符串。角色与成员管理的可选中心查询及生效范围按对应参考中的规则选择。

## 请求调用方式

| 接口说明 | CLI 用法 |
| --- | --- |
| 请求方法与路径 | `--method GET/POST` 和 `--path` |
| 查询参数 | `--query` 接收 JSON 对象，例如 `'{"limit":20,"offset":0}'` |
| 写入参数 | `--body` 接收 JSON 对象，例如 `'{"planned_sample_size":150}'` |
| 项目凭证 | `--token-id` 使用已选定的本地凭证 ID |
| 请求环境 | `--test-env` 或 `--test-env=true` 使用测试环境；省略或传入 `--test-env=false` 使用生产环境 |

接口表用 `--query` 或 `--body` 标明参数位置，所列字段直接放入对应 JSON 对象，不要额外嵌套 `query` 或 `body`。GET 不传 `--body`，POST 按具体接口填写请求体。JSON 中的 ID 使用整数，ID 列表使用整数数组；不同接口的 `id`、`ids`、`site_id` 和 `site_ids` 不可混用。

参数表中的“必填/可选”描述请求字段本身；条件必填、“必须显式提交”和“完整替换”等业务规则另行说明，并按具体接口执行。响应属性不能直接当作同名请求参数回传；权限、状态及级联影响按对应参考说明核对。技能要求的先读后写、演练和状态范围可能严于服务端，仍须遵守，不能把服务端接受请求当作这些前置已满足的证明。

`--test-env` 是 `req` 的参数，适用于 GET 和 POST，省略时使用生产环境，单独填写即选择测试环境。`special: "TEST"` 是接口的中心类型参数，`--test-env` 选择本次请求的测试环境；两者分别按用户目标和接口要求填写，不能相互替代，也不能仅因查询测试中心就自动切换请求环境。

示例中的凭证和业务 ID 必须替换为已核对的实际值。按当前 Shell 正确引用 JSON，不把用户文本直接拼接成命令。完整 CLI 参数、登录恢复和安装方法见 `heyin-cli` 技能。

## 基本调用示例

凭证 ID、项目 ID 及字段值均需替换为实际值；具体接口路径、字段和限制见对应参考文件。

```sh
heyincli req --token-id <token-id> --method GET \
  --path '/api/project/settings/general/get_project/'
```

`req` 成功时标准输出为平台响应中的 `data`，例如 `{"id":123,"name":"示例项目","planned_sample_size":120}`；成功与否以退出码判断。参考文件中的“业务返回内容”指 `data`；“无”表示接口没有约定业务数据，输出可能为 `null`。

```sh
heyincli req --token-id <token-id> --method POST \
  --path '/api/project/settings/general/update_project/' --body '{"planned_sample_size":150}'
```

修改前读取现状并确认在用户授权范围内，只提交需要变化的字段。该接口成功时输出 `null`；更新后再次 GET 查询，以实际结果核对变更，不能仅凭命令成功认定所有目标都已生效。GET 和 POST 均可按用户目标添加 `--test-env`，写后查询使用相同环境。

## 分页与输出

读取 `req` 返回的业务结果，只向用户展示任务所需字段。

对明确支持分页且返回 `list` 和 `total` 的接口，通过 `req --query` 的 JSON 对象传入接口规定的 `limit` 和 `offset`，每次将偏移增加实际返回的记录数，直到覆盖目标或读完全部结果。未读完却出现空页时报告结果不完整，不能因目标不在当前页就认为其不存在。

缺失状态、许可、名称、发布标记或统计时保留“未知”，不要根据其他字段推断。不得展示认证材料、签名地址、内部路径、项目外数据或无关个人信息；各类业务数据的展示范围见对应参考。

## 修改与结果验证

- 写前读取最新现状，唯一确定项目及全部目标，核对用户要求的字段、前后值、权限、状态与影响。查询请求不能自动升级为修改。
- 部分更新接口只提交用户明确要求变化的字段，不用空值覆盖未提及配置；全量覆盖接口按参考说明构造完整目标集合，保留用户未要求移除的部分，不能把增量直接当作完整集合提交。目标已满足时跳过无变化更新。
- 删除中心、关闭 SD 或 eTMF、发布 SD 配置、删除 SD 分类或文件夹及取消事件关联，必须先执行对应演练并说明结果及相关级联影响；其他领域的演练要求与高影响修改按对应参考执行并展示实际影响。已有明确授权覆盖相同目标和实际影响时无需重复确认；否则取得确认后再执行。目标或现状变化时重新演练。
- 写后按实际返回 ID 或原目标集合重新查询，以读取结果反馈变化。批量操作可能跳过部分目标，必须逐项区分已变更、未变化和无法确认，不把一次成功响应解释为所有目标都已完成。
- 写入超时、回读失败或结果不明时，先查询实际状态，不盲目重复提交。无法核实的变更报告“变更未确认生效”。

## 失败处理与客户端更新

权限不足、项目或中心不可写、类型不符、功能未获许可、依赖不满足、状态冲突或平台拒绝时，保留实际错误并停止。不要更换凭证、业务 ID、方案或模板，不删减批量范围或关闭附带模块来绕过限制。

服务端明确要求更新客户端时，按 `heyin-cli` 技能中的“版本管理”说明更新，确认版本满足要求后再执行原指令；此前写入结果不明确时，更新后先查询实际状态。不要索取或展示访问令牌、刷新令牌或二次认证材料。
