# 念法指令（instructions）最佳实践

`instructions` 控制**怎么念**（语气、节奏、重音、情绪），不进入朗读正文。音色决定"是谁在说"，指令决定"这一次怎么说"。

**默认不写。** 音色自带的基线已经能用于大多数旁白。只有在需要统一风格、放慢强调、或角色化表演时才写，并且**一条片子用同一条指令**——逐段改指令会让音色漂移。

## 好指令的结构

Breeze 官方 `tts enhance` 输出的中文指令是这个范式，照着写最稳：

> 请以**冷静、温和且沉稳**的语气进行**讲解**。保持**语速稍慢**，**字句清晰**，**发音圆润**，展现出**耐心且专业**的态度。

四段式：

1. **语气**：2–3 个形容词（冷静、温和、沉稳）
2. **动作**：在做什么（讲解 / 播报 / 讲述 / 引导）
3. **节奏**：语速、停顿、句尾处理（语速稍慢、句子之间留出换气、句末自然收住）
4. **态度/场景**：让人听出什么感觉（耐心、专业、亲近）

## 正例

```sh
# 课程讲解，稳定清楚
--instructions "请以冷静、温和且沉稳的语气进行讲解。保持语速稍慢，字句清晰，数字和字母逐个读清楚，句末自然收住。"

# 播客，去掉播音腔
--instructions "像跟朋友聊天一样自然，语速略快，句尾不要上扬，避免播音腔和朗诵感。"

# 纪录片旁白
--instructions "低沉、克制的叙述，语速平稳，句间留出较长停顿，不加重音强调。"

# 冥想引导
--instructions "接近耳语的柔和气声，语速极慢，每句之间停两秒，不要有任何上扬的疑问语气。"

# 儿童内容
--instructions "轻快明亮，语调有起伏，像讲故事一样，关键词可以稍作夸张。"
```

## 反例

| 写法 | 问题 |
| --- | --- |
| `--instructions "温柔"` | 只有一个形容词，模型自由发挥，每次结果不同 |
| `--instructions "读得好听一点"` | 无信息量，等于没写 |
| `--instructions "语速 1.2 倍"` | 语速该用 `--speed 1.2`，不要写进指令 |
| 把"（温柔地）"写进正文 | 括号内容会被念出来，正文保持干净 |
| 逐段写不同指令 | 音色与语气漂移，听感断裂 |

## 与其它参数的分工

| 想要的效果 | 用什么 |
| --- | --- |
| 整体快慢 | `--speed`（0.5–2.0，保持音高） |
| 整体音量 | `--volume`（0.01–2.0） |
| 语气、情绪、重音、停顿 | `--instructions` |
| 表演强度 | `--guidance-scale` |
| 更贴近参考音色 | `--use-speaker-boost` |

`--use-speaker-boost` 与 `instructions` 互斥：写了指令或 `guidance-scale > 1` 时，speaker boost 不生效（指令始终生效）。要"更像原音色"就别写指令；要"按这次要求表演"就写指令。

## guidance-scale 怎么取

默认 1。官方指引：连续旁白从 1 开始，需要更多表现力时在 1–2 之间试。

- `1`：最稳，长片优先，不易失常
- `1.5–2`：情绪更明显，适合宣传片、故事
- `> 3`：容易过火、拖腔、失真，不要在长旁白里用

## 写不出来就让官方扩写

```sh
breeze tts enhance --instruction "冷静温和的讲解，语速稍慢" --language zh --json
```

返回：

```json
{"instruction":"请以冷静、温和且沉稳的语气进行讲解。保持语速稍慢，字句清晰，发音圆润，展现出耐心且专业的态度。","language_code":"zh"}
```

用法：先写一句粗糙的中文描述 → `enhance` 扩写 → 把返回的 `instruction` 原样传给 `tts --instructions`。**用中文描述就配 `--language zh`**，中英混写会得到不匹配的指令。

`enhance` 只扩写文本，不合成音频，不产生配音费用。

## 一致性规则

- 一条片子（或一套卷）固定一条指令，写在工程配置里复用，不要每次重写。
- 改指令 = 新 take：音频缓存失效，会重新计费。定稿前先用一段 15 秒的样音试。
- 指令不改变正文内容。加停顿靠标点（`，` `。` 换行）和句式，不要靠指令里的"停一下"。
