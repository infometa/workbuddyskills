# 表单数据新增和更新

先按[发现规则](form-discovery.md)定位对象并取得当前操作字段；实际定位既有记录时按[查询规则](form-data-query.md)及其条件门禁执行。命中对象特有限制时先停止受限分支。

## 区分修改目标、内容来源与关联自然值

| 用途 | 处理 |
| --- | --- |
| 被修改的主记录，或被增删改子表的父记录 | 用名称/编号等自然值查询，唯一定位并取得可信 `dataId`；零匹配或多个匹配先澄清 |
| 新增或更新的内容取自既有记录，如“参照 SO-001 的明细新建订单” | 按[查询规则](form-data-query.md)唯一定位来源记录，读取本次需要的字段；涉及子表时读取对应详情并确认完整性，再按目标对象当前可写字段映射。来源缺失、不唯一或读取不完整时保留待补内容，不猜造或静默省略 |
| 新增/更新字段中交给服务端解析的关联名称 | 按当前关联字段与服务端契约提交；异常重名按已声明契约处理，不强制客户端唯一，不添加内部 ID 参数 |
| 用户指定更具体关联范围，如上海部门的同名人员 | 只用 Tool 确实支持的范围；不能表达时说明并确认差异，不假装已精准选中 |
| 用户要求先验证关联存在性或选择具体人员 | 执行相应查询；按用户要求处理零匹配、多匹配与身份范围 |

服务端已支持自然名称解析时，不为了再传同名而无条件查询组织。缺少重名处理契约且歧义影响结果时说明并澄清。

## 新增

```text
对象 → 必需模板 → ycrm_form_add_field_list → 用户事实/必要的来源记录读取
    → 字段映射与缺项校验 → 必要的文件导入或关联验证
    → ycrm_form_data_insert → 回读
```

- 提交可信 `templateId` 和 `data` 对象；没有主表字段时 `data` 传空对象，不能仅提交 `relationDatas`。
- `data` 仅包含当前新增允许字段。逐项映射用户事实并校验必填；缺项保留待写记录并集中补问，只使用 Tool 明确允许的默认值。
- 创建草稿、计划或尚未履行的单据是否可行看当前契约；不要求单据预先存在，也不将计划伪装为已发生事实。
- 系统编号、`AUTO_NUMBER`、`STATISTICAL` 等字段依据当前可写性处理；通常自动生成不等于当前可写性结论。
- 用户给出的业务值无法匹配可写字段时说明并澄清，不能静默丢弃或塞进近似通用字段。替代映射获明确认可后才能使用。
- 外部图片/附件按[文件规则](file-assets.md)先导入，随后单独写入记录。

## 增量更新

```text
唯一目标及 dataId → ycrm_form_upd_field_list → 必要的当前值
    → 本次变化 → ycrm_form_data_update → 回读本次变化
```

- 只校验本次提交字段的可更新性和取值，不重复索取或提交未变化的客户、日期、金额等必填字段。未提交的主表字段保持原值。
- 默认读取将被覆盖的当前值；单主表场景列表能覆盖所需字段时可用列表，其余用详情。目标已唯一、变化完全不依赖当前值且无子表时可省略当前值读取。
- 追加、累加、替换、按条件修改必须读取相应当前值；不能以直接赋值豁免替代依赖状态的计算。
- `null`、空字符串和未传不同；清空含义及必填字段是否能清空以当前更新契约为准，不明确则先澄清。
- `data`、`relationDatas`、`deleteRelationDataIds` 至少一种构成非空且合法操作；映射后无可执行变化则说明并停止，不能把服务端过滤无效字段当成功。
- 只有涉及子表才读取[子表写入规则](subform-write-rules.md)；主表更新不加载该文档。

## 执行与核验

授权与差异确认按[共享规则](shared-rules.md)执行；批量主记录写入，或未分组新增材料的主记录数量、归属边界待判断时，使用[通用批量规则](multi-entity-rules.md)。提交前确认用户要求的字段和行均已覆盖，部分执行必须符合明确授权。

新增通常只返回主记录 `id`；主表用详情或列表回读关键自然值，子表必须用 `ycrm_form_data_dtl(needSubForm=true)`。按业务值比较：允许契约明确的类型转换、名称规范化和日期展示变化；真实差异、缺失、截断或回读失败均如实说明。未知响应进入共享恢复规则。

## 最小示例

输入：“把 HK-001 和 HK-002 的备注都改为已核对。”

当前对象及真实编号字段已发现，两条记录各唯一，备注可更新：取得各自 `dataId`，分别只提交真实备注字段及新值，再回读。不索要旧到账日期或金额，不读回款新增候选信号，也不重复确认已明确的范围。

若准备时发现 HK-002 不存在，保留缺项；用户未授权部分执行时先澄清，不悄悄只更新 HK-001。若执行途中失败，则按批量规则记录已经生效及尚未执行项。
