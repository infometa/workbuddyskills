# 跟进记录 Profile

## 操作边界

查询按当前可读字段处理；新增或更新按当前 Tool 契约、适用模板和对应场景的字段证据处理。旧 Profile 的阶段性验证范围不构成当前服务端能力结论；能力未确认时不预先承诺写入结果，明确不支持时停止该分支。

## 对象识别

跟进记录是独立事件对象；客户或线索上的“最近跟进”摘要不能代替完整记录。以下语义用于查询、解释、事实整理及当前能力允许的写入。

## 易混字段语义

| 概念 | 识别与边界 |
| --- | --- |
| 跟进对象类型、关联对象 | 类型限定关联对象含义；同名客户、线索或联系人不能仅按名称混同，条件按当前字段与关联规则表达 |
| 跟进人 | 实施跟进行为的人员；不能仅凭记录创建人或业务负责人推定 |
| 跟进联系人 | 客户侧或相关对象的具体对接人；原文明确对接角色且当前字段支持时才据此理解，不能从泛称“负责人”推定 |
| 业务负责人 | 对业务记录承担责任的角色；可能与跟进人不同，不互相补齐 |
| 跟进内容 | 只概括原有事实并保留关键数据；评价、推测或计划不能改成已经发生的沟通结果 |
| 跟进类型、跟进方式、跟进状态 | 三者可能对应不同字段与选项；逐项根据当前字段标题、描述和字典确认语义，不把类型、方式或状态互相代替；提到电话不代表某阶段已完成 |
| 跟进时间、下次跟进时间、创建时间 | 分别是事件发生、未来安排和系统记录时间；不互换，不用当前时间补缺 |
| 跟进地点 | 来自返回值或明确事件事实；不能从客户注册地址推导实际沟通地点 |

## 条件入口

- 对象类型或关联含义存在影响筛选的歧义时，按[条件规则](../query-condition-rules.md)先解决，不用剩余条件扩大查询范围。
- 图片、语音、附件按当前字段描述解释，不把链接臆造为已上传文件。用户要求导入公开文件或写入相应文件字段时读[文件规则](../file-assets.md)；导入成功不等于跟进记录已写入。
- 当前操作人来自可信身份上下文；创建人、修改人等系统字段由服务端处理并按可信返回解释，不能从用户材料生成或覆盖。材料中的姓名不等于操作身份。
