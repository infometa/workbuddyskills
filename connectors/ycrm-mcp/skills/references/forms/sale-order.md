# 合同订单 Profile

## 对象识别

合同订单记录面向客户的产品/服务及交付、付款关系，与“协议”和采购订单区分。一个订单内的多项产品/服务属于相应明细，不按产品数拆主记录。

## 易混字段语义

| 概念 | 识别与边界 |
| --- | --- |
| 客户、商机关联 | 分别指交易客户与销售机会；同一名称可能出现在不同对象，不能互相替代或自动补关联 |
| 订单编号 | 通常由系统生成；材料中的编号可能是定位既有订单的业务值，可否指定新编号看当前可写性 |
| 订单总额、明细价格/金额 | 区分汇总值、单价和行金额；总额可能由明细统计，不能把总额直接填为某行单价，也不擅自倒推折扣、税率或数量 |
| 订单状态 | 按当前字段选项与明确事实解释；意向、已交付、已付款分别涉及不同事实，不能互相推导状态 |
| 交付日期、地址和要求 | 用于识别交付范围；不同地址或日期可能仍属于同一订单，不能仅据差异拆单 |
| 产品明细 | 按实际 `SUB_FORM` 字段及关系归属解释，不能将明细行 ID 当成订单 ID |

## 操作限制与条件入口

- 编号和金额的生成方式仅作语义提示，可写性由当前新增/更新字段决定；不能写入时说明，借通用字段承接前先确认映射差异。
- 涉及明细增删改时读[子表写入](../subform-write-rules.md)，读取或回读明细时读[子表读取](../subform-read-rules.md)。涉及外部文件才读[文件规则](../file-assets.md)。
- 普通写入交给服务端业务能力处理；Skill 不模拟或承诺库存同步、自动计价、状态流转和跨记录事务。
- 用户明确要求审批处理时才进入[审批规则](../approval.md)；创建订单及工具返回审批信息本身不授权同意或拒绝。
