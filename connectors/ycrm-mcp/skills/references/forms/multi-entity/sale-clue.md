# 线索：身份、交互与需求范围

## 识别依据

独立线索编号或明确分别建档支持候选；没有编号时结合联系人/公司、独立留资或计划跟进对象、需求及来源判断。来源、时间变化本身不证明新线索。

## 合并与区别

- 同一联系人一次交互提出服务器和软件需求，先归入该线索内容；电话、邮箱和需求分段补充不增加线索。
- 同一联系人再次提出独立需求可能形成新候选，也可能延续旧线索；结合明确的新建意图和需求范围，不能仅因“再次”拆分。
- 来源不同但内容指向同一交互时保留来源差异待确认，不自动新建或随意选一个来源。

## 澄清重点

材料有多次交互但没有建档边界时，问是否分别维护；只说营销活动“计划获取很多线索”时尚无具体身份，不能生成虚构线索。用户明确为未来跟进建立具体线索时保留候选，按当前字段补缺，不要求先发生实际留资。
