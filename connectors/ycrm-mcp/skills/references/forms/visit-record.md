# 拜访签到 Profile

## 当前限制

服务端当前不支持新增或更新；只使用对象/字段发现、列表与详情查询。写入请求在此停止，不加载对象多实体写入规则，不以通用写入或拜访计划代写。

## 对象识别

拜访签到记录已发生的签到事件，拜访计划表达安排。查询签到时计划可以是关联对象；用户明确操作计划才单独发现该对象。以下提示用于查询与解释，不授权通知或写入。

## 易混字段语义

| 概念 | 识别与边界 |
| --- | --- |
| 客户、联系人、项目 | 分别指业务主体、对接人员和项目范围；不能因共同出现在材料中就推定关联关系 |
| 拜访内容、类型、状态 | 分别解释事实、分类和进展；按当前选项匹配类型/状态，不能从“有意向”“已回来”等片段猜选项 |
| 签到时间、签退时间 | 分别对应到达与结束事件；计划时间、创建时间或当前时间不能补作实际签到/签退时间 |
| 签到地址、签退地址 | 分别对应各自事件位置；不能由一端地址或客户地址补另一端，结构与格式按当前字段解释 |
| 拜访时长 | 区分工具返回值与自行计算结果；起止时间完整且用户需要时可计算并标明依据，不能称为工具已有字段或写入未知字段 |
| 抄送对象 | 与参与人、客户联系人、负责人不同；返回的抄送字段按事实展示，文本中的姓名或 @ 不自动证明已通知，也不自动授权另发消息 |
| 签到照片、其他附件 | 按当前字段用途及返回元数据区分；普通附件不自动充当签到照片，也不以图片存在证明已经签到 |

## 条件入口

- 查询或解释需要判断材料描述的是同次还是多次拜访时，读[事件边界规则](multi-entity/visit-record.md)；该规则只用于查询中的事件辨别和结果解释，不进入新增或更新路径。
- 需要子表事实时读[子表读取](../subform-read-rules.md)。
- 用户明确要求导入公开文件时读[文件规则](../file-assets.md)，文件导入不等于创建签到或将照片绑定签到。
- 创建人、创建时间等系统字段由可信返回解释，不能从用户描述生成或覆盖。
