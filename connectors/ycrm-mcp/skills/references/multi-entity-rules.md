# 批量主记录与材料分组

本文件用于批量主记录的新增或更新准备，也用于判断未分组新增材料应形成多少条主记录；判断结果可以只有一条。同一父记录多行子表按[子表写入规则](subform-write-rules.md)处理；查询、分析及已明确的单主记录操作不使用本文件拆分或筛除结果。

## 按操作选择路径

| 路径 | 处理 | 对象多实体文件 |
| --- | --- | --- |
| 批量更新 | 从用户目标集合逐条唯一定位，仅校验本次变化，旧事实从可信查询取得 | 不读，不以新增完整性筛除更新目标 |
| 用户已逐条分组的批量新增 | 保留明确记录边界，检查重复引用及父子表结构，逐条校验当前必填项 | 不读，不重新推导分组 |
| 未分组材料拟新增，数量或归属边界待判断 | 按下述协议形成候选，确认边界后进入新增准备；结果可以只有一条 | 从[对象索引](forms/index.md)只读目标对象对应文件 |

## 对象分组依据的用法

对象文件提供识别依据、辅助信号、合并/明细边界及针对性澄清。它们解释材料中的对象或事件，不是额外的必填字段清单。Tool 元数据决定可写结构和约束，不能单凭字段齐全证明两段材料属于两个独立记录。

- 有明确记录边界但缺写入必填值：保留候选，进入字段准备后补缺。
- 有具体业务事实但边界不明：保留原文分段和可能分组，只询问会改变记录数量或归属的差异。
- 只有“几笔款、几家客户”等泛称：保留用户任务与未确定数量，不编造身份或展开虚构记录。
- 识别依据可以来自编号、主体、事件、周期或明确指代的组合，不要求每一项都齐全；辅助信号不能单独决定拆分。
- 对象文件的“澄清重点”仅在歧义影响记录数量、归属或本次操作时使用；上下文已有答案时直接复用，不逐项询问。
- 正反例说明决策差异，不要求生产数据与例子使用相同词语、数字或字段。重复、冲突、确认及失败处理沿用本文件的通用协议，对象文件只补非显然差异。

## 未分组材料协议

1. 保留每个候选的原文、身份/业务锚点及用户要求的动作。独立编号、明确分别建立、明确分组是强信号；客户、日期、金额、地点、状态等差异只辅助判断。
2. 区分多个主记录和一个主记录的多条明细；物料、联系人、条款等差异不能自动增加父记录。同实体别名或补充描述合并；是否同一实体不明则确认。
3. 组合值不同不要求每个分量都变化：同人不同月份、同成品独立 BOM 版本、同客户不同账户都可形成候选，是否独立建档结合用户意图与当前能力判断。
4. 同一事件重复提及去重，不相加金额或数量；用户明确增量、确为不同事件且语义允许时才聚合，冲突值先确认。
5. 分别确认创建意图、业务事实、字段约束。新增不以业务已发生或已有单据为前提；草稿/计划状态按 Tool 能力处理，不补造到账、出入库等事实。
6. 缺少主体、归属、周期或必填值时保留候选及缺项，集中补问，不静默丢弃用户要求处理的条目。没有操作意图的功能介绍不产生写入计划。
7. 模型自行形成的分组提交前，展示主记录数量、每组关键自然值、子表行数及未解决差异，请用户确认；已明确的分组与授权不重复确认。材料提到其他对象不扩展操作范围。

## 批量执行和失败

- 提交前检查各项是否可按原范围执行；已有缺失目标或缺项时，先补齐受影响范围。部分执行仅在用户明确授权后进行。
- 按单条记录追踪执行与回读。默认首个失败或未知结果后停止后续业务写入，说明成功、失败、未知、未执行项。
- 用户明确要求独立逐条尽力处理时，可继续无依赖项；未知项按[共享恢复规则](shared-rules.md)处理，不盲目重交。这里不启用主记录批量删除能力。
- 全成全败要求不能在无事务能力时承诺；不执行未经授权的反向删除或更新。

## 边界示例

- “一个订单包含服务器和服务”：一个主记录，产品明细多行。
- “A、B 各一份订单，每份两项产品”：按用户分组准备两个主记录及各自两行子表。
- “我的九月和十月月报分别录入，材料按月份分好”：主体与年份能从可信上下文确定时准备两条；年份不明只补问年份，不要求额外根因分析。无需读取对象分组文件。
