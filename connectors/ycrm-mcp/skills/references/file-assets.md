# 文件导入和字段使用

## 导入

- `ycrm_file_upload_by_url` 一次接收 1 至 9 个公开 HTTP/HTTPS 文件；全部上传成功时才按输入顺序返回完整文件列表。
- 只接受可公开访问的 HTTP/HTTPS URL：不使用本地路径、`file://`、`data:`，不使用需要登录态（Cookie、Token、Authorization）或内嵌私密凭据的地址；用户只能提供本地文件或私有链接时，说明无法导入并请对方提供公开 URL，不假装上传成功。
- 文件名在业务上可选；用户未指定时按当前 Tool 输入 Schema 处理：允许省略 `fileName` 就省略，仍要求该属性且允许 null 时传 `fileName: null`，不猜造名称。超过 9 个按原顺序分批，每批 1–9 个。文件名、源 URL 和返回元数据逐项对应，不自行替换来源；上传失败不假设已成功文件自动回收。
- 用户明确给出公开 URL 文件清单并要求导入时视为已确认；仅导入文件不要求目标业务字段。需要继续写入业务记录时，必须核对目标记录、图片/附件字段及追加、替换或清空语义，发现歧义、部分失败或范围变化时再请求确认。
- 上传成功只表示企业 OSS 文件对象已生成，不代表业务记录已经写入或审批已经处理；后续操作仍需单独执行并复核。

## 写入字段

- 图片字段使用返回文件对象中的 `downloadUrl` 组成数组，数组顺序即文件顺序。
- 附件字段使用完整返回对象数组；不要只传 URL 代替附件对象。
- 导入成功后文件保存在企业 OSS，后续使用返回的文件对象，不依赖源地址持续可用。
- 字段具体清空、替换和保留语义以当前对象的字段 Tool 描述为准。

## 失败和不确定结果

- 工具按输入顺序逐项上传；遇到首个失败即停止本次调用并返回错误，后续项不再处理。本次调用不会返回失败前已上传文件的元数据，也不会返回“成功 k 项、失败 m 项”的部分结果；此前已上传文件不自动回收，可能成为未被业务记录或审批意见引用的文件。
- 导入成功但用户取消或未完成后续操作时，同样说明已存在未被引用的文件。
- 当前没有文件持久化查询/回读接口；成功上传只核对成功响应和元数据，不虚构重新读取 OSS。
- 已收到成功响应的前序批次按返回元数据确认。错误明确发生在本批上传前的参数校验阶段时，该批可记为未上传；处理中的失败、超时、响应不完整或连接中断且没有完整成功响应时，该批逐项结果未知，可能已有部分文件上传。不能按输入位置猜测成功项或生成文件对象。
- 当前没有查询能力核对结果未知的文件；停止后续批次及依赖写入，不自动重传未知批次。报告已确认导入的批次、明确未上传的批次、结果未知的批次和未执行范围。恢复或只使用已确认文件导致范围变化时按[共享授权规则](shared-rules.md)确认具体差异。
- 任务需要逐文件确认结果时，从开始就每次只上传一个文件；单文件调用结果未知时仍不得自动重传。
- 导入成功后的追加、替换或清空仍进入[表单写入](form-data-write.md)，依赖既有字段值时先读取。
