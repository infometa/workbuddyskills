# 人才库与智能推荐

看有哪些人才库、看系统按职位从人才库推荐了谁。只编排以下两个工具：

- `mcp__moka__list_talent_pools`
- `mcp__moka__list_talent_pool_recommendations`

## 选择工具

- 「我有哪些人才库」「有哪些库可以运营」：用 `mcp__moka__list_talent_pools`。无需入参，返回当前招聘模式下本人可见的库清单，多级库按「父库/子库」的名称路径给出。
- 「这个职位系统从人才库推荐了谁」「推荐结果怎么样」：用 `mcp__moka__list_talent_pool_recommendations`。按职位返回最近一次推荐任务的候选人卡片、推荐分数、推荐总结与推荐原因。

概念先分清：

- **人才推荐不等于候选人**：推荐是系统按职位从人才库算出来的「可能合适的人」，不代表已进入招聘流程；不要把推荐名单说成流程里的候选人，也不要把推荐人数计入流程阶段的数字。
- **库清单与推荐结果是两个问题**：清单回答「有哪些库」，推荐回答「某职位系统推荐了谁」；用户只问其中一个时不要用另一个替代作答。

主动在人才库中按自然语言条件搜索新候选人、跟进已进入流程的候选人、查看职位详情——这些问题应由当前可用的其他 Moka 工具处理。

## 常见问题速查

- 「我有哪些人才库」「有哪些库可以运营」→ `mcp__moka__list_talent_pools`
- 「社招/校招这边有哪些库」→ `mcp__moka__list_talent_pools`（按返回项的招聘模式区分陈述）
- 「这个职位系统从人才库推荐了谁」→ `mcp__moka__list_talent_pool_recommendations`（带职位 ID）
- 「推荐里谁最合适、为什么」→ `mcp__moka__list_talent_pool_recommendations`，按系统给出的分数与原因忠实转述
- 「推荐结果还没出来吗」→ 看返回的任务状态：推荐中如实说明、稍后再查

## 调用规范

1. 通过当前平台的工具发现能力读取实时 description 与参数 Schema，以它们为入参事实源。
2. 稳定顺序是先列库、再按职位取推荐：用户对人才库整体不熟时，先用 `mcp__moka__list_talent_pools` 了解有哪些库，再用 `mcp__moka__list_talent_pool_recommendations` 按职位看推荐结果。
3. 推荐查询需要职位 ID（jobId），它来自职位查询的返回项，不要自行构造；职位搜索本身应由当前可用的其他 Moka 工具处理。
4. 只传用户明确给出的条件，不自行扩展同义条件或推断条件。
5. 分页游标（nextCursor）原样回传，不要自行构造或修改；游标缺省即没有更多。
6. 分页结果只汇报实际取到的范围，需要完整清单就接着翻页，不要把已列出的条数说成全部。
7. 库名不是唯一标识：同名库可能同时存在，转述时按返回的完整名称路径区分（如「重点岗位/算法方向」）。
8. 推荐结果按返回的任务状态解读：推荐中表示任务还在跑、结果未齐，可如实说明再稍后重查；推荐完成才是完整结果；已废弃或未发起过推荐时如实说明该职位当前没有可用的推荐结果，不要凭空生成推荐。

## 结果与权限

- **推荐结果是系统产出**：推荐分数、推荐总结与推荐原因只能原样转述，不要自行改写、重算或补写推荐分，也不要在系统结论之外追加自己的排序依据；可以在忠实呈现之后按用户要求做归纳，但要区分哪些是系统结论、哪些是你的归纳。
- 空的库清单只表示「未返回数据」：可能当前招聘模式下没有本人有权查看的库，也可能企业尚未建库——如实说明，不要反推为无权限。
- 该职位推荐列表为空按「暂无推荐结果」说明，不解释为职位不好或没有合适人选。
- 库的可见范围是本人创建的、公开的与被授权的库，不等于全公司所有人才库；不同账号看到的清单可能不同。
- 系统自动维护的内建库（入职、离职、黑名单、潜在人才库）不在清单中，属正常现象，不要当作数据缺失。
- 清单按当前账号的招聘模式收窄；要看另一种招聘模式的库，需要用户在 Moka 页面切换招聘模式后再查。
- 未能识别当前账号的招聘模式时，列表可能同时含社招与校招的库，按各库自己的招聘模式分别陈述，不要混在一起计数。
- 两个工具都需要 HR 角色权限，面试官、用人经理账号会被拒绝——被拒绝时如实说明权限边界，不要换身份绕行。
- 工具返回的 notices 与 message 是数据解读须知，先读再组织回答，如实转达，不自行改写归因。
- 全部只读：不能建库、改库、授权，也不能把候选人放入人才库或加入招聘流程，这些操作需要用户在 Moka 页面完成。

## 安全边界

- 不向用户展示访问令牌、内部标识符或原始技术响应；职位 ID、分页游标只用于串联工具，不出现在回答里。
- 候选人的电话、邮箱等隐私字段与内部标识不会出现在结果中，不要向用户许诺提供。
- 只使用工具返回的字段组织回答，不虚构推荐理由或候选人背景。
- 推荐数据按当前账号可见的人才库范围返回，不扩散与提问无关的候选人信息。
- 面向用户的回答只用业务语言：没数据说「没有查到」，不说「返回为空/字段缺失」，也不引用参数名或状态值。
- 出现未登录、凭证过期或授权失效时，提示用户重新连接 Moka 连接器后重试；服务异常可稍后重试，报障时附上返回的 requestId。
- 不用缓存结果冒充实时数据；一个能力的问题不能用另一个能力的结果冒充。
