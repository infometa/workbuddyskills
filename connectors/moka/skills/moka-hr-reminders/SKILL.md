# Moka 人事提醒

以人事负责人视角查出需要跟进提醒的人群，按收件人整理成提醒清单并起草可直接转发的文案。只编排以下三个工具：

- `mcp__moka__search_hr_data_list`
- `mcp__moka__get_attendance_reports`
- `mcp__moka__get_onboarding_progress`

## 定位与边界

- 本技能的交付物是「提醒清单 + 逐人/逐组提醒文案」：查出人群、按收件人分组去重、写好每条提醒的内容。**实际发送由用户或宿主的消息渠道完成，本技能不发送任何消息**，也不要声称「已提醒」「已通知」。
- 与「Moka 人事巡检」的区别：巡检交付的是异常盘点报告；本技能在人群名单之上多走一步——生成可直接转发的提醒内容。用户只要盘点结论时不必用本技能。
- 用户在系统里已发起过一轮提醒后仍想补一轮人工跟进时，本技能可以基于同一人群名单起草跟进文案；系统侧提醒是否已发出、发给了谁，以用户提供的信息为准，本技能不代查也不代发。
- 三个工具全部只读，不修改任何数据。

## 提醒场景与人群来源

- 合同到期、试用期到期、离职办理滞留、异动跟进等名单，用 `mcp__moka__search_hr_data_list` 的对应业务场景查询：合同（即将到期、到期未续签、入职未签）、试用期（待转正、试用期离职）、离职（进行中）、异动（审批中、待生效）等，各场景确切取值以工具实时 description 为准。
- 考勤异常人群走月报链路：先用 `mcp__moka__get_attendance_reports` 的月报视图解析月报配置拿到月报标识，再用 `mcp__moka__search_hr_data_list` 的假勤月报场景查列表、按异常项筛出人群；需要逐人核实异常明细（迟到、缺卡次数等）时回到 `mcp__moka__get_attendance_reports` 查单人月报详情。
- 入职材料未齐、入职任务未完成的人群，用 `mcp__moka__get_onboarding_progress`：待入职员工清单、单人材料完整度、任务准备状态与运行详情。
- 审批滞留提醒：本技能的工具无法代查他人的审批进度。用户要做这类提醒时如实说明，请用户自备待提醒名单（或让被提醒人自行在 Moka 页面查看待办），本技能只负责按名单起草文案。
- 其他问题（员工查自己的数据、导出文件、薪酬等）不属于本技能，应由当前可用的其他 Moka 工具处理。

## 编排规范

1. 使用 Moka 连接器提供的工具（本技能内的工具名即实际注册名）；连接器未安装或未连接时如实告知用户，不改用其他来源。
2. 通过当前平台的工具发现能力读取实时 description 与参数 Schema，以它们为入参事实源。
3. **确认场景与范围**：先与用户对齐提醒事项类别、时间口径（如「未来 30 天到期」）、提醒对象是员工本人还是其负责人；只传用户明确给出的条件，不自行扩展筛选范围或时间区间。
4. **查询人群**：`mcp__moka__search_hr_data_list` 是两段式——先取字段目录与筛选协议（`schemaHash` 原样回传），再执行查询；枚举字段先取候选值再构造筛选，禁止猜测候选值。结果按页返回：总数是符合条件的全量数，人群要作为提醒依据时需翻页取全，只汇报实际取到的范围。
5. **考勤异常链路不跳步**：先解析月报配置、再查月报列表筛人群、需要时才查单人详情；不要跳过配置消歧凭月份直接猜标识，也不要用单人详情逐个遍历代替列表查询。
6. **按收件人聚合去重**：同一收件人涉及多条事项时合并为一条提醒，把事项并列列出，不逐条重复；区分「收件人」与「事项关联员工」——提醒办理人跟进他人事项时（如提醒负责人跟进新员工材料），文案对象是办理人，关联员工只作为事项信息写明。收件人与关联员工是不是同一人拿不准时先问用户，不要默认发给事项员工本人。
7. **起草文案**：每条提醒包含四要素——对象（称呼收件人）、事项（业务名称与具体清单）、截止时间或风险点、期望动作（要做什么、在哪里办）。以用户（发起人）名义署名，落款前与用户确认。
   - 人数较多时先给 1–2 条样例让用户确认模板与语气，确认后再批量生成，避免整批返工。
8. **交付**：向用户输出「提醒清单 + 逐条文案」两部分。清单分两栏：可提醒（收件人明确）与暂不提醒（收件人无法确定、同名歧义待确认、对方已离职或状态异常等），暂不提醒的逐条写明原因交用户人工处理，不得静默丢弃。最后说明发送方式由用户决定，可复制转发或交给宿主的消息渠道。
9. 用户点名要提醒的具体某个人时，同样先经工具查询核实其在册状态与事项数据后再入清单；查不到时如实告知并列入暂不提醒，不凭记忆或用户口述编造事项内容。

## 文案规范

- 文案里只写完成提醒所必需的信息：不写电话、证件、薪酬数值等他人隐私字段，也不写内部标识。
- 不代替业务判断给员工定性：不写「违规」「旷工属实」等结论性表述，只陈述工具返回的数据事实（如「本月记录显示缺卡 3 次」），把定性留给收件人与用户。
- 事项用业务名称表述，不出现工具名、字段名等技术词；同类事项合并表述，人数多时可按部门或事项类型给分组文案。
- 语气是提醒与协助，不是问责：说明事项与期望动作即可，不施加压力性措辞；对负责人类收件人可附「如已处理请忽略」。
- 涉及截止时间的，把相对日期换算成绝对日期写入文案；查询用的时间口径与文案里的截止时间要一致，回答中说明实际查询的日期或区间。

## 结果与权限

- 空列表按「该条件下未返回数据」处理：可能是条件过严或范围内确实没有记录，不得反推为无权限，也不要断言「没有需要提醒的人」。
- 工具返回的 notices 与 message 如实转达，先读 notices 再组织清单。
- 查询需要对应场景的人事管理权限：人事列表按场景鉴权、考勤月报需月报权限、入职进度需相应查看权限；无权限时工具会明确提示，如实转述，不要绕行。
- 考勤月报数据有账期与封存状态：文案引用的迟到、缺卡等数字要注明所属月份；账期未封存时数据可能还会变化，在清单中注明口径。
- 人群名单以工具返回为准：名单里没有的人不主动补进提醒清单；用户点名要加的人，在清单中标注「用户指定」。

## 安全边界

- 不向用户展示访问令牌、内部标识符或原始技术响应；月报标识等句柄只用于串联工具，不出现在回答与文案里。
- 不虚构工具未返回的字段；电话、证件、头像等隐私字段与内部标识不会出现在结果中，不要向用户许诺提供。
- 本技能是管理视角的员工数据，只在用户为人事管理目的提问时使用，文案与清单不扩散与提醒事项无关的员工信息。
- 全部只读且不发送：不能修改人事数据，不能代用户发出任何消息；在拿到用户确认发送结果之前，不要把提醒描述为已送达。
- 用户把文案转发后回来同步发送结果时，只做口径整理（几人已提醒、几人待跟进），不据此更新或推断任何系统数据。
