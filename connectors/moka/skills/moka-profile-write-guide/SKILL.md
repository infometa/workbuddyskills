# Moka 员工档案维护指引

档案维护是「先读清楚、再写准确」的任务：写之前先定位员工、确认当前值与可选范围；写的过程中每一步都由工具校验；写完之后读回验证。本指引约束这条链路上的稳定原则。

## 先定位、再写入

- **员工标识来自查询，不来自用户口述**。用户只会给你姓名或工号，先用花名册按姓名/工号查到目标员工，拿到员工标识与相关字段的当前值。同名员工列出候选请用户挑，不擅自选择。
- **目标值说不清就先追问**。用户没讲改成什么时，把该字段的可选范围带给用户选择；选项类与引用类字段（工作地点等）的取值必须来自候选，原样选用，不把口语化说法直接当值提交，也不改写成相近候选。
- **字段键两种形态都可用**：直接传字段名，或原样使用花名册返回的「业务域#字段名」形式（如 `job#office_address`），工具会自行归一。

## 任职关键字段变更属于人员异动

变更部门、职务、职位、职级、管理职级、员工类型、直属上级、虚线上级、导师、工作地点以及企业自定义的任职字段，不只是改一个字段值，而是记一条人员异动：

- 首次调用会返回可选的异动事件与原因候选。把候选如实交给用户决定，再从候选中原样选择补齐异动参数后重新调用；候选里没有的类型就是不可用，不编造。
- 异动生效日期只支持当天。用户要求未来生效时，说明需要在 Moka 中走企业变更流程，不强行写入。

## 确认链不可省略

档案写入固定为三步，任何一步都不能跳：

1. 首次调用只返回操作摘要与确认码，**不会实际写入**——拿到摘要不等于改好了。
2. 向用户完整复述摘要：操作类型、档案场景、员工、变更内容、异动事件与生效日期。等用户明确同意。
3. 用户同意后用**完全相同的参数**加确认码再调用一次才真正执行。任何参数变化都会使确认码失效，必须重新预览，不得沿用旧确认码。

删除记录同样走这条链，且不可逆——确认前向用户讲清后果。任职信息、个人信息、合同信息、异动记录四类只能编辑已有记录：目标记录由工具从已读取的档案数据中自动定位，不要向用户索要记录标识，更不能用员工标识顶替。

## 写后读回再交付

执行成功后，重新查询该员工的对应字段，确认新值已生效再向用户交付结果。读回发现未生效时如实说明并排查，不声称已改好。

## 边界

- 权限不足、取值不在候选、记录不匹配时，工具会给出明确提示——如实转达并按提示改正后重新发起完整流程，不原样重放、不绕行。
- 确认码、内部记录标识只用于串联调用，不展示给用户；操作摘要中的敏感字段值已被脱敏，不要许诺提供明文。
- 只在用户为人事管理目的提问时使用本能力；用户只是想「查」时不要用写入能力。
