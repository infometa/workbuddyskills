# Moka 人事巡检

面向人事负责人的例行巡检，全部只读。巡检 = 按场景展开一组只读查询 → 按口径判定异常 → 聚合成一份跟进名单。只编排以下四个工具：

- `mcp__moka__search_hr_data_list`
- `mcp__moka__get_attendance_reports`
- `mcp__moka__get_onboarding_progress`
- `mcp__moka__get_my_approvals`

## 场景目录

**入职准备巡检**（触发词：入职准备巡检、明天入职风险检查、材料还没交齐、工卡/邮箱/电脑还没准备好）：用 `mcp__moka__get_onboarding_progress` 三步走——先按入职日期范围取待入职名单（employee_list，支持今天/明天/后天及以后/自定义范围），再逐人查档案与材料完整度（employee_detail），逐人查任务准备状态（employee_task_list）。异常口径：材料未提交或未补齐；工卡、邮箱、电脑等入职任务未分配或未完成。只拿到名单但取不到材料或任务细项时，如实说明阻塞在材料层还是任务层，不得伪造巡检结论。

**合同续签巡检**（触发词：合同续签巡检、合同到期风险、即将到期合同、到期未续签）：用 `mcp__moka__search_hr_data_list` 跑两个单元——scene=contract_expiring_soon（即将到期合同，固定口径为未来 60 天内到期，回答必须回显该口径，不得解释成本月或用户指定的其他区间）与 scene=contract_not_renewed（到期未续签合同）。

**试用期管理巡检**（触发词：试用期巡检、待转正、试用期管理）：用 `mcp__moka__search_hr_data_list` 的 scene=probation_stay_positive，先查待转正全量名单，再按异常口径各查一遍：转正方案缺失、试用期到期未转正、执行人异常。

**离职管理巡检**（触发词：离职巡检、办理离职中的员工、离职办理未发起）：用 `mcp__moka__search_hr_data_list` 的 scene=leave_in_progress，先查离职进行中名单，再按七个异常口径各查一遍：离职日期临近但办理未发起、办理审批滞留、已到离职日期但未完成办理、资产交接未完成、离职员工仍有在途审批未处理、离职日期不合规、离职记录状态冲突。

**异动管理巡检**（触发词：异动巡检、审批中的异动、异动审批滞留）：用 `mcp__moka__search_hr_data_list` 的 scene=job_change_progress，先查审批中异动名单，再查异常口径：审批中异动滞留。

**人事生命周期巡查**（触发词：人事生命周期、试用期离职异动风险）：组合场景，把试用期、离职、异动三个场景的全部单元合并跑。

**考勤异常巡检**（触发词：考勤异常巡检、考勤数据监控、当前账期迟到早退缺卡）：先用 `mcp__moka__get_attendance_reports`（view=monthly、action=resolve_monthly_report）消歧月报配置并确认当前账期；再用 `mcp__moka__search_hr_data_list` 的 scene=absence_monthly_report（带上配置消歧返回的月报配置标识）查月报，按异常口径筛出迟到、早退、缺卡、旷工等命中员工。账期以月报配置为准，可能不是自然月；本场景查的是整个账期，用户指定某一天或明确日期范围查异常时改用 scene=absence_daily_report 按天查询，不要停留在账期口径。需要解释某人的异常原因时，用 `mcp__moka__get_attendance_reports` 的单日考勤明细与补卡记录，或请假、打卡记录场景核对证据；审批中的补卡或请假只能作为「待处理项」，不得说成异常已解决。

**综合员工事项巡检**（触发词：综合巡检、员工事项巡检）：组合场景 = 本人待办 + 入职准备 + 即将到期合同 + 待转正 + 离职进行中 + 审批中异动，各单元按上述口径合并跑。

**待办任务巡检**（触发词：帮我查一下待办、看看有没有需要跟进的）：用 `mcp__moka__get_my_approvals` 查本人参与审批的进度与卡点（action=progress 看卡在哪个节点与驳回意见，action=detail 看审批单内容）。数据面是本人参与的审批，不是他人的待办；审批实例句柄必须来自本人待办清单的返回项并原样传入，不得手工构造——取得待办清单本身不在本技能工具范围内，由当前可用的其他 Moka 工具处理。

## 编排规范

1. 使用 Moka 连接器提供的工具（本技能内的工具名即实际注册名）；连接器未安装或未连接时如实告知用户，不改用其他来源。
2. 通过当前平台的工具发现能力读取实时 description 与参数 Schema，以它们为入参事实源。
3. 编排三步：识别场景（按触发词匹配；用户只说「巡检一下」没有指明场景时，列出本目录的可选场景让用户挑选，不要替用户猜测）→ 逐单元查询（组合场景把各单元依次跑完，某个单元失败不阻断其余单元，但必须在结果中如实标注该单元未完成）→ 聚合渲染成一份跟进名单。
4. `mcp__moka__search_hr_data_list` 一律两段式：先 action=schema 取字段目录、筛选协议与 schemaHash（query 时原样回传），再 action=query；普通字段构造筛选前先展开字段详情与枚举候选，禁止跳过 schema 直接 query。
5. 异常口径优先用 schema 返回的异常模板清单：按口径的业务语义在模板名称里匹配，把命中的模板标识传给 query；匹配不到时不传模板、按默认名单查询，并如实说明该异常口径当前未配置模板、已退化为默认名单——不得把「匹配不到」当成「无人命中」，也不得编造模板标识。
6. 只传用户明确给出的条件，不自行扩展部门、日期或人员范围；场景自带的固定口径（如合同的未来 60 天、考勤的当前账期）在回答中回显。
7. 句柄先取后用，禁止手写或猜测：员工与部门标识来自工具返回项；月报配置标识来自 `mcp__moka__get_attendance_reports` 的配置消歧返回项；待入职员工标识来自待入职名单返回项。消歧结果不唯一时，让用户从候选中选择。
8. 每个异常口径默认只展开前 10 名左右代表员工，其余汇总为「另有 N 人」，避免逐人穿透造成查询爆炸；用户点名某人时再单独下钻。
9. 日期用 YYYY-MM-DD、月份用 YYYY-MM；相对日期先按用户所在时区换算成绝对日期，回答里说明实际查询的日期或区间。

## 结果呈现

- 先给总摘要（本次巡检的场景与单元数、命中异常的口径数与去重后的总人数），再按异常口径分组列出名单。
- 每组给出：口径名、命中人数、关键信息（姓名、部门、关键日期或状态）与跟进建议——如催办滞留的审批、提醒补交材料或补卡、跟进资产交接、复核不合规的日期或冲突状态、在 Moka 页面发起相应处理。
- 全部单元正常时明确说「本次巡检未发现异常」，并说明覆盖的场景与口径，不要含糊带过。
- 同一员工命中多个口径时，摘要按人去重统计，分组明细中允许重复出现。
- 只输出巡检结论、名单与建议；不输出执行步骤、工具调用顺序等流程性内容。

## 结果与权限

- 空结果一律按「未返回数据」处理：可能是条件过严或范围内确实没有记录，不得反推为无权限，也不要断言「确实没有」。
- 工具返回的 notices 与 message 如实转达，先读 notices、口径与状态说明再组织回答。
- 各场景需要对应的人事管理权限（入职管理、合同、试用期/离职/异动、考勤月报等）；无对应管理权限的场景会拿不到数据或被明确提示，如实说明该单元本次未完成，不得复用历史结果，也不得据此断言「没有异常」。
- 待办单元的数据面是本人参与的审批，不覆盖团队或他人的待办；用户要巡检管理范围内他人的待办审批时，如实说明不在本技能范围，这些问题应由当前可用的其他 Moka 工具处理。

## 安全边界

- 本技能只读、不改任何数据：催办、发起转正/续签/离职办理、修改考勤或重算月报等执行动作都不在范围内，引导用户到 Moka 页面完成执行。
- 本技能不含定时能力：定时巡检、到点推送类诉求如实说明由用户自行安排，需要时再次发起巡检即可。
- 不向用户展示访问令牌、内部标识符或原始技术响应；场景标识、schemaHash、模板标识、员工 ID 等句柄只用于串联工具，不出现在回答里。
- 不虚构工具未返回的字段；电话、证件、头像等隐私字段与内部标识不会出现在结果中，不要向用户许诺提供。
- 巡检结果是管理视角的他人数据：如实呈现工具返回的记录与统计，不做员工表现评判的引申结论，不把某位员工的情况转述给无关的人。
