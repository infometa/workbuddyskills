# Moka 入职

以入职负责人视角跟进入职进度，全部只读。只编排以下一个工具：

- `mcp__moka__get_onboarding_progress`

## 选择工具

`mcp__moka__get_onboarding_progress` 是单工具多视角，按 action 选择：

- 待入职清单：分页查询普通待入职员工。
  - 入职日期支持相对口径（昨天及以前/今天/明天/后天及以后/今天及以前）或自定义区间。
  - 还可按姓名、部门、职位、工作地点、员工类型、签署状态、信息审批状态、入职地点、入职计划、职级、公司筛选。
  - 适用于「今天有哪些待入职员工」。
- 材料齐备度：按员工查档案与材料完整度，回答「这名员工材料是否齐全」。
- 任务视角：
  - 任务聚合统计：当前账号数据权限范围内各任务的完成情况，可按截止日期、名称关键词、负责人、待入职员工、入职计划筛选。
  - 任务下钻：从聚合任务查某任务下已完成或未完成的员工任务实例。
  - 员工任务：按员工查其全部任务的准备状态，可按任务分类筛选（团队融入、培训、了解公司、手续办理、第三方培训、发起签署）。
  - 任务详情：按运行任务标识查单条任务的运行详情。
- 扫码入职：
  - 配置摘要：某个扫码入职配置的内容。
  - 员工总数：当前账号作为负责人可见的扫码员工总数——仅问「扫码进来多少人」时用它，不必拉列表。
  - 员工列表与详情：分页查可管理通道下的扫码员工（可按姓名、部门、职务、职位、配置、地点、员工类型筛选），再按记录标识看单人安全字段详情。

易混辨析：

- 「普通待入职」与「扫码入职」是两条数据面：前者走待入职清单与任务视角，后者走扫码入职的配置、总数、列表与详情，不要混用。
- 任务的「聚合统计」回答整体完成情况，「员工任务/任务下钻」回答具体到人的状态；先统计后下钻，不要为汇总问题逐人拉取。

候选人筛选、面试、录用审批等招聘流程侧问题，以及员工入职后的花名册与档案管理，不在本技能范围内。这些问题应由当前可用的其他 Moka 工具处理。

## 调用规范

1. 使用 Moka 连接器提供的工具（本技能内的工具名即实际注册名）；连接器未安装或未连接时如实告知用户，不改用其他来源。
2. 通过当前平台的工具发现能力读取实时 description 与参数 Schema，以它们为入参事实源；各 action 的参数彼此严格隔离，只传该 action 声明的参数。
3. 只传用户明确给出的条件，不自行扩展日期、部门或状态筛选；自定义入职日期区间必须起止成对提供。
4. 句柄先取后用，禁止猜测：
   - 员工标识来自待入职清单的返回项。
   - 任务下钻时，聚合任务的模板标识与任务名称必须取自任务统计的同一返回项，成对传入。
   - 运行任务详情只能用员工任务或任务下钻结果里的运行任务标识，不能拿任务统计的模板标识充当，两者语义不同。
   - 扫码员工与扫码配置的标识来自对应列表或业务上下文。
5. 协议外、身份控制或含义不明确的筛选条件工具会直接报错，不会忽略条件扩大范围；报错时如实转述并向用户澄清条件，不要换个说法重试猜测。
6. 相对日期（「今天」「本周」）按用户所在时区换算，清单查询的相对口径取值以工具实时 description 为准，回答里说明实际查询的日期范围。
7. 列表结果按页返回，只汇报实际取到的范围；需要完整清单就继续翻页。

## 结果与权限

- 空结果一律按「未返回数据」处理：可能是当天确实没有待入职员工或条件过严，不得反推为无权限，也不要断言「确实没有」。
- 工具返回的 notices 说明数据范围、引用键与结果口径，消费前必读，如实转达其中面向用户的信息。
- 数据范围受当前账号的查看权限约束：任务统计只覆盖当前账号数据权限内的任务，扫码视角只覆盖当前账号可管理的通道；如实按此口径转述，不要把可见范围说成全公司。
- 材料齐备度按返回内容逐项转述，未提交不等于缺失流程，不要替系统判定「不合格」。
- 任务完成情况以返回的统计与状态为准，不要根据截止日期自行推断「已逾期未完成」之外的结论。
- 待入职员工尚未正式入职，状态随时可能变化，回答时说明数据的查询时点。

## 安全边界

- 不向用户展示访问令牌、内部标识符或原始技术响应；员工与任务的标识句柄只用于串联工具，不出现在回答里。
- 不虚构工具未返回的字段；电话、证件、头像等隐私字段与内部标识不会出现在结果中，不要向用户许诺提供。
- 待入职员工信息属于敏感人事数据，只在用户为入职管理目的提问时使用，不扩散与问题无关的员工信息。
- 全部只读：不催办任务、不修改入职安排、不代提交材料；用户要操作时引导其在 Moka 页面处理。
