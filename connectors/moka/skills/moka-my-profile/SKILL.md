# 我的档案

帮员工查清自己的档案信息、绩效结果与工资条状态。只编排以下两个工具：

- `mcp__moka__get_my_profile`
- `mcp__moka__get_my_payslip_status`

## 选择工具

- 问任职信息：我在哪个部门、职务职级是什么、工号、入职日期、员工类型、工作地点——`mcp__moka__get_my_profile`（view="profile"，缺省）。
- 问汇报关系：「我向谁汇报 / 我的直属上级是谁」——同样在 view="profile" 的任职信息里。
- 问「我入职多久了 / 工作几年了」：用任职信息里登记的入职日期与当前日期换算，回答时说明基于登记的入职日期。
- 问个人基本信息：登记的学历、联系方式、居住地址、政治面貌、证件等——同一次 view="profile" 调用会一并返回基本信息、联系方式、个人概况三个分组，不必再查。
- 问绩效：我最近一次绩效结果、上个周期考核怎么样——同一工具传 view="performance"，返回最近一次本人可见的已归档绩效结果。
- 问工资条状态：本月工资条出来了吗、我有没有工资条、有没有要确认的——`mcp__moka__get_my_payslip_status`，返回开通状态、是否有已发放记录、是否待确认与查看验证要求。
- 问「工资条在哪看 / 怎么看」：同一工具返回 PC 与移动端的查看入口指引，转达给用户即可。

易混概念先分清再回答：

- **档案 vs 绩效**：两者是同一工具的两个视角，问「我的档案 / 汇报关系」用缺省视角一次查全，问绩效结果才传 view="performance"，不要为档案问题多查绩效。
- **工资条状态 vs 工资金额**：`mcp__moka__get_my_payslip_status` 只回答「有没有、要不要确认、在哪看」，**不返回任何工资金额、工资项或月份明细**。金额受工资条密码/短信验证码保护，需本人在 Moka 页面完成验证后查看。
- **待确认 vs 没有工资条**：「有待确认的工资条」只统计模板要求确认且尚未确认的，没有待确认不代表本月没有工资条；「有没有记录」才是存在性结论。
- **登记信息 vs 实际情况**：档案返回的是登记在人事系统里的信息。用户说登记有误、要改信息时，说明本技能只读、不能代改，请到 Moka 页面走个人信息修改流程。
- **他人信息**：本技能只覆盖本人。问同事或下属的档案，这些问题应由当前可用的其他 Moka 工具处理。

## 调用规范

1. 通过当前平台的工具发现能力读取实时 description 与参数 Schema，以它们为入参事实源。
2. 只传用户明确给出的条件，不自行扩展；两个工具都不需要用户提供任何身份参数，身份由当前会话决定。
3. 用户问「我这个月工资多少 / 帮我看下工资条金额」时：调用 `mcp__moka__get_my_payslip_status` 确认状态后，如实说明本技能查不到金额，把返回的查看入口指引转达给用户，请其本人到 Moka 页面完成验证后查看。
4. 不猜测、不推算任何金额，也不要求用户提供工资条密码或短信验证码来「代查」。
5. 回答档案问题前先读返回的 notices：受控字段为 null 的语义、脱敏规则、分组覆盖范围都在里面，与结论相关的提醒如实转达。
6. 绩效视角只有最近一次结果；用户要历史多个周期时，如实说明当前只能看到最近一次。
7. 结果带本次查询视角的回显，按视角读对应侧内容；另一侧为空是正常结构，不要当成缺数据。
8. 跨事务组合只组合问题真正涉及的事：如「按我的职级该休几天年假」= 本技能查职级 + 制度与假期问题交给对应能力，不要替用户脑补规则。

## 结果与权限

- 任职字段为 null 有两种可能：企业档案权限未向本人开放该字段（职级、职务、直属上级、部门、工号、入职日期等均受档案权限控制），或数据本身未录入。接口不区分这两种情况，不要把 null 解读为「没有职级 / 没有上级」。
- 个人信息分组仅覆盖基本信息、联系方式、个人概况；银行卡、紧急联系人、家庭成员等不在范围内，完整信息请用户到 Moka 员工端「个人资料」查看。
- 手机号、证件号已脱敏（仅保留末 4 位），如实呈现脱敏后的值，不要尝试补全。
- 分组内某字段有名无值表示数据未录入；某字段完全不在列表里表示本次未返回该字段，两种情况都不能反推企业的权限配置。
- 分组为空或字段缺失按「未返回数据」处理，不得反推为无权限，也不要断言用户没有这项信息。
- 企业未向本人开放「个人信息」页时，工具会降级为只返回任职信息并在须知中说明：如实转达，不当作错误；个人信息分组为空不影响任职信息的有效性。
- 查看工资条明细需要哪种验证（工资条密码、短信验证码）以返回为准，转达给用户便于其提前准备。
- 绩效结果为空表示当前没有可返回的已归档结果，不解释为「绩效差」或无权限。
- 绩效结果只呈现返回的结论与字段，评价口径以返回内容为准，不做主观解读或横向比较。
- 企业未开通工资条服务或未向本人开放时，工具会返回明确提示，如实转达其 message，可建议联系管理员确认。
- 「没有已发放的工资条记录」是存在性结论，不区分具体月份；用户确认本月应发而未见时，建议联系管理员。

## 安全边界

- 数据面仅限本人：两个工具都只返回当前用户自己的数据，不能用来查他人档案或工资信息。
- 绝不输出、猜测或推算任何工资金额、工资项或月份明细。
- 不要求用户在聊天中提供工资条密码、短信验证码或任何登录凭证，也不在回答中输出这些内容。
- 不向用户展示访问令牌、内部标识符或原始技术响应；不虚构工具未返回的字段。
- 面向用户只用业务语言：没数据说「没有查到」，解释原因不引用字段名、参数值或状态码。
- 不用缓存结果冒充实时数据；档案与工资条状态可能变化，用户再次询问时重新查询。
- 出现未登录或授权失效时，提示用户重新连接 Moka 连接器后重试。
