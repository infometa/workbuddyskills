# Yihook 汽车营销短视频

此 WorkBuddy Skill 使用已连接的 yihook MCP，通过宿主原生 OAuth 授权。缺少业务工具或权限时，请用户在 WorkBuddy 重新连接并授权；不要索要或输出 Token。业务均调用主站 MCP。附件上传使用包内 `scripts/upload.mjs`，先阅读 [原样上传指引](references/upload.md)。通过宿主能力保存工具原始 JSON 响应后交给脚本，不重新拼写或编码签名字段，不临时编写 curl/Python 上传命令；脚本只负责 OSS 字节传输。


方案版本、素材用途、确认范围和任务信息仅由宿主在单次对话中维护。每个渠道固定使用其所属账号、素材、积分和任务；以本包 runtime 的真实契约为准，不通过发现其他工具切换后端。声音通过生成模型与提示词表达，无独立配音、配乐或剪辑收费步骤。

## 用户提供什么

| 内容 | 要求 |
|---|---|
| 车辆图片 | 生成成片必填，至少1张清晰车辆图；同一车型可补充不同角度、内饰与局部细节，多车型或多版本先确认制作范围。只写创意或提示词时，可先提供标注素材缺项的概念稿。 |
| 车型介绍或卖点 | 选填；先识别图片，只追问无法确定的车辆主体、版本或必须展示的信息，不要求用户先写好卖点文案。不从模糊照片推断准确车型。 |
| 营销目标或活动信息 | 选填，如展示外观、介绍卖点、门店引流、预约试驾或品牌氛围；涉及门店、价格、优惠或权益时，需提供对应的真实信息。 |
| 人物图片 | 选填，用于参考出镜人物形象；需要人物但未提供时，根据场景设计虚拟出镜人物，不阻塞制作。无需人物的车辆展示片不强行加人。 |
| 补充要求 | 选填，如受众、发布渠道、场景、风格、口播内容、语言、时长、不露脸或无口播。 |

## 默认生成设置

| 项目 | 默认值 |
|---|---|
| 生成入口 | 当前发行渠道的视频生成能力 |
| 模型与模式 | Seedance 2.0、角色参考 |
| 清晰度与画幅 | 720p、9:16竖屏 |
| 时长与数量 | 默认15秒、1条；单条最长15秒 |
| 声音 | 中文口播、轻微场景环境音、与场景相符的背景音乐 |

用户明确要求的语言、声音、画幅等在可用范围内优先采用；单条时长始终遵守上限。默认根据场景、情绪与镜头节奏搭配背景音乐，音量不盖过口播或关键环境声；仅在用户明确要求不要背景音乐时关闭配乐。无口播仅去掉口播人声，仍保留场景配乐与环境音；完全静音表示关闭所有声音。人物是否出镜与是否口播分别判断。

在展示完整方案与预计积分前，核对模型、模式、设置及素材引用的实际支持情况，不支持时先按异常处理规则调整；提交前仅复核是否发生变化。车辆与人物分别标注素材用途，按工具实际支持的方式引用；“角色参考”不要求必须有人物，也不将车辆图误标为人物图。

## 交互流程

1. **整理需求与素材**：识别营销目标、车辆和人物素材，逐车建立图片与版本对应关系。只追问影响制作的缺项或冲突，尽量一次问齐；不让用户逐项确认已知信息或默认设置。用户授权“你决定”等情形时，按下方自主决策规则直接完成方案。
2. **完成方案与内部检查**：先选营销场景，再应用人物规则。按内容目的编写口播与动作，核对事实、素材角度覆盖、模型与设置支持、素材可访问性及完整表达所需时间，自拟稿在展示前完成精简；具体规则见“内容较多时如何处理”和“口播与镜头规则”。
3. **取得报价，与完整方案一起展示并确认一次**：先按最终素材、模型、设置和条数取得真实预计积分，再在同一轮回复中展示创意方向、素材用途、完整提示词（含时间分镜及对应口播）、设置、条数、预计总积分和方案版本；多条任务同时列明各条积分。口播时长注明实测或估算，全文可从分段台词汇总。最后只询问一次是否按该方案和报价生成，不先问“文案是否满意”再另问费用。用户回复“可以，就这版”等明确同意后，视为确认本轮展示的内容、设置、数量与报价，直接进入提交步骤。初始“帮我做”不替代这次合并确认。用户也可直接编辑展示的完整提示词并发回，按下方“用户手动修改提示词”规则处理。
4. **提交生成并跟进**：用户确认后按该版本直接提交，不再重复询问。提交前复核已确认的设置、素材引用及费用是否变化；有实质变化则更新方案后统一确认。逐条保存方案版本与任务标识并查询对应原任务；修改时按“再做一条或修改版本”处理。
5. **交付结果**：提供预览、下载及实际规格；按通用约束检查车辆、人物、动作、口播与文字。列明发现的问题和未检查项，不凭生成成功判定质量合格，不自动付费重做。

用户只要提示词或明确暂不生成时，交稿即止。确认仅覆盖本次方案、条数和费用；多个创意备选不代表多次生成授权。必要的事实澄清不作为额外审批步骤，能在最终方案中合并确认的修改一并展示。

同一任务保留需求、素材映射、方案版本、确认范围与真实任务信息；用户品牌和车型不成为其他任务的默认配置。多条制作时，逐条记录主题、方案、任务标识、状态与结果；部分成功先交付成功条目，并列明其余状态，不整批重做。失败条目的重做单独列出修改内容与预计积分，按版本规则确认。

## 只上传图片时如何追问

先识别车辆与图片可支持的画面，不直接要求“请提供卖点”。

| 图片情况 | 追问示例 |
|---|---|
| 车辆外观明确、未说明用途 | “这张图可以先做车辆外观展示。想侧重门店引流、卖点介绍，还是出游氛围？没有特别要求的话，我先围绕外观和日常出行设计。” |
| 车辆品类明确、具体车型或版本不明 | “如果要在口播里提到具体车型，请补充车型和版本；不需要提车型的话，我先按图片中的车辆外观设计，不加入配置或性能介绍。” |
| 图片模糊、车辆主体不清楚 | “这张图里车辆细节不够清楚，请补一张清晰车辆图；如果有指定车型，也可以一起说明。” |
| 只有外观图、要求展示内饰或功能 | “现有图片只能支持外观展示。要拍后排、内饰或功能操作，请补同款同版本的对应图片和必要说明；也可以先做外观方案。” |

用户说“你决定”“你看着做”或表达同等授权时，保留已明确的要求，其余生成设置采用默认值，创意方向、人物安排、口播和配乐由 Skill 根据现有素材与营销目标决定，不再追问风格、人物、配乐等可自行判断的偏好。将采用的默认值与创意选择写入完整方案，与真实预计积分一起展示，供用户统一确认一次；该授权不替代生成前的方案与报价确认。只有车型或版本冲突、必要卖点缺少依据、核心画面缺少必需素材、模型能力限制等影响真实性或执行且无法按现有规则解决的问题，才继续集中追问必要信息，不擅自删改核心目标。未明确营销目标时，优先围绕素材支持的外观及已有内饰细节展示，不默认导向直播或促销。报价不可得时仍按异常处理规则展示草案，不发起生成确认。

## 内容较多时如何处理

**禁止 Skill 将自拟超长稿作为候选方案展示或提交。** 所有镜头、口播、必要动作与收尾必须在所选时长内完整结束，并遵守单条上限。不能靠加速、截断台词或过快剪辑通过检查。

- **Skill 自拟内容**：围绕用户目标控制信息量，在展示前自行缩减重复表达、次要镜头和自加内容，不让用户替 Skill 解决写得过长的问题。不能因此删除用户指定台词或必要卖点。
- **用户指定内容过长**：先给出符合时长的精简方案，标明拟删改的原句或卖点。已有明确删改授权时按授权处理；否则将删改说明与完整方案、预计积分合并，请用户一次确认。必须保留的内容有歧义时，只追问必要的取舍，不先展示一版明知超时的完整稿。
- **缩减无法满足要求或用户拒绝缩减**：再引导按卖点或场景拆条。逐条完整表达，不机械截断句子或动作，列明各条主题、时长、总条数及总预计积分，在完整方案中一次确认后执行。用户已明确拒绝缩减时不反复劝删，也不自动增加条数。

拆条后的跟进与部分成功处理沿用交互流程中的逐条记录规则。用户要求单条超过上限时，说明限制并按上述顺序处理。时长判断方法统一见“口播与镜头规则”。

## 其他素材情况

| 情况 | 处理方式 |
|---|---|
| 多车型、多版本或多种车身颜色 | 确认主推车辆，以及分别制作还是同片展示；分清各自参考图与卖点，不混车型、版本或配置。 |
| 只有人物图、没有车辆图 | 提示补充车辆图，人物图不能替代车辆素材；可先整理概念方案。 |
| 多张人物图或合照 | 出镜对象不明确时，确认使用哪一个人、哪张图作为主要参考，不自动混合不同人的外貌。 |
| 人物图只有面部，但需要全身出镜 | 在方案中说明服装、身体及未展示部分将由模型补全；有特殊要求时再补图或描述。 |
| 车辆图带销售人员、促销文字或复杂背景 | 默认只参考车辆；需要沿用人物时确认，不自动照搬促销文字、价格或背景。 |
| 外观图与内饰图可能不是同款同版本 | 明确指出冲突，确认素材对应关系后再使用，不把不同版本的细节拼在同一辆车上。 |
| 功能操作或配置不清楚 | 询问实际功能与操作方式，必要时补充资料；无法支持时提出只展示外观或静态细节的方案，不编造操作。 |
| 看不清车牌、标识或局部细节 | 不自行补造准确文字或结构，优先改用现有参考可支持的镜头；必须展示时补清晰素材。 |
| 图片与描述矛盾 | 明确指出冲突，如车身颜色、轮毂或车型版本不同，确认后再写提示词。 |
| 未提供门店活动或优惠依据 | 可用预约试驾、到店咨询等一般性引导，不编造门店地址、价格、优惠金额或权益。 |

## 创作前读取参考

新建或修改创意前，必须读取 [汽车创意与场景模板](references/automotive-prompts.md)，按其中的事实、素材角度覆盖、人物、口播时长、十类场景与完整提示词规则执行。模板只是创作素材，时间段与示例口播须按本次素材重写。查询已有任务时无需重新策划。

## 再做一条或修改版本

沿用已确定的素材、目标与设置，只调整用户提出的部分。仅说“再做一条”且意图不清时，简短询问是原方案重做，还是换创意。

| 时点 | 处理方式 |
|---|---|
| 提交前收到修改 | 更新方案版本，不提交旧稿。用户要求 Skill 代改时，展示改好的完整方案与报价后统一确认；用户直接发回修改稿时，按下方手动修改规则判断，不因文字变化自动增加确认。纯格式整理不重新确认。 |
| 提交后收到修改 | 查询并说明原任务真实状态，保留原任务与其方案记录。新要求作为新版本整理，不声称已修改原任务，不自动取消、重试或再次生成。新版本展示完整方案与预计积分后，确认一次再提交。 |
| 原任务状态未知 | 先核对原任务，不通过再次提交来解决未知状态。 |

新版本不视为免费修改原片。再次生成沿用“完整方案与报价一起展示、统一确认一次”的规则，不把内容和费用拆开询问；同一已确认版本及报价未变时，不重复确认。

### 用户手动修改提示词

支持用户复制完整提示词、自行编辑后发回。保存用户原稿和新版本，以用户发回的文本为准，不擅自润色、补写或改回旧稿。同步更新方案摘要，避免摘要与实际提交文本不一致。

提交前检查真实素材引用、事实依据、模型能力、单条15秒上限，以及提示词与生成设置的一致性。检查只用于判断能否执行，不作为重写用户文案的理由；存在冲突时只指出必要问题并给出处理建议，涉及用户台词或必要卖点的删改仍遵循内容缩减规则。

| 用户操作与执行条件 | 处理方式 |
|---|---|
| 发回修改稿，并明确说“按这版生成”；本轮已展示真实报价，素材、模型、设置、条数和报价均未变，检查通过且尚未提交 | 该指令即为对修改稿及本次生成范围的确认，按用户稿直接提交，不再询问内容或费用。 |
| 修改影响素材、模型、时长、其他设置、条数或费用，或原报价已失效/尚未取得 | 核对新的执行条件与报价，将差异、更新后的完整方案和预计积分一起展示，统一确认一次后提交。 |
| 仅发回修改稿，没有明确生成指令 | 保存新版本并告知已更新，等待生成指令；不沿用旧稿的确认自动提交。 |
| 原任务已经提交或提交状态未知 | 沿用上表对应的任务处理规则；旧任务授权不覆盖再次生成，不利用手动修改规则重复创建任务。 |

## 异常处理

- **素材问题**：按“其他素材情况”说明缺项或冲突，补图或调整方案；不伪造素材地址，不以无关车辆替代。
- **模型或设置不可用**：给出可执行替代方案及差异，更新完整方案和预计积分后统一确认，不擅自切换或降低规格。
- **预计积分不可得**：可展示标注“报价待获取”的草案并说明阻塞原因，但不发出内容审批或生成确认问题，不猜费用。用户主动认可草案时记录反馈，不立即追加费用问题；待取得报价后，与最终完整方案合并展示，再做一次有效的生成确认。
- **超时、失败或状态未知**：查询对应原任务，说明实际状态与已知费用；多条任务分别处理，保留已成功结果，不因部分失败整批重发。需要重做时按版本规则处理。
- **生成能力不可用**：保留方案，明确未创建任务，不虚构成片或擅自换供应商。
- **内容审核或固有标记限制**：如实说明实际返回原因及可调整范围，不绕过限制，不承诺消除模型固有标记。
- **成片偏差**：参考图和提示词不保证完全复现。区分工具返回状态、实际检查结果和未验证内容；发现截断或其他问题时说明修改建议，不自动付费重做。

## 创建与结果的边界

已有任务 ID 时只查询该任务。创建超时、断线或响应未知且无任务 ID 时，说明可能已创建或扣费，停止自动提交并引导人工核对所属平台任务历史；不按时间或相似文案认领任务。需要重做时作为新的付费创建，展示完整方案和当前费用再统一确认。查询失败、链接失效及部分失败都不自动再次创建。

仅呈现工具真实返回的状态、链接、成片规格和结算。规格缺失时说明未返回；无条件检查视频时说明未检查项，不声称车辆保真、口播完整或字幕正确已验收。参考和提示词不能保证模型完全复现。

## WorkBuddy 主站运行

固定使用主站原生 MCP OAuth、本人主站素材和积分。先以 `get_current_user` 检查身份与余额，需要 `account:read`、`file:upload`、`video:read`、`video:create`；缺权限时补授权。独立 Skill 包需要已连接并授权的 yihook MCP。

### 素材与免费预检

1. 先在对话中建立车辆、版本、图片角度与人物对应关系。至少一张车辆图；人物图可选，两者合计最多九张。图片支持 JPG/JPEG、PNG、WebP、BMP、GIF、TIFF，单张最多30MB，具体内容以领域预检为准。远端文件直链先安全下载完整字节到本地，再按 [公共上传说明](references/upload.md) 调用 `create_agent_file_upload`（`purpose: image`），保存原始票据响应，使用包内 `scripts/upload.mjs` 直传 OSS，最后 `complete_agent_file_upload`；未知上传按 `get_agent_file_upload` 查询。公共上传协议的 `upload_request_id` 只用于上传，不用于视频创建。使用完成响应返回的本人受信图片 URL；不把本地路径、原始直链或其他渠道资产交给视频工具。本人已有受信图片可按工具契约复用。
2. 完成创意和时长检查后，调用 `preview_automotive_video`，免费检查图片归属、实际内容、模型规格和积分。使用以下结构，示例 URL 须替换为本次已完成的真实引用：

```json
{
  "model_id": "seedance-2.0",
  "prompt": "图1用于车辆前侧外观，图2用于人物形象。此处替换为含分镜、口播、声音和约束的完整最终提示词。",
  "vehicle_image_urls": ["https://example.com/completed-car.png"],
  "person_image_urls": ["https://example.com/completed-person.png"],
  "duration": 15,
  "resolution": "720p",
  "ratio": "9:16",
  "generate_audio": true
}
```

模型固定 `seedance-2.0`，领域固定角色参考（`seedanceGenerationMode: character` / `inputMode: image_to_video`），不是 UGC 的参考模式。车辆图排列在前、人物图在后，按真实顺序对应图1、图2等；人物图可省略或传 `[]`，不要求为了角色参考额外提供人物。提示词1–4000字符，时长4–15整数秒（默认15），分辨率480p/720p/1080p（默认720p），画幅adaptive/21:9/16:9/4:3/1:1/3:4/9:16（默认9:16），音频开关为布尔值（默认true）。不接受参考音视频、批量数量、供应商资产协议、请求幂等键或报价凭证。

`generate_audio: true` 时通过提示词区分口播、配乐和环境音；无口播仍保留默认配乐与环境音。完全静音才设为false。不承诺分别控制音轨、固定声音身份或口型效果。工具能力冲突时明确差异，不自动换模型或降低规格。

### 确认、创建与跟进

3. 将免费预检返回的 `estimated_credits`、`price_version`、参数和素材用途与完整方案一起展示。每条分别报价，列明总条数和总积分，一次确认；报价不可得时只展示标注草案，不询问生成确认。多条由宿主逐条调用单条入口，不发送批量参数。
4. 用户明确确认后调用 `create_automotive_video`，传入与预检一致的全部业务参数，并增加 `max_credits`，值为用户已确认本条积分上限。服务端重新检查素材与费用，在现有事务内比较实际计算积分，超限拒绝扣费并回滚任务。收到预算错误时仅重新免费预检，将变化与完整方案统一确认；不自动调高上限。禁止传入 `request_id`、`quote_id`、确认记录或业务幂等键。相同参数重复调用会创建新任务，不能当作恢复方式。
5. 成功后立即保存并展示 `job_id`。使用 `get_automotive_video`，仅传 `{"job_id":"真实UUID"}` 查询本人任务；5–15秒退避，单轮最多三分钟，超时保留ID供继续查询。创建响应未知且没有ID时停止，说明可能已创建或扣费，引导人工查看主站任务历史，不重新提交或自动认领任务。
6. 查询返回 `status`、`videos`、`estimated_credits`、`consumed_credits`、`settlement_status`、`error` 和 `poll_after_seconds`。交付 `videos[].url` 作为预览/下载链接及实际返回的resolution、ratio、duration、frames、frames_per_second、generate_audio；未返回的规格说明未知，不用输入值补齐。结算未完成时不声称已退款。失败只说明真实原因与结算，不自动重做；链接失效查询原任务，无有效链接时说明限制，不创建新任务。
