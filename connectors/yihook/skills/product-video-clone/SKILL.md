# 爆款商品视频克隆与改编

提供一条参考视频和自己的商品素材，借鉴参考视频的框架、结构与表现形式，生成适配自身商品的新视频。适合已有对标素材、希望快速拓展带货创意的电商运营和内容团队。

商品链接解析仅支持 TikTok Shop 美国站。其他站点请提供商品名称和1—16张商品图，商品描述选填，按手动素材路线继续；不自动提交其他站点的链接解析。

此 WorkBuddy Skill 使用已连接的 yihook MCP，通过宿主原生 OAuth 授权。缺少业务工具或权限时，请用户在 WorkBuddy 重新连接并授权；不要索要或输出 Token。业务均调用主站 MCP。附件上传使用包内 `scripts/upload.mjs`，先阅读 [原样上传指引](references/upload.md)。通过宿主能力保存工具原始 JSON 响应后交给脚本，不重新拼写或编码签名字段，不临时编写 curl/Python 上传命令；脚本只负责 OSS 字节传输。


按下方渠道运行契约执行所有工具操作；使用已连接的主站账号，首次操作可免费调用 `get_current_user` 核对身份。素材、参数、分析、授权和任务标识均保留在本次对话，由宿主维护。

## WorkBuddy 运行契约

仅支持已通过原生 OAuth 连接的 Yihook 主站 MCP。身份核对需要 `account:read`，通用上传需要 `file:upload`，商品读取/解析需要 `product:read` / `product:create`，分析读取/创建需要 `analysis:read` / `analysis:create`，成片预检/查询需要 `video:read`，创建需要 `video:create`，下载同属 `video:read`。缺工具时重新连接补授权，不索要 Token，不切换开放平台。手动商品路线无需调用商品解析工具。

### 前置解析与分析的研策费用

商品解析和参考分析免费预检分别展示 `quote.totalCredits`、`quote.researchCredits`、`quote.generalCredits`、`quote.quoteUnits`、`quote.priceVersion` 与有效期，检查 `quote.canSubmit`；有收费单元还需 `quote.available=true`。缺少完整报价或不允许提交时停止，不将缺失金额填 0。未开通套餐可按真实报价使用通用积分，不自动购买套餐；专用优先、通用补差，赠分到期重置、不结转。

前置解析/分析双积分费用与成片通用积分费用分别确认和展示，不能用研策专用积分抵扣生成费，不把研策总费用全算成通用积分。免费复用依据本次报价；费用来源变化时重新确认；原创建响应未知只查原请求，不借重新报价重建。手动商品路线不产生商品解析费。

前置结算取本次解析 `run.entitlement`（逐行 `items[].attempt.entitlement`）或分析 `job.entitlement`，分别展示 `researchCreditsCharged/generalCreditsCharged` 与 `researchCreditsRefunded/generalCreditsRefunded`；整单与逐行不重复相加，历史报告费用不算成本次收费。`reserved` 是预占，`partial/unknown` 是结算未决，`released` 是已释放，`workflow_included` 不重复收费；缺失快照不以预估替代。生成仍按各任务的 `settlement` 展示通用积分。

### 素材与商品

首次上传前必须读取 [公共上传指引](references/upload.md)，使用随包注入的 `scripts/upload.mjs`：本地原始字节 → `create_agent_file_upload` → 保存完整原始工具响应 → `node scripts/upload.mjs response.json /absolute/path/file` → `complete_agent_file_upload`；仅使用已完成的本人上传 ID。上传未知时按公共协议查询，不重新拼写票据、不绕过上传脚本。

- 本地参考视频接受 MP4/MOV/WEBM，最大 300 MiB（300×1024×1024 字节）；使用 `purpose: "video"`。先核对文件实际类型、大小和可读取性，再上传。
- 视频链接或含单个视频链接的分享文案走主站正常的视频链接解析与分析链路，直接传给 `preview_viral_analysis` 的 URL 路线，不要求先下载到本地再上传，不自行另建下载或解析流程。以主站实际预检核实支持范围；不支持、失效、非视频或解析失败时说明实际原因，请用户更换链接或上传本地视频。多个候选先选定一条，不静默取首条。不能用历史分析报告替代原视频。
- 商品图片使用 `purpose: "image"`；上传格式、单图大小按公共上传能力校验，总数 1—16 张。远端商品图片文件直链由宿主按公共上传指引安全下载完整字节到本地后上传，不将原 URL 传给创建。商品页面链接交给商品解析工具，不按图片下载。
- TikTok Shop 商品链接调用 `preview_product_parse({"source_type":"links","links":[{"url":"用户的商品详情链接"}]})`。商品链接解析仅支持美国站；通过免费预检核实站点，不仅凭 URL 外观判断。预检确认非美国站时不提交解析，引导用户提供商品名称和1—16张商品图，商品描述选填，转为手动素材路线。解析若产生费用且未授权，先展示账号实际总报价与专用/通用积分拆分并取得授权；保存本次 `links`、`quote_id` 与独立 `request_id` 后调用 `submit_product_parse`，入参为 `{"source_type":"links","links":[{"url":"原链接"}],"quote_id":"原预检ID","request_id":"宿主生成的8—128位标识"}`。查询 `get_product_parse_run({"run_id":"返回ID"})`，需要时用 `get_product({"product_id":"返回ID"})` 获取完整素材；不虚构或静默裁剪商品信息。
- 商品解析使用现有请求与报价协议。响应未知时只调用 `get_product_parse_request({"request_id":"原ID"})`；查不到停止。手动路线不创建商品解析任务或新的商品记录。

### 参考分析与费用

素材齐备并补齐国家和语言后，按选定来源免费预检：

- 本地上传：`preview_viral_analysis({"type":"upload","upload_id":"参考视频的已完成上传ID"})`。
- 视频链接：`preview_viral_analysis({"type":"url","source_input":"用户的视频链接或含单个链接的原分享文案"})`；复用主站链接解析、原视频获取与完整分析，保存本次选定链接及返回的来源信息，不另外创建上传任务。

返回 `quote_id`、`expires_at`、`quote`（包含总费用、专用/通用积分拆分、逐项单元、价格版本及 `canSubmit`）。需要收费且未获授权时先确认分析费用；`canSubmit: false` 时停止收费提交。不要用生成费用授权代替尚未授权的分析费。

分析创建复用既有工具：提交前保存宿主生成的稳定 `request_id`（8—128位字母、数字、下划线或连字符）和原 `quote_id`，调用 `create_viral_analysis({"request_id":"原ID","quote_id":"原预检ID"})`。取得 `job.id` 后保存，按返回 `poll_after_seconds` 调用 `get_viral_analysis({"job_id":"原分析ID"})`。状态未知且有 ID 时只查原任务；创建响应丢失则用 `get_viral_analysis_request({"request_id":"原ID"})`，查不到停止，不重复分析。报价失效且确认未创建时只刷新免费预检，费用增加或费用来源变化时补充确认；创建响应未知不能借此重提。

只有本人分析任务 `job.status: "done"`、`job.jobKind: "full_ai"`、`job.contentType: "video"`、`job.sourceVideoUrl` 和 `job.analysisResult` 可用才继续。直接展示 `job.analysisResult` 的接口内容，沿用其结构，仅做必要的可读排版；不要生成新结论、固定报告模板、改编说明、改编脚本或分镜，不把 `generated_prompt` 当成参考分析或用户确认对象。本地参考上传与分析任务必须对应同一文件；链接参考使用本次选定链接创建的原 URL 分析任务，通过 `job.sourceInput` / `job.sourceUrl` / `job.canonicalUrl` 核对来源，不挪用其他链接的分析。只更改商品或参数时复用原分析。

### 免费成片预检与创建

`preview_hookreel_reference_video` 和 `create_hookreel_reference_video` 使用同一业务输入；创建额外必填 `max_credits`。两者都校验本人分析归属、完整视频分析已完成及商品素材完整性。本地路线必传 `reference_upload_id`，校验本人已完成上传及分析与原文件一致；链接路线省略 `reference_upload_id`，`viral_analysis_id` 必须指向本次链接的 URL 分析任务，由既有主站链路取得原视频后生成。不能省略上传ID来使用上传类型分析，也不能混用上传ID和链接分析。不要新增 `request_id`、`quote_id`、幂等键或恢复工具。预检不创建、不扣生成费，无报价凭证或后台确认记录；创建重新校验，费用超过上限时在扣费前拒绝。

本地参考＋手动商品预检示例（ID 均替换为真实返回值）：

```json
{
  "reference_upload_id": "11111111-1111-4111-8111-111111111111",
  "viral_analysis_id": "22222222-2222-4222-8222-222222222222",
  "product": {
    "type": "manual",
    "name": "桌面收纳盒",
    "image_upload_ids": ["33333333-3333-4333-8333-333333333333"]
  },
  "person_region": "FR",
  "video_language": "Japanese",
  "count": 2,
  "disable_voiceover": false
}
```

链接参考使用相同商品和创作参数，省略 `reference_upload_id`，将 `viral_analysis_id` 换成本次链接分析返回的真实任务ID；创建同样额外传 `max_credits`。生成入口不再传原始链接、不重复解析，不要求链接视频创建本地上传记录。

手动商品 `name` 必填，最长1000字符；`description` 选填，最长2000字符；`image_upload_ids` 必须为1—16个本人已完成图片上传ID。省略描述时不追问或编造。

解析商品使用 `product: {"type":"parsed","product_id":"本人已完成商品ID"}`，服务端读取商品名称、描述和图片。用户确认补充或替换时，可传 `name`、`description`（空字符串表示去掉原描述）、`image_upload_ids` 和 `product_image_indexes`（`get_product` 返回图片列表的0基索引）。规则如下：

- 两个图片字段都不传：使用全部解析图片；超过16张时让用户选择，不截断。
- 只传 `image_upload_ids`：使用上传图替换解析图。
- 同时传 `product_image_indexes` 与 `image_upload_ids`：合并指定解析图和上传图，去重后最多16张；只保留指定解析图时仅传索引列表。
- 不静默决定冲突素材；按共同正文仅核对冲突部分，明确选定后传参。替换商品事实时也核对旧描述是否适用，必要时明确替换或清空。

参数枚举（不是默认值）：

| 人物外观国家                           | `person_region`        |
| -------------------------------------- | ---------------------- |
| 美国/英国/德国/法国/意大利             | US / GB / DE / FR / IT |
| 西班牙/墨西哥/日本/泰国/越南           | ES / MX / JP / TH / VN |
| 菲律宾/印度尼西亚/马来西亚/新加坡/巴西 | PH / ID / MY / SG / BR |

`video_language`：英语 English、德语 German、法语 French、意大利语 Italian、西班牙语 Spanish、爱尔兰语 Irish、日语 Japanese、印尼语 Indonesian、马来语 Malay、菲律宾语 Filipino、泰语 Thai、越南语 Vietnamese、葡萄牙语 Portuguese、简体中文 `简体中文`、繁体中文 `繁体中文`。两项独立且必填，不能推断或省略。条数 `count` 只支持1/2/3/5/10，默认1；`disable_voiceover` 默认false，true只取消口播，不是静音。相同参数应用于本批全部视频。

预检返回 `parameters`、实际读取的 `product` 摘要、`count`、`estimated_credits`、`price_version`、固定目标 `target`（9:16、15秒）。生成估价不含商品解析和参考分析，分别展示已付/待付的双积分费用与生成通用积分费用，不写死积分价格。`target` 是生成规格，不是输出探测结果。

展示原分析后，汇总商品、图片选择、数量、国家、语言、声音、固定成片规格和实际费用，按共同正文统一询问是否沿用结构生成。明确同意后调用 `create_hookreel_reference_video`，传入最终完整业务参数及用户确认的本批生成 `max_credits`。一次调用即创建整个批次，不循环单条创建；不启用试用、不额外做付费样例。确认中明确同意且修改语言等参数、费用不变且无歧义时，重新免费核对参数费用、简短说明更新后直接提交。

### 查询、交付与停止条件

创建返回 `jobs` 数组，每项包含 `job_id`、实际 `status`、`batch_order`、`reserved_credits`；立即保留全部ID。逐项调用 `get_hookreel_video({"job_id":"原ID"})`，按 `poll_after_seconds` 查询；`queued`、`stage1_running`、`stage1_done`、`stage2_running`、`stage2_done`、`stage3_running` 为执行中；`done`、`failed`、`stage1_failed`、`stage2_failed` 为终态。保留成功结果，继续查询其余任务，不重新生成成功条目。

`done` 使用实际 `video_url` 供预览，调用 `get_hookreel_download({"job_id":"同一ID"})` 获取实际 `download_url`、`expires_at`（临时下载链接）。逐条展示状态、链接和 `settlement`：`reserved_credits`、`consumed_credits`、`refunded_at`、实际结算状态；失败展示真实 `error`，`pending_refund` 不表示已退款。缺少输出尺寸等属性如实说明，不将固定目标或输入属性冒充实际测量值。链接过期只刷新原任务下载链接，不重新生成。

新增成片创建无业务请求键：取得ID后只查这些ID；响应未知且未取得ID时，说明可能已经创建或扣费，停止自动提交，请人工核对已有任务历史，不按时间或相似文案认领任务，不调用原创模式的 `get_hookreel_request` 恢复此批次，不承诺重复调用只扣一次。用户明确要重做时作为新的付费创建重新核对素材、参数、结构和费用。

已有工具不支持暂停、恢复后台执行、取消、修改生成中任务、无人物、去字幕、全静音及其他时长画幅控制。用户提出这些要求时说明实际边界并核对是否接受；停止后续提交不表示后台已停止，也不承诺退款。分析失败不改为无参考生成；余额不足、素材失效或费用不明时停止收费步骤。


## 一、完整流程

```text
读取用户已提供的素材和已填写参数，选定本次商品与参考视频并补齐输入
  → 确定商品来源（二选一）
     ├─ TikTok Shop 美国站商品链接 → 解析商品名称、图片与描述
     └─ 手动提供 → 上传 1—16 张商品图 + 填写商品名称，商品描述选填
  → 核对商品信息与图片，缺少名称或有效图片时先补齐
  → 确定参考来源：本地上传（校验文件规格与可读取性）或视频链接（走主站正常解析链路）
  → 选定并校验参考视频，仅在多个候选或用途不明时询问
  → 素材齐备后，确定一个人物外观国家和一种视频语言，多条视频共用这组设置
  → 条数与声音设置静默采用默认值；用户主动指定时按其要求处理
  → 核对参考分析费用；如另行收费且未获授权，先确认分析费用
  → 调用爆款分析接口 → 展示接口返回的参考视频分析结果
  → 汇总商品、生成参数与预计积分，说明成片固定为 9:16 竖屏、15 秒
  → 提问：是否沿用以上参考视频的爆款结构，为你的商品生成 {条数} 条视频？
     ├─ 用户确认 → 结合商品信息自动改编并生成完整成片，记录任务标识
     └─ 用户未确认或要求更换参考 → 暂不生成；更换后重新分析并展示确认
  → 查询任务 → 逐条交付成片预览、下载入口及费用说明
```

- 商品与参考视频都必须提供，参考支持本地上传或视频链接；商品可通过商品链接或手动素材提供。多个商品或多条参考的对应关系不明确时，先选定本次组合；已有拆解报告不能代替原参考视频。
- 只追问缺失或冲突的信息，保留其他有效输入。商品描述选填，不因未填写而阻塞流程，也不编造卖点或直接套用参考商品的功能、功效。
- 人物外观国家与视频语言独立选择，每次各选一种，本次所有成片共用；改编条数未填写时默认 1 条，无人声模式默认关闭。输入引导中不主动介绍或询问这两项，用户主动指定时按其要求处理；生成前统一展示实际参数与费用，不另行追问默认设置。
- 参考分析若另行收费且未获授权，先确认分析费用。分析完成后必须展示结果并询问是否沿用该结构生成视频，用户确认后才开始生成；已有预算授权不能代替本次结构确认。同一结构、素材、参数与费用已确认后，不重复询问。
- 生成前直接展示爆款分析接口返回的参考视频分析结果，不另写分析模板，也不提供改编后脚本或分镜的确认环节。用户确认沿用参考结构后，自动完成改编与成片生成，也不设置首帧或配音的中途审核；参考分析完成不等于整个任务完成。只需要拆解报告时，转入“爆款短视频拆解与创意分析”。
- 部分成功时先交付成功结果，继续跟进其余任务；状态不明时先查询原任务，不重复提交。

## 二、参数与素材要求

### 2.1 商品输入：二选一

| 输入方式                   | 必填内容                        | 选填内容           | 校验要求                                                                                   |
| -------------------------- | ------------------------------- | ------------------ | ------------------------------------------------------------------------------------------ |
| TikTok Shop 美国站商品链接 | 1 条 TikTok Shop 美国站商品链接 | 用户补充的商品说明 | 应为商品详情链接，不能用普通短视频链接代替；解析后需获得有效商品名称与图片，缺项时再补充。 |
| 手动提供商品素材           | 商品名称、1—16 张商品图         | 商品描述           | 图片需能清楚展示本次商品；多款商品或不同规格混杂时，先确认使用哪一款。                     |

商品描述可补充核心卖点、使用场景和希望突出的特点。描述缺失时使用已确认的名称与图片，不强制补写。商品链接与手动素材同时提供时，内容一致的素材可作为补充，不要求用户重新二选一；名称、图片、型号或规格冲突时，只核对冲突内容，确认采用哪套信息，不静默覆盖。

图片包含多个颜色、型号或套装时，确认推广单款还是整套。截图、拼图或带人物的商品图不一律拒绝；先检查商品是否清晰、主体是否明确，无法识别时再请用户补充清晰单品图。

### 2.2 参考视频输入：本地上传或视频链接

| 输入方式 | 必填内容         | 校验要求                                                   |
| -------- | ---------------- | ---------------------------------------------------------- |
| 本地视频 | 1 个本地视频文件 | 文件可正常读取与播放；支持 MP4、MOV、WEBM，文件最大 300M。 |
| 视频链接 | 1 条视频链接，或包含单个视频链接的分享文案 | 复用主站正常的视频链接解析与分析链路，以实际预检结果核实是否支持、内容是否为视频及费用。 |

收到参考视频链接或含单个视频链接的分享文案时，直接走主站正常的视频链接解析与分析链路，不要求先保存为本地文件；商品链接仍按商品输入规则处理。链接不支持、失效或解析失败时，说明实际原因，请用户更换链接或上传本地视频。

每次改编以一条参考视频为依据。用户只提供一条且用途明确时，直接选用并校验，不额外询问是否使用；提供多条或同时上传文件和链接且未明确采用哪一条时，先确认本次参考，不自动选择或重复分析。图片或图文截图不能代替参考视频。

### 2.3 创作参数

| 参数         | 要求                                      | 说明                                                                                                                                                                          |
| ------------ | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 改编条数     | 选填，默认 1 条；可选 1、2、3、5 或 10 条 | 未填写时不追问，按 1 条展示并估价。用户指定时采用指定值；不支持的数量应让用户从可选项中选择，不擅自凑单或拆单。同一任务生成多条时，所有视频使用相同的人物外观国家和视频语言。 |
| 人物外观国家 | 必填；从支持范围中选择一个国家            | 与视频语言独立设置，本次所有视频共用。                                                                                                                                        |
| 视频语言     | 必填；从支持范围中选择一种                | 本次所有视频共用；不直接沿用参考视频语言，也不根据人物外观国家推断。开启无人声模式仍需填写。                                                                                  |
| 无人声模式   | 可选；开启或关闭                          | 默认按关闭汇总，并在生成前展示。开启后不生成口播，仅保留字幕、花字、背景音乐与环境音；不等于完全静音。                                                                        |

**人物外观国家的含义**：选择“人物外观属于哪个国家”，不代表视频语言或投放市场；人物外观国家与视频语言独立设置。

**固定成片规格**：无论参考视频的画幅、时长等参数如何，每条生成结果统一为 **9:16 竖屏、15 秒**。这两项不作为用户可选参数，参考视频也不要求必须为 9:16 或 15 秒。

**人物外观国家（15 项）**：美国、英国、德国、法国、意大利、西班牙、墨西哥、日本、泰国、越南、菲律宾、印度尼西亚、马来西亚、新加坡、巴西。

本 Skill 面向 TikTok 支持地区提供上述人物外观选项，当前不支持“中国”。用户选择中国时，提示修改，并可引导选择新加坡；须由用户确认，不自动替换。人物外观国家与视频语言仍独立设置，新加坡可搭配简体中文。

**视频语言（15 项）**：英语、德语、法语、意大利语、西班牙语、爱尔兰语、日语、印尼语、马来语、菲律宾语、泰语、越南语、葡萄牙语、简体中文、繁体中文。

例如，人物外观国家可选美国，视频语言可选西班牙语。

**单次任务限制**：每次只能选择一个人物外观国家和一种视频语言，即使生成多条，也共用这组设置。不支持一次性为不同视频设置不同人物外观国家或语言。用户提出此类需求时，先明确本次采用的人物外观国家、语言及对应条数；其他版本需分次制作，不自动拆分为多个任务或合并提交。

## 三、如何引导用户输入

### 3.1 第一步：提供商品和参考视频

商品和参考视频在同一步中一起引导，不强制拆成两轮；允许用户一次提供或分开发送。先收集素材，不同时询问人物外观国家和视频语言。用户已提供的素材直接复用，只追问缺失内容。用户说「用刚才那个商品／视频」时，本次对话中对象明确且素材仍可用就直接复用；有多个候选时仅询问采用哪一个，不要求重新上传。

> 请先提供商品和参考视频：
>
> - **商品**：发送 TikTok Shop 美国站商品链接，或上传商品图并填写商品名称，商品描述选填。
> - **参考视频**：上传一条本地视频（MP4、MOV、WEBM，最大 300M），或发送一条视频链接／含单个链接的分享文案。

用户只提供其中一类素材时，保留已收到的内容，只追问另一类，不重复整段引导：

- **只收到商品**：「商品已收到，请上传一条本地参考视频，或发送视频链接。」
- **只收到参考视频**：「参考视频已收到，请再提供商品素材：TikTok Shop 美国站商品链接，或商品图＋商品名称。」
- **两类素材均已齐备且可用**：直接进入第二步，只询问尚未提供的人物外观国家和视频语言。

商品缺少名称或有效图片、参考视频无法读取时，只补齐或更换对应素材，不要求整套重新提交。商品描述未填写时不追问。

### 3.2 第二步：说明人物外观国家和视频语言

商品与参考视频齐备后，再集中询问尚未提供的人物外观国家和视频语言；两项均已明确时直接继续，不重复询问。

> 视频中的人物外观属于哪个国家？视频使用什么语言？例如：人物外观选择美国，视频使用英语。

人物外观国家与视频语言独立设置，每次各选一种。用户说「两条，一条英语、一条法语」等多语言或多个人物外观国家要求时，说明需分次制作，只询问本次选哪个人物外观国家、哪种语言及对应条数，不把原总条数直接用于本次任务。「欧美风」「外语版」等表述不明确时，仅追问对应选项。「美国市场」只说明目标市场，不能直接确定人物外观国家或语言；「法语版」只确定语言，人物外观国家未明确时仍需询问。

用户说「其他都默认／你决定」时，条数与声音设置继续采用默认值；人物外观国家和视频语言没有预设默认。若仍缺失，根据已知需求选用一个支持范围内的合理组合，在最终生成摘要中明确展示为本次建议，与生成统一确认，不单独增加确认轮次，也不将建议表述为系统默认。

改编条数与声音设置静默采用默认值，不在上述两步中介绍选项、解释默认值或邀请用户调整。用户主动提出多条、无人声等要求时，再按参数规则处理；「完全静音」不能直接等同于无人声模式，需说明区别并核对是否能满足。

用户选择人物外观“中国”时，优先给出明确的替代建议，无需先罗列全部国家：

> 当前人物外观暂不支持中国，可以选择新加坡；视频语言可选择简体中文。人物外观改为新加坡可以吗？

用户同意后更新人物外观国家，保留已明确的视频语言；语言尚未明确时再补问。用户不接受新加坡时，提供其他支持的国家供其选择。

### 3.3 两步交互示例

> 用户：商品是自动喂食机，已上传商品图，参考我上传的本地视频。
>
> Skill：视频中的人物外观属于哪个国家？视频使用什么语言？
>
> 用户：人物外观国家为法国，法语。

收到上述信息后，完成并展示接口返回的参考视频分析，再汇总生成参数与费用，统一询问是否沿用该结构生成视频。若用户首次已提供人物外观国家与视频语言，则跳过第二步提问。

### 3.4 展示参考分析并引导确认

接口仅返回参考视频的爆款分析结果，不返回改编说明；不得自行编写或承诺交付改编说明。直接展示接口返回的分析内容，沿用返回结果的内容结构，不另设固定分析字段，不重新撰写或补充分析结论。若返回的是结构化数据，仅做必要的可读排版；接口未返回的内容不自行补齐。分析结果已展示时不重复展示，直接接续生成摘要与统一确认。

展示分析后，连同商品、条数、人物外观国家、语言、声音设置、固定成片规格（9:16 竖屏、15 秒）与费用摘要，一次提问：

> 是否沿用以上参考视频的爆款结构，为你的「{商品名称}」生成 {条数} 条视频？

用户明确同意后开始生成。未回复不视为确认；不再要求审核改编后的脚本或分镜。用户在分析展示前要求「直接生成／跳过分析」时，仍先展示接口返回的分析结果，再完成本次统一确认。

用户在统一确认时回复「可以，但换成日语」等明确同意且附带参数修改的内容，视为对修改后方案的确认。人物外观国家或语言的修改适用于本次全部视频；仅修改其中部分视频时，先按单次任务限制明确本次设置与条数。修改项受支持、费用不变且无其他歧义时，简短告知更新后的参数并直接生成，不重复询问；只有修改意图而未明确同意生成时，更新摘要后再确认。费用变化、条件不明确或修改无法满足时，仅补充核对相关内容。更换参考视频仍需重新展示分析并确认。

## 五、交互示例

以下为交互示意。方括号表示实际操作或返回内容，不是需要对用户照读的话术；分析结果直接使用接口返回内容，积分与链接使用实际值。收费分析在已有授权范围内执行，否则先说明并确认分析费用。

### 示例 1：素材齐备，补充人物外观国家与语言后生成

> 用户：帮我参考上传的本地视频做商品视频。商品是自动喂食机，商品图和参考视频都上传了。
>
> Skill：视频中的人物外观属于哪个国家？视频使用什么语言？
>
> 用户：人物外观国家为法国，法语。
>
