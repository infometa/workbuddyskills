# 数字农人接口参考

版本：0.1.1。配套 CLI：0.1.2，配套 Skill：0.1.1。

CLI npm 包名及命令名为 `sznr-cli`，Windows 命令入口为 `sznr-cli.cmd`。

CLI 自动维护当前设备身份并为授权、状态和业务请求签名。设备身份不是业务参数，调用方不读取、迁移或覆盖它；本 reference 不提供设备管理接口。

## 已开放业务能力

当前没有已确认的 Gateway 业务白名单及对应 NCP 企业权限评审记录，因此本版本没有可调用的业务方法和路径。登录成功不代表任意业务接口可用。收到业务请求时应说明尚未接入，不能从前端源码、旧接口文档或用户给出的地址推断可调用接口。

## GET/POST 通用契约

下面只定义命令参数含义，不提供未开放的业务路径。能力表为空时不得据此发起业务调用。

| 参数 | 类型与规则 |
| --- | --- |
| 方法 | `get` 或 `post`，必须与已开放能力一致。POST 不自动等同于写操作，以接口风险定义为准。 |
| 路径 | 已开放能力中的相对路径，以单个 `/` 开头；不带域名、片段、反斜杠或路径逃逸。 |
| `--query` | JSON 对象；字段类型、必填性、枚举和示例由具体能力定义。 |
| `--body` | 仅 POST 使用，合法 JSON；具体能力必须提供 JSON Schema、必填项和完整示例。 |
| `--header` | 可重复的 `名称: 值`；只传能力明确允许的业务 header。当前允许列表为空。 |

认证和企业上下文由 CLI 与服务端管理，调用方不传认证、Cookie、企业身份或用户身份 header。不支持文件上传、multipart、二进制下载及流式响应。

stdout 使用固定 JSON 信封：

```json
{"ok":true,"status":200,"headers":{"content-type":"application/json"},"body":{}}
```

`body` 的 JSON 类型保持不变，UTF-8 文本保持字符串。`ok` 表示 HTTP 是否成功，不是业务成功标记。HTTP 非 2xx 仍返回相同信封，`ok=false`。不能把通用示例中的空对象当作某个业务接口的成功、空结果或分页结构。

## 失败处理

| 错误或退出码 | 解释与动作 |
| --- | --- |
| `WB_AUTH_PENDING` | 等待页面批准，由 WorkBuddy 默认状态检测继续查询。 |
| `WB_AUTH_DENIED` | 用户拒绝，停止；不自动再次打开授权。 |
| `WB_AUTH_EXPIRED`、`WB_AUTH_REVOKED` | 授权已过期或撤销，需要重新授权。 |
| `WB_REAUTH_REQUIRED`、`WB_DEVICE_MISMATCH`、`WB_DEVICE_REVOKED` | 固定会话或设备授权失效，启动一次登录；写操作不得自动重放。 |
| `WB_DEVICE_REQUIRED`、`WB_DEVICE_SIGNATURE_INVALID`、`WB_REQUEST_REPLAYED` | 设备签名或防重放校验失败，停止当前请求并报告连接故障；不得修改 header 或盲目重试。 |
| `WB_INVALID_KEY` | 连接凭证无效，当前请求立即失败，不重试旧请求；用户可重新连接。 |
| `WB_TOKEN_RECOVERY_FAILED` | 服务端无法恢复原会话，停止并报告故障，需要重新授权；不重试获取替代会话。 |
| `WB_CUSTOMER_FORBIDDEN` | 企业无权限或不匹配；说明原因，用户决定重新选择企业后再退出并重新授权。 |
| `WB_PATH_FORBIDDEN` | 能力未开放或方法不符，停止并报告配置问题，不探索其他路径。 |
| `WB_RATE_LIMITED` | 遵守响应提供的重试时间，不高频重试。写操作先查明是否生效。 |
| 普通业务 `403` | 权限或业务拒绝，解释上游业务信息，不删除连接、不自动重新授权。 |
| 退出码 `2` | 参数或受管配置错误，检查已公开的参数定义；不覆盖受管环境。 |
| 退出码 `3` | 未登录、等待授权或需要重新授权，结合状态及稳定错误码处理。 |
| 退出码 `4` | 业务 HTTP 非 2xx，读取信封并按业务错误处理。 |
| 退出码 `5` | 网络或超时，状态未知；不视为未授权，写操作结果可能不确定，禁止盲目重放。 |
| 退出码 `6` | CLI 内部或本地持久化失败，报告阶段并停止；不尝试读取凭证文件排错。 |

## 新增能力要求

发布新能力前，维护者必须取得 Gateway `WORKBUDDY_BUSINESS_ALLOWLIST` 中的精确方法与路径及其配置版本，并记录 NCP 企业权限评审依据。仅有旧版凭证能访问的接口不构成登录器版白名单证据。

每项能力必须补全：用户可理解的名称、GET/POST 方法、相对路径、query 字段类型/必填性/枚举/示例、body JSON Schema/必填性/示例、允许的业务 header、成功响应/空结果/分页/部分失败/业务错误，以及读写影响和具体确认要求。没有 query、body、header 或分页时明确写“无”。

支付、删除、批量更新等高风险操作必须列出执行前需要用户确认的对象、范围、金额或字段以及不可逆影响。接口、白名单、Skill 与版本兼容记录须同步评审、发布。
