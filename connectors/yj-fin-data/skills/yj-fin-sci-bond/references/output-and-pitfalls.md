# 输出纪律与常见坑位（科创债可行性自查）

本文件为成稿纪律，适用于 SKILL.md 输出契约落地的所有文本。下列禁词清单中的词**仅在本文件作为"不可写入内容"的说明出现**，正文与交付物中不得出现。

## 一、去 AI 化禁词清单（正文中禁用）

严禁在交付物正文中使用：总而言之、综上所述、值得注意的是、需要指出的是、不难看出、由此可见、总体而言、此外、另外、首先其次、值得一提的是、可以说、显而易见、可想而知、毋庸置疑、从某种程度上、在一定程度上、值得一提的是、总的来说。

严禁自我方法标签括号：标题不写"主名（方法标签）"，如"可行性自查（Step 0 闸门）"。方法论质量放正文句、表头列或表尾批注，不进标题。

## 二、排版与成文纪律（九项，逐条过）

1. 列表项独立成行，一条一行，不复用长段落堆砌。
2. 一段一要点，不把多个结论塞进一段。
3. 生成期整段重复自查：严禁把同一整段复制两遍（常见坑：开头摘要与正文首段逐字重复）。
4. 空格/分隔符合拢：中文之间用 A/B/C、A·B 形式；箭头 `→`、连字符 `-`、加号 `+`、波浪号 `–` `—` 两侧无空格；英文复合词原样（如 `yj-fin-data`）。
5. 特殊 Unicode/装饰符优先 ASCII：指数用 `10^-7` 非 `10⁻⁷`；比较用 `<=` 非 `≤`；禁用 `✓ ✔` 等装饰勾，用文字"满足/缺口"。
6. 禁自创伪专业空壳名词：先给数值与来源再命名，不凭空造"XX 系数""XX 模型"名词。
7. 约量词不悬空："约 X"后必跟具体数字，不写"约较高""约较大"。
8. 通篇中文为主，专有工具名保留原文。
9. 无残留物：不得出现 `__` 占位、裸 `TBD`、孤立"待补"无说明；不得有孤立标题无正文。

## 三、不适用清单（PDF 专属，勿迁移到 HTML 产物）

以下为 PDF 渲染纪律，本技能交付物为单份自包含 HTML，不适用：分页控制、页码、封面页、三册分册、reportlab 调用。HTML 产物用内联 SVG/CSS 实现版式，不外链本地资源。

## 四、领域坑位（科创债自查特有）

1. 交易所/银行间两套规则口径混用：必须 Step 0 先锁死适用体系，不得交叉套用门槛。
2. "央行担保"误列为独立债种：其性质为增信安排，须归入③层，非④独立品种。
3. 科创属性认定过宽：须落到高新/专精特新/小巨人/研发驱动主业等可核验资质，不写"科技感强"等空泛判定。
4. 合规风险静默假设无违规：处罚/诉讼/失信不可达时标"待补充核验"，绝不写"未发现违规"当作无违规证明。
5. 募资用途漂移：须明确投向科创领域，不得默认可用于非科创扩产或偿还非科创债务。
6. 监管硬结论越界：结论性质为"可行性自查框架，非法律/监管意见"，不写"该公司符合/不符合发行条件"。
