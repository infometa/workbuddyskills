# 科创债发行可行性自查框架

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

## 一、定位与边界

面向有发行科创债（科创公司债、科创票据，含央行担保科创债）意向的企业，按现行规则形成逐条可对照的发行可行性自查清单，引导用户自行比对，输出一份结构化的**自包含 HTML 自查报告**。

**重要边界**：本技能输出的是**可行性自查框架与缺口提示，非法律意见、非监管认定、非承销发行承诺**。最终能否发行，以上海/深圳证券交易所、北京证券交易所或交易商协会审核，以及主承销商与担保增信机构判定为准。规则条文随时间修订，请用户以最新有效监管原文核验，本清单不保证现行有效。

## 二、何时触发

- 用户询问"这家企业能不能发科创债 / 是否满足发行条件 / 帮我逐条对照科创债资格 / 做一份发行可行性自查"；
- 用户描述标的企业情况并要求逐条对照科创债发行可行性；
- 出现关键词：科创债、央行担保科创债、科创公司债、科创票据、发行条件、科创属性、募集资金用途、创新积分、专精特新、小巨人、高新技术企业；
- 输入形态：① 用户上传标的基本情况、财报、资质、募投说明、公告；② 用户仅以文字描述评估需求。

不适用于纯信用债、普通公司债（非科创）、企业债、中期票据（非科创）的通用资格评估。已明确不适用时主动提示本技能仅覆盖科创债体系。

## 三、工作流（六步法）

### Step 0 — 标的板块与主体类型定位（前置闸门，不可跳过）

跑任何判定之前先锁死**标的适用哪类科创债与主体类型**，防把银行间/交易所两套体系、上市/非上市门槛错配，导致条件错配、自查结论失真。

按监管领域映射四层定位（精神沿用价值链定位闸门，非照搬产业分层）：

| 层 | 典型主体 | 条件口径取向 |
|---|---|---|
| ① 交易所科创公司债（上市） | 科创板/创业板/北交所/沪深主板上市公司 | 适用证监会/交易所科创债规则，以披露财报与公告为准 |
| ② 银行间科创票据（各类） | 具高新技术企业/专精特新等资质或募投科创的企业 | 适用交易商协会规则，中短期为主、相对标准化 |
| ③ 央行担保科创债 | 纳入央行担保增信的科创债项目 | 在①②基础上叠加担保增信适配，非独立债种 |
| ④ 非上市科创主体 | 未上市企业 | 以用户上传材料核验科创属性与财务指标 |

**易混淆点防错（强制）**：交易所/银行间两套规则口径不同，显式标注适用体系；"央行担保"为增信安排而非独立债种，不得误列为第四类独立品种；主板盈利/ROE 门槛仅约束主板再融资，不得误加到科创债口径。

**判定输入**：用户上传材料（板块、代码、资质、财报、募投说明）+ 公告/研报旁证；泛称与披露实质冲突时**以披露文件中的板块与代码为准**。

### Step 0.5 — 主动交叉验证纪律（强制，不可降级）

对关键数字与合规事实（最近一年营收、净利润/扣非净利润、资产负债率、可分配利润、研发投入与专利、行政处罚/诉讼/立案/失信记录）一律做 **≥2 独立源交叉验证**：

- 优先源：上市公司公告/定期报告（权威，带披露日期快照）；
- 旁证源：可及研报、纪要、观点（`yj-fin-data（knowledge_search）` / `yj-fin-data（fetch_document）` / `yj-fin-data` 取数）；
- 用户材料：上传的报表/资质/合规文件标 `[用户提供]`。

规则：

- 独立源之间不一致，显式标注差异（差异来源标签），不静默取其一；
- 任一维度缺口，写"受数据可得性限制，XX 待补充核验"，**绝不静默编造、绝不按金额倒推、绝不假设无违规无处罚**；
- 凡可公开复核的硬数字（营收、可分配利润、审计意见、处罚文号），给时间快照与就近复核通道；
- 不使用"探活 / 未连通 / 故障 / 兜底 / 已降级"等故障词；缺口一律以自然措辞带过。

### Step 1 — 收集与整理标的资料

优先使用用户提供的标的基本情况；信息不足时，以用户上传材料与可及研报/公告旁证补充关键字段，并注明来源与日期。缺失字段标注"待核实"，不得默认填充、不用记忆补全。

### Step 2 — 逐条对照判定清单

读取 `references/standards.md` 与 `references/system_prompt.md`，按四组清单逐项比对：

- A 科创属性（科创企业类/科创升级类/科创投资类；高新、专精特新、小巨人等资质或研发驱动主业）
- B 财务门槛（营收规模、盈利、资产负债率、可分配利润覆盖一年利息、主体评级）
- C 合规风险（近 12–24 个月处罚/诉讼/立案/失信、环保安全质量事故、非法集资）
- D 募集资金用途（须投向科创领域；不得用于非科创扩产、偿还非科创债务）

每项给出"自查结果"三态之一：**满足 / 缺口 / 待核实**。存在"缺口"或"待核实"时，综合结论不得判为"整体通过"。

### Step 3 — 综合自查结论与缺口清单

- 综合自查结论四档参考：通过 / 基本通过 / 需补充 / 不通过（性质为可行性自查参考，非监管判定）。
- 缺口清单：对"缺口"或"待核实"项给出可执行的补充材料方向或整改线索，不输出确定性监管结论。
- 风险桥接：每项"缺口/待核实"与综合结论之间用一句话连起来。

### Step 4 — 输出（单份自包含 HTML）

按 `references/report_template.md` 的 HTML 结构输出，章节顺序：标的基本信息（板块定位已含）→ 逐条对照表 → 综合自查结论 → 缺口清单与补充方向 → 自查声明 → 文末固定声明。

### Step 5 — 特别事项与免责

- 列示特别事项（资料限制、期后事项、未决合规事项等）。
- 明确声明：本框架为可行性自查参考，不构成法律意见、监管认定或发行承销承诺；最终以交易所/交易商协会审核与承销、担保机构判定为准。

## 四、数据来源与可达性
见 `references/data-sources.md`：工商/司法/涉诉等维度本技能不可达，缺口标“待补充核验”，绝不编造或假设无风险。

## 五、输出契约

- 交付物：**单份自包含 HTML**（SVG/纯 CSS 内联，不外链本地资源，双击可开），非 Markdown、非 Word、非 PDF。
- 布局：头部一句自查结论 + 标的信息（含板块定位）→ 逐条对照表（表格/要点为主）→ 缺口清单与补充方向 → 文末固定声明。
- 所有数字必须可溯源：就近标注来源类型与基准日；估算与假设单列并标明"假设"。
- 标题用自然成句名词，不写"主名（方法标签）"式自贴括号；方法论质量放正文句、表头列或表尾批注。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_科创债可行性自查.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
