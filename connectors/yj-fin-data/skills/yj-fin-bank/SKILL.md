# 银行信贷与项目贷款 · 融资结构分析

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

## 一、定位与边界

本技能为企业的银行债权融资提供**结构化分析框架**：覆盖融资结构诊断、还款来源与现金流测算（DSCR）、申贷材料清单、增信安排与多方案比选参考，最终交付**单份自包含 HTML 融资结构分析报告**。

**重要边界**：产出的是**结构诊断与方案比对参考**，不替代持牌机构的授信审批、法律意见与审计报告，不构成投资建议。凡涉具体授信结论，须以经办银行审批为准。

## 二、何时触发

- 用户需要梳理一笔债权融资的结构（流贷/项目贷/并购贷/融资租赁/科技贷/票据/组合），判断融什么、融多少、怎么还；
- 用户要准备银行尽调材料，或要一份申贷材料清单与责任分工；
- 银行嫌担保不足，用户要理增信与替代方案（保证、质押、政策性工具、信用贷）；
- 用户手里有两三家银行的方案，要按利率、期限、担保、放款节奏做结构比选参考；
- 用户要在放款前对融资总成本、隐性费用做一遍体检。

**不适用**（分别路由，不越界）：股权融资与估值、并购交易财务尽调、上市与发债、诉讼与合同审查。

## 三、工作流（六步法）

### Step 0 — 融资主体与交易类型定位（前置闸门，不可跳过）

报告前先锁死**融资主体性质与交易类型**，防债权/股权错配、授信品种错配导致方法口径与条款口径三处连锁失真：

| 层        | 典型定位                         | 方法取向         |
| -------- | ---------------------------- | ------------ |
| ① 主体性质   | 国企/上市公司/民企/科技型轻资产/重资产        | 决定增信可得性与综合成本 |
| ② 交易类型   | 流贷/项目贷/并购贷/融资租赁/科技贷/票据/政策性工具 | 决定品种、期限与合规边界 |
| ③ 还款来源结构 | 经营性现金流/再融资/股东支持              | 决定 DSCR 测算口径 |
| ④ 对标参照   | 同类主体、同品种市场条款                 | 决定比选基准       |

**定位卡五字段（强制引用，缺任一项须补完）**：主体性质标签（禁写大类，须写到类型）／交易类型定位（债权内何种品种，禁与股权融资混淆）／还款来源口径（经营现金流/再融资/股东支持，明确用哪层）／可比对标层（同类主体同品种条款）／结构方法指引（匹配该主体与品种的测算逻辑）。

**易混淆点防错（强制）**：若标的存在常见误称，显式标注——「易混淆点：X 常被误按 Y 口径；本框架按 Z（第 N 层）口径，品种匹配与 DSCR 口径均据此」。典型错配：把流贷误用于固投/股权、把项目贷误用于日常周转、把债权融资误述为股权融资。

**判定输入**：用户上传材料 + 用途/财务描述 + 可及研报与公告旁证；泛称与实质冲突时**以实质为准**，不依赖工商/司法外部库。

### Step 1 — 融资结构诊断

- **需求定位**：锁定四项硬参数——金额、期限、用途、借款主体（含股权结构与实控人，工商不可达时标"待补充核验"）。
- **品种匹配**：按用途性质选品种——日常周转→流贷/票据；新建产能/产线→项目贷；买资产→并购贷/融资租赁；科技型轻资产→信用贷/科技贷；有政策导向→再贷款/专项工具。多用途并存给组合建议，标额度占比与先后。
- **合规边界**：流贷严禁流入固投/股权/房地产；项目贷提醒资本金比例（一般自有资金≥20%–30%），不足则先补资本金。用途不清晰时标"口径待补"，不编造。

### Step 2 — 还款来源与现金流测算

- **主轴指标 DSCR**：DSCR =（息税折旧摊销前利润 − 税金 − 资本性支出）÷ 当年还本付息额。基础情景 DSCR ≥ 1.3 视为安全；压力情景（收入−20% 或 利率+100bp）DSCR ≥ 1.0 视为底线。
- **三层还款来源**：经营性现金流 / 再融资 / 股东支持，各自注明假设。
- **情景表**：基础与压力两情景 + 假设清单；拿不到真实财务数据时用区间与情景框架，不填死数，每个数字标假设来源。
- 细则见 `references/loan-playbook.md` 第六、七节。

### Step 3 — 申贷材料清单

按银行尽调标准清单成套准备：基础证照、财务三表与纳税、征信与涉诉、资产与权属、项目可研与批复、担保物估值。清单每项标「责任人 / 状态 / 缺口」，直接用作内部推进表。常见退回原因（用途不清晰、还款来源弱、担保不足、财务不规范、行业受限、资本金不足）提前对冲。司法/征信维度不可达时标"待补充核验"，不假设无瑕疵。

### Step 4 — 增信安排

- **工具排序**：抵押（房产/设备）→ 质押（应收/股权/存单）→ 保证（集团/母公司/政府性担保机构）→ 信用贷（科技型企业白名单），按成本与可得性排序。
- **替代逻辑**：银行嫌抵押不足时，依次评估"加保证人→加质押→进政策性担保/白名单→降额度或缩短期限"，只给可得性判断，不空许。
- **政策性工具**：设备更新贷、科技创新再贷款、政府性融资担保单列，标注申请门槛与额度上限。

### Step 5 — 多方案比选参考

- **七维对比**：利率（LPR±bps）、期限、担保要求、放款节奏、综合成本（含担保费/过桥/评估/顾问费）、提前还款条款、交叉违约。
- **综合成本归一化**：把利率与各项费用年化到「实际年化融资成本」再排序，避免被低表面利率误导；输出对比表 + 综合成本由低到高排序，给首选与备选。
- **边界声明**：银行方案与报价须来自用户上传的各行询价结果，本技能不提供银行对接；本模块只做结构比对参考，**具体授信以经办银行审批为准，不做谈判促成、不替客户去谈**。

## 四、数据来源与主动交叉验证纪律

见 `references/data-sources.md`。核心纪律：

- **可用维度**（研报/纪要/观点/公告/行情财务）正常用并就近标注。
- **不可达维度**（工商登记、司法冻结、央行征信、一级融资库、非上市财务、公网检索）如实标注"受数据可得性限制，XX 待补充核验"，**绝不假设无诉讼/无冻结、绝不按金额倒推、绝不编造股东名册与银行报价**。
- **主动交叉验证（强制）**：关键数字（利率、抵押率、占比、DSCR 参数等）须以 ≥2 个独立来源交叉核对，业务材料主张与独立源不一致处显式标注差异；缺口"待补充核验"，绝不静默编造或按金额倒推。以原生 `yj-fin-data（knowledge_search）`/`yj-fin-data（fetch_document）`/`yj-fin-data` 与用户上传材料做交叉验证。
- 凡维度拿不到可靠来源，一律用自然措辞"受数据可得性限制，XX 待补充核验"带过，不写"故障/未连通/兜底"。

## 五、输出契约

- 交付物：**单份自包含 HTML**（SVG/纯 CSS 内联，不外链本地资源，双击可开），非 Markdown、非 Word、非 PDF。
- 布局：头部一句结构结论 + 概览 → 各分析模块（表格/要点为主）→ 风险与结论 → 文末固定声明。
- 所有数字必须可溯源：就近标注来源类型与基准日；估算与假设单列并标明"假设"。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_融资结构分析.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
