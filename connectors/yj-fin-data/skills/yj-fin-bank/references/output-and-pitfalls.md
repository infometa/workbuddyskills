# 去 AI 化 + 排版与成文纪律（hu-fin-bank）

## 一、去 AI 化硬禁词（命中即改）

- **过程痕迹**：作为 AI 助手 / 根据公开信息 / 建议进一步核实 / 值得关注。
- **工具与系统内词**：skill 名、yj-fin-knowledge/data/file（仅作来源标签允许）、Reportlab、tyc、zerone、云极、Stage 0、定位闸门、markitdown、docx、xlsx、脚本名。
- **故障词**：未连通 / 故障 / 会话异常 / 兜底 / 已降级 / 探活。
- **内部指代**：朋友点名 / 核心痛点；与既往报告对照（"上一版误判"）一律不写。
- **数据缺失** → 自然措辞"受数据可得性限制，…待补充核验"，不写"故障 / 未连通"。
- **禁自曝取数能力**：不写"本技能可调用 / 无公开机构库可调用 / 机构库 / 上下游三库"。

## 二、标题禁"主名＋括号方法标签"

标题用自然成句名词，不写"主名（方法标签）"式自贴括号。方法论与质量要求放正文句、表头列或表尾批注。

- **可保留的括号**：仅客观归属型，如 `(项目贷)` `(流贷)` `(公司公告)`。
- **必删的括号**：用途口径＋合规判定 / 单中性 / 赋值+依据 / 口径治理 等自我方法说明。

## 三、排版与成文纪律（九项，交付前逐条过）

1. **列表项独立成行**：`①②③`／`1. 2. 3.` 等并列项不得用分号或全角空格串接在同一行，每项独立成行或成 bullet（防断号、防粘连）。
2. **一段一要点**：一个段落只承载一个核心观点；多个独立要点各自独立成段／bullet／单元格，禁止"一坨"长段；单元格内禁止用 `+` 串接多个长项。
3. **生成期整段重复自查**：同一内容只写一次；"风险／结论"等收尾段严禁整段复制两遍，交付前通读查重。
4. **空格与分隔符**：中文并列项写 `A/B/C`、`A·B`（不带空格）；中文语境下 `→` `-` `+` `–` `—` 两侧不带空格（如 `流贷-项目贷`、`5000万元→2026E`）；纯英文 compound（`EV-Sales`、`2025-11`）保持原样。
5. **特殊 Unicode／装饰符**：优先用 ASCII（写 `10^-7` 而非 `10⁻⁷`、`<=` 而非 `≤`）；不用 `✓`/`✔` 等装饰符号，改用文字（「属实」「是」）。
6. **禁自创伪专业空壳名词**：凡"专业名＋调整／展宽／溢价／折损"结构，先给数值＋来源再命名；无数值支撑的一律改为「待量化，不计入」或直接删除。
7. **约量词不悬空**：「约／大约／左右／近乎」后必须紧跟具体数字（如「约 5000 万元」），禁止「融资额约—」这类残句。
8. **通篇中文**：正文与表格统一中文；英文术语（DSCR、LPR、EBITDA 等）可保留但须置于中文语境，不得整句英文残留。
9. **无残留物**：不得出现占位符（`__`／`TBD`／裸「待补」）、半截自我修正残句；同一数字在不同位置口径一致；标题下必须有内容，不留孤立标题或空区块。

## 四、不适用清单（PDF 专属，勿迁移、勿回退）

- 分页／页码／页眉页脚（HTML 无页；且成稿闸门明令"无长页脚"）；
- 封面页：本报告不设封面，版式为「头部一句结论＋概览 → 各模块 → 风险与结论 → 文末声明」；
- 多册分册（摘要／正文／附件分册）：输出归一为**单份 HTML**；
- reportlab／两端对齐 `TA_JUSTIFY`：HTML 无此概念，且属禁词；
- 反引号包裹中文 → ■：浏览器可正常回落渲染，非问题。

## 五、常见坑位（债权融资域）

1. **参数凭记忆填数**：LPR、抵押率、行业 DSCR 基准必须有来源与基准日，无来源则标"待补充核验"并在敏感性中体现，不得自行设定后当既定参数用。
2. **工商与涉诉臆断**：不可达维度一律标待补充，绝不写"无诉讼""无冻结""无股权瑕疵"。
3. **银行报价虚构**：银行方案与报价只来自用户上传询价；无来源则写"待用户补充"，不虚构银行利率或授信意向。
4. **品种错配**：流贷不得用于固投/股权/房地产；项目贷须先确认资本金；错配须在结构诊断小节显式纠正。
5. **综合成本漏算隐性费用**：必须含担保费、过桥、评估、顾问等隐性费用，不得只报表面利率。
6. **把区间写成承诺**：DSCR/综合成本为测算框架输出，须与"非授信结论""以经办银行审批为准"同时出现。
7. **主动交叉验证缺位**：关键数字须 ≥2 独立源交叉；差异显式标注，绝不静默取其一或按金额倒推。
