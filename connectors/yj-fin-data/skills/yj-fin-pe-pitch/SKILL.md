# 融资路演准备（路演蓝图＋问答预案＋复盘 · 单份 HTML 准备成品）

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。
- **可比公司与行业背景分析由本技能基于 `yj-fin-data` 取数自行完成**：用 `securities_search` 定位可比上市公司 → `knowledge_search`/`fetch_document` 取研报与公告 → `financial_*`/`quote_*`/`valuation_analysis` 取财务行情估值，自行做一页通 / 同业对比 / 投资主线梳理。**不调用任何外部 agent 工具**；标的自身数据以用户上传为准，缺失即标"待补充核验"，绝不虚构。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

面向一级市场融资路演的准备与自检 skill。输入一份路演稿 / BP / 业务材料，按模块拆解讲稿结构、梳理投资人高频问答预案、做逐轮复盘改进，最终交付**一份自包含 HTML 路演准备报告**，只服务于路演前的准备与自检。

> 工商登记 / 一级融资 / 司法 / 非上市财务等本技能不提供的维度，为默认已知限制——凡涉此类维度以材料与可及旁证为准，缺的如实写"待补充核验"，不静默编造。

## 一、定位与边界

本 skill 是**路演准备与自检框架**（分析/复盘类），产出的是讲稿结构、问答预案与改进清单，**非执业评估报告、非投资建议、不替代法律/财务/税务专业服务**。

**重要边界**：
- 不做"去找某投资人""对接 FA""组织中介"等对外推介或撮合动作；结论性质为「路演准备复盘与参考」。
- 不输出确定性投资/交易结论（"保证拿到投资""估值必达 X 倍"）。
- 涉及具体条款、税务、审计、法律结论时，直接说明能力边界并建议咨询对应专业机构。

## 二、何时触发

- 用户要打磨路演讲稿或 BP 讲解结构，尤其是开场与主线；
- 要准备投资人会问的问题，或做问答对练、模拟提问；
- 要对一版 BP / 路演稿做逻辑与数据口径诊断；
- 要复盘刚结束的一轮路演，拿改进清单；
- 关键词：路演演练、路演陪练、讲稿打磨、开场三分钟、BP讲解、投资人问答、投资人会问什么、答辩复盘、模拟提问、模拟路演、问答演练、路演彩排、投资人高频问题、BP逻辑薄弱、路演提纲、演讲稿结构、怎么讲给VC听、估值怎么答、风险怎么说、临场准备清单、投前演练、上会演练、董事会汇报演练。

## 三、工作流（三模块一次跑通）

### 模块一 · 盘项目与定位（路演蓝图前置）

1. **盘点项目与材料** — 基于用户提供的 BP / 讲稿提炼核心事实清单（融资阶段、标的、材料版本、关键事实）。材料为 PDF/PPT/Word 时按既有转写能力读取，不把整份文档直接读进上下文；扫描件无文字层时直接读原文件。输出项目事实 + 缺口清单（缺口一律标"口径待补"并注明补的出处，例如第三方尽调/审计报告/客户确认），不编造任何数字。
2. **确认关键前提** — 融资阶段、标的、路演时长、本轮目标。任一缺失先用不超过 5 个问题把背景、目标、约束问清再动手，不做基于错误假设的产出。
3. **讲解主线一句话** — 先立住主线——"我们给【明确客户】解决【具体问题】，靠【唯一壁垒】，现在【阶段与凭证】，本轮融资【金额与用途】"，四要素缺一即说明主线没想清。细则见 `references/pitch-blueprint.md`。
4. **时间分配与逐段讲稿** — 按总时长倒推各段时长（开场固定前 20%、问答留 25–35%），给出逐段讲稿框架与每部分要点；确认后逐段展开正文，单轮聚焦一到两段。

**标的所处环节（前置定位，不可跳过）**

选讲稿重点与可比口径之前，先锁死**标的在产业链哪一层**，防把上游芯片/模组公司误讲成下游设备/系统公司，导致市场规模(TAM)、可比公司、估值逻辑三处连锁失真。

| 层 | 典型对象 | 讲稿与技术重点取向 |
|---|---|---|
| ① 芯片/核心元器件 | 半导体、IC、传感器芯片 | 器件指标、良率、流片/封测供应链 |
| ② 模组/组件 | 芯片+外围功能模组 | 模组集成度、适配性、成本结构 |
| ③ 设备/终端 | 整机、仪器 | 整机性能、认证、客户绑定 |
| ④ 系统/方案 | 软硬一体解决方案 | 方案落地、运维、切换成本 |

**定位卡（下游模块强制引用，缺任一项须补完）**：精确子行业标签（禁写大类，须写到环节）／价值链位置（上游·中游·下游·系统）／市场数据口径（芯片级·模组级·设备级，明确用哪层）／可比公司对标层（同层对标，芯片对芯片）／估值方法指引（匹配该层的估值逻辑）。

**易混淆点防错（强制）**：若标的存在常见误称（如把"芯片厂商"按"整机方案商"口径讲），显式标注——「易混淆点：X 常被误称为 Y；本报告按 Z（第 N 层）口径，市场规模/可比公司/估值方法均据此」。判定输入：用户上传材料 + 官网/BP 产品词 + 可及研报/公告 + 行业标签；泛词与产品实质冲突时**以下游产品实质为准**。

### 模块二 · 投资人问答预案（对练与自检）

1. **逐段讲练** — 按模块一结构从开场段开始逐段讲练，每段练完转问答。
2. **问答对练** — 加载 `references/investor-qa-bank.md`，按融资阶段与赛道取题（5–8 题，先主线后硬骨头），每题以「问题 → 应对要点 → 禁忌 → 追问预案」四列呈现，不写成散文。问答清单只作准备与自检参考，不构成任何机构的真实投资意见。
3. **答案缺口登记** — 用户答不上来的题与缺口径的数字记进演练记录，下一轮优先回炉。

**主动交叉验证纪律（强制）**

对关键数字（市场规模、收入、毛利率、客户集中度、融资额/估值等）用 ≥2 个独立来源交叉验证；项目方材料主张与独立源（可及研报/公告/行情财务）不一致处显式标注差异来源标签，缺口"待补充核验"，**绝不静默编造或按金额倒推**。可用 `yj-fin-data（knowledge_search）`/`yj-fin-data（fetch_document）`/`yj-fin-data` 做交叉核对与差异标注；不可达维度（工商/司法/一级融资）照 `references/data-sources.md` 标"待补充核验"，**不重新引入本机专属工商/一级融资硬依赖**。

### 模块三 · 复盘与改进（三维度自评）

1. **三维度复盘** — 按**内容、结构、表达**给改进点：内容看事实是否站得住、口径是否前后一致；结构看主线有没有被听懂、时间是否失衡；表达看术语密度、口头禅、有没有可被当场追问的破绽。评分表见 `references/pitch-blueprint.md`。
2. **下一轮训练清单** — 给 3–5 条具体到段落与题型的改进项；第二轮起以首轮记录为基线，只报相对变化项，不重复全量。

**估值精度纪律（路演估值口径焊死，不可降级）**

路演中"估值怎么答"须按统一方法论口径，避免被问穿：
- **单一中性基准 + 窄幅可谈区间**：先给一个中性基准值，区间 = 基准 ×(1±半宽)，半宽控制在 **±10%~22%**；禁用保守/中性/进取三档大跨度并列当谈判筹码。
- **流动性折让**：涉及非上市股权、受限权益等流动性较弱者，作锚时须显式计入流动性折让（0.40–0.70）并说明依据。
- **剔除情绪与题材溢价**：不得以题材热度、市场情绪、政策预期单独上调估值；此类因素若影响参数，须给出数值与来源。
- **收入三档情景化**：收入预测给保守/中性/进取三档情景，各档附假设与触发条件，不写成对具体标的的买入/卖出建议。
- 口径放正文句或表头列，**标题不得加"单中性/不进倍数"等自我方法标签括号**；与文末"不构成任何投资建议"声明一致。

## 五、输出契约

- 交付物：**单份自包含 HTML**（SVG/纯 CSS 内联，不外链本地资源，双击可开），非 Markdown、非 Word、非 PDF。
- 文件名建议：`{标的}_融资路演准备.html`。
- 布局：头部一句结论（讲清了吗/可信吗/答得住吗）+ 标的概况 → 各模块（路演蓝图 / 问答清单 / 复盘改进，表格/要点为主）→ 风险与结论 → 文末固定声明。
- 所有数字必须可溯源：就近标注来源类型与基准日；估算与假设单列并标明"假设"。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_融资路演准备.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
