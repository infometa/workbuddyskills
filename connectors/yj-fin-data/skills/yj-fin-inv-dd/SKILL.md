# 股权投资投前尽调框架（PE/VC 全流程 · 单份 HTML 结构化交付）

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。
- **可比公司与行业背景分析由本技能基于 `yj-fin-data` 取数自行完成**：用 `securities_search` 定位可比上市公司 → `knowledge_search`/`fetch_document` 取研报与公告 → `financial_*`/`quote_*`/`valuation_analysis` 取财务行情估值，自行做一页通 / 同业对比 / 投资主线梳理。**不调用任何外部 agent 工具**；标的自身数据以用户上传为准，缺失即标"待补充核验"，绝不虚构。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

面向一级市场（PE/VC）股权投资投前尽职调查的祜·Care及Gangtise合作股权投研。输入一份业务材料（BP、业务介绍，或标的全称＋官网），或一句尽调需求，直接按工作流拆解清单、生成会议准备与投委会备忘录，并给出回报/单位经济/价值创造的测算框架，**最终交付一份单份自包含 HTML 尽调报告**。

> 工商登记 / 一级融资 / 司法 / 非上市财务等本技能不提供的维度，为默认已知限制——凡涉此类维度以材料与可及旁证为准，缺的如实写"待补充核验"，不静默编造。方法论文档在 `references/`。

## 一、定位与边界

按通用 PE/VC 投前尽调方法论，为标的提供**尽调清单、红旗汇总、会议准备与投委会备忘录框架**，并给出回报/单位经济/价值创造的**测算框架与情景示意**。

**重要边界**：本框架产出的是**方法论参考与尽调框架，非执业评估报告、非投资顾问结论**，不构成对具体标的的买入/卖出建议，不替代 GP/LP 最终决策责任。本技能已去除"投资人推荐 / FA 对接 / 银行谈判 / 中介组织 / 监管资格硬结论（符合/不符合）"等对外责任动作，结论性质为"投前尽调复盘与参考"。凡需对外出具具法律效力的尽调报告，须由具备资质的机构与人士执行。

## 二、何时触发

- 用户需要做 PE/VC 投前尽调、尽调清单、红旗汇总、尽调会议准备、IC Memo 或回报测算框架；
- 出现关键词：投前尽调、尽职调查、尽调清单、财务尽调、商业尽调、法律尽调、红旗、投委会、IC Memo、回报测算、IRR、MOIC、单位经济、LTV、CAC、价值创造、VCP；
- 输入形态：① 用户上传 BP/业务介绍/财务资料；② 用户仅以文字描述标的与尽调需求；③ 用户给标的全称或官网并说明尽调意图。

## 三、工作流（七步法）

### Step 0 — 前置输入核对（激活后先做）

| 输入类型 | 示例 | 是否必须 |
|---|---|---|
| 标的标识 | 全称、官网 URL、主营业务描述 | 至少一项 |
| 业务材料 | BP/摘要、主营、产品、技术壁垒、客户、团队 | 推荐 |
| 财务数据 | 三张表（含非规范报表） | 推荐 |
| 交易信息 | 历史融资、交易类型、本轮额/结构/估值 | 可选 |
| 限定条件 | 可比交易所、三级赛道、基准日、尽调深度 | 可选 |

逐项核对，说明缺失项对精度的影响，但基于可得信息推进并显式标注假设。

### Step 1 — 标的所处环节定位（前置闸门，不可跳过）

选方法、排清单之前先锁死**标的位于产业链哪一层**，防把上游芯片/模组公司误写成下游设备/系统公司，导致市场规模（TAM）、可比公司、估值方法三处连锁失真：

| 层 | 典型标的 | 尽调侧重 |
|---|---|---|
| ① 芯片/核心元器件 | 半导体、IC、传感器芯片 | 重技术尽调、IP 与流片能力、客户验证 |
| ② 模组/组件 | 芯片+外围功能模组 | 技术+供应链、关键物料依赖 |
| ③ 设备/终端 | 整机、仪器、终端产品 | 商业+客户集中度、GTM 与渠道 |
| ④ 系统/方案 | 软硬一体解决方案 | 重商业（大客户/项目制）、交付与回款 |

**定位卡五字段**（下游模块强制引用，缺任一项须补完）：精确子行业标签（禁写大类，须写到环节）／价值链位置（上游·中游·下游·系统）／市场数据口径（芯片级·模组级·设备级，明确用哪层）／可比公司对标层（同层对标，芯片对芯片）／估值方法指引（匹配该层的估值逻辑）。

**易混淆点防错（强制）**：若标的存在常见误称，显式标注——「易混淆点：X 常被误称为 Y；本报告按 Z（第 N 层）口径，市场规模/可比公司/估值方法均据此」。

**判定输入**：用户上传材料 + 官网/BP 产品词 + 可及研报/公告 + 行业标签；**不依赖**任何本机工商或一级融资库。泛词与产品实质冲突时**以下游产品实质为准**。

### Step 2 — 六大工作流尽调清单

按交易类型覆盖六条工作流，输出表格化清单（事项/关注点/优先级/状态/负责人/备注）：

1. **财务尽调**：QoE（收入与 EBITDA 调整）、营运资本 normalization、债务及类债务项、维护性 vs 成长性 Capex、税务结构与敞口、审计历史与会计政策、备考调整（run-rate、协同）。非规范报表做标准化，输出原始 vs 标准化对比。
2. **商业尽调**：TAM/SAM/SOM、竞争定位与份额、客户集中度/留存/NPS、定价力与合同结构、销售漏斗与 backlog、GTM 有效性。
3. **法律尽调**：公司结构与组织图、重大合同（客户/供应商/合作）、诉讼历史与未决索赔、IP 组合与保护、监管合规、雇佣协议与竞业。
4. **运营尽调**：管理层评估、关键人风险、IT 系统与基础设施、供应链与供应商依赖、设施与不动产、保险覆盖。
5. **HR 与人才尽调**：组织图与人数趋势、薪酬对标、留任风险、文化评估、工会/劳工协议。
6. **IT 与技术尽调（技术驱动型）**：技术栈与架构、技术债、网络安全态势、数据隐私合规（GDPR/CCPA/SOC2）、产品路线图、可扩展性。

行业附加项（自动叠加）：软件/SaaS（ARR 质量、队列分析、托管成本、SOC2）、医疗健康（监管审批、报销风险、付费方结构）、工业（设备状况、环境修复、安全记录）、金融服务（监管资本、合规历史、信贷质量）、消费（品牌健康、渠道结构、季节性、库存管理）。

### Step 3 — 状态跟踪与红旗汇总

- 状态机：Not Started → Requested → Received → In Review → Complete → Red Flag。
- 红旗汇总：发现内容 / 所属工作流 / 严重度（deal-breaker / significant / manageable）/ 缓释路径 / 对估值或交易条款的影响。

### Step 4 — 尽调会议准备

按会议类型生成一页 meeting prep（会议信息、Top 3 目标、分组问题清单标★必问、基准数据、红旗、跟进事项）：

- **管理层演示**：业务概览、收入与增长、竞争定位、运营与团队、财务深潜、前瞻假设。
- **专家网络电话**：市场定位、长期趋势、最强竞争者、最该尽调的点。
- **客户参考电话**：选择原因、替代方案、优劣、续约/扩展意愿、提价 10–20% 反应。

原则：开放式问题开场、不诱导、结尾必问"还有什么我们该问但没问的"、问题数 15–20 封顶。

### Step 5 — 投委会备忘录（IC Memo）

标准九段结构：

- I. 执行摘要（1 页：公司描述、交易逻辑、关键条款、建议与 headline returns、Top 3 风险与缓释）
- II. 公司概况（业务/产品、客户与 GTM、竞争定位、管理层）
- III. 行业与市场（规模增长、竞争格局、长期趋势、监管）
- IV. 财务分析（历史业绩、QoE 调整、营运资本、Capex）
- V. 投资逻辑（3–5 支柱、价值创造杠杆、100 天优先级）
- VI. 交易条款与结构（EV 与倍数、S&U、资本结构/杠杆、关键法律条款）
- VII. 回报分析（熊/基/牛三情景、IRR/MOIC 框架示意、关键假设、敏感性）
- VIII. 风险因素（按严重度与可能性排序、缓释、deal-breaker）
- IX. 建议（Proceed / Pass / Conditional，关键条件与下一步）

纪律：事实与平衡、不淡化风险、财务表须勾稽（EBITDA bridge、回报数学一致）、缺输入则问而非假设。

### Step 6 — 回报 / 单位经济 / 价值创造框架（测算示意，附估值精度纪律）

仅作测算框架，非真实交易建议；参数须透明、可复算，附"受数据可得性限制待补充核验"。

**回报分析**：MOIC = 退出股权价值 / 股权出资；IRR 解 r：股权出资 × (1+r)^n = 退出股权价值（计入期间现金流）；回报归因（增长/倍数/偿债/费用）；敏感性矩阵与熊/基/牛三情景。进入倍数、退出倍数、EBITDA 增长、持有期、杠杆均须标来源与假设。

**单位经济**：ARR bridge、CAC、LTV、LTV:CAC（>3x 目标）、回收期、毛/净留存、队列矩阵、Rule of 40、Magic Number 等基准对标。收入质量评分须有依据。

**价值创造计划（VCP）**：EBITDA bridge（当前→目标）、杠杆（增长/利润/倍数扩张）、100 天计划（稳定评估/规划启动/执行度量）、KPI 看板。

**估值精度纪律（本框架不可降级）**：

- **单一中性基准 + 窄幅区间**：先给一个中性基准值，区间 = 基准 ×(1±半宽)，半宽控制在 **±10%~22%**；禁用保守/中性/进取三档大跨度并列。
- **二级做锚强制流动性折让**：以二级可比或上市公司做锚时，非上市股权、受限资产等流动性较弱者须显式计入流动性折让（0.40–0.70）并说明依据。
- **剔除情绪与题材溢价**：不得以题材热度、市场情绪、政策预期单独上调估值；此类因素若影响参数，须给出数值与来源。
- **收入三档情景化**：保守/中性/进取三档须以收入（或 EBITDA）三档情景驱动，而非凭空给倍数区间。
- 结论须**可复算**（初始基准 × 系数；区间 = 基准 ×(1±半宽)，半宽来自敏感度档）；不写成对具体标的的买卖建议，与文末"不构成任何投资建议"一致。

### Step 7 — 主动交叉验证纪律（不可跳过）

对关键数字用 ≥2 独立源交叉验证，业务材料主张与独立源不一致处显式标注差异（差异来源标签），缺口"待补充核验"，绝不静默编造或按金额倒推。

- **判定与交叉验证口径**：以 数据工具取数（研报/纪要/观点/公告/行情财务，入口为 yj-fin-data（knowledge_search） / yj-fin-data（fetch_document） / yj-fin-data）做主动交叉验证 + 差异标注；不可达维度（工商/司法/一级融资）照 `references/data-sources.md` 标"待补充核验"。
- **缺口措辞**：一律写"受数据可得性限制，…待补充核验"，不写探活/未连通/故障/兜底/已降级等故障词；缺口不假装查过、不按金额倒推轮次、不编造股东名册。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_投前尽职调查.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
