# PE-VC 分析师（一级股权投资 · 单份 HTML 结构化分析）

面向一级市场（VC/PE/FA）的标准化股权投资分析 skill。输入一份业务材料（BP、业务介绍、或企业全称+官网），直接按模块拆解，**不设 Stage 前置定位闸门、不做数据可达性强制前置声明、不做面向机构的 FA 推广建议**；最终交付**一份自包含 HTML 股权投资分析报告**。

> 本 skill 以 **祜·Care及Gangtise合作股权投研** 为主体数据源：数据来源统一标注「祜·Care及Gangtise合作股权投研」，不出现外部平台名、工具名或"项目方 BP（本地解析）"等字样。工商登记 / 一级融资 / 司法 / 非上市财务等本技能不提供的维度，为默认已知限制——凡涉此类维度以材料与可及旁证为准，缺的如实写"待补充核验"，不探活、不跑空、不静默编造。方法论文档在 `references/`。

## 触发条件（满足任一即激活）
1. BP 文档 / 业务介绍文本 + 估值 / 融资 / 投资人 / 可比公司 等关键词；
2. 企业全称 / 统一社会信用代码 / 官网 URL + 上述任一意图；
3. 企业历年财务原始报表 + 估值 / 可比关键词；
4. 融资历史、本轮融资需求、出让股权比例。

仅给企业名未明意图时，主动问是否需要做股权投资分析。**已上市公司的估值/调研/纪要等另有对应专项能力；本 skill 聚焦一级/成长期标的的结构化投研，已上市标的则以其为市场参照与上限校验。**

## 前置输入核对（激活后先做）
| 输入类型 | 示例 | 是否必须 |
|---|---|---|
| 企业标识 | 全称、统一社会信用代码、官网 URL | 至少一项 |
| 业务材料 | BP/摘要、主营、产品、技术壁垒、客户、团队 | 推荐 |
| 财务数据 | 三张表（含非规范报表） | 推荐 |
| 工商/司法 | 外部工商/司法核验结论（股权穿透/实控人/诉讼冻结） | 推荐（未提供则标"待补充核验"） |
| 融资信息 | 历史融资、上轮投后估值、本轮额/出让比例 | 可选 |
| 限定条件 | 可比交易所、三级赛道、基准日 | 可选 |

逐项核对，说明缺失项对精度的影响，但基于可得信息推进并显式标注假设。

## 数据与出处（默认约束 · 必须实取）
- **数据主体**：本技能为不绑定任何平台的祜·Care及Gangtise合作股权投研。
- **取数纪律（硬约束）**：所有外部数据必须来自 yj-fin-data MCP 工具实取（维度→工具映射见 `references/data-sources.md`），**不得凭记忆撰写**；工具返回未授权(UNAUTHORIZED)时立即停止并引导用户完成云极账号授权，严禁用记忆填空。
- **默认已知**：本技能无工商登记 / 一级融资 / 司法 / 非上市财务专属库。运行时不为此探活、不中断。
- **缺失处理**：某维度（如股权结构、一级融资事件、诉讼）拿不到可靠来源时，在对应处如实写一句"受数据源限制，XX 待补充核验"，**绝不假设"无诉讼/无冻结"、绝不按金额倒推轮次、绝不编造股东名册与股权比例**。
- **报告成品禁“自曝取数能力词”**：报告内不得出现“本技能某库可调用”“无公开机构库可调用”“机构库/天眼查/执中/上游三库”等能力或工具库词句；凡维度拿不到可靠来源，一律只用自然措辞“受数据可得性限制，XX 待补充核验”带过，不解释为何缺失、不点任何内部取数通道或库名。
- **出处标注**：关键经济/行业/公司数据附来源标签 `[项目方-BP]` / `[研报]` / `[纪要]` / `[观点]` / `[公告]` / `[行情/财务]` / `[用户提供]` 等，就近标注；凡自曝取数通道、工具库、内部能力与"外部机构平台名"的表述仍一律禁止（见上行，两者不冲突：署名品牌≠取数能力自曝）。TAM/增速尽量用可及的多来源交叉；冲突以更权威为准。一级/二级可比乘数、财务调整、估值系数均须带来源。
- 交付物是分析成品：局限用"受数据源限制/待补充核验"等自然措辞，不写"故障/未连通/兜底"。

**取数铁律（硬约束）**：① 所有取数一律经 yj-fin-data MCP——工具含 `securities_search` / `quote_*` / `financial_*` / `valuation_analysis` / `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` / `concept_*` / `sector_*` / `macro_indicator_*` / `indicator_*`；② 研报/纪要/观点/公告一律经 `knowledge_search`/`fetch_document`/`meeting_summary_list`/`domestic_chief_opinion_list`/`management_discussion`/`qa_list` 实取，不得凭记忆填空；③ **不得调用任何未暴露的 agent 结论工具**（`agent_*`/`investment_clues`/`hot_topic` 等在本环境均不可用），可比公司与乘数用 `financial_*`/`quote_*`/`valuation_analysis`/`earnings_consensus` 自行计算；④ 遇 `UNAUTHORIZED`（云极账号未授权）即停并引导用户在连接器里完成授权，绝不编造数据。

## 模块化分析流程（按一→四顺序一次跑通；不设 Stage 前置定位闸门）

### 模块一 · 企业基础画像
1. **基础信息表格**：基础信息项 | 业务材料提炼 | 可及研报/公告核实。注册地/成立/实控人/核心团队/知识产权等（缺省如实一句带过）。
2. **工商与股权**：尽可能穿透至实控人/GP。外部工商/司法核验结论优先；工商/司法本级不可达 → 风险提示"待补充核验"，绝不假设无诉讼。
3. **财务**：按上市状态分流；非规范报表做 CAS 标准化（见 `references/financial-standardization.md`），输出【原始 VS 标准化】对比。
4. **行业与市场规模（简版）**：三级赛道 + TAM/SAM/SOM。
5. **核心优势**：技术/商业模式/阶段/下游/客户集中/格局/政策，以材料与可及旁证归纳为要点即可。

### 模块二 · 行业深度分析（八点，禁漏项、禁只写大类）
① 细分+技术壁垒 ② 产业链+卡脖子+国产化 ③ 国内外规模+近3年增速+未来3年空间（口径自洽、写明量纲） ④ 融资热度+估值体系+冷热 ⑤ 海内外格局+集中度 ⑥ 政策+合规 ⑦ 机遇/风险/真实痛点 ⑧ 对标本项目优劣关键指标。以研报/纪要/线索为独立源交叉，**严禁整段只引 BP 叙事**。

### 模块三 · 可比公司对比（以上市二级可比作市场参照/上限校验，VC 法兜底）
以同三级细分、可比阶段的可公开市值/乘数作**市场参照**（sanity check + 上限），财务运营对标近3年 CAGR/毛利率/研发费率/净利率等；二级可比不足时直接 VC 法兜底并注明（本币口径下不引入一级市场对比作主锚；无可靠一级公开源的轮次不做臆测反推）。可比含不同价值链层时单列"参照（不进倍数）"。一级轮次表用外部核验渠道/BP/研报交叉，无可靠来源标"公开披露有限，一级可比轮次待补充"。

### 模块四 · 估值测算（去融资建议，只做中性的估值+交易结构）
> 输出口径：单一**中性基准**为结论档 + 窄幅**建议可谈区间**（通常 ±10%~22%），不进保守/中性/进取三档大跨度。

细则见 `references/valuation.md`。
1. **估值路径**：二级上市可比乘数作市场参照 / 上限校验（见模块三），二级可比不足或无可靠锚时 VC 法兜底。场景A(盈利) PE/PEG/EV-EBITDA；场景B(未盈利硬科技) PS/EV-Sales/PB+订单管线，口径与可比层保持一致。
2. **五维打分 + 雷达**：技术壁垒(0~+40%)/商业化(-30~+30%)/团队(0~+20%)/政策竞争(-25~+25%)/经营风险(0~-40%)，合成中性基准投前估值 + 可谈区间，雷达图由 `scripts/generate_report.py` 渲染。
3. **交易与条款（中性）**：投前/投后/出让比例/稀释的换算逻辑，价格贵贱双视角并标注假设与局限。

## 交付物结构（仅一份自包含 HTML）

**唯一的投研成品 = 单份自包含 HTML 股权投资分析报告**（文件名 `{公司}_股权投资分析.html`）。覆盖各分析模块 + 风险提示 + 结论。

- **布局建议**：顶部一句 IC/投资结论 + 公司概况头部 → 各分析模块按序（表格/要点为主，大段文字禁超长）→ 结尾风险与结论。随内容内联图表（五维雷达 + 可比柱/条，均用内联 ECharts），**不外链本地资源**，双击即可在浏览器打开。
- **不用 Markdown**：HTML 为最终交付格式，不另出 .md 或 PDF。中文字体用系统常见栈（`"Microsoft YaHei","PingFang SC","Noto Sans CJK SC",sans-serif`）即可正常显示。
- **排版 sanity**：成稿后用浏览器/纯文本抽查，确认无未闭合标签、无乱码、关键中文无异常换行。
- **标题写法**：报告中模块/小节标题用自然成句名词或自足短语，不写"主名（方法标签）"式自贴括号；方法论/质量要求（口径治理、冷热、赋值依据证据强度、可谈区间等）放正文句、表头列或表尾批注，不进标题括号（细则见 output-and-pitfalls「标题禁主名＋括号方法标签」）。
- 表格/乘数/调整均带来源行；结论与估值长句拆短。来源与口径说明放**表下注解**（纵向展开），**不占表格列**——详见 `references/output-and-pitfalls.md`「表格列纪律」。

**文末统一声明（强制固定款 · 各版本文末唯一收口）**：
页面底部不再设长页脚（不生成"本报告｜署名(分析/署名)｜数据源与可复核公开通道：…｜单位：RMB；口径注释随文"这类长行）；报告最末只落这一固定句，一字不改——
`本报告由祜·Care 与 Gangtise 合作开发，属测试技能，仅供股权投研复盘与尽调参考。本报告不构成任何投资建议，据此决策风险自担。如有优化建议或业务咨询，请联系 13386019198。`

## 生成流程（脚本）

1. 用数据通道 MCP 工具取数 + 外部核验结论与 BP 材料，组装成报告输入 JSON（可经 `scripts/assemble_data.py` 校验归一：必填 `company` 与 `valuation.five_dims` 五项）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（内联 ECharts，离线自包含）。
3. 对照 `references/evaluation-gates.md` 十关逐条勾选，任一不过打回修订。
