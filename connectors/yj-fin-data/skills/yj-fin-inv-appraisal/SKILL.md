# 资产评估方法论参考

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。
- **可比公司与行业背景分析由本技能基于 `yj-fin-data` 取数自行完成**：用 `securities_search` 定位可比上市公司 → `knowledge_search`/`fetch_document` 取研报与公告 → `financial_*`/`quote_*`/`valuation_analysis` 取财务行情估值，自行做一页通 / 同业对比 / 投资主线梳理。**不调用任何外部 agent 工具**；标的自身数据以用户上传为准，缺失即标"待补充核验"，绝不虚构。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

## 一、定位与边界

按中国资产评估执业准则口径，为各类资产提供**估值方法论参考**：覆盖机器设备、房地产、无形资产、企业价值、金融资产等资产大类，含收益法、市场法、成本法三类基本方法及其交叉验证纪律，输出**单一中性基准与窄幅可谈区间**的测算框架。

**重要边界**：产出的是**方法论参考与测算框架，非执业资产评估报告**，不替代注册资产评估师的法定签字与法律责任，不构成交易保证或投资建议。凡需法定效力的评估结论，须由具备资质的机构与人士出具。

## 二、何时触发

- 用户需要资产估值分析、估值方法比对、评估参数口径梳理；
- 出现关键词：评估、估值、资产评估、价值评估、收益法、市场法、成本法、重置成本、成新率、资产入账、抵押评估、出资评估、企业价值评估、机器设备评估、房地产评估、无形资产评估、金融资产评估；
- 输入形态：① 用户上传资产清单 / 财务资料 / 权属文件；② 用户仅以文字描述评估需求。

## 三、工作流（六步法）

### Step 0 — 评估要素确认闸门（不可跳过）

先锁定五项基本评估要素，**缺失则向用户澄清，不臆造**：

1. **评估目的**：交易 / 抵押 / 出资（入股）/ 清算 / 财报目的 / 税基 / 司法 / 转让 / 租赁
2. **价值类型**：市场价值、投资价值、清算价值、在用价值、残余价值、公允价值（见 `references/value_types.md`）
3. **评估基准日**：明确到具体日期，所有参数均锚定该日
4. **评估对象与范围**：资产名称、数量、规格、权属状态、是否含负债
5. **委托人及使用人**：限定用途与责任边界

### Step 0.5 — 评估对象所处环节定位（前置闸门，不可跳过）

选方法之前先锁死**评估对象位于资产谱系的哪一层**，防口径错配导致方法、参数、区间三处连锁失真：

| 层 | 典型对象 | 方法取向 |
|---|---|---|
| ① 单项资产 | 单台设备、单套房产、单项专利 | 成本法 / 市场法为主 |
| ② 资产组 | 生产线、成套设备、资产组合 | 成本法 + 收益法 |
| ③ 企业价值 | 股权、整体资产 | 收益法 + 市场法（两种并用） |
| ④ 金融资产 | 股权、债券、基金份额 | 市场法为主，收益法为辅 |

**易混淆点防错（强制）**：若标的存在常见误称（如把"单项设备组"按"企业价值"口径测算），显式标注——「易混淆点：X 常被误按 Y 口径；本框架按 Z（第 N 层）口径，方法组合与参数均据此」。

**判定输入**：用户上传材料 + 资产清单/权属描述 + 可及研报与公告旁证；泛称与资产实质冲突时**以资产实质为准**。

### Step 1 — 资产分类与资料调查

| 资产大类 | 典型对象 | 首选方法组合 |
|---|---|---|
| 机器设备 | 生产线、车辆、电子设备 | 成本法为主，市场法为辅 |
| 房地产 | 住宅、厂房、商业地产 | 市场法 + 收益法（两种并用） |
| 无形资产 | 专利、商标、软著、商誉 | 收益法为主，成本法为辅 |
| 企业价值 | 股权、整体资产 | 收益法 + 市场法（两种并用） |
| 金融资产 | 股权、债券、基金份额 | 市场法为主，收益法为辅 |

资料来源：用户上传材料优先；可及研报、公告、行业公开信息作旁证。缺失项标注"需用户提供"，**不凭记忆填数、不补估数**。

### Step 2 — 评估方法适用性分析

适用与不适用条件见 `references/method_applicability.md`。决策规则：

- **成本法**：适用于可再生/可复制资产（设备、房地产、在建工程），需能可靠估算重置成本与贬值。
- **市场法**：适用于活跃交易市场、有可比案例（房地产、金融资产、二手设备），需 ≥3 个可比案例做因素修正。
- **收益法**：适用于有独立可预测收益流的资产（企业、无形资产、收益性房地产），需收益期、收益额、折现率可合理估算。

**交叉验证强制**：企业价值、房地产、无形资产原则上须采用两种以上方法；单一方法须说明理由。

### Step 3 — 参数估算与测算

- **成本法**：`评估值 = 重置成本 × 成新率 − 功能性贬值 − 经济性贬值`
  - 重置成本：现行购置价 + 运杂费 + 安装费，或重置核算法。
  - 成新率：年限法 `尚可使用年限/(已使用年限+尚可使用年限)`、工作量法、或观察打分法（实体/功能/经济损耗）。
- **市场法**：`比准价格 = 案例成交价 × 交易情况修正 × 交易日期修正 × 区域因素修正 × 个别因素修正`，多个比准价格取中位数或均值。
- **收益法**：`评估值 = Σ 预期收益_t / (1+折现率)^t + 终值折现`；折现率用 WACC 或行业风险收益率，收益期按法定寿命/经济寿命/合同期确定。
- 参数就近标注来源与基准日（`[用户提供]` / `[研报]` / `[公告]` / `[行情/财务]`），并做敏感性观察（折现率 ±1%、成新率 ±10% 等）。

### Step 4 — 交叉验证与评估结论（精度纪律，不可降级）

- **单一中性基准 + 窄幅区间**：先给一个中性基准值，区间 = 基准 ×(1±半宽)，半宽控制在 **±10%~22%**；禁用保守/中性/进取三档大跨度并列。
- **流动性折让**：二手设备、非上市股权、受限资产等流动性较弱者，作锚时须显式计入流动性折让（0.40–0.70）并说明依据。
- **剔除情绪与题材溢价**：不得以题材热度、市场情绪、政策预期单独上调估值；此类因素若影响参数，须给出数值与来源。
- **多方法差异**：各方法差异 > 20% 须说明原因（数据质量、假设差异、方法局限），不得强行平均。
- 结论须**可复算**（初始基准 × 系数；区间 = 基准 ×(1±半宽)，半宽来自敏感度档）。

### Step 5 — 输出（单份自包含 HTML）

按 `references/report_template.md` 的 HTML 结构输出，章节顺序：摘要（评估对象 / 目的 / 价值类型 / 基准日 / 方法 / 中性基准与区间 / 关键参数）→ 方法适用性 → 参数与测算 → 交叉验证与结论 → 特别事项与假设前提 → 文末声明。

### Step 6 — 特别事项与免责

- 列示特别事项（权属瑕疵、资料限制、期后事项、未决诉讼等）。
- 明确声明：本框架为分析参考，不替代注册资产评估师法定签字与法律责任；估值区间非交易保证；最终决策由具备资质的专业人士与委托人承担。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_资产评估分析.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
