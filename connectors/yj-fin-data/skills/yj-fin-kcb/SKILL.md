# 科创板可转债发行条件自查框架

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

## 一、定位与边界

面向上海证券交易所科创板上市公司的可转换公司债券发行条件自查框架。输入标的企业基本情况（板块、财务数据、公司治理、合规记录、募集资金用途、科创属性等），按现行法规条件逐条生成可对照的核对清单，引导用户自行比对，输出一份结构化的**自包含 HTML 自查报告**。

**重要边界**：本技能输出的是**条件自查框架与缺口提示，非法律意见、非监管认定、非发行审核承诺**。最终是否符合发行条件，以上海证券交易所审核问询、中国证监会注册结论为准。法规条文随时间修订，请用户以最新有效监管原文核验，本清单不保证现行有效。

## 二、何时触发

- 用户询问"这家科创板公司能不能发可转债 / 是否满足发行条件 / 帮我逐条对照发债资格 / 做一份可转债条件自查"；
- 用户描述标的企业情况并要求逐条对照可转债发行条件；
- 出现关键词：科创板、可转债、发行条件、再融资、证券发行注册管理办法、募集资金用途、科创属性、合规自查、负面清单、发行资格；
- 输入形态：① 用户上传标的基本情况、财报、公告、合规材料；② 用户仅以文字描述评估需求。

不适用于主板、创业板、北交所上市公司、非上市主体，以及其他融资品种（定增、配股、公司债）的资格评估。已明确不适用时主动提示本技能仅覆盖科创板可转债。

## 三、工作流（六步法）

### Step 0 — 标的所处板块与主体类型定位（前置闸门，不可跳过）

跑任何判定之前先锁死**标的适用于哪一监管板块与主体类型**，防把主板/创业板/北交所的门槛误加到科创板，导致条件错配、自查结论失真。

按监管领域映射四层定位（精神沿用价值链定位闸门，非照搬产业分层）：

| 层 | 典型主体 | 条件口径取向 |
|---|---|---|
| ① 科创板上市公司 | 上交所科创板代码 688 开头 | 不适用主板盈利/ROE 门槛；适用本办法统一条件 |
| ② 主板上市公司 | 上交所/深交所主板 | 向不特定对象发行须连续三年盈利且 ROE 均值不低于 6% |
| ③ 创业板/北交所上市公司 | 深交所创业板/北交所 | 各有独立再融资规则，不适用本办法科创板口径 |
| ④ 非上市主体 | 未上市企业 | 本技能不适用，无公开发行可转债资格 |

**易混淆点防错（强制）**：标的常被误称或跨板对比时，显式标注——「易混淆点：X 常被误按 Y（第 N 层）门槛；本框架按 Z（第 ① 层·科创板）口径，通用条件与板块差异项均据此」。尤其：主板"连续三年盈利 + ROE≥6%"**仅约束主板**，科创板不得误加此项。

**判定输入**：用户上传材料（板块、代码、上市地）+ 公告/招股书 + 可及研报旁证；泛称与上市实质冲突时**以披露文件中的板块与代码为准**。

### Step 0.5 — 主动交叉验证纪律（强制，不可降级）

对关键数字与合规事实（近三年可分配利润、资产负债率、现金流量、审计意见、行政处罚/公开谴责/立案调查记录、前次募资用途）一律做 **≥2 独立源交叉验证**：

- 优先源：上市公司公告/定期报告（权威，带披露日期快照）；
- 旁证源：可及研报、纪要、观点（`yj-fin-data（knowledge_search）` / `yj-fin-data（fetch_document）` / `yj-fin-data` 取数）；
- 用户材料：上传的报表/合规文件标 `[用户提供]`。

规则：

- 独立源之间不一致，显式标注差异（差异来源标签），不静默取其一；
- 任一维度缺口，写"受数据可得性限制，XX 待补充核验"，**绝不静默编造、绝不按金额倒推、绝不假设无违规无处罚**；
- 凡可公开复核的硬数字（可分配利润、审计意见、处罚文号），给时间快照与就近复核通道；
- 不使用"探活 / 未连通 / 故障 / 兜底 / 已降级"等故障词；缺口一律以自然措辞带过。

### Step 1 — 收集与整理标的资料

优先使用用户提供的标的基本情况；信息不足时，以用户上传材料与可及研报/公告旁证补充关键字段，并注明来源与日期。缺失字段标注"待核实"，不得默认填充、不用记忆补全。

### Step 2 — 逐条对照判定清单

读取 `references/regulations.md`，按其六大类清单逐项比对：

- A 通用条件（组织机构 / 可分配利润 / 资产负债与现金流）
- B 板块差异化（主板盈利/ROE 门槛不适用于科创板，不得误加）
- C 附加条件（分向不特定对象发行 C1、向特定对象发行 C2 两套负面清单）
- D 可转债专项禁止
- E 募集资金用途（含科创板须投向科技创新领域）
- F 科创属性披露与审核关注

每项给出"自查结果"三态之一：**满足 / 缺口 / 待核实**。存在"缺口"或"待核实"时，综合结论不得判为"整体满足"。

### Step 3 — 综合自查结论与缺口清单

- 综合自查结论三态：整体满足 / 存在缺口 / 信息不足（存在待核实项时）。
- 缺口清单：对"缺口"或"待核实"项给出可执行的补充材料方向或整改线索，不输出确定性监管结论。
- 风险桥接：每项"缺口/待核实"与综合结论之间用一句话连起来（如"可分配利润均值低于拟发行年利息额 → A2 缺口 → 综合结论为存在缺口"）。

### Step 4 — 输出（单份自包含 HTML）

按 `references/report_template.md` 的 HTML 结构输出，章节顺序：标的基本信息（板块定位已含）→ 逐条对照表 → 综合自查结论 → 缺口清单与整改方向 → 自查声明 → 文末固定声明。

### Step 5 — 特别事项与免责

- 列示特别事项（资料限制、期后事项、未决合规事项等）。
- 明确声明：本框架为条件自查参考，不构成法律意见、监管认定或发行审核承诺；最终以交易所审核问询与证监会注册结论为准。

## 四、数据来源与可达性
见 `references/data-sources.md`：工商/司法/涉诉等维度本技能不可达，缺口标“待补充核验”，绝不编造或假设无风险。

## 五、输出契约

- 交付物：**单份自包含 HTML**（SVG/纯 CSS 内联，不外链本地资源，双击可开），非 Markdown、非 Word、非 PDF。
- 布局：头部一句自查结论 + 标的信息（含板块定位）→ 逐条对照表（表格/要点为主）→ 缺口清单与整改方向 → 文末固定声明。
- 所有数字必须可溯源：就近标注来源类型与基准日；估算与假设单列并标明"假设"。
- 标题用自然成句名词，不写"主名（方法标签）"式自贴括号；方法论质量放正文句、表头列或表尾批注。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_科创板条件自查.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
