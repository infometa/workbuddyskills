# 去 AI 化 + 排版与成文纪律（hu-fin-kcb）

## 一、去 AI 化硬禁词（命中即改）

- **过程痕迹**：作为 AI 助手 / 根据公开信息 / 建议进一步核实 / 值得关注。
- **工具与系统内词**：skill 名、Reportlab、tyc、zerone、云极、Stage 0、定位闸门、markitdown、docx、xlsx、脚本名。
- **故障词**：未连通 / 故障 / 会话异常 / 兜底 / 已降级 / 探活 / 跑空。
- **内部指代**：朋友点名 / 核心痛点；与既往报告对照（"上一版误判"）一律不写。
- **数据缺失** → 自然措辞"受数据可得性限制，…待补充核验"，不写"故障 / 未连通 / 探活"。
- **禁自曝取数能力**：不写"本技能可调用 / 无公开机构库可调用 / 机构库 / 上下游三库 / 本技能某库不存在"。

## 二、标题禁"主名＋括号方法标签"

标题用自然成句名词，不写"主名（方法标签）"式自贴括号。方法论与质量要求放正文句、表头列或表尾批注。

- **可保留的括号**：仅客观归属型，如 `(A股)` `(科创板)` `(公司公告)`。
- **必删的括号**：分级处理 / 不进倍数 / 单中性 / 核查+依据+证据强度 / 口径治理 等自我方法说明。

## 三、排版与成文纪律（九项，交付前逐条过）

1. **列表项独立成行**：`①②③`／`1. 2. 3.` 等并列项不得用分号或全角空格串接在同一行，每项独立成行或成 bullet（防断号、防粘连）。
2. **一段一要点**：一个段落只承载一个核心观点；多个独立要点各自独立成段／bullet／单元格，禁止"一坨"长段；单元格内禁止用 `+` 串接多个长项。
3. **生成期整段重复自查**：同一内容只写一次；"缺口清单／整改方向"等收尾段严禁整段复制两遍，交付前通读查重。
4. **空格与分隔符**：中文并列项写 `A/B/C`、`A·B`（不带空格）；中文语境下 `→` `-` `+` `–` `—` 两侧不带空格（如 `科创板-非上市主体`、`3.2亿元→年利息额`）；纯英文 compound（`EV-Sales`、`2025-11`）保持原样。
5. **特殊 Unicode／装饰符**：优先用 ASCII（写 `10^-7` 而非 `10⁻⁷`、`<=` 而非 `≤`）；不用 `✓`/`✔` 等装饰符号，改用文字（「属实」「是」）。
6. **禁自创伪专业空壳名词**：凡"专业名＋调整／展宽／溢价／折损"结构，先给数值＋来源再命名；无数值支撑的一律改为「待量化，不计入」或直接删除。
7. **约量词不悬空**：「约／大约／左右／近乎」后必须紧跟具体数字（如「约 3.2 亿元」），禁止「可分配利润约—」这类残句。
8. **通篇中文**：正文与表格统一中文；英文术语（ROE、WACC、DCF 等）可保留但须置于中文语境，不得整句英文残留。
9. **无残留物**：不得出现占位符（`__`／`TBD`／裸「待补」）、半截自我修正残句；同一数字在不同位置口径一致；标题下必须有内容，不留孤立标题或空区块。

## 四、不适用清单（PDF 专属，勿迁移、勿回退）

- 分页／页码／页眉页脚（HTML 无页；且成稿闸门明令"无长页脚"）；
- 封面页：本报告不设封面，版式为「头部一句结论＋概览 → 各模块 → 缺口清单与结论 → 文末声明」；
- 多册分册（摘要／正文／附件分册）：输出归一为**单份 HTML**；
- reportlab／两端对齐 `TA_JUSTIFY`：HTML 无此概念，且属禁词；
- 反引号包裹中文 → ■：浏览器可正常回落渲染，非问题。

## 五、常见坑位（监管条件自查专属）

1. **监管硬结论越界**：不得输出"该公司符合/不符合科创板发行条件"等确定性监管认定；一律改写为"条件自查框架，非法律/监管意见"，综合结论为"整体满足/存在缺口/信息不足"三态自查结果。
2. **板块条件错配**：主板 ROE≥6%、连续三年盈利等门槛仅约束主板，科创板不得误加；跨板对比须显式标注适用层级。
3. **合规字段凭记忆填**：行政处罚、立案调查、公开谴责、控股股东犯罪记录等合规事实必须有来源与基准日，无来源则标"待补充核验"，绝不假设"无违规无处罚"。
4. **缺口静默跳过**：任一"缺口"或"待核实"项存在时，综合结论不得判为"整体满足"。
5. **把政策红利当能力**：科创板政策支持、再融资优化措施仅作程序性框架提示，不记为某公司"满足发行条件"的实质证据；经营与合规维度只靠自身证据判定。
6. **远期程序性参照给具体点位**：再融资间隔期、破发后融资路径只给"条件示意＋假设来源"，注明系程序性框架提示、非独立预测，不给可反推上沿的具体数。
