# 股权财务分析与估值复盘

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。
- **可比公司与行业背景分析由本技能基于 `yj-fin-data` 取数自行完成**：用 `securities_search` 定位可比上市公司 → `knowledge_search`/`fetch_document` 取研报与公告 → `financial_*`/`quote_*`/`valuation_analysis` 取财务行情估值，自行做一页通 / 同业对比 / 投资主线梳理。**不调用任何外部 agent 工具**；标的自身数据以用户上传为准，缺失即标"待补充核验"，绝不虚构。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

## 一、定位与边界

面向两类标的的标准化财务与估值分析：① 一级股权（PE/VC/Pre-IPO/未上市）读取尽调资料包；② 上市公司以用户上传财报 + 可及研报/公告/行情财务旁证为口径。两条轨共用同一套比率引擎（45+ 项比率、杜邦三因子、18 类风险扫描、六维加权评分）与分析框架。

**重要边界**：产出的是**分析复盘与参考**，非执业审计报告、非现场核查、不构成投资或交易建议。凡需法定效力的审计/评估结论，须由具备资质的机构与人士出具。

## 二、何时触发

- 用户需要股权财务分析、财务尽调（FDD）、盈利质量、跑道测算、EBITDA 调整桥、净债务桥、单位经济、稀释测算、可比公司或财务预测分析；
- 出现关键词：股权财务分析、一级市场财务尽调、PE 财务尽调、VC 尽调、Pre-IPO 财务分析、未上市公司财务分析、融资前财务核查、跑道测算、DD EBITDA、稀释测算、财务尽调、财务体检、盈利质量、杜邦分析、风险扫描、FDD、上市公司财务报告；
- 输入形态：① 用户上传尽调资料包（管理层报表/银行流水/融资历史/股权结构/单位经济）；② 用户上传上市公司财报与可及研报旁证；③ 用户仅以文字描述财务分析需求。

## 三、工作流（含定位闸门与估值精度纪律）

### Step 0 — 选轨判断

| 判定依据                                 | 走哪条轨                                 |
| ------------------------------------ | ------------------------------------ |
| 有营业执照、有融资历史，但无公开定期报告                 | 一级股权轨（P 轨）                           |
| 拿到管理层报表 / BP / 月度现金流 / 尽调资料包         | P 轨                                  |
| A 股 / 港股 / 美股上市公司，用户上传财报或提供代码 + 可及旁证 | 上市公司轨（L 轨）                           |
| Pre-IPO 阶段，已股改、有公开招股书                | 先 P 轨（回答"能不能买"），再做 L 轨式公开对比（回答"贵不贵"） |
| 用户明确"用一级市场口径"/"用上市公司口径"              | 以用户为准                                |

### Step 0.5 — 标的所处环节定位（前置闸门，不可跳过）

选方法、定市场空间、选可比公司之前先锁死**标的位于产业链哪一层**，防口径错配导致市场空间、可比公司、估值方法三处连锁失真：

| 层            | 典型对象         | 估值取向                      |
| ------------ | ------------ | ------------------------- |
| ① 芯片 / 核心元器件 | 半导体、IC、传感器芯片 | 高研发、PS/PB 为主，看国产替代与晶圆产能绑定 |
| ② 模组 / 组件    | 芯片 + 外围功能模组  | 成本传导与毛利率，看客户/产能绑定         |
| ③ 设备 / 终端    | 整机、仪器、终端产品   | 盈利质量 + EV/EBITDA，看产能利用率   |
| ④ 系统 / 方案    | 软硬一体解决方案     | 订单/订阅驱动，看单位经济与 NDR        |

**定位卡五字段（下游模块强制引用，缺任一项须补完）**：

- 精确子行业标签（禁写大类，须写到环节）
- 价值链位置（上游·中游·下游·系统）
- 市场数据口径（芯片级·模组级·设备级，明确用哪层）
- 可比公司对标层（同层对标，芯片对芯片）
- 估值方法指引（匹配该层的估值逻辑）

**易混淆点防错（强制）**：若标的存在常见误称（如把"模组厂商"按"整机厂"口径测算），显式标注「易混淆点：X 常被误称为 Y；本报告按 Z（第 N 层）口径，市场空间/可比公司/估值方法均据此」。

**判定输入**：用户上传材料 + 官网/BP 产品词 + 可及研报/公告旁证 + 行业标签；泛词与产品实质冲突时**以下游产品实质为准**。

### Step 1 — 资料完备度门槛（P 轨）

先问清楚三件事，拿不到就相应降级并在报告中标注：

1. 最近 3 年财报（审计年报 > 审阅 > 管理层报表）——缺它标注差距。
2. 最近 12 个月银行流水——唯一能独立验证收入真伪的外部凭证，拿不到本身就是重大红旗。
3. 股权结构表与历轮融资文件——没有则无法做稀释与优先清算分析。

L 轨以用户上传财报 + 可及旁证为口径；无上传财报时仅做框架性复盘，关键数值标注来源与时间点。

### Step 2 — 财务比率与杜邦/风险/评分（两轨共用）

按 `references/financial_ratios.md`（45+ 项比率、杜邦三因子、18 类风险扫描、六维加权评分）展开；行业差异化口径见 `references/industry_analysis.md`（10 大行业）；实地核查与舞弊识别清单见 `references/fieldwork_checklist.md`。

### Step 3 — 一级市场专项（P 轨独有）

按 `references/private_equity_fdd.md` 展开：报表可靠性评级（A/B/C/D）、收入 Run-rate 口径、现金消耗与 Runway、EBITDA 调整桥 + 净债务桥、单位经济、融资历史与稀释测算、隐含交易倍数、一级市场专项风险。

### Step 4 — 主动交叉验证纪律（不可降级，§0.1 ②）

- 对关键数字（收入、毛利率、乘数、估值倍数、跑道月数）须以 **≥2 个独立源**交叉验证；业务材料主张与独立源不一致处显式标注差异来源标签。
- 缺口一律写"受数据可得性限制，XX 待补充核验"，**绝不静默编造、绝不按金额倒推轮次、绝不编造股东名册**。
- 取数以用户上传材料 + 数据工具旁证（研报/纪要/公告/行情财务）为准；不可达维度（工商/司法/一级融资）照 `references/data-sources.md` 标"待补充核验"。
- **禁止**出现"探活 / 未连通 / 故障 / 兜底 / 已降级"等故障词。

### Step 5 — 估值与可比公司（精度纪律，§0.1 ③）

估值章节焊死以下规则，**放正文/表头，不写成对具体标的的买卖建议**：

- **单一中性基准 + 窄幅区间**：先给一个中性基准值，区间 = 基准 ×(1±半宽)，半宽控制在 **±10%~22%**；禁用保守/中性/进取三档大跨度并列。
- **流动性折让**：非上市股权、受限资产等流动性较弱者作锚时，须显式计入流动性折让（0.40–0.70）并说明依据。
- **剔除情绪与题材溢价**：不得以题材热度、市场情绪、政策预期单独上调估值；此类因素若影响参数，须给数值与来源。
- **收入三档情景化**：预测收入须给出保守/中性/进取三档情景，注明假设来源。
- 结论须**可复算**（初始基准 × 系数；区间 = 基准 ×(1±半宽)）。

### Step 6 — 输出（单份自包含 HTML）

按本文件 §五契约输出：头部一句结论 + 概览 → 各分析模块（表格/要点为主）→ 风险与结论 → 文末固定声明。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_财务与估值分析.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
