# 融资主体资信核验自查框架

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

## 一、定位与边界

在出资、放款、承销、认购等融资决策前，对融资主体做资信穿透核验，覆盖股权融资、银行借款、债券发行等场景。核心回答一个问题：**这家公司（这个人）值不值得签合同、给钱（股权或债权）**。

核验不产出"感觉"，只产出三件东西：**证据 + 定级 + 处置**。

**重要边界**：本技能输出的是**资信核验自查框架与结论参考，非法律意见、非司法认定、非监管判定**。工商登记、涉诉、失信、执行等维度本技能不可达，须以用户上传材料与可及官方披露为准，缺口如实标注"待补充核验"，绝不假设无诉讼、无失信、无冻结、无处罚。

## 二、何时触发

- 用户要核查一家融资主体（股权融资方/借款人/发债企业/合作方/供应商）靠不靠得住；
- 用户要查某主体是否失信被执行人、被限高、被吊销、进破产；
- 用户要做股权穿透找最终受益人、排查关联企业与互保联保；
- 用户要出一份资信核验底稿/报告，或把多个候选主体比选定级；
- 签约前、放款前、出资/认购前的背景核查与复检。

**不适用**（分别路由，不越界）：并购交易财务尽调、合同条款审查与法律意见书、工程造价与结算审核、诉讼应诉、项目合规手续与五证核查。

## 三、工作流（六步法）

### Step 0 — 主体类型与交易角色定位（前置闸门，不可跳过）

跑任何核验之前先锁死**被核验主体全称、统一社会信用代码与在本交易中的角色**（股权融资方 / 借款人 / 发债主体 / 合作方 / 供应商）。防把错误主体、错误角色代入核验，导致结论失真。

**易混淆点防错（强制）**：主体全称与信用代码须用户提供，不得以简称或商业平台显示名臆测；集团内多主体须显式区分被核验主体与关联方，不混同定级。

**判定输入**：用户上传营业执照、股权结构、合规材料；泛称与披露冲突时**以用户上传的权威材料为准**。

### Step 0.5 — 主动交叉验证纪律（强制，不可降级）

对关键事实（存续状态、注册资本、法定代表人、实控人、行政处罚、诉讼/执行/失信记录）一律做 **≥2 独立源交叉验证**：

- 优先源：用户上传材料（营业执照、裁定、处罚决定、公告）；
- 旁证源：可及研报、纪要、观点、公开披露（`yj-fin-data（knowledge_search）` / `yj-fin-data（fetch_document）` / `yj-fin-data` 取数）；
- 官方核验：公示系统、执行信息公开网、信用中国、裁判文书网等以用户上传或可及公开披露为准。

规则：

- 独立源不一致，显式标注差异，不静默取其一；
- 任一维度缺口，写"受数据可得性限制，XX 待补充核验"，**绝不静默编造、绝不假设无诉讼/无失信/无冻结、绝不按金额倒推**；
- 凡可公开复核的硬记录（案号、文号、处罚机关），给来源与日期；
- 不使用"探活 / 未连通 / 故障 / 兜底 / 已降级"等故障词；缺口一律以自然措辞带过。

### Step 1 — 任务界定与底稿生成

确认被核验主体全称、角色、交易概况、核验级别（L1–L4）、用途与交付时限；明确单主体核验还是多主体比选。用户未提供准确全称与统一社会信用代码时，先索要，不臆测主体。按 `references/screen-framework.md` 的十六项清单建作业台账，逐项留空待核。

### Step 2 — 五查十六项取证

把"查一个交易对手"拆成五组十六项，逐项取证、逐项留痕。**缺项即核验不合格，不得出具结论**。

| 查什么 | 项数 | 解决的问题 | 红线可能落点 |
|---|---|---|---|
| **查主体** | 3 项 | 它是谁？还在不在？谁说了算？ | 吊销/注销、频繁变更 |
| **查资格** | 3 项 | 有没有资格干这件事？干得动吗？ | 资质缺失/被吊销 |
| **查信用** | 4 项 | 有没有官司？欠不欠钱？被罚过没？ | **失信/限高/破产** |
| **查过往** | 3 项 | 以前干得怎么样？口碑如何？ | 欠薪/暴雷/烂尾 |
| **查关联** | 3 项 | 跟谁绑在一起？风险会不会传导？ | 关联方失信、互保联保 |

逐项"为什么查/查什么/到哪里查/留什么证据/常见坑"见 `references/screen-framework.md`。

### Step 3 — 三级结论与红线判定

| 结论 | 判定条件 | 后续动作 |
|---|---|---|
| **可合作** | 无红线命中；综合得分 ≥ 85 | 正常推进；合同保留资信复核条款与阶段性付款安排 |
| **谨慎** | 无红线命中；综合得分 60—84 | **可谈不可签**；落地前置条件与增信措施后复审 |
| **不合作** | 命中任一红线；或综合得分 < 60 | 中止推进；书面上报，已签约的评估止损 |

🔴 **红线一票否决**：命中任一红线信号（失信被执行人、限制高消费、吊销注销、严重违法失信、重大税收违法、破产受理、单位犯罪涉刑、非法集资等），结论一律为"不合作"，不受得分高低影响。红线判定以用户上传材料与可及官方披露为准，本技能不可独立核验工商/司法，缺失标"待补充核验"，不得以"利润高/关系硬/领导催/先干后补"为由降级。

### Step 4 — 分级响应 L1—L4

按"标的额、是否新交易对手、是否集团型主体、是否需上会"四项判定，取最高档：

1. **L1 快检**：小额、单一对手方、已有长期合作基础。跑官方三件（公示系统 + 执行信息公开网 + 信用中国），出核验简报。
2. **L2 标准核验**：常规合作、新对手方或中等标的额。五查十六项全跑，出标准核验报告（六章）。
3. **L3 深度穿透**：大额合作、垫资比例高、集团型主体。在 L2 基础上增加股权逐层穿透、集团内关联与担保链排查、财务与舆情穿透、实地踏勘，附核查底稿。
4. **L4 联合会商**：特大标的或需上投委会/风控会。风控+法务+财务+业务会商，出核验报告+专项法律意见+增信方案。

### Step 5 — 输出（单份自包含 HTML）

按 `references/report_template.md` 的六章骨架成文，交付资信核验报告与核查底稿（含全部检索留痕台账）。未核实项标 `【待核：具体说明】` 并高亮。

### Step 6 — 特别事项与免责

列示资料限制、期后事项、未决合规事项；明确声明本框架为资信核验自查参考，不构成法律意见、司法认定或监管判定。

## 四、数据来源与可达性
见 `references/data-sources.md`：工商/司法/涉诉等维度本技能不可达，缺口标“待补充核验”，绝不编造或假设无风险。

## 五、输出契约

- 交付物：**单份自包含 HTML**（SVG/纯 CSS 内联，不外链本地资源，双击可开），非 Markdown、非 Word、非 PDF。
- 布局：核验概况（含主体定位）→ 主体与资格 → 信用与涉诉 → 过往与口碑 → 关联与传导 → 核验结论与处置 → 附表（五查十六项表 + 检索留痕台账）。
- 所有事实必须可溯源：涉诉/执行/处罚记录须注明案号/文号 + 来源 + 日期，三项缺一即不合格。
- 标题用自然成句名词，不写"主名（方法标签）"式自贴括号。

## 七、边界限制（不做）

- 不做并购交易财务尽调、不做工商结构化数据直接查询替代、不做项目合规与五证核查、不做合同条款审查与法律意见书、不做造价与结算审核、不做诉讼应诉。
- 禁止编造或推测记录、案号、文号、处罚金额与日期；禁止用"据了解/听说/看到"代替可溯源取证。
- 禁止把商业平台的"暂无风险"当作官方无记录证明；禁止把"未检索到"写成"不存在"——须写明检索关键词与日期。
- 禁止采信舆情传闻作事实定级；禁止传播未经核实的负面信息。
- 用户未提供主体全称时先索要准确全称与统一社会信用代码，不臆测主体。
- 不越界替对手方判断其内部经营或预测其未来业绩；同一事实不混用多个口径而不加说明。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_资信核验报告.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
