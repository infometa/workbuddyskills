# 数据来源与可达性声明（融资主体资信核验）

取数以平台原生能力与用户上传材料为主。下列维度可达性须严格遵守，不可达维度一律标"待补充核验"，绝不静默编造或假设无风险。

## 二、不可达维度（如实标注，绝不假装查过）

| 编号 | 维度 | 说明与处置 |
|---|---|---|
| D6 | 工商登记全量（股权穿透、实控人、变更史、存续状态） | 不可达；以用户上传营业执照/股权结构为准，缺则标"待补充核验" |
| D7 | 司法冻结、裁判文书、执行案件、失信/限高 | 不可达；以用户上传裁定/合规声明为准，缺则标"待补充核验" |
| D8 | 一级市场融资史、机构库 | 不可达；以用户上传材料为准，缺则标"待补充核验" |
| D9 | 非上市公司未披露财务与履约记录 | 不可达；以用户上传材料为准，缺则标"待补充核验" |

## 三、铁律（不可降级）

1. 凡关键事实（存续、注册资本、法定代表人、实控人、处罚、诉讼/执行/失信）须 ≥2 独立源交叉验证，不一致显式标注差异。
2. 缺口一律写"受数据可得性限制，XX 待补充核验"，不得留空、不得凭记忆补全、不得按金额倒推。
3. 不使用"探活 / 未连通 / 故障 / 兜底 / 已降级"等故障词；缺口以自然措辞带过。
4. 工商/司法/执行/失信等不可达维度，绝不假设无诉讼、无失信、无冻结、无处罚；禁止把"未检索到"写成"不存在"。
5. 红线判定以用户上传材料与可及官方披露为准，缺失标"待补充核验"，不得因得分高而降级。
6. 用户上传材料优先，接入数据为旁证；二者冲突以披露文件为准。

## 四、用户材料优先原则

用户上传的营业执照、股权结构、合规材料、裁定、处罚决定、财报为权威输入，优先于接入数据旁证；接入数据用于交叉验证与补充，缺失时以用户材料为准并标注。
