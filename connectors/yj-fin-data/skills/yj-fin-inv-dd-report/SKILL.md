# 投行尽调报告方法论（单份 HTML 结构化交付）

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。
- **可比公司与行业背景分析由本技能基于 `yj-fin-data` 取数自行完成**：用 `securities_search` 定位可比上市公司 → `knowledge_search`/`fetch_document` 取研报与公告 → `financial_*`/`quote_*`/`valuation_analysis` 取财务行情估值，自行做一页通 / 同业对比 / 投资主线梳理。**不调用任何外部 agent 工具**；标的自身数据以用户上传为准，缺失即标"待补充核验"，绝不虚构。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

面向股权融资（IPO/再融资/北交所上市）及上市公司并购重组（重大资产重组/发行股份购买资产/重组上市）独立财务顾问尽职调查的方法论助手。输入业务类型与项目材料，按核查模块拆解，最终交付一份自包含 HTML 尽调方法论文档。

> 工商登记、司法、实时法规库等本技能不提供的维度，为默认已知限制——凡涉此类维度以材料与可及旁证为准，缺的如实写"待补充核验"，不探活、不跑空、不静默编造。规则引用一律作为方法论参考框架，请以最新监管原文为准自行核验。

## 一、定位与边界

按投行股权类与并购重组独立财务顾问尽调的方法论口径，把"核查什么、怎么核查、底稿怎么留痕、对外怎么脱敏"讲清楚、落地成可执行的提纲、清单与模板。

**重要边界**：产出的是方法论框架与核查口径参考，不替代保荐代表人、独立财务顾问主办人及质控合规的签字判断，不构成对"是否符合发行条件/重组条件"的监管硬结论（符合/不符合）。凡涉及"是否构成某禁止情形"的解释论判断，须标注"系解释论判断，非明文豁免，须专项论证"。

## 二、何时触发

- 用户需要编制投行股权类或并购重组类尽调核查方案、底稿框架、脱敏规范或论证结构；
- 出现关键词：尽调、尽职调查、核查、底稿、工作底稿、脱敏、问询回复、独立财务顾问、IPO 尽调、再融资核查、重大资产重组核查、发行股份购买资产、重组上市、业绩补偿、定价公允；
- 输入形态：① 用户上传招股书草稿、底稿目录、核查清单、问询回复骨架、合同清单；② 用户仅以文字描述项目背景与核查需求。

仅给"帮我写份尽调报告"未明业务类型与板块时，主动问清业务类型、板块与行业再推进。

## 三、工作流（六步法）

### Step 0 — 标的所处环节定位（前置闸门，不可跳过）

设计核查模块前先锁死标的在产业链与业务版图中的位置，防把上游器件/模组公司误写成下游整机/方案公司，导致可比公司、市场规模口径、核查重点三处连锁失真。

| 层 | 典型对象 | 核查取向 |
|---|---|---|
| ① 芯片/核心元器件 | 半导体、IC、传感器芯片、核心材料 | 重技术先进性、量产能力、上游依赖核查 |
| ② 模组/组件 | 芯片+外围功能模组、关键部件 | 重供应链、良率、客户认证核查 |
| ③ 设备/终端 | 整机、仪器、终端产品 | 重产线、收入真实性、渠道核查 |
| ④ 系统/方案 | 软硬一体解决方案、平台 | 重商业模式、交付能力、持续性核查 |

**定位卡五字段（下游模块强制引用，缺任一项须补完）**：精确子行业标签（禁写大类，须写到环节）/ 价值链位置（上游·中游·下游·系统）/ 市场数据口径（芯片级·模组级·设备级，明确用哪层）/ 可比公司对标层（同层对标，芯片对芯片）/ 估值方法指引（匹配该层的估值逻辑）。

**易混淆点防错（强制）**：若标的存在常见误称，显式标注——「易混淆点：X 常被误称为 Y；本报告按 Z（第 N 层）口径，可比公司、市场规模与核查重点均据此」。

**判定输入**：用户上传材料 + 官网/BP 产品词 + 可及研报/公告 + 行业标签；不依赖外部工商或一级融资库。泛称与产品实质冲突时以下游产品实质为准。

### Step 1 — 界定范围

明确业务类型（IPO/再融资/北交所 或 重大资产重组/发行股份购买资产/重组上市）、板块与行业，确定适用的核查模块与抽样标准；重组类先判断是否构成重组上市或适用简易程序/小额快速；再融资须明确品种。

### Step 2 — 设计核查程序

针对每个二级目录列出可执行的访谈/函证/走访/穿行/细节测试/资金流水核查程序及样本量标准；财务类程序按"科目余额表→序时账/明细账"拆解路径设计。模块核查口径见「各专业模块核查要点」。

### Step 3 — 执行与留痕提示

提示项目组取得盖章文件、回函快递单、盘点记录、流水等佐证；说明选取方法与过程；财务核查须同步取得业务侧证据（订单、合同、物流、验收）以印证；买方/卖方并购须按差异维度分别设计核查重点。

### Step 4 — 形成分析论证

按"核查事项—程序—过程—问题—结论—复核"产出，结论与披露文件一致，差异事项单独说明；对发现的每个问题均须给出解决方案，并区分"可会计调整更正"与"需整改/规范/论证消除的实质性障碍"两类。

### Step 5 — 底稿编制与脱敏

产出访谈提纲、询证函、流水核查表、控制表等模板（主体 `XXXX` 占位）；标注仍需补充的核查证据；按工作底稿分类归档。发行人、客户、供应商、自然人等敏感主体默认 `XXXX` 占位，输出不含可识别来源券商的内部标识。

### Step 6 — 输出（单份自包含 HTML）

交付一份自包含 HTML 尽调方法论文档，章节顺序见 §六。

## 四、交叉验证与数据纪律（主动交叉验证，不可降级）

- **关键数字 ≥2 独立源交叉验证**：业务材料主张（[项目方材料]）与独立源（[研报]/[公告]/[行情/财务]）不一致处，显式标注差异来源，不静默取其一。
- **缺口"待补充核验"**：凡工商股权、诉讼冻结、最新法规条文、未提供财务等拿不到可靠来源时，在对应处写"受数据可得性限制，XX 待补充核验"；绝不假设无诉讼/无冻结、绝不按金额倒推轮次、绝不编造持股比例与处罚结论。
- **绝不静默编造**：无可靠来源的数字一律标"待补充核验"或量级表述，不以"行业一般""通常"等模糊措辞掩盖未核验事实。
- **取数纪律**：用 kb/file/data 做主动交叉验证；缺口只用自然措辞带过，不使用"探活/未连通/故障/兜底/已降级"等故障词，不点任何内部取数通道或库名。

## 五、各专业模块核查要点（内置口径）

- **一般操作要求**：底稿资料完整、来源可靠、标识统一；不适用的目录章节须注明"不适用"及原因，不得删除目录；每个二级目录形成分析论证，经保荐代表人与质控专员复核签字。
- **客户与供应商**：报告期各期主要客户/供应商须实施访谈与函证，至少覆盖各期前十大及新增前五大；经销收入或毛利占比超 30% 的，额外覆盖各期前十大经销客户及新增前五大；函证回函须直接寄回项目组办公场所。
- **重大合同**：核查对发行人有重大影响的合同，近三年占净资产 10% 以上的采购/销售/合作/特许经营合同应纳入清单并抽查。
- **货币资金**：独立获取银行账户清单；独立取得报告期所有账户资金流水，发现与控股股东/实控人/董监高异常往来须补充核查其流水。
- **同业竞争**：结合产品/技术/客户/供应商/渠道重叠度，论证是否构成重大不利影响的同业竞争。
- **关联方与关联交易**：比照企业会计准则第 36 号及上市规则识别关联方，核查关联交易定价公允性、必要性、审批程序与披露完整性（关联交易对应收入/成本费用/利润总额占比达 30% 须充分说明并披露减少措施）。
- **销售与收款**：执行穿行、截止、细节测试，细节测试须覆盖主要客户并核查至收款（含票据）；收入确认对照企会第 14 号判断控制权转移时点。
- **采购与付款、成本与存货**：存货至少监盘报告期最后一期期末；成本波动须与产量、料工费、业务排产相互印证。
- **长期资产**：核查权属、转固时点、折旧摊销、减值迹象；土地使用权/房屋建筑物核查权属证书与抵押查封。
- **期间费用**：核查研发活动与研发费用归集、资本化起点；对比费用率与同行业差异。

## 六、数据来源与输出契约

**数据来源可达性**见 `references/data-sources.md`：可用维度（研报/纪要/观点/公告/行情财务）正常用并就近标注；不可达维度（工商登记、司法冻结、实时法规、公网检索）如实标注"受数据可得性限制，XX 待补充核验"，绝不假设无诉讼/无冻结、绝不按金额倒推、绝不编造。

**输出契约**：
- 交付物：单份自包含 HTML（SVG/纯 CSS 内联，不外链本地资源，双击可开），非 Markdown、非 Word、非 PDF。
- 布局：头部一句范围界定与风险总览 → 各核查模块（表格/要点为主）→ 工作底稿与脱敏规范 → 风险分级与结论 → 文末固定声明。
- 所有数字必须可溯源：就近标注来源类型与基准日；估算与假设单列并标明"假设/未经审计"。

## 八、边界限制（不做）

- 不替代保荐代表人、独立财务顾问主办人及质控合规的签字判断；不输出"符合/不符合发行条件"的监管硬结论。
- 不提供投资人推荐、FA 对接、银行谈判、中介组织、监管资格硬结论等对外责任动作；结论性质为核查框架与条件自查参考。
- 不虚构股权结构、诉讼状态、财务数据；缺失标注"未提供/待补充核验"。
- 规则引用均标"基线提示，请以最新监管原文核验，不保证现行有效"，不做"已逐条核验现行有效"的绝对承诺。

## 九、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_尽调报告方法论.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
