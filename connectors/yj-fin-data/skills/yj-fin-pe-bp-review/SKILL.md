# 商业计划书评审与投前辅导

## 〇、原生取数入口

本技能优先调用以下已注册原生工具取数，并按来源标签就近标注：

- `yj-fin-data（knowledge_search）`：研报 / 观点 / 纪要 / 内部报告（向量检索，取论点与结论片段）——行业背景、可比研究、监管动态旁证。
- `yj-fin-data`：A/港/美股日K、财务三大表、估值分位、题材指数与成分股——可比上市公司财务与估值倍数、交易价格。
- `yj-fin-data（fetch_document）`：读取 / 解析用户上传及数据文件（BP/工商/财报/合同），核心依据以用户上传为准，标 `[用户提供]`。
- **可比公司与行业背景分析由本技能基于 `yj-fin-data` 取数自行完成**：用 `securities_search` 定位可比上市公司 → `knowledge_search`/`fetch_document` 取研报与公告 → `financial_*`/`quote_*`/`valuation_analysis` 取财务行情估值，自行做一页通 / 同业对比 / 投资主线梳理。**不调用任何外部 agent 工具**；标的自身数据以用户上传为准，缺失即标"待补充核验"，绝不虚构。

不可达维度（工商 / 司法冻结 / 一级融资 / 非上市财务 / 公网检索）本技能无专库，照 `references/data-sources.md` 标"待补充核验"，绝不编造。

取数铁律：① 先 `securities_search` 解析带交易所后缀的标准代码，再调对应工具；② 研报 / 纪要 / 观点 / 公告一律经 `knowledge_search` / `fetch_document` / `meeting_summary_list` / `domestic_chief_opinion_list` / `management_discussion` / `qa_list` 实取，不得凭记忆填空；③ 遇 `UNAUTHORIZED`（云极账号未授权）即停，引导用户在连接器里完成授权，绝不编造数据。

## 一、定位与边界

面向一级市场（以种子轮到 A 轮为主）的标准化 BP 评审与投前辅导。输入一份 BP、pitch deck 或项目大纲，从投资人/评委视角做**六维度结构化评分、行业差异化适配、关键问题清单与 30/90 天行动建议**，并保留三项分析方法论（实体价值链定位闸门、主动交叉验证、估值精度纪律）。

**重要边界**：产出的是**方法论文档参考与评审框架，非执业尽调报告，不构成任何投资建议**。凡涉及投资人推荐、FA 对接、银行谈判、中介组织、监管资格硬结论等对外责任动作，本技能一律不做，结论性质为"复盘与参考"。

## 二、何时触发

- 用户需要 BP 评审、打分、改 BP、模拟投资人/评委提问、按行业要点优化 BP；
- 出现关键词：BP、商业计划书、pitch deck、项目大纲、路演、答辩、投资人视角、评委提问、六维评分、投前辅导、12 章法重构；
- 输入形态：① 用户上传 PDF/PPT/Word/文字大纲；② 用户仅以文字描述项目。

仅给项目名或一句话且未提供任何 BP 内容时，先确认是否要做 BP 评审，并请补充关键章节，不臆造内容。

## 三、工作流（六步法）

### Step 0 — 标的所处环节定位（不可跳过）

评分前先锁死**标的在产业价值链的哪一层**，防把上游芯片/模组公司误写成下游设备公司，导致市场规模（TAM）、可比公司、融资合理性三处连锁失真。

| 层 | 典型对象 | 方法取向 |
|---|---|---|
| ① 芯片/核心元器件 | 半导体、IC、传感器芯片 | 芯片级口径，对标同层芯片公司 |
| ② 模组/组件 | 芯片+外围功能模组 | 模组级口径，看集成度与良率 |
| ③ 设备/终端 | 整机、仪器、终端产品 | 设备级口径，看整机出货与份额 |
| ④ 系统/方案 | 软硬一体解决方案 | 系统级口径，看总包与运维 |

**定位卡五字段（缺任一项须补完）**：

- 精确子行业标签（禁写大类，须写到环节，如"AI 推理芯片"而非"半导体"）
- 价值链位置（上游·中游·下游·系统）
- 市场数据口径（芯片级·模组级·设备级，明确用哪层）
- 可比公司对标层（同层对标，芯片对芯片、设备对设备）
- 估值方法指引（匹配该层的估值逻辑，用于融资合理性评审）

**易混淆点防错（强制）**：若标的存在常见误称，显式标注——「易混淆点：X 常被误称为 Y；本报告按 Z（第 N 层）口径，市场规模/可比公司/融资合理性均据此」。

**判定输入**：用户上传材料 + 官网/BP 产品词 + 可及研报/公告 + 行业标签；泛词与产品实质冲突时**以下游产品实质为准**；不依赖任何本机工商/一级融资库。

### Step 1 — 项目画像与双输入识别

1. **项目画像表**：项目名称、所属行业、当前轮次、创业者目标类型、目标评审方、BP 完整度、篇幅与版式。
2. **双输入驱动**：识别创业者目标类型（资本驱动/技术转化/稳健经营/产业合作/社会影响/人才创业）与评审方类型（投资机构/大赛评委/园区招商/孵化器/产业方/成果转化专家），据此确定评分与推演的优先级权重。
3. **BP 结构体检**：对照 12 章标准叙事模板（执行摘要、公司概述、行业与市场、问题与解决方案、产品与技术、商业模式、竞争分析、市场策略、运营与团队、财务数据与预测、融资计划、风险与应对）与黄金叙事线（我是谁→为什么做→怎么做→做得怎么样→未来怎么做→需要什么），标注缺失章节。

### Step 2 — 六维度评分卡

按总权重 100% 对每维度独立评分（0–100），每条评分须有 BP 具体引用；总分落到 A/B/C/D 四档（A 85+ / B 70–84 / C 55–69 / D <55）。

| 维度 | 权重 | 核心子指标 |
|------|------|-----------|
| 结构完整性 | 15% | 12 章覆盖率、章节命名规范、目录可视化 |
| 数据可信度 | 20% | 市场规模来源、测算逻辑、技术指标实测、财务真实性 |
| 商业可行性 | 25% | 商业模式清晰度、收入来源、单位经济模型、盈利路径 |
| 竞争壁垒 | 20% | 技术壁垒、专利与 IP、网络效应、规模效应、替代品 |
| 团队实力 | 15% | 创始人资历、成员互补、学术产业双标签、股权合理性 |
| 融资合理性 | 5% | 估值依据、资金用途、里程碑匹配、退出路径 |

行业差异化权重见下表（在维度总分基础上做 ±N 调整，调整须显式说明）：

| 行业 | 加权项 | 重点关注子项 |
|------|--------|---------------|
| AI / 人工智能 | 数据可信度 +30%，结构 -10% | 算法性能对比、模型参数、客户案例、收入验证 |
| 医疗健康 | 竞争壁垒 +25%，商业可行性 +15% | 临床数据、注册证时间线、支付端分析 |
| 航空航天 / 低空 | 结构 +20%，商业可行性 +20% | 适航认证路径、空域申请、签约合同、基地布局 |
| 新能源 / 硬科技 | 竞争壁垒 +25%，数据可信度 +15% | TRL、产线经济分析、碳排放数据 |
| 消费 / 食品 | 商业可行性 +35%，结构 +10% | 单店盈利模型、品类毛利率、复购率、供应链利润 |
| B2B SaaS | 数据可信度 +30%，商业可行性 +20% | MRR/ARR、留存率、CAC、LTV/CAC |
| 半导体 / 芯片 | 竞争壁垒 +30%，团队 +15% | 工艺节点、量产能力、专利布局 |
| 文娱 / 内容 | 商业可行性 +25%，结构 +15% | 用户增长曲线、内容生产机制、版权布局 |

### Step 3 — 行业差异化适配

识别 BP 所属行业大类（8 类），抽取行业特有展示要素是否齐备，输出行业特定强化建议（医疗的注册证 / AI 的客户案例 / 消费的单店模型 / 航天的签约合同）。以研报/纪要/公告为独立源交叉，**严禁整段只引 BP 叙事**。

### Step 4 — 关键问题清单与主动交叉验证

按 P0/P1/P2 排序，每条含严重度、问题描述、影响维度、改进方向。主动对照失败模式黑名单（无真实需求 / 现金跑道 / 团队不匹配 / 被竞争击败 / 定价成本 / 产品体验 / 商业模式不清 / 营销失效 / 时机错位 / 团队冲突）识别高风险信号。

**主动交叉验证纪律（强制）**：对关键数字（市场规模、增速、财务、技术指标）用 ≥2 个独立源交叉验证；BP 主张与研报/公告/行情等独立源不一致处，**显式标注差异来源**，不静默取其一。缺口"待补充核验"，**绝不静默编造、绝不按金额倒推轮次**。验证以  原生研报/纪要/公告/行情财务（`yj-fin-data（knowledge_search）`/`yj-fin-data（fetch_document）`/`yj-fin-data`）与用户上传材料为主；缺失维度只写"受数据可得性限制，XX 待补充核验"，不出现探活/未连通/故障/兜底/已降级等故障词。

### Step 5 — 投资人/评委视角推演（如指定评审方）

根据用户指定评审方调用对应视角，模拟 5–8 个该视角会问的关键问题，评估强弱项，给出视角切换补强建议：

- 综合型成长期机构：商业本质 + 市场规模 + 团队执行力
- 早期信号型机构：创始人特质 + 早期验证信号（Pre-revenue 尤甚）
- 长线价值型机构：长线价值 + 行业深度（B 轮及以后、消费医疗）
- 技术驱动型机构：技术驱动力 + 商业模式匹配度（AI 硬科技）
- 全球化创业加速器：增长信号 + PMF 早期证据
- 创业大赛评委：创新性 + 落地理由 + 团队
- 园区招商视角：招商引资 + 区域产业匹配度
- 成果转化专家：技术成熟度（TRL）+ 产业化路径

### Step 6 — 行动清单与融资合理性评审纪律

1. **行动清单**：按优先级排出 30 天 / 90 天可执行行动，每条含目标、负责人、产出物、验收标准（30 天解决 P0，90 天做结构性优化与数据补强）。
2. **重写建议**（如用户要求）：按 12 章法给章节级大纲——每章核心主张、必备数据点、推荐图表、篇幅（投资人版 18–25 页，大赛路演版 12–15 页）。

**估值精度纪律（融资合理性评审口径，强制）**：当 BP 提出估值、轮次或融资额主张时，按以下方法论评审其合理性，而非替用户建模：

- **单一中性基准 + 窄幅区间**：先给一个中性基准值，区间 = 基准 ×(1±半宽)，半宽控制在 **±10%~22%**；禁用保守/中性/进取三档大跨度并列。
- **流动性折让**：非上市股权、受限资产等流动性较弱者，作锚时须显式计入流动性折让（0.40–0.70）并说明依据。
- **剔除情绪与题材溢价**：不得以题材热度、市场情绪、政策预期单独上调估值；此类因素若影响参数，须给出数值与来源。
- **收入三档情景化**：营收预测须给保守/中性/进取三档情景，而非单一乐观线。
- 本纪律是**评审方法论规则**，不输出为对具体标的的买入/卖出建议；与文末"不构成任何投资建议"声明一致。

### Step 7 — 输出（单份自包含 HTML）

按本技能"输出契约"交付：单份自包含 HTML 评审报告（文件名 `{项目}_BP评审.html`），章节顺序为头部一句总体判断 → 项目画像 → 六维度评分卡 → 行业适配 → 关键问题清单 → 投资人视角推演（如适用）→ 行动清单与重写建议 → 文末固定声明。

## 七、边界限制（不做）

- 不输出投资人推荐、FA 对接、银行谈判、中介组织、监管资格硬结论等对外责任动作；结论性质为复盘与参考。

## 八、生成流程（脚本）

本技能的结构化分析经脚本组装为**单份自包含 HTML 报告**（内联图表引擎，离线可打开、双击即用）：

1. 取数 + 用户材料 + 外部核验结论 → 组装报告输入 JSON：`company`（标的/主体名）、`ic_conclusion`（头部一句结论）、`kpi`（概览指标卡）、`sections`（各章节的 `blocks`）、`charts`（图表数据）。
2. `python3 scripts/generate_report.py --data <input.json> --output-dir <dir>` 生成单文件 HTML（文件名 `{主体}_BP评审.html`）。
3. 成稿后对照 `references/output-and-pitfalls.md` 逐条核查排版与成文纪律（表格列纪律、禁自曝取数能力、来源就近标注）。

> 渲染器与本技能自包含：图表引擎 `scripts/assets/echarts.min.js` 随包分发、由脚本**内联**进产物，报告运行时零外部请求。
