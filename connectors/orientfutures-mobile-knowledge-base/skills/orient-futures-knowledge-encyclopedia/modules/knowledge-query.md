# 前置合规门

先执行 [回答与合规边界](answer-and-boundaries.md)。以下章节提示只用于定位定义、变量、条件和一般机制，不授权行情分析方法、实盘分类、交易操作或排除业务办理。纯查数/纯研判不为教学而检索。

# 期货知识查询策略

本模块规定如何使用知识 MCP 定位章节、读取正文、判断时效并回答投教问题。工具签名见 `../references/api-spec.md`。

## 1. 识别知识任务

保证金/手续费先执行 [三层口径](fees-and-margin.md)：一般概念在这里解释并附相关公司入口，实际合约码表保证金走合约分支；计算和明确个人标准转开户助手。普通问题不自动扩展为个人咨询；公司公示只展示链接，不读取页面。

将问题拆成一种或多种知识目标：

- 定义或术语；
- 比较或易混概念；
- 原理、机制或市场作用；
- 制度、流程或参与者职责；
- 公式、变量或案例演算；
- 行情字段、图表元素与术语定义；
- 风险、监管和风险控制。

同时识别是否混入动态行情、当前精确规则、具体合约参数、公司业务、个人账户、预测或建议。这些内容不能用通用知识正文替代。

先于知识章节定位识别实际参与交易意图：

- “怎么交易期货”“期货怎么交易”“怎么开始做期货”“怎么买卖期货”等未说明已有账户的独立问题，默认转 `orient-futures-account-opening-assistant`，不只做通用流程科普，也不先追问是否已经开户。
- 当前对话已明确讨论期货时，“怎么交易、怎么买、怎么卖、我想交易、第一步呢”等省略“期货”的承接式表达沿用期货上下文并转开户助手；上下文不是期货时不得抢占其他产品的交易问题。
- “想做期货、准备交易、想买/卖期货、怎么/在哪里下单、准备开仓、在哪里交易、用什么平台开户、第一步做什么”等属于强参与信号，同样转开户助手；“下单是什么意思、开仓和平仓有什么区别”等定义问题仍进入知识分支。
- 只有用户明确询问开仓、平仓、保证金、多空、竞价、结算等术语或机制，且没有开始参与的行动表达时，才进入本知识分支。
- 用户明确已有账户或已经提交开户申请时，保留其存量业务上下文，不要求再次预开户。基金、资管、特殊品种权限办理与所有非个人账户业务先转开户助手执行排除门，不检索通用流程绕过。

通用概念通常不需要品种或日期。只有缺少的变量会改变公式结果，或同一术语存在会产生不同答案的含义时才追问。

### 解释深度

仅按当前问题和用户明确理解调整长短；不因一个专业词判定水平、不强制追问、不追加学习路径。需要例子时仅采用正文原例或用户明确假设，不获取实盘示例、不让用户猜行情或选动作。

## 2. 书目与目录

1. 调用 `knowledge_base_list_books`。
2. 从真实响应中按主题选择知识集合：通用期货知识使用“期货及衍生品基础”；MACD、RSI、KDJ、BOLL、移动平均等技术分析体系优先使用本次真实返回的 `technical-analysis-financial-markets` / 技术分析知识集合。已知键只能用于匹配，不得跳过书目发现。
3. 调用 `knowledge_base_get_book_toc`。首次定位可以省略 `root`；需要下钻时只使用本次目录返回的 `key`。
4. 按问题中的主题、同义词、缩写和上下文匹配标题。知识 MCP 没有关键词搜索工具，不得虚构搜索接口。
5. 优先选择能完整回答问题的最窄叶子章节；整体介绍或多个紧密子主题才选择上级章节。

目录节点中的 `selfSizeBytes`、`subtreeSizeBytes` 和 `childCount` 用于控制读取粒度。章节路由表只提供定位提示，最终必须以本次目录真实结果为准。

期权及独立远期/互换知识排除，不因目录有第 9～11 章就读取；期货与远期比较仅取直接相关定义。

## 4. 正文读取

调用 `knowledge_base_get_section_content`：

- `section` 必须作为字符串逐字复用目录返回的 `key`，保留前导零和 `/`，不得把 `"003"` 改成 `3` 或 `"3"`；
- 单一叶子概念默认 `view="self"`；
- 小节及其完整分类、比较或案例使用 `view="subtree"`；
- `max_bytes` 结合目录大小设置，范围 1000～200000；
- 正文工具没有 `depth`，不得传入；
- 一个问题涉及多个独立概念时可以读取多个窄章节，不为减少调用而加载无关大章节；
- 比较问题必须读取比较双方的必要正文；
- 公式和案例必须读到变量、前提、方向、单位和计算步骤，不能只凭章节标题回答。

检查 `book`、`section`、`titlePath`、`view`、`oversized` 和 `markdown`。书名、章节或主题不一致时丢弃响应并回到目录重新定位。

### `oversized=true`

1. 不把正文缺失解释为无知识。
2. 优先根据 `children`、`hint` 和目录标题下钻。
3. 只需要当前章节本身时改用 `view="self"`。
4. 只有问题确实需要完整子树时才调大 `max_bytes`，最多调大一次且不超过 200000。

## 5. 知识时效判断

把正文内容分成四类：

- **稳定通用知识**：概念、机制、分类、通用公式和历史性说明，仅在回答模块白名单内组织解释。
- **制度性知识**：可以解释一般制度含义和机制，不能自动表述为当前有效规则。
- **具体品种、机构、合约参数或市场概况**：只能作为背景或历史示例；“现在、最新、目前、今天”需要其他现行数据源。
- **操作、套保、套利或投机案例**：只提取独立定义、公式变量与假设，不复述交易步骤、市场判断、收益评价或具体操作建议。

监管主体职责和制度安排也可能变化。用户询问当前法律效力、最新规定或具体合规结论时，转现行权威规则能力。

## 6. 公式与案例

1. 公式、变量、方向、单位、假设和适用条件必须来自相关正文。
2. 缺少会改变结果的参数时先给公式和缺失项，不猜价格、合约乘数、利率、汇率、β、久期或保证金率。
3. 知识 MCP 没有计算工具。只使用运行环境真实可用的确定性计算能力；没有时保留公式和可人工核对的代入过程，不虚构 MCP 计算服务。
4. 区分正文原始示例和基于用户明确假设的纯公式演算；不得自行编数或使用实际行情作为交易例证。
5. 历史示例不能写成当前市场值、当前合约参数或东证期货客户标准。

## 7. 异常处理

- 书目列表失败：原参数重试一次，仍失败则停止知识分支。
- 目标书目未返回：不用相似书名或模型记忆代替。
- 目录无匹配：说明当前无法可靠回答该主题，不从相邻标题拼凑。
- 多个知识主题会导致不同答案：用自然语言说明可能含义并确认，不展示内部章节号。
- 正文为空：先区分章节自身无正文和子树过大，必要时读取子章节。
- 正文与问题不匹配：丢弃并重新定位。
- 用户要求当前规则或数据：完成可独立回答的一般知识，再转相邻权威能力。

## 8. 内部核验

内部保留本次使用的 `book_key`、`section` 和 `titlePath`。这些字段仅用于核验，不进入普通用户答案。
