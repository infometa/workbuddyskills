# 合规前置

先执行 [回答与合规边界](answer-and-boundaries.md)。本模块只核验静态字段，不产生合约优劣、适用人群、交易价值或当前状态研判；单一实际合约资料与通用定义可并列，不能转化为操作建议。

# 单一实际期货合约查询策略

本模块规定如何通过行情 MCP 搜索、消歧并查询一个实际期货合约的码表静态资料。工具签名见 `../references/api-spec.md`。

## 1. 能力边界

本分支回答：

- 一个完整代码对应什么合约；
- 合约名称、国内或境外市场、交易所、所属品种和对象类型；
- MCP 本次实际返回且语义明确的其他静态码表信息。

本分支不处理：

- 只有品种名但未指定月份的模糊对象；
- 多个合约、全部挂牌合约、当前主力实际合约；
- 主连、指数或其他连续序列；
- 最新价、涨跌、盘口、成交量、持仓量、分时或 K 线；
- 公司/个人实际保证金或手续费及码表不能核验的现行规则；本轮实际返回的合约码表多空保证金率与保证金算法属于本分支，不得一律排除。

用户提出越界对象时保留其真实意图并转相邻能力，不把它改写成任意实际合约。

## 2. 提取对象

从当前问题和上下文提取：

- 原始代码或名称；
- 国内或境外期货市场线索；
- 用户需要的字段，或“全部可用静态信息”；
- 是否同时要求字段解释、动态行情或当前规则。

完整实际合约代码已经明确时不重复追问。只有品种名、月份缺失、简称多义或对象可能是主力/主连时，确认会改变结果的部分。

## 3. 搜索与消歧

1. 调用 `futures_search_instruments`。
2. 市场明确时只查该市场；未明确时可以查询允许的期货市场。
3. 明确查询实际合约时传 `future_types=["normal"]`。
4. 用本次响应的代码、名称、市场、交易所和对象类型核对用户意图。
5. 候选唯一且口径一致时继续。
6. 多个候选无法排除时，只列少量候选的代码、名称和市场或交易所，请用户确认。
7. 没有候选时请用户核对代码、月份或市场，不自动改查相近品种。

## 4. 查询静态信息

对已确认合约调用 `futures_get_instrument_info`：

- `codes` 只包含该合约的一个代码键；
- 只传基础展示代码；
- `market` 只在代码有市场歧义时提供；
- 核对响应对象与搜索确认的代码、名称、市场、交易所和类型一致；
- 响应为空、对象不一致或返回多个无法区分的记录时停止，不合并记录。

### 精确补充码表字段

只有静态信息未返回用户需要的字段，而且代码和市场已经确认时，才使用 `futures_list_instruments`：

1. 使用精确 `market` 和 `codes` 筛选同一合约。
2. 范围限制到核对单一合约所需的最小值。
3. 需要显式 `fields` 且字段名未知时，先调用 `quote_list_parameter_options`：
   - `domain="futures"`
   - `parameter="fields"`
   - `usage="instrument_list"`
4. 只使用 `options` 中适用于 `futures_list_instruments` 的 `value`。
5. 没有匹配字段时省略 `fields` 或说明不可确认，不猜字段名。
6. 检查返回总数、分页、截断和精确代码匹配；返回多条时不拼成单一合约资料。

### 补充品种属性

只有用户询问所属品种、交易所或是否有夜盘，且前述响应缺失时，才考虑 `futures_get_product_list`：

- 必须先从真实合约响应取得可匹配的品种代码或名称；
- 不根据合约代码自行截取或推断品种；
- 品种属性必须标明是品种级信息；
- “有夜盘”不能转换成具体开收盘时间。

## 5. 字段选择

保证金先执行 [`fees-and-margin.md`](fees-and-margin.md)。发现 `long_margin_ratio`、`short_margin_ratio`、`margin_type` 后仅展示同一合约实际返回且口径明确的原值；不猜百分比转换、合并多空或冒充公司/个人标准。报价单位沿用可信码表和字段定义，不仅凭币种推导物理分母。

用户只问一个属性时直接回答该属性。用户泛问“合约信息”时，从本次响应实际存在且含义明确的内容中选择：

- 合约代码和名称；
- 市场和交易所；
- 所属品种代码和名称；
- 对象类型或实际合约标识；
- 合约月份、上市日、到期日、最后交易日或交割日期；
- 交易或挂牌状态；
- 交易单位或合约乘数、报价单位、最小变动价位、币种；
- 其他明确返回的交易、交割或品种属性；
- 数据更新时间或码表时间。

这些是输出分类，不是接口字段承诺。字段不存在、为空、单位不明、编码不明或与其他字段冲突时，不作为用户事实输出。

不得根据接口名称、代码格式、知识正文或相似合约补造任何具体参数。

## 6. 输出

1. 先用一句话确认该代码对应的合约。
2. 用户需要多个字段时使用短表格，只展示非空且语义明确的字段。
3. 不展示 `backendId`、`domain`、`capability`、内部市场枚举、原始技术字段名或工具调用过程。
4. 响应有明确时间时说明资料对应时间；没有时间时不声称“实时”“最新”或“交易所当前”。
5. 合约资料和字段解释混合时，先给查询结果，再从知识分支解释通用含义。

## 7. 异常与回退

- MCP 工具未注册：说明当前未获得合约查询能力，不用知识正文替代。
- 连接或调用失败：相同参数只读重试一次，仍失败则停止合约分支。
- 候选不唯一：等待用户确认，不继续查详情。
- 候选不是 `normal` 实际合约：保留对象类型并转相邻能力。
- 静态信息为空：说明当前未取得资料，不把空值写成 0 或“不存在”。
- 用户所问字段未返回：说明本次合约资料未包含该项，不推断。
- 搜索候选与详情对象不一致：停止输出并重新核对。
- 信息疑似陈旧或状态异常：只展示响应实际状态或时间，不声称仍在交易。
- 混入动态行情：静态部分继续，动态部分转通用行情 Skill。
- 混入当前规则：静态部分继续，规则部分转现行权威规则能力。

## 8. 完成前检查

- 是否只有一个明确实际合约；
- 是否先搜索并唯一定位，再查询同一代码和市场；
- 是否避免把品种、主力、主连、指数或合约集合静默替换；
- `fields` 是否来自参数选项工具，而不是猜测；
- 品种属性是否与合约特有信息清楚区分；
- 是否只使用本次实际返回且含义明确的字段；
- 是否把动态行情和当前规则正确分流；
- 是否隐藏了 MCP 技术细节并直接回答用户问题。
