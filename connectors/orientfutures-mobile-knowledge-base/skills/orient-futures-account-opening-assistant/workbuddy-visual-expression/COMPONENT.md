# WorkBuddy 视觉表达

内部公共 Component，不单独注册或发布为 Skill。识别出可视化任务时先完整读取本文件，完成必要业务查询后根据已有证据编排；它负责“为了回答这个问题，画什么、先看什么”，不负责业务取数、配色或像素绘制。

## 输入与决策

输入是本轮用户目标、已核验的业务结果与审核知识，以及原子工具实际返回的 `presentation.evidenceRef`、`evidenceExpiresAt`、`evidenceBindings` 和可选 `evidenceCharts`。`ready` 只表示存在可用展示能力，不是必须调用组合器的指令。不得因为先拿到某种数据，就把问题改写成那种图表。

由当前 WorkBuddy LLM 在业务工具阶段末尾作一次表达决策，不另起一个规划模型。用户明确要求纯文字时直接选择纯文字，不调用本项目组合器，也不调用 WorkBuddy 原生制图；除非用户另行明确要求带图的最终文件。

- 若图形能直接解释用户关心的比较、机制、关系、流程或变化，且证据和支持的区块足够，默认编排一个项目 Dashboard；不能仅因尚未调用组合器而改用原生制图。
- 简单答案或缺少足够证据时直接文字回答。用户明确指定原生制图，或已核实当前组件不支持所需表达／运行时无法提供对应工具时，才可在未提交项目组合器的前提下选择原生路径。不能把未读取协议或未搜索延迟工具当作“不支持”。原生绘图同样不能补造缺失的事实。
- 部分诉求超出业务边界、产业链节点少或部分证据缺失，不是放弃整个项目 Dashboard 的理由：保留相关且有效的区块，其他内容用正文说明。不要让供需预测等不支持的部分挤掉已有真实产业链图。
- 不为填满模板而调用额外行情或知识工具；不因展示需求扩展业务权限。证据有缺口时缩小结构或明确缺口，不伪造另一领域的证据。

## 对外来源

图表标题、小标题、图内注释、图例、脚注和导出内容仅围绕业务主题，不附书名、章/节标题、章节编号或知识库名称。对外统一标注一次“数据来源：东方证券期货”；来源详情仅用于内部证据核验。

## 按问题组织，不按工具堆叠

需要核对金融场景资格时读取 [金融场景摘要](references--financial-scenes.md)；它不增加取数步骤，也不替代当前业务 Skill 的权限。

| 问题目标 | 优先结构 | 不应自动替换成 |
| --- | --- | --- |
| 现货客户如何理解现货价和期货价 | `comparison` → `formula` → `scenarios`；若已有相关真实值，在独立数值槽绑定 | 只有一条基差历史线 |
| 沪铜主力行情与 MACD | 行情摘要和 MACD 的 `market-chart`；审核含义/公式可在同一 Dashboard 补充 | 未要求走势时默认加整块 K 线 |
| MACD 金叉/死叉怎么理解 | `mechanism: macd-cross` 与必要知识要点；已获真实指标时再合入相关图块 | 用短长价格均线交叉冒充 DIF/DEA 交叉 |
| 简单产业链上下游关系 | 关系概述和业务名称映射表 | 自动补一张关系图 |
| 完整产业链或拓扑组织供需证据 | `market-chart.chart_ref` 引用本轮 Provider 图，保留方向和节点类型 | 原生图、字符画、Mermaid 或自制 HTML/SVG 重建拓扑 |
| 开户步骤、材料、条件 | `process` 或 `key-points`；仅画本轮审核内容覆盖的步骤 | 虚构办理进度或后台状态 |

学习路径须有真实先后关系；并列要点不能硬画成流程。机制示意须明确 `data_nature="illustrative"`，它不是实盘序列。不得把“画得直观”解释为允许生成不存在的价格、时间、信号或业务事实。

## 一题一个完整实时承载者

一个 Dashboard 可以包含多个相关区块，知识和行情共同服务一个阅读目标；不是只保留一张图、把其他领域全部挤进正文。按本题有依据的内容安排，最多 8 个区块，不逐工具生成卡片和标题，也不固定增补“场景或限制”。

## 内容准入：只展示知识、事实和有据的联合解读

- 每个区块、要点和解释必须属于以下之一：本轮审核知识库覆盖的知识点；本轮工具核验的行情或技术指标实际情况；将该知识点与相同对象、时间和单位的真实数据结合的解释。联合解读要能指出知识依据与数据依据，不以推测补足缺口。
- 不为凑区块增加 LLM 自己的意见、阅读建议、泛化的“怎么看／不能推出什么”，也不把检索过程、唯一命中、工具调用、证据数量或验收状态画进图里。正文已有的通用提醒不再单独制成图块。知识库确实讲解且与问题直接相关的适用条件、风险和限制仍应保留，不能一概删掉。
- 标题直接写具体主题，例如“K 线的四个价格”“沪铜日 K 线与当日行情”，不用“对象与当前读数”之类编排用语。行情对象、数据时间、盘中／收盘口径、单位仍作为必要标注保留，不扩展成空泛的解释卡。
- 提交前逐条核对文字是否被所引证据实际支持；仅挂一个知识引用并不代表文字已有依据。无依据的句子删除，剩余内容不足以成块就删除整个区块。
- 展示数值最多两位小数，行情数量使用千位分隔；比例按工具或指标公式明确的单位显示百分比，不能凭数值大小猜测比例制或重复乘以 100。精确原值保留用于计算与证据。时间戳交给渲染层显示可读时间，不在文案中复制长整数。

选好结构后读取相邻的 `../workbuddy-visual-design/COMPONENT.md` 和 `../workbuddy-visual-rendering/COMPONENT.md`。表达层只输出正式 `dashboard_spec`，不输出主题值、HTML、CSS、SVG、`renderPlan` 或任意字段路径。主题替换不能改变上述结构选择；语气整理不能改动已经核验的事实和表达决策。
