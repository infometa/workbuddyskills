# 金融场景与表达选择

本文件是三个业务 Skill 共用的内部执行摘要。唯一详细维护源为 contracts/financial-visualization/v2/specifications/FINANCIAL-SCENE-SPECIFICATION.md；不能用摘要新增业务权限或取数工具。

| 用户目标 | 表达结构 | 事实条件 |
| --- | --- | --- |
| 理解现货、期货和基差 | comparison → formula → scenarios | 审核知识支持解释；当期数字只绑定同对象、时间和单位的证据。没有当期数据仍可保留知识结构 |
| 最新行情和技术指标 | 行情摘要 → 指标 market-chart | 指标名称、公式参数、实际对象和时间已经核验；没有走势需求不额外加入 K 线 |
| 金叉、死叉等机制 | mechanism → 有据的要点；已有实盘证据时同图补充 | MACD 使用 DIF/DEA，价格均线使用独立机制；示意固定 illustrative，不造实盘信号 |
| 产业链上下游 | 已声明的 graph 作为 market-chart | 保留 Manifest 节点、关系、方向；COMMODITY 矩形、PROCESS 小椭圆，CATEGORY 不冒充加工环节 |
| 开户与学习顺序 | process；并列材料用 key-points | 2～8 个有依据的步骤；不推断用户进度。满足业务入口条件且 Provider 签发行动证据时，以 provider-action 作为唯一末块 |
| 基差、价差变化 | 策略 market-chart；审核公式可作为 formula | 采用实际策略口径，保留单位和样本时间；缺单位不猜，缺值不补零 |

选图先看问题，再看已取得的证据，不能反过来按工具数量堆图。场景支持还受当前发布 Profile、工具 Schema 和本 Skill 权限限制；未发布的盘口深度、波动率曲面、风险归因等不能仅凭规范示例调用或自造。

金融语义与主题分开：涨红跌绿、昨结棕黄是角色映射；普通序列不暗示涨跌，选中态不代表收益或推荐。具体颜色仅从设计组件绑定的契约取得。换主题不改变区块顺序、对象、单位、拓扑或交互。

同一问题的知识与市场证据只交给一个 Composer，一次提交完整 Dashboard；无需新增规划模型。正文随后解释结果，独立最终文件仍由 WorkBuddy 交付。

## 现货指标与数量级差异

先回答四个问题：本图在回答什么？每个指标是什么？单位是什么？为什么放在一起？不要把批量取到的数据直接全部叠成一张折线图。

- 从本轮已有证据选与问题直接相关的核心指标，默认 3～4 项只是展示预算，不是取数上限；不按目录顺序截取，不按涨跌幅挑样。用户点名的指标不能静默丢弃，其他指标留在折叠内容、正文或交付物。
- 只问价格：价格当前状态与走势；问期现关系：匹配口径的期现价与独立基差面板；问供需：必要的供应、需求或库存证据，不机械凑齐四维，也不为了填图新增取数。
- 为 market-chart 填写具体 title；需要解释组织目的时用 purpose 表达本图回答的问题，不加入新的业务结论。有 presentation.evidenceSeries 时，以 series_ids 选择并排序其中的真实 ID，重点在前；没有 ID 不猜造。省略选择会保留全部指标，并由 Renderer 折叠辅助小图。
- 不指定左右轴、不猜单位、不提供归一化后的点值。数量级或单位不适合叠加时由 Renderer 分图，共享时间范围但独立纵轴；不同面板的曲线高度不能比较大小。现货每指标一图，首屏展开两项，其余同一 Dashboard 内可展开。
- 相对涨幅或基期指数只能引用已具备明确计算口径的 Provider 证据；当前 Composer 不计算指数、不做对数变换。没有相应证据时保留原值小图，不能为同轴而改写数据。
