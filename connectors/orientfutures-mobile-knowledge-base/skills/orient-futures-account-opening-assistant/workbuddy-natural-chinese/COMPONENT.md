# WorkBuddy 中文自然表达 Component

本 Component 是纯表达层，只接收已经完成业务查询与事实核验的中文答案草稿，并返回语义等价的最终文字。三个业务 Skill 只依赖本 Component 的固定目录和下述稳定契约；具体语气、句式和编辑偏好全部放在 [`style-profile.md`](style-profile.md)。以后调整风格时，只替换本 Component 目录内的文件并重新构建，不修改业务 Skill、Expert、Connector、MCP 或可视化协议。

## 稳定契约

### 输入

输入必须是已经完成以下工作的答案草稿：业务取数、知识检索、确定性计算、对象与时间校验、风险与服务边界、来源标注、开户链接判断，以及本轮实时可视化路径处理。是否调用组合器由公共视觉 Component 决定，不要求每题都有 Widget。草稿仍有事实缺口时，先回到负责该事实的业务规则；本 Component 不补数、不检索、不调用工具。

### 输出

只返回整理后的最终文字答案。保持原意、信息覆盖范围、结论强度和段落顺序；可以删除套话、合并重复句、缩短冗长过渡并改善中文节奏，但不得增加新的事实、理由、案例、判断、承诺或操作建议。

### 不可变内容

输入须先由业务层完成对客字段隔离；内部 ID、机器枚举、原始参数、证据引用和工具字段不属于需保留的业务事实，不得在润色时恢复。再执行下述对外来源规则，移除内部出处；此规则优先于保留来源和引用原文。仅对客数据视图中的以下内容逐字或等值保留，风格规则与其冲突时以保留为先：

- 数字、正负号、百分比、日期、时间、时区、样本数、单位、公式、参数和阈值；
- 品种、合约、市场、交易所、指标、策略的业务名称及有客户识别意义的品种/实际合约代码；
- 统一后的对外数据来源、查询时间、数据时间、交易日和事实/估算/不可得等口径；
- 风险提示、适当性、隐私、授权、服务边界及其他合规限定；
- Markdown 链接的完整显示文字、目标地址及 `[文案](URL)` 结构、经来源规则处理的引用、代码、表格数据和用户明确要求的格式；
- 已经确定的单一实时绘图路径与业务链接交付顺序；MCP 结构化结果、`evidenceRef`、`dashboard_spec`、`renderPlan` 不属于本 Component 的输入或对客文字，不读写或回显。独立交付文件不受实时图数量限制，但仍遵守业务展示边界。

本 Component 不得改写、生成或再次调用可视化，不得把 Widget 内容复制成第二张图。

## 执行方式

1. 只在业务答案与本轮实时可视化路径处理完成后执行一次；不等待 Widget 显示确认。组合器结果未知时保留互斥状态，依据已核验原子结果整理正文，不启动补图或盲重试。
2. 先清理标题、小标题、正文及括注中的书名、章节和知识库出处，再读取并应用 [`style-profile.md`](style-profile.md)。
3. 默认使用其中的轻量模式；用户明确要求特定语气时，在不可变内容不受影响的范围内执行。
4. 核心业务入口交给业务链接 Component，表达层不生成、复制、恢复或改写其 Markdown；只润色前置说明，保留交付顺序。普通非目录资料链接按 `link-output.md` 保留。
5. 编辑后逐项核对不可变内容；无法确认某处改写是否改变含义时，保留原句。
6. 风格文件缺失、不可读或与本契约冲突时，先执行对外来源规则，再返回业务草稿，不阻塞答案，也不向用户暴露内部后处理失败。

## 边界

- 不处理工具调用参数、工具返回、可视化协议、HTML、SVG、JSON 或其他机器消费内容。
- 不用更口语的说法弱化“不确定、不可得、仅供投教、不构成建议”等限定。
- 不把正式金融术语替换成含义不精确的网络用语，不为了显得有人味加入情绪、经历、揣测或营销承诺。
- 用户明确要求原文、逐字引用、法律或监管固定文本时，不改写相应段落。
- 本 Component 不决定是否回答、是否展示开户链接、是否调用 MCP 或选择何种图表；这些决定始终属于对应业务 Skill。

所有 MCP 支持内容的对外来源只输出“数据来源：东方证券期货”。标题、小标题、正文、括注、引用块、表格、图表、脚注及交付文件均不附书名、章/节标题、章节编号、知识库名称、内部集合或下级供应商。书名、章节、titlePath、section 和 provenance.sources 仅用于内部检索与核验；用户追问来源时仍使用同一对外来源。知识、行情、系统公式与自行计算须区分证据性质和适用口径，不分别展开资料出处。
标题只保留业务主题；例如“客观读法”，不要添加出处括注。最终答案统一标注一次来源，独立图表或文件各自标注一次。
