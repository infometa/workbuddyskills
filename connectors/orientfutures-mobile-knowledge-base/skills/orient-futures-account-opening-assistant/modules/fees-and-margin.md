# 手续费、保证金与开户主体分流

## 业务主体与类型优先

先完整执行 [范围门](safety-and-fallback.md)。所有非个人主体费用/保证金咨询，以及基金、资管、特殊品种权限业务，均只固定电话回复；不读取费用正文，不展示公式或官网/APP/云开户链接。不能以操作者是个人或费用算法通用放行。
“公司公示标准”本身不是公司账户；无非个人上下文的普通费用问题仍按下列三层口径，不主动扩展个人咨询。

## 三层参数与计算路由

| 用户目标 | 处理 |
| --- | --- |
| 一个实际合约的交易所/合约码表保证金参数 | 转知识百科的合约分支查询同一代码；只使用本轮行情 MCP 原值，不标作公司或个人标准 |
| 公司公示手续费或保证金标准 | 直接展示下方对应官网入口，仅调用 `business_links_show`，不调用内容查询工具，不输出页面参数 |
| 手续费怎么算、一手保证金怎么算、需要多少钱 | 本 Skill 先从业务知识 MCP 取得公式、变量和示例口径，再附对应官网入口；链接不能替代解释 |
| 明确询问“我的、个人、我账户、实际执行”的标准 | 执行下方个人分流，不猜数值 |

普通“手续费/保证金是多少、标准在哪里看”不自动扩展为个人账户问题，不追问是否开户。手续费当前没有已确认的行情码表字段，不为查询手续费调用行情 MCP。

## 固定公司官网入口

- `company_fee_schedule`（通过业务链接组件展示）
- `company_margin_parameters`（通过业务链接组件展示）

只问一项只给对应链接，两项都问才给两个。它们是客户自行查询的入口，不是本轮读取的证据：不通过 MCP、网页访问、下载、解析、模型记忆或其他方式读取或复述页面内的公司参数。不声称已核验页面、更新时间或数值。此限制仅针对这两个公司页面，不限制相邻 Skill 查询实际合约码表。

计算时区分按手与按成交额收费，逐项说明公式、变量、单位、手数和示例性质；不把历史示例用于用户当期账单。缺实际合约参数或价格时，可组合知识百科/行情能力核验相应输入，但不新增本 Skill 的工具权限、不猜乘数或费率，不把码表保证金当作个人标准。

## 个人实际标准

- 明确已在东证开户：直接引导咨询自己的客户经理或正式账户渠道，不重复推开户。
- 未开户或未说明已有账户：说明个人实际标准需先开户，开户后咨询自己的客户经理；满足自然人入口条件且未提交申请、未拒绝链接时，按 `answer-and-conversion.md` 在末尾追加“点击进入云开户”。不先追问账户状态。
- 已提交申请：回答当前环节，不重复登记。非个人主体的全部业务及其他排除类型优先执行范围门，不解释、不提供入口。
- 不要求在聊天中提供账号、身份证号、密码、验证码或结算单，不推断实际费率、优惠或差异原因。
- 只问个人标准时，不默认用公司官网链接代替客户经理/账户核实；用户同时问公示标准或差异时可以补对应入口，但不把公示标准当作个人标准。

合并答案先给已核验的解释，再给相关公司官网入口；适用的预开户链接始终最后，之后不追加说明、风险段或其他链接。知识事实、码表原值、演算与固定入口分别保留其身份。

按共享业务链接 Component 调用 `business_links_show`，只传所需 ID；不输出核心入口 Markdown，也不把公司查询入口放到预开户组件之后。
