# 在线答题卡片备选流程与需求模板

本文件仅用于用户明确要求在线访问或多人分享的备选分支。默认离线 HTML 仍按主 Skill 构建并交付；本文件不证明当前客户端具有在线生成或发布能力。

## 适用条件与能力检查

1. 先检查当前客户端实际暴露的工具列表和参数说明。不能根据工具名示例推断 `app_builder_agent` 存在，也不能仅凭 MCP 的 `health_check` 判断客户端有网页构建能力。
2. 如果实际提供 `app_builder_agent` 且参数说明支持下方的 `arch_type`、`user_prompt` 等字段，才使用本文件的该工具调用示例。客户端提供其他网页构建或发布工具时，只按其真实参数和能力执行，不把本文件中的字段直接套用，也不猜测工具名称或前缀。
3. 缺少可用工具或只能生成本地文件、不能发布时，保留并交付已生成的离线 HTML，说明“当前客户端不具备在线发布能力，已提供可下载的离线页面”；不能虚构 URL、把本地文件路径当作公网链接，或自动安装工具、创建托管服务、部署到服务器。用户仍要求发布时，先请其指定可用的托管方式和授权范围。
4. 工具存在但参数或能力无法确认时，不试探未知调用，说明缺少的信息。执行失败时说明实际错误，并继续交付可用的离线 HTML，不无限重试，也不把在线失败描述成 MCP 出题失败。
5. 向外部服务上传材料或发布页面前确认目标及访问范围；不传入 Token、上传票据、API Key 或工作流地址。只有工具真实返回或可核验的可访问 URL 才能作为在线结果交付。在线编辑和持久化参数也必须以当前工具实际能力为准。

可用的 `app_builder_agent` 支持下方参数时，把本文件「功能规格」一节的内容**原样**作为 `user_prompt` 的前半部分，再把全部题目按标准格式追加在后面。不要替该工具做技术栈选型，也不要自行扩写视觉风格描述。使用其他工具时保留这些功能要求，但按其真实输入格式传递。

## 功能规格（原样传入 user_prompt）

```
做一个可交互的答题卡片应用。共 {N} 道题，按题目顺序逐题展示，卡片上标注题型标签（单选/多选/判断/填空/简答）。

功能要求：
1. 卡片式逐题展示，一道题一张卡片，带流畅的切换动画。
2. 各题型交互方式：
   - 单选题/判断题：点击选项即提交判分（判断题选项固定为"正确""错误"两项）。
   - 多选题：点击可勾选/取消多个选项，选好后点"提交"按钮判分；必须全部选对才算正确，漏选、多选、错选均判错。
   - 填空题：提供输入框，点"提交"后与正确答案比对（语义相近即算对，去除空格差异）。
   - 简答题：提供多行输入框，点"提交"后展示参考答案要点，由用户自评"答对了/答错了"。
3. 即时判分反馈：答对选项/区域显示绿色高亮（✓），答错显示红色（✗），多选题和填空题同时标出正确答案。
4. 判分后在题目下方展开两个区块：「答案解析」和「助记口诀」。某题没有助记口诀时不显示助记区块，不得留空白区块。
5. 文字与背景必须保证足够对比度：解析正文用深色文字配浅色底；助记口诀用深褐色文字（如 amber-900）配浅琥珀底（如 amber-50），禁止浅色文字配浅色底导致"看不见"。
6. 顶部固定答题进度条，实时显示"已答 x/{N}"，进度条平滑填充。
7. 每题判分后出现"下一题"按钮；最后一题判分后进入结算页。
8. 结算页显示：总得分（每题计分相同）、得分率百分比、答对/答错数量、鼓励性文案；提供"重新开始"按钮，一键重置从头再做。
9. 答过的题不允许修改答案，保证判分唯一。

题目内容如下：

{此处按标准格式粘贴全部题目}
```

## 组装示例（仅供理解，不要把示例题目传给应用）

- `{N}` 替换为实际题目总数。
- 题目区按 SKILL.md 的标准格式逐题粘贴：题型、题目、选项、正确答案、解析、助记。
- 混合题型时题型标签分别显示，顺序与题目列表一致。
- 若全部来自背书匠 MCP 的一次或多次 `generate_questions_from_material` 返回，保持返回顺序，按题型分块或混排均可，与用户要求一致即可。

## 调用参数

以下参数仅用于已确认存在且参数兼容的 `app_builder_agent`，不是 WorkBuddy 必须提供的接口；未满足上述适用条件时不得调用。

- 工具：`app_builder_agent`
- 新建：`arch_type="jspage"`，`user_prompt` = 功能规格 + 题目。
- 编辑修复：额外传 `app_id`，user_prompt 中写清要修复的具体问题和正确内容。
- 仅当用户明确要求持久化保存答题记录、错题本、跨设备成绩等数据能力时，才改用 `arch_type="fullstack"`，并在功能规格中补充数据存储需求。
