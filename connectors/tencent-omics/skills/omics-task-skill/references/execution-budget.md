# 运行预算、试跑与失败恢复

适用于 WDL、Nextflow、Lambda，以及已选定的沙箱分析。它约束本次任务的执行决策，不新增平台资源限额。实际规格、配额与权限以当前后端为准；不要从单个案例推导“最多 3 个并发”“最多 2 次失败”或 Lambda 专属 CPU、内存、磁盘、时长上限。

## 不把估计变成强制期限

Lambda 当前契约中，计算 `timeoutSeconds` 省略或为 `0` 表示不设固定墙钟期限；输入准备、传输与结果发布默认也不加阶段期限。仅在用户已明确期限时填写正数，保留已有显式期限；模板、生成器和专家不能自行补 600、1800、3600 等秒数，也不从预计耗时自动导出硬截止。正数计算期限不能替代上传期限，计算完成仍须等到真实发布与内容验收。旧客户端/服务若拒绝 `0`，报告实际版本不兼容并升级，不自动换成短时限或沙箱。真实容量、权限、取消与环境生命周期仍按平台现有规则处理。

镜像、输入、输出按真实大小准备磁盘和传输，不增加 Lambda 专属 10 GB 镜像等人为门槛；保留实际协议范围和后端容量校验。大型内联内容按 CLI 提示上传到本次环境桶，再用真实桶路径引用。

## 先复用适用证据，再决定是否试跑

已有相同算法、镜像/依赖、输入格式和相近规模的可信运行记录时，先复用它的准备方式、资源观测和验收器。小任务或已验证路径可直接执行，不为每次分析另跑一轮 pilot，也不查找演示数据替代用户输入。历史成功只覆盖它的规模、参数与输出契约，不能直接证明更大输入能完成。

对首次大规模、输入结构改变或运行时间高度不确定的任务，先用数据摘要检查关键规模，再选择能回答具体风险的代表性试跑。记录真实样本/供体、细胞或 spot、特征、参考细胞、迭代数、稀疏度等适用维度，以及分层抽样方式和随机种子。试跑既要包含昂贵的实际阶段，也要包含真实的输出发布；仅预览或读取文件不能证明计算成本。没有适用的子集方案时，说明限制，利用算法复杂度、历史观测或可中止的进度观测制定计划。

不要固定要求 50–100 个 spot，也不要只按一个维度线性放大时间。依赖安装、镜像拉取和输入准备有固定开销；不同算法随细胞、特征和迭代数的增长可能非线性，分批还会重复初始化。给出估计区间、依据、未覆盖的阶段和不确定性；算法打印的 ETC 是观测信号，不是完成承诺。比较剩余计算估计、当前计算超时与发布阶段时限，不能只把 timeout 加大就认为风险已消除。

多个独立方法放在同一串行命令中时，前一方法超时可能让后续方法从未开始。若方法可以独立运行，优先拆为有各自产物、状态和预算记录的任务，复用已核验输入；需要保留前后依赖时按真实依赖执行。选择算法须符合用户目标与输入假设，不因较快就用另一方法冒充原方法。

## 预算跟踪整个任务

开始时记录用户已给出的截止时间、费用/资源预算、方法和数据范围；用户未给数值时写“未指定”，不捏造默认金额或硬时限。普通、费用范围清楚且已授权的执行继续完成。只有下一步将超出已确认范围，或重大成本/方法取舍无法从已有授权判断时，先把可执行方案与预计影响准备好，再请用户选择。

大任务、多方法或排障重跑时，在本次任务记录中持续维护下面的信息；一次简单运行可直接用提交摘要与回执记录，不强制另建系统：

| 记录项 | 要求 |
| --- | --- |
| 目标与范围 | 所需结果、数据/方法版本、明确的用户预算和授权边界；未知项单列 |
| 每次尝试 | RunUuid / 步骤或 SandboxId / 命令标识、输入及定义校验和、实际项目/环境、与前次的关系 |
| 当前阶段 | 准备、排队、输入传输、计算、结果发布、下载/验收；用实际时间或标注估计 |
| 已消耗 | 所有成功、失败、取消和试跑的时间/资源；包含重复准备与传输，不只计算成功任务 |
| 剩余计划 | 下一步的目标、资源声明、估计区间及其依据、仍需发布和验收的工作 |
| 继续/停止依据 | 明确预算剩余、已确认的故障是否修复、是否有新证据、是否改变数据或方法范围 |

并发任务的总墙钟时间按实际时间线计算，不能把重叠时段简单相加；累计资源量可按各任务的实际分配与占用时长计算，缺失字段标为未知。资源时不是账单金额，未取得有效价格/账单时不推算确定费用，也不把超时内已发生的计算称为“空转”。并发根据实际配额、调度和 CPU/内存/I/O/上传观测确定；任务数量本身不能证明相互抢占或上传限流。

在新一批提交、重跑或明显偏离估计时更新记录。实际消耗或下一步保守估计将超过用户明确预算时，暂停新的有成本提交，说明已完成/未完成工作和可选方案；已在运行的任务按已有取消授权处理，不擅自终止其他任务。没有明确预算不等于允许无限重试：同一故障未定位、条件未改变且没有新证据时，停止重复投递，继续取证和准备最小修复；需要用户决定的具体范围再询问。不使用固定失败次数触发沙箱或另一算法。

## 按失败阶段决定下一步

| 信号 | 下一步 |
| --- | --- |
| 提交或查询超时，任务是否创建/完成未知 | 查同一请求与运行；不创建重复计算。Lambda 的幂等回放与重跑见 [运行恢复](lambda-recovery.md) |
| 排队/镜像/输入准备失败 | 定位对应事件、身份、路径或依赖，复用已核验的输入与资产；不能直接归因于算法太慢 |
| 计算超时或无进展 | 核对计算开始时间、阶段、进度、实际资源及应用日志，比较剩余估计与预算；识别可恢复检查点，不假设平台 retry 会断点续跑 |
| 计算完成，输出发布/回执失败 | 先保留日志、实际发布清单与可取回产物，检查权限、配额、上传和文件完整性；不要为解决传输问题先全量重算 |
| 日志 UnauthorizedOperation / 403 或查询失败 | 核对实际身份、项目和权限；错误本身不能证明日志过期或产物不存在 |

每次有成本重跑都要有具体、可检验的理由：记录失败证据、假设、这次改动及预期信号。在能够区分原因时只改变必要因素；若必须同时修复多个已知问题，逐项列出，不把随后成功归因于某一个未经隔离的因素。没有新的证据或故障条件未消除时，预算剩余也不构成盲目重跑的理由。改变基因数、参考细胞、迭代数或抽样范围会改变科学输入或方法，必须记录影响，不能只作为隐藏的降成本开关。

已发布文件能通过真实 URI 取回时，先核对清单、字节数/校验和和内容语义。只有实际保留的文件或应用检查点且存在支持的恢复入口，才能提出只发布、断点恢复或复用上游；没有入口时明确不可恢复。普通 `omics retry` 会创建新运行，不是通用的“只重传结果”命令。确需重算时计入累计预算，修复导致发布失败的条件，隔离新输出，并记录复用输入与新计算的边界。

多步工作流本身已提供步骤级复用边界：只要上游产物真实发布且符合下游输入合同，就可从冻结定义抽取单步或后续子图继续运行，不要求应用另有专用“恢复模板”。优先沿用原镜像、命令与输出合同；把子图外的 `from` 替换为真实产物 URL，保留子图内依赖。原 Run 整体失败不否定其中已发布的有效步骤产物。参数或输入变化时，从最早受影响步骤向下游标记失效，不能复用这些旧结果；步骤内的恢复仍需要应用真实检查点。操作与通用组合脚本见 [多步续跑](lambda-continuation.md)。复用上游是新的部分执行，不改写旧 Run 状态，也不声称后端自动断点续跑。

不同 Run 的部分结果不得按同名文件拼成一次 SUCCESS，随机分析尤其不能默认等价。独立分片或上游步骤确需组合时，建立新的组合产物清单，逐项记录来源 Run/步骤、输入和定义版本、种子、校验和及兼容性检查；将其标为“组合交付”，保留各源运行真实状态。不能借组合交付抹去发布失败或未执行部分，不能把缺少的对照结果当零值。

## 方法与执行路径保持可追溯

执行路径遵循四级优先级：① 优先使用随包默认 Lambda → ② 模板不匹配时先考虑保持科学方法的 Lambda 输入适配或由用户/Agent 组装自定义 Lambda → ③ 需要交互式探索、动态依赖或 Lambda 通道受阻时切换至云沙箱（`omics-sandbox-skill`） → ④ 若云端 Lambda 与云沙箱均不可用或受阻且本地具备所需运行环境，使用本地环境兜底执行并如实记录实际执行方式。用户指定的方法在当前资源/预算内无法完成时，给出尚未完成的部分与可比方案。已有授权允许选择替代方法时说明其名称、输入假设、输出差异和验证范围后执行；用户明确要求某方法或平台时，改变该约束须先取得针对这一变更的确认。

最终报告分开列出完成计算、完成发布和内容验收的证据，保留失败与未执行阶段。预算优化不能把不同算法、不同细胞/供体范围或部分产物的结果描述为原目标已全部完成。
