# 生命科学分析与结果核验

根据问题决定检查深度。先理解输入和实验设计，再选方法；模板工具清单仅帮助发现执行环境。已有分析脚本、论文方法或应用输出契约应优先作为本次依据，保留用户指定参数。

## 数据探索与脚本准备

先读取文件元信息、表头和少量记录，判断格式、压缩方式、行列规模与预计内存。大矩阵优先保持稀疏或分块读取，不在未确认容量时整体转成稠密矩阵。输入保留原件，清洗写新文件并记录规则。

| 数据/任务 | 需要核对的事实 |
| --- | --- |
| 表格与样本表 | 列类型、缺失比例、重复 ID、单位、日期格式、分组与批次；连接前确定主键和一对一/一对多关系，连接后核对行数及未匹配项 |
| 表达或单细胞矩阵 | 行列方向、基因与样本/细胞 ID 对齐、原始计数或已归一化/对数变换、稀疏格式、批次及生物学重复；不要再次套用不适用的变换 |
| 序列、比对和变异文件 | 格式可解析、序列/样本数量、索引与主体文件一致、参考基因组及版本、染色体命名、坐标基准和区间边界 |
| 分子与蛋白结构 | 标识、SMILES/结构可解析、无效或重复记录、标准化规则、链/残基与序列对应、坐标有限性；按实际方法保留立体化学和命名信息 |
| 多组学与通路结果 | 物种、参考版本、跨数据集样本对应、特征 ID 转换、背景集合来源；报告无法匹配的比例，不静默丢弃 |

若分组、独立样本单位、处理条件或数据含义无法由元数据确定，先完成可独立进行的结构检查，再补齐会改变结论的关键信息。不能从文件名臆造实验设计。

编写脚本时把输入路径、分组列、过滤阈值、参考版本和输出位置变成明确参数。需要随机过程时固定并记录种子。保存 CLI/解释器/主要包版本，以及输入和脚本的 SHA256；依赖必须按实际使用情况确认导入或工具版本，不能仅引用模板名称。

## 统计与绘图

根据数据类型、配对关系、生物学重复和研究问题选择方法；细胞、读段、技术重复不能自动当作独立生物学重复。处理缺失值和离群值时记录规则及影响的样本数，保持原始与处理后统计可对照。

统计结果保留样本量、效应量、适用的区间估计和显著性指标；存在多重比较时使用与本次问题一致的校正范围。样本量或设计不足时仍可做描述性探索，但结论说明这一限制，不把相关性写成因果。

绘图保存底层表格与绘图脚本，使用非交互后端写文件。按交付要求选择可编辑的矢量图或足够分辨率的位图；检查轴、单位、分组、图例和缺失值处理。降维图应记录所用数据、特征选择及参数，不能仅凭分群图得出差异或机制结论。

## 实际产物核验

每次执行使用新的输出目录，防止旧结果被当成本次产物。完成后至少读取本次任务的关键结果，按其契约核对：

- 表格能完整解析，列名/类型及样本标识符合预期；数量变化能解释；无意外全空列、无穷值或大量缺失。
- 统计量在其定义域内；效应方向、对照关系和单位与脚本一致。对关键汇总用独立计算或少量可手算记录交叉检查。
- 科学文件能被相应解析器读取，结构和伴随元数据一致；已有 checker 必须覆盖本次模式，不能为通过而调整科学断言。
- 图像或 PDF 实际可打开，绘图区和文字完整，展示的数据范围与汇总表一致。可用本地预览工具查看取回文件。
- 下载清单与远端产物对应，必要时比较大小及 SHA256；下载到新目录再核验，避免本地旧文件混入。

对每项结论分别记录“已执行”“已取回”“内容已核验”以及具体未验证原因。工具缺失、checker 不适用或仅生成文件不能记成科学结果已通过；真实校验失败保留错误和输入参数，先定位原因再决定是否需要新执行。

## 可复现交付

通常交付最终数据表、图形、脚本、参数、工具版本、输入/产物清单和简短结果说明；只保留对本次任务有用的中间文件。说明数据筛选、方法、关键参数、统计单位、验证范围与局限，结果中的主要数字应能追溯到文件。记录实际 SandboxId 和执行 UUID 便于定位命令摘要，不保存认证信息。

沙箱状态为 `RUNNING` 只证明环境可执行；命令退出成功只证明程序完成；内容核验也只覆盖检查过的断言。若用户目标是已有 Lambda 应用的正式验收，应按该应用的独立验收流程保留冻结定义、运行及发布证据。
