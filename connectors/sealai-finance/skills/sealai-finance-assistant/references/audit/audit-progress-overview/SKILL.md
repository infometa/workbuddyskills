# 企业审核进度与记录

## 适用范围与连接器

关联 `sealai-finance` Connector。承接企业整体“有多少单据、多少未启动审核、目前审核到哪一步”等汇总，以及明确的任务查询。

只查本人报销使用“本人报销进度”；需要风险排名、原因归纳或改进建议时使用“费用风险洞察”。用户未说明是本人还是企业范围，且会话也无法确定时，先澄清，不默认扩大到企业。仅出现“审核”一词不表示用户要求启动任务。

未连接时，引导用户通过 SealAI OAuth 登录、选择企业并确认授权。沿用 Connector 和 Tool 的既有权限校验，不改变 `DATAS_APPROVALS` 等权限边界，不把只读汇总视为免授权。权限拒绝时停止，不改用其他身份或范围绕过。

## 执行步骤

1. **查询单据审核覆盖。** 调用 `financial_audit_reimbursement_overview`，查询用户指定的业务日期范围；未指定时采用 Tool 默认最近 30 天，不自行扩大。该 Tool 按单据 `source_start_time` 统计，不按创建或提交时间统计，缺少业务日期的单据不得自行归入范围。

2. **按单据口径展示结果。** 展示实际业务日期范围、总单据数、未启动审核数、审核状态与决定分布，以及 Tool 返回的持久审核记录。数量以 Tool 的统计口径为准，分页列表条数不冒充总数，不遗漏“没有启动审核”的单据；没有返回某项统计时说明未提供，不自行填成零。

   `summary` 是全量统计，`items` 是 `limit` / `offset` 对应的本页。需要完整列表时沿同一范围翻页并按 `document.id` 去重，不把每页相同的 summary 累加。分页中总量变化时说明统计正在变化。`approve`、`reject`、`review`、`error` 与任务状态分别展示；`decisionDenominator` 不含 ERROR 和无决定单据，分母为零时 `approvalRate=null` 表示不可计算，不显示为 0% 通过。重复提交的多个调用结果不能当作多张单据。

3. **仅在用户明确要求时补查队列。** 用户明确询问队列任务和失败原因时，另调用 `financial_audit_overview`。它按任务操作时间查询；展示时单独注明任务时间范围，不把它当作 `source_start_time` 业务日期统计，不用队列列表替代单据覆盖统计。只问覆盖数量或已有审核记录时，不顺带查询任务列表。

4. **用真实任务 ID 查看详情。** 用户要求查看某个任务详情时，使用查询结果中的真实 `job_id` 调用 `financial_audit_status`。尚无可靠 `job_id` 时先通过对应任务查询取得，不将 `document_id`、单据编号或猜测值当作 `job_id`，也不为查询详情创建新任务。

5. **分开报告任务进度和业务结论。** 队列 `completed` 只说明队列任务状态，不等于审核通过；审核结论只能来自真实持久审核记录。没有启动审核、执行失败或结论尚未形成时，明确说明实际情况及 Tool 提供的原因，不推断人工审批或付款结果。

## 异常与协作边界

空结果只说明当前查询条件下未找到可见记录，不表示企业从未发生报销。查询失败时保留真实错误；只取得部分数据时，明确哪些统计或记录尚未取得，不补造数量或结论。

企业汇总不自动排除 `demo_data=true`，也不支持该筛选参数。已知演示范围须标注“合成演示数据”，即使实际执行了审核也不代表真实企业业务分布；混合或来源未确认时说明可能含演示数据，不把全量汇总称为真实业务统计。不能仅凭当前页没有演示标记就推断其他页均为真实数据。

同一请求还包含风险分析时，将分析交给“费用风险洞察”；企业、业务日期范围、查询条件一致且仍适用的真实结果可以复用，避免重复查询，但不跨范围复用。不要因同时存在多个子任务而复用写操作确认。

本流程不调用 `financial_audit_start`，不修改企业规则，不生成 Top 风险或建议，不执行人工审批、付款或通知。
