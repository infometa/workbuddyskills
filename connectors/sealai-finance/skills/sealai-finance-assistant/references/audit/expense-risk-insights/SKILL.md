# 费用风险洞察

## 适用范围与连接器

关联 `sealai-finance` Connector。承接企业费用风险、主要原因和改进建议的分析；只问审核覆盖、完成数量、任务状态或队列执行失败原因时，使用“审核进度汇总”；只查本人单据时，使用“本人报销进度”。不因查询结果出现失败或驳回，就自动追加风险分析。

未连接时，引导用户通过 SealAI OAuth 登录、选择企业并确认授权。沿用 Connector 和 Tool 的既有权限校验，不改变 `DATAS_APPROVALS` 等权限边界，不把只读分析视为免授权。权限拒绝时停止，不用本人查询、他人身份或其他 Connector 绕过。

## 执行步骤

1. **确定业务日期范围。** 调用 `financial_audit_reimbursement_overview`，传用户明确给出的业务日期范围和分页参数；未指定日期时采用 Tool 默认最近 30 天，不自行扩大范围，也不因固定演示数据存在而改查 2026 年 8 月。参数使用 Tool 既有键名，不新增筛选参数。

   该 Tool 按单据 `source_start_time` 选择费用月份，不按创建、提交或任务处理时间选择。缺少业务日期的单据不得自行归入范围，查询条件不足或有歧义时先明确范围。

2. **核对统计范围与证据是否足够。** 使用 Tool 返回的 `summary`、`reasonSummary`、`ruleHitSummary`、`riskEvidence` 和 `items`，区分全量统计和本页样本。`summary` 为查询范围内全量统计；`items` 与 `riskEvidence` 是本页证据。原因和规则汇总按全量计数后降序截取前 `limit` 类，`reasonSummaryTotal` / `ruleHitSummaryTotal` 是类别总数，`offset` 不为这两个汇总翻页。不得把各页重复返回的汇总相加；`documentIds` 也只是最多 `limit` 条示例，不是该类别的全部单据。

   需要更多单据证据时保持同一企业、业务日期与 `limit`，按 `offset` 获取后续 `items`，按 `document.id` 去重，不用本页条数代替总量。类别被截断时可在 Tool 上限内增大 `limit`，仍不完整则披露截断；不能声称已遍历全部类别。分页期间总量或统计变化时披露快照不稳定，不拼成完整排名。

   分母必须保留 Tool 语义：`decisionDenominator` 为有 `APPROVE`、`REJECT`、`REVIEW` 决定的单据数，不含 `ERROR` 或无结论单据；通过率为 `approve / decisionDenominator`，分母为零时是不可计算而非 0%。普通 `reasonSummary` 用该分母，`ERROR` 原因用 `summary.error`；不混算。`reasonSummary` 按决定与整段原因分组，不是拆分后互斥的业务风险分类。`ruleHitSummary` 同单同规则只计一次，但同单可命中多个规则，跨规则计数合计可超过分母、比例合计可超过 100%；不可称为互斥单据风险分布。归并原因时只有取得完整、去重后的单据证据才计算新类别数量，否则保留 Tool 原分类或仅作样本描述。

   同一请求同时要求进度与风险分析时，分别按两个流程的职责处理；企业、日期范围、查询条件一致且结果仍适用时，可复用已取得的真实查询结果，不为相同数据重复调用。不得复用其他企业、不同范围或已经不适用的结果。

3. **归纳最多三类有证据支持的风险。** 每项包含风险名称、数量或占比、主要原因、证据样本和可执行建议，并交代统计范围与分母。先明确按原因还是规则命中数量排名，不把两者混排。每项至少关联实际 `documentId`、`approvalRecordId`、决定与对应原因/规则证据；首页找不到该类证据时补查后续单据页，不能用 fixture 标签填补。只在统计可比、证据足够时归纳 Top 3，第三名有并列或截断时说明排名限制；不足三类就返回已有类别。只有样本证据时，明确为样本发现，不声称是企业整体排名。

   原因汇总也可能包含 `APPROVE` 或 `ERROR` 类别，不能直接将返回的前三行命名为业务风险。保留 REJECT 与 REVIEW 的不同含义；若排除非业务风险后候选不足且类别仍被截断，不宣称完整 Top 3。规则汇总是所有非 ERROR 决定的命中统计，不能未经完整证据重算就改称“已确认拒绝单据数”。

4. **区分审核决定和执行异常。** 按 Tool 实际返回区分 `REJECT`、`REVIEW`、`ERROR` 等结果及失败原因；`REVIEW` 是待核对，不等于已确认违规。未审核、`queued`、`processing` 或仅有队列 `failed` 且没有持久决定的单据不纳入已判定业务风险；`ERROR` 单列为执行/模型异常，不算 `REJECT`，不列入业务风险 Top 3。队列 `completed` 不等于审核通过。原因必须有记录支持；改进建议明确作为建议，不声称已经修改规则、补齐材料或执行处置。

5. **如实反馈证据缺口。** 没有真实审核结果时，明确说明“当前没有足够的真实审核结果，无法形成风险排名”，不说“没有风险”或“全部通过”，不用演示预期或模型常识补齐。查询失败时展示真实错误和无法确认的范围；部分有证据时只报告可支持的发现，并说明限制。涉及个人信息时，只展示完成分析所需的最小证据。

本流程不修改或发布规则，不启动审核，不执行人工审批、付款或通知。用户要求实际处置时，应按对应能力和独立确认处理，不把分析请求作为执行授权。

## 演示口径

`demo_data=true` 即使真实提交并产生持久审核结果，仍是合成业务数据。演示预期不能替代实际记录；实际演示结果也只能描述为“演示数据的审核结果/统计”，不能外推真实企业风险、人员分布、费用分布或异常率。展示姓名不同也不证明存在不同真实用户。

该 Tool 不自动排除演示数据，也没有 `demo_data` 筛选参数。通过 `items[].document.fields` 核对可见的演示标记，并结合本次独立测试租户确认说明范围。仅查到部分页时不得据此断言全量都是演示或真实数据；混合或来源不明时披露企业汇总可能含演示数据，不把总量命名为真实业务统计。若需要纯真实口径而现有结果无法分离，明确无法完成，不编造过滤后的统计，也不修改后台隔离逻辑。
