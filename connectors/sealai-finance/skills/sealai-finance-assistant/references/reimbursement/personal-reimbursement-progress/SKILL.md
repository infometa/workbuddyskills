# 本人报销进度

## 适用范围与连接器

关联 `sealai-finance` Connector。承接“我的报销到哪一步了”“查看我这张单据”等本人进度查询。用户要修改或提交草稿时，转到“报销草稿提交”；用户要看企业整体情况时，转到“审核进度汇总”，不在本流程扩大查询范围。

未连接时，引导用户通过 SealAI OAuth 登录、选择企业并确认授权。只查询当前 OAuth 用户按 Tool 权限可见的本人记录，不接受或构造他人身份；权限拒绝时停止，不换身份或改查企业数据绕过。

## 执行步骤

1. **明确单据或列表范围。** 查询指定报销时，调用 `expense_form_progress` 并传真实 `document_id`，不把单据标题或任务 ID 当作 `document_id`。指代不清时请用户明确目标，不猜测。查询本人列表时，同样调用 `expense_form_progress`，省略 `document_id`；只传用户明确给出的 `start_time`、`end_time`、`limit` 和 `offset`，这些参数均可选，时间值为正整数，`limit` 为 1–100 的整数，`offset` 为非负整数。未指定的筛选保持 Tool 默认，不套用其他流程的日期口径或默认范围，也不补造日期、单据 ID 或他人身份。

2. **按返回数据说明当前进度。** 区分草稿、已提交、审核排队、审核中、审核完成和失败。以 Tool 返回的状态和记录为准，这些中文说明不替代或新增后端状态枚举。列表只展示本次返回的记录，分页条数不冒充全部单据数量。

3. **将任务状态与审核结论分开。** 只有 Tool 返回真实持久审核记录时，才展示其中已经形成的结论和原因。没有启动审核就明确说明未启动；仍在排队、处理中或任务失败时展示实际状态和原因；即使队列为 `completed`，没有持久审核结论也不能说审核通过。不推断人工审批或付款状态。

4. **反馈空结果或查询失败。** 空结果表述为“当前查询条件下未找到可见记录”，不扩大为“没有报销单”。查询失败时说明真实错误和当前未能确认的信息，不用旧会话内容或演示预期补齐，不通过重新提交来解决查询问题。

本流程不调用 `approval_document_write` 或 `expense_form_submit`，不修改报销单，不启动审核、付款或通知。
