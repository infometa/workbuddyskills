# 异常排查

## 错误码分流（按前缀认领）

| 前缀 | 含义 | 是否自动重试 |
|------|------|--------------|
| `E-USER-` | 参数缺失、格式错误、输出目录不可写 | 否，修正后手动重跑 |
| `E-HOST-` | 宿主能力缺失（无 MCP 客户端、无 Python 运行时、QR 降级） | 否，走降级路径 |
| `E-MCP-` | MCP 调用失败 | 仅幂等工具可重试（`ai_customer.get`、`organization.*` 查询类）；`ai_customer.update`、文档上传**禁止自动重试** |

## 错误码表（in-band）

HTTP 200 + `code=20000` + `results.error_code/error_message`：

| 码 | 含义 | 处理 |
|---|------|------|
| 40001 | 参数无效 | 检查参数 |
| 42901 | 配额超限 | 等待或联系管理员 |
| 42902 | 频率超限 / 在飞任务超上限（≤3） | 等待后重试 |
| 43501 | 课程不存在 | 核对 courseId |
| 43502 | 无编辑权限 | 核对权限 |
| 43503 | 课程正在生成中 | 等待当前任务完成 |
| 43504 | 任务不存在 / 已过期 / 不属于当前用户 | 重新 submit |
| 43505 | fileIds 无效 | 检查文件 |
| 50002 | agent 调用失败 | 重试一次，仍失败则报告 |
| 50003 | 会话创建失败 | 等 60s 重试（冷却期） |
| 50000 | 内部错误 | 报告运维 |

## 错误处理表

| 错误 | 原因 | 处理 |
|------|------|------|
| 401 / 未认证 / invalid_token | 未登录或认证过期 | **立即停止当前步骤**，调用 `coach-mcp-connect` 技能恢复连接；重连成功后**重试失败的调用**，不要跳过失败步骤继续执行 |
| 50003 会话创建失败 | 建课/改课完成后 **<60s** 内发的 update 被拒（冷却期） | 等 60s 后重试，最多 3 次 |
| 43503 课程正在生成中 | 同课程已有任务进行中 | 等待当前任务完成（轮询 update_status） |
| 42902 频率超限 | 在飞任务超上限（≤3）或 submit 频率超 10/min | 等待后重试 |
| 43504 任务不存在/已过期 | taskId 过期或不属于当前用户 | 重新调用 `ai_customer.update` 提交新任务 |
| 工具不存在或无权访问 | 工具名拼错（如 `training.enum_lookup` 应为 `training.enum.lookup`，**必须带 `training.` 前缀**） | 对照常用工具表核对全名 |
| 工具参数无效 | ① JSON 格式错误；② 缺必填参数；③ 参数含 schema 外字段 | 检查参数格式 |
| 40404 / 40000 / 40801 | 文件解析相关错误 | 立即停止，检查文件状态（见 [file-upload.md](file-upload.md)） |

## 冷却期处理（50003）

建课完成后 ~60s 内发改课 update 可能遇到 50003（会话创建失败）：

1. 等待 60s
2. 重试 update，最多 3 次
3. 仍失败 → 向用户报告

## 超时预算

| 层 | 超时 | 说明 |
|---|---|---|
| MCP 网关层 | timeoutSeconds=120 | 新工具为异步请求-响应，update 秒返，不受 120s 限制 |
| update_status 轮询 | 无硬超时 | 每 5s 一次，总时长建议 ≤10 分钟 |
| 建课完整流程 | 3-6 分钟 | 文档驱动可能更长 |

**超时 ≠ 失败**：超时后服务端后台继续处理。

## 调用契约（调用前必读）

| 契约 | 说明 |
|---|---|
| **业务数据在 structuredContent 顶层** | 无 `.data` 信封；拿不准就先查看原始 JSON 自查，不凭回复文字判断 |
| **requestId 幂等键** | update 接口支持 `requestId`（string，可选）防止重复创建任务。MCP 工具 schema 可能限制此字段，如被拒绝则不传 |
| **禁并行多次 update** | **严禁**对同一会话并行发起多次 update——同一会话 update 严格串行 |
| **并发上限 ≤3** | 同时建课 >3 门会队列积压 |

## 认证失败处理

任何 MCP 调用返回 401 / 未认证 / invalid_token 时：

1. 停止当前步骤
2. 调用 `coach-mcp-connect` 技能恢复连接
3. 重连成功后，**重试刚才失败的调用**
4. 不要跳过失败的步骤继续执行

## 已知行为模式（实测发现）

| 现象 | 说明 | 应对 |
|------|------|------|
| AI 回复"配置已满足要求"但实际未修改 | AI 对话回复与实际 config 不一致 | 只信 `ai_customer.get` 的字段值 |
| 建课后立即改课报 50003 | 建课完成后有约 60s 冷却期 | 等 60s 后再发 update |
| AI 自动补充阶段/维度 | 如要求 2 阶段但 AI 生成 3 阶段 | 属正常 AI 行为，只要满足判定条件即可 |
| 3 门并发建课正常 | 实测 3 并发正常，无队列积压 | 并发上限 3 内可放心并行 |
| update_status 轮询中 taskId 过期（43504） | 任务过期或不属于当前用户 | 重新调用 update 提交新任务 |

## 实测经验标注（M07）

本文定量结论（60s 冷却期、10 分钟轮询上限、3 门并发正常等）适用日期 **2026-09-21**，**测试环境（服务版本未记录）**，为阶段性实测结论；不得直接断言为服务端确定行为。生产环境或服务升级后需复测更新。
