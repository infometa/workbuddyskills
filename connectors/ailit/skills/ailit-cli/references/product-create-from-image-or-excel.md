# 根据图片或 Excel 批量创建商品

## 何时读取

用户提供图片、文字、普通 Excel 或智慧记官方 Excel 模板，并要求从中提取或导入多个商品时读取。

不要为以下请求读取：

- 查询商品、商品详情或库存。
- 创建一个字段已经明确的商品；直接使用 `SKILL.md` 的单商品创建命令。
- 更新已有商品价格或备注。

## 选择处理路径

| 输入 | 处理路径 |
|---|---|
| 明确是智慧记官方商品模板，文件为 `.xlsx` | `ailit product import` |
| 普通 Excel、列名不确定的 Excel、图片或文字 | Agent 提取为 JSON，再执行 `product batch-create` |
| 无法判断是否为官方模板 | 检查表头；仍不确定时询问用户，不直接上传 |

CLI 不解析普通 Excel 或图片；`batch-create` 接收 Agent 提取后的 JSON 草稿。

## 官方 Excel 模板

文件必须是 `.xlsx` 且不超过5MB。需要模板时运行：

```powershell
ailit product import-template -o <输出文件.xlsx>
```

官方模板导入没有逐行 `--dry-run`。导入前：

1. 展示文件名、大小、表头和可安全读取的行数摘要。
2. 说明将执行批量新增。
3. 等待用户在看到本次摘要后回复“确认”。

确认后：

```powershell
ailit product import <文件.xlsx> --yes
```

`--yes` 不能绕过 Agent 确认。CLI 会上传文件、轮询任务并报告总数、成功数和失败数；失败时保留详情链接。

官方导入当前不支持多单位、多规格、商品属性、云店和智能匹配，不要承诺这些能力。

## 普通 Excel、图片或文字

1. 读取输入并逐行提取商品。
2. 保留原始行号，用于报告跳过项。
3. 统一商品名称、规格、编号/货号、条码、单位、分类、供应商、价格、库存和备注等列。
4. 商品名称无法可靠识别时询问；其他可选字段可按默认值处理。
5. 去除完全重复行，不合并名称相同但规格不同的商品。
6. 复制 `templates/product-batch-create.json` 为临时草稿并填写；不得修改或直接执行模板原文件。

草稿结构：

```json
{
  "source": "excel",
  "lines": [
    {
      "name": "农夫山泉550ml",
      "spec": "550ml*24",
      "code": "NFSQ-550",
      "unit": "箱",
      "barcode": "6921168500116",
      "supplier": "",
      "remark": "",
      "category": "饮料",
      "purchasePrice": 20,
      "retailPrice": 28.8,
      "wholesalePrice": 24,
      "memberPrice": 0,
      "costPrice": 0,
      "stock": 120
    }
  ]
}
```

## 草稿字段规则

- 每行只有 `name` 必填；缺少名称的行跳过。
- `unit` 可为空；非空单位必须精确匹配已有单位。
- 文本字段缺失时默认为空；价格默认 `0.00`；库存默认0。
- `costPrice` 缺失时回退到 `purchasePrice`。
- 分类缺失或未知时回退到默认分类。
- 不支持商品属性、多单位和多规格；一行对应一种规格和一个单位。
- 服务端可能允许同名商品。创建前检查重复名称，并在预览中标记疑似重复项。

## 预览、确认与创建

```powershell
ailit product batch-create --json <临时草稿文件> --dry-run
```

试运行后，必须主动逐条展示商品名称，以及本次将写入系统、且来源于有效输入或 Agent 转换补全的字段最终值；未映射字段和仅由默认规则填充的可选字段省略。

同时展示总解析数、可新增数、异常跳过数，以及每个跳过项及其原因。

常见原因包括缺少名称、名称重复、单位无法解析和未找到供应商。空单位可以提交，不得仅因单位为空跳过。

实际创建必须同时满足：
1.上一轮已向用户展示本次完整预览；
2.用户在看到预览后发送了新的消息，并明确回复“确认”或“确认创建”。

满足以上条件后，才运行：

```powershell
ailit product batch-create --json <临时草稿文件>
```
修改任何待创建字段后，必须重新试运行、展示预览并再次确认。

## 结果处理

- 报告总数、成功数、失败数、跳过数和成功商品名称。
- 部分失败时只报告，不自动重试，避免重复创建已成功商品。
- 预览中被跳过的行不得提交。
- 部分成功不得笼统回复“全部成功”。
- 默认不展示商品内部ID。

## 场景示例

会触发：

- “我上传一张商品清单照片，识别后批量创建商品。”
- “这个Excel不是官方模板，帮我提取商品并预览，确认后新增。”
- “把这份官方商品模板导入系统。”

不会触发：

- “创建一个商品：矿泉水，零售价3元。”
- “查一下矿泉水库存。”
