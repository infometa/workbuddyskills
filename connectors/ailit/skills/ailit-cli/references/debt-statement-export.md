# 组合欠款查询与对账单导出

## 何时读取

只有请求同时涉及以下一种复杂组合时读取本文件：

- 按多个条件筛选或排序欠款对象，例如“累计欠款前10且本期欠款不为0”。
- 为一个或多个客户生成对账单 PDF，并下载、命名或批量保存到本地。
- 查询、导出、验证和交付组成完整对账流程。

不要为简单请求读取本文件。以下请求直接使用 `SKILL.md` 的基础命令：

- “查一下欠款客户。”
- “查张三本月欠款。”
- “查看张三本月对账明细。”

进入本流程后，继续遵守 `SKILL.md` 的认证、消歧、输出、文件和隐私规则。

## 识别组合条件

提取对象类型、对象范围、日期、筛选条件、排序数量、输出格式、保存目录和命名要求。

- “本月”解析为当前时区的当月1日至最后一天，并显式传入日期。
- 对账列表默认本月、隐藏零欠款、每页100条、按累计欠款降序；开始日期最多回溯最近6个月。
- “累计欠款前 N 且本期欠款不为0”必须先过滤本期欠款，再按累计欠款降序取前 N。
- 不得把 `--hide-zero` 的“隐藏零欠款”自动解释为“本期欠款不为0”。缺少本期字段时明确报告限制，不要推算。

## 客户对账单导出

优先通过对账列表查找客户和对账记录：

```powershell
ailit report customer-check list --keyword "张三" -s 2026-08-01 -e 2026-08-31 --format json
```

处理结果：

1. 零结果：说明在条件和日期范围内没有对账记录。需要区分“客户不存在”与“本期无记录”时，再运行 `customer search`。
2. 唯一结果：取得稳定 `company-id` 和客户名称。
3. 多结果：展示名称、联系人等字段让用户选择，不得默认第一条。

需要明细时运行：

```powershell
ailit report customer-check detail <company-id> -s 2026-08-01 -e 2026-08-31
```

生成官方客户对账单 PDF URL：

```powershell
ailit customer print pdf <company-id> -s 2026-08-01 -e 2026-08-31 --format json
```

从结果中提取 URL，使用宿主下载能力保存到用户指定目录。默认文件名：

```text
<客户名称>对账单.pdf
```

用户指定命名时服从用户。目标文件已存在时不得静默覆盖。

## 批量客户对账单

以“累计欠款前10且本期欠款不为0”为例：

1. 使用 `customer-check list --format json` 获取足够的候选记录；不要过早用 `-z 10` 截断。
2. 按本期欠款字段过滤非零记录。
3. 按累计欠款降序排列并取前10。
4. 为每个客户取得稳定 `company-id`。
5. 逐个生成 PDF URL、下载文件并验证大小大于0。
6. 逐项记录成功、失败和跳过原因；失败项不要自动重试。
7. 汇总成功数、失败数、日期范围和保存目录。

## 供应商对账

```powershell
ailit report supplier-check list --keyword "供应商名称" -s 2026-08-01 -e 2026-08-31 --format json
ailit report supplier-check detail <company-id> -s 2026-08-01 -e 2026-08-31
```

当前 CLI 没有供应商官方对账单 PDF 命令。用户要求供应商 PDF 时：

1. 完成列表和明细查询。
2. 说明只能返回供应商对账明细，不能生成官方 PDF。
3. 不得错误调用 `customer print pdf`，不得声称文件已生成。
4. 用户另行同意时，可以把明细整理为非官方本地文件，但必须明确标注。

## 验证与交付

- 核对对象名称、日期范围、累计欠款和导出结果。
- 列表、明细与 PDF 金额不一致时停止后续批量交付，报告差异。
- 文件实际存在且大小大于0后才能报告“已保存”。
- 只取得 URL 时只能报告“已取得下载链接”。
- 成功回复包含对象、日期、文件名和绝对路径。

## 场景示例

会触发：

- “把累计欠款前10、而且本期欠款不为0的客户对账单分别保存到这个文件夹。”
- “查询张三7月份欠款，生成对账单PDF并保存为张三对账单。”

不会触发：

- “查张三本月欠款。”
- “列出本月欠款客户。”
