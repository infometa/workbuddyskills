# 发票查验工作流清单

按顺序勾选，任何一步卡住就停下问用户，**不要靠"多试几次"推进**——每次尝试都消耗该票当日配额。

## 0. 前置检查

- [ ] 连接器 `wpe-general-connector`（腾讯数电发票）已加载？没加载就按名称去连接器列表加载该 MCP
- [ ] 首次调用不带 token 探活，返回 401 → 停下提示用户完成 MCP 授权，通过后再继续
- [ ] 连接头 `X-Subject-Id` 的税号已接入（access_status=00）？未接入会 403 / -32007

## 1. 要素收集

入口判断：用户给的是 **PDF/PNG/JPG 文件** 还是 **文字要素**？

- [ ] 文件入口 → 用视觉能力直接读文件（PDF 读不清先 `scripts/prepare-image.mjs` 转 PNG）
- [ ] 按 `templates/ocr-fields.md` 提取要素并**输出识别表给用户确认**（未确认不发起查验）

- [ ] `InvoiceNo` 发票号码（数电票 20 位，逐位核对 0/O、1/I）
- [ ] `InvoiceDate` → **已转成 `yyyyMMdd`**（例：2026-09-16 → 20260916）
- [ ] `Amount` 单位【分】（`元 × 100`），且**口径与票种匹配**：
      31/32/61/83 价税合计；01/09/23、04/10/24、11/14 不含税金额（04/10/24 可置 0）；03/15 车价合计
      → 用 `node scripts/calc-amount.mjs <票种> <元>` 换算
- [ ] `InvoiceType` 票种代码 → **不确定就问用户，禁止批量扫描**
- [ ] `InvoiceCode`：数电票可空，其余票种必填
- [ ] `CheckCode`：`24` 取全电号码后六位；04/09/10/11/14 取校验码后六位；其余传 `""`

## 2. 首次查验

- [ ] 单次单票种发起，记录 RequestId
- [ ] 超时 → 脚本自动重试 2 次（退避 2s → 4s），无需人工干预

## 3. 判读分支

- [ ] `Error == null` 且 `Data` 有值 → 走报告模板 A，逐项比对票面
- [ ] 中文 Message → 查 `references/api_protocol.md` 对照表 → 走报告模板 B
- [ ] 三次仍无票面 → 走报告模板 C，**如实告知用户未取到票面**
- [ ] 403 / -32007 → 走报告模板 D

## 4. 疑难排查（仅在目标票查不通时）

- [ ] 用 `call_internal_api(api="invoice_check", ...)` 对目标号码做 +1 对照实验（占 2 次配额）
- [ ] 对照"不存在" → 票有记录，问题在票种/金额口径 → 确认后**单票种**重查
- [ ] 对照"不规范" → 修日期格式

## 5. 收尾

- [ ] 输出含税局原文 Message + RequestId
- [ ] 涉及税率的，连同税收优惠类型一起说明（可配合 `intelligent-tax-code-match` 技能核税编）
- [ ] 未取到票面的，明确写"无法判定真伪"并给出重试时间建议
