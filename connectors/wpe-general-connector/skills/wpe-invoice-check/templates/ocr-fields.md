# 图片 / PDF 发票要素识别模板

用户上传 **PDF / PNG / JPG** 发票文件时，用多模态视觉能力直接阅读文件，按下表提取要素。

## 1. 提取字段（位置 / 关键词）

| 待提取字段 | 位置 / 关键词 | 输出要求 |
|---|---|---|
| 发票类型 | 标题区，如「增值税专用发票」「增值税电子普通发票」「电子发票（普通发票）」「数电票」等 | 映射为枚举值（见 SKILL.md §1.2） |
| 发票代码 | 右上角「发票代码」 | 10-12 位；数电票/电子发票没有则置空 |
| 发票号码 | 右上角「发票号码」 | 数电票为 20 位长号码，逐位核对 |
| 开票日期 | 右上角「开票日期」 | **紧凑 `yyyyMMdd`**，如 2026 年 9 月 16 日 → `20260916` |
| 金额 | 见 SKILL.md §1.4 票种口径 | 记录「取的哪一栏」（不含税金额 / 价税合计 / 车价合计）+ 原值（元） |
| 校验码 | 右下角「校验码」 | 取**后六位**；部分票种无校验码则置空 |

## 2. 识别结果输出模板

```
已从文件识别出以下要素，请核对后我再发起查验（查验次数有限，错了会占用配额）：

| 字段 | 识别结果 | 置信 |
|---|---|---|
| 发票类型 | 电子发票（普通发票） → 32 | 清晰 |
| 发票代码 | （数电票无） | — |
| 发票号码 | 26507200000011978330 | 清晰 |
| 开票日期 | 2026-09-16 → 20260916 | 清晰 |
| 金额口径 | 价税合计 | 清晰 |
| 金额 | 9.00 元 → Amount=900 分 | 清晰 |
| 校验码 | （该票种可省略） | — |

以上哪一项有误？确认无误我就开始查验。
```

## 3. 常见识别坑

1. **日期**：票面「2026 年 09 月 16 日」必须转成 `20260916`，带分隔符会报「查询发票不规范」。
2. **号码**：20 位数电票逐位核对；`0/O`、`1/I/l`、`8/B` 易混，模糊时**必须问用户**。
3. **金额栏别选错**：票面上「金额」「税额」「价税合计」三栏相邻，
   按票种口径取：31/32/61/83 取「价税合计」；01/09/23、04/10/24、11/14 取「金额」（不含税）；
   03/15 取「车价合计」。
4. **校验码**：只要**后六位**；`24` 票种取全电号码后六位；其余可省略票种传 `""`。
5. **单位**：识别到的是「元」，发起查验前必须 ×100 转「分」（`node scripts/calc-amount.mjs <票种> <元>`）。

## 4. 识别后流程

1. 输出上表 → 等用户确认（**不要未确认就发起查验**）。
2. `node scripts/calc-amount.mjs <票种> <元>` 换算 `Amount`。
3. 用连接器 `wpe-general-connector` 的 `call_internal_api(api="invoice_check", params={...})` 发起查验。
4. 按 `templates/report-template.md` 输出结果与逐项比对。
