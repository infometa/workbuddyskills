# MCP 分层对账结果模板

## 结果口径

- 数据来源：本地 Amazon CSV 与 eccang-mfc-reconcile MCP。先查 `queryFmsTransaction`；费用项有差异时自动查 `queryFmsTransactionDescription`，再查差异原始 types 的 `queryFmsTransactionDetail`。
- 成功标题：“对账完成，类型汇总金额匹配”；差异且流程成功：“对账完成，类型汇总金额存在差异”。
- 汇总后发生失败：“对账流程未完成；类型汇总金额存在差异”（或“匹配”），保留已知汇总事实，但不导出正常报告。
- 已支持类型汇总比较及描述、订单差异定位。全费用及显式附加查询尚未启用；财务记录总数显示“未查询”，不能用类型数量替代。
- CSV 数量为全部交易记录行数；订单对比的来源记录数为该订单与费用组内实际记录数；描述接口数量为汇总条目数。这些均不是去重订单数。
- 金额比较排除 Transfer，并应用既有类型映射、合并及两位小数规则；总金额相等不能掩盖费用项差异。
- 控制台和 Excel 共用实际查询上下文及比较结果。汇总或订单聚合匹配不代表交易逐笔一致。

## 控制台报告

```text
${结果标题}

数据来源：eccang-mfc-reconcile MCP / queryFmsTransaction
客户代码：${company_code}
店铺：${user_account}
平台：${platform}
时间口径：${date_label}
账单开始时间：${start_time}
账单结束时间：${end_time}
CSV 交易记录数：${excel_row_count}
MCP 财务记录总数：未查询
CSV 总结算金额(total)：${excel_total_sum}
MCP 财务总结算金额(total)：${db_total_sum}

日期范围：
   date_start_time：${date_start_time}
   date_end_time：${date_end_time}
   transaction_start_date：${transaction_start_date}
   transaction_end_time：${transaction_end_time}

Type 对比汇总（按 |total| 降序）：
   type                         CSV total       MCP total   结果
   ${type_rows}
   合计                         ${excel_total_sum} ${db_total_sum}

范围说明：Transfer 不参与金额对比；CSV 记录数包含全部交易行。
CSV 定位记录回勾：${local_status}
描述分析：${description_status}
订单定位：${order_status}
全费用明细：未执行（尚未启用）
${差异下钻内容或汇总匹配范围说明}
```

`type_rows` 展示双方金额、匹配状态、差额及合并说明。保留的 `db_total_sum` 变量名仅表示远端财务金额，不意味着数据库直连。

## 差异下钻展示

1. 展示差异比较组与全部实际原始 types 的对应关系，不向接口发送合并显示名称。
2. 描述构成按“比较组 + description”显示双方金额、差额、来源数量及原始 type/description。只规范两端空白，不翻译或模糊匹配；空值单独分组。缺 description 列时 CSV 金额显示“不可比较”，仅展示远端构成，继续订单定位。
3. 订单按“订单号 + 比较组”累计，不去重交易。输出“仅 CSV 有／仅 MCP 有／金额不同”，附双方金额、差额、来源记录数及 CSV 物理起始行号。比较覆盖差异类型的完整返回集合，不能声称按描述查询或逐笔配对。
4. 空订单号按费用组单列，并附 CSV 描述与行号，不伪造订单。CSV 单边类型单列“远端汇总缺少该类型”及本地记录，不伪造原始类型，不推断缺单。
5. 状态为“未执行／完成／部分可比较／失败”。汇总匹配时不执行描述或订单定位；CSV 缺描述列、无可查询远端类型时注明部分可比较；回勾失败停止后续确定性结论。
6. 各层按原始类型及比较组回勾。回勾不能排除正负抵消的漏记录，描述差异不能直接证明缺单；不把任何聚合结果升级为逐笔完整性证明。

## Excel 导出

仅在明确指定 `--output <文件路径.xlsx>` 且当前流程未失败时生成。默认不生成任何业务结果文件。

工作表“对账结果”包含：
1. CSV 日期范围、实际查询口径和起止时间、公司、店铺、平台及数据来源。
2. CSV 交易记录数、MCP 财务记录总数“未查询”、双方金额合计。
3. 类型汇总结论、逐笔一致性边界、`type / CSV total / MCP total / 结果` 对比表。
4. 存在汇总差异时追加 `type / CSV total / MCP total / 差额` 表。
5. 与控制台一致的分层状态、描述构成、订单差异及空订单号/CSV 单边类型说明；导出不重新查询或比较。

## 执行失败与验收

输入、接口、响应、时间、回勾、会话或导出失败返回 `1`；当前流程成功且存在汇总差异返回 `2`；汇总匹配且流程成功返回 `0`。argparse 参数错误仍返回 `2`。失败时不生成伪造零金额、不导出正常完成报告；显示具体失败层，不展示凭据或原始敏感响应。

已有两份真实账单按入账口径执行过汇总、描述及订单层对账，不代表所有站点、结算口径、全费用或逐笔一致性已验收。其他响应包装、时间字段与 CSV 的业务对应、大结果集及费用归类差异仍需获准账单和脱敏响应确认；不能仅因总额相等宣布完全一致，也不自动修改映射。离线合成数据及 SDK 内存服务测试不构成真实业务证明。
