# 任务状态与异常处理

## 查询正确的任务

`get_task_status` 一次查询一个任务，参数是 `{"task_id": "真实任务ID"}`。ID 来自当前用户生成响应的 `taskId/taskIds`，或用户明确提供的待查询任务 ID；不要使用 `conversationId`、`messageId`、结果 URL 或自行编造 ID。

工具描述的任务 ID 为 32 位无连字符 UUIDv7。客户端可以校验格式以发现误传，但不能推断所有权；服务端授权失败时不尝试绕过或查询别人的任务。

| `status` | 处理 |
|---|---|
| `PENDING` | 已提交、待投递，继续等待 |
| `RUNNING` | 运行中，可展示返回的 `progress`，不能当成完成 |
| `SUCCEEDED` | 停止轮询，读取 `resultUrl`，否则读取 `results[].fileUrl` |
| `FAILED` | 停止轮询，解释经脱敏的 `errorMessage`，不自动新建任务 |
| `CANCELLED` | 停止轮询，说明已取消；不推断是否退款 |
| 缺失或未知 | 明确状态无法识别，保留 ID，不判成功、不新建替代任务 |

## 有限轮询

- 同一任务两次查询间隔约 3 秒。一次等待窗口最多 30 轮或约 90 秒，以先到者为准；这是本 Skill 的等待预算，不是服务端生成超时。
- 多任务每轮只查询尚未终结的 ID；已成功/失败/取消的任务不再查。等待过程中定期简短说明仍有任务运行。
- 达到等待预算后，交付已有结果及剩余 ID，明确其仍在运行，用户说“继续查”时续查这些 ID。没有后台调度能力时不承诺自动通知。
- `429` 遵循 `Retry-After`；只读查询的临时网络错误或 `5xx` 最多重试 2 次，分别等待约 3 秒、6 秒。仍失败或要求等待超过本窗口时，结束本轮并保留 ID。
- `SUCCEEDED` 但无结果地址时最多再查一次；仍无地址则说明“服务返回成功，但尚未返回可交付链接”，不生成虚假结果或重新提交。

## 提交失败的区别

| 情况 | 下一步 |
|---|---|
| 未授权、登录过期 | 完成WorkBuddy 内跳跃视界重新授权；有任务 ID 时恢复查询，不先重做 |
| 余额不足、账户不可用 | 停止新生成，说明余额或账户状态；不代用户充值 |
| 参数被明确拒绝，且确认没有创建任务 | 按当前工具说明修正；不改动用户的模型、数量、时长、素材或预算。最多修正一次，仍失败则说明原因 |
| 网络断开、请求超时、含糊的 `5xx` | 不能推断未创建任务。有 ID 就查；无 ID 则提示到跳跃视界核对生成记录，本次停止自动提交 |
| 批量返回部分 ID | 查询已知 ID，说明其他项提交状态未知；不把整批再发一次 |
| 任务终态失败 | 交付错误及任务 ID；解释可调整项，由用户决定是否发起新一轮收费生成 |

当前四个工具没有取消、退款、任务列表、费用试算、上传或客户端幂等键能力。不能通过猜测字段、重复生成或虚构工具弥补。错误信息可能带内部地址或凭据，只报告用户需要的业务原因，不原样倾倒完整响应。
