# 错误处理与失败分流（references/error-handling.md）

> 加载时机：工具返回失败信封（`ok=false`）、HTTP 401、连续失败、用户要求未暴露能力时加载。
> 信封形态见 [`mcp-envelope.md`](mcp-envelope.md)。

## 1. 错误形态总表

工具返回带 `content[0].text` 信封（`kind=mcp-tool-content`，契约见
`tool-catalog.md`「返回信封」/ `mcp-envelope.md`）。**失败时 `ok=false`，原因在
`error.message`，协议层同时 `isError=true`**。有 `structuredContent` 的成功调用业务不在
失败分支讨论。`error.message` 正文仍是三类。告知用户失败时，把信封 `requestSeqNo`
的值附在句末即可，不要解释该号码。

| 形态 | 来源 | 含义 | 你的动作 |
|---|---|---|---|
| `未识别到登录员工身份，请重新授权连接` | 身份校验 | token 失效/缺失，或登录态解析不到员工 | 走 `cli-connection.md`：先 `fh auth refresh`；仍失败则助手前台登录（Windows：`auth-login.cmd`；macOS/Linux：`sh auth-login.sh`）。退出码 3 是未登录。命令找不到时读 stderr 的 `[fh]` 行，技能目录即本 `SKILL.md` 所在目录，不要全盘搜索。**不要**重试同一调用，不要让用户自己找安装目录 |
| `业务错误: {message}` | 业务校验 | 请求语义不合法（参数缺失/状态不允许/业务规则拦截），message 可安全转述（意译，不念原文字段名） | 按业务语义纠正：缺前置回前置阶段，参数错改参数，规则拦截如实告知 |
| `工具调用失败: {异常类名}` | 服务端内部异常（已脱敏） | 非业务性故障（超时、下游异常等） | 同一调用最多**重试 1 次**；再失败如实告知「服务暂时异常，请稍后再试」并建议转人工 |

HTTP 层：

| 状态 | 含义 | 动作 |
|---|---|---|
| 401 + `WWW-Authenticate: Bearer resource_metadata="..."` | 未认证 | 按响应头元数据发现授权服务器，走授权流程；禁止带旧 token 盲重试 |
| 400（token 端点） | 缺 `code=` 空占位 / 缺 `client_id` / grant_type 不支持 | 按 `cli-connection.md` §认证/§常见问题 修正请求形态，不是业务错误 |
| 429（register） | 单 IP 单日注册超 20 次 | 次日再试，或改用运维预置 client |

## 2. 国内查询失败分流

| 场景 | 识别 | 分流 |
|---|---|---|
| 查询通道失败 | 「工具调用失败…」/ 超时 | 说「查询失败」而非「没有航班」；重试 1 次 |
| 查询结果为空 | 正常返回但 flightList 空 | 如实告知本次无匹配。往返且 serialNumber 空串时不要断言该日期无航班（可能上游空壳），不要为此重跑或拆两次单程 |
| 城市/航司码被拒 | shopping 业务错误且代码可疑 | 用 `air_city`（scope=DOMESTIC）/ `domestic_airline_resolve` 重新取码后重查，禁止继续用猜的码 |
| 用户要下单/支付/退改/查订单 | 自然语言诉求 | 能力未暴露：说明只能查询与选舱，引导去飞鹤 portal 完成；不得伪造写操作 |

## 3. 国际查询失败分流

| 场景 | 识别 | 分流 |
|---|---|---|
| 城市代码被拒 | shopping 业务错误/空结果且代码可疑 | 用 `air_city`（scope=INTERNATIONAL）关键词检索重新取码后重查（禁止继续用猜的码） |
| 结果为空 | groupList 空 / 文本「未查到符合条件的航班。」 | 如实告知，建议改日期/放宽中转、舱等、航司 |
| HTML 未返回 | 结果只有文本 | 回退展示实际文本；**只有结果明确标记错误才算查询失败** |
| 选舱位报「航班数据已过期」 | serialNumber 失效 | 回查询阶段重查，用当次新 serialNumber + priceId 重新选舱 |
| 跳转后页面报错/未登录 | portal 侧现象 | 按 `sso-forward.md` 处理；portal 页内问题按 portal 提示 |
| 用户要核价/政策/申请单/创单 | 自然语言诉求 | 读 `air-intl-capability-gap.md` 如实说明能力未暴露，引导去 portal 完成 |
| 用户要支付/出票/改签/退票 | 自然语言诉求 | 超边界：说明只能查询与跳转下单，引导去飞鹤 portal 或转人工 |

## 4. 重试与降级纪律

1. **同一调用最多重试 1 次**（仅「工具调用失败」/超时类）；业务错误（「业务错误: …」）
   **不可重试**——必须改变输入或回退阶段。
2. 连续 2 次失败 → 停止重试，如实告知并建议转人工；**禁止**为「显得有用」换工具乱试。
3. 运行时缺少文档中列出的工具（如下线的写链路工具）→ 不得伪造调用，按实际能力降级：
   能查询就查询，不能就引导去 portal，并如实说明当前无法完成的部分。
4. 身份类错误（401 / 重新授权提示）修复的是**连接**，不是参数；修好连接后从被中断的
   阶段继续（serialNumber 等仍有效则可续用，失效则重查）。
5. 对用户只说结论与建议，**不念**：工具名、字段名、错误码、异常类名、接口路径。

## 5. 红线（任何错误下都不得违反）

- 不得编造航班、舱位、价格、政策结论、订单号、支付链接、工单号。
- 不得声称已完成验价、政策校验、申请单匹配或创单——这些能力当前未暴露。
- 不得把查询失败说成「没有航班」。
- 不得承诺「已下单 / 已出票 / 已支付 / 一定有位」——下单与后续状态以 portal 为准。
