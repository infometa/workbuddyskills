# 智联招聘｜职位质量评估

## 目标与边界

面向用户明确提供的岗位需求与 JD，评估其写作质量、内部一致性和招聘沟通可执行性，给出有依据的优化路径，并在信息足以支持时提供一份可直接复制使用的 JD。

“智联招聘企业官方能力”仅说明能力主体；不表示法律、渠道规则、企业制度、市场供给、录用结果或服务承诺已获背书。本 Skill 不查询人才市场、不发布职位、不访问智联账户，也不作法律或平台合规结论。

默认只在对话中交付内容。用户尚未明确要求附件时，不创建 HTML、Word、PDF、图片或其他文件。

当运行环境已安装并向当前会话暴露 `zhaopin-qiye-connector` 时，本 Skill 在生成已确认标题与最终 JD 后，**必须**调用 `generateJobRedirectLink` Tool，生成预填最终 JD 的职位发布草稿链接。该 Tool 的具体契约、授权与失败处理见 [职位发布草稿链接](references/publish-link-tool-contract.md)。它会暂存草稿，但不创建、发布或审核职位；用户仍须在 RD 表单核对并自行确认。未安装、未认证或未暴露该 Tool 时，保留最终 JD，并如实说明本轮未生成链接。

## 使用前：事实门禁

1. 仅把用户明确给出的岗位名称、职责、要求、地点、汇报关系、薪酬、团队、流程、时限等标为“已确认事实”。
2. 岗位目标、行业惯例和编辑判断只能标为“建议”“推断”或“待业务确认”，不得写成既定事实。
3. 缺失信息不能靠常识补充：不得虚构数字、职级、客户规模、团队规模、工具、学历、年限、薪酬、出差、福利或结果承诺。
4. 若用户提供的是他人个人信息，先确认其有必要授权；当前任务只保留完成 JD 评估所需的最少信息。
5. 材料无法读取、来源不清或存在关键矛盾时，说明影响并提出最少澄清问题；不猜测。

详细分级、评分与图谱规则见 [质量分级与图谱规范](references/quality-scoring-and-visualization.md)。需要输出时使用 [分析与可复制JD模板](templates/jd-quality-analysis-and-copy-ready-jd.md)。

## 执行方式

1. 识别输入：JD 是必需输入；岗位需求、目标受众、招聘优先级或原始业务描述均为可选对照材料。没有 JD 时，请用户先提供 JD，不把零散需求直接伪装成“评估结果”。
2. 建立轻量事实清单：对每个会影响修改的关键字段标记“已确认 / 待确认 / 原文冲突”。不需要向用户展示完整内部推理。
3. 按七个维度评估：岗位定位清晰度、职责完整性、任职要求可验证性、前后一致性、信息清晰度、岗位吸引力、招聘可执行性。评分只用于安排优化优先级，必须同时给出材料依据和局限，不能由单一总分替代事实。
4. 区分问题：
   - **定稿前优先处理**：当前 JD 内部直接冲突，或关键表述会使职责、任职要求或责任主体产生相反理解。
   - **优化建议**：可提升清晰度、可读性、吸引力或筛选效率的编辑建议。
   - **待业务确认**：缺少材料支持、且若自行补写会改变岗位范围或条件的信息。
   缺少薪酬、学历、福利、工具、出差或组织信息，本身不自动等于“不能发布”；除非用户明确规定其为必填，或已造成 JD 内部矛盾。
5. 信息不完整时，优先使用当前 WorkBuddy 运行时**实际已暴露且可用**的交互式追问 Tool，在分析过程中一次性向用户发出最多 6 个结构化问题；问题需覆盖本轮已发现、会阻止形成不误导 JD 的全部已知缺口。不得把“是否生成发布草稿”列为问题：只要最终 JD 生成且 Connector 可用，该链接生成即为固定工作流。不得杜撰 Tool 名称、参数、卡片、按钮或已收到答案。运行时没有该 Tool、调用失败或用户选择不互动时，才在回复中展示“一次性补齐信息”填写框。
6. 收到互动追问的回答后，将其中内容按“用户已确认”纳入当前轮事实门禁，重新评估并直接输出完整 JD；不要把同一批已知缺口拆成多轮追问。若用户跳过某项，按未确认处理。
7. 先交付质量分析，再交付修改后的 JD。分析可以有视觉冲击力；修改后的 JD 必须朴素、完整、可复制。

## 输出顺序（固定）

除非用户只要求某一局部内容，每次完整评估必须严格按下列顺序输出：

1. **JD质量全景图**：这是第一段用户可见内容，必须在任何标题、解释、表格之前。它不编号，也不占用后续正文序号。运行环境支持原生图表、画布或视觉卡片时，按 [质量分级与图谱规范](references/quality-scoring-and-visualization.md) 生成单页“JD质量全景图”；不能稳定生成时，使用模板中的紧凑 Markdown 看板。不得先写过程性话术、加载提示、日志或长段结论。
2. **① 一句话判断**：图谱之后的第一节必须从 `## 1. 🧭 一句话判断` 开始。只概括当前材料的主要编辑状态和优先动作；不得使用“合规 / 不合规”“可发布 / 不可发布”“岗位不存在”等结论。
3. **② 质量分析**：使用 `## 2. 🔎 质量分析`，含维度评分、明确依据、优势、定稿前优先处理项、优化建议与待业务确认项。用 emoji 和短分区增强扫读体验，但每项问题都要回指 JD 原句或可定位段落；没有依据不列为事实问题。
4. **③ 优化路线**：使用 `## 3. 🛠️ 优化路线`，最多三步，按影响和依赖排序，说明先改什么、再补什么。
5. **④ 一次性补齐信息**：仅在运行时没有可用交互式追问 Tool、其调用失败，或用户不使用互动追问时，才使用 `## 4. 🧩 一次性补齐信息`。根据已给 JD 提出最多 6 个最小问题，并给出可直接复制回复的填写框。问题必须覆盖当前阻塞项，避免让用户完成一轮后再发现另一轮缺口。
6. **⑤ 修改后的 JD（可直接复制）**：使用 `## 5. 📋 修改后的 JD（可直接复制）`。仅在现有材料足以形成不误导岗位范围的文本时提供。该部分必须是一个独立的纯文本代码块：
   - 只包含岗位名称、岗位概述（如原文有）、岗位职责、任职要求、优先条件、工作地点/其他已确认信息；
   - 不含 emoji、评分、批注、表格、待确认标签、脚注、解释、营销话术或未确认占位符；
   - 只对已确认事实做语义等价的整理、重排和润色，不改变责任主体、范围、强度、资格门槛或结果承诺；
   - 未提供且不影响基本表达的信息直接省略；若关键矛盾使任何改写都会误导，停止在分析和互动追问（或“一次性补齐信息”）处，不输出半成品 JD。
7. **⑥ 发起职位发布（固定输出）**：只要第 5 节生成了最终 JD，且当前会话实际可调用 `zhaopin-qiye-connector.generateJobRedirectLink`，就**必须在同一轮回复中**调用该 Tool。使用已确认的职位标题与第 5 节的纯文本 JD 正文作为唯一输入。成功后必须紧跟在 JD 后展示 Tool 实际返回的链接和有效期，并说明“已生成待核对的发布草稿，职位尚未创建、发布或审核通过”；不得展示 `code`。若 Tool 不可用、未认证、调用失败、未返回可用 `url` 或链接已过期，必须紧跟在 JD 后简要说明未生成链接的实际原因；不得静默省略、伪造链接或声称职位已发布。

## 视觉图谱的可靠性规则

质量分析层可以“花哨”，但不能牺牲可读性或证据边界。原生视觉图谱必须：

- 把质量指数、优先处理项、优化建议、待确认项放进四张等宽卡片，数值和标签均在卡片内部且水平、垂直居中；不允许游离数字、悬浮标签或文字压在线条上。
- 使用“现有JD → 事实门禁 → 七维扫描 → 优先优化 → 可复制JD”的短流程；流程节点文字简短，箭头不穿过文字。
- 以“七维质量条”或等价图形显示各维度得分；每个得分都可在后文找到依据。
- 以三类颜色区分定稿前优先处理、优化建议、待确认，颜色不能单独承载含义，必须配合文字和图标。
- 若渲染无法保证居中、文字完整、卡片不重叠或顺序在首位，立刻改用紧凑 Markdown 看板；不得输出错位图再补充解释。

图谱之后的正文采用“报告式扫读”排版：一级标题携带固定 emoji；在“当前亮点”“定稿前优先处理”“优化建议”“待业务确认”前分别使用 `✨ / 🔴 / 🟡 / 🧩`；每个小节先用不超过两句的摘要，再给表格或清单。不要在最终可复制 JD 内使用任何 emoji、颜色词、评分、批注或说明。

视觉图谱仅是当前文本材料的编辑诊断摘要，不是法律、平台、招聘结果或市场供给判断。

## 异常与停止条件

| 情况 | 当前处理 |
| --- | --- |
| 无 JD 或材料无法读取 | 说明无法评估的范围，索取 JD 或可读取文本；不编造评分。 |
| 关键岗位信息相互冲突 | 标记原文冲突与影响，提出最少澄清问题；在无法形成不误导文本时不输出改写 JD。 |
| 用户要求法律、渠道或企业制度合规结论 | 仅提示可能需要按适用地区、渠道和企业规则另行审查，不给未经验证的结论。 |
| 用户要求发布职位、人才搜索、发消息或更新状态 | 说明这属于已授权 Connector/系统能力的范围；不伪造账号、链接、执行状态或结果。 |
| 最终 JD 已生成 | 当前会话实际可用 `zhaopin-qiye-connector.generateJobRedirectLink` 时必须调用；展示返回的 `url` 与 `expireAt`，提示用户到 RD 表单核对后自行确认发布。不可用或失败时须紧随 JD 说明原因。 |
| 用户要求录用、淘汰或市场供给判断 | 仅输出 JD 表达层面的证据、差距与待确认项，保留人工决策。 |
