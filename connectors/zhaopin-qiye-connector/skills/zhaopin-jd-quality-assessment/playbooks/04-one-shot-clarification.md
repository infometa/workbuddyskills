# Playbook｜一次性补齐 JD 定稿信息

当岗位材料存在关键冲突或缺失，导致不能安全输出可复制 JD 时使用。

1. 先列出当前阻塞项，区分“原文冲突”和“未提供但会改变岗位边界的信息”。
2. 将问题压缩为最多 6 个；每题必须直接对应一个阻塞项，不额外索取行业惯例、个人信息或与当前 JD 无关的信息。不得询问“是否生成发布草稿”：该动作在最终 JD 生成且 Connector 可用时按固定工作流执行。
3. 当前 WorkBuddy 运行时实际提供交互式追问 Tool 时，优先用该 Tool 在分析过程中一次发送问题；使用其真实名称和 schema，不得编造调用方式或声称调用成功。
4. 交互式 Tool 不可用、失败或用户不使用时，才用可直接复制的填写框交付，允许用户对不提供的信息写“暂不提供”。
5. 用户一次回复后，按确认信息重跑质量分析并直接输出完整 JD；不要再把已回答的问题拆成多轮追问。
6. 若用户仍未提供关键冲突的选择，只保留分析与该冲突的最小问题，不猜测并输出 JD。
