# 质量分级与图谱规范

## 七维评分口径

评分对象仅是当前输入材料的**编辑质量与内部一致性**，不是人才市场供给、法律合规、企业政策或最终招聘成效。每一维以 1–5 分表示：

| 分数 | 含义 |
| --- | --- |
| 5 | 当前材料清楚、完整且可由原文支撑。 |
| 4 | 基本清楚，可做轻量编辑优化。 |
| 3 | 可以理解，但有影响沟通或筛选的缺口。 |
| 2 | 存在明显模糊、遗漏或前后张力，建议优先处理。 |
| 1 | 当前材料存在直接冲突或无法据此稳定理解该维度。 |

维度与关注点：

| 维度 | 关注点 |
| --- | --- |
| 岗位定位清晰度 | 名称、级别、汇报关系、岗位目标是否互相支持。 |
| 职责完整性 | 核心工作、边界、协作对象与结果表述是否足以理解。 |
| 任职要求可验证性 | 必备与优先条件是否清楚、可理解且不混淆。 |
| 前后一致性 | 名称、职责、条件、地点、时间与责任主体是否存在直接矛盾。 |
| 信息清晰度 | 句式、层级、术语、重复和歧义是否影响阅读。 |
| 岗位吸引力 | 已提供信息是否有效说明工作价值和机会；不以未提供薪酬或福利自动扣分。 |
| 招聘可执行性 | JD 是否足以支持候选人沟通和初步筛选；不推断市场是否一定有人。 |

可展示“质量指数”为七维分数之和（满分 35），但它必须紧邻“仅用于编辑优先级”说明；后文必须展开各维依据。材料不足时用“未评分”替代猜测性分数。

## 问题分级

| 类型 | 定义 | 输出方式 |
| --- | --- | --- |
| 定稿前优先处理 | 同一 JD 中存在可定位的直接冲突，或关键措辞会导致职责、条件、主体有相反理解。 | 标红，引用原文位置、影响、最小修正方向；不把它称为法律或发布阻塞。 |
| 优化建议 | 可提升清晰度、可读性、吸引力或沟通效率的编辑改进。 | 标黄，说明改前问题与建议改法。 |
| 待业务确认 | 材料未提供，且擅自补写会改变岗位边界、门槛或承诺。 | 标蓝/灰，说明为何需要确认；不写入最终 JD。 |

不要把“行业通常会写”“未写薪酬/福利/学历/工具”本身升级为优先处理项。没有明确证据时，不将偏好称为硬性要求。

## 原生视觉图谱

只有运行环境确实支持图表、画布或视觉卡片时才生成。图谱位于回复第一屏，顺序固定如下：

1. 标题行：`JD质量全景图｜<岗位名称或“岗位名称待确认”>` 与一行材料范围。
2. 四张等宽卡片：`质量指数`、`定稿前优先处理`、`优化建议`、`待业务确认`。
3. 一行流程：`现有JD → 事实门禁 → 七维扫描 → 优先优化 → 可复制JD`。
4. 七维质量条：每维名称、1–5 分和短标签；不得只有颜色。
5. 两个简短信息区：优先处理前三项、下一步三步路线。

图谱不编号。其后的文字报告从 `1. 🧭 一句话判断` 开始，依次使用 `2. 🔎 质量分析`、`3. 🛠️ 优化路线`、`4. 🧩 一次性补齐信息`（仅有缺口时）和 `5. 📋 修改后的 JD（可直接复制）`。这样图谱不会造成正文从“第 2 节”开始的错觉。

强制排版：

- 所有卡片使用相同宽高；图标、名称、数字均放在同一卡片内，居中对齐。
- 文字不超过卡片可容纳范围；长名称改用短标签，完整名称留给正文。
- 连接线仅连接节点中心，不能遮挡文字；不使用浮动标题或悬浮说明。
- 视觉失败或空间不足时，输出下方 Markdown 看板，不尝试低质量图像。

```text
JD质量全景图｜<岗位名称或“岗位名称待确认”>
材料范围：<仅描述实际收到的材料>

┌────────────┬────────────┬────────────┬────────────┐
│ 质量指数   │ 优先处理   │ 优化建议   │ 待确认     │
│ <x>/35     │ <n> 项     │ <n> 项     │ <n> 项     │
└────────────┴────────────┴────────────┴────────────┘

现有JD → 事实门禁 → 七维扫描 → 优先优化 → 可复制JD
定位 <x>/5 ｜职责 <x>/5 ｜要求 <x>/5 ｜一致性 <x>/5
清晰度 <x>/5 ｜吸引力 <x>/5 ｜可执行 <x>/5
```

在事实不足无法评分时，把对应 `<x>` 写为“未评分”，并解释缺少什么；不要填默认分。
