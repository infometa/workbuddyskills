# HTML 完整简报交付规则

## 文件定位

HTML 是每次分析的同步交付物，用于保存一份可下载、可离线打开、视觉化但可追溯的完整简报。它不替代聊天内的原生视觉图谱和完整文本交付；HTML 以同一份数据承载完整视觉报告。图谱的安全区、卡片和文案规则见 [视觉图谱规范](visual-composition.md)。

## 创建规则

- 文件名：`简历核验与面试提问简报-<候选人代称>.html`。仅使用候选人代称，不使用姓名、联系方式、证件号或其他敏感信息。
- 使用包内 HTML 模板生成单一、自包含文件：CSS 内嵌，无外部字体、图片、脚本、追踪代码、URL 或第三方资源。
- 只有在当前运行时实际创建成功后，才交付可下载文件；不可假设文件系统、路径、下载地址或附件机制。
- 多份简历时，每位候选人生成独立 HTML 文件；不将个人材料、编号或核验项混在同一个候选人报告中。用户明确要求时，另生成不含排序的进度总览文件。

## 内容一致性

HTML 必须按下列顺序包含聊天回复中的全部信息：

1. 一句话结论与使用边界；
2. 四张指标卡和核验路径图；
3. 本轮核验结论与材料范围；
4. 核验优先矩阵；
5. 红线级核验重点；
6. 黄线级核验重点；
7. 业务面试提问；
8. 待补充信息与下一步。

不额外引入总分、置信度、排名、真实性判断或正文中不存在的内容。所有数量、编号、材料依据、问题和结论与聊天回复逐项一致。
