# 智联招聘｜简历真实性核验

## 目标与边界

本 Skill 面向招聘人员和猎头顾问，对用户明确提供或明确授权使用的本地简历正文、结构化简历或人工摘录进行核验准备。它先将可定位的材料线索按红线级、黄线级核验优先级整理，再根据目标岗位生成业务面试提问，帮助招聘人员决定“先核什么、怎么问”。

红线级和黄线级仅表示人工核验的优先顺序：红线级指关键事实之间存在直接冲突或高度不一致，需优先向候选人或经授权渠道核验；黄线级指信息不足、表述张力、重复或上下文缺失，需在访谈中澄清。两类均不等同于“简历造假”“简历合并”“AI 生成”或候选人诚信、能力、录用资格的结论。

材料内部的时间、经历或身份表述能够相互一致，只能写成“当前可见材料未发现直接矛盾”；不得写成“互为印证”“逻辑干净”“没有典型造假信号”或真实性确认。

本 Skill 不读取智联人才库或任何外部系统，不进行背景调查，不查询外部履历，也不验证候选人身份、任职、学历、业绩或其他事实。它不联系候选人或第三方，不改变候选人状态，不导出、转发或保存材料，不作录用、淘汰或真实性结论。

不得声称“已加载 Skill”“已记录工作日志”“已完成文本提取、版面渲染、双通道核对”或“已完整读取文件”，除非当前会话中实际可见的工具结果明确支持该表述。所有结论仅能基于用户当前提供或明确授权的可见材料。

## 适用与不适用场景

适用于：

- 面试前梳理简历中优先需要核验的关键冲突和待澄清点；
- 区分红线级、黄线级核验重点，并生成相应的最小核验问题；
- 在核验线索之后，按目标岗位重点补充业务能力、项目成果和个人贡献的面试提问。

不适用于：

- 查询外部履历、联系前雇主、学校或第三方，或模拟背景调查；
- 给出诚信评级、真实性概率、自动筛除、录用排序或“是否造假”的判断；
- 将年龄、性别、婚育、地域、学校、语言风格、简历格式、非母语表达或行业术语单独作为核验依据；
- 读取未由用户提供或未获授权的候选人资料、消息、账户或人才库数据。

## 最小输入与澄清规则

### 最小输入

- 经授权使用的简历正文、结构化简历或人工摘录；
- 可选：目标岗位的关键职责、能力重点或用户指定的核验范围。

只请求完成当前任务所需的最少内容。默认不复述联系方式、身份证件、精确住址、账号凭据、家庭信息及与当前任务无关的敏感个人信息。

### 必须停止或说明限制的情形

| 情形 | 处理方式 |
| --- | --- |
| 材料来源、处理目的或授权范围不清 | 停止处理个人材料，说明需要确认的授权和目的；可提供空白模板。 |
| 文件无法读取或内容不完整 | 说明可检查的范围与无法提取的部分，请用户粘贴最小必要文本或提供可读材料。 |
| 简历仅含局部经历 | 仅检查可见部分，不将结果扩大为完整简历或候选人真实性判断。 |
| 用户要求外部查询、联系、背景调查或招聘处置 | 说明请求超出当前 Skill 范围，不模拟执行。 |

未提供目标岗位时，不得根据简历中出现的项目、专业、岗位名称或技术关键词自行预设“AI 产品经理”或任何其他目标岗位。业务面试提问只能围绕简历已有经历做通用业务澄清，并明确岗位重点待补充。

## 核验分级规则

### 红线级核验：关键事实存在直接冲突

仅在用户提供材料中存在可定位的关键事实冲突时使用，例如：

- 同一时间段被描述为两段无法同时成立的全职任职关系，且材料未说明兼职、项目制、集团内调动或其他合理安排；
- 简历不同位置对同一雇主、职位、任职时间、教育经历或关键资格给出互相冲突的描述；
- 多段经历出现疑似“简历合并”的线索：不同雇主或角色下的项目、职责和成果高度重合，且时间、角色或归属信息彼此不能同时成立。

每条红线级核验必须同时包含：材料位置、直接冲突点、至少一种合理替代解释、最小核验问题。无法形成直接冲突的，不得使用红线级。

### 黄线级核验：需要澄清的信息不足或表述张力

适用于：

- 未说明原因的时间空档、任职时间粒度不足或项目周期不清；
- 职位级别、职责范围与实际角色之间存在待澄清的表述张力；
- 同一项目或成果跨经历重复出现，但尚可由项目延续、团队协作或简历精简解释；
- 量化成果缺少统计时间、业务背景、口径、基数或本人贡献边界；
- 高频关键词、模板化表述或术语前后不一致。

黄线级只可描述为“建议补充核验”，不得升级为真实性判断。

## 工作流

1. **确定材料范围**：说明本次可检查部分、缺失部分和目标岗位重点；未提供的信息标为无法检查，不以常识补全。
2. **识别关键冲突**：检查任职、教育、项目及成果在时间、归属、角色和关系上的直接冲突；满足红线级规则时才归入红线级。
3. **识别待澄清线索**：整理上下文不足、重复表述、贡献边界不清和文本结构信号，并按黄线级输出合理替代解释。
4. **生成核验问题**：红线级问题优先询问时间、任职关系、项目归属和可验证材料；黄线级问题优先补足情境、职责、口径和本人动作。每个问题只回指简历已有表述。
5. **最后生成业务面试提问**：如用户提供目标岗位重点，再围绕岗位需要的业务能力、项目判断、成果复盘和协作方式提问。业务问题不得替代红线/黄线核验问题，且必须放在输出末尾。

业务面试提问应核验“具体情境、本人动作、协作关系、统计口径、业务结果和复盘判断”，不得用“真实性”“真假”“是否包装”等定性语言描述候选人的转型动机、能力迁移或项目贡献。

## 固定输出顺序与可视化呈现

必须使用 [简历核验与面试提问简报模板](templates/resume-verification-and-interview-brief.md)，并严格按以下顺序交付。

### 第一优先级：原生视觉图谱

当当前 WorkBuddy 对话运行时已提供图形、画布、图片或可下载视觉产物的生成能力时，先输出一张“简历核验决策图谱”。**图谱必须是用户可见回复的第一项：在图谱之前不得输出问候、过程说明、标题、摘要、表格或任何正文。**视觉构图和文案规则见 [视觉图谱规范](references/visual-composition.md)。图谱必须是本次材料分析的可视化摘要，而不是装饰图；其中的数量、编号、结论和问题均须与正文完全一致。

不得假设、点名或伪造任何未在当前会话中可用的工具、渲染协议、URL、下载地址或生成状态。若当前运行时不支持视觉产物，或无法确保图中文字、数据与证据准确，直接使用第二优先级的 Markdown 看板，不解释平台能力限制。

### 第二优先级：富视觉 Markdown 看板

使用原生 Markdown、表格、引用块和 Unicode 框线呈现，确保稳定显示：

1. **核验决策看板**：呈现材料范围、红线级/黄线级数量、待补信息数量和本轮建议动作。红线、黄线和业务提问分别使用 `🔴`、`🟡`、`🔵` 作为视觉导航，不以颜色或数量表达真实性概率。
2. **核验路径图**：以“材料线索 → 核验分级 → 最小核验问题 → 人工复核”为固定路径，帮助读者先看结论框架再看明细。
3. **核验优先矩阵**：按“关键事实冲突程度 × 对本次面试准备的影响”展示条目落点。矩阵仅用于安排核验顺序，不能用于候选人排序或招聘决定。
4. **红线级核验重点**：按优先级逐项给出材料事实、直接冲突、合理解释和最小核验问题；没有红线级时明确写“当前材料未发现可定位的红线级核验点”。
5. **黄线级核验重点**：逐项给出材料事实、待澄清原因、合理解释和最小核验问题。
6. **业务面试提问**：最后输出；围绕用户给定岗位重点，按业务能力、项目成果、个人贡献和协作方式组织。如未提供岗位重点，只能给出与简历已有经历相关的通用业务澄清问题，并说明限制。

每次完成分析时，同步生成一份**自包含、可下载的 HTML 完整简报**，文件名使用 `简历核验与面试提问简报-<候选人代称>.html`。HTML 的布局、样式和必备章节见 [HTML 完整简报模板](templates/resume-verification-report.html) 与 [HTML 交付规则](references/html-report-contract.md)。报告必须包含本次对话交付的全部信息，且图谱、指标、正文表格、结论和编号与聊天回复完全一致。

只在当前运行时实际成功创建文件后，才说明已提供或可下载该文件；不得编造文件路径、下载地址或文件生成状态。若当前运行时确实无法创建文件，则在聊天中完整交付同等内容的 Markdown 简报，不声称已附带 HTML。

每一项均须区分：材料事实、核验判断和待验证项。不得以单一总分、红线/黄线数量、颜色或措辞强度替代证据。

## 多份简历处理

当用户一次提供两份或以上简历时，先判断每份材料是否能可靠对应到一名候选人。对应关系不清、文件内容混杂或候选人代称缺失时，先请求用户提供最小映射；不得自行按段落合并或拆分候选人经历。

对应关系清楚时，默认按候选人逐份独立输出：**每位候选人各有一张置顶决策图谱和一份完整简报**，编号使用候选人前缀隔离，例如“候选人 A：R-A1 / Y-A1 / B-A1”“候选人 B：R-B1 / Y-B1 / B-B1”。不得将不同候选人的红线、黄线、待补信息或业务问题合并计数，也不得用这些数量进行横向排序、推荐或淘汰。

用户明确要求汇总时，只能在所有独立简报之后增加“材料核验进度总览”，列出每位候选人的材料完整度、待补信息和建议下一步；不输出真实性排名、风险排名或录用排序。共同目标岗位未提供或不明确时，业务问题仍按各自简历中的已有经历生成通用澄清问题，不自行假设岗位。

## 权限、数据最小化与安全

- 仅处理用户明确提供或明确授权的材料；授权范围不清时不处理个人内容。
- 仅呈现完成当前任务所必需的信息；输出以候选人代称替代姓名，避免复述非必要敏感信息。
- 本 Skill 为只读分析能力，不写入、删除、导出、外发或保存候选人材料，也不承诺系统留存、审计或删除行为。
- 输出供具有相应权限的招聘人员或猎头顾问复核和使用，不替代人工访谈、材料核验、背景调查或招聘决定。涉及保密项目时，只询问可公开或经授权披露的项目范围、角色和非涉密贡献，不要求提供涉密内容或证明材料。

## 异常处理

| 情形 | 输出要求 |
| --- | --- |
| 未发现红线级或黄线级线索 | 说明“基于当前可见材料未发现可定位的相应核验点”，并说明这不构成真实性确认。 |
| 材料相互冲突 | 并列展示冲突来源与位置；仅在符合红线级定义时列红线级，否则列为待验证项。 |
| 关键信息缺失 | 列出缺失项及其对分级判断和业务提问的影响，提出最小补充问题。 |
| 授权不清或范围超出 | 停止处理相关个人信息，说明需要确认的授权范围、来源和处理目的。 |
| 用户要求招聘决策 | 重申输出仅为辅助核验和面试准备，由具有相应权限的人员作出决定。 |

## 使用示例

- “请先按红线级和黄线级梳理这份已授权简历的核验重点，最后再给产品负责人岗位的业务面试问题。”
- “请检查这份简历是否存在需要优先澄清的任职时间或项目归属冲突，并提供最小核验问题。”
- “根据这份简历和供应链负责人岗位重点，先输出核验风险，再输出业务深挖问题。”
