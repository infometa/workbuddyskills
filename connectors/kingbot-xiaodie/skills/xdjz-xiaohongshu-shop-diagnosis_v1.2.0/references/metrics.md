# 授权数据分析

只有取得真实数据后才启用。先明确字段、时间与状态，再计算；连接器返回的是可用字段，不一定包含全部业务定义。

## 统一口径

- 区分订单头与明细行，先按正确粒度去重。金额、退款、结算不可因一对多关联重复加总。
- 明确日期采用下单、支付、发货、退款完成或结算日期；跨表对比时保留口径差异。检查时区、币种、取消/测试单、优惠、运费与部分退款。
- “本期支付金额减本期退款金额”是期间收支/净额口径，不等于“本期支付订单最终净收入”。名称与口径紧随核心结果。
- 区分退款申请、审核通过、退款完成、退货退款与仅退款，区分退款订单率与退款金额率。
- 退款/损坏率优先使用同一发货或支付订单群及相同成熟观察窗口；未成熟窗口标注，不能用当天新订单冲淡售后比例。
- 复购需要稳定脱敏买家标识及足够历史窗口，说明按订单数还是按客户数计算；评论和粉丝数据不能代替。
- 支付转化遵循平台可取得的实际归因定义，说明分子分母和窗口；没有曝光/访客分母则不算转化率。点击/订单无法关联笔记时，不强做因果归因。

## 结算与利润

区分支付、待结算、应结算、已结算、已到账；结算跨期、冻结、退款回扣、平台费、调整项都可能造成差额，不把差额直接判为少到账。用订单/结算编号对账，无法关联的单独列示。

利润需覆盖相应成本口径。只有采购成本时可计算明确限定的毛利，不能称净利润；平台费用若已在结算净额中扣除，不再重复扣除。退款商品是否回收、物流双程费、推广分摊需有依据。无法可靠分摊时展示可直接归属的贡献及未分摊费用，不编造SKU利润。

发现异常后优先输出金额、商品/订单群、来源与可核查动作。改进收益只有基线、成本与可靠假设齐备才测算；方案预测注明假设，不能说实施后必然提升。

## 数据不足时

保留可以验证的维度；将缺口说明为“哪些经营问题尚不能回答，需要什么数据”。不要用0表示未知，不为填图生成伪数据。公开版也可以完整交付，后台授权不是前置门槛。
