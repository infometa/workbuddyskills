# 报告与视觉规范

## 金字塔结构

整份报告：经营目标 → 一个有证据的核心判断 → 至多三个支撑论点 → 事实与图像证据 → 对应成品示例 → 少量优先行动。每页：结论式标题 → 2–3个支撑点或一个主图 → 一个明确动作；不是“背景/发现/原因/建议/限制/小结”都挤在一页。

## 文案：专业，也要一遍读懂

用老板日常说法写标题、发现和建议，优先说清具体对象、动作与结果。专业性来自证据与判断，不来自抽象名词；避免把分析过程术语直接放进正文。

- 将“尚非已量化瓶颈”改成“目前还不知道这个问题影响了多少订单”；将“到货分流、证据复核”改成“先检查到货状态，再由专人核查”。例子用于说明写法，不固定店铺结论或用词。
- 删除“找到问题位置”“从线索走向规模”“内容与需求匹配”等结构旁白。可保留“顾客旅程”“行动安排”等简短导航，主标题直接说结论或顾客的问题。
- 将“同款反证”“候选原因”等内部分析标签写成“同款反馈”“要查什么”。后台仍完整比较原因与反证，不能因语言简化而省略分析。
- 一句话集中表达一个意思，少用连续斜杠、名词堆叠与重复免责声明。重要限制紧随对应判断，用一句易懂的话说明；其余方法、样本与缺口集中放来源页。
- 逐页检查：老板能否直接理解发现、影响和要做的事？删去只有报告作者才需要看的说明，不通过缩小字号容纳多余文字。

## 页面顺序与内容职责

默认采用以下结构；证据足够时约8页，案例页数量随关键议题调整，不强行凑页数，也不因凑页将案例与效果拆开。

| 页面/部分 | 老板要得到的答案 | 内容与表达 |
|---|---|---|
| 第1页：核心结果 | 发现了什么，影响什么，先做什么？ | 一个总判断；将重要发现分为值得保留、需要改善，必要时单列待核查。每项串起发现→影响→建议。关键建议通常两项、最多三项；不为对称硬凑好坏发现。 |
| 第2页：顾客旅程总览 | 哪些环节有问题，哪些最重要？ | 按实际购买过程画旅程图；各节点对应顾客问题、影响、证据与重点。阶段可有所侧重，不能照搬用户随口举例的阶段。 |
| 中部：案例与优化效果 | 为什么改，改后是什么样？ | 一页一个观点，真实商品/页面/评论案例与对应优化样张同页，默认左右或上下对照。不能直接优化时提供具体可执行建议；优秀案例链接按需添加。 |
| 行动计划 | 谁在何时交付什么，怎样算完成？ | 保持责任角色、建议时间、交付物、验收方式；收敛到最多三项，避免复制前面整段建议。 |
| 数据与来源：一页 | 依据从哪里来，判断范围是什么？ | 分类列店铺身份、商品与自有内容、买家评论与外部体验、已有授权数据（如有）；来源标题可直接点击对应原页面。集中说明采样、口径与待验证事项。 |

### 旅程页的证据与优先级

从店铺实际触点重建旅程。例如发现花束→比较选款→确认下单→等待配送→开箱养护→售后与再购买只是鲜花案例，不是跨品类固定模板。服饰、食品、定制品按其实际决策和使用过程调整。

每个节点简洁呈现“顾客遇到什么 → 可能影响什么”，用已采集的评价、提问、外部体验帖或授权数据支持。图上区分优势、重点改善和待核查，并保持颜色/图标含义一致。没有负面证据可写已有优势或待验证，不制造全程都有问题的印象。实际行为未追踪时标明为诊断旅程重建，不画虚构转化率。

### 案例与效果合页

用真实案例证明具体问题，同时让老板看到改后样子。优先取实际商品详情页与真实图片；只能取得笔记时如实说明。证据、建议设计与已验证事实要可辨识。复杂度超出一页时先收窄该页观点，再考虑拆页，不能缩小字号或重现旧式“诊断页＋重复建议页”。

可直接优化的内容（如商品说明、选款卡、收货卡、售后说明）提供完整可审核文案或视觉样张。需要商家流程、人员或未知参数才能执行时，写具体动作、依赖和验收，不伪造已经完成的效果。优秀案例仅引用已读过且确实支持建议的页面，说明借鉴点；不把竞品做法或未验证成绩当成本店可保证的收益。

页面多不等于专业；保留一页一观点，删除重复摘要、重复行动和重复免责声明。

## 成品示例是必需的交付，不是字段占位

优先取得一个与核心问题相关的真实商品详情页，核对当前SKU、规格、价格条件、包含物、包装、时效及服务规则；选取原图制作“优化后”示例。尽量完成至少一个不依赖未知参数的可直接审核成品，而不是所有问题都写“咨询客服”。

事实不足时采用两类方式，必须标明：

- **基于已知事实的设计稿**：只填核实信息，其他信息在稿外列为商家确认项。可选择已有规格的选购说明、服务入口文字等，不假装取得完整详情。若关键字段缺失，称“待确认设计稿”，不称可直接上架成品。
- **演示设定的完整效果稿**：只有完整演示确实帮助用户理解时使用。顶端醒目标记“效果示例，含演示假设，非本店实际承诺”，紧邻标明哪些包装、时效等是演示设定；发布前必须替换真实资料。不得混用演示值计算店铺问题或收益，也不得让读者误以为是假设经过验证。

无法取得详情页但取得笔记时，明确写“基于笔记制作，非原详情页改版”。制作可用部分并说明剩余限制；不要只因做不到完美就阻塞全部报告。禁止把未经核实的“48小时发货”“包赔”等写成真实服务。

内容示例可适应品类：服饰尺码/版型对照，食品净含量/保存说明，家居尺寸/包含物，定制品确认步骤。养护、食用、安装等具体指导应有可靠商品依据，不为填卡片编造。

## 用图降低阅读负担

每页一个主要视觉，正文通常2–3短段即可。

| 要传递的信息 | 优先视觉 |
|---|---|
| 全过程与问题位置 | 顾客旅程图，阶段图标与颜色跨页一致 |
| 原页面缺口 | 原始截图+少量标注，不改写证据 |
| 建议落地效果 | 已填具体内容的商品/服务成品样张 |
| 评价中的重复主题 | 精选原文或明确标为摘要的反馈卡，不伪造聊天截图 |
| 节点、责任、复核 | 简短流程图，正常和异常去向完整 |
| 金额、趋势、比例 | 有真实口径与样本量的统计图 |
| 实施安排 | 路线图或简短行动表 |

不用花朵素材装饰非鲜花店，不为好看堆放图标。没有可靠分母不画转化漏斗；没有标准不画雷达评分。库存/销量未知不补0。效果图不等于实测经营改善。

## 版式与输出

默认A4竖版，36–42pt页边距；正文10.5–12pt，说明不低于8pt，结论标题22–26pt；真实图片不拉伸变形。可按阅读场景改用横版，但全篇一致。首选深绿主色、浅灰背景、少量蓝/暖棕区分阶段；不冒用平台或咨询公司的标识。

图、字号、间距和色彩层级应固定。正文是可选择文本，图表与流程优先矢量；图片是证据，图片内关键文字在正常阅读尺寸可辨。不要把整份报告做成长截图塞进PDF。

字体使用环境可用且支持中文的字体，嵌入或验证输出环境可正常显示。若用 `scripts/pdf_components.py`，通过 `--font` 传中文TTF，可另传 `--bold-font`；组件出现溢出时应拆页/精简而不是无界缩字。示例运行只用于验证组件，不是实际诊断报告。

## 交付检查

- 标题结论有证据；报告对象与商品归属已核实。
- 首页有发现→影响→少量建议；第二页旅程源于真实过程，展示问题位置与重点。
- 案例与优化效果默认同页；不能直接优化的部分有具体建议，优秀案例链接已核验。
- 每页能用一句话说出观点，没有两套不相干的论证。
- 首要建议有具体商品/场景的成品效果，缺失参数与假设清楚。
- 原图、设计稿、反馈摘要、实测图表可区分；私人信息已脱敏。
- 无重复表格、装饰性雷达图、伪造统计或未经核实的服务承诺。
- 已渲染并查看每一页；无断字标题、溢出、重叠、过小图文或坏链接。
- 数据与来源压缩一页并分类，原页面可点击；关键数字旁保留必要口径。
- 文案一遍读懂，无内部分析术语和结构旁白；简化措辞不改变证据强度。

## 公开信息版的分析深度验收

首页写清本轮拟改善的经营结果，不把公开线索当已量化瓶颈。专题以“具体证据＋原因判断＋同页改后效果”支持主张，避免只做美观或信息完整性点评。优先行动加入实施依赖、验证方法和调整条件；公开可验收项与未来需后台数据的效果指标分开。后台数据只在深度诊断引导说明“补哪份数据能判断哪个问题”，本报告不等待授权。八类任务用于筛选，不作为八张必填页面。
