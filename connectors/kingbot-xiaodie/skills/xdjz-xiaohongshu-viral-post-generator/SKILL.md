# 一站式爆款小红书帖子生成

把「你在卖的货」变成「能发的小红书笔记」：三套不同钩子的完整方案 + 三张 AI 封面 + 一个可直接截图的 HTML 预览页。

**核心承诺**：笔记里出现的具体数字与事实（价格、规格、销量、成分、检测背书）必须有依据——用户提供或用户确认过的才能写进正文；没有的一律标「待确认」，禁止编造。

## 交付物清单

| 交付物 | 形态 | 说明 |
|--------|------|------|
| ① 三套方案 | 对话内结构化呈现 | 每套含：封面视觉提示词、封面主文案、标题（≤20字）、正文、话题标签、挂车组合 |
| ② 三张封面图 | 本地图片 | **必出**。3:4 竖版 AI 生图，与三套方案一一对应，写入 HTML 预览页 |
| ③ HTML 长图预览页 | 本地 `.html` | 三套方案并排预览，可直接截图发布 |
| ④ 合规校验报告 | 对话内简短结论 | 极限词/违禁词/标题字数检查结果 |

## [硬规则 0] 数据诚信（最高优先级，覆盖所有章节）

- **禁止编造事实性数字**：价格、规格、销量、库存、成分、检测报告、认证背书——用户没提供或没确认过的，一律写「待确认」，禁止占位数字、禁止凭品类常识写成既定事实。
- **禁止虚构买家评价与权威背书**：用户口碑、明星同款、第三方排名——没有真实来源就不写。
- **区分「用户确认的事实」与「创作」**：哪些是用户提供的信息、哪些是营销表达，界限要清楚，不得把营销话术伪装成事实结论。
- **价格红线**：正文里出现的价格必须来自用户输入；用户未提供时标「待确认」，渲染 HTML 前提醒用户补齐。挂车表售价列改走 [硬规则 4]——给参考区间并注明来源，**不得冒充本店售价**。

## [硬规则 1] 用户可见性规则（最高优先级，覆盖所有章节）

执行细节与用户输出**严格分离**。以下内容**仅用于内部执行**，**禁止**出现在任何对用户的回复中：

- 工具名：如 `ImageGen`、`AskUserQuestion` 等
- 参数名：如 `prompt`、`size` 等参数名
- 内部模板占位符、脚本名、文件内部结构

仅向用户展示：三套方案的标题与文案、封面图、HTML 预览页位置、合规检查结论、待确认信息清单、操作最终结果。

### 用户输出示例对照

❌ BAD（暴露技术细节）：
> 已调用生图工具生成封面，提示词已写入，三张图生成成功。

✅ GOOD（业务语义）：
> 三套方案的封面已生成，完整预览页在 `小红书笔记-精华油-20260914-2210.html`。

## [硬规则 2] 数据源命名（禁止出现「帐套」二字）

笔记预览页与对话回复里，凡是提到后台 / 系统 / 数据源的地方，一律写作 **「小蝶记账（小程序）数据中心」**。

- 禁止输出「帐套」「账套」「后台系统」「经营系统」等字样。
- 字段没维护时写「小蝶记账（小程序）数据中心未维护」，不写「帐套没填」。
- 该命名覆盖：商品信息卡、挂车表、合规结论、发布前确认清单、对话回复全文。
- 商品在小蝶记账（小程序）数据中心里的登记名若与用户口头叫法不一致（如少品牌前缀），
  必须在商品信息卡标注，并提醒「挂车时按数据中心登记名对应」。

## [硬规则 3] 挂车档位只有两档

挂车推荐表与每套方案的挂车清单**只保留「主推」+「搭配」**：

- 禁止出现「引流凑单」档位（含 `role-trial` 样式）。
- 搭配档必须来自真实在售商品（用户提供，或从小蝶记账（小程序）数据中心读到）；
  没有第二款真实商品时，挂车只保留主推一行，**不要为凑满而虚构**。
- 搭配档说明不要写「凑单款」，改写真实用途（「对比款 / 佐餐搭配款 / 组合款」等）。

## [硬规则 4] 挂车售价必须给参考区间

挂车表的售价列**必须给出参考区间**，不允许只写「待确认」。
取数口径与写法见 **[references/xiaodie-data-rules.md](references/xiaodie-data-rules.md)**：

- 取小红书店铺**同源供应链**（淘宝 / 天猫 / 京东 / 酒类等垂直电商）公开在售与历史价作样本。
- 输出三个数：**最低价 / 中位数 / 最高价**，并标注样本口径（同类、同规格、样本数）。
- 挂车表下附一行说明：数据来源、样本口径、「实际挂车价以店铺为准」。
- 促销到手价（如「买 2 件」的单件价）单独注明，避免被当成常规售价。
- 参考区间与正文里的价位带表述若冲突，**必须向用户点名提示**，由用户决定是否统一口径。

## 执行流程

```
1. 输入引导（商品品类 / 商品名称）
   ├─ 用户已明确给出品类或商品名 → 进入 2
   └─ 用户没给或只说"帮我做个小红书" → 必须先问，禁止硬跑。
       用 AskUserQuestion 问「你想推哪个商品/品类？」，
       选项给出常见的切入角度（单品种草 / 组合推荐 / 新品首发），
       商品名由用户自行填写。

2. 关键信息收集（一次性问齐，禁止连环追问）
   └─ 用 AskUserQuestion 一次性收集（用户可跳过任意项，跳过的标「待确认」）：
        · 售价（必问，影响文案调性与挂车组合）
        · 核心卖点（1-3 个，决定钩子方向）
        · 目标人群（影响痛点与话题标签）
        · 是否有赠品/优惠（影响转化钩子）
   拿到多少用多少，不阻塞：信息不足时按品类常规角度创作，
   涉及具体数字的位置留「待确认」。
   若用户说「按我的小蝶记账 / 小蝶记账数据确认」→ 走
   references/xiaodie-data-rules.md 读取商品档案，
   只回填真实读到的字段（命名按硬规则 2）。

3. 三套方案创作
   └─ 按 references/xhs-copy-playbook.md 执行。
      按三种**不同钩子类型**做差异化：
        方案1 痛点共鸣型 / 方案2 效果反差型 / 方案3 权威测评型
      每套输出：封面视觉提示词、封面主文案、标题（≤20字）、
                正文、话题标签、挂车组合、适用说明。

4. 封面生成（**必做步骤，三张缺一不可**）
   └─ 用生图能力**同时生成 3 张** 3:4 竖版封面，与三套方案一一对应：
        方案1 痛点共鸣 → 封面-方案1-痛点共鸣.png
        方案2 效果反差 → 封面-方案2-效果反差.png
        方案3 权威测评 → 封面-方案3-权威测评.png
      禁止只生成部分方案的封面，禁止用占位图或同一张图复用给多个方案。
      prompt 写法与**已踩坑清单**见 playbook 第四章。
      出图后对每张必须做的四件事：
        a. 目检：主体是否跑偏（如出现糊脸/病灶/乱码文字），跑偏就换 prompt 骨架重做
        b. 按 3:4 从顶部裁切（1024×1536 → 1024×1365），同时去掉右下角水印
        c. 核对图上商品数量与文案数字是否一致，不一致就以图为准改文案
        d. 重命名为 `封面-方案N-<钩子名>.png`，废弃版本删除
      某张生成失败 → 先重试一次（可简化 prompt 或降 quality）；仍失败才允许该张
      降级为 HTML 内嵌排版封面，且必须在回复里说明是哪张降级了、原因是什么。

5. 合规校验
   └─ 运行 scripts/check_copy.py 校验三套方案的标题与正文。
      有命中项 → 改写后复跑，直到通过或在报告里写明保留理由。

6. 挂车参考价区间（必做）
   └─ 联网检索同类商品在小红书店铺同源供应链（淘宝 / 天猫 / 京东 / 酒类等垂直电商）的在售价，
      汇总成样本后算出**最低价 / 中位数 / 最高价**，写入挂车表售价列与表下说明。
      取数口径与写法见 references/xiaodie-data-rules.md。
      参考区间与正文价位带冲突 → 向用户点名提示，**不擅自改正文**。

7. 渲染 HTML 长图预览页
   └─ 拷贝 assets/longimage-template.html，按 references/longimage-html.md 填充。

8. 交付
   └─ present_files 打开 HTML 预览页 → 对话内给三方案对比表 + 待确认清单 → 请用户选择。
```

## 流程节点说明

### 第 2 步：关键信息收集

**一次性问齐，禁止连环追问**。用 AskUserQuestion 的多个 question 一次发出。

问什么、为什么问：

| 信息 | 必要性 | 用途 |
|------|--------|------|
| 售价 | 必问 | 决定文案调性（低客单走性价比、高客单走品质感）与挂车组合 |
| 核心卖点 | 建议提供 | 决定三套方案分别主打哪个点 |
| 目标人群 | 可选 | 影响痛点描写与话题标签 |
| 赠品/优惠 | 可选 | 影响正文转化钩子 |

用户跳过的项不阻塞流程：按品类常规角度创作，涉及具体数字的位置（价格、成分、销量）留「待确认」，并在最终回复的待确认清单里点名列出。

### 第 3 步：三套方案创作

标题公式库、三种钩子的封面/正文/标签写法见 **[references/xhs-copy-playbook.md](references/xhs-copy-playbook.md)**。执行到这一步时必须完整读取该文件。

要点：三套必须在**钩子类型**上真正不同，不能只是换词；标题必须能在手机首屏 20 字内读完；正文结构、话题标签数量、挂车位置按 playbook 规范。

### 第 4 步：封面生成

**三张封面是必交付物**：每套方案一张、一一对应，缺任何一张都算未完成，不允许用占位图或同一张图复用。

prompt 骨架、三种钩子各自的视觉方向、以及**生图已踩坑清单**（水印裁切、负面皮肤描述会跑偏、商品数量不可控等）见 **[references/xhs-copy-playbook.md](references/xhs-copy-playbook.md)** 第四章。执行到这一步时必须完整读取该节。

要点：封面必须体现目标商品——测评型直接以商品为主体；痛点型与反差型通过场景道具（产品瓶身、包装、使用瞬间）让商品在场。负面/病理化的皮肤描述会让图跑偏，改用光线与情绪的冷暖对比；出图后务必逐张目检、裁水印并核对商品数量。生图消耗额度，生成前需告知用户预计消耗。

### 第 5 步：合规校验

```bash
python3 scripts/check_copy.py --title "标题文本" --body "正文文本"
python3 scripts/check_copy.py --input notes.json   # 三套方案批量校验
```

输出：标题字数、命中的极限词/违禁词清单、风险等级。

### 第 6 步：挂车参考价区间

按 **[references/xiaodie-data-rules.md](references/xiaodie-data-rules.md)** 执行：联网取同类商品在售样本 → 算最低价 / 中位数 / 最高价 → 写入挂车表售价列 + 表下说明。

要点：样本必须同品类同规格；促销到手价单独注明；参考区间与正文价位带冲突时**提示用户**而不是自行统一。

### 第 7 步：HTML 长图预览页

结构规范、占位符替换规则、CSS 变量、截图建议见 **[references/longimage-html.md](references/longimage-html.md)**，模板为 **[assets/longimage-template.html](assets/longimage-template.html)**。

要点：直接复制模板改内容，**不要**从零手写 HTML，保证三方案版式一致；成品必须用 `present_files` 打开；文件名建议 `小红书笔记-<商品名>-<YYYYMMDD-HHMM>.html`，放在当前工作目录。

## 错误处理

| 错误场景 | 处理策略 | 用户提示 |
|---------|---------|---------|
| 用户没给商品 | 用 AskUserQuestion 引导，给切入角度选项，商品名让用户填 | "你想给哪个商品做小红书笔记？" |
| 用户只给品类不给单品 | 先给该品类下的常规单品方向让用户确认，或直接以品类为主角创作并说明 | "先按「XX品类」整体来写，你如果想推具体某款告诉我名字。" |
| 售价/卖点未提供 | 不阻塞：按品类常规角度创作，涉及数字处标「待确认」 | "价格你没给，文案里先留了待确认，发布前补一下。" |
| 封面生图失败/额度不足 | 先重试一次（简化 prompt 或降 quality）；仅失败的那张降级为 HTML 内嵌排版封面，其余两张照常出图 | "方案2 封面生成失败（已重试），该张改用排版式设计，其余两张正常。" |
| 合规检查命中极限词 | 自动改写后复跑；无法改写则提示手动确认 | "原文含「XX」，已改写为「XX」。" |

## 常见问题

**Q1：用户没说具体商品怎么办？**
→ 不许硬跑。用 AskUserQuestion 问，同时给切入角度选项（单品种草 / 组合推荐 / 新品首发），商品名由用户填写。

**Q2：用户不给价格怎么办？**
→ 不阻塞。正文不写具体价格或只写价位带；挂车表售价列**必须**给参考区间（联网取同类在售样本的最低 / 中位 / 最高并注明来源），同时保留「实际挂车价待补录」标注。禁止凭空估一个"本店售价"。

**Q3：用户要多于三套的方案怎么办？**
→ 默认三套。用户明确追加时，从 playbook 的钩子类型库再取，仍保持每套钩子类型不同。

**Q4：用户只要标题不要图怎么办？**
→ 仅当用户**明确表示不要图**时才可跳过生图与 HTML 渲染，只出标题 + 正文 + 挂车推荐（仍走合规校验）；用户没说就不要自作主张省略封面。

**Q5：可以编造用户评价放进文案吗？**
→ 不可以。标「待确认（请提供真实买家反馈）」占位。

**Q6：需要读取经营系统/进销存的真实数据吗？**
→ 默认不读，本 Skill 是内容创作工具，商品信息以用户在对话里提供的为准。
  仅当用户明确要求「按我的小蝶记账数据确认待确认项」时才读商品档案，
  见 references/xiaodie-data-rules.md。

**Q7：可以写「帐套」吗？**
→ 不可以。一律写「小蝶记账（小程序）数据中心」，见 [硬规则 2]。

**Q8：挂车售价用户没给，能只写「待确认」吗？**
→ 不能。必须联网取同类商品在售样本给出参考区间（最低 / 中位 / 最高）并注明来源；
  用户本店售价未录入时另标「待补录」，两者并列，不互相替代。
