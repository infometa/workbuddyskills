## [硬规则 0] 小蝶记账连接器检查与「打开连接器」（最高优先级，最先执行）

本 Skill 的全部能力都由「小蝶记账」连接器提供。识别到文件录入意图后，**第一件事是确认连接器已连接**，确认通过后才允许上传文件与调用服务。

### 一、判断连接器是否已连接

- 本 Skill 声明的录单服务可正常调用、调用不返回授权类错误 → 视为**已连接**，直接进入「工具调用规范」流程。
- 服务不存在、调用返回未授权 / 未登录 / 凭证失效 / 连接失效等错误 → 视为**未连接**，执行下方「打开连接器流程」。

### 二、打开连接器流程（未连接时的唯一动作）

未连接时**不得调用录单服务**，也不得用文字解释「MCP」「Token」「服务地址」「接口」等技术细节。

#### 1. 呈现连接器授权卡片（必须首选，禁止只用文字引导代替）

用下面这套**固定的工具调用顺序**把「小蝶记账」的连接卡片内联呈现到本次回复中，用户点卡片上的「连接」即可完成授权：

```
第一步：调用 search_plugins
        参数：type = "connector"
              keywords = ["小蝶记账", "金蝶", "记账"]
第二步：从返回结果中找到「小蝶记账」，取其 id（通常为 kingbot-xiaodie，以实际返回为准）
第三步：调用 suggest_plugin_install
        参数：type = "connector"
              pluginId1 = <第二步取得的 id>
              contextLabel = "连接小蝶记账后继续文件录单"
```

执行约束：

- `search_plugins`、`suggest_plugin_install` 是平台内置工具，**直接调用即可**；禁止用网络搜索代替，禁止推荐任何其他连接器。
- `suggest_plugin_install` **同一轮只允许调用一次**；卡片发出后即停止动作，等用户在卡片上点「连接」，不要继续追问。
- 若平台对呈现卡片弹出确认/授权提示，用一句话请用户点「允许」，卡片即可显示。
- 卡片已呈现时，本轮不再输出长篇文字指引（一句话说明"请在上方卡片点「连接」"即可）。

#### 2. 文字兜底（仅当卡片工具不可用或调用失败时）

仅当 `search_plugins` / `suggest_plugin_install` 不存在、被禁用或调用报错时，才退回一句话指路：

> 这个操作需要先连接「小蝶记账」连接器：请打开「连接器」面板，找到「小蝶记账」，点击「连接」完成授权，完成后回复我一声，我马上帮你录入文件。

#### 3. 用户回复已连接后

重新从本节第 1 步开始走一次完整流程（不要复用授权失败前的输入与判断），授权通过后继续文件录入。

### 三、授权失败或凭证失效

按「打开连接器流程」重新引导用户连接或重新授权，提示语与未连接时一致，不暴露技术细节。同一轮对话内最多提示一次，用户未处理则等待用户回应，不重复弹窗打扰。

### 四、禁止事项

- 禁止在未连接状态下把录入结果编造给用户，或假装录入成功。
- 禁止因连接器未连接而改口说"我不支持文件录单"——应引导完成连接后继续。
- **禁止在卡片工具可用时偷懒只用文字引导**——文字兜底只允许在卡片工具不可用/调用失败时使用。
- 禁止展示 Token、服务地址、连接器内部标识、授权链路等技术信息。

## [硬规则 2] 禁止主Agent生成与录入测试数据（最高优先级）

本 Skill 产生的都是**真实业务记录**：后端没有"测试模式"，任何一次上传调用都会真实保存记录，且已录入的记录无法删除。

- 录入内容**只能来源于用户上传的真实单据文件**
- **主 Agent 一律不得自己生成测试文件或测试数据**：无论用户是否要求、无论出于任何理由（测试、演示、验证功能等），都**禁止主 Agent 自行编造文件内容或构造示例文件**上传录入——**生成即违规**
- 用户要求"测试/演示"时 → **不上传、不调用录单服务**，回复用户："每次文件录入都会真实保存记录，无法撤销。请直接上传您真实的单据文件，我马上帮您录入。"
- 宁可多问一句（确认文件内容），不可错录一批

## [硬规则 3] 文件上传必须由脚本执行（最高优先级，禁止 Agent 触碰文件内容）

单据文件内容 **Base64 编码后体积膨胀约 33%**，一旦进入对话就会撑爆上下文token，导致任务失败。因此**读取文件、编码、上传、发起录单**这整条链路 **只允许由本 Skill 自带的脚本完成**。

### 一、强制要求

- **一律执行脚本**：所有文件上传与录单调用，只能通过 `scripts/file_entry.py` 完成
- **Agent 只传文件路径**：不传内容、不传编码结果
- **禁止**下列任何行为（无论文件多小）：
  - 用文件读取工具打开单据文件、或用命令行 `cat`/`type`/`base64`/`xxd` 等把文件内容输出到对话
  - 自行对文件内容做 Base64 编码并把编码串写进任何工具参数
  - 把文件里的行项目、金额等大段内容复制到对话中复述
  - 绕开脚本直接调用录单服务

### 二、脚本调用方式

脚本路径（相对 Skill 目录）：`scripts/file_entry.py`，用本机 `python` 执行；若 `python` 不可用改用 `python3`。**文件一律用绝对路径**。

**1）先本地校验（不联网、秒级返回）**

```
python "<Skill目录>/scripts/file_entry.py" check --file "<文件绝对路径>"
```

返回 `ok:true` 才继续；返回 `ok:false` 时按下方「错误码处理」直接告知用户，不再执行上传。

**2）再上传并录单**

```
python "<Skill目录>/scripts/file_entry.py" upload --file "<文件绝对路径>"
```

脚本内部依次完成：本地校验 → 读取并编码文件 → 上传取文件标识 → 发起录单，最后只回传一段**几十字节的结果 JSON**。

### 三、输出契约

- 成功：`{"ok":true,...,"reply":"<录单服务返回的识别摘要>"}`，其中 `reply` 即为需要展示给用户的识别结果
- 失败：`{"ok":false,"error":{"code":"...","message":"..."}}`
- 脚本只回传摘要，**永不回传文件内容、编码内容或凭据**

### 四、错误码处理

| 错误码 | 含义 | 处理方式 |
|--------|------|---------|
| FILE_NOT_FOUND / NOT_A_FILE | 文件不存在或不是文件 | 请用户确认文件路径后重新发起 |
| UNSUPPORTED_FORMAT | 格式不支持 | 告知支持的格式，请用户另存后重传 |
| FILE_TOO_LARGE | 超过 20 MB | 告知超出大小限制，**不拆分、不压缩后重试** |
| EMPTY_FILE | 文件为空 | 请用户检查文件 |
| NO_MCP_CONFIG / NO_UPLOAD_SERVER | 录单服务未连接 | 执行「硬规则 0」的打开连接器流程（呈现连接卡片） |
| MCP_HTTP_ERROR / MCP_PROTOCOL_ERROR / TOOL_ERROR / NO_DOCUMENT_ID | 服务侧失败 | 把 `message` 的业务语义原样告知用户，**严禁重跑脚本** |
| TIMEOUT | 响应超时 | 告知用户稍后查看结果，**严禁重跑脚本** |

### 五、失败禁止重跑（强制）

上传与录单调用**都会真实生效**。脚本退出码非 0（或返回 `ok:false`）时：

- **严禁再次执行同一文件的上传命令**：不换参数重跑、不改写文件名重跑
- 同一文件只允许执行**一次** `upload`
- 正确做法：把失败信息原样告知用户，请用户检查文件后由用户重新发起
- 例外：`check` 命令是纯本地校验，可重复执行；用户主动补充信息后要求重传，属用户驱动，可执行

## 业务范围

本 Skill 专注**文档类单据文件的批量录入**：用户上传单据文件，系统上传解析后自动批量保存单据。

**适用场景**：
- 批量采购单："这是这个月的采购单 Excel，帮我录进去"
- 批量销售单："把这份销售明细表格保存一下"
- 收支明细导入："把这个 txt 里的账目都记了"
- 多月份批量单据："宠物用品_采购单_2026.xlsx，保存"

### 能力边界外的处理（一句话引导，不硬做）

| 用户意图 | 处理方式 |
|---------|----------|
| 纯文字描述收支事项（无文件） | 引导用户改用「智能录单」（一句话描述即可录入） |
| 上传的是单据图片/截图 | 引导用户改用「智能录单」（其读取图片转写录入） |
| 文件超过 20 MB | 直接告知超出大小限制，不支持拆分上传 |
| 文件格式不支持（xlsx/xlsm/xls/docx/pdf/txt 之外） | 直接告知格式不支持，并列出支持的格式 |
| 想查询/分析文件里的数据而非录入 | 引导用户改用数据查询/数据导出分析能力 |
| 想要正式会计凭证 | 引导用户改用凭证生成能力 |
| 想修改/删除已录入的单据 | 直接告知不支持（录入结果请到小蝶记账小程序查看与处理） |

## 脚本内部调用规范（内部机制，不展示给用户）

> **主 Agent 不直接使用本节内容**。以下两个工具由 `scripts/file_entry.py` 在脚本内部依次调用，
> 主 Agent 只需按「硬规则 3」执行脚本。本节仅作为脚本行为说明与排障参考。

脚本内部依次使用两个工具：先 `kingbot_upload_file` 上传文件取 `document_id`，再 `kingbot_chat` 以 Document 消息发起录入。
文件内容由脚本读取并编码，**全程不进入对话上下文**。

### 工具一：kingbot_upload_file

上传文件到后端，返回 `document_id`。

**参数说明**（四个参数全部必填、**禁止传入任何额外参数**）：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file_name | string | 是 | 文件名（含扩展名），如"宠物用品_采购单_2026.xlsx" |
| content_type | string | 是 | 文件 MIME 类型，仅支持 10 种，与扩展名一一对应（见下表） |
| file_size | integer | 是 | 文件字节数，取值 1~20971520（**上限 20 MB**） |
| file_content_base64 | string | 是 | 文件内容的 Base64 编码字符串（由你读取用户文件内容后编码） |

**扩展名与 MIME 类型对应表**：

| 扩展名 | content_type |
|--------|--------------|
| xlsx | application/vnd.openxmlformats-officedocument.spreadsheetml.sheet |
| xlsm | application/vnd.ms-excel.sheet.macroEnabled.12 |
| xls | application/vnd.ms-excel |
| jpg / jpeg | image/jpeg |
| png | image/png |
| webp | image/webp |
| docx | application/vnd.openxmlformats-officedocument.wordprocessingml.document |
| pdf | application/pdf |
| txt | text/plain |

**上传约束**：
- `file_size` 超过 20 MB（20971520 字节）→ **不上传、不拆分**，直接告知用户文件超出大小限制
- 扩展名不在支持范围 → 直接告知用户格式不支持
- **上传失败时原样告知用户失败原因，不自动重试**

### 工具二：kingbot_chat

创建对话并发送 Document 消息，同步等待 AI 回复。

**参数说明**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| title | string | 是 | 对话标题，固定使用 `"新对话"` |
| sid | string | 是 | 当前轮次的会话 ID，按「调用要点」规则取值后原样传入 |
| input | string | 是 | 固定传值 documents 数组 + content="保存"（见调用要点，**不改写**为文字描述） |
| variables | object | 是 | 对话变量，需填充 messageType=Document、agent_id=main（**不传 skills 字段**），以及来源参数 source_agent_id=""、source_agent_name=""、source_skill_id=xdjz-file-order-entry、source_skill_name=文件录单、source_type=workbuddy |

**调用要点**：
- `title` 固定为 `"新对话"`，用户不可见
- `sid` **必须传入**当前轮次的会话 ID；**由脚本自动解析**（优先级：命令行传入 → 环境变量 → 本机会话记录中 cwd 匹配项的 sessionId → 随机生成 UUID），主 Agent 无需手工取值；同一轮次内保持一致
- `input` **固定传值** `{"documents":[{"documentId":"<document_id>","size":<文件字节数>,"name":"<文件名>","contentType":"<MIME类型>"}],"content":"保存"}`——content 固定为"保存"，**文件本身已含全部单据信息，禁止改写为文字描述**；documentId 为 kingbot_upload_file 返回的 document_id，size/name/contentType 与上传时一致
- `variables` **禁止**传入 `skills` 字段（不同于智能录单的 Message 通道）；除下列字段外，**禁止**传入任何额外参数：

```json
{
  "messageType": "Document",
  "agent_id": "main",
  "source_agent_id": "",
  "source_agent_name": "",
  "source_skill_id": "xdjz-file-order-entry",
  "source_skill_name": "文件录单",
  "source_type": "workbuddy"
}
```

**调用示例**（内部参考，不展示给用户）：

```json
{
  "title": "新对话",
  "sid": "<按「调用要点」规则取得的会话ID>",
  "input": "{\"documents\":[{\"documentId\":\"01a16d49-14d2-7673-abcd-468f4570c8fe\",\"size\":8291,\"name\":\"宠物用品_采购单_2026.xlsx\",\"contentType\":\"application/vnd.openxmlformats-officedocument.spreadsheetml.sheet\"}],\"content\":\"保存\"}",
  "variables": {
    "messageType": "Document",
    "agent_id": "main",
    "source_agent_id": "",
    "source_agent_name": "",
    "source_skill_id": "xdjz-file-order-entry",
    "source_skill_name": "文件录单",
    "source_type": "workbuddy"
  }
}
```

## 结果处理

脚本 `upload` 成功后返回的 `reply` 字段即录单服务的 AI 回复内容。文件录入的回复通常为**后台异步处理**语义（如"已转入后台处理，系统将依次保存单据到数据中心，可在上传历史中查看结果"）。处理方式：

### 成功录入

**展示要点**：
- 展示**识别摘要**：笔数、合计金额、示例商品（从 AI 回复中提取，如"检测到深圳市龙华区御宠电子科技 智能循环饮水机 2L 等 44 件商品，总金额 571440 元"）
- **明确告知用户**：「单据已转入后台处理，请前往小蝶记账小程序查看上传历史与保存结果」
- 以简洁的业务语义展示，不暴露对话 ID、工具名、document_id 等
- **措辞规范（强制）**：结果展示统一使用「录单」「单据」「记录」表述，**禁止出现「凭证」「记账」等会计字眼**；AI 回复中出现此类字样时（如"记账成功""凭证编号"），须转写为"录入成功""单据/记录编号"后再展示，金额、编号等实际内容保持不变
- 回复中的 **navigateLink/点击查看类引导文案按输出过滤规则屏蔽、不透传链接**（「小蝶记账」为连接器品牌名，措辞规范允许保留）
- 严格执行下方【输出过滤规则】

### 输出过滤规则（强制）

AI 回复中如包含引导用户进入单据详情的文案（如"你可以点击【修改/查看】进入单据详情"及其任何变体、navigateLink 代码块），**必须整条删除**，禁止出现在对用户的回复中。当前环境不支持打开单据详情页，透传该文案会误导用户。

过滤规则：
- 命中"修改/查看"、"单据详情"、navigateLink 等引导文案/链接 → 整条删除，不做改写、不做替换说明
- 删除后仅保留识别摘要的业务信息（笔数、合计金额、示例商品）与后台处理告知
- 禁止向用户解释"已屏蔽某提示"，静默过滤即可

### 异常处理

| 场景 | 处理方式 |
|------|---------|
| 脚本返回上传类失败（`FILE_*` 之外的服务错误） | 把失败原因的业务语义原样告知用户，**不重跑脚本**；请用户检查文件后重新发起 |
| 脚本返回 `NO_MCP_CONFIG` / `NO_UPLOAD_SERVER` | 执行「硬规则 0」的打开连接器流程，不展示错误码与原文 |
| 脚本 `reply` 为空 | 告知用户"录单服务暂时无响应，请稍后重试"，**不重跑脚本** |
| 脚本 `reply` 包含失败/错误信息 | 原样展示失败提示，不暴露技术细节；**严禁主 Agent 重试** |

### 失败禁止重试（强制）

文件上传与录入调用**都会真实生效**。当脚本返回失败信息时：

- **严禁主 Agent 自行重试**：禁止对同一文件再次执行上传命令、或改名/换参数后重跑；同一文件只允许主 Agent 主动执行**一次** `upload`
- 正确做法：原样展示失败提示，请用户调整文件（如缩小体积、另存为支持格式）后，由用户再次发起
- 唯一例外：AI 回复要求补充信息时，可原样转达，等用户在对话中补充后再调用（属用户驱动，非主 Agent 自动重试）

## 执行流程

```
0. 连接器检查（最先执行）
   ├─ 已连接 → 进入步骤 1
   └─ 未连接 / 授权失效 → search_plugins 找「小蝶记账」→ suggest_plugin_install 呈现连接卡片（同一轮一次）
       └─ 卡片工具不可用/调用失败 → 一句话指路（打开「连接器」→ 找「小蝶记账」→ 点「连接」）
       └─ 用户确认已连接后，重新从步骤 1 开始

1. 意图与文件确认
   ├─ 确认用户意图为录入/保存单据文件，且用户提供了文档类单据文件（xlsx/xlsm/xls/docx/pdf/txt）
   ├─ 用户提供的是图片/截图或纯文字描述 → 不属于本技能，引导用户改用「智能录单」
   └─ 取得文件的绝对路径（格式与大小交由步骤 2 的脚本校验）

2. 本地校验（脚本 check）
   ├─ 执行：python "<Skill目录>/scripts/file_entry.py" check --file "<绝对路径>"
   ├─ 校验存在性、扩展名、大小（≤20 MB）
   └─ ok:false → 按错误码告知用户，流程终止（不上传）

3. 上传并录单（脚本 upload，文件内容不进上下文）
   ├─ 执行：python "<Skill目录>/scripts/file_entry.py" upload --file "<绝对路径>"
   ├─ 脚本内部：读取并编码文件 → 上传取文件标识 → 发起 Document 录单（sid 自动解析）
   ├─ 命令行中只出现文件路径，禁止把文件内容、编码结果写进命令或对话
   └─ 同一文件仅执行一次 upload；失败时严禁重跑（见硬规则 3「失败禁止重跑」）

4. 结果展示
   ├─ 成功（后台处理语义）→ 展示识别摘要（笔数、合计金额、示例商品），明确告知用户前往小蝶记账小程序查看上传历史与保存结果（先执行输出过滤与措辞规范：删除"修改/查看单据详情"类引导文案与 navigateLink，统一使用录单/单据/记录表述）
   ├─ AI 要求补充信息 → 原样转达，等待用户补充后重新调用
   └─ 异常/失败信息 → 原样展示错误提示，禁止主 Agent 重试，请用户调整文件后重新发起
```

## 常见问题

**Q1: 用户上传的文件超过 20 MB 怎么办？**
→ 不上传、不拆分，直接告知用户："文件超过 20 MB 的大小限制，暂时不支持上传。您可以精简文件内容后重新发送。"

**Q2: 用户上传的文件格式不支持（如 csv、zip、mp4）怎么办？**
→ 直接告知用户当前支持的格式：Excel（xlsx/xlsm/xls）、Word（docx）、PDF、TXT；请用户另存为支持的格式后重新上传。

**Q3: 上传失败怎么办？**
→ 原样告知用户失败原因（不暴露技术细节），**严禁自动重试**；请用户稍后再试或检查文件。

**Q4: 用户上传的是单据图片/截图怎么办？**
→ 不属于本技能：引导用户改用「智能录单」，其会读取图片内容转写录入。

**Q5: 用户用文字描述了多笔事项、没有文件怎么办？**
→ 引导用户改用「智能录单」（一句话描述即可录入，多笔会合并处理）；若用户能提供单据文件，也可上传后由本技能批量录入。

**Q6: 用户一次上传了多个文件怎么办？**
→ 逐个文件各执行一次脚本（先 `check` 再 `upload`），每个文件独立处理；任一文件失败不影响其他文件继续，但失败的文件严禁重跑脚本。

**Q7: 录入结果在哪里查看？**
→ 告知用户："单据已转入后台处理，系统将依次保存到数据中心，请前往小蝶记账小程序查看上传历史与保存结果。"

**Q8: 用户想修改或删除已录入的单据怎么办？**
→ 直接告知本技能不支持修改/删除，请到小蝶记账小程序的上传历史中处理。

**Q9: 用户说"帮我测试一下文件录单"怎么办？**
→ 禁止主 Agent 自行生成测试文件（硬规则 2）。告知用户："每次文件录入都会真实保存记录，无法撤销。请直接上传您真实的单据文件。"

**Q10: 调用返回失败信息怎么办？**
→ 原样展示失败提示，**严禁主 Agent 重试**：不要对同一文件重跑上传命令或改写后再发起。请用户调整文件后由用户再次发起。

**Q11: 用户上传的文件很大（十几 MB），会不会超出对话长度限制？**
→ 不会。文件读取、编码、上传全部在脚本内完成，文件内容不会进入对话，Agent 只拿到一段结果摘要。超过 20 MB 仍按大小限制处理（不上传、不拆分）。

**Q12: 能否先看看文件里有什么再决定要不要录？**
→ 可以先用 `check` 命令确认格式与大小（纯本地校验，不会录入任何数据）。但**禁止**用读取工具或命令行把文件内容输出到对话——大文件会撑爆上下文；确需核对内容，请让用户自行告知关键信息。
