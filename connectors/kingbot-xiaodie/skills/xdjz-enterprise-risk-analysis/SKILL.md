## [硬规则 0] 小蝶记账连接器检查与「打开连接器」（最高优先级，最先执行）

本 Skill 的全部能力都由「小蝶记账」连接器提供。识别到企业风险分析意图后，**第一件事是确认连接器已连接**，确认通过后才允许调用服务。

### 一、判断连接器是否已连接

- 本 Skill 声明的服务可正常调用、调用不返回授权类错误 → 视为**已连接**，直接进入「工具调用规范」流程。
- 服务不存在、调用返回未授权 / 未登录 / 凭证失效 / 连接失效等错误 → 视为**未连接**，执行下方「打开连接器流程」。

### 二、打开连接器流程（未连接时的唯一动作）

未连接时**不得调用服务**，也不得用文字解释「MCP」「Token」「服务地址」「接口」等技术细节。

#### 1. 呈现连接器授权卡片（必须首选，禁止只用文字引导代替）

用下面这套**固定的工具调用顺序**把「小蝶记账」的连接卡片内联呈现到本次回复中，用户点卡片上的「连接」即可完成授权：

```
第一步：调用 search_plugins
        参数：type = "connector"
              keywords = ["小蝶记账", "金蝶", "记账"]
第二步：从返回结果中找到「小蝶记账」，取其 id（通常为 xdjz-mcp，以实际返回为准）
第三步：调用 suggest_plugin_install
        参数：type = "connector"
              pluginId1 = <第二步取得的 id>
              contextLabel = "连接小蝶记账后继续风险分析"
```

执行约束：

- `search_plugins`、`suggest_plugin_install` 是平台内置工具，**直接调用即可**；禁止用网络搜索代替，禁止推荐任何其他连接器。
- `suggest_plugin_install` **同一轮只允许调用一次**；卡片发出后即停止动作，等用户在卡片上点「连接」，不要继续追问。
- 若平台对呈现卡片弹出确认/授权提示，用一句话请用户点「允许」，卡片即可显示。
- 卡片已呈现时，本轮不再输出长篇文字指引（一句话说明“请在上方卡片点「连接」”即可）。

#### 2. 文字兜底（仅当卡片工具不可用或调用失败时）

仅当 `search_plugins` / `suggest_plugin_install` 不存在、被禁用或调用报错时，才退回一句话指路：

> 这个操作需要先连接「小蝶记账」连接器：请打开「连接器」面板，找到「小蝶记账」，点击「连接」完成授权，完成后回复我一声，我马上帮你进行风险分析。

#### 3. 用户回复已连接后

重新从本节第 1 步开始走一次完整流程（不要复用授权失败前的输入与判断），授权通过后继续处理。

### 三、授权失败或凭证失效

按「打开连接器流程」重新引导用户连接或重新授权，提示语与未连接时一致，不暴露技术细节。同一轮对话内最多提示一次，用户未处理则等待用户回应，不重复弹窗打扰。

### 四、禁止事项

- 禁止在未连接状态下把分析结果编造给用户，或假装分析成功。
- 禁止因连接器未连接而改口说“我不支持企业风险分析”——应引导完成连接后继续。
- **禁止在卡片工具可用时偷懒只用文字引导**——文字兜底只允许在卡片工具不可用/调用失败时使用。
- 禁止展示 Token、服务地址、连接器内部标识、授权链路等技术信息。

## 业务范围

本 Skill 专注**企业风险分析**，通过关键词搜索企业并获取完整风险评估报告。

### 风险问题路由规则（执行前最先判断）

遇到"风险"类问题，先按**提问对象 + 风险类型**判断是否属于本技能：

**场景一：用户问"我的"（自己企业）的风险**

| 用户提到的风险类型 | 路由 | 说明 |
|------------------|------|------|
| 经营风险 / 运营风险 / 业务风险 / 财务风险 | → **经营分析**（本技能不处理） | 该类风险基于用户自己企业的业务数据评估，经营分析可覆盖 |
| 企业风险 / 法务风险 / 法律风险 | → **本技能**（企业风险分析） | 涉及工商、司法、行政处罚等外部风险信息 |

> 处理方式：命中第一行时，告知用户该类风险可通过「经营分析」获取（例如回复"分析一下经营状况"），本技能不执行、不调用任何工具，本轮结束。

**场景二：用户问"客户 / 供应商 / 其他企业"的风险**

| 用户提到的风险类型 | 路由 | 说明 |
|------------------|------|------|
| 任何风险类型（经营风险、运营风险、业务风险、财务风险、企业风险、法务风险、法律风险、信用风险等） | → 均走**本技能**（企业风险分析） | 系统没有其他企业的业务数据，无法进行经营分析，一律通过企业风险分析评估 |

### 企业全名要求（本技能所有场景的前置条件）

无论评估"我的"企业还是客户/供应商/其他企业，都必须先获得**目标企业的全名（或可用于搜索的名称）**：

| 用户表达 | 处理方式 |
|---------|---------|
| "我的公司/我们企业有什么风险"（未提供企业名） | 先询问："请提供您企业的全称，我来为您进行风险分析" |
| "我的供应商/某客户有什么风险"（未提供企业名） | 先询问："请提供该企业的全称，我来为您进行风险分析" |
| 已提供企业名称（全称或简称） | 直接进入搜索流程 |

- 未获得企业名称前，**禁止**凭空猜测、**禁止**调用企业搜索
- 用户提供简称时可先搜索，借助搜索结果帮用户确认企业全称

**适用场景**：
- 评估"我的"企业的企业风险/法务风险/法律风险（需提供自己企业的全名）
- 评估客户/供应商/其他企业的任何风险问题（需提供对方企业的全名）
- 用户需要了解企业的六维风险指标（经营异常、严重违法、行政处罚、司法协助、动产抵押、股权出质）

**不包含**：
- "我的"企业的经营风险/运营风险/业务风险/财务风险 → 走经营分析，本技能不处理
- 内部 ERP 系统中的客户/供应商查询 → 不支持，直接告知用户
- 仅搜索企业信息而不需要风险分析 → 仍使用本技能（搜索是风险分析的前置步骤）

## 工具调用规范

### 工具 1：搜索企业

调用 `kingbot_search_companies` 工具，传入搜索关键词：

```json
{"keyword": "搜索关键词"}
```

**参数说明**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 是 | 企业搜索关键词，如公司名称、简称等 |

**调用要点**：
- `keyword` 直接使用用户输入的企业名称或简称，忠实传递用户意图
- 无需对关键词做预处理
- 用户仅说"我的/我们的"而未提供企业名 → 不调用，先按「企业全名要求」向用户索要全称

### 工具 2：获取风险评估报告

调用 `kingbot_enterprise_risk_report` 工具，传入企业关键词及可选的关系参数：

```json
{"keyword": "企业名称", "relationship": "supplier", "cooperation_mode": "formal_order"}
```

**参数说明**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyword | string | 是 | 公司名称或简称，如"腾讯"、"华为技术有限公司" |

**调用要点**：
- `keyword` 使用搜索阶段确认的企业全称（优先）或用户原始输入

## relationship 参数路由

根据用户意图判断是否传入 `relationship` 参数：

| 用户表达 | relationship | 说明 |
|---------|-------------|------|
| "评估供应商XX的风险" / "XX供应商风险怎么样"（含供应商的任何风险类型） | supplier | 供应商风险审查 |
| "客户XX的风险分析" / "查一下客户XX的风险"（含客户的任何风险类型） | customer | 客户风险评估 |
| "我的企业风险怎么样" / "我的公司有法律风险吗"（已提供自己企业全名） | 空 | 自己企业的风险评估 |
| "XX企业的风险分析" / "查一下XX的风险" | 空 | 通用风险评估 |
| "合作前评估XX" / "XX靠谱吗" | 空 | 通用风险评估（未明确关系） |

> `cooperation_mode` 一般留空由系统自动推断，除非用户明确指定合作方式。

## 结果处理

### 搜索结果处理（kingbot_search_companies）

| 场景 | 处理方式 |
|------|---------|
| 无结果 | 告知用户未找到匹配企业，建议更换关键词重试 |
| 单条结果 | 确认企业后直接进入风险评估步骤 |
| 多条结果 | 列出候选企业，请用户选择目标企业后再进行风险评估 |

### 风险报告展示（kingbot_enterprise_risk_report）

获取风险报告数据后，**直接交由主 Agent 使用内置能力生成可视化 PDF 报告**。

风险评估报告包含以下信息，供主 Agent 渲染使用：

| 展示模块 | 内容 | 说明 |
|---------|------|------|
| 企业基本信息 | 法人、注册资本、成立日期、经营状态、经营范围 | 企业概览 |
| 风险评分 | 0-100 分，**分值越低风险越高** + 风险等级 + 颜色标识 | 核心指标，优先展示 |
| 六维风险指标 | 经营异常、严重违法、行政处罚、司法协助、动产抵押、股权出质次数 | 维度化风险展示 |
| 风险事件明细 | 事件类型、日期、内容、严重程度 | 如有风险事件则详细列出 |
| 股东信息 | 持股比例、是否质押 | 关注股权质押风险 |
| 年报摘要 | 营收、资产、利润、员工数、参保人数 | 经营状况参考 |
| 变更记录 | 变更内容 | 如有则展示 |
| AI风险分析报告 | 结构化风险分析结论 | 综合评估结论，重点展示 |

**展示要点**：
- 风险评分和风险等级**优先展示**，让用户快速了解整体风险水平
- 风险评分必须按「**分值越低，风险越高**」解读：低分（如 35 分）表示风险偏高，高分（如 85 分）表示风险偏低；严禁反向解读，风险等级以系统返回为准
- 六维风险指标以列表形式展示，标注每项的次数
- 风险事件明细按严重程度排序展示
- 企业未找到时（status=error）→ 告知用户并建议更换关键词

## 执行流程

```
1. 意图识别与路由
   ├─ 用户问"我的"+经营风险/运营风险/业务风险/财务风险 → 不属于本技能，引导用户走经营分析，结束
   ├─ 用户问"我的"+企业风险/法务风险/法律风险 → 属于本技能，评估对象为用户自己的企业
   ├─ 用户问客户/供应商/其他企业的任何风险 → 属于本技能（无其他企业业务数据，均走企业风险分析）
   ├─ 未提供企业全名 → 向用户索要目标企业全称，等待补充后重新进入本步骤
   ├─ 提取搜索关键词（企业名称、简称等）
   └─ 判断是否指定企业关系（供应商/客户）

2. 搜索企业
   ├─ 调用 kingbot_search_companies 搜索企业
   ├─ 无结果 → 提示更换关键词，结束
   ├─ 单条结果 → 确认企业，进入步骤 3
   └─ 多条结果 → 列出候选，用户选择后进入步骤 3

3. 获取风险评估报告
   ├─ 构建 kingbot_enterprise_risk_report 参数
   ├─ keyword = 确认的企业名称
   ├─ relationship = 根据用户意图判断（supplier/customer/空）
   └─ cooperation_mode = 留空（自动推断）

4. 结果处理
   ├─ 企业未找到（error）→ 告知用户，建议更换关键词，结束
   └─ 成功 → 将完整风险数据提供给主 Agent，由主 Agent 自行生成可视化 PDF 报告，**直接使用默认配置，不得向用户确认任何 PDF 参数**
```

## 常见问题

- **无搜索关键词**：用户说"帮我查企业风险"/"我的公司有什么风险"但未提供企业名 → 询问用户提供目标企业的全称（问"我的"时索要用户自己企业的全称）
- **用户问"我的经营风险/运营风险/业务风险/财务风险"**：→ 不属于本技能，告知用户该类风险基于自己企业的业务数据评估，可通过「经营分析」获取（如"分析一下经营状况"），本技能不执行
- **用户问"客户/供应商的经营风险/财务风险等"**：→ 属于本技能。系统没有其他企业的业务数据，无法做经营分析，统一通过企业风险分析评估，需向用户索要对方企业全名
- **搜索无结果**：建议用户尝试企业全称、简称或其他关联关键词
- **风险报告返回企业未找到**：搜索阶段能找到但风险报告未找到时，建议用户提供更精确的企业全称
- **关键词过短**：如单个字"中" → 可执行搜索，但提醒用户结果可能较多，建议提供更精确的关键词
- **内部客户/供应商查询**：用户想查 ERP 系统中的客户信息 → 直接告知不支持该操作
- **仅查企业信息不需要风险分析**：仍使用本技能，搜索结果展示后询问是否需要风险分析
