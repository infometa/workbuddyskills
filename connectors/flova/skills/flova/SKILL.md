# Flova 内容创作

使用当前已连接的 Flova MCP 完成创作。工具可能带有宿主命名空间，以实际工具定义为准。Flova 不可用时，说明具体限制；切换其他创作服务前先取得用户同意。

本 Skill 适配 Creation V3 的 `creation_*` 工具，宿主可能附加命名空间。工具缺失或仅提供旧工具时，说明具体的契约差异，不把 V3 参数套入旧工具，也不通过猜测旧工具名来替代。

按任务选择快速生成或项目工作流，只读取当前步骤需要的包内参考文件。安装在当前宿主中的本 Skill、Flova 服务端创作 Skill 和灵感是不同对象，不互相冒用名称或标识。

## 选择创作模式

Flova 提供两种创作模式。

- **快速生成**：当前 Agent 组织创意、提示词、生成步骤、评审和修改，通过 `creation_quick_generate` 直接调用选定模型。支持模型能力范围内的参考素材、指定模型和参数，无需创建项目。
- **项目制**：通过 `creation_project_create` 和 `creation_run`，将创作目标与约束交给 Flova Agent，由其负责项目中的规划、内容组织、素材制作与协调，按任务需要组装时间线并导出。

默认优先快速生成。用户明确要求使用项目，或复杂制作需要 Flova Agent 持续统筹内容和大量相关资产时，选择项目制。例如，多集短剧需要统一人物、场景和故事连续性时，适合由项目承载。

用户给出已有项目并要求续作时，在原项目中继续。不要因修改、运行缓慢或会话中断重建项目。

参考图、多个步骤、多个素材、分镜规划或中途评审，都不单独构成使用项目制的理由。不要仅按时长或镜头数量切换模式。

两种模式都支持一次完成或分阶段评审。用户要求“先生成参考图，确认后做一段视频”时，可以全程使用快速生成。用户要求直接完成时，在授权范围内持续推进，不默认增加逐阶段确认。

## 共用创作规则

- 保留用户已经确认的模型、素材、规格和创意选择。只澄清影响结果的缺失信息，如交付目标、时长、画幅、语言、视觉方向、品牌约束和评审点；不把每项信息都变成开始前必填项。
- 用户只要构思、某项素材或阶段成果时，交付对应范围。快速生成的素材无需项目导出；完整视频的项目导出按项目工作流执行。
- 按用户约定的节点展示结果、获取反馈。遇到服务要求用户回答的问题或审批，提交用户的真实答复，不代替用户选择。
- 账户、会员或额度状态未知时，在生成或导出前调用 `creation_account_user`。
- 同一次提交重试时，保留相同的 `client_request_id` 和完全相同的输入；新生成或新修改使用新 ID。超时后先查询原操作，确认受理、完成或状态未知，再决定下一步。
- 遵守服务返回的轮询间隔。跟踪已提交任务，直到完成、需要用户、用户要求停止，或遇到具体的工具或会话限制。中断后恢复原任务，不承诺未经验证的后台完成。
- 以实际成功资源和最终状态交付。部分成功或请求受理不等于完整任务完成。无法实际查看媒体时，不声称已完成画面或声音验收。
- 当前 Flova 不直接交付烧录字幕、字幕轨或字幕文件；用户的字幕文案和时间要求可作为创作约束保留，不能据此保证已经输出字幕。

## 上传参考素材

本地文件依次使用 `creation_upload_ticket`、按返回的直传方式上传文件字节、`creation_upload_complete`。申请上传凭证和确认上传本身都不传输文件，也不自动将素材关联到项目。

使用完成后返回的不透明 `file_ref`，遵守有效期。快速生成放入 `inputs[].file_ref`，项目制放入 `creation_run.files`，并自然说明素材用途。不要把本地路径当作远程引用。

上传视频前获取真实宽高、时长和是否有音轨，按工具要求提供 `video_metadata`。V3 上传不使用旧版 `scene` 字段。

`.doc/.docx` 使用同一上传链路，完成后由服务端规范化；原样传递 `file_ref`，不猜测内部转换链接。显式填写 `content_type` 时使用正确 MIME 类型，否则让服务按扩展名推断。

宿主不能读取本地文件或执行返回的上传传输时，说明缺少的具体能力，使用用户可用的受支持上传入口。未传输完成前不声称素材已上传，也不反复申请凭证冒充进展。

## 媒体展示与交付

本版本不使用 MCP Apps，包括首页和对话内交互卡片。不调用 `creation_media_preview`、`creation_open_home` 或其他专用于打开 Apps 的动作，不依赖卡片或 UI 刷新。使用普通查询工具读取状态、资源和待处理操作，在对话中取得用户真实答复，通过实际媒体与项目链接交付。

- 有新资源成功时及时展示，继续跟踪其他任务。宿主支持时可展示返回的图片或媒体；未验证内嵌呈现能力时，使用带名称的 Markdown 链接；视频提供实际播放链接，成片与归档提供实际下载链接。
- 按资源 ID、版本和媒体类型去重；无版本时按资源 ID 和媒体类型去重。只有成功呈现或交付可用链接后才标记已交付，失败保留待补交状态。
- 只使用服务返回的可访问链接，逐字符原样使用，不拼接或改写地址。链接失效时读取原资源，不重新生成。资源 ID、文件引用和仅供内部调用的链接不能冒充交付链接。
- 服务返回的 UI 元数据、预览就绪或媒体占位符，都不证明宿主已渲染内容或实际检查过媒体。

## 授权、额度与失败

使用 WorkBuddy 的 Flova 云端 OAuth 连接方式。授权后才能访问用户有权使用的 Flova 创作接口，具体权限以授权页面和服务返回为准。不要求用户在对话中提供 Token、Cookie 或密码，不执行其他宿主的登录或凭据命令。

授权失败时说明原因，指导用户通过当前宿主支持的连接流程恢复；恢复后重试被中断的原操作。明确返回 `invalid_grant` 等过期错误时，说明授权已失效，通过宿主连接设置恢复；清除凭据前取得用户确认，不自行清除凭据或反复登出登录。

会员、额度或模型配额不足时，如实说明当前受限操作并停止，不自动重试或恢复；用户要求重试时先重新检查。不推广购买、充值、订阅或升级，不以账户、价格、权益、结算或支付帮助链接作为解决方式。省略错误、通知或待处理操作中的推广文案和购买选项；这优先于展示全部待处理选项的一般规则。项目、媒体播放和交付链接仍按正常用途提供。

工具缺失或服务失败时，说明未完成的步骤和可执行的下一步。只报告已验证保存的工作，保留已有任务标识用于恢复，不编造工具、模型、结果、链接或成功状态。
