# 快速生成工作流

选择快速生成后阅读。当前 Agent 组织创作步骤，直接调用模型生成素材，无需先创建 Flova 项目。

## 1. 选择模型与准备输入

调用 `creation_generation_models` 查询可执行模型，使用 `detail="full"` 读取能力、参数、输入角色与访问条件。复用用户指定的模型，匹配实际支持的媒体、规格和输入；不猜测模型 ID 或参数。

本地参考素材先按[入口 Skill 的上传规则](../SKILL.md)上传，取得 `file_ref` 后放入受支持的 `inputs`。复用已生成资源时使用观察到的 `inputs[].resource_id`，如将用户确认的图片作为模型支持的 `first_frame`。输入角色、数量和格式均以所选模型为准。

## 2. 提交生成或修改

使用 `creation_quick_generate`，传入新的 `client_request_id`、媒体类型、模型、能力、提示词、支持的参数及参考输入。

修改既有快速生成结果时，使用实际返回的 `source_task_id` 或 `source_resource_id`，按工具规则继承未填写的生成配置。新修改使用新请求 ID；同一次提交的重试保持原 ID 和原输入。

若服务要求准备快速生成历史，按返回的下一步和状态标识使用 `creation_quick_migration_status` 跟踪；成功后以原请求 ID 重试原操作。这不需要创建项目。准备失败或取消后，只在用户要求重试时使用 `creation_quick_migration_retry`。

服务要求批量或高成本确认时，向用户呈现真实选项；取得答复后，使用返回的 `confirmation_token` 和原请求 ID 提交，不代替用户确认，也不擅自换模型绕过确认。

## 3. 跟踪和交付

通过 `creation_quick_status`，使用返回的批次 ID、任务 ID 或原请求 ID 查询。遵守 `poll_after_seconds`，检查每个任务及其 `tasks[].resources[]`；部分成功时说明其余任务的真实状态。

按[入口 Skill 的媒体展示规则](../SKILL.md)交付。使用状态结果和实际可用的资源读取工具取得图片、播放和下载链接，第一次成功即可展示；链接缺失时读取原任务或资源详情，不改用 Apps 预览，也不重新生成。

## 4. 评审、续作与取消

用户要求先审图再生成视频时，先完成并展示图片，保留任务和资源 ID。用户确认后，将该图作为下一次快速生成的受支持输入；修改时保留已确认的要求和素材。

一次完成的任务在授权范围内持续推进。需要项目规划与统筹的新范围按[入口 Skill 的模式选择规则](../SKILL.md)重新判断，不因单纯增加一次确认或修改自动切换项目。

通过 `creation_quick_history` 查找历史结果，翻页时保留筛选条件及已观察的任务、资源标识。

用户要求取消时，对准确批次调用 `creation_quick_cancel` 并核对返回状态。取消不撤销已完成输出或实际消耗。

素材完成后直接交付，不调用项目成片导出或项目资源归档来包装快速生成结果。
