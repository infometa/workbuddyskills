## 🔴🔴 第 0 层：英文输入总锁（v6.3 新增 · 优先级高于本文件一切路由）

> **这是本文件最高优先级的门，先于载体分流、先于四维标签、先于所有 combo 路由执行。一旦触发，锁死的三项参数在后续所有步骤中不可被任何标签/combo/默认值覆盖。**

### 触发条件（命中任一即锁）
- 用户**用英文发起请求**（哪怕只有一句 `give me a short drama`）
- 用户**显式要求英文短剧 / english / 海外 / 海外 / DramaBox**
- 用户给出的赛道/人名/场景是英文或西方的

### 锁死三项（LOCKED，全程不可解锁）
| 锁定项 | 锁定值 | 说明 |
|---|---|---|
| ① **输出语言** | **英文** | 全部产出（人名/台词/场景/旁白/工单）一律英文，**禁止任何中文人名、中文台词、中文剧情逻辑** |
| ② **目标市场** | **海外·欧美**（除非用户另指东南亚/拉美/日韩） | 自动加载 `markets/western.md` + 海外 Beats |
| ③ **本土化** | **全盘"该市场式"强制** | 人名/场景/制度/文化 100% 本地化到命中市场——默认欧美=西式；若用户另指日韩/东南亚/拉美则按该市场式（日式/在地式/拉美式）。**反中式故事套英文皮原则全市场通用**（详见对应 `markets/<市场>.md`；欧美见 western.md 0.1 节） |

### 🚨 多赛道独立过门铁律（本次新增核心修复）
当用户一次请求里包含**多个赛道**（如 `ceo romance / werewolf / cute baby / reverse harem short drama`）：

1. **逐赛道独立锁**：上述三项锁对请求里的**每一个赛道分别强制生效**，无一例外。
2. **🔴 命中国内国内 combo 不切回中文**：某些赛道（**cute baby/萌宝、reverse harem/逆后宫/团宠、真假千金、替身**）在国内国内体系里是高频 combo，模型会本能地"一命中国内赛道就切回中文输出 + 中式人设"——**这是本次要根除的头号 bug**。英文输入下，这些赛道**必须**：
   - 输出语言仍 = 英文（萌宝叫 Liam/Emma，不叫陆念念/苏暖暖）
   - 市场仍 = 海外（场景在美国，不在中式豪门大宅）
   - 人设仍 = 美式原型（见 `english-short-drama.md` 第九节美式角色原型库）
3. **赛道映射**：命中国内国内 combo 的赛道，**取其爽感骨架，换西式皮**——按海外"降级取料"兜底方案链取料（有海外原生 combo 直接用 → 无则回海外通用层 + 弱继承国内骨架，见 `ARCHITECTURE.md` 一·五节）：
   - 萌宝 → **有原生 combo**：`overseas/combos/secret-baby.md`（American single-dad / secret baby），直接用。
   - 逆后宫 → **暂无原生 combo（待建 reverse-harem）**：走海外通用层 + 弱继承国内逆后宫骨架（多个西式男主竞逐），强制换西式原生皮。
   - 团宠 → **暂无原生 combo（待建 found-family）**：走海外通用层 + 弱继承国内团宠骨架（everyone-adores-her / found-family），强制换西式原生皮。
   - 骨不变，皮全换；无原生 combo 时不指向不存在的文件，靠兜底方案链落地。
4. **禁止局部妥协**：不允许"前两个赛道写英文、后两个因为像国产题材就写中文"的混合产出。**任一赛道出现中文 = 整体不合格，重写。**

### 自检口令（生成前必跑）
> 请求是英文的吗？→ 是 → 那么**这一批所有赛道**的产出里，**有没有任何一个**出现了中文人名 / 中文台词 / 中式豪门大宅 / 唐人街 / 玉佩 / 华裔世家？→ 有 → **不合格，重写该赛道**。

## 载体维度分流（一级分流，先于四维标签）

在四维标签之前，先判定**载体维度**——决定加载哪套格式规范。漫剧复用短剧全部节奏规则，仅在格式与视觉表达上做补充。

| 载体 | 触发关键词 | 创作规范 |
|---|---|---|
| 竖屏短剧（默认） | 短剧、分集、剧本、国内、抖音、快手 | 通用短剧规范（stages/ + frameworks/） |
| 竖屏漫剧 | 漫剧、动态漫、漫画剧本、分镜、条漫 | 短剧全部节奏规则 + `references/formats/manga-drama.md` |

> 未命中漫剧关键词时默认走竖屏短剧。命中漫剧载体时，剧本阶段额外加载 `formats/manga-drama.md`，在标准剧本基础上补充「核心分镜提示」与视觉识别字段。

### 漫剧专属三维标签库（仅命中漫剧载体时加载）

漫剧题材偏好与短剧略有差异，命中漫剧载体时**优先加载独立的漫剧标签库 `references/tags-manga/`**（与真人三库标签体系分离）。该库每个标签为一个目录，含 `meta.yaml`（机器调度/质检的结构化数据，受 `references/common-tags/schema/tag.schema.json` 约束）+ `doc.md`（自由采样的创作素材，不参与评分）。优先级与四维一致（主题＞设定＞背景）：

| 维度 | 标签池（共 25 个，目录见 `tags-manga/{category}/{id}/`） |
|---|---|
| 主题（theme，8） | 末世、脑洞、豪门、剧情、玄幻、奇幻、科幻、冒险 |
| 设定（setting，8） | 异能、逆袭、重生、穿越、总裁、系统、反转、娱乐圈 |
| 背景（background，9） | 都市、乡村、年代、古代、架空、校园、异界、职场、民国 |

> **加载顺序**：先读全局索引 `references/tags-manga/registry.yaml`（由 `scripts/build_registry.py` 自动生成）定位标签目录 → 再读对应 `meta.yaml` 取权威规则（红线/互斥/叠加/融梗/视觉块）→ 需创作灵感时读同目录 `doc.md` 采样。
> 漫剧标签仍走第二轨原子标签拼接逻辑，不新增预设爆款组合；主轴仍从 `domestic/combos/` 取最接近 combo。每个漫剧标签的 `meta.yaml` 含 `manga` 扩展块（visual_signature / high_affinity / visual_hooks），供分镜与视觉钩子参考。**漫剧另有视觉化高适配的专属子类型**（玄幻修仙/异能觉醒/末世废土/星际科幻/神话志怪/国风古言），命中漫剧载体且用户说"随意"时，优先从 `formats/manga-drama.md` 漫剧专属子类型库展示选项。

## 四维标签体系（对齐国内官方筛选维度）

| 官方维度 | 创作定位 | 权重优先级 |
|---|---|---|
| 受众 | 决定叙事视角、爽点逻辑、台词风格，是底层逻辑 | 1（最高）|
| 设定 | 决定核心金手指、核心爽点、核心钩子，是短剧灵魂 | 2 |
| 主题 | 决定主线冲突方向、故事内核、价值落点 | 3 |
| 背景 | 决定世界观载体、场景道具、人物身份，是舞台 | 4（最低）|

> 优先级铁律：**受众 > 设定 > 主题 > 背景**。高优先级定主轴，低优先级做润色。标签体系对齐国内官方 60 标签全表（详见 `references/domestic/INDEX.md` 与 v7.0 标签库 `references/common-tags/INDEX.md`）。

## 受众基调路由（全局总开关 · 内联于路由层）

**受众（男频/女频）不是普通标签，是分发与创作的总开关**——它先于设定/主题/背景定调，决定整部剧的叙事视角、爽点逻辑、情感权重与台词风格。故内联在本路由层，**不建独立标签文件、不参与标签分级与质检号**。步骤 0 推断出受众后，以下基调全局覆盖，与其它三维标签规则冲突时一律按受众基调修正。

### 男频基调
| 项目 | 基调 |
|---|---|
| 核心视角 | 男性主角第一视角，观众代入主角实现自我投射 |
| 爽点优先级 | 实力碾压 > 阶层跨越 > 情感获得 > 情绪共鸣 |
| 节奏偏好 | 快节奏、高密度打脸、短压大放（压弹簧周期 ≤5 集） |
| 情感线权重 | 副线，占比 ≤30%，服务于主角成长/逆袭主线 |
| 反派塑造 | 必须纯坏，嚣张愚蠢欺软怕硬，打脸反应身体化（腿软/瘫坐/喷血），忌长篇忏悔 |
| 女性角色 | 可作助力/见证/情感副线，不应成为主角核心决策动因 |
| 高频设定 | 战神归来、赘婿逆袭、神豪、龙王、天下无敌、强者回归、无敌神医 |

### 女频基调
| 项目 | 基调 |
|---|---|
| 核心视角 | 女性主角第一视角，观众代入体验情感与成长 |
| 爽点优先级 | 情感获得 > 自我成长 > 打脸解气 > 实力碾压 |
| 节奏偏好 | 压放交替、细节拉扯，甜虐交错（甜-虐-甜振荡） |
| 情感线权重 | 主线或核心副线，占比 ≥40%，是核心情绪供给来源 |
| 女主塑造 | 有闪光点但不完美，可柔弱但有底线，成长弧光清晰；忌无脑圣母、全程依附男性 |
| 男主塑造 | 反差核心——对外冷酷/强大，对女主专属温柔；忌油腻、花心、不尊重女性 |
| 反派塑造 | 反派必须纯坏，女性反派侧重心机/绿茶/仗势欺人，打脸侧重社会性死亡而非物理伤害 |
| 高频设定 | 霸总、大女主、真假千金、团宠、萌宝、替身、王妃、女帝、皇后 |

> 受众基调冲突消解：男频挂载现言甜宠/虐恋仅可作极弱副线点缀；女频挂载战神归来/龙王/赘婿仅可作背景设定点缀。**受众基调为最高优先级，所有其它标签规则与之冲突时按受众逻辑修正。**

### 🔴 受众判定铁律（v7.2.1 新增 · 全局 · 修正"关键词对号入座"误判）

**[作用域：全局 · 中英通用]** 受众判定按以下优先级执行，**高优先级覆盖低优先级**：

| 优先级 | 判据 | 说明 |
|---|---|---|
| 1（最高） | **主角性别** | 主角是男性 → 男频；主角是女性 → 女频；**LGBTQ 主角对（含 BL/GL/双性）一律归女频**（女频基调覆盖） |
| 2 | 主导动作校验 | 性别不明/双视角时，看"谁推动核心冲突"——男主推动复仇/碾压/归来 → 男频；女主推动成长/打脸/选择 → 女频 |
| 3（最低） | 关键词硬匹配 | 第一层关键词表（霸总→女频、战神→男频 等）**仅作兜底**，性别已知时一律让位 |

**反例（必避）**：
- ❌ "Billionaire CEO secretly funds wife... exposes identity + destroys empire" → 见"霸总"关键词判女频。**错**：主角 Kieran 是男性 + 主导动作是毁灭反派 → **男频**
- ❌ "CEO 的宠妻日常" → 见"CEO/霸总"判女频。**对**：主角虽是男主，但叙事重心是宠女主/情感供给，按优先级 2 校验后仍女频

**关键判据**：是"主角性别 + 主导动作"决定受众，不是"赛道关键词"决定受众。赛道关键词（霸总/CEO/战神）只决定标签，不决定受众。受众错了，后续基调全错。

### v7.0 标签库加载（设定/主题/背景三维）
推断出三维标签后，**必须先 Read `references/common-tags/INDEX.md` 的「中文别名 → 标签速查表」做中文匹配定位**，再按命中行的"文件"列 Read 对应标签文件（按 market 落在 `common-tags/` 或 `domestic/tags/` 或 `overseas/tags/` 的 `{setting|theme|background}/<文件名>.md`）：
- **🔴🔴 全表扫描铁律（v8.1 新增 · 先于速查表 · 防漏标）**：速查表只覆盖约 80% 高频口语别名，**不得只匹速查表就下结论**。打标签前，必须**完整通读当前市场对应的 INDEX 全表**，逐行比对"标签"列中文名 + 别名，而非命中速查表一行即停——目的是"库里有的标签绝不因别名未收录而被漏掉"。具体：① 先读 `common-tags/INDEX.md` 的速查表快速定位常见项；② **再逐行扫描该文件第三/四/五节的设定/主题/背景全表**（当前市场可用的每一个标签都要过目一遍）；③ **海外任务额外通读 `overseas/tags/theme/beats-shared.md` 与 `beats-overseas-only.md` 的全部 `##` Beat 标题**（海外 Story Beats 聚合在这两个大文件里、不在离散全表中，只匹 INDEX 必漏）；④ combo 同理——**通读当前市场 `domestic/INDEX.md` 或 `overseas/INDEX.md` 路由表的每一行 combo**，再挑命中项，不止看第一个像的。此扫描是"全表比对候选"，不是"全文加载"：只读索引表与 Beat 标题清单，命中后才 Read 具体文件正文，token 增量可控。
- **🔴 市场分池铁律（先于选标签）**：先确定市场，**只在 `market` 字段匹配当前市场的标签池里选**——**国内任务**取 `market ∈ {cn, both}`（禁用纯 overseas 标签）；**海外任务**取 `market ∈ {overseas, both}`（**绝不命中纯 cn 标签**，如女帝/赘婿/仙侠/古代权谋/民国等中式专属题材）。海外任务可用标签的 `markets` 字段进一步匹配具体海外市场（欧美/日韩/东南亚/拉美），优先推荐标了当前市场的标签。**全表扫描铁律与本铁律叠加：先按市场分池，再在池内做全表扫描（国内不扫 overseas 全表，海外不扫 domestic 全表）。** 见 `ARCHITECTURE.md` 一·五节双分支规则。
- **定位铁律**：用户与 LLM 全程用中文；英文文件名只是内部标识符。**严禁把中文标签直译成英文去猜文件名**——一律以 INDEX.md 速查表/全表的"文件"列为唯一真相源。表中无命中 → 按下方「库外标签处理铁律」兜底，**绝不虚构英文文件名**。
- **🔴🔴 库外标签处理铁律（v8.1 新增 · 全表扫描后仍无命中时）**：当用户给的题材/标签，经全表扫描（速查表 + 当前市场全表 + 海外 Beats 标题清单）确认**库里确实没有对应项**时（如"电竞/赛车/美食复仇/AI 觉醒"等库外题材），按以下四步**静默兜底，不就此打扰用户**：
  1. **不静默替换成库内标签**：保留用户原始题材外壳，**不得**把"电竞逆袭"硬掰成库内某个最像的标签（如直接替换为"职场逆袭"），以免丢失用户真实意图；
  2. **拆解到"机制层"**：把陌生题材拆成库里有的底层元素——借库内标签的**情绪骨架 + 爽点机制**，陌生题材只作**外壳皮**。例："电竞逆袭"→ 借「逆袭」情绪骨架 + 「打脸虐渣」爽点机制，电竞仅是包装皮；"美食复仇"→ 借「复仇」骨架 + 「打脸虐渣」机制，美食是舞台皮；
  3. **走通用兜底 combo + fusion 五步法现场构造**：Read 当前市场的通用兜底（国内 `domestic/combos/general.md` 通用爽感公式 + Top3 套路差异化对照；海外 `overseas/general-overseas.md` 跨市场爆款结构 5 条 + 本土化基调），再按 `fusion/_METHODOLOGY.md` 五步法把"库内机制骨架 × 库外题材皮"构造成反应式；**短剧性红线（R1-R10）照常体检，不因库外题材豁免**；
  4. **工单内部标注**：在标签化工单里把该题材标为"库外题材·按〈XX 库内机制〉兜底生成"（供 agent 自己追溯），无需单独向用户解释兜底过程。
  > 核心原则：**库外标签 = 保留用户原始外壳皮，借库内机制骨架**；全表扫描铁律只保证"库里有的不漏"，本铁律负责"库里没有的也能落地"，二者互补。
- **变体素材库（第二节）** → 作为创作灵感，仅参考、可自由组合/原创/豁免，**不强制命中**；
- **红线（第五节）** → level-1 强红线标签的 `AP-` 反模式纳入步骤 4 自审扣分（见 `common-tags/INDEX.md` 号段总表）；level-2 弱红线仅作避坑提示。
- 标签文件的 `related_combo_cn` / `related_combo_overseas` 字段按市场指向对应 combo；当前市场侧无对应则走该市场的兜底方案链（海外见"降级取料"三级继承，`ARCHITECTURE.md` 一·五节）。

### 第二层：概率默认补全（中置信度，用大盘数据兜底，80% 场景不需要问用户）

缺失的维度用国内大盘分布补默认值：

1. **受众默认**：中文输入、无明确男频关键词 → 默认女频（国内女频体量占比更高）
2. **背景默认**：无明确时代/场景 → 默认现代都市（大盘占比最高）
3. **设定默认**：有重生/穿越默认附带「打脸虐渣」；有赘婿默认附带「强者回归」
4. **主题默认**：现代都市默认「现言」；古代默认「古言」
5. **市场默认**：中文提问、无海外关键词 → 默认国内；**英文提问/明确要英文短剧 → 默认海外·欧美**
6. **集数默认**：无明确集数 → **默认 80-100 集**（竖屏短剧标准体量）。⚠️ 即使用户给了较小集数（如 30 集），节奏仍按"每集 1-2 个反转/爽点"的短剧密度走,**绝不能因为集数少就放慢成长剧节奏、铺长线慢热**。集数少 = 爽点更密、推进更快,不是更慢。
7. **🔴 模糊海外/英文输入的赛道默认（v6.2 新增 · 关键修订）**：当用户输入模糊（如 "give me a short drama" / "写个英文短剧"）、未指定具体题材时,**默认走"最爽"的商业赛道,严禁默认走"最文艺/最有深度"的方向**：
   - ✅ **默认候选**：霸总契约（Billionaire/Contract）、灰姑娘逆袭打脸（Revenge/Comeback）、命定狼人（Werewolf/Fated Mates）、豪门复仇（Wealthy/Revenge）、闪婚甜宠（Flash Marriage）——这些是 海外/DramaBox 真实头部爆款。
   - ❌ **严禁默认**：心理惊悚、家庭伦理深度剧、悬疑剧、社会议题剧、缓慢的女性自我觉醒文艺片——这些是 HBO/Netflix 调性,**不是短剧**。模型会本能地觉得这些"更高级",必须强行掰回爽剧方向。
   - **判据**：模糊输入时,问自己"海外 首页推荐位上最多的是哪类?"——是霸总、狼人、复仇、契约,不是心理惊悚。默认就走首页爆款款式。
   - 展示 2-3 个最爽方向给用户选,用户不选则自选其中最爽的一个开写。

### 第三层：缺失 & 冲突检测（仅此时发起提问，且一次问完）

只有满足以下任一条件，才发起一次确认，**绝不拆成多轮**：

1. **核心维度双缺失**：受众、核心设定两个维度都没命中，完全无法推断主轴（如用户只说"写个短剧"）
2. **强互斥冲突**：出现甜宠+虐恋、喜剧+恐怖等强互斥标签，无法自动判定主轴
3. **极低置信度**：所有维度全靠默认填充，没有命中任何关键词

**极简提问话术（一次问完）：**

> 我初步梳理了创作方向，两点跟你确认下就可以开始：
> 1. 主轴偏男频爽感还是女频情感？
> 2. 核心设定你更偏向哪类：重生穿越、系统金手指、还是身份马甲？

用户回答一次即可补全所有核心标签，不再追问。

### 选题菜单机制（v6.0 平台标签驱动）

> 🔴 **prompt 复杂度分流闸门（v6.6 新增 · v8.0 调整 · 全局 · 最先判定）**：进入选题菜单前，先判断用户 prompt 的复杂度，决定"给不给选项"——这是治"简单 prompt 永远产出同一部剧"（霸总→苏念念/陆景琛/替嫁满分）的核心闸门。**v8.0 调整：不再一刀切禁止经典款，改为"差异化选项 + 保留 1 个经典款兜底"**——因为有的用户就是需要经典套路。
>
> | prompt 类型 | 判定标准 | 处理方式 |
> |---|---|---|
> | **简单 prompt** | 只给赛道/类型，无具体设定。如"给我个霸总短剧""写个短剧""sports 短剧""给我个甜宠选题" | **走融梗 + 给 3 个选项（含经典款兜底）**：① 做融梗——至少 2 个选项从机制层找非默认切入（提供新鲜方向，避免永远同一部）；② 3 个选项在「主角身份/核心冲突/爽点机制」三维度尽量拉开差异；③ **保留 1 个「经典热门款」并明确标注**——该赛道最成熟、观众最熟悉的经典组合（霸总→替嫁/先婚后爱等）也作为一个选项列出，供想要经典套路的用户直接选（**用户要经典款是正当需求**）；④ 选项里的人名仍需避开高频黑名单（见 `2-character.md` 命名红线，防苏念念/陆景琛式撞名）。**若用户直接点名"就要最经典的/就要替嫁那种"→ 直接给经典款，不强制融梗** |
> | **复杂 prompt** | 已含完整设定/大纲/人物/世界观，或贴了一大段剧本/小说。如"重生贵族复仇+具体人名+完整synopsis" | **不给选项，直接执行**：用户已经表达了明确创作意图，再给选项是干扰。直接按其设定推进（但仍需用 anti-tv-drama 红线体检，崩坏照样拦） |
> | **中等 prompt** | 给了赛道+1-2个具体要素（如"霸总+重生复仇"） | 按融梗三问处理，可给 2 个选项或直接定一个方向并说明理由，不强制 3 选项 |
>
> 判据：**用户给的信息越少，你越要主动融梗+给差异化选项**（防同质化），**但始终保留经典款兜底供用户选择**；**用户给的信息越完整，你越要少打断**（防过度干预）。


当步骤 0 推断出四维标签后，**按平台路由**：国内市场 → **Read `references/domestic/INDEX.md`** 查爆款组合路由表，命中 → **Read 对应 combo 文件**获取核心知识与参考方向（按需加载，只读命中的 1 个 combo）。海外市场 → **Read `references/overseas/INDEX.md`** 查 海外 路由表，命中 → Read 对应 combo 文件。

### 🔴 combo 命中度评分机制（v7.2.1 新增 · 全局 · 修正"贪图对号入座"误落 combo）

**[作用域：全局 · 国内国内 + 海外 海外 通用]** combo 文件顶部都标有**主标签 + 辅标签**两层结构（如 海外 #5：主标签=Revenge Comeback；辅标签=Identity Reveal / Long-Lost Heir / Rebirth / Second Chance）。命中规则：

1. **主标签必须全部命中**才能走该 combo——这是硬约束，任一主标签未命中即整 combo 不命中
2. **辅标签是可叠加项**，不强制命中——命中越多 combo 匹配深度越高，用于多 combo 都满足主标签时做排序
3. **无 combo 主标签全部命中时 → 走 Beats 组合兜底方案链**：
   - 海外：Read `overseas/tags/theme/beats-shared.md` 取命中的非红线 Beats 组合 + `overseas/real-hooks.md` 真实爆款桥段库 + `overseas/general-overseas.md` 兜底
   - 国内：Read `domestic/combos/general.md` 通用兜底 + 命中标签文件 + `frameworks/emotion-spring.md`

**展示规则（v6.0 平台标签版）**：
1. 从该赛道的参考方向中，展示 **2-3 个差异最大**的选项（在主角身份/核心冲突/爽点机制/开局切入/叙事结构上尽量分散）
2. 每个参考方向只展示：**方向名称 + 一句话卖点 + 情绪底色**
3. 用户选编号即可，不说"帮我推荐"就全部展示后让用户挑
4. 用户说"随意""都行"→ 选择**本次会话中未展示过**的方向；若全部已展示过，则基于赛道核心爽感**自由发散一个新方向**（不受参考示例限制）
5. 用户也可以自行指定任意方向，不受参考示例限制——参考方向仅供启发，不是可选清单的边界
6. **维度差异去重规则**：同一会话内再次生成选题时，本次选题必须在以下 5 个维度中至少更换 2 个——**主角核心身份、核心冲突类型、爽点触发机制、开局切入方式、叙事视角结构**。不足 2 个维度差异时，须主动调整后再展示。
7. **机制优先于包装**：生成选题时，先确定"用什么底层机制制造爽感/揪心"（信息差、身份反转、代价交换、规则博弈、命运闭环……），再为它套一个**原创的外壳**；严禁先抓一个现成的烂大街外壳（如"签到系统""战神归来"）再往里填内容。

**展示话术**：

> 这个题材有几条不同的爆款路径，看看哪个更心动：
> ① **强宠占有型**：霸道入侵→沦陷→独宠（心动+被征服感）
> ② **暗线反转型**：甜宠外壳→暗线揭出→抉择→选择爱（甜蜜→震撼→重建）
> ③ **治愈偏爱型**：各有伤痕→看见脆弱→相互治愈（心疼+被接纳感）
>
> 选个编号就行，也可以自己说个方向，说"再看看"我换一批。

### 融梗碰撞模式（v5.3 升级）

#### 被动触发：标签组合无对应 combo/配方 时
当命中的标签组合无对应 combo 文件和融梗配方文件时，进入融梗碰撞模式：
1. Read `references/fusion/_METHODOLOGY.md`，按**融梗五步法**执行
2. **内核提取**：读取各标签文件的 `emotion_core` 字段与叙事功能
3. **张力识别**：判断标签间关系（增强型/对冲型/裂变型）
4. **化学反应构造**：构造融梗反应式（主轴+辅轴+裂变新特性）
5. **创新涌现**：基于反应式生成 3 个差异化方向供用户确认

#### 主动融梗推荐：主流组合叠加弱相关标签
当命中主流配方时，基于配方文件的"裂变型亲和"表或以下推荐表，主动推荐 1 个碰撞标签：

| 主流配方 | 推荐碰撞标签 | 碰撞预期 |
|---|---|---|
| 霸总甜宠 | 种田/玄学/年代 | 烟火气治愈/神秘感/时代反差 |
| 战神赘婿 | 校园/萌宝/种田 | 身份反差/铁汉柔情/隐忍日常 |
| 重生复仇 | 甜宠/种田/年代 | 情感温度/经营慢节奏/时代质感 |
| 女性成长 | 种田/职场/年代 | 事业感/现代独立/时代觉醒 |
| 宫斗重生 | 甜宠/种田/系统 | 情感供给/日常烟火/任务驱动 |

用户选"是" → 叠加该标签规则，走融梗碰撞生成；选"否" → 走原配方流程。不增加用户负担。

主动融梗的核心逻辑：主流底盘保爽感基本盘，小众标签贡献新鲜感——80% 熟悉 + 20% 新鲜，是短剧差异化的配方。融梗不是把两个标签"拼在一起"，而是让它们产生**化学反应**——A×B 产生 A 和 B 单独都不具备的新叙事特性。
