# 融梗方法论（v2.0 精简版）

> **v2.0 设计原则**：Skill 的核心价值是「指明方向 + 守住底线」，不是「规定每一步怎么走」。
> 纠正错误的规则（别写拼接梗、别节奏拖沓）：多多益善。
> 规定正确答案的规则（必须按这几个方向写、必须满足这几个量化指标）：越少越好。
> 能让 LLM 把算力花在「故事本身」上的设计：加分。
> 让 LLM 把算力花在「走流程、做自检、满足规则」上的设计：边际效益递减，适可而止。

---

## 一、融梗的本质（唯一不可动摇的底层认知）

**融梗 ≠ 拼接，融梗 = 化学反应。**

- **物理拼接**（A+B）：穿越的桥段 + 系统的桥段，两者各演各的，只是出现在同一部剧里。删掉穿越，系统的故事完全不受影响。
- **化学反应**（A×B）：穿越的核心设定改变了系统的运作方式，产生 A 和 B 单独都不具备的新叙事特性。删掉穿越，系统的故事核心坍塌。

> 这是所有 S 级爆款融梗短剧的共同特征——梗和梗必须互相作用、互相改变，生出两个梗单独都没有的新冲突和新爽点。这不是人为加的条条框框，是爆款创作的底层规律。

---

## 二、融梗三问（创作时自问，非流程化拆解）

LLM 在处理多标签组合时，只需自问三个问题。不需要走完整流程，不需要填表，不需要打分——三个问题回答完，融梗方向就清楚了。

> **推导提示（自评前三问前先做）**：直接复用步骤 2 用户已确认的「融梗一句话」——A×B 产生了什么新叙事特性（不是 A 的 + B 的，是"乘"出来才有的）。用户已确认则直接用，未确认或方向已调整才重新推导。写不出这句话→说明还没想通融梗方向，先想通再进入三问。
>
> 示例：穿越×系统×甜宠 → "系统任务约束让穿越者的开天眼不再是无限开挂，攻略男主才能通关但真心爱上就触发惩罚"——这个困境是三个标签单独都没有的。

### 问题 1：删掉标签 A 后，标签 B 的核心冲突会不会坍塌？

**这是判断真假融梗的黄金标准**——朴素但极其有效。

- **会坍塌** → 融梗成功。A 已经深度融入 B 的核心结构。
- **不坍塌** → 物理拼接。A 只是表面叠加，需要重构。

**怎么用**：写之前想清楚"如果没有这个设定，这段戏还成立吗"。写完后做一次思想实验——把 A 的桥段全删掉，B 的故事还讲得下去吗？

**示例**：
- 穿越 × 系统：删掉穿越，系统故事还成立吗？→ 如果系统任务是"攻略目标"，而穿越者恰好知道前世的悲剧结局，删掉穿越后系统任务变成普通的"做任务"——核心冲突坍塌 → 融梗成功
- 甜宠 + 打脸（各演各的）：删掉甜宠，打脸故事还成立吗？→ 完全成立，甜宠只是插入的恋爱戏——不坍塌 → 物理拼接

### 问题 2：全剧最关键的 3 个转折点，有没有至少 1 个是 A×B 产生的新桥段？

**纯 A 或纯 B 单独能产生的桥段不算**——必须是两个标签共同作用才能产生的。

- **有** → 裂变新特性在剧情中体现了
- **没有** → 裂变只是概念，没有落地到剧情

**示例**：
- 穿越 × 系统：关键转折"穿越者违抗系统任务救人"——纯穿越产生不了（没有系统约束），纯系统也产生不了（没有前世记忆的冲突）→ 这是 A×B 产物 ✓
- 穿越 × 系统：关键转折"穿越者用现代知识种田"——这是纯穿越的桥段，系统没有参与 → 不是 A×B 产物 ✗

### 问题 3：前 3 集每集有没有至少 1 个明确爽点释放？

**短剧商业约束**——创意再好，前 3 集抓不住人就是扑。

- 前集 1：有没有一个"开局即爽"的钩子？
- 前 2 集：有没有持续释放爽点？
- 前 3 集：有没有一个让人"必须看下一集"的悬念？

> 这三个问题不是流程，是创作时自然思考的维度——就像厨师做菜时自然会想"咸不咸、熟没熟、好不好看"。不需要填表打分，问完就写。

## 三、四条底层规律（落地到 Skill，多多益善）

### 规律 1：化学反应 ≠ 物理拼接

已在第一节详述。落地方式：步骤 1 第三轨加载本文件，步骤 4 反模式 12 检测。

### 规律 2：抽离测试

已在问题 1 中详述。落地方式：步骤 4 作为反模式 12 的检测工具（坍塌=通过/不坍塌=扣分）。

### 规律 3：四维各取一个（融梗选料铁律 · v8.1）

**短剧单集 1-2 分钟，叙事容量极其有限，核心设定超过 3 个必然散焦。** 融梗标签严格按平台四维取料：

- **受众**（男频/女频）：只定全剧基调，是总开关，**不进反应式**（受众基调为全局最高优先级，见路由层）
- **进反应式的 3 个标签 = 设定 / 主题 / 背景各取 1 个**：
  - 设定标签 → 主角身份 / 金手指 / 能力体系
  - 主题标签 → 主线冲突机制
  - 背景标签 → 世界观舞台
- 正好 3 个融梗标签，与"3 标签上限"自动对齐

**同维度多标签时的取舍**：某一维度命中多个标签，按 **用户指定 > 权重 high > 爽点/情感供给最强** 取 1 个进反应式，其余降级为"背景调性"（只在氛围层渗透，不参与反应式构造）。

**某一维度缺失时**：用步骤 0 概率默认补全的标签顶上（如背景缺失→默认现代都市；主题缺失→现代默认现言/古代默认古言）。

**仅命中两维时**：按命中的两维各取一个（如只有设定+主题）做标准两标签融梗。

> 这不是限制创意，是保护叙事聚焦度，同时让融梗选料对齐平台四维体系。很多新手编剧（和 LLM）都喜欢贪多，觉得元素越多越好看，实际效果恰恰相反。

### 规律 4：短剧商业约束

创意不是"想出来就行"，而是"想出来的东西能在短剧赛道上赚钱"。创作时自问：

| 维度 | 自问 |
|---|---|
| 爽点密度 | 前 3 集每集有没有爽点？ |
| 受众预期 | 核心爽感对齐受众基调了吗？（男频→爽感驱动；女频→情感驱动） |
| 单集钩子 | 每集结尾有没有让人必须看下一集的钩子？ |
| 节奏适配 | 融梗后的节奏符合短剧体量吗？（80-100 集，每集 1-2 分钟） |

> 这四条不是"五维标尺"式的流程化校验，是创作时自然考虑的商业维度——想到了就规避，不需要填表打分。

## 四、融梗参考工具（可选使用，不强制走完）

> 以下工具是"思维脚手架"——LLM 遇到不知怎么融的组合时可以拿来参考。但不需要每次都走完全部工具，也不需要按顺序走。

### 4.1 三种反应类型（判断标签间关系）

| 类型 | 特征 | 识别方法 |
|---|---|---|
| **增强型** | A 放大 B 的爽感，不改 B 的核心机制 | 情绪方向一致 + A 不改变 B 的玩法 |
| **对冲型** | A 和 B 情绪方向相反，交替主导产生振荡 | 情绪方向相反 |
| **裂变型** | A 的设定使 B 产生全新可能（最高形态） | 情绪方向一致 + A 改变 B 的核心机制 |

> 遇到不知怎么融时，先判断是哪种反应类型，再推导裂变方向。但这只是参考——如果 LLM 能直接想出好的裂变方案，不需要先判断类型。

### 4.2 四种裂变推导方法（想不出裂变时用）

| 方法 | 操作 |
|---|---|
| **设定碰撞法** | "如果 A 的设定是真的，B 的玩法会怎么变？" |
| **情绪逆转法** | "如果 A 的情绪被 B 逆转了，会产生什么新体验？" |
| **功能反转法** | "如果 A 的功能反过来了，B 会怎么应对？" |
| **载体置换法** | "把 A 的叙事功能用 B 的载体/场景来实现" |

> 四种方法不需要全部尝试——遇到卡壳时挑一个试试，想出来就行。

### 4.3 冲突消解（标签规则矛盾时参考）

当两个标签的规则/红线出现矛盾，从以下模式中选最合适的：

| 模式 | 适用场景 |
|---|---|
| 主轴优先 | 辅标签的规则与主轴冲突 |
| 交替主导 | 对冲型组合，两个标签都要主导 |
| 融合重构 | 两个标签的规则可以合并为新规则 |
| 功能降级 | 辅标签的核心功能与主轴不兼容 |
| 互斥剥离 | 强互斥标签中保留主轴 |

> 这是"参考"不是"必须按模式走"——如果 LLM 能自己想到更好的消解方式，不用查表。

## 五、融梗红线（守住底线，不可突破）

| # | 红线 | 崩的表现 |
|---|---|---|
| 1 | **爽点抵消** | 两个标签的爽点互相抵消，观众不知道该爽还是该虐 |
| 2 | **节奏撕裂** | 两个标签的节奏要求冲突，剧情忽快忽慢 |
| 3 | **逻辑矛盾** | 两个标签的世界观/设定逻辑矛盾 |
| 4 | **主次失衡** | 辅标签喧宾夺主，主轴标签被边缘化 |
| 5 | **四不像** | 融合后既不是 A 也不是 B，失去核心定位 |

**绝对互斥组合**（不可融，二选一）：

| 标签 A | 标签 B | 互斥原因 |
|---|---|---|
| 沙雕喜剧 | 虐恋 | 轻松基调与心碎根本冲突 |
| 无敌神医 | 悬疑推理 | "一招秒杀"与"层层推理"逻辑互斥 |

## 六、配方使用规则（v5.4 降级为参考）

`references/fusion/recipes/` 下的 16 个配方文件：

- **定位**：最佳实践参考，不是强制命中
- **使用方式**：可选 Read，了解市面成熟写法
- **禁止**：直接使用配方的 3 个方向
- **要求**：推导方向必须与配方方向做差异化对照（身份/冲突/爽点至少 2 维有本质差异）

> 配方是"素材库"——告诉你市面上有什么鱼，不是替你决定钓什么鱼。弱模型可以拿配方起跳，强模型可以跳过配方直接推导。

## 七、与主流程的接入

| 步骤 | 接入方式 |
|---|---|
| 步骤 0 | 标签推断完成后，LLM 按融梗三问自行推导融梗方向 |
| 步骤 1 | Read 本文件获取方法论；配方可选 Read 做参考 |
| 步骤 2 | 输出融梗一句话+核心冲突+2-3个差异化方向供用户选择 |
| 步骤 2.5 | 骨架三件套中标注融梗方向 |
| 步骤 3 | 基于融梗方向创作，而非各标签独立拼接 |
| 步骤 4 | 抽离测试（删掉A后B崩不崩？）作为反模式12检测工具 |

> **核心原则**：本文件只提供方向和底线，不规定每一步怎么走。LLM 的大部分算力应该花在"怎么把故事写好看"上，而不是花在"走流程、做自检、满足规则"上。融梗的终极目标从来不是"融合了多少个标签"，而是"好不好看、抓不抓人"。
