# 标签库 Schema 与编写规范（v7.0.0 · 唯一标准）

> 本文件是三库（`common-tags/` 公用 + `domestic/tags/` 国内特有 + `overseas/tags/` 海外特有）下所有标签文件的**唯一编写标准**。新增或修改任何标签文件前必读。
> 核心设计：**双开关模式** —— 只设失败下限（红线），不限创作方向（素材）。

---

## 0. 设计总原则（不可违背）

| 开关 | 作用 | 落地方式 |
|---|---|---|
| **开关① 红线（守下限）** | 每个标签只回答"违反什么会让这部剧崩？" | 有强失败模式 → 列红线 + 挂质检号 + 步骤4必检 |
| **开关② 素材（提上限）** | 给 LLM 灵感，绝不限制发挥 | 所有桥段一律"变体素材库"，标注"仅参考·可自由组合·可原创·可豁免"，**永不强制命中** |

**铁律：**
1. **禁止任何"强制命中"表述**——删除"必备桥段池""至少命中N项""最小适配桥段数""全剧至少呈现N个台阶"等一切硬性命中要求。桥段池只供启发，绝不作为评分依据。
2. **标签文件只扣分、不加分**（见第3节分值机制）。
3. **红线按"崩不崩"分级，不按"市场热度"分级**（见第2节）。

---

## 1. 目录与命名

### 1.1 目录结构（v8.0 三库架构）
```
references/common-tags/          ← ★公用标签库（market=both · 两地通用）
  _SCHEMA.md          ← 本文件
  INDEX.md            ← 标签全表 + combo映射 + 号段总表（权威副本）
  schema/tag.schema.json ← 机器校验数据契约
  background/ theme/ setting/  ← 三维通用标签
references/domestic/tags/        ← ★国内特有标签库（market=cn，含团宠）
  background/ theme/ setting/
references/overseas/tags/        ← ★海外特有标签库（market=overseas）
  theme/              ← 含 Story Beats（beats-shared / beats-overseas-only）
  background/         ← 海外专属背景（中世纪/北欧神话/希腊神话/西方奇幻）
references/routing/
  decision-tree.md    ← 受众（男频/女频）作为全局基调路由，写在此处，不进 tags
```
> 归库铁律：`market=both`→公用库；`market=cn`→国内特有库；`market=overseas`→海外特有库。团宠为唯一人工覆盖项（both 但归国内）。

### 1.2 文件名规则
- 英文小写 + 连字符，如 `ceo-male-lead.md`。
- **防撞名后缀**：当 theme 标签与 `combos/` 下文件同名时，theme 文件加 `-theme` 后缀，避免调用混淆。
  - 例：`theme/counterattack-theme.md`（区别于 combos/counterattack.md）、`theme/war-god-return-theme.md`、`theme/wealthy-clan-theme.md`。

### 1.3 受众维度定位
男频/女频**不是普通标签**，是"分发与创作的总开关"。规则写进 `references/routing/decision-tree.md` 的全局基调段落，**不建 tags 文件、不写 weight/level、不参与标签分级与质检号**。

## 2. 红线分级标准（severity）

判定依据只有一条：**"违反这一条，整部剧会不会崩？"**——与市场热度无关。

| severity | 判定 | level | 是否挂质检号 |
|---|---|---|---|
| **强** | 有"违反即崩"的机制红线或价值观红线 | level-1 | ✅ 挂唯一 AP- 前缀 |
| **弱** | 违反只是"不够爽"，不会崩 | level-2 | ❌ 仅写避坑提示 |

- **机制红线**示例：马甲揭露顺序乱（最强马甲前置）→ 后续全崩；契约规则开局全破 → 无拉扯。
- **价值观红线**示例：女性成长靠男人赢 → 价值观崩；追妻男主不卑微/伤害没清零就复合 → 爽感全失。
- **反例（弱红线）**：龙王/神豪即便市场极热，没守住也只是"不够爽"，不会崩 → 弱红线，不挂号。

### 2.1 强红线标签清单（共7个，level-1，挂号）
马甲、女性成长、追妻、破镜重圆、虐恋、大女主、霸总。
> 这7个之外，若某标签的反模式中存在"极高/崩级"项（如真假千金的圣母无底线、战神归来的战力崩坏、赘婿的轻易原谅），在其文件第五节须**以弱红线避坑提示**写明，但不挂全局质检号——避免质检号段膨胀。其崩级风险由通用反模式 anti-patterns.md（#7世界观硬伤/#8性格漂移等）兜底覆盖。

## 3. 分值机制（关键更正 · 与 4-review.md 对账 · v5.7 校准）

**`stages/4-review.md` 的"标签与逻辑"为 20 分，已被 7 个固定子项占满**（核心标签爽点命中3 + 融梗抽离测试3 + 创意差异化2 + 人物设定符合标签2 + 金手指3 + 能力边界4 + 世界观3 = 20）。另有独立的"创意差异化"维度 5 分单列（见 4-review.md 三·五节）。

> v5.7 口径校准：旧版 _SCHEMA.md 曾写"标签与逻辑 25 分/6 子项"，与 `4-review.md` 实际的"20 分/7 子项"不一致，已统一为 20 分口径。后续若调整 4-review.md 权重，必须同步本节，避免自审时分值歧义。

→ **结论：标签文件一律不设"加分关键节点"，不占用这 20 分。**

强红线标签的 `AP-` 质检号**只作为反模式扣分项**，挂靠 `anti-patterns.md` + `4-review.md` 现有扣分机制（从对应维度扣分）。**只扣分、不加分**——这才是"只设失败下限"。

### 3.1 大女主 × 女性成长 互斥扣分
两者价值观红线高度重叠（均为"关键胜利靠男人 = 崩"）且常同时挂载。
→ 对齐 `4-review.md` 第98行"同一问题不重复扣分"注释：**当 AP-DN（大女主）与 AP-NC（女性成长）同时命中"关键胜利靠男人"这同一问题时，只按其一扣分，不叠加。**

## 4. frontmatter 字段（含市场维度）

```yaml
---
name: 英文唯一标识（小写+连字符）
category: background / theme / setting
weight: high / medium / low
level: level-1 / level-2
path: references/{common-tags | domestic/tags | overseas/tags}/<维度>/<文件名>.md  ← 按 market 归库
version: v7.0.0
market: cn / overseas / both                         ← 市场维度（新增）
markets: 欧美,日韩,东南亚,拉美                          ← 仅 overseas/both 需要时标注适用海外市场；cn 可省
related_combo_cn: <国内combo路径> / 无对应预置combo，走通用规则组装
related_combo_overseas: <海外combo路径>               ← 仅当该标签海外有原生combo时填，无则省略
call_node: 步骤1 标签规则组装 · 第二轨原子标签拼接
review_node: 步骤4 自审 · 标签与逻辑维度
emotion_core: <3-5个情绪关键词，用于融梗内核提取>
---
```
- **删除** `aligned` 等一切多余字段。
- `level` 与第2节 severity 对应：强红线=level-1，弱红线=level-2。
- **`market`（市场维度）**：`cn`=纯中式题材（女帝/赘婿/仙侠等，海外不用）；`overseas`=海外专属；`both`=中外通用。路由判市场后**只在 market 匹配当前市场的标签池里选**（海外任务取 `market ∈ {overseas, both}`，国内取 `{cn, both}`）。见 `ARCHITECTURE.md` 一·五节双分支规则。
- **`markets`（可选）**：`overseas`/`both` 标签可标注适用的具体海外市场（欧美/日韩/东南亚/拉美），供海外分市场路由优先推荐；`cn` 标签可省略此字段。
- **`related_combo_cn` / `related_combo_overseas`**：按市场拆分的关联 combo。只能填真实存在的 combo 路径，无对应则填"无对应预置combo，走通用规则组装"或省略该侧，**严禁虚构文件名**。海外侧暂无原生 combo 时省略，走"降级取料"兜底方案链。
- `emotion_core`：3-5个情绪关键词，用于步骤 1 第三轨融梗配方加载时的内核提取（见 `fusion/_METHODOLOGY.md` 步骤1）。

## 8. 与主流程的接入点
- **步骤0 路由**：受众基调在 decision-tree.md；标签经四维推断命中后定位到本目录文件。
