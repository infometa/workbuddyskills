# 步骤 5：修改成稿流程

主 SKILL.md 步骤 5 必读本文件。基于步骤 4 的评审报告，对初稿进行修改。

## 修改原则

1. **逐条修改，不要重写**——除非整体评级是 C 级（建议重写）
2. **优先修严重问题，其次中等，最后轻微**
3. **修改不要引入新问题**——每次修改后局部自检
4. **保留作者风格**——修改是改问题，不是改风格

## 修改工作流

```
1. 读评审报告，按严重程度排序问题清单
2. 对每一个严重问题：
   a. 定位原文位置
   b. 分析根因（结构？人物？台词？节奏？）
   c. 制定修改方案
   d. 执行修改
   e. 局部自检（看周边是否被影响）
3. 修完所有严重问题，对中等问题重复上述流程
4. 修完所有中等问题，对轻微问题（时间允许时）重复
5. 全篇通读一次，检查整体性
6. 输出成稿 + 修改对照说明
7. 走快速自检（步骤 4 简化版）
8. 如有未消除问题，回到步骤 1 再修一轮（最多 3 轮）
```

## 修改类型对应方案

### 1. 结构问题

| 问题 | 修改方案 |
|---|---|
| 核心爽点出现太晚 | 把核心爽点设定前移到前 3 集，删除铺垫 |
| 情绪曲线平缓 | 加大压/放幅度，每 5-10 集设一个高潮 |
| 付费点不在高潮位 | 把放弹簧大爆点对齐到第 10/20/30 集 |
| 连续同类型集 | 拆开连续 3 集以上的同类型（压或放） |

### 2. 人物问题

| 问题 | 修改方案 |
|---|---|
| 主角被动 | 在关键节点增加主角主动选择的场景 |
| 主角弧光不清晰 | 强化开场缺陷 + 结局变化的对照 |
| 反派太弱 | 提升反派的能力、资源、智慧 |
| 配角工具化 | 给配角增加独立动机或独立小弧光，否则合并 |
| 动机不可信 | 补足背景或激励事件 |

### 3. 台词问题

| 问题 | 修改方案 |
|---|---|
| 对白冗长 | 砍掉一半，留下功能性最强的句子 |
| 直白无潜台词 | 用具体动作或话题转移代替直白表达 |
| 对白缺乏性格 | 给每个角色设定语言习惯（用词、句长、口头禅） |
| 信息后置（短剧） | 把第一句改成抛出冲突/身份的硬信息 |

### 4. 节奏问题

| 问题 | 修改方案 |
|---|---|
| 拖沓 | 砍场景、砍对白、砍铺垫 |
| 跳跃 | 增加过渡场景或前置信息 |
| 高潮不够 | 增加冲突强度、增加赌注 |
| 钩子无效（短剧） | 重新设计开篇 5 秒 / 结尾 10 秒 |
| 弹簧错位（短剧） | 重新分配压/放/压放 |

### 5. 题材匹配问题（短剧）

| 问题 | 修改方案 |
|---|---|
| 爽点密度不够 | 对照 `platforms/hongguo/combos/{题材}.md` 的"必备桥段清单"补桥段 |
| 缺少打脸场景 | 在付费点附近增加打脸戏 |
| 主角早期不够惨 | 加强压弹簧戏份，让爆发更爽 |

## 修改对照说明格式

每一处修改输出：

```
## 修改 N
- 位置：第 X 集 / 第 X 页 / 第 X 场
- 严重程度：严重 / 中等 / 轻微
- 问题：[评审报告中的问题描述]
- 修改方案：[采取的方案]

【原文】
...

【改后】
...

【修改理由】
...
```

## 成稿交付清单

```
实际交付给用户：
1. 修改后的完整剧本/大纲（只交付正文，不带设计说明/字数/合规自检等内部底稿）

内部保留（默认不主动输出，仅在用户明确要求时才给）：
2. 修改对照说明（按问题严重程度排序）
3. 快速自检报告（确认问题消除情况）
4. 已知缺陷（若有 3 轮后仍未消除的）
5. 后续优化建议
```

> 交付铁律：用户要的是可以直接用的剧本正文。改稿过程中的设计说明、字数统计、合规自检、修改理由都是你的内部工作记录，默认不要塞给用户；除非用户主动说"把修改了什么也告诉我"，才输出第 2-5 项。

## 局部修改 vs 整体重写

判断标准：

- **修改**：评审评级 ≥ B 级，问题集中在某些章节或具体场景
- **重写**：评审评级 C 级，或者超过 50% 的章节存在严重问题

需要重写时：

1. 先整理评审报告中的"结构性问题"
2. 重新跑一次步骤 0-3，但带着"避坑清单"
3. 不要直接基于初稿改，把初稿里能保留的素材摘出来作为参考

## 多稿并行（可选）

如果用户希望生成多个修改版对比：

- 主 agent 顺序生成多版本即可，不需要 sub agent
- 每版强调不同方向（保守版、激进版、市场版）
- 输出对比表，让用户选

## 何时停止

满足以下任一条件，停止修改并交付：

- 所有严重问题消除
- 走完 3 轮修改
- 用户主动确认成稿
