# ARCHITECTURE.md · 短剧剧本 Skill 迭代宪法

> 这是本 skill 的"改动宪法"。**每次要加/改东西之前，先读这份文件**，按规矩落点，防止越迭代越臃肿、越改越乱、规则层层叠加打架。
> 核心背景：本 skill 曾因把"给人看的历史"与"给 agent 用的规则"混写在 SKILL.md 而使常驻上下文膨胀到 3.8 万字。本宪法就是为根治这一点而立——**SKILL.md 只做调度，不存知识、不存历史。**

## 一、分层职责（每层只干一件事）

| 层 | 职责 | 加载时机 | 改动频率 |

## 一·五、中外双分支宪法（国内 / 海外 独立平行 · 共享底座）

> 立此宪法的背景：本 skill 的海外能力早期是"依附国内 + 换皮"的补丁结构（海外 combo 靠"vs 国内差异表"存在、标签库中外共用一套无市场维度、换皮映射还有断链）。这导致每加一个海外题材负担翻倍、海外质量天花板被"国内骨架英文版"锁死。本宪法把海外提升为**与国内对等、独立完整的分支**，为后续持续扩展海外内容立规矩。

### 三大区块的边界

| 区块 | 放什么 | 不放什么 |
|---|---|---|
| **共享底座 shared**（`anti-tv-drama` / `stages` / `frameworks` 通用部分 / `anti-patterns` / `fusion/_METHODOLOGY`） | "是不是一部合格短剧"的通用规则：短剧性红线 R1-R10、结构宪法五件套、节奏/字数/环境铁律、融梗方法论 | 任何市场专属的题材知识 |
| **国内分支 domestic**（现 `platforms/hongguo/`） | 红果 combo / 原子标签 / 中式题材标签（market=cn）/ 中式案例 / 中式融梗配方 | 海外题材 |
| **海外分支 overseas**（现 `platforms/reelshort/`，将升级为分市场结构） | ReelShort 原生 combo / 海外原子标签 / 海外题材标签（market=overseas）/ 海外案例 / Story Beats；内部按市场分 `western/ japan-korea/ southeast-asia/ latam/` + 跨市场通用层 `_shared/` | 中式题材 |

### 五条核心边界原则（不可违反）

1. **共享底座只放"是不是一部合格短剧"的通用规则**——短剧性红线、结构宪法、节奏铁律、反模式，中外都必须遵守。
2. **国内分支、海外分支各自完整**——各有独立的 combos / atoms / tags / 案例 / 融梗配方，互不依赖。
3. **禁止跨分支硬依赖**——海外 combo 不得以"先懂国内同类"为前提；`vs 国内差异表` 只能作为**可选对照附录**，删掉它海外 combo 仍能独立读懂。
4. **市场路由先于题材**——先判市场（国内 / 海外+哪个海外市场），再只在对应分支的题材池里选，不跨分支混判。
5. **本土化基调随市场走**——反华裔换皮原则全市场通用；但"西式 / 日式 / 在地式"的具体基调由命中市场决定，措辞不写死"西式"。

### 海外"拆而不穷"三级兜底继承链

海外某市场缺料时，按序向上继承，**永不落空**：
```
① 命中市场有对应 combo/标签  → 直接用
        ↓ 该市场没有
② 回 overseas/_shared 海外通用层  → 英文原生规则 + 通用兜底 combo（general-overseas）
        ↓ 通用层也没细则
③ 软继承国内骨架  → 可借国内爽点骨架，但强制换成该市场原生皮（软继承≠硬依赖）
        ↓ 仍无
④ 回 shared 共享底座  → 短剧性红线 + 结构宪法保底出一部合格短剧
```
> 各海外市场**可薄可厚、按需生长**：欧美先做成完整样板，日韩/东南亚/拉美允许先只有目录+市场基调占位，靠本兜底链运行。

## 二、落点判定树（要加新东西，先走这棵树）

```
我要加的这条规则 / 能力 / 知识是——
├─ 关乎"是不是一部短剧"、每个项目必守、不可违反的形态红线？
│     → references/anti-tv-drama.md（短剧性总宪法，最高优先级）
│
├─ 【先判市场分支！】这条知识/题材是国内的、某海外市场的、还是中外通用的？
│     → 决定进 domestic（国内）/ overseas/<市场>（海外）/ shared（通用）哪个分支
│       ——先定分支，再往下走题材/标签/配方的落点（见「一·五 双分支宪法」）
│
├─ 是某个具体赛道/题材的爆款公式、卡点、桥段（会写出来的知识）？
│     → 国内 → references/platforms/hongguo/combos/（= domestic）
│       海外 → references/platforms/reelshort/<市场>/combos/（= overseas，按市场归目录）
│       + 对应 INDEX.md 路由表加一行。海外 combo 禁止以"先懂国内"为前提
│
├─ 是某个标签维度的变体素材 / 红线（一标签一文件）？
│     → references/tags/<维度>/<标签>.md（照 _SCHEMA.md 结构）
│       + frontmatter 标 market（cn/overseas/both）+ tags/INDEX.md 全表加一行
│       + 强红线在号段总表分配唯一 AP- 前缀
│
├─ 是两个及以上梗如何化学反应的配方？
│     → 方法论通用（fusion/_METHODOLOGY = shared）；具体配方按市场归 fusion/recipes/ 并标市场
│       新建照 _TEMPLATE.md + INDEX.md 加一行
│
├─ 只对某个流程阶段生效（怎么写大纲/人设/剧本/怎么评审）？
│     → references/stages/ 对应文件
│
├─ 只对某个市场（海外欧美/东南亚…）生效？
│     → references/markets/ 对应文件
│
├─ 只对某个载体/格式（英文短剧/漫剧/好莱坞排版）生效？
│     → references/formats/ 对应文件
│
└─ 是全流程每步都要遵守、跨阶段的通用铁律？
      → 先问：能不能挂到某个 stages 文件？能就挂那里。
        确实是全局铁律 → 加进对应主题文件，并在 SKILL.md「铁律速查摘要」补 1 行
```

### 关键辨析：什么该进 SKILL.md，什么不该

- **能进 SKILL.md 的，只有四类**：① 主流程骨架（6 步 + 步骤 2.5 锁点）；② 加载策略三张表；③ 铁律速查摘要（每条 1 行，指向细则文件）；④ 作用域元规则这类"进门就要知道"的元规则。
- **绝对不许进 SKILL.md 的**：具体赛道知识、标签细则、融梗配方、版本历史、某次迭代的"为什么这么改"的解释。这些各有其层。
- **识别触发条件（几行特征清单）常驻 SKILL.md 注册表，细则永远按需加载**。例：能识别"这是海外项目"靠常驻的英文输入总锁几行；"海外怎么本土化"才去读 `markets/western.md`。

## 三、SKILL.md 减肥红线（防止再次膨胀）

以下是 SKILL.md 的硬性体量纪律，**每次改 SKILL.md 后自查**：

1. **不写版本历史**：版本记录一律只在 `CHANGELOG.md`。SKILL.md「版本」处只留一行指针 `> 完整版本历史见 CHANGELOG.md（当前 vX.Y.Z）`。
2. **不写迭代来历**：正文里禁止出现 `（v6.7 补）` `（v5.6 新增）` 这类历史标注。规则本身留下、来历删掉——来历去 CHANGELOG 查。
3. **不复制知识**：SKILL.md 提到某赛道/标签/配方时只写"读 X 文件"，不把 X 的内容抄进来。
4. **description 只讲"做什么 + 何时触发"**：frontmatter 的 description 控制在几行内，不塞迭代史、不塞设计哲学长篇。
5. **铁律用速查摘要**：每条铁律压成 1 行放速查区，细则在 references，不在 SKILL.md 展开。
6. **体量目标**：SKILL.md 常驻部分控制在约 1.2 万字级；若超过 1.5 万字，说明有知识/历史又漏进来了，回本节逐条排查。

## 四、命名与编号规范

- **短剧性红线编号 R1-R10 只增不改不复用**：现有 R1-R10 永久保留，新增用 R11、R12……这样所有历史"命中 R6"引用永远有效。
- **反模式编号（anti-patterns.md 的 #1-#16）同理只增不复用**。
- **强红线 AP- 前缀全局唯一**：现有 7 个（马甲 AP-MJ / 女性成长 AP-NC / 追妻 AP-ZQ / 破镜重圆 AP-PJ / 虐恋 AP-NL / 大女主 AP-DN / 霸总 AP-BZ）+ 漫剧库 AP-XX01 系列，新增红线分配未用前缀，绝不撞号。
- **文件名语义化 kebab-case**（英文），中文定位靠 `tags/INDEX.md` 的「中文别名→标签速查表」，**严禁把中文直译成英文猜文件名**。
- **资产/引用格式固定**：正文引用红线统一写"R6（见 anti-tv-drama.md）"、引用反模式写"反模式13（见 anti-patterns.md）"。

## 六、版本记录规范

**版本历史一律写入 `CHANGELOG.md`，不写进 `SKILL.md`。**
- 原因：版本记录是给人看的历史，对 agent 生成剧本无用，却会常驻上下文（曾占 SKILL.md 约 2.4 万字）。迁出后常驻上下文显著变小。
- 每条 CHANGELOG 条目写清：**改了什么 / 根因 / 具体改动点 / 影响范围 / 是否动红线编号 / 落点层级**（anti-tv-drama / stages / tags / fusion / platforms / markets / formats 哪一层）。
- **发版只需改三处**：SKILL.md frontmatter 的隐含版本认知（如描述里提到的当前能力）+ SKILL.md 版本指针那行 + CHANGELOG.md 顶部新增一条（标当前，旧条目去掉当前标记）。

## 七、知识库拆分/去重的触发阈值（暂不拆，达标再拆）

references 下的知识库**默认保持现状不动**（它们是按需加载的"弹药库"，不进常驻上下文，越厚越好）。仅当满足以下任一条件才动内容：
- 某单个知识文件超过约 12,000 字，导致单次按需加载也偏重 → 拆分。
- 发现 `tags/` 与 `platforms/atoms/` 对同一概念重复维护且已产生内容冲突 → 择一为真相源、另一改为引用。
- `validate_skill.py` 报出"索引指向空气"断链 → 补文件或删索引。

> **不要为了"看起来干净"去动没病的知识文件。** 减负的目标是常驻上下文，不是仓库总字数。知识文件只要不常驻、不断链、不冲突，就让它厚着。

## 八、风格/规则全局锁定原则（防"按需加载导致规则前后不一致"）

> 澄清：references"按需加载" ≠ 规则"每次随机决定"。references 只是"知识手册的取用"，跨阶段应一致的决策必须一次性锁定。

- 凡跨集/跨阶段应一致的维度——**美学风格、人物命名、能力边界、结构宪法五件套、字数口径**——都必须在**步骤 2.5 锁骨架时**一次性拍板，写进结构宪法，后续每批逐字复用，不得逐批自由发挥。
- 分工：**references 管"有哪些选项/知识"，步骤 2.5 的结构宪法管"选定后全剧统一"。**
