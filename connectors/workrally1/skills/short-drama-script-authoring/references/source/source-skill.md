# 短剧创作全流程引擎 · 生成短剧剧本

本 skill 是**头部流程总纲（决策树 + 加载器，不存知识）**。**只做短剧内容**——以短剧为主，兼做漫剧/动态漫（复用短剧全部节奏规则 + 视觉化分镜补充）。

所有题材知识与方法论在 `references/` 下分层存放，**按需 Read**（见下方「加载策略」三张表）。**严禁凭模型常识跳过 reference**：每个 combo/标签文件都含模型不具备的非平凡爆款公式、卡点位置、底线规则。

**核心设计原则**（本 skill 的不变式）：
- **平台标签驱动**：路由层按红果 60 标签 / ReelShort Story Beats 推断加载，不用"创作者题材"分类。
- **双开关标签库**：`tags/` 一标签一文件——「变体素材库」给灵感不强制命中（提上限）+「红线」按崩不崩分级、强红线挂质检号纳入扣分（守下限），即"只设失败下限、不限创作方向"。
- **融梗是化学反应不是拼接**：命中≥2 标签时查 `fusion/` 求 A×B 反应式（主轴+辅轴+裂变新特性），非 A+B 共存。
- **节奏单位是情节单元不是单集**：一个完整事件跨 2-8 集，单集只承担一个节拍，不强制每集起承转合闭环。
- **形态守门先于题材创作**：短剧是"短平快爽点机器"不是"浓缩电视剧"，电视剧化在骨架期就拦、做减法不做加法（见 `anti-tv-drama.md`）。
- **松绑结构不松标准、按需加载不全文注入**：参考方向仅供启发创意、不强制填空；但硬指标（字数、结构宪法、分批制、环境预算、短剧性红线）必须执行。

> **维护者/agent 改本 skill 前必读 `ARCHITECTURE.md`（迭代宪法）**——它规定新增能力该落在哪一层、SKILL.md 的减肥红线、编号规范与改动同步清单，防止本文件再次膨胀。

> **载体说明**：默认载体为短剧。命中"漫剧/动态漫/漫画剧本/分镜"等关键词时切换为漫剧载体，额外加载 `references/formats/manga-drama.md`。**海外/英文项目（最高优先级）：进入剧本生成前必须先 Read `references/formats/english-short-drama.md`（英文短剧创作圣经）建立语感关键节点——这是对冲"模型把英文剧本写成好莱坞美剧"的核心文件,优先级高于格式与本土化规则；其中第八节「美式角色原型库」对冲中式故事套英文皮陷阱（禁止中文名配英文别名/唐人街/玉佩/华裔世家）。英文输入下，请求里每个赛道都独立锁定英文+海外+西式人，命中萌宝/逆后宫/团宠等国内红果 combo 也绝不切回中文（详见 `decision-tree.md` 第 0 层英文输入总锁）；** 若同时要求"好莱坞格式/标准剧本格式"，再加载 `references/formats/hollywood-script.md`（仅排版规范，体量仍按短剧）。

## 🔴 短剧性总宪法（最高优先级 · 先于一切题材/标签/市场规则）

**[作用域：全局 · 中英通用 · 短剧+漫剧通用]** 进入任何创作前，必读 `references/anti-tv-drama.md`（反电视剧化总宪法）。它治本 skill 最致命的病——**剧情越往后越像传统影视剧**（5 幕结构 / 宏大世界观 / 立体反派 / 证据链翻案 / 设定过载）。十条短剧性红线（禁 act 分幕 / 设定≤3条 / 禁宏大叙事 / 反派禁立体化前史 / 真相靠当场行动不靠证据链 / 付费钩2-3集/个 / 爽点机制≥4种 / 单线推进 / 禁配角抢戏 / 禁解释型反转）为一票否决级，不可被任何下游规则覆盖。**核心心法：短剧是"短平快爽点机器"，不是"浓缩的电视剧"——宁可设定简单到一句话讲完，绝不堆叠宏大叙事；宁可爽点直给到俗，绝不靠解释和铺垫。** 崩坏必须在步骤 2.5 骨架期就用"崩坏自查 13 问"拦下，绝不拖到剧本期。

## 作用域元规则（读规则前先判作用域）

本 skill 的规则分**作用域**。加载任何 reference 或执行任何规则前，先判断该规则的作用域是否匹配当前任务，**不匹配的规则不要套用**：

| 作用域标记 | 含义 | 不匹配时 |
|---|---|---|
| `[作用域：全局]` | 所有任务通用（中英、短剧漫剧、所有赛道） | 永远生效 |
| `[作用域：仅国内]` / `[作用域：仅海外]` | 按目标市场二选一 | 海外任务不套国内规则，反之亦然 |
| `[作用域：仅短剧]` / `[作用域：仅漫剧]` | 按载体二选一 | 漫剧不套短剧专属格式，反之亦然 |
| `[作用域：仅<赛道>]` | 仅命中该赛道时生效 | 未命中赛道不套用 |

> 无标记的旧规则默认按"全局"处理，但若与某市场/载体明显冲突，以高优先级的带标记规则为准。新增规则一律带作用域标记。**修改 skill 时，凡新增规则必须先想清楚它是全局还是局部，并打上对应标记**——避免把海外规则套到国内、把短剧红线漏给漫剧。

## 📌 短剧性红线速查（10 条 · 常驻 · 细则见 `anti-tv-drama.md`）

> 进入任何创作前先持有这 10 条；**R1/R6/R7 为一票否决**（命中即整体降级）。骨架期（步骤 2.5）必用「崩坏自查 13 问」逐条过。

- **R1** 禁 act/幕结构（分幕即电视剧化）｜**R2** 核心设定 ≤3 条｜**R3** 禁宏大叙事/世界拯救（千年诅咒/三界存亡式见到即砍）
- **R4** 反派禁立体化前史（立体=够欠揍+诉求清晰+能力在线，≠给可怜前史洗白）｜**R5** 真相靠当场行动，不靠证据链翻案
- **R6** 付费钩 2-3 集/个（钩子不能稀疏）｜**R7** 爽点机制全剧 ≥4 种（禁复读同一种）｜**R8** 单线推进，禁多阵营混战
- **R9** 禁配角抢戏/独立救赎弧｜**R10** 禁解释型反转（反转靠当场行动不靠事后解释）
- **心法**：短剧是"短平快爽点机器"不是"浓缩电视剧"——宁可设定简单到一句话讲完，绝不堆宏大叙事；宁可爽点直给到俗，绝不靠解释铺垫。**修改永远做减法**（砍集数/删支线/删前史，不加人物/加阵营）。

> 其它常驻硬指标：篇幅（真相源 `shared/base.md`，每集 200-448 词 · 英文词数口径）｜结构宪法五件套（步骤 2.5）｜环境描写单集 ≤2 句/句 ≤15 字｜**每句台词/动作必带情绪+关系姿态、禁中性平淡（铁律13，见 `stages/3-script.md`；情绪有梯度非全程拉满）**｜融梗三问（多标签必过）｜人名+标题黑名单（见 `2-character.md`）｜T/G 内部编号禁泄漏给用户｜🔴 **禁内部骨架/节拍标注（起承转合/压放/情节单元/关键节点/Plot Unit/Beat:）泄漏进交付正文（一票否决 · 英文项目尤其致命 · 见 `shared/base.md`）**。

## 步骤 0：智能标签识别（必做）

读 `references/routing/decision-tree.md`，跑**三层标签推断**，输出「标签化工单」交用户确认。**核心原则：能推断的绝不问，必须问的一次问完。**

> 🔴 **prompt 复杂度分流（全局 · 先判定）**：简单 prompt（只给赛道，如"给我个霸总短剧"）→ **融梗 + 给 3 个选项（至少 2 个新鲜方向 + 1 个明确标注的经典热门款兜底）**（防同质化，同时满足"就要经典款"的正当需求；人名避开高频黑名单；用户点名要经典款则直接给）；复杂 prompt（已含完整设定/大纲/小说）→ **不给选项直接执行**（防过度干预，但仍用短剧性红线体检）。**🔴 复杂 prompt 即使直接执行，也必须先内部跑步骤 2.5「情节单元规划表」作隐形骨架，再展开为完整大纲——不能跳过骨架直接铺 50/80 集逐集**（治"一次性交付全套产物导致跳骨架"）。详见 decision-tree 选题菜单机制顶部分流闸门。

> 🔴🔴 **英文输入总锁（最高优先级，先于下方一切推断）**：只要用户用英文发起请求，或显式要英文/海外短剧，则**对请求里的每一个赛道**强制锁死三项——① 输出语言=英文（禁止任何中文人名/台词/剧情逻辑）；② 市场=海外（默认欧美，用户另指日韩/东南亚/拉美则按该市场）；③ 全盘"该市场式"本土化（默认西式；反中式故事套英文皮全市场通用）。**关键修复**：cute baby/萌宝、reverse harem/逆后宫/团宠、真假千金等命中国内红果 combo 的赛道，**绝不因此切回中文**——取其爽感骨架，换该市场原生皮（萌宝→secret-baby 有原生 combo；逆后宫/团宠暂无原生 combo，走海外通用兜底+弱继承，见 `decision-tree.md` 第 0 层）。多赛道混合请求时每个赛道独立过此门，任一赛道出现中文即整体重写。详见 `decision-tree.md` 第 0 层 + `formats/english-short-drama.md` 第八节美式角色原型库。

1. **四维标签推断**：从用户 prompt 推断红果官方四维标签（受众/设定/主题/背景），按「关键词硬匹配 → 概率默认补全 → 缺失检测」三层逻辑。80% 场景可直接推断出完整组合，**不需要提问**。
   > 🔴 **受众判定铁律（v7.2.1 新增）**：受众判定按"主角性别 > 主导动作 > 关键词硬匹配"优先级执行——主角男→男频，主角女→女频，LGBTQ 主角对归女频。**赛道关键词（霸总/CEO/战神）只决定标签不决定受众**，详见 `decision-tree.md`「受众判定铁律」段。
2. **平台标签路由**：推断出四维标签后，**按平台路由**——国内市场 Read `references/domestic/INDEX.md` 查爆款组合路由表，命中 → Read 对应 combo 文件获取核心知识与参考方向；海外市场 Read `references/overseas/INDEX.md` 查 ReelShort 路由表。按需加载，只读命中的 1 个 combo。向用户展示 2-3 个差异最大的参考方向供选择，用户也可自由指定任意方向。用户说"随意"→ 选择本次会话中未展示过的方向，或基于核心爽感自由发散。**维度差异去重规则**：同一会话内再次生成选题时，必须在主角核心身份、核心冲突类型、爽点触发机制、开局切入方式、叙事视角结构 5 个维度中至少更换 2 个。详见 `decision-tree.md` 选题菜单机制。
   > 🔴 **combo 命中度评分机制（v7.2.1 新增）**：combo 文件顶部"主标签"必须**全部命中**才能走该 combo，辅标签是可叠加项不强制。无 combo 主标签全部命中时**强制走 Beats 组合兜底方案链**——宁可兜底不可强行落 combo，详见 `decision-tree.md`「combo 命中度评分机制」段。
3. **目标市场**：国内 / 海外（欧美/东南亚/拉美/日韩）。海外命中时加载 `references/overseas/markets/` 对应反模式适配规则。
4. **语言**：识别用户输入语言。**所有产出用用户的语言输出**；海外按目标市场做本土化。
5. **任务阶段**：仅大纲 / 仅人设 / 仅剧本 / 仅评审 / 仅修改 / 全流程从零写；以及素材形态（一句话创意 / 已有大纲 / 已有初稿 / 整本小说）。

**仅当**核心维度（受众+核心设定）双缺失、出现强互斥标签、或全靠默认填充时，才发起**一次性**确认（话术见 decision-tree）。输出标签化工单（标签组合+参考方向+置信度+市场+起点步骤），用户确认后进入步骤 1。

素材是"整本小说"且 > 2 万字：默认**整本喂入**（长上下文模型可直接处理，禁止有损截断以免丢失中段情节/伏笔/人物演变）；**仅当**确实超出上下文窗口时，用 `scripts/text_splitter.py` 做**无损语义分块**后分批引用。

## 步骤 1：标签规则组装（平台标签驱动 · 按需加载）

读 `references/domestic/INDEX.md`（国内）或 `references/overseas/INDEX.md`（海外）确定标签路由后，**按需加载**——步骤 0 已确定标签组合，只需 Read 对应的那 1 个 combo 文件（+混搭时 Read 2-3 个相关 combo 文件）。不再预加载所有 combo 文件，省 token、减噪音。

> 💡 **「三轨」讲人话**：下面的三轨就是**从三个仓库取料**——第一轨 combo=「爆款套餐」（平台验证过的成熟剧情模板），第二轨 tags=「零件库」（单个题材元素，如重生/甜宠），第三轨 fusion=「配方书」（两个元素怎么炒出化学反应）。先铺 base+frameworks 地基，再依次取这三类料，组装成骨架。

1. **加载通用主骨架**：`shared/base.md`（含 Logline 变体模板库 + 梗概开头变体库）+ `frameworks/`（**loop-model 全赛道必读**、emotion-spring、hook-design）。**先判 loop 型**：单主角剧只需外部 loop（loop-model 型 A）；双主角剧（男女/男男等）需外部 loop + 内部关系 loop 咬合（型 B）。**女频爱情赛道**（霸总/强制爱/契约婚/豪门甜虐/狼人/追妻火葬场/萌宝等）额外加载 `frameworks/narrative-loop.md` 取其 6 触发器/5 权力钩子作内部关系 loop 的具体手法；大女主自洽/群像/纯功能向（末世/悬疑）等单主角或非情感驱动赛道用 loop-model 通用规则即可，不套情感触发器。
2. **第一轨·查预设爆款组合**：标签组合命中红果/ReelShort 爆款组合路由表 → **Read 对应 combo 文件**（仅这 1 个）作**主轴参考**。combo 文件顶部含**平台标签组合**标识，用于快速核对命中关系 → 参考 combo 的参考方向（仅供启发创意，不强制按模板填空），结合用户选定方向执行核心知识、底线规则与节奏模板。
3. **第二轨·标签素材加载（标签库 · 双开关）**：按 `references/common-tags/INDEX.md` 把命中的设定/主题/背景标签定位到对应库——**公用标签**在 `common-tags/{setting|theme|background}/`（两地通用），**国内特有**在 `domestic/tags/{...}/`（market=cn，仅国内项目可读），**海外特有**在 `overseas/tags/{...}/`（market=overseas，仅海外项目可读），按需 Read。**市场分池铁律**：国内项目只读 公用库+国内特有库（禁读海外特有），海外项目只读 公用库+海外特有库（禁读国内特有）。每个标签文件提供两个开关——**开关①变体素材库（第二节）**作创作灵感，仅参考、可自由组合/原创/豁免，**绝不强制命中**（提上限）；**开关②红线（第五节）**作硬约束，level-1 强红线标签的 `AP-` 反模式纳入步骤 4 扣分，level-2 弱红线仅避坑提示（守下限）。标签文件 `related_combo` 指向对应高速通道 combo；无对应则走通用规则组装。长尾/未建标签取最接近标签或走通用规则组装。
4. **第三轨·融梗**：当命中的标签组合包含 2 个及以上主题/设定标签时，Read `references/fusion/_METHODOLOGY.md`（融梗方法论精简版）。融梗核心原则：**A×B 化学反应 ≠ A+B 物理拼接**——梗和梗必须互相作用、互相改变，生出两个梗单独都没有的新冲突和新爽点。
   - **融梗三问**（创作时自问，非流程化拆解）：
     1. 删掉标签 A 后，标签 B 的核心冲突会不会坍塌？会→融梗成功；不会→物理拼接，需重构
     2. 全剧最关键的 3 个转折点，有没有至少 1 个是 A×B 产生的新桥段（非纯 A 或纯 B 能产生）？
     3. 前 3 集每集有没有至少 1 个明确爽点释放？（短剧商业约束）
   - **四维各取一个（融梗选料铁律 · v8.1）**：融梗标签严格按平台四维取料——**受众**（男频/女频）只定全剧基调，是总开关，**不进反应式**；真正进融梗反应式的是**设定 / 主题 / 背景各取 1 个标签**，正好 3 个融梗标签，与"3 标签上限"自动对齐（短剧单集 1-2 分钟，核心设定超过 3 个必然散焦）。三者分工：设定标签=主角身份/金手指/能力体系，主题标签=主线冲突机制，背景标签=世界观舞台。
   - **同维度多标签 / 缺维处理**：某一维度命中多个标签时，按"用户指定 > 权重 high > 爽点/情感供给最强"**取 1 个**进反应式，其余降级为背景调性；某一维度缺失时，用步骤 0 概率默认补全的标签顶上（如背景缺失→默认现代都市）。最终裂变的新特性必须由这 3 个融梗标签共同作用产生，不得某个标签全程打酱油。两标签(仅命中两维)时按命中的两维各取一个即可。
   - **配方降级为参考**：`references/fusion/INDEX.md` 下的配方文件**可选 Read 做参考**（了解市面成熟写法），**禁止直接使用配方的 3 个方向**，推导方向必须与配方做差异化对照
   - **三轨合并优先级**：融梗红线 > combo 底线规则 > 标签红线 > 标签素材
5. **旧混搭规则**（已被第三轨替代）：原"Read 多个 combo 文件按优先级合并"升级为"第三轨融梗配方加载"，不再仅做规则拼接，而是构造化学反应。
6. **按优先级合并、消解冲突**：依「受众 > 设定 > 主题 > 背景」优先级合并各标签规则，按优先级铁律消解冲突，生成「本剧专属创作规范」。冲突消解采用**叙事优先级**（见 `_METHODOLOGY.md` 第四节）：观众情绪贡献度 > 受众基调 > 主轴>辅轴 > 红线>素材。

> 长尾组合（如"年代+乡村+种田+系统+福宝"）无需预存模板，第三轨融梗方法论可动态构造反应式，规则一拼即出。

读 `references/case-studies/INDEX.md`：

- **辅轴桥段**：从其他命中标签的必备桥段里挑 2-3 个融入（如"重生+种田"，主轴用逆袭节奏，再加种田标签的开荒/盈利/打脸桥段）。

**融梗化学反应分析**：基于步骤 1 第三轨的融梗三问，输出以下分析供用户确认：

1. **融梗一句话**：这个标签组合产生了什么两个标签单独都没有的新东西？（如穿越×系统→"系统任务约束让穿越者的开天眼不再是无限开挂"）
2. **融梗核心冲突**：由融梗产生的新冲突/新困境（如穿越×系统×甜宠→"救他还是完成任务"的永恒两难）
3. **2-3 个差异化方向**：LLM 自行推导（非配方照搬），在主角核心身份、核心冲突类型、爽点触发机制 3 维度全部不同。如命中配方可选 Read 做参考，但推导方向必须与配方方向做差异化对照

提炼爆款公式（情绪曲线、卡点位置、人物关系结构），列出用户素材的**爽点缺口**（已有 vs 缺失），输出对照分析让用户确认创作方向。

## 步骤 2.5：核心骨架锁定确认（必经节点）

**本步骤为强制确认节点，仅输出精简版骨架，未通过不得进入步骤 3**。本步骤产出为「骨架确认版」，后续大纲、人设将在此基础上展开细节，不重复产出同粒度内容。

> 🔵 **loop 术语对齐（见 `frameworks/loop-model.md`）**：本步骤的「关键节点」= 各**大 loop 的终局反转里程碑**（**关键节点由每个大 loop 的结尾派生，不独立预设数量**——切几个大 loop 就有几个关键节点，故关键节点数 = 大 loop 数 = 情节单元数 = **5-12 个**，三者一一对应）；「情节单元」= **大 loop**（一个完整故事弧）；「单元内节拍（起/承/转/合）」= **大 loop 的四段**（起=发难 / 承=N个小loop攻防逐级加码 / 转=终局反转 / 合=收尾埋钩）；「小 loop」= 承段里的**一次攻防回合**（反派一招+主角一招），比节拍更细。骨架期先判 loop 型——单主角剧只铺外部 loop；双主角剧须让外部 loop 与内部关系 loop 咬合（关系副线相位栏即内部关系 loop）。并按 loop-model 第五节在**大 loop 收尾后安排缓冲集**（呼吸感）。

交付确认五件套：

1. **全剧核心事件节点表（精简版）**：**5-12 个**全剧里程碑事件（= 大 loop 数 = 情节单元数，**一一对应**；每个节点 = 一个大 loop 的**终局反转里程碑**；短剧取 5-8 / 80-100集长剧取 10-12），仅含核心事件名称、集数范围、戏剧功能三大核心字段，固定全剧节奏骨架；
2. **核心冲突路径轮换表（精简版）**：全剧 8-10 轮核心冲突的解路径大类预分配，明确跨类轮换规则，杜绝单循环模板化；
3. **核心能力/资源边界总纲**：若为战力/金手指类题材，明确初始上限、升级次数、终极边界；若非战力类题材，明确主角核心资源/优势的边界与限制。
4. **情节单元规划表（精简版）**：全剧 **5-12 个**情节单元（**= 大 loop，与关键节点一一对应**；每个跨 **2-8 集，长度按剧情松紧不均分**——重头戏弧 6-8 集、过场弧 2-3 集；**数量由故事状态跃迁点决定=反派阵营数/身份跃迁数/权力倒置次数，不是集数除法**，详见 `frameworks/loop-model.md` 第一节数量定法），仅含单元序号、集数范围、单元核心事件、所属关键节点、单元内节拍分配（起/承/转/合）、**关系副线相位**六个字段。钉死"一个事件跨几集"的节奏单位 + 双线交替结构,从结构端杜绝"一集完成起承转合"和"单线剧像美剧"。**粒度补足**：大 loop（2-8集）与单集之间由「承段的小 loop（攻防回合·跨2-3集）+ 第五件套逐集节拍表」承接，不再靠"多切情节单元"来填密度。
5. **逐集节拍表（v8.1 新增 · 第五件套）**：每集一行,固定六列——集号 / 所属情节单元 / 节拍（起/承/转/合）/ 弹簧类型（压/放/压放）/ 钩子类型（悬念型/危机型/反转型/揭晓型）/ **承接上集方式（时间锚定句/场景延续/角色状态承接/情节单元边界硬切）**。最后两列是治"单集自闭环 + 跨集硬切"的核心约束——**钩子类型栏禁止全剧都是"反转型/揭晓型"**（说明每集都给放点,违反起承集只压不放）；**承接上集方式栏禁止连续两行写"硬切"**（说明跨集衔接断裂,违反 `stages/3-script.md` 铁律 14）。本表与情节单元规划表互为表里：情节单元规划表管"事件跨几集",逐集节拍表管"每集在事件中承担什么角色"。

**情节单元规划表格式**：

| 单元序号 | 集数范围 | 单元核心事件 | 所属关键节点 | 节拍分配 | 关系副线相位 |
|---|---|---|---|---|---|
| 1 | 第1-4集 | 主角被退婚+觉醒金手指，首次反抗立威 | 关键节点1（=本单元终局反转） | 起-承-承-转 | 男女主:初遇→误解加深 |
| 2 | 第5-10集 | 正面打脸前夫家、夺回家产 | 关键节点2（=本单元终局反转） | 起-承-承-转-合 | 男女主:误解→被迫靠近 |

> **一一对应铁律**：单元序号 = 关键节点序号（一个大 loop 一个终局反转里程碑），"所属关键节点"列填本单元自己的终局，**不再出现"关键节点1-2"这种一个单元跨多个节点、或多个单元共用一个节点的写法**（那是旧两层设计的残留）。密度不足时靠承段多铺几轮**小 loop**（跨2-3集的攻防回合）解决，**不靠多切情节单元**。
| ... | | | | | |

> 节拍分配栏写该单元各集的起/承/转/合位置，明确哪几集是"压"、哪一集是"放"。合集可省略或并入下一单元的起。**关系副线相位栏写该单元结束时,关系副线(男女主拉扯/主角团互动/主角内心自洽)推进到哪个相位——loop 是跨情节单元的长线,不是每单元独立闭环。详见 `emotion-spring.md`「情节单元双线交替结构」段(v7.2.2)**。

> 🔴🔴 **单元核心事件填写铁律（v8.2 新增 · 全局 · 治"一集一事件"根因 · 骨架期必过）**：这是治"每集一个独立故事、下一集换事件换地点"的**头号根因修复**——病根不在剧本期，在骨架期把"核心事件"字段填错了。
> - **① 核心事件必须是"单一贯穿冲突句"，禁止"话题/场合名词"**：
>   - ❌ 错误（话题/场合名词，天然可塞多个独立小事件）：`The Contract`（契约）、`The Gala`（晚会）、`同居生活`、`公司风波`、`初遇`——这些是**话题/地点/场合**，不是冲突。一个话题底下可以塞 3 个各自了结的独立事件，"起承转"标签一贴就假装跨集了，实则每集自闭环。
>   - ✅ 正确（单一冲突句，含"谁 vs 谁，为了什么，从 X 状态推向 Y 状态"）：`女主被继姐当众夺走婚约 → 隐忍取证 → 当众甩出证据反夺`、`男主的隐藏身份因一通电话开始松动 → 女主步步逼问 → 身份彻底曝光`。一个冲突句只有**一个**核心矛盾，它的起始状态和结束状态横跨整个单元。
> - **② 冲突守恒校验（填完每个单元自问三条，任一"否"即重填）**：
>   1. 这个单元的**核心矛盾是不是同一个**？（不是"签约"+"同居"+"晚会"三个不同矛盾打包，而是一个矛盾的三个阶段）
>   2. 这个矛盾是不是在**起集点燃、承集只加压不解决、转集才第一次也是唯一一次引爆/解决**？（若某集内既起又解决 = 该集自闭环 = 违规）
>   3. 相邻两集的**时间和地点是不是连续承接**的？（下一集开头能接住上一集结尾的场景/时间，除非跨到新单元的起集）
> - **③ 拆分口令**：填单元时，先写死"这个单元只讲一个冲突"，再问"这一个冲突要几集才能从点燃走到引爆"（2-8 集），最后把这几集标成起/承/转/合。**绝不能反过来——先有 N 个想写的独立事件，再打包硬贴一个单元名。**
> - **④ 反例对照（本 skill 实测踩过的坑）**：`Plot Unit 1 = The Contract，下辖 EP1 签约(闭环) / EP2 同居(闭环) / EP3 晚会羞辱+反击(闭环)` = **三个独立冲突打包成假单元**，每集换事件换地点。正确重构：`Plot Unit 1 = "女主为救母被迫签下契约、并在契约束缚下逐步卷入男主的世界" → EP1 绝境签约(起,只点燃不解决) / EP2 契约束缚下的第一次冲撞(承,加压) / EP3 束缚逼出第一次心动或第一次反抗(转,引爆) `——同一个"契约束缚"矛盾贯穿三集，地点/时间连续。

> 确认规则：关键节点集数偏差不得超过 ±2 集，核心事件与戏剧功能不得替换；如需调整必须先修改本骨架再往下推进。后续大纲、人设仅可在本骨架框架内补充细节，不得推翻核心设定。

> **结构宪法 = 步骤 2.5 五件套**：步骤 2.5 确认的「节点表 + 冲突轮换表 + 能力边界总纲 + 情节单元规划表 + 逐集节拍表」即本剧的**结构宪法**（最高约束），是后续所有剧本生成不得突破的硬性节点清单。剧本生成采用**分批制**：默认单批最多 10 集，每批开写前先注入结构宪法 + 上一批审计结论 + 前情摘要，每批写完做节点审计，确认无偏离再写下一批（详见步骤 3 与 `stages/3-script.md`）。

> 🔵 **【作用域：仅海外】英文项目专项 · 五件套用中文写**：海外/英文项目下，步骤 2.5 五件套（节点表 / 冲突轮换表 / 能力边界总纲 / 情节单元规划表 / 逐集节拍表）以及其中的单元核心事件、节拍归属、戏剧功能**强制用中文写**，步骤 3 才切英文写正文。**为什么**：模型对中文短剧/网文的爆点结构先验远强于英文，英文项目若从骨架期就用英文想结构，好莱坞引力会从最上游介入，把"短平快爽点骨架"想成"美剧式慢热弧光"。先用中文锁死结构层，再用英文落地语言层。**护栏（防中式故事套英文皮）**：中文骨架只写"语言无关层"——节拍归属、情绪功能、爆点机制类型（打脸/反转/钩子）、冲突解路径、爽点密度；**严禁写"语言相关层"**——场景、道具、人名、文化设定、具体台词句式，后者必须在步骤 3 英文阶段按 `formats/english-short-drama.md` 第八节美式原型库现生成。否则中文骨架会把中式桥段/道具带进英文正文，产出"中文故事换英文皮"，与中式故事套英文皮硬锁正面冲突。**此为仅海外条件分支，国内项目不受影响。**

> 🔴 **骨架期崩坏拦截（必跑 · 全局）**：五件套一旦成型，**立即 Read `references/anti-tv-drama.md` 用"崩坏自查 13 问"逐条过一遍**——分幕、设定过载、宏大叙事、反派洗白、证据链查案、付费钩稀疏、爽点机制复读、多阵营混战、配角抢戏、解释型反转、单元剧化、注水、单集自闭环。**任一条命中，当场改骨架再往下走，绝不带病进入剧本生成。** 这是治"越往后越像电视剧"的核心拦截点——崩坏在骨架期改成本最低，拖到剧本期=灾难。

## 步骤 3：生成初稿

按任务阶段读方法论，**所有硬指标必须执行**：

| 任务阶段 | 必读 reference |
|---|---|
| 写大纲 | `stages/1-outline.md` |
| 写人设 | `stages/2-character.md` |
| 写剧本 | `stages/3-script.md` + `frameworks/emotion-spring.md` + `frameworks/loop-model.md`（loop 节奏建模·全赛道） |
| 拆条/节奏校验（全赛道通用底层） | `frameworks/loop-model.md`（大小 loop、单/双主角型、逐级加码、呼吸感） |
| 内部关系 loop 具体手法（女频爱情赛道） | `frameworks/narrative-loop.md`（4拍引擎+三层分形+逐级加码底层已通用；6触发器/5权力钩子为女频爱情具体化层） |
| 写漫剧剧本（命中漫剧载体） | 上述 + `formats/manga-drama.md`（视觉化分镜补充） |
| **海外/英文短剧（最高优先级 · 必读）** | **上述 + `formats/english-short-drama.md`（英文短剧创作圣经 · 建立语感关键节点,先于一切）** + `markets/western.md`（本土化换皮） |
| 海外英文剧本（要求好莱坞格式） | 上述 + `formats/english-short-drama.md` + `formats/hollywood-script.md`（仅排版规范，体量仍按短剧） |
| 故事五元素分析 | `frameworks/five-elements.md` |
| 钩子设计 | `frameworks/hook-design.md` |

按 combo 文件的核心知识和底线规则落地。参考方向仅供启发创意，不强制按模板填空。**字数硬性区间（v8.8.0 · 英文词数口径）**：每集 **200-448 词**（目标 320 词；节拍类型分下限：转/合集 ≥300 词、起/承集 ≥200 词）——一律以英文词数（words）衡量，不再使用任何中文字数（字）口径，否则历史误读"700-800 词"≈4-5 分钟严重超时（详见 `shared/base.md` 字数红线与 `formats/english-short-drama.md` 第一点五节）。第 1 集不特殊加长，与其它集同体量（拍出来 1-2 分钟）；每集严格"压弹簧/放弹簧"二选一。

**生成前置约束**：所有内容必须严格对齐步骤 2.5 确认的节点表、冲突轮换表与能力边界总纲（结构宪法），偏离框架的内容必须自行重写。**🔴 分集大纲交付规则（全局 · 省上下文）**：大纲成品默认只输出到「情节单元层」（一个大 loop = 2-8 集、长度不均分），逐集节拍降级为内部底稿、只在分批写正文时临时展开，**不全量铺 80-100 集逐集大纲**（除非用户明确要求）。**采用分批生成制：默认单批最多 10 集，每批开写前注入结构宪法 + 上一批审计结论 + 前情摘要，每批写完对照结构宪法做节点审计，偏离则自行重写后再进入下一批**——这是对抗长上下文遗忘、逻辑漂移的核心机制。

**发散-收敛两阶段**：

- **全剧级发散**：在大纲生成前，基于标签组合与结构宪法，一次性生成 3 个核心设定差异最大的方向——方向A：最符合标签直觉的经典方向；方向B：同一情绪内核但核心爽点机制反转的反套路方向；方向C：跨标签碰撞的小众创新方向。3 个方向在「主角核心身份、核心冲突类型、爽点触发机制」3 个维度必须全部不同。从 3 个方向中选出差异化系数最高且不违反红线的 1 个，展开为完整大纲。发散过程为内部工作底稿，不交付用户。
- **批次级发散**：每批 10 集开写前，对本批次的核心冲突强制分配到 3 种不同的解路径大类（如：靠信息差解决/靠人脉资源解决/靠对手内部矛盾解决），相邻批次不得连续使用同一解路径大类。每批节点审计时加做「解路径去重校验」：本批次与上一批次的解路径重复不得超过 1 次。

**交付铁律：只把剧本正文交付给用户。** 设计说明（弹簧类型/钩子/付费点/标签适配/解路径）、篇幅统计、合规自检都是你自己的内部工作底稿，绝不输出给用户。写每集前按设计构思、写完后逐项自检，**任一项不通过（篇幅不足/解路径重复/人设漂移/世界观硬伤/关键节点偏离/能力越界/内部骨架标注泄漏）必须自行重写至通过再交付**——这是你的职责，不是用户要做的事。**交付正文里每一集只有集号+集标题+场次+人物+动作+台词，集标题后严禁带任何括号里的节拍/压放/起承转合标注（见 `shared/base.md`）。**

**内部自评闭环（适用于一句话故事 / 故事梗概 / 人物设定）**：

这三项是全剧地基，质量直接决定上限。生成它们时必须走**「内部生成 → 内部自评 → 不达标重写 → 达标再输出」**闭环——草稿与评分过程是内部工作底稿，**绝不展示给用户，用户只看到达标后的成品**。

```
1. 内部生成草稿（不展示）：先放开手脚生成一句话故事/梗概/人设
2. 内部自评打分（不展示）：用下方对应自评标准逐条过，每条标注"达标/不达标 + 理由"
3. 不达标就重写（不展示）：针对不达标项定向重写，重新自评，循环直到全部达标（最多 5 轮；5 轮仍不达标则取最优稿并标注待用户决策的硬伤）
4. 达标才输出（展示）：只把达标的成品交付给用户，不附带任何自评过程
```

**通用自评标尺——融梗三问（多标签作品必过，单标签作品免）**：

> **推导提示（多标签时，自评前先做，不展示）**：直接复用步骤 2 用户已确认的「融梗一句话」作为自评基准——如果用户已确认了 A×B 产生的新叙事特性，不需要重新推导。仅在用户未确认或融梗方向已调整时，才重新写这句话。
>
> 示例：穿越×系统×甜宠 → "系统任务约束让穿越者的开天眼不再是无限开挂，攻略男主才能通关但真心爱上就触发惩罚"——这个困境是三个标签单独都没有的。

1. **删掉标签 A 后，标签 B 的核心冲突崩不崩？** 崩→融梗成功；不崩→物理拼接，重写
2. **关键转折有没有 A×B 的化学产物？** 有→合格；只是 A 的转折 + B 的转折并列→重写
3. **前 3 集有没有爽点？** 有→合格；慢热铺垫→重写

> 各产物的专属自评标准见 `stages/1-outline.md`（一句话故事/梗概）与 `stages/2-character.md`（人物设定）。自评不是给用户看的流程，是你交付前在心里跑完的质量闸门。

## 步骤 4：自审

读 `stages/4-review.md`，按**四维度百分制量化评分**（结构与节奏 40 / 人物与人设 20 / 标签与逻辑 20 / 硬指标与表达 15 / 创意差异化 5）逐项打分，输出评级（S/A/B/C）+ 爆款概率预估。**🔴 短剧性专项（最高优先级 · 全局）**：必须 Read `references/anti-tv-drama.md` 第四节，对十条短剧性红线逐条检测——R1 分幕 / R6 付费钩>3集/个 / R7 爽点机制重复≥4次 为一票否决项，命中任一即整体降一级评级；其余红线按对应维度扣分。必须执行 **AI 通病专项检测**（依据 `shared/anti-patterns.md` 全部反模式 + 分品类阈值表，以该文件当前实际条目为准）。**标签红线联动**：本剧激活的 level-1 强红线标签（见 `common-tags/INDEX.md` 号段总表：马甲 AP-MJ / 女性成长 AP-NC / 追妻 AP-ZQ / 破镜重圆 AP-PJ / 虐恋 AP-NL / 大女主 AP-DN / 霸总 AP-BZ）的 `AP-` 反模式逐项检测，**只作扣分项挂靠对应维度，不另设加分**；大女主 AP-DN 与女性成长 AP-NC 命中同一"关键胜利靠男人"问题时只扣其一，不叠加。输出专项报告（每处问题含位置+扣分+整改建议）。可对接 `references/tools/auto-review-rules.md` 做自动化初检。新增专项检测项：节点对齐度、叙事单循环、能力边界合规性、副线掉线、**创意差异化检测**（检测产出是否与同标签组合常见套路有本质区别，如打脸虐渣是否跳出隐忍爆发型、战神归来是否跳出兵王归来型，缺乏差异化即扣分）。**融梗抽离测试**（挂在"标签与逻辑"维度下，不另设分值，作为反模式12的检测工具）：对多标签组合做**抽离测试**——删掉标签 A 后，标签 B 的核心冲突是否坍塌？坍塌→融梗成功（不扣分）；不坍塌→物理拼接（触发反模式12扣分）。单标签作品不适用。

## 反模式（不要做）

- 跳过步骤 0 的标签推断/市场/语言识别
- 海外题材照搬国内叙事（打脸 vs 追妻必须区分；按 `markets/` 适配阈值）
- 能从 prompt 推断的标签却反复追问用户（违背"能推断绝不问"）
- 必须确认时拆成多轮提问（应一次问完）
- 生成时连续使用同一冲突解路径/同一情绪表达（违背反重复校验）
- 凭常识省略 reference 读取
- 跳过步骤 2.5 骨架锁定，直接生成剧本
- 生成完不走 4-5 直接交付
- 一次性读完所有题材/标签模块（按需读，省 token）
- 用 sub agent 跑顺序流程（单线串行，主 agent 一个上下文跑完）
- 突破预设能力边界、无关键节点随意升级金手指
- 一次性硬写完 80-100 集而不分批审计（违背分批生成制，必崩）
- 存在独立副线却全程依附主线、副线中途掉线
- 海外项目未做完全本土化、出现中式人名/中式家庭/中式职场逻辑
- 漫剧产出缺少视觉化分镜设计、靠大段对话推进、画面冲击力不足
- 选题与同赛道常见套路无本质差异（如复仇永远是隐忍爆发型、战神永远是兵王归来），缺乏差异化
- 同一会话内多次生成选题时，核心设定（主角身份/冲突类型/爽点机制）高度雷同

## 多语种说明

本 skill 只维护一份中文源文件，**不需要双语/多语版本**。模型按步骤 0 识别的用户语言输出最终内容。海外题材的本土化要求写在 `overseas/` 分支各模块里。
