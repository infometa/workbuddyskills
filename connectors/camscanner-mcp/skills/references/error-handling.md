# MCP 错误与恢复

## 先识别结果状态

MCP 传输成功（包括 HTTP 200）不等于工具业务成功。先检查调用层错误及 `isError`，再读取 `structuredContent` 或 `content` 中的业务数据。成功响应缺少必需产物/字段时属于结果不完整，不宣称已完成。

区分上传任务、二进制上传、上传完成确认、处理、下载落盘、云文档创建各阶段。保留已成功的 file_id、本地文件和云结果，只恢复失败步骤；不要因为下载失败而重新转换或因为保存失败而重新上传仍有效的产物。

## 常见错误

| 错误 | 处理 |
|------|------|
| 参数错误 / 400 | 对照当前 schema 检查参数、类型、文件格式，修正后才重新调用 |
| 认证失败 / 401 | 提示重新连接连接器；不重复业务调用、不索取 Token |
| 无权限 / 403 / tool not allowed | 检查当前可见工具；不改调用名称猜测绕过授权 |
| tool not found | 核对工具名称及当前可见工具；不当作文件过期重新上传 |
| file_id 无效或过期 | 核实输入来源；原文件仍可用时重新上传，已有云文档可重新下载获取引用；不要把所有 404 都解释为过期 |
| 上传地址过期 | 重新创建上传任务，按新的返回信息传输；保留仍有效的业务产物引用 |
| 文件过大 | 告知限制；不擅自压缩、删页或拆成多个产物 |
| too many files | 最多 100 张；单文件要求不能自动分批，只有用户接受分卷时才分批 |
| 429 | 允许重试的步骤等待 10 秒后重试 |
| 500 / 504 / 网络超时 | 先检查失败阶段和是否可能已创建云文档；确认可安全重试后等待 5 秒 |

仅在工具 schema 支持 timeout_sec 且确为处理超时时调整它；增加业务超时不能保证解决宿主或网关超时。

## 重试与停止

- 每个步骤对同一组输入最多 2 次尝试（首次 + 1 次重试），包括修正参数后的重新调用。不通过改名或换目录规避计数。
- 认证、权限、已知不支持的能力、缺少必要传输能力，直接停止受影响流程。
- 批量任务中同类故障连续影响两个输入时停止该流程，说明共同阻塞，列出未处理项。不要对剩余每个文件重复同样的失败。
- 达到上限后报告已成功、失败和未处理的部分；只有用户明确要求继续时才恢复。

## 云保存状态不明

`create_cloud_doc` 不是幂等操作。超时、断连或多文件操作失败时，可能已创建文档，不能把重复创建默认视为可接受。

1. 保留输入 file_id、标题、调用时间及已收到的结果。
2. 可用 search_cloud_doc 按标题、时间等核查；相近标题不是本次成功证据，无匹配也不证明未创建。
3. 能明确识别本次创建结果时按真实结果反馈；仍不确定时停止自动重建并告知用户。
4. 云端明确未成功且原因已修正、结果 file_id 仍有效时，只重试 create_cloud_doc，不重跑转换。

本地下载与云保存是独立步骤。一端失败不抹去另一端的成功；交付时分别说明实际状态。缺少本地写入能力只能给出真实下载地址，不报告不存在的本地路径。
