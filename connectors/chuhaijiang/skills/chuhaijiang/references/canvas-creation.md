# AI 画布创作 SOP

目标：用 canvas / canvas_tasks / assets 三个工具在出海匠 AI 画布上程序化创作——带货视频、商品图、口播 TTS、多镜头短片。顺序就是方法：先定「说什么」（脚本与 hook），再定「怎么拍」（路线与画面语言），最后才是「怎么生成」（画布工作流）。

## 开始前必告知用户（第一动作）

接到画布任务，先向用户说明再动手：

- **使用画布需要出海匠企业版**（写入操作被套餐拦截时引导用户升级，不要反复重试）
- **画布接口本身调用免费；AI 生图/生视频等生成任务按出海贝计费**——图片按 image_size、视频按模型×分辨率的每秒单价×时长、TTS 按字符数，参考单价见 canvas 工具契约的计费说明，以产品内定价表为准

**两套账户体系，严禁混用推断**：

| | 出海匠会员（网站账号） | API 账户（开放平台 Key） |
|---|---|---|
| 管什么 | 画布写权限（企业版套餐）+ **出海贝**（生成任务计费） | **credits**（数据查询/上传等接口计费） |
| 哪里看 | 出海匠产品内 | account_info |

account_info 查不到会员套餐与出海贝——credits 充足**不代表**能用画布或生成；生成报「余额不足」指的是出海贝，与 credits 无关，引导用户去出海匠产品内充值

## 铁律（违反任何一条都是错误）

1. **先脚本后画面**：没定「说什么」之前不生成任何东西——脚本框架、hook、卖点的画面翻译先落在文本节点上，分镜画板和视频 prompt 都是脚本的翻译
2. **一条视频配一张专属分镜画板**（1:1 图片），画板只含该条要演的镜头——多余镜头信息会干扰视频模型
3. **视频 prompt 用时间轴节拍表，每 2~4 秒一拍**（如 15s 拆 4~6 镜：「0-3秒：…；3-6秒：…」）。分镜拆得细，模型每一拍都有明确指令，抽卡率才低——只给首尾帧的话中间过程完全不可控。但一拍只装一个动作要点，塞多必崩
4. **节点先行**：apply add_node（带 generationDraft 草稿）→ add_edge（引用连线）→ **canvas generate 一步闭环**（服务端读节点草稿与一跳连线上下文，自动完成文本展开/@引用解析/参考图角色分配/Seedance 字段路由，提交任务并自动绑定）→ 产物由平台自动回填（含素材库登记），**无需守候**：图片任务快（~30s）可短轮询 canvas_tasks detail 后验收；视频任务提交后即告知用户「已提交，画布会自动回填」，不轮询，等用户看完回来反馈。画布全程反映「待生成→生成中→完成」，**严禁体外循环**（先生成后补节点）
5. **文本优先直写**：商品卡/脚本/标注这类 Agent 自己能写的文本，apply update_node 直写文本节点，零成本；只有需要基于画布素材上下文做 AI 文本生成时才用 canvas generate（text 节点，计费）
6. **花钱操作先报价**：提交生成前把模型、关键参数、预估成本展示给用户；批量任务（>3 个）先给清单和总预估。用户明确指定过或说"你来定"时不必反复问

## 第一步 · 说什么：脚本框架与 Hook

脚本定了，后面全是翻译。**唯一的跨框架铁律：画面证明卖点，不靠口播说教**——每个卖点都翻译成一个可拍的画面：「续航 5000 次」写成「充一次电拖完 120 平一周不充」，「承重强」写成「压满重物实拍」。脚本里出现没有对应画面的卖点，就是断点。

### 脚本框架（收敛共识，查表套用）

| 框架 | 结构 | 适用 |
|---|---|---|
| **UGC 6 要素**（当前最优） | Hook → 痛点+情绪 → 方案 → 价值主张 → 社会证明 → 单一 CTA | 20-25s；比经典框架多「社会证明」这一拍，别省 |
| TikTok 4 段式 | Hook–Problem–Proof–Push | 15-30s 跨境带货 |
| 千川 5 段式 | 痛点(3s)–对比(7s)–卖点(8s)–证据(7s)–CTA(5s) | 30s，各段配比直接抄 |
| FABV | 特征→优势→利益→情感价值升华 | 30s，理性+感性完整链路 |
| S-A-B 卖点分层 | S 人无我有(抓人) → A 人有我优(信任) → B 人人都有(兜底) | 写脚本前先给卖点分层排序，再套任一框架 |
| PAS / BAB | 痛点-激化-解决 / 之前-之后-桥梁 | 痛点驱动用 PAS，有前后对比素材用 BAB |

时长纪律：6s 只装一句话；**先写 30s 完整版再裁剪，永远别直接写 60s**。

### Hook：前 3 秒的设计（值得花一半功夫）

Hook 是整条视频里杠杆最高的 3 秒。纪律：**每次生成 5 个候选，拒掉第一个**（第一个几乎总是最安全也最弱的）；hook 的口播、字幕、画面必须三重一致。四类十二式：

- **好奇类**（开环留人）：①悬念视觉——开头呈现反常识画面；②提问式——抛用户自己也在问的问题；③好奇闭环——开一个问题吊到落点才合上
- **痛点类**（「这和我有关」）：④痛点直击——「如果你也 X，这条一定看完」+痛点实拍；⑤场景痛点还原——不说痛点，直接演痛点发生的那一刻；⑥反向断言——甩一个与品类常识相反的断言再辩护（天花板最高、翻车风险也最高）
- **证据类**（先给结果）：⑦结果先行——直接展示 after 再倒回过程；⑧反差对比——左右分屏/前后对比；⑨数据/权威——具体数字或权威背书开场
- **模式中断类**（打断滑动惯性）：⑩Pattern Interrupt——视觉/听觉突兀元素；⑪POV 代入——第一人称把观众放进场景；⑫Bold Claim——大胆承诺（正文必须兑现，否则是标题党）

### VoC：hook 和痛点从用户原声里来，不凭空编

- amazon(action=reviews)：好评里的卖点原话 → 证据类 hook；差评里的痛点原话 → 痛点类 hook
- get_related(products, id, "reviews")：TikTok 侧商品评论同理
- 拆竞品爆款（search videos + ai_generate script_breakdown）：借它的 hook 类型与结构配比，换自己的产品细节

## 第二步 · 怎么拍：路线二选（选错路线比执行差更致命）

| | 原生感（带货/UGC，默认） | 高级感（品牌片/TVC） |
|---|---|---|
| 画面语言 | 手机直拍质感、手持微抖、自然光、真实生活场景、真人出镜（哪怕只有手） | 受控运镜（单一慢动作）、棚拍定向布光、精确设计的动作、大量留出的纯净背景 |
| 底层逻辑 | 「这不是广告」的信任感——广告感越弱转化越高 | 情绪先行、故事驱动；质感一半靠调色与声音设计 |
| 分镜方法 | 脚本框架直译分镜 | **Moodboard 先行**：先用低价图出几张风格差异大的概念图给用户挑，对齐想象再进分镜——人不能想象没见过的东西 |
| 食品类要点 | 真实使用、试吃反应 | **appetite appeal 第一**：光泽/蒸汽/融化/拉丝是食欲信号；产品永远完整、诱人、被尊重；定向光点燃食欲、平光杀死食欲 |

两条路线的 prompt 词汇表完全不同，不要混。带货默认原生感；用户明确要品牌片才走高级感。

### 带货主场景：15 秒竖屏五幕结构

经典节拍（每幕对应分镜画板 1~2 镜）：

1. **0-2 秒 hook**——从上面十二式里选，前 2 秒决定完播
2. **产品是什么**——产品清晰入画，主体占画面
3. **细节 / 使用场景**——材质特写、上手使用、功能演示
4. **情感满足 / 生活方式**——用了之后的状态，场景化共鸣
5. **产品 hero cut + 行动号召**——产品定格 + 促购信息（画面文字易乱码，promo 文字留给发布端字幕）

**商品一致性是命门**：纯文字生成的商品和真品对不上就不能用。商品实拍图/详情页图作参考图锚定（get_detail 的商品图、amazon detail 的 image_urls、用户实拍图）；prompt 里的商品外观词必须和参考图一致，不要让文字和图打架。

## 模型选择：按场景推荐，附成本口径

给用户带理由的推荐（用户比你更不懂模型差异），不要摊裸选项：

**抽卡保持默认，终稿才升档**：画布视频生成的平台默认模型即 sd_pro_mini，抽卡阶段保持默认即可——抽卡验证的是 prompt 和分镜对不对，画质档位不是瓶颈（Seedance 系各档位参考体系相同）。prompt 验证通过的终稿再考虑升 sd_pro/sd_pro_fast 重生成；直接上高档抽卡，一次失败的成本能抵 mini 好几轮迭代。

| 场景 | 首选 | 理由 | 备选 |
|---|---|---|---|
| 带货视频量产 / 一切抽卡迭代 | sd_pro_mini | Seedance 系最低档，成本最低；参考体系与高档位相同 | 效果不满意升 sd_pro_fast |
| prompt 已验证的终稿 / 需要参考音频 | sd_pro | Seedance 系参考体系最全（model_images + reference_videos + reference_audios） | sd_pro_fast（更快更省） |
| 真实感人物 / 口播画面 | veo31 | 人物真实感强 | sd_pro |
| 单图起手的图生视频 | wan26 | 图生视频专长 | grok（15s 档必须传参考图） |
| 分镜画板 / 信息图 / 商品图 | gpt_image_2 | 结构化文字渲染稳（画板要求模型"看图读字"） | nanobanana |
| 风格化 / 多参考图商品图 | nanobanana | 参考图 ≤5 张 | gpt_image_2 |

happyhorse：未沉淀出场景定位，用户点名时用。视频费用 = 模型×分辨率的每秒单价×时长，同模型降分辨率/缩时长就是降成本。效果与本表冲突时以实测为准，并沉淀回本文件。

## 第三步 · 怎么生成：画布工作流

### 阶段 0：素材与设定（零成本）

1. canvas create 建画布，apply rename_canvas 为项目名
2. **设定卡文本节点**（update_node 直写）：
   - 带货场景：商品卡——卖点清单（已做画面翻译）、目标人群、外观锁定要点（颜色/材质/logo 位置）、VoC 原声摘录
   - 叙事场景（短剧/品牌片）：角色卡——外观特征 + 性格 + 口头禅 + prompt 要点，每角色一张
3. **参考图**：商品用实拍图/详情页图；角色用正版标准像（**不要 AI 生成商品/角色的标准形象**，生不准，请用户提供或用官方图）。upload_file(accelerated=true) 上传 → PUT → apply add_node(image) + attach_asset（坐标 os_bucket/os_key 映射为 osBucket/osKey）→ add_edge 与设定卡连线。**必须加速版**：只有加速版上传登记画布素材归属，标准版传的文件挂载会被归属校验拒绝。已在素材库的素材用 assets 工具找（返回的 bucket_name/os_key 即坐标）
4. **脚本文本节点**：按选定框架写镜头脚本，每镜头 [画面]（景别+动作）/ [台词/声音]（口播词/音效，台词用目标市场语言）/ [情绪]

### 阶段 1：分镜画板（每条视频一张，图片生成）

分镜画板 = 千字结构化 prompt 生成的「导演画板」信息图——视频模型会看图读字，整条视频的脚本通过画板喂给它。五区版式模板：

```
高度结构化的极简 UI 网格化排版，高级灰、透明 UI 元素、细线框、半透明信息卡片、
清晰模块分区，专业电影级画板感、导演分镜感，图文混排、中文信息层级清晰
（台词保留原语言），干净整齐，信息图表化，可读性强。

一、顶部 Header：《项目名 · 第 N 条：标题》
二、左侧 主体设定：商品外观锁定要点 / 每个出场角色的外观+性格+声线，注明"必须与参考图完全一致"
三、中间 场景设定：环境描述，锚定场景参考图画风
四、右侧 分镜脚本区：每镜头 [画面]（景别+动作）/ [台词/声音]（原语言）/ [情绪]
五、底部 核心参数卡片区：主题/视频类型/镜头语言/光影/色调/构图/分镜数量/输出格式

严禁 AI 变形、物理破绽、文字乱码、比例失真。参考图中的商品/角色外观、颜色、比例、
关键识别特征必须严格保持一致。
```

- **分镜数量**：在模型能力范围内多拆——15s 拆 4~6 镜（每镜 2~4 秒），镜头越细中间过程越可控；但每镜只一个动作要点
- 参数：model=gpt_image_2、ratio=1:1、imageSize=2K（ratio 用比例串如 1:1/9:16，square 类词形会被接口拒绝——字段与枚举以工具说明为准）；参考图 = 商品图/出场角色官方图 + 场景图（≤5 张，连线到画板节点即可）
- **生成后必须亲眼验收**（hydrate 换签名 URL 下载看图）：文字是否正确、镜头缩略图演出是否符合脚本。文字乱码基本不可修，重新生成

### 阶段 2：视频生成（单条 ≤15s）

prompt 六要素骨架：[主体] + [动作] + [环境] + [镜头] + [风格] + [约束]，按时间轴节拍表组织：

```
严格按分镜画板（图片1）的镜头顺序生成。
0-3秒：[镜头1 画面+动作]，[台词/音效]
3-6秒：[镜头2 …]
…
镜头：[一个主运镜，如 缓慢推近]。风格：[路线选择+光线]。
音频：0-3秒 [环境音/台词]；3-6秒 […]
避免：肢体变形，画面抖动，文字乱码。
```

- 参考图 = 专属分镜画板 + 商品图/角色官方图，**连线到视频节点即可**——generate 自动收集一跳邻居、分配参考图角色并路由 Seedance 字段；需精确控制时用 input_node_ids 限定参与节点、generation.inputMode 指定 reference / first-frame / first-last-frame
- **一条视频只用一个主运镜**（多运镜必抖）；光线描述必写（对画质影响最大）；不要用"快速"类词（显著降画质）
- **只写模型能执行的动作**——三类词必然失控：①设计行话（「留白」被画成白色色块——翻译成物理描述如「下方三分之一为纯净的深色背景区域」）；②光的时序与内部物理（「光亮起/扫过/物体显形」「液体内部光流涌动」都拍不出——光永远写成静态状态，动感交给镜头运动、烟雾、粒子、表面光斑）；③自相矛盾指令（「定格」与「推近」勿并用）。负面提示要圈定作用域（「避免画面文字」会连产品标签一起抹掉——写「避免生成额外文字，产品标签以参考图为准保留」）
- **多镜结构的两条路**（mini 单镜契约见工具说明）：升 sd_pro 一次生成，或每镜单独生成短片后在成片编辑器拼接——分镜拼接每条 prompt 只写一个镜头，执行压力最小、抽卡最可控
- 图生视频时画面信息已由参考图提供 90%，prompt 只写动作、镜头、音频、负面约束，不重复描述画面
- 音频与画面分开描述、标时间点
- canvas generate 提交后**不守候轮询**——产物由平台自动回填，告知用户已提交即可，等用户看完回来反馈；节点已有内容时自动分支新版本，原版本不被覆盖。**改 prompt 走 update_node 改 draft 再 generate**，保持网页端所见即所执行（顶层覆盖仅用于一次性试验）
- **one body × N hooks**：hook 值得多做变体——固定正文只换前 2-3 秒，对视频节点多次 generate 天然产出版本分支，hook 变体成本趋近于零，这是 AI 生成对传统拍摄的结构性优势
- **视频鉴赏归人、归因归 Agent**：成片好坏是品味判断，交给用户看；用户反馈问题后（如「第 3 镜产品变形」「节奏拖」），Agent 再 hydrate 下载、本地抽帧（如 ffmpeg；签名 URL 不支持事后追加处理参数）对照分镜画板与 prompt **归因**——画板缺约束→补画板重生成；prompt 没写清→改 draft 重生成；纯抽卡失手→原样重抽。确诊才改料，别让用户为盲目重试买单。常见病灶：商品/角色变形穿模、画面文字乱码、动作没做完（=一拍塞太多）、比例不对

### 阶段 3：成片与交付

- 多条拼接与配乐在出海匠**网页端**完成：提示用户打开画布、框选视频进成片编辑器（此环节暂无 API）
- canvas share_create 生成分享链接（/c/{token}）可作为交付物，也能当误删/误改后的恢复点（share_clone 找回）——画布无版本历史。但**不要自行判断"重要节点"就主动创建**：这是一条任何人打开都能看的公开链接，属于对外可见的动作，只在用户明确要交付成果、或明确要求备份时才创建
- 提醒用户：Agent 改完画布后网页端需刷新才可见

## 防呆清单（行为约定；参数契约以各工具说明为准，不要凭记忆猜字段）

- 写操作前拿最新 revision（已持有文档结构时用 canvas list 轻量取，否则 load）——服务端任务回填、用户在网页端编辑都会推进版本号，Agent 与用户同时在线操作同一画布是常态；409 冲突响应自带 current_revision，直接用它重试，连续冲突 2~3 次停下来与用户确认
- 花钱操作（generate）提交前报模型、关键参数、预估成本；余额不足报错时引导用户去出海匠充值，不要反复重试
- 生成失败先诊断再重试——原 prompt 直接重发大概率复现同样问题，白花钱
