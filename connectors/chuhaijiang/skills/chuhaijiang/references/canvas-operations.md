# 出海匠画布操作契约

在调用 `canvas`、`canvas_tasks`、`assets` 或为画布调用 `upload_file` 前阅读本文件。字段、模型、枚举和错误码以当前 MCP schema 为准；本文件只规定跨工具的执行策略，不复制接口参数。需要为图片、分镜画板、视频或口播编写 prompt 时，继续阅读 [画板与视频 Prompt 模板](prompt-templates.md)。

本文中的“画布”指承载节点和连线的 Canvas；“分镜画板”指画布中生成、用于约束视频的一张 Storyboard 图片，不要混用两者。

## 用户与成本边界

- 画布写入需要出海匠**网站企业版**，与开放平台 API 套餐无关。画布 API 调用免费；图片、视频、TTS 消耗网站侧出海贝；上传可能消耗 API credits。
- 在画布写入或生成前向用户说明上述区别。`account_info` 只能查看 API credits，不能证明网站写权限或出海贝余额。
- **每次付费生成必须先获得用户明确确认**：调用 `canvas.generate` 前展示最终创意/脚本、实际 prompt、参考素材及职责、模型、数量、时长、比例、分辨率或图片尺寸、参考模式和已知成本，停下来等待用户明确同意。最初说“帮我生成”、提供素材、确认创作方向或保持沉默，都不等于批准最终付费任务。
- 用户可以一次确认一份参数完整的批量任务清单。确认后只要 prompt、参考素材/职责、模型、数量、时长、比例、分辨率/图片尺寸或参考模式任一实质变化，就必须重新确认；重做、变体和重试也是新的付费提交，不沿用旧确认。
- 余额或权限错误、超时或其他响应未返回 `task_id` 时，停止当前提交并说明状态；不盲重试、不额外生成变体，也不擅自分享、发布或删除画布。

## 创作阶段门禁

1. **先定内容，零成本起草**：视频项目先与用户收敛目标观众、核心卖点/情绪、hook、脚本、CTA、镜头节拍和事实边界，再把确认内容写入文本节点。概念图、角色/场景设定图、首帧和分镜画板等服务于视频的图片同样受此门禁约束；独立商品图或单图任务只需确认该图片的目标，不强行补写视频脚本。
2. **先搭骨架，不提交生成**：创建画布后只搭设定/脚本文本节点、已上传或素材库参考节点、带完整渲染字段的空输出节点及真实连线。此阶段不得调用 `canvas.generate`；若上传当前会消耗 API credits，上传前也要说明并确认。
3. **用户视觉确认骨架**：通过画布页面或 hydrate 后的实际预览让用户检查每张参考图是否正确、清晰、齐全，主身份/细节/场景/风格等职责与引用关系是否正确，以及脚本和目标输出节点是否完整。只报文件名、节点名或存储坐标不算视觉确认。用户明确确认前停止；后续新增、替换参考图或改变职责时重新打开此门禁。
4. **图片/分镜画板确认后生成**：用户未指定图片模型时默认使用 `gpt_image_2`；用户明确指定其他当前 schema 支持的模型时服从。把最终 prompt 与 `generationDraft` 参数写回节点并按“用户与成本边界”确认后，才可提交。分镜画板完成后先做主体一致性、镜头可读性和文字层级检查，再让用户视觉确认；用户未确认该画板前，不得把它用于视频生成。
5. **视频参数由脚本与用户共同确定**：时长来自已确认的脚本时间轴；各镜头时码必须连续且总和等于提交时长，口播应能在对应时段自然说完。先基于脚本、素材和预算给出一个带理由的模型建议，再由用户确认模型、分辨率、比例及参考模式。当前模式以 schema 为准，常见映射为全能参考 `reference`、首帧 `first-frame`、首尾帧 `first-last-frame`、无参考 `none`；确认后把模型、分辨率和 `inputMode` 显式写入 `generationDraft`，不依赖平台默认值或自动推导。若模型不支持脚本需要的时长或参数，修改/拆分方案并重新确认，不擅自裁剪或拉长脚本。
6. **提交前核对确认版本**：重新取得最新 revision，并核对目标节点的 prompt/`generationDraft`、引用连线、`input_node_ids` 和素材职责仍与用户确认版本一致；任何实质变化先重新展示并确认，再调用 `canvas.generate`。

## 默认交互：通过画布页面与用户协作

1. 实际操作画布时，取得有效画布 ID 后，若当前会话提供内置浏览器，优先在其中打开画布。画布页面是用户与 Agent 的协作界面：用户可以随时查看 Agent 写入的节点，也可以直接检查和操作画布。
2. 画布基础地址为 `https://www.chuhaijiang.com/app/create/canvas/{canvas_id}`。用户给出画布 ID 时，先 `load` 确认画布存在，再打开基础地址；用户给出完整 URL 时，从中提取 ID 并用 `load` 确认，打开时保留原 URL 中的 `nodeId`；创建新画布时，在 `create` 返回 ID 后打开基础地址。
3. 内置浏览器的登录态通常独立于用户日常浏览器，首次打开很可能进入登录页。调用打开工具只表示发起导航；只有打开结果能够确认已进入画布，或用户明确确认已经看到画布，才可说“画布已打开”。若进入登录页或无法确认页面状态，请用户在当前内置浏览器中登录或确认页面，然后停下来等待回复；不得索取、代填或保存账号密码。
4. 用户确认登录完成后，重新打开登录前的完整画布地址。不要依赖登录后的首页、工作台或其他默认跳转，也不要只刷新登录页；原地址带有 `nodeId` 时，仍须重开同一节点定位地址。
5. `canvas.generate` 成功后，使用同一次调用的 `canvas_id` 和响应返回的 `execution_node_id` 构造节点定位链接：`https://www.chuhaijiang.com/app/create/canvas/{canvas_id}?nodeId={URL 编码后的 execution_node_id}`，再按上述方式打开，让用户直接看到本次生成的元素；若进入登录页，仍按第 3—4 条处理。必须使用 `execution_node_id`，不能使用提交时的 `target_node_id`，因为目标节点已有内容时生成会落在新的版本分支节点。`nodeId` 只是前端页面的导航参数，不是 `canvas` API 的请求参数。
6. 同一任务中复用已经打开且登录态已确认的画布页面，不必在每次 API 调用后重复打开。打开画布与用户完成骨架视觉确认是两个不同状态：即使已经进入画布，也不能视为用户已经确认。
7. 当前会话没有内置浏览器，或打开失败时，如实说明原因，并提供当前应使用的基础地址或节点定位地址让用户手动打开。这不妨碍后续 API 操作，但需要用户视觉确认的步骤仍须通过画布页面或实际预览完成。

## 执行边界

- 用户给出画布 URL、ID 或要求继续时先 `load`；响应没有 `document` 说明画布已删除，不创建替代品。其余画布创作请求再 `create`。
- 画布动作都通过 `canvas({action, params})`；节点、边、改名和挂载资产通过 `apply.operations`，不能当成独立工具。每次写入使用最新 `expected_revision`；409 时只重试同一意图，连续 5 次仍冲突则停止。
- 本地或附件素材进入画布必须走加速 `upload_file`，完成 PUT 后核对远端字节数，再用返回的坐标挂载。上传不会自动进入 `assets` 素材库。
- 参考图/文本必须通过真实节点和边影响目标节点；需要收窄或固定引用顺序时再传 `input_node_ids`。常规生成使用节点的 `generationDraft`，不要用一次性顶层 prompt 覆盖代替长期草稿。
- 画布内生成通过 `canvas.generate` 提交，后续只用 `canvas_tasks` 查询；不要与 `ai_generate` 的 `check_task` 混用。若 `generate` 失败且未返回 `task_id`，先读 MCP 响应中的 `generation_diagnostic`：它已自动回读同一画布目标节点，并安全返回 `status`、`attempt_id`、`error_code`、`error_message`。以其中的 `error_message` 诊断根因，不把外层 4xx/5xx 当作最终原因；字段缺失或旧版 MCP 无此字段时，再手动 `load` 后检查节点的 `data.generation`。成功后记录 `task_id`；已完成资产优先回填或复用，不重新生成。
- 图片可按任务需要检查。视频默认提交后交用户鉴赏；只有用户要求等待或质检时才 hydrate、检查时长和画面问题，并先定位素材、画板、prompt 或模型原因再决定是否重做。
