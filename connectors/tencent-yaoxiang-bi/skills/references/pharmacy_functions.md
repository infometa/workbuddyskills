## 版本归属 → 升级预期效果（商业化引导依据）

功能所属「版本归属」直接决定药箱侧策略的「升级预期效果」怎么引导：

| 功能当前版本归属 | 升级预期效果（引导方向） |
|---|---|
| 基础版 / 专业版 | 引导升级至专业版 / 企业版，获取更完整的提醒、打卡、复购数据与看板 |
| 专业版 / 企业版 | 引导升级至企业版 / 定制版，开通精准人群触达、定制内容与私域运营 |
| 企业版 / 定制版 | 引导升级至定制版 / 增值服务，获取深度定制规则、专属标签与数据服务 |
| 定制版 | 引导开通增值服务，获取数据看板、Agent 能力等付费项 |
| 增值服务 | 直接作为商业化钩子，引导企业开通对应增值服务包 |

> 一句话：**「版本归属」越靠后，商业化价值越高**。策略里把「当前能做什么」落到用户价值/药企价值，把「升级后还能多做什么」落到升级预期效果。

## 策略模板（写死 · 四段式）

每条药箱侧策略按下列结构展开，功能与价值**取自《药箱产品功能明细表.xlsx》原文**：

```
[功能名（明细表真实功能）] → [用户价值（「用户价值」列）] → [药企价值（「药企价值」列）] → [升级预期效果（「版本归属」列：基础版→专业版→企业版→定制版/增值服务）]
```

**示例（基于 30-39 岁主力 + 老客回扫渗透深的洞察）**：

> 策略：「接入**用药提醒 + 复诊续方提醒** → 帮患者简化设置、降低漏服并按时续方避免断药（用户价值）→ 提升用药依从性、减少脱落并拉动复购（药企价值）→ 建议由基础版升级至专业版，获取分人群打卡与复购数据看板（升级预期效果）」

## 不在《功能明细表》内的禁用词

新生成报告时，药箱侧策略**禁止使用**以下「可能不在功能表里」的词，避免无法回查：

- ❌「数字医生」「智能客服」（非表内功能名，表内对应为「数字人智能问药」「企业私域客服」）
- ❌「AI 助理」（表内对应为「智能助手」）
- ❌「用药人档案」（表内对应为「加入药箱」「健康计划」）
- ❌ 自创新词、自造价值描述
- ✅ 引用时统一写为：表内功能名 + 「（明细表第 N 类）」可追溯定位
