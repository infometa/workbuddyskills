# 字段目录与口径参考 —— 在线客服部日报表（企微报备群版）

数据源：`query_daily_report_messages`（数据桶 `channel`）。工具拉取当天企微「报备群」里咨询师发的报备消息**原文**（linkwechat_prod 的 `im_room` / `im_msg_room` / `im_msg_room_content`），本 skill 负责解析与聚合。所有字段名/信封格式以网关实时返回为准。

## 0. 口径一句话

报表某天（D）的数字 = 当天报备群里、咨询师报备消息里的 `今日门诊` / `今日触点数量` / `今日社群邀约打标情况` 逐条解析后按「咨询师→组别」聚合。**预约门诊 = 今日门诊；项目 = 明日门诊(项目)里的项目名；今日触点 = 今日触点数量；今日社群入群 = 今日社群邀约打标情况。** 报备群 room_id 清单由服务端固定（`.env` 的 `REPORT_ROOM_IDS`），本 skill 不需要也不应猜测 room_id。**不再用 网电预约/booking/cfintent 估算口径。**

## 1. 工具与返回信封

工具签名：`query_daily_report_messages(date: str, limit: int = 500, offset: int = 0)`

成功返回：
```json
{
  "success": true,
  "data": [
    {
      "msg_id": "…", "from_id": "…", "room_id": "…", "room_name": "…",
      "msg_time": "2026-09-02 09:15:30", "msg_type": "…",
      "text": "咨询师:周垣宏\n今日门诊:1\n明日门诊(项目):1痘坑\n今日触点数量:120今日社群邀约打标情况:1",
      "file_name": null
    }
  ],
  "meta": {
    "row_count": 18,
    "masked_fields": [],
    "fields": ["msg_time", "from_id", "room_id", "room_name", "text", "file_name", "msg_type", "msg_id"],
    "limit": 1000,
    "offset": 0
  },
  "audit": { "trace_id": "…" }
}
```

- `data` 每行即一条企微群文字消息。**解析对象只有 `text`**（报备原文）；`msg_time` 用于排序/定位异常；`room_name` 用于标注未识别消息的出处；`from_id` 是发送者企微 id（不是姓名，不要当咨询师名用）。
- 服务端只回**报备群内、当天、员工发的文字消息**（`from_type=1`、`text` 非空）。图片/文件消息 `text` 为空会被过滤掉（如需图片里的报备，另行人工处理，本工具不回图片内容）。
- `meta.row_count` 受 `limit` 封顶 → 分页判断以「本批 `data` 长度 < limit」为准。
- 失败：`{"success":false,"error":{"code":"...","message":"..."}}`；常见 `CONFIG_MISSING`(未配 REPORT_ROOM_IDS)、`PERMISSION_DENIED`(带 `missing_bucket`/`hint`)、`QUERY_FAILED`、`INVALID_PARAMS`(date 格式非法)。

## 2. 报备消息文本格式

一条报备消息（`text`）形如：

```
咨询师:周垣宏
今日门诊:1
明日门诊(项目):1痘坑
今日触点数量:120今日社群邀约打标情况:1
```

字段以「键:值」出现，键名固定为：

| 键 | 含义 | 值示例 | 报表映射 |
|---|---|---|---|
| `咨询师` | 咨询师姓名 | `周垣宏` | 咨询师（→ 组别映射） |
| `今日门诊` | 当天预约门诊数 | `1` | **预约门诊** |
| `明日门诊(项目)` | 项目 | `1痘坑` | **项目**（取非数字后缀 `痘坑`） |
| `今日触点数量` | 当天触点数量 | `120` | **今日触点** |
| `今日社群邀约打标情况` | 当天社群邀约打标数 | `1` | **今日社群入群** |

**格式要点（解析时必须容忍）**：
- 键值之间可能换行，也可能连续拼接在同一行（如 `今日触点数量:120今日社群邀约打标情况:1`）。**用正则按「键名」定位**，不要假设每条键一定独占一行。
- `明日门诊(项目)` 的值 = `<数字><项目名>`：先匹配 `^(\d+)\s*(.*)$`，数字是「明日门诊」数量（本报表不用于预约门诊列），项目名 = 数字后的剩余文本（可能为空）。例：`1痘坑` → 项目名 `痘坑`；`2玻尿酸` → `玻尿酸`；`1` → 项目名为空。
- 键名可能带空格/全半角差异，先做一次规范化（去首尾空白、全角冒号 `：` 归一为半角 `:`）。
- 一条消息里可能出现多个 `明日门诊(项目)`（多个项目），全部收集；也可能同一咨询师当天发多条报备（见下）。

**推荐解析思路（示意，非强制）**：
```
keys = ["咨询师", "今日门诊", "明日门诊(项目)", "今日触点数量", "今日社群邀约打标情况"]
对 text 做规范化后，逐个键用「键名后紧跟的 : 到下一个键名或行尾」切分取值；
数字字段 int() 失败按 0 计并标注。
```

## 3. 聚合规则

- **键 = 咨询师**（一位咨询师一行）。
- 同一咨询师当天多条报备：**默认取最后一条**（按 `msg_time` 升序后取末尾，视为更正后的最终值），并在结果里标注「该咨询师当天多条报备」；若需叠加/拆行，先与人工确认。
- 项目名多个 → 用「、」连接展示（如 `痘坑、玻尿酸`）；无项目名 → `—`。
- 组别：查 `references/consultant-groups.md` 的「咨询师→组别」映射；未收录 → `未分组`，并提示补录。
- 组小计 = 组内各咨询师「预约门诊/今日触点/今日社群入群」逐列求和；总计 = 各组小计之和。
- 表格外汇总：`报备人数`（= 参与报备且识别出咨询师的条数/人数）、`今日门诊合计`、`今日触点合计`、`今日社群邀约入群合计`。

## 4. 咨询师 → 组别 映射

- 见 `references/consultant-groups.md`。**这是唯一组别来源**，不要凭空猜组别。
- 咨询师名字须与报备里 `咨询师:` 后的文本**逐字一致**（含空格/全半角/生僻字）；不一致视为未收录。
- 组别缺失时如实标注「未分组」，不要回退到旧口径（客户档案 `ftype`）——旧口径属于网电预约数据源，已废弃。

## 5. 网关部署前提

`query_daily_report_messages` 需要网关新版本：
- 代码：`gateway/mysql.py`（pymysql 只读层）+ `gateway/server.py`（`query_daily_report_messages` 工具）。
- 配置：`.env` 的 `MYSQL_HOST/MYSQL_PORT/MYSQL_DB/MYSQL_USER/MYSQL_PASSWORD` + `REPORT_ROOM_IDS`（报备群 room_id，逗号分隔）。
- 依赖：`requirements.txt` 增 `pymysql>=1.1`。

旧版本网关无此工具；`list_available_datasets` 里看不到则说明未部署。

## 6. 推荐查询模板

```json
query_daily_report_messages(date: "2026-09-02", limit: 1000, offset: 0)
```

分页拉全（`data` 长度 == limit 则 `offset += limit` 继续）后逐条解析 `text`、按咨询师聚合。
