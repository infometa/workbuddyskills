## §1 选型决策树

### 数据规模 → 计算节点规格

```
数据规模判断：
├── < 500GB（小规模）
│   ├── 并发 < 10 QPS → 4C16G × 2 节点
│   └── 并发 ≥ 10 QPS → 8C32G × 2-3 节点
├── 500GB - 5TB（中小规模）
│   ├── 并发 < 20 QPS → 16C64G × 2-3 节点
│   └── 并发 ≥ 20 QPS → 16C64G × 4-6 节点
├── 5TB - 20TB（中等规模）
│   ├── 查询简单（聚合为主）→ 32C128G × 4-6 节点
│   └── 查询复杂（多表 JOIN）→ 64C256G × 4-8 节点
├── 20TB - 100TB（大规模）
│   ├── 延迟要求宽松 → BIGDATA 机型 × 6-12 节点
│   └── 延迟要求严格 → 64C256G × 8-16 节点
└── > 100TB（超大规模）
    └── BIGDATA/HIGHIO 机型 × 12+ 节点，建议分集群
```

### 并发要求 → 节点数量调整

| 并发 QPS | 调整策略 |
|----------|---------|
| < 10 | 基础配置即可 |
| 10-50 | 节点数 × 1.5（向上取偶数） |
| 50-100 | 节点数 × 2，考虑读写分离 |
| 100-500 | 增加节点数至 8-12 节点，选更高规格（32C128G 或 64C256G），单集群可承载 |
| > 500 | 多集群方案 / 云原生弹性集群 |

### 延迟要求 → 存储与内存调整

| 延迟要求 | 调整策略 |
|----------|---------|
| > 5 秒（宽松） | 高性能云硬盘即可 |
| 1-5 秒（标准） | SSD 云硬盘 |
| < 1 秒（严格） | 增强型 SSD + 内存规格上调一档 |
| < 100ms（极致） | 增强型 SSD + 大内存 + 物化视图预计算 |

## §2 规格映射表

### 规格命名与磁盘类型绑定规则

> **重要**：规格名称的后缀直接决定了必须配置的磁盘类型，选型时不需要单独选择磁盘类型——选定规格即确定磁盘类型。

| 规格名后缀 | 含义 | 对应 DiskType | 中文名 |
|-----------|------|--------------|--------|
| `_P` | Premium | `CLOUD_PREMIUM` | 高性能云硬盘 |
| `_H` | HSSD | `CLOUD_HSSD` | 增强型SSD云硬盘 |

**HIGHIO 型（H_ 开头）特殊规则**：
- 数据盘固定为 `LOCAL_BASIC`（本地盘）
- 磁盘大小和数量固定在命名中，如 `H_32_128_2_7140` = 32C128G + 2 块 7140GB 本地盘

**完整命名规则**：
```
S_{CPU}_{MEM}_{P|H}  → 标准型，_P = CLOUD_PREMIUM, _H = CLOUD_HSSD
H_{CPU}_{MEM} 或 H_{CPU}_{MEM}_{DiskCount}_{DiskSize} → 高IO型，LOCAL_BASIC
```

**强制约束**：
- 选了 `S_16_64_P` 就**必须**配 `CLOUD_PREMIUM`
- 选了 `S_32_128_H` 就**必须**配 `CLOUD_HSSD`
- 不允许规格后缀与 DiskType 不匹配（如 `S_16_64_P` 配 `CLOUD_HSSD` 是错误的）

### 标准型（STANDARD）规格

| 规格名称 | CPU | 内存 | 磁盘类型 | 适用场景 |
|---------|-----|------|---------|----------|
| S_4_16_P / S_4_16_H | 4 核 | 16 GB | CLOUD_PREMIUM / CLOUD_HSSD | 测试/开发/小数据量 |
| S_8_32_P / S_8_32_H | 8 核 | 32 GB | CLOUD_PREMIUM / CLOUD_HSSD | 小规模生产/低并发 |
| S_16_64_P / S_16_64_H | 16 核 | 64 GB | CLOUD_PREMIUM / CLOUD_HSSD | 中等规模/通用场景（最常用） |
| S_32_128_P / S_32_128_H | 32 核 | 128 GB | CLOUD_PREMIUM / CLOUD_HSSD | 大规模/复杂查询 |
| S_64_256_P / S_64_256_H | 64 核 | 256 GB | CLOUD_PREMIUM / CLOUD_HSSD | 超大规模/高并发 |

### 大数据型（BIGDATA）规格

| 规格名称 | CPU | 内存 | 适用场景 |
|---------|-----|------|---------|
| BIGDATA 系列 | 变化 | 变化 | 大容量本地盘，适合冷数据/历史数据存储 |

### 高 IO 型（HIGHIO）规格

| 规格名称 | CPU | 内存 | 适用场景 |
|---------|-----|------|---------|
| HIGHIO 系列 | 变化 | 变化 | 高 IOPS 本地 NVMe SSD，适合低延迟场景 |

### Common 节点（ZooKeeper/ClickHouseKeeper）规格

| 场景 | 推荐规格 | 节点数 |
|------|---------|--------|
| 小集群（≤ 5 数据节点） | 4C16G | 3 |
| 中集群（6-20 数据节点） | 8C32G | 3 |
| 大集群（> 20 数据节点） | 16C64G | 3 或 5 |

**Common 节点磁盘参数推导**：

Common 节点的磁盘配置从 `TCHouseCDescribeSpec` 返回的 `CommonSpec[].DataDisk` 中获取：
- `DiskType`：使用 CommonSpec 返回的 DiskType（通常为 CLOUD_HSSD）
- `DiskSize`：默认 100GB（满足 ZK/CKKeeper 元数据存储需求）
- `DiskCount`：固定 1 块（CommonSpec 的 DiskCount 通常为 1）

若 CommonSpec 返回多种磁盘类型可选，优先选择 CLOUD_HSSD（性能更好），成本敏感场景可选 CLOUD_PREMIUM。

## §3 存储选型指南

### 磁盘类型对比

| 磁盘类型 | 代码 | IOPS | 吞吐量 | 单价 | 适用场景 |
|---------|------|------|--------|------|---------|
| 高性能云硬盘 | CLOUD_PREMIUM | 中等 | 中等 | 低 | 冷数据/日志/成本敏感 |
| SSD 云硬盘 | CLOUD_SSD | 高 | 高 | 中 | 通用 OLAP/标准场景 |
| 增强型 SSD | CLOUD_HSSD | 极高 | 极高 | 高 | 低延迟/高并发/热数据 |

### 磁盘容量计算

```
所需磁盘容量 = 原始数据量 × 压缩比 × 副本数 × 冗余系数 ÷ 节点数

其中：
- 压缩比：根据业务场景选择（见下表）
- 副本数：高可用模式为 2，非高可用为 1
- 冗余系数：建议 1.3（预留 30% 空间用于合并/临时文件/增长）
```

### 压缩比参考值（按业务场景）

| 业务场景 | 压缩比 | 说明 |
|---------|--------|------|
| OLAP 聚合分析（报表/BI） | 0.25~0.35 | 数据列式存储 + 高重复度字段（如枚举、时间戳），压缩效果最好 |
| 实时写入/日志分析 | 0.35~0.50 | 日志文本字段较多，字符串压缩率相对较低 |
| 混合负载（OLAP + 点查） | 0.30~0.45 | 取决于数据结构，介于两者之间 |
| 宽表/高基数字段多 | 0.40~0.55 | UUID、URL、JSON 等高基数字段压缩率较差 |
| 时序数据（监控/IoT） | 0.15~0.25 | 数值型时序数据重复度极高，压缩效果最佳 |

> **选型建议**：
> - 用户未明确场景时，默认使用 **0.35**（偏保守）
> - 用户明确为纯数值型时序数据时，可使用 **0.20**
> - 用户明确有大量文本/JSON 字段时，建议使用 **0.50**
> - 如果不确定，宁可高估（使用较大的压缩比值），避免存储不足

### 云盘数量建议

| 场景 | 云盘数量 | 说明 |
|------|---------|------|
| 小规模（< 2TB/节点） | 1 块 | 简单管理 |
| 中规模（2-10TB/节点） | 2-4 块 | 并行 IO 提升性能 |
| 大规模（> 10TB/节点） | 4-10 块 | 最大化 IO 带宽 |

## §4 高可用与网络方案

### 高可用决策

| 场景 | 是否开启 HA | 是否跨 AZ | 说明 |
|------|------------|-----------|------|
| 测试/开发 | 否 | 否 | 节省成本 |
| 生产-容忍分钟级中断 | 是 | 否 | 同 AZ 双副本 |
| 生产-高可用要求 | 是 | 是 | 跨 AZ 部署，容灾能力强 |
| 金融/核心业务 | 是 | 是 | 跨 AZ + 备份策略 |

### 高可用对资源的影响

- 开启 HA：数据节点数必须为偶数（2 副本），存储翻倍
- 跨 AZ：需要在两个可用区各有子网，网络延迟增加 1-3ms
- ZK 高可用：Common 节点至少 3 个

### HAZk / ClickhouseKeeper / NoKeeper 选型指导

根据集群模式确定这三个布尔值的取值：

| 推荐场景 | HaFlag | HAZk | ClickhouseKeeper | NoKeeper | 是否需要 COMMON 节点 |
|---------|--------|------|-----------------|----------|--------------------|
| 生产集群（双副本 + ZooKeeper） | true | false | false | false | 是（3 节点） |
| 生产集群（双副本 + CKKeeper） | true | false | true | false | 是（3 节点） |
| 测试/开发（单副本，无高可用） | false | false | false | false | 否 |
| 单副本 + ZK 高可用 | false | true | false | false | 是（3 节点） |
| 单副本 + CKKeeper 高可用 | false | true | true | false | 是（3 节点） |

**选型建议**：
- 新建集群默认推荐 `ClickhouseKeeper=true`（内核版本 ≥ 23.8 时），CKKeeper 相比 ZK 资源占用更少
- `NoKeeper=true` 为白名单功能，选型推荐中不主动使用
- 当 `NoKeeper=true` 时，Resources 中不应包含 Type=COMMON 的节点配置

### 网络方案建议

| 场景 | VPC 建议 | 子网建议 |
|------|---------|---------|
| 单 AZ | 1 个 VPC + 1 个子网 | 子网 IP 充足（≥ 节点数 × 2） |
| 跨 AZ | 1 个 VPC + 每个 AZ 各 1 个子网 | 每个子网 IP ≥ 节点数 |
| 与已有业务互通 | 使用业务所在 VPC | 避免 IP 冲突 |

## §5 容量规划公式

### 存储容量

```
总存储需求(GB) = 日增量(GB) × 保留天数 × 压缩比(0.3~0.5) × 副本数 × 1.3(冗余)
单节点存储 = 总存储需求 ÷ 数据节点数
```

### 内存估算

```
建议内存 ≥ 热数据量 × 10%（用于缓存和查询中间结果）
单次查询内存 ≈ 扫描数据量 × 2-5%（取决于查询复杂度）
并发内存需求 = 单次查询内存 × 并发数
```

### 节点数估算

```
最小节点数 = max(
  ceil(总存储需求 / 单节点最大磁盘容量),
  ceil(并发 QPS / 单节点可承载 QPS),
  2  // 最少 2 节点
)

其中：
- 单节点可承载 QPS ≈ CPU 核数 × 0.5-1（简单查询）或 CPU 核数 × 0.2-0.5（复杂查询）
```

### 存储容量校验（强制 ASSERT）

> **重要**：在输出任何推荐方案前，必须对每个方案执行以下校验，校验不通过则自动调整配置。

```
集群可用存储 = 节点数 × 盘数 × 单盘大小(GB) × 0.9（格式化损耗）
需求存储 = 数据量(GB) × 副本数 × 1.3（冗余系数）

ASSERT: 集群可用存储 ≥ 需求存储
```

**参数说明**：
| 参数 | 含义 | 取值 |
|------|------|------|
| 节点数 | 总数据节点数量（包含所有副本，即 HA 模式下 Count 已含 2 副本） | 方案中的 Count |
| 盘数 | 每节点云盘数量（DiskCount）。**标准版（STANDARD 规格）默认每节点 1 块数据盘**；`TCHouseCDescribeSpec` 返回的 `DataSpec[].DataDisk.DiskCount` 表示的是「最大云盘数量」上限，不是默认值。数据量较大时可显式在 Resources.DiskSpec.DiskCount 中调大（一般 2-10 块）以并行 IO；HIGHIO 型（本地盘）盘数固定在规格名中，不可调整 | DiskCount（默认 1，可配置至规格上限） |
| 单盘大小 | 单块云盘容量 | DiskSize (GB) |
| 0.9 | 格式化损耗系数 | 固定值 |
| 数据量 | 压缩后实际存储量 | 原始数据量 × 压缩比(0.3~0.5) |
| 副本数 | HA=2, 非HA=1 | 由 HaFlag 决定 |
| 1.3 | 冗余系数 | 固定值（merge/临时文件/增长缓冲） |

**校验失败时的自动调整策略**（按优先级顺序）：

1. **上调单盘大小**：`新单盘大小 = ceil(需求存储 / (节点数 × 盘数 × 0.9))`，向上取整到 100GB 的整数倍
2. **增加云盘数量**：若单盘大小已达 MaxDiskSize 上限，增加 DiskCount
3. **增加节点数**：若云盘数量也达上限，增加节点数（HA 场景向上取偶数）

**示例**：
```
场景：10TB 压缩后数据，HA 双副本，4 节点 × 10 盘 × 200GB

集群可用存储 = 4 × 10 × 200 × 0.9 = 7,200 GB = 7.2 TB
需求存储 = 10,000 × 2 × 1.3 = 26,000 GB = 26 TB

ASSERT 失败：7.2 TB < 26 TB
→ 自动上调单盘大小 = ceil(26000 / (4 × 10 × 0.9)) = ceil(722.2) = 800 GB
→ 校验：4 × 10 × 800 × 0.9 = 28,800 GB = 28.8 TB ≥ 26 TB ✓
```
