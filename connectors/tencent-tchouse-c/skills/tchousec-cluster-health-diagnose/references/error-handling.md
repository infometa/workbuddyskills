# TCHouse-C 错误码统一处理规范

> **何时使用本文件**：所有 tchousec 系列 skill 在调用云 API 遇到错误码时，均以本文件为准；SKILL.md 中的「错误码与处理策略」表若与本文冲突，以本文为准。

## 1. `UnsupportedRegion`（该接口不支持此地域访问）

### 1.1 典型错误返回

```json
{
  "code": "UnsupportedRegion",
  "msg": "该接口不支持此地域访问。(\"cdwch.XxxAction\")",
  "data": {
    "Response": {
      "Error": {
        "Code": "UnsupportedRegion",
        "Message": "该接口不支持此地域访问。"
      }
    }
  }
}
```

### 1.2 语义

- 后端返回该错误码时，含义为：**当前请求的 `Region` 参数所指向的地域，TCHouseC（ClickHouse）产品未在该地域开服**。
- 这**不是**参数格式错误、也**不是**权限问题、**不是**限流。
- 产品支持哪些地域会随业务发展变化（新增地域时接口会自动放开），因此 skill **不维护"支持地域白名单"**，一律以本错误码作为运行时判定依据。

### 1.3 Agent 行为（强约束）

| 行为项 | 要求 |
| --- | --- |
| 是否重试 | ❌ **不重试**（重试无意义，同一地域的下次请求仍会返回同样错误） |
| 是否切换地域 | ❌ **不自行切换**（不要"猜"用户想去的地域） |
| 是否报 error | ❌ **不在最终报告中作为 error 抛出** |
| 必须动作 | ✅ 调用 `ask_user`（WorkBuddy 中为 `AskUserQuestion`）询问用户，让其确认当前指定的地域是否正确 |

### 1.4 询问模板

```text
您指定的地域「{中文地域名}（{Region}）」当前不支持 TCHouseC 产品。可能原因：
  1) 地域填错了 —— 例如把"上海金融"当成了"上海"，或把兄弟产品的地域套过来；
  2) 该地域尚未开通 TCHouseC 服务。

请确认：
  A. 目标集群实际所在地域是什么？（例如："广州 ap-guangzhou"）
  B. 如果就是 {中文地域名}，请通过腾讯云控制台确认该地域是否已开通 TCHouseC；
     未开通时，需要走产品申请流程，本 skill 无法绕过。
```

### 1.5 用户答复后的后续动作

- 用户给出**新地域** → 重新调用原工具（新的 `Region` / `RegionId`）。
- 用户确认**就是这个地域** → 输出以下结论并终止流程：
  > "TCHouseC 在地域『{中文地域名}』暂未开通，本次任务无法继续。请通过腾讯云工单或产品经理确认开通计划。"
- 用户未回复 / 超时 → 按 skill 通用规则处理（一般是暂停并告知用户）。

### 1.6 反例（禁止行为）

- ❌ 在 skill 内维护"支持地域列表"并做白名单校验（业务新增地域时 skill 会过时）。
- ❌ 收到该错误码后自动改成 `ap-guangzhou` 之类的默认地域重试。
- ❌ 把该错误码包装成 `InvalidParameter.*` 或"内部错误"上报给用户。
