## §1 图表选择规则

### 决策树

```
用户需求
├── 有时间维度？
│   ├── 是 → 单系列？
│   │   ├── 是 → 📈 折线图
│   │   └── 否 → 📈 多折线图（每个分类一条线）
│   └── 否 → 有分类维度？
│       ├── 是 → 分析占比？
│       │   ├── 是 → 分类 ≤ 8？
│       │   │   ├── 是 → 🥧 饼图/环形图
│       │   │   └── 否 → 📊 柱状图 + 百分比标注
│       │   └── 否 → 📊 柱状图（纵向或横向）
│       └── 否 → 单一数值？
│           ├── 是 → 🔢 数字卡片
│           └── 否 → 📋 数据表格
```

### 详细规则表

| 数据特征 | 分析意图 | 推荐图表 | 备选 |
|---------|---------|---------|------|
| 时间序列 + 单指标 | 趋势变化 | 📈 折线图 | 面积图 |
| 时间序列 + 多指标 | 多指标趋势 | 📈 多折线图 | 双Y轴图 |
| 时间 + 分类 + 数值 | 分类趋势对比 | 📈 多折线图 | 堆叠面积图 |
| 分类（≤ 10）+ 数值 | 大小对比 | 📊 纵向柱状图 | 条形图 |
| 分类（> 10）+ 数值 | 排名对比 | 📊 横向柱状图 | — |
| 分类（≤ 8）+ 占比 | 占比分布 | 🥧 饼图 | 环形图 |
| 分类（> 8）+ 占比 | 占比分布 | 📊 柱状图+百分比 | 树状图 |
| 两组数值 | 对比（同比/环比） | 📊 分组柱状图 | 瀑布图 |
| 单一汇总数值 | 关键指标展示 | 🔢 数字卡片 | — |
| 多步骤 + 递减数值 | 漏斗转化 | 🔽 漏斗图 | 横向柱状图 |
| 地理维度 + 数值 | 地域分布 | 🗺️ 地图 | 气泡图 |

### 特殊场景处理

| 场景 | 处理方式 |
|------|---------|
| 数据只有 1 行（汇总结果） | 使用数字卡片展示关键指标 |
| 数据行数 > 50 | 建议只展示 TOP 20，其余归为"其他" |
| 多个指标量级差异大 | 使用双 Y 轴或分开展示 |
| 时间粒度过细（秒级） | 建议聚合到分钟/小时级别 |

## §2 图表配置规范

### 折线图配置

```markdown
**图表类型**：折线图
**X 轴**：日期（时间维度）
**Y 轴**：[指标名称]（[单位]）
**系列**：[分类维度]（如有多系列）
**建议**：
- 数据点标注关键值（最大值/最小值）
- 时间轴按自然顺序升序排列
- 多系列时使用不同颜色区分
```

### 柱状图配置

```markdown
**图表类型**：柱状图（纵向/横向）
**X 轴**：[分类维度]
**Y 轴**：[指标名称]（[单位]）
**排序**：按指标值降序
**建议**：
- 柱子数量 ≤ 10 个
- 标注具体数值
- 横向柱状图适合分类名称较长的场景
```

### 饼图配置

```markdown
**图表类型**：饼图/环形图
**分类**：[分类维度]
**数值**：[指标名称]
**建议**：
- 分类数量 ≤ 8 个
- 标注百分比和具体数值
- 占比 < 3% 的归为"其他"
- 按占比从大到小顺时针排列
```

## §3 业务结论规范

### 结论结构模板

```markdown
## 📊 分析结论

### 核心发现
[1-2 句话概括最重要的发现，使用加粗突出关键数字]

### 数据详情
[用表格或列表展示关键数据]

### 趋势判断
[描述数据的变化趋势，包含环比/同比对比]

### 异常提示（如有）
[标注明显的异常值或突变点]

### 建议行动（可选）
[基于数据给出的业务建议]
```

### 写作规范

| 规范项 | 要求 | 示例 |
|--------|------|------|
| 语言 | 中文，面向非技术人员 | ✅ "支付金额" ❌ "pay_amount 字段的 SUM" |
| 数字格式 | 千分位分隔 | ✅ 1,234,567 ❌ 1234567 |
| 百分比 | 保留 2 位小数 | ✅ 23.45% ❌ 23.4512% |
| 金额单位 | 根据量级自动选择 | < 1万 → 元；1万~1亿 → 万元；> 1亿 → 亿元 |
| 趋势描述 | 使用方向词 + 幅度 | ✅ "环比增长 15.2%" ❌ "比上期多了一些" |
| 对比表述 | 明确基准和变化 | ✅ "较上月增长 23%" ❌ "增长了" |
| 异常标注 | 使用 ⚠️ 标识 | ⚠️ 6月5日支付金额骤降 40%，需关注 |

### 结论质量要求

1. **数据驱动**：每个结论必须有对应的数据支撑，不做无依据的推测
2. **业务视角**：从业务角度解读数据，而非技术角度
3. **可行动**：结论应能指导业务决策（如"建议加大 A 渠道投放"）
4. **简洁明了**：核心发现控制在 2 句话以内
5. **突出重点**：使用加粗标注关键数字和结论

## §4 输出格式模板

### 完整输出示例

```markdown
## 📊 分析结果

### 查询说明
> 分析需求：统计过去 7 天各渠道的用户支付金额，按天汇总
> 数据范围：2026-06-02 ~ 2026-06-08
> 数据来源：db_order.payment_records

### 数据结果

| 日期 | 微信支付 | 支付宝 | 银行卡 |
|------|---------|--------|--------|
| 06-02 | 125.3万 | 89.2万 | 45.6万 |
| 06-03 | 132.1万 | 91.5万 | 48.2万 |
| ... | ... | ... | ... |

### 可视化建议

**推荐图表**：📈 多折线图
- **X 轴**：日期
- **Y 轴**：支付金额（万元）
- **系列**：支付渠道（微信支付/支付宝/银行卡）
- **标注**：标记每条线的最高点

### 分析结论

#### 核心发现
过去 7 天总支付金额为 **1,823.5 万元**，其中**微信支付占比 48.2%**，为最大支付渠道。整体支付金额呈**稳步上升趋势**，日均环比增长 3.2%。

#### 趋势判断
- 微信支付：稳步增长，7 天增幅 12.3%
- 支付宝：基本持平，波动在 ±2% 以内
- 银行卡：小幅增长，7 天增幅 5.7%

#### ⚠️ 异常提示
6月5日支付宝渠道金额骤降 18%（从 91.5 万降至 75.1 万），次日恢复正常，建议排查当日是否有系统异常。

#### 建议行动
1. 微信支付为主力渠道，建议持续优化微信支付体验
2. 支付宝渠道增长停滞，建议分析是否有优惠活动到期
3. 关注 6月5日支付宝异常，确认是否为技术故障
```

### 简洁输出（单一指标查询）

```markdown
## 📊 分析结果

### 🔢 关键指标
**过去 7 天总 GMV：1,823.5 万元**
- 日均 GMV：260.5 万元
- 最高日：6月8日（298.3 万元）
- 最低日：6月2日（225.1 万元）
- 环比上周：+8.7%

### 结论
本周 GMV 整体表现良好，较上周增长 8.7%，呈稳步上升趋势。周末（6月7-8日）为支付高峰，建议在周末加大营销活动力度。
```
