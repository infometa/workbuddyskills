# Seedance 2.5 双 PE 对照规范

适用版本：AI-HIVE Connector 1.1.4

本参考只在用户明确要求“双 PE”“A/B prompt”“稳健版和增强版”“两版提示词对照”或“组内盲测”时读取。普通视频请求仍使用单一最佳 Prompt。

## 模式边界

- 版本 A：**稳健基线版**。完整、清晰、少发挥、低风险，但不能故意写弱。
- 版本 B：**优化增强版**。在相同事实和素材边界内增强镜头组织、节奏、场景 knowhow、素材调度、商业表达与可观察细节。
- 两版必须独立成篇，不写“同上”或互相引用。
- 不把任何缺少可核验来源链的内部 PE 包描述为官方发布物。
- Connector 可接收 MP3/WAV 外部音频并通过 `audioMediaIds` 提交；只有当前模型配置明确支持参考音频及当前任务组合时才使用。外部参考音频、Prompt 声音描述与 `params` 原生声音开关分别冻结，不能混用。

## 先冻结共同输入

生成两版前，在内部建立并共用以下台账：

### 事实台账

- 任务类型：Generate、Edit 或 Extend；
- 主体身份、数量、外貌、服装、结构与材质；
- 场景、空间关系、动作、事件顺序和道具归属；
- 台词原文、声音来源、必须保留项与明确禁区；
- 品牌、型号、参数、价格、奖项、授权或专业结论的证据边界。

不能从素材直接观察或由用户明确提供的信息，不得写成事实。品牌、价格、性能、身份、关系和授权尤其不能推测。

### 素材职责台账

按各自实际上传顺序使用“图片1、图片2……”“视频1、视频2……”“音频1、音频2……”：

- 图片可负责主体外貌、服装、商品结构、道具、场景、光线或关键帧；
- 视频可负责动作、运镜、节奏、时间线、编辑母版或延长源；
- 音频可负责 BGM 节拍、台词/音色、声音风格或延长时的声音连续参考；
- 用户指定的素材职责优先，两版不得为同一素材分配不同职责；
- 未采用素材不写进 Prompt，也不得暗中用于人物、场景、道具、动作或镜头。

## 任务合同

### Generate

两版共享同一生成目标、主体、场景、主要事件、素材映射、外部参考音频职责和终态。版本 B 可增强动作连续性、镜头关系、节奏和场景表达，但不能新增人物、功能、剧情事实或素材职责。

### Edit

把 `videoMediaIds` 的首个视频视为待编辑母版。两版必须明确“只修改什么”和“必须保持什么”：非目标人物、动作、时间线、空间关系、镜头、道具与背景保持不变。若配置允许音频编辑，`audioMediaIds` 只承担共同冻结的声音修改或参考职责。版本 B 只可增强透视、光影、接触阴影、遮挡和融合方式。

### Extend

把 `videoMediaIds` 的首个视频视为延长源，明确前延长或后延长。两版都要保持边界帧、主体身份、空间方向、动作惯性、镜头运动、光线与声音氛围连续；若配置允许外部音频，使用共同冻结的音频职责。版本 B 可增强合理的后续事件，但不得改写原片事实。

## 两版写法

### 稳健基线版

按“目标 → 素材职责 → 主体与关系 → 事件顺序 → 镜头与声音 → 保持项”组织。使用中性、明确、可观察的动作，不堆叠复杂运镜，不补写未经提供的事实。

### 优化增强版

与稳健基线版共享全部冻结项，只从以下维度增强：

- 镜头技术、目标主体、起始关系、方向/速度与结束关系；
- 事件节奏、动作连续性、情绪的可观察表演；
- 商品展示、剧情冲突、口播亲近感等场景 knowhow；
- 透视、遮挡、接触阴影、空间锚点和生成稳定性；
- 用户已提供的声音、台词与节拍的层次组织。

不得通过新增品牌、参数、价格、身份、关系、人物、素材或剧情结果制造优势。

## 时间与参数纪律

- 仅在用户给出分镜/节拍，或卡点、对白对齐、关键事件边界需要时使用连续整数秒时间段；其他情况按自然事件顺序或“镜头 N”组织。
- 时长、画幅、分辨率、输出格式、模型 ID、路由和声音开关不写进 Prompt 正文。
- 这些参数只使用 `list_models` 当前模型配置明确暴露的键和值，并放入 `generate_video.params`。

## Prompt-only 与实际运行

### 默认：Prompt-only

只输出以下内容，不调用 `generate_video`：

1. 用户意图摘要；
2. 稳健基线版 Prompt；
3. 优化增强版 Prompt；
4. 两版核心差异；
5. 建议选择。

### 实际 A/B 运行

用户明确要求生成两版视频时，先说明这是两次独立计费调用并取得确认。确认后，为保证公平对照：

- 使用同一 publicModelId；
- 使用同一 routingMode；
- 使用同一 pricingSnapshot；
- 使用同一 params；
- 使用同一媒体字段：`imageMediaIds`、`videoMediaIds`、相同 `audioMediaIds`、`firstFrameMediaId`、`lastFrameMediaId` 的值与顺序全部一致；其中 `audioMediaIds` 的值与顺序也不得改变；
- 只允许 `prompt` 不同；
- 两个 `taskId` 分别跟踪，不把一个任务的状态或结果归到另一个任务。

任一共同输入发生变化，就不再称为同一轮 A/B；应说明变化并重新建立对照。

## 输出前检查

1. 两版任务类型是否相同；
2. 主体身份、数量、素材职责和事实边界是否相同；
3. 稳健基线版是否完整可用，而非故意写弱；
4. 优化增强版是否存在真实策略差异，而非同义改写；
5. 是否没有编造品牌、参数、身份、授权、价格或奖项；
6. 是否没有把接口参数混入 Prompt；
7. Prompt-only 是否没有调用付费工具；
8. 实际运行是否先确认两次计费并保持除 Prompt 外的全部输入一致。

## 评测记录

实际生成两版后，可按以下维度各评 1–5 分并记录依据：

| 维度 | 判断重点 |
|---|---|
| 意图还原 | 是否覆盖核心主体、事件与用途 |
| 素材一致 | 是否正确使用素材且没有错配、漏配 |
| 场景专业 | 是否体现任务场景所需的专业表达 |
| 视频可生成性 | 是否具体、可观察、复杂度合理 |
| 镜头与节奏 | 是否连续、清楚且服务于事件 |
| 事实安全 | 是否没有编造或越过证据边界 |
| 结果偏好 | 用户更偏好哪版以及具体原因 |

记录两个 `taskId`、共同输入摘要、各维度评分、偏好版本、偏好原因和严重错误；不把主观偏好描述成普遍模型结论。
