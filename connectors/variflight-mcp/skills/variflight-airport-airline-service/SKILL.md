# 飞常准机场与航司服务

## 能力范围

- 机场：基础资料、机场电话、失物招领、地面交通、点评、乘机流程、餐饮、行李寄存和特殊旅客服务等。
- 航司：基础资料、联盟、客服电话、值机选座、退改、行李、会员、休息室、延误保障、中转和特殊旅客服务等。
- 位置：根据用户明确提供或授权的经纬度查询最近机场及同城市机场。
- 服务分类和正文以本次 MCP 返回为准，不假设所有机场或航司提供相同项目。

本 Connector 不查询机场大屏、机场运行态势、具体航班动态、机票价格、订单或支付。

## 鉴权

出现未授权或 401 时，提示用户在 Connector 设置中检查或更新 C 端用户 MCP Key；不要在对话中索要或展示完整 Key。

## 可用 Tool

### `searchAirport`

根据机场名称、城市名称或模糊关键词查找机场和城市代码。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `name` | string | 是 | 机场或城市名称关键词 |
| `region` | string | 否 | `CN` 表示中国大陆，`INT` 表示全球；不传默认全球 |

返回：

- `airportList`：匹配机场，包含名称和机场三字码。
- `cityList`：匹配城市，包含名称和城市代码。

调用机场服务时只能使用 `airportList[].code`，不得把 `cityList[].code` 当作具体机场代码。

### `getAirportInfoByCode`

按机场 IATA 三字码查询基础资料和旅客服务。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `code` | string | 是 | 机场三字码，如 `PEK`、`PVG` |

主要返回：

- `baseInfo`：IATA、ICAO、经纬度、跑道数量、国家、时区、机场中英文名、城市和航站楼坐标。
- `telList`：机场联系电话及归属说明。
- `traffic`：地面交通信息；当前结果不含地铁类型。
- `comment`：点评总数和评分，字段可能为字符串。
- `serviceList`：服务分类、标题、关键词和 Markdown 正文资源。

`offsetTime` 单位为秒，例如 `28800` 表示 UTC+8。接口未返回地铁不代表当地没有地铁。

### `getAirlineInfoByCode`

按航司 IATA 二字码查询基础资料和旅客服务。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `code` | string | 是 | 航司二字码，如 `CA`、`MU`、`CZ` |

主要返回：

- `baseInfo`：联盟、航司名称、简称、IATA/ICAO、国家、电话和 Logo。
- `serviceList`：值机选座、退改、行李、会员、休息室、延误保障、餐食、中转和特殊旅客等服务正文。

当前 Connector 没有航司名称检索 Tool。用户只给航司名称且上下文没有可靠二字码时，应追问二字码，不能猜测。

### `getAirportByLatLng`

根据经纬度查询最近机场和同城市机场。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `lat` | string | 是 | 纬度，如 `31.2304` |
| `lng` | string | 是 | 经度，如 `121.4737` |

返回 `airport` 最近机场和 `nearAirport` 同城市机场列表。

只在用户主动提供经纬度或明确授权使用位置时调用。用户已经给出机场名称或代码时，优先使用 `searchAirport` 或直接查询机场信息。

## 机场服务流程

1. 用户已给机场三字码时，直接调用 `getAirportInfoByCode`。
2. 用户给机场名或城市名时，先调用 `searchAirport`。
3. 一个城市对应多个机场且意图不明确时，列出候选机场名称和代码并追问，不替用户选择。
4. 根据用户问题只读取相关模块。电话读 `telList`，交通读 `traffic`，设施和流程读 `serviceList`，不要一次倾倒全部结果。
5. `serviceList` 的 Markdown 正文按原有层级展示；加密内容地址只能原样使用，不自行拼接。

## 航司服务流程

1. 用户已给航司二字码时，调用 `getAirlineInfoByCode`。
2. 用户从某个航班继续询问“这个航司”时，可使用当前结构化上下文中已经返回的航司二字码。
3. 无可靠代码时追问，不凭模型常识猜测。
4. 根据问题只返回最相关服务项；明确区分机场规则与航司规则。

## 异常和缺失处理

- Tool 没有返回某项服务时，说明“本次 MCP 返回中未提供该项信息”，不要断言服务不存在。
- 电话、营业时间、价格、预约入口、资格条件或退改规则缺失时，不使用通用经验补齐。
- `tel` 为空时说明当前数据未提供联系电话。
- Tool 调用失败时说明查询暂时失败并建议稍后重试，不用模型常识伪装成接口结果。
- 返回内容可能有时效性，联系方式和规则均以本次 MCP 返回为准。

## 回复要求

- 先直接回答用户所问的服务，再补充必要的机场或航司名称与代码。
- 内容较长时按服务分类分段，只展示当前问题相关部分。
- 区分“接口未返回”和“服务不存在”。
- 不展示内部 Tool 名、MCP Key、请求头、完整原始 JSON 或技术错误堆栈。
