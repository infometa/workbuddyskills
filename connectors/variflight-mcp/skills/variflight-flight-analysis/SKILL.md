# 飞常准航班分析

## 能力边界

- 基于 MCP 实际返回的航班动态、历史、前序、机场、天气、流控和队列信号分析航班风险。
- `flightAnalyze` 是风险分析主 Tool；`getFlightStatus` 用于确认航班四要素和当前事实。
- 分析结果是运行风险判断，不是航司、机场或空管的确认结论。
- 已发生的延误、起飞、到达或取消优先按事实回答，不继续把事实表述为预测风险。
- 不使用卡片、H5、订单、支付或外部机票搜索 Tool。本 Connector 返回的价格和售罄状态只代表本次查询，不是可订库存、可改签资格或出票承诺。

需要解释风险等级、生命周期和预计起飞区间时，读取 `references/flight-analysis-rules.md`。该文件是本 Skill 的分析口径，不替代 MCP 取数。

## 鉴权

出现未授权或 401 时，提示用户在 Connector 设置中更新 C 端用户 MCP Key；不要在对话中索要或展示完整 Key。个人行程只查询该 Key 绑定的当前用户。

## 可用 Tool

### `queryUserFutureTrip`

查询当前用户未来或正在进行中的行程。用户说“分析我下一趟航班”但未给航班号时使用。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `identityType` | integer | 否 | 默认 `0` 乘机人；`1` 接机、`2` 送机、`3` 机组、`99` 仅关注 |

身份由 MCP 鉴权上下文确定，不追问内部 `uid`。

返回航班号、起降机场、出发日期、起降时间戳和飞行距离等当前用户行程列表。

### `searchAirport`

把城市或机场名称转换为标准代码。`name` 必填；`region` 可选为 `CN` 或 `INT`。返回 `kind=collection` 和 `items[]`，每项通过 `type=city` 或 `type=airport` 区分；`code` 是当前结果三字码，`cityCode` 是机场所属城市三字码。分析具体航班时使用机场代码；调用逐航班机票 Tool 时使用城市代码。

### `getFlightStatus`

查询航班当前事实和完整动态详情。

调用组合：

- 航班号查询：`fnum + date`，已知具体航段时同时传 `dep + arr`。
- 航线详情查询：`dep + arr + date`。同城多机场时按 MCP 描述拼接机场代码，一次调用。

返回始终为完整动态详情列表，包含当前状态、计划/预计/实际时间和可用的运行详情。使用 `fnum + date + dep + arr` 识别目标航段。

### `flightAnalyze`

对一个确定航段执行规则分析。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `fnum` | string | 是 | 航班号 |
| `date` | string | 是 | 航班日期，`yyyy-MM-dd` |
| `dep` | string | 是 | 起飞机场三字码 |
| `arr` | string | 是 | 到达机场三字码 |

主要返回：

- `status`：分析执行状态。
- `inputCompleteness`：输入数据块完整性和缺失项。
- `rawResult`：规则层完整结果，包括风险信号、队列、区间和分析输入。
- `analysis`：预计起飞点、预计起飞区间、风险和突破候选等常用摘要。

### `getFlightList`

用户明确要求比较或寻找同航线候选航班时，按 `dep + arr + date` 查询摘要列表。返回航班号、航司、计划/预计/实际时间、基础状态和航站楼等列表级信息。不要用于航班号直查，也不要把摘要字段冒充完整风险分析。

### `getRouteFlightTickets`

用户需要比较指定日期同一航线候选航班的价格或售罄状态时使用。`dep`、`arr` 必须是城市三字码，`date` 使用 `yyyy-MM-dd`。返回逐航班的 `fnum + date + dep + arr`、计划时间、航司、机型、`FPrice`、`EPrice`、`minPrice` 和 `soldStatus`。

在售记录的 `soldStatus=0`，售罄记录为 `1`。返回顺序不代表价格排序；比较可售最低价时只使用 `soldStatus=0` 且 `minPrice` 有效的记录。该 Tool 不查询日期范围或往返组合。

用户已明确具体机场时，先用 `searchAirport` 取得机场所属城市代码发起查询，再按返回的实际机场 `dep`、`arr` 筛选。后续与动态、详情或风险结果关联时必须使用 `fnum + date + dep + arr`。

### `getFlightTicketPrice`

仅在用户询问单程日期范围、低价日期参考或往返价格时使用。`dep`、`arr`、`type` 必填；`depDateBegin`、`depDateEnd` 用于单程日期范围，往返使用 `type=2` 并提供 `arrDate`。返回 `EPrice`、`FPrice`、`minPrice` 及 `flightList` 或 `detailList`。价格从明天开始，不代表库存或可改签资格。指定单日逐航班比较价格时使用 `getRouteFlightTickets`。

## 主流程

1. 确定目标航班。用户给航班号时补齐明确日期；相对日期转换成 `yyyy-MM-dd`。用户只说“我的下一趟”时先调用 `queryUserFutureTrip`。
2. 调用 `getFlightStatus` 获取目标航段并确认 `fnum + date + dep + arr`。多航段无法判断时，列出航段后让用户选择。
3. 对唯一目标使用四要素调用一次 `flightAnalyze`。
4. 先判断生命周期和事实状态，再解释风险。实际时间和已确认状态优先于预计时间和风险字段。
5. 只解释 Tool 实际返回的信号；输入缺失进入不确定性说明，不按正常或零风险处理。
6. 当日未起飞航班可以解释 Tool 返回的预计起飞区间；远期、已起飞或已取消航班不生成新的起飞区间。
7. 输出“结论、主要依据、不确定性、建议关注节点”。不要倾倒 `rawResult` 全量 JSON。

## 替代航班流程

只有用户明确提出“其他航班”“替代方案”“换一班”“比较同航线”时才进入：

1. 复用当前航班的 `dep + arr + date` 调用一次 `getFlightList`。
2. 需要比较准点率、取消率、平均延误、机型等详情时，再复用同一组 `dep + arr + date` 调用一次 `getFlightStatus`；用四要素关联，不逐航班重复调用。
3. 优先排除已经取消、已经起飞或明显不符合用户时间条件的候选。
4. 用户要求比较风险时，只对最终少量候选分别调用 `flightAnalyze`；不得把未分析候选说成低风险。
5. 用户同时询问该日期各候选航班的价格或售罄状态时，通过 `searchAirport` 将起降机场归并为对应城市代码，调用一次 `getRouteFlightTickets`；使用四要素与动态候选关联，不依赖数组顺序。
6. 用户改为询问日期范围、低价日期或往返组合时，才调用 `getFlightTicketPrice`。任何价格结果都不是可订、可改签或同舱位保证。

## 回复要求

- 风险等级只能使用 Tool 返回或规则文件允许解释的等级，不能从模糊文案自行映射。
- 延误事实与延误风险分开；取消事实与取消风险分开。
- 平均延误时长不等于延误率。
- 缺失值不按 `0`、无风险或否定值处理。
- 使用绝对日期，跨日预计区间必须带日期。
- 不展示内部 Tool 名、MCP Key、完整原始 JSON 或技术错误堆栈。
