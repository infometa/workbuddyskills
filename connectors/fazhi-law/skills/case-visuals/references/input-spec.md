## §1 输入参数定义

### 1.1 必填参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `content` | string | 用户提供的原始内容。支持自然语言、结构化数据、上游技能输出等多种格式 |

### 1.2 可选参数

| 参数 | 类型 | 默认值 | 取值范围 | 说明 |
|------|------|--------|----------|------|
| `goal` | string | 自动推断 | 自由文本 | 想表达的重点，如"突出履约延误""展示股权关系""梳理审批步骤" |
| `preferred_chart` | enum | auto | auto / timeline / relation / evidence / flow / dispute / matrix / data_table | 图表类型偏好 |
| `audience` | enum | 通用 | 法官 / 客户 / 内部团队 / 领导汇报 / 通用 | 目标受众，影响标题措辞和详细程度 |
| `style` | enum | 正式 | 正式 / 商务 / 法律 / 极简 / 科技 / 演示 | 视觉风格偏好，影响配色方案 |
| `detail_level` | enum | 标准 | 简略 / 标准 / 详细 | 节点详细程度 |
| `output_format` | enum | mermaid | mermaid / markdown / json | 输出格式 |

### 1.3 参数交互规则

- `preferred_chart=auto` + `goal` 明确：根据 goal 推断最适合的图表类型
- `preferred_chart` 指定 + `goal` 明确：使用指定类型，goal 仅影响内容编排侧重
- `audience=法官`：标题使用正式措辞，节点精简，标注证据来源，matrix 表格精简为4列
- `audience=客户`：可适当增加解释性文字，使用商务风格，data_table 增加计算说明
- `audience=内部团队`：matrix 展开三级细节，data_table 标注版本号和数据来源
- `audience=对方当事人`：matrix 选择性呈现，突出我方优势证据
- `style=演示`：配色更鲜明，节点更大，适合大屏展示
- `detail_level=简略`：仅保留核心节点，适合概览
- `detail_level=详细`：保留所有事件/节点，附完整标注，matrix 包含全部抗辩角度

## §2 输入格式支持

### 2.1 自然语言输入

最常见的输入形式，用户以自然语言描述事实或需求。

```
2023年1月签约，2月支付首付款，4月乙方延期交付，6月双方协商未果，7月发律师函，9月起诉。
```

### 2.2 结构化列表输入

用户以列表形式提供事件/节点。

```
- 2023-01-15 签订买卖合同（材料A第3页）
- 2023-02-20 支付首付款50万元（材料A第8页）
- 2023-04-01 乙方应交付货物，但未交付
- 2023-06-15 双方协商未果
```

### 2.3 上游技能输出

消费上游技能（如 civil-fact-multisource、civil-fact-strategy）的结构化输出。自动识别JSON结构中的事件、主体、关系字段。

### 2.4 混合输入

同时包含事实描述和参数指令：

```
甲公司由张三控股，甲公司与乙公司签订买卖合同。请生成关系图，风格商务，受众客户。
```

## §3 触发机制

### 3.1 显式触发

用户直接使用技能名称或明确指令：

- "用诉讼可视化技能生成..."
- "帮我画一个案情图"
- "生成时间轴图/关系图/流程图"

### 3.2 口语化触发词

用户描述中包含以下关键词时，建议触发本技能：

| 触发场景 | 关键词示例 |
|----------|-----------|
| 时间梳理 | "时间轴""时间线""时间节点""梳理经过""发展过程" |
| 关系展示 | "关系图""结构图""股权""控股""关联公司""交易结构" |
| 证据梳理 | "证据图""证明链""证据关联""证据清单" |
| 流程展示 | "流程图""步骤""审批""办理""程序" |
| 争议分析 | "争议点""争点""矛盾""冲突点""争议链路" |
| 攻防策略 | "攻防""策略矩阵""质证预案""庭审准备" |

| 图表请求 | "画图""图表""可视化""图解""展示" |

## §4 多时间轴分类规则

当时间轴包含多个主体或多个主题时，支持按以下方式拆分为多时间轴：

### 4.1 按角色分

不同角色的事件分别展示在不同时间轴上，便于对比。

适用场景：多主体交易过程、多方履约对比

```
时间轴一（甲方视角）：签约 → 付款 → 催告 → 起诉
时间轴二（乙方视角）：签约 → 收款 → 延期交付 → 收到律师函
```

### 4.2 按阶段分

按事件所处阶段分组，每个阶段一个时间轴。

适用场景：案件发展历程、项目阶段性总结

```
阶段一（合同签订）：签约 → 备案 → 生效
阶段二（合同履行）：交付 → 付款 → 验收
阶段三（争议处理）：协商 → 律师函 → 诉讼
```

### 4.3 按主题分

按不同主题或事实链条分组。

适用场景：复杂案件多争议焦点

```
主题一（合同效力）：签约 → 要约 → 承诺 → 生效
主题二（违约事实）：应交付 → 未交付 → 催告 → 确认违约
```

### 4.4 拆分判断规则

- 事件总数 ≤ 12：单时间轴
- 事件总数 13-20：建议按角色或阶段拆分
- 事件总数 > 20：必须拆分，每个子图 ≤ 12 事件
- 多主体各自独立事件链：建议按角色拆分

## §5 证据坐标格式

证据锚点使用标准化坐标格式，便于追溯原文。

### 5.1 坐标格式

```
{材料ID}/{页码}/{段落号}
```

- **材料ID**：材料编号（如 材料A、证据1、卷宗P1）
- **页码**：页码数字
- **段落号**：段落序号（从1开始），如有多段落用逗号分隔

### 5.2 示例

```
材料A/3/2      → 材料A第3页第2段
证据1/12/1,3   → 证据1第12页第1段和第3段
卷宗P1/5/1     → 卷宗P1第5页第1段
```

### 5.3 可信度标注

在证据坐标后附加可信度标记：

| 标记 | 含义 | 说明 |
|------|------|------|
| 📄 | 原件 | 原始文件，证明力最强 |
| 📑 | 复印件 | 复制文件，需核对原件 |
| 💾 | 电子数据 | 电子形式，需审查完整性 |
| ⚠️ | 待确认 | 证据形式或来源待核实 |

### 5.4 标注示例

```
2023-01-15 签订买卖合同 [📄材料A/3/2]
2023-04-01 乙方应交付但未交付 [⚠️材料A/8/1]
2023-06-15 双方协商记录 [💾材料C/1-3/1]
```

## §6 时间精度标注体系

### 6.1 五级精度

| 级别 | 标记 | 格式 | 说明 |
|------|------|------|------|
| 精确 | ✅ | YYYY-MM-DD | 有确切日期记录 |
| 近似 | 📅 | YYYY-MM约 | 有月份但无确切日期 |
| 模糊 | 🌫️ | YYYY年X月左右 | 时间表述含模糊修饰 |
| 期间 | 📏 | YYYY-MM ~ YYYY-MM | 时间区间 |
| 未知 | ❓ | （待确认） | 无法确定时间 |

### 6.2 标注规则

- 有确切日期的文件（合同、判决书等）→ 精确 ✅
- 当事人回忆、证人陈述中的时间 → 近似 📅 或 模糊 🌫️
- 法定期限、合同约定的期间 → 期间 📏
- 仅有逻辑推断的时间 → 未知 ❓

### 6.3 标注示例

```
✅ 2023-01-15 签订合同
📅 2023-02月约 支付首付款
🌫️ 2023年4月左右 乙方延迟交付
📏 2023-06-15 ~ 2023-07-20 协商阶段
❓ 甲方实际收到催告函 （待确认）
```
