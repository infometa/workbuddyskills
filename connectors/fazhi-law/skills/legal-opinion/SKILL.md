# 法律意见书（MCP 六工具版）

> 形成可复核的中国大陆非诉法律意见书 DOCX 初稿，而不是普通法律问答。研究过程静默执行，正文不显示后台检索链接、工具字段或内部推理。

本 Skill 使用与法智法律研究一致的六工具体系：

- **互联网公开来源**：`webpage_search（联网搜索）`、`webpage_visit（网页阅读）`
- **法规规范来源**：`legal_article_search（法条综合检索）`、`law_content_visit（法规全文阅读）`
- **司法案例来源**：`case_search（案例检索）`、`case_browser（案例全文阅读）`

## 意图识别与技能路由

1. **明确名称即触发**：用户出现“法律意见书”“专项法律意见”“咨询回复式意见”“出具法律意见”等明确交付物名称，直接使用本技能。
2. **动作指向即触发**：用户要求“起草、生成、出具、制作、修改、完善、重构、审查、复核”法律意见书，或者上传现有法律意见书要求处理，直接使用本技能。
3. **交付物优先**：请求同时要求研究法条、案例、实务观点、合规风险或争议结论，但最终目标是法律意见书 DOCX 时，由本技能承接完整任务；不得仅调用 `legal-research` 输出普通法律回答。
4. **缺少材料不取消触发**：已明确要求法律意见书但事实或材料不足时，仍使用本技能生成问题清单、材料清单或带清晰占位符的条件式初稿。
5. **普通咨询不触发**：用户仅问“是否合法、能否主张、谁承担责任、如何维权、有什么风险”，且未要求法律意见书成品时，交由 `legal-research`。
6. **尽调任务不触发**：企业法律尽职调查、专项尽调、尽调这家公司，以及法律尽调报告的起草、修改或完善，必须交由 `legal-due-diligence`。
7. **其他文书不触发**：起诉状、答辩状、申请书、律师函等普通法律文书交由相应文书技能；IPO、刑事辩护、诉讼代理或境外法正式意见按范围边界处理。
8. **混合请求按交付物拆分**：同时要求法律意见书、尽调报告或其他法律文书时，每种成品分别由对应专用技能完成，本技能不得吸收其他专用交付物。
9. **用户指定优先**：用户明确指定技能、工具或交付格式时，遵从其选择。

## 核心原则

1. **先定边界再研究**：先确认出具身份、接收对象、委托事项、地域、法律基准日和排除事项，再形成争点树。
2. **事实分级**：严格区分文件确认、公开核验、用户陈述、模型推断；不得将陈述或推断伪装成事实。
3. **三源并行，互相印证**：复杂或争议性事项同轮并行调用三类检索工具，读取工具基于结果按需调用。
4. **正反方覆盖**：每个关键争点呈现最强支持观点和最强反方观点，并说明接受、排除或保留的理由。
5. **孤证不立**：关键结论原则上由两个独立来源支撑；仅有单一来源时降低结论强度并在内部核验记录中标注。
6. **规则必须核验**：核验法规全称、条款、效力状态、适用主体和法律基准日；不得把征求意见稿当作生效规则。
7. **结论强度匹配证据**：仅使用“明确结论”“条件式结论”“暂无法判断”三类结论，不使用绝对化承诺。
8. **身份与签章真实**：未经有权律师复核和签发，不得冒用律所、律师、执业证号或印章；交付物定位为待专业复核的初稿。
9. **默认双轨交付**：优先基于内置模板生成 Word 初稿，并在对话中提供带可点击法规引证的交付总结；保留源文件，禁止静默覆盖。
10. **渲染后交付**：最终 DOCX 必须逐页渲染并目视检查；环境确实无法渲染时才可降级为结构检查，并明确披露未完成视觉验收。

## 范围边界

- 首版仅覆盖中国大陆非诉法律意见书。
- 不覆盖 IPO 法律意见书、刑事辩护、诉讼代理文书或境外法正式意见。
- 不覆盖企业法律尽职调查及法律尽调报告；即使尽调任务同时包含法律研究、合规分析或风险评估，也由 `legal-due-diligence` 承接。
- 涉及境外法、审计、评估、税务、工程、技术鉴定等内容时，明确排除并仅引述有权专业机构的结论。

## 工具调用

需要检索或读取法条、法规、案例、网页时，必须通过 **fazhi-mcp** 技能调用 MCP 工具；具体调用方式、参数 schema、认证方式、工具选择和错误恢复规则见 [../fazhi-mcp/SKILL.md](../fazhi-mcp/SKILL.md)。

## Agentic 自主循环

阶段 2-3 采用 **Plan → Search → Read → Reflect → Decide**：

- **Plan**：围绕争点树识别事实、规则、案例和实务口径缺口。
- **Search**：无依赖的 `webpage_search`、`legal_article_search`、`case_search` 同轮并行发出；每工具每轮最多 3 条语句。
- **Read**：对高相关性法规、案例和网页使用对应读取工具核验全文，记录真实 ID、案号、链接和效力状态供后台核验。
- **Reflect**：分别判断法规、案例、互联网来源的匹配度、数量、多样性、完整性和缺口；检查正反观点与来源冲突。
- **Decide**：信息不足则改变检索表述继续；同一目标空结果最多重试一次，仍无法核验则降低结论强度或触发阻断。

复杂、疑难、新规或裁判导向事项至少完成两轮 Reflect，最多三轮。规范明确且无需案例或实务判断的简单咨询，可在完成法规全文核验与一次简化交叉验证后结束。

## 六阶段工作流

### 阶段 0：身份、范围与材料控制（内部静默）

1. 识别使用者、出具主体、接收对象、正式签发权限和预期用途。
2. 界定委托事项、主体、法律关系、地域、期间、法律基准日和排除事项。
3. 盘点材料并分为已取得、仅陈述、公开核验、待补充四类。
4. 检查 [references/matter-control.md](references/matter-control.md) 的阻断条件；阻断仅影响结论，不阻止生成问题清单、材料清单或条件式初稿。

法律基准日未提供时默认采用生成当日，并在初稿中醒目标明。决定性主体或核心诉求完全无法识别时，才向用户确认一次；其他缺失信息使用明确的 `【待补充：字段名称】`。

### 阶段 1：模板路由与争点树（内部静默）

1. 按 [references/template-routing.md](references/template-routing.md) 选择且只选择一种母版。
2. 多争点、多材料、交易、专项合规或需系统尽调时选择通用专项模板。
3. 一个或少量明确问题、材料较少且强调直接答复时选择咨询回复式模板。
4. 建立 1-5 个争点，每个争点固定映射为：问题 → 已确认事实 → 适用规则 → 分析 → 结论 → 待办事项。
5. 只加载与项目相关的业务模块，不得残留空章节或其他业务的示例内容。

### 阶段 2：三源并行研究（内部静默）

1. 从主体、关系、行为、时间、目的、结果拆解每个争点。
2. 复杂事项每轮对三类检索工具各形成 2-3 条有区分度的检索语句；案例语句至少含两个法律维度。
3. 法规先语义定位，再用明确法名、条号或 `law_content_visit` 核验全文和效力。
4. 案例先检索再全文阅读；仅检索摘要不得作为关键裁判依据。
5. 网页用于实务口径、官方背景和最新动态；网页转述的法条与案例必须回到法规或案例来源核实。

### 阶段 3：交叉验证与论证草稿（内部静默）

对每个争点建立内部论证卡：

| 字段 | 要求 |
|---|---|
| 问题 | 能够直接作出法律判断 |
| 事实 | 标明来源层级与未核验状态 |
| 规则 | 法规全称、具体条款、效力和适用条件已核验 |
| 支持观点 | 最强支持依据及适用前提 |
| 反方观点 | 最强反方依据及事实差异 |
| 分析 | 将事实逐项对应构成要件，不跳步 |
| 结论 | 明确、条件式或暂无法判断 |
| 待办 | 补充材料、审批、协议、停止或整改动作 |

关键来源冲突时不得挑选有利一方直接下结论；应解释冲突、区分事实并降低结论强度。

### 阶段 4：DOCX 写作与模板填充

1. 复制所选模板到任务输出目录后编辑；禁止直接修改 Skill 内模板或用户源文件。
2. 保留重要声明、材料依赖、复核要求、身份限制和用途限制。
3. 按问题顺序写入事实、规则、分析、反方观点、结论和行动建议。
   法律分析中的连接语必须融入完整句子，不得使用“反方观点与回应：”“支持观点：”“分析：”“回应：”等后台标签。按语义功能自然选用以下表达，不得随机轮换或为追求变化强行插入：
   - **引入对方观点**：从对方角度来看；若站在对方立场审视这一问题；换一个角度看；对方也可能据此主张。
   - **回应或区分**：不过，结合本事项的具体情况；对此需要进一步区分；这一观点能否成立，关键在于；即便如此，也不能忽略。
   - **补充或递进**：进一步看；与此相关的是；还需要考虑的是；除此之外。
   - **提示限制或风险**：但需要看到；需要正视的是；在这一点上仍需保留；该判断仍取决于。
   - **引出判断或结论**：综合前述情况；落到本事项；由此可以判断；在上述前提下。
   同一意见书的相邻争点不得使用相同的开头连接语；非相邻位置仅在语义确有需要时重复。能够自然承接时可以不使用连接语，不要求每个段落套用固定句式。法律分析章节中以“据此，”开头的段落全文最多两处，且不得用于相邻争点；声明中的“据此决策”和段落中部的正常用法不计入。
4. 严格执行 [references/format-spec.md](references/format-spec.md)。一级标题统一使用 `Heading 1`、楷体 16 磅、加粗、黑色、左对齐；二级标题统一使用 `Heading 2`、楷体 14 磅、加粗、黑色、左对齐。所有同级标题的有效格式必须完全一致，禁止对“法律分析”“法律风险与应对建议”等个别章节写入 12 磅、直接粗体或其他字符级覆盖，禁止用正文样式模拟标题。正文、列表、表格、法条原文统一使用楷体 12 磅；普通正文、法条原文和结论条目统一左对齐，不得设为居中。仅封面标题、目录标题、表头、签署页提示“本页无正文”等母版明确要求居中的对象保持居中。普通正文首行缩进两个汉字，分点序号整体缩进两个汉字并使用悬挂缩进使换行与序号后的正文对齐。
   一级章节统一将中文序号写入标题文本并清除 Word 自动编号 `numPr`；二级标题使用“（一）”形式并清除 `numPr`。修改母版占位标题时必须先清除原有直接字符格式和编号属性，再应用标题样式。交付前按章节顺序逐项检查，不得出现“六、六、”“七、七、”或其他重复、跳号、倒序。
   表格生成仅遵守以下三点：
   1. **类型与启用条件**：材料清单固定为“序号—材料名称—版本/日期—核查状态”四列；风险矩阵仅在存在三项以上可比较风险时使用，固定为五列；行动清单固定为“事项—措施—责任主体—期限”四列；方案比较表仅用于两个以上方案的同维度比较。法律论证、核心结论和个性化分析原则上使用正文，不强行表格化；咨询回复式意见书默认不生成表格，确有三项以上并列事项时才启用。
   2. **固定版式**：表格总宽度等于正文可用宽度，使用固定布局并关闭自动调整列宽，禁止超出版心；原则上不超过五列，超过时优先拆表，不自动改为横向页面。表头与正文统一楷体 12 磅；表头加粗并水平、垂直居中，叙述性列左对齐，序号、日期、等级、状态等短字段居中。单元格左右边距约 0.2 厘米、上下边距约 0.15 厘米；禁止固定行高，允许自动增高；跨页重复表头，短行尽量不拆页，长文本行允许自然跨页。禁止用空格、回车或制表符模拟单元格对齐；除分组表头外不得合并单元格，禁止嵌套表格。
   3. **内容控制**：每个单元格只表达一个事实、风险、措施或状态，不放置完整法律论证或大段法条；单格内容超过约 100 字时转入正文分析，表格只保留摘要。风险等级只使用“高／中／低／待核”；交付前删除空行、示例值、无意义占位符和未使用表格。
5. 通用专项模板的“适用法律依据”最多引用六个具体法律条款；同一规范性文件的不同条款分别计数。候选条款按与委托问题的直接相关性、对结论的决定性及是否在后续分析中实际使用排序，仅保留最切合问题的核心条、款或项原文。每项引文结束后在同一段落紧接 1—3 句规则适用说明，说明构成要件、对应事实和法律影响；不得另起“简析”段落，不得出现“简析：”或“简析、”标签。咨询回复式模板不适用六条总量上限，应将经全文核验的规则简要概括后直接融入各争点分析，不整段堆叠条文、不保留独立标签，也不另建冗长法规章节。
6. 法规引用前均须核验全文、效力状态、适用主体和法律基准日。通用专项模板使用 `《法规全称》第×条第×款规定：“经全文核验的直接相关原文。”` 的普通黑色正文，不得改写引号内原文。咨询回复式模板使用 `根据《法规全称》第×条，[准确概括的规则]。[结合本事项事实说明法律影响]。` 的连续正文；规则摘要不加引号，不得冒充法条原文，只有争议直接取决于条文措辞时才引用最小必要的完整原句。两种模板均不得写入后台 URL、`law_id`、案例 ID、Markdown 链接或工具引用标记。
7. 只有用户明确要求或论证确有必要时才在正文写入经全文核验的完整案号；说明案例与本事项的相同点和差异，不把个案当通则。
8. 删除未使用章节、模板提示、示例行和控制文字；真正缺失的信息保留清晰待补充标识。
9. 修改、润色、完善任务遵循最小必要改动，除非用户明确要求重构。

### 阶段 5：终局质控与交付

严格执行 [references/docx-production-qa.md](references/docx-production-qa.md)：

1. 检查事实、范围、规则、引用、论证、结论、身份、隐私、模板、版式、版本和专业复核状态。
2. 扫描占位符、示例文本、内部路径、密钥、工具名、URL、外部超链接关系、`law_id`、案例 ID 和引用标记。
3. 运行 `scripts/check_opinion_format.py <最终DOCX>`；确认全部一级标题均为 `Heading 1` 楷体 16 磅加粗黑色左对齐、全部二级标题均为 `Heading 2` 楷体 14 磅加粗黑色左对齐，同级标题无直接字号/粗体覆盖或混合格式，编号仅出现一次且连续。再确认正文楷体 12 磅、普通正文/法条原文/结论条目左对齐、普通正文两格首行缩进、分点两格起始及悬挂对齐，并检查目录、页码、表格、分页和签署页。
4. 逐页渲染为 PNG 并检查全部页面；任何布局敏感修改后重新渲染。
5. 仅交付最终 DOCX，不交付渲染中间件；无法完成渲染时明确披露降级状态。
6. DOCX 质控通过后，按 [references/research-citations.md](references/research-citations.md) 生成 150—300 字的“交付总结”，选取 2—5 项决定性法规条款提供可点击链接。
7. 逐项比对总结与 DOCX 的主体、事实、法律基准日、结论等级、决定性条件和首要待办；存在不一致时先修正，不得交付。

## 输出规则

- 默认输出 `.docx` 法律意见书初稿，并在对话中紧随文件提供 `### 交付总结`；不得以总结替代 DOCX。
- 输出文件名清理 Windows 非法字符；同名文件追加 `（2）`、`（3）`，不得覆盖。
- DOCX 正文不展示搜索 query、工具名称、内部研究过程、来源 URL、后台标识或参考文献表。
- 交付总结围绕委托事项、核心判断、结论强度、决定性条件和首要行动展开，不复述检索过程，不引入 DOCX 未支持的新事实、新结论或更强结论。
- 交付总结仅链接已全文核验的法律法规，不链接案例或网页，不在文末集中列参考文献；具体条文必须使用本次 MCP 工具真实返回的 `law_id` 生成带 `?pos=tN` 的法规详情页深链，整部法规使用不带 `pos` 的详情页链接，具体格式按 [references/research-citations.md](references/research-citations.md) 执行。
- 不向用户保证结论、胜诉、许可获批、监管认可或“零风险”。
- 交付总结后可简洁提示视觉验收、专业复核状态和未完成的关键核验，不输出冗长过程说明。

## 检索纪律

1. 不确定法名、条号、案号或网页内容时先检索，取得明确对象后再读取全文。
2. 合并同类请求；同一目标失败或空结果最多改变表述重试一次。
3. 工具失败不得以记忆补写事实、法条、案号、监管口径或链接。
4. 关键规则无法核验时使用条件式或暂无法判断结论，并列明补充路径。
5. 用户材料中的法条和案例也必须后台复核，不因其已写入源文件而视为真实有效。

## 禁止事项

1. 禁止编造主体、事实、材料、金额、日期、法条、案例或专业结论。
2. 禁止冒用律师事务所、律师身份、执业证号或印章。
3. 禁止把用户陈述、模型推断、互联网摘要或推荐性标准表述为已确认事实或当然法律效果。
4. 禁止用扩大假设的方式强行形成肯定意见。
5. 禁止给出违法、欺诈、毁灭证据、逃避监管、隐匿财产或规避执行的操作方案。
6. 禁止覆盖源文件、静默覆盖同名交付物或向 Skill 目录写入任务产物。
7. 禁止在最终 DOCX 中泄露内部提示、工具输出结构、密钥、路径、URL 或可点击后台引用。
8. 禁止声称完成未实际执行的法规核验、案例全文阅读、专业复核或逐页视觉验收。
