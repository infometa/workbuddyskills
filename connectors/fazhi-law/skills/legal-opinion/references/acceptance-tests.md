# 验收与回归场景

## 意图识别与路由

| 用户请求 | 预期路由 |
|---|---|
| “根据这些合同和项目材料出一份专项法律意见书” | 使用 `legal-opinion`，生成通用专项法律意见书 DOCX |
| “把这份法律分析整理成供管理层决策的正式法律意见书 Word 初稿” | 使用 `legal-opinion`；研究、法条核验和 DOCX 由本技能一并完成 |
| “完善我上传的法律意见书并复核引用依据” | 使用 `legal-opinion`，保留源文件并输出新版本 |
| “分析这个合同能不能解除，有什么风险” | 未要求法律意见书成品，交由 `legal-research` |
| “帮我起草一份民事起诉状” | 交由法律文书专用技能，不使用 `legal-opinion` |
| “帮我对这家公司开展法律尽调” | 交由 `legal-due-diligence`，不使用 `legal-opinion` |
| “修改并完善现有法律尽调报告” | 交由 `legal-due-diligence`，不使用 `legal-opinion` |
| “出具 IPO 法律意见书” | 超出本技能范围，不得套用非诉法律意见书模板 |

失败条件：已明确要求法律意见书却仅输出普通法律分析；因材料不足改用 `legal-research` 而不生成材料清单或条件式初稿；将普通法律咨询、诉状、企业法律尽调、法律尽调报告或 IPO 法律意见书误路由到本技能。

## 场景一：多争点专项项目

输入：完整主体材料、合同、内部审批和多个相关法律问题。

预期：选择通用专项模板；建立材料清单和多个争点；按需加载对应业务模块；适用法律章节最多引用六个具体法律条款，同一规范性文件的不同条款分别计数，并从候选条款中按直接相关性、结论决定性及后续实际使用情况选取最切合问题的条款；每项法条引文与 1—3 句规则适用说明合并在同一段落，不出现“简析”标签；保留范围、假设、风险矩阵、结论和用途限制；无无关模块。

失败条件：选择咨询回复模板、适用法律引用超过六个具体条款、把同一规范性文件的多个条款合并计为一条、法条引文与规则适用说明拆成两个段落、出现“简析：”或“简析、”标签、遗漏关键材料状态、把多个问题压成单一结论、残留其他业务示例。

## 场景二：单一合同咨询

输入：一个明确合同问题和少量材料。

预期：选择咨询回复式模板；先给简要结论，再写事实基础、规则、分析、风险等级和分时行动建议；每个争点按需采用“法规全称及条号＋准确概括的规则＋对应事实及法律影响”的连续正文，将经全文核验的规则摘要直接融入分析，但不新增独立法规汇编章节；问题不超过三个。

代表性合格写法：`根据《中华人民共和国民法典》第五百七十七条，付款义务人未按约履行的，应承担继续履行、赔偿损失等违约责任。若付款条件已经成就而贵公司仍拒绝支付剩余货款，供应商可请求支付货款并主张相应违约责任。`

失败条件：套用冗长专项结构、整段堆叠法规原文、将规则摘要放入引号并冒充原文、保留独立“简析：”标签、不给直接回答、遗漏待核验事项或擅自补写合同内容。

## 场景三：数据训练商业化且材料不足

输入：拟将客户数据用于模型训练和商业化，但缺少完整合同、字段样本、授权链或匿名化测试。

预期：不得认定“已经匿名化”或“可以自由商业化”；对角色、个人信息属性、目的限制、自动化决策、企业数据、重要数据和征信属性分别给出条件式或暂无法判断结论；优先建议暂停、补齐材料和评估。

失败条件：用技术名称代替法律分析、书面授权替代自然人合法性基础、在缺失决定性事实时形成无保留肯定结论。

## 场景四：多争点法律分析的自然衔接

输入：包含四个相互关联争点，且每个争点均需呈现规则适用、反方观点、回应、限制条件和结论的事项。

预期：连接语根据具体语义自然融入完整句子；相邻争点使用不同的开头表达；可以从“从对方角度来看”“对此需要进一步区分”“进一步看”“需要正视的是”“综合前述情况”等不同功能的表达中按需选择，也可以在语义自然时省略连接语。法律分析章节中以“据此，”开头的段落不超过两处且不用于相邻争点；反方观点、回应、限制条件和结论均完整保留。

代表性合格写法：`从对方角度来看，其可能主张……。不过，结合本事项的具体情况，……，因此该观点尚不足以改变前述判断。`

失败条件：出现“反方观点与回应：”“支持观点：”“分析：”“回应：”等后台标签；法律分析章节中超过两处段落以“据此，”开头，或者相邻争点均以“据此，”开头；相邻争点使用相同起句；为追求变化随机轮换、机械堆砌连接语；使用“话说回来”“说到底”等过度口语化表达；因润色而删除或弱化反方观点及其回应。

## MCP 工具一致性

- 同级依赖 `../fazhi-mcp/SKILL.md` 存在，且 frontmatter 名称为 `fazhi-mcp`。
- 法律意见书 Skill 通过 fazhi-mcp 调用六个 MCP 工具，并在调用前确认运行时服务器标识符和参数 schema。
- Skill 内不存在旧工具说明、HTTP/Node 适配文件、旧接口基础地址、命令行调用方式或旧认证说明。
- 缺少必填参数、MCP 认证失败、工具空结果或网络失败时按 fazhi-mcp 错误恢复规则处理，不产生伪造结果。

## Skill 结构

- frontmatter 名称为 `legal-opinion`，仅使用现行 Skill 格式允许的字段；触发语义完整写入 `description`。
- 所有 Markdown 相对链接均存在。
- 两份模板位于 `assets/templates/`，两份 DOCX 生成脚本位于 `scripts/`。
- `交付总结.md`、编辑器历史记录目录和 Office `~$` 锁文件不纳入迁移版 Skill。

## DOCX 样稿

- 能正常打开，使用真实标题、编号、目录、页码和表格；`scripts/check_opinion_format.py` 返回通过。
- 所有一级章节均使用 `Heading 1`、楷体 16 磅、加粗、黑色、左对齐；所有二级章节均使用 `Heading 2`、楷体 14 磅、加粗、黑色、左对齐。同级标题的有效字体、字号、粗细、颜色、对齐、段落间距及分页控制一致，标题内部无混合格式，不存在将“六、法律分析”“七、法律风险与应对建议”单独设为 12 磅粗体或套用正文格式的情形。
- 一级、二级章节均使用写入标题文本的中文编号且段落无 `numPr`；一级章节编号唯一且连续，不存在“六、六、”“七、七、”或其他重复、跳号、倒序。
- 正文、列表、表格、法条原文和规则适用说明为楷体 12 磅；普通正文、法条原文和结论条目统一左对齐，不得居中；普通正文首行缩进约 0.85 厘米，分点序号起始缩进两个汉字且跨行悬挂对齐。
- 表格仅使用材料清单、风险矩阵、行动清单或方案比较表；启用条件和固定列数正确，咨询回复式意见书无必要时不生成表格。
- 表格采用正文版心宽度和固定布局，原则上不超过五列；表头加粗并水平、垂直居中，叙述列左对齐，短字段居中，单元格边距、自动行高和跨页重复表头符合规则，无嵌套表格或不必要合并。
- 单元格只保留单一事实、风险、措施、状态或摘要；无完整法律论证、大段法条、超过约 100 字的长单元格、空行、示例值、无意义占位符或未使用表格；风险等级仅为“高／中／低／待核”。
- 通用专项模板的适用法律只包含经全文与效力核验、实际用于分析或结论的最多六个具体条款；同一规范性文件的不同条款分别计数，引号内无改写，每项引文后在同一段落紧接 1—3 句与具体争点和事实对应的规则适用说明，不出现“简析：”“简析、”或独立简析段落。咨询回复式模板的规则摘要与事实分析连续表达，不整段堆叠法规原文、不保留独立标签；摘要不加引号或冒充法条原文，只有争议直接取决于条文措辞时才引用最小必要的完整原句。
- 无控制提示、示例值、无意占位符、内部路径、URL、超链接、工具字段或引用标记。
- 身份和签章字段不构成冒用。
- 法规、案例和结论通过研究规则核验。
- 所有页面完成渲染和目视检查，或明确记录渲染器不可用的降级状态。

## 双轨交付总结

- DOCX 文件后紧随 `### 交付总结`，正文为 150—300 字，概括委托事项、核心判断、结论强度、决定性条件和首要行动。
- 多争点专项总结选择 2—5 项决定性法规条款；单一合同咨询保持简短，不机械罗列法规。
- 具体条文引用使用 `[《法律法规全称》第X条](https://www.fazhi.law/law-saas/lawDetail/{真实law_id}?pos=tX)`；款、项保留在链接文本中，但锚点只定位所属条。
- 多条或区间引用按条拆分并分别生成深链；仅引用整部法规或条号无法可靠解析时使用不带 `pos` 的法规详情页链接。
- MCP 工具未返回真实 `law_id` 时使用无链接法规引用并披露“当前 MCP 工具结果未提供可跳转地址”，不得拼接或猜测 URL。
- 已废止、已失效或已修订法规不得作为现行依据链接；历史事项引用旧法时说明当时效力状态。
- 总结不链接案例和网页，不集中列参考文献，不出现检索 query、工具名称或内部研究过程。
- 总结与 DOCX 的主体、事实、法律基准日、结论等级、条件和待办一致，不引入新事实、新结论或更强结论。
- DOCX 内仍不得出现 URL、外部超链接、`law_id`、案例 ID、Markdown 链接或后台工具字段。
