# 报告数据契约

本文件只约束最终 Word 报告的结构化输入。内部核查底稿可继续采用既有八章或模块模型，但进入生成器前必须完成本文件规定的映射。

## 一、元数据

`meta` 必须包含：

- `client_name`：委托方全称；
- `target_entity`：目标主体全称；
- `report_date`：报告日期；
- `cutoff_date`：报告基准日。

可选字段为 `target_short_name`、`report_short_title`、`report_no` 和 `engagement_type`。不得填写“示例”“待定”或虚构文号来占位；文号缺失时保持空字符串，生成器会隐藏文号行。

## 二、内部来源控制

`source_control` 为必填内部对象，不写入正式报告，字段如下：

- `primary_basis`：仅可为 `current_accepted_materials` 或 `public_information_pre_dd`；
- `primary_material_ids`：当前采信资料 ID 数组；`current_accepted_materials` 模式下必须非空，`public_information_pre_dd` 模式下必须为空；
- `external_verification_role`：固定为 `corroboration_only`；
- `brand_disclosure_required`：固定为 `true`；
- `conflicts`：内外部口径差异数组，可为空；其技术字段和查询细节不得直接写入正式报告。

存在尽调资料或底稿时必须使用 `current_accepted_materials`。只有未提供任何项目资料时，才允许使用 `public_information_pre_dd`；生成器将在报告函中加入公开信息 Pre-DD 范围限制。

## 三、固定内容块

按下列键向模板写入内容：

| 键 | 正式报告位置 |
|---|---|
| `report_letter` | 报告致送页/报告函 |
| `disclaimer` | 免责声明 |
| `basic` | 目标公司基本情况 |
| `history` | 历史沿革 |
| `ownership` | 股权结构、股东及实际控制人 |
| `governance` | 公司治理 |
| `business` | 业务、资质及重大合同 |
| `assets_ip` | 资产与知识产权 |
| `employment` | 劳动用工 |
| `compliance` | 税务、诉讼、处罚及合规 |
| `other_modules` | 其他实际启用模块 |
| `major_issues` | 重大问题及风险提示 |
| `pending_items` | 待核实事项 |
| `conclusion` | 结论与建议 |
| `attachments` | 附件或资料清单 |

普通内容块可用字符串、字符串数组，或由 `type` 和 `text` 组成的对象数组。`type` 仅可使用 `paragraph`、`no_indent`、`heading2`、`heading3`、`heading4` 或 `table`。不得提交空占位段；材料不足时应写明核验限制，并将具体缺口列入 `pending_items`。

正文段落引用有限外部检索事实时，必须使用对象形式并在 `paragraph` 或 `no_indent` 内容块中增加 `external_sources` 数组。每项来源必须包含：

- `source_name`：发布机构、媒体、平台或公司名称；
- `title`：页面或报道标题；
- `published_on`：发布日期；页面未载明时可为空，脚注据实显示“未载明”；
- `accessed_on`：访问日期，格式 `YYYY-MM-DD`；
- `url`：以 `http://` 或 `https://` 开头的原始页面地址。

生成器在段落末尾为数组中的每项来源插入连续编号的 Word 原生脚注，脚注在当页底部显示。不得将搜索摘要、内部查询记录或底稿编号写入 `external_sources`。重大问题引用外部检索事实时，可在该 `major_issues` 条目直接增加同结构的 `external_sources`，生成器将脚注附在“事实与证据状态”段落。表格不直接承载 `external_sources`；表中存在外部事实时，应另设带脚注的说明段落。

## 四、重大问题

`major_issues` 每项使用：`number`、`title`、`facts`、`evidence_status`、`risk`、`impact`、`recommendation`。问题编号采用 `DD-01` 起连续编号。风险只用“高”“中”“低”，但不得用颜色表达等级。每项必须同时包含事实与证据状态、风险及影响、建议处理路径。

## 五、待核实事项与附件

`pending_items` 每项使用 `priority`、`item`、`reason`、`related_issue`。`attachments` 每项使用 `number`、`name`、`source`、`status`。生成器会将两者转换为白底、黑字、黑框的原生 Word 表格。

## 六、签署信息

`signature.issuer` 为出具主体，`signature.date` 为签署日期。负责人和经办律师姓名未确定时保留签署横线，不得编造姓名。

完整字段范例见 `assets/report-data.example.json`。该文件只说明字段结构，任何正式报告不得直接复用其中内容。

正式报告内容块不得包含内部状态名 `EMPTY_RESULT`、`UNSUPPORTED`、`FAILED`、`INCOMPLETE`，也不得包含 MCP、discover、call、tool_id、查询日志、分页完整性、参数错误、权限错误、服务错误、快查接口或内部工作材料等内部技术信息。单独的业务术语“API”不受禁止，例如模型 API 合同。
