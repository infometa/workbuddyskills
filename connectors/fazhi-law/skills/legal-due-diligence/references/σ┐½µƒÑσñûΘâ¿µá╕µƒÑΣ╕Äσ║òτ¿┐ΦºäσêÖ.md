# 快查外部核查与底稿规则

## 快查 MCP 外部信息核查规范

本文件中的“快查 MCP”是指 [法智/快查共享 MCP](../../fazhi-mcp/SKILL.md) 中由 `discover`、`call` 提供的快查企业数据能力，不是另一套 Connector。接口发现、认证、主体消歧、标识优先级、参数 schema、分页和通用错误恢复统一以 `fazhi-mcp` 的规则为准；本文件只补充法律尽调场景下的证据控制、查询底稿、状态链和报告写入门槛。

本 skill 的自动外部企业信息查询以该共享 MCP 的快查企业数据能力为主要渠道。企业提供材料、经授权取得的主管机关材料、访谈记录和用户上传文件属于项目证据，不是自动外部查询。存在项目资料时，版本受控的当前采信资料库是正式报告的主信息源；快查及本文件限定的可信公开信息仅作一致性复核、补充公开线索和冲突发现。

除本文件“有限外部核查例外”明确允许的公司、核心人员、产品/业务、商标/品牌四类事项外，禁止使用环境 WebSearch、浏览器、搜索引擎、官网直查、研究/探索子代理自带的网络能力或其他企业数据库。快查对其他事项不覆盖、连接失败或权限不足时，记录为“外部核查受限”，转为资料催收或律师人工复核，不编造、不推断。

调用前先确认项目授权、账户认证、API/数据许可、报告再分发、缓存与留存边界。不得查询个人征信，也不得为取得个人信息绕过快查能力边界。内部底稿应记录数据来源及许可核验状态；正式报告只在报告函中使用本文件规定的单次来源声明，不得在每项结果中重复品牌名称或许可状态。

### 有限外部核查例外

只有先审阅当前采信资料、再完成相关快查查询后，仍存在材料不足、快查不覆盖，或者确需补充商业真实性及舆情线索时，才自动开展下列定向外部检索：

- **公司**：公司官网、融资历史、可信新闻报道、媒体与行业评价、有明确发布机构、日期、样本范围和评选方法的行业排名，以及行政处罚或诉讼新闻、产品下架、数据泄露事件等负面舆情。
- **核心人员**：创始人或高管的公开职业履历、过往创业经历、公开采访或对外言论、涉诉或失信报道，以及与前雇主竞业限制或知识产权纠纷线索。仅处理公开、必要的职业和商业信息，不查询个人征信、住址、联系方式、家庭关系等非必要个人信息。
- **产品/业务**：官网及公开产品页、应用商店、公开备案、可信媒体实测和大型用户平台评价，用于核对产品是否实际上线运营、公开市场反馈，以及技术宣称是否与可观察事实或其他来源明显矛盾。不得据此确认底层技术、模型能力或知识产权归属。
- **商标/品牌**：品牌实际使用情况、侵权或被侵权报道、相同及近似商标线索。近似商标检索须结合文字、图形及商品服务类别，只能形成初步线索，不直接形成确定性侵权或可注册结论。

有限外部检索的来源可信度依次为：主管机关或司法机关公开信息、公司官网及正式公告、权威行业机构、可靠主流或专业媒体、应用商店及大型用户平台、其他公开信息。搜索引擎只用于发现原始页面，搜索结果摘要不得作为证据；不得登录、付费订阅、注册账户或绕过访问限制。

公司官网、高管自述只能证明相关主体作出过该陈述，不能独立证明陈述真实。行业排名缺少发布机构、日期、样本范围或评选方法时只作宣传线索。用户口碑只能描述特定平台、时间和样本中的公开反馈，不得由少量评论推导市场份额、产品质量或违法事实。新闻、自媒体和用户评论中的处罚、诉讼、失信、侵权、产品下架或数据泄露信息先标记为 `外部线索`；能以快查或官方来源复核的继续复核，不能复核的列入待核实事项。

公开检索无结果时记录覆盖范围、关键词和访问日期，不得写成“不存在”“没有负面舆情”“无近似商标”或其他否定性事实。已复核且与委托目的相关的事实写入对应正文，重大负面事项写入“重大问题及风险提示”，单一报道、冲突信息或证据不足事项写入“待核实事项”；引用外部检索事实的正文段落必须配置结构化 `external_sources`，由生成器在该段末尾插入 Word 原生脚注，并在当页底部列明来源名称、页面标题、发布日期、URL 和访问日期。重要外部来源仍可同时列入“附件或资料清单”，但附件清单、普通括号或固定页脚不能替代逐项脚注溯源，也不新增报告一级章节。

每次有限外部检索在内部底稿记录：`检索事项 / 关键词 / 来源名称 / 页面标题 / 发布日期 / 访问日期 / URL / 支持事实 / 可信度`。轻量记录追加保存，不覆盖历史记录。

### 一、固定调用流程

#### 1. 锁定主体

1. 企业名称为简称、品牌名或存在歧义时，先用中文能力描述 `企业模糊搜索` 调用 `discover`。
2. 用 `call` 执行候选工具，核对企业全称、统一社会信用代码、住所和法定代表人。
3. 固化主体标识，后续优先级为：`orgid` > `creditcode` > 完整 `corp_name`。
4. 主体无法唯一匹配时暂停实体级核查，列出候选并要求人工确认。

#### 2. 发现并调用能力

- 按 `fazhi-mcp` 的企业数据标准流程调用 `discover`、`call`，不得在本文件另行定义或猜测接口 schema。
- 尽调人员提供具体核查维度的中文能力描述，例如：`企业股权质押及注销信息`、`企业被执行人信息`，并在底稿中记录实际 `tool_id` 和参数摘要。
- 对列表类结果必须完成分页并记录停止条件；不得只取第一页就形成完整性、数量或“未发现”结论。

#### 3. 建立查询日志

每次调用记录：

| 字段 | 内容 |
|---|---|
| 查询编号 | KQ-001 起连续编号 |
| 查询时间 | 含时区，精确到分钟 |
| 报告基准日 | 与项目统一 |
| 主体标识 | 企业全称、orgid、统一社会信用代码 |
| discover 描述 | 使用的中文能力描述 |
| tool_id | 实际调用工具 |
| 参数摘要 | 不包含凭证和无关个人信息 |
| 分页范围 | 已取页码及是否完整 |
| 返回总数/本页数 | 工具返回的总数及逐页数量；工具未提供总数时注明 |
| 分页终止条件 | 空页/达到总页数/明确结束标记/异常中止 |
| 返回状态 | 成功/空结果/未匹配/参数错误/权限错误/服务错误 |
| 原始结果定位 | 文件名、底稿路径或响应编号 |

首次查询时复制 `references/快查外部核查与底稿规则.md`，保存为 `{{outputPath}}/快查外部核查底稿.md`。兼容旧项目路径时，`outputPath` 可归一为 `{{roundFolder}}/08_尽调`。增量查询追加记录，不覆盖历史记录。

### 二、状态机

外部核查按以下状态推进，不得跨越核验门直接形成确定性结论：

```text
S0 初始化
 -> S1 主体消歧
 -> S2 固化主体标识和报告基准日
 -> S3 discover 发现能力
 -> S4 call 查询并完成分页
 -> S5 规范化事件和字段语义
 -> S6 构建状态链
 -> S7 与内部证据交叉验证
 -> S8 标记证据状态
 -> S9 写入报告
```

证据状态仅可使用：

- `已核实`：内部原始材料与快查结构化结果一致，且不存在未解释的后续事件；
- `外部线索`：只有快查结果，尚无内部原始材料支持；
- `口径冲突`：内部材料与快查结果不一致；
- `待补正`：事件链不完整、字段含义不明或材料版本过旧；
- `未覆盖`：快查无对应能力或该事项属于快查能力边界之外；
- `查询失败`：连接、权限、参数或服务错误导致未完成核查。

只有 `已核实` 可以无保留地写成确认性事实。其他状态必须使用限定措辞并列入待核实事项。

### 三、事件状态链强制规则

查询到登记或风险事件后，必须继续发现并查询后续状态，不得只凭单一事件下当前状态结论。

| 事项 | 必须核查的状态链 |
|---|---|
| 股权质押 | 设立 -> 变更 -> 注销；未查注销能力或结果不完整时不得写“现存有效” |
| 动产抵押 | 设立 -> 变更 -> 注销/到期 |
| 司法案件 | 立案/开庭 -> 裁判 -> 执行 -> 终本/结案/恢复执行 |
| 被执行/限高 | 首次列入 -> 金额变化 -> 履行/解除/撤销 |
| 行政处罚 | 立案/处罚 -> 履行 -> 整改/信用修复 |
| 资质许可 | 首次发证 -> 延续/变更 -> 到期/注销/吊销；旧证不得代表当前无证 |
| 对外投资 | 设立/受让 -> 持股变化 -> 清算/注销/转让退出 |
| 董监高/法定代表人 | 任职 -> 变更 -> 离任，以报告基准日状态为准 |

事件日期、数据更新时间和报告基准日分别记录。基准日后事件放入“期后事项”，不得倒推为基准日事实。

### 四、字段语义与禁止推论

#### 空结果

快查返回空数据时，内部底稿记录：

> `EMPTY_RESULT`：记录查询时间、检索条件、覆盖限制和补正要求。

正式报告不得复制上述内部状态或查询过程，必须转换为：

> 截至报告基准日，现有项目资料及已核验的公开信息未显示相关事项；该判断仍受资料完整性及信息更新时点限制。

禁止写“无诉讼”“无贷款”“无处罚”“无质押”等绝对结论，除非同时有符合项目标准的内部或主管机关原始证明。

#### 年报社保人数

年报“社保参保人数”是特定年度和填报口径的公示字段，不等于实际员工人数。发现异常时只写“年报口径与业务规模/内部名册不一致”，并催收员工名册、劳动合同、工资表及社保公积金缴费明细。

#### 融资历史

“融资历史”通常指股权融资或公开融资事件，不等于银行贷款、授信、保理、融资租赁负债或全部债务。结果为 0 时不得写“公司没有融资或贷款”。债务结论必须依赖企业信用报告、征信、银行函证、借款合同和财务账簿等内部/第三方原始材料。

#### 资质许可

查询到过期旧证时，必须继续查询当前有效证照、延续和变更记录；仅有旧证不能推出当前无证。快查未覆盖的行业许可标记为 `未覆盖`，向公司催收主管机关出具的有效证照。

#### 统计与风险数量

风险数量是记录条数，不当然等于案件数、有效风险数或未结事项数。先去重并按事件状态链归并，再进行数量描述。

### 五、能力映射

模块中的“外部核查渠道”均视为核查维度说明，实际调用统一映射到快查能力，不直接访问所列网站。

| 尽调维度 | 优先 discover 能力描述 |
|---|---|
| 主体资格/沿革 | 企业模糊搜索、企业基本信息、工商变更、年报信息、分支机构 |
| 股权/控制 | 工商股东、股权穿透、实际控制人、最终受益人、股权质押及注销 |
| 对外投资/关联方 | 企业对外投资、企业图谱、主要人员对外投资任职、所属集团 |
| 经营风险 | 经营异常、行政处罚、严重违法、欠税、破产重整、动产抵押 |
| 司法风险 | 法律诉讼、裁判文书、开庭公告、被执行人、失信、限高、终本、司法协助 |
| 资质许可 | 企业资质证书、医疗器械、互联网药品信息、网站备案及相关行业许可 |
| 知识产权 | 商标、专利、软件著作权、作品著作权、网站备案 |
| 经营与交易 | 招投标、主要客户供应商、融资历史、招聘、核心团队 |
| 新闻舆情 | 快查新闻舆情、公告详情、快查通用搜索 |

快查通用搜索只作商业资讯线索，不替代结构化工具。发现新闻、品牌或关系线索后，能用结构化能力验证的必须再查询；不能验证的标记为 `外部线索`。

### 六、主信息源与证据等级

#### 1. 主信息源规则

- 已提供项目资料或底稿：`primary_basis=current_accepted_materials`，当前采信资料库为正式报告主信息源，快查不得直接覆盖。
- 未提供任何项目资料：`primary_basis=public_information_pre_dd`，可以快查公开信息形成 Pre-DD，但报告函必须明确范围限制。
- 主管机关原件或其他更高等级材料到达后，须先登记版本并转为当前采信版本，再替换对应事实主源。
- 快查与主信息源不一致时，将差异写入内部 `source_control.conflicts`；完成补正前，客户报告仅披露口径差异和待核实事项。

#### 2. 证据等级

证据优先级：

1. 主管机关、银行、税务、社保或登记机构出具的原始证明；
2. 经审计财务报告、用印合同、章程、决议及可验证业务记录；
3. 快查结构化企业数据；
4. 企业书面说明和访谈记录；
5. 本文件允许的可信公开信息；其中公司自述、媒体报道、行业排名和用户评价通常只作交叉验证或外部线索；
6. 快查新闻舆情或通用搜索结果。

优先级高不等于自动正确。证据冲突时不得静默覆盖，建立冲突表：

| 事项 | 内部证据及日期 | 快查结果及查询时间 | 冲突点 | 暂定采信 | 补正措施 |
|---|---|---|---|---|---|

没有完成补正前，报告表述为“存在口径冲突，尚待核实”。

### 七、内部状态与客户报告写入门槛

内部底稿应完整记录事实内容、事件日期、查询时间、证据状态、快查工具/底稿编号、分页和与内部材料是否一致。正式报告只写客户可理解的事实、范围限制、证据冲突和补正要求，不写工具、接口、参数、分页、底稿编号或能力评价。

内部查询状态进入正式报告前按下表转换：

| 内部状态 | 客户报告固定表述 |
|---|---|
| `EMPTY_RESULT` | 截至报告基准日，现有项目资料及已核验的公开信息未显示相关事项；该判断仍受资料完整性及信息更新时点限制。 |
| `UNSUPPORTED` | 现有公开信息不足以支持完整核验，相关事项暂不作无保留结论。 |
| `FAILED` | 本阶段尚未取得足以支持明确判断的资料，建议补充取得相关证明。 |
| `INCOMPLETE` | 现有公开信息样本不足以支持完整统计，相关数量及状态应以完整清单和原始证明为准。 |

不得在正式报告中出现状态名、接口名、工具名、参数、分页、失败原因或“能力未覆盖”等作业语言。任何状态均不得转化为“无诉讼”“无处罚”“不存在风险”等否定性事实。

禁止：

- 把空结果改写为不存在；
- 把历史事件改写为当前状态；
- 把数据更新时间当作事件发生日期；
- 把企业年报字段跨口径解释；
- 用快查数据替代合同、征信、审计、社保或许可证原件；
- 在四类有限外部核查事项之外因快查不可用而切换其他外部来源；
- 未满足有限外部核查触发条件即自动使用 WebSearch 兜底；
- 在内部底稿中隐去查询失败、未覆盖、分页不完整或主体歧义；正式报告应将其转换为上表所列的证据限制和补正要求。

正式报告仅在报告函中添加一次，其他部分不得重复：

> 本次公开信息核验以同花顺旗下快查企业数据引擎为主要渠道，并对官网、官方公示及可信公开报道进行有限补充核查；相关结果仅用于一致性复核和线索补充，不替代委托方提供并纳入当前采信范围的资料及原始证明。
