# 尽调模块：知识产权与数据合规

## 知识产权 尽调

> 场景门控：核查目标、资料、程序和判断标准属于通用核心；含交割、投资、估值、Holdback、前轮或投后的段落仅在投融资/并购场景适用，其他场景按 `委托流程与证据问题处置规则.md` 映射处理出口。

### 调查任务与适用边界
查明目标主体知识产权（专利、商标、著作权、软件著作权、域名及核心技术）的权属清晰性、有效性与主营业务关联性，重点查清核心技术归属公司而非创始人个人/第三方，发现开源合规与侵权风险；核验结果应能够直接对应后续风险判断和报告写入。

### 风险事项与场景关注
1. 核心专利/软件著作权登记在创始人个人或前雇主名下，未转让给公司；结论应由当前采信材料、外部核验或访谈记录相互支持。
2. 核心技术系职务成果但权属约定缺失，出现归属争议
3. 商标被第三方抢注，或申请被驳回致品牌使用受限；核验结果应能够直接对应后续风险判断和报告写入。
4. 使用开源软件、模型或数据集时未遵守对应许可证的署名、通知、源代码提供、再分发或使用限制
5. 产品涉他人专利，未做 FTO，出现侵权诉讼风险
6. 知识产权处于质押状态或面临失效（未缴年费/未续展）；发现异常时，应继续追查形成原因、持续期间及处置进展。

### 科技企业与交易场景附加关注

#### 专项核验：IP 是早期科技/AI企业的估值核心（汉坤、金杜、东方律师分析）

**核心技术权属——投资安全的基础**：围绕形成过程、开发人员、资金投入、登记主体和授权文件还原权属链，使核验结果可以直接支撑风险判断和报告写入。
- 早期企业IP权属问题最为集中和致命——"专利已质押给银行却未披露"是典型雷区；同时记录对应证据、影响范围和待补正状态。
- **创始人个人持有IP**：创始人在公司成立前即以个人名义申请专利/软著，尚未转让给公司——应当查验全部IP权利人是否为公司；结论应由当前采信材料、外部核验或访谈记录相互支持。
- **前雇主职务成果风险**：结合任职任务、完成时间、技术关联、单位资源、合同和专利法相关规则判断；“离职一年”只能作为触发线索，不能单独认定权属
- **高校/科研机构成果转化**：核查课题、经费、职务任务、合作协议、权属约定和必要审批，不预设全部在校成果当然归高校

**技术来源查验——初创企业的特殊风险**：
- 初创公司成立不久即拥有领先技术，意味着相关技术可能会在公司成立前已产生
- 按实际情况排查技术来源，例如：
  1. 创始团队在学校/科研机构的课题研究成果；同时记录对应证据、影响范围和待补正状态。
  2. 创始团队/研发成员在前雇主处掌握的技术；结论应由当前采信材料、外部核验或访谈记录相互支持。
  3. 收购其他公司获得的技术；发现异常时，应继续追查形成原因、持续期间及处置进展。
  4. 从母公司拆分获得的技术；核验结果应能够直接对应后续风险判断和报告写入。
  5. 与第三方业务合作获得的技术；同时记录对应证据、影响范围和待补正状态。
- 查验方法：公司发展历史 + 核心技术人员背景 + 第三方合作历史 + 专利申请日期分析

#### 标签触发事项：AI企业IP特殊风险 **【触发条件：`AI大模型`】**（观韬律所分析）
- **训练数据IP侵权**：对训练语料中的文字、图片、音视频和代码逐类检查著作权授权。缺乏权利人合法许可时，风险不仅发生在数据处理环节，也可能影响模型及生成内容的商业使用基础；核验材料应能直接支撑风险判断与报告表述。
- **AI生成内容的侵权风险**：遵循"接触+实质性相似"原则，即使无主观故意，生成内容与在先作品高度相似仍可能会侵权；同时记录对应证据、影响范围和待补正状态。
- **开源模型与组件许可**：逐项核对具体许可证、组件组合、链接/分发方式、模型权重与数据集条款；不得假定 GPL 自动适用于模型或数据，也不得用“传染性”替代条款分析
- **微调成果与权利边界**：结合上游许可、训练方式、权重发布、合同和适用法律判断，不预设所有微调成果均属于衍生作品

#### 专项核验：商业秘密保护
- AI企业的未公开算法参数、训练数据集均属商业秘密；同时记录对应证据、影响范围和待补正状态。
- 应当查验保密协议、竞业限制是否覆盖核心商业秘密
- 是否对核心数据、算法代码采取了分级权限管理、加密存储、访问留痕等技术保密措施

#### 专项核验：FTO（自由实施）分析
- 完整FTO分析费用高、周期长，早期项目通常不做完整FTO；同时记录对应证据、影响范围和待补正状态。
- 替代方案：在尽调时对核心产品/技术做初步侵权风险排查，判断是否存在明显的高风险专利
- 关注竞品公司的专利布局和诉讼历史；发现异常时，应继续追查形成原因、持续期间及处置进展。

### 核验资料与证据清单
知识产权资料先按取得方式列明重要技术，再分别提供已登记权利清单及证书、申请中权利的受理文件、未登记成果清单，以及被驳回、无效或终止项目的说明。涉及转让、许可、合作开发、第三方使用、登记在股东或员工名下、权利负担和侵权争议的，逐项附协议、对价与权属安排；商业秘密制度一并提供。

**投融资/并购或AI场景按需取得**：
- 核心技术人员的入职/离职时间线及前雇主信息；核验结果应能够直接对应后续风险判断和报告写入。
- 与高校/科研机构的合作协议（IP归属条款）；同时记录对应证据、影响范围和待补正状态。
- 开源软件使用明细及许可证合规自查报告
- 训练数据来源的IP授权链条文件；发现异常时，应继续追查形成原因、持续期间及处置进展。
- 商业秘密保护制度及保密措施说明；核验结果应能够直接对应后续风险判断和报告写入。

### 外部核验维度
- 快查 MCP：专利、商标、软件著作权、作品著作权、网站备案能力
- 快查 MCP：裁判文书、法律诉讼能力（知识产权纠纷）
- 开源组件和许可证、海外专利若快查不覆盖，标记“外部未覆盖”，改由公司提供清单、扫描报告、权利证书和境外代理人意见
- 当前采信资料和快查不足时，按 `快查外部核查与底稿规则.md` 有限检索品牌实际使用、侵权或被侵权报道以及相同、近似商标线索；近似检索须结合商品服务类别，只形成初步线索

### 访谈核实安排
- 技术总监/研发负责人（专利与产品对应、技术来源、开源使用）；结论应由当前采信材料、外部核验或访谈记录相互支持。
- 法务/IP 负责人（权属、纠纷、开源合规、商业秘密保护）；发现异常时，应继续追查形成原因、持续期间及处置进展。
- **核心技术人员**（职务成果归属查清、前雇主竞业/IP限制、高校审批情况）
- **创始人**（创业前技术积累的来源和权属）；同时记录对应证据、影响范围和待补正状态。

### 核查步骤与交叉验证
**事实还原主线：权属链。**
1. **清单与外部核对**：以公司完整名称、`orgid` 或统一社会信用代码通过快查 MCP 查询，核对权利人、法律状态和清单外相关 IP；同时将快查支持查询的创始人和核心技术人员关联 IP 列入核查范围；
   - 材料和快查不足时，有限检索公司官网、公开产品页、应用商店及可信报道，核对品牌是否实际使用；相同或近似商标、侵权报道均先标记为“外部线索”，不得直接形成侵权、无冲突或可注册结论；
2. **权属查验（VC核心）**：
   - 权利人非公司的 IP，查验转让协议、对价、登记变更；
   - 创始人个人专利确认是否存在任职期间形成的职务发明并完成转让；
   - **前雇主职务发明排查**：将核心IP的申请日与发明人从前雇主的离职时间比对，1年内的标注高风险；核验结果应能够直接对应后续风险判断和报告写入。
   - 高校/科研机构人员创业：查验合作协议中IP归属条款和审批程序；
   - 外包软著查验"成果归委托方所有"约定；
3. **技术来源排查**：把公司发展时间线与核心团队履历、第三方合作经历及专利申请时点相互对照，据此判断技术来源是否合法；发现异常后继续查明形成原因、持续期间和处置进展。
4. **有效期**：查验专利年费缴纳、商标续展，发现即将失效的核心 IP；
5. **核心技术关联性**：将核心产品/技术与持有专利逐一对应，查清支撑性与技术来源书面依据；同时记录对应证据、影响范围和待补正状态。
6. **侵权与开源**：同步核对第三方权利主张、开源许可证义务、代码扫描结果和产品发布方式，结论由当前材料、外部核验及技术访谈相互支持。
   - 查验 FTO 或初步侵权风险排查结果；
   - 结合快查 MCP 的裁判文书和法律诉讼能力检索 IP 纠纷；
   - **AI企业**：分别核查开源模型、代码和数据集的具体许可证义务、分发方式与合规证据；
   - 查验训练数据中的IP授权链条；
7. **商业秘密保护体系**：查验保密协议/竞业限制覆盖范围、技术保密措施（权限管理/加密/访问留痕）；发现异常时，应继续追查形成原因、持续期间及处置进展。
8. 取得核心技术人员/创始人"IP 无代持、无纠纷、无未披露的权属争议"声明纳入底稿；核验结果应能够直接对应后续风险判断和报告写入。

### 结论形成标准
- 全部核心 IP 登记在公司名下，权属清晰（含创始人转让完成）；结论应由当前采信材料、外部核验或访谈记录相互支持。
- 无前雇主职务发明争议或高校权属纠纷；发现异常时，应继续追查形成原因、持续期间及处置进展。
- 核心专利/商标有效、无即将失效风险；核验结果应能够直接对应后续风险判断和报告写入。
- 开源软件、模型和数据集的具体许可证义务已识别并有履行证据；训练数据IP授权链条完整；
- 核心技术来源有书面依据，职务成果归属明确；结论应由当前采信材料、外部核验或访谈记录相互支持。
- 商业秘密保护体系健全；发现异常时，应继续追查形成原因、持续期间及处置进展。

### 问题分级与处理出口
| 风险分级 | 典型情形 | 处置出口 |
|---|---|---|
| 红线 | 典型情形：核心 IP 权属实质争议（归创始人前妻或前雇主或第三方或高校）、核心 IP 被质押面临失效 | 处置安排：交割前确权或解押并作为交割先决条件；否则放弃；交割前明确是否满足退出或停止条件 |
| 高 | 典型情形：核心 IP 在个人名下未转让、前雇主职务成果风险、重大侵权风险、严重许可证违规 | 处置安排：交易场景可设先决条件或陈述保证；其他场景制定权属或许可整改措施；同步确定责任主体和完成期限 |
| 中 | 典型情形：商标被抢注、软著归属待补、训练数据授权瑕疵 | 处置安排：陈述保证，并配套交割后整改（异议或补签或更换）+ 投后监控；纳入交割后整改及跟踪清单 |
| 低 | 典型情形：未及时变更登记但权属清晰、年费续展、隐私文本 | 处置安排：披露，并配套交割后补办；在报告中披露并持续观察 |

#### 投融资/并购附加安排（条件启用）
- 要求就「核心 IP 权属清晰、均登记在公司名下、无代持无纠纷、无未披露权属争议」作核心陈述保证；核验结果应能够直接对应后续风险判断和报告写入。
- 个人名下核心 IP 的转让登记作为打款前置条件；同时记录对应证据、影响范围和待补正状态。
- 侵权敞口以 Holdback 覆盖，创始人就历史 IP 瑕疵个人补偿；结论应由当前采信材料、外部核验或访谈记录相互支持。
- **前雇主风险专项**：创始人就"核心技术不侵犯前雇主知识产权、核心人员无竞业障碍"作陈述保证并承担个人补偿；发现异常时，应继续追查形成原因、持续期间及处置进展。
- **AI企业专项**：训练数据IP授权瑕疵导致的模型不可商用是deal breaker——授权链条完备程度是估值前提；核验结果应能够直接对应后续风险判断和报告写入。

## 数据合规与网络安全 尽调

> 场景门控：核查目标、资料、程序和判断标准属于通用核心；含交割、投资、估值、Holdback、前轮或投后的段落仅在投融资/并购场景适用，其他场景按 `委托流程与证据问题处置规则.md` 映射处理出口。

### 调查任务与适用边界
查明目标主体在个人信息保护、数据处理、数据出境、网络安全等级保护及算法/大模型备案方面的合规状态，发现数据来源合法性与重要数据/跨境传输风险，判断合规缺口对业务持续性的影响；核验结果应能够直接对应后续风险判断和报告写入。

### 风险事项与场景关注
1. 收集使用个人信息未取得有效同意、隐私政策/用户协议缺失或不合规；结论应由当前采信材料、外部核验或访谈记录相互支持。
2. 训练数据来源不合法（未经许可抓取受版权保护数据、第三方数据无授权）；发现异常时，应继续追查形成原因、持续期间及处置进展。
3. 重要数据或个人信息向境外提供时，没有履行适用的安全评估、标准合同备案或认证程序
4. 网络安全等级保护测评未做或等级不足；CII（关键信息基础设施）义务未履行；同时记录对应证据、影响范围和待补正状态。
5. 算法推荐、生成式 AI 大模型未备案或未做安全评估
6. 缺网络安全负责人/部门、缺监测预警与应急预案，曾发生数据泄露/被处罚；发现异常时，应继续追查形成原因、持续期间及处置进展。

### 行业专项关注（按标签触发）

#### AI/科技企业数据合规 **【触发条件：`AI大模型`】**

**训练数据合规——模型的生命线**：围绕数据来源、授权范围、处理方式和使用留痕建立可追溯的证据链，并记录证据缺口、影响范围和待补正状态。
- 训练数据来源合法性是大模型备案的前置条件，也是估值基础；结论应由当前采信材料、外部核验或访谈记录相互支持。
- 按实际来源分类核查，例如：
  - **自采数据**：是否遵守 robots 协议、是否绕过验证码抓取、是否完成脱敏或去标识化处理；核验结果应能够直接对应后续风险判断和报告写入。
  - **采购数据**：应当穿透审查供应商资质、原始数据来源、授权范围是否明确覆盖"AI模型训练"用途，合同中应当有数据权利瑕疵担保条款；同时记录对应证据、影响范围和待补正状态。
  - **开放或共享数据**：逐项核对数据集许可、权利主体、使用范围和再分发限制；不得把 GPL 等软件许可证规则机械套用于数据集或模型
  - **用户输入数据**：用于训练应当留存完整授权记录、去标识化处理、为用户提供关闭方式和行权响应机制；发现异常时，应继续追查形成原因、持续期间及处置进展。

**个人信息处理合规**：围绕告知同意、最小必要、敏感信息处理、影响评估和主体权利响应核对制度与实际操作，并记录证据缺口、影响范围和待补正状态。
- 落实"最小必要"原则，敏感个人信息（人脸、医疗等）应当取得单独同意
- 定期开展个人信息保护影响评估（PIA）
- 隐私政策应当清晰完整告知处理目的、方式、期限、共享及跨境情形

#### 数据出境合规 **【触发条件：`出海/跨境SaaS` `外资成分`】**
- 先识别是否属于关键信息基础设施运营者、重要数据、个人信息或敏感个人信息，再判断豁免、安全评估、标准合同或认证路径
- 非关键信息基础设施运营者自当年1月1日起累计向境外提供100万人以上个人信息（不含敏感个人信息）或1万人以上敏感个人信息的，应申报数据出境安全评估；10万人以上但不足100万人的非敏感个人信息，或不足1万人的敏感个人信息，原则上进入标准合同/认证区间，并须核对法定豁免。依据 `SRC-DATA-EXPORT-2024`，核验日期 2026-08-21
- **AI企业特殊场景**：跨境研发（共享训练数据）、海外融资（向境外投资人提供数据）、海外部署——均应当判断数据出境合规路径；同时记录对应证据、影响范围和待补正状态。
- 应当同时查验业务所在国的数据合规要求（如欧盟GDPR、美国州法）

#### 网络数据与AI内容标识规则
- 将三法（网安法/数安法/个保法）核心义务织成可实施、可检查的制度网络；同时记录对应证据、影响范围和待补正状态。
- 新增自动化采集前的合规判断要求
- 明确重要数据定义和数据备案具体要求；发现异常时，应继续追查形成原因、持续期间及处置进展。
- AI生成合成内容的显式/隐式标识义务来自《人工智能生成合成内容标识办法》，自2025年9月1日起施行；应按服务类型和传播角色核查，不能笼统归入《网络数据安全管理条例》。依据 `SRC-AI-LABEL-2025`，核验日期 2026-08-21

#### 专项核验：早期企业常见特有问题
- 无专职数据安全负责人/部门；结论应由当前采信材料、外部核验或访谈记录相互支持。
- 隐私政策照搬模板、与实际业务不符；发现异常时，应继续追查形成原因、持续期间及处置进展。
- 训练数据来源不清，大量使用网络爬取数据但无授权记录；核验结果应能够直接对应后续风险判断和报告写入。
- 等保定级/测评未做或等级不足；同时记录对应证据、影响范围和待补正状态。
- 预算有限，数据安全投入不足——应当区分"法定必须做"和"最佳实践"

### 核验资料与证据清单
数据资料应能够还原从收集到使用、共享及出境的处理链，包括隐私政策、用户协议、收集方式与范围、数据类型和用途、同意机制、第三方采购协议、跨境传输及重要数据说明，并列示数据违规引发的监管行动或诉讼。网络安全方面另提供责任部门和负责人信息、监测预警与通报制度、应急预案及演练记录。

**AI/科技企业应当额外取得**：
- 训练数据来源分类说明及授权链条文件；发现异常时，应继续追查形成原因、持续期间及处置进展。
- 已完成的个人信息保护影响评估（PIA）及其报告
- 数据出境所适用的安全评估结果或标准合同备案材料
- 数据安全保障体系文件，包括加密、权限控制、备份与恢复安排；结论应由当前采信材料、外部核验或访谈记录相互支持。

### 外部核验维度
- 快查 MCP：企业资质、网站备案、行政处罚及新闻舆情能力
- 算法/大模型备案、等保测评和数据出境备案如快查不覆盖，标记“外部未覆盖”，取得备案凭证、测评报告及主管机关材料
- 快查 MCP：行政处罚、经营风险及新闻舆情能力；备案信息未覆盖时列为资料缺口
- 当前采信资料和快查不足时，可有限检索产品下架、公开数据泄露事件及相关可信报道；新闻、自媒体或用户评论先作外部线索，优先以官方通报或快查结构化信息复核

### 访谈核实安排
- 技术/数据负责人（数据来源分类、处理流程、出境场景）；核验结果应能够直接对应后续风险判断和报告写入。
- 网络安全负责人（等保、应急、事件历史、安全架构）；同时记录对应证据、影响范围和待补正状态。
- 法务/合规（同意机制、备案、处罚、数据出境路径）；结论应由当前采信材料、外部核验或访谈记录相互支持。
- **采购负责人**（第三方数据采购的供应商审核与授权审查）；发现异常时，应继续追查形成原因、持续期间及处置进展。

### 核查步骤与交叉验证
**事实还原主线：合规链。**
1. **数据地图**：梳理收集的个人信息与商业数据的类型、来源、目的、存储与流向，发现重要数据；**对AI企业应当特别梳理训练数据的四大来源（自采/采购/开源/用户输入）占比和合规状态**；结论应由当前采信材料、外部核验或访谈记录相互支持。
2. 同意与告知：查验隐私政策/用户协议文本与实际收集是否一致、同意机制是否有效；**AI企业应当查验用户输入数据用于训练的授权记录**；发现异常时，应继续追查形成原因、持续期间及处置进展。
3. **训练数据来源合法性**：核查采购数据的供应商授权链条、开放数据集许可、自采数据的采集依据及用户输入的授权机制；软件、模型和数据许可证分别适用，不以“传染性”概括结论；
4. 出境合规：发现个人信息/数据出境场景（含跨境研发、海外融资），比对是否完成安全评估/标准合同备案/保护认证；同时记录对应证据、影响范围和待补正状态。
5. 网络安全：查验等保定级与测评、CII 认定与义务、算法/大模型备案与安全评估（与「业务经营与资质许可」联动）；结论应由当前采信材料、外部核验或访谈记录相互支持。
6. **规则分层核查**：分别核查网络数据管理要求、AI生成合成内容标识要求及重要数据识别/申报要求；
7. 治理与事件：查验安全负责人/部门、监测预警与应急预案、历史泄露/处罚及整改闭环；有限外部检索发现的数据泄露或产品下架线索不能替代内部事件记录、技术调查和整改证明。

### 结论形成标准
- 个人信息处理有合法性基础与有效同意，文本合规；结论应由当前采信材料、外部核验或访谈记录相互支持。
- 训练/第三方数据来源合法、授权链完整；发现异常时，应继续追查形成原因、持续期间及处置进展。
- 出境场景已走合规路径；等保、算法/大模型备案到位；核验结果应能够直接对应后续风险判断和报告写入。
- 网络安全治理体系健全，无未整改的重大事件/处罚；同时记录对应证据、影响范围和待补正状态。
- 符合《网数条例》新增合规要求；结论应由当前采信材料、外部核验或访谈记录相互支持。

### 问题分级与处理出口
| 风险分级 | 典型情形 | 处置出口 |
|---|---|---|
| 红线 | 典型情形：核心训练数据来源违法、未备案致业务面临叫停 | 处置安排：交割前整改或备案并作为交割先决条件；否则放弃；交割前明确是否满足退出或停止条件 |
| 高 | 典型情形：违规出境、重大数据泄露未整改、训练数据大规模侵权 | 处置安排：先决条件或价格调整，并配套陈述保证，并配套补偿；同步确定责任主体和完成期限 |
| 中 | 典型情形：等保或算法备案待补、同意机制需要优化、PIA 未做 | 处置安排：陈述保证，并配套交割后限期整改，并配套投后监控；纳入交割后整改及跟踪清单 |
| 低 | 典型情形：隐私文本待完善、AI内容标识待补充 | 处置安排：披露，并配套交割后整改；在报告中披露并持续观察 |

#### 投融资/并购附加安排（条件启用）
- 数据合规作专项陈述保证（合法收集、合法来源、已备案、无重大处罚）；发现异常时，应继续追查形成原因、持续期间及处置进展。
- 备案缺失/训练数据来源整改作为打款前置条件；核验结果应能够直接对应后续风险判断和报告写入。
- 潜在数据合规处罚敞口以 Holdback 覆盖，创始人个人补偿历史违规损失；同时记录对应证据、影响范围和待补正状态。
- **AI企业专项**：训练数据授权链条完备程度直接决定模型合法性——授权瑕疵导致的模型不可商用是deal breaker；结论应由当前采信材料、外部核验或访谈记录相互支持。
