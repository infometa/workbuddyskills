# 委托流程与证据问题处置规则

## 委托类型与输入归一规则

本文件是 `engagementType`、直接输入和风险处理出口的单一事实源。

### 1. 允许值

仅使用以下规范值：

| engagementType | 典型委托目的 | 默认处理出口 |
|---|---|---|
| 投融资尽调 | 判断投资可行性并配置投资人保护 | 先决条件、陈述保证、价格/Holdback、赔偿、交割后义务、投后监控 |
| 并购尽调 | 判断收购风险及交易结构 | 交易结构、先决条件、价格调整、专项赔偿、陈述保证、交割整合 |
| 常年法律顾问合规体检 | 识别制度与执行缺口 | 整改事项、责任人、期限、制度修订、培训、持续监测、复查 |
| 供应商/合作方尽调 | 决定准入与合作保护 | 准入/拒绝/附条件准入、合同保护、审计权、终止权、定期复核 |
| 融资方尽调 | 支持授信、放款或债权风险判断 | 授信/放款前提、担保增信、陈述承诺、财务/合规约束、贷后监控 |
| 上市前专项核查 | 支持规范整改与申报核查 | 规范整改、信息披露、专项核查、中介交叉验证、申报一致性 |
| 其他专项尽调 | 处理预先定义的专项问题 | 按委托目的定义决定、整改、披露、合同或复核出口 |

用户使用近义名称时归一为上表值。无法判断且不同类型会改变结论出口时，先询问；不得默认成投融资尽调。

### 2. 输入归一

#### 项目兼容路径

读取实际存在的项目档案、轮次档案、控制文档和材料目录。任何文件不存在都只记为缺口，不构成必须运行其他 Flow 的理由。

#### 直接输入路径

没有项目目录时，最小输入为：

- `targetEntity`：目标主体；
- `engagementPurpose`：委托目的；
- `reportCutoffDate`：报告基准日；
- `materialPath`：材料目录；
- `scope`：调查范围与排除项；
- `outputPath`：输出目录。

`ddMaterialPath` 与 `materialPath` 同时存在时，以 `materialPath` 为准并记录别名冲突。`reportCutoffDate` 不得从查询时间自动推断。

### 3. 统一内部上下文

两条路径均生成：

| 字段 | 要求 |
|---|---|
| engagementType | 使用规范值 |
| targetEntity | 全称；主体消歧后补充信用代码与 orgid |
| engagementPurpose | 用一句话明确最终决定或交付目的 |
| reportCutoffDate | YYYY-MM-DD；期后事项单列 |
| materialPath | 可为空；为空时披露未收到材料 |
| scope | 包含主体范围、期间、模块、重点和排除项 |
| outputPath | 所有控制文档、底稿和报告的唯一写入根目录 |
| enabledModules | 依据核心层、标签、用户指定范围计算 |

### 4. 问题处理字段

每个问题至少记录：`issueId`、`moduleId`、`riskLevel`、`evidenceStatus`、`engagementType`、`dispositionCategory`、`action`、`owner`、`deadline`、`verificationStatus`、`supportingEvidence`。

风险等级只描述问题严重程度，不自动决定唯一处理措施。处理措施须结合委托目的、风险可补救性、持续经营影响、金额、时间和证据完整性确定。

### 5. 特殊门控

- 只有投融资尽调或并购尽调读取 `投融资并购附加规则.md`；
- 并购项目使用其中的交易工具时，应按控制权收购、资产收购或合并结构调整，不机械套用 VC 术语；
- 非交易项目不得默认输出估值调整、Holdback、交割或投后条款；
- engagementType 不替代行业标签：供应商尽调也可能触发数据、环境或安全生产模块；
- 上市前专项的红线结论、披露判断和申报障碍必须由负责项目的执业律师及相关中介复核。

## 深度专项核查方法

本方法适用于通用企业法律尽调的全部模块，目标是把资料请求推进为可追溯、可复核的证据链。

### 一、统一原则

- 先明确核查边界，再收集材料；
- 每个结论追溯到当前采信版本、快查查询编号或经授权的访谈记录；
- 存在项目资料时，重大事实以当前采信资料库为主信息源；快查结构化结果仅用于一致性复核、补充公开线索和冲突发现；
- 快查与主信息源冲突时保留主资料口径并记录冲突；主管机关原件完成版本登记并转为当前采信版本后，方可替换对应事实主源；
- 权属、许可、征信、审计、税务、社保等事项不能只凭企业说明或快查确认；
- 取不到独立证据时标 `无法独立核验/待补正`，不得下确定结论；
- 外部自动核查完整遵守 `快查外部核查与底稿规则.md`，本文件不重复快查状态机；
- 行业与模块门控完整遵守 `调查范围与模块启用规则.md`；
- 处理出口完整遵守 `委托流程与证据问题处置规则.md` 和 `委托流程与证据问题处置规则.md`。

项目档案不是前提。存在项目档案时复用；不存在时，以直接输入和 `outputPath` 下初始化的控制文档作为项目上下文。

### 二、深度核查六步法

#### 1. 核查边界

明确期间、主体、业务线、人员、资产、地域、排除项和报告基准日。

| 维度 | 本次范围 | 排除范围 | 依据/说明 |
|---|---|---|---|

#### 2. 资料控制

资料项使用稳定 ID；记录版本、当前采信、来源路径、完整性和补正要求。

| 资料ID | 资料名称 | 内容口径 | 优先级 | 适用性 | 状态 | 当前采信版本 | 缺口/补正 |
|---|---|---|---|---|---|---|---|

无既有控制文档时先创建轻量控制表，不要求用户运行其他 Flow。

#### 3. 核查程序矩阵

每个关键事实配置具体程序，不能只写“查阅资料”。

| 程序编号 | 核查事项 | 内部资料 | 快查能力 | 访谈/其他证据 | 交叉验证点 | 初步状态 |
|---|---|---|---|---|---|---|

快查不覆盖时，在“快查能力”列标 `未覆盖`，转资料补充或人工复核。

#### 4. 事实链还原

按模块选择：

- 时间轴：沿革、处罚、诉讼、整改、许可；
- 权属链：股权、知识产权、重大资产、数据资产；
- 交易链：合同、关联交易、客户供应商、资金；
- 控制链：实际控制人、股东穿透、VIE、境外架构；
- 合规链：数据、反商业贿赂、环保、安全、劳动、外汇海关。

| 节点/事项 | 时间/期间 | 主体 | 关键事实 | 支撑版本 | 快查查询 | 待确认事项 |
|---|---|---|---|---|---|---|

#### 5. 风险判断与场景处理

先区分资料缺口、事实冲突、程序瑕疵、实质风险、披露事项，再依据 `engagementType` 选择处理出口。

| 问题ID | 问题类型 | 事实基础 | 证据状态 | 风险等级 | 法律依据/核验日 | 场景处理 | 验证要求 |
|---|---|---|---|---|---|---|---|

业务陈述与财务数据矛盾时标 `口径冲突`，追查合同、发票、验收、回款、关联往来和会计记录，不得简单采信一方。

#### 6. 文书化输出

每个模块至少输出：核查边界、程序矩阵、事实链、主要问题、证据状态、资料缺口、场景化建议、法律来源和待人工复核事项。

### 三、底稿控制

| 底稿编号 | 模块 | 核查事项 | 支撑版本/查询编号 | 核查程序 | 结论状态 | 备注 |
|---|---|---|---|---|---|---|

发现缺口、补正、版本冲突或新材料时回写控制文档，不得只写入一次性报告。不得覆盖历史版本或律师人工修改。

### 四、专项适配

- 历史沿革：形成完整时间轴，区分新设与存量公司的出资期限规则；
- 股权/控制：形成穿透与控制链，公司法第88条按交易日期及具体事实复核；
- 关联交易/客户供应商：核对合同、发票、物流/验收、收付款、工商穿透和定价依据；
- 知识产权/资产：形成取得、转让、许可、质押、争议和使用限制的权属链；具体开源许可证逐份判断，不使用笼统“传染性”结论；
- 数据/环保/安全/劳动：形成制度、执行、检查、处罚、整改和复查证据的合规链；
- 投融资或并购：额外读取 `投融资并购附加规则.md`；其他场景跳过交易附加规则。

## 尽调发现问题处理规范

本文件定义通用问题记录、证据状态和风险分级。具体处理出口以 `委托流程与证据问题处置规则.md` 为准；投融资或并购交易工具另见 `投融资并购附加规则.md`。

### 一、先分清问题状态

| 状态 | 含义 | 是否可下确定结论 |
|---|---|---|
| 已核实 | 原始材料与快查结构化结果一致，且状态链完整 | 可以，但仍须写明范围与基准日 |
| 外部线索 | 只有快查线索，缺少内部或原始证据 | 不可以 |
| 口径冲突 | 内部材料与快查、不同版本或不同说明不一致 | 不可以 |
| 待补正 | 材料缺失、版本过旧、字段含义不明或事件链不完整 | 不可以 |
| 未覆盖 | 快查无对应能力或事项超出能力边界 | 不可以 |
| 查询失败 | 连接、权限、参数或服务错误 | 不可以 |

空结果不是问题不存在的证据，按 `快查外部核查与底稿规则.md` 使用限定表述。

### 二、问题记录

每个问题至少包含：

| 字段 | 内容 |
|---|---|
| issueId | 稳定编号 |
| moduleId | 对应模块文件名 |
| description | 事实、时间、主体和具体异常 |
| evidenceStatus | 上表状态 |
| riskLevel | 红线/高/中/低 |
| legalBasis | 来源 ID、适用条件、核验日期或待人工复核 |
| supportingEvidence | 当前采信版本 ID、路径、快查查询编号 |
| contradiction | 被替代版本或内外部冲突 |
| engagementType | 规范委托类型 |
| dispositionCategory | 对应场景的处理类别 |
| action | 可验证的具体措施 |
| owner / deadline | 责任人与期限；不适用时说明 |
| verificationStatus | 待处理/处理中/已验证/无法验证 |

### 三、风险等级

| 等级 | 通用含义 | 使用限制 |
|---|---|---|
| 红线 | 可能实质影响主体存续、核心业务合法性、委托目的或决定基础 | 必须由执业律师复核；不能仅凭快查线索认定 |
| 高 | 重大风险或重大证据缺口，需要优先补正、整改、披露或交易保护 | 结合金额、可补救性、期限和持续经营影响判断 |
| 中 | 风险可控但需采取具体措施并复查 | 不因“可整改”而省略责任人和验证证据 |
| 低 | 提示性、形式性或低影响事项 | 仍应记录基准日和后续跟踪条件 |

风险等级不自动对应唯一条款或措施。重大性必须结合委托目的、主体、行业、金额、期间、发生概率、可补救性和证据完整性。

### 四、场景化出口

| engagementType | 处理类别示例 |
|---|---|
| 投融资尽调 | 先决条件、陈述保证、专项赔偿、价格/Holdback、交割后义务、投后监控 |
| 并购尽调 | 结构调整、先决条件、价格调整、赔偿、交割整合、范围剥离 |
| 常年法律顾问合规体检 | 整改、制度/流程修订、责任人、期限、培训、复查、持续监测 |
| 供应商/合作方尽调 | 准入、拒绝、附条件准入、合同保护、审计权、终止权、定期复核 |
| 融资方尽调 | 授信/放款条件、担保增信、承诺、约束、贷后监控 |
| 上市前专项核查 | 规范整改、信息披露、专项核查、申报一致性、中介复核 |
| 其他专项尽调 | 按委托目的预先定义的决定、整改、披露、合同或复核措施 |

非交易项目不得默认出现交割、估值、Holdback、投后或投资人保护话术。

### 五、处理原则

1. 先补事实，再作法律判断；资料缺口不能伪装成低风险。
2. 一项问题可以叠加多个处理措施，但每项都需可验证。
3. 对时效性法律、地方口径、许可状态和裁判规则记录 `verifiedOn`；未核验则标人工复核。
4. 对个人信息、个人流水、亲属关系或个人司法事项先核验授权、必要性和最小范围。
5. 供应商准入、交易放弃、上市障碍等决定性结论不得由自动风险等级直接触发。
6. 报告只陈述本次范围内有证据支持的结论，并披露排除项、能力边界和未解决冲突。
