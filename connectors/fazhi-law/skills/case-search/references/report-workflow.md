# 类案检索报告

只生成固定结构的类案检索报告。不得把本技能扩展为一般法律意见、诉讼策略或自由格式研究备忘录。

## 必读资源

1. 开始检索前完整阅读 [fazhi-mcp/SKILL.md](../../fazhi-mcp/SKILL.md)，并按当前会话实际暴露的 MCP 工具名和参数 schema 调用；不得直接请求 HTTP API 或使用本地包装脚本。
2. 整理研究数据和生成报告前完整阅读 [report-spec.md](report-spec.md)。
3. 以 [research-schema.json](research-schema.json) 作为研究数据接口，不增加字段或改变字段语义。

## 强制工作流

1. 从用户文字、附件或案号中提取案件名称、主体、法律关系、基本事实、诉讼请求、1–3 个争议焦点和用户明确提出的时间地域限制。信息足以检索时直接继续；只有缺少核心法律关系或争议焦点且无法从附件、案号查明时才向用户提问。
2. 用户提供案号时，先调用 `case_search` 定位原案，再调用 `case_browser` 核验原案，随后用原案事实与焦点检索类案。禁止直接用“案号＋类似案例”。
3. 用户未指定范围时使用全国近五年，并把准确起止日写入 `search.date_from`、`search.date_to`；任何纳入案例的 `judge_date` 均须落入该闭区间。生成覆盖支持、部分支持或附条件支持、不支持三种方向的多维检索式；每条必须至少含“关键事实＋争议焦点”等两个维度。
4. 初筛 10–15 件，按案号和 `lawsuit_id` 去重。依次按焦点相同、事实相似、理由完整、参考级别、审级、日期筛选。
5. 对拟纳入的每件案例调用 `case_browser`。未完成全文核验的案例不得写入报告。最终纳入 5–8 件；不足时按实际数量出具并填写不足原因，不得凑数。
6. 调用 `legal_article_search` 与 `law_content_visit` 核验核心规范和效力状态。只有涉及近一年新规、热点或用户明确要求时才调用网页工具。
7. 在任务工作目录编写 `research.json`，不得把研究中间文件放入最终输出目录。将下列 `<skill-root>` 替换为当前 `case-search` Skill 的绝对目录后运行：

   ```text
   python <skill-root>/scripts/validate_research.py research.json
   python <skill-root>/scripts/build_case_report.py --input research.json --output report.docx
   ```

8. 使用文档技能的渲染流程逐页检查 DOCX。只向用户交付最终 DOCX，不交付 JSON、PDF、PNG 或检索日志。

## 续生成报告适配

用户在普通检索后确认继续生成 Word 报告时，执行以下适配；除此之外仍完整遵守上述强制工作流：

1. 复用当前会话中已经实际执行的检索式、地域时间条件、候选案例、排序结果和裁判方向判断，不重复执行已经完成且仍满足报告范围的初筛。
2. 普通检索得到的摘要不视为全文核验。对拟纳入报告的 5–8 件案例逐件调用 `case_browser`，并仅将核验通过的案例写入研究数据。
3. 若已有候选案例不在报告日期闭区间内、去重后不足、方向失衡或理由不完整，只针对缺口按本报告流程补检；不得从头重跑普通检索的 8–10 条首轮检索式。
4. 仍须调用 `legal_article_search` 与 `law_content_visit` 核验核心规范，重新整理完整 `research.json`，运行校验器和生成器，并完成 DOCX 渲染检查。
5. `search.keywords` 只记录当前会话中真实执行过的检索式；`candidate_count` 记录本次普通检索与定向补检中实际审查的去重候选总数。

## 不可变规则

- 只使用法智工具真实返回的案名、案号、法院、日期、裁判理由、结果、法规和链接。
- 不得编造、补全、拼接或根据常识猜测任何来源字段。
- 不得绕过 `validate_research.py`；生成器必须验证与研究 JSON 对应的哈希标记。
- 不得修改固定章节、八列表格、标题名称、列顺序、方向分组、字体、颜色、边距或纵横向分节。
- 不得新增执行摘要、本案分析、律师建议、风险提示、办案策略、法律依据专章、图表、目录或裁判全文。
- 某一裁判方向无合格案例时保留固定小节，并使用规范中规定的唯一缺省句。
- 不能确认的非必填展示字段统一写“检索结果未载明”，不得自行解释。

## 失败处理

- 同一检索目标失败或空结果时只允许改写检索式重试一次。
- 在线接口连续失败时停止生成正式报告，说明无法取得可靠结果；不得改用虚构案例。
- 校验器报错时修正研究数据后重新校验，不得修改校验器以放宽单次任务。
- 渲染发现表格溢出或分页异常时只压缩内容至规范上限；不得改变列宽、字号或章节结构。
