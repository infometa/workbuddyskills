# 执行、结果与错误协议

选择同步/异步、轮询任务、解释返回值或处理失败时读取本文。

## 同步与异步

### 同步

解析和抽取默认传 `wait=true`，包括大文件、复杂文档和批量任务。`timeout_seconds` 默认 300，主动限制在 1～900 秒。

注意：`timeout_seconds` 是 MCP Node 客户端的 HTTP 中止计时，不是服务端任务取消。客户端超时后，服务端处理可能仍然继续，也可能已经扣费。

### 异步

只有用户明确指定异步处理时才传 `wait=false`。文件大小、复杂度或批量处理本身不构成切换异步的条件。

用户明确指定异步后：

1. 从顶层 `code` 判断任务创建请求是否成功。
2. 从 `data.task_id` 读取并持久保留本次任务 ID。
3. 保存创建时的 `accept_language`。
4. 使用相同语言调用 `query_task`。
5. 状态成功但查询未返回完整结果时，再调用一次 `get_result`。

`wait=false` 只切换到异步创建端点，不会由 MCP 自动轮询。

## 状态机

| `data.status` | 含义 | 动作 |
|---:|---|---|
| 0 | 未知 | 退避后有限复查；持续为 0 时返回结果不明 |
| 1 | 等待/排队 | 继续轮询 |
| 2 | 运行中 | 继续轮询 |
| 4 | 成功 | 停止轮询并读取结果 |
| 5 | 失败 | 立即停止，报告 `message/tips` |
| 6 | 已取消或拒绝 | 立即停止，报告终态 |

当前后端 DTO 只允许 0、1、2、4、5、6；公开 OpenAPI 中出现过的状态 3 与当前实现不一致。遇到 3 或其他未定义状态时，不要解释成“抽取中”；退避后有限复查，持续存在则按协议漂移停止并保留原值。

推荐轮询间隔为 2、4、8 秒，此后最多每 15 秒一次；服务返回 `Retry-After` 时以它为准。达到用户允许的等待时间后返回任务 ID 和最后状态，不要无限等待或创建新任务。

当前 `query_task` 与 `get_result` 实际使用同一查询端点。查询响应已经包含完整结果时，跳过 `get_result`。

## 成功校验

按以下顺序校验：

1. MCP 调用是否返回 `isError`。
2. 顶层 `code` 是否为 `success` 或服务当前定义的成功值。
3. 顶层 `message/tips` 是否表示业务异常。
4. 异步 `data.status` 是否为 4。
5. 目标结果数组是否实际存在。

不要仅凭 HTTP 200 或工具调用未抛异常宣称成功。

## 结果读取

### 解析结果

读取 `data.doc_recognize_result`：

- `page_num`：页码。
- `document_content`：按阅读顺序的页面文本。
- `document_details`：文本、表格、图片和坐标详情。
- `ocr_confidence`：存在时用于说明识别可靠度。

默认完整保留每一页、每个字段、每个数组项及其嵌套属性。不要只抽取正文或模型认为重要的页面属性，也不要合并不同页面中的重复字段。

### 抽取结果

读取 `data.extraction_result`：

- 普通字段通常有 `field_key`、`field_name`、`field_values`。
- 表格字段通常有 `table_values`。
- `references`、页码和置信度存在时作为证据使用，不要自行生成。

默认逐项输出 `data.extraction_result` 中的全部条目及每个条目的全部原始属性。不要只展示有值或高置信度字段，不要合并重复的 `field_key` / `field_name`，不要把表格压缩成摘要。字段不存在时明确写“响应未返回”，不要从其他字段猜值。

### 完整性核对

生成最终回答前执行无损核对：

1. 统计目标结果载荷的顶层字段数和字段数组项数。
2. 统计最终展示中可逐项对应的字段数；二者必须相等。
3. 对分页结果核对页数，对表格核对行、列和单元格数量，对嵌套数组核对每层元素数量。
4. 保留原始键名、顺序、层级、重复项和空值；格式转换不得造成字段丢失或合并。
5. 若 MCP 返回 25 个字段，最终展示也必须包含 25 个可核对字段。输出过长时分段继续，不得省略。

仅当用户明确列出字段子集或要求摘要时允许缩减，并在回答中说明已按用户要求筛选。

## 批量结果账本

每个文件至少记录：

```text
文件标识 | upload file_id/URL | 处理工具 | task_id | accept_language | 最后状态 | 是否成功 | 错误
```

成功、失败和结果不明必须分开。已成功文件不得因其他文件失败而重跑；只重试明确失败且符合重试条件的项目。

## 错误分类与动作

| 观察到的错误 | 动作 |
|---|---|
| `ADP_API_KEY is required.` | 停止，请用户重新连接/授权 Connector；不要索要 Key |
| `Accessor not found`、401、403 | 停止，检查 Key 的禁用、过期或区域问题 |
| 400、422 | 修正参数、文件或工具类型；不要原样重试 |
| 404 | 核对文件 URL、`task_id` 和区域；不要猜 ID |
| 429 | 遵守 `Retry-After`；只对明确未受理或只读调用做一次退避重试 |
| 5xx、网络断开 | 查询类调用最多再试一次；计费 POST 按“是否受理不明”处理 |
| 客户端超时 | 不等于服务端取消；没有 `task_id` 时标记结果不明 |
| `data.status=5/6` | 终止任务，不继续轮询或切换工具 |
| 顶层 `code` 非成功但 HTTP 200 | 按业务失败处理，报告 `message/tips` |

## 幂等性与重试

上传、同步处理和异步创建都没有暴露幂等键。

- 查询类 GET：临时失败可退避后额外重试一次。
- 上传：后端已对部分异常内部尝试最多两次；Agent 最多额外一次，可能产生新的文件 ID。
- 计费处理 POST：只有响应明确说明未受理时才可自动重试一次。
- 计费处理超时、断连或 5xx 且是否受理不明：不要自动重提。先查询已有 `task_id`；没有 ID 时向用户说明重复扣费风险并取得确认。
- 参数、格式、权限、余额不足和终态失败不是“等一会再试”问题；不要消耗重试预算。

## 停止后的报告

至少说明：

- 哪个文件和哪个工具失败。
- 实际 `code/status/message/tips` 或 MCP 错误文本。
- 是否获得 `file_id` 或 `task_id`。
- 结果是失败还是不明。
- 下一步需要用户做什么，或是否需要授权一次可能重复计费的重试。
