# 积分、认证与服务限制

估算积分、决定并发、判断消费授权、处理区域问题或认证失败时读取本文。

## 当前基础费率

| MCP 能力 | 积分/页 | 依据 |
|---|---:|---|
| `parse_document` | 关闭印章识别：0.5；文档解析 + 印章识别：1.0 | SaaS 文档解析计费，按实际启用状态区分 |
| `extract_china_invoice` | 0.8（票据抽取基础费率） | 验真成功时另收 0.5 积分/次，详见下方规则 |
| `extract_global_invoice` | 1.5 | 官网计费表和后端映射 |
| `extract_global_invoice_fast` | 1.0 | 后端高速海外映射 |
| `extract_sea_invoice_fast` | 1.0 | 后端东南亚高速映射 |
| `extract_purchase_order` | 1.5 | 官网计费表和后端映射 |
| 11 个卡证工具 | 0.5 | 官网计费表和后端逐项映射 |
| 标准或高速自定义抽取 | 通常 1.0 | 当前产品/后端基础映射；实际应用配置优先 |

### 印章识别

- 文档解析开启印章识别时，合计 **1 积分/页**，不是在 0.5 积分/页基础上再加 1 积分/页。
- 关闭印章识别时，文档解析为 **0.5 积分/页**。
- 无法确认印章识别开关状态时，分别说明两种费率，不要默认按 0.5 积分/页报价。是否启用以实际应用配置或服务响应为准；不要编造 MCP 未暴露的开关参数，也不要声称已经开启或关闭。

### 发票验真

- 票据抽取按 **0.8 积分/页**计费；发票验真另按 **0.5 积分/次**计费，**仅验真成功时收取**。
- 同一份发票无论包含多少页，仅需验真 1 次；文件内有多份独立发票时分别验真，不能把文件页数当作验真次数。
- **总消耗 = 0.8 × 文件页数 + 0.5 × 验真成功次数**。
- 未识别到发票或验真失败时，不收取验真积分；这不代表票据抽取也免费。
- v0.1.4 没有独立验真 MCP 工具，但不代表 SaaS 不收取验真费用。不要编造独立工具；只报告响应实际返回的验真状态，并按上述规则解释费用。验真成功次数未知时提供公式或条件估算，不要把预计成功次数当作实际扣费记录。

价格可能因活动、套餐、应用配置和后续产品调整而变化。实际控制台与扣费记录高于本表；用户未要求报价时，不必在每次正常处理前复述完整费率。

## 消费授权

按以下边界执行：

- 用户明确要求处理一个文件：授权对该文件执行一次最小充分的计费处理。
- 用户明确要求处理一个批次：授权每个明确输入执行一次最小充分的计费处理，并受并发上限约束。
- 上传、查询应用和查询任务不是再次选择另一个文档处理能力；仍要避免无界调用。
- 再调用第二种处理工具、扩大批次、重跑成功项或重跑结果不明项：属于新增消费，先解释并确认。
- 不要仅凭 Key 已配置、账户已登录、免费额度存在或曾经允许调用，推断用户允许额外消费。

如果页数、印章识别启用状态或验真成功次数未知，提供对应的计费公式或条件估算，不要编造总价；涉及发票验真时必须同时计入按次收取的费用，不能只计算按页费用。

## 免费额度与余额

- 社区版当前每月刷新至 100 免费积分，上月余额不结转。
- 100 积分不等于固定 100 页：0.5、0.8、1.0、1.5 积分/页对应的可处理页数不同。
- 官方 OpenAPI 有积分查询接口，但 v0.1.4 没有注册对应 MCP 工具。
- `adp credit` 是其他接入面的命令，不是当前 MCP 工具。不要尝试调用，也不要声称知道 `remaining_credits`。
- 余额不足时停止，引导用户前往 ADP 控制台查看或充值。

## 并发

文档处理并发默认值：

| 账户状态 | 最大处理并发 |
|---|---:|
| 默认处理窗口 | 10 |

把 10 用作安全的文档处理窗口，不要描述成上传路由的硬限制或 SLA。

大文件仍以客户端和服务端内存为约束，将上传并发降至 1～2。超出 10 或需要稳定高并发 SLA 时停止扩容并建议商务确认，不要自行压测生产服务。

## 认证边界

WorkBuddy 通过 Connector 托管 `ADP_API_KEY`，MCP 使用该环境变量并发送 `X-API-KEY`。执行以下规则：

- 不要求用户把 Key 作为 `file`、`chunk`、`app_id` 或任何工具参数。
- 不在回答、调试输出或持久文件中打印 Key。
- 缺少 Key 时让用户重新连接 Connector。
- `Accessor not found` 可能表示 Key 禁用、过期、环境错误或区域不匹配；让用户在相应区域控制台重新授权，不要静默切换身份。
- 不要把官方远程 MCP 的 URL Query Key 形式混入本地 stdio Connector 配置。

## 区域和语言

| `accept_language` | MCP 域名 | 使用场景 |
|---|---|---|
| `zh` | `https://adp.laiye.com` | 中国区，默认 |
| `en` | `https://adp-global.laiye.com` | 全球区 |

创建异步任务、查询状态和获取结果时必须保持相同值。Key 与区域不匹配时停止并让用户修正授权。

当前 `upload_temporary_file` Schema 不暴露 `accept_language`，它使用 Connector 环境配置或默认中国区；当前 WorkBuddy Connector 默认只注入 API Key。全球区本地文件必须在调用前确认进程已配置 `ADP_ACCEPT_LANGUAGE=en`。未配置时不要先试错，也不要给上传工具添加不存在的参数；停止并请用户配置全球区 Connector，或提供 HTTP(S)/Base64 输入。

## 文件产品限制

- 中国区公开产品合同当前写每份不超过 260 页、50 MB。
- 英文合同仍写每份不超过 100 页、50 MB。
- 上传存储层本身的部署配额可能更高，但不代表后续解析/抽取支持。
- 跨区域未知时使用 100 页、50 MB 的保守上限；已确认中国区时可以按 260 页、50 MB 提示。
