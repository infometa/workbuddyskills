# 深知可信工作台 MCP

当用户咨询法律法规、政策文件、国家或行业标准、产业研究、公共服务事项，或提出其他需要可信依据的问题时，按下述规则选择工具。对复杂问题，应先拆解检索任务，再结合多来源材料交叉验证，并将关键结论追溯到权威原文。一般情况下优先使用轻量工具，避免不必要的长耗时调用。

当前 MCP Server 提供 3 个工具：

- `credible_chat`：可信问答
- `trusted_search`：可信搜索
- `deep_query`：深度搜索

工具调用时使用原始 MCP Tool 名称。WorkBuddy 界面里可能会自动显示连接器前缀，例如：

- `dknowc-mcp_credible_chat`
- `dknowc-mcp_trusted_search`
- `dknowc-mcp_deep_query`

## 工具选择

### 工具选择规则

按以下优先级判断：

1. 一般咨询、解释法律政策或办事流程、回答明确的单点问题，使用 `credible_chat`。
2. 用户要求搜索材料、查找政策文件、法律法规、标准、具体条款、原文、发布机关、依据或链接时，使用 `trusted_search`。
3. 用户明确要求深度研究、系统梳理、多地区或多文件对比，或任务本身需要拆解多个子问题并交叉验证时，使用 `deep_query`。
4. 不要仅因为问题涉及政策、地区较多或需要引用来源就调用 `deep_query`；可以由 `credible_chat` 或 `trusted_search` 可靠完成的，优先使用前两者。
5. 使用 `deep_query` 时应围绕子问题拆解检索，并对影响结论的关键事实进行多来源验证和权威原文溯源。

### credible_chat

用于一般性的法律、政策、标准或公共服务咨询，直接回答用户提出的明确问题。

适合：

- 法律政策问答
- 公共服务和办事咨询
- 条件或材料清单说明
- 需要可信溯源报告链接的回答

最小参数：

```json
{
  "query": "深圳市住房公积金租房提取目前需要满足哪些条件、准备哪些材料？"
}
```

常用参数：

```json
{
  "query": "深圳市住房公积金租房提取目前需要满足哪些条件、准备哪些材料？请引用现行政策原文并附权威来源链接。",
  "area": "深圳",
  "interpretation_model": "autoModel",
  "show_reasoning": false
}
```

### trusted_search

用于搜索权威材料、政策文件、法律法规、国家或行业标准、具体条款、公共服务事项和原文链接。

适合：

- 用户要求搜索权威材料
- 用户要求查找具体文件或原文
- 用户要求列出法律、政策或标准依据
- 用户要求返回知识专库或权威来源链接

最小参数：

```json
{
  "query": "GB/T 35273—2020《信息安全技术 个人信息安全规范》个人信息保存期限和删除要求"
}
```

常用参数：

```json
{
  "query": "GB/T 35273—2020《信息安全技术 个人信息安全规范》对个人信息保存期限和删除有哪些要求？请列出对应原文条款及权威来源链接。",
  "max_articles": 5
}
```

### deep_query

用于用户明确要求的复杂法律、政策、标准或产业研究，以及跨地区、跨文件材料梳理和较长链路查证（非流式同步接口，复杂任务耗时通常在数十秒级），不作为默认工具。使用时应围绕子问题拆解检索，并对关键事实进行多来源交叉验证和权威原文溯源。

适合：

- 复杂法律、政策或标准问题的系统研究
- 多地区、多文件或多时间范围的政策对比（`areas` 数组原生支持一次传入多个地域）
- 需要拆解子问题并汇总多来源证据
- 需要核对关键事实并追溯权威原文
- 需要形成产业研究或公共服务研究基础材料

参数（v3）：

- `query`（必填）：复杂研究问题
- `areas`（可选）：地域数组，例如 `["北京市"]` 或 `["北京市", "上海市", "深圳市"]`
- `queryId`（可选）：查询标识，缺省由接口自动生成

最小参数：

```json
{
  "query": "研究2024年以来国家层面支持低空经济发展的主要政策。"
}
```

常用参数：

```json
{
  "query": "请研究2024年以来国家层面支持低空经济发展的主要政策，拆解政策目标、重点任务和适用领域，结合多份权威来源交叉验证并追溯原文。"
}
```

返回结构：`data.searches`（按子问题分组的检索结果，每组含 `query`、`areas`、`result` 材料数组，材料字段为文章标题/源网址/数据源/发布日期/发布日期可信度/段落）、`data.common_articles`（通用参考材料）。材料均带原文链接，回答时保留。

## 调用示例

### 示例 1：可信问答

用户问：

```text
请使用深知可信工作台查询：深圳市住房公积金租房提取目前需要满足哪些条件、准备哪些材料？请引用现行政策原文并附权威来源链接。
```

调用 `credible_chat`：

```json
{
  "query": "深圳市住房公积金租房提取目前需要满足哪些条件、准备哪些材料？请引用现行政策原文并附权威来源链接。",
  "area": "深圳"
}
```

### 示例 2：可信搜索

用户问：

```text
请使用深知可信工作台检索：GB/T 35273—2020《信息安全技术 个人信息安全规范》对个人信息保存期限和删除有哪些要求？请列出对应原文条款及权威来源链接。
```

调用 `trusted_search`：

```json
{
  "query": "GB/T 35273—2020《信息安全技术 个人信息安全规范》对个人信息保存期限和删除有哪些要求？请列出对应原文条款及权威来源链接。",
  "max_articles": 5
}
```

### 示例 3：深度研究

用户问：

```text
请使用深知可信工作台研究：2024年以来国家层面支持低空经济发展的主要政策有哪些？请拆解政策目标、重点任务和适用领域，结合多份权威来源交叉验证并追溯原文。
```

调用 `deep_query`：

```json
{
  "query": "请研究2024年以来国家层面支持低空经济发展的主要政策，拆解政策目标、重点任务和适用领域，结合多份权威来源交叉验证并追溯原文。"
}
```

## 回答要求

- 调用工具后，基于工具返回结果回答用户。
- 复杂问题先拆解为清晰的子问题或核验点，再分别检索、汇总和作答。
- 对影响结论的关键事实，尽可能使用两个或以上相互独立的来源交叉验证；如果只能找到单一来源，应明确说明。
- 法律、政策和标准问题优先引用制定机关、发布机关、官方标准信息平台或其他权威渠道的原文；二手解读只能作为补充，不替代原文依据。
- 每项关键结论应尽量对应具体来源，不得用无关链接或笼统参考资料代替逐项依据。
- 区分工具返回的原文、检索摘要和模型归纳；不要把摘要当作原文，不要擅自补充工具未返回的具体条件。
- 如果来源存在版本、有效期、适用范围或解释冲突，应明确说明，不能强行合并为单一结论。
- 如果工具返回了可信溯源报告、知识专库或原文链接，应在回答中保留链接。
- 如果用户明确要求“只调用工具，不要自行回答”，则只展示工具返回结果。
- 不要向用户索要 API Key、access token 或其他连接凭证。
- 如果工具返回空结果，明确说明未检索到可用材料，并建议用户补充地区、时间范围或更具体的关键词，不要编造结论。
- 如果工具调用失败、超时或触发限流，简要说明当前查询未完成，可建议稍后重试或缩小查询范围，不要把认证凭证或服务端内部错误直接展示给用户。
- 检索与研究结果仅提供信息和依据参考，不保证办理、申报、审批、合规审查等外部结果；法律相关回答不替代律师意见、行政机关解释或司法裁判。
- 产业研究只基于检索材料归纳政策环境、标准要求、产业信息和公开事实，不承诺企业经营结果、市场竞争结果或投资收益。
