# 卡片 JSON 模板（数电票**开具**场景 · 默认输出形态 · 直接复制改数值）

> 🚨 有数据要展示时**默认走本文件**。模板结构固定，**只改数值和文案**，
> 数值一律来自 `scripts/calc_amount.py` 的输出（见 SKILL.md 第八节）。
> 每个模板都必须配 `scripts/check_card.py --reference` 自检通过后才可输出。

通用规则：
1. 根节点固定 `{"type": "Card", "children": [...]}`，一条消息只一个 Card。
2. 顺序固定：顶部 `Text` 结论 / `Descriptions` 范围 → 中部 `Descriptions` 字段或 `Table`。
3. **不展示数据口径说明**——单价、合计的口径是内部定义，不写在卡片上。
4. 金额已是元（接口原值为分，已 ÷100），带 `¥`；数量按实际单位（「1 个」「2 件」「1 升」）。
5. 文案里不得出现接口名、参数名、字段名（`total_fee`、`out_trade_no`、`goods_id` 等）。
6. **字段一律不换行、不滑动**：渲染时标签 `white-space:nowrap`，值列 `white-space:nowrap`
   （**禁止 `overflow-x:auto` 横向滚动**），默认按一行完整铺开展示，一行放不下就加宽容器。
7. **待确认清单底部不放确认按钮**——确认必须来自用户明确的文字指令。

## 模板一：开票信息清单（待确认，最常用）

```json
{
  "type": "Card",
  "props": { "title": "开票信息确认" },
  "children": [
    { "type": "Text",
      "props": { "content": "开票信息确认一下～确认无误的话回复「确认」，我马上提交 😊" } },
    { "type": "Descriptions",
      "props": { "items": [
        { "label": "🏷️ 抬头类型", "content": "个人" },
        { "label": "🧾 发票抬头", "content": "李小羊" },
        { "label": "📦 商品", "content": "包子" },
        { "label": "🗂️ 税收类目", "content": "-" },
        { "label": "📊 税率", "content": "13%" },
        { "label": "💰 单价", "content": "¥0.01" },
        { "label": "🔢 数量", "content": "1 个" },
        { "label": "🧮 合计", "content": "¥0.01" },
        { "label": "📬 接收邮箱", "content": "lxy@example.com" }
      ] } }
  ]
}
```

- 字段顺序**固定**：抬头类型 → 发票抬头 → 商品 → 税收类目 → 税率 → 单价 → 数量 → 合计 → 接收邮箱。
- 订单开票时在顶部加一条 `Descriptions` 带订单号与交易时间：
  `{ "label": "📋 订单号", "content": "2026101312345678" }`。
- **订单开票金额以订单为准**，商品/税率按 SKILL.md 3.4 顺序读默认商品税率并与用户确认；**⛔ 禁止挑商品凑单价×数量倒推金额**。
- 成品油场景「数量」写「1 升」「2 升」，单价取 `invoice_oilGunLatestPrice` 的最新生效价。
- 税收类目取不到填 `-`，不编造。
- **底部不加按钮**。

> ★ **九项字段一项都不许少**。查不到的值写「待补充」，**不允许整行省略**。
> `check_card.py` 会校验九项齐全（`INFO-FIELDS-MISSING`），缺项直接判 ERROR。

```json
{
  "type": "Card",
  "props": { "title": "开票信息确认" },
  "children": [
    { "type": "Text",
      "props": { "content": "商品和税率待扫呗侧确认，其余信息请核对一下～" } },
    { "type": "Descriptions",
      "props": { "items": [
        { "label": "🏷️ 抬头类型", "content": "待补充" },
        { "label": "🧾 发票抬头", "content": "李小羊" },
        { "label": "📦 商品", "content": "待补充" },
        { "label": "🗂️ 税收类目", "content": "待补充" },
        { "label": "📊 税率", "content": "待补充" },
        { "label": "💰 单价", "content": "待补充" },
        { "label": "🔢 数量", "content": "待补充" },
        { "label": "🧮 合计", "content": "¥86.00" },
        { "label": "📬 接收邮箱", "content": "待补充" }
      ] } },
    { "type": "Alert",
      "props": {
        "type": "warning",
        "content": "商品、税率、单价、数量需要扫呗侧商品清单确认，完成「扫呗商户服务」授权后我立刻补齐～"
      } }
  ]
}
```

- **合计行永远有值**：订单金额来自订单（÷100，`calc_amount.py` 取值），不因商品税率缺失而缺席。
- 「待补充」是占位说明不是数据——**绝不编造商品名或税率去填**。
- 若用户已授权口径（「商品按店里常用的来就行」），则商品/税率**写实际用的值**，
  并在顶部 `Text` 说明来源是「按您说的口径」，**不改写成「待补充」**。

## 模板四：订单明细

```json
{
  "type": "Card",
  "props": { "title": "订单明细" },
  "children": [
    { "type": "Text",
      "props": { "content": "今天（10月13日）共 3 笔订单～" } },
    { "type": "Table",
      "props": {
        "columns": ["订单号", "订单金额", "交易时间", "门店", "支付状态"],
        "rows": [
          ["2026101312345678", "¥86.00", "10-13 12:34:56", "中心广场店", "支付成功"],
          ["2026101312345987", "¥120.00", "10-13 13:02:10", "中心广场店", "支付成功"]
        ]
      } }
  ]
}
```

- 表格只读，行内不放按钮、输入框、选择框、下载入口。
- 列数 1—6，行数 ≤10；超出时只放前 10 行并在底部用一句 `Text` 说明节选情况。
- **卡片以表格收尾**：底部不再放「总条数 / 是否节选」的 `Descriptions`
  （顶部结论句已含笔数，重复了）。
- **渲染留白**：容器宽度 `520px`；
  列宽 订单号 32% / 订单金额 12% / 交易时间 21% / 门店 17% / 支付状态 18%；
  每列 `padding-right:12px`（最后一列 0），单元格上下 `padding:9px 12px 9px 0`；
  订单号列用等宽字体单行展示。**否则 20 位订单号会与金额列粘连。**
- **单笔订单字段顺序固定（定稿，按用户截图从上到下）**：
  交易时间 → 门店 → 支付方式 → 交易金额 → 交易状态 → 商户订单号 → 渠道订单号。
  订单号拆成两行完整展示，**不得**压缩成一行、不得省略号截断。
- **查单笔订单时严禁附带汇总数据**（今日总笔数、总金额）——单笔场景改用
  `Descriptions`（交易时间/门店/支付方式/交易金额/交易状态/商户订单号/渠道订单号），不用 `Table`。
- **不展示「查询时间」「查询范围」字段**（定稿，适用所有场景）：
  查询时照常显式传 `begin_time`/`end_time` 取数，但卡片上不出现查询口径字段。
- ⛔ **单笔订单卡片不加结论句**（定稿）：标题已说明「最新一笔微信订单」，
  再写「最新一笔微信订单是 18:33:50 这笔」是重复。单笔卡片结构 =
  `Card(title)` + `Descriptions`，中间不加 `Text`。
- 支付状态只写「支付成功 / 支付中 / 已撤销 / 支付失败」。

## 模板五：异常 / 未开通 / 失败提示

```json
{
  "type": "Card",
  "props": { "title": "开票服务状态" },
  "children": [
    { "type": "Descriptions",
      "props": { "items": [
        { "label": "📋 订单号", "content": "2026101312345678" },
        { "label": "📬 接收邮箱", "content": "lxy@example.com" }
      ] } },
    { "type": "Alert",
      "props": {
        "type": "warning",
        "content": "当前开票服务暂时异常，我已经把您确认过的开票信息保留好了，稍后回复「重试」我就直接提交～"
      } }
  ]
}
```

- 数电票未开通 → `Alert` 内容：「当前商户还没有开通数电票功能哦～」（`type` 用 `warning`）。

- 降级时**不得**出现接口没返回的金额与笔数。
- 授权引导只写「扫呗商户服务」，不出现内部部署标识等技术信息。

## 自检命令

```bash
# 取权威数值（分 → 元），带标签，基准与卡片字段才能逐一比对
python <技能目录>/scripts/calc_amount.py one 8600 合计 > ./ref.txt     # → 合计：¥86.00
# 基准文件可写多行「标签：¥金额」，check_card.py 会与卡片同名标签逐一比对：
#   合计：¥0.01
#   单价：¥0.01
#
# ★ 基准与卡片文件都写在当前工作目录（相对路径）。
#   不要用 /tmp/... —— Windows 上 Python 会把 /tmp 解析为当前盘符根目录的 \tmp，
#   该目录通常不存在，实测会抛 FileNotFoundError。

# 卡片自检
python <技能目录>/scripts/check_card.py ./card.json --reference ./ref.txt
```

ERROR 必须清零后才能输出。退出码：`0` 通过（可能含 WARN）、`1` 有 ERROR、`2` 用法错误（基准文件不存在/参数错）。
