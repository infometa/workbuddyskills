# 卡片 JSON 模板（默认输出形态 · 直接复制改数值）

> 🚨 **列表/详情/发送结果类**有数据要展示时**默认走本文件**。模板结构固定，**只改数值和文案**，
> 数值一律来自 `scripts/calc_amount.py` 的输出（见 SKILL.md 8.1）。
> 每个模板都必须配 `scripts/check_card.py --reference` 自检通过后才可输出。
>
> ⚠️ **开票汇总数据不需要卡片**：模板一仅作口径与顺序参考，
> 汇总请直接用 `output-templates.md` 的「汇总文字模板」输出文字，不要生成汇总 Card。

通用规则：
1. 根节点固定 `{"type": "Card", "children": [...]}`，一条消息只一个 Card。
2. 顺序固定：顶部 `Descriptions`（查询时间、查询范围）+ `Text` 结论 → 中部 `Table`。
3. **查询时间与查询范围放在数据上方**（顶部 `Descriptions`），让商户先看到查的是哪段时间、哪个范围。
4. **不展示数据口径说明**——开票金额 / 有效开票金额的口径是内部定义，不写在卡片上。
5. 明细/详情卡里的金额标签用「发票金额」；基准文件里的「开票金额 / 有效开票金额 / 蓝票 / 红票」
   用于汇总文字形态比对，`check_card.py` 按同名标签逐项比对。
6. 金额已带 `¥`，数量一律带「张」或实际单位。
7. 金额已是元（接口原值为分，已 ÷100）。
8. 文案里不得出现接口名、参数名、字段名。
9. **汇总数据不用卡片**（`Statistic` 汇总卡已废止）；现有模板只用 `Descriptions` / `Text` / `Table` / `Alert` / `Button`。

## 模板一：开票汇总 — **不用卡片，仅供参考口径**

> 🚨 汇总卡片已废止。下面只用来说明指标**口径与顺序**，
> **不得**据此生成 JSON 卡片，实际输出走 `output-templates.md` 8.0/1.1 的纯文字模板。
> 保留此段只为让「开票数量 → 开票金额 → 有效开票金额 → 蓝票 → 红票」的口径有据可查。

口径与顺序（文字模板的取值规范）：

| 顺序 | 指标 | 取值 |
|---|---|---|
| 1 | 开票数量 | `calc_amount.py` 的「开票数量」 |
| 2 | 开票金额 | \|蓝票\| + \|红票\| |
| 3 | 有效开票金额 | \|蓝票\| − \|红票\| |
| 4 | 蓝票（正常开具） | 张数 + \|蓝票金额\| |
| 5 | 红票（红冲） | 张数 + \|红票金额\| |

指定门店时，文字模板的「查询范围」填门店真实名称。

## 模板二：发票明细表格

```json
{
  "type": "Card",
  "props": { "title": "9月11日发票明细" },
  "children": [
    { "type": "Descriptions",
      "props": { "items": [
        { "label": "📅 查询时间", "content": "2026年9月11日" },
        { "label": "🏪 查询范围", "content": "整个商户" }
      ] } },
    { "type": "Text",
      "props": { "content": "共 6 张，全部列出" } },
    { "type": "Table",
      "props": {
        "columns": ["发票号码", "发票金额", "发票类型", "开票状态", "开票时间"],
        "rows": [
          ["26427200000007146676", "¥0.01", "蓝票（正常开具）", "开票成功", "2026-09-11 10:57:13"],
          ["26427200000007146675", "¥0.01", "红票（红冲）", "已红冲", "2026-09-11 10:56:29"]
        ]
      } }
  ]
}
```

规则：
- 表格只读，行内不放按钮、输入框、选择框、下载入口。
- 列数 1—6，行数 ≤20；超出时只放前 20 行并在 Descriptions 说明总数。
- 发票号码完整展示，禁止省略号截断。
- 开票状态只写「开票成功 / 开票中 / 开票失败 / 已红冲 / 红冲中 / 红冲失败」（**红冲**，不写「冲红」）。
- 开票来源只写「自定义开票 / 订单开票 / 物料码开票 / 扫码开票」。
- 需要加「开票来源」列时列数最多 6，注意 Table 列数上限。
- **底部 Descriptions 省略**：顶部结论句「共 6 张，全部列出」已含总数信息，
  底部再放「总条数 / 是否节选」是重复。仅当数据超过 20 行被节选时，才在底部用一句 Text 说明节选情况。
- **金额列取绝对值展示**（红票写 `¥6.00`，不写负号）；负号只出现在「红票（红冲）」语义中。
- 等效 HTML 渲染（show_widget）时，根节点用
  `display:inline-block; width:100%; max-width:100%;`（表格类用 100%，不是详情类的 280px），
  表格 `table-layout:fixed` + colgroup 固定列宽（号码 29% / 金额 13% / 类型 20% / 状态 15% / 时间 23%），
  金额列左对齐紧跟号码列，各列 `white-space:nowrap`。

## 模板三：单张发票详情

```json
{
  "type": "Card",
  "props": { "title": "发票详情" },
  "children": [
    { "type": "Text",
      "props": { "content": "发票号码 26427200000007146676" } },
    { "type": "Descriptions",
      "props": { "items": [
        { "label": "💰 发票金额", "content": "¥0.01" },
        { "label": "📄 发票类型", "content": "蓝票（正常开具）" },
        { "label": "✅ 开票状态", "content": "开票成功" },
        { "label": "🛒 开票来源", "content": "订单开票" },
        { "label": "🕐 开票时间", "content": "2026-09-11 10:57:13" },
        { "label": "🏢 购方名称", "content": "小米汽车有限公司" }
      ] } }
  ]
}
```

- **卡片内不放「📥 下载发票 PDF」等纯文字入口**（死文字点不了，见 SKILL.md 7.6 第 8 条）。
  PDF 一律通过文件交付通道（present_files / 附件）发给用户。
- `invoice_url` 为空时，正文一句话说明「这张发票暂时还没有生成 PDF 哦，开具完成后就可以下载啦～」，不编造链接。
- 下载只在用户明确要求时提供，汇总/明细卡片里不主动给。

## 模板四：无数据 / 异常提示

```json
{
  "type": "Card",
  "props": { "title": "9月11日开票情况" },
  "children": [
    { "type": "Descriptions",
      "props": { "items": [
        { "label": "查询时间", "content": "2026年9月11日" },
        { "label": "查询范围", "content": "整个商户" }
      ] } },
    { "type": "Alert",
      "props": { "type": "info", "content": "9月11日没有开票哦～" } }
  ]
}
```

- 确实无开票：`type` 用 `info`。
- 接口异常 / 连接器不可用：`type` 用 `warning`，文案写「开票数据暂时取不到」，并给出授权恢复动作；
  **不得**写金额、笔数、发票号码，**不得**说「没有开票」，**不得**断言「未开通数电票」。
- 降级时仍须在顶部给出「查询时间」和「查询范围」。

## 模板五：后续动作选择（最多一组 Button）

```json
{
  "type": "Card",
  "props": { "title": "还需要看什么？" },
  "children": [
    { "type": "Text",
      "props": { "content": "可以继续查看明细或下载发票 PDF" } },
    { "type": "Button", "props": { "label": "查看发票明细", "action": "detail" } },
    { "type": "Button", "props": { "label": "下载发票 PDF", "action": "download" } }
  ]
}
```

- 整条消息最多一组 Button，点击后直接继续对话，不再加统一确认按钮。
- Button 不得模拟多选提交。

## 模板六：发票发送到邮箱结果（必配，字段不换行）

```json
{
  "type": "Card",
  "props": { "title": "邮件发送成功" },
  "children": [
    { "type": "Descriptions",
      "props": { "items": [
        { "label": "发送方式", "content": "扫呗电子发票邮箱服务" },
        { "label": "收件邮箱", "content": "lxy@example.com" },
        { "label": "发票号码", "content": "26427200000007146980" },
        { "label": "发票流水号", "content": "309106260020261021162556000001" },
        { "label": "发票类型", "content": "红票（红冲）" },
        { "label": "发票金额", "content": "¥0.02" },
        { "label": "发送状态", "content": "邮件发送成功" },
        { "label": "发送时间", "content": "2026-10-21 16:53" },
        { "label": "凭证号", "content": "f52973cad07a4643b3eccd1fbd4afd87" }
      ] } }
  ]
}
```

规则：
- 发送只走扫呗自带接口 `invoice_sendEmail`（见 SKILL.md 第十二节），
  不支持换发件箱、不引导连接器安装。
- **所有字段单行不换行**：标签列 100px + `white-space:nowrap`，
  值列 `white-space:nowrap; overflow-x:auto`；28 位流水号、20 位发票号码、32 位凭证号
  全部单行完整展示（折行观感差）。
- 图标：📨 发送方式 / 📬 收件邮箱 / 🔢 发票号码 / 🔗 发票流水号 / 📄 发票类型 /
  💰 发票金额 / ✅ 发送状态 / 🕐 发送时间 / 🧾 凭证号。
- 金额已是元（接口原值为分，已 ÷100）；凭证号取接口返回的 `trace_no`，如实展示。
- **批量发送时只出一张汇总卡**：字段用「发送方式 / 收件邮箱 / 发送张数 / 发票日期 / 发送状态」，
  正文另列「流水号 → 凭证号」对应关系，便于对账；部分失败要如实列出失败的流水号，
  不得笼统说「已全部发送」。

## 自检命令

```bash
# 中间文件写在当前工作目录（相对路径）。不要用 /tmp/...：
# Windows 上 Python 会把 /tmp 解析为当前盘符根目录的 \tmp，该目录通常不存在，实测抛 FileNotFoundError。
python <技能目录>/scripts/calc_amount.py list '<invoice_list JSON字符串>' > ./ref.txt
python <技能目录>/scripts/check_card.py ./card.json --reference ./ref.txt
```

ERROR 必须清零后才能输出。
