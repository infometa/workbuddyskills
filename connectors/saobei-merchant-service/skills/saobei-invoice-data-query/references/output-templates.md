# 输出模板与对话示例（汇总用文字；卡片场景降级时用文字）

> 🚨 **本文件承担两类用途：**
> ① **开票汇总场景默认就用本文件的文字模板**（汇总不需要卡片）；
> ② 卡片形态无法产出时的降级形态，此时需在回复中说明原因。
> 发票明细 / 单张详情 / 发送结果仍用卡片（`SKILL.md` 第七节 + `genui-card-spec.md`）。
> 特别提醒：不要因为「当前环境没有原生卡片渲染器」就直接走文字形态——
> 正确做法是生成 card.json → check_card.py 自检 → 等效可视化渲染（见 SKILL.md 零·一 强提醒 2）。
>
> 首选形态是卡片，编排规范见 `@references/genui-card-spec.md`。
> 两种形态的**字段、顺序、口径、数值完全一致**，数值都取自 `scripts/calc_amount.py`。
>
> 🚫 **输出风格（最高优先级）**：回复只给数据和结论。
> 不写主观解读、「几点观察」、猜测性归因，不在结尾追加「需要我帮你…吗」这类主动引导句。
> 详见 `SKILL.md` 零·二，脚本侧由 `check_reply.py` 的 STYLE-SUBJECTIVE / STYLE-INVITE 规则拦截。

> 本文件所有门店名称、发票号码、金额、邮箱均为**脱敏示例值**，不代表任何真实商户数据。直接套用模板时必须替换为接口实际返回值。

> ⚠️ **模板中的金额单位是「元」。接口返回的金额单位是「分」，展示前必须 ÷100。**
> 模板里的数值仅示意版式，**真实数值一律以 `scripts/calc_amount.py` 的输出为准**，
> 不得把接口原始值（分）直接填进模板。
> 口径：`开票金额` = |蓝票| + |红票|，`有效开票金额` = |蓝票| − |红票|。


> **开票汇总数据不需要卡片。** 汇总场景直接用本文件的文字模板输出指标行；
> 发票明细 / 单张详情 / 发送结果等场景用卡片（见 `card-templates.md`）。

## 一、汇总输出模板（汇总不需要卡片，直接用本节文字模板）

### 1.1 整个商户有开票数据

```
📅 查询时间：2026年9月7日～9月13日
🏪 查询范围：整个商户

🔢 开票数量：6 张
💰 开票金额：¥18.00
💵 有效开票金额：¥6.00
🔵 蓝票（正常开具）：4 张，¥12.00
🔴 红票（红冲）：2 张，¥6.00
```

（版式：标题行只保留「📅 查询时间」「🏪 查询范围」两行，
指标用 🔢 开票数量 / 💰 开票金额 / 💵 有效开票金额 / 🔵 蓝票 / 🔴 红票，
「张」前留一格空格。不加「📊 上周开票情况」这类小标题。）

规则：
1. 固定顺序：开票数量 → 开票金额 → 有效开票金额 → 蓝票 → 红票，**不可调整**。
2. **有效开票金额 = |蓝票金额| − |红票金额|**，必须用脚本算，禁止心算。
3. 有效开票金额必须**紧跟在开票金额之后**。
4. 金额带 `¥`，数量带「张」。
5. 商户有多家门店时，继续按门店展示实际有数据的门店（见 1.5）。

### 1.2 指定门店有开票数据

```
🏪 A门店

📅 查询时间：2026年9月11日

🧾 开票数量：3张
💰 开票金额：¥18.00
💰 有效开票金额：¥6.00
🔵 蓝票（正常开具）：2张，¥12.00
🔴 红票（红冲）：1张，¥6.00
```

门店名称必须使用接口返回的真实名称，不使用占位符。

### 1.3 查询时间内没有开票

不使用「暂无符合条件的开票记录」，按时间自然生成：

```
😊 上周没有开票哦～

📅 查询时间：2026年9月7日～9月13日
🏪 查询范围：整个商户
```

按时间范围替换首句：

| 时间范围 | 话术 |
|---|---|
| 今天 | 今天没有开票哦～ |
| 昨天 | 昨天没有开票哦～ |
| 本周 | 本周没有开票哦～ |
| 这个月 | 这个月没有开票哦～ |
| 上周 | 上周没有开票哦～ |
| 自定义范围 | 9月10日到9月15日没有开票哦～ |

> ⚠️ 仅在接口 `return_code = "01"` 且计数确实为 0 时使用。接口异常、连接器不可用时**不得**使用本模板，走 1.6 降级交付。

### 1.4 商户未开通数电票

**仅在 `invoice_getSwitchByType` 确认 `invoice_switch = 0` 时**使用：

```
当前商户还没有开通数电票功能哦～
```

不追加技术原因解释，不列下一步选项。

**注意：连接器未授权不属于此情况。** `invoice_switch` 调用失败也不属于——那是状态未知，走 1.6 降级交付。

### 1.5 多门店展示规则

有数据门店单独展示，无数据门店统一归纳：

```
🏪 A门店

🧾 开票数量：3张
💰 开票金额：¥18.00
💰 有效开票金额：¥6.00
🔵 蓝票（正常开具）：2张，¥12.00
🔴 红票（红冲）：1张，¥6.00

📍 其余9家门店当天没有开票：

B门店、C门店、D门店、E门店、F门店、G门店、H门店、I门店、J门店
```

规则：
1. 有数据门店单独成组展示完整数据。
2. 无数据门店统一归纳，名称完整列出，不省略。
3. 不为每一家无数据门店单独展示一组数据。
4. 不使用宽表格，改用分组与换行。
5. 不主动展示与本次查询无关的门店信息。

### 1.6 降级交付（连接器不可用 / 授权失效 / 接口异常）

**这是补充，不是替代。** 必须先给出能确定的范围信息，再说明取不到数据。

```
😊 好的呢～我先把查询范围确认一下：

📅 查询时间：2026年9月7日～9月13日
🏪 查询范围：整个商户

开票数据暂时取不到，需要先完成「扫呗商户服务」授权才能继续～
请在对话窗口左下角的连接器面板中找到「扫呗商户服务」并完成授权，
授权完成后告诉我一声，我马上帮你把这段时间的开票情况查出来～ ✨
```

规则：
1. **必须包含**：确切查询时间范围、查询范围、取不到数据的说明、恢复动作。
2. **禁止出现**：任何金额/笔数/发票号码、「XX 没有开票哦～」、「商户未开通数电票」、技术过程描述。
3. **禁止**一上来就只丢授权引导，把时间范围和查询范围都跳过。
4. 时间范围换算不依赖网络，即使接口不可用也必须准确给出。
5. ⚠️ 连接器一律称**「扫呗商户服务」**（面板中的展示名），**不得**说出
   接口名、参数名、内部字段名等技术标识——商户找不到这些名字。
6. 用户找不到该连接器时，说明它属于扫呗商户服务侧的授权入口，如实提示连接器暂不可用。

### 1.7 发票明细

仅在用户明确要求查看明细时展示：

```
可以，我把发票明细整理给你啦～🧾

🧾 发票 1
发票号码：26427200000000000001
发票金额：¥0.01
发票类型：蓝票（正常开具）
开票状态：开票成功
开票来源：自定义开票
开票时间：2026-09-11 10:57:13

🧾 发票 2
发票号码：26427200000000000002
发票金额：¥6.00
发票类型：红票（红冲）
开票状态：已红冲
开票来源：订单开票
开票时间：2026-09-11 11:05:21
```

规则：
1. 发票号码必须完整展示，禁止「……001」「…001」。
2. 标题使用 `🧾 发票 1` 格式，不使用单独成行的「①」「②」。
3. 发票类型使用统一表述：蓝票（正常开具）、红票（红冲）。
4. 开票状态使用统一表述：开票成功 / 开票中 / 开票失败 / **已红冲 / 红冲中 / 红冲失败**。

   ⚠️ 接口枚举是「已冲红 / 冲红中 / 冲红失败」，**展示时必须转为「红冲」**，不可直接透传接口文案。
5. 开票来源使用统一表述：自定义开票 / 订单开票 / 物料码开票 / 扫码开票。
6. 红票金额可能为负，展示时取绝对值。
7. 不主动展示用户没有要求的信息。

### 1.8 下载发票

用户明确要求下载时：

```
好的，这张发票可以下载 👇

🧾 发票号码：26427200000000000003
💰 发票金额：¥6.00
🔵 发票类型：蓝票（正常开具）
✅ 开票状态：开票成功

📥 下载发票 PDF
```

规则：
1. 下载地址必须使用接口返回的 `invoice_url`。
2. **若 `invoice_url` 为空字符串**，如实说明：
   ```
   这张发票暂时还没有生成 PDF 哦，开具完成后就可以下载啦～
   ```
   不得编造下载链接。
3. 下载入口统一为 `📥 下载发票 PDF`，图标与文字同行。
4. 不得单独出现 `📥`。
5. 汇总查询时不得主动展示下载入口。

### 1.9 发送发票到邮箱（走扫呗自带接口）

用户明确要求把某张发票发送到指定邮箱时，**必须走扫呗自带接口**
`invoice_sendEmail`（`email_type=1`、`email_address`=收件邮箱、
`content`=发票流水号），**只走这个接口，不支持换发件箱**。

成功后渲染「发送结果卡片」（card-templates.md 模板六），字段配图标且**一律不换行**：
📨 发送方式 / 📬 收件邮箱 / 🔢 发票号码 / 🔗 发票流水号 / 📄 发票类型 /
💰 发票金额 / ✅ 发送状态 / 🕐 发送时间 / 🧾 凭证号。

正文一句话，如：

> 📬 好的呢～发票已经通过扫呗的电子发票邮箱服务发送到 lxy@example.com 啦，
> 凭证号 f52973cad07a4643b3eccd1fbd4afd87，注意查收哦～ ✨

接口偶发失败时只做引导，不换第三方通道：
> 😅 发票邮件服务这会儿有点忙，暂时发送不出去呢～请稍后重试，
> 或稍后重试～

## 三、核心交互原则

### 3.1 先换算时间，再谈数据

「上周」必须先换算成确切起止日期（周一至周日）再进入流程。**这一步不依赖任何接口调用**，即使连接器不可用也必须完成并写明。

### 3.2 默认查询整个商户

用户没有指定门店时直接查整个商户，不先反问「你要查哪个门店」。

### 3.3 查询范围必须透明

未指定门店时明确展示 `🏪 查询范围：整个商户`；指定门店时明确展示门店真实名称。

### 3.4 拿不到数据 ≠ 没有开票

```
接口正常返回且计数为 0 → 该范围确实没有开票，可以说「XX 没有开票哦～」
接口异常 / 连接器不可用 → 数据未知，必须走降级交付
```

两者**绝不可混淆**，也不可把异常包装成「没有开票」。

### 3.5 未开通要基于真实依据

只有 `invoice_switch = 0` 才能说未开通。接口调用失败是"状态未知"，不是"未开通"。

### 3.6 不主动扩展需求

用户问汇总只返回汇总；未要求明细不展示明细；未要求下载不提供下载入口。

### 3.7 不向商户暴露技术过程

禁止出现：接口名、参数、调用失败、查询通道、服务异常、系统没有返回数据。只输出业务结果。
