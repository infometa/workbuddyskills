# GenUI 卡片编排规范（扫呗数电票场景）— 默认输出形态

> 🚨 **本文件是列表/详情/发送结果类的默认输出形态。**
> **开票汇总数据不需要卡片**，汇总直接用文字输出（见 `output-templates.md`）；
> 发票明细、单张详情、发送结果、无数据/异常提示等场景走本文件卡片规范。
> 卡片完全无法产出时降级文字（见 `output-templates.md`）。
> 对齐《GenUI 卡片使用教程》的组件选择与页面结构规范。
> 教程明确：业务 Skill 只需说明**触发场景 / 业务内容 / 组件选择 / 页面结构**四件事，
> 不描述组件内部协议层级；实际可用组件以本文档末节的组件白名单为准。
> 若当前环境没有原生卡片渲染能力，仍须按本规范生成 card.json 并做等效可视化渲染，
> 不得直接改用文字形态。

## 一、通用原则

1. **一条消息只保留一个 Card。** 指标、图表、表格、说明放进同一个 Card。
2. **整条消息最多一个含 Button 的卡片块。** 需要继续操作时，在整张卡片底部保留一组 Button。
3. **卡片代替同内容 Markdown。** 卡片已含标题、结论、指标时，不要在卡片外再复述一次。
4. **展示组件与输入组件不混用。** `Text`/`Statistic`/`Table`/`Descriptions` 只展示；
   `RadioGroup`/`Select`/`CheckboxGroup`/`Input`/`Textarea` 只收集。
5. **能选就不要让用户手输。** 固定候选优先 `RadioGroup`（≤12）→ `Select`（≤30）→ `ChoiceList`。
6. **用户可见文案用自然中文业务语言。** 不出现 `total_fee`、`invoice_type` 等内部字段名。
7. **一个 Card 内的信息层级固定为：顶部 → 中部 → 底部。**

## 二、场景一：开票汇总（最常用）— **不用卡片，文字输出**

**触发场景**：用户问开票数量、开票金额、有效开票金额、蓝票/红票拆分，或问某段时间/某门店的开票情况。

> **汇总数据不需要卡片。** 不生成含 Statistic 的汇总 Card，
> 直接按 `output-templates.md` 的「汇总文字模板」输出指标行。
> 下表仅保留口径与顺序参考，不作为卡片结构使用。

**指标顺序与口径**（文字输出同样遵守）：

| 顺序 | 指标 | 取值口径 |
|---|---|---|
| 1 | 开票数量 | N 张 |
| 2 | 开票金额 | \|蓝票\| + \|红票\| |
| 3 | 有效开票金额 | \|蓝票\| − \|红票\| |
| 4 | 蓝票（正常开具） | N 张，¥金额 |
| 5 | 红票（红冲） | N 张，¥金额 |

输出位置（文字形态）：查询时间与查询范围放在指标之前；**不展示数据口径说明**（口径是内部定义，不写给商户）。

**业务 Skill 写法（可直接写入 SKILL.md）**：

```markdown
展示开票汇总时（汇总不需要卡片），不使用卡片，
直接用文字按 output-templates.md 的「汇总文字模板」输出指标行：
查询时间与查询范围放在指标之前，随后按「开票数量 → 开票金额 → 有效开票金额 →
蓝票（正常开具）→ 红票（红冲）」顺序输出；数值取自 scripts/calc_amount.py，
口径与顺序不变；不展示数据口径说明。
```

**注意**：
- 金额一律为元（接口原值为分，必须 ÷100，见 SKILL.md 4.4）。
- 有效开票金额紧跟开票金额之后，顺序不可调换。
- 无数据时改用**场景四**（Alert 提示），不要用全 0 的 Statistic 假装有数据。

## 三、场景二：发票明细表格

**触发场景**：用户明确要求查看发票明细、逐张列表，或指定发票状态/来源筛选后要求列表。

**页面结构**（对应教程 5.8 明细表格）：

| 位置 | 组件 | 内容 |
|---|---|---|
| 顶部 | `Descriptions` | 查询时间、查询范围 |
| 顶部 | `Text` | 筛选条件与展示范围 |
| 中部 | `Table` | 发票号码 / 发票金额 / 发票类型 / 开票状态 / 开票来源 / 开票时间 |
| 底部 | 不追加 | 仅超 20 行节选时补一句 |

**业务 Skill 写法**：

```markdown
展示发票明细时，使用 Card、Descriptions、Text、Table 和 Descriptions：
- 顶部用 Descriptions 说明查询时间与查询范围，紧接一句 Text 说明展示范围；
- 中部用 Table 展示发票号码、发票金额、发票类型、开票状态、开票来源和开票时间；
- 底部用 Descriptions 说明总条数与是否为节选；
- 表格只读，不生成行内编辑、删除或下载按钮；下载入口放在卡片底部单独说明。
```

**注意**：
- `Table` 适合 1—6 列、最多 20 行。超出时先展示前 20 条并说明总数。
- 发票号码必须完整展示，禁止省略号截断。
- 发票类型只写「蓝票（正常开具）」「红票（红冲）」。
- 开票状态统一写「开票成功 / 开票中 / 开票失败 / 已红冲 / 红冲中 / 红冲失败」。

## 四、场景三：单张发票详情

**触发场景**：用户明确要求查看某一张发票的详细信息。

**页面结构**（对应教程 3.1 Descriptions）：

| 位置 | 组件 | 内容 |
|---|---|---|
| 顶部 | `Text` | 发票号码（一句话说明这是哪张） |
| 中部 | `Descriptions` | 发票金额、发票类型、开票状态、开票来源、开票时间、购方名称、接收邮箱 |
| 底部 | `Text` | 有 `invoice_url` 时说明「📥 下载发票 PDF」 |

**业务 Skill 写法**：

```markdown
展示单张发票详情时，使用 Card、Text 和 Descriptions：
顶部用 Text 标明发票号码，中部用 Descriptions 展示发票金额、发票类型、
开票状态、开票来源、开票时间与购方信息；底部在存在 PDF 时说明下载入口。
发票 URL 为空时如实说明暂无 PDF，不编造下载链接。
```

## 五、场景四：无数据与异常提示

**触发场景**：该时间范围内确实没有开票，或数电票未开通。

**页面结构**（对应教程 5.10 结果或风险提示）：

| 位置 | 组件 | 内容 |
|---|---|---|
| 顶部 | `Descriptions` | 查询时间、查询范围 |
| 顶部 | `Alert` | 状态说明（无数据 / 未开通 / 授权异常） |
| 底部 | 不追加 | 无 |

**业务 Skill 写法**：

```markdown
无开票数据或状态异常时，使用 Card、Descriptions 和 Alert：
顶部用 Descriptions 说明查询时间与查询范围，紧接 Alert 表达状态
（无数据用 info、异常用 warning）；已完成的提示卡片不再添加确认按钮。
```

**注意（底线）**：
- 接口正常返回且计数为 0 → 才能说「XX 没有开票哦～」。
- 接口异常 / 连接器不可用 → 状态为「暂时取不到数据」，**不得**说成没有开票，
  **不得**断言商户未开通数电票；授权引导只写「扫呗商户服务」，不出现技术标识。
- 降级时**不得**出现任何金额与笔数。

## 六、场景五：后续动作选择

**触发场景**：汇总已展示，商户可能想继续看明细或下载发票。

**页面结构**（对应教程 5.1 点击候选后立即继续）：

| 位置 | 组件 | 内容 |
|---|---|---|
| 顶部 | `Text`（可选） | 一句说明 |
| 中部 | `Button` ×N | 「查看发票明细」「下载发票 PDF」等明确候选 |
| 底部 | 不追加 | 点击后直接继续对话 |

**业务 Skill 写法**：

```markdown
需要商户从多个后续方向中选择时，使用 Text 和 Button：
顶部用一句 Text 说明选择目的，中部用多个 Button 展示可点击候选；
点击任一按钮后继续对话，不再增加统一确认按钮。
```

**注意**：`Button` 不得模拟多选提交；单条消息只能有一组按钮。

## 七、组件选择速查（本技能场景）

| 需求 | 用哪个组件 | 不用什么 |
|---|---|---|
| 展示一个金额/张数 | `Statistic` | 不用 `Text` 硬凑数字 |
| 展示查询时间、查询范围 | `Descriptions` | 不用多行 `Text` |
| 展示一句核心结论 | `Text` | 不用 `Alert`（除异常外） |
| 发票明细列表 | `Table` | 不用 `Text` 逐行罗列 |
| 门店/时间范围筛选 | `Select` | 固定候选不用 `Input` |
| 多选关注项 | `CheckboxGroup` | 不用多个 `Button` 模拟 |
| 下载、继续等动作 | `Button` | 不在 `Table` 行内放按钮 |

---

## 八、与文字输出的关系

- 卡片不可用（当前环境无原生卡片渲染能力）时，退回文字输出，
  版式与字段顺序见 `@references/output-templates.md`，字段与口径完全一致。
- 两种形态的**数值必须同源**：都来自 `scripts/calc_amount.py` 的输出，不得各算各的。
