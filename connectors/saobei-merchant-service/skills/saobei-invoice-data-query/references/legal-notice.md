# 数据来源、合规与免责声明

## 一、产品与主体

- **产品名称：** 扫呗（利楚商务服务有限公司核心产品）
- **提供主体：** 利楚商务服务有限公司
- **本技能定位：** 扫呗商户服务在 WorkBuddy 上的数电票数据查询助手，通过「扫呗商户服务」连接器调用商户侧已授权的只读查询接口，完成开票数据查询、统计、明细展示与下载入口提供。

## 二、能力边界

本技能为**纯只读技能**，仅执行查询、统计、明细展示与下载入口提供：

- 不执行开票、红冲、开票授权等任何写操作。
- 不修改、不删除、不导出任何票据数据。
- 下载入口仅提供接口返回的 `invoice_url` 原始地址，不下载、不转存、不二次分发发票文件。

## 三、授权与数据来源

1. **连接器授权为前置条件。** 本技能全部能力依赖「扫呗商户服务」连接器。商户须在 WorkBuddy 客户端完成连接器授权，未授权时本技能不执行任何操作。
2. **授权范围最小化。** 授权后仅在查询所需范围内读取商户自身的开票汇总与发票记录，不读取与开票查询无关的经营数据。
3. **只读接口。** 全部调用均为查询接口，不涉及任何写入或状态变更。
4. **不绕行、不伪造。** 严禁绕开连接器调用未授权接口；严禁编造开票数量、金额、发票号码、发票状态等数据后输出。
5. **数据不外传、不落盘。** 查询结果仅用于本次对话内的展示，不向任何第三方服务传输，不写入本地文件，不跨会话留存。

## 四、个人信息处理

发票记录中包含以下个人信息与敏感业务数据，本技能的处理方式如下：

| 字段 | 处理方式 |
|---|---|
| 购方名称 `purchase_name` | 仅在用户明确要求查看明细或详情时展示 |
| 接收邮箱 `receive_email` | 仅在用户明确要求查看详情时展示，不主动列出 |
| 发票 PDF 地址 `invoice_url` | 仅在用户明确要求下载时以链接形式提供，不预取、不缓存 |
| 发票二维码地址 `invoice_qrcode_url` | 不主动展示，仅在用户明确要求时提供 |

- 本技能不主动收集与查询无关的个人信息，不对用户或购方做额外画像。
- 不主动展示用户未要求的信息字段（如购方名称、接收邮箱默认不列出）。
- 发票号码完整展示，不做省略处理，但仅在用户明确要求查看明细或详情时展示。

## 五、财税专业内容免责

1. 本技能提供的是**开票数据查询与展示**，不构成税务意见、法律意见或财务建议。
2. 数电票相关数据受国家税务总局及地方税务机关政策约束，**具体口径与统计规则以税务机关最新规定和开票系统实际数据为准**。政策调整时以最新规定为准。
3. **有效开票金额 = 蓝票金额 − 红票金额**，该口径为本技能的展示约定，实际财务与税务口径以商户自身核算规则和税务机关口径为准。
4. 开票失败原因仅在接口返回 `error_msg` 时如实转述，**不自行归因、不推测原因、不给出未经确认的判断**。
5. 查询结果与商户自身账簿、申报数据存在差异时，以税务机关系统数据为准；本技能不对差异原因作出解释，除非用户主动询问且接口数据足以支撑说明。
6. 若查询结果与实际经营情况不符，应核实后再作判定，不以本技能的输出作为责任判定依据。

## 六、数据查询范围责任边界

- 本技能仅查询商户**自身账号下**的开票数据，不跨商户、不跨主体查询。
- 用户指定门店时，查询范围以接口返回为准；匹配不到门店时如实说明，不擅自改用其他门店范围。
- 用户未指定门店时默认查询整个商户，结果中明示查询范围，用户可据此判断数据口径。

## 七、服务可用性

- 「扫呗商户服务」连接器为第三方服务，其可用性、接口稳定性与响应时效由该服务提供方负责。
- 本技能不承诺 7×24 可用，不对服务中断期间的查询请求提供补偿。
- 查询异常时按 SKILL.md 第二节第 4 步的异常分流处理，仍无法解决时如实说明当前状态并建议稍后重试。

## 八、第三方接口授权声明

本技能调用的全部接口均通过商户已授权的渠道开放，不绕过任何付费墙、验证码或反爬机制，不进行逆向工程，不调用未公开接口。
