# 七色米进销存

用户需要查询或管理七色米进销存中的商品、库存、仓库、客户、供应商、销售、采购、收付款或其他业务单据时使用本技能。

## 工具选择

1. 先根据用户意图在 @references/tool-catalog.md 的相关业务域中选择一个最具体的工具。
2. 以 WorkBuddy 当前展示的 MCP 工具名称、描述和输入 Schema 为最终依据。参考目录用于发现工具，不代替实时 Schema。
3. 业务参数直接放在工具参数顶层；不要增加 `toolName` 或嵌套的 `arguments` 包装。
4. 严格使用 Schema 中的字段名和类型，补齐所有必填字段；不要猜测业务 ID、枚举值、门店、仓库、客户或供应商。
5. 缺少 ID 时，先调用对应列表或名称查询工具取得候选项；有多个候选项时请用户选择。
6. 分页查询按实时 Schema 使用 `Page`、`Rp` 等字段。用户未指定数量时先取一页合理大小的数据，需要更多时再继续翻页。

## 单据路由

- “销售单”属于 `Sale`；“销售订单”“销售预订”属于 `SaleOrder`，二者不能混用。
- “进货单”“采购单”属于 `Buy`；“进货订单”“采购订单”“进货预订”属于 `BuyOrder`，二者不能混用。
- 用户只说“订单”且无法从上下文判断销售或采购时，先询问业务类型，不调用工具。
- 查询“最近”“最新一笔”或列表且未提供单据 ID 时，优先调用对应列表工具，再按日期或返回顺序筛选；不要虚构 ID 调用详情工具。
- 收款单与付款单方向相反。调用前必须核对用户表达的是收款还是付款。

## 写入与确认

当前只有以下三个高风险写入工具：

- `qisemi_sale_save_sale`：新增销售单；
- `qisemi_receive_and_pay_add_receive`：新增收款单；
- `qisemi_receive_and_pay_add_pay`：新增付款单。

调用任一高风险工具前：

1. 先完成只读查询，解析真实业务 ID 和枚举值。
2. 向用户展示即将写入的业务类型、往来单位、日期、门店/仓库、经手人、金额以及商品明细等关键字段。
3. 取得针对本次写入的明确确认。用户只是在描述需求、提供字段或确认查询结果，不等同于授权提交。
4. 获得确认后，在对应工具参数顶层传入 `confirm: true`；不得把 `confirm` 放进业务对象或明细数组。

没有明确确认时不得调用。用户修改任何关键字段后，重新展示摘要并再次确认。

写入调用超时、断线或返回结果不明确时，不得自动重试。优先使用只读工具核对单据是否已经创建；仍不能确定时说明状态并询问用户，避免重复单据或重复收付款。

## 认证与安全

- 认证由 WorkBuddy 与七色米 MCP 的 OAuth 2.1 流程处理。不要要求用户在对话中粘贴账号密码、Access Token 或 API Key。
- 不要把认证信息放入工具参数；工具参数中的 `token` 不能作为认证凭据。
- 只请求完成当前任务所需的数据，不扩大门店、仓库、日期或人员范围。
- 返回内容可能包含客户、供应商、联系方式和经营数据，只展示完成用户任务所需的信息。

## 错误恢复

- 遇到 `401`、`MCP_AUTHENTICATION_REQUIRED`、Token 失效或 OAuth 错误时，提示用户在 WorkBuddy 中重新连接七色米，然后再重试原操作。
- 遇到缺少字段、类型错误或参数无效时，对照实时 Schema 指出需要补充或修正的字段。
- 遇到限流、超时或暂时不可用时，说明调用未完成；只读调用可在用户仍需要结果时重试，高风险写入按上文的不确定结果规则处理。
- 遇到权限不足时说明所需权限或数据范围，不尝试绕过权限。
- 工具结果附带“七色米业务枚举解释（权威）”时，以该说明解释数值；未提供说明时保留原值，不自行推断。

## 结果呈现

- 列表结果优先呈现用户关心的名称、单号、日期、状态、数量和金额，并说明筛选范围。
- 金额保留工具返回的币种和精度；日期时间不擅自变更时区。
- 没有结果时明确说明查询条件，不将空结果表述为系统中绝对不存在。
- 完成写入后返回工具给出的单号或 ID、关键金额和状态；不得宣称未由工具结果证明的成功状态。
