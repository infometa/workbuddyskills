# 品类槽位取值与查询规则

对应 PRD「品类槽位目录」。每个品类槽位包含：提取规则、取值/value 处理逻辑、查询接口规则。
下方列出核心品类的完整规则；未列出品类（冷柜/波轮/电视/柜机/家中机/洗碗机/烤箱/热水器等）
结构同构，规则见 `assets/category_rules.json`。宿主大模型读取该 JSON 做规则映射，
将命中的槽位整理为 `categorySlots` 传给 `query_product_recommend` 工具。

## 通用约定
- 查询接口：属性类走 `haier_product_params`（name-value），品类/套系/中线走 `haier_product_info`。
- 尺寸类 value 统一处理为「宽,深,高」三段，用逗号隔开（如 "300,200,500"），分别比对。
- 尺寸槽位的填法与模糊词区间见下方「通用尺寸规则」。
- 多标签功能：命中一个或多个即符合（或条件）。
- 颜色"深色/浅色"映射到多个具体颜色再查询。
- **通用槽位（套系、价格、渠道、品牌偏好）适用所有品类**，命中即与品类槽位一并映射进 `categorySlots`（详见下方「通用槽位」与 `slot_mapping.md`）。
- **标准槽位名是「价格」，不存在「预算」槽位**：用户说的「预算」只是触发词，`slotName` 一律填「价格」。
- **冰箱、冷柜、烤箱、洗碗机的原「尺寸」槽位已拆成「产品尺寸」与「安装尺寸」两个**，
  这四个品类下**不再有「尺寸」槽位**：见下方「通用尺寸规则」。
- **能效等级的值写法按品类分两套**（「1级」vs「1级能效」），门型偏好要把关键词**推断成固定标签**
  （三开门→三门、十字→T型），且槽位名只能是「门型偏好」（不是参数库字段名「门体结构」）：
  见下方「通用能效等级规则」与「通用门型偏好规则」。

## 通用能效等级规则（所有有 `能效等级` 槽位的品类）

能效等级填 `tags`（不填 `numMin`/`numMax`）。**值的写法按品类分成两套，写错既不报错也筛不出产品**：

| 值格式 | 品类 | 值写法 | 示例 |
|--------|------|--------|------|
| 「数值+级」 | 冰箱、冷柜、波轮洗衣机、滚筒洗衣机 | 数值（阿拉伯数字）+`级`，**不带「能效」二字** | `1级` / `2级` / `3级` |
| 「数值+级能效」 | 挂机、柜机、家中机、电热水器、燃气热水器 | 数值（阿拉伯数字）+`级能效`，**「能效」二字必须带** | `1级能效` / `2级能效` / `3级能效` |

取值按优先级来：

1. 正则提取等级数值 → 转成阿拉伯数字 N → 套该品类的写法拼出值；
2. 没有数值、只提到**节能 / 省电**这类模糊描述 → 取最高等级（「级」类填 `1级`、「级能效」类填 `1级能效`）。

**用户原话带不带「能效」后缀不作为判断依据，只看品类**：

| 用户说 | 冰箱 / 冷柜 / 波轮 / 滚筒 | 挂机 / 柜机 / 家中机 / 电热水器 / 燃气热水器 |
|--------|--------------------------|---------------------------------------------|
| 一级能效 / 一级 / 1级能效 / 1级 | `1级` | `1级能效` |
| 二级能效 / 二级 / 2级能效 / 2级 | `2级` | `2级能效` |
| 三级能效 / 三级 / 3级能效 / 3级 | `3级` | `3级能效` |
| 节能 / 省电（无数值） | `1级` | `1级能效` |

实测曾出现「挂机 + 能效等级 `tags=["1级"]`」——挂机的正确值是 `1级能效`，少写「能效」二字
这个条件就筛不出产品。完整口径见 `assets/trigger_dict.json` 的 `energy_efficiency`。

## 通用门型偏好规则（仅冰箱、冷柜有该槽位）

**槽位名只有「门型偏好」一个。** 「门体结构」「箱门结构」是参数库字段名，
下发过去后端按「品类+槽位名」匹配不到，门型条件整个丢失。

**下发的是推断出的固定标签，不是用户原话。** 用户说「三开门」要推断成 `三门`、
「十字门」要推断成 `T型`：下发 `tags=["三开门"]` 匹配不到规则，这个条件白填了。

> 实测「推荐三开门冰箱」曾下发 `{"slot_name":"门体结构","tags":["三开门"]}`——
> **名字和值两处都错**，正确入参是 `{"slotName":"门型偏好","tags":["三门"]}`。

| 品类 | 关键词 → 固定标签 | 合法标签 |
|------|------------------|----------|
| 冰箱 | 单门→`单门`；两门/双门/**双开门**→`双门`；对开门/对开→`对开门`；三门/**三开门**→`三门`；法式/多门/F+/**四门及以上**→`多门`；**T型/十字/十字门/T型双开门→`T型`** | 单门、双门、对开门、三门、多门、T型 |
| 冷柜 | 单门→`单门`；两门/双门/**对开门/双开门**→`双门`；三门/**三开门**/法式/多门/四门→`多门` | 单门、双门、多门 |

- **冰箱下「双开门」与「对开门」是两个不同标签**：「双开门」按门数归 `双门`，
  「对开门」指左右对开的并列双门柜体，归 `对开门`。冷柜下两者都归 `双门`。
- **门数超过三的一律归 `多门`**：四门/四开门/五门/法式/F+ 都是 `多门`，没有「四门」这类标签。
- 关键词按**最长匹配**取值：「十字四门」取 `T型`（不要先命中「四门」拿到 `多门`）；
  「T型双开门」取 `T型`（不要先命中「双开门」拿到 `双门`）。
- **冷柜没有「对开门」和「T型」标签**：照搬冰箱的映射会填出冷柜不存在的值。
- **门型词长在品类短语里也要产出该槽位**：「十字门冰箱」「对开门冰箱」「三门冰箱」既是品类触发词
  也含门型信息，识别出 `category=冰箱` 的同时也要产出门型偏好
  （「推荐十字门冰箱」= `category=冰箱` + `门型偏好 tags=["T型"]`；
  「推荐三开门冰箱」= `category=冰箱` + `门型偏好 tags=["三门"]`）。

完整口径见 `assets/trigger_dict.json` 的 `door_type`。

## 通用尺寸规则（所有 `type=size` 的品类）

尺寸槽位按 `width` / `depth` / `height` 的 `{min,max}` 填，单位统一 **mm**（cm×10、m×1000）。
**无界的一侧整个省略**：`{"width":{"min":900}}`，不要写 `max:null`；下限为 0 时可省 `min`。

### 先按品类定槽位名：产品尺寸 / 安装尺寸 / 尺寸

**冰箱、冷柜、烤箱、洗碗机的原「尺寸」槽位已拆成「产品尺寸」与「安装尺寸」两个，
这四个品类下不再有「尺寸」槽位**——继续下发「尺寸」后端匹配不到，条件静默失效。
判定只看用户有没有提**安装类词**（安装 / 嵌入 / 橱柜 / 预留 / 开孔 / 全嵌 / 零嵌 / 半嵌 / 齐平）：

| 品类 | 没提安装类词 | 提了安装类词 |
|------|-------------|-------------|
| 冰箱、冷柜、烤箱、洗碗机 | `产品尺寸` | `安装尺寸` |
| 波轮洗衣机、滚筒洗衣机 | `尺寸` | `尺寸`（该品类没有安装尺寸槽位） |
| 吸排油烟机、燃气灶 | `安装尺寸` | `安装尺寸`（该品类只有安装尺寸） |
| 平板电视 | `尺寸偏好`（屏幕英寸，填 `numMin`/`numMax` 而非三维） | 同左 |

- 用户同时说了机身与开孔（「机身别超过 600 宽，橱柜预留 700」）时**两个槽位都产出**。
- 维度词归位（两个槽位同一套口径，安装尺寸下即安装宽 / 安装深 / 安装高）：
  提**深度 / 厚度**→`depth`，提**长度 / 宽度**→`width`，提**高度**→`height`。
- 固定值填成该侧的定值，区间填 `{min,max}`，单位默认 mm。
- **模糊尺寸词只对「产品尺寸」有规则**（它们说的是机身大小，不是橱柜开孔）：
  `安装尺寸` 只按用户给出的明确数值填，没有模糊词规则。

### 模糊尺寸词 → 三维区间

**「大尺寸」「小尺寸」「超薄」这类词有确定规则，必须查表产出槽位**——它们不是「识别不到就不产出」
的长尾表达。完整口径见 `assets/trigger_dict.json` 的 `size_fuzzy.by_category`
（与 `assets/category_rules.json` 各品类 `产品尺寸.fuzzy_dim` 同一份）。
**下表的槽位名按上一节取**：冰箱 / 冷柜 / 烤箱 / 洗碗机是 `产品尺寸`，洗衣机是 `尺寸`。

| 品类 | 模糊词 | width(mm) | depth(mm) | height(mm) |
|------|--------|-----------|-----------|------------|
| 冰箱 | 大尺寸 | ≥900 | — | — |
| 冰箱 | 超薄 | — | ≤594 | — |
| 冰箱 | 小尺寸 / 小户型 / 不占地 | ≤600 | ≤650 | ≤1600 |
| 冷柜 | 大尺寸 | ≥1200 | — | — |
| 冷柜 | 中等尺寸 | 1000-1200 | — | — |
| 冷柜 | 小尺寸 / 迷你 / 小户型 / 不占地 / 阳台 | 600-1000 | — | — |
| 波轮洗衣机 | 大尺寸 | ≥600 | ≥580 | ≥920 |
| 波轮洗衣机 | 标准 / 常规 | 550-600 | 560-600 | 900-920 |
| 波轮洗衣机 | 小尺寸 / 迷你 / 小型 / 小户型 / 不占地 / 阳台 | ≤550 | ≤560 | ≤920 |
| 滚筒洗衣机 | 大尺寸 | ≥600 | ≥600 | ≥850 |
| 滚筒洗衣机 | 标准 / 常规 | 550-600 | 550-600 | 800-850 |
| 滚筒洗衣机 | 小尺寸 / 迷你 / 小型 / 小户型 / 不占地 / 阳台 | ≤600 | ≤550 | ≤850 |
| 烤箱 / 洗碗机 | — | 无模糊词规则，只有明确数值时才产出尺寸槽位 | | |

用户给了明确数值（宽 600 以内、深不超过 60cm、预留 700mm）时按数值填；与模糊词同时出现时数值优先。
该品类在表里没有对应模糊词就不产出尺寸槽位，**不要拿别的品类的区间套用**。

### 「大 / 小」要同时产出容量槽位

用户说「大尺寸冰箱」时，「大」在他嘴里通常同时指**机身大**和**能装**，所以尺寸与容量两个槽位都要产出：

| 用户表达 | 品类 | 产出的槽位 |
|----------|------|-----------|
| 大尺寸 / 大容量 / 大冰箱 | 冰箱 | `产品尺寸` width.min=900 **＋** `容量偏好` 400-600L |
| 囤货 | 冰箱 | `产品尺寸`（若同时提了大）**＋** `容量偏好` 500-600L |
| 小尺寸 / 小容量 / 小冰箱 | 冰箱 | `产品尺寸` width≤600/depth≤650/height≤1600 **＋** `容量偏好` 90-280L |

只传一个是漏筛：只传容量则宽度不受约束，只传尺寸则可能筛出「机身大但分区浪费」的款。
其它品类的容量侧模糊区间见下方各品类表的「容量偏好 / 洗涤容量」行。

### 为什么拆成两个槽位

拆分前只有一个「尺寸」槽位，安装类词只切换后端比对哪个字段（安装尺寸字段 vs 产品尺寸字段），
槽位名不变。**现在安装类词直接决定槽位名**：冰箱 / 冷柜 / 烤箱 / 洗碗机没提安装类词填
`产品尺寸`、提了填 `安装尺寸`，这四个品类下「尺寸」已不是合法槽位名。
其余品类未拆分：洗衣机仍是「尺寸」，吸排油烟机 / 燃气灶只有「安装尺寸」，
平板电视是「尺寸偏好」（单位为英寸，非 mm，用 `numMin`/`numMax`）。

## 通用槽位（所有品类通用）
套系、价格、渠道、品牌偏好适用于全部品类，已在 `assets/category_rules.json` 每个品类下展开；触发词统一拆分到
`assets/trigger_dict.json`（套系见 `suite_cate` 数组，价格见 `price` 对象，渠道见 `channel` 对象，
品牌偏好见 `brand_preference` 对象），此处不重复维护触发词。

| 槽位 | 必填 | 提取规则 | 查询字段/规则 |
|------|------|----------|--------------|
| 套系 | 否 | 触发词精准匹配套系名（致境/指挥家/银河/鉴赏家/光年/揽光/星云/藏家/设计师/原石/小红花/麦浪/云溪/山茶花/天悦/Seeker/懒人，见 `trigger_dict.suite_cate`）；映射为 `tags=[套系名]` | 走 `haier_product_params`（`field=spectrum`），`tags=[套系名]` 精准查询 |
| **价格** | 否 | **命中价格关键词或「数值+金额单位」时必须产出「价格」槽位（`slotName=价格`），禁止把价格短语塞进 `userTags`。用户说「预算」也映射为「价格」——没有「预算」槽位。** 触发词：正则命中「数值+单位（元/块钱/左右/以内/上下/出头）」或 预算/价位/价格/花了/花费/控制在/不超过/限（见 `trigger_dict.price`）；**先做中文口语数字转换**（中文数字与口语简写：五千四=5400、五千二=5200、一万二=12000），再单位归一 万→×10000、千→×1000 统一为元；区间修饰 "X以内/以下"→[0,X]、"X以上/出头"→[X,+∞)、"X到Y/X-Y"→[X,Y]、"X左右/上下"→[X*0.8,X*1.2]；**无区间修饰词的裸数值（如「预算五千四」「价格8000」）按「左右」处理：[X*0.8, X*1.2]，即 numMin=X*0.8、numMax=X*1.2、single=false**；出现明确数值归本槽位，仅定性描述归价格预期 | 走 `haier_product_params`：① `name in ('价格','价格(元)')` value 落在所给区间内即符合；② `name in ('价格（区间）','价格区间','价格区间(元)')` 产品价格区间与所给区间重合即符合 |
| 渠道 | 否 | 多标签（同「功能偏好」结构）。枚举值固定：线下/天猫/京东/抖音/快手/拼多多/小红书/视频号；触发词见 `trigger_dict.channel.trigger`，取最长匹配后映射为标准枚举值，多渠道并列全部写入同一槽位 `tags`；「线上/网上/网购/电商/旗舰店/官网」按 `channel.online_expand` 展开为七个线上渠道；「附近/门店在哪」等只提位置的表达归入线下；「不限渠道/都可以」不产出该槽位；否定词（不要/不想要/不考虑/排除/别/除了）前置拦截命中的渠道，否定后无剩余渠道则不产出该槽位；未命中不产出、不追问、不填默认值，禁止把渠道短语塞进 `userTags` | 与「功能偏好」同构：`tags` 多标签或条件，命中任一渠道即符合，由后端按「品类+槽位名」定位过滤规则 |
| 品牌偏好 | 否 | 多标签（同「功能偏好」结构）。枚举值固定：海尔/卡萨帝/Leader（**统帅的标准值是 `Leader`**）；触发词见 `trigger_dict.brand_preference`：海尔/haier、卡萨帝/casarte、统帅/leader；否定词（不要/排除/除了/别）命中的品牌不写入 `tags`，否定后无剩余则不产出该槽位；未命中不产出、不追问、不填默认值，禁止把品牌短语塞进 `userTags` | 与「功能偏好」同构：`tags` 多标签或条件，命中任一品牌即符合 |

## 缺失处理（必填槽位）
- 品类缺失：追问。
- 匹数/风量/款式/气源/容量等品类必填槽位缺失：优先按场景/家庭推断，无法推断则定向追问；
  能效等有默认值的直接填默认——**默认值也要按品类取写法**：冰箱/冷柜/波轮/滚筒填 `1级`，
  挂机/柜机/家中机/电热水器填 `1级能效`。
