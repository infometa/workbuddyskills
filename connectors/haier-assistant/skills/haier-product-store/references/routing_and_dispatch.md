# 门店引流分流与派发规则（F1 / F2）

对应 PRD 3.3.2「门店引流 Skill」、3.3.2.4「F1-渠道引流」与 3.3.2.5「F2-门店引流」。宿主大模型据本文档与
`assets/routing_rules.json` 判定流程与分支，用 `assets/response_templates.json` 生成话术。

## 一、先选流程（F1 / F2）

```
输入：产品型号(名称) + 意向渠道 + 地址 + 上下文记忆
  → 用户问「某产品在哪买 / 某产品在我的意向渠道有没有售」？  → F1 渠道引流（型号必填）
  → 用户直接问「附近 / 指定地址附近的海尔门店」？            → F2 门店引流（不依赖型号）
```

- F1 的产品型号必填：本轮没有则从上下文记忆补齐；补不到且用户其实在问附近/指定地址门店时，转 F2。
- 槽位与多轮特殊内容解析见 `slot_extraction.md`；地址解析见 `address_parsing.md`。

## 二、F1-渠道引流

### (一) 命中规则
用户询问指定产品的售卖渠道，或问产品在其意向渠道是否有售。**产品型号为必填**。

### (二) 查在售渠道
- 工具：`query_product_sale_channel`。
- 入参：
  - `productName`（产品型号，必填）；
  - `intentChannels`（用户意向购买渠道，可空）：真实渠道名数组，取值参考 `trigger_dict.intent_channels.canonical_channels`
    （抖音 / 快手 / 拼多多 / 天猫 / 京东 / 小红书 / 视频号 / 线下）。「线下」是唯一线下渠道名，其余视为线上。
    用户只说「线上」「全部」这类聚合词时**留空**，不要枚举平台名（见 `trigger_dict.intent_channels.aggregate_handling`）。
    **异常地点（火星/月球/霍格沃茨）不是地址，直接忽略、不据此命中「线下」**：`intentChannels` 留空按未指定处理，
    正常返回该型号的在售渠道（含线上）——实测「…在火星有卖吗」下发了 `["线下"]`，把在售渠道范围凭空缩小了。
    境外真实城市（纽约/东京）**是**真实地址，不属此列，照常处理后走无结果兜底。见 `trigger_dict.invalid_location`。
  - `excludeChannels`（排除的渠道，可空）：取值同为上述八项真实渠道名。用户说「不要天猫的」「不要这些渠道」
    「换个渠道」时填入被排除的渠道（见 `trigger_dict.slot_adjust.channel_exclude`）：点名某渠道则填该渠道；
    泛指「不要这些渠道」则填上一轮 `channelName` 里命中的渠道；「不要线上的」需把聚合词展开成除线下外的
    七个真实渠道名；「不要线下的」填 `["线下"]`。同一渠道不得同时出现在 `intentChannels` 与 `excludeChannels`。
- 返参：
  - `productCode`、`productName`、`channelName`（多渠道英文逗号隔开，**仅供话术展示**）；
  - `sceneType.type`：`1`=在用户意向渠道售卖（命中意向渠道）、`2`=在用户意向渠道无售卖（未命中）、`3`=产品不在库；
  - `sceneType.detailType`：仅 `type=1` 时有值，`1`=命中线下意向渠道、`2`=命中线上渠道、`3`=同时命中线下与线上。
- 仅调用一次。**意向渠道是否命中由服务端判定**：分支判定只看 `sceneType`，不要自己拿 `channelName` 与意向渠道求交，
  也不要凭 `channelName` 猜测分支。

### (三) 路由分发（判定见 `assets/routing_rules.json` F1_branches）

| 分支 | 达成条件 | 输出 |
|------|----------|------|
| 三.1 产品在用户意向渠道售卖 | `sceneType.type="1"` | 按 `detailType` 进细分流程（见下表） |
| 三.2 产品在用户意向渠道无售卖 | `sceneType.type="2"` | 话术③问是否查全部渠道；用户确认后**清空 `intentChannels`** 重新调用工具并重走 F1 分流 |
| 三.3 产品不在库 | `sceneType.type="3"` | 话术④兜底 |
| 兜底 | `sceneType` 缺失 / `type` 不在 1-3 / 工具 `ok=false` | 按话术④处理，不猜测渠道 |

`type=1` 的细分流程（由 `detailType` 决定）：

| detailType | 含义 | 动作 |
|------------|------|------|
| `1` | 命中线下意向渠道 | 走**线下门店细分流程**：有地址则按省/市/区调用 `query_store`；已授权则留空按当前位置就近查；**两者都没有则直接追问地址**（`address_flow`） |
| `2` | 命中线上渠道 | 输出 `channelName` 中可购买的线上渠道（`online_only`），**不查门店** |
| `3` | 同时命中线下与线上 | 两条同时执行：① 按 `detailType=1` 查询并展示门店；② 门店列表后补充 `online_supplement` 线上渠道 |

> 流程图对照：`type=1 & detailType=1` 即「产品在用户意向渠道售卖」分支里「通过省市区查询线下门店」这条细分流程。

### (四) 渲染输出
按 `response_templates.json` 的 `f1_scene1_on_sale`（`online_only` / `with_address` / `without_address` /
`online_supplement`）、`f1_scene2_cross_channel`、`f1_scene3_not_found` 生成，最多展示 5 个门店。

## 三、F2-门店引流

### (一) 命中规则
用户要求查询附近/指定地址附近的海尔门店。

### (二) 判断有无地址，没有就直接追问

门店查询有两个位置来源：用户说出来的省/市/区/地址，以及用户授权后由宿主注入的当前位置
（模型不可见，不填不构造经纬度）。因此「附近」两个字本身**不构成位置**：用户只说
「查附近的门店」而又未授权时位置仍是空的。

| 步骤 | 分支 | 动作 |
|------|------|------|
| 2.1 | 用户本轮或上下文给了地址 | 按 `address_parsing.md` 提取省/市/区，进 (三) |
| 2.2 | 没有地址（含只说「附近」「就近」「我这边」） | **直接追问地址（话术②），本轮结束**：不调 `query_store`，不请求定位授权，不输出任何授权信号 |
| 2.3 | 追问后提供了地址（主 Agent 带「槽位追问」标识） | 直接进入【判断地址】，省市区解析后 `query_store`（→ F2-场景1） |
| 2.4 | 追问后仍不提供地址 | 话术⑤兜底，不再重复追问 |

> `query_store` 位置为空时后端按 `2005` 拒绝，不会返回空列表——这是刻意的：
> 空列表会被误读成「该地区没有门店」，而真实原因是压根没带地址。拿到 `2005` 就回到 2.2 追问地址。

### (三) 查询门店信息
- 工具：`query_store`。模型侧只填 `request`（对应后端 `reqLocation`）：用户指定的省/市/区/地址。
  **本渠道 `currLocation`（经纬度就近查询）恒为空**，`request` 里的地址是唯一位置来源，不能留空。
- `request` 另有两个可选字段（详见 `slot_extraction.md`）：
  - `size`（查询门店数，正整数）：用户要「多看几家」时填，只影响后端取多少家，展示条数不变；
  - `excludeStoreNames`（排除门店名）：「换一批 / 不要这些店」时填上一轮已展示的 `storeName` 原文，
    多轮连续换批需**累计**，后端不再返回命中门店，无需本地过滤。
- **不要传 `radius`**：它只对按经纬度就近搜索生效，本渠道用不到；「远一点/近一点」改为
  放宽或收窄行政区范围（区 → 市 / 市 → 区）。
- 返参 `StoreInfoResDto` 每项字段：`storeName`（门店名称）、`storeAddress`（门店地址）、`phone`（门店电话）、
  `province`/`city`/`district`（省/市/区）、`longitude`/`latitude`（经纬度，仅供后端排序）。
  按省市区查询**不返回 `distance`**，话术里不提距离。
- 门店数量上限 10。

### (四) 组合输出
按 `response_templates.json` 的 `f2_scene1_by_region`（省市区查询）生成。

## 四、门店展示与安全

- `query_store` 上限 10 家，面向用户**最多展示 5 家**：≤5 家逐行展示并补充"为您找到 N 家"，>5 家只展示前 5 家并补充"部分门店"。
- **家数只说"为您找到 N 家"**：返回条数是本次查询命中数，不是区域门店总量（换一批、放宽行政区、
  调整 `size` 都可能返回此前没出现的门店）。禁用"共 N 家""总共 N 家""只有 N 家""就这 N 家"
  "以上就是全部""全部为您列出""无法达到 N 家"这类总量断言；要 10 家只查到 5 家时说"本次为您找到 5 家"
  并给下一步，不说"该区域只有 5 家"。完整口径见 `response_templates.json.count_wording`。
- 字段展示口径统一见 `response_templates.json.field_render_rules`：
  - `storeName` 必展示；`storeAddress` 有值则展示，已含省市区时不再重复拼 `province`/`city`/`district`；
  - `phone` 非空才渲染「电话 xxx」，为空整段省略，不写"暂无"；
  - **不展示距离**：本渠道按省市区查询，返参不带 `distance`，不提距离、不猜测距离、不排远近；
  - `longitude`/`latitude` 仅供后端排序，**不展示给用户**；展示顺序保持工具返回顺序。
- 查不到门店时输出对应兜底话术，可引导补充/更换地址或拨打 4006-999-999。
- **授权由宿主发起，技能不代劳**：不自行请求授权、不输出授权信号、不描述或承诺授权卡；
  未授权又没有地址就直接追问地址。用户提供的地址只用于本次查询，不入日志、记忆、Prompt。
- 不得虚构渠道、门店、地址；仅使用工具返回的真实数据。
