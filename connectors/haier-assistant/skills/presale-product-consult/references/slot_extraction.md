# 售前咨询槽位提取与参数名映射

对应 PRD 3.3.4「意图判断 / 上下文记忆与槽位继承 / 槽位提取」。处理顺序：
**意图判断 → 记忆合并 → 型号/品类定位 → 参数维度映射 → 下发工具**。

## 一、意图判断

判定顺序以 `assets/consult_intents.json` 的 `decision_order` 为准，触发词见 `assets/trigger_dict.json`。

| 触发条件 | 命中词典 | 子意图 | 调用工具 |
|----------|----------|--------|----------|
| 产品型号有值 **或** 原文提取到具体型号 | `value_intent.words`（值得买吗/性价比/推荐/值不值/好不好/值得入手吗） | 型号-购买建议 | `query_product_attribute` |
| 产品型号有值 **或** 原文提取到具体型号 | `attribute_intent.words`（价格/容量/能效/尺寸/品牌/参数/功能） | 型号-参数/价格 | `query_product_attribute` |
| 产品品类有值且型号为空 **或** 原文只提取到品类 | `attribute_intent.words` | 品类-参数/价格 | `query_product_attribute_by_category` |
| 型号与品类均为空 | — | 要素缺失 | 不调用，走 `4002` |

- 型号优先于品类；两者同时存在只走型号分支。
- 同时命中购买建议词与参数词 → 型号-购买建议，参数词仍写入 `attributeNames` 当卖点素材。
- 只有品类却问「值得买吗」→ 按品类-参数/价格输出 TOP3 型号参数，不做性价比推荐。

## 二、型号识别（→ `query_product_attribute` 的 `productName`）

用户很少说完整型号，多是「云溪5.0 D3」「小红花502」「卡萨帝601鉴赏家」这类口语说法。按**优先顺序**提取：

1. **查别名映射**：`assets/product_name_aliases.json` 的 `aliases`，触发词**取最长匹配**
   （「云溪5.0 D3 12kg洗烘一体机」命中 `XQG120-HBLE7AD3U1`，不是更短的「云溪5.0 D3」）。
   匹配忽略大小写与空格差异（「云溪4.0pro」≈「云溪4.0 Pro」）；命中后 `productName` 填**标准型号名**，
   不要回填用户的口语说法。
2. **按型号形态摘取**：映射表未收录时，按该文件 `fallback_pattern` 从用户话语/记忆里原样摘出型号——
   以大写字母或数字开头，含大写字母、数字、`-` `/` `（）` `()` 空格、中文，长度 4~60；
   可能有半角/全角括号、中间空格，结尾可能是中文（一体机、套机等）。**不改写、不补全、不纠正拼写。**
   品牌智能体传入的型号（示例 `BCD-345XXXX`）同样原样使用。
3. **降级**：两者都取不到时，本轮/记忆里有品类就改走 `query_product_attribute_by_category`；
   两者都没有才走 `4002`。禁止编造型号、禁止拿相近型号顶替。

一个说法命中多个型号时（如只说「云溪4.0」但有单洗/洗烘、10kg/12kg、Pro/Max 多个版本），
按 `product_name_aliases.json` 的 `series_disambiguation` **只追问缺失的那一个维度**，不要一次抛出全部型号。

> 别名映射**不是参数值来源、也不是在售清单**：它只负责把口语还原成型号。参数名与参数值一律以工具返回的
> `attributeName`/`attributeValue` 为准；映射表里的 `brand`/`category` 仅用于消歧与追问，不得当参数答给用户。
> 型号是否真实存在同样以工具返回为准，查不到走 `4003`（下游对「型号不存在」与「参数名没匹配上」
> 返回同一个空结果，不可区分，因此不宣称型号有误）。

其余约束：

- 品类词、套系名、品牌名不是型号（「冰箱」「致境」「卡萨帝」不得当型号下发）。
- 型号数量：当前轮 1~5 个，记忆 1~5 个；同一批数据按进入时间先后顺序取前 5 个。
- 识别到 **2 个及以上型号且用户要求对比** → 交回营销 Agent 走 `haier-product-comparison`，本技能不处理。

## 二之二、品类识别（→ `query_product_attribute_by_category` 的 `category`）

标准品类共 15 个，`category` 取值必须是其中之一（触发词见 `assets/trigger_dict.json` 的 `category`，
**取最长匹配**）：

冰箱、冷柜、波轮洗衣机、滚筒洗衣机、电热水器、太阳能热水器、燃气热水器、平板电视、
家中机、挂机、柜机、烤箱、洗碗机、吸排油烟机、燃气灶。

用户说模糊品类时按 `category_ambiguous_default` 取默认优先品类，**不要追问**：

| 用户表达 | 取值 |
|----------|------|
| 洗衣机 | 滚筒洗衣机 |
| 热水器 | 电热水器 |
| 空调 | 挂机 |

更具体的说法优先于本表：「滚筒洗衣机」直接命中 `滚筒洗衣机`，「柜机」命中 `柜机`，都不走默认表。

## 三、记忆合并与指代消解

| 场景 | 处理策略 |
|------|----------|
| 当前轮有型号，记忆也有型号，两者一致 | 直接使用，无需处理 |
| 当前轮有型号 A，记忆有型号 B，A≠B | 覆盖：以当前轮为准 |
| 当前轮无型号，记忆有型号 | 补全：使用记忆中的型号 |
| 当前轮说「第一款」「第二个」 | 定位：按 `memory_reference.ordinal` 从记忆最近一次搜索/推荐结果的型号列表按序号取 |
| 当前轮说「这款」「那个」 | 指代消解：按 `memory_reference.demonstrative` 使用记忆提取的槽位型号 |

- 序号超出记忆列表长度时不猜测，追问用户指的是哪一款。
- 品类：当前轮 1 个、记忆 1 个，均按时间先后（记忆按最近时间）截断；本轮品类覆盖记忆品类。
- 记忆里的型号与本轮品类冲突时（如记忆是冰箱型号、本轮问空调）以本轮为准，清掉不匹配的记忆型号。

## 四、参数维度 → 标准参数名（`attributeNames`）

参数名分两类，两个工具的 `attributeNames` 用同一套规则：

1. **品类专属参数名**：见 `assets/trigger_dict.json` 的 `attribute_slots_by_category`。
   **先确定品类，再只在该品类下的槽位里匹配**——品类下没列出的参数名不得下发。
2. **通用参数名**：见同文件 `universal_attribute_slots`，**所有 15 个品类下都有**，无需按品类判定。

`assets/consult_attributes.json` 的 `slot_synonyms` 作为口语同义词兜底（「多少钱」→ 价格、
「吵不吵」→ 噪音），并提供全量参数排序与卖点优先级。

### 通用参数名（所有品类）

| 参数名 | 触发词 |
|--------|--------|
| 套系 | 致境、指挥家、银河、鉴赏家、光年、揽光、星云、藏家、设计师、原石、小红花、麦浪、云溪、山茶花、天悦、Seeker、懒人 |
| **价格** | 数字 +（元/块钱/左右/以内/上下/出头）、预算、价位、价格、花了、花费、控制在、不超过、限 |
| 品牌偏好 | 海尔/haier、卡萨帝/casarte、统帅/leader（标准值 **海尔 / 卡萨帝 / Leader**） |
| 渠道 | 抖音/dy、快手/ks、拼多多/pdd、天猫/淘宝/tb、京东/jd、小红书/xhs、视频号/微信/小程序、线下/附近/门店/苏宁/国美…（枚举仅八项） |

- **金额条件的参数名是「价格」，不存在「预算」槽位**——用户说「预算」只是触发词，`attributeNames` 填「价格」。
- 渠道的「线上」「全部/不限渠道」是**聚合词不是枚举值**，命中时不产出具体平台名。
  用户真正问「在哪买」时交回门店引流技能，本技能只在用户把渠道当参数问时使用。

### 品类专属参数名（按品类取）

各品类下的槽位与触发词以 `attribute_slots_by_category` 为准，此处只列每个品类有哪些槽位。

> **冰箱、冷柜、烤箱、洗碗机的原「尺寸」参数已拆成「产品尺寸」与「安装尺寸」两个，
> 这四个品类下不再有「尺寸」**：下发「尺寸」后端匹配不到、返回空参数。
> 用户没提安装类词（安装 / 嵌入 / 橱柜 / 预留 / 开孔 / 全嵌 / 零嵌 / 半嵌 / 齐平）时问的是机身
> → `产品尺寸`；提了就是问橱柜开孔或预留空间 → `安装尺寸`；两头都问就两个都下发。
> 型号分支定不出品类时按合法名直接下发「尺寸」，或留空查全量。
>
> **门型类问题的参数名只有「门型偏好」**：「门体结构」「箱门结构」是参数库字段名，不得下发。

| 品类 | 专属参数名 |
|------|-----------|
| 冰箱 | 容量偏好、门型偏好、能效等级、定频/变频、噪音、**产品尺寸、安装尺寸**、颜色、功能偏好、安装方式 |
| 冷柜 | 容量偏好、颜色、能效等级、定频/变频、噪音、**产品尺寸、安装尺寸**、门型偏好、款式类型、制冷方式、功能偏好 |
| 波轮洗衣机 | 洗涤容量、能效等级、颜色、脱水噪音、洗涤噪音、尺寸、功能偏好、洗净比 |
| 滚筒洗衣机 | 洗涤容量、能效等级、颜色偏好、脱水噪音、洗涤噪音、尺寸、功能偏好、洗净比、筒数 |
| 烤箱 | 颜色、**产品尺寸、安装尺寸**、功能偏好 |
| 洗碗机 | 颜色偏好、容量偏好、**产品尺寸、安装尺寸** |
| 平板电视 | 尺寸偏好、产品颜色、安装方式 |
| 挂机 | 匹数偏好、能效等级、定频/变频、功能偏好、噪音、产品颜色 |
| 柜机 | 匹数偏好、能效等级、定频/变频、功能偏好、噪音、产品颜色 |
| 家中机 | 匹数偏好、能效等级、定频/变频、功能偏好、噪音、产品颜色 |
| 吸排油烟机 | 风量偏好、款式类型、功能偏好、安装尺寸 |
| 燃气灶 | 气源类型、灶眼数量、火力大小、功能偏好、安装尺寸 |
| 电热水器 | 容量偏好、加热类型、能效等级、功能偏好、安装限制 |
| 太阳能热水器 | 容量偏好、集热类型、辅助加热、功能偏好、安装条件 |
| 燃气热水器 | 容量偏好（单位为热水产出率 L/min）、气源类型、能效等级、功能偏好、安装方式 |

注意同名维度在不同品类下的**标准参数名不同**，不要跨品类套用：

- 「容量」：冰箱/冷柜/洗碗机/电热水器/太阳能热水器/**燃气热水器** → `容量偏好`（燃气热水器的
  取值口径是热水产出率 L/min，不是容积 L）；洗衣机 → `洗涤容量`；空调（挂机/柜机/家中机）→ `匹数偏好`。
- 「噪音」：洗衣机分 `脱水噪音` 与 `洗涤噪音`（分不清时两个都填）；其余品类为 `噪音`。
- 「颜色」：冰箱/冷柜/波轮洗衣机/烤箱 → `颜色`；滚筒洗衣机/洗碗机 → `颜色偏好`；
  平板电视/空调 → `产品颜色`。
- 「尺寸」：多数品类为 `尺寸`；吸排油烟机/燃气灶为 `安装尺寸`；平板电视为 `尺寸偏好`。
- 「安装」：电热水器为 `安装限制`；太阳能热水器为 `安装条件`；燃气热水器/平板电视为 `安装方式`。

映射要点：

1. 取**最长匹配**；同一句命中多个维度时全部写入 `attributeNames`，按用户提问顺序排列。
2. 只命中 `full_attribute_intent.words`（参数/配置/规格/全部参数）且没有具体维度 → `attributeNames` 留空，查全量参数。
3. **先定品类再匹配槽位。** 用户只给型号不说品类时（如「BCD-652WGCFDAGDXU1的容量多少」），
   先按 `trigger_dict.json` 的 `category_from_model_prefix` 由型号前缀推断品类
   （`BCD` → 冰箱 → 「容量」取 `容量偏好`），再取该品类下的标准参数名。
   **前缀推断不出品类时，`attributeNames` 留空查全量参数** —— 全量结果里同样包含用户问的那一项，
   照样答得出；而下发一个不存在的参数名（如「容量」）会让后端匹配不到、返回空参数，反而答不出来。
4. `attributeNames` 去重后最多 10 个，超出由宿主截断。
5. 映射不到标准参数名的长尾表达**不硬塞**：宁可留空查全量参数，也不得自造参数名。
6. **下发前用 `trigger_dict.json` 的 `legal_attribute_names.names` 逐个核对**：不在该全集内的
   字符串一律不许出现在 `attributeNames` 里。常见错填见 `legal_attribute_names.common_mistakes`
   （「容量」→ 按品类取 容量偏好/洗涤容量/匹数偏好，燃气热水器同取 容量偏好；「预算」→ 价格；「品牌」→ 品牌偏好；
   「功能」→ 功能偏好；「能效」→ 能效等级；「噪音值」→ 噪音）。
7. **不许自造「更正式」的近邻参数名。** 合法名只认 `legal_attribute_names.names` 这一份，
   不得参考产品对比/产品推荐技能里出现的参数库字段名（`噪音值`、`噪音值(dB)`、`内机噪音`、
   `总容积(L)` 等）——它们在本技能的两个查参数接口里都匹配不到，会返回空参数。
   某个维度的标准名拿不准时留空查全量参数，而不是拼一个看起来更专业的名字。

### 跨品类歧义词（最易出错）

「容量」「尺寸」「噪音」「颜色」这几个口语词**跨品类对应不同的标准名**，必须先定品类再取：

- 「容量」在任何品类下都**不是合法参数名**，必须换成该品类的标准名。
- 「尺寸」「噪音」「颜色」**本身就在 `legal_attribute_names.names` 里**，只是部分品类另有取值
  （洗衣机噪音拆成 `脱水噪音`/`洗涤噪音`、平板电视尺寸为 `尺寸偏好`、滚筒洗衣机颜色为 `颜色偏好`）。
  按下表取到哪个就下发哪个，**不要因为怕不合法而改写成 `噪音值` 这类自造名**。

| 用户口语 | 冰箱/冷柜 | 洗衣机 | 空调 | 燃气热水器 | 平板电视 | 其他 |
|----------|-----------|--------|------|-----------|---------|------|
| 容量 / 多少升 | `容量偏好` | `洗涤容量` | `匹数偏好` | `容量偏好`（L/min） | `尺寸偏好` | 洗碗机/烤箱/电热水器/太阳能热水器 → `容量偏好` |
| 尺寸 / 多宽 | `尺寸` | `尺寸` | `尺寸` | `尺寸` | `尺寸偏好` | 吸排油烟机/燃气灶 → `安装尺寸` |
| 噪音 / 吵不吵 | `噪音` | `脱水噪音` + `洗涤噪音`（两个都填） | `噪音` | — | — | `噪音` |
| 颜色 | `颜色` | 滚筒 → `颜色偏好`；波轮 → `颜色` | `产品颜色` | — | `产品颜色` | 洗碗机 → `颜色偏好` |

对照表见 `consult_attributes.json` 的 `_容量类消歧` / `_尺寸类消歧` / `_噪音类消歧` / `_颜色类消歧`。
**品类推断不出来时统一留空查全量参数**，不要赌某个标准名。

## 五、数值与区间表达

售前咨询是「查参数」而非「筛产品」，因此**不把数值下发为过滤条件**：

- 「BCD-526 多少钱」→ `attributeNames=["价格"]`，价格值以工具返回为准。
- 「5000 以内的冰箱有哪些」→ 这是选购筛选诉求，交回营销 Agent 走 `haier-product-recommend`。
- 用户原文里的数值只用于识别型号（如 510 那款）与理解语义，不参与参数值判断。

## 六、缺失与不追问原则

- 型号与品类**至少 1 项**；都没有时按 `4002` 引导补充，不猜测常见型号、不默认品类。
- 参数维度缺失不追问：直接查全量参数（场景二）比反问更符合用户预期。
- 记忆中的型号已失效或下游查不到时走 `4003`，只说查不到参数，不宣称型号有误。
