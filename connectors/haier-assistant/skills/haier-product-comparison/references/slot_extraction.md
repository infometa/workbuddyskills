# 上下文记忆与槽位提取（产品对比）

对应 PRD 3.3.1.4「上下文记忆与槽位提取」。触发条件：**上下文内容或本轮输入中存在产品型号**。
触发词与编辑动词见 `assets/trigger_dict.json`；对比参数口径见 `assets/comparison_attributes.json`。

## 一、型号槽位的合并规则

| 上一轮槽位 | 本次交互内容 | 解析规则 |
|------------|--------------|----------|
| 产品型号 | 增加对比产品型号：「再加个 C 一起比」/「把 D 也加上」 | 上一轮记忆中的型号列表 **增加** 本次交互产品型号 |
| 产品型号 | 删减对比产品型号：「去掉 B」/「不要 B 了」 | 从上一轮记忆的型号列表中 **移除** 指定型号 |
| 产品型号 | 替换：「换成 X 和 Y 比」/「重新对比」/「只比 X 和 Y」 | 用本轮型号 **整体替换** 记忆列表 |
| 对比粒度 | 「详细对比 / 逐项对比 / 再详细点」 | 切到场景4，型号列表保持不变 |

处理顺序：**先删除 → 再追加 → 最后判定替换**。同一句同时含增删时按此顺序处理（如「去掉 B，把 D 加上」）。

## 二、型号列表的规范化

1. 按**首次出现顺序**去重，忽略大小写（`bcd-510wdpz` 与 `BCD-510WDPZ` 视为同一型号）。
2. 保留用户书写的原始大小写传给工具，不改写、不补全、不纠正拼写。
3. **最多对比 5 个**：去重后超过 5 个时只取前 5 个，剩余型号进入截断提示（场景5）。
4. 去重后不足 2 个：不调用工具，直接走场景1 引导补充型号。

宿主已实现 2、3、4 的兜底：工具返回的 `comparedProductNames` 是实际参与对比的产品名，
`truncatedProductNames` 是被截掉的产品名，直接使用这两个字段渲染，不要自行重算。

## 三、型号识别边界

- 型号常见形态：`BCD-510WDPZ`、`BCD-470WLMDZ`、`KFR-35GW/xxx`、`EG100MATE`、`JSQ31-16WT5`。
- 用户只给部分型号（如「510 那款」「刚才第一个」）时，按上下文记忆回填完整型号；无法唯一确定则**追问完整型号**，不猜。
- 不得把品类词、套系名、品牌名当型号（「冰箱」「致境」「卡萨帝」都不是型号）。
- **不得为凑够 2 个型号而编造型号或从记忆外补充型号**——这是场景1 存在的原因。

## 四、对比参数提取

对比参数**按型号推荐槽位口径提取**：与 `haier-product-recommend` 的品类槽位一致
（容量偏好/洗涤容量/门型偏好/能效等级/定频变频/噪音/洗净比/匹数偏好/风量偏好/款式类型/
气源类型/火力大小/灶眼数量/功能偏好/安装方式/产品尺寸/安装尺寸/尺寸/颜色，以及通用槽位 套系/价格/品牌偏好）。
燃气热水器的升数/热水产出率槽位名就是 `容量偏好`（单位 L/min），**不存在「升数偏好」这个槽位名**。
价格槽位就叫「价格」，**不存在「预算」槽位**（「预算」只是触发词）；
**「渠道」不是对比参数**，用户提渠道时不要填进 `attributeNames`——填了下游也会被宿主剔除。

> **冰箱、冷柜、烤箱、洗碗机的原「尺寸」槽位已拆成「产品尺寸」与「安装尺寸」两个，
> 这四个品类下不再有「尺寸」**：下发它后端匹配不到、返回空参数。用户没提安装类词
> （安装 / 嵌入 / 橱柜 / 预留 / 开孔 / 全嵌 / 零嵌 / 半嵌 / 齐平）时比的是机身 → `产品尺寸`；
> 提了就是比橱柜开孔或预留空间 → `安装尺寸`；两头都问就两个都下发。
> 洗衣机仍是 `尺寸`，吸排油烟机 / 燃气灶只有 `安装尺寸`，平板电视是 `尺寸偏好`。
>
> **门型类参数名只有 `门型偏好`**：「门体结构」「箱门结构」是参数库字段名，不得下发。

- 参数**对齐与差异由工具后端完成**：同名参数对齐后分为 `sameAttributeList`（取值一致）与
  `differentAttributeList`（存在差异），Skill 不重算、不合并、不补齐缺失参数。
- 两个列表都是**优点总结的素材**，不是要渲染的表格：正文只出各自优点 + 选购建议。
- 参数排序与评判标准查 `assets/comparison_attributes.json`；参数值只来自工具返回。
- 用户点名要看某个参数（如「就看能效和噪音」）时，把标准槽位名填入 `request.attributeNames`，
  由后端只返回这些参数；工具没返回该参数就说明「暂无该参数数据」，不推断。
- **对比入参里没有品类字段，但跨品类歧义词（尺寸 / 容量 / 噪音 / 颜色）必须先定品类才能定名。**
  品类由型号前缀判断（`BCD` → 冰箱、`XQG` → 滚筒洗衣机、`XQB` → 波轮洗衣机、`CWY` → 洗碗机、
  `CXW` → 吸排油烟机、`JSQ` → 燃气热水器、`KFR-*GW` → 挂机、`KFR-*LW` → 柜机），
  与 `presale-product-consult` 的 `category_from_model_prefix` 同一份表。
  「比较前两款尺寸」+ 两台 `BCD-*` → 品类是冰箱 → 填 `产品尺寸`（**不是「尺寸」**，
  冰箱下没有这个参数）。前缀认不出或两款跨品类时不猜品类：省略 `attributeNames` 查全量。
- `attributeNames` 省略即对比全部有值参数。参数名不确定时**省略该字段**，不要猜——猜错会让后端
  返回空参数，表现为「查不到参数」。

## 五、与其它营销技能的边界

| 用户表达 | 归属 |
|----------|------|
| 「BCD-510WDPZ 和 BCD-470WLMDZ 哪个好」（有型号） | 本技能：产品对比 |
| 「三口之家五千预算的冰箱推荐哪款」（只有需求无型号） | `haier-product-recommend` |
| 「帮我比较两款空调」但一个型号都没给 | 本技能场景1 引导补充型号；用户给不出型号则转推荐 |
| 「这款在哪买 / 附近有没有门店」 | `haier-product-store` |
| 对比完用户问「那买哪个、去哪买」 | 先给出选购建议，购买渠道诉求再加载门店技能 |
