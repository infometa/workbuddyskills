# 参数对齐、差异与对比分析

对应 PRD 3.3.1.4「参数对齐与差异」「对比分析」。说明数据从哪来、怎么判优劣、怎么落到输出。

## 一、参数对齐与差异（下游完成）

拿到各产品参数列表后，**对齐同名参数、提取差异项**——这一步由 `query_product_comparison`
后端完成，Skill 直接消费结果，不本地重算：

| 工具字段 | 含义 | 用途 |
|----------|------|------|
| `sameAttributeList` | 相同参数列表：参数名 + 一致的取值 | 提炼「共同具备的优点」，写进各自优点段的开头一句 |
| `differentAttributeList` | 差异参数列表：每个产品一条（参数名 + 该产品的值） | 提炼各型号的差异化优点与选购建议的分流依据 |
| `productName` | 该条参数所属的产品名（型号） | 判断某条参数属于哪一款，据此归入该款的优点 |
| `priority` | 参数影响力排序，数字越小越高。**下游当前恒为空** | 排序依据；为空时按 `comparison_attributes.json` 的 `fallback_rank` 兜底 |
| `comparedProductNames` | 实际参与对比的产品名（去重截断后） | 各自优点分段的顺序、截断提示 |
| `truncatedProductNames` | 被 5 款上限截掉的产品名 | 场景5 截断提示 |

**这两个列表只是优点总结的素材，不是要渲染的表格**：按 `productName` 把参数归到各款名下，
按影响力排序挑出能构成优点的条目写成短句，**不逐项铺开、不出表格、不列相同点清单**。
某款缺某个参数就跳过该维度，不猜测、不用其它产品的值填充、不写「暂无数据」占位。

`sameAttributeList`/`differentAttributeList` 中**不会出现「渠道」**——宿主在下发前已剔除。
渠道是购买渠道信息而非产品能力，永远不作为对比参数；即便异常出现也不得写进优点或选购建议。

入参侧另有一个可选字段 `attributeNames`：用户点名只看某些参数时填入，省略即返回全部有值参数。
用户指定了参数时，优点与建议**优先按用户指定的参数**总结，顺序即用户提问顺序。

## 二、有效性校验与场景分派

下游先做「对比产品有效性校验」，Skill 按返回码分派场景：

| 下游判定 | 错误码 | Skill 行为 |
|----------|--------|-----------|
| 有效产品 ≤1 | `3002` | 场景1 话术②：引导补充型号（宿主在本地去重后不足 2 个、或**排除渠道后有效型号不足 2 个**时也直接抛该码） |
| 无同一类别下的有效产品型号 | `3003` | 场景2 话术③：跨品类无法逐项对比，给三个替代方向 |
| 同一类别下有效型号 ≥2 | `code=0` | 走对比正文：场景3（默认）或场景4（逐项），型号 >5 时先出场景5 截断提示 |
| 有对比数据但两组属性都为空 | `3001` | 提示核对型号，不输出空结论 |
| 服务繁忙 / 超时 | `3004` / `3005` | 输出稳定提示，不编造对比结果 |

**有效产品型号的判定标准**：排除渠道参数后，其它参数仍有有值的才算有效型号；
**只有渠道参数有值、其它参数全为空的型号是无效型号**。该判定由宿主完成（有效型号 <2 直接返回
`3002`），Skill 不必也不应自己判断某个型号是否有效。

## 三、优劣判定口径

判读标准取 `assets/comparison_attributes.json` 的 `judgement_standards`：

| 类型 | 例子 | 能否写成「优点」 |
|------|------|------------------|
| 越低越好 | 价格、噪音、额定功率、耗电量 | 能（如「更省电静音」） |
| 越高越好 | 能效比、最大风量、火力大小、质保年限 | 能 |
| 等级越小越优 | 能效等级 | 能（1级最优） |
| 有则更优 | 功能项（自清洁、变频、除菌、WiFi 互联…） | 能（对方没有才算差异化优点） |
| 中性 | 容量、尺寸、颜色、门型、气源、套系 | 不能判优劣，只作客观差异描述 + 适用场景 |

中性维度**不做胜出计分、不出胜出统计表**：容量更大不等于更好，写成「容量更大，适合囤货需求」
这类适用场景描述，把选择权交回用户。渠道不在上表任何一类里——它根本不参与对比。

## 四、各自优点的写法

- 每条优点必须**对应一条真实参数**（差异项或共同项），并带上参数值：「能效更优（1级 vs 2级）」。
- 每款 2-4 条短句，按影响力从高到低取；**不逐项铺开、不列表格、不写参数清单**。
- 不足 2 条时如实少写，不凑数、不虚假补充发散：参数没给的卖点不写，不推断使用体验。
- 中性差异不写成优点，改写成客观差异描述 + 适用场景。
- 不贬低竞品、不引入未在参数中出现的说法。

## 五、选购建议的写法

- ≤100 字，**按使用场景推荐，不强行指定唯一答案**。
- 结构参考：「看重 X（如省电静音）→ 选 {model_A}；看重 Y（如大容量）→ 选 {model_B}。」
- 参数不足以支撑判断时，说明还缺哪个维度，或反问用户更看重哪一项。
- 不承诺库存、价格有效期、优惠、赠品，也不引导下单支付；购买渠道诉求交由门店引流技能处理。
