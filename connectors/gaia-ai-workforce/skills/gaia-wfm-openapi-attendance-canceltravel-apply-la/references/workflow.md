# 销出差申请流程（LA）

本 Skill 仅通过 Gaia CLI 的 `YA ATD_FORM_APPLY` 命令处理当前登录人员的销出差业务。执行前先阅读并遵循 `gaia-cli` 的认证、租户、权限、安全确认和错误恢复规则。不得使用 curl、wget、SDK、直接 URL 或自建 HTTP 客户端，也不得索取或写入 Token、Secret、私钥等凭据。

使用本 Skill 前按 `gaia-cli` 执行 `gaia status --json`，核对当前租户的 `release_channel` 为 `LA` 且与本 Skill 的 `metadata.releaseChannel` 匹配；不匹配或无法确认时停止使用，不执行其中的业务命令。

## 当前业务接口契约

本 Skill 维护当前业务范围、方法目录和业务流程，不固化任何方法的请求参数、响应字段、Header、路径或示例值。执行任一方法前，先使用方法表中的“当前契约查询命令”读取该方法的最新 `--help`；帮助不足时，再运行 `gaia api show <module> <resource> --json`。仅按本次读取到的当前业务契约组装命令和解释结果。

如果方法不存在、当前契约无法读取，或当前方法含义已经变化，停止执行并说明原因；不要猜测其他方法替代。

## 适用场景

- 申请本人销出差：先检查销出差权限，再按日期范围获取可销出差的出差记录；用户选择记录并确认后提交申请。
- 修改本人已有销出差单：用户必须提供或在当前对话中确认表单号，同时确认要修改的记录、日期范围和说明后提交修改。
- 撤回本人销出差单：用户必须提供或确认表单号；撤回属于破坏性操作，执行前二次确认。
- 查询辅助信息：按日期范围查询当前用户可销出差的出差记录。

不处理他人的销出差、普通出差申请或撤回、销出差审批、附件传输、权限授予，或本 Skill 未列出的命令。普通出差的 `travelCancel` 不属于本 Skill。

## 工作流

### 查询可销出差记录
1. 调用 `getCancelTravelAccess`，仅在成功且未拒绝时继续；权限失败、认证失败、网络错误或业务错误均停止。
2. 收集用户明确的日期或日期范围，将自然语言解析为当前方法契约要求的范围；缺少或有歧义时先追问日期。
3. 调用 `getTravelRecordList`，展示真实返回的候选记录并标明实际查询范围；隐藏记录标识和其他技术标识，使用日期、出差类型、时段等业务信息区分候选。
### 申请销出差
1. 按“查询可销出差记录”流程取得并展示候选记录；用户必须使用日期、出差类型、时段等非 ID 业务字段明确选择一个或多个记录，并确认销出差日期范围及说明（如有）。选中后仅按当前方法契约在内部映射目标标识。
2. 展示申请摘要（销出差开始/结束日期、选中记录的业务字段、说明）并取得明确确认；摘要和确认提示不得展示技术字段或任何记录标识。
3. 确认后调用 `applyCancelTravel`。当前方法契约要求的字段仅按用户或可信上游明确给出的值传递，不自行推断。只有返回明确成功标志时才报告已提交，并记录真实返回的业务标识，供本次对话后续修改或撤回时作为候选目标。


### 修改

仅在用户明确表达修改意图且已确认表单号时调用 `modifyCancelTravel`。若用户没有表单号但给出日期范围，可先调用 `getTravelRecordList` 展示候选出差记录；查询契约未声明记录项结构，只有真实结果明确提供可用业务字段且用户选择后才能使用。展示表单号、待修改的日期范围、记录业务字段和说明并取得确认；修改摘要和确认提示不得展示 记录标识或任何记录标识。只传入用户确认的新值及契约字段。成功判定依据顶层 `code`、`message`、`reason` 与响应中的结果标志等真实响应，不因出现表单号就宣称成功。

### 撤回

仅在用户明确表达撤回意图且已确认表单号时调用 `cancel`。撤回是 destructive 操作，执行前展示表单号和影响并取得二次确认；该方法只传入契约声明的租户标识字段 Header（如已确认）和表单号 body。只有明确成功响应才报告已撤回。

## 跨命令业务顺序

保留本 Skill 规定的权限检查、辅助查询、用户选择、确认和提交顺序。前一步的结果只能在当前对话中真实返回且用户确认后，按下一步方法本次读取到的契约映射；不在 Skill 中固定响应字段名、路径或目标参数名。前置方法失败、结果为空或当前契约无法读取时停止后续调用。

## 结果、空结果与错误恢复

- 查询结果按真实响应内容中的数组展示，并说明实际日期范围；用户可见内容必须过滤 记录标识、内部记录标识和其他技术标识，不猜测记录项未声明字段的含义。
- 申请、修改或撤回后，只展示当前响应中实际返回且已通过当前契约确认的业务内容，不预设响应字段名或结果结构，也不根据历史描述改写字段含义。
- 空的响应内容或记录数组不是成功提交。说明实际日期范围和为空的字段，给出补充明确日期或重新选择记录的方向，不自动放宽范围或重试。
- 参数错误：保留 CLI 的字段级错误，只追问对应缺失/非法字段；用户修正后再执行原命令。
- 401/认证失败：按 `gaia-cli` 的认证恢复流程恢复登录或刷新状态后，仅重试原命令一次；仍失败则停止。
- 权限拒绝：展示 CLI 返回的 scope/诊断信息，不绕过检查或代为申请权限。
- 4xx/5xx、业务错误或服务异常：展示可用的 HTTP 状态、`code`、`message`、`reason` 和响应中的错误信息，说明下一步。写操作超时、502/504 或连接中断时，标记为“提交结果未知”，不得自动重试或重复写入；请用户先核对考勤系统记录。
- 多命令流程中，前置步骤失败立即停止；不要在权限、内部目标记录或表单号为空时继续写操作。记录标识只作为 CLI 请求字段使用，不向用户回显。

## 安全边界与确认

权限和记录查询为 read，无需额外确认；申请和修改为 write，提交前必须展示摘要并明确确认；撤回为 destructive，必须展示目标和影响并二次确认。查询结果、申请/修改摘要和确认提示不得展示 记录标识、内部记录标识或其他技术标识。不得输出凭据、服务 URL 或未被 CLI 契约确认的字段。

## 统一权限与排障输出

权限错误按证据区分三层：租户未获得 OpenAPI 授权时提示联系租户管理员；当前登录账号未获得业务接口权限时提示联系公司管理员或业务负责人；前两层通过后接口仍返回 403 时，标记为接口自身业务或数据限制，携带任务 ID 联系 CLI 业务负责人排查。无法从响应确认具体层级时，不武断归因，保留原始诊断和任务 ID。

缺少必填参数时只询问缺失字段；认证失败按 WorkBuddy `gaia-cli` 基础 Skill 恢复；业务接口 4xx/5xx、网络错误、解析失败或未知异常时停止依赖步骤，说明具体操作、接口错误信息和下一步。写操作超时、连接中断或最终状态无法确认时报告“提交结果未知”，不自动重试或重复提交。普通回复先给问题摘要、已确认事实、用户动作和任务 ID；用户明确要求完整链路时才使用 `gaia logs --info` 整理 stages、请求方法/路径、脱敏参数、响应、权限判断、重试关系和 Correlation/Trace ID，不原样转发日志 JSON。业务流程不得使用 `--debug`，不得展示 Token、密码、Secret 或服务地址。
