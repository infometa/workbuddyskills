# superun 创作

命令 `superun-ai`；工作目录 `./superun-workspace`；输出 schemaVersion "1"。具体命令和阶段以当前 CLI 返回为准。业务默认服务 superun.com，不增加服务器地址。

## 共享能力与职责边界

当前宿主直接使用本 Skill。产品、风格选择、设计、开发、质量检查与运营是执行阶段，按用户目标和 CLI 返回状态进入对应方法；各阶段复用同一套命令、认证与权限，阶段切换不扩大授权。

阶段转换时，先读取在途命令到可恢复状态，保留 sessionId、未决交互、已答内容与在途标识，由当前宿主继续下一阶段。同一 Session 只有一个写入者，CLI 自动推进时不强制回退。

宿主负责 CLI 调用、展示、收答与回复。业务问题、需求结论、设计、代码和运营产出来自 superun。新建任务直接进入 CLI，不先产出范围摘要或自建问卷；仅项目定位、认证和工具执行所需信息可以由宿主询问。

## 开始执行

### 先区分用户诉求与交互答案

- 已有项目的新诉求使用原 sessionId，将用户原话放入 `content`，通过 `chat send <sessionId> --input <文件>` 提交一次；新建仍走 `chat create`。聊天或宿主后续菜单的自定义输入同样处理，复用此前已说明的目标，不强制先选“继续创作”或推荐功能。
- “开启生图”“开启 superun 通用智能体”“给网站加个客服”等已包含目标，按普通需求送入 Superun 对话，由 Superun 判断用途、启用能力并返回必要问题或配置向导。不能因为识别到插件就改成直调 `plugin enable/disable`，也不能用宿主本地代理替代 Superun 能力，或改写成“自主优化项目”。
- 仅选择“继续创作”或“其他”且上下文没有诉求时，补问一句“你想新增或调整什么？直接告诉我就行。”；业务细节交给 Superun 澄清，不在宿主反复生成菜单或要求用户重述。
- 实际 Superun 问卷、功能选择或向导的答案（含自定义答案）按原 `interactionId`、选项映射和 `answerSchema` 回复，不改成新需求。明确的审查、测试、发布和报告修复保留对应专用流程；纯咨询、无关任务或明确切换宿主代理不自动作为创作需求发送。
- 必要的只读查询、CLI 当前返回的明确执行动作及用户明确指定的底层命令仍按原契约处理。每条业务命令读取完整回执后再决定下一步；需要用户配置、仍在等待或失败时走固定循环，不预先串接多个写命令。插件 `ENABLED` 只证明能力已启用，不代表图片已生成、应用已接入或原始需求已完成。

### 提交与读取

1. 保留用户目标、已有 sessionId、未决交互、已答内容及本轮相关附件。用户交给宿主的页面素材先取得本地可读文件，在本次 create/send 上按[命令表](commands.md#json-消息输入)逐个附加 `--file <path>`，让 Superun 同时收到需求和素材；继续项目不重新 create。
2. 使用宿主提供的 CLI 实际路径；缺失或不兼容时报告环境缺口并保留原任务，交环境层处理。需要账号授权时读取 [认证](authentication.md)。
3. 可能长时间运行的 CLI 调用使用已加载渠道的 Bash 后台参数与原任务结果工具，不让前台阻塞，也不自己加 &。从 [命令表](commands.md) 选择本次命令，通过包内运行脚本提交一次；脚本过滤重复进度，完整保留最终结果。
4. **进入 [固定执行循环](state-and-recovery.md)，每次命令返回后都回到该循环。** 不自行设计等待流程，不只读 stderr。

每次读到本轮可展示 URL，立即按已加载的协作预览规则调用展示工具：风格候选就绪即展示，每轮研发/修复完成都展示，不等待研发快照。创作与发布分别按 [全部端入口](project-links.md) 消费 development.routing 和 publish.routing：单端直接给入口，多端完整展示各端有名链接并引导进入，不只给默认端。当前宿主调用实际可用的展示工具，工具不可用时说明限制并提供全部真实链接。

## 循环需要什么，就读哪份文件

| 当前动作 | 读取 | 产出 |
|---|---|---|
| 读取结果、等待、问答与继续、异常恢复 | [固定执行循环](state-and-recovery.md) | 唯一下一步 |
| 展示问题、预览页面或进度 | [展示](host-presentation.md) | 用户实际看到的控件/页面 |
| 已收到用户答案，要回复交互 | [交互](interactions.md) | 对应原 interactionId 的一次提交 |
| 判断本轮阶段、允许展示的内容或上线流程 | [阶段](creation-flow.md) | 本轮允许的动作 |
| 自动测试、代码审查、报告后的修复或判断检查结果 | [质量检查](quality-checks.md) | 本次报告、来源标识、问题与验证证据及符合条件的下一步 |
| 安全扫描，或已上线项目的 Agent 友好接入 | [扩展能力](extend.md) | 扫描报告摘要；或所选方式的接入原文及三项接入引导 |
| 内容、活动、用户及业务数据查询或维护 | [运营](operations.md) | 原样转交需求，等待 superun 的真实执行结果 |
| 准备报告完成 | [交付](delivery.md) | 实际成果、证据和缺口 |

只读当前动作需要的文件，不一次读完所有参考。材料与输出字段由 CLI 提供；工具名称和能力从渠道配置生成。当前宿主展示问题、收集真实答案，再回复原交互继续执行。

保留用户原文和已有授权。密钥仅用安全输入；不绕过 CLI、版本门禁或权限。没有明确上线要求不发布；失败或未验证不能写成完成。
