# 展示：让用户实际看到

仅在固定循环要求展示时读取。CLI 返回数据；宿主调用工具展示。工具日志、JSON 或口头承诺都不是展示完成。

## 先加载宿主工具

读取 [宿主工具](host-tools.md) 的提问与页面小节；下面只规定云端业务材料如何展示。

每次展示业务预览（风格候选、演示页面、研发或修复后的预览）时，调用当前渠道对应的页面展示工具，并在同一轮面向用户的输出文案中写出 CLI 返回的完整真实 URL。可同时使用可点击链接，但不能只把 URL 藏在链接目标、工具参数或卡片中；多端预览逐端写明名称和 URL。工具成功后仍要写出 URL，工具不可用或失败时说明实际情况并保留这些 URL。

用户选项必须有明确名称，不能只显示“1、2、3”或自行改成含糊简称。需求澄清保留 CLI 的问题和选项原文；功能清单按 CLI 顺序展示全部“编号＋完整功能名称（title）”，详细说明（description）在用户追问时展开。提问控件放不下名称时，先在正文列出完整名称再收答。费用等影响用户决定的信息不能省略。

功能规划清单使用多选弹框，标题为“功能规划清单已生成，共 N 项，请选择要实现的功能（可多选）”，按实际数量填写；分页标明“第 p/m 页”，每个功能独立作为选项，禁止生成“实现 1、2、3”等组合套餐。分页收答与统一提交规则见交互指引；不能仅展示正文后结束提问。

## 按材料执行

| 材料 | 动作 | 完成依据 |
|---|---|---|
| 发布后高级设计师（ADVANCED_DESIGNER_POLISH） | 保留原发布结果与链接，将「高级设计师」加入本次原有选项一起收答；选中但没有具体要求时原样提示「请告诉我想调整哪些页面、具体想怎么改；也可以重新设计方案。」。有要求后执行 chat design；本项不适用风格阶段「委托设计师再设计一版方案」的文案、费用及不询问调整要求规则 | 用户明确选择并提供具体要求；重新设计也不调用 style append |
| 当前问题与选项 | 调用上方提问工具；完整保留题目、选项说明、单/多选、自定义输入及 ID 映射 | 用户看得到并能回答；预选和推荐不是答案 |
| 新就绪风格 previewUrl | 立即用上方页面工具打开并附链接；index 0/1/2/3 固定为 A/B/C/D | 页面工具真实回执；不可用时明确提供链接 |
| 采用方案 / 委托设计师 | 采用入口带方案名称与真实预览链接；委托入口使用“委托高级设计师再设计一版方案”，保留 CLI 当前费用说明，不缩成“设计一版”“继续”或单独编号；不新增调整要求或参考文件提问 | 用户看清选择对象和费用后再决定 |
| 功能清单 | 按 CLI 顺序展示全部“编号＋完整功能名称（title）”；description 在用户追问时展开，不自行概括名称，不只给编号 | 用户能明确知道每个编号对应什么功能，再选择 |
| 规划、changeLog | 按 CLI 要求原样展示，不扩写、重排或删减；用提问工具收当前未决决定 | 用户先看到内容，再作决定 |
| 本轮可展示的 demo.url、development.routing、publish.routing（兼容基础链接） | 按 [全部端入口](project-links.md) 主动交付全部端入口：单端一个链接，多端每个有名链接/卡片并引导进入，不能只给默认端。原始成果和报告仍保留；新轮次即使 URL 相同也重新展示 | 使用当前轮次与快照的真实工具回执；已打开不等于关键功能已验收 |
| autoTest/codeReview 与 conversation_message | 按 [质量检查](quality-checks.md) 展示真实报告和修复前告知，消息按 ID 更新，结果按 when 筛选引导 | 不能从操作完成推断检查通过 |
| securityReview | 按 [扩展能力](extend.md) 展示本次检查列表与报告摘要；不展开完整正文、不给报告或 PDF 下载链接 | 完成、消息结束或修复启动都不代表通过 |
| agentFriendly | 同一文档：`READY` 用当前提问工具收一次接入方式，`INSTRUCTIONS` 把所选原文放进一个文本代码块原样展示、不改写 URL | 原文已展示不等于已接入 |
| task_reminder | 原样展示 data.message 并链接 data.url；同一 data.id 去重，不同 ID 再次展示 | 仅提醒，不决定业务状态或重新提交 |
| Secret | 仅用安全输入渠道；没有就让用户在 CLI 安全环境完成 | 不在聊天中索取或回显密钥 |
| taskProgress | 按下面的进度规则展示 | 进度不决定继续等待或完成 |

完整材料超出工具题数/选项限制时，先展示完整正文，再分工具允许的批次收答。确实不支持题型才降级完整文本；不能截断选项、把多选改成单选或伪造不可点击按钮。

页面是否允许展示由 [阶段表](creation-flow.md) 决定。stylePlanning 不打开过渡演示或展示内部规划审批；研发预览缺失说明缺口，不用旧链接补位。不自行拼接域名，不以截图代替风格页面。

## 进度：有变化才展示

- 启动本地命令时只说明正在提交或等待回执；没有服务端接受或当前业务阶段的证据，不能说“需求已提交”“正在生成问卷”。
- 开始任务时说明正在做什么；已有真实步骤就展示步骤和状态，没有步骤时不编造计划、总数或百分比。格式不限，可用短句、列表、表格或卡片。
- 收到步骤开始/完成、阶段切换、新预览或新 warnings 时更新；同一批变化合并展示。保留本轮真实任务信息，不从历史补回已完成的旧任务。
- 普通进度没有变化就安静等待；CLI 主动发来的 task_reminder 按 ID 展示，不受进度去重影响。不为了汇报而启动查询、读日志或唤醒模型。重复事件先由包内运行脚本过滤。
- 问卷、用户需要处理的事项、失败、取消和最终结果立即处理，不能受进度去重或补查间隔影响。
- 宿主支持原位更新时更新同一张卡；否则有变化才追加。用户主动询问进度时说明当前已知事实，必要时查询一次，不把旧进度说成最新回读。
- 记录已展示任务内容、warnings、候选 choiceId+previewUrl 和文档轮次。changed/revision 只是辅助信号，不能仅因 revision 变化而重复一整段状态，也不能因 changed=false 丢掉首次进度或新问题。

`inspect-result` 的 presentation 是动作描述，performed=false 表示它没有替宿主调用 UI。程序过滤重复进度可以减少输入，但不能保证所有宿主都不会因其他通知唤醒模型。最终结果始终从原任务 stdout 接收，不能改成只看 progress.ndjson。
