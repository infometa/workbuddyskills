# 运营：原样转述、对话和等待

已有项目的内容维护、活动调整、用户及业务记录查询或修改属于运营范围，例如“查一下昨天各活动的报名人数”“把活动 A 的报名截止时间改到周五”。superun 本身是智能体，可以访问用户数据库理解并执行这些需求；宿主负责 CLI 交互。

## 进入与转交

保留原 sessionId、用户原话、附件、已有答案和授权；有在途操作先读取或恢复，有未决交互则沿原 interactionId 回复。项目定位不明时使用命令表中的 session 查询，仍无法确定才询问用户；不为运营任务重新创建项目。

将用户原话放入命令表定义的 JSON `content`；有本地附件时按命令表的文件上传规则加 `--file`，不构造内联附件，通过包内运行脚本调用一次：

```text
superun-ai chat send <sessionId> --input <输入文件> --timeout 600
```

不将原话改写成提示词、运营方案、任务分解或 SQL，不猜表名、字段或数据范围，不要求用户先导出数据。数据库访问和操作由 superun 完成，宿主不直连数据库，也不切换到另一套执行入口。查询需求不能自行扩大为修改需求，原授权随原话传递。

## 对话与等待

提交后立即回到 [固定执行循环](state-and-recovery.md)，复用同一套后台句柄、chat wait、interaction reply 和异常恢复规则。保存本轮 sessionId/messageId；本地超时或暂时没有回复不重发 send，结果不明先恢复状态，避免重复执行数据操作。

superun 返回问题时展示原文并收集真实答案，回复原 interactionId；不自行增加运营问卷。superun 返回结果时忠实展示，可调整排版，但不改写业务结论、操作范围或执行状态。

## 边界与交付

- 内容、活动和业务记录的数据维护继续由运营处理；新增功能、代码修改或界面改版按对应职责交接，保留原话及真实状态。宿主不把简单数据修改扩写成开发任务。
- 仅本次目标涉及上线状态时查询发布信息。运营操作本身不授权发布，不把“已上线”设为额外门槛；superun 返回真实权限或能力限制时展示缺口。
- 按本轮回复区分查询结果、执行完成、建议和未执行操作。只有方案、SQL、进度或 `COMPLETED` 时，不能声称数据库已修改；操作结果缺少依据就如实说明。
- 展示实际结果、影响范围和失败/未验证项；有本轮效果 URL 时按共享预览规则展示。纯数据结果不强求新页面、研发功能清单或发布菜单。
