# GATE 确认门检测

## 概念

pro agent 的首轮和每轮修改的回复可能**不是成品**，而是「方案确认请求」或「中间生成状态」。
方案确认请求需向终端用户转述方案、征得同意后发确认轮；中间生成状态直接续轮，**不需打扰用户**。

## 检测逻辑（按顺序短路）

1. **完成标志优先**：response 含「已完成 / 已保存 / 已生成并保存 / 修改已完成 / ✅」任一
   → 按**正常结果**处理，不再查关键词。
   - 例：「课程已生成并保存完成 ✅ …… 如需调整题目或配置，随时告诉我。」→ 成品，非 GATE。
2. **中间生成状态**：response 为「正在生成计划卡片，请稍等。」→ 直接发续轮（用户原话如
   「继续生成」），**不向用户要确认**（见 known-behaviors.md #1）。
3. **GATE 关键词**：命中下表任一 → 向终端用户转述方案，征得同意后发确认轮。
4. 未命中 → 按**正常结果**处理。

## GATE 关键词全表

### 方案类

| 关键词 | 示例文案 |
|---|---|
| 是否 | "是否开始生成？" |
| 确认 | "请确认修改方案" |
| 方案 | "修改方案：…… 确认后我即开始执行" |
| 请确认 | "请确认是否按此方案新增" |
| 是否开始 | "是否开始生成10道单选题" |
| 是否按此 | "是否按此方案修改" |

### 反问/澄清类

| 关键词 | 含义 |
|---|---|
| 请告诉 | 信息不足，agent 追问用户 |
| 请明确 | 需要更具体的需求 |
| 题型 | 追问要出什么题型（且无完成标志） |
| 知识点 | 追问覆盖哪些知识点（且无完成标志） |

## 旧版关键词更正（2026-09-14 实测）

| 已移除 | 原因 |
|---|---|
| `正在生成` / `请稍等` | 实测为中间生成状态（known-behaviors.md #1），误判会多余地打扰用户 |
| `告诉我` | 完成文案「随时告诉我」会误报 GATE（test 环境复现）；真实澄清场景已被 `请告诉` 覆盖 |
| `?` | 误报率高，任何含问号的完成文案都会命中；真实方案请求均含方案类关键词 |
