# 雀聘-简历管理平台

面向招聘顾问使用。用户用日常说法提需求即可，本技能说明每个功能的用途、参数和调用顺序，避免参数填错或跳过绑定步骤。

## 一、先判断是否已绑定

除「绑定雀聘账号」「查询绑定状态」外，**所有功能都要求账号已绑定**。
未绑定时功能会返回「尚未绑定」的提示，此时不要重试，直接引导用户绑定：

1. 调用「绑定雀聘账号」。它会自动打开浏览器授权页。
2. 告诉用户：已在浏览器打开雀聘页面，请在页面上**注册账号或登录已有账号**，然后点击「确认绑定」；页面上会显示一个校验码，可让用户核对。
3. 用户确认后调用「查询绑定状态」确认结果。已绑定即可继续原来的任务。
4. 若等待超时，把返回的链接原样给用户，让用户自行在浏览器打开。

授权码有效期 10 分钟，超时后重新调用「绑定雀聘账号」即可。
浏览器没自动弹出时，不要反复调用，改为把链接给用户。

## 二、功能与常用参数

| 功能 | 用途 | 关键参数 |
|---|---|---|
| 绑定雀聘账号 | 打开浏览器完成注册或登录并绑定当前设备 | 一般无需传参 |
| 查询绑定状态 | 确认是否绑定成功 | 无 |
| 查询当前账号信息 | 查看登录账号的姓名、机构、角色、联系方式 | 无 |
| 按职位要求搜索简历 | 从人才库检索候选人 | 职位要求、城市、行业、职位名称、页码、每页条数 |
| 查看简历详情 | 取某位候选人的完整简历 | 简历编号 |
| 新增简历 | 把一份简历录入人才库 | 简历原文或文件路径、是否只预览 |
| 简历与职位匹配分析 | 多份简历 vs 一份职位要求，给出匹配排序与结论 | 职位描述、多份简历、特别看重的点、返回前几名、细致程度 |
| 退出登录 | 清除本机登录状态 | 是否保留平台侧绑定记录 |

## 三、逐个功能的用法

### 按职位要求搜索简历
- 把用户给的职位要求**整段**放进「职位要求」参数，系统会据此智能匹配；不要自行拆解成关键词再拼。
- 用户额外提到的城市、行业、职位名称，分别填到对应参数，不要混进职位要求文本里。
- 用户说「多找一些」时调大每页条数或翻页；默认第 1 页、每页 10 条。
- 返回结果里每位候选人都带一个**简历编号**。需要看某人的完整简历时，把这个编号传给「查看简历详情」。

### 查看简历详情
- 优先用搜索返回的编号。用户直接给了别的简历编号时，用第二个编号参数。
- 展示时整理成基本信息、工作经历、教育经历、项目经历等板块，便于阅读。

### 新增简历
- 用户粘贴了简历内容 → 用「简历原文」；用户给了本机文件路径 → 用「文件路径」。
- **默认先预览**：先以「只预览不录入」的方式整理出内容给用户核对，用户确认后再正式录入。
- 简历里缺少求职状态、联系方式这类必填信息时，系统会补默认值，需如实告知用户补了什么。
- 「识别方式」一般保持默认的智能识别即可；只有在用户明确要求快速处理时才用简易识别。

### 简历与职位匹配分析
- 适用场景是**一次分析多份简历**（用户上传或粘贴了多份）。单份简历不必用本功能，直接查详情再加搜索即可。
- 多份简历可以粘贴多段原文（用数组），也可以给多个本机文件路径；两种方式二选一，不要都传。
- 用户说了「重点看大厂经验」「看重团队管理」这类偏好，填到「特别看重的点」，会显著影响结论。
- 用户只说「谁最合适」时，用「返回前几名」限制条数，避免输出过长。
- 结论按「最匹配的是谁、匹配度多少、强在哪、风险或差距在哪」来讲，不要罗列原始数据。

## 四、错误与恢复

- **提示尚未绑定** → 按第一节引导绑定，不要重试原功能。
- **提示登录状态已失效** → 调用「退出登录」，再重新「绑定雀聘账号」。
- **提示网络连接异常** → 稍等片刻重试一次；仍失败则告知用户服务暂时不可用。
- **提示找不到简历** → 编号可能抄错或简历已不在库中，回到搜索结果重新取编号。
- **文件读取失败** → 让用户确认文件路径正确、文件不是加密或扫描件；可请用户改为粘贴简历原文。

## 五、需要用户确认的操作

- 新增简历在**正式录入前**必须让用户确认过整理结果；用户没确认就不要去掉预览。
- 退出登录会清除本机登录状态，用户没明确要求时不要主动调用。

## 六、表达要求

只讲业务结论与下一步建议。不要说调用了哪个功能、传了什么参数、结果里有哪些字段名，
也不要说内部处理过程或数据结构。候选人相关以「姓名 + 关键亮点」的方式呈现。
