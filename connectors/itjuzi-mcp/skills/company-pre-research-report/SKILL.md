# IT桔子公司预研 Skill

## 适用场景

当用户要给客户、商务、投研或内部评审输出一份“数据先行、判断可追溯、风险可拆解”的公司预研材料时，使用本 Skill。

典型问题：

- 帮我给某家公司做一份 IT桔子预研报告。
- 生成一份某公司的 BP 核查稿。
- 我给你一个公司名，先查 IT桔子数据，再补公开信息，输出客户可看的初筛材料。
- 帮我判断这家公司是否值得继续跟进，并列出公开风险和下一步建议。

## 核心目标

1. 先识别公司，再输出公司画像和融资信息。
2. 遇到多候选时先消歧，不要猜。
3. MCP 不足时，允许结合公开联网信息补强。
4. 所有结论都要区分“已核验”和“待核实”。
5. 报告要形成 IT桔子自己的判断框架：数据口径、资本路径、业务线索、赛道参照、风险清单、下一步动作。

## 证据原则

### 1. MCP 优先

先用 IT桔子 MCP 获取结构化事实：

- `resolve_companies`
- `get_company_profile`
- `get_company_funding_events`
- `search_events`
- `search_tags`
- `get_lookup_options`

### 2. 联网补强

当以下信息需要补充时，使用运行时可用的公开联网能力：

- 最新融资、股改、上市、产品发布、组织变化
- 官方口径、公告、招股书、监管披露
- 公开客户、合作案例、第三方研究

### 3. 来源优先级

优先级从高到低：

1. 官网、公告、招股书、监管披露
2. 公司采访、产品发布、权威媒体
3. 可核验的第三方报道
4. 百科、社区、转载，只能辅助

### 4. 冲突处理

- MCP 与公开来源不一致时，两者都保留。
- 必须说明来源名称、时间和差异。
- 不把传闻写成结论。

## 工作流

### 1. 建立公司识别口径

调用 `resolve_companies`。

如果只有一个命中：

- 继续查公司画像、融资事件、标签和相关事件。

如果有多个命中：

- 列出候选。
- 给出主体名称、简称、地区、行业、融资阶段等可辨识字段。
- 让用户确认后再继续，不要默认选择。

如果没有命中：

- 明确写出“IT桔子暂未收录或未命中”。
- 进入公开信息补强或用户素材整理模式。
- 不要虚构融资轮次、投资方和估值。

### 2. 拉取 IT桔子事实底座

优先输出：

- 公司主体、简称、地区、成立时间、经营状态
- 业务定位、行业、标签、关联概念
- 融资事件、轮次、金额、时间、投资方
- 相关并购、上市、投资、招投标或新闻事件
- 与查询词相关的消歧说明

### 3. 补公开来源

补强以下内容：

- 最新产品、客户、合作、招聘、组织变化
- 官网、公告、招股书、监管披露中的可核验事实
- 公开报道中的竞争位置、商业化进度和争议信号
- 与 MCP 数据不一致的时间、金额、主体或轮次差异

### 4. 输出报告结构

使用 IT桔子自有结构，不复刻外部报告模板。建议结构：

1. **识别结论与数据口径**：说明命中的公司、是否存在同名候选、使用了哪些 MCP 工具和公开来源。
2. **公司基础画像**：主体、定位、行业标签、产品/服务、区域和发展阶段。
3. **融资与资本路径**：按时间梳理融资轮次、金额、投资方、估值线索和资本化进度。
4. **业务与商业化线索**：产品能力、客户/合作、收入或落地迹象，只写可追溯事实。
5. **赛道位置与参照对象**：结合行业、标签、竞品或相邻公司，说明公司所处位置。
6. **IT桔子预研判断**：用“继续跟进 / 谨慎跟进 / 暂缓跟进”给出明确判断，并说明理由。
7. **决策参考维度**：必须包含“公开风险与待核实事项”和“投资关注点与下一步建议”。
8. **来源与置信度**：区分 MCP 事实、公开联网事实、用户输入和推断。

### 5. 决策参考维度

最后的决策部分必须增加以下两项，不要只作为普通风险段落带过。

#### 公开风险与待核实事项

按“风险信号 / 为什么重要 / 当前证据 / 核实动作”组织：

- 公开风险：诉讼、监管、经营异常、舆情争议、客户集中、融资停滞、商业化不足、估值倒挂、关键人员变动等。
- 待核实事项：收入规模、客户真实性、技术壁垒、核心团队稳定性、融资金额和估值口径、投资方是否真实参与、产品是否仍在运营等。
- 不能确认的内容写成“待核实”，不要写成事实。

#### 投资关注点与下一步建议

按“关注点 / 核验方法 / 建议动作 / 优先级”组织：

- 投资关注点：赛道空间、增长质量、资本效率、客户质量、竞争壁垒、融资节奏、退出可能性。
- 下一步建议：约访创始人、核验客户、拉取工商/知识产权/招投标信息、对比竞品融资、复盘历史投资方、请求 BP 或财务口径。
- 建议必须可执行，不要只写“持续关注”。

## 报告写法

### 该写什么

- 先给识别结果和数据口径。
- 明确区分 MCP 事实、公开来源事实和推断。
- 用短句写判断，用表格或清单承载证据。
- 把公开风险和待核实事项拆开写。
- 给出下一步可执行动作。

### 不该写什么

- 没有来源的确定性结论
- 把公开传闻写成事实
- 用模糊词掩盖信息缺失
- 把未核验信息和 MCP 事实混在一起
- 复刻外部供应商报告的章节顺序、标题和固定文案

## 默认假设

- 这个 Skill 面向 IT桔子公司预研、项目初筛、BP 核查和客户沟通材料。
- 联网不是技能内置能力，而是运行时可用的公开信息补强能力。
- 若公开来源与 MCP 冲突，必须同时呈现差异。
- 最终报告应体现 IT桔子的数据产品特色，而不是外部报告复刻。
