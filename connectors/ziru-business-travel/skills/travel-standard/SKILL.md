# 差旅标准查询

查询当前用户的差旅标准（差标），包括机票舱位等级、火车席别、酒店价格限制等。

## 工具

| 工具 | 用途 |
|------|------|
| `ziru_travel_standard` | 查询用户差标 |

**参数要点**：
- 传 `cityName` + `checkInTime`：返回机票+火车+酒店三类
- `cityName`：必须传完整官方城市名，如"南京市"、"句容市"、"恩施土家族苗族自治州"
- `parentName`：`cityName` 的上级行政区划名称（酒店差标用），必须传完整名称。地级市的上级是省（如南京市→江苏省），县级市的上级是地级市（如昆山市→苏州市）
- `cityLevel`：城市级别，需根据城市类型正确设置：
  - `1`：省级（如"江苏省"）
  - `2`：地级市/自治州（如"南京市"、"苏州市"、"恩施土家族苗族自治州"）
  - `3`：区县/县级市（如"句容市"、"昆山市"、"江阴市"）
- 不传城市：只返回机票+火车（酒店必须知道城市）
- 传 `businessType`：只查指定类型（flight/train/hotel）

详细参数与返回字段见 `@references/standard.md`。

## 核心规则

### 0. 严禁捏造差标内容

接口返回的 `text` 字段是差标的**唯一来源**：
- **原样展示** `text` 内容，不要编造舱位代码、折扣、价格、席别等
- `hasStandard=false` 时直接展示接口返回的文案
- 下方示例的具体内容**仅为格式参考**，实际必须用接口返回的真实 `text`

### 1. 调用策略

| 用户诉求 | 处理方式 |
|----------|----------|
| 泛问差标，**有城市+日期** | 一次调用 `ziru_travel_standard(cityName=xx, parentName=xx, cityLevel=xx, checkInTime=xx)` 返回三类 |
| 泛问差标，**无城市+日期** | ① 先调用一次返回机票+火车；② `AskUserQuestion`弹窗问城市和日期；③ 拿到后再调用一次返回酒店 |
| 只问酒店差标 | **必须追问**城市和日期，拿到后再查 |
| 只问机票/火车差标 | 直接查，无需城市 |

**cityLevel 判断规则**：根据用户提到的城市名称判断：
- 省会、地级市、自治州 → `cityLevel=2`（如南京、苏州、恩施土家族苗族自治州）
- 县级市、区、县 → `cityLevel=3`（如句容、昆山、江阴）
- 如果无法判断，默认用 `cityLevel=2`

### 2. 展示格式

```
您的差旅标准如下：

【机票差标】
{接口返回的text}

【火车差标】
{接口返回的text}

【酒店差标】（{城市}，{日期}入住）
{接口返回的text}
```

某项差标为空或"未开启"时，告知用户该业务暂无限制。

### 3. 追问规则

用 `AskUserQuestion` 弹窗补齐缺失信息：
- 一次问完所有缺失项（城市+日期），禁止挤牙膏
- 选项只给常见枚举，依赖卡片自带的自由输入框承接开放值
- 追问卡与答案**不要放在同一轮**：要问就只弹卡
- 用户取消/跳过时，告知"未选择城市和日期，无法查询差标"

**追问示例**：

```js
AskUserQuestion({
  questions: [
    {
      header: "出差城市",
      question: "要查哪个城市的酒店差标？",
      options: [
        { label: "南京市", description: "江苏省会" },
        { label: "恩施土家族苗族自治州", description: "湖北自治州" },
        { label: "昆山市", description: "江苏县级市" }
      ]
    },
    {
      header: "入住日期",
      question: "计划哪天入住？",
      options: [
        { label: "今天入住" },
        { label: "明天入住" },
        { label: "本周末" }
      ]
    }
  ]
})
```

> 注意：必须使用完整官方城市名（如"南京市"而非"南京"，"恩施土家族苗族自治州"而非"恩施"），上级行政区划名称也要传完整（如南京市的上级是"江苏省"，昆山市的上级是"苏州市"）。只缺日期时，只传日期一个问题即可。

## 输出示例

> ⚠️ 示例中的具体差标内容**仅为格式参考**，实际必须替换为接口返回的 `text`。

### 场景一：无城市，先机火后酒店

```
用户：我的差标是什么？

AI：
（调用 ziru_travel_standard()，返回机票+火车）

您的差旅标准如下：

【机票差标】
{text}

【火车差标】
{text}

（同时弹窗询问城市和日期）

[用户选择：南京，明天入住]

AI：
（南京是地级市，cityLevel=2，上级行政区划为江苏省）
（调用 ziru_travel_standard(cityName=南京市, parentName=江苏省, cityLevel=2, checkInTime=明天)）

【酒店差标】（南京市）
{text}
```

### 场景二：有城市+日期，一次三类

```
用户：10月1日去南京，我的差标是什么？

AI：
（南京是地级市，cityLevel=2，上级行政区划为江苏省）
（调用 ziru_travel_standard(cityName=南京市, parentName=江苏省, cityLevel=2, checkInTime=2026-10-01)）

您的差旅标准如下：

【机票差标】
{text}

【火车差标】
{text}

【酒店差标】（南京市，2026-10-01入住）
{text}
```

### 场景三：无差标/异常

```
接口返回：hasStandard=false, text="用户未开启飞机差标"

→ 展示：您当前未开启机票差旅标准，可按需预订，无限制。
```

鉴权失败时，提示用户重新填写 Access Token。

## 不做的事

- 不修改差标配置（只读查询）
- 不替用户做差标申请或审批
