前置条件

必须 Node.js >= 18（node -v 检查）

必须 macOS / Linux / Windows 环境

必须 我方提供的 slclaw-connector.zip 包

必须 我方提供的 API Key（sl- 开头）

提交包结构（给 WorkBuddy 审核）

我方提供的 slclaw-connector.zip 即为 WorkBuddy 连接器提交物，解压后结构如下：

slclaw-connector/
├── connector-meta.json     ← WorkBuddy 读取：市场展示信息
├── cli.json                ← WorkBuddy 读取：CLI 生命周期管理
├── icon.png                ← WorkBuddy 读取：图标
├── default.env             ← CLI 默认环境配置模板
├── skills/                 ← WorkBuddy 读取：AI 技能（WorkBuddy 加载给 AI）
│   └── starrocks-business-analysis-sly/
│       ├── SKILL.md        ← 入口文件（AI 从这里理解能力）
│       ├── intents/        ← 78 个业务意图模板
│       ├── rules/          ← 安全规则、输出规范、参数补全
│       └── references/     ← 数据表结构参考
├── install.sh              ← init 脚本（macOS/Linux）
├── install.ps1             ← init 脚本（Windows）
├── package.json            ← CLI 依赖描述
└── dist/                   ← CLI 编译产物（运行时依赖已打包）
source 主键：connector-meta.json 中 source 固定为 shanlong-claw，上架目录请使用 connectors/shanlong-claw/。zip 文件名仅作为交付物名称，不作为端侧持久化主键。
关于 Skills 的放置：Skills 在 zip 包内随连接器提交，WorkBuddy 平台负责加载 skills/ 目录内容给 AI。init 命令（install.sh）只安装 CLI 程序本身，Skills 不需要安装到用户机器上。

打包（开发者操作）

# 在 slclaw-cli 项目根目录执行
bash connector/pack.sh

# 产出：slclaw-connector.zip

安装

macOS / Linux

# 1. 解压（-o 覆盖已存在文件）
unzip -qo slclaw-connector.zip -d slclaw-install

# 2. 执行安装脚本
cd slclaw-install && bash install.sh

# 3. 如需在普通终端直接使用 sl，可手动添加 PATH
export PATH="$HOME/.slclaw/bin:$PATH"

# 4. 填入 API Key
sed -i.bak 's/^SL_API_KEY=.*/SL_API_KEY=你的Key/' ~/.slclaw/.env && rm -f ~/.slclaw/.env.bak

# 5. 验证
sl connector status
# 输出 {"authenticated":true} 表示成功

Windows (PowerShell)

# 1. 解压
Expand-Archive -Force slclaw-connector.zip -DestinationPath slclaw-install

# 2. 执行安装脚本
cd slclaw-install
powershell -ExecutionPolicy Bypass -File install.ps1

# 3. 安装脚本不会自动修改用户 PATH；WorkBuddy 使用绝对路径调用

# 4. 编辑 %USERPROFILE%\.slclaw\.env，填入 SL_API_KEY
notepad $env:USERPROFILE\.slclaw\.env

# 5. 验证
& "$env:USERPROFILE\.slclaw\bin\sl.cmd" connector status
# 输出 {"authenticated":true} 表示成功
已安装过？直接再次执行安装脚本即可升级，已有的 API Key 和 Token 会保留。

验证调用

认证状态

# 检查连接器认证状态
sl connector status
# 输出 {"authenticated":true} 表示成功

StarRocks 数据仓库查询

# 查询集团门店列表
sl starrocks read-query --query "SELECT store_code, store_name, brand_name \
  FROM e000.dt_store_view \
  WHERE group_code = '#{SL_UNIFIED_G_ID}' \
    AND store_code IN (#{omShopCodes}) LIMIT 5"

# 查询营收汇总
sl starrocks read-query --query "SELECT store_name, SUM(recv_money) as recv \
  FROM dm.v_pos_corp_sale_analysis_with_sly \
  WHERE group_code = '#{SL_UNIFIED_G_ID}' \
    AND store_code IN (#{omShopCodes}) \
    AND settle_biz_date >= '2025-06-01' \
  GROUP BY store_name ORDER BY recv DESC LIMIT 3"

正常返回 "success": true + "rows" 数组。

CY7 餐饮收银

# 获取门店列表
sl cysms getshops

# 获取 Access Token
sl cysms accesstoken

正常返回 "shopList" 数组 / "msg": "success"。

CRM 会员管理

# 查询优惠券列表
sl coupon get-coupon-list

# 按手机号查询会员
sl member member-query --mobile "手机号"

正常返回 "total" + "list" 数据。

SCM 供应链

# 查询物料列表
sl scm_archive_item get-item-select-list

# 按关键词搜索物料
sl scm_archive_item get-item-select-list --keyword "关键词"

正常返回物料 JSON 数组。

注意：各产品线命令可以任意顺序调用，互不干扰。StarRocks 查询中的 #{SL_UNIFIED_G_ID} 和 #{omShopCodes} 是系统变量占位符，CLI 自动替换为当前认证用户的集团和门店信息。

卸载

macOS / Linux

# 方式一：用安装脚本卸载（推荐）
cd slclaw-install && bash install.sh --uninstall

# 方式二：手动删除
rm -rf ~/.slclaw

Windows (PowerShell)

# 方式一：用安装脚本卸载
cd slclaw-install
powershell -ExecutionPolicy Bypass -File install.ps1 -Uninstall

# 方式二：手动删除
Remove-Item -Recurse -Force $env:USERPROFILE\.slclaw

重复安装 / 重置

macOS / Linux

# 覆盖安装（保留 Key 和 Token）
bash install.sh

# 完全重置（清除所有配置后重装）
bash install.sh --reset

Windows

# 覆盖安装
powershell -ExecutionPolicy Bypass -File install.ps1

# 完全重置
powershell -ExecutionPolicy Bypass -File install.ps1 -Reset

无论之前是否卸载干净，重新执行安装脚本都能正确安装。

WorkBuddy 接入配置（cli.json）

# WorkBuddy 使用 cli.json 管理 CLI 生命周期：
           darwin / linux              win32
─────────────────────────────────────────────────────
init       bash install.sh             powershell ... install.ps1
auth       "$HOME/.slclaw/bin/sl" connector auth
status     "$HOME/.slclaw/bin/sl" connector status
unAuth     "$HOME/.slclaw/bin/sl" connector unauth
version    "$HOME/.slclaw/bin/sl" --version

win32 auth/status/unAuth/version:
powershell -NoProfile -ExecutionPolicy Bypass -Command "& "$env:USERPROFILE\.slclaw\bin\sl.cmd" ..."

statusMatch: "\"authenticated\"\\s*:\\s*true"
runtime:     { "type": "node", "version": ">=18" }

# WorkBuddy 从 zip 包中加载 skills/ 目录给 AI：
skills/starrocks-business-analysis-sly/SKILL.md  ← 入口
skills/starrocks-business-analysis-sly/intents/  ← 业务意图
skills/starrocks-business-analysis-sly/rules/    ← 规则
skills/starrocks-business-analysis-sly/references/ ← 参考
WorkBuddy 加载流程：用户点击「连接」→ WorkBuddy 执行 init 安装 CLI → 执行 auth 认证 → 轮询 status 确认已认证 → 加载 skills/ 给 AI。Skills 由 WorkBuddy 从连接器包中读取，不依赖用户本机文件。

常见问题

sl: command not foundWorkBuddy 不依赖 PATH；手动终端使用时确认 export PATH="$HOME/.slclaw/bin:$PATH" 已添加
缺少 SL_API_KEY_BASEURL用 --reset 重装恢复完整配置
API Key 换 Token 失败确认 Key 正确且未过期
查询返回空数据测试集团可能无交易数据，属正常
Windows 执行策略报错使用 -ExecutionPolicy Bypass
