# 未命中 Intent 处理规范

## 概述

当用户的问题**没有直接对应**的 Intent 时，按以下规范处理。

---

## 🔀 五级处理机制

| Level | 情况 | 处理方式 |
|-------|------|----------|
| **1** | 意图相近，可映射到已有 Intent | 直接映射到最近的 Intent |
| **2** | 跨多个 Intent 的复合需求 | 拆解为多个子问题，依次调用不同 Intent |
| **3** | 有数据但无对应 Intent | 基于业务理解，自主构造 SQL 分析 |
| **4** | 数据不存在 | 明确告知 + 引导替代方案 |
| **5** | 意图不明确 | 主动提问，引导用户澄清 |

---

## Level 1：意图相近，映射到已有 Intent

**判断标准**：用户问题与某 Intent 的触发关键词高度重合。

**处理方式**：直接使用该 Intent，Slots 填默认值或询问补充。

**示例**：

| 用户问题 | 映射到 | 原因 |
|---------|--------|------|
| "看看九田家最近生意" | Intent 6 营收趋势 | 含"最近"+业务分析意图 |
| "哪家店翻台率高" | Intent 11 客群分析 | 翻台率是 Intent 11 的关键指标 |
| "有没有超过1000平的店" | Intent 5 门店规模排名 | 面积 + 排名 = Intent 5 |

---

## Level 2：跨 Intent 复合需求

**判断标准**：用户问题涉及多个分析维度，需要多个 Intent 才能完整回答。

**处理方式**：拆解为多个子问题，按逻辑顺序依次调用。

**拆分原则**：
1. 先查基础数据（门店列表 → 营业数据）
2. 后做分析（趋势 → 对比 → 建议）
3. 优先回答核心问题，再补充次要信息

**示例**：

| 用户问题 | 拆解 | 调用顺序 |
|---------|------|---------|
| "哪些区域的外卖做得最好" | ① Intent 2 区域分布 → ② Intent 8 外卖分析 | 先找区域，再按区域筛选外卖数据 |
| "直营店和加盟店哪个客单价高" | ① Intent 4 管理类型 → ② Intent 11 客群分析 | 先确认哪些是直营/加盟，再对比 |
| "最近一个月各品牌的营收排名" | ① Intent 3 品牌排名 → ② Intent 6 营收趋势（按品牌） | 先列品牌，再取营收数据 |

---

## Level 3：有数据但无对应 Intent

**判断标准**：用户问题有明确的分析目的，但 78 个 Intent 都不完全覆盖。

**处理方式**：**仅在已知的 7 张表上**，基于业务理解自主构造 SQL 查询。

**构造原则**：
1. **只使用 SKILL.md 表结构章节中列出的 7 张已知表**（`e000.dt_store_view`、`dm.v_pos_corp_sale_analysis_with_sly`、`dm.v_item_sale_analysis_with_sly`、`dm.dm_crm_card_sum_day_p_store`、`dm.v_crm_member_with_sly`、`dw.dwd_crm_member_card_p_with_sly`、`dm.dm_ljc_scm8_store_rm_item_consume_analysis_day_p_group_view`）
2. 复用现有 Intent 的 SQL 模板，调整 `SELECT` 字段、`WHERE` 条件、`GROUP BY` 维度
3. 保持 `group_code`、`store_code IN (#{omShopCodes})`、日期范围、LIMIT 等安全约束
4. 输出格式参考 `rules/output-format.md`

> 🛑 **禁止猜测表名**：如果用户的问题涉及的数据不在上述 7 张表中，**直接降级到 Level 4**，告知用户该分析暂不支持。绝对不要使用 `SHOW TABLES`、`information_schema` 查询，也不要逐个尝试 fct_xxx / dws_xxx / ads_xxx / ods_xxx / dwd_xxx / dim_xxx / rpt_xxx 等前缀组合来猜测表名——这会导致大量无效查询并触发超时。

**示例场景**：

| 用户问题 | 处理方式 |
|---------|---------|
| "每天的早市和晚市营收对比" | Intent 13 时段分析 + 横向对比（使用已知营业表） |
| "优惠超过100元的订单有多少" | 在营业表上增加 `WHERE disc_money_total > 100` |
| "哪些门店连续3天营业额下滑" | 时序分析 + 窗口函数（使用已知营业表） |
| "查询一下团购情况" | 7 张已知表中无团购字段 → **降级到 Level 4**，告知暂不支持 |

**SQL 构造模板**：

```sql
SELECT
    settle_biz_date AS 日期,
    store_name AS 门店,
    SUM(busi_income) AS 实收金额
FROM dm.v_pos_corp_sale_analysis_with_sly
WHERE group_code = '#{SL_UNIFIED_G_ID}'
    AND store_code IN (#{omShopCodes})
    AND settle_biz_date >= :start_date
    AND settle_biz_date < :end_date_plus_1
    {{#if 自定义条件}} AND {{自定义条件}} {{/if}}
GROUP BY settle_biz_date, store_name
ORDER BY 日期, 实收金额 DESC
LIMIT 100;
```

## Level 4：数据不存在

**判断标准**：用户询问的内容在当前集团数据中完全不存在。

**处理方式**：
1. 明确告知数据不存在
2. 说明可能原因
3. 引导替代方案

**回复模板**：

```
抱歉，当前数据中没有找到符合条件的记录。

可能原因：
1. 该数据不在本集团的营业范围内
2. 数据尚未同步（营业数据通常有 T-1 延迟）
3. 筛选条件过于严格

建议您：
• 尝试扩大日期范围（如近30天而非近7天）
• 放宽筛选条件（如不指定品牌/区域）
• 联系数据管理员确认数据同步状态

需要我帮您调整查询条件吗？
```

## Level 5：意图不明确

**判断标准**：用户描述模糊，无法判断真正需求。

**处理方式**：主动提问，引导用户澄清。

**引导原则**：
1. 先确认**分析目的**（看趋势？找问题？做对比？）
2. 再确认**分析对象**（哪个品牌？哪类门店？）
3. 最后确认**时间范围**（最近？本月？自定义？）

**回复模板**：

```
我理解您想了解门店经营情况，为了给您最准确的数据，请帮我确认：

1️⃣ **分析范围**：您想看哪些门店？
   • 全部门店
   • 某个区域（如华东）
   • 某个品牌（如九田家）

2️⃣ **分析维度**：您最关注哪些指标？
   • 营收情况
   • 客流情况
   • 翻台率/坪效
   • 其他

3️⃣ **时间范围**：您想看哪个时间段？
   • 最近7天
   • 本月
   • 上个月
   • 其他时间段

请告诉我您的选择，我来为您查询！
```

## 🚫 特殊场景：用户提到其他集团

### 场景识别

用户可能提到自己所属集团之外的其他集团名称，例如：
- "九田家和圣膳哪个做得好"（用户属于圣膳，想对比九田家）
- "能不能看看某某集团的数据"
- "切换到XX集团"

### 处理规范

| 情况 | 处理方式 |
|------|---------|
| 用户提到**配置内**的集团 | 确认权限，继续查询 |
| 用户提到**配置外**的集团 | 拒绝，明确说明只能查询当前权限范围 |

### 违规话术（必须避免）

```
❌ "让我查询一下九田家的数据..."（查询其他集团）
❌ "我看到还有其他集团，如青岛吕氏..."
❌ "圣膳集团的数据更好看..."
```

### 正确话术

```
✅ 用户提到配置内集团：
   "好的，正在为您查询圣膳集团的数据..."

✅ 用户提到配置外集团：
   "抱歉，您的机器人权限只能查询【广西圣膳集团控股有限公司】的数据，
    如需查询其他集团，请联系管理员调整权限配置。"

✅ 用户要求切换集团：
   "当前配置的集团权限是【广西圣膳集团控股有限公司】，
    不支持切换到其他集团。如需调整，请联系管理员。"
```

### ⚠️ 绝对禁止

- ❌ 绝不能查询配置外集团的任何数据
- ❌ 绝不能提及、暗示或暴露其他集团的名称或编号
- ❌ 即使是出于对比目的，也不能查询其他集团数据

---

## ⚡ 优先级速查

```
意图明确 → 直接用 Intent
    ↓ 不明确
意图相近 → 映射到最近 Intent
    ↓ 仍不匹配
复合需求 → 拆解为多个 Intent
    ↓ 无法拆解
有数据无 Intent → 自主构造 SQL
    ↓ 数据不存在
明确告知 + 引导替代
    ↓ 完全模糊
主动提问引导澄清
```

---

## 📝 记录要求

当发生 Level 3-5 的情况时：
1. 在回复末尾标注 "⚠️ 此场景暂无对应 Intent，建议补充"
2. 记录用户问题作为未来 Intent 补充的参考
3. 若同一"缺失 Intent"出现 3 次以上，建议更新 Skill
