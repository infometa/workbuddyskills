# Action envelope、交付与消费合同

本合同适用于旧API2以及已实际开放的OAuth legacy core3；画像工具不用该信封替代contextRef。新资源的binding/下一跳还须属于当前OAuth账号、client/grant及代次，跨授权复制即停止；不从旧匿名绑定构造用户身份。

## 接收

`skill_whoami` 的返回只有在当前工具回执明确成功时才可驱动下一步。下一工具、参数、binding、幂等材料和可选状态回读必须来自同一返回 envelope。

## 原样转发

当服务明确返回 `actionEnvelope` 时：

1. 当前 `tools/list` 必须包含 envelope 指定工具。
2. `toolArguments` 必须通过该工具当前 input schema。
3. 参数整体原样传递，不增删、不改名、不改大小写、不把外部候选字段混入。
4. envelope 缺字段、工具不存在、schema 不匹配或 binding 冲突时停止；保留可读的 unknown/conflict，不选择“最像”的专家继续写。
5. envelope 指向 consume、激活、完结、登出、领取或兑换等写操作时，仍须满足对应 mainline/session/lebao 的用户意图、真实交付、凭证和未决写规则；服务建议不单独构成写授权。
6. 校验本次真正传给SDK的参数，不以“准备调用”的文字替代。用户只允许只读链时，到scene后即停止写步骤；包内记忆/记录习惯不扩大工具范围。只读身份小错误的唯一补正例外见[执行说明](identity-and-permission.md)，不得改已封印参数或换业务号。

OAuth beta若指向未开放的旧高级工具，不调用、不换后台代理。`FBS_LEGACY_OUTCOME_UNCONFIRMED`表示上游结果未知；保留原参数核对，不能重做并声称没有产生进度。账号所有权校验与旧上游结果不是跨系统原子提交证明。

`actionEnvelope` 是服务返回结构的通称。本 Skill 不声明固定新增字段；实际名称与字段始终服从当前 schema。

## 真实交付

场景内容返回不是首值完成。按当前产品授权前置与降级合同形成用户可使用的成果；连接器失败时可提供产品合同允许的本地帮助，但不全局删除超级独董会三授权等产品专用要求。画像缺失不增加首值阻塞。

只有成果已经真实交付，且 envelope 给出同一 binding 的消费参数时，才调用 `skill_consume`。事件类型限当前 schema 接受且与成果相符的 `first_value_completed` 或 `continued_use_completed`。


### 文件与聊天成果的呈现门

- 文件型成果：先通过当前宿主真实的文件展示工具把本次成果呈现给用户（例如实际可用的 present_files），核对成功返回包含本次文件；只有这一步完成后才能消费。文件已创建、已校验、已有路径、准备展示或其它文件曾展示都不能代替本次呈现。
- 聊天型成果：先在用户可见消息中给出可使用内容，再考虑消费；思考过程、进度播报、工具内部结果不算已交付。
- 展示工具未开放、返回失败、只排队或结果不明时，不能调用 consume；明确说明尚未完成展示。不能先消费再补展示，也不能把本地 artifact.presented 事件当作宿主已呈现。
- 展示成功仅证明成果已通过当前入口提供，不等于用户阅读、验收、外部送达或商业成交。保持同一成果、binding和原幂等键，成果修改后重新呈现，已成功或未决的消费不能因此重做。

## 未决消费

- 明确业务拒绝：报告失败，不写完成。
- 连接超时/丢响应：标记 `consume_outcome_unknown`，保留原幂等键；不得生成新键重放。
- 当前能力提供状态回读：只按服务给定参数回读，再决定是否用同一键继续。
- 无状态回读：停止自动动作，请用户看到明确的未确认状态。
