# 促销域 — 创建、编辑与提审的业务表单校验

> 活动与券模板创建、复制、改期、切换配置模式、编辑和提审前读取；仅查询、暂停/恢复等状态操作无需读取。
> 本文件补齐页面中的字段联动与写前检查，不提供独立能力。字段结构分别见 `activity-action.md`、`coupon-template-action.md`、`specialty.md`；审核状态与版本处理见 `pending-action.md`。
> 下文区分**前端运营口径**与**服务端约束**。页面允许输入不代表接口一定接受；页面的警告也不等于接口禁止。不得通过保存宽松草稿或传内部控制字段绕过提审校验。

## 写前处理顺序

1. 创建取用户已确认字段；编辑先读 `pending.detail` 的完整快照及 version，复制正式活动另取 `activity.goods-all`。保留本次未修改的有效字段，不能仅凭列表摘要重建配置。
2. 合并本轮修改后，按**当前活动类型与当前配置模式**构造完整入参，再检查所有相互依赖字段。旧窗口、隐藏字段和复制来的过去日期都不是新配置的有效默认值。
3. 日期按入口约定的时区解释、转为正的毫秒时间戳后比较；取执行时的当前时间，不把示例时间戳或会话开始时间当“现在”。只给日期而缺时刻时，沿用已确认的业务日期边界；未确认则补齐，不能自行设成零点或一天末尾。
4. 保存不完整草稿可按对应契约保留缺项，但应说明缺项/冲突及尚未满足提审条件。`draft=false` 创建、提审或重新提审前必须做完整检查；草稿保存成功不是规则合法的证据。
5. 修改活动开始/结束、定金/尾款、发货、券领取/使用窗口、配置模式、SKU 或价格后，重算受影响约束。错误时指出**具体字段、现值和冲突关系**，按用户明确给出的修正执行；仅有“按业务修正”而不足以唯一决定具体日期/金额时，先给出可行范围并补齐缺项，不静默延后发货、缩短活动或改价。
6. 提交与回读核对同一组完整配置：保存草稿查 pending 快照；审核后查正式对象。仅审核通过阶段（含已过开始时间的待审单）允许开始时间已过、按当前时间回算状态（见审核链）；编辑、提审和重新提审仍须检查未来时间，历史查询不受写前校验限制。

## 活动通用检查

- 前端运营表单：常规活动名称非空且≤20字符；满赠/买赠原表单名称2..30字符、活动说明≤300字符；券名称最终保存≤20字符（输入框可显示30，不能据此生成21..30字符），券描述兑换券≤200字符、其他券≤100字符；内部备注≤100字符。复制增加后缀后也检查长度。**入口有既有差异**：满赠/买赠的新建保存草稿代码另拦20字符，工作副本的非主题名称也统一拦20字符。说明所用入口的限制，不擅自截断名称；不能以通用接口历史标题上限更宽为由忽略页面口径。
- 新建或编辑后提审：`now < startTime < endTime`。若配置预热，秒杀、预售、周期购须 `now < preheatStartTime < startTime`；拼团还须至少提前 5 分钟。预热可不设，不自动加默认窗口；不把拼团的 5 分钟限制推广到其他类型。
- 单品活动（秒杀/直降/口令购/预售/拼团/周期购）按 SKU 选品并传 `productScopeType=product`，至少一个有效 SKU，身份与 SPU 归属来自真实商品数据，不能用仅含 SPU 的行代替 SKU 配置。
- 指定门店、商品、类目、品牌、人群时，对应清单不能为空；“清单没查到/加载失败”不能改成全部。范围切换时按当前类型构造字段：普通非商品范围不带旧 goodsList，非指定人群不带旧标签。赠品行与买赠主品按 specialty 的独立通道保留。

## 预售：完整时间链与模式切换

### 全款预售 `full_payment`

`now < startTime < endTime < estimatedDeliveryTime`。

预计发货严格晚于活动结束，**等于也不允许**。如用户要求保留现有发货时刻，活动结束的可行范围只能在该时刻之前，并仍晚于活动开始；不能仅把活动结束延后、保留已冲突的发货时间。

### 定金膨胀预售 `deposit_expand`

```text
startTime = depositStartTime
endTime   = depositEndTime
now < depositStartTime < depositEndTime ≤ balanceStartTime < balanceEndTime < estimatedDeliveryTime
```

- 活动起止窗口**同步定金窗口**，不是尾款窗口，也不是从定金开始一直填到发货。修改定金窗口须同步更新 startTime/endTime；定金结束与尾款开始可以相等，尾款开始与尾款结束不能相等。
- 保留发货时刻时，尾款结束必须在其之前；仅检查活动结束早于发货仍不够。定金、尾款四个时刻与发货均应在提审时晚于当前时间。
- 预热参考当前模式的开始：全款参考 startTime，定金类参考 depositStartTime。切换模式后不再使用隐藏的旧窗口作为校验基准。
- 全款切定金：补齐定金/尾款窗口、每 SKU 定金与膨胀配置，活动时间随定金窗口重建。定金切全款：明确全款活动窗口，重新校验预热与发货，不传失效的定金/尾款及膨胀配置。
- `MULTIPLIER` 与 `FIXED_AMOUNT` 切换后，只构造当前分支的活动级 typed 字段与每 SKU 扩展键。编辑时不把旧 `operationValue` 同时提交，否则可能遮蔽新的 typed 日期/配置；从快照提取有效字段，按 specialty 重新构造。

### 预售价格联动

- 每 SKU 预售总价 >0；定金类 `0 < depositAmount < discountValue`，金额比较统一为分。活动级倍率/抵扣值须同步到各 SKU 的相应扩展键，不能只改活动级字段。
- 当前前端倍率输入范围为 **1..10**；服务端下限为 **≥1**，1 倍合法，不能继续按“必须 >1”拒绝。
- 还需逐 SKU 计算服务端尾款约束：`尾款应付 = 预售总价 − 定金 − 抵扣金额 > 0`。倍率模式按服务端的 **double 浮点乘法后截断取整**计算抵扣金额，不能等同于精确十进制乘积再取整（如100分×2.3可能截断为229分）；固定金额模式取 SKU `expandDeductAmount`。抵扣金额必须**严格小于**“总价−定金”，等于会导致零尾款并被拒绝。浮点临界1分以实际服务端校验/回读确认，不替用户改金额、不把估算说成实际应付。页面仅显示“活动价−定金”的预估不能替代此校验。
- 同一活动级倍率/抵扣额对多个 SKU 生效时，每个 SKU 都检查；最低总价或最高定金的 SKU 可能首先失败，不能只验证第一行。

## 其他活动的同类联动

| 类型 | 前端运营检查与字段联动 |
|---|---|
| 秒杀 / 直降 / 口令购 / 预售 | 活动价 >0，且不高于真实 SKU 原价；原价缺失/0 不能据此声称已通过比价，应查询商品事实并说明无法核验项。前端原价字段与页面活动价单位可能不同，先统一单位再比较。价格的入参位置、显式库存见 specialty |
| 拼团 | 拼团价 >0 且**严格低于**真实 SKU 日常价，等价不合法；SKU ≤100 且不重复。改变成团人数、增删 SKU 后，THRESHOLD 模拟阈值重新与**全部 SKU 最小成团人数**比较；切到非 THRESHOLD 不传旧阈值，FOLLOW_ACTIVITY_END 不传旧 customDurationMinutes。自定义团有效期是开团后的持续分钟数，不是活动结束日期，勿自行增加“必须小于活动总时长”的限制 |
| 周期购 | 活动价 >0 且不高于日常价；库存、单次起购/限购为有效正整数，起购≤限购。更改配送方案或最大付费期数后，每组重新检查 `cycleWeeks × maxPaidPeriods ≤51`；**不计赠送期数**，不能按“付费+赠送”错误拒绝。关闭赠期时不传旧 giftRule；启用时买期门槛在付费区间内、赠期为正整数，并检查总期数整数溢出。earliestDeliveryDays 是相对配送天数，不构造预售发货时间字段 |
| 满元减 MYJ | 减免金额不能大于金额门槛，等于允许；该比较不要套用到按件数门槛的 MJJ/DNJ（件数与金额不同单位）。修改门槛后重验优惠值 |
| 满元/满件折 MYZ/MJZ、第 N 件折 DNZ | 前端折扣 0.1..9.9 折，转换为千分比整数；金额门槛转分，件数不转分。DNZ 的 N≥2，前端只配置一条；不把满额/满件最多5档套到第N件 |
| N 件 Y 元 NJY | 前端1..3档，每档 N 为≥2整数、Y>0且按固定**总价**传分；各档件数严格递增。后一档总价低于前一档是页面**警告**，需提示核对，不能冒充硬性禁止或自动改价 |
| 满赠 / 买赠 | 至少一个真实赠品 SKU，买赠 MG 还须主品；增删赠品时保留 giftPoolItemId 和该 SKU 限量值。0表示不限量，不能当成缺失而自动补库存 |

## 券模板：领取与使用窗口

所有券类型均须有完整领取窗口，提审前 `now < acquireExpireStart < acquireExpireEnd`；领取后生效券也不能省略。若传兼容 startTime/endTime，按前端同步为领取开始/结束，不得用使用期代替。

### 固定使用期 `useExpireType=1`

同时满足：

```text
now < useExpireStart < useExpireEnd
acquireExpireStart < useExpireStart
acquireExpireEnd ≤ useExpireEnd
```

领取开始与使用开始**不能相等**；领取结束与使用结束可以相等。没有“领取结束必须早于使用开始”的约束，领取期与使用期可以重叠。修改领取截止后，必须重新检查使用截止是否覆盖；不传失效的 useExpireDuration。

### 领取后生效 `useExpireType=2`

前端填写 1..365 天，入参 `useExpireDuration = 天数 ×86400`，单位秒；服务端本身检查时长>0。仅构造相对时长，不保留旧固定 useExpireStart/End，也不套用固定期的跨窗口关系。切换到固定期则补齐两个使用时刻。

### 券规则与配置模式

- 满减券金额门槛与折扣券金额门槛按当前服务端规则须 >0；满减面额≤金额门槛。页面输入框允许0不代表可提审。前端满减/折扣券只配置单档；折扣券输入0.1..9.99折，折扣上限金额选填、填则>0。不要把活动折扣页面的9.9上限套给券。
- 运费券区分“运费全免/固定减免”：全免传 freeShipping=true 并省略金额；固定减免传>0的减免分值。兑换券与运费全免券按前端固定 maxStack=1；其他同券叠加按用户意图在1..50内配置，不能依赖服务端静默截断。
- 前端发行量为正整数；不擅自省略 quantity 而接受服务端默认发行量。限领关闭时用0表达不限，切换后清理旧的正限额。
- 领取控制、渠道、转赠是不同配置，不能互相替代。前端渠道为单选可清空，首次审核通过后不可改；编辑按完整快照保留channelCodes，不能省略已配置渠道。分销入口当前只向满减券开放（页面业务护栏，服务端不完整强制这组限制）。切换券种时不沿用不适用渠道。具体枚举和字段见券模板 create 契约。

## 主题日期覆盖

主题表单名称非空且≤50字符（接口当前上限64），周期开始<结束；不对主题统一加“必须为未来”的促销活动限制。缩短或移动主题周期后，必须完整覆盖**全部保留活动**的生命周期开始（含预热）至结束；否则扩大周期或由用户明确移出冲突活动。不能为了保存自动移出成员，版本与源主题 revision 按 calendar 契约处理。

## 范围与快照的边界

- 全部门店须由用户确认。当前能力调用路径中，已明确确认ALL时省略或传null；正式提交[]无效。若快照为[]且范围意图未确认，先向用户确认，不擅自扩大范围或任意选店；用户已确认ALL后可将旧[]规范化为省略/null。
- 口令购正式提交只允许PASSCODE/SPECIFIED，不允许ALL，且不支持预热；口令仅1..20位英文字母数字、按大写规范化。直降页面没有预热输入，周期购/拼团页面隐藏预热，不等于API统一禁止；不主动加预热，复制时重验旧隐藏值。
- 直降/口令购/秒杀/预售每SKU正式提交都需要显式库存，限量stockPolicy=1/totalCount>0，不限量stockPolicy=2/totalCount=null；预售还须与extJson.activityStock的0/正数一致。0限购表示不限，不因旧页面回填成1就改用户配置。
- 编辑保存是完整快照覆盖。先取请求形态的可编辑快照并合并，不直接回传整个详情VO，也不只发送本次改变的字段；已失效模式字段、只读运行态字段和已被完整配置替代的私有草稿按specialty清理。
- 券模板已有激活券时，不允许缩短useExpireDuration。DH_COUPON显式maxStack非1会被拒绝，草稿也一样；省略时服务端规范化为1。
- 四类常规单品不能依赖服务端一定执行原价比价；写前查真实商品价。按本能力路径逐类型检查合并后的完整入参，服务端拒绝时如实报告。
