# 物流域 — 运营流程

> 快递公司/物流平台配置、行政区划逐级查询、发货与售后轨迹（跨域）。
> 概念知识见 `references/domains/logistics.md`；执行闭环见 `trade-core.md`。
> 对应契约：`express-company-query.md` / `express-company-action.md`、`platform-query.md` / `platform-action.md`、`region.md`、`track.md`（均在 `references/apis/logistics/`）。

## 快递公司配置

1. 查询现有快递公司及启用平台，复用已有编码并检查重复。
2. 新增或编辑前确认名称、统一编码、排序及完整平台映射清单。新增后会立即进入启用列表，按高风险写入确认。
3. 写入后重新查询并逐项核对。改码、停用或删除都可能让保存旧编码的历史订单/售后轨迹失效；执行前必须让用户确认历史单影响，删除前优先停用观察。
4. 微信运力同步会按名称匹配并写入共享映射，执行前确认用户明确要求，执行后报告匹配数量并回读。

## 物流平台配置

1. 先查询运行时支持的平台编码与当前配置；不允许凭空创建未支持平台。
2. 平台创建与凭据变更暂不开放：创建会立即启用，连接验证可能误判，普通轨迹也无法确定使用了目标平台。用户命中时说明当前不可安全执行并整理需求。
3. 连接验证只能作为诊断信号，`success=true` 不能证明凭据有效。启用仅在用户已有目标平台的外部验证证据并明确要求时执行。
4. 停用或删除前确认轨迹查询是否依赖该平台；服务没有历史运单或映射引用保护，可能回落到其他平台并最终返回误导性的空轨迹。当前开放能力集不含平台删除恢复操作。

## 行政区划

先查省列表，再用返回的 `code` 查市，再用市级 `code` 查区。不要用名称代替编码，也不要自行拼接子级编码。

## 发货与售后轨迹（跨域）

```text
trade 发货结果 ──> expressCompanyCode + trackingNumber ──> 物流轨迹
trade 售后退货 ──> expressCompanyCode + trackingNumber ──> 物流轨迹
地址创建/编辑 ──> 省列表 ──> 市列表 ──> 区列表
```

发货或售后详情已有快递公司编码与运单号时直接查询；服务提示手机号后四位必需时，再向用户索取并严格校验为四位数字后重试（Java 当前不校验格式）。空轨迹可能是平台异常降级，不能向用户断言尚未揽收。

## 写入确认分级

- 高风险：快递公司新增（创建后立即启用）、改码、删除、停用、平台映射全量替换、微信运力同步。执行前确认明确对象与影响。平台创建与凭据变更未开放，不进入执行分级。
- 中风险：名称、排序、备注编辑。确认关键字段后执行并回读。
- 查询及连接验证不改变配置；连接验证可能调用外部平台，但不自动重试。
