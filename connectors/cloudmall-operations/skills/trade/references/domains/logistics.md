# 物流域 — 领域知识

> 实体模型、运单状态机、业务字典、运行时语义与风险边界（物流子域的状态机与枚举字典也在本文件）。
> 主域实体/规则见 `trade-concepts.md`，主域状态与枚举见 `trade-enums.md`；能力契约见 `references/apis/logistics/`，操作流程见 `references/flows/logistics.md`。

## 核心链路

行政区划为地址与配送范围提供标准编码；快递公司提供业务统一编码；物流平台保存外部查询能力配置；快递公司平台映射把统一编码转换为平台侧编码；轨迹查询结合运单绑定平台或启用平台返回统一状态。

```text
行政区划(code) ──> 地址/配送依赖
快递公司(companyCode) ──> 平台映射 ──> 物流平台(platformCode) ──> 轨迹查询
                                 ↑
                 发货 / 售后退货的运单号
```

## 核心实体

- **快递公司（ExpressCompany）**：运营配置的快递公司词库，发货与退货物流录入时传入 `companyCode`（同租户唯一）。`platformMappings` 是平台编码映射列表——同一快递公司在不同平台有不同编码（如快递100 的 `zhongtong`），映射列表在新增/编辑时全量替换。停用后不出现在发货选择列表（enabled-list），已有运单不受影响；删除为逻辑删除。
- **物流平台配置（PlatformConfig）**：第三方物流平台对接配置。`platformCode` 小写字母+数字+下划线，同租户唯一、创建后不可修改；`credentials` 为 JSON 格式凭据，**整体 AES-256-GCM 加密存储**，各平台适配器自行解析（VO 不返回明文凭据）。平台与快递公司是多对多关系（一个快递公司可映射多个平台）。
- **运单（Waybill）**：物流域核心单据，记录一次物流配送全生命周期；由交易域发货时通过 Feign 创建，**运营端不直接操作运单**。运单分正向（`FORWARD`）/逆向（`RETURN`）两类；关联业务类型 `BizType`：`ORDER` 订单发货 / `RETURN_ORDER` 退货 / `EXCHANGE_SHIP` 换货发货。
- **行政区划（Region）**：省市区三级树形结构，六位标准编码，父级 `code` 即子级查询的 `parentCode`。
- **物流轨迹（Track）**：从物流平台实时查询（不缓存），含快递公司名、运单号、顶层 `currentStatus` 与轨迹时间线。

## 运单状态机（WaybillStatus）

`CREATED`（已创建）→ `COLLECTED`（已揽收）→ `IN_TRANSIT`（运输中）→ `DELIVERING`（派送中）→ `SIGNED`（已签收）；任意运输中阶段可转 `ABNORMAL`（异常件）/ `REJECTED`（已拒签）。状态由物流平台回调驱动更新，运营端只读；**状态可能跳过中间状态**（如直接从已创建跳到已签收），状态机仅表示常见流转路径而非强制约束。

## 业务字典

- 启停状态：`0` 停用，`1` 启用。
- 平台编码只能是小写字母、数字、下划线；当前运行时支持 `kuaidi100`（快递）与 `fengniao`（即时配送）。快递公司编码允许大小写字母、数字、下划线、横线，但应优先复用现有编码。
- 区划采用六位标准编码并逐级查询。省级示例 `440000`；父级 `code` 是下一次子级查询的 `parentCode`。
- 统一轨迹状态：`COLLECTED` 已揽收、`IN_TRANSIT` 运输中、`DELIVERING` 派送中、`SIGNED` 已签收、`ABNORMAL` 异常、`REJECTED` 已拒签、`RETURNING` 退回中、`RETURNED` 已退回、`CLEARING` 清关中。
- 配送方式约定值（非枚举类）：`express` 快递 / `city_express` 同城 / `rider_delivery` 骑手 / `self_service` 商家自配。

## 运行时语义

- 轨迹查询优先使用运单绑定且已启用的平台；不可用时回落到任一启用平台。平台异常会降级为空轨迹，因此空列表不等于没有物流动态。
- `kuaidi100` 原始状态先精确映射，未知扩展码再按首位回落；完全未知值回落为 `IN_TRANSIT`。
- 默认要求手机号后四位的快递公司由运行时配置决定；当前默认包含 `zhongtong`、`shunfeng`。手机号仅在服务提示需要时补充，必须为用户提供或可合法取得的信息。
- 平台凭据是 JSON 字符串。当前 `kuaidi100` 适配器读取 `customer` 与 `key`；前端示意中的 `secret` 当前运行时不消费。

## 风险边界

- 快递公司与平台是跨订单、售后共享配置，新增、编辑、停用、删除都按高风险配置写入处理。
- 快递公司创建后立即启用。平台创建也会立即启用且无法原子化先停用验证，因此当前开放能力集不包含平台创建。
- 平台编码创建后不可修改；平台列表不返回凭据。编辑不传 `credentials` 表示保留原值。
- 快递公司平台映射在编辑时为全量替换；遗漏旧项会删除其映射。
- 快递公司改码、停用或删除没有历史运单引用保护：旧订单仍保存旧编码，之后的轨迹查询可能直接失效。改码与停删前必须确认历史单追踪影响。
- 平台停用或删除没有映射及历史运单引用保护；轨迹可能回落到其他启用平台，并在缺少映射时用统一快递编码尝试查询，失败还可能降级为空轨迹。
- 当前快递100连接验证把部分平台错误响应也判作成功；普通轨迹查询又可能命中缓存、使用运单既有绑定平台或其他启用平台，所以两者都不能确定性证明目标平台凭据有效。平台创建与凭据变更暂不开放。
- 轨迹明细的 `status` 字段在当前查询实现中未赋值，只可靠使用顶层 `currentStatus`。
