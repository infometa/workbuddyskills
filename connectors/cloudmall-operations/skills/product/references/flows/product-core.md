# 商品域 — 写操作共同执行闭环

> 所有商品域写操作共用的执行纪律；各业务族流程见 `flows/` 下对应文件，能力契约见 `references/apis/product/`。
> 写操作风险档位与字段确认红线以入口 SKILL.md 为准（🔴/🟡/🟢 分级不在本文件重复）；执行器为单次提交、永不自动重试。

---

## 执行闭环

定位唯一对象 → 读取当前事实 → 判断适用状态与字段来源 → 确认具体影响 → 执行一次 → 回读核验。

- **对象定位**：多个候选对象（同名商品/相似名称标签）时，列出必要的业务差异请用户选定，不取第一条；分页翻完前不宣称不存在。
- **字段来源**：系统可读的 ID 和状态由读取结果取得；价格、库存数量、名额等数值必须由用户明确给出，禁止 AI 编造。
- **写前变化**：写入前状态改变：重新说明影响。输入缺失、未知嵌套结构或未开放依赖：停止对应写入，明确缺什么。
- **超时纪律**：写操作超时或网络错误时结果不确定（可能已提交）——先查询对象状态再向用户说明，不自动重复提交；ADD/SUBTRACT 类库存调整与 toggle 类操作超时后严禁盲目重试（可能重复加减/状态反转）。
- **回读不明确**：报告「已提交，结果待核验」；不以列表延迟或空结果断言失败，不通过执行反向动作试探。
- **批量结果**：批量操作结果含逐条失败明细的（SPU 侧）逐条报告，不把 HTTP 成功当全部业务成功；仅计数的（门店商品侧）按计数报告并回读列表核对。
- **只读查询**：搜索/详情/SKU/库存/流水/字典/变更记录/草稿/统计无需确认直接查；⚠️ 评价详情身份类字段（昵称等）**禁止转述给终端用户**（手机号已脱敏）。
- **未开放能力**：不调用未开放能力，引导用户在管理后台操作。
