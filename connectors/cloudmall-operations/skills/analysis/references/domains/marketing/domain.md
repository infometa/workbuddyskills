# 🟥 营促销域 域知识

> 活动复盘 + 渠道效果 + 补贴 ROI + 分销推广 + 营销归因，回答"花了多少钱、效果怎么样、钱花对了吗、分销带了多少量"。

---

## 一、域定位

**业务定位**：营促销域聚焦营销投入的效果评估、渠道效率优化和分销推广管理
**核心问题**：活动 ROI 如何？渠道效率差异？补贴是否可持续？分销带来多少增量？营销异常根因？
**分析能力数**：4 个（能力 19-22）
**意图路由关键词**：活动/优惠券/渠道/补贴/ROI/流量/PV/UV/访客/引流/分销/推广/佣金/推广人

**核心数据表**：
| 表名 | 粒度 | 说明 |
|------|------|------|
| `app_market_stat_promotion_di` | 天×活动ID | 活动维度统计（MV，pay_uv/pay_cnt 为 BITMAP） |
| `app_market_stat_coupon_overview_di` | 天×门店×券类型 | 优惠券概览统计（领取/核销/成本/成交，领取指标跨门店需去重） |
| `app_market_stat_coupon_di` | 天×门店×券批次 | 优惠券列表统计（券模板明细，成交类按门店拆分） |
| `app_market_stat_cps_di` | 天×推广人 | CPS 分销推广业绩（MV，click_uv/pay_uv/order_cnt 为 BITMAP） |
| `app_market_channel_stat_di` | 天×渠道ID | 渠道维度统计（MV） |
| `dwm_market_activity_detail_di` | 天×活动ID×SPU | 活动商品明细（⚠️ 基座2.0已下线，见 `metric_catalog.md` 4.2节说明） |
| `dim_market_activity_config` | 活动ID | 活动配置维表 |

## 二、分析能力配方（Component Recipe）

### 能力 19：活动/大促复盘

**组件链**：

| 序号 | 组件 | 章节 | SQL 来源 |
|------|------|------|---------|
| 1 | C01 | S1 活动概览 | → 引用 A-6a（活动维度统计） |
| 2 | C04 | S2 券漏斗 | → 引用 A-6b / A-11（优惠券维度） |
| 3 | C06 | S3 活动对比 | → 引用 D-8（本次 vs 上次） |
| 4 | C03 | S4 活动日走势 | 活动期间逐日 |
| 5 | C05 | S5 活动商品明细 | → 引用 MK-2（活动×商品 TOP） |
| 6 | C05 | S6 薅羊毛检测 | 三角检测 |
| 7 | C12 | S7 洞察建议 | ROI 评估 + 券策略 |

**薅羊毛检测**：①活动客单价/日常<0.6 ②活动退款率/日常>1.5 ③补贴率>15%。命中≥2条→🔴高风险

## 三、Gate Check 域专项规则

| 检查项 | FAIL 条件 | 意义 |
|--------|-----------|------|
| channel 表未建降级 | A-6c / D-7 报 unknown table | 告知用户"渠道数据暂未就绪"，不报错（⚠️ 需与最新 `metric_catalog.md` 核实该表是否已建，本文件为遗留未更新） |
| activity 空数据降级 | 活动表查询返回 0 行 | 标注"暂无活动数据"而非报错 |
| coupon 空数据降级 | 券表查询返回 0 行 | 标注"暂无优惠券数据"而非报错 |

## 四、健康基线阈值

| 指标 | 警戒 ⚠️ | 红线 🔴 |
|------|---------|---------|
| 渠道转化率 | < 2% | < 1% |
| 活动 ROI | < 3 | < 1.5 |
| 补贴率 | > 15% | > 20% |
| 领券核销率 | < 15% | < 8% |
| 补贴依赖度 | > 30% | > 50% |
| 分销 ROI | < 3 | < 1.5 |
| 分销点击→支付转化率 | < 3% | < 1% |
