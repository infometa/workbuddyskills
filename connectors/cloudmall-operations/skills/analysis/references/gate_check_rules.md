# Gate Check 通用框架（L3 报告专用）

> L1/L2 快速问答不需要 Gate Check。L3 报告在生成 HTML 之前必须执行完整 Gate Check。
> 核心原则：任何一项 FAIL 必须修复后重新检查，全部 PASS 才能生成报告。最多修正重试 1 次，仍有 FAIL 则告知用户决定。

> **当前运行时适配说明**：本技能不提供原版的 `audit_logger.py`，不要求或声称已生成 `sql_audit_log.md`。以下查询完整性检查以本轮实际执行结果及用于报告的数据为依据。

---

## 通用审查项

### 审查一：查询执行证据完整性
- 成功查询条数 ≥ 域定义的预期条数；逐项核对实际工具返回结果
- 必查 SQL 全覆盖（由域 domain.md 定义）
- 标明失败、部分成功、截断和缺失结果；必查数据缺失时不得判为 PASS
- 仅在工具实际返回时记录 traceId 和耗时，不推测或编造执行记录

### 审查二：数据可信度
- 漏斗自洽（上游 UV ≥ 下游 UV，由域定义漏斗步骤）
- 率值合理（rate/ratio/率 字段 ≤ 1.0，pct/占比 字段 ≤ 100%）
- 关键指标非零

### 审查三：组件产出完整性
- Recipe 中必选组件均有输出

### 审查四：域专项检查（由域 domain.md 定义）

各域可在 `domain.md` 的 "Gate Check 域专项规则" 章节定义额外检查：

| 域 | 典型专项检查 |
|----|------------|
| 交易域 | 门店求和校验（门店 GMV 总和 ≈ 大盘 GMV ±5%） |
| 商品域 | 品类 GMV 总和 ≈ 大盘 GMV；SPU 退款率 ≤ 100% |
| 用户域 | 新老客人数之和 ≈ 总人数；各分群不重叠 |
| 营促销域 | 渠道覆盖检查（channel 非空）；activity_type 空表降级 |
| 跨域 | 各域数据口径一致性（总 GMV 来源一致） |

### 审查五：数据防膨胀

针对 JOIN 查询和跨表聚合：

| 检查对象 | 校验规则 | 检测目标 |
|---------|---------|---------|
| TOP 商品 | `pay_cnt ≤ pay_uv × 3` | 防宽表多维度膨胀 |
| 价格带 | 总 GMV ≈ 大盘 GMV（±50%） | 防 JOIN 膨胀 |
| 品类聚合 | 品类 GMV 总和 ≈ 大盘 GMV（±10%） | 确保口径一致 |
| 用户分群 | 各分群 UV 总和 ≈ 总 UV（±5%） | 防重复计数 |

膨胀检测：`IF 聚合结果 / 大盘基准 > 1.5 OR < 0.5 → 🔴 FAIL`，停止报告生成。

## 结构化输出格式（⛔ 强制使用）

```
🔍 数据自审查报告（Gate Check）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
审查一：查询执行证据完整性
  ✅/❌ 成功查询条数：实际值 / 预期最小值
  ✅/❌ 必查 SQL 覆盖：已覆盖数 / 应覆盖数

审查二：数据可信度
  ✅/❌ 漏斗自洽：{具体检查结果}
  ✅/❌ 率值合理：{具体检查结果}
  ✅/❌ 非零校验：{具体检查结果}

审查三：组件产出完整性
  ✅/❌ 必选组件输出：{具体检查结果}

审查四：域专项检查
  ✅/❌ {域专项规则}

审查五：数据防膨胀
  ✅/❌ {膨胀检查结果}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Gate Check 结果：✅ PASS / ❌ FAIL（需修复项数）
```

## 自由分析模式护栏

走"自由分析"模式时默认不走 Gate Check，但输出需标注 "⚠️ 自定义分析，未经标准化校验"。
