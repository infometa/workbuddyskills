## 交易域归因——诊断规则

完整归因分析，按 **找拐点 → 三因子拆解 → 按主因子下钻 → 结构风险 → 建议** 的顺序执行。

### 第一步：找拐点（D-9 逐日趋势）

拉逐日 GMV 走势，标注环比变化最大的那天为拐点。计算当期均值 vs 基期均值的偏离度：

| 偏离度 | 判定 |
|--------|------|
| < ±10% | 正常波动，告知用户无需归因 |
| ±10% ~ ±20% | ⚠️ 值得关注，继续第二步 |
| > ±20% | 🔴 显著异常，必须继续 |

基期为空 → 只输出当期走势，标注"暂无基期"。数据 < 3 天 → 标注"拐点识别精度受限"。

### 第二步：GMV 变化拆解——是什么原因导致 GMV 变化？（D-1）

GMV 的变化可以从三个角度拆解：
- **来了多少人**（浏览人数）
- **有多少人买了**（转化率 = 支付人数 / 浏览人数）
- **每人花了多少**（客单价 = GMV / 支付人数）

分别计算三个因子的环比变化率，量化各自对 GMV 总变化的贡献度（三者之和 ≈ 100%），贡献度最大的标记为主因。

> **贡献度说明**：贡献度 = 该因子变化对 GMV 总变化的拉动占比。例如"转化率贡献约 80%"表示：假设浏览人数和客单价不变，仅转化率的变化就能解释本次 GMV 下跌的约 80%。

### 第三步：按主因子下钻

**主因子分支表**（D-1 完成三因子杜邦后，按贡献度最大的主因子选择下钻 SQL）：

| 主因子 | 下钻 SQL 组合 | 下钻逻辑 |
|--------|-------------|---------|
| **UV 是主因**（贡献 > 50%） | D-7(渠道贡献) → D-4(新老客) → D-2(品类UV对比) | 哪个渠道 UV 掉了？新客还是老客？哪个品类引流少了？ |
| **转化率是主因**（贡献 > 50%） | D-1(构建漏斗: visit→browse→click→order→pay) → D-2(品类转化率对比) → D-4(新老客转化率) | 漏斗哪步断了？哪个品类拖了转化？新老客谁的转化降了？ |
| **客单价是主因**（贡献 > 50%） | D-1(件单价+连带率计算) → D-2(品类客单价+GMV占比) | 是件单价降了还是连带率降了？哪个品类结构变了？ |
| **双因子均贡献**（各 30~50%） | 全展开：D-7 + D-2 + D-4 | 两条线并行归因 |

**UV 是主因** 时各维度诊断：

| 数据信号 | 诊断结论 | 数据为空时 |
|---------|---------|----------|
| 某渠道 UV 降幅最大 | {渠道}是 UV 下降主因 | 渠道数据为空，跳过 |
| 新客 UV 贡献降幅 > 50% | 获客端萎缩 | 新老客数据为空，跳过 |
| 老客 UV 贡献降幅 > 50% | 用户留存/回访不足 | — |
| 某品类 UV 降幅最大 | {品类}引流缩水 | 品类数据为空，跳过 |

**转化率是主因** 时漏斗断点诊断：

| 数据信号 | 诊断结论 |
|---------|---------|
| 某步骤转化率偏差最大 | 该步骤是漏斗断点 |
| 有效漏斗步骤 < 3 | 标注"漏斗不完整，精度受限" |

**客单价是主因** 时拆解：

| 数据信号 | 诊断结论 | 前置条件 |
|---------|---------|---------|
| 件单价(`gmv/sales_qty`)降幅大 | 商品价格下移 | sales_qty > 0 |
| 连带率(`sales_qty/pay_cnt`)降幅大 | 每单件数减少 | pay_cnt > 0 |
| 某低价品类 GMV 占比上升 > 5个百分点 | 品类结构拉低客单价 | D-2 有数据 |

### 第四步：品类集中度检查（D-2 数据）

| 数据信号 | 诊断结论 | 前置条件 |
|---------|---------|---------|
| 单品类 GMV 占比 > 50% | ⚠️ 品类过度集中，抗风险弱 | 品类数 ≥ 2 |
| Top3 品类占比 > 80% | ⚠️ 高度集中，建议培育长尾 | — |
| 集中度环比上升 > 5个百分点 | ⚠️ 在恶化 | 有环比 |

## 建议模板

| 根因类型 | 建议 |
|---------|------|
| UV↓ 渠道萎缩 | 恢复/加大该渠道投入，排查渠道策略变更 |
| UV↓ 新客不足 | 拓展获客渠道，优化拉新活动/分销佣金 |
| 转化率↓ 浏览→点击断点 | 优化商品卡主图、标题、价格竞争力 |
| 转化率↓ 下单→支付断点 | 排查支付通道/优化支付体验/检查库存提示 |
| 客单价↓ 件单价降 | 检查促销折扣力度，引入中高价商品曝光 |
| 客单价↓ 连带率降 | 设置凑单满减、搭配推荐等组合优惠 |
| 客单价↓ 品类结构变动 | 提升高客单品类曝光权重，培育高毛利品类 |
| 品类集中度过高 | 分散品类依赖，培育第二/三增长品类 |

**输出结构**：找拐点 → 三因子拆解（标注主因）→ 主因子下钻结论 → 集中度风险 → 2~3 条建议

## 退款率归因——诊断规则

> 触发词：退款率为什么涨/降、退款为什么变多/变少、退款原因、退款集中在哪、退款原因分布

### 执行步骤

1. **查退款原因分布**（D-10 默认版）：按退款原因聚合，看哪些原因占比高
2. **按商品下钻**（D-10 取消注释版）：加入 spu_id/spu_name 维度，看退款集中在哪些商品
3. **查品类退款率分布**（Q-2b）：从 SPU 表按品类聚合退款金额和退款率
4. 综合分析，输出归因结论和建议

### 诊断规则

| 数据信号 | 诊断结论 | 前置条件 |
|---------|---------|---------|
| 某退款原因占比 > 40% | 退款集中在"{原因}"，属品控/物流/价保问题 | 有退款原因数据 |
| TOP 3 商品退款金额占总退款 > 50% | 退款集中在少数商品，{商品名}是重灾区 | 有商品下钻数据 |
| 某品类退款率 > 15% | {品类}退款率严重偏高 | Q-2b 有数据 |
| 退款原因分散（TOP1 占比 < 25%） | 无明显单一根因，属全面性退款上升 | 有退款原因数据 |

### 建议模板

| 根因类型 | 建议 |
|---------|------|
| 品控/质量问题占比高 | 加强入库品控抽检，排查高退款 SPU 的供应商质量 |
| 物流/配送问题占比高 | 排查物流合作方时效和破损率，考虑增加包装保护 |
| 不想要了/冲动消费占比高 | 检查是否存在过度促销引导冲动下单，优化商品详情页设置合理预期 |
| 价保退款占比高 | 检查近期促销节奏，是否频繁降价导致大量价保退款 |
| 品类集中退款 | 排查该品类商品质量/描述/图片一致性，暂停高退款 SPU 的推广投入 |

### 输出结构

退款原因分布 → 问题商品定位 → 品类概览 → 主因判定 → 2~3 条建议
