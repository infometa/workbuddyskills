# Workflow — 动态报告（AI 生成 HTML）

> L3-dynamic · AI 直接生成 HTML → PDF · 存入 本地工作目录 · 2~5 分钟
> 适用于没有现成模板的专题分析、自定义报告、一次性深度分析

---

## 触发条件

从 SKILL.md 意图判定分流到本路径的条件：

| 触发词 | 说明 |
|--------|------|
| "做个专题分析" / "帮我分析一下XX" | 没有标准化报告模板的分析需求 |
| "自定义报告" / "定制一份报告" | 用户明确要求自定义 |
| "出一份XX分析报告"（XX 不在报告路由表中） | 非标准能力的报告需求 |
| "深度分析" / "全面诊断" / "根因分析报告" | 需要深度 + 图表的分析 |

---

## 与 L3 固定模板路径的区分

| 判定条件 | 走哪条路径 |
|---------|-----------|
| 触发词命中 workflow_report.md 路由表（经营周报/门店报告/经营日报） | → 路径 B（固定模板） |
| 触发词未命中路由表，但含"报告/分析报告/专题" | → 本路径（动态生成） |
| 不确定时 | 先尝试路径 B 路由匹配，未命中再走本路径 |

## 执行步骤

```
0. 环境检查（幂等）
   → Bash 检查 python3 / python / py -3 和可选 Node.js 依赖；不自动安装
   → 确认 Python 和 Node 可用（沙箱通常预装）

1. 确认分析需求
   → 明确分析主题、关注维度、时间范围
   → 确定需要查询哪些业务域的数据
   → 推算日期参数（同 SKILL.md 动态日期计算规则）
   → 确定输出路径：demo-reports/dynamic-{主题简称}-{日期}/

2. 执行 SQL + 收集结果
   → 先 当前运行时的 Capability 分析执行器(action=table_structure) 确认字段，SQL 传参按运行时形态（本地编码：写文件经 encode_sql.py 生成参数；服务端编码：明文直传，每批最多 10 条），仅用 当前运行时的 Capability 分析执行器 查询
   → 根据分析主题，从 sql_templates_Q/A/D.md 选择匹配的 SQL 模板
   → 不受固定路由表约束，可灵活组合任意 SQL 模板
   → 逐条执行，保留完整返回结果
   → SQL 报错时读 references/sql-few-shots.md（最多修正重试 1 次）

3. 组织数据摘要
   → 将所有 SQL 结果整理为结构化的数据摘要（类似 research.md 的角色）
   → 包含：核心 KPI 数值 + 环比变化 + 维度分布 + 异常信号
   → 计算衍生指标：客单价、转化率、连带率、退款率等（公式见 metric_catalog.md）
   → 这一步不输出给用户，仅作为下一步的内部输入

4. 读取 html-report-spec.md，生成完整 HTML
   → 先按 references/gate_check_rules.md 自审数据、截断和缺失，保留结论，不能将缺失填零
   → 读取 references/html-report-spec.md，获取完整的技术规范和组件库
   → 基于数据摘要，选择合适的组件组合
   → 直接输出完整 HTML（从 <!DOCTYPE html> 到 </html>）
   → 数据通过 <script> 标签嵌入，Chart.js 图表直接初始化
   → 保存为 {输出目录}/report.html

   组件选择参考：
   - 有 KPI 概览数据 → KPI 卡片（3~6 个）
   - 有逐日数据 → Chart.js 折线图
   - 有品类/门店排行 → 柱状图或数据表格
   - 有占比数据 → 环形图
   - 有漏斗数据 → CSS 漏斗
   - 有异常信号 → 诊断卡（红/绿/橙）
   - 有可执行建议 → 行动建议卡
   - 末尾 MUST 附录章节 → 指标说明表（列出报告中涉及的所有指标名称 + 说明）

5. HTML → PDF
   → Bash: python3 "<技能目录>/scripts/generate_report.py" --html-file "<本地输出目录>/report.html" --output-dir "<本地输出目录>" --name "report"
   → 失败则跳过 PDF，后续直接用 HTML

6. 生成分析概览（Markdown，与报告双输出）
   → 从生成的数据中提取 Markdown 概览
   → 包含：一句话总结 + 核心 KPI + 异常提醒 + 报告文件路径

   → 文件写入用户当前本地工作目录；交付脚本实际返回的绝对路径 Markdown 链接。
   → 文件写入用户当前本地工作目录；交付脚本实际返回的绝对路径 Markdown 链接。
```

## 关键约束

1. **数据必须来自 SQL**：HTML 中展示的所有数值必须来自步骤 2 的 SQL 查询结果，禁止编造
2. **先组织后生成**：步骤 3（组织数据摘要）是必需的中间步骤，不能跳过直接从 SQL 结果生成 HTML
3. **图表用 Chart.js**：所有图表必须使用 Chart.js（已在现有报告中验证 html2pdf.js 兼容性），不使用其他图表库
4. **组件来自规范**：HTML 布局和组件样式必须遵循 html-report-spec.md 定义的组件库，不自创样式
5. **浏览器可预览**：生成的 HTML 必须能直接在浏览器中打开预览，所有依赖走 CDN
6. **兼容 html2pdf.js**：HTML 结构必须兼容 Puppeteer 截图（宽度 1200px，无 iframe，Chart.js 有足够渲染时间）

## 与现有 SQL 资产的关系

动态报告复用现有全部 SQL 模板，但不受路由表约束：

- L3 固定模板：按路由表指定的 SQL 序列执行（如 cap=1 固定是 Q-1 → A-2 → A-3）
- L3-dynamic：根据分析主题自由组合 SQL 模板（可以用 Q-1 + D-1 + D-2 + A-7 等任意组合）

这意味着动态报告可以覆盖更多分析场景，而不需要为每种场景编写 Python 插件。
