# 直播子域 — 实体模型与业务规则

> 实体模型、数据口径与业务规则要点——构造入参/理解概念时读本文件。
> 查状态含义/操作前置/枚举值见 `live-enums.md`；能力契约见 `../apis/live/`，操作流程见 `../flows/live.md`。
> 本文件只描述业务事实。事实来源为当前 Java 枚举、服务状态分支、DTO/VO 与运营前端构造；没有既有直播域文档，不使用行业常识补齐。

---

## 实体关系

```text
直播分类 1 ── N 直播间 1 ── N 讲解场次 N ── 1 主播
                         │
                         ├── N 场次直播商品 ── 1 商品SPU
                         │                    └── N 被选SKU
                         ├── 0..N 回放分片（开放能力仅包含回放记录）
                         ├── 1 场次复盘数据 ── N 五分钟趋势桶
                         │                 └── N 商品转化行
                         └── N 内容审核记录
```

- **直播间**是长期频道容器，承载标题、封面、分类、标签和默认配置。`currentSessionId`、`nextSessionId`、`defaultAnchorId` 是实体字段，运营端分页 VO **不投影**（恒不返回）；当前/下一场次经直播间场次列表获取。
- **讲解场次**是实际排期与直播生命周期对象；同一直播间可有多个场次。主播、计划起止、实际起止、商品编排、回放和复盘以场次为首选边界。
- **主播**可绑定会员账号，并可关联多个直播间/场次。`anchorId` 是主播业务 ID，`userId` 是会员 ID，不能互换。
- **场次商品**跨商品域引用：每个添加项必须是 `{spuId, skuIds[]}`。SPU 决定商品归属与排序/移除维度，SKU 决定实际参与直播的规格以及直播价、直播库存。
- **回放记录**反映录制产物状态；播放凭证与媒资删除不开放。
- **统计看板**偏直播间聚合；**场次数据中心**偏单场复盘，包含流量、互动、商品点击、订单与支付指标。两者口径不同，不应互相替代。

## 数据口径

- 场次数据 `viewerUv` 等字段可为 null：历史未采集不等于 0（null 字段在 JSON 中整体省略，语义等价）。
- 趋势按五分钟时间桶返回；除 `onlinePeak`（桶内观察峰值）外各指标为桶内增量；`paidAmountFen` 单位为分。
- 商品转化行的 `spuId` 以 `liveGoodsId` 标识当时的直播商品记录；名称/封面为**当前商品资料优先**（SPU 存在时以商品中心当前值返回），仅商品中心异常或 SPU 删除时为空——不是「冻结的历史快照」。
- 统计看板是**统计行维度**：每场次结束落一行（含旧房间级历史行），`totalRooms` 为统计记录数而非直播间去重数；排行取观看数前 10 统计行（同一直播间多场次可重复）；旧场次统计的时间过滤基准是统计快照落库时间，不是场次开播时间；`totalAmount` 单位为分（支付事件实付金额累加）。
- IM 在线人数是外部实时查询，与复盘 UV/PV 不同；IM 未开放。

## Java 实现缺口转化为调用纪律

- 创建场次 DTO 的 `roomId` 带必填校验，而控制器在校验后才尝试用路径直播间 ID 回填；创建结果还含 `streamName`。该缺陷与敏感返回无法由 DIRECT 能力安全修正，因此场次创建未开放。
- 场次商品的 `items`、`items[].spuId`、`items[].skuIds` 均没有可依赖的完整级联 Bean Validation 保证。调用前必须保证 `items` 非空、每项 `spuId` 存在且 `skuIds` 非空。
- SKU 直播价/库存 DTO 没有 Bean Validation 数值范围注解，服务运行时也未校验非负，且更新逻辑只处理非 null 字段。Skill 调用纪律要求先从商品域核对 SKU 归属与原价，只提交用户明确给出的非负数值；null 不会清空或恢复默认。场次维度 SKU 更新**不写商品变更记录、不同步托管库存池**（房间维度旧端点才有该行为）。
- 商品排序只校验数组非空，未证明会校验完整集合。排序前读取当前场次商品，提交完整且不重复的 SPU ID 集合；未传入的 SPU 保持旧排序值，部分提交产生排序值碰撞。
- 商品变更记录仅覆盖**房间维度** SKU 更新产生的直播价/库存实质变更（`PRICE`/`STOCK` 两类、值相同不记、最多 50 条）；场次维度添加/排序/移除/SKU 更新均不产生记录。
- 添加场次商品无场次状态守卫（已结束/已取消场次同样可加），单场次上限 50 个商品；`items` 空数组或 null 静默成功无效果；服务端对 SPU/SKU 存在性与归属零校验，错误数据以「默认规格/无价格」落库。
- 直播间编辑服务端仅拦截直播中(1)（暂停可写入）；直播间编辑/删除的业务拒绝以普通运行时异常抛出，响应为 500「系统异常」、具体原因不透出——前置状态核验必须依赖查询而非错误反馈。分类域守卫则走 400 通道、业务消息可透出。
- 分类编辑的 `sortOrder` 省略或 null 会重置为 0（非「不更新」）；分类列表首次调用会种子 6 个默认分类并迁移历史空分类数据。
