# 数据标签子域 — 运营流程

> 对应契约：`apis/data-tag/category-query.md` / `apis/data-tag/category-action.md`（分类）、`apis/data-tag/tag-query.md` / `apis/data-tag/tag-action.md`（标签）、`apis/data-tag/crowd-query.md` / `apis/data-tag/crowd-action.md`（人群包）、`apis/data-tag/manual-tag-action.md`（动态人群包）、`apis/data-tag/operator.md`（运算符）；概念知识：`references/domains/data-tag.md`。

## 分类与标签

1. 先查询分类树，创建或选择目标分类。⚠️ **预判拒绝**：读取分类树后如果发现操作违反已知约束（如目标父分类已是一级子分类、要建三层），**禁止提交写操作**——直接向用户说明"标签分类最多两层"并停止。已知不可能成功的操作不需要"试一下看服务端是否拒绝"。
2. 创建规则标签前，查询可引用标签和运算符；为每个标签值提供独立 `valueDefine` JSON 字符串。**规则条件值（阈值/金额等）没有系统预定义选项**——追问时仍应发起结构化追问等待用户回答，但阈值/金额类不要编造预定义值（如500/1000/2000），应利用系统自动追加的自由输入项让用户输入具体值；可引用的维度和运算符以查询结果为准。
3. 创建手工标签前，先确认绑定人群包已 ONLINE；每个标签值都要绑定 crowdId。
4. 更新标签前先读详情。带 `tagValues` 是差量全量清单：遗漏既有 ID 会使该标签值被软删除；空数组会被拒绝；只改名称/备注/状态时不传 `tagValues`。执行前应向用户说明本次会删除和保留的值清单，让用户知情。
5. 启停和删除前读详情并复述名称、ID、影响范围。删除会清理标签值，不能恢复；全局标签不允许普通租户改删。**启用与停用均需说明业务影响**（启用恢复定向触达；停用中断定向触达）。⚠️ **影响面表述规范**：`tagCount` 是统计字段（初始化为 0，不实时反映引擎命中），**禁止**说"打标人数为 0 所以无会员受影响"——正确表述为"统计字段为 0，引用与实时命中未确认"。

## 规则圈选人群包

1. 查询标签与运算符，依据 `apis/data-tag/crowd-action.md` 构造 `queryCondition` 字符串（规则项只能使用 `tagId`）。⚠️ **计算周期必须来自用户**：用户未指定计算周期（每天/每周/每月）时**禁止默认值**——必须追问；后端不校验，默认 NONE=0 会导致创建后不刷新。`value` 也不能自行编造（如 `"*"`），必须来自用户或查询结果。
2. 提交规则圈选后报告"已提交计算"，不是"已生效"。
3. 查询人群详情和任务记录轮询；最新任务 `status=0` 继续等待，`1` 且人群 ONLINE 后才报告成员数量与可用于促销定向，`2` 或人群 FAILED 时报告失败原因。
4. 更新规则条件会清空旧统计并重新进入 CALCULATING；更新频率但规则未变不会重算。
5. 上下线、删除前先读详情。上线仅 OFFLINE；下线仅 ONLINE；删除不可恢复。对可能被促销定向引用的人群，读详情确认类型后在回复中说明影响。⚠️ **重上矩阵（读详情后核对，禁止试探）**：周期性规则圈选与动态包 ✅ 可重上；文件上传与单次规则圈选（NONE=0）❌ **不可重上**——读详情确认类型后，如属于 ❌ 行，直接告知用户无法重上并说明原因，**不要提交 online 操作**。

## 动态人群包与促销闭环

1. 需要口令码或运营手工定向时，创建"手工标签 + 动态人群包"原子组合，保存返回的 tagValueId/crowdId。
2. 批量加用户每批最多 500 个 UID；`tagValueId` 与 `crowdId` 至少一个，优先用前者。⚠️ **双目标一致性**：两者同时传入时必须先读标签详情确认 tagValueId 绑定的 crowdId 与传入的 crowdId 一致；不一致时**停止写操作并向用户澄清**（后端以 tagValueId 为准写入其绑定的人群包，不会校验冲突）。
3. 返回 `addedCount=0` 不一定是失败（成员可能已存在）。成员位图已写入，但 Redis 标签命中同步异步完成，向运营说明秒级延迟。
4. 在促销域创建 SPECIFIED 定向时使用返回的 tagValueId，绝不把 tagId 或 crowdId 代替它。
5. 标签删除/启停前，**`tagCount` 是统计字段不是实时命中集合**——0 不代表无促销/装修引用或无影响；人群包 `hasActiveLinkedTag` 仅检查已启用的标签关联，不查促销/装修等外部引用。影响面不完全可查时应如实说明"引用与实时命中未确认"，不要断言"无业务影响"。

## 文件上传人群包

1. **确认文件与 ID 类型**：向用户复述文件名、行数量级与 `convertType`（0=UID / 1=OpenID / 4=手机号——**2=W_UID 与 3=UNION_ID 后端未实现，传入全部行失败，勿使用**）；文件为 CSV/TXT（≤50MB）单列 ID 清单，官方模板表头行会被自动跳过（用户自建文件可不带表头）。
2. **选择模式**：新建（CREATE，crowdName 必填 ≤50 字符）或追加（APPEND，targetCrowdId 必填——仅 DYNAMIC / FILE_UPLOAD 类型人群包允许追加，规则圈选包拒绝，避免规则重算冲掉）。
3. **上传后核验**：导入异步执行——轮询 `crowd.task-records` 或以 `crowd.members` 计数核验，未完成不得当作失败。
4. **失败明细**：`crowd.download-fail` 取「最近一次导入」失败明细；`crowd.task-download-fail` 按任务 ID 取历史任务失败明细（taskId 来自 task-records）；把 URL 转告用户（有时效）。
5. **成员明细**：`crowd.download` 取人群包成员明细下载 URL，转告用户。
