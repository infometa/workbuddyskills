# DxC 金句库

内部调用 DxC CLI 时只使用 PATH 中的全局入口：`dxc <参数>`。本 Skill 的版本是 `0.3.28`，
安装流程必须已经验证 `dxc version --json`、本 Skill 集和该版本完全一致。正常任务不得通过 npm、
npx 或其他包执行器解析 DxC，也不得硬编码任何用户的可执行文件绝对路径。若 `dxc` 不在 PATH，或
CLI 报告官方 Skill 版本不一致，停止并请用户按安装说明重新安装同一指定版本；不在当前任务内联网
解析、切换版本或改用仓库源码。

DxC 的调用由本 Skill 给出。每次只直接执行当前 Skill 明确写出的一个 DxC 命令，不寻找或猜测替代命令。只把 CLI 上一次结构化结果中的 `workItemId` 或 `choiceId` 作为不可解释也不可编辑的字段直接交给下一次结构化调用；字段传递不得经过模型重新生成或自然语言转录。禁止手工复制、拼接、改写、截取、解码、重建、落盘、持久化或转存这些值，也不要求用户接触它们。

调用仍在运行时，`DXC_BROWSER_EVENT` 只表示需要立即承载当前页面，不表示命令失败或完成。等到进程退出并收到唯一的 `DXC_RESULT` 最终帧后，先把其中完整结构化结果作为当前事实保存，再向用户转述；不得用进度文案、浏览器地址或自己概括的字段替代最终工作项。

禁止用 Python、Shell、PowerShell 临时脚本、循环、管道、命令替换、后台任务、并发或定时器包装 DxC 命令。禁止调用 CLI help，禁止查看源码、日志、内部文件或解析返回值内部结构来推断下一步。没有明确的下一步时，停在这里，如实告诉用户当前还不能继续。

CLI 失败时，若当前 Skill 明确规定了 CLI 返回选项、用户选择后继续的分支，只按该分支等待并提交用户选择。
其余失败禁止再次调用、轮询、跳阶段、重新进入阶段或创建替代项目。只转述其中面向用户的 `message` 和唯一 `recovery` 所表达的安全方向，隐藏命令、内部标识、本地位置和诊断细节，然后停止；不得自行执行恢复动作或推测根因。

若宿主无法把完整结构化字段直接传给下一次调用，停止并说明交接能力不足；不得为了继续而手抄或重建引用。
状态目录权限被拒绝时，用户的自然语言同意不改变沙箱。只有宿主实际授予目标目录权限后才能继续；
不要反复在相同受限环境执行，也不要修改全局安全配置、放宽目录权限或搬迁文章。doctor 的工作目录检查不代表文章状态目录可写。

### 宿主接入与执行能力

本机安装核验不代表宿主已能执行当前任务。开始新的内容生产任务前，依据当前实际暴露的工具核对：
完整结构化结果能原样交接；执行环境已获准写入当前工作区与已选择的状态目录。完整文章流程还须
具备独立干净上下文子智能体，以及把真实图片直接保存为要求格式的能力。只处理标题、已有成稿交付
等中途入口时按本轮实际工作检查，不为未执行的阶段要求无关工具。目录或文件存在不证明已授权。
若宿主提供有效权限查询，先核实授权；安装流程已选且已存在的状态目录可由 `dxc doctor --directory <已选 Skill 目录> --state-directory <已选状态目录> --json` 验证实际写入与原子重命名。

能力缺失时，在创建项目或产出候选稿之前说明具体缺项并停止，不等写完正文才发现无法独立审校；
不能用自审代替独立审校、用占位图代替真实素材，或请求用户放宽全局权限。没有侧边栏浏览器时使用
CLI 的系统浏览器与短时链接降级，不因宿主名称假定有侧边栏；没有适用原生 UI 时沿用下方文本交互。
`doctor` 的 `hostCapabilities: not-checked` 表示宿主能力仍由本次实际工具核对，不能转述为全流程已通过。

### 用户选择与确认

所有 DxC Skill 共享以下交互合同。需要用户决定时，优先调用当前宿主实际提供、且允许用于该目的的原生 UI 交互工具，展示可点击选项；不能只在聊天中列编号并要求用户输入“确认”“继续”或数字。阶段采用、标题选择、公众号选择、返修方向、模板、长期资产变更和最终草稿确认都适用。

- 先展示待决定的真实内容，再用简短的业务选项表达动作，例如“采用并继续 / 修改 / 暂停”。选项只携带当前 CLI 返回的可执行选择；内部引用不展示给用户。
- 按 CLI 问题类型保留单选、多选与自由文本语义；多选优先用原生多选，只有单选工具时分成简短的逐项点击，不把多选擅自缩成一个选项。只对确实缺失且无法提供候选的内容使用文本输入。
- 用户已经明确指定入口、选择或授权当前动作时直接执行，不再问同一个问题；尤其不要逐项询问是否跳过研究、Brief 或大纲。每个确认只授权该次展示的内容与动作。
- 工具名以当前宿主实际暴露的能力为准，不假设某个工具永远存在。例如允许该用途的 AskUserQuestion、request_user_input 或 request_user_input_async；只有计划模式或只允许可选澄清的工具不能拿来做权限确认。
- 异步 UI 问题发出后，等待用户实际提交结果再执行依赖它的动作。默认选中、超时、无回答、取消和关闭面板均不代表同意，也不能自动选推荐项。取消时保留当前成果，停止依赖该决定的动作。
- 只有宿主确实没有可用于该目的的原生 UI 时，才简短说明限制，并使用最少输入的文本选择；不得伪造按钮、用终端交互提示代替宿主 UI，或要求用户执行命令。用户始终可直接用自然语言纠正、修改或拒绝。
- “准备公众号草稿”表示准备到最终预览；创建或覆盖草稿仍须展示当前不可变预览，并通过允许用于确认的 UI 取得明确决定。原生交互不改变快照、租户、幂等或未知结果停止规则。

面向用户只展示金句、来源和使用边界，不展示命令、内部标识、位置或实现过程。

查看、导出和归档免费；检索、收录、修改和采用需要有效试用或订阅。收到 `DXC_BILLING_*` 时不改金句库或当前项目，只提供 CLI 返回的订阅恢复方向并停下。

金句在统一创作记忆中属于 `expression` + `suggest`；本 Skill 是保留署名、来源和逐字许可的兼容入口。不得把“合并”理解为丢弃出处或让金句自动进入正文。

- 查看：执行一次 `dxc knowledge quotes list --json`。
- 收录：用户给出金句和来源性质后，执行一次 `dxc knowledge quotes add --text <正文> --origin <original|third-party> --verbatim-use <使用边界> --json`。本人明确原创用 `original`，来自他人或来源不明用 `third-party`；已提供的出处用 `--source <出处>` 一并提交。第三方必须附 `--attribution <署名>`，未提供时先问，不能编造作者或用“未知”凑参数。
- 修改或归档：用户明确选中一条金句后，分别执行一次 `dxc knowledge quotes update <用户选定金句> --text <用户修改内容> --json` 或 `dxc knowledge quotes archive <用户选定金句> --json`。
- 检索：执行一次 `dxc knowledge search <用户的写作目标> --source quotes --json`。
- 采用：用户明确选中检索结果和当前文章后，执行一次 `dxc knowledge adopt --project <用户选定文章> --item <用户选定结果> --json`。

本人明确说明原创才能按原创收录；来自他人、书籍、网页或来源不明的内容不得冒充原创。逐字使用是否获许可不明确时，先向用户提问。不要直接改写金句资料、自动初始化或同步、自动选择检索结果、连续试错或把未获许可的内容作为可逐字采用的金句。

`--verbatim-use` 按已知事实填写：本人原创用 `original`；第三方明确允许逐字使用用 `permitted`；
尚待核实用 `needs-verification`；明确禁止逐字使用用 `do-not-use-verbatim`。收录待核实内容不等于
取得许可。修改来源、署名或使用边界时，沿用 `quotes update` 并附对应参数，只提交用户明确改变的字段。

检索遇到本地语义模型不可用、CLI 返回需要用户选择的选项时，展示选项并等待用户；选定后执行一次
`dxc knowledge search <原写作目标> --source quotes --choice <所选 choiceId> --json`，原样传递
该选项引用，保持原检索目标和参数。其他失败仍停止，不自动选择或重试。
