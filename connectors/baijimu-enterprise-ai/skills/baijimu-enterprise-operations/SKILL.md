# 百积木企业业务

通过 `baijimu` CLI 使用用户已授权的百积木工作区。把 CLI 的当前分级帮助和目标工作区返回的动态资源目录视为命令与业务参数的事实来源。

## 开始前

1. 运行 `baijimu --version`，确认 CLI 可用。
2. 运行 `baijimu auth status --verify --json`，确认登录状态。未登录时停止并引导用户通过连接器的“连接”操作完成授权，不要求用户粘贴 Token。
3. 先运行 `baijimu --help`，只定位当前任务需要的命令组；再沿目标路径逐级运行 `--help`。帮助中不存在的命令不得猜测执行。
4. 需要工作区动态资源时先查询工作区列表或当前工作区。不要把展示名、列表第一项或历史记录当作稳定 ID；零匹配或多匹配时让用户选择。

## 常用能力

- 工作区与项目：查询用户可访问的工作区、当前工作区、项目和只读项目文件。
- 智能体：创建或继续智能体会话，并读取执行结果。
- 工作流：启动已安装的业务流程，查询实例、节点执行和失败原因。
- 运行时服务：先列出服务，再读取方法定义，最后按方法声明组织参数并调用。
- 应用与模块：查询工作区应用、模块和安装状态；安装、升级或发布前先解释影响并取得确认。

优先为业务用户完成具体目标，例如查询订单或客户、启动审批、让数字员工处理任务、跟踪工作流，而不是展示底层命令清单。

## 执行规则

- 查询、列表、帮助、状态和审计属于只读操作，可以直接执行。
- 创建、更新、安装、升级、启动流程、调用会改变业务状态的方法，执行前说明准确目标、工作区和影响，并获得用户确认。
- 删除、卸载、取消运行、撤回、回滚、覆盖内容、外发消息、交易、审批及可能产生费用的动作，必须在执行前再次获得对准确目标的明确确认。
- 运行时调用固定采用“列服务 → 读方法定义 → 调用”的顺序。所有业务参数放入命令声明的参数对象；不得从示例猜测服务名、方法名或参数结构。
- 工作区级操作使用用户选择并由平台返回的工作区 ID。不要在 Skill、脚本或命令模板中写死工作区、用户、环境、主机、域名或业务资源 ID。
- 使用 `--json` 获取结构化结果；向用户展示业务结论，不倾倒无关响应。
- 不输出、记录或要求用户提供 PAT、模型密钥、服务令牌、Cookie 或完整认证响应。
- 遇到认证失效，停止业务调用并引导重新连接；不得修改认证文件或绕过平台权限。

## 完成标准

只有当目标操作成功，并通过对应的 `get`、`list`、`status`、实例详情或审计记录回查一致时，才报告完成。失败时保留公开错误码和可读错误信息，区分认证、权限、资源解析、业务校验和服务不可用。
