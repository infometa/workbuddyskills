# 数据导出流程

## 流程概述

本流程指导从**查找导出能力** → **发起导出任务** → **轮询任务状态** → **下载导出文件**的完整异步导出流程。

---

## 触发条件

用户表达导出数据意图时触发，常见表述：
- "帮我导出客户"
- "导出商品列表"
- "把订单数据导出来"
- "导出XX数据"
- "我要下载客户/商品/订单列表"

---

## 执行流程

### 步骤一：查找导出能力（查询 site-assistant）

当用户要求导出数据时，首先查阅 [`site-assistant/SKILL.md`](../site-assistant/SKILL.md) 中的**二、核心业务数据导出**路由表，确认用户想要导出的数据类型是否支持导出。

**判断是否支持逻辑：**
- ✅ **支持导出**：找到对应的导出文档，继续执行步骤二
- ❌ **不支持导出**：告知用户当前不支持该类型数据导出，建议用户查看已支持的导出类型

---

### 步骤二：确认导出筛选条件

**重要：在发起导出任务前，必须先查阅对应的导出接口文档，了解支持的筛选条件，并询问用户具体的导出需求。**

**询问示例：**

**示例1 - 导出客户：**
```
AI：请问您需要导出哪些客户数据？可以设置以下筛选条件：
- 客户名称/编码/联系人/电话（关键字搜索）
- 客户分类
- 所属区域
- 客户状态（启用/禁用）
- 业务员
- 客户标签
- 创建时间范围
- 其他条件...

如果不设置筛选条件，将导出所有客户数据。请告诉我您的具体要求。
```

**示例2 - 导出商品：**
```
AI：请问您需要导出哪些商品数据？可以设置以下筛选条件：
- 商品名称/编码/条码（关键字搜索）
- 商品分类
- 商品品牌
- 商品标签
- 库存状态（有库存/无库存）
- 上架状态
- 商品类型（普通商品/套餐商品）
- 其他条件...

如果不设置筛选条件，将导出所有商品数据。请告诉我您的具体要求。
```

**示例3 - 导出订单：**
```
AI：请问您需要导出哪些订单数据？可以设置以下筛选条件：
- 订单号
- 订单状态（待审核/已审核/已出库等）
- 买方机构
- 订单创建时间范围
- 付款状态
- 出库状态
- 发货状态
- 业务员
- 其他条件...

如果不设置筛选条件，将导出所有订单数据。请告诉我您的具体要求。
```

**确认筛选条件后，根据用户回答构建导出参数JSON。**

---

### 步骤三：发起导出任务

根据步骤一找到的参考文档，调用对应的导出接口发起异步导出任务。

**接口返回示例：**
```json
{
    "code": 200,
    "message": "操作成功",
    "data": {
        "key": "cabaedfc-6e25-4c30-a55a-9ab18c795e81",
        "name": "客户dh列表导出_20260414100000.xlsx",
        "type": 1,
        "status": 0,
        "read": 0,
        "progress": 0
    }
}
```

**关键信息提取：**
从返回结果中记录以下字段：
- `key`：任务标识（用于后续查询进度），示例值：`cabaedfc-6e25-4c30-a55a-9ab18c795e81`
- `name`：导出文件名，示例值：`客户dh列表导出_20260414100000.xlsx`

---

### 步骤四：轮询导出任务状态

使用步骤三获取的 `key` 值，调用导出任务查询接口[`exportTaskProgress`](../site-assistant/references/导出/导出任务查询.md) 轮询任务执行状态，传入参数 `{"taskKey": "<任务key>"}`。

**轮询规则：**
- ⏱️ **轮询间隔**：每 5 秒查询一次
- 🔁 **持续轮询**：直到任务状态为成功（status=3）或失败（status=4）
- 📊 **结果展示**：轮询结束后展示最终的导出结果，轮询过程中无需展示进度

> 注意：轮询过程中无需向用户展示进度，等待任务完成后直接展示最终结果即可。

---

### 步骤五：处理导出结果

根据轮询返回的任务状态进行不同处理：

#### 场景 A：导出成功（status = 3）

**返回示例：**
```json
{
    "code": 200,
    "message": "操作成功",
    "data": {
        "key": "cabaedfc-6e25-4c30-a55a-9ab18c795e81",
        "name": "客户dh列表导出_20260414100000.xlsx",
        "type": 1,
        "status": 3,
        "progress": 100,
        "read": 0,
        "result": {
            "message": "导出成功",
            "filePath": "https://oss-img.dinghuo123.com/liteJob/34579128/ABCD.xlsx",
            "ossPreview": null,
            "extra": null
        },
        "businessType": 1100012
    }
}
```

**处理方式：**
1. 从 `result.filePath` 获取文件下载地址
2. 告知用户导出成功，提供文件下载链接
3. 展示文件名和下载链接

**回复示例：**
```
✅ 客户数据导出成功！

📄 文件名：客户dh列表导出_20260414100000.xlsx
🔗 下载地址：https://oss-img.dinghuo123.com/liteJob/34579128/ABCD.xlsx

请点击链接下载文件。
```

#### 场景 B：导出失败（status = 4）

**返回示例：**
```json
{
    "code": 200,
    "message": "操作成功",
    "data": {
        "key": "cabaedfc-6e25-4c30-a55a-9ab18c795e81",
        "name": "客户dh列表导出_20260414100000.xlsx",
        "status": 4,
        "result": {
            "message": "导出失败：数据量过大，请缩小查询范围"
        }
    }
}
```

**处理方式：**
1. 从 `result.message` 获取失败原因
2. 告知用户导出失败，并说明失败原因
3. 提供解决建议

**回复示例：**
```
❌ 客户数据导出失败

📋 失败原因：数据量过大，请缩小查询范围

💡 建议：
- 增加筛选条件（如时间范围、客户分类等）
- 分批导出不同时间段的数据
- 联系系统管理员调整导出限制
```

## 完整流程示例

### 示例：导出客户列表

**用户请求：** "帮我导出所有客户数据"

**执行步骤：**

1. 查阅 ../site-assistant/SKILL.md，找到客户导出接口文档（`../site-assistant/references/导出/客户导出.md`）
2. 询问用户筛选条件
3. 调用 `customerConditionsExport` 接口（由 site-assistant 提供），发起客户导出任务，从返回结果中提取 `key`
4. 每 5 秒调用 `exportTaskProgress` 接口轮询任务状态，直到 `status=3` 或 `status=4`
5. 导出成功后从 `result.filePath` 获取下载地址，告知用户

**与用户交互示例：**
```
用户：帮我导出所有客户数据

AI：请问您需要导出哪些客户数据？可以设置以下筛选条件：
- 客户名称/编码/联系人/电话（关键字搜索）
- 客户分类
- 所属区域
- 客户状态（启用/禁用）
- 业务员
- 客户标签
- 创建时间范围

如果不设置筛选条件，将导出所有客户数据。请告诉我您的具体要求。

用户：导出全部客户

AI：正在为您发起客户导出任务...

AI：✅ 导出任务已创建
📄 文件名：客户列表导出_20260414100000.xlsx
⏳ 正在处理导出任务，请稍候...

（等待任务完成...）

AI：✅ 客户数据导出成功！

📄 文件名：客户列表导出_20260414100000.xlsx
🔗 下载地址：https://oss-img.dinghuo123.com/liteJob/34579128/ABCD.xlsx

请点击链接下载文件。
```

## 注意事项

### 1. 异步导出机制
- 所有导出接口均为**异步操作**，不会直接返回文件
- 必须先创建导出任务，再通过轮询获取结果
- 不得假设导出会立即完成

### 2. 轮询控制
- **必须**按照 5 秒间隔进行轮询
- **不得**过于频繁查询（避免服务器压力）
- **不得**间隔过长（避免用户体验差）
- **轮询过程中无需展示进度**，等待任务完成后直接展示最终结果即可

### 3. 状态判断
| status 值 | 状态说明 | 处理方式 |
|-----------|---------|---------|
| 0 | 已加入队列 | 继续轮询 |
| 1 | 等待执行 | 继续轮询 |
| 2 | 执行中 | 继续轮询，展示进度 |
| 3 | 成功 | 停止轮询，下载文件 |
| 4 | 失败 | 停止轮询，提示失败原因 |

### 4. 文件下载
- 文件下载地址来自 `result.filePath` 字段
- 仅在 `status=3` 时该字段有效
- 文件可能存在有效期限制（`read=2` 表示已过期）
- 建议用户及时下载

### 5. 错误处理
- 导出接口调用失败：检查参数是否正确，重新发起
- 轮询接口调用失败：重试1-2次，仍失败则提示用户
- 导出任务失败：展示失败原因，提供解决建议
- 文件下载失败：检查链接是否过期，建议重新导出

### 6. 用户体验
- **发起任务前必须询问筛选条件**，不得直接导出全部数据
- 展示支持的筛选条件选项，让用户选择
- 发起任务后告知用户任务已创建
- 轮询过程中无需展示进度，避免频繁打扰用户
- 任务完成或失败时明确告知结果
- 提供清晰的操作指引（下载链接或失败原因）

### 7.特殊情况解释
- 不支持修改导出模板，例如用户要求导出时增加/删除字段时，委婉告诉用户不支持调整导出模板字段
