# 场景：订单签收

**适用意图**：用户说"帮我签收订单XXX"、"签收，订单号是XXX"、"我要签收XXX订单"

**所用接口**（按执行顺序）
- `findDispatchBills`（参考：[site-assistant/references/仓库/发货单.md](../../../site-assistant/references/仓库/发货单.md)）— 查询发货单获取签收单ID
- `searchOutStorageBills`（参考：[site-assistant/references/仓库/销售出库单.md](../../../site-assistant/references/仓库/销售出库单.md)）— 通过出库单号查询出库单ID
- `updateReceivingBill`（参考：[site-assistant/references/订单/订单-签收.md](../../../site-assistant/references/订单/订单-签收.md)）— 签收指定签收单

---

## 功能说明

订单签收是一个多步骤的组合流程，需要先查询发货单获取签收单 ID，再调用签收接口完成签收操作。

## 业务流程

```
用户提供订单号/发货单号 
    ↓
步骤1：查询发货单（获取签收单ID）
    ↓
步骤2：确认签收信息（整单签收 or 部分签收）
    ↓
步骤3：调用签收接口完成签收
```

## 第一步：查询发货单获取签收单 ID

### 场景 A：用户提供订单号

通过订单号查询发货单，获取签收单 ID：

> [findDispatchBills](../../../site-assistant/references/仓库/发货单.md)
> **调用参数**:
```json
  {"orderNum": "订单号"}
```

从返回结果中提取签收单 ID：
- `receivingBillId`：签收单主键 ID（即签收需要的签收单 ID）
- `receivingBillNum`：签收单号
- `receivingStatus`：签收状态（`-1`=作废，`0`=待签收，`1`=已签收）

**注意事项**：
- 一个订单可能有多个发货单，会返回多条记录
- 如果返回多条发货单，需要让用户确认要签收哪一单
- 仅 `receivingStatus=0`（待签收）的发货单才能签收

### 场景 B：用户提供发货单号

通过发货单号查询发货单：

> [findDispatchBills](../../../site-assistant/references/仓库/发货单.md)
> **调用参数**:
```json
  {"dispatchBillNums": ["发货单号"]}
```
> 注意：`dispatchBillNums` 必须是数组格式

从返回结果中提取 `receivingBillId`。

### 场景 C：用户提供出库单号

**第一步**：通过出库单号查询出库单，获取出库单 ID：

> [searchOutStorageBills](../../../site-assistant/references/仓库/销售出库单.md)
> **调用参数**:
```json
  {"billNums": ["CK20240101001"]}
```

从返回结果中提取出库单的 `id`。

**第二步**：使用出库单 ID 查询发货单：

> [findDispatchBills](../../../site-assistant/references/仓库/发货单.md)
> **调用参数**:
```json
  {"outStorageBillIds": [<出库单ID>]}
```

从返回结果中提取 `receivingBillId`。

## 第二步：确认签收方式

在签收前，需要向用户确认签收方式：

### 询问用户

```
请问您要如何签收？
1. 整单签收（按发货数量全部签收）
2. 部分签收（有数量差异或少货/破损）
```

### 签收方式说明

**整单签收**：
- 不传 `contents` 参数
- 系统自动按发货单数量全部签收
- 适用于货物完好、数量一致的场景

**部分签收**：
- 需要传 `contents` 明细
- 适用于实际收到数量与发货数量不一致的场景
- 需要填写差异原因（`differenceReason`）

## 第三步：调用签收接口

### 场景 1：整单签收（无差异）

> [updateReceivingBill](../../../site-assistant/references/订单/订单-签收.md)
> **调用参数**:
```json
{
  "id": 987654321,
  "warehouseId": 111222333,
  "remark": "整单签收"
}
```

**参数说明**：
- `id`：签收单 ID（从第一步的 `receivingBillId` 获取）
- `warehouseId`：入库仓库 ID（必填，需向用户确认或从发货单中获取）
- `remark`：签收备注（可选）

### 场景 2：部分签收（有差异）

> [updateReceivingBill](../../../site-assistant/references/订单/订单-签收.md)

**调用参数**：
```json
{
  "id": 987654321,
  "contents": [
    {
      "id": 555666777,
      "count": 8,
      "diffType": 1,
      "differenceReason": "少发货2箱"
    },
    {
      "id": 555666778,
      "count": 5,
      "diffType": 2,
      "differenceReason": "破损1箱"
    }
  ],
  "warehouseId": 111222333,
  "remark": "部分签收，有差异",
  "differenceReason": "少发货、破损"
}
```

**参数说明**：
- `id`：签收单 ID（从第一步的 `receivingBillId` 获取）
- `contents`：签收明细列表（**必须提供**）
  - `id`：签收明细 ID（从发货单的 `contents` 中获取）
  - `count`：实际签收数量（直接传数字，如8）
  - `diffType`：差异类型（`1`=少发货，`2`=破损）
  - `differenceReason`：差异原因（**必填**）
- `warehouseId`：入库仓库 ID
- `differenceReason`：总体差异原因


## 注意事项

1. **必须先查询发货单**：
   - 签收单 ID（`receivingBillId`）不能直接提供，必须通过查询发货单获取
   - 使用 `findDispatchBills` 接口查询发货单

2. **签收单状态检查**：
   - 仅 `receivingStatus=0`（待签收）的单据可以签收
   - `receivingStatus=1` 表示已签收，无需重复签收
   - `receivingStatus=-1` 表示已作废，不能签收

3. **入库仓库建议填写**：
   - `warehouseId` 虽然不是必填参数，但建议填写
   - 可以从发货单的 `storageWarehouseId` 获取默认值
   - 需要向用户确认是否使用该仓库

4. **差异单处理**：
   - 部分签收时，`contents` 中每个明细的 `differenceReason` 是必填的
   - 差异类型 `diffType`：`1`=少发货，`2`=破损
   - 不支持上传照片作为附件，如需上传则提示用户前往客户端上手动签收

5. **多发货单场景**：
   - 一个订单可能有多个发货单
   - 需要让用户确认签收哪个发货单
   - 可以批量签收多个发货单（需要多次调用签收接口）

6. **客户电子签名**：
   - 移动端签收时可上传客户签名：`customerSignaturePath`
   - PC 端签收通常不需要
