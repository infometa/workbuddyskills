# 场景：订单发货

**适用意图**：用户说"帮我给这个订单发货"、"订单XXX发货"、"发货，快递/自有物流"、"我要给订单发货"

**所用接口**（按执行顺序）
- `searchSortingCars`（参考：[site-assistant/references/组织/车辆.md](../../../site-assistant/references/组织/车辆.md)）— 自有物流时可选
- `findOrderEmployees`（参考：[site-assistant/references/员工部门/员工.md](../../../site-assistant/references/员工部门/员工.md)）— 自有物流时可选
- `getSettings` + `listLogisticsCompanies`（参考：[site-assistant/references/组织/物流公司.md](../../../site-assistant/references/组织/物流公司.md)）— 快递发货时可选
- `createDispatchBill`（参考：[site-assistant/references/订单/订单-发货.md](../../../site-assistant/references/订单/订单-发货.md)）

---

## 发货前置说明

### 发货形式限制

系统支持两种发货形式：
- **正常发货**：Openclaw 支持，本流程执行此形式
- **电子面单**：Openclaw **暂不支持**，若用户要求电子面单发货，告知用户需前往页面手动操作

### 正常发货的两种途径

| 发货途径 | dispatchMethod 值 | 说明 |
|------|------|------|
| 自有物流 | `1` | 自备车辆/司机配送 |
| 快递发货 | `2` | 三方快递公司寄送 |

---

## 执行步骤

### 第一步：确认出库单 ID

**前置要求**：发货必须基于已出库（且出库单已审核）的订单，需要出库单的主键 ID（`billId`）。

- `billId` 是出库单的主键 ID，**不是出库单号**（`billNum`）
- 若用户未提供单号，需主动询问用户：**请提供订单号或出库单号**

#### 场景 A：用户提供订单号（orderNum）

调用订单出库单查询接口，获取该订单下的出库单列表：

> [listOrderOutStorageBills](../../../site-assistant/references/订单/订单-出库单查询.md)
> **调用参数**:
```json
  {"orderNum": "<订单号>", "status": 1}
```
从返回结果中提取出库单信息：
- `id`：出库单主键 ID（即发货需要的 `billId`）
- `billNum`：出库单号（展示给用户确认）
- `status`：单据状态（-1=作废，0=待审核，1=已审核）
- `dispatched`：发货状态（false=未发货，true=已发货）

**注意**：
- 若订单对应多个出库单（部分出库、分仓出库），向用户展示所有出库单，让用户确认要发哪个出库单
- 仅 `status=1`（已审核）且 `dispatched=false`（未发货）的出库单才能发货

#### 场景 B：用户提供出库单号（billNum）

调用销售出库单列表查询接口，通过出库单号精确查询：

> [searchOutStorageBills](../../../site-assistant/references/仓库/销售出库单.md)
> **调用参数**:
```json
  {"billNums": ["CK20240101001"]}
```

从返回结果中提取：
- `id`：出库单主键 ID（即发货需要的 `billId`）
- `billNum`：出库单号（用于核对）
- `status`：单据状态
- `dispatched`：发货状态

**注意**：
- `billNums` 是数组类型，即使只查一个单号也要传数组 `["单号"]`
- 仅 `status=1`（已审核）的出库单才能发货

---

### 第二步：收集发货信息并向用户确认

⚠️ **重要**：发货单创建后无法修改快递单号，必须在创建前收集完整信息并向用户确认后再调用创建接口。

### 2a. 确认发货途径

询问用户发货方式：
```
请问您要用哪种方式发货？
1. 自有物流（填写车牌号/司机信息）
2. 快递发货（填写快递公司/单号）
```

### 2b. 收集物流信息

**快递发货**（用户选择顺丰快递为例）：
| 参数 | 值 |
|------|-----|
| dispatchMethod | 2 |
| expressCompany | 顺丰速运 |
| expressNum | SF0251067913780（如果有） |

**自有物流**：
| 参数 | 值 |
|------|-----|
| dispatchMethod | 1 |
| plateNumber | 粤A12345 |
| driverName | 张师傅 |
| carId | 车辆ID |

### 2c. ⚠️ 展示发货预览并等待确认

**创建发货单前必须展示给用户确认**，格式如下：

```
## 📦 发货预览

**出库单号**：CO000000-260413-00115
**发货途径**：快递 / 自有物流
**快递公司**：顺丰速运（快递发货时展示）
**快递单号**：SF0251067913780（如果有）
**收货人**：张三
**收货地址**：北京市北京市东城区

---
是否确认发货？
```

**等待用户回复后再继续创建。** 用户确认后才调用 `createDispatchBill`。

### 2d. 快递单号为空时的处理

若用户暂时没有快递单号：
- 仍可先创建发货单（`expressNum` 传空字符串 `""`）
- **但需告知用户**：快递单号稍后需手动在系统页面补充
- 示例话术：`快递单号创建时为空，请在发货后前往系统页面手动编辑填写快递单号以便物流跟踪`

### 第三步（自有物流）：收集物流信息

自有物流所有字段均**非必填**，按需询问用户。

#### 3a. 查询车辆（选填）

若用户需要指定车牌号，调用车辆查询接口获取车辆列表：

> [searchSortingCars](../../../site-assistant/references/组织/车辆.md)

从返回列表中让用户选择车辆，记录：
- `id`（carId）
- `name` / `plateNumber` 展示给用户选择（注意：SortingCarVO 中无 plateNumber 字段，`name` 即为车辆名称，用于展示）
- `driverId`（若车辆已绑定司机，可直接使用）
- `driverName`（车辆绑定的司机名称）

#### 3b. 查询司机（选填）

若用户需要指定司机（或车辆未绑定司机），查询司机类型员工：

> [findOrderEmployees](../../../site-assistant/references/员工部门/员工.md)
> **调用参数**:
```json
   {"status": 1, "types": [2]}
```
> `types` 传 `[2]` 以过滤司机类型的员工。

记录司机的 `id`（driverId）、`name`（driverName）。

#### 3c. 汇总自有物流参数

| 参数 | 来源 | 备注 |
|------|------|------|
| dispatchMethod | 固定传 `1` | |
| carId | 用户选择的车辆 `id` | 非必填 |
| plateNumber | 用户告知的车牌号或车辆 `name` | 非必填 |
| driverId | 司机员工 `id` | 非必填 |
| driverName | 司机员工 `name` | 非必填 |
| remark | 用户填写的物流备注 | 非必填 |

---

### 第三步（快递发货）：收集物流信息

快递发货所有字段均**非必填**，按需询问用户。

#### 3a. 查询可用物流公司（选填）

若用户需要选择物流公司，先获取当前组织启用的物流公司列表：

**第一步**：查询 logisticsTracking 设置获取启用的物流公司 ID：
> [getSettings](../../../site-assistant/references/组织/物流公司.md)
> **调用参数**:
```json
  {"properties": ["logisticsTracking"]}
```

**第二步**：用 `logisticsTracking.ids` 查询物流公司详情：
> [listLogisticsCompanies](../../../site-assistant/references/组织/物流公司.md)
> **调用参数**:
```json
  {"ids": [<logisticsTracking.ids>]}
```

展示物流公司列表（优先使用 `logisticsTracking.ext[].customerName` 作为自定义别名展示），让用户选择，记录：
- `name`（expressCompany）
- `code`（expressCode）

#### 3b. ⚠️ 特殊规则：部分物流公司必须填写寄件人手机号后4位

当用户选择的物流公司编码（`code`）在以下列表中时，**必须要求用户填写"寄件人手机号后4位"**，填入 `merchantCode` 字段：

```
['SF', 'kuayue', 'zhongtong', 'shunfeng']
```

> 此信息用于快递鸟查询物流轨迹时鉴权使用。

#### 3c. 汇总快递发货参数

| 参数 | 来源 | 备注 |
|------|------|------|
| dispatchMethod | 固定传 `2` | |
| expressCompany | 物流公司 `name` | 非必填 |
| expressCode | 物流公司 `code` | 非必填 |
| expressNum | 用户填写的快递单号 | 非必填 |
| merchantCode | 寄件人手机号后4位 | **当 expressCode 在 `['SF', 'kuayue', 'zhongtong', 'shunfeng']` 中时必填** |
| remark | 用户填写的物流备注 | 非必填 |

---

### 第四步：调用发货接口

组装参数后调用发货接口：

**自有物流示例：**
> [createDispatchBill](../../../site-assistant/references/订单/订单-发货.md)

**调用参数**：
```json
{
  "billId": 2399148462991008,
  "dispatchMethod": 1,
  "carId": 2395657197618848,
  "plateNumber": "oyq车辆",
  "driverId": 1537631326291424,
  "driverName": "司机小王",
  "remark": "测试发货"
}
```

**快递发货示例（普通快递）：**
```json
{
  "billId": 2399148462991008,
  "dispatchMethod": 2,
  "expressCompany": "中通快递",
  "expressCode": "zhongtong",
  "expressNum": "ZT1234567890",
  "merchantCode": "1234",
  "remark": "易碎，轻拿轻放"
}
```

**快递发货示例（无需 merchantCode）：**
```json
{
  "billId": 2399148462991008,
  "dispatchMethod": 2,
  "expressCompany": "德邦物流",
  "expressCode": "debang",
  "expressNum": "DB987654321"
}
```

> 发货接口无返回值（void），调用成功即视为发货完成。

---

### 第五步：告知用户结果

**发货成功：**
```
✓ 发货成功！
发货途径：自有物流 / 快递（{快递公司名}）
快递单号：{expressNum}（如有）
```

**发货失败：**
```
✗ 发货失败：{错误原因}
请根据提示调整后重试，或手动前往页面处理。
```

## 注意事项

- **电子面单不支持**：Openclaw 仅支持正常发货，电子面单需前往页面操作
- **billId 是出库单主键 ID，不是出库单号**（billNum）；发货前必须先完成出库并审核
- **所有物流字段均非必填**，但建议引导用户填写以便后续物流跟踪
- **merchantCode 特殊规则**：expressCode 在 `['SF', 'kuayue', 'zhongtong', 'shunfeng']` 时必须填写寄件人手机号后4位
- `logisticsTracking.ext[].customerName` 为组织自定义物流公司别名，展示时优先使用
- 自有物流的车辆查询来自分拣车辆（`searchSortingCars`），非一般车牌

## 已知问题

### 1. 发货单创建后无法补填快递单号
- **现象**：调用 `createDispatchBill` 时 `expressNum` 为空字符串，发货单创建成功后无法通过接口补填
- **原因**：系统不允许重复创建发货单
- **解决**：需要用户手动在系统页面编辑发货单填写快递单号
