# 场景：创建订单

**适用意图**：用户说"帮我给XX客户下一单"、"我要给XX客户创建订单"、"帮我下单，商品是XXX"、"给XX客户下单买XXX"

**所用接口**（按执行顺序）
- `customerList` / `searchDirectUnder`（参考：[site-assistant/references/客户与商机/客户.md](../../site-assistant/references/客户与商机/客户.md)）
- `getCustomerDetail`（参考：[site-assistant/references/客户与商机/客户.md](../../site-assistant/references/客户与商机/客户.md)）
- `findOrderWarehouses`（参考：[site-assistant/references/仓库/仓库.md](../../site-assistant/references/仓库/仓库.md)）
- `findOrderCustomerSku`（参考：[site-assistant/references/商品/商品.md](../../site-assistant/references/商品/商品.md)）
- `findOrderEmployees`（参考：[site-assistant/references/员工部门/员工.md](../../site-assistant/references/员工部门/员工.md)）
- `getPermittedDeliveryMethod`（参考：[site-assistant/references/订单/配送方式.md](../../site-assistant/references/订单/配送方式.md)）
- `listDeliveryAddresses`（参考：[site-assistant/references/组织/收货地址.md](../../site-assistant/references/组织/收货地址.md)）
- `calculateOrderPrice`（参考：[site-assistant/references/订单/订单-计价.md](../../site-assistant/references/订单/订单-计价.md)）

---

## 执行步骤

### 第一步：确认往来单位

**向用户确认**（若未在初始消息中提供）：
- 往来单位类型：**客户**（默认）/ 门店 / 分公司
- 往来单位名称或编码

**类型对应的 hierarchyCode：**
| 往来单位类型 | hierarchyCode |
|---|---|
| 客户（默认） | `customer` |
| 门店 | `store` |
| 分公司 | `branch` |

调用 `customerList`（客户类型优先）或 `searchDirectUnder`（门店/分公司）搜索往来单位：

> [customerList](../../../site-assistant/references/客户与商机/客户.md)
> [searchDirectUnder](../../../site-assistant/references/组织/组织.md)

> 若返回多条，向用户确认选择哪一个。记录 `id`（buyerId）和 `hierarchyCode`。

---

### 第二步：并行获取客户详情、可用仓库、业务员

**三个接口无依赖关系，可同时发起：**

**2a. 获取客户详情**（含收货地址、默认业务员）
> [getCustomerDetail](../../../site-assistant/references/客户与商机/客户.md)
> **调用参数**：
```json
{"id": <buyerId>}
```
记录：
- `salesId`、`salesName`（默认业务员，客户类型时使用）
- `deliveryAddresses`（收货地址列表，暂存备用）
- `contactName`、`mobile`（客户联系人）

**2b. 获取可用仓库**
> [findOrderWarehouses](../../../site-assistant/references/仓库/仓库.md)
> **调用参数**：
```json
{"status": 1, "salesBanned": 0}
```
warehouseId默认传值-1，代表“全部仓库”

**2c. 获取业务员列表**（仅往来单位为客户时需要）
> [findOrderEmployees](../../../site-assistant/references/员工部门/员工.md)
> **调用参数**：
```json
{"status": 1}
```
默认使用客户详情中的 `salesId` 作为业务员，**不需要额外询问用户**，除非用户明确要求更换业务员。

---

### 第三步：获取可购商品列表，确认商品信息

若用户已指定商品名称，搜索匹配；否则向用户询问需要购买的商品。

> [findOrderCustomerSku](../../../site-assistant/references/商品/商品.md)
> **调用参数**：
```json
{
  "targetId": <buyerId>,
  "q": "商品名称或编码",
  "shelfStatuses": [1],
  "warehouseId": <warehouseId>
}
```

对每个用户指定的商品：
- 确认商品名称（`name`）、规格（`spec`）、编码（`code`）
- 确认下单单位：取 `multiUnitList` 中 `defaultOrderUnit: true` 的项作为默认单位，记录其 `id`（unitId）、`unitName`、`price`（originalPrice）
- 若商品 `enableMultiUnit: false`，`multiUnitList` 只有一条，直接使用
- 确认购买数量（purchaseNumbers），必须满足 `minimum`（起订量）且为 `orderMultiple`（倍数）的整数倍
- 若用户未指定数量，询问用户

**商品数量限制规则：**
- 数量 ≥ `minimum`（起订量）
- 数量 % `orderMultiple` == 0（倍数约束，orderMultiple 为 0 时不限）
- 若设置了 `purchaseLimit`，数量 ≤ `purchaseLimit`

> 若商品 `shelfStatus != 1`（未上架），告知用户该商品不可购买。商品行数不超过 100 行。

---

### 第四步：获取配送方式，并按需查询收货地址

**4a. 获取配送方式**
> [getPermittedDeliveryMethod](../../../site-assistant/references/订单/配送方式.md)
> **调用参数**：
```json
{
  "hierarchyCode": "<customer|store|branch>",
  "buyerId": <buyerId>
}
```

默认选取规则（按优先级）：
1. 优先选 `latestDeliveryWay: true` 且 `enabled: true` 的项
2. 若无，取第一条 `enabled: true` 的项

记录 `id`（deliveryMethodId）、`name`（配送方式名）、`deliveryWay`。

**4b. 若 `deliveryWay == "DELIVERY"`（送货上门），需查询收货地址**
> [listDeliveryAddresses](../../../site-assistant/references/组织/收货地址.md)
> **调用参数**：
```json
{"orgId": <buyerId>}
```
默认取第一条收货地址，记录：
- `id`（addressId）
- `name`（contactName）
- `phoneNum`（contactPhone）
- `provinceId`、`cityId`、`districtId`、`details`（addressDetail）
- `longitude`（addressLongitude）、`latitude`（addressLatitude）

> 若 `deliveryWay == "PICK_UP"`（自提），无需收货地址，收货相关字段留空。

---

### 第五步：调用计价接口，获取整单价格

将前几步收集到的信息组装计价参数：

> [calculateOrderPrice](../../../site-assistant/references/订单/订单-计价.md)

从计价结果中提取：
- `productTotalAmount`：商品小计之和
- `discountAmount`：促销优惠金额
- `orderDiscountAmount`：整单优惠金额（传入 createToBOrder）
- `productDiscountAmount`：商品促销优惠（传入 createToBOrder）
- `couponAmount`：优惠券金额（默认传 0）
- `totalFreight`：系统计算的运费（将此值用于 createToBOrder.totalFreight）
- `orderTotalAmount` = productTotalAmount + totalFreight - orderDiscountAmount
- `productPriceList[]`：各商品行的 `salePrice`（折后单价）、`subtotal`（小计）、`discountRate`（折扣率）、`type`（商品类型）

> 若计价返回促销赠品（`type == 3`），需将赠品行也加入 createToBOrder.orderDetails。

---

### 第六步：汇总订单预览，向用户确认

将以上信息整理为订单摘要，**输出给用户确认**，格式如下：

```
## 订单预览

**往来单位**：{客户名称}
**发货仓库**：{仓库名称}
**业务员**：{业务员姓名}（可更换）
**配送方式**：{配送方式名}
**收货地址**：{省市区 + 详细地址}（如有）
**联系人**：{联系人} {电话}（如有）

**商品明细**：
| 商品名称 | 规格 | 单位 | 数量 | 单价 | 小计 | 折扣 | 促销说明 |
|---|---|---|---|---|---|---|---|
| {商品名} | {规格} | {单位} | {数量} | {单价} | {小计} | {折扣率} | {促销说明} |
...（赠品行标注"赠品"）

**费用汇总**：
- 商品合计：{productTotalAmount}
- 促销优惠：-{discountAmount}
- 运费：{totalFreight}
- 订单总额：{orderTotalAmount}

**备注**：{用户指定的备注，若无则空}

---
是否确认下单？如需调整（更换商品/数量/业务员/地址/备注等），请告知。
```

**等待用户回复后再继续。**

---

## 注意事项

- **往来单位类型默认为客户**，不主动询问类型除非用户明确说明
- **业务员默认取客户信息中的 `salesId`**，不额外询问，除非用户主动要求更换
- **仓库字段（warehouseId）默认传-1**，不额外询问，除非用户主动要求更换
- **配送方式按优先规则自动选取**，若用户有明确要求再替换
- **收货地址仅在配送方式为 DELIVERY 时才需要查询**，自提时跳过
- **计价接口必须在下单前调用**，createToBOrder 的金额字段必须来自 calculateOrderPrice 的返回值，不可自行估算
- **促销赠品行**（`type == 3`）必须包含在 orderDetails 中，`activityId` 必填
- `orderTotalAmount` = `productTotalAmount` + `totalFreight` - `orderDiscountAmount`
- **运费字段**：calculateOrderPrice 返回的 `totalFreight` 即为系统计算的运费，若用户未指定运费则直接使用，若用户指定了自定义运费则传入用户指定值并设置 `customFreight: true`
- 商品行数最多 **100 行**，超出需告知用户
- 不支持发票（`orderInvoice` 不传）
- `orderStatus` 固定传 `"ORDER_AUDIT_PENDING"`（待审核）
- `orderSource` 固定传 `"WEB"`
- `orderDetails[].type`：必须是字符串枚举值，不是数字。普通订单:"NORMAL",赠品订单: "GIFT",样品订单: "SAMPLE"
- 订单详情展示时禁止出现枚举值和 id**，全部翻译为直白名称。

## ⚠️ 下单接口（createToBOrder）踩坑总结

### 1. countryId 必传，否则报"获取数据异常"
API 文档未将 countryId 标为 required，但实际调用时若缺少该字段，服务端会返回模糊的"获取数据异常"错误。送货上门时，countryId 传 `1`（中国）。

### 2. deliveryDate 格式为 yyyy-MM-dd HH:mm:ss
```
deliveryDate: "2026-04-25 00:00:00"
```
字段类型为 DATETIME，直接传日期字符串，不传时间戳数字。

### 3. 促销场景下 productTotalAmount 必须传 0
当客户存在可用促销活动（如满减优惠券），且促销可覆盖当前商品时，**计价接口返回的 productTotalAmount=0**（商品金额被促销全部抵扣）。此时下单时：
- `productTotalAmount` 必须传 `0`（不是商品原价小计！）
- `productDiscountAmount` 传促销优惠金额（如 `1`）
- `orderDiscountAmount` 传整单优惠金额（如 `1`）
- `totalFreight` 传计价返回的运费（如 `5`）
- `orderTotalAmount` = `0 + totalFreight - orderDiscountAmount`（如 `4`）
- 对应商品行的 `salePrice` 和 `subtotal` 也必须传 `0`

> ⚠️ `ignorePromotion: true` 字段无法绕过此校验，系统仍会强制要求 productTotalAmount=0。

### 4. 金额字段必须与系统期望值完全匹配
系统在校价和下单时会对多个金额字段做交叉校验，常见报错：
| 报错信息 | 原因 | 解决方案 |
|---|---|---|
| `订单小计之和productTotalAmount不正确（actual: 1.00 expect: 0.00）` | 商品有促销，productTotalAmount 应为 0 | 见上文第3条 |
| `订单优惠金额不正确（actual: 0.00 expect: 1.00）` | 优惠金额未正确传入 | productDiscountAmount + orderDiscountAmount 应等于总优惠 |
| `订单总金额不正确（actual: 6.00 expect: 4.00）` | orderTotalAmount 计算公式不对 | 用 `productTotalAmount + totalFreight - orderDiscountAmount` 重算 |
| `获取数据异常` | 缺少 countryId 或其他必填字段 | 检查 countryId 是否传了 `1` |

### 6. 常见报错速查（2026-04-13 新增）
| 报错信息 | 原因 | 解决方案                                                               |
|---|---|--------------------------------------------------------------------|
| `productTotalAmount不正确（actual: 13.00 expect: 0.00）` | 缺少关键字段或 warehouseId 传错 | 检查未指定发货参数时 warehouseId 默认传-1，irObjects、invoiceType、useAppApi 等是否传入 |
| `订单优惠金额不正确（actual: 0.00 expect: 13.00）` | 优惠金额未正确传入 | productDiscountAmount + orderDiscountAmount 应等于促销优惠金额              |
| `获取数据异常` | countryId 缺失或其他必填字段缺失 | 确保 countryId=1 传入                                                  |
