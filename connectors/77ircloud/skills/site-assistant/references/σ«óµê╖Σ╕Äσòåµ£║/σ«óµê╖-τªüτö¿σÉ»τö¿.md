## batchDisableEnableCustomer - 批量禁用/启用客户

### 接口描述
批量禁用或启用指定客户。接口为异步任务，返回任务信息后需通过 `exportTaskProgress` 轮询获取最终执行结果。

### 请求参数

#### Body参数

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| ids | NUMBER | 是 | 是 | 客户ID列表 |
| status | NUMBER | 是 | 否 | 状态：1-启用，0-禁用 |

### 响应数据

- 返回类型：`OBJECT`

| 字段 | 类型 | 说明 |
|------|------|------|
| key | STRING | 任务标识 |
| name | STRING | 任务名称 |
| type | NUMBER | 任务类型（1:导出 2:导入） |
| status | NUMBER | 任务状态（0:已加入 1:等待执行 2:执行中 3:成功 4:失败） |
| progress | NUMBER | 进度（执行中时有效，0-100） |
| read | NUMBER | 已读状态（0:未下载 1:已下载 2:过期） |

### 异步任务结果获取

该接口为异步操作，调用后返回任务标识 `key`，需通过 **`exportTaskProgress`** 接口轮询获取最终执行结果。详细轮询方式见 `../导出/导出任务查询.md`。

**轮询建议**：
- 间隔 2-5 秒查询一次
- status = 0/1/2：任务尚未完成，继续轮询
- status = 3：任务成功完成
- status = 4：任务失败，查看 `result.message` 了解失败原因
- 建议超时时间 30 秒，超时后告知用户稍后通过任务 key 查询

### 使用场景
当需要批量禁用或启用客户时使用。典型场景：运营人员发现异常客户需要暂时禁用其下单权限，或恢复之前被禁用的客户。

### 调用示例

**场景**：禁用客户ID为 123 和 456 的两个客户
```bash
ircloud-cli batchDisableEnableCustomer '{"ids":[123,456],"status":0}'
```

**场景**：启用客户ID为 789 的客户
```bash
ircloud-cli batchDisableEnableCustomer '{"ids":[789],"status":1}'
```

### 注意事项
1. **异步操作**：接口返回仅为任务提交结果，不代表操作已完成，必须通过 `exportTaskProgress` 轮询确认最终结果
2. **客户确认**：执行前需先通过 `customerList` 搜索确认客户身份，避免误操作
3. **用户授权**：涉及客户状态变更，必须在用户明确确认后方可执行
4. **批量限制**：单次操作的客户数量建议控制在合理范围内
5. **任务时效**：任务结果可能存在有效期，建议及时查询
