# 新建客户

本文档覆盖新增客户接口（`createCustomer`），包含完整参数说明与前置数据获取指引。

## 接口目录
- [checkOrganizationName](#checkorganizationname) - 检查客户名称是否已被使用
- [createCustomer](#createcustomer) - 新建客户

---

## checkOrganizationName

**功能**：新建客户前，通过名称检查是否已存在同名客户。返回非空表示名称已被占用，返回空（null）表示名称可用。

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| name | STRING | 是 | 否 | 待检查的客户名称 |
| hierarchyCode | STRING | 是 | 否 | 组织层级，检查客户时固定传 `CUSTOMER` |

**响应数据**
- 返回类型：`OBJECT`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 组织ID |
| name | STRING | 组织名称 |
| code | STRING | 组织编码 |
| hierarchyCode | STRING | 层级编码 |
| status | NUMBER | 状态（1=启用，0=禁用） |
| parentId | NUMBER | 所属机构ID |
| parentName | STRING | 所属机构名称 |
| salesId | NUMBER | 业务员ID |
| salesName | STRING | 业务员名称 |

- 返回**非空对象**：名称已被占用
- 返回 **null**：名称未被占用，可以使用

---

## createCustomer

**功能**：新建一个客户组织，支持同步设置基础信息、联系人、收货地址、定价方式、商品授权方案、账期/资金配置及订货账号。

**典型场景**
- 手工建档新客户
- 商机审核通过后开通客户账号（需传 `customerRegisterAuditId`）
- 批量导入客户数据

---

## 典型调用参数示例

**最简建客户（仅必填项）：**
```json
{
  "name": "新客户名称",
  "salesId": 123,
  "productAuthorization": {"authorizationId": 456},
  "priceModeInfo": {"pricingMode": 3, "priceLevelId": 789},
  "parentId": 1,
  "status": 1
}
```

**新建客户并开通客户账号：**
```json
{
  "name": "客户名称",
  "salesId": 123,
  "customerRegisterAuditId": 999,
  "productAuthorization": {"authorizationId": 456},
  "priceModeInfo": {"pricingMode": 3, "priceLevelId": 789},
  "parentId": 1,
  "status": 1,
  "accountInfo": {"userName": "张三", "password": "密码", "phone": "13800138000", "sendSmsMessage": false, "status": 1}
}
```

## ⚠️ 地址字段注意事项（重要）

### 联系地址 ≠ 收货地址

创建客户时，系统中有**两套地址**，不可混淆：

| 地址类型 | 使用字段 | 所属分组 | 用途 |
|---------|---------|---------|------|
| **联系地址** | `provinceId` / `cityId` / `districtId` / `details` | **基础信息（参数一）** | 客户的公司地址、注册地址、办公地址 |
| **收货地址** | `deliveryAddresses` 数组 | **参数四** | 每次发货配送的收货地址，可设多个 |

**典型错误**：
- ❌ 将联系地址填入 `deliveryAddresses` 数组
- ❌ 认为 `details` 是收货地址

**正确做法**：
- 用户说"联系地址/公司地址/办公地址" → 用 `provinceId` / `cityId` / `districtId` / `details`
- 用户说"收货地址/发货地址/送货地址" → 用 `deliveryAddresses` 数组
- 如果只提供一个地址且未说明用途，优先视为联系地址

### 快速判断口诀
> **联系地址用 details，收货地址用 deliveryAddresses**
