# 现金账户充值

本文档覆盖现金账户相关的三个接口：卖家支付方式列表查询、现金账户配置列表查询、现金账户充值执行。前两个查询接口均支持独立查询；其返回的 `buyerPayModeCode`、`typeId` 等字段可作为充值接口 `cashAccountIncreaseAmount` 的参数来源；如需同时返利到返利账户，`rebateFundAccounts.accountTypeId` 来源于 `findRebateAccountDefinitionPage.typeId`。

## 接口目录

- [searchPayModeList](#searchpaymodelist) - 卖家支付方式列表查询
- [findCashAccountDefinitionPage](#findcashaccountdefinitionpage) - 查询现金账户配置列表
- [cashAccountIncreaseAmount](#cashaccountincreaseamount) - 现金账户充值

---

## searchPayModeList

**功能**：查询当前机构可用的卖家支付方式列表，返回支付方式编码与名称。

**典型场景**
- 查询当前机构可用的支付方式列表及其启用状态
- 查询线上/线下支付方式及其启用状态

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| onlineFlag | BOOLEAN | 否 | 否 | 是否为线上（线上：true，线下：false，默认 false） |
| useCase | STRING | 否 | 否 | 应用场景：TOB_ORDER TOB订单交易 / TOC_ORDER TOC订单交易 / FINANCIAL_SETTLEMENT 财务结算（默认 TOB_ORDER） |
| systemDefault | BOOLEAN | 否 | 否 | 是否是系统默认 |
| currentQueryOrgId | NUMBER | 否 | 否 | 当前查询对象orgId |

> 接口调用时一般不传额外参数，调用方内部固定使用以下默认值：
> - `onlineFlag`：`false`（只查线下）
> - `useCase`：`TOB_ORDER`（只查 TOB 订单交易场景）
> - `useTerminal`：`WEB`（只查 WEB 终端）

**响应数据**
- 返回类型：`ARRAY`（数组）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 支付方式ID |
| buyerPayModeCode | STRING | 买家支付方式code |
| buyerPayModeName | STRING | 买家支付方式名称 |
| onlineFlag | BOOLEAN | 是否为线上（线上：true，线下：false） |
| status | STRING | 启用状态（正常：ENABLE，禁用：DISABLE） |
| customDescription | STRING | 自定义描述 |
| promotionInfo | STRING | 营销活动信息 |

## findCashAccountDefinitionPage

**功能**：查询现金账户配置列表，返回当前机构已启用的现金账户配置及对应 `typeId`。

**典型场景**
- 查询当前机构启用的现金账户配置
- 查询现金账户的启用状态、能否充值、能否为负、能否支付订单等属性

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| name | STRING | 否 | 否 | 账号名称 |
| enable | BOOLEAN | 否 | 否 | 是否启用（默认 true） |

> 接口调用时一般不传额外参数，调用方内部固定使用以下默认值：
> - `enable`：`true`（只查已启用）

**响应数据**
- 返回类型：`PAGE`（分页）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 账号ID |
| orgId | NUMBER | 机构ID |
| tenantId | NUMBER | 租户ID |
| chainId | NUMBER | 链路链ID |
| name | STRING | 账号名称 |
| accountType | STRING | 账号类型（CASH_ACCOUNT 现金账户） |
| code | STRING | 账户编码，目前使用 typeId 填充 |
| typeId | NUMBER | 账户编码（type_id 实际值） |
| enable | BOOLEAN | 是否启用 |
| canPayOrder | BOOLEAN | 能否支付订单 |
| canRecharge | BOOLEAN | 能否充值 |
| enableNegative | BOOLEAN | 能否为负 |
| description | STRING | 账号说明 |
| canDownRecharge | BOOLEAN | 下游自主充值 |
| canPayPreOrder | BOOLEAN | 能否支付预售订单 |

## cashAccountIncreaseAmount

**功能**：为指定往来单位的现金账户充值，生成一笔收款单。需配合 `searchPayModeList` 获取 `payMode`、`findCashAccountDefinitionPage` 获取 `accountTypeId`，并通过组织机构查询获取 `otherOrgId`。如需将预收款同时返利到返利账户，可传 `rebateFundAccounts`。

**典型场景**
- 为客户现金账户充值（如预收充值、人工调整余额）
- 为门店、分公司现金账户充值
- 充值的同时返利到客户的返利账户（`rebateFundAccounts`）

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| payMode | STRING | 是 | 否 | 支付方式（来源：`searchPayModeList` 返回的 `buyerPayModeCode`） |
| otherOrgId | NUMBER | 是 | 否 | 往来单位机构id（来源：`searchDirectUnder` 返回的 `id`） |
| tradeTime | DATETIME | 是 | 否 | 交易时间 |
| otherOrgType | STRING | 是 | 否 | 交易对手机构类型（默认 `CUSTOMER`，与 `searchDirectUnder` 的 `hierarchyCodes` 同源：`BRANCH` 分公司 / `STORE` 门店 / `CUSTOMER` 客户） |
| exemptAmount | NUMBER | 否 | 否 | 优惠金额（未传时按 0 计算） |
| realTradeAmount | NUMBER | 是 | 否 | 实收金额 |
| tradeMoney | NUMBER | 是 | 否 | 交易金额，**必须按 `exemptAmount + realTradeAmount` 计算后传入**（无优惠时 = realTradeAmount） |
| accountTypeId | NUMBER | 是 | 否 | 账号类型id（来源：`findCashAccountDefinitionPage` 返回的 `typeId`。取值：默认账户(1)、现金账户(10-29)、返利账户(30-49)） |
| rebateFundAccounts | OBJECT | 否 | 是 | 预收款充值返利到返利账户明细（可空） |
| rebateFundAccounts[].accountTypeId | NUMBER | 否 | 否 | 资金账户类型id（来源：`findRebateAccountDefinitionPage` 返回的 `typeId`） |
| rebateFundAccounts[].money | NUMBER | 否 | 否 | 返利金额 |
| remark | STRING | 否 | 否 | 备注 |

> **必填字段**：`otherOrgId`、`otherOrgType`、`payMode`、`tradeTime`、`realTradeAmount`、`tradeMoney`。
> **金额公式**：`tradeMoney = exemptAmount + realTradeAmount`。无优惠时 `exemptAmount` 不传（按 0 处理），`tradeMoney = realTradeAmount`。

**响应数据**
- 返回类型：`OBJECT`（单对象）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 收付款单ID |
| receiptCode | STRING | 收款单号 |
| money | NUMBER | 收付款金额 |
| payTime | DATETIME | 收付款时间 |
| paymentMethodCode | STRING | 收付款方式（1：微信，2：支付宝，3：现金，4：银行转账） |
| paymentChannel | STRING | 收款渠道（ONLINE 线上，OFFLINE 线下） |
| paymentMethodName | STRING | 收付款名称 |
| remark | STRING | 备注信息 |
| createName | STRING | 制单人 |
| createTime | DATETIME | 制单时间 |
| status | STRING | 状态（UN_CONFIRM 待审核、CONFIRMED 已审核、CANCEL 已作废） |
| fundSummaryId | NUMBER | 摘要id |
| fundSummaryDesc | STRING | 摘要描述 |
| tradeType | STRING | 交易类型（PAY 付款、REFUND 退款） |
| subjectAccountId | NUMBER | 交易主体账户卡id |
| subjectAccountNum | STRING | 交易主体账户卡号 |
| subjectAccountName | STRING | 交易主体账户名称 |
| exemptAmount | NUMBER | 优惠金额 |
| realTradeAmount | NUMBER | 实收/实付金额 |
| merchantName | STRING | 商户名称 |
| otherOrgId | NUMBER | 交易对手id |
| otherOrgType | STRING | 交易对手结构类型 |
| orgType | STRING | 当前机构类型 |
| otherOrgCode | STRING | 交易对手机构编码 |
| otherOrgName | STRING | 交易对手机构名称 |
| otherDownFlag | BOOLEAN | 与当前结构的关系（false：上游，true：下游） |

## 跨接口组合示例

**场景一**：为某客户现金账户充值 100 元（充值到现金账户，不返利）

1. `searchPayModeList` → 不传参（默认 `onlineFlag=false`、`useCase=TOB_ORDER`），从返回结果中取启用支付方式的 `buyerPayModeCode` 作为 `payMode`
2. `findCashAccountDefinitionPage` → 不传参（内部固定`enable=true`），从返回结果中取启用现金账户的 `typeId` 作为 `accountTypeId`
3. `searchDirectUnder`（参考：[组织/组织.md](../组织/组织.md)）→ `hierarchyCodes=["CUSTOMER"]` 配合关键词查询客户，从返回结果中取客户的 `id` 作为 `otherOrgId`，并取其 `hierarchyCode` 作为 `otherOrgType`（默认 `CUSTOMER`）
4. `cashAccountIncreaseAmount` → 传入 `payMode`、`otherOrgId`、`otherOrgType="CUSTOMER"`、`exemptAmount=0`、`realTradeAmount=100`、`tradeMoney=100`（= exemptAmount + realTradeAmount）、`accountTypeId`，执行充值

**场景二**：为某客户现金账户充值 100 元，其中 10 元返利到其返利账户

1. `searchPayModeList` → 同场景一第 1 步，取 `buyerPayModeCode` 作为 `payMode`
2. `findCashAccountDefinitionPage` → 同场景一第 2 步，取启用现金账户的 `typeId` 作为 `accountTypeId`
3. `findRebateAccountDefinitionPage`（参考：[返利账户充值.md](返利账户充值.md)）→ 不传参（内部固定 `accountType=REBATE_ACCOUNT`、`enable=true`、`closePage=true`），从返回结果中取启用返利账户的 `typeId` 作为 `rebateFundAccounts[].accountTypeId`
4. `searchDirectUnder`（参考：[组织/组织.md](../组织/组织.md)）→ `hierarchyCodes=["CUSTOMER"]` 查询客户，取客户 `id` 作为 `otherOrgId`
5. `cashAccountIncreaseAmount` → 传入 `payMode`、`otherOrgId`、`otherOrgType="CUSTOMER"`、`exemptAmount=0`、`realTradeAmount=100`、`tradeMoney=100`、`accountTypeId`、`rebateFundAccounts=[{"accountTypeId": <返利账户typeId>, "money": 10}]`，执行充值

> **默认值说明**：
> - `cashAccountIncreaseAmount` 接口的 `otherOrgType` 在大部分场景下为 `CUSTOMER`，调用方可以默认传 `CUSTOMER`，无需再额外调用接口反查。当充值对象为门店或分公司时，对应调用 `searchDirectUnder` 时将 `hierarchyCodes` 改为 `["STORE"]` 或 `["BRANCH"]`，并把 `otherOrgType` 设为 `STORE` / `BRANCH`。
> - `tradeMoney` 必须满足 `tradeMoney = exemptAmount + realTradeAmount`，禁止直接传任意值。
> - 当同时返利到返利账户时，`rebateFundAccounts[].money` 之和需要与「充值金额中应返利部分」一致，具体返利到哪个返利账户（`accountTypeId`）取决于 `findRebateAccountDefinitionPage` 返回的启用返利账户的 `typeId`。
