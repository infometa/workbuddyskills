# 执行规则与输出格式

## 一、数据查询规范

### DATETIME 类型参数
- DATETIME 类型的参数直接传时间字符串，格式为 `yyyy-MM-dd HH:mm:ss`
- 示例：`"2024-01-01 00:00:00"`

### TIME_RANGE 类型参数
- TIME_RANGE 类型的参数需要传递一个包含 `startTime` 和 `endTime`（DATETIME 类型）的对象，格式为：
  ```json
  {"paramName": {"startTime": "2024-01-01 00:00:00", "endTime": "2024-01-31 23:59:59"}}
  ```

### SORT 类型参数
- SORT 类型的参数传递格式为 `"排序字段值:排序方向"`，方向取值 `asc` 或 `desc`
- 排序字段值必须使用 `enums` 中对应枚举定义的**实际值**
- 示例：`{"sort": "soleMoney:desc"}`

### 分页参数（返回类型：`PAGE`）
- 需要翻页时传 `currentPage` 和 `pageSize` 参数

### 枚举参数
- 所有枚举参数必须使用 `enums` 定义的**实际值（value）**，不得使用中文 key

### 金额与价格字段单位
- CLI 接口返回的所有**金额**和**价格**字段，单位均为**元**
- 示例：`amount: 100.50` 表示 100.50 元，`price: 29.90` 表示 29.90 元

## 二、输出展示规范

### 日志输出规范

### 预览
- 默认仅展示查询结果的前 **3 条**作为预览
- 枚举必须使用转为中文展示

### ircloud-cli说明

### 通用输出规则
**stderr/stdout 分离原则**：
- **stdout**：仅输出业务数据（JSON/JSONL），可供脚本直接解析
- **stderr**：输出所有进度、提示、错误等日志信息
- 所有日志统一使用 `[ircloud-cli]`，编写脚本时识别和过滤该行
- 日志示例：
  ```
  [ircloud-cli] 已获取19000/20174
  ```

### 参数
```bash
--out-path # 保存数据到指定的jsonl(Newline-delimited JSON)中，后缀.jsonl。 PAGE时需同 page-all 合并使用
--page-all # `PAGE`限定，自动翻阅所有页面, 耗时长timeout=3600s
```
- ⚠️ **禁止**自行编写循环脚本逐页拉取——使用 `--page-all ` 是最可靠的方式

### 输出

输出到 stdout 的格式取决于返回数据量：

**数据量 ≤ 10 行**：直接输出 JSON 对象或数组

PAGE 类型接口：
```json
{
  "totalCount": 1,
  "currentPage": 1,
  "pageSize": 100,
  "totalPage": 1,
  "items": [...]
}
```

ARRAY 类型接口：
```json
[{...}, {...}]
```

**数据量 > 10 行**：输出 JSON 字符串，数据自动写入 JSONL 文件（每行一个 JSON 对象）。按触发路径分为三种：

PAGE 类型（非全量查询）：
```
"本页输出过大 (总行数: 325, 当前页: 1, 本页行数: 100). 当前页输出已保存至: /path/to/file.jsonl\n\n预览 (前 3 行):\n{\"id\":1,\"name\":\"张三\"}\n{\"id\":2,\"name\":\"李四\"}\n{\"id\":3,\"name\":\"王五\"}\n..."
```

ARRAY 类型
```
"输出过大 (150 行). 完整输出已保存至: /path/to/file.jsonl\n\n预览 (前 3 行):\n{\"id\":1,\"name\":\"张三\"}\n{\"id\":2,\"name\":\"李四\"}\n{\"id\":3,\"name\":\"王五\"}\n..."
```

`--page-all` 全量查询：
```
"全量查询完成 (325 行). 完整输出已保存至: /path/to/file.jsonl\n\n预览 (前 3 行):\n{\"id\":1,\"name\":\"张三\"}\n{\"id\":2,\"name\":\"李四\"}\n{\"id\":3,\"name\":\"王五\"}\n..."
```

## 三、业务合规规范

以下规则不可违反：

### 预警类输出
- **必须先输出**数据来源声明（如「以下数据来源于客户预警」），再展示结果
- 对用户**不得**暴露 `module`、编码、括号说明等技术细节
- 无预警数据时，**不得**改用统计/报表接口拼装数据（见「应答与数据溯源」）
