# 拜访计划-普通业务操作

本文档覆盖普通拜访计划的创建、修改、作废接口。

## 接口目录
- [createVisitPlan](#createvisitplan) - 创建普通拜访计划
- [updateVisitPlan](#updatevisitplan) - 修改拜访计划
- [discardVisitPlan](#discardvisitplan) - 作废拜访计划

---

## createVisitPlan

**功能**：创建普通拜访计划，返回计划ID。创建时关联客户（或按线路自动带出客户）/商机，并指定业务员和计划时间。

**典型场景**
- 为业务员创建一段时间的客户拜访计划
- 选择一条拜访线路，自动带出线路客户生成拜访计划
- 创建商机拜访计划（传入 businessIds）

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| name | STRING | 是 | 否 | 计划名称 |
| type | NUMBER | 否 | 否 | 计划类型，0=常规计划，1=周期计划，2=预警计划，默认0 |
| summary | STRING | 否 | 否 | 计划内容 |
| startTime | DATETIME | 是 | 否 | 计划开始时间 |
| endTime | DATETIME | 是 | 否 | 计划结束时间 |
| salesId | NUMBER | 否 | 否 | 关联业务员ID |
| customerIds | NUMBER | 否 | 是 | 关联客户ID集合，与商机、线路至少传一个，总数不超过1000 |
| businessIds | NUMBER | 否 | 是 | 关联商机ID集合（商机拜访时传入） |
| routeId | NUMBER | 否 | 否 | 拜访线路ID，传线路ID时按线路自动带出客户 |

**注意**
- `customerIds`、`businessIds`、`routeId` 三者至少传一个；客户数量与商机数量之和不能超过1000
- 传 `routeId` 时可不传 `customerIds`，系统按线路自动带出客户

**响应数据**
- 返回类型：`NUMBER`（新建计划ID）

---

## updateVisitPlan

**功能**：根据ID修改拜访计划。修改后计划状态会根据计划明细的拜访状态自动重新计算（见注意）。

**典型场景**
- 调整计划名称、内容、起止时间
- 增删计划的关联客户/商机
- 更换计划所属业务员

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 计划ID |
| name | STRING | 否 | 否 | 计划名称 |
| type | NUMBER | 是 | 否 | 计划类型(不支持修改，修改时原值传入)，0=常规计划，1=周期计划，2=预警计划 |
| status | NUMBER | 否 | 否 | 计划状态，0=未开始，1=进行中，2=已结束，3=已延期，4=已作废 |
| summary | STRING | 否 | 否 | 计划内容 |
| startTime | DATETIME | 是 | 否 | 计划开始时间 |
| endTime | DATETIME | 是 | 否 | 计划结束时间 |
| salesId | NUMBER | 否 | 否 | 关联业务员ID |
| customerIds | NUMBER | 否 | 是 | 关联客户ID集合 |
| businessIds | NUMBER | 否 | 是 | 关联商机ID集合 |
| routeId | NUMBER | 否 | 否 | 线路ID（传线路ID时按线路自动带出客户） |

**响应数据**
- 返回类型：`NUMBER`（修改结果）

---

## discardVisitPlan

**功能**：根据ID作废拜访计划，作废后计划状态置为「已作废」。

**典型场景**
- 计划不再执行时作废
- 误建的计划作废

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 计划ID |
| discardReason | STRING | 否 | 否 | 作废原因 |

**响应数据**
- 返回类型：`NUMBER`（作废结果）

## 跨接口组合示例

**场景1**：为业务员创建客户拜访计划
1. `employeeList` → 获取业务员ID（见员工部门/员工.md）
2. `customerList` → 获取客户ID集合（见客户与商机/客户.md）
3. `createVisitPlan` → 传入 salesId + customerIds + startTime + endTime，创建计划
4. `visitPlanDetail` → 查看计划详情及计划数量

**场景2**：按拜访线路创建计划
1. `crmRouteSearchList` → 查询拜访线路，获取线路ID（见拜访/拜访线路.md）
2. `createVisitPlan` → 传入 routeId + salesId + startTime + endTime，系统自动按线路带出客户
4. `visitPlanDetail` → 查看计划详情及计划数量

**场景3**：查看计划执行情况并作废
1. `visitPlanSearchList` → 按状态筛选计划
2. `visitPlanDetail` → 查看已拜访数量/计划数量
3. `discardVisitPlan` → 不再执行的计划作废，传入作废原因
