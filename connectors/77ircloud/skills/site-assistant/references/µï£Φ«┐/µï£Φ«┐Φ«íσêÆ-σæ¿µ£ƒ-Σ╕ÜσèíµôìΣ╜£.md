# 拜访计划-周期业务操作

本文档覆盖周期拜访计划任务（按周循环的拜访计划）的创建、修改、作废接口。周期计划按固定星期（如每周一、三、五）循环生成拜访计划。

## 接口目录
- [createVisitPlanCycleJob](#createvisitplancyclejob) - 创建周期计划任务
- [updateVisitPlanCycleJob](#updatevisitplancyclejob) - 修改周期计划任务
- [discardVisitPlanCycleJob](#discardvisitplancyclejob) - 作废周期计划任务

---

## createVisitPlanCycleJob

**功能**：创建周期计划任务，返回任务ID。周期任务支持按线路（type=0）或按客户（type=1）关联，并指定每周循环拜访的星期。

**典型场景**
- 为业务员创建每周固定日期的客户拜访计划（如每周一、三、五拜访指定客户）
- 按拜访线路创建周期拜访任务（选择线路，每周固定日期按线路拜访）

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| name | STRING | 否 | 否 | 计划名称，不传根据类型自动生成 |
| type | NUMBER | 是 | 否 | 关联类型，0=关联线路，1=关联客户/商机 |
| status | NUMBER | 否 | 否 | 计划状态，0=未开始，1=进行中，2=已结束，3=已延期，4=已作废 |
| summary | STRING | 否 | 否 | 计划内容 |
| startTime | DATETIME | 是 | 否 | 计划开始时间 |
| endTime | DATETIME | 是 | 否 | 计划结束时间 |
| salesId | NUMBER | 否 | 否 | 关联业务员ID |
| routeId | NUMBER | 否 | 否 | 路线ID，type=0（关联线路）时必填 |
| customerIds | NUMBER | 否 | 是 | 关联客户ID集合，type=1（关联客户/商机）时，必须传入 customerIds、businessIds中的一个 |
| businessIds | NUMBER | 否 | 是 | 关联商机ID集合，type=1（关联客户/商机）时，必须传入 customerIds、businessIds中的一个 |
| cycleInfo | OBJECT | 是 | 否 | 周期信息，每周固定拜访的星期 |
| cycleInfo.week | STRING | 否 | 是 | 周期星期集合，MON/TUE/WED/THU/FRI/SAT/SUN |

**响应数据**
- 返回类型：`NUMBER`（新建周期计划任务ID）

## updateVisitPlanCycleJob

**功能**：根据ID修改周期计划任务。

**典型场景**
- 调整周期拜访的星期（每周几拜访）
- 更换关联线路或客户
- 调整计划起止时间

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明                                                         |
|------|------|------|------|------------------------------------------------------------|
| id | NUMBER | 是 | 否 | 周期计划任务ID                                                   |
| name | STRING | 否 | 否 | 计划名称                                                       |
| type | NUMBER | 是 | 否 | 关联类型(不支持修改，修改时原值传入)，0=关联线路，1=关联客户/商机                       |
| status | NUMBER | 否 | 否 | 计划状态，0=未开始，1=进行中，2=已结束，3=已延期，4=已作废                         |
| summary | STRING | 否 | 否 | 计划内容                                                       |
| startTime | DATETIME | 是 | 否 | 计划开始时间                                                     |
| endTime | DATETIME | 是 | 否 | 计划结束时间                                                     |
| salesId | NUMBER | 否 | 否 | 关联业务员ID                                                    |
| routeId | NUMBER | 否 | 否 | 路线ID，type=0（关联线路）时必填                                       |
| customerIds | NUMBER | 否 | 是 | 关联客户ID集合，type=1（关联客户/商机）时，必须传入 customerIds、businessIds中的一个 |
| businessIds | NUMBER | 否 | 是 | 关联商机ID集合，type=1（关联客户/商机）时，必须传入 customerIds、businessIds中的一个 |
| cycleInfo | OBJECT | 是 | 否 | 周期信息，每周固定拜访的星期                                           |
| cycleInfo.week | STRING | 否 | 是 | 周期星期集合，MON/TUE/WED/THU/FRI/SAT/SUN                         |

**响应数据**
- 返回类型：`NUMBER`（修改结果）

## discardVisitPlanCycleJob

**功能**：根据ID作废周期计划任务，作废后任务状态置为「已作废」，不再按星期循环生成计划。

**典型场景**
- 周期拜访任务不再执行时作废
- 误建的周期任务作废

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 周期计划任务ID |
| discardReason | STRING | 否 | 否 | 作废原因 |

**响应数据**
- 返回类型：`NUMBER`（作废结果）

## 跨接口组合示例

**场景1**：按线路创建周期拜访任务
1. `crmRouteSearchList` → 查询拜访线路，获取线路ID（见拜访/拜访线路.md）
2. `createVisitPlanCycleJob` → 传入 type=0 + routeId + cycleInfo.week（如 ["MON","WED","FRI"]）+ startTime/endTime
3. `visitPlanCycleJobSearchList` → 查询周期任务列表，确认创建成功

**场景2**：按客户创建周期拜访任务
1. `customerList` → 获取客户ID集合（见客户与商机/客户.md）
2. `createVisitPlanCycleJob` → 传入 type=1 + customerIds + cycleInfo.week + startTime/endTime
3. `visitPlanCycleJobDetail` → 查看周期任务配置及生成的计划

**场景3**：调整并作废周期任务
1. `visitPlanCycleJobSearchList` → 查询周期任务列表，获取任务ID
2. `updateVisitPlanCycleJob` → 调整 cycleInfo.week（如改为每周二、四）
3. `discardVisitPlanCycleJob` → 不再执行的周期任务作废，传入作废原因
