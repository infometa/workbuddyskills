# 签收指定ID的签收单

本文档覆盖签收单签收接口，用于完成订单签收操作。

## 接口目录
- [updateReceivingBill](#updatereceivingbill) - 签收指定ID的签收单（支持整单/部分/差异签收）

## updateReceivingBill

**功能**：指定ID签收一个签收单。

**典型场景**
- **整单签收**：不传 `contents` 参数，系统自动按发货数量全部签收
- **部分签收**：传 `contents` 明细，按指定数量签收
- **差异单签收**：传差异原因和附件，记录签收差异（如少发货、破损等）

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 签收单ID（路径参数） |
| contents | ARRAY | 否 | 是 | 签收内容明细，为空或null时做整单签收 |
| contents[].id | NUMBER | 是 | 否 | 签收单据内容ID（明细行ID） |
| contents[].count | NUMBER | 是 | 否 | 签收数量（直接传数字，如1） |
| contents[].auxCount | NUMBER | 否 | 否 | 辅助单位签收数量（直接传数字，如0） |
| contents[].remark | STRING | 否 | 否 | 备注 |
| contents[].costPrice | NUMBER | 否 | 否 | 成本价 |
| contents[].differenceReason | STRING | 否 | 否 | 差异原因（签收有差异时必填） |
| contents[].differenceType | NUMBER | 否 | 否 | 差异类型：1=少发货，2=破损 |
| contents[].batches | ARRAY | 否 | 是 | 商品批次信息（签收单对应的源出库单的批次信息） |
| contents[].batches[].batchNum | STRING | 否 | 否 | 批次号 |
| contents[].batches[].productionDate | DATETIME | 是 | 否 | 生产日期 |
| contents[].batches[].expirationDate | DATETIME | 否 | 否 | 过期日期 |
| contents[].batches[].count | NUMBER | 是 | 否 | 批次库存数量（直接传数字，按下单单位） |
| contents[].batches[].orderDetailId | NUMBER | 否 | 否 | 订单详情ID |
| contents[].batches[].auxUnitId | NUMBER | 否 | 否 | 辅助单位ID |
| contents[].batches[].auxUnitName | STRING | 否 | 否 | 辅助单位名称 |
| contents[].batches[].auxCount | NUMBER | 否 | 否 | 辅助单位数量 |
| contents[].batches[].originOutSkuBatchId | NUMBER | 否 | 否 | 退单原出库单的出库批次ID，退单场景必传 |
| contents[].skuId | NUMBER | 否 | 否 | 商品SKU ID |
| contents[].orderDetailId | NUMBER | 否 | 否 | 单据详情ID |
| remark | STRING | 否 | 否 | 签收备注 |
| warehouseId | NUMBER | 否 | 否 | 入库仓库ID |
| buyerDepartmentId | NUMBER | 否 | 否 | 购买方部门ID |
| differenceReason | STRING | 否 | 否 | 差异原因（签收有差异时必填） |

**响应数据**
- 返回类型：`VOID`（无返回）

签收成功无返回内容

## 使用场景参数示例

### 场景 1：整单签收（无差异）

用户确认收到的货物与发货完全一致，直接整单签收：

```json
{
  "id": 123456789,
  "warehouseId": 111222333,
  "remark": "货物完好，整单签收"
}
```

> **说明**：不传 `contents` 参数，系统自动按发货单数量全部签收。

### 场景 2：部分签收（有差异）

用户实际收到数量少于发货数量，需要记录差异：

```json
{
  "id": 123456789,
  "contents": [
    {
      "id": 987654321,
      "count": 8,
      "differenceType": 1,
      "differenceReason": "少发货2箱"
    },
    {
      "id": 987654322,
      "count": 5,
      "differenceType": 2,
      "differenceReason": "破损1箱"
    }
  ],
  "warehouseId": 111222333,
  "remark": "部分签收，有差异",
  "differenceReason": "少发货、破损"
}
```

### 场景 4：带批次信息的签收

签收时指定批次信息：

```json
{
  "id": 123456789,
  "contents": [
    {
      "id": 987654321,
      "count": 10,
      "batches": [
        {
          "batchNum": "B20260101001",
          "productionDate": "2026-01-01 00:00:00",
          "expirationDate": "2027-01-01 00:00:00",
          "count": 10
        }
      ]
    }
  ],
  "warehouseId": 111222333
}
```

## 注意事项

1. **整单签收 vs 部分签收**：
   - 不传 `contents` → 整单签收（按发货数量全部签收）
   - 传 `contents` → 部分签收（按指定数量签收）

2. **差异单处理**：
   - 当签收数量与发货数量不一致时，必须填写 `differenceReason`（差异原因）
   - 差异类型 `differenceType`：`1`=少发货，`2`=破损

3. **批次信息**：
   - `contents[].batches` 用于记录商品批次信息（对应源出库单的批次）
   - 生产日期必填，过期日期可选

4. **入库仓库**：
   - `warehouseId` 指定货物入库的仓库
   - 如果未指定，系统可能使用默认仓库或从签收单中获取

5. **客户退单场景**：
   - 退单场景需要在 `batches` 中传 `originOutSkuBatchId`
