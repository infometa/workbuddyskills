# 订单批量财务审核

本文档覆盖订单批量财务审核接口，用于批量审核B2B订单的财务信息。

## 接口目录
- [batchFinanceAudit](#batchFinanceAudit) - 批量财务审核（同步返回审核失败的订单详情）

---

## batchFinanceAudit

**功能**：批量财务审核B2B订单，返回审核失败的订单详细信息（包括订单ID、订单号、买方信息、订单金额、失败原因等）。与订单审核接口类似，但专门用于财务审核环节。

**典型场景**
- 财务人员对多笔待财务审核的订单进行批量审核
- 审核订单的付款状态、资金信息
- 查看财务审核失败的订单及失败原因
- 订单审核通过且配置了跳过财务审核时自动触发

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| ids | NUMBER | 否 | 是 | 订单ID列表，按订单主键ID审核，优先使用 |

**响应数据**
- 返回类型：`ARRAY`（数组）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 订单ID |
| orderCode | STRING | 订单编码 |
| orderStatus | NUMBER | 订单状态 |
| buyerName | STRING | 买方机构名称 |
| buyerCode | STRING | 买方机构编码 |
| totalAmount | NUMBER | 订单总金额 |
| auditFailedReason | STRING | 审核失败原因（仅审核失败时存在） |

**注意**
- 返回的是**审核失败**的订单列表，空列表表示全部审核成功
- 财务审核通常在订单审核之后进行（除非配置了跳过财务审核）
- 财务审核会校验订单的付款状态、资金配置等业务规则
- 审核失败的订单会返回具体的失败原因，需根据原因处理后重新审核

## 跨接口组合示例

**场景**：查询待财务审核订单并批量审核
1. `customerOrderList` → 查询订单列表，筛选 `paymentStatus: [3]`（待确认）的订单
2. `batchFinanceAudit` → 传入待审核订单的 `ids`，批量财务审核
3. 检查返回结果，如有失败订单则查看 `auditFailedReason` 并处理

**场景**：订单审核后自动财务审核
1. `orderAudit` → 批量订单审核（见[订单-批量审核.md](订单-批量审核.md)）
2. 如果订单配置了"跳过财务审核"，则订单审核通过后自动完成财务审核
3. 如果未配置跳过，则需手动调用 `batchFinanceAudit` 进行财务审核

**场景**：查看财务审核失败原因并重新审核
1. `batchFinanceAudit` → 批量财务审核
2. 检查返回的失败订单列表，查看 `auditFailedReason`
3. 根据失败原因处理（如确认付款、调整资金配置等）
4. 重新调用 `batchFinanceAudit` 审核失败的订单
