# 成本调整单

成本调整单用于调整商品的库存成本价（**不改变库存数量**），调整逻辑**以调整金额为主**：对每个SKU录入调整金额，审核通过后 `新库存金额 = 旧库存金额 + 调整金额`，新价由调整后金额折算（`新价 = 新库存金额 ÷ 库存数量`）。单据状态流转：`待审核(0) → 已审核(1)`；仅待审核的单据可修改、删除。

成本按仓库核算的说明：库存设置 calculateCostByWarehouse（查询 [findInventorySettings](仓库.md)）=2 表示已完成分仓成本切换、按仓库计算成本，此时单据必须指定调整仓库（warehouseId）；其他值（0=未启用 1=切换中）按总仓成本调整，可不传仓库。

调整金额是核心入参（可为负，负数即调低成本）：直接传差额，或按目标新价换算 `调整金额 = 目标新价 × 库存数量 − 旧库存金额`。约束：**调整后的新库存金额（旧库存金额 + 调整金额）不允许为负**（即调整后成本价不为负）；调整金额不允许为0；结余库存数量小于0的商品不允许成本调整。

## 接口目录
- [searchCostAdjustmentBills](#searchcostadjustmentbills) - 成本调整单列表
- [costAdjustmentBillDetail](#costadjustmentbilldetail) - 成本调整单详情
- [createCostAdjustmentBill](#createcostadjustmentbill) - 新增成本调整单
- [updateCostAdjustmentBill](#updatecostadjustmentbill) - 修改成本调整单
- [approveCostAdjustmentBill](#approvecostadjustmentbill) - 审核成本调整单
- [deleteCostAdjustmentBill](#deletecostadjustmentbill) - 删除成本调整单

## searchCostAdjustmentBills

**功能**：分页查询成本调整单列表。

**典型场景**
- 按单号/制单人关键字搜索成本调整单
- 按单据状态（待审核/已审核）筛选
- 查看某段时间内的成本调整业务量

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|----|------|------|
| q | STRING | 否  | 否 | 搜索关键字（单号/制单人） |
| status | NUMBER | 否  | 否 | 单据状态，-1=作废 0=待审核 1=已审核 |
| createTime | TIME_RANGE | 是  | 否 | 创建时间范围 |

**响应数据**
- 返回类型：`PAGE`（分页）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 成本调整单ID |
| billNum | STRING | 单据号 |
| status | NUMBER | 单据状态（-1=作废 0=待审核 1=已审核） |
| warehouseId | NUMBER | 调整仓库ID |
| warehouseName | STRING | 调整仓库名称 |
| creatorId | NUMBER | 制单人ID |
| creator | STRING | 制单人名称 |
| approverId | NUMBER | 审核人ID |
| approverName | STRING | 审核人姓名 |
| approveTime | DATETIME | 审核时间 |
| createTime | DATETIME | 创建时间 |
| remark | STRING | 备注（取单据备注数组中最新一条） |
| totalAmount | NUMBER | 总调整金额（明细调整金额合计） |

**典型场景**

## createCostAdjustmentBill

**功能**：新增成本调整单，返回新建单据ID。创建时服务端自动填充商品当前成本价，并校验调整后结余成本金额不允许为负。

**典型场景**
- 修正采购价录错导致的库存成本偏差（按差额调增/调减）
- 将某商品库存成本一次性调整到目标金额

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| warehouseId | NUMBER | 否 | 否 | 调整仓库ID，calculateCostByWarehouse=2 时必传（见 findInventorySettings） |
| remark | STRING | 否 | 否 | 备注 |
| items | ARRAY | 是 | 是 | 成本调整明细列表（至少1条） |
| items[].skuId | NUMBER | 是 | 否 | SKU ID |
| items[].adjustAmount | NUMBER | 是 | 否 | 调整金额（核心入参，可为负）：新库存金额 = 旧库存金额 + 调整金额 |
| items[].remark | STRING | 否 | 否 | 明细备注（最长256字符） |

**注意**
- 数据计算折算等操作，请使用python + decimal模块进行高精度计算
- 必须查询 [findInventorySettings](仓库.md) 获取calculateCostByWarehouse设置
- calculateCostByWarehouse=2（已启用分仓成本运算）时 warehouseId 必传，否则报错；未启用时 warehouseId 可不传（按总仓成本调整）
- 调整仓库来源 [findOrderWarehouses](仓库.md)
- 商品与旧成本信息来源 [findStorageBillSelectSku](出入库单选商品.md)（启用分仓成本运算时传相同 warehouseId，查对应仓库库存与成本金额）：skuId => id、旧库存金额 => costAmount、库存数量 => amount、旧价 => costPrice
- **调整以 adjustAmount 为准**：`旧库存金额 + adjustAmount ≥ 0` 不成立即拒绝（调整后新库存金额/新价不允许为负）
- 新成本价时 adjustAmount 换算方式：按目标新价折算 `adjustAmount = 目标新价 × 库存数量 − 旧库存金额`；按目标金额调整时直接传差额。
- 调整金额不允许为0；结余库存数量小于0的商品不允许调整
- 套餐商品无须维护库存、已淘汰/已删除商品不允许调整
- 成本调整不改变库存数量，仅调整库存成本金额（新价随之折算）

**响应数据**
- 返回类型：`NUMBER`（新建单据ID）

## updateCostAdjustmentBill

**功能**：根据ID修改成本调整单（仅待审核状态可修改）。明细项传 `id` 表示更新原明细，不传 `id` 表示新增明细。

**典型场景**
- 修改备注、调整仓库
- 增删改单据的调整明细（改调整金额）

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 成本调整单ID |
| warehouseId | NUMBER | 否 | 否 | 调整仓库ID，calculateCostByWarehouse=2 时必传（见 findInventorySettings） |
| remark | STRING | 否 | 否 | 备注 |
| items | ARRAY | 是 | 是 | 成本调整明细列表（至少1条） |
| items[].id | NUMBER | 否 | 否 | 明细ID，传了id表示更新，没传表示新增 |
| items[].skuId | NUMBER | 是 | 否 | SKU ID |
| items[].adjustAmount | NUMBER | 是 | 否 | 调整金额（核心入参，可为负）：新库存金额 = 旧库存金额 + 调整金额 |
| items[].remark | STRING | 否 | 否 | 明细备注（最长256字符） |

**注意**
- 必须查询 [findInventorySettings](仓库.md) 获取calculateCostByWarehouse设置；calculateCostByWarehouse=2 时 warehouseId 必传
- 仅待审核的单据可修改
- 修改前先调 [costAdjustmentBillDetail](#costadjustmentbilldetail) 获取原明细 id，保留的明细带原 id，新明细不传 id
- 调整以 adjustAmount 为准，校验规则与新增一致（旧库存金额 + 调整金额 ≥ 0、调整金额不为0）

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即修改成功）

## approveCostAdjustmentBill

**功能**：审核成本调整单，审核通过后单据状态变为已审核，调整生效（更新商品成本价与库存成本金额，不改变库存数量）。

**典型场景**
- 制单人提交后由有权限的人审核生效
- 审核前核对明细的调整金额与折算新价

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 成本调整单ID |

**注意**
- 仅待审核的单据可审核
- 审核时校验：商品是否已删除/淘汰、分仓成本配置是否满足（calculateCostByWarehouse=2 时单据必须有调整仓库，查询 [findInventorySettings](仓库.md)）、旧库存金额 + 调整金额 ≥ 0
- 审核生效后按调整金额更新库存成本金额（新价随之折算），出入库成本核算按新成本价执行

**响应数据**
- 返回类型：`BOOLEAN`（审核结果）

## deleteCostAdjustmentBill

**功能**：根据ID删除成本调整单。

**典型场景**
- 删除误建的待审核单据

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 成本调整单ID |

**注意**
- 仅待审核的单据可删除
- 已审核的单据不可删除（成本已生效）

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即删除成功）

## 跨接口组合示例

**场景1**：完整成本调整流程（查询设置与商品 → 新增 → 核对 → 审核）
1. `findInventorySettings` → 获取 calculateCostByWarehouse 设置（见 仓库.md）：=2 时后续必须传 warehouseId
2. `findOrderWarehouses` → 获取调整仓库ID（见 仓库.md），calculateCostByWarehouse=2 时必查
3. `findStorageBillSelectSku` → 按名称/编码查商品，获取 skuId（=> id）、库存数量（amount）、旧库存金额（costAmount）（见 出入库单选商品.md）；启用分仓成本时传相同 warehouseId
4. 确定调整金额：按目标新价折算 adjustAmount = 目标新价 × amount − costAmount；或直接给差额（正数调增、负数调减）。校验：adjustAmount 不为0、costAmount + adjustAmount ≥ 0
5. `createCostAdjustmentBill` → 传入 items（skuId + adjustAmount 为核心），得到单据ID；calculateCostByWarehouse=2 时传 warehouseId
6. `costAdjustmentBillDetail` → 核对单据内容、调整金额与折算新价
7. `approveCostAdjustmentBill` → 审核生效（状态变为已审核）

**场景2**：修改待审核的调整单
1. `searchCostAdjustmentBills` → 按 q=单号 找到待审核单据（status=0）
2. `costAdjustmentBillDetail` → 获取原明细及 items[].id
3. `updateCostAdjustmentBill` → 修正 adjustAmount（保留的明细带原id，新明细不传id）
4. `approveCostAdjustmentBill` → 审核生效

**场景3**：删除误建的成本调整单
1. `searchCostAdjustmentBills` → 按 q=单号 找到待审核单据ID
2. `deleteCostAdjustmentBill` → 传入单据ID删除
