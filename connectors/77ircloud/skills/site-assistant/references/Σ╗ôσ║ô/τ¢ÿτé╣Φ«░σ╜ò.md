# 盘点记录

盘点单用于仓库定期/临时盘点：对指定仓库的商品录入**实盘数量**，与**账面库存**对比得出**盘盈/盘亏**；审核后按盈亏结果自动生成盘盈/盘亏出入库单调整库存。单据状态：`待审核(0) → 已审核(1)`；待审核状态可修改、追加商品、删除明细、作废；已审核单据不可再变更。盘点方式分两种：**非批次盘点**（整货，按多单位拆分录入）与**批次盘点**（按批次逐个录入实盘数量）。盘点单不支持删除，不再需要的单据请使用作废。

## 接口目录
- [searchCheckInventoryBills](#searchcheckinventorybills) - 盘点单列表
- [getCheckInventoryBillWithoutContents](#getcheckinventorybillwithoutcontents) - 盘点单详情（不含明细）
- [searchCheckInventoryBillContents](#searchcheckinventorybillcontents) - 盘点单明细列表
- [searchCheckInventoryBillBatchContents](#searchcheckinventorybillbatchcontents) - 盘点单明细批次
- [createCheckInventoryBill](#createcheckinventorybill) - 新增盘点单
- [appendCheckInventoryBillProducts](#appendcheckinventorybillproducts) - 追加盘点单商品
- [modifyCheckInventoryBillContent](#modifycheckinventorybillcontent) - 修改盘点单明细
- [deleteCheckInventoryBillContent](#deletecheckinventorybillcontent) - 删除盘点单明细
- [approveCheckInventoryBill](#approvecheckinventorybill) - 审核盘点单
- [discardCheckInventoryBill](#discardcheckinventorybill) - 作废盘点单

## searchCheckInventoryBills

**功能**：分页查询盘点单列表（不含商品明细），自动按仓库数据权限过滤。

**典型场景**
- 按单号搜索盘点单
- 按仓库、制单人、单据状态筛选
- 查看某段时间的盘点记录

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| q | STRING | 否 | 否 | 搜索关键字（单号） |
| statuses | NUMBER | 否 | 是 | 单据状态列表，-1=作废 0=待审核 1=已审核 |
| createTime | TIME_RANGE | 否 | 否 | 创建时间范围 |
| warehouseIds | NUMBER | 否 | 是 | 盘点仓库ID列表 |
| createId | NUMBER | 否 | 否 | 制单人员工ID |
| sort | SORT | 否 | 否 | 排序字段，如 createTime:desc |

**响应数据**
- 返回类型：`PAGE`（分页）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 盘点单ID |
| billNum | STRING | 盘点单号 |
| warehouseId | NUMBER | 盘点仓库ID |
| warehouseName | STRING | 盘点仓库名称 |
| status | NUMBER | 单据状态（-1=作废 0=待审核 1=已审核） |
| creatorId | NUMBER | 制单人ID |
| creator | STRING | 制单人名称 |
| approverId | NUMBER | 审核人ID |
| approverName | STRING | 审核人姓名 |
| approveTime | DATETIME | 审核时间 |
| createTime | DATETIME | 创建时间 |
| orgId | NUMBER | 单据所属机构ID |
| orgName | STRING | 单据所属机构名称 |
| remark | STRING | 备注 |
| totalCostMoney | NUMBER | 合计盘盈盘亏金额 |

## createCheckInventoryBill

**功能**：创建盘点单，指定盘点仓库并录入商品盘点明细，返回新建单据ID。

**典型场景**
- 仓库全盘/部分商品盘点建档

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明                    |
|------|------|------|------|-----------------------|
| warehouseId | NUMBER | 是 | 否 | 盘点仓库ID                |
| remark | STRING | 否 | 否 | 盘点单备注                 |
| contents | ARRAY | 是 | 是 | 商品盘点明细列表              |
| contents[].skuId | NUMBER | 是 | 否 | 商品SKU ID              |
| contents[].spuId | NUMBER | 是 | 否 | 商品SPU ID              |
| contents[].code | STRING | 是 | 否 | 商品SKU编码               |
| contents[].name | STRING | 是 | 否 | 商品SKU名称               |
| contents[].categoryId | NUMBER | 是 | 否 | 商品分类ID                |
| contents[].baseUnitId | NUMBER | 是 | 否 | 商品基础单位ID              |
| contents[].baseUnitName | STRING | 是 | 否 | 商品基础单位名字              |
| contents[].bookBaseCount | NUMBER | 是 | 否 | 盘点时，商品对应的账面库存 |
| contents[].checkCountUnitList | ARRAY | 是 | 是 | 盘点数量按多单位拆分   |
| contents[].checkCountUnitList[].id | NUMBER | 是 | 否 | 单位ID                  |
| contents[].checkCountUnitList[].rate | NUMBER | 是 | 否 | 转换比率                  |
| contents[].checkCountUnitList[].count | NUMBER | 是 | 否 | 该单位盘点数量               |
| contents[].checkCountUnitList[].unitName | STRING | 是 | 否 | 盘点单位名称                |
| contents[].batchContents | ARRAY | 否 | 是 | 批次盘点信息（批次商品必传）        |
| contents[].batchContents[].id | NUMBER | 否 | 否 | 批次ID（传了表示更新该批次盘点记录）   |
| contents[].batchContents[].batchNum | STRING | 是 | 否 | 批次号(不传按生产日期生成)        |
| contents[].batchContents[].bookBaseCount | NUMBER | 是 | 否 | 批次账面库存数量（按基础单位）       |
| contents[].batchContents[].productionDate | DATE | 是 | 否 | 生产日期                  |
| contents[].batchContents[].expirationDate | DATE | 否 | 否 | 过期日期（不传时按生产日期+商品保质期自动计算） |
| contents[].batchContents[].checkCountUnitList | ARRAY | 是 | 是 | 该批次盘点数量按多单位拆分   |
| contents[].batchContents[].checkCountUnitList[].id | NUMBER | 是 | 否 | 单位ID                  |
| contents[].batchContents[].checkCountUnitList[].rate | NUMBER | 是 | 否 | 转换比率                  |
| contents[].batchContents[].checkCountUnitList[].count | NUMBER | 是 | 否 | 该单位盘点数量               |
| contents[].batchContents[].checkCountUnitList[].unitName | STRING | 是 | 否 | 盘点单位名称                |
| contents[].costPrice | NUMBER | 是 | 否 | 当前成本价                 |
| contents[].remark | STRING | 否 | 否 | 明细备注                  |

**关键数据及来源**
- 盘点仓库来源 [findOrderWarehouses](仓库.md)，需要盘点仓库权限
- 盘点明细来源 [findStorageBillSelectSku](出入库单选商品.md)：id => skuId、categoryId、baseUnit => multiUnitList.rate==1(baseUnitId => id、baseUnitName => unitName)、amount => bookBaseCount、costPrice => costPrice、checkCountUnitList(未指定数量的单位count=0) => multiUnitList(id,rate,unitName)
- 批次商品（启用批次管理findStorageBillSelectSku中enableProductionDate=true）需用 [findSkuSelectBatch](出入库单选商品.md) 选择批次录入 batchContents，批次号/生产日期必填，过期日期可不传（自动计算）
- 同一商品存在**未审核的盘点单**（同仓库）时不允许重复盘点，创建会失败
- checkCountUnitList必须与multiUnitList数量一致。checkCountUnitList 非批次盘点时传多单位拆分数量，批次盘点时 按batchContents[].checkCountUnitList[]数量汇总。
- 批次商品盘点时，必须询问未提供批次号且非0库存的批次处理方式，账面库存不作调整的批次要传入batchContents中。
- 明细检查：批次商品检查所有账面非0库存的批次号，均需要提供

**响应数据**
- 返回类型：`NUMBER`（新建单据ID）

## appendCheckInventoryBillProducts

**功能**：向待审核的盘点单追加商品盘点明细；追加的SKU已在单据中时累加修改其盘点数量，不存在时新增明细。

**典型场景**
- 盘点过程中发现漏盘商品，补充录入
- 追加的商品已在单内时直接累加实盘数量

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| billId | NUMBER | 是 | 否 | 盘点单ID |
| warehouseId | NUMBER | 是 | 否 | 盘点仓库ID（需与原单据仓库一致） |
| remark | STRING | 否 | 否 | 盘点单备注 |
| contents | ARRAY | 是 | 是 | 追加的商品盘点明细列表（结构同 createCheckInventoryBill 的 contents） |

**关键数据及来源**
- 仅**待审核**状态的单据可追加
- 追加的SKU若已存在于单据中，则**累加**盘点数量而非覆盖
- 追加的SKU不允许存在于其他未审核盘点单中（同仓库）
- contents 字段结构同 [createCheckInventoryBill](#createcheckinventorybill) 的 contents
- 追加商品盘点明细来源 [findStorageBillSelectSku](出入库单选商品.md)：id => skuId、categoryId、baseUnit => multiUnitList.rate==1(baseUnitId => id、baseUnitName => unitName)、amount => bookBaseCount、costPrice => costPrice、checkCountUnitList(未指定数量的单位count=0) => multiUnitList(id,rate,unitName)
- 批次商品（启用批次管理findStorageBillSelectSku中enableProductionDate=true）需用 [findSkuSelectBatch](出入库单选商品.md) 选择批次录入 batchContents，批次号/生产日期必填，过期日期可不传（自动计算）
- 同一商品存在**未审核的盘点单**（同仓库）时不允许重复盘点，创建会失败
- checkCountUnitList必须与multiUnitList数量一致。checkCountUnitList 非批次盘点时传多单位拆分数量，批次盘点时 按batchContents[].checkCountUnitList[]数量汇总。
- 批次商品盘点时，必须询问未提供批次号且非0库存的批次处理方式，账面库存不作调整的批次要传入batchContents中。
- 明细检查：批次商品检查所有账面非0库存的批次号，均需要提供

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即追加成功）

## approveCheckInventoryBill

**功能**：审核盘点单，审核通过后状态变为已审核，并按盘盈/盘亏结果自动生成相应的出入库单调整库存。

**典型场景**
- 盘点完成、明细核对无误后审核生效
- 生成盘盈入库单/盘亏出库单

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 盘点单ID |

**注意**
- 仅**待审核**状态的单据可审核
- 审核会按盈亏生成出入库单并调整库存，操作前请确认明细数据准确
- 审核中有锁保护，请勿重复提交（3秒后可重试）
- 审核后单据不可再修改/追加/删除明细，如需终止盘点请走作废

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即审核成功）

## discardCheckInventoryBill

**功能**：根据ID作废盘点单，作废后状态置为作废(-1)，不再参与盈亏调整。

**典型场景**
- 盘点数据全部错误，放弃本次盘点
- 重复建立的盘点单做废弃处理

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 盘点单ID |
| remark | STRING | 否 | 否 | 作废备注 |

**注意**
- 盘点单不支持删除，需要终止盘点时使用本接口作废
- 作废后单据不可恢复、不可审核
- 已审核的单据一般不可作废（库存已调整）

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即作废成功）

---

## 枚举

### 单据状态

| 状态值 | 名称 | 说明 |
|------|------|------|
| -1 | 作废 | 已作废的单据，不参与盈亏调整 |
| 0 | 待审核 | 新建待审核，可修改/追加/删除明细 |
| 1 | 已审核 | 审核完成，已按盈亏生成出入库单 |

## 跨接口组合示例

**场景1**：新建盘点单并审核生效（完整流程）
1. `findOrderWarehouses` → 获取盘点仓库ID（见 仓库.md），需要盘点仓库权限
2. `findStorageBillSelectSku` → 查询仓库内商品与账面库存（见 库存.md）：skuId、categoryId、baseUnit、amount（账面数）、costPrice（成本价）等
3. `createCheckInventoryBill` → 传入 warehouseId + contents（录入各商品实盘数量），得到单据ID
4. `searchCheckInventoryBillContents` → 核对各商品盈亏数量（实盘-账面）
5. `approveCheckInventoryBill` → 审核生效（自动生成盘盈/盘亏出入库单）

**场景2**：盘点中补录/修正商品
1. `searchCheckInventoryBills` → 按单号找到待审核盘点单ID
2. `appendCheckInventoryBillProducts` → 补录漏盘商品（已存在的SKU自动累加数量）
3. `searchCheckInventoryBillContents` → 查明细列表，找到需修正的明细 id
4. `modifyCheckInventoryBillContent` → 修正该明细实盘数量；误录的用 `deleteCheckInventoryBillContent` 删除
5. `approveCheckInventoryBill` → 审核生效

**场景3**：批次商品按批次盘点核对
1. `searchCheckInventoryBillContents` → 查明细列表，找到批次商品的明细 id（isBatch=true）
2. `searchCheckInventoryBillBatchContents` → 传 billId + 明细id，逐批次核对账面/实盘数量
3. `modifyCheckInventoryBillContent` → 需要调整时按批次修正（batchContents[].id 对应批次明细）

**场景4**：放弃本次盘点
1. `searchCheckInventoryBills` → 按单号找到待审核盘点单ID
2. `discardCheckInventoryBill` → 传入单据ID与作废备注作废
