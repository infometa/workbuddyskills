# 其他入库-管理

本文档覆盖其他入库单的管理接口，包括新增、修改、审核、作废、删除。单据的列表与详情查询见 [其他出入库.md](其他出入库.md)。

## 接口目录
- [createOtherInStorageBill](#createotherinstoragebill) - 新增其他入库单
- [updateOtherInStorageBill](#updateotherinstoragebill) - 修改其他入库单
- [approveOtherInStorageBill](#approveotherinstoragebill) - 审核其他入库单
- [discardOtherInStorageBill](#discardotherinstoragebill) - 作废其他入库单
- [deleteOtherInStorageBill](#deleteotherinstoragebill) - 删除其他入库单

---

## createOtherInStorageBill

**功能**：创建其他入库单（如盘盈入库、调拨入库等非订单/非采购产生的入库），返回新建单据ID。新单据默认为待审核状态，审核后才正式增加库存。

**典型场景**
- 盘盈商品录入其他入库单
- 样品/赠品入库登记

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明                            |
|------|------|------|------|-------------------------------|
| warehouseId | NUMBER | 是 | 否 | 仓库ID                          |
| typeId | NUMBER | 是 | 否 | 其他出入库原因ID                   |
| typeName | STRING | 是 | 否 | 其他出入库原因名称                   |
| relatedType | NUMBER | 否 | 否 | 往来单位类型，3=客户，7=供应商，8=商家        |
| relatedId | NUMBER | 否 | 否 | 往来单位ID（客户id/供应商id/商家id，与relatedType配合使用） |
| remark | STRING | 否 | 否 | 备注                            |
| contents | ARRAY | 是 | 是 | 商品明细列表，1-500条                 |
| contents[].skuId | NUMBER | 是 | 否 | SKU ID                      |
| contents[].count | NUMBER | 是 | 否 | 单据执行单位数量（大于0）               |
| contents[].unitId | NUMBER | 是 | 否 | 单位ID                        |
| contents[].unitName | STRING | 是 | 否 | 单位名                         |
| contents[].costPrice | NUMBER | 是 | 否 | 成本价，不传默认为当前库存成本价或商品基准进货价      |
| contents[].costMoney | NUMBER |是 | 否 | 成本金额                          |
| contents[].remark | STRING | 否 | 否 | 明细备注                          |
| contents[].unitBarcode | STRING | 否 | 否 | 单位对应条码                        |
| contents[].batchContents | ARRAY | 否 | 是 | 批次号信息              |
| contents[].batchContents[].batchNum | STRING | 否 | 否 | 批次号                           |
| contents[].batchContents[].productionDate | DATE | 是 | 否 | 生产日期                          |
| contents[].batchContents[].expirationDate | DATE | 否  | 否 | 过期日期                  |
| contents[].batchContents[].count | NUMBER | 是  | 否 | 数量                    |

**注意**
- 必须查询 [findInventorySettings](仓库.md) 获取billPriceStrategy设置
- 其他出入库原因来源 [findOtherStorageTypes](其他出入库.md)（参数 ioType=1 and status=1），取id/name
- 商品明细来源 [findStorageBillSelectSku](出入库单选商品.md)（billPriceStrategy=1时 参数priceStrategy=1 and storageType=1，billPriceStrategy!=1时无需处理）
- 明细至少1条、最多500条；明细值映射findStorageBillSelectSku： skuId => id、unitId => multiUnitList[].id、unitName =>  multiUnitList[].name、costPrice => costPrice(支持输入)、costMoney=> costPrice * count(支持输入,优先级高于costPrice，系统自动计算costPrice)
- findStorageBillSelectSku中enableProductionDate=true时，contents[].batchContents必填
- 获取往来单位：客户(查询[searchDirectUnder](../组织/组织.md)文档)、供应商(暂不支持)、商家(暂不支持)

**响应数据**
- 返回类型：`NUMBER`（新建单据ID）

## updateOtherInStorageBill

**功能**：根据ID修改其他入库单。明细项传 `id` 表示更新原明细，不传 `id` 表示新增明细。

**典型场景**
- 调整单据的仓库、单据类型、备注
- 增删改单据的商品明细
- 变更往来单位信息

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明                     |
|------|------|----|------|------------------------|
| id | NUMBER | 是  | 否 | 其他入库单ID          |
| warehouseId | NUMBER | 是  | 否 | 仓库ID                   |
| typeId | NUMBER | 是  | 否 | 单据类型ID（其他出入库自定义类型）     |
| typeName | STRING | 是  | 否 | 单据类型名称（与typeId对应）      |
| relatedType | NUMBER | 否  | 否 | 往来单位类型，3=客户，7=供应商，8=商家 |
| relatedId | NUMBER | 否  | 否 | 往来单位ID                 |
| remark | STRING | 否  | 否 | 备注                     |
| contents | ARRAY | 否  | 是 | 商品明细列表，1-500条          |
| contents[].id | NUMBER | 否  | 否 | 明细ID，传了id表示更新，没传表示新增   |
| contents[].skuId | NUMBER | 是  | 否 | SKU ID（明细内必填）          |
| contents[].count | NUMBER | 是  | 否 | 单据执行单位数量（明细内必填，需大于0）   |
| contents[].unitId | NUMBER | 是  | 否 | 单据执行单位ID（明细内必填）        |
| contents[].unitName | STRING | 是  | 否 | 单据执行单位名（明细内必填）         |
| contents[].costPrice | NUMBER | 否  | 否 | 成本价                    |
| contents[].costMoney | NUMBER | 否  | 否 | 成本金额                   |
| contents[].remark | STRING | 否  | 否 | 明细备注                   |
| contents[].unitBarcode | STRING | 否  | 否 | 单据执行单位对应条码             |
| contents[].batchContents | ARRAY | 否  | 是 | 批次号信息                  |
| contents[].batchContents[].batchNum | STRING | 否  | 否 | 批次号                    |
| contents[].batchContents[].productionDate | DATE | 是  | 否 | 生产日期                   |
| contents[].batchContents[].expirationDate | DATE | 否  | 否 | 过期日期                   |
| contents[].batchContents[].count | NUMBER | 是  | 否 | 数量                     |

**注意**
- 必须查询 [findInventorySettings](仓库.md) 获取billPriceStrategy设置
- 其他出入库原因来源 [findOtherStorageTypes](其他出入库.md)（参数 ioType=1 and status=1），取id/name
- 商品明细来源 [findStorageBillSelectSku](出入库单选商品.md)（billPriceStrategy=1时 参数priceStrategy=1 and storageType=1，billPriceStrategy!=1时无需处理）
- 明细至少1条、最多500条；明细值映射findStorageBillSelectSku： skuId => id、unitId => multiUnitList[].id、unitName =>  multiUnitList[].name、costPrice => costPrice(支持输入)、costMoney=> costPrice * count(支持输入,优先级高于costPrice，系统自动计算costPrice)
- findStorageBillSelectSku中enableProductionDate=true时，contents[].batchContents必填
- 获取往来单位：客户(查询[searchDirectUnder](../组织/组织.md)文档)、供应商(暂不支持)、商家(暂不支持)

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即修改成功）

## approveOtherInStorageBill

**功能**：根据ID审核其他入库单，审核通过后单据状态变为已审核并执行入库。

**典型场景**
- 盘盈单录入完成后的审核确认
- 批量待审核单据逐张审核

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 其他入库单ID |

**响应数据**
- 返回类型：`BOOLEAN`（审核结果）

---

## discardOtherInStorageBill

**功能**：根据ID作废其他入库单，作废后单据状态置为作废。

**典型场景**
- 误录的单据作废
- 业务取消后不再执行的入库单作废

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 其他入库单ID |
| discardReason | STRING | 是 | 否 | 作废原因 |

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即作废成功）

---

## deleteOtherInStorageBill

**功能**：根据ID删除其他入库单。

**典型场景**
- 删除误建的待审核单据

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 其他入库单ID |

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即删除成功）

## 跨接口组合示例

**场景1**：为商品创建其他入库单并审核
1. `findWarehouses` → 获取仓库ID（见 仓库.md）
2. `findInventorySettings` → 获取billPriceStrategy设置（见 仓库.md）
3. `findStorageBillSelectSku` → 按名称/编码查商品，获取skuId、单位信息（见 出入库单选商品.md）
4. `findOtherStorageTypes` → 获取入库类型，得到 typeId/typeName（见 其他出入库.md）
5. `createOtherInStorageBill` → 传入 warehouseId + typeId/typeName + contents，得到单据ID
6. `otherInStorageBillDetail` → 核对单据内容（见 其他出入库.md）
7. `approveOtherInStorageBill` → 审核通过，完成入库

**场景2**：修改待审核的其他入库单明细
1. `searchOtherInStorageBills` → 筛选待审核单据，获取单据ID（见 其他出入库.md）
2. `otherInStorageBillDetail` → 获取原明细及其 id（见 其他出入库.md）
3. `updateOtherInStorageBill` → 变更明细（保留的明细带原id，新明细不传id）
4. `approveOtherInStorageBill` → 审核通过

**场景3**：作废已审核的其他入库单
1. `searchOtherInStorageBills` → 按单号/时间找到目标单据（见 其他出入库.md）
2. `discardOtherInStorageBill` → 传入单据ID与作废原因
3. `searchOtherInStorageBills` → 确认单据状态已变为作废
