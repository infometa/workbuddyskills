# 转仓单

转仓单用于仓库之间的商品调拨：商品从**转出仓库**发出（转出审核），到达**转入仓库**收货入库（转入审核）。单据状态流转：`待审核(0) → 转出审核 → 待入库审核(2) → 转入审核 → 已审核(1)`，转出审核后发现异常可**退回**到待审核；仅待审核的单据可修改、删除。

## 接口目录
- [searchStockTransferBills](#searchstocktransferbills) - 转仓单列表
- [stockTransferBillDetail](#stocktransferbilldetail) - 转仓单详情
- [createStockTransferBill](#createstocktransferbill) - 新增转仓单
- [updateStockTransferBill](#updatestocktransferbill) - 修改转仓单
- [approveStockTransferBillOut](#approvestocktransferbillout) - 转出审核转仓单
- [approveStockTransferBillIn](#approvestocktransferbillin) - 转入审核转仓单
- [returnStockTransferBill](#returnstocktransferbill) - 退回转仓单
- [deleteStockTransferBills](#deletestocktransferbills) - 删除转仓单

## searchStockTransferBills

**功能**：查询转仓单列表。

**典型场景**
- 按单号/制单人关键字搜索转仓单
- 按单据状态（待审核/待入库审核/已审核/作废）筛选
- 按转出/转入仓库、商品、创建/修改/审核时间筛选
- 查看某段时间内的调拨业务量

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| q | STRING | 否 | 否 | 搜索关键字（单号/制单人） |
| statues | NUMBER | 否 | 是 | 单据状态列表，-1=作废 0=待审核 1=已审核 2=待入库审核 |
| createTime | TIME_RANGE | 否 | 否 | 创建时间范围 |
| types | NUMBER | 否 | 是 | 单据类型列表，0=转仓单 1=车销-提货单 2=车销-回库单 |
| fromWarehouseIds | NUMBER | 否 | 是 | 转出仓库ID列表 |
| toWarehouseIds | NUMBER | 否 | 是 | 转入仓库ID列表 |
| skuId | NUMBER | 否 | 否 | 商品ID，搜索单据明细中包含该商品的单据 |

**响应数据**
- 返回类型：`PAGE`（分页）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 转仓单ID |
| billNum | STRING | 转仓单号 |
| type | NUMBER | 单据类型（0=转仓单 1=车销-提货单 2=车销-回库单） |
| fromWarehouseId | NUMBER | 转出仓库ID |
| fromWarehouseName | STRING | 转出仓库名称 |
| toWarehouseId | NUMBER | 转入仓库ID |
| toWarehouseName | STRING | 转入仓库名称 |
| status | NUMBER | 单据状态（-1=作废 0=待审核 1=已审核 2=待入库审核） |
| creatorId | NUMBER | 制单人ID |
| creator | STRING | 制单人名称 |
| approverId | NUMBER | 审核人ID |
| approverName | STRING | 审核人姓名 |
| approveTime | DATETIME | 审核时间 |
| outApproverId | NUMBER | 转出审核人ID |
| outApproverName | STRING | 转出审核人姓名 |
| outApproveTime | DATETIME | 转出审核时间 |
| createTime | DATETIME | 创建时间 |
| amount | NUMBER | 单据金额（转仓明细成本总额） |
| totalCount | NUMBER | 总数量 |

## stockTransferBillDetail

**功能**：根据ID查询转仓单详情，包含单据基础信息、商品明细（含批次、报损信息）与单据备注列表。

**典型场景**
- 查看某张转仓单的完整信息（单据头+商品明细）
- 审核前确认转出/转入仓库、明细数量与成本
- 查看转入审核后的合格数量/损坏数量
- 修改/审核/删除前先确认单据内容

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 转仓单ID |

## createStockTransferBill

**功能**：创建转仓单（将商品从转出仓库调拨到转入仓库），返回新建单据ID。

**典型场景**
- 正常仓库间调拨

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|-----|
| fromWarehouseId | NUMBER | 是 | 否 | 转出仓库ID |
| toWarehouseId | NUMBER | 是 | 否 | 转入仓库ID |
| type | NUMBER | 否 | 否 | 单据类型，0=转仓单（默认） 1=车销-提货单 2=车销-回库单 |
| remark | STRING | 否 | 否 | 备注 |
| contents | ARRAY | 是 | 是 | 商品明细列表（至少1条） |
| contents[].skuId | NUMBER | 是 | 否 | SKU ID |
| contents[].count | NUMBER | 是 | 否 | 单据执行单位数量（大于0） |
| contents[].unitId | NUMBER | 是 | 否 | 单据执行单位ID |
| contents[].unitName | STRING | 是 | 否 | 单据执行单位名 |
| contents[].unitBarcode | STRING | 否 | 否 | 单据执行单位对应条码 |
| contents[].remark | STRING | 否 | 否 | 明细备注 |
| contents[].costPrice | NUMBER | 是 | 否 | 成本价 |
| contents[].batchContents | ARRAY | 否 | 是 | 批次号信息 |
| contents[].batchContents[].batchNum | STRING | 是 | 否 | 批次号 |
| contents[].batchContents[].productionDate | DATE | 是 | 否 | 生产日期 |
| contents[].batchContents[].expirationDate | DATE | 是 | 否 | 过期日期 |
| contents[].batchContents[].count | NUMBER | 是 | 否 | 数量 |

**注意**
- 转出/转入仓库来源 [findOrderWarehouses](仓库.md)，可能没有转出/转入仓库权限需要notCheckWarehousePermission=true
- 商品明细来源 [findStorageBillSelectSku](出入库单选商品.md)：skuId => id、unitId => multiUnitList[].id、unitName => multiUnitList[].name、costPrice => costPrice
- contents[].batchContents findStorageBillSelectSku中enableProductionDate=true时，必填。使用[findSkuSelectBatch](出入库单选商品.md) 选择批次，必须同仓库且批次库存>0
- 转出仓库与转入仓库不能相同
- 启用批次管理的商品审核时会校验批次库存，不允许超库存出库

**响应数据**
- 返回类型：`NUMBER`（新建单据ID）

## updateStockTransferBill

**功能**：根据ID修改转仓单（仅待审核状态可修改）。明细项传 `id` 表示更新原明细，不传 `id` 表示新增明细。

**典型场景**
- 调整转出/转入仓库、备注
- 增删改单据的商品明细
- 补充单据附件

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 转仓单ID |
| fromWarehouseId | NUMBER | 是 | 否 | 转出仓库ID |
| toWarehouseId | NUMBER | 是 | 否 | 转入仓库ID |
| remark | STRING | 否 | 否 | 备注 |
| contents | ARRAY | 是 | 是 | 商品明细列表（至少1条） |
| contents[].id | NUMBER | 否 | 否 | 明细ID，传了id表示更新，没传表示新增 |
| contents[].skuId | NUMBER | 是 | 否 | SKU ID |
| contents[].count | NUMBER | 是 | 否 | 单据执行单位数量（大于0） |
| contents[].unitId | NUMBER | 是 | 否 | 单据执行单位ID |
| contents[].unitName | STRING | 是 | 否 | 单据执行单位名 |
| contents[].unitBarcode | STRING | 否 | 否 | 单据执行单位对应条码 |
| contents[].remark | STRING | 否 | 否 | 明细备注 |
| contents[].costPrice | NUMBER | 是 | 否 | 成本价 |
| contents[].batchContents | ARRAY | 否 | 是 | 批次号信息 |
| contents[].batchContents[].batchNum | STRING | 是 | 否 | 批次号 |
| contents[].batchContents[].productionDate | DATE | 是 | 否 | 生产日期 |
| contents[].batchContents[].expirationDate | DATE | 是 | 否 | 过期日期 |
| contents[].batchContents[].count | NUMBER | 是 | 否 | 数量 |

**注意**
- 商品明细来源 [findStorageBillSelectSku](出入库单选商品.md)：skuId => id、unitId => multiUnitList[].id、unitName => multiUnitList[].name、costPrice => costPrice
- contents[].batchContents findStorageBillSelectSku中enableProductionDate=true时，必填。使用[findSkuSelectBatch](出入库单选商品.md) 选择批次，必须同仓库且批次库存>0
- 仅待审核的单据可修改
- 修改前先调 [stockTransferBillDetail](#stocktransferbilldetail) 获取原明细 id，保留的明细带原 id，新明细不传 id

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即修改成功）

## approveStockTransferBillOut

**功能**：转出审核——确认商品从转出仓库发出。单据状态由待审核(0)变为待入库审核(2)，需转出仓库权限；审核时校验转出仓库批次库存，不允许超库存出库。

**典型场景**
- 转出仓库管理员确认发货
- 批量待审核单据逐张转出审核

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 转仓单ID |

**注意**
- 仅待审核的单据可转出审核
- 需要转出仓库权限
- 审核后单据进入待入库审核，等待转入方收货

**响应数据**
- 返回类型：`BOOLEAN`（审核结果）

## approveStockTransferBillIn

**功能**：转入审核——确认转入仓库收货入库。支持按明细/批次录入合格数量、损坏数量与损坏原因，报损数据随审核入库。

**典型场景**
- 转入仓库收货时录入实收合格数量与损坏数量

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 转仓单ID |
| damageContentList | ARRAY | 否 | 是 | 报损数据 |
| damageContentList[].id | NUMBER | 否 | 否 | 转仓单明细ID |
| damageContentList[].qualifyCount | NUMBER | 否 | 否 | 合格数量 |
| damageContentList[].damageCount | NUMBER | 否 | 否 | 损坏数量 |
| damageContentList[].damageReason | STRING | 否 | 否 | 损坏原因 |
| damageContentList[].batchDamageContentList | ARRAY | 否 | 是 | 批次商品的报损信息 |
| damageContentList[].batchDamageContentList[].id | NUMBER | 否 | 否 | 批次商品明细ID |
| damageContentList[].batchDamageContentList[].qualifyCount | NUMBER | 否 | 否 | 合格数量 |
| damageContentList[].batchDamageContentList[].damageCount | NUMBER | 否 | 否 | 损坏数量 |
| damageContentList[].batchDamageContentList[].damageReason | STRING | 否 | 否 | 损坏原因 |

**注意**
- 仅待入库审核的单据可转入审核
- 需要转入仓库权限
- 传入报损数据时明细ID需与 [stockTransferBillDetail](#stocktransferbilldetail) 返回的 contents[].id 对应

**响应数据**
- 返回类型：`BOOLEAN`（审核结果）

## returnStockTransferBill

**功能**：退回——转出审核后将单据退回到待审核状态。

**典型场景**
- 转出审核后发现明细错误，退回修改后重新审核
- 转入方拒收，退回给制单人调整

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| id | NUMBER | 是 | 否 | 转仓单ID |
| remark | STRING | 否 | 否 | 退回原因 |

**注意**
- 仅待入库审核的单据可退回
- 退回后单据变为待审核，可修改后重新转出审核

**响应数据**
- 返回类型：`BOOLEAN`（退回结果）

## deleteStockTransferBills

**功能**：根据ID列表批量删除转仓单。

**典型场景**
- 删除误建的待审核单据
- 批量清理无效单据

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| ids | NUMBER | 是 | 是 | 转仓单ID列表（1-50个） |

**注意**
- 仅待审核的单据可删除
- 已进入审核流程（待入库审核/已审核）的单据不可删除

**响应数据**
- 返回类型：`VOID`（无返回值，命令执行成功即删除成功）

## 枚举

### 单据状态

| 状态值 | 名称 | 说明 |
|------|------|------|
| -1 | 作废 | 已作废的单据 |
| 0 | 待审核 | 新建待转出审核 |
| 1 | 已审核 | 转入审核完成，库存调拨生效 |
| 2 | 待入库审核 | 转出审核通过，等待转入方收货 |

### 单据类型

| 类型值 | 名称 |
|------|------|
| 0 | 转仓单 |
| 1 | 车销-提货单 |
| 2 | 车销-回库单 |

## 跨接口组合示例

**场景1**：仓库间调拨商品（完整流程）
1. `findOrderWarehouses` → 获取转出/转入仓库ID（见 仓库.md），可能没有转出/转入仓库权限需要notCheckWarehousePermission=true
2. `findStorageBillSelectSku` → 按名称/编码查商品，获取 skuId、单位信息（见 出入库单选商品.md）；enableProductionDate=true 时用 `findSkuSelectBatch` 选择批次
3. `createStockTransferBill` → 传入 fromWarehouseId + toWarehouseId + contents，得到单据ID
4. `stockTransferBillDetail` → 核对单据内容
5. `approveStockTransferBillOut` → 转出审核（状态变为待入库审核）
6. `approveStockTransferBillIn` → 转入审核收货入库（状态变为已审核）

**场景2**：转出审核后发现错误，退回修改
1. `searchStockTransferBills` → 按单号找到单据（status=2 待入库审核）
2. `returnStockTransferBill` → 传入单据ID退回（状态回到待审核）
3. `stockTransferBillDetail` → 获取原明细及其 id
4. `updateStockTransferBill` → 修正明细（保留的明细带原id，新明细不传id）
5. `approveStockTransferBillOut` → 重新转出审核

**场景3**：转入收货时部分商品损坏
1. `searchStockTransferBills` → 找到待入库审核的单据
2. `stockTransferBillDetail` → 获取明细ID（contents[].id）
3. `approveStockTransferBillIn` → 传入 damageContentList：明细ID + qualifyCount（合格数量）+ damageCount（损坏数量）+ damageReason

**场景4**：删除误建的转仓单
1. `searchStockTransferBills` → 按 q=单号 找到待审核单据ID
2. `deleteStockTransferBills` → 传入 ids=[单据ID] 删除
