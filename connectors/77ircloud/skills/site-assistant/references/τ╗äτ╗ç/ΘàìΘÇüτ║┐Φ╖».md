# 配送线路管理

本文档覆盖配送线路查询接口，用于查询和管理分拣配送线路信息。

## 接口目录
- [searchRoutes](#searchroutes) - 分页查询配送线路列表（支持按名称/编码/状态筛选）

---

## searchRoutes

**功能**：分页查询配送线路列表，支持按线路名称、编码模糊搜索，按状态筛选。返回线路的详细信息，包括关联的车辆、司机、客户数量、地理位置等。

**典型场景**
- 查询所有配送线路列表
- 按线路名称或编码搜索特定线路
- 查询启用状态的线路
- 查看线路关联的车辆和司机信息
- 查看线路服务的客户数量
- 获取线路ID用于下游接口（如订单分拣、客户关联等）

**参数**

| 参数 | 类型 | 必填 | 数组 | 说明 |
|------|------|------|------|------|
| q | STRING | 否 | 否 | 搜索关键词（线路名称/编码模糊搜索） |
| status | NUMBER | 否 | 否 | 状态过滤（1:启用 0:禁用） |
| ids | NUMBER | 否 | 是 | 线路ID列表 |
| names | STRING | 否 | 是 | 线路名称列表 |
| excludeHavingCarBind | BOOLEAN | 否 | 否 | 排除有车辆绑定的线路（true则只返回未绑定车辆的线路） |

**响应数据**

- 返回类型：`PAGE`（分页）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NUMBER | 线路ID（用于下游接口如订单分拣、客户关联等） |
| name | STRING | 线路名称 |
| code | STRING | 线路编码 |
| status | NUMBER | 状态（1:启用 0:禁用） |
| remarks | STRING | 备注 |
| totalCustomers | NUMBER | 客户合计数量（该线路服务的客户总数） |
| car | OBJECT | 车辆信息 |
| car.id | NUMBER | 车辆ID |
| car.name | STRING | 车辆名称 |
| car.code | STRING | 车辆编码 |
| car.driverName | STRING | 司机名称 |
| car.driverId | NUMBER | 司机ID |
| provinceId | NUMBER | 省份ID |
| provinceName | STRING | 省份名称 |
| cityId | NUMBER | 城市ID |
| cityName | STRING | 城市名称 |
| districtId | NUMBER | 区ID |
| districtName | STRING | 区名称 |
| details | STRING | 详细地址 |
| longitude | NUMBER | 经度 |
| latitude | NUMBER | 纬度 |

**注意**
- `excludeHavingCarBind=true` 时，只返回未绑定车辆的线路，常用于为新车辆分配线路
- `totalCustomers` 字段可用于评估线路的业务量
- `car` 字段为null表示该线路未绑定车辆
- 线路的地理位置信息可用于地图展示和路径规划

## 跨接口组合示例

**场景**：为订单分配配送线路
1. `searchRoutes` → 查询启用的配送线路列表
2. 根据订单的客户地址，选择合适的线路（可参考地理位置信息）
3. 将线路ID传入订单分拣接口

**场景**：查看某线路的服务情况
1. `searchRoutes` → 查询线路列表，获取线路ID和客户数量
2. `searchRouteCustomerRel` → 传入线路ID，查看该线路关联的客户详情
3. 根据客户列表规划配送路线

**场景**：为新车辆分配线路
1. `searchSortingCars` → 查询未分配线路的车辆（见组织/车辆.md）
2. `searchRoutes` → 传入 `excludeHavingCarBind: true`，查询未绑定车辆的线路
3. 将车辆与线路进行关联

**场景**：查询某客户的配送线路
1. `searchDirectUnder` → 查询客户信息（见组织/组织.md）
2. `getRouteByCustomerId` → 传入客户ID，获取该客户所属的线路信息
3. 查看线路关联的车辆和司机信息
