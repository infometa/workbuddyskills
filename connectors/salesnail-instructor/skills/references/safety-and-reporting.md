# 安全、确认与报告
## 写操作

- 先读取当前资源和归属。
- 先 preview，展示准确对象、变更、费用、时间、影响范围和警告。
- 等待本步骤的明确确认。
- apply 时使用稳定 clientRequestId。
- 完成后必须回读。
- OAuth 自动开通只作用于当前登录账号；其他讲师生命周期写操作仍需 preview 和确认。
- Profile、客户、方案、交付写入不得包含 userId、tenantId、密码、Token、学员隐私或客户机密。

不得使用后端数据库、SSH、任意 API 或学员写接口绕过产品流程。

## 隐私

- 普通报告只取最少必要数据。
- 对外报告优先 `anonymizeLearners=true`。
- 不输出手机号、账号、Token、密码、tenant、原始用户对象或内部堆栈。
- `includeRaw` 仅限明确的技术诊断授权。

## 报告规则

MCP 提供数据和证据，当前 CLI 负责写报告。每个重要结论至少引用一个 actionId、messageId、npcId 或 opportunityId。

商业 Profile、客户 Brief、方案和交付工作区可以作为业务上下文，但不是课堂表现证据。方案生成结果必须标记为草稿和假设，不能当成客户已承诺范围或正式报价。

推荐结构：

- 轮次复盘：摘要、结果、探索与聚焦、决策链、对话证据、团队对比、下一轮建议、数据质量。
- 结案报告：摘要、商业结果、策略类型、MEDDPICC/SPIN、团队反馈、学员辅导边界、工作迁移、数据质量。
- 商机报告：事实、MEDDPICC 矩阵、SPIN、决策链、资源、缺失证据、下一问题、下一行动。

不得把代理指标或关键词命中写成客户已确认事实。
