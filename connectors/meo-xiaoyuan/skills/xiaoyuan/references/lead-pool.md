# WorkBuddy 中的小元线索池

在 WorkBuddy 中统一处理线索查询、去重入池、匹配评分、用户反馈、跟进、联系方式解锁和复用筛选。企业身份由企业 Key 决定，底层存储及物理表设计由服务端实现；业务字段见 lead-pool-fields.md。

## 查询、入池与同步

- 使用企业绑定的线索池标识；不按相似标题寻找其他企业的池，也不根据公司名自行生成授权身份。
- 真实线索 ID 与企业范围组成稳定去重键。线索 ID 为空拒绝写入；同键更新，不创建第二条；批次内重复先处理冲突。
- 展示候选买家不等于已入池。入池后读取回执并可回查；记录首次入池、最近更新、推送时间、次数、批次与消息标识。
- 更新接口事实和 AI 分析时保留已有用户反馈、跟进和解锁状态。数据来源按真实渠道记录，不能把普通买家搜索一律标成猎客询盘。
- 展会行为有真实报名展会时保存，没有时不造空行为记录。主记录、评分细节和参展行为保持关联，不强制拆成固定数量的表。

## 匹配评分与纠偏

事实包括公司、国家、类别、需求、产品、买家类型与特征；buyerType 只保留接口原值，不从其他标签推导覆盖。评分依据正式企业画像和确定性匹配结果，分别保存原始分、反馈扣分、最终分、等级、理由、逐维证据、MOQ、权重版本、画像版本和处理时间。

原字段资料记录的权重版本为 v10-32-24-18-10-6-4-2-2-2，评分明细含九个维度。若使用该版本，应保存完整分项证据；不能仅凭版本字符串编造评分算法或分数。核心匹配只取产品名称、产品类别和目标市场国家的闸门；买家类型为该版本的次级加分项，不单独改变核心匹配通过值。当前企业使用其他评分器时，记录其真实版本和规则。

写入前核对企业、正式画像、运行上下文及状态版本一致；防止将一家企业的画像、评分或反馈用于另一家。没有评分结果时可展示事实与待评分状态，不生成看似精确的数字。

用户反馈包括匹配／不匹配及原因，原因可多选，详细选项见字段参考。反馈只更新目标线索；长期企业偏好变更走 company-profile.md。

## 跟进与筛选

跟进状态保留“未跟进、已联系、已回复、已转化、关闭”和备注、操作者及时间。状态变化基于实际事件或用户明确更新，不因消息送达就自动改为已回复。

提供可复用的筛选：今日新线索、待确认、匹配线索、不匹配线索、已跟进、已解锁、高匹配机会。原高匹配规则为 AI匹配分 ≥ 70 且核心匹配通过；只有分数体系与该阈值匹配时应用，不把缺分线索当 0 分。服务端支持保存视图时保存，否则使用同样条件查询，不声称已创建视图。

## 解锁与联系方式

用户在 WorkBuddy 线索界面选择解锁，或在对话中要求解锁，汇入同一授权流程：核对企业与线索 → 显示对象与实际费用 → 按授权解锁 → 查询联系方式 → 在授权会话展示 → 记录成功回执。选中“已解锁”先视为操作意图，不能替代实际开通结果。

仅成功后写入解锁人、时间、方式和投递／展示回执；失败或未知结果不标完成。有已解锁状态和成功回执时复用，不重复解锁、扣费或推送。两种入口的最终状态一致。普通线索摘要、导出或隐藏字段不应旁路联系方式权限；服务端可以在受控详情中提供获授权的联系人，不把隐藏列当安全隔离。

## 字段契约检查

查询、保存和解锁前使用实际服务端的字段契约，不以本地参考文档强制创建物理表。若接口提供 expected_fields 与 fields，可用 scripts/schema_guard.py plan 检查规范化字段：缺字段给出新增计划；保留用户自定义字段及额外选项；同名类型冲突、缺必需选项或主键异常时停止相关写入并报告。只在授权工具确认完成补齐后继续，不自动改型、重命名、删除或迁移用户数据。
