# WhatsApp 与邮件回信跟进

用户询问某位买家、某条线索或某个 AI 猎客任务有没有回信时，查询与该对象关联的入站消息。区分“已发送、已送达、已读”和“买家真实回复”；只有入站消息记录才能证明收到回复。

1. 确定企业、买家、任务或会话范围，并查询最新入站消息；按消息 ID、时间和渠道去重。不能把其他企业或不相关会话的消息归给当前买家。
2. 展示渠道、发件人、收到时间、原文摘要和关联线索；有附件或敏感信息时按授权范围展示。
3. 用户要求回复时，先起草内容并确认收件人、渠道和完整正文；只有用户确认后才调用发送工具。发送受理不等于对方已收到或再次回复。
4. 用户要求持续提醒时，确认提醒对象和范围；优先按下一节的定时回查承接，存在服务端订阅或通知能力时读取其状态。只有拿到定时任务或订阅的真实回执才报告已开启监控；单次查询不等于后台持续监听。

## 定时回查：发送后等回信

消息或邮件发出后，买家回信不会推送到当前对话；「等回信」要靠周期性回查实现。只查一次不算持续跟进，也不要在没有凭据时向用户承诺「我会一直盯着」。

1. 优先在当前上下文可用的工具里寻找定时／计划任务类能力（如定时提醒、周期任务、计划执行，具体名称以宿主注入为准，不限于某个固定工具名），把回查注册为定时任务：基线约每 5 分钟一次，按用户要求调整频率。拿到注册回执才报告「已设置定时回查」，并告知用户如何停止。
2. 回查先轻量探测再下钻：WhatsApp 查 `xiaoyuan_list_whatsapp_conversations`，与上次已见快照比对，`unreadCount` 增加或 `lastDirection` 为入站才调 `xiaoyuan_list_conversation_messages` 读原文——该调用会把会话置为已读（代表本企业已查看），仅在确要读消息时使用；邮件按原邮件 ID 查投递，回信走本文入站消息流程。
3. 新回信才提醒：按消息 ID 与时间游标去重，同一回信不重复提醒；用户已处理、明确要求停止或跟进事项关闭时，取消定时任务。
4. 当前环境没有定时任务类工具时如实说明，改用可行方式：请用户稍后回来问一句即可查到最新回信（查询工具现成），或把跟进项挂到 WorkBuddy 的任务／待办界面（如有），或由用户自行设置提醒；不虚构后台监听，也不反复空查。

WhatsApp 与邮件应分别核对通道授权和收发身份。无法关联到买家或任务的入站消息应作为待核对消息，不猜测归属；需要人工接手时给出准确的会话线索。

入站消息须在服务端持久化并按渠道消息 ID 去重，将当前企业、买家、发送号／邮箱、原任务／线索和 WorkBuddy 会话关联起来。用户切换工作面不应丢失回信；提醒只投递给获授权的用户或会话，内部讨论不自动外发。一次外发只走一个通道，不同时通过工作面同步与发送工具各发一遍。

猎客询盘用 ai-hunter-inquiries.md 的列表、解锁、时段与沟通入口；企业自有 WhatsApp 用本企业 WABA 的会话链路；邮件用真正的入站邮箱或 webhook。三者分别维护状态，站内通知和邮件投递事件不能代替买家原话。
