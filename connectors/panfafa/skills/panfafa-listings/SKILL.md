# 盘发发盘库

只读当前用户自己录入的盘源，不是全网房源。用户说找厂房、找仓库、搜盘、盘库、青浦/松江等区域房源时，必须调用本连接器的 MCP 工具，不要用网页搜索。

未授权时先完成 OAuth。WorkBuddy 会打开浏览器，用户用盘发发小程序扫码确认。盘库工具需要 `mcp:listings.read`。新授权还会带上客户只读 `mcp:customers.read`；已经连过的用户要读客户必须重新扫码。遇到 401 或授权失效，提示用户重新授权，不要猜测盘源。

## 可用工具

### search_listings - 搜索盘库

按自然语言或关键词搜索当前用户盘库。

**参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| query | string | ✅ | 自然语言或关键词，例如：青浦 3000平 厂房。最长 500 字 |
| propertyType | string | - | 只传中文：`厂房`、`仓库`、`研发办公` |
| region | string | - | 区域名称，例如青浦 |
| areaMin | number | - | 可租面积下限 |
| areaMax | number | - | 可租面积上限 |
| rentMin | number | - | 租金下限 |
| rentMax | number | - | 租金上限 |
| page | integer | - | 页码，从 1 开始 |
| size | integer | - | 每页条数，1–20，默认 10 |

**返回**

`总数`、`页码`、`每页条数`、`房源`。每条含 `房源名称`、`房源类型`、`城市`、`区域`、`地址`、`可租面积`、`最低租金`、`最高租金`、`租金单位`、`租金`、`盘源状态`、`更新时间`，有封面时还有 `封面`。`租金` 已带单位，例如 `2.5～3.0 元/㎡/天`。

`房源类型` 只会是 `厂房`、`仓库`、`研发办公`，不会出现 factory、office、warehouse、plant。

**用法**

- 用户说找某区域某类型盘源：调用 `search_listings`，把原话放进 `query`，能确定类型时再填中文 `propertyType`
- 向用户展示时只用 `房源名称` 标识盘源，不要展示 publicId 或其他内部编号
- 先按套房源单独一块：名称、关键信息，封面紧跟在该名称下面。全部封面之后，文末再给一张汇总表（房源名称、区域、地址、可租面积、租金），方便对照。租金列必须带单位，优先用返回的 `租金` 字段，或把表头写成 `租金（元/㎡/天）`。禁止先做表格再把封面堆在文末
- 需要看下一页：同一 `query` 增大 `page`
- 不要编造未返回的盘源

### get_listing - 读取盘源详情

读取当前用户自己的一条盘源。先用 `search_listings` 拿到 `房源名称`，再调用本工具。

**参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| name | string | ✅ | 房源名称，必须来自工具返回 |

**返回**

搜索摘要字段，外加 `详细字段`（中文标签）。有封面时含 `封面`。同名房源多于一条时，会提示用区域或地址区分。

## 展示封面

向用户介绍盘源时，每张封面正上方必须用加粗写出房源名称，再贴图：

```markdown
**北京丰台办公出租**
![北京丰台办公出租](封面)
```

不要只口头说有封面，也不要向用户解释链接、签名或有效期。没有 `封面` 时跳过图片，不要伪造封面。封面必须跟在对应房源名称下面；文末可以再给一张对照表，但不要只靠表格后面的图库让用户猜是哪套。

## 注意事项

- 本连接器不能创建、修改、删除盘源，也不能发盘或带看
- 向用户说话只用中文：房源名称、厂房/仓库/研发办公、城市、区域、地址。禁止输出 publicId、factory、office、warehouse、plant
- `name` 必须来自工具返回；对不上或无权查看时会返回盘源不存在
- 盘库搜索偶发超过 30 秒，超时后可缩小条件重试，不要改用网页搜索
- 结果为空时如实说明盘库里没有匹配项，不要补全网房源
