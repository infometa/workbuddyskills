# 企业微信私域运营：补充能力与支持范围

企业微信私域运营负责企业微信客户、客户群、活码、群发及会话存档等业务。用本指引判断**该不该转交**、**钉哪个 `--skill`**（第 1 节）、**CLI 能交付到什么程度**（第 2 节）、**结果怎么展示**。不要改写用户原话，也不要替营销云选更细的子技能。

## 1. 触发与转交

- 用户提到营销虾、企微营销虾、企微互动智能助手、企业微信私域运营，或下表场景时，先判断是不是「六项创建」，再转交用户原话。`--skill` 是独立字段，**不要把技能名写进原话**，也不要拆成多次请求。
- **六项创建**钉 `--skill wecom-scrm-bot-skill`：创建员工活码、创建群活码、创建群发客户任务、创建群发客户群、创建群发朋友圈、创建跟进任务。逐条说法与判据见第 2.5 节。
- **其余企微私域运营**（查询、列表、群发详情 / 效果 / 催办 / 停用、欢迎语、跟进任务列表、标签、会话存档、文案等）钉 `--skill wecom-scrm-intent`。
- 营销策划、预算分配、会员体系、跨渠道内容包等不属于企微私域运营的请求**不加 `--skill`**，让营销云自行选择能力。
- 营销云若没有按企微口径理解（例如反问“团队指什么、数据来自哪个系统”），把反问原样展示给用户，由用户补充“企微”等上下文后再提问。
- 查询结果常以 `result_card` 事件交付（见 [事件与 HITL 指引](events-and-hitl.md)），这一轮可能没有 `answer` 正文；不要把卡片的占位文字“查询结果已在卡片中展示”当作结果。

## 2. 支持范围

本节的「CLI」列用于判断交付方式。实际数据与可用权限以当前任务返回为准；无权限、缺数据或仅返回方案时，如实说明，不宣称已完成业务执行。

| 记号 | 含义 |
| --- | --- |
| ✅ | 可完整交付：`answer` 正文，或只读 `result_card`（`payload` + `timeRange`，另附 `cardFile`） |
| 💬 | 写操作可在对话内完成：钉 `wecom-scrm-bot-skill`，补参 → 确认闸门 → 用户真实确认后提交。**仅限 2.5 的六项创建** |
| ⚠️ | 只能读不能操作，或需先过选择卡（见第 3 节）、先完成企微授权 |
| ❌ | 必须到营销云页面完成：空表单卡、预览确认卡、卡片按钮提交 |

### 2.5 六项创建 💬：钉 wecom-scrm-bot-skill

这六类创建在 `wecom-scrm-intent` 里会直接下发 a2ui 空表单 / 预览卡，由 H5 前端走流程，CLI 点不了也提交不了。改钉 `wecom-scrm-bot-skill` 后在对话内完成。**只有这六类改**，其它写操作不要钉 `wecom-scrm-bot-skill`。

| 场景 | 算创建 → `wecom-scrm-bot-skill` | 不算创建 → `wecom-scrm-intent` |
| --- | --- | --- |
| 员工活码 | 建员工活码、新建员工活码、创建员工活码、单人活码、多人活码、加员工的码 | 员工活码列表、我有哪些活码、扫码加人效果 |
| 群活码 | 建群活码、新建群活码、创建群活码、创建群码、入群码 | 群活码列表、查看群码 |
| 群发客户任务 | 创建群发客户、群发客户、客户群发、给客户发消息 | 群发客户任务详情、群发效果、催办、停用 |
| 群发客户群任务 | 创建群发客户群、群发客户群、客户群群发 | 客户群群发详情与效果、催办、停用 |
| 群发朋友圈任务 | 创建群发朋友圈、发朋友圈、群发朋友圈、朋友圈群发 | 朋友圈任务详情、朋友圈发布情况、催办、停用 |
| 跟进任务 | 创建跟进任务、跟进任务、创建跟进、提醒跟进、跟进客户 | 跟进任务列表、跟进任务统计 |

> 🔴 **同一个对象由动词决定通道**：建 / 新建 / 创建 / 生成 → `wecom-scrm-bot-skill`；列表 / 详情 / 效果 / 有哪些 / 催办 / 停用 → `wecom-scrm-intent`。两边都沾（先建再看效果）时按用户本轮的动作走，下一轮再按新动词重新判断。
> 只说「创建活码 / 建活码」先确认员工活码还是群活码；只说「提醒」先确认营销跟进任务还是企微待办。确认后再钉 `wecom-scrm-bot-skill`。
> 同一会话内补参、改字段、回复「确认」时继续钉 `wecom-scrm-bot-skill`，Magic sessionId 由 CLI 自动沿用，中途禁止改钉 `wecom-scrm-intent`。
> 钉了 `wecom-scrm-bot-skill` 仍收到空表单卡、或提示该能力不存在时，如实说明并请用户到营销云页面完成；不要改钉 `wecom-scrm-intent` 重试，那只会再出同一张卡。
> `wecom-scrm-bot-skill` 只出纯文本：追问、确认闸门与创建结果都在 `answer` 正文里，本轮通常没有 `result_card`，不要等卡片，也不要把这段文本套用指标卡模板。

### 2.6 其余写操作：当前版本必须到页面

营销云对这些能力下发带按钮或表单的卡片，CLI **不能点击按钮、不能提交表单**（`result_card` 的 `actions` 只列按钮名称）。发起前先说明；出现此类卡片时请用户到营销云页面完成。不要改用对话收集表单字段，不替用户确认。**不要**把它们改钉 `wecom-scrm-bot-skill`。

| 场景 | 常见说法 |
| --- | --- |
| 群发任务催办 / 停用 / 删除 | 催办群发、催一下没发的员工、停用群发任务 |
| 欢迎语 | 好友欢迎语、群欢迎语的新建 / 修改 / 删除 |
| 标签写入 | 打标签、批量打标、创建标签（**同能力的只读查询见 2.1** ✅） |
| 快捷运营动作 | 新客激活、销售转化、VIP 关怀、沉默唤醒 |

> 营销云若改用对话提问（`input_required`）确认写操作，按 HITL 指引让用户真实作答；这不代表整项能力已可用，结果以后续事件为准。

### 2.7 企微办公协同

🔴 **本节所有能力都依赖一次企微扫码授权**。未授权时营销云下发二维码卡（在 CLI 里是 `result_card`），文本宿主无法扫码 → 先请用户到营销云页面完成授权。第一次问日程就卡住通常是这个原因，要说清楚，不要反复重试。

| 域 | 常见说法 | CLI |
| --- | --- | --- |
| 日程与会议 | 日程、本周日程、约个会、查忙闲、订会议室、视频会议、入会链接、会议纪要 | ⚠️ 查询可读；建 / 改 / 取消走卡片 → 页面 |
| 企微原生待办 | 创建待办、记待办、分派待办、查企微待办、完成待办 | ⚠️ 同上 |
| 消息 | 发企微消息、在群里通知、发文件到群、我最近有哪些会话 | ⚠️ 同上 |
| 邮件 | 发邮件、回邮件、转发、搜邮件、未读邮件、邮件附件 | ⚠️ 发送前有预览确认卡 → 页面 |
| 文档与表格 | 创建文档、导入 excel、智能表格、在线文档、填表、加一行、搜文档、文档权限 | ⚠️ 笼统说法先出选择卡 |
| 微盘与媒体 | 微盘、上传到微盘、下载微盘文件、新建文件夹 | ⚠️ |

## 3. 收到选择卡时：两轮变通

营销云对“候选 ≥ 2”一律出选择卡，在 CLI 里是带 `actions` 的只读 `result_card`，按钮点不了。不要当作失败或断链：

1. 把 `actions` 原文作为选项，用 AskUserQuestion 问用户。
2. 拿到真实选择后，**新起一轮 `chat start`，`--query` 只传所选能力名原文**（如「企微通讯录」「创建员工活码」）；人名、时间等槽位从上一轮用户原话补在后面。所选能力按 2.5 判通道：命中六项创建 → `--skill wecom-scrm-bot-skill`；其余 → `--skill wecom-scrm-intent`。
3. 🔴 **第二轮的 `--skill` 不能省**：裸能力名没有业务上下文，漏掉会掉回通用问答，用户看到的是“选完反而没反应”。六项创建漏钉 `wecom-scrm-bot-skill` 会再出同一张空表单卡。
4. 禁止把出卡前的长原话再发一次 —— 会再出同一张卡。

**说法笼统时必然出卡**，可在转交前用一句话确认对象：

| 笼统说法 | 会被问 |
| --- | --- |
| 待办 / 我的待办 / 今天任务 | 营销待办 还是 企微原生待办 |
| 会话 / 最近会话 | 企微消息会话 还是 会话存档分析 |
| 发消息 / 通知一下 / 在群里发 | 群发客户 / 群发客户群 / 给同事发企微消息 |
| 今天有什么安排 | 营销今日待办 还是 企微日程 |
| 群分析 / 我的客户群 | 客户群获客看板 还是 群聊会话存档分析 |
| 提醒 / 提醒我 | 营销跟进任务 还是 企微待办（选跟进任务后钉 `wecom-scrm-bot-skill`） |
| 我有哪些文件 / 找个文件 | 企微文档表格 还是 微盘 |
| 排行 / 排名 | 我的排行 还是 团队业绩 |
| 找人 / 搜一下 / 联系方式 | 企微通讯录 / 客户搜索 / 营销员工搜索 |
| 创建活码 | 员工活码 还是 群活码（确认后钉 `wecom-scrm-bot-skill`） |
| 创建文档 / 创建表格 | 智能文档 / 在线文档 / 智能表格 / 在线表格 |

> 高命中的说法是“动作 + 明确对象”：创建员工活码、群发客户、创建跟进任务、查团队业绩、我的排名、营销待办、企微待办、群聊会话情绪。前三类属六项创建，直发时钉 `wecom-scrm-bot-skill`。发现用户说法过于泛化时可以先确认对象，但**不得改写原话后直发**。

## 4. 身份与个人数据

- 「我的 XX」是当前 OAuth 授权用户的数据。由服务端确认用户、企业、空间和访问权限。
- 不指定其他用户身份，不把企业级结果、他人数据或空结果说成个人数据。认证或权限失败时按服务端结果提示重新连接或核对权限。
- 结果提示无权限、未绑定员工身份或查询失败时，照实转达，不反复重试。

## 5. 口径

- **我的 vs 团队**：数值不同，分别展示；用户意图是团队口径却没说“团队”时先确认。
- **两套待办**：营销系统的“今日待办”与企微原生待办是不同数据源，写明来源，不合并条数。
- **客户 vs 客户群**；**群发客户 ≠ 群发客户群 ≠ 群发朋友圈 ≠ 给同事发企微消息**；跟进任务是派发任务，群发是推送消息；员工活码与群活码不同；文案 ≠ 海报 ≠ 商品图。
- **时间**：统计时间以结果的 `timeRange` / 统计期字段为准，不用任务创建时间代替；用户没说时间范围时不替用户补。
- **零值与排名**：全为 0 不代表调用失败；名次与参与人数只用结果里的值，不自行重算或排序。
