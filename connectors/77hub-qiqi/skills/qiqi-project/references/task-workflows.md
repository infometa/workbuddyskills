# 任务管理与执行工作流

## 任务的业务角色

任务用于把项目目标拆解为可承担、可计划和可执行的工作。项目计划/WBS与日常执行任务可能是不同对象或不同汇总规则；在当前元数据未确认前，不把任何父子结构默认解释为 WBS 汇总。

- **项目任务**：归属明确项目，是项目交付的一部分。
- **日常任务**：没有项目和父任务，不应被用来替代未确认归属的项目工作。
- **子任务**：依附明确父任务，是工作拆分关系；项目归属必须与父任务一致。

名称只用于产生候选。项目、负责人和父任务必须通过稳定引用或可验证关系确认。

## 计划、执行与单据阶段

计划开始/完成日期描述预期安排；实际开始/完成日期描述已经发生的执行事实；执行状态与单据状态也分别表达不同事实。创建成功只表示任务记录形成，不能表述为已生效、已开始或已完成。

用户意图应先归入以下工作流，再读取当前叶子命令帮助确认可用入口：

| 用户意图 | 应形成或改变的事实 |
| --- | --- |
| 新增工作 | 任务名称、归属、负责人和计划安排 |
| 调整工作安排 | 名称、负责人、计划或当前允许的业务属性 |
| 开始执行 | 实际开始与执行状态 |
| 完成执行 | 实际完成与完成状态 |

不要用修改入口提前填写实际日期或直接改写状态。当前任务如需经过提交、审批或生效流程，以当前记录的可用动作和业务规则为准；不要把它假设为 `project task` 的固定子命令。

未展开的可写模型字段遵循主技能「写入保护」。

## 写入保护

- 只提交本次意图需要的业务事实，不构造状态、来源、审计、计算或未确认的扩展字段。
- 同一父任务下的子任务开始、完成等写操作默认串行；前一项状态未知时暂停后续操作，先核查。
- 字段、值或命令定义不明确时读取当前元数据和 `--help`；命令被拒绝时说明当前状态与业务规则，不绕过。
- 超时、连接中断或结果不明确时，按稳定任务引用、项目、负责人和时间窗口核查；仍无法确认时报告状态未知，不重放。
