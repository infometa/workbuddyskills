# 项目工时归集

## 核心数据模型

工时单及其明细承载人员在业务日期对项目的实际投入。每条投入至少需要项目、日期和投入量；任务、项目阶段、部门、成本、计费或结算维度是否可用，取决于当前工时单类型和企业配置。

工时具有三层业务价值：

1. **项目管理**：说明人力实际投入，可与任务计划和项目阶段共同分析。
2. **成本归集**：工时单生效后，当前企业可能按工价、人员或其它规则归集项目成本并参与预算控制。
3. **客户经营**：当前企业如启用客户计费、结算或服务确认维度，工时可作为可计费服务投入的依据；不从工时本身推断已计费、已确认收入或已回款。

## 登记前的业务判断

1. 确认项目唯一且当前业务允许登记工时。
2. 用户表达的是项目级投入还是任务级投入；仅当当前工时单类型支持任务级填报时才关联任务，且任务必须属于该项目。
3. 明确业务自然日、投入量及其单位；同一明细不能同时把小时和人天作为两份投入。
4. 工作内容记录已经发生的投入，不把计划、承诺或任务完成结论写成工时事实。
5. 不创建占位任务来满足项目级工时登记。

## 操作入口与结果判断

当前 profile 公开 `project work-hours log` 时，先读取叶子命令帮助，再按当前定义提交最小事实。复杂明细如何传递、扩展字段是否允许以及一次请求形成几张工时单，均由当前命令和单据类型决定。未展开的可写模型字段遵循主技能「写入保护」。

登记成功以返回的工时单引用、明细结果和单据阶段为准。草稿只表示工时记录形成；未提交或未生效时，不表述为已确认成本、预算执行、客户计费或收入。

任一项目、任务、日期、数量或扩展字段结果不明确时，先按当前用户、项目、任务和时间窗口核查近期工时；确认前不重复登记。
