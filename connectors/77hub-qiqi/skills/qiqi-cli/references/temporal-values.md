# 时间值规则

## 先读字段语义

`describe fields` 对时间字段返回：

- `temporalKind`：业务时间语义。
- `format`：外部格式标识，即 `date`、`date-time`、`time`、`year-month` 或 `year`。
- `example`：符合该字段语义的示例。

这些内容是字段描述，不是查询条件。字段没有声明时间语义，或返回不支持的语义时，停止猜测并报告元数据不足或错误。

## 外部格式

| `temporalKind` | 业务含义 | 外部格式 | 示例 |
| --- | --- | --- | --- |
| `date` | 业务自然日 | `YYYY-MM-DD` | `2026-07-20` |
| `dateTime` | 精确时间点 | RFC 3339，必须带偏移或 `Z` | `2026-07-20T09:30:00+08:00` |
| `time` | 一天中的时刻 | `HH:mm:ss` | `09:30:00` |
| `yearMonth` | 自然月 | `YYYY-MM` | `2026-07` |
| `year` | 自然年 | `YYYY` | `2026` |

返回值保持当前字段的业务语义；`null` 保持 `null`。

## Agent 行为

- 原样传递符合字段描述的字符串，不生成、接受或解释 Unix 秒和毫秒。
- 用户说“今天”“下周一”等相对时间时，基于会话日期和当前用户时区解析为明确值；会改变写入结果时展示解析结果。
- `date` 是业务自然日，不计算内部起始时间点。
- `dateTime` 必须包含明确偏移或 `Z`，不发送无时区的本地日期时间。
- `time` 本身没有日期；需要日期锚点时只使用用户或当前命令明确提供的日期。
- 不用创建时间替代业务日期，不用计划日期替代实际日期，也不根据字段名称猜测时间语义。
- 列表筛选、记录读取和领域写入复用同一时间语义，不建立另一套格式。
