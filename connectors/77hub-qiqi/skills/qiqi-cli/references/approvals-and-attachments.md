# 审批与附件

## 审批

审批动作必须按当前记录实时发现，不维护静态 actionId 清单：

1. 从当前 profile 已公开的待办 View 或用户指定的业务记录取得稳定 `RecordRef`。
2. 读取记录必要详情，再用 `describe actions <RecordRef>` 获取此刻允许的动作和参数定义。
3. 向用户确认具体单据、动作语义、意见和影响；`submit`、`agree`、`deny` 等仅是可能出现的示例，不构成完整清单或固定契约。
4. 用 `do-action` 执行一次，并根据返回事实或最小读取核对结果。

同一状态的不同记录、不同用户或不同企业可能返回不同动作。批量审批也必须逐条重新发现和确认，不能复用首条记录的动作或参数。

## 附件

附件是挂载在业务记录或其明细上的业务资料，不是可独立猜测或直接访问的公共文件。

1. 先确认业务记录或明细的稳定 `RecordRef`，再通过 `records attachments` 查询其附件元信息。
2. 附件名称、附件 ID、存储位置和访问地址含义不同，不能互换；附件 ID 仅在已确认的业务记录范围内使用。
3. 文件访问必须通过 `records attachments url` 为当前有权身份签发的临时 URL。未取得签名 URL 时，不直接构造、猜测或访问文件地址。
4. 上传、删除或处理未知结果属于写操作：先确认目标、用户意图和影响；具体参数、限制及确认要求以目标命令 `--help` 和当前返回为准。

签名 URL 有时效且受当前业务记录权限约束。取得 URL 不等于文件已下载、读取或解析；只有任务需要且具备文件访问能力时才继续处理。
