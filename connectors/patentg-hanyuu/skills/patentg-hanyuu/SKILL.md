# 瀚與 专利查询（patentg-hanyuu）

中国专利数据查询服务：**应缴费用 / 费减备案 / 著录项目 / 说明书 PDF / 工商信息 / 无效决定 / 复审决定 / 企业专利清单**，外加账号基点查询，共 11 个工具。除企业专利清单走 CNIPA 外部检索外，其余均查本地库，全部只读。

## 铁律（先看这五条）

1. **查费用、查费减、下载全文、查无效/复审、查企业专利清单，直接调对应工具，不要先调 `get_patent_info`。**
   这些工具都会自行校验专利号或按条件检索；名称/申请人不是回答这些问题所必需的。
   只有用户**明确要著录项**（名称、申请人、发明人、公开日、摘要）时才调它。
2. **多件专利合并成一次数组调用**（`query_patent_fee` 支持批量），不要循环单件调用。
3. **每次调用消耗用户基点**（`query_patent_fee` 1 点/件、`download_patent_pdf` 5 点、`search_company_patents` 2 点、其余 1 点/次）。
   用户没问的事不要顺手查——多调一次就是多扣一次。
4. **下载链接原样交付**：不改写、不截断、不自行拼接。
5. **企业专利清单必须分页**：先看 `total` / `pages`，再按需取页；大企业动辄数万件，不要试图取全量。

## 工具选择

| 用户想要什么 | 用哪个 | 不要用 |
| --- | --- | --- |
| 公司**能不能**费减（只要结论） | `is_fee_reduction_valid` | ~~`query_fee_reduction`~~ |
| 费减**历年备案明细** | `query_fee_reduction` | ~~`is_fee_reduction_valid`~~ |
| 专利**还要交多少钱 / 什么时候到期** | `query_patent_fee` | ~~`get_patent_info`~~ |
| 专利**是什么 / 谁申请的 / 何时公开** | `get_patent_info` | — |
| **下载**说明书全文 PDF | `download_patent_pdf` | ~~`get_patent_info`~~ |
| 公司**工商详情**（法人 / 地址 / 邮编） | `query_company_info` | ~~`search_company`~~ |
| 只有公司简称，下一步要查费减 | `search_company`（**仅解析主体**） | ~~`query_company_info`~~ |
| 专利**被无效过吗 / 无效结果** | `search_invalid_decisions` | ~~`search_reexam_decisions`~~ |
| 专利**复审结果 / 复审请求人** | `search_reexam_decisions` | ~~`search_invalid_decisions`~~ |
| **某公司一共申请了多少专利 / 专利清单** | `search_company_patents` | ~~`get_patent_info`~~ |
| 账号**剩余基点 / 还能查几次** | `query_my_points` | — |

> **最容易混的三组**
> ① `search_company` 是模糊检索，只给「标准名称 + 统一社会信用代码」，专为费减查询解析主体；查工商详情必须用 `query_company_info`。
> ② `is_fee_reduction_valid` 只回答是/否；要明细走 `query_fee_reduction`。
> ③ **无效宣告 ≠ 复审**：无效是「专利授权后被人请求宣告无效」，复审是「驳回后申请人请求复审」。两个工具不要混用，也不要互相替代。

## 前置条件

- 已连接本连接器并填写有效 **orkey**。orkey 由 `mcp.json` 的 `X-MCP-Orkey` 请求头自动注入，**AI 不需要、也不应该向用户索要或代为传递 orkey**。
- 凭证失效时返回 `isError: true`，文本含「orkey「…」无效或未授权」。此时提示用户重新连接并填写正确 orkey，**不要重试**同一请求。

## 一、费减备案

### `search_company` — 主体模糊检索（辅助工具）

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `keyword` | string | 是 | — | 企业名称关键词，模糊匹配，不能为空 |
| `limit` | integer | 否 | 10 | 最多返回条数 |

```json
{ "keyword": "腾讯科技", "limit": 10 }
```

返回候选清单（每行 `[序号] 标准名称 (gsid: 统一社会信用代码)`），拿到标准名称与 gsid 后再去查费减。

**能力边界**：只做名称检索，**不返回**法定代表人、企业类型、注册地址、邮编。

### `query_fee_reduction` — 费减备案明细

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `company_name` | string | 是 | — | 企业/单位/个人名称（可模糊） |
| `gsid` | string | 否 | — | 统一社会信用代码或身份证号；已知时直接传，最快 |
| `pick_index` | integer | 否 | — | 多候选时指定第几个（1 起） |

```json
{ "company_name": "腾讯科技（深圳）有限公司", "gsid": "9144030071526726XG" }
```

返回 = 人类可读摘要 + **末尾一行可解析 JSON**：

```json
{"company_name": "...", "gsid": "...", "current_year": 2026, "current_year_valid": false, "record_count": 0, "records": []}
```

**取数只认末尾 JSON 行**的 `current_year_valid` / `record_count` / `records`。

### `is_fee_reduction_valid` — 费减资格判定

参数同 `query_fee_reduction`。返回一句结论，例如：

```text
否。腾讯科技（深圳）有限公司（9144030071526726XG）未查询到费减备案记录。数据来源：CNIPA 实时
```

### 主体解析规则（两个费减工具通用）

1. 传了 `gsid` → 直接查询，最快，推荐。
2. 只传 `company_name` → 自动在企业库解析；命中多家返回候选清单，用 `pick_index`（1 起）或补传 `gsid` 重查。
3. 解析不到（事业单位、个人）→ 服务提示需补充「完整单位名称 + 信用代码」或「姓名 + 身份证号」，**原样转达用户**。
4. **多候选 ≠ 已定位**：同名歧义时先向用户确认，不要默认取 `[1]`。

## 二、专利费用与文献

### `query_patent_fee` — 应缴费用（支持批量）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `patent_nos` | array\<string\> | 是 | 中国专利申请号列表。**单件也必须写成只含一项的数组** |

- 号码格式：**13 位**（12 位数字 + 1 位校验位，校验位可为 `0-9` 或 `X`）。带 `CN` / `ZL` 前缀、点分写法都能识别。
- **一次最多 60 件**（服务端硬上限，超过直接报错并提示分批，不会静默截断）。
- 个别号不合法**不影响**其它号，会在结果末尾单独列出。

```json
{ "patent_nos": ["2025116396651", "2024104299406"] }
```

返回按申请号分组：

```text
【2025116396651】2 项应缴费：
  - 发明专利第2年年费 ｜ 金额 135.00 ｜ 期限 2026-12-11
```

**「无应缴费记录」是正常结果**（已缴清或不适用），不是错误。

### `get_patent_info` — 著录项目

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `patent_no` | string | 是 | 13 位申请号（`2025116396651`）或 `CN` 开头的公开（公告）号（`CN121087679B`） |

返回：发明名称、申请号、公开（公告）号、申请日、公开（公告）日、申请人、发明人、主分类号、摘要。

- **一次只查一件**，批量场景会放大调用次数——查费用/费减/下载/无效/复审**不要**用它做前置确认。
- 首次查询可能约 5 秒（服务端冷缓存），属正常。

### `download_patent_pdf` — 说明书全文 PDF

参数同 `get_patent_info`。返回一条短时效签名链接：

```text
说明书 PDF 已就绪：
  文件名：CN121087679B.pdf
  下载地址：https://www.patentg.com/mcp/file/CN121087679B.pdf?t=eyJmIjoi…
（链接 10 分钟内有效；过期后重新调用本工具即可获取新链接）
```

- 链接**默认 10 分钟**有效，过期访问返回 `403`。重新调用取新链接，**不要**把旧链接再给用户，也不要猜测或拼造链接。
- 链接与文件名**强绑定**；链接很长且带签名，必须**整条原样**交付。
- 文件已缓存在服务端，**不要**为同一专利号反复调用。
- 只把地址给用户，**不要**自行下载、转存或解析 PDF 内容。

## 四、无效与复审决定

两个工具查的是**决定书的元数据**，不是决定书全文。

**两个工具都暂不支持下载决定文件**：返回的 `url` 字段恒为空串，末尾会带一句
「决定书全文暂不支持下载」。用户要决定书全文时如实说明边界，不要承诺、不要自己拼链接、
也不要暗示"可以到官网下载"——你没有能力核实对方能不能拿到。

### `search_invalid_decisions` — 无效宣告决定

| 参数 | 类型 | 必填 | 对应字段 | 说明 |
| --- | --- | --- | --- | --- |
| `patent_no` | string | 否 | `zlshqh` | 专利号，精确匹配 |
| `decision_no` | string | 否 | `wxfsbh` | 无效决定编号，如 `5W127942` |
| `patent_name` | string | 否 | `zlshmc` | 专利名称关键词，模糊匹配 |
| `patentee` | string | 否 | `zlsqlr` | 专利权人，模糊匹配 |
| `requester` | string | 否 | `wxqqir` | 无效请求人，模糊匹配 |
| `conclusion` | string | 否 | `jielun` | `全部无效` / `部分无效` / `维持有效` |
| `keyword` | string | 否 | `juedyaod` | **只搜决定要点**；查专利名称请用 `patent_name` |
| `panel` | string | 否 | `zhushy`/`zuzhan`/`canshe` | 合议组成员姓名，主审/组长/参审任一命中 |
| `decision_date_from` / `_to` | string | 否 | `juedir` | 决定日区间，`YYYY-MM-DD`（含当天） |
| `hearing_date_from` / `_to` | string | 否 | `koutim` | 口审日区间，`YYYY-MM-DD`（含当天） |
| `limit` | integer | 否 | — | 默认 10，上限 50 |
| `offset` | integer | 否 | — | 翻页跳过条数，默认 0，上限 1000 |

至少给一个检索条件（`limit` / `offset` 不算条件）。日期格式不认识会直接报错，不会静默忽略。

返回：

```text
共 1 条

【5W127942】2016206016794　多功能健腹轮
  结论：部分无效　决定日：2022-11-08　口审日：2022-08-01
  专利权人：台州市黄岩安康健身器材有限公司　请求人：杭州小姿智能科技有限公司
  合议组：李晓惠（主审）／张琳（组长）／林萍娟（参审）
  要点：……

{"total": 1, "returned": 1, "has_more": false, "url": ""}
```

`total` 是**满足条件的总条数**（不受 `limit` 影响）；`has_more=true` 时加 `offset` 继续翻。

**必须知道的三个坑**：

1. 结论字段约 **19%** 在原表为空（显示为「原表未标注」）——按结论筛选会漏掉这批。这是原表缺失，不是「结果未知」。
2. 决定日字段约 **26%** 为空（23,372 条空 + 1,321 条 NULL），按 `decision_date_*` 筛选同样会漏。口审日则是全表齐全的，要按时间筛优先用 `hearing_date_*`。
3. 表里混着 34 条 `anjllx='复审'` 的记录，**全部无结论、无决定日**，属残缺数据。工具已固定按 `anjllx='无效'` 过滤，查复审请用 `search_reexam_decisions`。

返回末尾的 JSON 里 `url` 恒为 `""`——**无效决定书暂不支持下载**，只有要点没有全文。

### `search_reexam_decisions` — 复审决定

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `patent_no` | string | 否 | 申请号，精确匹配 |
| `case_no` | string | 否 | 复审案件编号 |
| `decision_no` | string | 否 | 复审决定号 |
| `requester` | string | 否 | 复审请求人，模糊匹配 |
| `agency` | string | 否 | 代理机构，模糊匹配 |
| `conclusion` | string | 否 | `撤销驳回` / `维持驳回` |
| `keyword` | string | 否 | 在专利名称中模糊匹配 |
| `limit` | integer | 否 | 默认 10，上限 50 |

返回：

```text
【1F30567】001040790　保护方法、控制电路以及电池装置
  结论：撤销驳回　发文日：2011-12-26
  复审请求人：富士通微电子株式会社　代理机构：中国贸促会专利商标事务所有限公司
  决定号：38430
```

两条硬边界：

- **没有专利权人字段**。数据源里根本没有申请人/专利权人名称，**无法按企业名查复审案件**。要按企业查，先拿专利号，再用 `patent_no` 精确查。
- **不提供决定书全文/PDF**。返回的 `url` 字段恒为空串，要如实告诉用户「暂不支持下载决定文件」，不要承诺、也不要自己拼链接。

## 五、企业专利清单

### `search_company_patents` — 按申请人检索专利

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `company_name` | string | 是 | 申请人**全称**（营业执照名），简称命中率低 |
| `page` | integer | 否 | 页码，从 1 开始，默认 1 |
| `size` | integer | 否 | 每页条数，默认 20，上限 100 |

返回：

```text
「上海悠途实业有限公司」共 68 件，第 1/14 页（每页 5 件）：

1. CN122856437A / 2026113199764　一种柔软亲肤无缝羊毛针织物及其制备方法　发明　申请日 2026-08-28　法律状态 --
```

要点：

- 数据源是 **CNIPA 专利检索及分析系统**（全国范围，不是本系统台账）。
- 单次可能耗时十几秒；凭证过期或风控会返回明确错误，**按提示处理，不要反复重试**。
- 大企业数量极大（如腾讯科技（深圳）55,340 件），**先看 `total` 再决定取哪几页**，不要一次要全量。
- 查单件著录项用 `get_patent_info`，不要用本工具凑。

## 六、账号基点

### `query_my_points` — 剩余基点

无参数，按请求头里的 orkey 认人。返回：账号、计费状态（VIP / 普通）、剩余基点、今日已扣。**查询本身不扣点**。

- 平台级静态密钥（如 qinzhiyun）没有绑定账号，会返回一句说明而不是数字——照实转达，不要编造余额。
- 用户问「还能查多少」时可以用它；但**不要为了「确认能不能查」而在每次业务调用前先查一次余额**，那是白跑一趟。余额不足时服务端会直接拒绝并告知差多少。

## 七、推荐调用顺序

```text
费减场景
  只有简称 → search_company 取标准名称 + gsid → query_fee_reduction / is_fee_reduction_valid
  已知全称 → 直接 query_fee_reduction(company_name)
  已知 gsid → 一步到位
工商场景
  完整名称 / 信用代码 → 直接 query_company_info（不要先 search_company）
专利场景
  查费用 → query_patent_fee（多件合并成一次数组调用，不要先查著录）
  查著录 → get_patent_info
  要全文 → download_patent_pdf，把地址原样给用户
  查无效 → search_invalid_decisions（按专利号 / 权利人 / 请求人）
  查复审 → search_reexam_decisions（按申请号 / 案件编号；没有权利人字段）
  查企业专利清单 → search_company_patents（先 total 再分页）
```

## 八、错误场景与应对

| 现象 | 原因 | 应对 |
| --- | --- | --- |
| `isError: true`，含「orkey「…」无效或未授权」 | 凭证未配置或失效 | 提示用户重新连接连接器；不要重试 |
| `isError: true`，「下载令牌签发失败…」 | `download_patent_pdf` 无有效凭证 | 提示用户重新连接并填写 orkey；不要重试 |
| 下载链接打开是 `403 凭证无效或已过期` | 签名链接已过 10 分钟 | **重新调用 `download_patent_pdf`** 取新链接 |
| 下载链接打开是 `401 缺少 X-MCP-Orkey 或下载令牌` | 链接被截断/改写 | 重新调用取完整链接，整条原样交付 |
| `isError: true`，「一次最多查询 60 件…」 | 批量超上限 | 分批调用，每批 ≤ 60 件 |
| `isError: true`，「请至少给出一个检索条件…」 | 决定书查询没给任何条件 | 补专利号 / 决定号 / 权利人 / 请求人之一 |
| 「未检索到符合条件的无效宣告决定」 | 条件不匹配，或结论字段原表空缺 | 换专利号或权利人再查；**不要断言「该专利没被无效过」** |
| `isError: true`，「CNIPA 检索凭证未配置」 | `users.admin.cnipaquery` 为空 | 告知需管理员刷新凭证，不要重试 |
| `isError: true`，「CNIPA 检索接口返回异常」 | 凭证过期或被风控 | 如实转达，稍后再试；不要连续重试 |
| `isError: true`，「专利号全部不合法」 | 校验位不通过 | 改用正确的 13 位申请号或 `CN` 公开号 |
| 「未检索到…对应的企业」/「无应缴费记录」/「未查询到费减备案记录」 | 查无数据 | 属**正常结果**，按结论作答 |

## 九、数据合规与使用边界

- 数据来自 CNIPA 公开专利数据、公开工商信息与公开决定书元数据，结果**仅供参考**，正式结论以官方系统为准。
- **个人信息**：
  - `query_fee_reduction` 支持以**身份证号**查询个人费减备案——不要主动索取；用户提供后仅用于本次查询，回复中做掩码（如 `4403**********1234`）。
  - `query_company_info` 返回**法定代表人姓名**；`search_invalid_decisions` 会返回专利权人/请求人姓名。不要在无关场景复述或汇总。
- **不批量抓取**：不得为批量导出而循环调用；`search_company_patents` 的分页能力仅用于用户明确要求的多页浏览，不要翻几十页。
- 不存储、不转发、不把结果汇总写入外部系统或文件，除非用户明确要求且知晓。
- **能力边界**：覆盖费减 / 费用 / 著录 / 说明书 PDF / 工商信息 / 无效决定 / 复审决定 / 企业专利清单八类。
  **不提供**：无效与复审决定书的全文与 PDF（两个工具都只给元数据，无效另给要点，`url` 恒空）、
  专利法律状态变更历史、审查文件、同族、引证、商标或软著数据。遇到此类需求应说明边界，不要含糊承诺。
