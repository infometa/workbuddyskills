# 公益文书写作规范（精要版）

> 仅保留公益领域特有规范，通用写作技巧由 AI 原生能力覆盖。

---

## 🚫 润色硬性约束（最高优先级，违反即返工）

> 公益文书的真实性是生命线。润色的本质是**优化表达**，不是**创造内容**。

### 禁止虚构清单

| 类型 | 禁止 | 必须 |
|------|------|------|
| **具体对象** | 添加原文未提及的人物、物种、机构 | 仅润色已有元素的措辞 |
| **数据数字** | 编造受益人数、金额、覆盖范围 | 保持 `[待补充]` 或原值 |
| **场景细节** | 添加"雪夜送棉衣"等未发生的具体场景 | 用泛化表达，如"在恶劣天气下提供物资" |
| **合作方** | 编造合作单位名称（XX社区、XX学校） | 用泛化表述（"与社区单位合作"） |
| **时间地点** | 编造具体日期、地点、事件 | 仅使用用户提供的真实信息 |

### 必须执行的"新增内容标注表"

每次润色完成后，**必须**输出：

```markdown
📋 润色变更说明
| 段落 | 原文要点 | 润色后表述 | 是否新增事实 |
|------|---------|-----------|------------|
| 项目背景 | 帮助山区儿童 | 为山区儿童提供学习物资 | ❌ 仅措辞优化 |
| 项目目标 | [待补充] | [待补充：建议填写"覆盖 X 所学校"] | ⚠️ 建议补充（待用户确认） |
| 故事描写 | 老人独居 | 老人独居，邻里偶尔探望 | ⚠️ 添加细节"邻里探望"，请确认 |
```

**用户审核闸门**：润色后必须等用户确认"内容真实"才进入下一步，禁止默认通过。

### 共情元素的正确添加方式

当确实需要增加情感张力时：

✅ **建议补充模板**：
```
[建议补充：可加入一段受益人原话，如"我每次想到孩子能继续上学就忍不住流泪..."；
请您提供真实素材，或确认是否可以从过往项目中借用类似表述]
```

❌ **错误示例**：
```
原文："帮助孤儿"
润色后："帮助 50 个失去父母的孤儿，他们曾在寒夜里哭着喊妈妈..."（编造场景）
```

## 一、公益财务数据硬规则

- 善款使用明细的 **支出合计 = 实际总支出 + 公募管理费**（必须严格一致）
- 执行机构管理费占比通常 ≤ 10%（具体上限见 compliance_checklist.md）
- 预算与实际支出差额超过 **10%** 须给出合理解释
- 票据日期 **必须在项目上线时间之后**
- 所有金额精确到元，大额可用"万元"单位

## 二、受益人数据规范

- 严格区分"直接受益人"（直接接受服务）和"间接受益人"（如受助儿童的家庭成员）
- 数据要可溯源、可验证

## 三、受益人故事五条铁律

1. **用化名**：不使用真实姓名，除非获得书面同意
2. **传递尊严而非怜悯**：主角是「正在改变的人」，不是「需要被同情的人」
   - ✅ "通过培训掌握了电商技能，现在每月稳定接单"
   - ❌ "家徒四壁，吃不饱饭，幸亏有我们的帮助"
3. **用细节说话**：一个具体细节胜过十句概括（**注意：细节必须真实，禁止编造**）
4. **前后对比**：展现变化过程，而不只是结果
5. **征得同意**：使用前需确认已获得本人（或监护人）知情同意

## 四、数据不完整时的降级策略

一线公益人经常面临"数据不全但文书要得急"的困境。根据数据完整度提供不同级别的服务：

| 级别 | 条件 | 处理方式 |
|------|------|---------|
| **A级** | 所有必需信息齐全 | 生成完整正式文书 |
| **B级** | 有核心数据，缺部分细节 | 生成文书框架 + 已有数据填入 + 缺失部分用 `[待补充：XXX]` 标注，输出「待补充清单」 |
| **C级** | 只有零星信息 | 生成「最低可交付版本」骨架，输出按紧急程度排序的「必须补充清单」，提示"骨架可先发给资方看框架" |

**常见缺失场景的替代方案**：

| 缺失内容 | 替代方案 | 注明 |
|---------|---------|------|
| 没有精确受益人数 | 用签到表估算/覆盖范围推算 | "据签到记录估算，约XXX人" |
| 没有分类支出明细 | 用总支出+大致比例估算 | "根据项目类型经验估算" |
| 没有受益人反馈 | 用工作人员观察代替 | "据项目团队反馈" |
| 没有往期对比数据 | 只写本期绝对值 | "首次报告，暂无历史对比" |

> ⚠️ **关键约束**：以上所有"替代方案"都必须**明确告知用户**所用的估算/替代方式，并在文书中保留 `[待补充]` 或来源说明。**禁止偷偷用编造的数据填充**。
