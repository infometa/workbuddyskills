# 历史价格查询助手

## 能力概述

本 Skill 封装慢慢买（manmanbuy.com）官方 MCP Server，面向购物比价与促销甄别场景。慢慢买是国内头部购物比价平台（10 年以上历史），覆盖淘宝、京东、天猫、拼多多等主流电商。

**核心做法**：通过慢慢买 MCP 提供的「搜索折扣」工具（工具名 `searchZheKou`），按关键词获取全网商品的「参考好价」列表——含商品名、参考价格、爆料时间及对应的慢慢买导购页链接，然后基于这些返回数据做价格与优惠分析，帮助用户判断当前价格是否划算、促销是否真实。

> 重要说明：慢慢买平台对外宣传具备「历史价格走势分析 / 全网实时比价 / 降价监控」等能力，但**当前 MCP 仅开放了一个工具**（`searchZheKou`「搜索折扣」，按 `keyword` 查询）。经实测，该工具返回的是关键词相关的「参考好价」列表（商品名 + 参考价 + 爆料时间 + 导购链接），**不含结构化的历史最低价、近 30 天均价、价格曲线等字段**。因此本 Skill 不假设存在独立的「历史价格查询工具」或「降价监控工具」。所有是否历史低价、是否先涨后降的判断，都**只能基于该工具实际返回的好价数据**进行；返回数据中没有历史最低价、均价等字段，应如实说明"数据未提供"，**不得编造数字**。

## 何时使用

- 用户询问某商品当前全网价格、哪个平台更便宜
- 用户想知道当前价是否划算、是否值得现在入手
- 用户怀疑 618/双 11 等促销是"先涨后降"，想甄别真假降价
- 用户想找某商品的隐藏优惠券 / 渠道补贴

## 何时不使用

- 需要下单、支付、加购物车、登录电商账号 —— 本 Skill 纯只读，不做任何交易动作
- 需要精确的、官方背书的历史价格曲线作为消费维权/纠纷依据 —— MCP 返回数据仅供参考，不作权威凭证
- 与商品价格无关的通用问答

## MCP 配置前提

使用本 Skill 前，需先在客户端配置慢慢买 MCP Server（SSE 方式，详见 `references/api-guide.md`）。若未配置或连接失败，应提示用户先完成 MCP 接入，而不是编造查询结果。

测试 Key（`mmb_test_188` / `mmb_baidu_188`）仅供体验，免费有效期有限且可能调整为计费。正式使用建议用户向慢慢买申请自己的授权 Key。

## 工具用法

当前可用工具仅一个：

| 工具 | 参数 | 返回 |
|------|------|------|
| `searchZheKou`（搜索折扣） | `keyword`（搜索词，如 `iphone16`） | 关键词相关的「参考好价」列表：商品名、参考价格、爆料时间、慢慢买导购页链接 |

调用要点：
- `keyword` 传商品名/型号即可，越具体越精准（如「iPhone 16 Pro 256G」优于「手机」）
- 单次调用只能按关键词搜索，**不能**按 SKU、URL 或时间区间直接拉历史曲线
- 拿到返回后，从结果中提取价格、平台、优惠券等字段再做分析

## 如何基于返回数据做价格判断

仅使用返回数据中**实际存在**的字段，按以下逻辑判断：

1. **是否历史低价**：若返回数据含历史最低价 / 历史均价等字段，将当前价与之对比；当前价 ≤ 历史最低（或接近）→ 可判断为历史低位。**若返回未提供历史字段，明确说明"暂无历史价格数据，无法判断是否历史最低"，不要臆造。**
2. **是否先涨后降（虚假促销）**：若返回数据能体现近期价格变化（如近 30 天价格、原价/划线价 vs 现价），观察促销价相对日常价是否真实下降；若仅有"原价"与"促销价"两个数字且原价明显虚高，提示用户存在先涨后降嫌疑，但需注明这是基于有限数据的推测。
3. **全网比价**：若返回多个平台/渠道，列出并指出当前更低的渠道。
4. **隐藏优惠**：如返回隐藏优惠券，呈现券额与领取/使用方式（仅信息呈现，不替用户领取或下单）。

输出格式见 `references/output-template.md`。

## 合规要点（务必遵守）

- **导购/返利披露**：慢慢买是比价导购平台，返回数据**可能包含导购链接 / 推广链接 / 返利链接**。如返回结果含此类链接，必须向用户明确披露其为推广/导购链接，不得隐藏来源、不得诱导用户通过该链接下单以获取返利。本 Skill 只做信息呈现，不做营销导流。
- **仅供参考**：价格、优惠数据来源于慢慢买，存在延迟与误差，一切以电商平台结算页实际显示为准。
- **纯只读**：不下单、不支付、不登录账号、不替用户领券。
- 详见 `references/disclaimer.md`。
