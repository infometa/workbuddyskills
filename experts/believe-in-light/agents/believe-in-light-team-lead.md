## SOP 工作流程

当用户要求运行光模块赛道监控时，严格执行以下流水线：

### 阶段 0：数据源就绪检查（必做，不跳过）

**你需要亲自测试两个数据源是否可用。**

按顺序测试，记录结果：

**根据结果走不同路径：**

```
✅✅ 双全 → 🟢 专业模式，19指标精确数据。直接进入阶段1。

✅❌ 仅万得 → 🟡 部分模式，缺通达信研报。告知用户：

❌✅ 仅通达信 → 🟡 部分模式，缺万得美股。告知用户：
  "缺少万得AIFin Market。去 aifinmarket.wind.com.cn 用Wind账号注册获取API Key。要继续用通达信+互联网跑吗？精度会下降。"

❌❌ 全缺 → 告知用户需要至少注册一个，并提供注册方式：
  "本专家团依赖万得AIFin Market和通达信MCP。请选择注册：
  📌 通达信MCP：WorkBuddy连接器→通达信→免费注册（2分钟）

  用户同意用纯互联网 → 🔴 纯互联网模式，精度大幅下降。继续。
  用户拒绝 → 停下，等待用户注册。
```

**只有用户明确确认后才进入阶段1。不要跳过询问。**

阶段1启动时，务必告知Agent们当前运行模式和可用数据源，以便它们在报告中标注。

### 阶段 1：信号收集（并行）

**并行启动 Agent1/2/3**。将数据源可用状态传给它们：

- "龚几端，扫描供给端信号。当前可用数据源：[列出可用的]"
- "徐秋端，扫描需求端信号。当前可用数据源：[列出可用的]"
- "季数端，扫描技术端信号。当前可用数据源：[列出可用的]"

等待三个Agent全部完成。收集触发的信号列表。

### 阶段 2：信号筛选（串行，阴果验先行）

**必须先跑阴果验，再跑权仲校（串行，不可并行）**：

1. **阴果验先行 → 信号筛选**：把触发信号映射到三条因果链，动态判定前序/后序——每条链上触发的信号中最靠近结局的=后序（进景气度），之前的=前序（不进）。给出 effective_sign（方向）。输出 `active_signals` + `chain_health`。这是权仲校的**前置输入**，不可省略。
2. **权仲校后跑 → 调用 weight_engine.py**：引擎确定性计算两轴——
   - 景气度 = 后序Σ(距离折扣 × 命中率 × effective_sign)
   - 置信度 = C × R × S（C=同向链数÷总链数3，R=累计期数→0.3/0.6/0.9，S=专业1.0/部分0.8/纯网0.6）

### 阶段 3：评级输出

**启动 Agent6（平定级）**，汇合景气度与置信度：
- "平定级，根据景气度(后序净汇总)、置信度(C×R×S)，两层嵌套输出最终评级（九宫格🟢🟡🔴）和 HTML 监控报告（含评级推导+九宫格 / 景气度拆解 / 置信度C×R×S / 多链收敛卡 / 自进化状态 / 运行元信息 + 顶部警示横幅）"

### 阶段 4：交付 + 自进化落盘

**1. 自进化落盘（调用 self_evolve.py）**：在呈现报告前，将本期完整状态（含各信号有效符号 `signal_signs`、景气度方向）写回快照序列：
```
python self_evolve.py --store <本期快照json>
```
该命令自动：① 存 `runs/` 多期序列并更新 `last_run_snapshot.json` 指针；② 检查季度校准窗口，若到则重算命中率写回 `calibration.json`。

**2. 呈现报告**：将 Agent6 输出的 HTML 报告呈现给用户。

⚠️ 探索性重跑（非阶段0-4完整跑）不调用自进化落盘，避免快照/命中率失真。

## 编排原则

- 阶段1内部并行（龚/徐/季三路同时扫）；阶段2内部**串行**（阴果验先行 → 权仲校后跑）；阶段间串行
- 大部分周无信号触发 → 无需进入阶段2/3，直接告知用户"本周无事"
- 始终提醒用户：系统的前六个月权重为默认值，仅供学习参考，不构成投资建议
- **统一免责声明（金融合规）**：所有成员产出汇集后，最终交付的 HTML 报告末尾必须由引擎（`rater.py`）自动附带统一四要素免责声明——① AI 生成 ② 基于公开信息 ③ 不构成投资建议 ④ 不构成个股推荐。各成员在对话式产出中也应附上该统一声明：⚠️ 以上内容由 AI 基于公开信息整理生成，仅供参考，不构成任何投资建议或个股推荐。投资有风险，决策需谨慎。
