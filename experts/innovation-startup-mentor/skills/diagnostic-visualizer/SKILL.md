# 诊断可视化生成器（Diagnostic Visualizer）

把一次诊断/自检/方案的结论，变成**专家评审建议**（HTML 单页：五关雷达图、评分条、建议卡片、评委质疑点、三层价值、下一步行动），并尽力发布为在线链接。这是「青创领航员」的标配交付动作：**文字回答 + 专家评审建议，一次对话同时给出**（双交付）。

> 与"待办清单/工作台"不同：专家评审建议是**展示型报告**——把建议用图表和卡片直观呈现，一眼看懂项目强在哪、弱在哪、下一步做什么。不做勾选、不做长期跟进工具。页面内不出现"可视化应用/工作台"字样，统一称"专家评审建议"。

## 何时使用

用户在对话中获得**关键交付**（立项澄清结论、五关自检报告、闭环陪跑方案、答辩清单）之后，必须同步生成可视化应用。普通闲聊、信息收集阶段不生成。

## 执行流程

1. **整理诊断数据**：从本次结论中提取结构化数据（结构见下）。
2. **渲染 HTML**：

   ```bash
   python3 <本目录>/generate.py --data '<json 文件路径或内联 JSON>' --out <输出路径>.html
   ```

3. **自检**：确认输出 HTML 中已无 `__WB_DATA__` 占位符残留。
4. **发布（尽力而为）**：
   - 若当前环境具备资料库发布能力（宿主 library 技能的 `page/import_html.py` + `page/publish_page.py` + 平台凭证）：上传为在线 page，取**公开链接**交付。
   - 若无法取得发布凭证：交付**本地 HTML 文件路径**，并说明"把这份文件交给 WorkBuddy 主助手，即可发布成在线链接分享"。
5. **回执**：给出应用链接（或文件路径）+ 一句话说明（页面含雷达图/评分/建议/质疑点/行动）。

## 诊断数据 JSON 结构

```json
{
  "project": "AI 电商项目",
  "subtitle": "专家评审建议",
  "date": "2026-08-10",
  "meta": [ {"k": "赛道", "v": "AI-Native 竞赛"}, {"k": "团队", "v": "研究生团队"} ],
  "summary": "一句话总体诊断结论",
  "gates": [ {"name": "价值关", "score": 55}, {"name": "创新关", "score": 35}, {"name": "专业关", "score": 40}, {"name": "落地关", "score": 30}, {"name": "规模关", "score": 25} ],
  "weakest": "创新关、落地关",
  "verdicts": [ {"gate": "价值关", "level": "中", "comment": "痛点方向存在，但场景过大"} ],
  "improve": [ {"title": "去相关测试", "gate": "创新关", "desc": "具体动作描述（改进型=必须做）"} ],
  "consolidate": [ {"title": "价值证明包", "gate": "价值关", "desc": "具体动作描述（巩固型=加分）"} ],
  "challenges": ["评委最可能质疑的点 1", "点 2", "点 3"],
  "values": { "技术": "…", "商业": "…", "社会": "…" },
  "actions": ["本周第一件事", "第二件事", "第三件事"]
}
```

- `gates[].score`：0–100 整数，决定雷达图与颜色（<40 红 / <70 琥珀 / ≥70 绿）。
- `improve`（改进型）与 `consolidate`（巩固型）建议各 2–4 条，每条标注服务哪一关。
- `actions` 3 条以内，必须具体到"本周能做的事"。

## 设计约束（铁律）

- 这是**专家评审建议**（展示型报告），不是待办清单：必须包含五关雷达图、评分条、建议卡片、评委质疑点、三层价值、行动建议。
- HTML 必须**自包含**：雷达图用内联 SVG/JS 绘制，不引用任何第三方外链（图片/字体/脚本/CDN），保证可独立上传发布。
- 数据必须来自本次真实诊断结论，不编造评分与建议；不确定的字段留空或标注"待验证"。
- 主语始终是同学的项目；页面只承载"项目落地"内容，不出现 AI 工具操作教学。
