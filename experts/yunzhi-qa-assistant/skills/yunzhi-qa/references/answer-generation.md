# 答案生成与引用规则

> 本文件规范基于检索片段产出最终答案的所有约束。

---

## 1. 严格基于检索结果

- 所有结论 **必须** 由检索返回的片段支撑，不得依赖预训练通用知识凭空回答。
- 对检索结果先做**甄别筛选**：
  - 与问题主语义直接相关的片段 → 保留并采纳；
  - 弱相关、广告位、目录页噪声 → 丢弃；
  - 标题命中但正文跑题 → 丢弃。
- **同一个 `target_id`** 的多个片段，合并到同一引用编号下，避免重复编号。

---

## 2. 引用标注规则

### 2.1 内部编号

把召回结果按相关性从高到低编号：

```
[知识点 1 begin]
{片段正文 / 摘要}
来源标题：{title}
来源链接：{url}
[知识点 1 end]

[知识点 2 begin]
...
[知识点 2 end]
```

### 2.2 内联引用（⚠️ 用学术风 `[X]`，不要用 `[citation:X]`）

> **渲染约束（务必遵守）**：WorkBuddy 的 Markdown 渲染器**不认识** `[citation:X]` 这种网页角标语法，用户看到的会是原始丑陋文本 `[citation:5]`。因此**一律改用学术风数字角标 `[1]` `[2]`**——纯方括号加数字，渲染稳定、阅读干净。

在答案的对应句子或论点之后**内联标注** `[X]`（X 为该来源在「参考资料」中的编号）：

✅ 正确：
> CVM 默认提供按量计费和包年包月两种模式 [1]，包年包月相对更实惠 [2]。

❌ 错误一（用了 WorkBuddy 不渲染的网页角标语法）：
> CVM 默认提供按量计费和包年包月两种模式 [citation:1]。

❌ 错误二（不要把所有引用堆在末尾）：
> CVM 默认提供按量计费和包年包月两种模式，包年包月相对更实惠。
>
> 参考：[1][2]

### 2.3 多来源引用

同一句话有多个来源支撑时，分别紧贴标注：

```
xxx 内容 yyy 内容 [1][3]
```

## 3. 结构化输出

### 3.1 通用结构

```markdown
## 简明结论
{1~3 句直击问题核心，关键论点带 [1] [2] 这样的数字角标}

## 详细说明
{展开内容，使用合适的排版，每个关键论点内联 [X]}

## 参考资料
1. [{文档标题}](https://{domain}/pages/{target_id})
   {可选：1~2 行原文片段}
2. [{文档标题}](https://{domain}/docs/{target_id})

## 信息来源说明
- 内部知识库（乐享）：N 篇
- 数据来源：仅基于乐享知识库（不使用联网搜索）
```

> **「参考资料」硬约束**：
> 1. 编号 `1.` `2.` 必须与正文里的内联角标 `[1]` `[2]` **一一对应**。
> 2. 每条**必须是真可点的 Markdown 链接** `[标题](url)`——不要写成 `🔗 https://...` 这种裸链纯文本；标题即链接文字，点击直达原文。
> 3. `url` 按 §6 的 `target_type` 规则生成（`kb_entry`→`/pages/`，`disknode`→`/docs/`），且必须来自检索返回的真实 `target_id`，不得虚构。

### 3.2 题型适配

| 题型 | 推荐排版 |
|------|---------|
| 对比类（A vs B、X 和 Y 区别） | **Markdown 表格** |
| 步骤类（怎么做、如何配置） | **有序列表** |
| 罗列类（有哪些、列表给我看） | **无序列表** |
| 说明类（什么是 X、定义） | 段落 + 关键术语加粗 |
| 排查类（报错怎么办） | 「现象 → 原因 → 排查步骤 → 修复方案」 |

### 3.3 竞品对比类答案（`mode=competitive` 专用）

当 Phase 1 判定为竞品对比时，用下方专用模板，**站内乐享来源与站外官网来源必须分区标注**，每条带 `[P0/P1/P2]` 等级 + `[站内/站外]` 通道标签：

```markdown
## 结论
{一句话直击核心差异，客观中性，带 [1] 这样的数字角标}

## 分维对比
### 1. 产品定位 / 能力映射
- 腾讯云 {产品}：…（乐享内部知识 / 腾讯云官网）[1]
- 阿里云 {产品}：…（阿里云官网）[2]
- 华为云 {产品}：…（华为云官网）[3]
### 2. 核心功能 / 规格差异
{按品类专属维度逐项对比，用表格}
### 3. 价格 / 计费差异
{区分标价 / 阶梯价 / 协议价}
### 4. 差异形成原因
### 5. 适用场景 / 选型建议

## 待确认信息
{未公开 / 口径不一致 / 映射待确认项单列}

## 数据来源
- [P0/站内] [腾讯云内部知识（乐享）](https://{domain}/pages/{target_id})，知识库：xxx，更新：YYYY-MM-DD
- [P0/站外] [阿里云官网](URL)，更新：YYYY-MM-DD
- [P0/站外] [华为云官网](URL)，更新：YYYY-MM-DD
- [P1/站外] 厂商官方博客 — URL，更新：YYYY-MM-DD
- [P2/站外] Gartner 报告 — 标题，发布：YYYY-MM-DD
```

**对比答案额外约束**（完整规则见 [`competitive-analysis.md`](./competitive-analysis.md)）：

- **实体防污染**：COS↔OSS↔OBS↔S3 等先映射再比，绝不把腾讯云数据归给竞品、反之亦然。
- **来源白名单**：站外只引厂商官网白名单域名，CSDN/知乎/新闻媒体/代理商页一律不得出现。
- **结论分三类**：明确事实（P0 支撑）/ 合理解释（P1/P2 支撑）/ 待确认（无充分来源）。
- **宁缺毋滥**：查不到官方数据就写「官方未披露」，绝不用低质来源填补。

## 4. 信息不足时的拒答策略

> 本节针对 **`mode=standard`**（默认纯站内链路）。`mode=competitive` 见 §3.3：站内外多轮仍无官方数据时，就该项写「官方未披露」，其余照常输出，不整体拒答。

### 4.1 触发条件（standard）

- 全部召回片段相关性低于阈值；
- 命中片段与用户问题语义不一致；
- 召回为空。

### 4.2 拒答步骤

1. **明确告知用户**：「抱歉，我在你绑定的乐享知识库中未检索到与该问题直接相关的内容。」
2. 给出建设性建议：
   - 换用更具体的关键词（如完整产品名、错误码、API 名）重新提问；
   - 或确认相关资料是否已上传至当前绑定的乐享知识库。
3. **严禁调用 WebSearch / WebFetch 等联网工具兜底**。
4. **严禁基于通用知识凭空作答 / 编造**。

### 4.3 部分命中场景

如果有部分命中（虽然命中数较少但确实相关），照常基于命中片段产出引用式回答；不要因为命中数少就拒答，但必须明确标注命中文档数。

---

## 5. 禁止行为

- ❌ **禁止虚构链接、文件路径、下载地址**：链接必须来自检索返回的字段。
- ❌ **禁止使用 `/teams/{team_id}/docs/{xxx}` 这种早期 docs 模板**：会 404；按 §6 表格按 `target_type` 分流。
- ❌ **禁止编造知识库中不存在的内容**。
- ❌ **禁止在没有引用支撑的句子里下断言**。
- ❌ **禁止把完整 Token / 用户私密信息回显给用户**。
- ❌ **禁止把所有角标 `[X]` 堆在文末**：必须内联。
- ❌ **禁止使用 `[citation:X]` 这种网页角标语法**：WorkBuddy 不渲染，必须用学术风 `[1]` `[2]`。
- ❌ **禁止把「参考资料」写成裸链纯文本**（如 `🔗 https://...`）：必须是可点的 Markdown 链接 `[标题](url)`。
- ❌ **禁止跨越知识库说事**：不要拿 A 公司知识库的内容回答 B 公司的问题。
- ❌ **默认禁止使用 WebSearch / WebFetch 等联网工具**：`mode=standard` 知识库无果时直接拒答。**唯一例外**：`mode=competitive` 竞品对比链路可走站外通道（见 §3.3 / `competitive-analysis.md`）。

## 6. 链接生成

> 🎯 **核心规则**：按 `target_type` 区分**云知 1.0**（旧版团队文档 / 网盘节点）和**云知 2.0**（乐享 AI 知识库条目），分别使用不同的 URL 模板。
> ❌ **不要再用** `/teams/{team_id}/docs/{xxx}` 这种早期 docs 模板——实测 404。

| `target_type` | 文档版本 | URL 模板 |
|---|---|---|
| `disknode` | **云知 1.0**（旧版团队文档 / 网盘节点） | `https://{domain}/docs/{target_id}` |
| `kb_entry` | **云知 2.0**（乐享 AI 知识库条目） | `https://{domain}/pages/{target_id}` |
| `kb_smartsheet` | 云知 2.0 智能表 | `https://{domain}/pages/{target_id}` |
| `attachment` | 附件 | 不出 URL，调附件下载接口 |
| `ai_external_doc` | 外部抓取的公开文档 | 用原文档自带 URL，或不附链接 |

- `{target_id}` 取检索返回的 `chunks[].target_id`。
- `{domain}` 优先取检索返回里的 company 域名，缺失时直接用默认 `csig.lexiangla.com`（不要为拿它调 `whoami`）。
- 同一文档可能同时以 `disknode`（1.0）和 `kb_entry`（2.0）召回（双轨期），**优先用 `kb_entry` 版本**。

---

## 7. 质量自检

输出前快速过一遍以下检查：

- [ ] 每个关键论点都至少有一条内联角标 `[X]`（学术风数字，**不是** `[citation:X]`）
- [ ] 「参考资料」每条都是可点 Markdown 链接 `[标题](url)`，且链接全部来自检索返回（无虚构、无裸链纯文本）
- [ ] 正文角标 `[X]` 编号与「参考资料」列表编号一一对应
- [ ] 对比题用了表格、步骤题用了有序列表
- [ ] 同一文档没有被分配到多个角标编号
- [ ] 没有回显完整 Token / 私密信息
- [ ] （`mode=standard`）「信息来源说明」明确标注"仅基于乐享知识库（不使用联网搜索）"；（`mode=competitive`）站内/站外来源分区标注，每条带 P0/P1/P2 + 站内/站外标签
- [ ] （`mode=standard`）知识库无果时按拒答策略处理，未调用 WebSearch / WebFetch；（`mode=competitive`）站外只引白名单官网，无 CSDN/知乎/代理商等黑名单来源
