# 交付状态机

本规则把脚本退出码和未决问题转换为统一交付状态。状态只说明产物完成度，不代表投资、法律或监管结论正确。

## 校验结果

- `0`：检查完成且无拦截项。
- `1`：检查完成但存在拦截项。
- `2`：未完成校验，包括缺少依赖、输入格式不支持或运行错误。
- 未运行：适用且必需的校验门没有执行。
- 无法识别：脚本没有返回约定退出码，或结果无法对应到具体产物。

## READY 必要条件

只有以下条件同时成立，才可以进入 `READY`：

1. 产物路径真实存在，且能够打开或解析。
2. 所有适用校验门均为 0。
3. `open_issues` 为空。
4. 路由表中的所有验收条件均已完成，`acceptance_status` 不含 `pending` 或 `failed`。
5. 所有必需人工检查均已完成；交易结构图必须记录 `SVG 视觉预览` 已完成，不能只依赖 XML 校验。
6. 产物包含外部事实或关键数字时，来源定位完整，信息截止日和报告期已经记录。
7. 产物包含显式公式、评分或估值测算时，`calculation_gate.py` 已返回 0；没有可复算公式但又给出推导结果时，必须保留为 `UNVERIFIED` 或补充可复算底稿。

任一必要条件不成立时不得进入 `READY`。

## 状态转换

| 条件 | `deliverable_status` | 对用户的表述 |
|---|---|---|
| 所有 READY 必要条件均成立 | `READY` | 已完成约定校验，可以交付 |
| 任一适用校验门为 1、`open_issues` 非空或验收条件失败 | `DRAFT_WITH_BLOCKERS` | 已生成草稿，但仍有明确拦截项 |
| 任一必需校验门为 2、未运行或无法识别，或产物、来源定位、验收状态、必需人工检查尚未确认 | `UNVERIFIED` | 已生成产物，但校验未完成 |

不适用的校验门应记录为 `not_applicable`，不参与状态计算。不得用“不适用”掩盖缺少输入或运行失败。

## 最多三轮

每项产物采用“校验、修复、复检”循环，最多三轮：

1. 第一轮运行适用校验门，把退出码、文件、验收条件和问题写入运行清单。
2. 能在当前材料和能力范围内修复的，修复后进入下一轮；需要用户补充的，直接列入 `open_issues`。
3. 第三轮后仍出现退出码 1、2、未运行或无法识别时，停止自动循环，保持 `DRAFT_WITH_BLOCKERS` 或 `UNVERIFIED`。

第三轮仍未通过的产物不得宣称为终稿，也不得用措辞弱化拦截项。用户补充新材料后，可以作为新的运行继续处理，并保留此前清单。

## 状态优先级

`UNVERIFIED` 高于 `DRAFT_WITH_BLOCKERS`，`DRAFT_WITH_BLOCKERS` 高于 `READY`。同一工作流包含多个产物时，以其中最保守的状态作为整次运行的 `deliverable_status`。
