# 长期记忆协议

> 本文件定义所有 skill 如何判断「哪些用户信息值得写入长期记忆」。
> 每个 skill 在自己的 SKILL.md §C 中引用本协议，并列出该 skill 的专属触发条件。

---

## 0. 存储位置

```
~/.workbuddy/career-broker/<rtx>/memory.md
```

- 仅存当前设备本地，不自动上传云端
- 文件按 Markdown 格式组织，含固定段落
- rtx 从登录态取，取不到时用 `unknown` 占位

---

## 1. 记忆分层

| 层 | 内容 | 更新策略 |
|---|---|---|
| **画像** | 最近一次 PP 生成的完整 profile_compact | 每次 PP.A5 覆盖旧内容 |
| **关键意向 & 偏好** | 用户在对话中表达的明确方向、驱动力、卡点、岗位偏好 | 追加（带时间戳 + 来源 skill） |
| **测评数据** | 最近一次职业DNA测评结果摘要 | 每次 AC.M1/T6 覆盖旧内容 |
| **关键经历片段** | 对话中透露的、但画像可能未覆盖的具体经历 | 追加 |

---

## 2. 通用写入规则（所有 skill 遵守）

写入前必须同时满足 **3 个条件**：

| # | 条件 | 反例 |
|---|---|---|
| 1 | 用户**在描述自己的情况**（不是泛泛而谈、不是问规则） | ❌ "活水一般多久能走完"（这是问规则） |
| 2 | 表述带有**明确的个人倾向/状态/经历** | ❌ "我想了解一下产品方向"（太泛，没到"意向"级别） |
| 3 | 信息在**当前对话的未来会反复用到**，值得跨会话记住 | ❌ "今天中午吃啥"（一次性上下文） |

**满足以上 3 条 → 写入**（静默操作，不告知用户"我已经记下来了"，不打断对话流）。

**不满足 → 不写**（宁可少记，不把聊天灌进去）。

---

## 3. 禁止写入的内容（红线）

- ❌ 薪酬数字 / 职级 / 梯队排名 / 绩效结果
- ❌ 他人的个人信息（同事 RTX、leader 评价等）
- ❌ 未公开决策信息（架构调整、HC 变动等）
- ❌ 用户的负面情绪发泄原文（改写为客观描述）
- ❌ 整段对话原文（只写凝练的关键信息，不 dump 原文）

> 仅存储在当前设备本地

- [来源skill] <一句话概括经历>

---

## 5. 写入时注意

- **画像段**：直接覆盖整段，不带旧内容
- **意向 & 经历段**：追加到对应日期的最后一行，向前追加
- **测评段**：覆盖整段
- **跨 skill 引用**：任何 skill 在对话开头，可以先 `Read` 此文件，看有没有可供当前对话用的 context
- **文件不存在时**：创建目录 + 文件（含表头）
- **rtx 取不到时**：跳过写入，不报错
