# 敏感问题前置过滤规则

> 这是 career-qa skill 进外部问询服务之前的硬规则，命中任一条**直接拒答**，不发请求。
> 设计原则：用关键词 + 正则，**不依赖 LLM 判断**——避免被 prompt 注入绕过。

---

## 1. 类别 A · 公司人员统计 / 名单

**目的**：员工不应通过本工具获取公司内部统计数据 / 人员名单。

**触发条件**（命中任一）：
- 询问词：`多少人 | 几个人 | 占比 | 比例 | 总数 | 人数 | 名单 | 谁在 | 哪些人 | 列表 | 都有谁`
- 同时（AND）出现对象：`活水 | 转岗 | 离职 | 招聘 | 入职 | 岗位 | 部门 | HR`

**示例命中**：
- "现在有多少人在活水流程中？"
- "今年校招招了几个人？"
- "我们部门有谁在转岗？"
- "活水匿名池有多少候选人？"

**拒答话术**：
```
这类问题我不太方便回答。
```

## 2. 类别 B0 · 薪酬零讨论

**触发条件**：出现任一薪酬词即拦截，不要求同时出现“多少 / 范围”等询问词。

关键词：`工资 | 薪资 | 薪酬 | 月薪 | 年薪 | 奖金 | 年终 | 年终奖 | 调薪 | 加薪 | 涨薪 | 涨幅 | package | offer 金额 | 股票 | RSU | 给钱 | 收入 | 回报`

**示例命中**：
- "活水可以涨薪吗？"
- "活水后会调薪吗？"
- "这个岗位给钱大方吗？"

**拒答话术**：
```
我不太方便回答这类问题。
```

## 3. 类别 B · 个人薪酬 / 福利金额（兼容旧规则）

**触发条件**：
- 询问词：`多少 | 范围 | 标准 | 怎么算 | 区间`
- 同时出现：`工资 | 薪资 | 薪酬 | 月薪 | 年薪 | 奖金 | 调薪 | package | offer 金额 | 年终奖 | 加薪 | 涨薪`

**说明**：B0 已覆盖绝大多数薪酬问题；本规则保留用于兼容旧测试和更具体的金额类问法。

**示例命中**：
- "T7 工资范围是多少？"
- "校招产品经理 package 大概多少？"
- "活水后会调薪吗，能调多少？"

**拒答话术**：
```
我不太方便回答这类问题。
```

## 4. 类别 C · 他人隐私

**触发条件**：
- 出现具体人名 / RTX（识别规则：纯英文 RTX 形如 `[a-z][a-z0-9_]{2,}`，或对话中明确标注的中文姓名）
- 同时出现：`工资 | 薪资 | 职级 | 评估 | 自评 | 简历 | 经历 | 项目 | KR | OKR`

**示例命中**：
- "张三的职级是什么？"
- "lisi 的工资是多少？"
- "wangwu 在做什么项目？"

**拒答话术**：
```
我只能帮你看你自己的信息，他人的不行。
```

> 注意：这条规则**有误伤风险**（用户用第三人称提自己也会被拦）。可以宽松一点：只在"工资 / 职级 / 评估"这种敏感词出现时才严格拦。

## 5. 类别 E · HR 决策 / 评级预测

**目的**：避免 RAG 给出"该不该 / 能不能"这种需要个性化判断的答案——这超出知识库能力。

**触发条件**：
- 询问词：`该不该 | 能不能 | 要不要 | 值不值 | 适不适合`
- 同时（OR）出现：`转 | 走 | 接 offer | 跳槽 | 离职 | 调岗 | 转岗 | 活水 | 申请`

**示例命中**：
- "我现在该不该走活水？"
- "这个 offer 我接不接？"
- "我适不适合转产品？"

**拒答话术**：
```
这种判断很个人化，我没法替你拍板。或者用「职业咨询」让我帮你梳理思路。
```

## 7. 类别 G · 员工梯队 / 排名 / 同事对比

**目的**：禁止任何形式的「你 vs 同事 / 你 vs 部门 / 你 vs 同期」对比和位次描述。这类信息一是数据敏感，二是即使能给也对"具体到 ta 这个人"无真实参考意义。

**触发条件**：
- 询问词：`排名 | 排第 | 梯队 | 头部 | 中部 | 尾部 | 同期 | 同 level | 同职级 | 比我 | 对比 | 横比 | 赛马 | 明星员工 | 末位 | 淘汰 | TOP | 高潜 | 梯队池`
- 同时出现：`我 | 你 | ta | 同事 | 员工 | RTX | 部门 | BG | 组里 | 团队`

**示例命中**：
- "我在我们部门排名第几？"
- "跟我同期的人都升到 T9 了吗？"
- "我这画像在司内属于头部吗？"
- "我们组谁是高潜？"
- "末位淘汰名单都有谁？"

**拒答话术**：
```
梯队、排名、同事对比这些我不碰——一是数据敏感，二是对'你这个具体人'没有真实参考意义。咱聊聊你能控制的事。
```

## 8. 类别 H · 公司 / 岗位 / BG 层面薪酬延伸

**目的**：B 类拦的是「我自己 / 张三」个人薪酬。本类补「这个职级一般多少 / 这个 BG 给得高吗 / 跳出去能涨多少」这种公司/岗位/外部对标层面的薪酬讨论。**任何薪酬维度，腾讯不让谈**。

**触发条件**：
- 询问词：`职级 / level / T7-T12 / BG / 业务群 / 部门 / 岗位 / 团队 / CSIG / TEG / IEG / PCG / WXG / CDG / FiT / S1 / S2 / 腾讯 / 司内 / 公司 / 外面 / 业内 / 这条线 / 这个方向`
- 同时出现：`薪资 / 薪酬 / 工资 / 年薪 / 月薪 / package / 年终 / 年终奖 / 奖金 / 股票 / RSU / 给钱 / 给得 / 给的 / 大方 / 抠门 / 涨薪 / 调薪 / 涨幅 / 钱 / 收入 / 回报 / 几个月`

**示例命中**：
- "T8 在腾讯一般年终奖几个月？"
- "CSIG 给钱大方吗？"
- "活水到 IEG 涨幅一般多少？"
- "腾讯这个方向跟外面比待遇怎么样？"

**拒答话术**：
```
薪酬这事儿我不能聊——不论是个人、岗位、职级还是 BG 层面。我这儿能帮你看的是方向、机会、画像匹配。
```

## 9. 类别 I · 劳动 / 孕产 / 合规争议

**目的**：这类问题容易诱导模型输出法律适用判断、对抗性流程路径、证据建议，或直接评价具体角色/团队责任。职业经纪人不能做这些。

**触发条件**（命中任一）：
- 法律/争议词：`劳动法 | 仲裁 | 起诉 | 取证 | 维权 | 违法 | 合法吗 | 合不合法 | 投诉 | 举报 | 赔偿 | 裁员赔偿 | 强制加班 | 加班费`
- 孕产争议词：`怀孕 | 孕期 | 产检 | 哺乳期 | 怀孕歧视`
- `产假` 只有与 `不给 / 怎么办 / 不敢 / 具体角色 / 歧视 / 辞退 / 调岗 / 降薪 / 必须 / 强制` 等争议语境同现时拦截；纯问“产假多少天”可作为制度问询处理。

**示例命中**：
- 用户围绕孕产安排询问是否要告知某个角色。
- 用户围绕工作时段消息、加班、费用等追问法律适用。
- 用户询问是否要走对抗性流程。
- 用户要求判断某个经历是否属于歧视或争议。

**温暖边界话术**：
```text
这件事听起来让你很有压力，先别急着把责任都放到自己身上。

我不能替你做法律判断、流程建议，也不评价具体角色或团队责任。如果你只是想了解资料，可以看公开制度或法律法规原文；我这里不做适用判断。

职业发展这部分，我可以陪你先把能控制的事拆开：身体和精力、沟通边界、节奏安排、后续选择。你现在最担心的是哪一块？
```

**禁止输出**：
- 任何法律适用判断或对具体角色/团队责任的断言。
- 任何对抗性流程、证据收集或具体渠道引导。
- 任何压迫用户立刻行动或替用户下结论的表达。

## 10. 实现建议

```python
# 伪代码
SENSITIVE_RULES = [
    {
        "name": "类别A 人员统计",
        "any_of": ["多少人", "几个人", "占比", "比例", "总数", "人数", "名单", "谁在", "哪些人", "列表", "都有谁"],
        "and_of": ["活水", "转岗", "离职", "招聘", "入职", "岗位", "部门", "HR"],
        "reply": "这类问题我不太方便回答。"
    },
    # 其余类别同结构；劳动/孕产/合规争议使用温暖边界话术，不发外部问答服务
]

def filter_query(query: str) -> str | None:
    """返回 None = 通过；返回 str = 命中后的拒答话术"""
    for rule in SENSITIVE_RULES:
        if any(k in query for k in rule["any_of"]) and any(k in query for k in rule["and_of"]):
            return rule["reply"]
    return None
```

**位置**：`scripts/sensitive_filter.py` 实现，`ask_qa.py` 在路由到 recruit-mcp 或小Q 之前先调它。
