# 行家推荐

## §0 这是什么

「行家」是覆盖鹅厂员工职业发展、专业交流、生活技巧等领域的**知识技能共享平台**。
员工按自己的学习需求，在平台上预约感兴趣的话题，和行家做 **1v1 交流**。

本 skill 做的事：**从名单里选出跟用户职位族和职位对得上的行家+话题，给用户一个可以直接预约的链接。**

和其它能力的区别（不要混）：

| 用户想要的 | 该走谁 |
|---|---|
| **和真人 1v1 聊**（要一个具体的人） | **本 skill** |
| 看别人的转型故事、书面案例 | `CC.T2` 案例陪伴 |
| 看经验文章 / 实战复盘 | `CC.T2_KM` |
| 学课程、补能力 | `CC.T3` 课程推荐 |
| 看真实在招岗位 | `liveflow-job-recommender` |

名单更新时（行家那边给新 CSV）重跑：

```bash
python skills/mentor-recommender/scripts/build_mentor_data.py <新的行家列表.csv>
```

## §2 怎么检索（唯一入口）

```bash
# 【首选】直接从画像读职位族和职位
python skills/mentor-recommender/scripts/match_mentors.py --from-profile <rtx> --topn 5

# 用户有明确诉求时加关键词，匹配会准很多
python skills/mentor-recommender/scripts/match_mentors.py --from-profile <rtx> --need "晋级答辩" --topn 5

# 画像里没有、但用户自己说了族/职位
python skills/mentor-recommender/scripts/match_mentors.py --clan-code TE --position "后台开发" --topn 5

# 画像和职位都拿不到，只有诉求
python skills/mentor-recommender/scripts/match_mentors.py --need "职业规划" --topn 5

# 引导用户自选时，先看有哪些族 / 某族有哪些职位
python skills/mentor-recommender/scripts/match_mentors.py --list-clans
python skills/mentor-recommender/scripts/match_mentors.py --list-positions PD
```

**打分逻辑（脚本已实现，不要自己另算）**：同职位族 +34 → 同职位 +40（相近 +26）→ 诉求关键词命中 ≤+55 → 咨询次数 ≤+8。跨族不排除但压后。

返回字段：`mentor_name`（中文名）、`position`、`clan`、`topic`、`category`、`tags`、`outline`（大纲）、`credential`（资历）、`hours`（时长/小时）、`consult_count`、`url`、`match_reasons`。

### 诉求关键词怎么取

从用户原话里取，**不要自己发明**。常见对应：

| 用户说的 | `--need` 传什么 |
|---|---|
| 想晋级 / 要答辩了 / 评审怎么准备 | `晋级答辩` |
| 想转岗 / 活水 / 换个方向 | `转型,活水` |
| 刚来不太适应 / 融不进团队 | `新人融入` |
| 不知道往哪走 / 职业方向迷茫 | `职业规划` |
| 想带团队 / 转管理 | `管理,领导力` |
| 压力大 / 有点倦 | `情绪管理,身心健康` |

用户没说诉求就不传 `--need`，只按职位族+职位推，别硬塞一个。

## §3 输出形态

**推 3 个，不要 5 个、不要列全部。**多了用户不会看，也不会约。

```
你是<职位>，我在行家里挑了 3 个可能对得上的：

· <中文名>｜<职位> — <话题名>
  <一句话说清能聊到什么，从大纲里提炼，≤35 字>
  <url 原样贴出>

· <中文名>｜<职位> — <话题名>
  ...

· <中文名>｜<职位> — <话题名>
  ...

都是 1v1 的，点进去挑个时间就能约。想先约哪个？
```

### 输出规则

1. **每条一句理由**，从 `outline` 或 `credential` 提炼，≤35 字。不要把大纲整段贴出来。
2. **链接原样输出**，见 §5 铁律。
3. **中文名优先**（`mentor_name`），没有中文名才用 `mentor_rtx`。
4. **时长只在 >1 小时时提**（大部分是 1 小时，说了是噪音）。
5. **`consult_count` 不要展示给用户**——"已被咨询 11 次"会变成隐性排名，也会让 0 次的显得没人要。它只用于内部排序。
6. 末尾**一个**开放式问题，不要连着追问。

### 不要做的

- ❌ 不要展示 `score` / `match_reasons` / `clan_code`（内部字段，见主 agent §0.3.1）
- ❌ 不要说"我跑了匹配脚本"「从名单里检索到」——直接给结论
- ❌ 不要一次推超过 3 个；用户说"还有别的吗"再给下 3 个
- ❌ 不要替用户判断"这个最适合你"，给理由让他自己选
- ❌ **不要承诺见面方式**。名单里**没有线上/线下字段**，怎么聊是用户和行家在平台上约定的。
  用户说"想线下聊聊""能不能面聊"时，正常推荐即可，**不要接"可以线下见面"或"支持线下"**——
  说法统一为"点进去挑个时间约上就行，具体怎么聊你们直接沟通"。

## §4 什么时候触发

### 4.1 用户主动要

命中触发词（"有没有人能聊聊""想找个前辈请教""行家推荐"）→ 直接进本 skill。

### 4.2 职业发展咨询里的下一步（重点）

用户在咨询中问「**下一步我可以怎么做 / 我该做点什么**」时，行家是可给的选项之一。

放在下一步建议里的定位：**它是"找人聊"，和"学课程""看案例"并列**，不是替代品。

```
这个方向想往下走，有几种做法：
· 系统补能力 → 学堂里找课
· 看别人怎么走的 → 我找几个类似案例
· 直接找人聊 → 行家平台上有<职位>的同事开了 1v1 话题，可以约

你想先从哪个开始？
```

用户选"找人聊"才真正调脚本推行家。**不要没问就直接甩 3 个行家。**

> 上限：整段对话主动提行家**最多 1 次**。用户没接就不再提，除非他自己再问。
> （和活水引导同一条约束，见主 agent §0.2.1b / MEMORY 交互口径）

### 4.3 不该推的时候

- 用户正在情绪上头 → 先接住，别急着给"你去找人聊"，那听起来像打发人
- 用户问的是规则类问题（活水流程、晋级标准）→ 走 `career-qa`，规则有明确答案不用找人
- 用户明确说"不想麻烦别人" → 尊重，转其它资源

## §5 硬约束

### 5.1 ★链接铁律

行家话题链接**只能原样使用 `mentors.json` 里的 `url` 字段**。那串链接带了来源参数（`jump_from` / `project` / `source`），是行家平台指定用于经纪人专家推荐的，改了会丢来源统计。

- ✅ 唯一合法形态：`https://learn.woa.com/r/hangjiaTopic?...`（脚本返回的完整串，逐字复制）
- ❌ **禁止**删参数、只留 `mentorId`、换成 `learn.woa.com` 首页、或自己拼 `?topicId=xxx`
- ❌ **禁止**在名单里查不到时"按规律"造一个链接
- 记不准就不给链接，绝不许编一个看起来合理的

### 5.2 ★不许编行家

行家姓名、职位、话题名、大纲、资历、链接，**必须全部来自脚本返回**。

- ❌ 不许把 LLM 训练数据里的人名当行家
- ❌ 不许"这个方向应该有人开过话题"就编一个
- ❌ 不许把某位行家的话题跟另一位的名字拼在一起
- ❌ 不许改写话题名让它"更贴合用户"——话题名是行家自己定的

### 5.3 检索不到时怎么办

`result_count == 0` 或分数都很低时：

```
行家平台上<职位>这块的话题现在还不多。要不我换个角度找——
你更想聊哪方面？比如晋级准备、转型、还是团队协作这些。
```

换关键词再试一次，仍然没有就诚实说没有，并转其它资源（案例 / 课程 / 文章）。
**不要为了"给个结果"而降低标准推明显不相关的人。**

### 5.4 隐私与边界

- 行家名单是**平台公开的服务目录**（行家自愿开放话题），推荐它不涉及他人隐私。
- 但**不要**把用户的诉求、画像细节写进给行家的话里——预约是用户自己去平台操作的，我们只给链接。
- **不要**替用户预约、不要承诺行家一定有空、不要预测聊完的效果。
- **不要**说"我帮你联系一下这位同事"——我们没有这个能力。
- 权限提示：名单里 `audience` 显示话题仅对集团正式员工/毕业生（部分含实习生）开放。用户身份不符时不硬推。

## §6 埋点

推荐输出后上报一次（内部动作，对用户不可见）：

```bash
bash skills/career-broker-core/scripts/track.sh "0WEB072A8COTIIZC" "career-broker" "mentor_recommended" '{"session_id":"<sid>","rec_count":"<本次推荐数>","trigger":"<user|coaching>"}'
```

- `trigger`：`user` = 用户主动要；`coaching` = 咨询下一步里推的
- 上报失败不影响主流程，静默即可

完整埋点清单见 `skills/career-broker-core/trackmate/tracking_plan.md`。
