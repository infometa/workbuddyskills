# 行家名单维护说明

> 面向**维护本专家包的人**，不是给用户看的。

## 名单从哪来

行家平台侧人工导出 CSV 给我们，**不是接口对接**，所以名单是**静态快照**，不会自动更新。

当前快照：**322 个话题 / 288 位行家**，覆盖 5 个职位族。

| 职位族 | 话题数 |
|---|---|
| 产品/项目族（PD） | 123 |
| 技术族（TE） | 88 |
| 专业族（SC） | 59 |
| 市场族（MA） | 32 |
| 设计族（DG） | 20 |

## 名单更新流程

行家那边给了新 CSV → 跑一条命令就行：

```bash
python skills/mentor-recommender/scripts/build_mentor_data.py <新的行家列表.csv>
```

脚本会：
- 只保留「已上架」话题（下架的直接丢）
- 丢掉链接前缀不是 `https://learn.woa.com/r/hangjiaTopic?` 的行（宁可少一条，也不改写成"看起来合理"的地址）
- 把「族」列的 `技术族（TE）` 解析出简码 `TE`
- 截断超长的大纲（220 字）和资历（160 字），避免单条把上下文吃满
- 按 族 → 职位 → 咨询次数 稳定排序，让每次重建的 git diff 可读

跑完检查输出的「跳过」统计。如果 `链接非法` 不为 0，先去问行家那边链接格式是不是改了，**不要自己猜着改脚本**。

## CSV 必须有的列

列名与行家平台导出保持一致，改了列名脚本会读不到：

```
行家姓名 / 职位 / 族 / 话题名称 / 分类 / 时长 / 咨询次数
大纲 / 资历 / 标签 / 话题权限 / 话题状态 / 下架时间
加参数url，请使用这个链接在“经纪人专家”中推荐行家
```

最后那列的**列名很长且带中文引号**，是行家平台原样给的，不要"顺手改简洁"。

## 为什么链接不能动

`url` 那串带了 `jump_from=zpzj&project=hj&source=hjyy` 三个来源参数，是行家平台专门给「经纪人专家」这个渠道的标记，用来统计从我们这里过去的预约量。删参数或自己拼链接会丢掉这个归因。

所以脚本和 SKILL.md 都把它当铁律：**原样复制，不改写、不精简、不换域名**。
`skills/career-broker-core/scripts/check_urls.py` 里也登记了三条黑名单规则挡编造写法（已做故障注入验证）。

## 和画像的字段契约

匹配靠 profile.json 的 `basic` 里两个字段：

| 用途 | 实测字段（驼峰） | schema 文档写法（下划线） |
|---|---|---|
| 职位族 | `clanName`（如 `产品/项目族（PD）`） | `clan_name` |
| 职位 | `positionName`（如 `产品策划`） | `position_name` / `position` |

**两种命名都要兼容**——实测接口返的是驼峰，而 `profile-schema.md` 里写的是下划线。
`match_mentors.py` 的 `read_profile()` 两种都读一遍，读不到就返回 None 走降级，不猜。

好消息是：画像 `clanName` 的值和 CSV「族」列**逐字一致**（都是 `产品/项目族（PD）` 这种带括号简码的形式），所以不用做映射表。

## 打分权重

用户的要求是「职位族和职位要合适」，所以权重这么定：

| 因素 | 分值 |
|---|---|
| 同职位族 | +34（跨族 -12，不排除但压后） |
| 同职位 | +40（相近职位 +26，职位相关 +18，部分相关 +10） |
| 诉求关键词命中 | 话题名 +22 / 标签 +18 / 分类 +14 / 大纲 +8，上限 55 |
| 咨询次数 | +min(次数, 8) |

咨询次数上限压到 8 分，是为了**不让热度盖过匹配度**——被咨询 30 次的通用话题不该排在同职位的精准话题前面。

## 已知取舍

- **跨族不硬过滤**：有些话题（情绪管理、职业规划）是通用的，硬过滤会让小族（设计族只有 20 条）几乎推不出东西。做法是跨族扣分压后，而不是排除。
- **职位近义词表是手工维护的**（`POSITION_KIN`），只做保守扩展。宁可少匹配，也不要把设计岗算成开发岗。名单里出现新职位时可以按需补。
- **大纲被截断到 220 字**：最长的原文有 1113 字，全量进上下文不值得。SKILL.md 里要求只从大纲提炼一句 ≤35 字的理由，所以 220 字够用。
