# 反问问题库 · clarify-question-bank

> 自动采集只能拿到前 3 维（基础 / 专业 / 经历），第 4 维「发展动机」和第 5 维「当前卡点」必须靠**反问**。
> 强约束：一次最多 2 问，最多 3 轮，避免压迫感。

---

## 0. 提问总原则

| 原则 | 解释 |
|---|---|
| **先动机后卡点** | 动机是正向的，卡点偏负向，先正后负不让人一上来就吐苦水 |
| **从开放到聚焦** | 第一轮开放题、第二轮选择题、第三轮兜底题 |
| **可拒绝** | 用户说「不想答 / 先这样」立刻停下，把当前 profile 标 `partial:true` |
| **不教育** | 不评价用户的回答（"这个想法不错"也不行） |
| **不灌鸡汤** | 不说"加油 / 没问题"，只复述+确认 |

## 1. 维度 4 · 发展动机（按轮次取题）

### 第 1 轮（必问，二选一）

| 题号 | 问题 | 用途 |
|---|---|---|
| M1.1 | "如果未来 1-2 年只能挑一个发力点，你更想往**技术深度**走（在当前序列继续上职级），还是**技术广度**走（探索新方向 / 跨序列）？" | 锁定方向 |
| M1.2 | "现在工作让你 0-10 分打分，几分？最影响这个分的是什么？" | 拿满意度 + 主因 |

### 第 2 轮（选问，按用户回答展开）

| 题号 | 问题 | 触发条件 |
|---|---|---|
| M2.1 | "刚才说想往「__」方向走，是有具体想做的事，还是先有个大方向？" | M1.1 答了方向 |
| M2.2 | "8 分以上：是什么把你留在这？6 分以下：什么变了你会想动？" | M1.2 答了分数 |

### 第 3 轮（兜底，可不问）

| 题号 | 问题 | 用途 |
|---|---|---|
| M3.1 | "如果让你描述一种「理想工作状态」，那是什么样的？" | 拿职业锚 |

> 把 M1+M2 的回答聚合成 `motivation.preferred_directions[]` 和 `motivation.satisfaction_reason`。

## 2. 维度 5 · 当前卡点（按四类取题）

### 第 1 轮（必问，开放题 1 题）

| 题号 | 问题 |
|---|---|
| B1 | "现在最让你觉得「卡住了」的事是什么？可以是技术、业务、人、动力，任一个都行。" |

### 第 2 轮（聚焦题，按 B1 回答归类）

四类卡点对应 4 个分支题，**只问归类后的那一题**：

| 归类 | 题号 | 聚焦问题 |
|---|---|---|
| 技术卡 | B2-Tech | "卡在「学不到新东西」、「现有技术栈固化」、还是「新方向没资源做」？" |
| 业务卡 | B2-Biz | "是「业务方向不明朗」、「价值感低」、还是「项目天花板看到了」？" |
| 关系卡 | B2-Rel | "是「和上级方向不一致」、「团队配合不顺」、还是「向上的资源拿不到」？需要的话可以匿名描述。" |
| 动力卡 | B2-Mot | "是「累」、「无聊」、还是「看不到下一步」？" |

### 第 3 轮（兜底题，可不问）

| 题号 | 问题 |
|---|---|
| B3 | "如果这个卡点解决了，下一年你会做什么不一样的事？" |

> 把 B1+B2 的回答聚合到 `blockers.tech_blocker / business_blocker / relation_blocker / motivation_blocker`。

## 3. 提问模板（直接套用）

### 第一次反问（动机 + 卡点开放题各 1）

```
我把你的基础信息、自评、TAPD / 工蜂里能用的部分拉了一遍，剩下两块要听你自己说：

1) 如果未来 1-2 年只能挑一个发力点，你更想往**技术深度**走，还是**技术广度**走？
2) 现在最让你觉得「卡住了」的事是什么？技术、业务、人、动力，任一个都行。

不想答可以先跳过，画像可以分阶段补。
```

### 第二次反问（按上一轮答案聚焦）

```
你刚才说 ___，我想再确认一下：

1) [M2 系列里挑一题]
2) [B2 系列里按归类挑一题]
```

### 第三次反问（兜底，可不发）

```
最后一组（可跳过）：
- 描述一个你心里的「理想工作状态」？
- 假如那个卡点解了，明年你会做什么不一样？
```

---

## 4. 用户拒答处理

| 用户表达 | 处理 |
|---|---|
| "不想答 / 跳过 / 先这样" | 立刻停止反问，profile 标 `partial:true`，告诉用户"OK，画像可以后面补" |
| "不太懂这个问题" | 换更具体的版本（用 M1.2 的"打分法"代替 M3.1 的"理想状态"） |
| 答得很短（< 10 字） | 不追问，直接收下，**不**说"能再展开吗" |
| 答得很情绪化 | 复述+共情，不评判：「听起来这块挺让你累的，我先记下来」，不展开 |

## 5. 反问后必做

```
1) 把回答 merge 到 profile.json 对应字段
2) 标记 captured_by="user_clarify" 和 captured_at=<时间戳>
3) 重新渲染 profile_summary.md
4) 给用户看："这是更新后的版本，对吗？"
5) 用户确认 → skill 结束，提示："这份画像可以作为「职业咨询 / 内部机会推荐」的输入"
```
