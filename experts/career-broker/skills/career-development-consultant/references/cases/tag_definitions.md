# 案例库标签字典 v1.0

> **用途**：本文件定义所有案例（`all_cases.json`）可用的标签。
> **强制原则**：案例只能用本文件列出的标签，**不允许自由文本**——否则双轴召回精度会失控。
> **扩展**：发现新场景时，先在本文件加标签，再去打标。不要先打标再补字典。

---

## 0. 案例的 5 个标签轴

每条案例必须打这 5 个轴的标签（轴内可多选）：

| 轴 | 字段名 | 多选？ | 用途 |
|---|---|---|---|
| 阶段轴 | `stage_tags` | ✅ 多选 | 用户处在哪个司龄/角色阶段 |
| 事件轴 | `event_tags` | ✅ 多选 | 用户正在经历的具体事件/触发点 |
| 场景轴 | `scene_tags` | ✅ 多选 | 用户的卡点类型（5 维度） |
| 画像轴 | `persona_tags` | 1-2 个 | 用户的个性/态度类型 |
| 跨度轴 | `span_tags` | ✅ 多选 | 案例的"跨度类型"（用于路径相似度匹配） |

---

## 1. `stage_tags`（阶段轴）— 用户在哪个阶段

⚠️ 阶段 ≠ 司龄。一个 P7 转新岗的人也可能在"新角色前 90 天"。

| 标签 | 含义 |
|---|---|
| `新人前90天` | 校招 / 社招入职 / 实习生前 90 天 |
| `转正前后` | 试用期评估 / 转正阵痛 |
| `1-2年成长期` | 司龄 1-2 年，处在能力快速积累期 |
| `3-5年瓶颈期` | 司龄 3-5 年，常见的活水心理临界点 |
| `5-10年中坚期` | 司龄 5-10 年，技术骨干 / 业务骨干 |
| `10年+资深期` | 老兵期，T11-T13 / 业务专家 |
| `产假休假回归` | 产假 / 长假 / 借调归来后的重新定位 |
| `新角色前90天` | 跨工作室 / 跨BG / IC→leader 等角色切换初期 |

---

## 2. `event_tags`（事件轴）— 用户正在经历什么

| 标签 | 含义 |
|---|---|
| `业务收缩` | 所在业务被砍 / 缩编 / 战略边缘化 |
| `业务承压` | 业务在调整但未明确收缩 |
| `组织调整` | 架构/leader/汇报线变动 |
| `晋升失败` | 答辩没过 / 答辩被卡 |
| `绩效下滑` | 当期绩效 B-/C / 连续低绩 |
| `活水冷却期` | 在 6/12 个月冷却窗口内 |
| `跨BG活水` | 涉及跨 BG 的转岗 |
| `跨行业活水` | 跨行业（如游戏→金融）|
| `跨工作室` | 同 BG 内跨工作室 |
| `跨岗位序列` | 改职能（如 IC→PM、技术→战略）|
| `跟老板调动` | 跟随 leader 一起换组织 |
| `Gigs破局` | 通过轻量项目/任务建立跨组连接 |
| `主动出走` | 业务还行但主动想换 |
| `被动出走` | 业务收缩/被卡导致必须换 |
| `拿offer不跳槽` | 有外部 offer 但选择内部活水 |
| `AI窗口期` | 抓住 AI 浪潮做转型 |
| `复合卡位` | 不裸跳，找"懂A+学B"的中间岗位 |
| `软着陆` | 用业务关联点降低跨界风险 |

---

## 3. `scene_tags`（场景轴）— 用户的卡点类型（5 维度·复用 V2 Excel）

| 标签 | 含义 | 典型问题 |
|---|---|---|
| `身份焦虑` | 对自己"还能不能"的怀疑 | "我都 X 岁/X 年了还能转吗" |
| `路径选择` | 在多条路之间犹豫 | "跨 BG 难还是跨行业难" |
| `决策犹豫` | 临门一脚迟疑 | "要不要走正式流程"、"该跳还是留" |
| `情境特殊` | 特殊触发条件 | "业务在收缩"、"AI 浪潮"、"产假回来" |
| `转型后90天` | 已经换了，正在阵痛 | "绩效折损"、"老毛病复发" |

---

## 4. `persona_tags`（画像轴）— 用户的个性/态度

| 标签 | 含义 | 信号词 |
|---|---|---|
| `🌱开放型` | 主动探索、敢折腾、容忍不确定 | "想试试"、"主动跨"、"从0到1" |
| `🔍挑剔型` | 谨慎、要论证、要看清才动 | "我得想清楚"、"代价是什么"、"不愿付就不付" |
| `🚪被卡型` | 被动局面、想动但被环境卡住 | "想动但被卡"、"司龄/绩效不够"、"Leader 不放" |
| `🍃混合型` | 不同议题下表现不同 | 同时具备多种特征 |

---

## 5. `span_tags`（跨度轴）— 案例的"路径跨度"

用来匹配"我想做和你类似跨度的转型"。

| 标签 | 含义 |
|---|---|
| `同BG同岗位` | 同部门内换组/换业务 |
| `同BG跨部门` | 同 BG 不同部门 |
| `同BG跨岗位` | 同 BG 改职能 |
| `跨BG同岗位` | 换 BG 但岗位序列不变 |
| `跨BG跨岗位` | 换 BG 又改职能 |
| `跨行业` | 出/入腾讯之外的行业（含 MBA 中转）|
| `多次跨度` | 案例本身有 2 次以上跨度（如 A→B→A）|

---

## 6. 写标签的硬规则

1. **每个轴至少打 1 个标签**——5 个轴都不能空
2. **`persona_tags` 最多 2 个**——避免画像描述失焦
3. **不允许自由文本**——遇到本文件没有的情况，先在本文件加标签
4. **case_id 命名规范**：`<事业群缩写>-<方向缩写>-<编号>`，例 `PCG-WXG-01`
5. **二手脑补案例必须标 `is_real: false`**——避免 Agent 当真人原话引用

## 7. 召回逻辑（给 Agent 用，不是给 Python）

教练在对话中推断用户当前状态后，按"轴交集"召回案例：

```
推荐召回顺序（精度从高到低）：
1. stage + scene + persona 三轴交集 → 精确命中
2. scene + persona 双轴交集 → 次优
3. event + persona 双轴交集 → 次优
4. scene 单轴 → 兜底
5. 全库相似度 → 最后兜底
```

**关键原则**：召回失败时**降级**而不是**放弃**——案例库永远要给出"虽然不太一样、但也许有启发"的内容。
