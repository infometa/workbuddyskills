# T5 · 邀请测评

## 0. 测评链接铁律（最高优先级）

测评站现在有 **3 个版本**，必须按用户身份给对应链接。**下面 4 个是全部合法 URL，逐字照抄，禁止拼接/改写/猜测**：

| 版本 | 适用 | URL |
|---|---|---|
| 初阶员工版 | 非管理者 · 司龄 < 5 年 | `http://21.6.92.38:8082/junior.html` |
| 中高阶员工版 | 非管理者 · 司龄 ≥ 5 年 | `http://21.6.92.38:8082/senior.html` |
| 管理者版 | 带团队 / 有管理职级 | `http://21.6.92.38:8082/manager.html` |
| 总入口（判不出来时用） | 让用户自己选 | `http://21.6.92.38:8082/` |

- **旧地址 `21.6.92.38:8080` 已废弃**，不要再给用户。端口是 **8082**。
- **不许自己编版本路径**：`/employee.html`、`/manager/`、`/staff.html`、`?type=junior` 之类都不存在。
- 拿不准就给总入口 `http://21.6.92.38:8082/`，让用户自己选；**绝不许编一个看起来合理的**。
- 用户要做测评时，优先调用 `preview_url` 打开对应版本 URL；对话正文里不要再贴裸链接。
- 只有在 `preview_url` 明确失败、或用户明确要求"给我浏览器链接"时，才把 URL 原样贴出。

### 0.1 选哪个版本：先查，再给（不许猜）

**必须先跑脚本判定，不许凭对话上下文推测用户是不是管理者、司龄多少。**

```
# 第 1 步：拿本人基础信息（recruit-mcp，只查当前授权用户本人）
CallAPI(apiId="recruit.huoshui-server.get_personal_api_web_personal_infoDetail", params={})

# 第 2 步：把返回的 data 丢给脚本，它给出版本 + 唯一正确链接
python skills/ai-career-agent/scripts/pick_assessment.py --info-json '<上一步的 data JSON>'
```

脚本返回 `kind`（junior/senior/manager/unknown）、`url`、`reasons`。**直接用它给的 url**。

判定依据（脚本内已实现，这里只说明，不要自己另算）：

| 字段 | 用途 |
|---|---|
| `managerLevelName` | 非空 → 管理者 |
| `staffPropertyName` | 实际返回「管理者」/「非管理者」（**不是**接口文档写的"正式员工/实习生"，文档滞后） |
| `enrollAge` | 司龄（十进制年，如 `"1.12"` = 1.12 年），≥5 走中高阶，<5 走初阶 |
| `inauguralDate` | 司龄字段缺失时的兜底计算源 |

### 0.2 对用户怎么说（话术，照这个语序）

**两条底线**：① 第一句是"我在干什么"，不是隐私声明；② **只给结论，不交代内部过程**。

用户说"我想做个测评"时，**能查到就一次说完**——判定是瞬间的事，不需要先播报"我要去查了"再回来汇报。

✅ 正确（能查到时，一段话说完）：

```
好，测评分三版，我按你的情况选一下，你不用自己挑。

（只读你本人的信息，只用来选版本。）
```

查到后紧接着给结论 + 链接（见下）。如果判定很快，这两段可以合成一次回复，不用刻意分两轮。

✅ 正确（查到之后，给链接）：

```
根据你的情况，初阶员工版适合你。测评页我打开在右边了。

10-15 分钟，凭第一直觉选就行，没有对错。
做完把页面底部的「结果码」整段复制贴回来，我帮你解读。
```

**给结论就行，不要交代"我查了什么"。** 判定过程是内部动作，用户不需要知道你读了哪些字段、他"留过"什么信息。

❌ 错误示范一（用户明确反馈"这个描述不好"）：

```
脚本确认了版本，给你打开测评页。
看了下你留的基础信息（非管理者、司龄不到 5 年），适合做 初阶员工版。
```

三处问题：
- **"你留的基础信息"** —— 数据是从系统查的，不是用户"留"给你的，这么说会让人以为自己填过表。
- **"脚本确认了版本"** —— 暴露内部实现。用户不关心你跑了什么脚本。
- **"非管理者"** —— 这是接口里的字段值，不是人话。对用户就说"不带团队"，或者干脆别提。

❌ 错误示范二（更早的翻车）：

```
我先给你一句：接下来我只读你本人的基础信息（司龄、是否带团队），
只用来判断给你哪一版测评，不外传、不落到别处。
```

整段只有隐私免责，**没说"我要帮你选版本"这个动作本身**，用户看不懂你想干什么。隐私那句要**收进括号或短句里跟在动作后面**，不能当开场白单独一段。

其它三条：
- **不要罗列三版的判定规则让用户对号入座**（"5 年以上选这个、以下选那个……"）——能查就直接给结论。规则只在查不到时才说。
- **不要复述接口字段名或字段值**（managerLevelName / enrollAge / `非管理者` / `staffPropertyName`）。对用户只说"带团队 / 不带团队"这种人话，能不提就不提。
- **不要暴露内部动作**（"脚本确认了版本""我调了接口""读取了你的 infoDetail"）。用户要的是结论和链接。

> 用户确实追问"你怎么判断的"时才解释一句：**"看了你的司龄和是否带团队"**，到此为止，不展开字段细节。

### 0.3 兜底：MCP 没连 / 查不到时，让用户自己选

**MCP 没连接、接口失败、或脚本返回 `need_user_confirm: true` 时，不要卡住，也不要猜**——直接让用户手选，两个问题问完就能定版本：

```
我这边暂时读不到你的基础信息（招活MCP 还没连上），你直接告诉我两件事就行：

1. 你目前带团队吗？（有下属向你汇报）
2. 司龄满 5 年了吗？

带团队 → 管理者版；不带团队 + 满 5 年 → 中高阶员工版；不带团队 + 不满 5 年 → 初阶员工版。
```

用户答完，直接给对应链接开测评，**不要再去劝他连 MCP**——他只是想做个测评，连接器可以以后再说。

也接受用户一次性说清（"我带团队"/"我 8 年了不带团队"），别拆成两轮问。

拿到答案后可以直接算，也可以跑脚本：

```
python skills/ai-career-agent/scripts/pick_assessment.py \
  --staff-property "非管理者" --enroll-age "8"
```

另外两种情况：
- **用户不想说 / 说"你别查我"** → 直接给总入口 `http://21.6.92.38:8082/`，让他自己在页面上选，不追问。
- **返回带 `borderline_note`**（司龄卡在 5 年线附近）→ 确认一次再给："你司龄正好在 5 年线上下，是满 5 年了吗？"

> 隐私口径见 `career-broker-core/references/privacy-statement.md`。这里的用法是**跟在动作后面的一句话**（"只读你本人的信息，只用来选版本"），不是单独一段声明，同会话只说一次。

## preview · 用户选 B 时直接打开测评页（右侧预览）

WorkBuddy 客户端有 `preview_url` 工具，可以把网页直接渲染在对话右侧——用户不用复制链接到浏览器，省一步操作。

### 触发条件
用户在 §"用户分流" 表里选了 **"B / 想测评"** —— 路径任一即可：
- 主入口路由 → CC.OPEN → 用户选 B
- 教练流 step 5-6 二次 offer → 用户答应做
- 画像生成完成后用户选择用测评补充软性素质 → 直接进 T5

> **硬约束：用户选了做测评，就必须真的调用 `preview_url` 工具把测评页打开在右侧产物区**，不能只在对话里说一句"我给你打开在右边"却不调工具——那样用户那边根本不会出现测评页（真实翻车案例）。说打开 = 必须调 preview_url。

### 调用方式

```
# url 用 §0.1 脚本返回的那个，不要写死成某一版
preview_url(
  url="<pick_assessment.py 返回的 url>",
  explanation="打开职业DNA测评页（已按你的身份选好版本），做完把结果码贴回来给我"
)
```

> **不要写死 url**。三版链接见 §0，选哪版由 §0.1 的脚本决定。

> `cwd` 取当前会话工作目录即可（agent 自己的 cwd），不需要手动指定。`explanation` 一句话说为啥要打开。

### 配套话术（在 preview_url 之前的对话里说）

```
好，我把测评页给你打开在右边（已经按你的情况选好版本了）——
做完把页面底部的「结果码」整段复制贴回这个对话就行。

凭第一直觉选，没有对错。大概 10-15 分钟。
```

> 把 url 和 explanation 写在工具调用里，**不要在对话文字里再贴一次裸链接**——
> 用户已经在右侧预览看到了，重复贴只是噪音。
> **不要凭印象讲答题规则**。三版题型不完全一样（有单选情境题，也有程度量表题），
> 话术里只说"凭第一直觉选，没有对错"就够；具体怎么答页面上写得很清楚。
> 以前版本要求"每题选最像+最不像"，**新版已不是这个作答方式**，别再这么说。

### 兜底
- 如果 preview_url 调失败（沙盒环境 / cwd 不对 / 工具不在）→ 退回到老办法：把 url 直接贴到对话里，让用户自己点
- 如果用户在 preview_url 里点完没动静（比如忘了）→ step 5-6 时再一次性提"你刚那个测评做了吗？"
- 如果用户说"我想在浏览器里做不在右侧" → 把 url 贴出来让用户自己选

## DNA 结果码识别

> ⚠️ **本节的格式细节只给你自己解析用，禁止念给用户。**
> 对用户只说「页面底部的**结果码**，整段复制贴回来」——不要讲"以 DNA: 开头"、
> "以 |V:JR 结尾"、"有几段"、各段是什么。用户按提示复制就行，讲格式只会让人以为要自己核对。
> 万一用户贴少了/贴错了，那时再说一句"看着像少了一截，把底部那一整段都复制过来"。

三种版本的码长度不同（都以 `DNA:` 开头、`|V:XX` 结尾）：

```
初阶员工版  DNA:...|A:...|S:...|P:...|D:D/I|R:...|K:...|N:...|V:JR
中高阶员工版 DNA:...|A:...|S:...|P:...|D:C/S|R:...|K:...|N:...|V:SR
管理者版    DNA:...|A:...|S:...|P:...|SL:S2/S3|EF:52|FX:17|AD:69|DG:3|R:...|K:...|N:...|V:MG
```

用**一个通用正则**兜住全部版本 —— 不要为每版写一条：

```python
import re
# 思路：DNA 头 + A/S/P 三段必有，后面所有 "|前缀:值" 段一律吃进来（含 D/SL/EF/FX/AD/DG/R/K/N）。
# R/K/N 段取到行尾：用户自填岗位可能含空格（"Go 后端"），按空格切会把 role 截断。
# V 段单独收口成两个字母：新码以 |V:JR 结尾，用户在码后接话（"…|V:MG 帮我看看"）不会被吃进来。
PAT = (r'DNA:[A-Z]{3}-[A-Z]{2}/[A-Z]{2}'
       r'\|A:[^|\s]+\|S:[^|\s]+\|P:[^|\s]+'
       r'(?:\|(?!V:)[A-Z]{1,3}:[^|\n]*)*'
       r'(?:\|V:[A-Z]{2})?')
m = re.search(PAT, user_msg)
if m:
    code = m.group(0).strip()
    # 解析交给 parse_result_code.py，别自己拆串
    # 它返回 assessment_kind = junior / senior / manager / legacy
```

**解析出来必须看 `assessment_kind`，决定用哪套解读**：

| kind | 怎么解读 |
|---|---|
| `junior` / `senior` | 员工版：职业锚 + 优势风格 + 心理状态 + **性格底色（DISC）** |
| `manager` | 管理者版：上面几块 + **领导风格（SL/EF/FX/AD/DG）**；倦怠阈值降到 B≥3.0 |
| `legacy` | 8080 旧站的码，只有前 4 段。正常解读，并说明"这是早期版本，没有性格底色这块，想看可以重做最新版" |

**版本不匹配时不要硬解**：
- 用户是管理者但贴了员工版码 → 正常解读员工版内容，末尾补一句"你带团队的话，管理者版会多一份带人风格的画像，有兴趣可以再做一次"。
- 用户贴了管理者版码但当前 skill 只做员工解读 → 先解读共有部分，告知领导风格那块需要管理者版解读。
- 脚本 `notes` 字段里有提示时，按提示说，不要自己加戏。

两个已知取舍，都不用管：
- **旧版 4 段 / 7 段码仍能识别**——后面的段是可选组。
- 用户在码后面接了话（"…|V:JR 谢谢"），尾巴可能被吃进最后一段。
  影响仅限 need 这类参考字段，**解读时不要逐字复述 need**，转述意思即可。

识别到后**不打断对话节奏**——
1. 静默调 T6 把数据写回 profile.json
2. 用一句简短的回复 ack：

```
拿到了，TEC×CR 组合——你冰山下确实是"想在专业里继续深"的味道。
我们继续刚才的话题——你刚说[复述用户最后一句]，我想问的是…
```

## 硬约束：本 agent 只有这一个测评

**不要编造其他测评工具。** 不存在"霍兰德 18 题"、"职业锚 24 题"、"MBTI"、"五大人格"等独立入口。

- 测评入口只有 §0 表里那 4 个 URL；**选哪版由 §0.1 的脚本判定**，不是让用户在多个测评里挑
- 时长：10-15 分钟
- 输出：一段 DNA 结果码。员工版含 8 锚 + 6 风格维 + 心理状态 + **性格底色（DISC）**；管理者版含前三块 + **领导风格（SLII）**
- **DISC 和情境领导力不是独立测评**，是员工版/管理者版**内部的一个部分**（对应结果码里的 `D:` 段和 `SL:` 段）。用户问"有没有 DISC 测评"时，答"我们的员工版里就含这块，做完一起给你解读"，不要另开一个入口
- 解读知识在 `skills/ai-career-agent/references/knowledge_base.md`；性格底色/领导风格的解读口径在 `ai-career-agent/SKILL.md` M7 / M8

**三版之间不要混着 offer**：一个用户只该做一版。已经做过员工版又想看带人风格的，才引导去管理者版，并说明"这是另一份测评，会重新答一遍"。

LLM 在 offer 测评时若想给用户"多个选择"，正确的做法是给"做 / 不做 / 之后再做"三选项，**不是**编多个测评。

## 硬约束：T5 不做深度解读

T5 的职责严格限定在「offer + preview_url + DNA 写盘 ack」。
**深度解读（8 锚 / 6 维 / 心理状态 / 方向倾向 / AI 时代竞争力）是 ai-career-agent skill 的职责。**

- 用户在 ack 后追问「帮我看看这个 DNA 怎么样」「适合什么方向」「八锚啥意思」→ 主入口路由切 ai-career-agent
- T5 自己**不复刻** ai-career-agent 的 M1-M6 内容
- 如果用户追问「我现在 B 倦怠值这么高怎么办」 → 同样路由切 ai-career-agent.M3
