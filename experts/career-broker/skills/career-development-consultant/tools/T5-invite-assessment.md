# T5 · 邀请测评

## 0. 测评链接铁律（最高优先级）

- **唯一可用测评 URL**：`http://21.6.92.38:8080/`
- **禁止自行拼接、改写或猜测任何测评链接**，尤其禁止输出任何“主域名 + 测评路径”这类看起来合理但并不存在的短链接。
- 用户要做测评时，优先调用 `preview_url` 打开上面的唯一 URL；对话正文里不要贴裸链接。
- 只有在 `preview_url` 明确失败、或用户明确要求“给我浏览器链接”时，才把上面的唯一 URL 原样贴出。
- 如果拿不准链接，就说“我这边没有可用测评链接”，不要补一个看似官方的短链。

## 触发时机（两个窗口）

> ⚠️ **先查全局 offer 计数再决定提不提**（见 `skills/career-broker-core/references/broker-runtime-mechanism.md` §5.5）：
> - 若 `profile.json#assessment` 已有数据 → **不 offer**，直接说"我看到你之前做过测评，DNA 是 XXX，今天用它来看"。
> - 若全局 `assessment_offered >= 2`（含别的 skill 已经提过的次数）→ **不再 offer**，直接进 step 1 聊。
> - 用户主动说"我想做测评" → 直接打开测评页，**不计入** offer 次数。

### 窗口 1 · skill 入口（开场必做，且未达全局上限时）
进入 skill 第一个回合的开场就 offer（详见 SKILL.md §1.1）；offer 后全局 `assessment_offered` +1。

### 窗口 2 · 对话中段（step 5-6 二次 offer）
当教练在「澄清」阶段判断"我真的需要冰山下的信息才能继续"时再 offer 一次；前提是全局计数仍未到上限。

> **全局最多 offer 2 次**（跨所有 skill 共享计数，不是 CC 内部单独 2 次）。第 3 次再提就是骚扰，伤信任。

## preview · 用户选 B 时直接打开测评页（右侧预览）

WorkBuddy 客户端有 `preview_url` 工具，可以把网页直接渲染在对话右侧——用户不用复制链接到浏览器，省一步操作。

### 触发条件
用户在 §"用户分流" 表里选了 **"B / 想测评"** —— 路径任一即可：
- 主入口路由 → CC.OPEN → 用户选 B
- 教练流 step 5-6 二次 offer → 用户答应做
- 画像生成完成后用户选择用测评补充软性素质 → 直接进 T5

> **硬约束：用户选了做测评，就必须真的调用 `preview_url` 工具把测评页打开在右侧产物区**，不能只在对话里说一句"我给你打开在右边"却不调工具——那样用户那边根本不会出现测评页（真实翻车案例）。说打开 = 必须调 preview_url。

### 调用方式

```
preview_url(
  url="http://21.6.92.38:8080/",
  explanation="打开 15 分钟职业测评页，做完把 DNA 结果码贴回来给我"
)
```

> `cwd` 取当前会话工作目录即可（agent 自己的 cwd），不需要手动指定。`explanation` 一句话说为啥要打开。

### 配套话术（在 preview_url 之前的对话里说）

```
好，我把测评页给你打开在右边——做完把 DNA 结果码贴回来这个对话里就行。

答题说明：每道题会给你几个描述，你要选出「最像你」和「最不像你」两个选项
（每题都是这两个都要选），凭第一直觉选就行，没有对错。约 15 分钟。
```

> 把 url 和 explanation 写在工具调用里，**不要在对话文字里再贴一次裸链接**——
> 用户已经在右侧预览看到了，重复贴只是噪音。
> **答题规则（每题选「最像」+「最不像」两个选项）必须在话术里说清楚**——这是这套测评的特殊作答方式，不说用户容易漏选、卡在页面上。

### 兜底
- 如果 preview_url 调失败（沙盒环境 / cwd 不对 / 工具不在）→ 退回到老办法：把 url 直接贴到对话里，让用户自己点
- 如果用户在 preview_url 里点完没动静（比如忘了）→ step 5-6 时再一次性提"你刚那个测评做了吗？"
- 如果用户说"我想在浏览器里做不在右侧" → 把 url 贴出来让用户自己选

## DNA 结果码识别

用户贴回来的码格式：`DNA:TCA-CR/AN|A:TEC8CHL7...|S:CR4AN3...|P:B2.5O4.0E3.5`

教练在每条消息里**用正则识别**：

```python
import re
m = re.search(r'DNA:[A-Z\-/]+\|A:[A-Z0-9]+\|S:[A-Z0-9]+\|P:[A-Z\d.]+', user_msg)
if m:
    code = m.group(0)
    # 静默调 T6 回流
```

识别到后**不打断对话节奏**——
1. 静默调 T6 把数据写回 profile.json
2. 用一句简短的回复 ack：

```
拿到了，TEC×CR 组合——你冰山下确实是"想在专业里继续深"的味道。
我们继续刚才的话题——你刚说[复述用户最后一句]，我想问的是…
```

## 硬约束：本 agent 只有这一个测评

**不要编造其他测评工具。** 不存在"霍兰德 18 题"、"职业锚 24 题"、"MBTI"、"DISC"、"五大人格"等独立入口——

- 唯一测评入口：§0 定义的完整 URL
- 时长：≈15 分钟
- 输出：一段 DNA 结果码（已融合 8 锚 + 6 风格维 + 心理状态）
- 测评的解读知识、8 锚 / 6 维 / 心理状态完整定义都在 `skills/ai-career-agent/references/knowledge_base.md`——是**用来解读这一个 DNA 码的理论框架**，不是分开的测评工具

LLM 在 offer 测评时若想给用户"多个选择"，正确的做法是给"做 / 不做 / 之后再做"三选项，**不是**编多个测评。

## 硬约束：T5 不做深度解读

T5 的职责严格限定在「offer + preview_url + DNA 写盘 ack」。
**深度解读（8 锚 / 6 维 / 心理状态 / 方向倾向 / AI 时代竞争力）是 ai-career-agent skill 的职责。**

- 用户在 ack 后追问「帮我看看这个 DNA 怎么样」「适合什么方向」「八锚啥意思」→ 主入口路由切 ai-career-agent
- T5 自己**不复刻** ai-career-agent 的 M1-M6 内容
- 如果用户追问「我现在 B 倦怠值这么高怎么办」 → 同样路由切 ai-career-agent.M3
