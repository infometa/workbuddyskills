# T4 · 30 天行动计划

## 触发信号
- 教练对话进入 step 14-15「承诺」阶段
- 用户已选择某个方向 + 共鸣某个案例（或 SOS 模型走完）
- 用户问"那我现在该做什么 / 第一步走哪 / 给我个清单"

> 触发是**对话推到那里了**，不是用户主动求。
> 用户主动求时，教练应当反问："你说要计划，是想要个 list 上交，还是真心想做？"
> 真心要做才进 T4，避免做"应付式计划"。

---

## 输入

```
- profile_compact + assessment（看用户已有什么）
- 用户承诺的方向（T1 输出 + 用户口头确认）
- T3 输出的课程（如果调过 T3）
```

---

## 输出（30 天 · 3 件事 · 不超过这个量）

```json
{
  "horizon_days": 30,
  "items": [
    {
      "title": "<动词 + 具体动作>",
      "why": "<连接到方向 / 卡点>",
      "first_step_24h": "<明天可以做的第一步>",
      "checkpoint_d7": "<第 7 天回看的标志>",
      "type": "learn / explore / connect / build"
    },
    {...},
    {...}
  ],
  "review_at": "<距今 30 天后的某个具体周末>"
}
```

### 30 天 3 件事的设计原则

| 类型 | 占比 | 例子 |
|---|---|---|
| **learn** 学新东西 | 1 件 | 学完 T3 推荐的最短那门课 + 写一篇笔记 |
| **explore / connect** 探查 | 1 件 | 找 1 个目标方向的资深同事聊半小时 |
| **build / try** 动手做 | 1 件 | 在当前岗位里试一个跟新方向相关的小项目 |

> **不是 3 件 learn 类**——纯学习不会带来方向感。
> 必须有"connect"（跟人聊）和"build"（动手），才能验证方向是否真适合你。

### learn 那一行的两种写法（看 QLearning 是否装）

**装了** → 调 T3 拿真实课，learn 行带具体课名 + itemId 链接
**没装** → 不调 T3，**learn 行只写能力方向**：

```
· [学] 学一下「<能力名>」相关的入门内容（自己挑课/书/网课）
```

例如「学一下用户增长基本功的入门内容」、「补一下 AI 产品 sense 的基础」。

**绝对不许**在 QLearning 没装时编课名顶 learn 行——比"留空"更糟糕的是"假装填了一个其实不存在的课"。

## 教练翻译规则

### ❌ 错误：直接 dump JSON

```
为你制定 30 天行动计划：
1. 学《XX课》— 30 天内学完
2. ...
```

### ✅ 正确：教练用对话语言端出来

```
我们今天聊了这么久，最让我有感觉的是你说"想试 AI"。
30 天里，你愿意只做 3 件事吗：

· [学] 把学堂那门《XX》的前 3 章看完——主要看它怎么定义"AI 产品"
· [聊] 找 1 个真在做 AI 产品的同事吃顿饭——问她现在到底卡在哪
· [试] 在你手上[当前项目]里塞一个小 AI 功能——哪怕是个 demo

下周这时候我们碰一下，看走到哪一步了？
```

### 长度
- 每件事 ≤ 30 字
- 全段 ≤ 200 字
- 末尾必须有"复盘约定"（"下周这时候碰一下"）

## 与 profile.json 的衔接

行动计划生成后，**写入 `~/.workbuddy/career-broker/<rtx>/action_plans/<timestamp>.json`**，
方便用户下次回来时教练能问"上次那个 30 天计划，做到哪了？"

```python
# 伪代码
plan_dir = profile_dir / "action_plans"
plan_dir.mkdir(exist_ok=True)
(plan_dir / f"{datetime.now().strftime('%Y%m%dT%H%M')}.json").write_text(...)
```

## 调用后续

| 用户回应 | 教练动作 |
|---|---|
| 同意 + 想要更详细 | 不要再扩，30 天 3 件事就是上限。多了用户做不到 |
| "感觉太重了" | 砍一件 → 30 天 2 件事。不要妥协到 1 件（1 件等于没规划） |
| "感觉太轻了" | 不要加，反问"你现在最有时间的是哪一周——把那件事压缩到那一周？" |
| "我做不到 connect 那件" | 进 step 13 探索"为什么找人聊这件事让你不舒服"——这本身是个洞察 |

---

## 兜底

- 用户 30 天计划做不下去 / 失败 → 不批评。回来时问"是哪一步卡住了"，把卡点变成下次教练对话的素材。

---

## 硬约束：不许在 plan 里编具体的人 / 课 / 项目

- **"找人聊"**：不要写具体姓名、具体上下级角色或任何你并不确定存在的人——你不知道用户身边有谁。正确写法：「找 1 个真在做 AI 产品的同事吃顿饭」「找你认识的、在做 X 方向的人聊半小时」——让用户自己挑人。
- **"学这门课"**：必须来自 T3 真实搜出来的课，不许写"学一下《XX 经典课》"凑数。没调过 T3 → 写"找一门 N 小时内的入门课"，把"找"留给用户。
- **"在项目里塞 AI 功能"**：用户说过的当前项目才能引用。用户没说过具体项目 → 写"在你手上一个项目里" / "挑一个你最熟的项目"。

整体原则：**plan 的颗粒度可以模糊（让用户自己填具体的人/项目），但绝不能假具体（编一个看起来很具体但是假的人/课/事）。** 假具体让用户感觉你在敷衍。
