# 交叉验证方法论（cross-verification）

> 解决"这条消息可信吗、怎么核实"的问题。这是新闻资讯专家相对竞品最硬的差异化——竞品直接把搜到的丢出来，我们核实后才呈现。

## 一、核心规则：关键事实 ≥2 独立来源

**什么算"关键事实"**（必须交叉验证的）：
- 重大事件的发生（某公司发布/收购、某政策出台、某事故）
- 具体数字（金额、涨跌幅、伤亡数、市场份额）
- 引语/表态（某人说了某话）
- 因果断言（X 导致 Y）

**什么可以单源**（低风险的）：
- S 级一手源的自我声明（公司官宣自己的产品）
- 常识性、无争议的背景信息

## 二、交叉验证流程

```
1. 拿到一条关键事实
2. 用 online-search 换关键词/措辞再搜，找其他独立来源（必要时 WebFetch 进原文）
3. 判断来源是否真独立（不是同一通稿转载，见 source-credibility.md 第五节）
4. 比对：
   - ≥2 独立 S/A 级源一致 → ✓ 已交叉验证，可作既定事实
   - 多源但细节有出入（数字/时间不同）→ 取权威源 / 并列标注差异
   - 多源但说法矛盾 → ⚠️ 并列各方说法，不下定论
   - 仅单一来源（非 S 级自证）→ ⚠️ 待核实
5. 需要精确细节（具体数字/原话）→ WebFetch 进原文核对
```

## 三、防假新闻 / 误导的识别清单

| 风险类型 | 识别信号 | 应对 |
|---------|---------|------|
| **旧闻新用** | 时间戳缺失/模糊；事件细节与"最近"对不上；图片是旧的 | 核对原始发布时间，标明真实日期；不当今日新闻 |
| **标题党/断章取义** | 标题极端、正文与标题不符 | 以正文/原文为准，不被标题带偏 |
| **深度伪造 / AI 生成** | 来源不明的"惊人"音视频、无原始出处、细节经不起推敲 | 找一手权威源印证；找不到则不收录 |
| **谣言/未证实传闻** | "网传""据传""内部消息"且无具名源 | 标"传闻未证实"或直接不收录 |
| **数字夸张/失真** | 数字异常大、无出处、与常识冲突 | 回原始数据源核对，不照搬 |
| **假交叉验证** | 多家媒体内容雷同（同一通稿） | 识别为单一源，继续找真正独立的源 |

## 四、矛盾信息的处理

当不同来源说法不一致时——**不要替用户下结论，并列呈现**：

```markdown
关于 XX 事件，目前有不同说法：
- 来源 A（路透）：称 ...
- 来源 B（XX 官方）：回应 ...
（两方说法存在出入，建议持续关注）
```

> 客观中立是底线：争议性、未定论的事件，呈现多方视角，让用户自己判断。

## 五、验证标记规范（写进简报）

| 标记 | 含义 | 用在哪 |
|------|------|--------|
| ✓ 已交叉验证 | ≥2 独立权威源印证 | 头条、重要条目 |
| （无标记） | 单一权威源、无争议 | 一般条目 |
| ⚠️ 待核实 | 单一非权威源 / 来源矛盾 | 需提醒用户的条目 |
| 🕐 注意时间 | 疑似旧闻，已标真实日期 | 防旧闻新用 |

## 六、务实边界

- 我能做的：多源比对、信源分级、识别明显的旧闻/标题党/无源传闻。
- 我不能做的：鉴定深度伪造的技术真伪、核实非公开的内部信息。遇到这类，**坦诚告知"无法独立核实"**，不假装确认。
- 核实不了的，宁可不收录或明确标注，绝不蒙混当事实。
