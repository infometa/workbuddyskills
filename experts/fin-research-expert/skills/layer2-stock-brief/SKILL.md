description: "当用户明确提到某个具体股票或上市公司时——如'保隆科技最近怎么了''帮我快速看一下600519''茅台最近有什么重要信息'。整合行情、公告、新闻和研报。行业整体问题用 industry-brief，研报专项用 research-digest，公告专项用 announcement-brief。"
---

Use when:
- 需要快速了解某个股票最近发生了什么
- 需要把行情、公告、新闻、研报放在一起看
- 仅当用户已经明确点名某个股票，且确实需要个股层信息时使用
- 用户用灵感页口吻问“手把手看懂一只股票”“朋友推荐这只股票靠谱吗”“这家公司最近到底怎么了”
- 典型场景：
  - 单一股票公开资料分析
  - 上市公司简析（客观视角）
  - 近期消息面意义及影响
  - 公司定期报告/预告/业绩修正

Not for:
- 不要直接用于纯投教、法规解释、财富规划
- 不要在缺少底层数据时强行输出“投资建议”或“目标价判断”
- 不要把它当成默认推荐个股、引导客户围绕个股反复追问的入口
- 如果用户问题更适合从行业、板块、宏观或市场结构解释，优先引导到这些层面，而不是把回答越做越细到个股

Depends on:
- `layer1-fin-data`
- `layer1-doc-search`

Workflow:
1. 先通过 `search_security` 或直接传入 `ticker` 确认标的身份，优先拿到标准证券代码。
2. 调用 `get_security_profile` 获取公司基础画像，至少确认市场、行业和证券简称。
3. 如果用户关注“现在怎么样”“最近怎么样”“帮我分析一下”“公司是做什么的”这类当前导向问题，不要只凭参数知识直接回答；至少先获取 `security_profile`，再补最近公开信息。
4. 如果用户关注“现在怎么样”或“最近走势”，优先调用 `get_latest_snapshot`；如果用户关注区间表现，再调用 `query_data`。
5. 如果用户问“最近发生了什么”或“帮我快速分析一下”，优先使用 `get_entity_event_timeline` 或 `search_normalized_events` 做一次近 `7-30` 天时间线梳理，避免把新闻、公告、事件分开重复查很多轮。
6. 如果需要拆开看来源，再调用 `search_company_news` 获取最近公司新闻，默认优先近 `7-30` 天。
7. 调用 `search_announcements` 获取最近公告，优先关注：
   - 定期报告 / 业绩预告 / 业绩修正
   - 分红、回购、减持、增持
   - 重组、重大合同、管理层变动
8. 如果线上研报链路可用，再调用 `search_research_reports` 获取最近个股研报；公司级研报必须使用第 1-2 步确认出的 `company` 和/或 `ticker` 做 scoped search，不要只把公司名放进 `query` 后配 `1y` 这类长窗口；如果研报不可用或参数报错，要明确说明而不是跳过不提。
   - 港股、美股、英国市场要保留解析出的市场代码；scoped 结果为空时，再用可靠公司名去掉 `ticker` 重试一次。
   - 当前结构化行情身份工具并非覆盖所有海外市场；未确认到行情身份时可以继续做明确公司名的文档检索，但必须把行情画像标为未返回，不能猜代码。
9. 合并输出为“个股快查摘要”，明确区分：
   - 市场表现
   - 新闻事件
   - 公告
   - 研报观点
10. 如果用户要求 HTML、灵感样张或“做同款”，把结果整理成 WorkBuddy 证据包：
   - 标的身份：公司名、证券代码、市场、行业
   - 最新状态：最新行情或区间表现；拿不到就标“未返回最新行情”
   - 最近 `7-30` 天发生的 3-5 件事：新闻、公告、研报分开标来源类型
   - 给小白看的解释：这些事为什么重要、影响的是收入/成本/政策/竞争/资金偏好中的哪一类
   - 支持证据、风险证据、还不能下结论的地方
   - 后续 3 个观察信号：公告、财报、订单/价格、行业数据、研报覆盖或政策
   - 源头复核入口：保留返回的 `source_url`、`document_url`、`report_url`、`original_url` 或小程序内容页；入选 Same Boat 内容缺少文章级 URL 时，按 `layer1-same-boat` 调用 `generate_content_url_link` 并只使用返回的 `url_link`；没有链接就只标来源类型
11. 在总结时优先补一句“这对所属行业、板块或更大市场环境意味着什么”，尽量把用户视角从单一个股拉回行业和宏观背景。
12. 最后如确有必要，再补一句“这对当前个股意味着什么”，但只做信息归纳，不做买卖建议。

Rules:
- 只要用户已经明确点名某个股票，就应先走个股信息链路，不要跳过工具直接凭模型常识作答。至少拿到 `get_security_profile` 后，再描述公司业务和近期状况；公司近期信息必须来自时间线、公告、新闻或研报，不要用模型记忆中的旧描述。
- 如果用户问题明显指向“财报 / 业绩预告 / 业绩修正 / 最近公告说了什么”，优先按公告链路处理：先 `search_announcements + get_document`，不要先把新闻和研报铺满。
- 只要回答里出现“近期动态”“最近发生了什么”“亮点”“风险点”“订单”“产能”“业绩”“研发布局”“机构观点”等近况表述，就必须先调用新闻、公告、研报中的至少一种工具；没有检索证据时不要写这些内容。
- “最近发生了什么”优先用 `get_entity_event_timeline` 或 `search_normalized_events` 收敛，不要先分别发起多轮新闻/公告搜索。
- 如果一个工具都没调到，不要输出带有时间性的个股分析，不要凭记忆补“2024Q1”“近期签约”“今年规划”这类信息。
- 新闻、公告、研报最多各取 `3-5` 条，不要堆太多。
- 如果用户问“最新价”，优先使用 `get_latest_snapshot`。
- 如果用户问“最近怎么了”，默认优先看最近 `7-30` 天，而不是拉很长历史。
- 如果用户问“这只股票怎么看”，先讲事实层，再讲风险点和待验证点，不要直接替用户做交易决策；涉及个人持仓、仓位或账户适配时必须回到公开资料研究边界。
- 如果用户问“朋友推荐这只股票靠谱吗”，把问题改写为“公开资料能支持哪些说法、哪些说法还没证据”，不要替用户判断是否买入。
- 默认弱化“个股推荐感”，不要把回答组织成“这只股票值不值得买/卖”的风格。
- 只要能从行业、景气度、政策、市场风格、资金偏好解释，就优先从这些层面组织信息，而不是把重点放在个股涨跌本身。
- 如果用户只是泛泛问“最近有什么机会”“该看什么”，不要主动落到单一个股，优先引导到行业、主题、指数或宏观框架。
- 如果新闻和公告都为空，要明确说明“近期公开信息较少”。
- 如果公告很多，优先选择高信息密度类型，不要把日常经营类流水公告铺满。
- 如果新闻、公告、研报结论不一致，要明确区分来源，不要合成一个过度确定的判断。
- 如果研报链路报错或不可用，要明确写出“研报暂不可用，本次摘要主要基于行情、新闻和公告”。
- 如果 `search_research_reports` 返回 `INVALID_BROAD_TIME_RANGE`、`MISSING_RESEARCH_FILTERS` 或其他参数/范围错误，这不是“没有研报”，应改用已确认的 `company`/`ticker` 重试；只有 scoped company/ticker 检索成功且结果为空，才写“本次未命中公司级研报样本”。
- 海外公司 scoped 研报为空时必须再用可靠公司名去掉 `ticker` 重试一次；两次均为空时只能写“当前研报源与时间窗下未命中”，不能写“公司没有研报”。
- 港股公告为空时要明确当前公告源不包含港交所披露易原生公告，不能把空结果写成“公司近期没有公告”。
- 登录页、OAuth 授权页、控制台、服务/反馈页、搜索页和门户首页都不是原文入口；不得把这些地址包装成“同舟认证证据”“认证查看”或其他源头复核卡片。
- 如果 `search_security` 未能确认标的，或 `get_security_profile` 未返回有效画像，要先说明“暂未确认到准确标的身份”，不要直接展开个股分析。
- 不要直接做投资建议，只做信息整合。
- 不要整段贴公告正文或研报长文本，只提炼关键事实与短摘要。

Suggested output template:
1. 标的与最新市场表现
2. 最近重要新闻
3. 最近重要公告
4. 最近研报观点
5. 所属行业或更大市场背景
6. 当前需要重点关注什么
7. 一句话综合摘要

WorkBuddy HTML handoff:
1. 页面标题建议用“手把手看懂：{公司名}最近发生了什么”
2. 首屏给一句话结论、证据窗口、3 个关键信号
3. 中段用“发生了什么 / 为什么重要 / 证据怎么说 / 风险在哪里 / 接下来盯什么”
4. 文末必须有信源复核和非投资建议

Examples:
- `保隆科技最近怎么了`
- `贵州茅台最近一周有什么重要信息`
- `帮我快速看一下 600519`
- `手把手看懂宁德时代最近发生了什么`
