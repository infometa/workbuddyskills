name: layer2-evidence-ledger
description: "当用户需要把已取证的公开股市投研材料整理成证据台账、信源审计、证据强弱表或结论依据清单时使用。只整理和校验已有证据，不负责新增取数、认证、预测、账户诊断或生成新事实。"
---

Use when:
- 用户问“依据是什么”“信源列清楚”“哪些证据支持/反对这个判断”
- 需要把行情、公告、新闻、研报、行业图谱、同舟观点整理成统一证据表
- 需要给 HTML 报告、投研摘要或客户可读解释补一个清晰的证据区
- 已经通过对应投研 L2 完成认证、取证和初步结论

Not for:
- 不要替代 `fin-mcp-gateway` 认证或底层工具调用
- 不要在没有证据底稿时凭模型记忆整理“看起来像证据”的材料
- 不要输出 raw MCP JSON、内部文档 ID、搜索得分、图谱节点 ID、API Key、验证码、手机号、持仓或交易历史
- 不要把证据台账写成买卖建议、评级、目标价或个人化适当性结论
- 用户可见输出必须保留证据来源、时间窗口和缺口边界；本技能仅做公开信息整理，非投资建议，不输出买入、卖出、目标价或个股推荐。

Depends on:
- 已完成的公开投研底稿
- `layer2-stock-brief`
- `layer2-industry-brief`
- `layer2-announcement-brief`
- `layer2-policy-event-brief`
- `layer2-research-digest`

Workflow:
1. 先确认底稿里至少包含研究问题、证据窗口、核心结论、来源类型和限制说明。
2. 如果底稿缺少关键证据，先回到对应投研 L2 补取证；不要直接补常识。
3. 将材料拆成证据单元，每条记录至少包含：
   - 来源类型：行情数据、公告、公开新闻、研报、行业图谱/异动、同舟要闻/观点
   - 时间或证据窗口
   - 证据摘要
   - 可跳转源头：保留 `source_url`、`document_url`、`report_url`、`original_url`、小程序页面链接或公开来源 URL；未返回链接的数据保留来源类型和证据缺口说明，不编造 URL
   - 支持、反对、背景、待验证或证据缺口
   - 对应的结论或假设
4. 单独列出冲突证据：同一问题下新闻、公告、研报、行情或同舟观点不一致时，不要揉成一个确定结论。
5. 用定性标签说明证据强弱：强、中、弱、待验证。不要伪造精确分数。
6. 输出前检查是否有结论没有证据支撑；没有支撑的结论必须移到“待验证/不能下结论”。

Rules:
- 证据台账是审计层，不是新的数据源。不得新增事实、删掉限制或改变数据口径。
- 不要把同舟观点写成券商研报，不要把 Doc Search 新闻写成同舟重要度评分，不要把图谱结构写成公告事实。
- 不要为了让结论更完整而补充未检索到的公司、行业、财务数字或历史事件。
- 对用户可见输出使用来源类型和简短出处描述，不暴露内部 route、tool name、参数、ID 或搜索得分。
- 可跳转链接只能来自已返回证据。不要把搜索页、门户首页或猜测的小程序路径伪造成原文链接。
- 如果用户问“能不能据此买/卖”，只能回到公开资料和风险边界，不给交易指令。

Suggested output template:
1. 研究问题与证据窗口
2. 结论与证据强弱总览
3. 证据台账表
4. 支持证据与反对证据
5. 冲突、缺口和待验证项
6. 源头复核入口与不能下结论的部分

Examples:
- `把刚才这份半导体分析的证据来源列清楚`
- `这个结论有哪些证据支持，哪些证据反对`
- `给这页 HTML 报告加一个信源审计表`
