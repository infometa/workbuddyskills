description: "当用户需要把公开事件、行业异动、政策或主题行情拆成事件到机制到产业链上下游的传导链路时使用。适用于 MLCC、新能源、AI 算力、半导体等行业/板块解释，不负责预测、回测、账户诊断或生成新事实。"
---

Use when:
- 用户问“这件事怎么传导”“影响链路是什么”“上中下游谁受益/承压”
- 行业或板块异动需要从 1-2 天新闻扩展成机制链路，而不是只做新闻摘要
- HTML 报告、行业简析或事件解读需要补“事件 -> 机制 -> 产业链 -> 验证指标”
- 已经有事件、行业、新闻、研报、图谱或行情底稿

Not for:
- 不要替代 `layer2-industry-brief`、`layer2-policy-event-brief` 或 `layer2-research-digest` 的取证
- 不要把传导链路写成确定性预测、回测结果、个股推荐或目标价
- 不要凭行业常识硬补未取证的上下游公司、产能、订单、价格或财务影响
- 不要输出 raw MCP JSON、图谱节点 ID、内部路径、搜索得分或未公开节点结构
- 用户可见输出必须保留证据来源、时间窗口和链路边界；本技能仅做公开信息整理，非投资建议，不输出买入、卖出、目标价或个股推荐。

Depends on:
- 已完成的公开事件/行业/市场底稿
- `layer2-industry-brief`
- `layer2-policy-event-brief`
- `layer2-research-digest`
- `layer2-stock-brief`
- `layer2-evidence-ledger`

Workflow:
1. 先锁定一个主事件或主异动，不要同时解释太多主题。
2. 如果链路涉及行业/主题，先复用 resolver 返回的 `source_ids`：保留 `canonical_id`、`source_ids`、`coverage_gaps` 和 `source_review`，用 `same_boat_sector_id`、`fin_data_theme_basket_id` / `fin_data_sw_basket_id`、`market_index_code`、`graph_subject`、`rfg_frame_id` 分别调用对应来源。没有覆盖就标注缺口，不要用宽基指数、示例行业或假 ID 替代。
3. 确认证据窗口：事件发生时间、新闻/公告/研报覆盖时间、行情观察时间。
4. 把链路拆成五层：
   - 触发事件：发生了什么
   - 直接机制：为什么会影响价格、需求、供给、成本、政策预期或风险偏好
   - 产业链位置：上游、中游、下游或应用端分别怎么受影响
   - 受益/承压环节：哪些环节可能更有利，哪些环节可能受压
   - 验证指标：后续看什么数据或事件来判断链路是否成立
5. 对每个链路节点标注证据来源类型：公开新闻、公告、研报、行情数据、行业图谱/异动、同舟观点。
6. 把“确定事实”“合理推演”“待验证假设”分开写；缺证据的链路节点必须标为待验证。
7. 如果需要代表公司，只能来自已检索到的成分、公告、新闻、研报或图谱信息；不要凭记忆列公司池。
8. 输出时保留反向链路：哪些情况会让受益逻辑变弱或反转。

Rules:
- 传导链路必须从已取证事件出发，不要先画宏大产业链再倒填证据。
- 如果 resolver 或 source_review 显示某来源缺失，只能说明覆盖缺口；不要凭行业常识硬补未返回的成分、图谱节点、样本统计或来源链接。
- 不要把短期行情异动直接写成基本面已经改善；必须说明“盘面信号”和“基本面证据”的区别。
- 如果证据只覆盖 1-2 天，要明确这只是短窗口事件链路，不是完整行业深度报告。
- 对小白用户要先用一句话解释“为什么这事会影响这个行业”，再给链路表。
- 对专业用户可以输出机制表、链路强弱、反向风险和验证指标，但仍不能给交易指令。

Suggested output template:
1. 一句话传导结论
2. 事件与证据窗口
3. 事件 -> 机制 -> 上中下游链路表
4. 受益/承压环节与证据强弱
5. 反向风险与真伪检查
6. 后续验证指标

Examples:
- `MLCC 最近的行业新闻怎么传导到产业链`
- `新能源汽车板块异动，按上中下游解释一下`
- `这个政策对 AI 算力链条的影响路径是什么`
