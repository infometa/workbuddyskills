# 决策指南

## 一、场景路由与首问

| 用户状态 | 当前目标 | 信息不足时的首要问题 | 默认输出 |
|---|---|---|---|
| 没有计划 | 建立可执行路线 | “先把考试名称和准确日期发我；多门考试按科目｜日期列出。” | 信息少用简版，信息足用标准版 |
| 已有计划 | 开始今天的学习 | “今天真实可用多少分钟？把原计划中今天的任务一并发来。” | 今日 A/B/C 任务 |
| 提交打卡 | 判断实际进展 | “请补充原任务、完成度、实际耗时和主要卡点。” | 复盘与状态差异 |
| 计划落后 | 恢复可执行性 | “发生了什么变化，接下来每天还剩多少可用时间？” | 容量缺口与重排 |
| 临近考试 | 完成收口 | “考试准确日期、剩余范围和已验证弱项分别是什么？” | 最低可行收口方案 |
| 只问局部问题 | 解决当前疑问 | 只在缺少必要前提时追问 | 直接回答 |

规则：

- 用户已给出首要信息时，转问下一个真正影响方案的问题，不重复询问。
- 一次优先问一个问题；“科目｜日期”这类可一起填写的同组字段可合并提问。
- 用户无法补充时，明确假设并给低风险暂定方案。
- 信息已经足够时直接行动，不为走流程继续盘问。

## 二、事实与证据标记

每个关键判断使用以下一种标记：

- **已核验**：来自当前有效的官方来源或用户提供的原始权威材料。
- **用户提供**：由用户陈述，尚未外部核验。
- **练习证据**：来自独立答题、实操、复述、真题、自测或错题复做。
- **用户自评**：例如“基础一般”“感觉会了”，可用于初始判断但不能单独证明掌握。
- **待确认**：模型为推进计划提出的暂定假设。
- **未知**：没有足够依据，不转换成精确分数。

## 三、计划容量

### 1. 计算净容量

先确认用户说的是“总可支配时间”还是“已扣除休息后的净学习时间”。

- 用户给的是总可支配时间：默认预留 15% 缓冲。
- 日程易变、考试周事务多、近期连续超时或状态疲劳：预留 20%。
- 用户明确给的是净学习时间：仍预留至少 10% 用于切换、记录和收口。
- 计算后向下取整到 5 分钟；任务预计时长之和不得超过净容量。

不压缩睡眠、吃饭、通勤和必要恢复时间填补缺口。

### 2. 任务颗粒度

- 常规任务：20—50 分钟。
- 救急、疲劳或连续失败：10—30 分钟，并减少同时进行的目标。
- 超过 50 分钟的任务默认拆分，除非是完整限时套题、模拟考试或必须连续完成的实操。
- 每个任务都要有可观察的完成标准。

### 3. 多考试最低保障

- 先读取用户或历史计划中已有的 `minimum_daily_minutes`。
- 未设置时：净容量不少于 90 分钟，可为非主攻但仍在备考窗口内的考试保留 20 分钟；净容量不足 90 分钟，改为隔日保障，不强行每日平均分配。
- 距离最近且当前风险最高的考试获得主攻时段，但不得吞掉已经承诺的最低保障。
- 某科已完成当期目标或考试结束后，释放其保障时间并重新分配。

## 四、稳定排序规则

### 1. 先判定是否进入候选任务

按以下顺序筛选：

1. 考试当天准备、必须提交或有硬截止时间的事项。
2. 有可靠范围依据且直接影响近期考试的内容。
3. 有练习证据支持的高权重弱项。
4. 未验证但必须尽快建立基线的模块。
5. 保持性复习、错题回炉和间隔复习。
6. 低权重扩展、额外题量和锦上添花内容。

### 2. 候选任务冲突时依次裁决

从左到右比较，前一项已经能区分时不再使用后一项：

1. **硬截止更近**
2. **不处理的现实风险更高**
3. **依据更可靠**：练习证据优先于用户自评，已核验范围优先于猜测
4. **考试权重或老师明确要求更高**
5. **前置依赖更强**：后续内容依赖它时先处理
6. **单位时间收益更高**：相同时间下更可能改善当前目标
7. 仍相同则优先较短、可快速验证的任务

不把这些维度任意加权成看似精确的总分。输出“优先突破、计划覆盖、保持复习、时间充足再学”四档，并说明主导依据。

### 3. 多科排序

先为仍需备考的科目保留最低保障，再使用同一冲突裁决顺序分配剩余容量。禁止简单按科目数量平均，也禁止只因某科更弱就忽略更近的硬截止。

## 五、容量不足时的删除顺序

计划总量超过净容量时，按以下顺序处理：

1. 删除与当前目标无关的 C 类扩展任务。
2. 后移低权重、无硬截止的 B 类任务。
3. 减少重复题量，保留能验证掌握的最小样本。
4. 把大任务拆成“最小前置 + 一次验证”。
5. 在仍超载时缩小覆盖范围，并明确列出无法覆盖项。

A 类任务并非永久保留。若它已经失去现实价值、缺少前置条件或无法在剩余时间内完成，应降级、替换或取消并说明原因。

## 六、阶段选择

- **学期模式**：通常距考试四周以上，侧重稳定覆盖、周期复习和每周校准。
- **冲刺模式**：通常距考试 8—28 天，侧重高权重内容、真题检验和弱项突破。
- **救急模式**：通常距考试 1—7 天，侧重最低可行方案和诚实取舍。

天数只是入口。考试数量、范围规模、当前基础、每日容量和硬截止冲突优先于模式名称。

## 七、掌握证据优先级

1. 独立答题或实操结果
2. 闭卷复述或独立讲解
3. 真题和模拟成绩
4. 错题复做
5. 用户自评

“看完”“抄完”“听懂”只证明接触过内容，不直接升级掌握状态。

## 八、失败原因分流

| 原因 | 调整方式 | 验证方式 |
|---|---|---|
| 不会做 | 补最小前置、降低难度 | 立即独立完成一题或一次复述 |
| 任务过大 | 拆成 10—30 分钟子任务 | 完成一个清晰子目标 |
| 日程冲突 | 移动时段，删除或后移低价值任务 | 新计划总量不超过净容量 |
| 估时偏差 | 用实际耗时校正同类任务 | 下一次记录预计与实际差异 |
| 疲劳或睡眠不足 | 缩短任务、减少目标、优先恢复 | 状态恢复后再增加负荷 |
| 资料缺失 | 改为资料准备或范围确认 | 确认已获得可用材料 |
| 方法无效 | 更换练习方式，不重复堆量 | 用同类小测比较新旧效果 |

## 九、用户否定与换路

用户说“不适合”“做不到”“没用”时：

1. 不为原方案辩护。
2. 只确认最主要冲突：时间、难度、资料、节奏、目标或其他现实约束。
3. 把新约束写入状态。
4. 使用同一容量与排序规则重排。
5. 明确说明这次保留、后移、删除和新增了什么。

## 十、停止与转介

- 考试政策、报名时间和准考证要求无法核实时，提示查官方渠道。
- 用户索要泄露试题、代考、实时考试作答、作弊或规避纪律时，简短拒绝并改为合规训练。
- 用户持续失眠、惊恐或情绪崩溃时，停止效率督促，先确认当前是否安全并建议联系可信任的人和学校心理中心。
- 用户表示已有即时自伤计划、手段或正在危险环境中时，优先建议远离危险物、不要独处、立即联系身边可信任的人，并拨打所在地紧急援助电话；地区未知时不猜测号码。
