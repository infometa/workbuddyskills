# 第一部分：检测 / 质检 / 质量管理案例

## 📌 检测行业核心洞察

检测行业天生是「标准 + 样品 + 结论」的三段式结构，与 AI 的多文档比对能力天然契合。**日常最疼的活——报告复核、方法验证、供应商评审、不确定度核查、评审迎检——本质都是"多文档比对"**：标准文件 1 份（国标/规范/招标要求）+ 待审材料 N 份（报告/记录/资质/标书），流程就是"拆标准 → 逐项比 → 找异常 → 出结论"。

**核心原则**：体力活（翻页、比对数字、抓过期证书、整理对比表）交给 WorkBuddy，判断力（供应商承诺能否接受、不确定度方法换不换、整改证据够不够）留给自己。

## 一、检测报告「符合性审查 Skill」（CNAS/17025 场景，最推荐）

> 真实痛点：CNAS 监督评审，17025准则 + RB/T 214 + 《质量手册》《程序文件》四层文件叠加，逐条核对 800 多份报告有无漏签、漏附不确定度、校准证书超期——三个人核三天。

### 四步法（从"多文档比对"平移）

**Step 1｜拆"标准文件"，提取硬性指标清单**
标准文件可以是：CNAS-CL01:2018 第7.8条（报告内容要求）/ RB/T 214 第4.5.20条（分包要明示）/ 院里《检验报告编制作业指导书》"必填项11条" / 招标文件技术规格。
让 WorkBuddy 把源文件拆成结构化清单，如："报告必须有不确定度？是/否""校准证书必须在有效期内？是/否""分包要标注分包方CNAS标识？是/否"——这就是检测的"考试大纲"。

**Step 2｜逐项比对，三态标记**
拿待审的 N 份报告/记录往"大纲"里套：
- ▲ 符合
- △ 偏差（如不确定度给了但没写 k=2）
- ✗ 不符合（如校准证书 2025年3月到期，报告 2026年1月出的）
- 技术参数对应"实测值 vs 限值"（如食品"菌落总数 ≤ 10⁴ CFU/g"直接标超没超）

**Step 3｜交叉验证 + 隐蔽异常专项**（质量负责人最怕的"隐蔽不符合"）
| 异常类型 | 例子 |
|---|---|
| 资质时效 | 校准证书过期、ISO 17025 认可附件没覆盖该项目却出了报告 |
| 名称口径 | 委托单写"XX食品厂"，报告封面写"XX食品有限公司" |
| 型号/批号置换 | 原始记录样品批号 A，报告写成 B |
| 附带条件 | 校准证书写"仅限实验室使用"，却拿去做法定监督抽查判定依据 |
| 数据异常 | 同一台液相三天内两份报告，保留位数 3 位变 5 位，Ur 从 2% 跳到 8% |

> AI 比人眼好在——它不累，800 份报告扫下来，第 799 份跟第 1 份一样认真。

**Step 4｜出审查报告，Word 可存档**
按院里《报告复核记录表》格式输出：哪份报告第几页第几条不符合、依据哪个标准哪款——形成可追溯审核轨迹。

### 封装为 Skill 复用
第一次调通后让 WorkBuddy 封成 Skill，命名如"检验报告符合性审查"或"供应商资质核查"：
- 核报告 → 拖入"标准文件（CL01/RB/T 214/作业指导书）+ N 份待核报告"，说"帮我核报告"
- 供应商评审 → 拖入"招标文件 + N 家投标书/资质包"，说"帮我评"
- 方法变更核查 → 拖入"新旧标准对照 + 存量报告清单"

一次构建，无限复用——不是去买几十万的 LIMS 模块，是先把最疼的核对活交给 AI。

## 二、质量数据分析实战（线束端子压接，30 份报告→15 分钟）

> 12 年汽车零部件质量工程师实战：线束端子压接三核心指标（压接高度=电气可靠性、拉脱力=机械强度、外观=完整性），SPC 监控看趋势（单点超差容易发现，连续5点偏向控制线同一侧、连续7点递增、Cpk 从 1.67 滑到 1.33 这些趋势信号人眼容易漏）。

### 四步流程（含完整指令）

**第 1 步：喂检测报告给 WorkBuddy**
```
请读取以下30份线束端子压接质量检测报告PDF，提取每份报告的：
- 批次号
- 压接高度实测值(10个端子的数据)
- 拉脱力实测值(10个端子的数据)
- 外观检查结论
- SPC控制线参数(USL/LSL/均值)
```
Excel 版本：
```
请读取线束压接质量数据.xlsx，按批次号提取压接高度和拉脱力的实测数据列，计算每批次的Cpk值。
```
（30 份 PDF 数据约 30 秒提取完毕；OCR 可处理扫描版，前提是扫描质量还行）

**第 2 步：自动算 SPC 指标**
```
对提取到的所有批次数据，计算以下SPC指标：
1. 每个批次的Cpk(压接高度Cpk+拉脱力Cpk)
2. 检查是否存在以下SPC异常信号：连续5个点在控制线同一侧 / 连续7个点呈递增或递减趋势 / 单点超过3σ控制线 / Cpk低于1.33
3. 输出异常批次清单，包含批次号、异常类型、异常数据位置
```
（WorkBuddy 跑 Python 脚本做统计计算，以前一上午算不完的 Cpk，5 分钟全出结果）

**第 3 步：自动标记异常批次，准备 8D 前置数据**
```
对标记为异常的批次，提取以下8D前置数据：
- 该批次连续3天的SPC趋势数据(压接高度和拉脱力)
- 该批次的设备参数(压接机型号、压接模具号、压接压力设定值)
- 该批次端子的供应商信息(端子型号、供应商批号、来料日期)
- 该批次前5个正常批次的对比数据
输出一份8D前置数据表，格式为Excel，包含趋势图数据列。
```
（8D 报告的 D2-D4 数据基本齐了；涉及对外回复的 8D 报告正文，AI 写完后人工再审一遍）

**第 4 步：生成每日质量汇总表**
```
生成今日线束压接质量日报，包含：
- 总批次数/正常批次次数/异常批次次数
- 异常批次的异常类型和Cp值
- SPC趋势预警（哪些指标在恶化）
- 需要立即处理的批次清单
```

### 实测效果（P3011 线束项目案例）
| 时间 | 动作 |
|---|---|
| 8:05 | 把 30 份 PDF 报告丢给 WorkBuddy |
| 8:08 | 数据提取完毕，600+ 数据点全在 |
| 8:10 | SPC 计算完毕，3 个批次有异常信号 |
| 8:12 | 8D 前置数据表生成完毕 |
| 8:15 | 每日汇总表生成，Cpk 最低 1.28，揪出 1 个连续 5 点偏向异常 |

> 以前一上午的活 15 分钟搞定。那个连续 5 点偏向信号以前手动核对漏掉了——若漏掉，Cpk 继续下滑到 1.0 以下客户就会要求停产整改。

### FAQ 速答
- **PDF 扫描版能处理吗**：能，WorkBuddy 有 OCR 能力，前提扫描质量尚可
- **SPC 控制线参数每个客户不一样怎么办**：把客户规范文件（PDF/Excel）一起喂给 WorkBuddy，让它先读规范值再计算
- **数据格式不一样怎么办**：告诉它你的格式（如批次号叫 "LOT No." 而非"批次号"），它按你的格式提取
- **数据量大会不会慢**：30 份 PDF 提取约 30 秒，SPC 计算+异常标记约 2 分钟，全流程 5-8 分钟

### 检测人新手建议
先从最折磨你的数据核对环节入手，痛点在哪就从哪开始让 WorkBuddy 接管，把一个环节搞顺了再扩展，别想一步到位。

# 第二部分：法务 / 法律案例

## 📌 法务核心洞察

律师日常中能标准化的任务 = AI 使用的最佳切入点。以下 8 个场景都是「标准化、重复性、耗时间但不需要高级判断」的工作——挑一个最烦的先试，不用一次全上。

## 律师使用 WorkBuddy 提高效率的 8 个场景

### 1. 类案检索（联网搜索+网页浏览+文档分析）
把案件基本事实、争议焦点、关心的法律问题发给 WorkBuddy，让它去裁判文书网、北大法宝等平台搜索类案：
- 自动打开搜索结果页，逐个点开判决书
- 提取裁判要旨、争议焦点、判决结果
- 按相似度排序，标注与手头案件的关联点
- 输出结构化的类案对比表（Excel 或 Markdown）
- **省时**：手动翻 20 个判决半天到一天 → 20-40 分钟
- **注意**：它搜到的不一定全，关键案件自己复核一遍

示例指令（口头辞退+未签合同）：
```
[基本事实或法律问题]: 我被公司口头辞退，入职半年没签书面劳动合同，能主张哪些赔偿？
[工作内容]: 去裁判文书网、北大法宝等平台搜索类案
[主要流程]: 自动打开搜索结果页，逐个点开判决书 → 提取裁判要旨、争议焦点、判决结果 → 按相似度排序，标注与手头案件的关联点 → 输出结构化的类案对比表
```

### 2. 合同审查（文件读取+长文本分析+批量对比）
```
【任务名称】：合同审查
【主要内容】：把合同文件（PDF、Word都行）发给你，你重点关注条款类型包括「......」，请你分析、提取核心条款并标注风险。
【主要流程】：通读全文，提取关键条款（违约责任、争议解决、交割条件、税费承担等）→ 自动检查条款之间的冲突（如付款节点和解锁条件是否矛盾）→ 标注缺失条款和风险条款 → 输出「条款清单+风险提示」审查报告
```
- **省时**：50 页合同手动审三遍 1-2 天 → AI 通读提取 10-15 分钟 + 人工复核 1 小时
- 输出含：风险等级汇总（高/中/低）、条款冲突对照、修改建议

### 3. 意见书底稿整理（文档转换+信息提取+结构化整理）
```
【任务名称】法律意见书底稿整理
【主要内容】把项目原始材料（工商信息、股东名册、合同关键条款、交易架构说明）发给，请你帮我整理成标准化的项目底稿。
【主要流程】把PDF、Word、Excel、PPT等不同格式的材料统一转成可读文本 → 按法律意见书的逻辑结构(基本事实→法律依据→分析论证→结论建议)整理信息 → 自动补充相关法规检索 → 生成底稿框架，你在这个框架上做分析
```
- **省时**：并购项目底稿整理手动 4-5 小时 → 1 小时内出初稿
- 需要安装 markdown 技能（markitdown）

### 4. 庭审准备（文档分析+逻辑推演+法规更新检索）
把证据材料、起诉状/答辩状、代理思路发给 WorkBuddy，做三件事：
- **① 证据清单初稿**：证据按时间线或逻辑分组 → 每个证据生成「证明目的」初稿 → 标注证据关联关系
- **② 对方反驳点预判**：根据代理方向反向推演对方抗辩理由 → 列出每个反驳点的应对思路 → 你来判断哪些预判有价值
- **③ 法规更新检查**：检索最近 3-6 个月司法解释、指导案例、法规修订 → 标注对案件有影响的新规
- **省时**：庭前准备压缩约 40-50%，尤其证据清单和法规更新检查

### 5. 尽职调查材料整理（批量文档处理+信息提取+交叉验证）
```
【任务名称】尽职调查材料整理
【主要内容】把尽调材料包发给你(工商档案、财务报表、合同台账、知识产权清单等)，请你按尽调清单逐项提取信息并标注异常。
【主要流程】按尽调标准清单(主体资质、资产权属、合同义务、诉讼仲裁、知识产权、劳动人事等)逐项填信息 → 自动交叉验证不同材料间的矛盾(如工商登记的股东和合同里写的出资方是否一致) → 标注信息缺失项和存疑项 → 输出尽调信息汇总表
```
- **省时**：尽调材料几十份文件人工 2-3 天 → 半天内出初稿

### 6. 客户沟通纪要（截图识别+信息提取+结构化整理）
把微信聊天截图、录音发给 WorkBuddy：
- 提取咨询时间、核心问题、答复要点
- 标注下一步行动事项和截止时间
- 按客户分类存档，下次客户再来直接调取上下文
- 识别待办事项按紧急程度排序
- **价值**：客户体验——隔三个月客户再来，你张口就能说出上次聊到哪，信任感比营销有用

### 7. 法律文书模板管理（文件管理+Skills 技能系统）
把常用文书模板（起诉状、答辩状、代理词、法律意见书、备忘录）和写作规范沉淀成 Skill：
- 固化写作习惯、格式要求、常用表述为可复用模板
- 每次生成初稿自动套用格式和风格
- 团队共享同一套标准，保证出品一致性
- 随时更新模板，所有调用自动同步
- **适合**：带团队的合伙人、有固定业务类型的律师

### 8. 个人知识库沉淀（记忆系统+Skills 技能系统）
日常处理案件过程中，让指令、反馈、常用分析框架自动沉淀进记忆系统，定期整理成「个人知识手册」：
- 记住每个项目的上下文（案件背景、客户偏好、分析思路）
- 记住工作习惯和偏好（文书风格、检索习惯、常用法规）
- 碎片经验串成体系化知识文档
- 带新人直接共享知识库，缩短培养周期

# 第三部分：连接器 / 平台接入案例

## 📌 连接器核心洞察

**比喻**：普通 AI 聊天像打印机（你问它答，结果留在屏幕上，要发别处得自己复制粘贴）；连接器（MCP）就像给打印机装了一根网线——"你告诉它打到这里，它自己送过去"。

**一句话总结整套逻辑**：在 WorkBuddy 里做完所有事，通过连接器，推到你工作的任何地方。连接器是所有工作流的最后一步，省掉"搬运"。

## 一、连接器使用场景速览

| 你让 AI 做了什么 | 通过哪个连接器 | 最终去哪里 |
|---|---|---|
| 写了一份会议纪要 | 飞书连接器 | 同步到飞书文档，生成链接转发团队 |
| 写好了一篇营销文案 | 邮箱连接器 | 直接以邮件正文形式发送给客户 |
| 整理了一批行业资料 | ima 连接器 | 自动导入知识库，下次直接搜索 |
| 完成了一次复盘报告 | 钉钉连接器 | 同步到项目文件夹，领导直接批阅 |
| 生成了一套教案 | 腾讯文档连接器 | 同步到共享空间，教研组一起修改 |

**四步工作流案例（写活动通知，30分钟→2分钟）**：
1. 告诉 AI 基础信息（时间/地点/主题/参加人）
2. AI 生成通知（记得你的组织语言偏好）
3. 你审阅修订（通常只改几个字）
4. 一键同步："通过钉钉连接器，把这份通知同步到我的钉钉文档空间"

**配置方式**：连接器管理页面 → 找到需要的服务 → 点击授权 → 开启 Trust，无需任何开发。

## 二、钉钉接入全教程（Claw 集成，约 5 分钟）

> 接入后钉钉变成 AI 指令终端：发一条消息，电脑自动执行；出差路上也能远程干活；机械操作全甩给 AI。

### 前提条件
- 电脑已安装 WorkBuddy 客户端并登录
- 手机/电脑已登录钉钉（个人版/企业版均可）

### 电脑端配置（简版）
1. **打开 Claw 设置**：WorkBuddy 客户端 → 右上角头像 → 「Claw 设置」
2. **开启钉钉集成**：找到「钉钉集成」→ 点击【配置】→ 弹出绑定二维码（**有效期仅 300 秒/5 分钟**，过期重新生成）
3. **扫码绑定**：手机钉钉扫一扫 → 界面显示「钉钉绑定成功」

### 钉钉开发者后台配置（简版）
1. 访问钉钉开发者后台（open.dingtalk.com），管理员登录；未加入组织可先创建个人企业
2. **创建应用**：「应用开发」→「创建应用」→ 企业内部应用 → 填应用名称/描述 → 保存
3. **添加机器人能力**：自动跳转「添加应用能力」→ 填机器人名称/图标/简介 → 确认发布
4. **配置权限**：「权限管理」→ 搜索并开通 Card.Streaming.Write 等权限
5. **获取凭证**：「凭证与基础信息」→ 拿到 Client ID（原 AppKey）和 Client Secret（原 AppSecret）
6. **在 WorkBuddy 配置**：Claw 设置 → 钉钉集成 → 填入 Client ID 和 Client Secret → 注册 → 复制 Webhook
7. **配置消息接收**：钉钉机器人配置页 → 消息接收模式切换「HTTP 模式」→ 粘贴 Webhook（**注意把 http 改为 https**）→ 发布
8. **发布应用**：版本管理 → 填版本号/描述 → 确认发布（通常自动审批）

### 群内使用
1. 创建/选择群聊（群归属组织与机器人创建组织相同）
2. 群设置 → 机器人 → 添加机器人 → 搜索选择创建的机器人
3. 群里 @机器人 发需求 → WorkBuddy 自动执行并回复结果

### 使用注意
- WorkBuddy 需保持后台运行，钉钉指令才能被执行
- 电脑睡眠/关机时任务无法执行，建议开启"防自动休眠"
- 首次使用先在电脑端授权 WorkBuddy 访问需要的文件夹
- 企业版钉钉遇权限限制，联系 IT 管理员开放第三方应用接入权限
