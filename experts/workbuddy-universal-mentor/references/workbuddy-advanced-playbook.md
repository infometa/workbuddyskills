# 第一部分：积分优化与成本控制（小骆笔记精华）

## 三大烧积分坑（先反问三个问题找原因）

### 坑 1：什么活都用 Craft 模式
三种模式用途和消耗完全不同：
- **Ask**：只问答、不碰文件。查概念、翻译词、问日期——轻量查询用 Ask，消耗极低
- **Plan**：先出方案再动手。复杂任务防翻车用它，多一步确认少一堆返工
- **Craft**：直接干。批量处理、真要动文件的时候才用

**切模式是最容易见效的一刀**——很多人从头到尾挂 Craft，问"今天几号"也走完整流程。

### 坑 2：简单任务也上大模型
模型分档，消耗差好几倍：
- 格式转换、分类、抽取、简单改写 → 轻量模型完全够
- 复杂分析、长链路规划、难代码 → 才值得上大模型
- **判断标准**：这个任务交给一个刚入职的实习生，他能做对吗？能，就用轻量档

> 💡 骆栈说：用旗舰模型做机械活，是最贵的坏习惯。大部分人的消耗都花在"大炮打蚊子"上。

### 坑 3：指令一改再改
"先写个总结"→"不对再详细点"→"太长了缩短"→"格式改一下"……每一轮都是完整消耗。
**一个好指令包含三件事**：
- 做什么：具体动作
- 有什么：文件路径、素材、背景
- 怎么样：格式、字数、风格、给谁看

## 两个小技巧
1. **一个会话只干一件事**：上下文越长每轮消耗越高，任务换了就开新会话
2. **让它别啰嗦**：指令加"不需要开场白""直接给结果"，输出短了就是省钱

> 💡 省积分的本质 = 减少无效动作（无效的模式、无效的模型、无效的返工）。

# 第二部分：进阶高手手册（夜秣，万字总结精华）

## 一、四级进阶路线图——你在哪一层？

| 阶段 | 核心能力 | 关键动作 | 预期效果 |
|---|---|---|---|
| L1 基础 | 单任务执行 | 安装WorkBuddy，发简单指令 | 代替手动操作 |
| L2 进阶 | 定时自动化 | 设置定时任务，沉淀工作流 | 每天省1-2小时 |
| L3 高手 | 多Agent并行 | 创建细分AI员工，多Agent协作 | 效率提升3-10倍 |
| L4 专家 | 生态集成+多机集群 | 从skillHub导入技能，多设备协同 | 7×24小时AI军团 |

**7 天上手建议顺序**：第1天安装登录→第2天装 xlsx/docx/pptx 三技能→第3天练"三要素"需求描述→第4天绑定微信远程操控→第5天第一个定时任务→第6天自动化工作流→第7天多Agent并行（3人团队起步）

**核心经验 8 条**：
1. 先写规范文档再执行（MASTER_PROMPT.md 是基石）
2. 用记忆文件传递跨会话上下文（MEMORY.md + 每日日志避免 AI"失忆"）
3. 复杂任务拆成流水线（每层独立可测可重试）
4. 人工只做"判断型"工作（审核、把关、决策）
5. 建立反馈循环（发现问题就更新规范）
6. 遇到重复工作 → 停下来想想能不能自动化 → 用 Skill 封装
7. 技能装了不用等于没装——关键是串成"能跑的流程"
8. 从"执行者"转变为"管理者"——AI 的价值是让你变成指挥官

## 二、多 Agent 并行——一个人指挥一支 AI 团队

**白话翻译**：同时派多个 AI 助手干活，每个负责不同的部分，同时开工效率翻倍。
- 串行总时间 = 调研 + 写文案 + 做图表；并行总时间 = 最慢的那个任务

**适合并行**：信息收集（多来源查不同信息）/ 并行开发（前后端同时）/ 多文件处理 / 对比分析
**不适合并行**：前后依赖的串行任务 / 需要严格顺序的操作

**三步启用**：
1. 判断任务是否可拆分（好描述："分别从市场数据、政策趋势、技术路线三个维度同时调研，最后汇总成一份完整报告"）
2. 用自然语言描述："请同时启动3个Agent做竞品分析：Agent1负责产品功能和定价，Agent2负责用户评价口碑，Agent3负责技术实现方案，最后合并成完整报告"
3. 确认方案，AI 自动拆分子任务并行执行

**推荐团队配置**：
- 最小三人团队（新手推荐）：总控官（分配/汇总/协调）+ 技术官（代码开发）+ 研究官（搜索/分析）
- 进阶六人团队：总控官 + 技术官(前端) + 技术官(后端) + 研究官 + 内容官 + 质检官
- ⚠️ Agent 数量 2-5 个最佳，太多增加协调成本

**进阶技巧**：明确职责边界 / 善用通信机制（Agent 可互发消息）/ 及时检查中间结果 / 配合定时自动化

## 三、空间管理——给 AI 分办公室

**空间 = AI 的"办公室"**：同一空间的 AI 共享文件柜（memory）和成果；不同空间像不同楼，共享信息需手动搬运。

**规划原则**：需要信息共享/成果直接衔接 → 放同一空间；独立工作不共享 → 分开放（避免串信息省 token）

> ⚠️ **超级重要警告：空间搬家 = 记忆丢失！** AI 的记忆和训练成果锁在创建它的空间里，无法迁移！真实案例：有人把 3 个 Agent 搬家后，新空间的 Agent 对之前教过的内容一无所知。一开始就规划好空间分配！

**工作目录命令**：`/folder` 查看当前目录；`/folder C:\Projects` 切换目录；`/cwd` 查看当前工作目录
**团队工作区**：左上角「工作区」→「+」→「新建团队工作区」→ 启用团队协作模式 → 添加成员分配角色（管理员/成员/访客）

## 四、自定义 Skill 开发——把工作流变成可复用的武器

### SKILL.md 基础结构
```
my-skill/
├── SKILL.md        ← 核心（名称、描述、触发词、工作流）
├── prompts/        ← 提示词模板目录
├── scripts/        ← 脚本文件目录
└── references/     ← 参考资料目录
```

### SKILL.md 模板
```
---
name: my-skill
description: 这个技能是干什么的（一句话说清楚）
version: 1.0.0
author: xxx
triggers:
- 自动化
- 自动批改
tags: [标签1, 标签2]
---

# 技能名称
## 触发条件
当用户说 [xxx] 或 [xxx] 时触发此技能
## 工作流程
1. 第一步做什么
2. 第二步做什么
3. 第三步做什么
## 提示词模板
（你的提示词内容）
## 输出格式
（期望的输出格式说明）
## 注意事项
（使用时需要注意的点）
```

### 三种创建方式
1. **图形化界面（推荐新手）**：个人中心 → Claw设置 → Skills管理 → +新建技能
2. **让 AI 帮你写（最快）**："帮我创建一个技能，功能是将PDF文件批量转成Word文档" → AI 自动生成 → 确认保存
3. **从操作习惯自动生成（最智能）**：通过企微等平台发三次结构相似指令，系统识别模式主动帮你生成带变量的 Skill

### 安装路径
- 用户级：`~/.workbuddy/skills/`（所有项目可用）
- 项目级：`{workspace}/.workbuddy/skills/`（仅当前项目）
- 通用技能放用户级，项目专属放项目级

### 调优技巧（从"能用"到"好用"）
1. **规则要具体不要模糊**："用三段结构：问题引入、解决方案、效果对比"而非"输出要好看"
2. **给出反例**：写完正面规则加"不要怎么做"（"不要用Markdown标题"比"输出纯文本"更有效）
3. **保留修改记录**：每次发现新坑就加到 SKILL.md，越用越准
4. **测试边界情况**：拿边缘场景测试

### 发布到技能市场
访问 clawhub.ai → GitHub 登录 → 填技能信息 → 提交审核（1-3 工作日）→ 通过后所有人可装

## 五、MCP 协议——给 AI 装一个万能插头

**白话翻译**：MCP（Model Context Protocol）是 AI 连接外部工具的"万能插头"。没有 MCP 的 AI = 有大脑但没手；有了 MCP 的 AI = 有大脑又有无数工具手的超人。

**MCP 配置模板**（配置文件 `~/.workbuddy/mcp.json`）：
```json
{
  "mcpServers": {
    "tencent-docs": {
      "command": "node",
      "args": ["path/to/mcp-server.js"],
      "env": { "API_KEY": "你的API密钥" }
    },
    "github": {
      "command": "npx",
      "args": ["@modelcontextprotocol/github"],
      "env": { "GITHUB_TOKEN": "你的GitHub Token" }
    }
  }
}
```

**可集成服务**：办公协作（飞书/企微/钉钉/Notion）、开发工具（GitHub/GitLab）、地图（高德/腾讯）、设计（墨刀）、本地应用（浏览器/邮件/文件系统）

**实战：连接墨刀 MCP 4 步出原型**：
1. 申请墨刀 MCP 权限（企业版/专业版 → 账户中心 → API/开发者设置 → 开启 MCP → 生成 Token + 团队空间 ID）
2. 配置到 WorkBuddy（type: http, url: https://mcp.modao.cc/sse, headers 带 Authorization 和 X-Team-Id）
3. 自然语言画原型："帮我在墨刀里创建一个'用户登录页面'：顶部 App Logo + 产品名称，中部手机号输入框 + 验证码输入框，底部蓝色'立即登录'按钮，风格白底蓝主色"
4. 打开墨刀查看微调

**连接器四大核心场景**：数据查询（检索腾讯文档/读邮件）、服务调用（发邮件/建日程）、文件管理（读网盘/传附件）、消息通知（发企微/飞书消息）

### 腾讯文档连接器三大革新
| 维度 | 传统流程 | 连接器新流程 |
|---|---|---|
| 资料获取 | 下载到本地再上传 | 语义搜索直接调用云端文档 |
| 格式保留 | 复制粘贴易乱码 | 字版式图表零损伤 |
| 结果同步 | 手动复制回文档 | 一键保存回云端 |

**实战场景**：报告摘要（"找到那份AI发展历程报告，提炼核心要点"）/ PPT大纲（"基于这份季度规划生成5页汇报PPT大纲"）/ 方案更新（"找到上次给客户的方案，基于新需求改写第三章"）/ 数据分析（"从腾讯文档读取Q1各部门销售表，合并计算环比"）/ 周报生成（"读取本周工作台账，生成周报，保存回腾讯文档"）

### 公众号配置与自动化
**获取 API 凭证**：微信公众平台 mp.weixin.qq.com → 设置与开发 → 基本配置 → 记录 AppID → 重置生成 AppSecret（**只显示一次，立刻复制保存！**）
- 认证服务号：完整草稿箱+素材管理接口；订阅号：只能推草稿不能直接群发
**配置 IP 白名单**：基本配置 → IP 白名单 → 添加公网 IP（不知道 IP 让 WorkBuddy 查："帮我检查一下当前电脑的公网IP"）
**配置到 WorkBuddy**："我的公众号配置如下：AppID: xxx, AppSecret: xxx, 请帮我配置公众号发布能力"

**一周运营节奏**：周一选题日（08:00 推热点→08:30 触发选题→09:00 你选3个）→ 周二写稿日（09:00 采素材→10:00 补案例→10:30 写稿→11:30 修改）→ 周三发布日（09:00 排版→09:30 发布→10:00 确认群发）→ 周四重复→周五完成第3篇+周复盘

### ima + WorkBuddy 双平台分工
- WorkBuddy = 执行中枢（对话入口、Skill调度、调用工具、定时触发）
- ima = 知识底座（素材库/风格库/模板库）
- 💡 一句话：WorkBuddy 负责"干活"，ima 负责"查资料"，你负责"拍板"

## 六、高级提示词工程——让 AI 听懂你的潜台词

### 黄金原则
清晰 > 模糊 / 具体 > 笼统 / 分步 > 一步到位 / 有示例 > 无示例

### 六种高阶技巧
1. **角色设定法**："你现在是一个有10年经验的新媒体运营专家，擅长公众号内容策划和增长策略。请帮我分析以下文章的优缺点并给出改进建议。"
2. **分步指引法**："请按以下步骤执行：1.先读取 data.xlsx 文件 2.筛选出销售额大于10000的记录 3.按地区分组统计 4.生成柱状图 5.输出分析报告到 report.docx"
3. **输出格式约束法**："请生成竞品分析报告，要求：格式Word、结构5章节（概述/市场定位/功能对比/定价策略/建议）、每章300-500字、正式商务风格、至少3个对比表格"
4. **异常处理法**："帮我批量处理这些图片：如果图片无法读取，跳过并记录文件名；如果压缩后仍超500KB，降低质量再试一次；每处理10张汇报一次进度；全部完成后生成处理报告"
5. **上下文传递法**："参考我之前写的这篇文章（已上传），按照相同的风格和结构，帮我写一篇关于[新主题]的文章"
6. **流水线提示词（多步骤协作）**：三层流水线（结构打碎→语言重写→灵魂注入），去掉模板化结构，加入口语连接词/个人观点标记/适当不确定性表达

### 四要素高质量 Prompt 框架
目标（达到什么目的）+ 输入（用什么数据干活）+ 格式（输出格式）+ 约束（边界条件）

### MASTER_PROMPT.md 模板（重复性工作全局规范）
```
# MASTER_PROMPT.md
## 你的角色
你是一个专注于[领域]的公众号写手，风格[特点描述]
## 写作规范
- 标题：[标题公式/风格]  - 开头：[开头模板]
- 正文：[结构要求]       - 结尾：[结尾风格]
- 字数：[字数范围]
## 排版规范
- 段落不超过3行  - 小标题用emoji开头
- 重点内容加粗    - 每500字插入一张配图描述
## 禁止事项
- 不使用「首先其次最后」这类模板词
- 不使用「总而言之」等总结套话
- 不堆砌形容词  - 不写空洞的大道理
```

## 七、记忆系统深度应用

### 三层架构
| 层级 | 存储位置 | 作用范围 | 内容类型 |
|---|---|---|---|
| 云端记忆 | 服务器自动管理 | 所有项目 | 用户长期偏好、习惯 |
| 用户级本地记忆 | ~/.workbuddy/MEMORY.md | 所有项目 | 精准的强制规则 |
| 工作区记忆 | {workspace}/.workbuddy/memory/ | 当前项目 | 项目规范、每日日志 |

### 记忆维护最佳实践
1. **重要决策必须写进 MEMORY.md**：心里想的"下次记住用深色背景"→ 写"配图规范-背景色:深色系#0D1117"
2. **每日日志是 AI 的"工作复盘"**：今日完成 / 遇到的问题（含解决方案）/ 明日计划
3. **定期压缩过时内容**：超 30 天的日志"蒸馏"精华合并到 MEMORY.md，删除旧日志

### 记忆错误处理
记忆过时（定期清理 MEMORY.md 过时内容）/ 记忆冲突（检查矛盾规则）/ 记忆丢失（确认文件存在且格式正确）

1 小时审核 AI 产出（决策型）+ 1 小时优化自动化流程（创新型）+ 1 小时客户沟通（关系型）+ 1 小时学习新技能（成长型），其余重复性工作全部交给 WorkBuddy

### 公众号日更实战（压缩到每天 1 小时）

- 早上人工决策：08:00 选 1 个选题 → 08:15 补观点案例 → 08:30 AI 生成全文
- 上午自动化+人工：09:00 自动排版配图 → 09:30 审核发布

素材库（行业报告/数据图表/案例故事/金句）+ 风格库（爆款TOP20/竞品收藏/写作风格）+ 模板库（排版模板/标题公式/开头结尾模板）+ 竞品库（同领域TOP10账号）+ 运营库（发布记录/数据复盘/读者反馈）

## 九、安全策略——玩得野但不能翻车

### Skill 安装安全审查红旗信号
| 风险类型 | 具体表现 | 等级 |
|---|---|---|
| 网络访问异常 | curl/wget 到未知 URL、向外部发数据 | 高 |
| 凭证获取 | 索要 API 密钥、令牌、密码 | 极高 |
| 敏感目录访问 | 读取 ~/.ssh、~/.aws 等 | 极高 |
| 动态代码执行 | eval()/exec() 执行外部输入 | 高 |
| 代码混淆 | base64、压缩、加密可疑内容 | 高 |

# 第三部分：Skill 避坑——装了 61 个，活下来的只有 1 个（副厂长）

## 血泪教训
- 作者装了 61 个 Skill（50 个市场装 + 11 个自建），真正反复被改的只有 1 个（公众号写作 Skill，13 个文件，每行都是翻车喂出来的）
- **装上的那天就是它一生的巅峰**：一大半目录的修改时间停在装上的那一天
- 公众号相关装了 13 个（选题雷达/爆款检测/文案生成/排版发布），真正每天跑的只有 1 个
- 有三对重复的（pro 和 pro-plus 并存、去 AI 味 v1 和 v2 并存、英文版和中文版并存）——装新版从不删旧版

## 核心洞察
- **装 Skill 这个动作，本来就产生不了价值**：它是约束文档，告诉 AI 在你这里什么能做什么不能做——可约束只能从你自己的翻车里长出来。别人的 Skill 写着"不要用深蓝模板"，你没被自己的封面恶心过，这行字对你就是空气
- 装 61 个和装 3 个，能力上没有区别，区别只发生在改第一行的那个瞬间

## 判断 Skill 该不该留的三个问题
1. 近 30 天，它有没有被真实调用过？
2. 它有没有因为你的某次翻车，被改过哪怕一行？
3. 现在删掉它，你慌不慌？
- 三个都答不上来，删。留着它只是给收藏夹交房租

> 💡 装是一秒钟的事，养需要几十篇稿子的翻车。工具这个东西，占有欲是最便宜的部分。
