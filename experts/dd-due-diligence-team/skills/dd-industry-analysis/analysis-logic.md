# 行业分析逻辑

## 分析五要素

行业分析围绕五个核心要素展开，对应 E1-E8 八个维度：

| 要素     | 对应维度                  | 回答的问题                       |
| -------- | ------------------------- | -------------------------------- |
| 市场多大 | E1 市场规模               | 这个行业的总盘子多大？           |
| 增长多快 | E2 增长率                 | 行业还在增长吗？增速趋势？       |
| 方向在哪 | E3 发展趋势 + E4 监管政策 | 行业往哪走？政策支持还是限制？   |
| 谁是玩家 | E5 竞争格局 + E7 行业地位 | 行业里谁领先？本企业排第几？     |
| 风险在哪 | E6 风险因素 + E8 上下游   | 有哪些行业风险？上下游议价能力？ |

## 分析顺序

```
E0 行业定位（已确认）
  │
  ├─ E1 市场规模（市场多大）
  │   └─ E2 增长率（增长多快，基于 E1 历史数据算 CAGR）
  │
  ├─ E3 发展趋势（技术/产业/出海方向）
  │   └─ E4 监管政策（政策方向 + 贸易壁垒）
  │
  ├─ E5 竞争格局（CR5 + 竞争者对标）
  │   └─ E7 行业地位（本企业在 E5 中的位置）
  │
  ├─ E8 上下游产业链（供应链 + 需求链）
  │
  └─ E6 风险因素（从 E1-E5/E8 识别风险）
```

## 判断逻辑

### E1 → E2 依赖

- E2 的 CAGR 基于 E1 的历史市场规模数据计算
- 脚本 calculate.py 输入 E1 的 marketRows，输出 CAGR

### E5 → E7 依赖

- E7 的"本企业市占率"和"行业排名"基于 E5 的 competitors 列表
- 脚本 calculate.py 输入 competitor_shares，输出 share_percentile

### E1-E5/E8 → E6 聚合

- E6 风险因素从其他维度识别：
  - E1/E2：增速下降 → 市场风险
  - E3：技术替代 → 技术风险
  - E4：贸易壁垒 → 政策风险
  - E5：CR5 过高 → 竞争风险
  - E8：上游集中度高 → 供应链风险

## 降级策略

当材料不足时，按以下策略降级：

| 缺失材料     | 降级处理                                                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 行业研究报告 | 优先通过 cnfinancialscraper 搜索引擎检索（百度/搜狗）；失败则降级为 web_search；仍无结果则 E1/E2 标注“数据不足，基于行业常识估算” |
| 竞争对手数据 | 优先通过 cnfinancialscraper 获取上市竞争对手实时行情（`get_stock_realtime`）；失败则降级为 web_search；仍无结果则 E5 填“暂无数据” |
| 产业政策文件 | 优先通过 cnfinancialscraper 搜索引擎检索监管政策；失败则降级为 web_search；仍无结果则 E4 标注“请补充政策文件”                     |
| 产业链图谱   | 优先通过 cnfinancialscraper 舆情爬取获取上下游动态；失败则基于行业常识推断                                                        |
| 宏观经济数据 | 优先通过 cnfinancialscraper 的 akshare 通道获取（`get_structured_data`，零反爬）；未装 akshare 则降级为 web_search                |

**数据源降级链**：

```
cnfinancialscraper（优先，结构化数据）
    │
    ├─ akshare 通道（零反爬，结构化市场数据）
    ├─ RSS 直连（零反爬，新闻资讯）
    ├─ 搜索引擎（百度/搜狗，可能触发限流）
    └─ 直接网页爬取（最容易触发反爬）
         │
         └─ 失败时降级为 web_search MCP 工具（稳定兜底）
```

降级时必须：

1. 在对应 evidence 标注“行业常识推断”或“公开搜索”
2. 在 insights 中加 warn 类型提示“数据不足”
3. 不影响 E0 已确认的字段
