# 财务分析逻辑

## 职责边界

| 工作                                                               | 执行者         |
| ------------------------------------------------------------------ | -------------- |
| 材料识别、原始字段抽取和来源定位                                   | LLM            |
| 公开缺口分类、定向检索、来源与主体语义核验                         | LLM            |
| 单位换算、平均余额、公式、期间变化、阈值、勾稽、行业和外部数据差异 | `calculate.py` |
| 行业/阶段/业务归因、证据强度、风险影响和核验建议                   | LLM            |
| 数字回填、章节组装、缺件披露、指纹和 Word/JSON 落盘                | `render.py`    |

## 证据链

`进件材料 → 本地抽取 → financial-input.json → 首次脚本计算 → 公开缺口计划 → 来源/主体核验 → financial-input-final.json → 最终脚本计算 → financial-render.json → 最终报告 JSON + Word`

材料事实要有文件、页码/表名或字段定位；公开事实还要有 URL、发布机构、检索日期、法定全称和稳定主体标识，公开补入的每个数值字段必须通过 `enrichments` 与同一 `source_id` 绑定；计算事实要有公式、输入和结果；业务推断要列依据及替代解释；资料不足要形成待核验事项。

## 分析顺序

1. 核对期间、主体、合并范围、会计准则、币种、单位、签章和审计意见。
2. 在本地材料中完成三表、附注、期初余额和上年同期抽取。
3. 执行首次脚本计算，区分抽取错误、公开可补缺口和只能由企业/银行提供的缺口。
4. 按 `research_mode` 定向检索；核验来源、主体、期间和口径后，只以 `fill-null` 合并公开值，进件冲突时保留进件值。
5. 执行最终脚本计算；报告只使用最终脚本结果。
6. 使用全部可计算结果和已核验证据完成主体分析；正文只写结论、关键依据和信贷影响。
7. 读取 `statement_changes` 的显著异动科目（`significant_items`）、分级（`severity`、`direction_reversed`）、双判据（`dual_trigger`）和归因（`attribution`）及匹配附注明细，优先解释 `severe_items` 与 `dual_trigger_items`，说明资产负债、利润和现金流变化及主因。
8. 分析偿债、营运、盈利和成长能力，交叉观察利润现金转化和期限匹配。
9. 只用有来源、年份、样本和定义的行业基准做对标。
10. 将规则信号与可用附注、账龄、库龄、债务和公开披露交叉观察；私有真实性材料缺失时明确未执行相应验证。
11. 总结第一还款来源、主要关注和条件性结论；将缺件、冲突、未执行验证、来源和追溯统一归入文末“资料与核验事项”。

默认在材料不完整时继续生成有限报告。仅当企业主体、报告期、报表口径或单位存在阻断性冲突时暂停；用户明确选择“确认后继续”时，首次计算后只进行一次集中确认。

## 失败与降级

- 任一 critical 勾稽未通过或不可计算：不得标记为已核验；失败项优先重新抽取，仍无法解决时生成有限材料 Word，并将失败项归入文末核验事项。
- 字段缺失、分母为零或分母不符合经济有效域：结果保留 `null`；Word 中显示“—”，限制统一在文末说明，不停止有限报告生成。
- 报表口径不可比：保留原值，不生成趋势或行业差异结论。
- 中期缺少上年同期、少于三个连续完整年度、15 项标准指标存在不可计算项：只能生成 `verified: false` 的有限材料 Word。
- `source_unit`、币种、报表口径或报告期天数未明确：停止计算；禁止默认按元、默认同口径或固定按 365 天处理。
- 行业基准无来源：不做数值对标，不允许模型补数。
- 外部材料缺失：在文末标记相应验证未执行，正文不得写“已验证”。
- 联网工具不可用或无合格结果：降级使用进件材料继续分析，并准确记录研究状态。
- 公开来源与进件冲突：不得覆盖、平均或择取有利值；以进件值参与计算，冲突统一在文末披露。
- 主体、期间、口径或单位不确定：拒绝公开来源；公司事实缺少“法定全称 + 证券代码/统一社会信用代码”双重匹配时不得进入数值字段。
- 第三方公开资料：只作背景或线索，除合格行业基准外不进入数值字段。
- narrative 缺失不是进件缺失：只要对应报表或指标可计算，LLM 必须完成该分析小节；默认兜底文字不能作为最终交付。
- 所需数字不在脚本输出：先扩展并测试脚本，再撰写。
- 降级不等于停止：只要结构化输入可被 `calculate.py` 合法处理，就必须生成 Word；不得仅返回 Markdown、聊天正文或缺件清单。
