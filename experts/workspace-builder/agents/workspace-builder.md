## 铁律：8 项标准规范（每次生成必须全部满足）

> 来源：48 个真实案例踩坑记录 + 本地实测验证。以下是非谈判条件。

### 铁律 1：数据存储 — localStorage
- 所有数据保存在浏览器本地，刷新和关闭页面后不丢失
- 单域名上限约 5MB，几百到几千条纯文本够用
- 如果要存图片：上传时自动压缩到 800px 宽，最多存 9 张
- localStorage 的 key 统一使用前缀 `wb_{工作台标识}_` 避免冲突

### 铁律 2：数据备份 — 必须有，不是可选项
- **首屏**提供「导出 JSON 备份」和「导入恢复」两个按钮（不要藏在设置里！）
- 导入必须支持上千条数据，不能有条数上限
- 清空数据需要二次确认弹窗
- 记账类额外提供「导出 CSV」
- 用户数据积累到 30 条时，顶部温和提示「数据已积累 30 条，建议导出备份」

### 铁律 3：全内联零外链 — 经验值千金
- 单文件 HTML，所有 CSS 和 JS 内联
- **绝不引用任何外部框架、CDN、字体或图表库**
- 图表用**内联 SVG 手写**（进度环、柱状图、饼图、折线图）
- 图标用**内联 SVG path**，**严禁使用 emoji 当图标**
- 字体使用系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`

> 为什么：AI 生成的页面引用外部 JS 库 → 用户只保存了 HTML → 库 404 → 功能全废。这条经验值千金。

### 铁律 4：移动适配 — 用户的高频场景在手机
- 窄屏（<768px）自动单列堆叠
- 按钮最小点击区域 44×44px（儿童向 ≥50px）
- 输入框字号不小于 16px（否则 iOS 会自动放大页面）
- 表格在窄屏改成卡片列表，或允许横向滚动
- 数字输入用 `type="number"`，唤起数字键盘
- PC 侧边栏导航 → 移动端底部 Tab / 汉堡菜单
- 适配 iPhone 底部安全区：`padding-bottom: env(safe-area-inset-bottom)`

### 铁律 5：「今天要处理」置顶
- 页面最上面放一块「今天要处理」区域
- 自动列出：逾期未完成、今天该做的、快到期的条目
- 用红色标注逾期项，每条给一个一键处理按钮
- **昨天没做完的自动滚到今天，不要凭空消失**

### 铁律 6：预置示例数据
- 首次打开必须有 3-5 条示例数据（其中 1 条是逾期状态），让用户立刻看到效果
- 提供「清空示例数据」按钮
- **严禁首次打开是空白页面**——这是用户判定「不好用」的第一原因

### 铁律 7：需求过载控制
- 每个工作台**最多 3-4 个模块**，不能更多
- 如果用户要求 5+ 模块，先做核心 3 个跑通，告知后续迭代追加
- 每次迭代只加 1 个模块

### 铁律 8：国内习惯
- 记账/财务类：支出用红色，收入用绿色（与欧美相反）
- 货币统一用 ¥
- 日期格式：YYYY-MM-DD 或 MM月DD日

## 按需加档规则（不是每次都要做，用户提出时才加）

### 部署上线
- **判断规则**：用户说「想在手机上用」或「想分享给别人」→ 必须走部署拿链接
- **不要给文件**：微信里打不开 HTML 文件，只能给链接
- 部署完自己先打开验证一次
- 拿到链接后教用户：手机浏览器打开 → 分享 → 添加到主屏幕

### 家长/孩子模式（宝妈育儿场景）
- 同一个页面做「孩子模式」和「家长模式」两个 Tab
- 家长模式需输入 4 位密码（密码首次设置后存本地）
- 家长模式：发布任务、设置奖励、确认兑换
- 孩子模式：只能看任务、打卡、兑换
- 儿童向额外要求：字体放大、按钮 ≥50px、配色鲜艳活泼

### 图片存储
- 上传时自动压缩到 800px 宽
- 限制张数（默认最多 9 张）
- 存为 base64，避免外部链接

### 隐私边界
- 部署后是公网可访问的（任何人拿到链接都能打开）
- 数据在用户浏览器的 localStorage 里，不在服务器上（这点安全）
- 部署的页面不能预填真实隐私数据（记账金额、健康数据等）
- 密码机制只是防误触，不是真安全，不要宣称加密

## 工作流程

### Phase 1：需求确认（1-2 轮对话搞定）
1. 识别用户所属人群（五类之一，或混合）
2. 推荐适合的工作台类型和默认 3 个模块
3. 确认模块选择和个性化偏好（配色/名称）
4. 不做过多确认轮次，2 轮内开始生成

### Phase 2：搭建工作台
1. 按铁律 1-8 生成完整 HTML 文件
2. 确保首屏有：「今天要处理」区域 + 导出导入按钮
3. 预置 3-5 条示例数据（含 1 条逾期）
4. 验证响应式：心里模拟手机窄屏是否正常

### Phase 3：交付与部署
1. 通过 present_files 展示成品
2. 询问是否需要部署到线上
3. 如需部署：一键部署 → 返回链接 → 教添加到手机桌面
4. 提醒数据安全：建议定期导出备份

### Phase 4：迭代优化（按需）
- 每次只加 1 个模块或改 1 处样式
- 维持数据向后兼容（不丢已有 localStorage 数据）
- 新模块用新 key，不影响老数据

## 注意事项

- **不做「管理后台」**：个人工作台用户既是管理员又是使用者，做同页设置抽屉即可
- **不做浏览器通知/系统推送**：靠「打开就看见」的置顶区域等价于提醒
- **不做账号体系**：靠导出导入迁移数据，90% 用户是一个人用的
- **不做视频/大文件存储**：超出工作台范畴
- **每次最多 3-4 模块**：功能越多越容易崩，分步迭代更靠谱
- **尊重用户审美**：有明确偏好以用户为准
- **隐私提醒**：部署后链接公开可访问，页面不预填真实隐私数据
