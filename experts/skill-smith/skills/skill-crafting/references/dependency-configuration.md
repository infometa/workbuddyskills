# 依赖配置、环境检查与功能降级

设计依赖 MCP、CLI、API、账号登录、本地工具、模型能力、网络、文件权限或特定运行环境的 Skill 时使用本文件。

## 依赖清单

逐项记录每个依赖，不把多个服务合并成“需要配置”。

| 字段 | 要求 |
|---|---|
| id | 稳定的 kebab-case 标识 |
| type | mcp、cli、api、account、local-tool、runtime、model、network、permission |
| required | 核心流程是否必须 |
| capabilities | 依赖支撑的具体功能 |
| checks | 可机器验证的环境检查 |
| configuration | 用户完成配置的精确步骤 |
| degradation | 缺失或故障时每项功能如何降级 |
| security | 凭据存储、权限最小化、轮换和撤销规则 |

依赖与功能必须可追溯。一个依赖不可用时，只关闭受影响的功能，不笼统宣布整个 Skill 不可用；核心输入、输出或正确性无法保障时才停止主流程。

## 配置引导

每个需要安装、登录、授权或凭据的依赖提供以下信息：

1. 依赖名称、用途和受影响功能。
2. 支持的版本、系统和前置条件。
3. 官方产品主页、官方文档地址、官方下载地址。
4. 需要登录时提供准确的官方登录网址。
5. 获取 Token、API Key、OAuth 授权或 MCP 凭据的准确入口。
6. 登录后的页面路径和逐步操作，例如“控制台 → 开发者设置 → API Keys → 创建密钥”。
7. 需要选择的权限、scope、项目、组织、区域或回调地址。
8. 凭据应写入的环境变量、配置文件字段、Secret 管理器或系统安全存储。
9. 最小验证命令或最小只读请求。
10. 凭据过期、权限不足、额度耗尽、账号无权访问时的处理方式。
11. 轮换、撤销和退出登录的方法及官方入口。
12. 核验日期和适用版本。

实际网址、页面路径和命令必须来自该服务的官方文档或用户提供的可信资料。无法核验时不凭记忆补写，标注“待核验”并停止进入正式交付。

不得：

- 要求用户在对话中粘贴完整 Token、API Key、密码、Cookie 或私钥。
- 在示例、日志、错误信息和交付物中回显完整凭据。
- 把凭据写进 SKILL.md、脚本源码、命令历史或公开仓库。
- 默认申请超出功能所需的权限。
- 用第三方教程、论坛帖子或搜索摘要替代官方配置说明。

## 环境检查

依赖型 Skill 在进入正常功能前先运行环境检查。检查只读取状态，不修改配置、不登录、不安装、不授权。

至少检查：

- CLI 是否存在、路径、版本和基本状态命令。
- Runtime 是否存在并满足最低版本。
- 环境变量是否存在且非空；只输出“已配置/未配置”，不输出值。
- 配置文件是否存在、格式可解析、所需字段是否存在。
- MCP 是否在 WorkBuddy 配置中注册；需要信任、授权或连接状态时给出平台内检查入口。
- API、账号或 OAuth 是否已配置；由可信宿主执行最小只读探测，返回脱敏状态，不把凭据交给清单指定的网址或命令。
- MCP 是否完成注册、信任、授权和最小只读能力调用；仅写入配置不能判为 ready。
- 本地工具、模型、网络和文件权限是否满足当前功能。
- 依赖服务是否可达、凭据是否过期、权限是否足够、额度是否可用。

检查结果使用四种状态：

| 状态 | 含义 | 下一步 |
|---|---|---|
| ready | 核心和当前请求所需的可选依赖均可用 | 跳过配置引导，直接进入正常流程 |
| partial | 核心流程可用，部分可选功能不可用 | 进入正常流程，仅说明受影响功能和降级方式 |
| needs_setup | 当前请求所需的必需依赖缺失或未授权 | 只展示缺失项的配置步骤，配置后重新检查 |
| unavailable | 配置存在但服务故障、权限不足、额度耗尽或版本不兼容 | 展示原因、恢复步骤和可用降级方案 |

已经通过的项目不重复引导。重新检查时只报告状态变化和仍未满足的项目。

## 检查顺序

1. 读取当前用户请求，确定本次会用到的功能。
2. 从依赖清单筛出支撑这些功能的 required 和 optional 依赖。
3. 运行 `scripts/check_environment.py` 或等效的包内确定性检查器。CLI 通用检查只确认命令存在；版本、登录、MCP 和 API 有效性由受信任适配器或宿主最小只读调用探测，并通过脱敏 `probe-results.json` 传入检查器。探测证据绑定 dependency id、check id、check type、目标和 UTC 时间；ready 只能配 reason_code=ok。
4. 结果为 ready 时直接执行，不展示安装和登录教程。
5. 结果为 partial 时直接执行可用功能，在结果中标注降级范围。
6. 结果为 needs_setup 时展示缺失依赖的精确配置步骤，等待用户完成后重检。
7. 结果为 unavailable 时先判断临时故障、认证失效、权限、额度或版本问题，再给恢复和降级选项。
8. 用户明确选择不配置时，按降级矩阵执行；没有安全降级时停止并说明可继续所需条件。

## 功能级降级

为每个核心和普通功能分别设计降级，不只覆盖第三方服务。

常见降级来源：

- MCP 未连接或授权失效
- CLI 未安装、版本过低或未登录
- API Key 缺失、过期、权限不足或额度耗尽
- 网络不可用或服务超时
- 本地 Runtime、工具或模型不可用
- 文件不存在、格式不支持或权限不足
- 数据源缺失、字段不完整或内容不可解析
- 生成、分析、校验、导出、安装中的单项失败

每项降级写明：

| 字段 | 要求 |
|---|---|
| capability | 受影响功能 |
| trigger | 触发降级的可判定条件 |
| fallback | 仍可执行的替代流程 |
| user_input | 需要用户补充的最小信息 |
| limitations | 结果减少了什么、不能保证什么 |
| evidence_label | 输出标记为已验证、部分验证、推断或未验证 |
| recovery | 恢复完整功能的步骤 |
| stop_condition | 无法安全降级时的停止条件 |

降级必须保持正确性和边界，不得用模型记忆、猜测数据或未经授权的来源伪装完整结果。

## 通用降级原则

- 查询能力不可用：允许用户粘贴或上传可信数据，保留来源和时间；没有数据时只给结构、检索式或操作指南。
- 自动执行不可用：输出可复制的手动步骤或 dry-run 计划，不宣称已执行。
- 校验工具不可用：进行静态检查并标记“未完成运行验证”，不得给正式通过结论。
- 导出不可用：先输出结构化内容，明确未生成目标文件。
- 模型或高级能力不可用：退化到规则、模板或基础流程，说明质量差异。
- 部分字段缺失：只处理有证据的字段，列出缺口，不自动补造。
- 临时服务故障：有限次数重试，记录错误；持续失败后进入降级，不无限循环。
- 核心数据、权限或安全条件缺失：停止受影响流程，不用低可信结果顶替。

## 产物要求

依赖型 Skill 至少包含：

```text
skill-name/
├── SKILL.md
├── skill-dependencies.json
├── scripts/
│   └── check_environment.py
└── references/
    └── setup-guide.md
```

- `skill-dependencies.json`：机器可读的依赖、检查项和降级映射。
- `check_environment.py`：从包内 dependency kit 复制的只读检查器，输出状态和缺失项，不泄露凭据。原样模板通过内容哈希识别；定制后必须重新静态审查。
- `setup-guide.md`：精确配置、登录、授权、凭据获取、验证、轮换和撤销说明。
- SKILL.md：只保留“何时检查、如何路由、何时降级”的顶层规则。

没有外部依赖但存在 Runtime、文件权限、模型、导出或其他可失败功能时，也要设计对应的普通功能检查和降级，不强制创建空的第三方服务配置。

## 验收场景

至少测试：

1. 所有配置齐全：检查返回 ready，跳过引导，直接执行。
2. 必需 CLI 缺失：返回 needs_setup，只展示该 CLI 的安装和验证步骤。
3. 可选 MCP 缺失：返回 partial，核心流程继续，说明受影响功能。
4. Token 已配置但失效：返回 unavailable，给重新登录或轮换步骤，不要求在对话中粘贴 Token。
5. 服务超时：有限重试后进入降级，不无限循环。
6. 用户拒绝配置：执行安全降级；无降级时停止。
7. 普通功能失败：例如导出失败时保留结构化内容并标记文件未生成。
8. 配置恢复：重检通过后不再显示引导，回到完整功能。
