# 触发词挖掘与触发测试

需求确认和实测阶段使用本文件。

## 触发词挖掘

1. 收集 3—5 句用户真实会说的原话，保留口语、不规范说法和省略表达。
2. 提炼用户会说的触发短语，不使用只有制作者知道的专业词替代。
3. 补充用户未点名领域词但实际应该触发的说法。
4. 收集 2—3 句关键词相近但不应触发的 near-miss。
5. 将做什么、何时用、关键能力和真实触发短语写入 description。

完成标准：不直接点名 Skill 或领域术语时，目标场景仍能触发；相近但不同的任务不会误触发。

## 测试集

- 正例：2—3 条，使用收集到的用户原话。
- near-miss：1—2 条，覆盖最容易混淆的邻近任务。
- 每条用例使用独立对话，不共享前一条上下文。
- 需要自然澄清时继续发送真实用户回复，不加入评测说明。

## 单条记录

每条测试记录：

- 用例 ID
- 类型：正例或 near-miss
- 用户原话
- 预期是否触发
- 实际是否触发
- 实际回复或产物摘要
- 可复核证据
- 判定：通过、失败或未执行
- 修复动作
- 回归结果

## 判定

- 正例全部触发且 near-miss 全部未触发：通过。
- 正例漏触发：补充 description 中的真实说法，重新运行全部用例。
- near-miss 误触发：收窄使用场景和边界，重新运行全部用例。
- 无法观察 Skill 是否加载时：记录为未验证，不得声明触发通过。
- 目标回复由静态推断而非真实对话产生时：记录为未执行。

## 基线对比

1. 选择一个典型任务。
2. 不带 Skill 执行一次并记录输出。
3. 带 Skill 执行一次并记录输出。
4. 对比结构、完整性、追问数量、模板、Gotchas、边界处理和错误恢复。

带 Skill 的输出必须存在可观察增量。若两者相近，收窄定位或补充具体信息增量，不以文案包装替代真实价值。

## 回归规则

- 修改 description 后重跑全部正例和 near-miss。
- 修改流程、模板或安全规则后重跑受影响场景和一个典型主流程。
- 修改脚本后重跑正常输入、用户直觉边界输入、错误输入和失败恢复。
- 所有失败用例保留在测试记录中，修复后追加回归结果，不删除原始证据。
