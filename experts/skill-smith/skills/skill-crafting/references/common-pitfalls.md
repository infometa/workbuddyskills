# 常见坑与选题建议

场景挖掘、选题建议和修改 Skill 时使用本文件。

## 新手八大坑

1. **触发描述写成功能介绍**：触发依赖 name 和 description。写清做什么、何时用、关键能力和用户真实说法。
2. **SKILL.md 写成长篇 prompt**：正文不超过 500 行，细节拆到 references。
3. **抄模型本来就会的内容**：重点沉淀具体 Gotchas、团队约定和容易误判的边界。
4. **多 Skill 职责重叠**：一个 Skill 聚焦一个切口，避免触发词撞车。
5. **示例使用伪代码或占位符**：示例必须是可直接参考的完整真实内容。
6. **把复杂工具调用留给模型临场拼接**：确定性操作下沉 scripts，并给参数、输出和失败状态。
7. **没有输出模板和验收标准**：固定输出结构，给完整示例和可判断的通过条件。
8. **工程细节不一致**：目录名与 name 一致，SKILL.md 大小写精确，加载式引用只放顶层。

## 必须实测的项目

- 真实用户说法能否触发
- near-miss 请求是否保持安静
- 长上下文下规则是否仍被遵守
- 不同模型和权限环境下行为是否一致
- 脚本边界输入、错误输入和失败回滚
- 带 Skill 与不带 Skill 是否存在可观察增量

正式交付前完成真实场景、触发边界和适用脚本的实测。无法安全执行的项目记录为未执行，不得声明通过。

## 修改已有 Skill 时清理

删除以下内容：

- “已调整”“已验证”“2.3 版本”等状态标注
- “用户之前要求”“这里改为”等解释性修改注释
- 历史调整记录和 changelog 块
- 已失效规则和重复规则

Skill 文件只保留当前有效规则，变更记录交给外部版本管理。

## 大赛选题

推荐：

- 有确定性对错的题材：格式校验、规范检查、数据转换
- 小而深的切口：触发准确、边界清晰、示例完整
- 自带实测证据：before/after 对比、边界输入和失败处理
- 有具体信息增量：团队约定、行业坑点、稳定模板

避开：

- 泛人格扮演
- 泛写作助手
- 多个不相干能力的合集
- 依赖无法配置的外部系统才能演示的题材
- 需要越权访问、抓取私密数据或绕过平台规则的题材

## 安全底线

公开 Skill 常见风险包括恶意脚本、凭据窃取、提示词注入、营销导流和静默文件操作。设计阶段写明权限、数据范围、授权机制、停止条件和降级行为；高风险操作不得默认执行。
