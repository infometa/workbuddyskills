# 选题与研究问题

## 输入

- 学科与论文类型
- 用户感兴趣的主题、对象或现象
- 可获得的文献、数据、案例、实验条件或访问对象
- 截止时间、篇幅、方法能力和导师限制

## 选题收敛

按以下顺序缩小范围：

1. 对象：谁、什么组织、什么文本、什么系统或什么现象。
2. 情境：在哪个地区、平台、时间段、制度或应用环境。
3. 问题：要描述、比较、解释、评估、设计还是验证什么。
4. 视角：采用什么概念、理论、机制或方法观察。
5. 证据：需要且能够获得哪些文献、数据、案例或实验结果。
6. 边界：明确不研究什么，不将题目扩展到无法完成的范围。

## 研究问题检查

每个候选研究问题检查：

- 能否在论文篇幅和时间内回答
- 核心概念能否定义或操作化
- 需要的证据是否现实可得
- 问题与方法是否匹配
- 结论是否可能超出数据能力
- 是否存在研究伦理、隐私或授权风险
- 与已有研究相比新增的是对象、情境、证据、方法还是解释

## 可行性等级

使用“可直接推进、补充条件后可推进、建议缩小范围、当前不建议”四档，不输出伪精确评分。

## 输出模板

### 候选题

- 暂定题目
- 核心研究问题
- 研究对象与边界
- 预期证据
- 可行性结论
- 主要风险
- 需要确认的一件事

### 定稿包

- 中文题目与英文题目草案
- 主研究问题与子问题
- 核心概念定义清单
- 研究范围与排除范围
- 预期贡献
- 下一步文献与材料清单

## 停止条件

- 只有宏大主题，没有可获得材料或可回答问题
- 题目要求证明预设结论
- 关键数据或参与者无法合法获得
- 涉及高风险人体研究但尚未确认伦理要求

## 创新点提炼

创新点是相对于已核验研究的可说明增量，不等于题目“新”、对象“少见”或使用了某个工具。禁止只写“填补空白”“首次研究”“具有创新性”等无对照依据的表述。尚无足够证据时，写成“候选增量，待文献核验”，不得升级为确定性创新。

### 五维模板

| 维度 | 表述模板 | 必须定位的证据 |
|---|---|---|
| 对象 | “相较于 `L___`—`L___` 主要研究的【既有对象】，本研究聚焦【对象及边界】，预期检验/描述【对象差异带来的问题】。” | 既有研究对象、样本与纳排范围；本研究对象可得性 |
| 情境 | “在 `L___`—`L___` 所覆盖的【既有地区/平台/时段/制度】之外，本研究考察【新情境】，重点比较【情境机制或边界】。” | 既有情境边界、情境差异依据；不能仅因地点不同就宣称创新 |
| 证据 | “针对 `L___`—`L___` 主要依赖的【既有证据】，本研究使用可合法取得的【新数据/案例/材料】，用于回答【新增可检验问题】。” | 既有证据类型与限制、本研究数据来源和可追溯计划 |
| 方法 | “相较于 `L___`—`L___` 的【既有方法】，本研究在【相同问题/材料】上采用【方法调整或组合】，以改进【可观察的分析能力】，同时承认【方法限制】。” | 既有方法、适用条件与限制；新方法选择理由，不以“用了软件”代替方法创新 |
| 解释 | “现有研究 `L___`—`L___` 对【同一现象】主要提供【解释 A】，本研究将检验/比较【解释 B 或边界条件】，并以【证据】区分两种解释。” | 既有解释、争议或边界；能够区分解释的证据与分析设计 |

### 创新点证据卡

每条创新点必须建立一张可追溯卡：

| 字段 | 要求 |
|---|---|
| 创新点 ID | `I001`、`I002`……，编号稳定不复用 |
| 所属维度 | 对象/情境/证据/方法/解释，可多选但须指出主维度 |
| 对照陈述 | 已有研究做了什么，本研究增加什么，增量为何影响研究问题 |
| 证据矩阵定位 | 至少列出支持对照的 `L` 编号及对应字段/原文位置；M1 不能支持内容型对照 |
| 本研究实现条件 | 数据、材料、方法、权限、时间和伦理条件 |
| 可验证产出 | 该增量将在何种分析、图表、章节或结果中体现 |
| 边界与风险 | 不能由现有证据支持的部分、可能退化为一般差异的条件 |
| 状态 | 已核验/候选增量/待补证据/不可成立 |

### 判断流程

1. 从证据矩阵归纳已有研究在五个维度上的共同做法、分歧和边界。
2. 将本研究计划逐维对照，删除只换名词、只换软件、只换地点但不改变问题或解释的伪增量。
3. 为每条候选创新绑定 `L` 编号和实现条件；无法定位证据矩阵的条目退回“待补证据”。
4. 使用克制措辞：“增量在于”“扩展到”“比较”“检验”“提供某类证据”，不使用无法证明的“首次”“完全填补”。
5. 将成立的创新点回写到研究问题、方法、证据计划和结论边界，确保论文后续能够兑现；开题阶段不得承诺尚未得到的研究结论。
