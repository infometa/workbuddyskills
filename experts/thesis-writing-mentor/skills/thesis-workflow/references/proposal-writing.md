# 开题报告写作

## 定位与输入

开题报告说明“为什么研究、研究什么、依据什么、怎样研究、能否完成”，不是预写研究结果。开始前收集：学校开题表/格式细则、选题定稿包、研究问题、证据矩阵、可用数据与材料、方法条件、伦理/权限、当前进度、学校硬节点和剩余时间。

学校模板、学院细则和导师明确要求优先。材料不足时输出骨架、待填字段和风险，不编造文献、数据、条件或审批，不承诺研究结论。

## 标准结构与写法

### 1. 背景与意义

背景按“现实或学术情境 → 可核实现象 → 具体问题 → 研究边界”推进，避免从宏大口号直接跳到选题。每个事实性背景绑定来源或标“待补证据”。

意义分层写：

- **理论意义**：可能扩展、比较或检验的概念、关系、机制或边界；用“拟考察”“可能提供证据”，不写“已经证明”。
- **实践意义**：面向何种主体、支持何种理解或决策、适用于什么范围；不保证必然改善或产生效果。

### 2. 国内外研究现状

调用 `literature-and-evidence.md` 的证据等级、证据矩阵和综述组织规则，不重复造一套文献规则。按主题、机制、理论、方法、对象或争议综合，说明共识、分歧、证据边界及与本研究的连接，不按作者逐篇罗列。

只有 M2 或 F 可以支持具体内容综合；M1 只用于身份和格式。每个对照与创新点定位 `L` 编号，检索过程记录 `Q` 审计 ID。证据不足时输出综述提纲和待补检索，不补写“研究空白”。

### 3. 研究内容与目标

先列内容表，再写目标：

| 内容 ID | 研究问题 | 对象/材料 | 分析任务 | 可检查产出 | 对应目标 | 边界 |
|---|---|---|---|---|---|---|

目标使用“描述、比较、解释、评估、设计、验证”等任务动词，并与研究问题、证据和方法一一对应。预期成果写拟形成的论文、数据字典、分析、图表、模型或设计文档，不写尚未得到的方向性结论。

### 4. 研究方法

至少说明：研究设计与选择理由、对象/样本/语料、纳入排除标准、数据或材料来源、收集过程、变量/编码/访谈框架、分析步骤、工具与版本、质量控制、伦理隐私、方法限制和替代方案。

方法必须能回答研究问题且符合现实条件。样本量只给基于设计、功效/精度、信息丰富度、饱和、资源和伦理的原则，不编造固定数字。

### 5. 技术路线

先输出可直接交给绘图软件或用户绘制的文字结构，不承诺自动生成图片。

#### 主线

```text
研究背景与证据 → 问题界定 → 文献与理论框架 → 研究问题/假设 → 研究设计 → 材料或数据获取 → 分析 → 结果呈现 → 讨论与边界 → 结论与交付
```

主线每个节点写“输入—动作—输出”，并绑定内容 ID 或产物 ID。

#### 分支

```text
节点A：材料是否可得？
├─ 是 → 进入数据质量检查
└─ 否 → 缩小研究范围/更换合法数据源/降级主张

节点B：方法前提是否满足？
├─ 是 → 执行预定分析
└─ 否 → 采用已说明的替代方法，并记录影响
```

分支只设置真实可能发生的决策，不用流程图掩盖未解决的方法问题。

#### 反馈环

```text
预调研/试分析 → 发现题项、编码或数据问题 → 回到研究设计修订 → 记录版本与影响 → 再次检查
导师反馈 → 回到研究问题/方法/结构对应节点 → 用户确认重大取舍 → 更新开题材料
```

正式研究开始后的变更不得静默覆盖原方案；记录发生时间、理由和受影响主张。

### 6. 可行性分析

从文献、数据/材料、方法能力、工具设备、权限授权、时间节点、伦理隐私和导师支持逐项写“已有条件—缺口—风险—应对/降级”。只把有材料证明的条件写成“已具备”；用户口述但未提供产物时标待核验。

### 7. 进度安排

进度表至少包含：阶段、任务、可检查产出、建议起止、学校硬节点、依赖/反馈环、风险缓冲和状态。

建议节奏按以下因素调整：

- **论文类型**：实验/准实验预留审批、招募、试验、失败重做；问卷/访谈预留伦理、预调研、招募、转写和编码；二手数据预留授权、清洗和口径核对；文本/案例研究预留材料获取、编码迭代；工程/设计类预留需求、原型、实现、测试；综述类预留检索、筛选、全文获取和证据综合。
- **剩余时间**：先锁定学校不可移动节点，从截止日反推；时间紧时缩小研究范围、减少非必要分支和降低主张，不压缩伦理、数据核验、导师确认和提交检查。
- **当前阶段**：只安排尚未完成且可核验的任务；声称完成但无产物时标 `REPORTED_DONE_UNVERIFIED`。
- **反馈轮次**：为导师反馈和返修保留回路，不承诺导师回复时间。

所有建议以学校公布的开题、中检、初稿、查重、答辩和归档节点为准；学校节点未知时先请用户补充，不给伪精确日期。

### 8. 参考文献

仅纳入身份字段可核验的条目，并按学校指定标准格式化。内容主张遵守 M1/M2/F 边界；字段缺失列待补，不凭记忆补齐。学校参考文献体例高于通用示例。

## 工作流

1. 读取学校开题表并建立字段对接表。
2. 用选题定稿包确认题目、主问题、边界和候选创新点。
3. 从证据矩阵生成研究现状骨架，标出 `L` 编号与待补证据。
4. 建立“研究问题—内容—目标—方法—产出”对应表，修复错位。
5. 输出技术路线的主线、分支和反馈环文字结构。
6. 逐项完成可行性和风险降级，不把计划写成事实。
7. 按学校节点、论文类型、剩余时间和当前状态生成进度表。
8. 调用 `output-templates.md` 的“开题报告逐节模板”和“学校开题表字段对接”交付。

## 交付检查

- 每节都能定位到用户材料、证据矩阵或明确待补字段。
- 创新点按 `topic-and-research-question.md` 定位到证据矩阵，未核验时称候选增量。
- 目标、方法、技术路线和进度能对应同一研究问题。
- 不出现“必然得到”“证明了”“显著提升”等结果承诺。
- 不代填导师意见、审核结论、签名、日期或伦理审批。
