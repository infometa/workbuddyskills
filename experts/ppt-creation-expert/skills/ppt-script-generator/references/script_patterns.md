# 分页型讲稿模板与范例

本文档为各类 PPT 页面提供讲稿写法模板和示例。所有示例中的数据均为占位演示，实际写稿时**必须替换为研究报告中的真实数据**。

---

## 通用口播节奏公式

> **立靶 → 展开 → 解读 → 钩子**

- **立靶**（1句）：开口先说本页最核心的一句话，让听众知道这页要听什么。
- **展开**（2-4句）：把页面要点逐条讲清楚。
- **解读**（1-2句）：讲数据/要点的"含义"，不是朗读。
- **钩子**（1句）：引向下一页。

---

## 一、封面页 → 开场白

**目标**：30-60 秒抓住注意力，建立期待。

**结构**：钩子 → 自我介绍 → 今天讲什么 → 为什么值得听。

**模板**：
```
[钩子：抛一个数据/问题/场景]
"大家有没有想过，{一个反差/痛点/趋势数据}？"

[自我介绍]
"我是{身份}，今天非常高兴和各位聊聊{主题}。"

[今天讲什么 + 为什么值得听]
"接下来大约{X}分钟，我会带大家看清三件事：{行业往哪走}、
{问题怎么解}、{已经有谁验证过它有效}。听完之后，相信您会
对{主题}有一个可以直接落地的判断。"
```

**范例（具身智能AI训练方案，售前场景）**：
> "先抛个数字——根据 IDC 2025 的报告，具身智能这个赛道未来三年的复合增长率超过 30%。[停顿] 但真正卡住大家的，从来不是算法，而是算力。我是腾讯云的解决方案架构师，今天大约 30 分钟，我会带各位看清三件事：这个行业正在发生什么、训练算力的瓶颈到底怎么破、以及已经有哪些头部机器人厂商用我们的方案跑出了结果。"

---

## 二、目录页 → 主线串场

**目标**：用一句话把各板块串成有逻辑的故事线，而不是念目录。

**模板**：
```
"今天的内容分四块，逻辑其实很简单：我先讲{板块一}，让大家看清
大势；再讲{板块二}，把问题摆到台面上；然后是重头戏{板块三}，
看我们怎么解；最后用{板块四}的真实案例，证明这套打法真的有效。"
```

> 切忌逐条朗读目录文字。要讲"为什么是这个顺序"。

---

## 三、章节封面 → 小结 + 预告

**目标**：承上启下，给听众"换挡"信号。

**模板**：
```
[承上：一句话总结上一板块]
"刚才我们看清了{上一板块结论}。"

[预告：本板块要讲什么]
"那么问题来了——{本板块要回答的核心问题}？接下来这部分，
我会重点讲{本板块2-3个要点}。"
```

**范例（进入"解决方案"板块）**：
> "刚才我们把客户最头疼的三个痛点都摆出来了：算力门槛高、资源碎片化、利用率上不去。[停顿] 那这些问题到底怎么解？接下来是今天的重头戏，我会从整体架构讲起，再带大家逐个看我们的核心能力，最后落到最硬的底层基础设施。"

---

## 四、内容页（概念/趋势/时间线）

**讲法**：把静态信息讲出"动态感"和"为什么重要"。

- **概念定义页**：先用大白话解释概念，再说它为什么现在重要。
- **时间线/发展阶段页**：像讲故事一样讲演进，强调"我们现在站在哪个阶段"。
- **对比表格页**：不要逐格念，挑 1-2 个最关键的对比维度展开讲差异。

**范例（发展阶段时间线）**：
> "这个领域其实走过了三个阶段。[强调] 早期大家还在拼单点算法，到了中间这几年开始拼工程化，而现在——我们正站在第三个拐点上：拼的是大规模训练的基础设施。[停顿] 谁能在这一关把算力成本和效率做到极致，谁就能甩开对手。这也正是今天方案要解决的核心。"

---

## 五、痛点页

**讲法**：让听众"对号入座"，把痛点讲到心坎里，再暗示有解。

**模板**：
```
[共情：把痛点说成听众自己的事]
"不知道在座的各位是不是也遇到过这种情况——{痛点场景描述}。"

[加深：用报告里的数据/事实佐证痛点的严重性]
"这不是个例。{报告中的数据/行业现象}。"

[埋钩：暗示有解，但先不展开]
"这些问题单独看都能忍，但叠加起来就是致命的。好在——它们都有对应的解，这正是后面要讲的。"
```

**范例**：
> "搭一套训练集群，光硬件采购周期就要几个月，钱投下去还可能买错规格。[停顿] 更麻烦的是，不同机器人型号要的算力规格还不一样，资源就这么碎掉了，平台利用率常年上不去。这三个问题，单拎出来都让人头疼，叠在一起就是研发效率的天花板。别急，[强调] 每一个，我们后面都有对应的解法。"

---

## 六、数据/图表页 ⭐（演讲高潮区）

**讲法**：**解读数据**而非朗读。讲清"这个数字意味着什么""和谁比""所以呢"。

**模板**：
```
[报数 + 出处]
"大家看这张图，{核心数字}——这是{出处}的数据。"

[对比 / 解读]
"什么概念？{横向对比 or 纵向对比}，相当于{打比方}。"

[结论]
"所以一句话：{这个数据支撑的结论}。"
```

**范例（性能对比图）**：
> "重点看这组对比。[强调] H20 和 H100 的算力差距，在我们的网络优化下，实际训练性能差距只有 20%——这是我们官方测试出来的数据。[停顿] 什么概念？用更容易拿到、更便宜的卡，跑出接近顶配的效果。再看这条线，64 卡的线性扩展率高达 97%，几乎没有损耗。所以结论很硬：在我们这儿，算力既省钱又不掉性能。"

> ⚠️ 数据页必须在「提示」区列出该数据的精确出处，便于演讲者应对追问。

---

## 七、方案/架构页

**讲法**：架构图从上往下或从下往上"走一遍"，但只讲主干，不堆术语。把每层和"解决了哪个痛点"挂钩。

**模板**：
```
"这是方案的整体架构。我从{上/下}往{下/上}带大家走一遍——
最{上/下}面是{X层}，负责{作用}；往{下/上}是{Y层}……
[挂钩痛点] 大家注意，{某一层}正好对应刚才说的{某痛点}。"
```

**范例（痛点-方案映射页）**：
> "这一页是今天的逻辑闭环。左边是刚才的三个痛点，右边是我们对应的解法，一一对上。[停顿] 算力门槛高，我们用 HCC 弹性算力，按需用、不用买；资源碎片化，我们做多规格 GPU 统一管理；利用率低，交给云原生智能调度。[强调] 每一个痛点，都有一把对应的钥匙。"

---

## 八、客户案例页 ⭐（信任高潮区）

**讲法**：讲成一个"小故事"——谁、遇到什么问题、用了什么、结果多好。量化成效是高潮，要重读。

**模板**：背景 → 痛点 → 方案 → 成效（前后对比）→ 结论。
```
"举个真实的例子。{客户名}，{一句话背景}。他们当时的难题是{痛点}。
用了我们的{方案}之后——[强调] {量化成效，带前后对比}。
{一句话结论}。"
```

**范例**：
> "说个真实案例。某头部人形机器人厂商，专注高性能机器人研发。他们最头疼的是不同型号机器人模型训练，要反复折腾算力集群。[停顿] 上了我们 8 卡 H20 带 RDMA 的计算集群之后——训练的线性扩展率做到了 97%，性能和 H100 的差距压到 20% 以内。[强调] 用更优的成本，拿到了几乎顶配的训练效率。这就是方案的价值，不是 PPT 上的承诺，是跑出来的结果。"

> ⚠️ 案例数据必须来自研究报告；报告无量化数据时讲定性价值，并在备注标注"[数据待客户确认]"。

---

## 九、结尾页 → 收尾 + CTA

**目标**：再次强调核心价值，回扣开场，给出明确的下一步。

**结构**：核心价值回顾 → 回扣开场钩子 → 行动号召 → 致谢。

**模板**：
```
[价值回顾]
"今天我们聊了{主题}：从{板块一}到{板块四}，核心就一句话——
{方案最核心的价值主张}。"

[回扣开场]
"回到开头那个{数据/问题}——{呼应}。"

[CTA]
"如果各位感兴趣，我们下一步可以{POC/试用/技术深聊}，
让方案在您的真实场景里跑一跑。"

[致谢]
"谢谢大家，期待和各位进一步交流。"
```

**范例**：
> "今天从行业大势，讲到痛点、方案，再到真实案例，其实核心就一句话：[强调] 在具身智能的训练这件事上，我们能让您算力既省钱、又不掉性能。[停顿] 回到开头那个 30% 增长的赛道——窗口期就在眼前。下一步，我建议我们做一个小规模 POC，用您自己的模型在我们集群上实测一把，数据不会骗人。谢谢大家！"

## 提示标签规范

讲稿「提示」区统一使用以下标签：

| 标签 | 含义 |
|------|------|
| `[强调]` | 该词/句重读、提气 |
| `[停顿]` | 此处停顿 1-2 秒，留白 |
| `[互动]` | 可向听众抛出的问题 |
| `[数据]` | 本页引用数据及精确出处 |
| `[提速]` | 此页可加快带过 |
| `[手势]` | 建议配合的手势/指屏动作（可选） |
