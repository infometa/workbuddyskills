# 标志性页面模板（高拜材料）

本文档定义高拜材料的三个标志性页面，是区分高拜材料与普通方案的核心页面。方法论提炼自 Call High 售前实战套路。

- **客户理解三栏**（板块二末，核心衔接页）
- **合作回顾三变体**（板块三首页）
- **合作蓝图金字塔**（板块三，核心视觉）

---

## 一、客户理解三栏（板块二 · 核心衔接页）⭐

### 用途

用宏观行业趋势铺垫后，自然推导出"我们看见你业务表象背后的真问题"。这是板块二到板块三的关键铰链——没有这一页，板块三的重点项目就成了空降的处方。

> ⚠️ **症结必须从客户/行业的真实痛点分析得出，不预设方向**。不同客户、不同行业的根因千差万别——可能是增长乏力、成本高企、效率低下、体验落后、安全合规压力、数据价值未释放、组织能力不足、市场竞争加剧等**任意维度**。**禁止不管什么客户都套"数字化/智能化不足"这种统一框子**——那是套模板，不是理解客户。

### 结构（3 栏对照）

```text
表象（客户/行业能看到的痛点）  →  症结（痛点背后的根本原因）  →  入口（腾讯云能切入帮解的合作方向 = 板块三重点方向）

例 1（运营商）：
- 传统语音/流量收入见顶，增长乏力    →  第二增长曲线未建立、产业侧变现能力弱  →  对应"产业数字化连接"项目
- 海量卡号/用户数据沉睡              →  数据资产价值未释放、缺合规运营体系    →  对应"全域数据要素运营"项目
- 网络运维依赖人工、故障响应慢       →  运维效率低、缺实时可视手段            →  对应"云网数字孪生"项目

例 2（连锁零售）：
- 同店销售下滑、获客成本攀升         →  流量红利见顶、私域复购运营薄弱        →  对应"全域用户运营"项目
- 门店扩张快但服务质量参差           →  一线人员能力难标准化复制              →  对应"门店智能助手"项目
```

> 症结的落点因客户而异：例 1 的第 3 行落在"效率/可视"，例 2 落在"流量/复购/人员能力"——都是从各自行业真实痛点出发，而非硬套同一套说辞。

底部一句承上启下：

> **"基于以上理解，我们认为可以一起做的事是…"** —— 自然过渡到合作蓝图金字塔。

### 三栏字段要求

| 列 | 必须包含 | 必须避免 |
|---|---|---|
| **表象** | 客户/行业可观察的痛点现象（来自公开财报/新闻/官网/调研） | 凭空臆测、未验证的判断 |
| **症结** | 该痛点背后的**根本原因**——从客户实际情况分析（成本/效率/增长/体验/安全/数据/组织/竞争等，视客户而定，不预设方向） | ①正确的废话（"需要转型"）②硬套"数字化/智能化不足" |
| **入口** | 腾讯云能切入、帮客户解决该症结的合作方向，须**精确对应**板块三重点方向（模式A 的重点项目 / 模式B 的建议优先方向） | 写成"→ 数字化转型"这种笼统入口 |

> 严格对应：每一行（表象→症结→入口）必须能**单独成立**，三栏的"入口"列加起来 = 板块三的重点方向列（模式A=重点项目列，模式B=建议优先方向）。逻辑链是"**客户痛点 → 根因分析 → 腾讯云能帮的合作方向**"，不是"腾讯云想卖什么 → 倒推客户需要数字化"。

### 反模式

- ❌ 不分析真实痛点，直接写"客户需要数字化转型"这种空话
- ❌ 把所有客户的症结都硬写成"数字化/智能化不足"（不看行业实际痛点，套模板）
- ❌ 表象写得对，但症结写得空（"需要 AI 赋能"）
- ❌ 入口与板块三重点方向不一致（衔接断开）
- ❌ 症结停留在表象复述（把"收入下滑"又抄一遍），没往下挖根因

### 推荐布局

- 布局：3 栏对照页；密度 L2
- 配色：表象（中性灰）→ 症结（辅橙 #EB8707）→ 入口（品牌蓝 #0060F0）

## 二、合作回顾三变体（板块三 · 首页）

根据"合作深度"选其一（Phase 1 表单已获取）：

| 变体 | 触发条件 | 形式 |
|---|---|---|
| **变体 A：合作回顾时间线** | 已合作 ≥ 3 年且有多个项目 | 横向时间轴 + 5-10 个里程碑 + 上下交错 |
| **变体 B：议题进展卡片** | 合作起步 / 已合作 1 年内 | 3-5 张议题卡片（议题/时间/进展/状态） |
| **变体 C：接触历程 / 行业共鸣** | 首次拜访（无直接合作） | 行业接触点 + 已服务同行业 2-3 个标杆 |

> 红线：不要把"潜在合作"写成"已合作"（高层一眼识破）；三个变体视觉上都可保持横向感，但内容必须诚实。

### 变体 A：合作回顾时间线

```text
标题：合作回顾：{客户} 在 XX、YY 等板块紧密合作

时间轴：横向贯穿，从最早合作年份到当前
节点布局：上下交错
节点字段：年份（蓝色加粗）+ 2-3 行事件描述；重点事件用品牌蓝加粗

选事件标准（按重要性）：
1. 战略级：高层互访 / 战略签约 / 集团级业务上云
2. 业务里程碑：新业务模块接入 / 行业首发
3. 规模性合作：明确数字背书

红线：每年最多列 3 条事件
```

### 变体 B：议题进展卡片

```text
标题：腾讯云与{客户}的合作探索 / 已沟通议题进展

3-5 张议题卡片，横向并列，每卡片：
- 议题名（用客户业务语言，不写产品名）
- 起始时间（真实，能查到对接记录）
- 沟通进展（一句话，不夸大，可写"已 N 次对接"）
- 状态点（严格三色：绿=已落地 / 橙=已交流 / 蓝=新提议）
```

### 变体 C：接触历程 / 行业共鸣

```text
标题：腾讯云与{行业}的同行 / 行业共鸣

左半页：腾讯对{行业}的接触点
- 与该行业的第一次接触：年份 + 事件
- 行业洞察 / 论坛 / 报告 / 与行业协会连接

右半页：已服务的同行业 2-3 个标杆
- 标杆 1-3：客户名 + 合作场景 + 关键价值

底部承上启下："正因如此，我们也希望与{客户}展开合作探索。"

红线：不要堆 5+ 个标杆 Logo；不要写"我们一直关注 X 行业"这种空话
```

## 三、合作蓝图金字塔（板块三 · 核心视觉）⭐

### 用途

把"未来双方将共建什么"用 5 层金字塔结构呈现，让客户高层一页看清"未来共建战略全图"。

### 结构

```text
标题：[年份]年双方合作蓝图规划

第 1 层（顶部三角）1 个目标：
  "助力 {客户} 建设 [战略愿景]"
  视觉：品牌蓝大三角，白字 30-36pt

第 2 层 3-4 个方向：
  并列方块（蓝底白字），每方块 6-10 字
  ⚠️ 方向 = 客户业务场景词，不是产品名
  例（运营商）：产业数字化连接 / 全域数据要素运营 / 云网数字孪生 / 无界安全防护

第 3 层 N 个场景：
  每个方向下 2-3 个具体场景（白底浅蓝边框），每场景 6-12 字
  最后一行用 "……" 表示开放性

第 4 层 技术基础（底座）：
  贯穿全宽的蓝色长条
  "腾讯云基础设施（云计算 + 大数据 + 人工智能 + 安全 + 异构算力……）"
```

### 字段填充指引

```yaml
合作蓝图金字塔:
  title: "[年份]年双方合作蓝图规划"
  goal: "助力 {客户} 建设 [战略愿景]"
  directions:   # 3-4 个（金字塔视觉对称要求）
    - name: "[方向1，6-10字业务场景词]"
      scenarios: ["[场景1.1]", "[场景1.2]", "……"]
    - name: "[方向2]"
      scenarios: [...]
    - name: "[方向3]"
      scenarios: [...]
  foundation: "腾讯云基础设施（云计算+大数据+人工智能……）"
  rendering:
    layout: "5 层金字塔（顶部三角 + 中间分栏 + 底部贯穿条）"
    color: "品牌蓝 #0060F0（顶部+第2层+底部）；第3层浅蓝边框 #5C90F6"
```

### 议题颗粒度铁律（不可妥协）

**方向 = 客户的业务场景，不是腾讯的产品名。**

判别公式：方向名去掉所有腾讯产品词后还成立吗？
- ✅「全域数据要素运营」去掉产品词仍成立 → 业务场景
- ❌「TBDS 数据套件」去掉产品词就剩"套件" → 产品名

产品名只能出现在第 3 层"场景"和底层"技术基础"，不允许出现在第 2 层"方向"。

### 各行业方向候选词

| 行业 | 候选方向词 |
|---|---|
| 运营商 | 产业数字化连接 / 全域数据要素运营 / 云网数字孪生 / 无界安全防护 / 智算算力协建 / ICT 生态共建 |
| 制造（家电/装备/汽车）| 智能生产 / AI 产品创新 / 全球化效率 / 用户体验 / 工业智能 |
| 政府国资 | 数字治理 / 公共服务 / 产业升级 / 社会民生 / 安全合规 |
| 能源化工 | 智能生产 / 安全合规 / 绿色低碳 / 全球化运营 |
| 金融 | 数字渠道 / 风控合规 / AI 营销 / 数字资产 |
| 零售 | 全域营销 / 私域沉淀 / 供应链 / 出海 / AI 客服 |

### 反模式

- ❌ 方向数量不是 3-4 个（破坏金字塔视觉对称）
- ❌ 各方向场景数量差异过大（方向1列 5 个，方向4只列 1 个）
- ❌ 把产品名放进方向或场景里（应是客户视角业务词）
- ❌ 顶部目标超过 25 字（一行装不下）
- ❌ 没有"技术基础"贯穿条（金字塔少了底座就不成立）
