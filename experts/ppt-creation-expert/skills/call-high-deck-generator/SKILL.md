# 高拜（Call High）材料生成器

## 概述

本 skill 专门用于生成**面向客户高层（一把手/二把手）的高拜拜访演示文稿**。

**文档定位**：面向客户董事长 / CEO / CXO 等最高决策层的战略级拜访材料。这类领导对具体业务理解不深，更希望从**行业发展趋势**和**腾讯云整体发展**的宏观视角看待"怎么合作"；同时高拜的目的不只是联络感情，更是通过高层策应**推动合作落地**——因此材料必须收口到高层可决策的落点：用户已明确重点项目时收口到**需老板拍板的重点项目**，未明确时收口到**行业全场景方案 + 建议优先方向供高层圈定**。

**核心目标**：生成一份**能直接拿去做高层拜访的专业 PPT**，宏观、有格局、有战略高度，最终收口到可供高层决策的合作落点（20-30 页）。

**工作模式**：用户给出**客户 + 行业**（如"某省联通 + 运营商"、"某车企 + 汽车制造"），并可补充**本次要探讨的重点项目**，Agent 自动完成：
1. 🔍 **深度研究**：优先通过乐享 MCP 知识库语义检索获取内容，不足时用 `WebSearch` + `WebFetch` 补充，整理为结构化研究素材
2. 🧠 **框架化内容组织**：按高拜标准三段框架（腾讯云介绍 → 行业趋势与理解 → 重点合作项目与探讨）组织内容
3. 📋 **幻灯片规划**：逐页规划 PPT 结构、内容和布局
4. 🎨 **PPT 生成**：调用 `generate_ppt` 工具，将规划和调研报告转化为演示文稿

用户也可以额外提供补充材料（PDF/文档/文字），Agent 会将其与调研结果融合。

> ⚠️ **与解决方案 skill 的区别（看用途，不看受众岗位）**：解决方案 skill（`solution-ppt-generator-v3`）**同时支持 CEO 和 CTO**，会按目标客户岗位自动调节技术深度，所以两者分界**不是"面向 CEO 还是 CTO"**。真正的区别在文档用途：解决方案 skill 围绕**一个具体行业+场景的方案**做汇报（行业背景→痛点→方案→案例），即使面向 CEO 也是"讲清一个方案的价值"；本 skill 面向**高层拜访/战略合作探讨**场景，不聚焦单一方案，而是"腾讯云整体介绍 + 行业趋势格局 + 多个重点合作项目探讨"，目的是建立战略共识并推动高层拍板落地重点项目。

## 核心工作流程

```
需求确认 → 深度调研 → 信息提炼与框架填充 → 幻灯片规划 → 调用PPT生成 → 汇总输出
```

## Phase 1 — 需求确认

### 1.1 意图澄清方式

> ⚠️ **必须使用 `show_form` 工具**进行需求确认，以**选择题**形式让用户快速选择，**禁止使用开放式填空题**（"本次要探讨的重点项目"允许填空框）。
>
> Agent 应根据用户输入的关键词，先自行推断可能的选项，再通过 `show_form` 呈现给用户选择确认。

### 1.2 需求确认信息

| 信息项 | 说明 | 是否必须 |
|--------|------|---------|
| 客户 / 行业 | 如"某省联通 / 运营商"、"某车企 / 汽车制造" | ✅ 必须 |
| 拜访对象层级 | 董事长/CEO（一号位）/ CTO/CFO/COO（二号位）/ 多人会面 | 可选 |
| 合作深度 | 首次拜访（First Call）/ 已有合作 1 年内 / 已有合作 3 年以上 / 战略级长期合作 | ✅ 必须（决定合作回顾形态） |
| 客户体量 | 战略级头部 / 中型（腰部、区域龙头）/ 中小型 | ✅ 必须（决定是否强调"共同基因/对等"） |
| 本次要探讨的重点项目 | 需高层拍板的 1-3 个重点合作项目/方向（**按业务场景词命名，不写产品名**）；**不填则板块三走"行业全场景方案"（模式B）** | 可选 |
| 拜访目标 | 建立战略共识 / 拿到明确下步动作(POC/专班) / 推进既有合作 / AI 启蒙 | 可选 |
| 页数要求 | 18-22 / 22-26 / 26-30 页 | ✅ 必须 |
| 补充材料 | 用户额外提供的 PDF/文档 | 可选 |

### 1.3 show_form 构造规则

Agent 需要根据用户输入的客户/行业关键词，**智能推断候选选项**，然后通过 `show_form` 工具一次性呈现选择题表单。

**构造原则**：
1. **核心问题用选择题**，降低用户输入成本；**"本次要探讨的重点项目"提供填空框**支持用户选填
2. **每道题提供 3-6 个选项** — Agent 基于行业知识预生成合理选项
3. **必须包含"其他"选项** — 允许用户突破预设范围
4. **可多选的问题标注多选** — 如"核心目标"可能涉及多个

**示例 show_form 构造**（以用户输入"某省联通 运营商"为例）：

```
show_form({
  "title": "高拜材料需求确认",
  "fields": [
    {
      "type": "select",
      "label": "本次拜访对象层级",
      "options": ["董事长/CEO（一号位，最高决策）", "CTO/CFO/COO（二号位）", "副总裁/总监（业务负责人）", "多人会面", "其他"],
      "required": false,
      "default": "董事长/CEO（一号位，最高决策）"
    },
    {
      "type": "select",
      "label": "与客户的合作深度",
      "options": ["首次拜访（First Call）", "已有合作 1 年内", "已有合作 3 年以上", "战略级长期合作", "其他"],
      "required": true,
      "default": "已有合作 1 年内"
    },
    {
      "type": "select",
      "label": "客户在行业中的体量",
      "options": ["战略级头部/上市公司", "中型（行业腰部/区域龙头）", "中小型（非头部）", "其他"],
      "required": true,
      "default": "战略级头部/上市公司"
    },
    {
      "type": "multiselect",
      "label": "本次拜访的核心目标",
      "options": ["建立战略层共识", "拿到明确下步动作（POC/联合专班）", "推进既有合作深化", "完成 AI/数字化启蒙", "其他"],
      "required": true
    },
    {
      "type": "text",
      "label": "本次要探讨、需高层拍板的重点项目（按业务场景描述，不写产品名，1-3 个；不确定可留空）",
      "placeholder": "如：全域数据要素运营 / 云网数字孪生 / 反诈全域应用；每个项目用 4-8 字业务场景词。留空则按行业全场景方案展开，由高层现场圈定方向",
      "required": false
    },
    {
      "type": "select",
      "label": "PPT 页数",
      "options": ["18-22页（精炼）", "22-26页（标准）", "26-30页（详细）"],
      "required": true,
      "default": "22-26页（标准）"
    }
  ]
})
```

> **"重点项目"的使用规则（决定板块三走哪种模式）**：
> - **填了重点项目 → 板块三走模式 A**（聚焦展开这几个项目，收口到拍板决策点）；这些项目**必须**成为板块三主体，逐一展开；板块二客户理解页的"入口"须对应这些项目方向
> - **未填重点项目 → 板块三走模式 B**（行业全场景解决方案图谱 + 逐场景概览 + 合作探讨收口）；**不要只列 2-3 个 AI 推断项目**，而是先给高层看腾讯云在本行业能做的全貌，再在合作探讨页给出建议优先方向供高层圈定
> - 两种模式详见 Phase 3 板块三

### 1.4 快速通道

如果用户的初始输入已经非常明确（如"帮我做一份拜访某省联通董事长的高拜材料，重点谈云网数字孪生和数据要素运营"），Agent 可以**跳过 show_form**，直接提取关键信息并进入 Phase 2。但如果有任何不确定项，**必须用 show_form 选择题确认，不要用文字追问**。

如果用户提供了补充材料（如 PDF），先提取材料内容，然后在后续调研中说明已有材料的覆盖范围和需要补充的维度。

### 1.5 模板与语言自动路由规则

#### ⚠ 规则一：英文腾讯云模板自动路由

用户 query 命中英文腾讯云模板意图时，**必须**将 template_id 设为 `tencent_cloud_template_en`，并将 PPT 内容语言切换为用户指定的外语（默认英文）。判定条件（满足任一即可）：

- 用户明确要求用某种外语（英语、日语、韩语等）制作
- 用户 query 本身为某种外语
- 用户 query 包含关键词：`国际版`、`英文版`

> 命中此规则时，Phase 5 中 `use_template` 改为 `"tencent_cloud_template_en"`，Phase 2 的 WebSearch 搜索关键词也应使用对应外语构造。

> ⚠️ **全流程语言切换**：当用户 query 本身为外语时，即使未明确要求外语模板，整个交互流程（大模型输出 / show_form / 调研 query / PPT 生成 / 汇总报告）也必须切换为对应语言。

#### ⚠ 规则二：页数范围选项约束

页数范围选项**禁止**出现超出实际能力（40页）的具体大区间选项。高拜材料默认 20-30 页，不建议超过 30 页（高层注意力有限）。

#### ⚠ 规则三：国际化内容调研路由（命中规则一或涉及海外/出海时触发）

当满足以下任一条件时，Phase 2 调研阶段**必须通过自定义属性（UDF）过滤，将乐享检索范围直接限定为"国际版=是"的文档**：

1. 命中规则一（英文腾讯云模板）
2. 用户 query 涉及海外/出海场景，包含关键词：`海外`、`出海`、`国际化`、`global`、`overseas`、`international`、`海外市场`、`跨境`、`多地区`、`多语言`

**执行流程**：
1. Phase 2 调用 `mcp__lexiang__search_kb_embedding_search` 时，**必须在 `filters.udf_values` 注入"国际版=是"属性过滤**（见下方结构），使服务端只返回国际版文档
2. 基于国际版文档范围的内容进行深度研究
3. 将研究内容整理为结构化 context，传给 `generate_ppt`
4. 未命中本规则时，`filters` 不带该 `udf_values`，照常全量检索

**国际版属性过滤结构（注入 `filters.udf_values`）**：

```json
"udf_values": [
  {
    "field_type": "select",
    "k_values": {
      "field_id": "250b20760fb74e8bb32955fe83c919cc",
      "values": [ { "type": "select", "value": "lsihfg3ix6d" } ]
    }
  }
]
```

> `field_id` `250b20760fb74e8bb32955fe83c919cc` = "国际版"属性，选项值 `lsihfg3ix6d` = "是"。

### 1.6 用户岗位获取规则

用户岗位**优先从 show_form 中用户选择获取**。若未明确，则尝试从 `<user_context>` 中的 `work_position` 字段兜底（销售 / 架构师）。高拜材料无论销售或架构师，均使用本三段框架，不切换成技术深度框架。

## Phase 2 — 深度研究

这是本 skill 的**核心驱动环节**。Agent 优先使用乐享 MCP 知识库语义检索，不足时用 `WebSearch` + `WebFetch` 补充，进行系统性深度研究。**高拜材料的调研偏宏观、战略视角**，不追技术 benchmark 细节。

### 2.1 调研维度矩阵

针对用户给出的客户/行业，调研需覆盖以下**7 个维度**：

| 维度 | 调研目的 | 期望获取的信息 | 对应板块 |
|------|---------|---------------|---------|
| ① 腾讯/腾讯云概览 | 集团架构、CSIG 定位、全栈能力、关键数据 | 组织架构、自研上云成果、全栈能力矩阵、代表数据 | 板块一 |
| ② 腾讯云行业角色 | 腾讯云在该客户行业的定位与标杆 | 实践者/助力者/连接器定位、行业标杆案例 | 板块一 |
| ③ 行业发展趋势 | 行业宏观趋势、政策方向、技术演进 | 3-5 个宏观趋势、市场判断、政策背景 | 板块二 |
| ④ 行业场景全景 | 该行业重点业务场景/发展重点图谱 | 场景全景图、重点场景解决方案概览 | 板块二/三 |
| ⑤ 客户理解 | 客户业务表象、痛点根因、机会入口 | 表象→症结→入口三栏素材 | 板块二 |
| ⑥ 重点项目 / 全场景方案 | 模式A：用户指定项目的背景/方案/价值/决策点；模式B：行业全场景多方案总览 | 模式A 每项目要素；模式B 全场景图谱+逐场景要点 | 板块三 |
| ⑦ 标杆案例 | 客户可对标的公开合作案例 | 客户名称、合作内容、量化成效 | 板块一/三 |

### 2.2 深度研究执行策略

**Step 1：乐享 MCP 知识库语义检索（优先内容来源）**

优先使用乐享 MCP 的 `mcp__lexiang__search_kb_embedding_search` 工具在乐享知识库中进行语义向量检索：

- **前置门禁**：调用 `mcp__lexiang__whoami` 校验 MCP 绑定状态。未绑定/过期时，引导用户通过 `https://lexiangla.com/mcp?company_from=CSIG` 获取 `LEXIANG_TOKEN` 完成绑定，绑定成功后再继续

按以下 query 框架逐一构造检索 query，批量并行调用 `mcp__lexiang__search_kb_embedding_search`：

```
围绕"{客户}{行业}高层拜访"进行系统性深度调研，需要覆盖以下方面：

一、腾讯云宏观概览（面向高层）
1. 腾讯集团组织架构与 CSIG（云与智慧产业事业群）定位、腾讯云全栈技术能力矩阵、自研上云等关键战略成果与代表性数据
2. 腾讯云在{行业}的角色定位（数字化转型的实践者/助力者/连接器）、已服务的{行业}标杆客户

二、行业宏观趋势与理解
3. {行业}的宏观发展趋势（3-5 个方向）、政策导向、技术演进路线、行业发展共识
4. {行业}的重点业务场景全景（分领域/分场景，从行业实际业务出发）、各重点场景的解决方案概览
5. {客户}的业务现状与痛点（表象）、这些痛点背后的根本原因（症结，从客户/行业实际出发分析，不预设为"数字化/智能化"）、腾讯云能切入帮解的合作机会（入口）

三、重点合作项目 / 行业全场景（按板块三模式二选一）
6a.【模式A · 用户已指定项目】围绕"{重点项目1}""{重点项目2}""{重点项目3}"，各自的背景意义、腾讯云对应解决方案、客户价值/收益、以及需要高层决策的关键点
6b.【模式B · 用户未指定项目】{行业}腾讯云能提供的全场景解决方案总览（分场景，如运营商六大场景）、各场景的定位与子方案要点、并结合{客户}给出建议优先推进的 2-3 个场景方向及理由
7. {行业}领域腾讯云公开客户合作案例及量化成效

请重点关注最近 1-2 年的信息，站在战略/宏观视角组织，优先使用腾讯云官方资料和行业权威报告。
```

- **调用参数**：`{"filters": {"keyword": "<query>"}, "limit": 10, "threshold": 0.3}`
  - ⚠️ **不要传 `_mcp_fields` 正向选择**：该参数 schema 要求**字符串**类型（非数组），且只接受负向排除路径（如 `"-staffs,-entry.html_content"`）。默认返回即包含正文片段，无需指定字段。
  - 🌐 **国际化场景（命中 Phase 1.5 规则三）**：`filters` 追加 `udf_values`（"国际版=是"，field_id `250b20760fb74e8bb32955fe83c919cc` / 选项值 `lsihfg3ix6d`）；普通场景不加。`threshold` 直接写 `0.3`（传 0 会被服务端抬到 0.3）。
- 汇总所有维度的检索结果，评估内容覆盖度
- **🔗 溯源链接**：每个 chunk 都带 `target_id`，可用它拼出乐享页面 URL：`{domain}/pages/{target_id}`。`{domain}` 取 `whoami()` 的 `company.company_domain`；顶级域名 `lexiangla.com` 需追加 `?company_from={company_from}`。标题用 `lexiang_search`（type=doc）回查 `original_title` 校正。
- **📋 全量素材追踪表（强制，边检索边记录）**：每跑一轮检索，**立即**把命中的每条 chunk 登记：`target_id` | 标题 | 命中维度 | 采用/弃用。最终「参考文档」清单须如实列全（去重后），禁止只挑几条代表性来源。
- **🔢 正文内联引用（强制）**：调研报告正文中每处具体数据、论断、案例都必须在句末标注来源序号 `[n]`，与文末清单双向对应。

> 若乐享 MCP 检索已充分覆盖全部维度，可跳过 Step 2 和 Step 3，直接进入 Step 4。

> 三段框架提炼自「2024 高拜场景+腾讯云和运营商行业介绍模板」的实战结构，并融合 Call High 方法论（合作回顾 / 客户理解 / 合作蓝图）。详细的各段内容组织指南见 `references/content_framework.md`，标志性页面模板见 `references/signature_pages.md`。

### 三段框架总览

```
封面页  →  主题金句 + 副标 + 客户名 + 日期

【板块一 · 腾讯云介绍（宏观）】5-7 页
  让高层"重新认识今天的腾讯云"，建立信任与格局

【板块二 · 行业趋势与理解（宏观）】6-9 页
  用行业趋势与格局对话高层，顺势落到"腾讯对客户的理解"

【板块三 · 重点合作项目与探讨（需拍板，核心重心）】7-11 页
  收口到高层可决策的落点：模式A 展开重点项目+合作蓝图，模式B 铺行业全场景+合作探讨；均给出下步建议

收尾  →  心法金句页 + 致谢页
```

---

### 板块一：腾讯云介绍（宏观，目标 5-7 页）

**整体思路**：让客户高层"重新认识今天的腾讯云"——这不是"我以为的腾讯"，而是"今天的腾讯云"。建立信任、格局与正式接待感。

**最佳实践内容层次**：

```
1. 腾讯集团组织架构 + CSIG 定位（1 页）
   → 六大事业群图 + CSIG（云与智慧产业事业群）定位高亮

2. 腾讯云全栈技术能力 + 自研上云（1-2 页）
   → 自研上云规模与反哺（成本效率/技术变革/自我演进）
   → 全栈能力矩阵（AI/安全/大数据/音视频/中间件/数据库/PaaS/SaaS）+ 关键数据

3. 腾讯云在【客户行业】的角色定位（1-2 页）
   → 数字化转型的"实践者 / 助力者 / 连接器"三重角色
   → 该行业的标杆合作速览（3-5 个可对标案例）

4. 标杆案例速览（1 页，可选）
   → 客户能直接对标的同行业标杆
```

**关键手法**：
- 用**组织架构图**建立集团格局认知
- 用**能力矩阵/大数据**建立"全栈、领先"的体感
- 角色定位落到**客户所在行业**，不泛泛而谈
- 此段偏"标准腾讯云介绍"，可较多复用既有素材

---

### 板块二：行业趋势与理解（宏观，目标 6-9 页）

**整体思路**：大领导对具体业务理解不深，更愿从**行业趋势**看合作。用宏观趋势与高层对话，最后顺势落到"腾讯对客户的理解"，为板块三的重点项目做铺垫。

**最佳实践内容层次**：

```
1. 行业宏观趋势判断（1-2 页）
   → 行业所处发展阶段 + 大判断（一句话立论）
   → 政策/技术/市场三重驱动

2. 关键趋势拆解（2-4 页）
   → 3-5 个核心趋势方向，每个趋势一页或半页
   → 每个趋势：趋势描述 + 对行业的影响 + 隐含的机会

3. 行业场景全景图谱（1 页）
   → 该行业的重点业务场景全景（图谱式，从行业实际业务/发展重点出发）
   → 建立"行业全貌"认知，自然引出重点场景

4. 腾讯对【客户】的理解（1 页）⭐ 核心衔接页
   → 三栏对照：表象（客户/行业痛点）→ 症结（痛点背后的根本原因，从客户实际分析，不预设方向）→ 入口（腾讯云能帮解的合作方向）
   → 底部承上启下："基于以上理解，我们认为可以一起做的事是…"
   → 详见 references/signature_pages.md「客户理解三栏」
```

**关键手法**：
- 用**趋势时间线/趋势卡片**展示行业演进
- 用**场景全景图谱**建立行业全貌
- **客户理解三栏页**是板块二到板块三的关键铰链，"入口"列必须对应板块三的重点方向（模式A 对应重点项目，模式B 对应全场景中的建议优先方向）
- 涉及市场数据的页面，**页面底部小字标注数据来源**

---

### 板块三：重点合作项目与探讨（需拍板，目标 7-11 页，占比最大 · 全场重心）

**整体思路**：高拜的最终目的是通过高层策应落地合作。本板块把对话从"展示"切到"决策"。**根据用户是否指定了重点项目，分两种模式**：

- **模式 A · 聚焦重点项目**（用户在 Phase 1 明确给出了 1-3 个重点项目）：直接聚焦展开这几个项目，收口到需老板拍板的决策点。
- **模式 B · 行业全场景方案**（用户未给出重点项目）：**先给该行业较全面的多场景解决方案图谱与逐场景概览**（对标高拜运营商模板的"六大场景解决方案"），再以"合作探讨"页邀请高层圈定重点方向。**不要因为用户没给项目就只列 2-3 个 AI 推断项目**——高层更希望先看到腾讯云在本行业能做的全貌，再共同锁定重点。

**模式 A 内容层次（用户给了重点项目）**：

```
1. 合作回顾 / 接触历程（1 页）
   → 按合作深度选变体（见 references/signature_pages.md「合作回顾三变体」）

2. 合作蓝图金字塔（1 页）⭐ 核心视觉
   → 1 个目标 + 3-4 个业务方向 + N 个场景 + 技术基础（底座）

3. 重点项目逐一展开（每项目 1-2 页，共 3-6 页）⭐ 主体
   → 按用户指定的重点项目逐一展开，每个项目：
     · 项目背景与意义（为什么现在做）
     · 腾讯云方案概要（不深挖技术细节）
     · 客户价值 / 预期收益（量化优先）
     · ⭐ 需高层决策的关键点（要老板拍板的是什么）
   → 可穿插代表案例佐证

4. 下步建议 / 合作探讨（1-2 页）
   → 落地动作四件套 / 三步法
```

**模式 B 内容层次（用户未给重点项目）**：

```
1. 合作回顾 / 接触历程（1 页）
   → 同模式 A

2. 行业全场景解决方案图谱（1 页）⭐ 核心视觉
   → 该行业腾讯云能提供的多场景解决方案总览（如运营商"六大场景"：
     自主创新 / 云网服务 / 无界安全 / 人工智能 / 异构算力 / ICT 合作）
   → 图谱式呈现，让高层一页看清"腾讯云在本行业能做的全貌"
   → 场景划分从行业实际业务出发，不硬凑

3. 逐场景方案概览（每场景 0.5-1 页，共 3-6 页）
   → 每个场景：场景定位一句话 + 2-3 个子方案要点 + 代表案例（如有）
   → 概览级别即可，不逐一深挖（高层看全貌，不看技术细节）
   → 每个场景可配 1 个代表案例佐证

4. 合作探讨（1-2 页）⭐ 收口
   → 对标高拜模板"合作探讨"页：请高层从上述全场景中圈定近期优先推进方向
   → 给出腾讯云的建议优先级（哪 2-3 个场景最适合本客户先落地，附理由）
   → 下步动作：深度交流 / 联合专班 / 小步 POC（带时间表+牵头人）
```

**关键手法**：
- 模式 A 用**合作蓝图金字塔**收敛，模式 B 用**行业全场景图谱**铺开——两者都让高层"一页看清全局"
- 模式 A 每个重点项目**必须有"需高层决策的关键点"**；模式 B 的收口页**必须给出建议优先级**，把"圈定方向"的决策交回给高层
- 下步建议**必须落到具体动作 + 牵头人 + 时间表**，不停留在口号
- 内容**按业务场景组织**，产品名只作为能力支撑出现，不罗列产品清单
- 模式 B 若调研中发现明显契合客户的方向，可在收口页把它标为"建议优先"，但**不替客户拍板**，措辞为"建议探讨"

### 5.1 调用方式

> ⚠️ PPT 工具调用时**必须**传入 `use_template` 参数。

### 5.4 轮询策略

调用 `generate_ppt` 后需要轮询等待生成完成：

- **首次查询**：等待 15-20 秒再开始轮询
- **轮询间隔**：30-60 秒
- **整体生成时长**：通常 20-30 分钟，需耐心等待
- **状态流转**：`pending` → `running`（多个子阶段）→ `success`
- **子阶段依次为**：规划并搜索配图 → 规划幻灯片结构 → 预生成SVG图表 → 并发生成幻灯片 → 视觉质量检查与修正 → 上传文件

## 特殊场景处理

### 场景一：首次拜访（First Call）

1. 板块三"合作回顾"页改用"行业接触历程 + 同行业标杆"变体，不虚构合作历史
2. 下步建议用**三步法**（技术深度交流 → 小步 POC → 建立长效机制），行动颗粒度宜小
3. 客户理解页更依赖公开资料（财报/官网/新闻），不臆测

### 场景二：中小型客户

1. 板块一务实简洁，不强调"共同基因/对等"，避免"装大"
2. 尽快进入行业趋势与重点项目
3. 总页数可下调至 18-22 页

### 场景三：调研信息不足

1. 用更宽泛的行业关键词扩大搜索范围，追加搜索轮次
2. 明确告知用户哪些部分信息不够，建议补充
3. 在 planning 中对信息不足的页面标注 `[建议补充]`

### 场景四：用户未提供重点项目 → 走板块三模式 B（行业全场景方案）

用户没给具体重点项目时，**不要只列 2-3 个 AI 推断项目**，而是按板块三"模式 B"组织：

1. 板块三改为**行业全场景解决方案图谱 + 逐场景概览**（对标高拜运营商模板"六大场景解决方案"），先给高层看腾讯云在本行业能做的全貌
2. 场景划分从行业实际业务出发（如运营商六大场景），由 Phase 2 深度研究支撑，每个场景给概览级要点 + 代表案例
3. 以"**合作探讨**"页收口：给出腾讯云建议优先推进的 2-3 个场景方向（附理由），把"圈定重点"的决策交回高层，措辞为"建议探讨"，**不替客户拍板**
4. 在 Phase 6 汇总时说明"本次未指定重点项目，已按行业全场景方案组织，并给出建议优先方向供圈定"

### 场景五：用户指定页数

1. 按 Phase 4.2 比例分配各板块页数
2. 无论页数多少，**板块三（重点项目）占比不低于 35%**
3. 页数极少（<18）时：压缩板块一，保住板块二趋势和板块三项目

## 关键约束

1. **面向高层**：内容宏观、有格局、有战略高度；弱化技术细节，强化趋势判断与决策价值
2. **收口到决策**：材料最终必须收口到高层可决策的落点——模式A 收口到"需高层拍板的重点项目"，模式B 收口到"合作探讨页 + 建议优先方向供圈定"；这是高拜区别于普通方案的核心
3. **信息可靠**：所有内容必须来自调研结果或用户材料，禁止编造数据
4. **标注来源**：所有涉及数据引用的页面，页面底部用**小字脚注**标注来源
5. **框架完整**：三段框架必须齐全，客户理解三栏页必出；板块三视模式必出合作蓝图金字塔（模式A）或行业全场景解决方案图谱（模式B）
6. **客户理解痛点驱动**：客户理解三栏的"症结"必须从**客户/行业真实痛点**分析根因（增长/成本/效率/体验/安全/数据/组织/竞争等，视客户而定），**禁止不看行业实际、把所有客户都套"数字化/智能化不足"这种统一说辞**；逻辑链是"客户痛点→根因→腾讯云能帮的方向"，不是"腾讯云想卖什么→倒推客户需要数字化"
7. **方向是业务场景词**：合作蓝图、重点项目与全场景图谱的"方向/场景"必须是客户业务场景词（如"全域数据要素运营""云网数字孪生"），**不是产品名**；产品只作为能力支撑出现
8. **合作回顾诚实**：不把"潜在合作"写成"已合作"，按合作深度选对变体
9. **下步建议可落地**：带具体动作 + 牵头人 + 时间表，不停留在口号
10. **品牌合规**：必须使用腾讯云模板，确保 Logo 和品牌元素正确
11. **布局多样**：连续 2 页不使用相同布局，全 PPT 至少 6 种布局模式
12. **多轮研究**：优先乐享 MCP 检索，不足时 WebSearch 补充（至少 3-5 轮），关键页面用 WebFetch 抓取
13. **context 传参**：研究内容整理为 2000-4000 字结构化文本，通过 `context` 参数传给 `generate_ppt`
14. **不主动罗列 WXG/微信生态产品**：需要"组织/沟通底座"时用不指名表述，客户主动问可简短作答
