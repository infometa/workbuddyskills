## 〇、服务定位

用户浏览器访问内网 Web 系统，经 webgw-server 反代鉴权后转发到后端业务。鉴权是一条插件链，按资源认证类型走不同路径。

### 日志文件（重要）

- **所有可落盘日志（info/error/access）统一写入 `/data/services/pcmgr_enterprise/logs/webgw-server/debug.log`**。
- 该服务**没有独立的 error 日志文件**（配置只有一个 file writer，level=info；Debug 级不落盘）。
- 访问日志优先**上报到总控**，上报失败时才落到 debug.log。

## 二、故障场景库

### 场景 A：访问某 Web 系统提示 403 / 没有权限（策略鉴权未通过）

**① 功能逻辑**：App 类资源经一次认证拿到用户身份后，调 ngn-query 判断该用户对该资源有无授权策略，无权限返回 403。
**② 大概原因**：用户对该资源无 ngn 策略权限（ngn-query 返回 false）。
**③ 排障方式**：在 `debug.log` 搜 `策略鉴权未通过`（对应 403）；用**访问日志的 user_id(账号) + resource_id** 定位。若要看 ngn 侧，去 ngn-query 日志按 **UID + ServiceID** 查。
> [安全化移除] 原始资料中的执行片段、敏感材料索取或变更步骤已删除；仅可按公共规范进行只读、限时、脱敏核实。

### 场景 B：二次认证过期 / 需重新认证（401，敏感资源）

> [安全化移除] 原始资料中的执行片段、敏感材料索取或变更步骤已删除；仅可按公共规范进行只读、限时、脱敏核实。

### 场景 C：网关内部错误 / 网关服务异常（406）

**① 功能逻辑**：链路中取用户信息/资源/策略地址等失败，返回 406（页面显示"网关内部错误"或"网关服务异常"+具体原因）。
**② 大概原因**：分多种，看关键字定位：

| 日志关键字 | 代表根因 |
|---|---|
| `策略鉴权服务异常` | 调 ngn-query/PolicyCheck 报错（服务/网络/超时5000ms） |
| `根据code获取用户信息异常 err:` | authkeeper `/oauth/user` 调用失败或返回非 success（code 换身份失败） |
| `获取请求资源相关数据异常:` | 资源解析/取租户失败 |
| `获取策略鉴权地址异常` | 全局 config 或总控地址为空 |

| `Secondary authentication acquisition resource not found` | ctx 中无 Resource（资源配置/缓存没下发） |

### 场景 D：请求被过滤拦截（406，IP/浏览器）

**① 功能逻辑**：资源可开 IP 策略、浏览器（User-Agent）策略，命中黑名单或不在白名单则返回 406。
**② 大概原因**：来源 IP 命中黑名单/不在白名单；或 User-Agent 命中浏览器规则；或开了 IP 校验但没配 IP 组。
**③ 排障方式**：在 `debug.log` 搜 `request is filtered, ` 后跟具体 Message：`当前IP不允许访问` / `该浏览器不允许访问...` / `开启IP校验,未设置IP组`。
