# 偏好学习机制（越用越懂你）

> 对应升级方案 W16 / 成长曲线第 3-5 次使用阶段。目标：把用户反复出现的编辑
> 决策沉淀为显式规则，让修改轮次随使用次数递减。**偏好只记编辑风格，
> 不记人物、家庭、隐私信息。**

## 存储位置

`~/.workbuddy/MEMORY.md` 的 `## 贴图头条-编辑偏好` 小节（用户级、跨项目、
显式规则区——与 WorkBuddy 云端隐式画像互补：这里是**必须精确执行**的规则）。

## 格式

```markdown
## 贴图头条-编辑偏好

- 模板倾向：综合版默认 synthesis；单版日报偏 authoritative
- 标题风格：只用报纸原标题；缩行可以，改写一个字都不行
- 忌讳：不要配图压字；报头必须完整露出
- 修改习惯：说「往左一点」指主图 x 坐标 -40px 左右
- 确认口径：同一偏好被确认 ≥2 次视为固化（记 [固化 2026-09-05]）
```

## 写入规则（写入前必须过用户这一关）

1. **触发时机**：用户确认终稿时（「就这个」「可以」「发吧」），专家从本次
   editorial_log 提炼 **至多 1 条** 候选偏好（模板选择/标题处理/常用修改
   模式），不得批量捞。
2. **复述确认**：候选偏好用一句人话复述给用户（「以后综合版都默认用
   synthesis 模板，对吗？」），用户点头才写入；摇头则只记入本日
   editorial_log，不入 MEMORY。
3. **固化计数**：同一偏好第二次被确认时追加固化标记与日期；固化前的表述
   保持「倾向」措辞，固化后改为「默认」措辞（默认可被单次明确指示覆盖，
   覆盖本身也算一次确认信号）。

## 读取规则（注入时机）

- **四阶段 SOP 的「决策」阶段开头**：读偏好小节，逐条检查是否命中本次任务
  （单版/综合、标题来源、版式约束）。命中的直接应用，并在方案说明里带一句
  「按你的偏好：……」，让用户知道这条规则在生效、随时可以推翻。
- 冲突处理：明确指示 > 固化偏好 > 倾向偏好 > 专家默认值。冲突结果写进
  editorial_log.decisions 备查。

## 边界

- 偏好小节总长控制在 20 行以内；超过时合并同类项，被合并项标注 superseded
  而非删除（保留可审计痕迹）。
- 不写敏感信息：家庭影像偏好、人物称呼等一律不入 MEMORY，进了也会被
  本工作区「隐私边界」条款拒绝执行。
- 偏好是加速器不是黑箱：用户随时说「忘掉 XX 偏好」即删除对应行。
