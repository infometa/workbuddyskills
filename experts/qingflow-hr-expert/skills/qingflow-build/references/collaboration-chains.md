# 人才管理端到端协作链路

> 原则：单一 Skill 可独立使用，链路组合产生增量价值；数据经轻流应用中转（record_insert/record_update → record_list/record_get）

---

## 核心设计原则

1. **单一 Skill 可独立使用，链路组合产生增量价值** — 链路是可选编排，不引入强依赖
2. **数据经轻流应用中转** — Skill 之间不直接传递数据，轻流应用即为链路的"数据总线"
3. **契约先行** — 链路定义关键字段契约（字段名/类型/取值约定）
4. **人在环节点明确** — 标注需要人工确认的关口，AI 不越权
5. **状态机字段必备** — 每个契约载体应用必须有"状态"字段，下游只消费终态记录
6. **幂等约定** — Skill 回写前先按业务键查重（如候选人手机号、员工工号），避免重复写入

---

## 人才管理闭环

```
#01 招聘引擎 → #04 入职搭建 → #02 培训设计 → #03 绩效管理 → #05 人力看板
```

| 环节 | 上游产出 | 下游消费 |
|------|---------|---------|
| 招聘 → 入职 | 候选人评估报告、Offer 状态 | 转为员工档案，触发入职审批流 |
| 入职 → 培训 | 员工档案、岗位信息 | 生成岗位培训需求与课程计划 |
| 培训 → 绩效 | 培训完成记录、考核成绩 | 作为绩效参考与能力评估输入 |
| 绩效 → 看板 | KPI/OKR 达成率、面谈记录 | 汇入人力分析看板指标 |

**契约要点**：候选人评估数据入职后转为员工档案；培训完成率与绩效结果汇入人力看板；全链路指标统一展示。

**人在环关口**：Offer 确认（HR）、入职审批（用人经理）、绩效面谈（直属主管）

---

## 关键字段契约示例

| 应用 | 关键字段 | 类型 | 说明 |
|------|---------|------|------|
| 候选人库 | 候选人状态 | 单选 | 待评估/面试中/Offer/已入职/淘汰 |
| 员工档案 | 员工工号 | 文本 | 全局唯一，入职时从候选人关联 |
| 培训记录 | 完成状态 | 单选 | 未开始/进行中/已完成 |
| 绩效记录 | 考核周期 | 日期 | 如 2026-Q1 |
| 人力看板 | — | 聚合 | 只读消费上述应用的终态数据 |
