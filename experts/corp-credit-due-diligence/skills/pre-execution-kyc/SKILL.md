# 执行前 KYC 与任务授权采集

## 定位

本 Skill 是**鉴权成功后的**尽调任务交互门禁，用于确认本次任务的数据授权和交付约束。调用前必须已经取得 `auth-permission` 的 success；鉴权未成功时不得调用本 Skill。它不等同于法定 AML/KYC 身份核验，不验证身份证件、受益所有人或制裁名单；如业务需要正式 KYC，必须另接合规身份核验服务。

## 触发规则

- `auth-permission` 返回 success 后，每个新尽调任务在首次实质执行前调用一次。
- 同一任务的追问、补充分析和报告导出继承已确认配置，不重复弹卡。
- 用户可随时用自然语言修改数据来源、证据标准、交付形式或企查查授权；表达清晰时直接更新，不重新弹出完整卡片。
- 只有修改意图不明确、答案不在支持范围内或多个要求互相冲突时，才仅针对受影响的配置项调用 `AskUserQuestion` 追问，不得重弹无关问题。
- 用户选择“自由探索”后，必须继续用单项卡片确认输出格式；未确认 PDF、HTML 或 Markdown 前，KYC 不视为完成。
- 用户选择企查查“需要指引”后，必须展示本文件规定的连接指引并停止企查查相关查询，等待用户完成连接。
- 简短问候、能力介绍、服务边界说明以及仅询问缺失的企业/行业名称时不调用。
- 鉴权未成功时不得调用本 Skill。
- 未收齐答案、用户取消、工具失败或答案存在关键冲突时，不得开始联网检索、材料解析、业务技能调用或报告生成。

### 自由探索输出格式追问

当用户在交付形式中选择“自由探索”（含历史兼容值“全量底稿”），且未明确指定输出格式时，必须继续调用 `AskUserQuestion` 弹出以下单选卡片。不得自行选择默认格式，也不得把该问题加入所有用户都会看到的首轮四项卡片。

      "multiSelect": false,

## 结果处理

将 `｜` 左侧作为本任务的标准配置值，并保留完整答案供后续约束执行：

- `data_source`: `用户材料` 或 `外部调研`
- `evidence_standard`: `严格证据` 或 `尽力补全`
- `delivery_format`: `自有模板`、`标准报告` 或 `自由探索`
- `output_format`: 自由探索时为 `PDF`、`HTML` 或 `Markdown`；其他交付形式不设置
- `qichacha_authorization`: `已授权`、`需要指引` 或 `不使用`
- `kyc_intake_status`: 四项均已回答，且自由探索已确认输出格式时，才为 `completed`

完成后向用户简短确认选择，再进入后续流程。选择企查查“需要指引”时，还必须展示下方连接指引并等待用户完成连接。不要把内部字段名展示给用户。

## 企查查连接指引

当用户选择“需要指引｜先完成连接授权再查询”时，按以下内容引导，不得在用户确认连接完成前调用企查查：

### 建议连接流程

1. 打开 WorkBuddy。
2. 从左侧进入“专家·技能·连接器”。不同版本也可能显示为“连接器”或“专家、连接器”。
3. 切换到“连接器”页面。
4. 搜索并找到：
   - **企查查**：企业工商、股东、经营风险等基础信息；
   - **企查查·法律数据**：司法案件、被执行、失信等法律风险信息。
5. 用于企业尽调时，建议根据账号权限同时连接以上两项。
6. 点击连接器右侧的“+”或“连接”。
7. 浏览器跳转后，登录企查查账号并确认授权。
8. 看到“授权成功”后，按页面提示返回或打开 WorkBuddy；不要直接关闭授权页面。
9. 确认连接器旁出现绿色圆点或“已连接”状态。
10. 新建任务并输入测试指令：

> 请通过企查查查询“腾讯科技（深圳）有限公司”的工商登记信息，并列出统一社会信用代码、法定代表人、注册资本、成立日期和股东信息。

11. 检查回答中是否明确调用企查查，并核对企业主体是否正确。

### 特别提示

- 完成连接只代表 WorkBuddy 获得调用权限，实际可查询的数据范围仍受企查查账号套餐和数据权限限制。
- 企业名称可能重名，正式查询建议同时提供统一社会信用代码。
- 涉及股权、司法、行政处罚等重要信息时，应核对数据更新时间，并以官方登记或司法机关信息为准。
- 授权页面不要直接关闭；看到“授权成功”后，应按页面提示返回或打开 WorkBuddy。
- 如果授权后仍不可用，依次检查登录账号、连接状态、启用开关、账号套餐权限以及网络环境。

展示指引后停止本轮企查查相关执行，请用户连接完成后回复“已连接”或说明遇到的具体问题。用户确认已连接后，将企查查授权状态更新为“已授权”，再继续任务。

## 自然语言修改接口

### 识别原则

在同一任务中，将以下表达及语义等价表达识别为配置修改，而不是新任务：

- “改用外部公开信息”“我上传材料给你” → 修改数据来源。
- “只保留可核验信息”“不要推测” → 修改为严格证据。
- “可以多找几个来源补全”“缺失项尽量补充” → 修改为尽力补全。
- “改成标准报告”“按我上传的模板”“自由探索就行”“给我全量底稿” → 修改交付形式；“全量底稿”作为“自由探索”的兼容别名处理。
- “给我 PDF”“输出 HTML”“生成 md/Markdown 文件” → 修改自由探索输出格式；如果当前不是自由探索，仅将其理解为导出要求，不改变交付形式。
- “不要用企查查”“企查查已经授权了”“先教我怎么授权企查查” → 修改企查查授权状态。
- “恢复刚才的配置”“撤销刚才的修改” → 如当前会话中存在唯一、明确的上一版本，则恢复上一版本；否则只询问要恢复哪一项。

### 更新规则

1. **明确即更新**：用户的目标值唯一明确时，直接更新对应项并简短确认，例如：“已将证据标准改为严格证据，其他配置保持不变。”
2. **局部更新**：只修改用户提及的字段，未提及字段保持不变。
3. **多项更新**：一句话可同时修改多项；更新后逐项摘要确认。
4. **最小追问**：表达含糊时，只询问受影响的一项。例如“报告形式换一下”只追问交付形式。
5. **卡片兜底**：需要结构化追问时，只提交受影响问题的原始选项，不得重新提交完整四项卡片。
6. **自由文本边界**：用户提出支持范围外的新配置时，不得擅自映射到最接近选项；应说明当前支持值并进行最小化确认。
7. **版本记录**：在当前会话任务上下文中保留修改前后的配置摘要，以支持后续继承和明确的撤销请求；不得向用户展示内部字段名或技术状态对象。
8. **条件字段联动**：交付形式改为自由探索时，如未同时明确输出格式，立即追问 PDF、HTML 或 Markdown；离开自由探索时清除该条件字段。

### 生效时点

- 尚未开始实质执行：新配置立即完整生效。
- 已开始检索、材料解析或分析：新配置对后续步骤立即生效；已经发生的操作无法追溯撤销。
- 新配置会使已取得证据不再合规时，不得继续引用该证据，并应在最终输出中披露范围变化。
- 从“已授权”改为“不使用企查查”后，不得继续调用企查查；此前已经取得的企查查数据不得用于后续结论或最终交付。
- 从“尽力补全”改为“严格证据”后，应重新检查尚未输出的结论，移除无法核验的推断。
- 交付形式在最终报告生成后发生变化时，可按新形式重新生成交付物，但不需要重新执行基础调研，除非新证据标准要求重新核验。

## 交付形式路由

- `自由探索`：先确认 `PDF`、`HTML` 或 `Markdown` 输出格式，再使用当前 Agent 的灵活任务模式，主要调用 `credit-industry-research` 开展公开网络搜索和综合分析；不强制生成九章报告。
  - `PDF`：先生成完整 Markdown 内容，再调用 `md2pdf` 生成 PDF 文件。
  - `HTML`：按 `credit-industry-research` 的 HTML 规范生成完整 HTML 文件。
  - `Markdown`：生成完整 `.md` 文件。
- `标准报告`：直接调用 `standard-credit-report`，由其独立完成用户材料处理、公开检索、九章分析和模板组装；不得调用或依赖 `credit-industry-research`，也不得把空模板当作报告交付。
- `自有模板`：等待并解析用户模板，按用户模板交付；用户模板未提供前不得生成最终报告。
- 历史会话中已记录为`全量底稿`的配置按`自由探索`处理，无需重新询问用户。

## 阻断与约束

1. 选择“用户材料”但尚未提供材料：鉴权已经完成；在材料到齐前不得进行依赖材料的核查，只询问本次任务必需材料。
2. 选择“自有模板”但尚未上传模板：鉴权已经完成；可继续收集对象信息，但在模板到齐前不得生成最终报告。
3. 选择“需要指引”：展示本文件“企查查连接指引”的完整内容并停止企查查相关查询；用户确认已连接后更新为“已授权”再继续。
4. 选择“不使用”：全程不得调用企查查，改用其他合规公开或已授权来源，并披露数据限制。
5. 选择“严格证据”：无法核验的信息留空或标为待核验，不得推断补齐。
6. 选择“尽力补全”：可以多源交叉补充，但必须标注来源、采集日期和置信度。
7. 用户拒绝或取消采集：说明必须先完成执行前确认，本轮停止业务执行。
8. `AskUserQuestion` 不可用或调用失败：明确说明结构化确认组件不可用并阻断，不得自行假定默认答案。
9. 选择“自由探索”但尚未确认输出格式：继续弹出输出格式单项卡片；确认前不得开始业务执行。
