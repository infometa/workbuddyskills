# 天御对公信贷 · 信贷尽调专家

> 腾讯云天御对公信贷专家 — 对公信贷全流程尽调助手，覆盖行业研究、财务核查、实控人画像与风险预警，依托腾讯云天御风控输出结构化信评报告，助力授信决策。

## 类型

Agent 型专家（单个 AI 专家 + 配套技能）。用户提供**企业名称**后，Agent 会先进行认证鉴权；鉴权成功后完成一次结构化 KYC/任务授权确认，再进入全流程尽调，最终产出一份可在聊天窗口呈现、并支持交付为 Markdown / HTML / PDF 的信用评估报告。

## 核心能力

| 能力 | 说明 |
|---|---|
| 鉴权后 KYC | 鉴权成功后，通过结构化卡片确认数据来源、证据标准、交付形式和企查查授权；自由探索继续确认 PDF / HTML / Markdown，企查查未连接时提供 WorkBuddy 授权指引；未确认前不执行尽调 |
| 双交付路由 | “自由探索”使用行业研究/综合调研技能；“标准报告”使用独立九章报告流程，两条路径不串联 |
| 行业研究 | 宏观环境（PEST）、行业生命周期、波特五力、行业财务特征与关键变量敏感性分析、竞争格局与监管政策 |
| 财务核查 | 三大表勾稽、营运资金与现金流分析、人效基准对标、民企财务偏差与关联交易风险识别 |
| 实控人画像 | 实控人背景、涉诉/被执行/对外担保等关键人风险扫描 |
| 风险预警 | 行业共性风险矩阵 + 企业个体风险（诉讼、监管处罚、同业违约匹配），带置信度标注 |
| 信评报告 | 标准化 Markdown 报告，含执行摘要、综合评级、一票否决红线与监控指标，支持渲染 HTML、导出 PDF |
| 人工补充提醒 | 所有“待客户经理补充”直接在正文原表格单元格、段落或清单项中标红；纯 Markdown 使用 `🔴 **待客户经理补充**`，并在报告末尾复核汇总 |
| 可核验引用 | 每项互联网事实在正文对应位置就地附可点击原始页面链接，末尾保留审计索引；无公开链接的用户材料或内部数据明确标注材料定位信息 |

## 内置技能

- `pre-execution-kyc`：鉴权成功后、首次业务执行前收集数据授权与交付约束，并作为检索和分析前的强制门禁。
- `credit-industry-research`：信贷尽调行业研究，7 大分析模块 + 附录，输出面向信贷经理的尽调建议与材料清单。
- `standard-credit-report`：整合并优化 `corp_20260727` 的九章模块逻辑，独立完成主体识别、材料处理、公开检索、财务核验、同业比较、司法筛查、风险归纳及模板组装；只在选择“标准报告”时调用。
- `md2pdf`：将 Markdown 报告转换为带专业排版、完整中文支持的交付级 PDF（支持封面、目录、书签）。
- `auth-permission`：最先执行的认证与鉴权步骤；鉴权通过后方可进入 KYC 配置确认。

> 此处“KYC”是任务级数据授权与执行约束确认，不替代法定 AML/KYC 身份、受益所有人或制裁名单核验。如需正式客户身份核验，应另接合规 KYC 服务。

初次确认后，用户可直接说“改成严格证据”“不要使用企查查”“按我上传的模板输出”等来局部修改配置；未提及的配置保持不变。只有表达不明确时，Agent 才会针对相关项进行最小化追问。

交付形式说明：

- **自由探索**：先选择 PDF、HTML 或 Markdown 输出格式，再使用 `credit-industry-research` 开展公开网络搜索，按问题灵活组织分析，不强制套用固定模板。历史配置中的“全量底稿”按自由探索兼容处理。
- **标准报告**：由独立标准报告能力完成公开信息检索、用户材料处理和九章报告生成，不调用 `credit-industry-research`。
- **自有模板**：按用户上传模板输出。

## 使用示例

- "帮我调研下 {企业名}。"
- "帮我对 XX 行业做系统性研究，覆盖竞争格局、监管政策、风险点。"
- "对 XX 公司开展财务核查，重点识别民企财务偏差与关联交易风险。"
- "评估 {企业名} 的授信风险 / {企业名} 能不能授信。"

> 数据来源：企业工商信息优先取自企查查连接器（不可用时通过联网公开搜索获取），其余信息通过联网搜索获取。本报告基于公开信息，不替代人行征信、银行流水等内部资料。
