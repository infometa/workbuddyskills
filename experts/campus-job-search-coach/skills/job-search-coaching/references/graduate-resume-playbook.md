# 应届生与实习简历制作手册

## 一、适用范围

用于从零制作大学生、应届生和实习生简历，也用于把零散经历、旧简历或信息表整理成完整投递版。单条改写、岗位证据映射和事实追溯仍以 `resume-playbook.md` 为准。

本流程只使用专家包内的模板、样式与脚本，不要求用户安装其他 Skill，也不默认写入桌面或覆盖原简历。

## 二、先判断交付层级

| 用户目标 | 默认交付 | 文件条件 |
|---|---|---|
| 先看看怎么写 | 对话内结构与首版正文 | 不主动创建文件 |
| 要完整简历 | 模块取舍说明、完整正文、待确认项 | 用户要求文件时生成 Markdown 与 HTML |
| 要投某个岗位 | 岗位摘要、证据映射、定制版正文 | 有 JD 时按真实证据调整顺序和措辞 |
| 要 PDF | Markdown、HTML、PDF 与页数结果 | 只有用户明确要求且浏览器渲染成功时交付 PDF |

用户提供的原始 PDF、Word、Markdown 或文本均视为只读底稿。生成候选版本，不覆盖原件。

## 三、最小信息集

先提取用户已经给出的内容，不重复询问。完整简历通常需要：

1. 目标岗位或大致方向；没有方向时可先做通用版。
2. 教育：学校、学历、专业、起止时间；GPA、排名、课程和荣誉均为可选。
3. 实习或实践：组织、角色、时间、本人动作、方法与真实结果。
4. 项目：名称、时间、角色、解决的问题、本人工作、技术或方法、真实结果。
5. 技能、语言、证书、奖项或开源成果。
6. 姓名与城市；电话、邮箱等敏感联系方式可由用户在终稿自行补充。
7. 输出语言，以及是否需要 Markdown、HTML 或 PDF。

若信息可用，先生成事实底稿，只追问一个会改变模块、顺序或核心表述的问题。若用户希望一次填写，可给出上述七项清单，但不得要求与简历无关的隐私信息。

## 四、模块选择与顺序

### 必选模块

1. 个人信息：姓名、电话、邮箱、城市；缺失时使用 `[电话待填写]`、`[邮箱待填写]`，不编造。
2. 一句话总结：最多一行，只写可由正文证明的学历、相关经历、项目亮点与技能关键词。
3. 教育背景：应届生默认前置；只写真实 GPA、排名、荣誉和相关课程。
4. 实习或实践经历：每段优先 2—3 条，按本人动作、方法、结果组织。
5. 项目经历：通常 1—3 个，相关性和可追问深度优先于项目数量。
6. 专业技能：按岗位需要分组，熟练度必须有事实依据。

没有实习时，用高质量项目、竞赛、科研或课程实践补位，不保留空章节。

### 可选模块

| 模块 | 使用条件 | 建议位置 |
|---|---|---|
| 论文或专利 | 已发表、已受理或有可核验状态 | 教育之后 |
| 开源贡献 | 有明确项目、提交或社区角色 | 项目之后 |
| 竞赛获奖 | 至少 3 项且值得独立展示 | 技能之后 |
| 社团与领导力 | 与岗位相关且能说明本人行动 | 靠后 |
| 证书与语言 | 有真实证书或成绩 | 并入技能或单列 |

一个可选模块内容少于 3 条时，优先合并到教育或技能；同一奖项不重复出现。超页时先删除低相关社团、课程和重复描述，不删除最相关证据。

## 五、内容生成规则

1. 每条经历先建立事实骨架：本人动作 → 方法/工具/协作 → 真实结果或交付物 → 与目标岗位的关系。
2. 没有数字时写清范围、对象、频率、交付物、复用或反馈，不制造百分比和规模。
3. 日期统一为 `YYYY.MM – YYYY.MM`；“至今”和“预计毕业”仅在用户确认后使用。
4. “参与”不得自动升级为“负责、主导、牵头、带领”；技术栈、熟练度和成果不得从岗位常识推断。
5. 中文和英文共享同一事实骨架，但分别按招聘语境改写，不逐句直译。
6. 使用 `scripts/resume_claim_audit.py` 检查新增数字、责任升级词、占位符与模板化表达；高风险项必须由用户确认后才能进入终稿。

## 六、文件生成

### 目录建议

在用户指定位置或当前工作区创建独立目录：

```text
resume-output/<version-id>/
├── resume-zh.md
├── resume-zh.html
└── resume-zh-ats-safe.pdf  # 仅在用户要求且成功生成时存在
```

不要创建虚假的 PDF 占位文件。若需记录事实风险，可另存审计结果；不默认长期保存用户的完整简历或 JD。

### Markdown

以 `templates/grad-template-zh.md` 为结构起点，但必须删除不适用的示例和空章节。约束：

- 使用 `##` 作为章节标题，不用 `---` 水平线分隔；
- 公司/项目标题使用粗体，不用多层标题制造额外间距；
- 联系信息是普通文本，不放在图片、页眉或复杂表格中；
- 量化缺口使用描述性占位符，如 `[请补充覆盖人数]`，不要只写无语义的横线。

### HTML 与 PDF

包内提供两条互补路径，共用 `assets/themes/ats-safe.css`。HTML 屏幕预览采用蓝色商务风 A4 纸张布局；打印和 PDF 使用独立的黑白样式，自动移除屏幕配色、阴影、画布与额外内边距，保留单列文本结构：

1. **完整投递版**：`scripts/export_pdf.sh` 使用 Pandoc 生成内联样式 HTML，再优先调用 Chrome、Edge、Brave 或 Chromium 输出 PDF；浏览器不可用时回退到 Tectonic。
2. **无 Pandoc 降级**：`scripts/render_resume.py` 可用 Python 标准库生成 HTML，并在存在 Chromium 系浏览器时直接输出 PDF。

完整投递版要求 Markdown 位于 `resume-output/<version-id>/resume-<lang>.md`：

```bash
bash scripts/export_pdf.sh \
  --workspace <workspace> \
  --version <version-id> \
  --lang zh \
  --theme ats-safe \
  --output resume-zh-ats-safe.pdf
```

需要先交付 HTML，或本机没有 Pandoc 时：

```bash
python3 scripts/render_resume.py resume-zh.md --html resume-zh.html
python3 scripts/render_resume.py resume-zh.md --html resume-zh.html --pdf resume-zh-ats-safe.pdf
```

两条路径均不得覆盖源 Markdown。任一渲染失败时保留 Markdown/已生成的 HTML，明确说明缺失依赖或失败状态，不得声称 PDF 已完成。

## 七、ATS 与单页规则

- 单列、标准章节、纯文本联系方式、统一日期、常见字体。
- 不使用照片、技能进度条、图标替代文字、复杂表格、多栏、浮动或绝对定位承载关键信息。
- 不承诺 ATS 通过率，不按关键词次数编造评分。
- 应届生常见目标是一页，但内容质量优先；研究型、作品型或经历丰富者可在用户确认后保留两页。

PDF 生成后优先检查页数。`render_resume.py` 会依次尝试 macOS `mdls`、`pdfinfo` 和 PDF 页面标记；使用 `export_pdf.sh` 时需另行运行 `mdls -name kMDItemNumberOfPages <pdf>`。无法可靠检测时必须提示人工打开核对。

超页修剪顺序：

1. 合并不足 3 条的独立模块；
2. 每段实习和项目保留最相关的 2—3 条；
3. 压缩超过一行的个人总结与重复职责；
4. 删除低相关课程、社团和证书；
5. 最后才小幅调整标题间距或页边距，不把正文字号压到难以阅读。

## 八、终稿检查

交付前确认：

- 每条关键陈述能回到用户材料；所有占位符已补充或明确保留。
- 学校、单位、职位、日期、数字、技能、奖项和语言能力前后一致。
- 最相关经历位于靠前位置，前两条能被快速扫到。
- 每个数字、角色和技术细节经得住面试追问。
- 文件没有覆盖原件；Markdown、HTML、PDF 的实际存在状态与对用户的说明一致。
- 提醒用户投递前亲自核对联系方式、事实、链接、文件名和页数。
