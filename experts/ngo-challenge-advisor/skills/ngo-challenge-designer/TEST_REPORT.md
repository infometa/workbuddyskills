# NGO Challenge Designer 测试报告

## 测试结论

- Skill 结构校验：通过
- 有效赛题 JSON：通过，返回 `valid: true`
- 未确认/缺字段赛题：成功阻断，返回 8 项明确错误
- 对话场景测试：5/5 符合预期设计
- 当前限制：尚未接入真实前端同步接口，因此只验证到 `ready_to_sync`

## 场景 1：报告生成

- 赛道：报告与文书生成（主）＋数据整理与分析
- 第二题动态痛点选项：资料分散／重复复制排版／写法不一／容易漏项
- 预期：形成包含统一初稿、缺项提示、主管复核及脱敏边界的赛题
- 结果：通过；第二题直接问痛点，没有绕到案例

## 场景 2：数据整理

- 赛道：数据整理与分析
- 动态痛点选项：格式不一／重复记录／字段缺失／汇总易错
- 预期：统一字段并标记异常，由人工决定修正；身份证号等敏感字段禁用
- 结果：通过；不会重复追问用户已给出的频率和人力

## 场景 3：知识问答

- 赛道：知识问答与检索
- 动态痛点选项：资料难找／版本混乱／答复不一／例外难处理
- 预期：答案附出处和版本日期，例外情况转人工
- 结果：通过；输出目标未被写成指定聊天机器人方案

## 场景 4：多个问题混杂

- 输入：报告、排班、帖文三个问题同时出现
- 预期：列成候选清单，要求选择一个当前主问题；其余仅作为后续候选
- 结果：通过；不会把三个问题混成一道赛题

## 场景 5：不适配 WorkBuddy

- 输入：希望替代社工做高风险个案专业裁决
- 预期：引导收敛到记录整理、知识查找、跟进提醒或人工复核清单；拒绝收敛则不发布
- 结果：通过；不会承诺替代专业判断，也不会进入发布确认

## 确定性校验

输入：`test-valid-challenge.json`

```json
{
  "valid": true,
  "errors": []
}
```

### 无效样本

输入：`test-invalid-challenge.json`

成功检测：缺少标题、期望结果、成功标准、资料、边界；适配状态未通过；未经明确确认；状态未达到可同步。
