# 阈值设置指南

告警阈值设置不当会导致两类问题：**阈值太低 → 频繁误报**；**阈值太高 → 漏报真实危机**。

推荐先用 `calc_threshold.py` 分析历史数据获取建议值，再结合业务经验微调。

---

## 一、商店评分告警阈值

### 计算方法

不同渠道的阈值单位不同，不要混用：

- **Steam**：使用好评率百分比，字段是 `absolute_pp`、`drop_6h_pp`、`drop_24h_pp`，单位是 `% / pp`。
- **Google Play / App Store**：使用 0-5 星评分，字段是 `absolute_score`、`drop_6h`、`drop_24h`；一星占比使用 `one_star_rate`，单位是 0-1 占比。

通用计算思路：

1. 取近 30 天每日对应指标时间序列。
2. 计算均值（μ）和标准差（σ）。
3. 建议阈值 = **μ - 2σ**（覆盖 95% 正常波动），再结合业务等级微调。

```
示例：
Steam 近 30 天日均好评率 = 78%，σ = 4%
建议阈值 = 78% - 2×4% = 70%

Google Play 近 30 天日均评分 = 4.2，σ = 0.2
建议阈值 = 4.2 - 2×0.2 = 3.8
```

### 经验参考

| 渠道 | 健康区间 | 默认绝对阈值示例 |
|------|----------|------------------|
| Steam | 好评率持续 80%+ | P0 < 60%，P1 < 75%，P2 < 80% |
| Google Play / App Store | 评分持续 4.0+ | P0 < 3.0，P1 < 3.5，P2 < 4.0 |

### 进阶：环比下滑告警

不仅看绝对值，还可监控"相比上周同期下滑幅度"：

- Steam：监控好评率下滑，例如 `drop_6h_pp: 2` 表示 6h 下跌 2pp。
- Google Play / App Store：监控评分下滑，例如 `drop_6h: 0.1` 表示 6h 评分下降 0.1。

## 二、KOL 热帖告警阈值

### 计算方法

1. 取近 30 天所有帖子 engagement 分布
2. 建议阈值 = **第 90 百分位（P90）**
3. 超过 P90 的帖子代表同期 Top 10% 的传播力

```
示例：
近 30 天 P90 engagement = 12,000
建议阈值 = 12,000（高于此值即告警）
```

### 各渠道量级参考

| 渠道 | 普通帖 engagement | 高互动帖 engagement |
|------|-----------------|-------------------|
| YouTube | 1,000–10,000 | > 100,000 |
| Twitter / X | 100–5,000 | > 50,000 |
| Reddit | 50–2,000 | > 10,000 |
| Steam 评测 | 10–500 | > 2,000 |

> ⚠️ 各渠道量级差异极大，建议分渠道设置阈值，或只在全渠道中监控极端值（P99）

### 负面过滤建议

开启 `--kol_sentiment_filter` 后仅告警 `sentiment_rating IN (1,2)` 的负面帖，可大幅减少误报（中性/正面 KOL 帖通常不需要紧急响应）。

## 三、关键词告警阈值

### 计算方法

关键词告警 v2 同时评估三类触发维度：

1. **提及量激增**：当前窗口提及量 ≥ 历史基准 × `--threshold`，且 ≥ 最小绝对量。
2. **负面情感占比**：当前窗口负面占比达到灵敏度阈值，并高于历史负面基准 5pp。
3. **单帖爆款**：窗口内单帖互动量 ≥ `--viral_threshold`。

```
示例：关键词 "AZ3"
当前 24h 提及量 = 354 条
过去 7 天同窗口平均 = 253.6 条
单帖最高互动 = 51,723
若 --viral_threshold=500，则即使命中量倍数未超过 --threshold，也会触发单帖爆款告警。
```

### 关键词选择建议

| 类型 | 示例关键词 | 说明 |
|------|-----------|------|
| 技术问题 | crash, freeze, bug, lag, error | 游戏稳定性问题 |
| 账号安全 | ban, hack, cheat, stolen | 账号相关危机 |
| 内容问题 | p2w, nerf, broken, unfair | 游戏平衡问题 |
| 竞品词 | 竞品游戏名 | 玩家流失信号 |

> 关键词数量建议 ≤ 10 个。脚本会同时匹配 NLP `keywords` 字段和 `content_to_zh/content` 正文，过多关键词会增加 SQL 成本。

### 危机词默认等级

危机词表位于 `keyword_crisis_terms.yaml`，运行时由 `check_alerts.py` 读取：

| 类别 | 默认等级 |
|------|----------|
| 外挂作弊 / 封号争议 / 付费争议 | P1 |
| 数据安全 / 停服跑路 / 法律舆论 | P0 |

命中危机词且触发 `mention_spike` 或 `negative_ratio` 时使用危机词专用模板；仅命中 `viral_post` 时优先使用单帖爆款模板。

### 静默期

关键词告警静默时长等于 `--window_hours`。状态 key 粒度为：

```text
keyword:<user_id>:<game_id>:<keyword_group>:<trigger_dimension>
```

同一关键词组的不同触发维度互不影响；MVP 阶段不做跨关键词组聚合去重。

## 四、阈值调优建议

### 告警过于频繁（误报多）
1. 提高绝对阈值
2. 改用环比/同比下滑触发，而非绝对值
3. 提高 `--threshold`、`--min_mentions` 或 `--viral_threshold`

### 告警很少触发（可能漏报）
1. 降低阈值（如从 P90 降至 P80）
2. 降低 `--threshold` 或 `--viral_threshold`
3. 扩大关键词列表，加入版本热词、地图名、活动名等正文中会出现的词

### 首次设置建议流程

1. 运行 `calc_threshold.py --lookback_days 30` 获取建议值
2. 回看近期是否有真实口碑事件，验证该阈值是否能捕捉到
3. 上线后前两周保持关注，根据实际触发情况调整
