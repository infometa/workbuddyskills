# 来源与版本台账

## 决策问题

如何让每条关键材料、外部来源和正式产物都能回答“来自哪里、何时有效、谁可使用、何时失效”。

## 适用与不适用

适用于材料整理、联网研究、长文档和正式交付。不用于判断专业观点对错，也不把来源权威性直接等同结论成立。

## 最小输入

材料定位符、提供者或发布者、发布日期/数据日期、检索日期、法域、版本、敏感级别、授权范围和内容摘要。

## 方法步骤

1. 为来源分配稳定 `sourceId`，区分用户一手、官方一手、研究原文、内部整理和二手材料。
2. 记录生成、使用、修订、取代和失效时点；本地文件可用 SHA-256 固定版本。
3. 将事实、推断和未知分别绑定来源，不为没有来源的推断补造引用。
4. 按新鲜度类别设复核日和过期策略；实时事实及现行规则使用前重新核验。
5. 对敏感、个人或受许可限制材料只保存必要索引和授权边界。

## 输出形状

来源台账、版本关系、有效期、权威级别、核验状态、敏感级别、使用边界和待复核项。

## 失败模式

只留网页标题；把检索日当发布日期；复制大段受版权保护内容；用旧版本支持现行规则；把秘书整理写成专业结论。

## 停止与人工关卡

来源权利不明、存在个人敏感信息、现行法或实时价格过期时标记 `needs_review`，不得进入生产资产或正式发布。

## 来源与边界

内部职责见 `[src:internal-agent-contracts]`。版本和失效关系借鉴 W3C PROV 的通用来源模型，见 `[src:w3c-prov-o]`；本资产不要求采用 RDF，也不复制标准正文。
