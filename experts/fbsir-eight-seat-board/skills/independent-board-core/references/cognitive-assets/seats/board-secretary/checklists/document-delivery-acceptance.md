# 正式产物交付检查清单

## 使用时点

审议结果收齐后生成 Markdown、Word、PDF、双语稿、视觉简报或发布草稿时。

## 检查项

- `S1` 必须项：产物类型、读者、用途、范围、格式和人工验收人明确。
- `S2` 必须项：只使用 N/N 收齐器接受的真实席位结果，保留席位 ID、结果哈希和异议。
- `S3` 必须项：主张可回到来源、用户材料或席位回执；事实、推断、假设和未知分开。
- `S4` 必须项：建议包含成立条件、失效条件、责任方向、时点和人工关卡。
- `S5` 必须项：Markdown 文件位置和 SHA-256 已校验；Word/PDF 已预览分页、目录、表格和中文字体。
- `S6` 必须项：外部发布目标、最终内容哈希、身份与权限获得当次确认。
- `Q-S/P/C/B`：检查语言句式、段落推进、跨节连续与去模板化表达；不让顺滑文风抹去异议。
- `Q-G`：事实、版权、用户约束、隐私和专业红线任一未闭合时标 `needs_review`。
- `DQ`：显示决策质量六链的最弱项，并保留选择、指标、触发器、负责人和复审日期。

## 完成规则

基础 Markdown 通过收齐、标题、路径和哈希门后可展示；其他格式必须获得真实产物回执和人工验收。

## 缺失处理

未收齐则不汇编；格式能力不可用则交付可验证 Markdown 和恢复建议；未授权则只准备草稿。

## 来源与边界

依据 `[src:internal-document-delivery]`。文件存在、成员绿勾或脚本成功均不等于用户验收。
