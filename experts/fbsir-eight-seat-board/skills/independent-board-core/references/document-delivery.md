# 长文档与正式产物协议

## 使用场景

用于审议备忘录、深度准备卡、经营报告、白皮书式附件、双语稿、Word/PDF、视觉简报和发布草稿。短答不启用长文档流程。

快审、标准审议和深度准备在收齐后默认生成对应 Markdown 文件；这是避免聊天终态与实际交付脱节的基础交付，不要求用户再次请求。Word、PDF、双语稿、视觉简报和外部发布仍需单独确认。

## 最小写作合同

先锁定产物类型、目标读者、使用场景、长度/时限、已授权材料、证据与合规模式、交付格式、人工验收人。材料足够时先给结构和一个可用样段，不以完整问卷阻断首值。

## 稳定模块

1. 决策摘要与适用边界；
2. 议案、选项和 Non-goals；
3. 来源、事实、估计、假设、判断、未知与最强反证；
4. 各席真实意见及回执索引；
5. 质询、修正与保留异议；
6. 建议、成立条件和失效条件；
7. 决策质量六链门禁：框架、替代、信息、取舍、推理、执行承诺；
8. 决策日志：选择、可解析概率、领先指标、触发器、负责人和复审日期；
9. 7/30/90 天行动、责任方向与验收标准；
10. 人工关卡、专业边界、资产包、版本和附件索引。

## 质量门

- S / Style and sentences：开头具体，句式克制，减少冗余、口号、长句和过度转折。
- P / Paragraph progression：每段围绕真实问题推进，有事实、引文、测算或明确证据缺口，不写填充段。
- C / Continuity and closure：各节有明确立场，承接上一节并指向下一决策、行动或来源缺口。
- B / Break-template quality：标题不重复，节奏、标点和结构有变化，避免对称口号与公式化 AI 文风。
- G / Guardrails：事实、法律/财税/金融/安全、版权、用户约束、隐私和未授权外部动作未解决时标 `needs_review`；不得用顺滑文风抹去异议或把沉默写成赞成。
- 专业与完整性：席位归因、术语、计算口径和专业边界准确；主张可回到用户材料、外部核验、真实席位回执或已验证资产包，异议、条件、失效、人工关卡与复审字段齐全。
- 决策质量：逐链检查框架、替代、信息、取舍、推理和执行承诺，显式展示最弱链；不得用平均分掩盖关键短板。
- 决策日志：只对可解析且有截止日的问题记录概率；其他问题记录可观察指标、触发器、负责人和复审日期，不制造伪精确。
- 格式：生成 Word/PDF 后必须预览、检查分页/目录/表格/中文字体，再交用户验收。
- 基础交付：必须先通过 N/N 收齐门，再校验 Markdown 的规范标题、文件位置与 SHA-256；随后在对话中展示可点击文件链接、收齐统计和证据边界。
- 发布：默认只准备草稿。外部发布需逐次确认目标、最终内容哈希、身份和权限，并保留供应商回执。

Word/PDF/图片/视频等由宿主真实能力生成；本 Skill 只提供结构、质量门和回执边界，不冒充媒体生成器。
