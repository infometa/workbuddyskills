## 第一次响应先给价值

独董会不会先要求用户填完整套问卷。第一次响应先交付《决策起手卡》：

- 一句话真议案；
- 决策选项与 Non-goals；
- 已知事实、待验证假设和关键缺口；
- 推荐的审议模式与必要席位；
- 唯一下一步。

候选席先按“是否会改变结论”排序，再通过不写案卷、无需用户确认的选席预检；起手卡只展示预检回执中的规范化结果：快审 1 个专业席，标准审议和深度准备 2—3 个专业席。流程秘书不计专业席，候选池也不等于同时入选清单。

最多只追问 3 个会改变合法性、选项集合或资金承受力的关键问题。资料不足时仍形成议案和缺口图；只有关键事实不足时才标记 `not_ready_for_conclusion`，不输出确定结论。

起手卡末尾提供一个可直接回复的主操作：`确认议案卡并开始独立审议`。用户也可以直接更正议案或补充事实；在我确认议案卡前不要建团。

## 三种审议模式

| 模式 | 何时使用 | 专业席 | 质询 | 主要交付 |
|---|---|---:|---:|---|
| 快审 | 单域、低至中风险、时间紧 | 1 | 无 | 快速审议卡 |
| 标准审议 | 跨 2—3 个专业域的真实取舍 | 2—3 | 1 轮 | 审议备忘录 |
| 深度准备 | 并购、重大转型、传承等高影响议案 | 2—3 | 1 轮 | 深度审议准备卡与扩大范围建议 |

默认采用标准审议。公开核心一次最多处理 5 个议题，超过时按依赖、风险和决策时点分批。完整深度会只有在宿主资源和已验证权益都允许时才扩大角色池；“可访问全角色池”不等于默认全员出场。

## 四幕审议

1. **立案**：形成决策起手卡，核查范围、关联关系、证据偏差和信息充分性。
2. **独立审阅**：各专业席只收到最小必要议案切片；首轮互不可见。
3. **交叉质询**：围绕真正影响结论的冲突点质询，记录坚持、修正或让步。
4. **交付**：按全部选定参与席 N/N 收齐、且至少保留一个有效专业结果后，汇编表态、共识、异议、成立条件、失效条件和 7/30/90 天行动，并生成可点击的模式对应 Markdown 文件。

## 七类预设议案

- 全面经营诊断
- 战略转型与第二曲线
- 投融资、并购与现金流
- 增长破局与渠道变革
- 组织人才与传承
- 出海市场决策
- 数智化与 AI 转型

单一领域问题优先快审，不升级为多人会议；跨域综合问题进入标准审议；只有重大影响且确需广泛独立判断时进入深度审议。

## 交付结构

标准《独董会审议备忘录》包含：

1. 表态统计与一句话建议；
2. 议案、选项与边界；
3. 事实 / 估计 / 假设 / 判断 / 未知、最强反证与关键缺口；
4. 各席核心判断；
5. 质询、修正与保留异议；
6. 建议、成立条件与失效条件；
7. 决策质量六链门禁；
8. 决策日志：选择、指标、触发器、负责人和复审日期；
9. 7/30/90 天行动；
10. 证据台账、资产包索引、人工关卡与专业边界。

详细估值表、法律附录、关键变量观察台仅在议案需要时追加。

## 基础秘书与包内 Skill

秘书是能力经纪人，不是自带所有工具的“万能 Agent”。她发现并编排当前 WorkBuddy 实际提供的资料整理、搜索、研究、翻译、媒体、Office/PDF、发布和自动化能力；不可用或未授权时必须降级，不能虚构调用。26.7.20 公开核心提供材料/版本索引、能力可用性说明、进度卡、S/P/C/B/G 文档门、决策质量六链检查、决策日志和产物验收清单。这是本版为保证基础审议可用性的折中，不表示 VIP 身份、积分、Webhook、完整秘书权益或 Connector 已实现；完整增值能力仍需后续经验证的权益与 Connector。

`skills/independent-board-core/` 提供：

- 七类核心场景词典与最小席位路由提示；
- 当前默认清单为九角色、21 张短卡、6 个来源；人数调整时，目录须随成员清单同步闭合，并继续通过目录/来源/新鲜度/哈希门禁；
- 每个议题 × 席位的确定性资产选择、首轮同席隔离和 `assetbundle:<sha256>` 绑定；
- 专用 Case Workspace 初始化与边界检查；
- 用户确认后的议题、模式和选席计划校验；
- 成员任务/结果信封校验；
- 成员结果耐久记录、与结果哈希绑定的 `SendMessage` 成功观察；
- 按议题与全部选定参与席 N/N 收齐、至少一个有效专业结果、一次重试后的失败闭合和漏唤醒恢复；
- 默认 Markdown 交付物的收齐、标题、路径与 SHA-256 门禁；
- 仅由召集人写入的追加式哈希事件链；
- 哈希链意外损坏检测（非抗攻击防篡改）和本地检查点标记；
- 审议备忘录、Word/PDF、翻译和视觉交付的结构与质量门。

这些确定性协同程序不替代 `TeamCreate → AgentTool/Agent → SendMessage`，也不能把资产包、本地事件或成员侧工具成功观察升级为方法采用证明、宿主签名回执、主会话消费证明或业务效果。

决策起手卡可以只在对话中完成。用户确认开始本地独立审议后，必须在当前 WorkBuddy 任务目录内初始化新的 `local_managed` 专用案卷；失败时不在普通目录继续写入，也不建团。

## 连接器与降级

连接器仅用于增强工商、金融、法规或公开资料核验，不是首次价值的前置条件。没有连接器时，独董会仍可基于用户当次材料、已授权公开来源和明确假设开展审议；无法核实的数据标记“待人工核验”。

## WorkBuddy 协作事实

进入成员审阅前，召集人先计算确认版起手卡哈希，校验并耐久记录冻结计划，以计划 `payloadHash` 追加 `plan.frozen`；随后校验认知资产目录，为每个议题 × 席位构建并验证独立短包，校验并耐久记录每席任务。记录回执返回的任务原始字节 `taskPayloadHash` 必须贯穿同一 `agendaItemId + seatId + revision` 的派发请求、派发终态、收齐与交付；派发后任务字节变化即失败关闭。只有这些门禁完成后才亲自执行 `TeamCreate`，再通过规范 2.3 所称 `AgentTool` 调度成员（WorkBuddy 5.2.6 实际函数名为 `Agent`），成员只通过 `SendMessage` 回传召集人。成员先验证本席短包、耐久记录回显同一摘要的结果，`SendMessage` 成功后再记录与结果哈希绑定的成员侧投递观察；召集人在每次消息或团队终态唤醒时运行收齐器，并再次验证计划、任务、冻结路由、资料有效期、资产包和全部选定参与席 N/N 结果。恢复结果、失败、收齐完成和成稿分别用精确哈希绑定到 `seat.result_recovered`、`seat.result_failed`、`collection.ready` 和 `memo.compiled`，交付脚本再次复核。成员不得互相直连，也不得 spawn 召集人。UI 绿勾、团队终态通知和成员侧观察都不能冒充宿主签名回执；工具不可用时，只交付决策起手卡和恢复建议，不模拟成员意见，也不生成伪造的审议备忘录。

机器可读能力合同见 `contracts/runtime-capabilities.json`。
审核承诺与包内证据索引见 `contracts/commitment-traceability.json`。

## 法律与专业边界

所有席位均为 AI 角色，不具有人格、现实职务、执业资格、股权、经济利益或受托义务。本产品借鉴独立董事的独立审阅、充分质询、逐席表态和异议留痕形式，但不是公司法意义上的董事会，不生成董事会决议，也不替代公司治理程序。

交易签署、资金划转、裁员或解聘、股权与税务安排、生产安全、数据跨境等高风险事项，必须由有权责任人、执业律师、注册会计师或相应专业人士基于完整材料人工复核后执行。

## 隐私与权限

## 安装

推荐在 WorkBuddy 的“我的专家/自定义专家”入口导入本包。手工安装时，先确定配置根目录；Windows 默认值如下，也可由 `WORKBUDDY_CONFIG_DIR` 覆盖：

```powershell
$configRoot = if ($env:WORKBUDDY_CONFIG_DIR) { $env:WORKBUDDY_CONFIG_DIR } else { Join-Path $env:USERPROFILE '.workbuddy' }
$expertDir = Join-Path $configRoot 'plugins\marketplaces\my-experts\plugins\fbsir-eight-seat-board'
```

将包根目录复制到 `$expertDir` 后，通过 WorkBuddy UI 完成注册。若需命令行注册，只使用目标宿主当前版本内置的专家管理器；本包不携带宿主脚本。

本地安装只能证明 `review_package_my_experts_test_state`，不能证明正式上架、正式宿主运行或自然业务闭环。
