# PPT 设计规范（Design System）

本规范用于统一 consulting-partners 团队所有 PPT 交付物的视觉语言，避免"一眼假"的 AI 生成感——配色随意、字号混乱、图表和数据不匹配。所有规则由交付设计师（deck-designer）在生成每一页时应用，脚本 `build_deck.py` 已内置这套常量。

## 配色体系

| 名称 | Hex | 用途 |
|------|-----|------|
| 深蓝 NAVY | #0B2A4A | 标题、封面背景、强调框边线 |
| 白 WHITE | #FFFFFF | 深色背景上的文字、留白区域 |
| 深灰 DARK_GRAY | #333333 | 正文文字 |
| 中灰 MED_GRAY | #6E6E6E | 次要文字、脚注、来源标注 |
| 强调金 ACCENT | #C88A2E | 洞察框标题、关键数字高亮，克制使用，不做主色 |
| 浅背景 BG_LIGHT | #F4F4F2 | 洞察框、卡片背景 |

**使用原则**：一页幻灯片最多出现三种颜色（背景色 + 文字色 + 一个强调色），避免彩虹式配色。深色背景必须搭配白色或高对比度文字，绝不允许深蓝背景配深灰文字这种低对比度组合。

## 字号层级

| 用途 | 字号 |
|------|------|
| 封面标题 | 40pt |
| 页面标题 | 26pt |
| 副标题/小节标题 | 16pt |
| 正文 | 14pt |
| 脚注/来源 | 9pt |

字号层级只用这五档，不要随意插入中间值，保证全篇视觉节奏统一。

## 版式目录

| 版式 | 适用场景 |
|------|---------|
| 标题居中型（cover） | 封面页、章节分隔页 |
| 项目符号型（bullet） | 执行摘要、结论罗列、行动清单 |
| 单图表型（chart_bar） | 数据趋势展示，配右侧洞察框 |
| 左右分栏型（two_column） | 方案对比、优劣势对照、前后对比 |

版式选择原则：先确定这一页要传达的核心论点，再选择能最有效呈现这个论点的版式，不要为了视觉多样性随意切换版式类型。

## 图表选型纪律

| 数据特征 | 图表类型 |
|---------|---------|
| 随时间变化的趋势 | 折线图 |
| 分类之间的规模对比 | 柱状图/条形图 |
| 占比结构（且分类不超过5个） | 饼图/环形图 |
| 从起点到终点的增量归因 | 瀑布图 |
| 两个维度的定位分布 | 散点图/矩阵图 |
| 问题的层级分解 | 树状图/议题树图 |

**红线**：图表必须由真实数据驱动。如果某一页找不到真实数据支撑图表，宁可换成对比表格或直接用文字论述，绝不能编造数据凑一张"看起来专业"的图。

## 信息密度

- 每页正文文字不超过 6 条要点，每条不超过 2 行
- 图表页的洞察框文字控制在 80 字以内，只讲"所以呢"，不重复图表已经显示的数字
- 宁可拆成两页，也不要把一页塞得过满导致字号被迫缩小到难以阅读

## 页面自检清单（每页生成后执行）

- [ ] 版式与规划的骨架一致
- [ ] 图表类型匹配数据结构
- [ ] 所有数字来自真实分析结果，不是占位符
- [ ] 颜色对比度足够，尤其深色背景配文字
- [ ] 信息密度合适，没有堆砌或过度留白
- [ ] 与前面页面的配色、字号保持统一
