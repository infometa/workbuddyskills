# 撰写：决策备忘录与研究报告

把分析结论变成能让决策者看完就能拍板的文字——不是信息的搬运工，是结论的压缩机。

## 核心方法

### 1. 决策备忘录

一页纸、约400字内，强制读者能在这一页上做出yes/no决定。四个不可妥协的标准：
- **极致简短**：每句话都要挣得它的位置
- **SCP故事线清晰**：现状→矛盾→方案，读者永远不会问"所以呢"
- **决策强制**：结尾是明确的决策请求（谁批、何时批），绝不是"进一步讨论"
- **证据密度**：每个论断都有数字或来源支撑，不靠形容词撑场面

**格式**：

```markdown
# {决策标题，≤10字，命名的是决定不是话题}

**现状**（3-4句）：决策前的世界是什么样，只讲事实和基线数字。
**矛盾**（2-3句）：发生了什么变化，或不决定会有什么风险，要有让人紧迫的数字。
**选项**（2-3个，各1-2句）：互斥选项，每个含最重要的取舍。不要在这里偷偷塞进推荐。
**推荐**：选定哪个选项，为什么在决策标准上胜出，引用最关键的证据。
**风险与缓解**（≤3条）：读者真正会问的三个风险，各配一句缓解方案。
**请求**（1句）：谁在何时前批准，谁负责下一步。
```

### 2. 金字塔原理结构化

结论先行，向下用最多3条支撑论据展开，论据本身互斥穷尽（MECE），不需要读者按顺序读完才能get到重点。

### 3. 行业/市场研究报告

采用"框架生成→报告撰写"两阶段写法：
1. 先产出章节骨架（每章有分析目标、分析逻辑、核心假设、数据需求）
2. 数据到位后再写正文，每个子章节遵循"可视锚点（图表/表格）→数据对比→综合分析"的节奏
3. 每个子章节收尾要有一段至少200字的分析段，把数据背后的用户心理和战略含义讲清楚，不是简单复述数字

**格式**：

```markdown
# {研究主题}分析报告

## 摘要
[3-5条关键发现，执行摘要形式]

## 一、引言
[背景、研究目标、方法说明]

## 二～N、[各章节，按框架骨架展开]
### 2.1 [子章节标题]
[图表/对比表]
[数据对比]
[综合分析段，至少200字，遵循"数据→心理/行为→战略含义"链条]

## N+1、结论
[纯叙事，不用列表，客观综合，不重复给具体建议——建议已经在各章正文里]

## N+2、参考来源
[数据来源列表]
```

### 4. 六段输出合约

任何完整分析产出必须包含以下六个部分，缺一不可：

1. **结论（Bottom Line）**：一句话，明确方向或决定
2. **支撑论据（最多3条）**：各标注证据等级
3. **风险（至少2条）**：各配缓解方案
4. **反转条件（Kill Conditions，至少2条）**：什么数据点出现会推翻推荐
5. **下一步行动（至少2条）**：各有负责人、截止时间、验证指标
6. **未决问题**：还不知道什么，怎么去补足

漏掉风险、反转条件或下一步行动任何一项都是不完整的，不能以"这个case比较简单"为理由跳过。详细的六段合约说明和反模式清单见 `references/output-contract.md`。

## 工作流程

1. **确认写作目的**：读者是谁、这份文字要驱动什么决定、截止时间
2. **整合上游分析**：假设树结论、证据分析、测算结果，不重复分析，只做结构化压缩和叙事组织
3. **确定文体**：决策备忘录还是行业研究报告
4. **草拟正文**：备忘录按"标题→现状→矛盾→选项→推荐→风险→请求"顺序；报告按章节骨架逐章写
5. **执行六段合约自检**：逐项核对是否齐全
6. **删减30%**：初稿总是太长，删掉修饰词、模糊限定语（"可能"、"或许"）、不承担论证功能的过渡句

## 注意事项

- 备忘录里的"选项"部分绝不能藏着推荐，选项要真的中立列出取舍
- 禁止"进一步分析后续讨论"式的软收尾，最后一句必须是可以直接执行的请求
- 研究报告的结论章节不放具体建议，建议应该已经分布在各正文章节
- 数字千分位统一用英文逗号，专业术语保留业界通用英文缩写（TAM、CAC、IRR等）不强行翻译
