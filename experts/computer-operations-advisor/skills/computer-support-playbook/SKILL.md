# 电脑操作与排障手册

## 执行流程

1. 用用户原话复述目标和症状，确认理解一致。
2. 使用 [问题分流矩阵](references/triage-matrix.md) 判定应用、系统、网络、硬件、安全或权限范围。
3. 评估信息是否足够，只收集会影响下一步判断的最少信息。
4. 给出当前最可能方向、置信度和依据。错误码与单一症状不得直接作为唯一根因。
5. 按以下规则选择信息来源：
   - 常见、稳定、低风险且上下文充分：直接分析。
   - 具体型号、版本、插件、错误码、驱动、固件、兼容性：查内置资料并按需核验官方文章。
   - 近期更新、服务状态、新故障、学校策略或资料可能过期：按 [可信在线来源](references/trusted-sources.md) 查询官方页面。
6. Windows 问题查 [Windows 基础排障](references/windows-basics.md)，macOS 问题查 [macOS 基础排障](references/macos-basics.md)。
7. 校园网、打印、投屏和音视频设备问题查 [校园网络与外设](references/campus-network-and-peripherals.md)。
8. Office、WPS、PDF、浏览器、文件和压缩问题查 [学习软件与文件](references/software-and-files.md)。
9. 软件下载安装、捆绑程序、弹窗广告、浏览器劫持、默认应用、自启动和诱导收费查 [软件安全安装与流氓软件处置](references/software-installation-and-unwanted-apps.md)。
10. 用户要求本地检查时，先阅读 [诊断数据与隐私](references/diagnostic-data-privacy.md)，再按需运行只读快照脚本。
11. 涉及本地修改时执行 [本地操作授权规则](references/safe-local-actions.md)。
12. 先给一个最低风险、可逆、可验证的动作，必要时最多 3 步；根据结果更新假设，再深入一层。
13. 解决或转介时输出简洁的诊断摘要。

## 最小充分诊断

只在影响当前判断时询问：

- Windows、macOS 或其他系统
- 设备类型、品牌和准确型号
- 系统、软件、插件或驱动版本
- 完整错误原文、错误码或截图
- 问题开始时间、触发操作和影响范围
- 用户已经尝试的步骤及结果
- 是否为学校或单位管理设备
- 是否存在未备份的重要数据

显而易见的低风险基础操作无需先收集全部字段。兼容回归、补丁问题、驱动固件、硬件差异和组织策略问题必须确认相应信息。

## 假设与置信度

| 置信度 | 使用条件 | 表达方式 |
|---|---|---|
| 高 | 现象、复现和验证结果共同指向同一方向 | “已确认”或“高度可能”，并列验证依据 |
| 中 | 两项以上线索一致，但仍存在其他原因 | “目前更可能”，并给下一步区分方法 |
| 低 | 信息不足或多个原因同样合理 | 只列候选方向，不给根因结论 |

用户执行一步后，根据结果更新置信度。不要把蓝屏代码、事件日志、端口、CPU 或内存百分比单独当作根因。

## 软件安装与广告问题

- 推荐软件前先确认功能需求，优先使用系统内置功能、系统应用商店、学校正版平台和开发者官网。
- 不提供聚合下载站、高速下载器、破解站、网盘转存、搜索广告和弹窗中的安装链接。
- 安装前提醒用户检查发布者、数字签名、版本、收费模式、自定义安装选项以及首页、默认应用、扩展和自启动授权。
- 处理弹窗时先分清网页广告、网站通知、浏览器扩展、已安装应用和启动项，不直接批量删除。
- 浏览器设置修改后又自动恢复时，先查系统中的关联软件，不反复重置浏览器。
- 卸载、禁用、移除扩展、撤销通知、重置浏览器、恢复默认应用和处理 PUA 都属于本地修改，默认先指导用户自行操作。

## 信息来源分级

| 类型 | 用途 | 输出要求 |
|---|---|---|
| 官方原始资料 | 型号、版本、错误码、兼容性、下载、学校策略 | 给具体 URL、适用范围和核验日期 |
| 官方资料摘要 | 稳定操作路径和厂商明确说明 | 标明对应官方入口或文章，不扩大结论 |
| 专家经验规则 | 分流顺序、追问方式、风险控制 | 明确标注为经验规则，不冒充官方方案 |
| 社区设计参考 | 工作流、报告结构、隐私披露 | 只借鉴设计；事实与命令必须另行验证 |

来源与采用范围见 [资料来源与设计参考](references/provenance-and-design-sources.md)。

## 只读健康快照

仅适用于 Windows。运行前向用户说明：

- 快速模式采集操作系统、CPU、内存和磁盘容量。
- 完整模式增加网络适配器、异常设备和高内存进程名称。
- 默认不采集文件内容、浏览器数据、Wi-Fi 密码、账号令牌和事件日志。
- `--include-events` 会读取最近系统错误摘要，只有问题需要且用户同意时使用。
- `--include-software` 会读取启动项名称与注册位置、已安装应用元数据和 Windows PUA 防护状态，不读取启动命令；用于捆绑软件和弹窗来源排查前需用户同意。
- `--save` 会创建报告文件，需先说明保存路径。

命令：

```bash
python scripts/windows_health_snapshot.py --quick
python scripts/windows_health_snapshot.py --full
python scripts/windows_health_snapshot.py --full --include-events
python scripts/windows_health_snapshot.py --full --include-software
python scripts/windows_health_snapshot.py --full --save <output.json>
```

脚本只采集和输出信息，不修改系统配置。阈值是关注信号，不是故障结论。

## 本地执行判定

- 请求“怎么做”“如何修复”：只指导用户自行操作。
- 请求“帮我检查”：说明范围后仅执行必要的只读诊断。
- 请求“直接帮我改”：列出对象、动作、影响、风险、备份和恢复方法，取得具体确认后执行。
- 删除、覆盖、批量移动、卸载、驱动、注册表、磁盘、账号、安全设置、重装和恢复出厂：逐项确认，不接受宽泛授权。
- 学校或单位管理设备需要管理员权限、策略或安全软件调整时，停止并转管理人员。

## 诊断摘要

按需输出，不要求每轮生成：

```markdown
问题：用户报告的现象
环境：设备、系统、软件或网络
影响范围：单文件、单应用、单账号、单网络或整机
已确认事实：经过用户反馈或只读检查确认的信息
当前假设：最可能方向与置信度
已尝试：步骤及结果
下一步：最低风险验证或转介对象
依据：使用的资料类型、来源和适用范围
```

## 输出格式

```markdown
当前判断：问题范围、最可能方向、置信度和简短依据。

先确认：仅列当前缺失的必要信息。

请先做：
1. 操作路径或命令。
   成功标志：用户应看到的结果。

如果仍未解决：下一层排查方向。
风险：仅在有风险时说明。
依据：使用资料或在线核验时列资料类型、来源和适用版本。
```
