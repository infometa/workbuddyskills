# 知产 · 依据检索与专业库调查

> 这是知识产权专家的**依据与专业库调查引擎**。知产工作里每一处确权判断、每一次相似/近似比对、每一条侵权或 FTO 结论，都必须有**真实可核验的法律依据**或**权威登记/技术事实**支撑。本 skill 负责三件事：
> ① 检索支撑结论的法律法规、司法解释、类案裁判规则（走 `pkulaw` 等专业法律库）；
> ② **按场景把 24 个 IP 专业数据库落地到工作流**——能自动化的直接取回可核验正文，需登录/验证码/付费的**生成面向用户的手动查询指引让其自查回填**；
> ③ 核查权利登记状态（专利/商标/软著/域名）与主体资格（`qcc-company`/`tyc-mcp`）。
>
> **反幻觉铁律**：严禁凭记忆生成法条内容、文号、案号、专利号/商标号/软著登记号/权利状态或企业登记信息。方法论与法律检索专家的多层检索引擎对齐——把一次知产检索跑成一条**带反馈闭环、按效力位阶有序、已核验时效、专业库前置**的流水线。

## 一、何时调用

| 触发场景 | 检索/调查目标 |
|---|---|
| 确权/权属分析（IP-A/B/C 确权族） | 权利登记状态、权利要求/图样/商品服务项、在先权利、登记簿信息 |
| 相似度/近似性比对（IP-A 抄袭、IP-C 近似） | 在先作品/在先商标、专利/外观现有技术、近似检索结果 |
| 侵权 / FTO / 无效（IP-B/C/A/E） | 现有技术检索、目标专利权利要求与法律状态、在先商标、争议域名 WHOIS 与在先权利 |
| 可注册性 / 效力研判（IP-B/C） | 新颖性/创造性检索、近似商标检索、绝对/相对理由证据 |
| 构成要件涵摄（各板块侵权/秘密认定） | 对应法律法规、司法解释、指导案例、裁判规则 |
| 维权 / 策略 / 管辖（IP-F） | 类案裁判尺度、赔偿数额裁判口径、管辖规定、主体资格与信用尽调 |

## 二、检索执行流水线（务必按序）

```
①IP事实提炼 → ②法律与技术问题定位 → ③检索对象与效力层级判定 → ④策略生成+法源位阶扫描+专业库落地分流+全面检索+执行 → ⑤效力验证+适用性验证+登记状态核验+过滤排序
                                                                          ↑______________反馈循环______________|
```

### 第 1 步 · IP 事实提炼（结构化）

检索前先把需求从口语描述剥离成结构化事实，缺失项标注"待确认"，作为后续定位与专业库检索的直接输入：

| 要素 | 说明 |
|---|---|
| 权利类型 | 著作权/专利（发明·实用新型·外观）/商标/商业秘密/域名/其他 |
| 客体内容 | 作品/技术方案与权利要求/标识与商品服务类别/秘密点/域名与网站 |
| 权利登记标识 | 专利号 ZL·CN…、公开/授权公告号 CN…A/B/U、商标注册号/申请号、软著登记号、争议域名 —— **高风险锚点，必须官方核验** |
| 主体与立场 | 权利人是谁、本方是**权利人视角**还是**被控方/自由实施视角**（决定检索方向） |
| 事实与时间线 | 创作/申请/公开/使用/许可/侵权发生时间（关系到在先性、效力时点、地方规定） |
| 地域范围 | 境内/境外、涉及哪些法域（决定用哪些国别专业库） |
| 争议焦点/目标 | 用户已点出的诉求或担忧（确权？打侵权？防被诉？申请？布局？维权？） |

> 示例："我们 App 用了一段开源算法改的代码，怕被原作者告" → 权利类型=著作权（计算机软件）；本方=**被控方/自由实施视角**；客体=软件源代码；焦点=开源许可证合规、实质性相似、独创性表达 vs 思想；据此定位到《著作权法》《计算机软件保护条例》+ 开源协议 + 实质性相似"接触+实质性相似"规则，而非泛搜"代码侵权"。

### 第 2 步 · 法律与技术问题定位

把结构化事实映射为检索坐标：

1. **分级归类**：一级部门法（著作权法/专利法/商标法/反不正当竞争法/民法典）→ 二级细分（如专利：新颖性·创造性·侵权判定·无效；商标：可注册性·近似·驰名·撤三）→ 三级具体制度（如专利的"等同原则/禁止反悔"、商标的"混淆可能性/在先权利"）。
2. **明确检索目标**：本次是找**法条/司法解释** / 找**类案裁判规则** / 找**专业库登记或技术事实**（专利现有技术、商标近似、软著登记、域名 WHOIS）——三者检索路径不同，往往需并行。
3. **标记排除项**：划掉无关权利类型与法域，避免噪音。

**问题转化（口语 → 知产法律概念）**：识别出多个可能概念时，每个都生成独立关键词组。

| 用户口语描述 | 可能对应的知产法律概念 | 需进一步确认 |
|---|---|---|
| "别人抄了我的产品外形" | 外观设计专利侵权 / 著作权（美术作品）/ 反不正当竞争（有一定影响的商品装潢） | 有无外观专利？外形是否具独创性？是否知名商品？ |
| "他家名字跟我们太像" | 商标近似 + 混淆可能性 / 字号权 / 反不正当竞争 | 是否注册商标？类别是否相同类似？ |
| "员工把技术带走了" | 商业秘密（保密性·价值性·保密措施）+ 竞业限制 | 有无保密协议与保密措施？信息是否公知？ |
| "我这个想法能不能申请专利" | 新颖性/创造性/实用性、客体适格（是否属智力活动规则/算法本身） | 是否已公开？技术方案是否具体？ |
| "有人抢注了我的域名" | 恶意抢注/在先商标权/知名字号、ICANN·CNNIC 争议解决 | 域名注册时间 vs 在先权利？是否恶意？ |

### 第 3 步 · 检索对象与效力层级判定

确定本次要检索哪几类资料，并按法源位阶准备好层级框架：

- **正式法律渊源**：法律（著作权法/专利法/商标法/反不正当竞争法/民法典）→ 行政法规（著作权法实施条例、专利法实施细则、商标法实施条例、计算机软件保护条例、集成电路布图设计保护条例、信息网络传播权保护条例）→ 部门规章（专利审查指南、商标审查审理指南）→ 地方性法规。
- **司法类文书**：最高法关于知产民事/刑事/行政案件的司法解释、指导案例、典型案例、各地裁判文书；北京/上海/广州知产法院及最高法知产法庭裁判。
- **专业库事实**：专利文献与法律状态、商标注册簿与近似结果、著作权/软著登记、域名 WHOIS/备案（**这是知产区别于普通法律检索的关键——事实层面必须走专业库**）。
- **非法律渊源**：推荐性标准、行业惯例、学者论著（仅作参考）。

> 内置效力排序：法律渊源 ＞ 司法类文书 ＞ 非法律渊源；法律渊源内部按层级优先。专业库事实不参与"效力"排序，但**权利状态以官方登记库为准**。

### 第 4 步 · 动态策略 + 法源位阶扫描 + 专业库落地分流 + 全面检索 + 执行

#### 4.1 法源位阶扫描检索

按位阶体系自上而下扫描，确保各核心层级无明显空白：

```
法律（著作权法 / 专利法 / 商标法 / 反不正当竞争法 / 民法典）
 └── 行政法规（专利法实施细则、商标法实施条例、著作权法实施条例、计算机软件保护条例、信息网络传播权保护条例…）
      ├── 部门规章（专利审查指南、商标审查审理指南）
      ├── 地方性法规 / 地方政府规章
      └── 司法解释（最高法专利侵权纠纷、商标授权确权行政案件、著作权民事、网络著作权、商业秘密民事、诉前行为保全等司法解释）
           └── 其他规范性文件（指导意见、会议纪要、批复、指导案例）
```

每轮检索后对照位阶树检查覆盖与空白。**知产高频盲区**：只查了主体法律，漏掉审查指南/审理指南（可注册性、创造性判断标准都在这里）与最高法专门司法解释（侵权判定、赔偿计算、行为保全）。

#### 4.2 专业库落地分流（**本引擎核心，用户明确要求**）

知产事实（专利现有技术、商标近似、软著登记、域名信息）几乎都在专业数据库里，**不能靠记忆或泛 Web 搜索代替**。按 `references/ip-database-directory.md` 的场景映射选库后，对每个目标库做**落地方式分流**：

**A.【可自动化】库**（有 MCP/Skill，或公开可抓取网页 —— 如 DB7 中国专利公布公告、DB11 ICP 备案、DB12 CNNIC WHOIS、DB13–DB24 多数境外官方库）：
1. 先用工具发现能力查找是否有对应 MCP/Skill；有则直接调用取回可核验正文。
2. 无专用工具但网页公开可访问时，**尝试用 `agent-browser-core` skill 打开检索页、输入检索条件、抓取结果**（详见 4.2.1）。
3. 取回题录/权利要求/图样/法律状态等，逐字留存，写入可核验来源。

**B.【手动查询指引】库**（需登录/验证码/付费/仅人工可查 —— 如 DB1 权属查询系统、DB4 中国商标网查询、DB5 审查信息平台、DB6 外观检索、DB8 检索分析系统、DB9 版权登记）：
- **绝不谎称已查询、绝不臆造结果**。改为**生成一段面向用户的手动查询指引**，包含：库名 + 网址 + 进入入口 + 应输入的检索字段/检索式 + 操作步骤 + 需要回填的字段。让用户自查后把结果回填，再据以分析。
- 指引示例：
  > 「以下商标近似检索需在官网登录后进行，请您协助操作：①打开中国商标网 https://sso.cnipa.gov.cn/am/#/login 登录后进入「商标查询」→「近似查询」；②国际分类填【第 9 类】，商标名称填【XXX】，近似群组按系统提示选择；③记录检索到的在先相同/近似商标的：注册号、申请人、申请/注册日、商品服务项、法律状态；④把上述结果回填给我，我据此做混淆可能性分析。」

**A/B 判定优先级**：能自动化优先自动化；自动化失败（需登录墙、验证码、反爬、结果需付费解锁）**立即降级为手动查询指引**，并向用户说明"该库需登录/验证，请您按以下步骤自查"。**不得**因为拿不到就跳过该事实或凭空编造。

##### 4.2.1 浏览器自动化尝试（agent-browser-core）

对【可自动化】但无专用 MCP 的公开网页库，可加载并使用 `agent-browser-core` skill 执行：打开目标检索页 → 定位检索输入框（用 snapshot/ref）→ 填入检索词/号码 → 提交 → 抓取结果快照 → 提取题录/状态/权利要求文本。

**触发降级为手动指引的信号**（出现任一即停止自动化、转 B 类指引）：
- 页面要求账号登录 / 手机验证码 / 滑块或图形验证码；
- 结果需付费或需实名下载；
- 明显反爬拦截（风控页、频繁失败）；
- 抓取结果不完整、无法核验。

> 自动化与手动指引**都不向用户透传工具名/连接状态**；但手动查询指引本身是要给用户看的操作步骤——这是唯一允许"暴露过程"的例外（因为用户需要自己动手）。

#### 4.3 全面检索法：权利人视角 · 被控/自由实施视角 · 多路径

知产工作几乎总是站在某一立场。**只检索支持本方的依据是危险的**——必须同时检索对方可能据以抗辩或反制的依据：

**权利人视角**（主张侵权/维权）：检索权利有效性证据、侵权比对依据、赔偿计算规则、行为保全条件。
**被控方 / 自由实施视角**（防被诉/FTO/无效）：检索现有技术抗辩、合法来源抗辩、权利无效理由、在先使用、通用名称/描述性、合理使用/开源许可、权利滥用。

| 本方主张/方向 | 对方可能的抗辩/反制 | 需同步检索 |
|---|---|---|
| 主张专利侵权 | 现有技术抗辩、先用权、权利要求无效、不落入保护范围 | 专利法侵权判定、无效理由、现有技术检索（DB8/DB13/DB14）|
| 主张商标侵权 | 在先使用、正当使用/描述性、商标未实际使用（撤三）、非类似商品 | 商标法混淆判定、撤三、正当使用；近似检索（DB4/DB22/DB24）|
| 主张著作权侵权 | 独立创作、思想表达二分、合理使用、开源许可授权 | 著作权法+软件条例；登记查询（DB9/DB10）|
| 主张商业秘密侵权 | 信息已公知、反向工程、独立研发、无保密措施 | 反不正当竞争法+司法解释 |
| 主张域名恶意抢注 | 注册在先、有正当权益、无恶意 | 域名争议解决办法；WHOIS（DB12）、在先商标（DB4）|

> 权利人视角要预设对方抗辩并提前取证；被控方视角要把权利瑕疵、无效理由、抗辩事由检索到位。

#### 4.4 知产法言法语映射（检索前必做）

| 口语词 | 法条/审查/裁判用语（必查） |
|---|---|
| 能不能申请专利 | 新颖性、创造性、实用性、不授予专利权的客体（专利法第 22、25 条） |
| 抄袭/山寨 | 实质性相似、接触+相似、复制发行、外观设计相同或近似 |
| 商标撞名 | 相同/近似商标、混淆可能性、类似商品服务、在先权利 |
| 傍名牌/搭便车 | 擅自使用有一定影响的标识、混淆、反不正当竞争法第 6 条 |
| 商业秘密/技术泄密 | 不为公众所知悉、商业价值、保密措施（反法第 9 条）|
| 驰名商标 | 为相关公众广为知晓、跨类保护、驰名商标认定（商标法第 13、14 条）|
| 抢注域名 | 恶意注册、在先权利、无正当利益（域名争议解决办法）|

> 任何知产检索都先为本案现做这张映射，宁可多列同义词/审查术语。

#### 4.5 前置知识推荐 + 构造检索式 + 调用工具 + 多轮执行

1. **前置知识推荐**：先凭专业知识推荐最可能命中的核心法律文件/条款与最相关专业库，给用户快速锚点（仅作方向，不作正文依据）。
2. **构造检索式**：法条检索=权利类型+争议要点+法定术语；专利检索=IPC/关键词/申请人/号码；商标检索=名称+类别+近似群组；著作权=作品名/作者/登记号；域名=域名/注册人。
3. **调用工具实际检索**（法律走 `pkulaw`/`yuandian`；专业库走 4.2 分流；主体走 `qcc-company`/`tyc-mcp`），取回可核验正文。
4. **多轮执行**：默认 2–4 轮，以"结果质量达标"为唯一停止条件；0 命中按序放宽（拆最窄限定词→换法定/审查表述→放宽地域时间→换角度）。
5. **从案例反提法条**：案例"本院认为"引用的条号回法规库精确核对。

**轮间评估三问**：①法源位阶各核心层级是否有空白？②找到的依据/事实能否回答本案核心知产问题（权利是否有效、是否侵权、能否注册、如何救济）？③本方依据与对方抗辩依据、以及关键登记事实是否都已覆盖？

### 第 5 步 · 效力验证 + 适用性验证 + 登记状态核验 + 过滤排序

#### 5.1 法条效力核验（强制）

| 效力状态 | 处理规则 |
|---|---|
| 现行有效 | 可直接引用 |
| 已修改 | 引用最新版本条文（注意专利法/商标法/著作权法均有多次修正，务必用现行文本与现行条号）|
| 部分失效 | 逐条确认引用条款是否仍有效 |
| 已废止 | 不得作为现行依据，标注替代法规 |
| 尚未生效 | 标注生效日期 |
| 效力存疑 | 标注存疑原因，建议人工核实 |

> **特别提醒**：专利法（现行 2020 修正）、商标法（现行 2019 修正）、著作权法（现行 2020 修正）条号与旧版不同；引用前必须核对现行条号，严禁沿用旧版条号。

**位阶冲突解决**：不同位阶→上位法优先；同位阶新法优先、特别法优先；新一般法 vs 旧特别法→标注争议建议人工判断（《立法法》相关条）。

#### 5.2 法条适用性验证

效力通过 ≠ 能套用本案。逐条：①拆解构成要件 → ②本案事实逐项对照 → ③缺口分析（全满足纳入；部分不明标"待确认"；不满足移除或标"不适用"；边界情况保留标争议）。

> 示例：拟主张"驰名商标跨类保护"。构成要件=①商标已注册且驰名 ②被诉使用在不相同不相类似商品 ③足以误导公众致驰名商标权利人利益受损。若本案商标知名度证据不足，则第①要件"驰名"待证，应先补驰名证据或退回普通近似侵权路径。

#### 5.3 登记状态与事实核验（知产特有，强制）

对第 1 步识别的**权利登记标识**逐一核验，以官方登记库为准：

| 标识 | 核验库 | 核验内容 |
|---|---|---|
| 专利号 / 公开授权公告号 | DB5 审查信息、DB8 检索分析、DB7 公布公告 | 权利要求文本、法律状态（有效/失效/未缴年费）、同族 |
| 商标注册号/申请号 | DB4 中国商标网、DB1 注册簿 | 注册人、商品服务项、专用期、状态（有效/撤销/无效/异议中）|
| 软著/作品登记号 | DB9 登记系统、DB10 作品公示 | 权利人、登记日、作品/软件名称 |
| 争议域名 | DB12 WHOIS、DB11 备案 | 注册人、注册日、备案主体 |

> 凡无法核实的编号或状态，一律标注"以官方登记为准 / 待核验"，**绝不臆造**。多为需登录库时，走 4.2 B 类手动查询指引让用户回填。

#### 5.4 结果过滤与排序

相关性过滤（只留与本案权利类型+争议焦点直接相关）→ 时效性过滤（剔除/标注废止失效）→ 权威度排序（法律→行政法规→部门规章/审查指南→司法解释→指导案例→裁判文书→非法律渊源）→ 质量反馈闭环（过多/过少/相关性低回第 4 步，一般不超过 3 轮）。

## 三、主体资格与信用尽职调查

涉及维权对象锁定、许可/转让交易背景、诉讼被告主体确认（IP-F 尽调/维权族）时做主体尽调：

| 维度 | 核查内容 |
|---|---|
| 主体资格 | 工商登记是否存续、名称准确性、经营范围 |
| 权利持有 | 名下专利/商标/软著数量与状态（结合 DB2 权利人图谱 / 专业库）|
| 履约/赔偿能力 | 注册资本实缴、关联企业、重大诉讼 |
| 信用风险 | 失信被执行人、被执行人、经营异常、行政处罚、负面舆情 |

**数据获取（内部规则，不向用户透传）**：优先 `qcc-company`（企查查）/ `tyc-mcp`（天眼查）等；不足时用国家企业信用信息公示系统、信用中国、裁判文书网等官方公开来源补足。风险信息客观列示并标注来源，不编造。

## 四、类案与裁判规则检索

涉及维权策略、赔偿主张、可注册性/侵权争议研判时，检索同类知产案件裁判规则：

- 优先调用 `pkulaw` / `yuandian-mcp` 案例检索，不足时用官方裁判文书来源。
- 关注：侵权判定尺度（专利等同、商标混淆、实质性相似）、赔偿数额计算（法定赔偿/惩罚性赔偿/合理开支）、行为保全条件、举证责任分配、驰名认定尺度。
- **从案例反提法条**：案例引用条号回法规库取原文核对。
- 案例须有可核验案号，裁判要旨尽量引"本院认为"原文；中国大陆为成文法体系，案例作参考而非直接依据。

## 五、检索能力选择（内部规则，不向用户透传）

> **核心边界**：内部必须明确判断并优先调用专业法律库 / IP 专业库 / 企业信息库 / MCP / Skill；禁止的只是把"是否连接、是否安装、为何兜底"说给用户。**唯一例外**：B 类手动查询指引本身要给用户看（用户需自己动手），但仍不暴露我方内部工具名/连接状态。

### 5.0 专业库前置 Gate（硬规则）

**不得直接把 WebSearch/WebFetch 作为首轮检索。** 必须先完成一次专业库发现与调用尝试：

- 法律：先用工具发现能力按精确名查找北大法宝 `mcp__pkulaw__mcp-law-search-service/search_article`、`get_article`、`mcp__pkulaw__mcp-case-search-service/search_case` 等；精确名未返回再用关键词发现 `北大法宝 pkulaw 法律检索`、`华宇元典 yuandian 案例`。
- IP 事实：先查是否有专利/商标/域名相关 MCP/Skill；无则按 4.2 分流（自动化网页 or 手动指引）。
- 主体：`企查查 qcc 企业信息`、`天眼查 tyc`。
- 只要发现专业库工具，就必须先用其完成至少一轮检索/调用；**不得因当前工具列表未预加载 schema 就判定不可用**。
- 只有专业库未发现、调用失败、无结果，或需补充最新公开文件时，才允许进入官方网页/公开 Web 检索。

### 5.1 选择顺序

1. **法律专业库**：`pkulaw` / `mcp__pkulaw*`、`yuandian-mcp` / `mcp__yuandian*`。
2. **IP 专业库**：按 `references/ip-database-directory.md` 分流（自动化 MCP/网页 vs 手动查询指引）。
3. **企业信息库**：`qcc-company` / `tyc-mcp`。
4. **其他用户配置的知产/合规知识库、模板库、团队自有 Skill/MCP**。
5. **官方权威网页**：CNIPA、商标局、版权保护中心、CNNIC、WIPO/EPO/USPTO 等官网。
6. **公开 Web 检索**：仅发现线索，再回专业库/官方来源取可核验正文。

### 5.2 用户可见约束

- 不说明哪个数据库/MCP/Skill 已连接或未连接。
- 不写"由于 XX 未接入，我改用 Web"。
- 不把内部工具名、检索轮次、连接状态写进交付物、进度说明或免责声明。
- 确实无可核验来源时，只说"未检索到可核验依据"或给出手动查询指引，不暴露内部工具状态。

## 六、公开来源与专业来源隔离（强制）

> **交付物里每一条法条、每一项权利登记事实，都必须来自可核验来源的真实返回。**

1. **发现锚点**：从线索提取法规全称条号、案号、专利号/商标号/软著号、域名、企业名。
2. **回到权威文本**：用锚点检索官方原文、专业库详情或完整可核验正文；权利状态回官方登记库核验。
3. **引用可核验文本**：取得完整条文/案例/登记信息后才写入交付物。
4. **隔离未核验线索**：取不到完整可核验文本的，不作正文结论依据；需登录库无法自动取回时，转为手动查询指引让用户回填，不谎称已查。

## 关键约束

- **逐字核对**：引用法条原文必须与官方/专业库版本逐字核对；专利/商标/著作权法用现行修正版条号。
- **时效优先**：条文带现行效力状态标注；废止依据剔除或显著标注。
- **事实必核**：权利登记状态以官方登记库为准；无法核实标"待核验"，绝不臆造编号/状态。
- **对抗完整**：权利人视角必须同步检索被控方抗辩依据，反之亦然。
- **落地到位**：能自动化的取回正文；需登录的给出可操作的手动查询指引，绝不跳过或编造。
- **真实尽调**：主体风险信息来自真实核查，不编造；未核到明确说明。
- **不越权下结论**：本 skill 只负责"检索到准确依据/事实"，实质研判交给 `ip-analysis-engine`，起草交给 `ip-drafting-engine`。
