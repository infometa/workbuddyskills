# 同程旅行助手 - WorkBuddy 专家包

这是可在 WorkBuddy 桌面客户端及移动端云端沙箱运行的 Agent 型专家包，不依赖移动端暂不支持的 Connector 注入。

打包时会从唯一源码 `extensions/workbuddy/SKILL.md` 及其运行脚本自动生成 `tc-chengxin-search`，并内置同版本授权 CLI。不要在专家源码目录中人工维护第二份查询 Skill。

专家打包器复用原始业务路由和渲染模板，单独生成授权/执行说明及配套 references。普通机票、火车票、酒店和景点简单查询直接执行，不再询问“快速查询还是专家解读”；火车缺日期默认查次日，机票缺日期仍只问出发日。结果末尾按资源类型引导用户补充偏好，同一对话可复用本次结果继续专家分析。已有偏好、比较、约束或行程规划时直接进入专家分析。连接器默认流程不变。

## 能力分层

1. `tc-chengxin-auth`：客户端与移动端统一授权。本机桌面端由脚本尝试打开浏览器并自动轮询，用户登录后无需回复“已登录”，授权成功即继续原操作；移动端、无头云端或浏览器打开失败时才展示登录链接，用户回复“已登录”后单次检查。
2. `tc-chengxin-coupon`：只识别领取优惠券/红包意图，经统一授权调用网关；当天重复领取复用首次结果，成功后引导继续查询酒店。已有券查询不调用 Skill，用户需前往同程旅行 App 查看。
3. `tc-chengxin-search`：从原始 WorkBuddy Skill 自动生成，负责实时查询、Markdown、预订入口、二维码和 HTML 产物。
4. `tc-chengxin-analysis`：获取或续期 CLI Token，只向查询子进程注入；保存原始接口快照。简单查询自动直接生成查询结果和全量产物，不产生 decision/plan；明确专家解读或请求已有偏好/约束时生成 `selection-overview-v2` 或 `itinerary-overview-v2`。分析回执直接给出 plan 路径、完整渲染参数和固定动作序列，避免模型探索脚本。
5. Agent：条件确认后直接提槽请求，不探索源码或解压脚本。简单结果只执行交付动作并原样输出回执中的 `finalAnswer`；复杂请求读完摘要/契约后一次提交结构化推荐或行程。`render-expert-result.js` 校验引用和行程显式冲突，再复用现有模板生成完整产物。

交付生成 `reply.md`、`full-result.md`、HTML、`delivery-manifest.json`。stdout仅返回短回执，缺字段直接读取完整清单；`render-data.json` 是数据备份而非交付清单。旧 `check-delivery.js` 仅保留作历史诊断兼容，新流程不创建回复草稿、不复制全文做指纹校验。无需额外模型调用润色或在交付前写工作日志。用户明确要求全部时，可展示完整MD。

精选不等于自由改写：`reply.md` 采用固定的标题、查询概况、推荐建议、精选表格/行程、提醒和原 Skill 客服区，Agent 原样交付这份短正文。价格和每行预订链接由脚本绑定；聊天保留 confirmations，额外取舍依据和 interpretation 只放在完整产物，详细解读不拉长聊天输出。HTML 继续全量展示；二维码仅使用接口提供的二维码图片/页面/数据，不用手机链接在本地生成替代码。接口未返回二维码字段时不会显示扫码按钮，需结合网关二维码增强日志排查。

CLI 在每次取 Token 时检查有效期，进入提前 1.5 小时续期窗口后静默刷新；业务接口返回 401 时清除失效凭证，重新执行移动端/客户端授权流程。

## 跨端交付

授权和查询共用 `scripts/client-context.js`：`WORKBUDDY_CLIENT_TYPE` 决定查看端，实际操作系统和 Linux 图形会话决定能否唤起浏览器。明确 PC 且脚本运行在 macOS、Windows 或有图形会话的 Linux 时自动打开默认浏览器并轮询；真正无头的云端 Linux 只展示登录链接。手机使用 `mobile`，未知客户端的云端/无头环境采用移动兼容回退。

最终回复前先处理产物工具调用：PC 按短回执中的 `presentFilesArgs` 实际调用 `present_files` 并等待结果；手机通过当前可用的文件工具交付原始 HTML，不要求 PC 侧边栏。简单查询正文直接内联在 `finalAnswer`，不再读 reply.md；复杂分析仍读取精选 MD。成功或已按规则处理失败后原样发送正文。文件已生成不代表已展示；工具不可用时如实说明，不能声称已经展示、伪造下载链接或公开上传文件。

本地安装脚本不负责云端发布。移动端端到端验收还需在真实云端环境验证登录链接、凭证持久化、401 重登、文件入口与预订跳转。

## 后续扩展

新增查询能力时继续修改原始 WorkBuddy Skill 和公共脚本，再由专家打包渠道自动生成对应内容，避免桌面连接器与云端专家形成两套实现。
