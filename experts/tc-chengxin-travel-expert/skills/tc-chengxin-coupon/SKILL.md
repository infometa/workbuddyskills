# 同程优惠券/红包

这是独立账号权益功能，不进入机票、酒店、景点查询的槽位澄清、专家分析或 HTML 渲染流程。

## 唯一执行路径

本 Skill 随包提供，不依赖 WorkBuddy Connector。命中后执行 `coupon.js claim`；不先问平台或登录方式，不扫描 Connector/目录，不读源码、帮助或手工 HTTP。领取阶段不得调用通用浏览器、电脑控制、截图或设备唤起；未登录/401后只转 `tc-chengxin-auth`。脚本缺失或失败就如实说明并停止。

## 意图路由

- 用户明确说“我要领券、领劵、领卷、领红包、领取酒店或机票优惠券、把能领的都领了、领券中心批量领取”时，直接执行，不追问平台、城市、日期或产品条件。在本专家内未指明平台即指同程；明确其他平台时只说明能力边界，不打开该平台网页。
- 用户说“我有哪些券、查一下优惠券、有哪些可用红包、优惠券什么时候过期”时，不执行本 Skill；告知用户前往同程旅行 App「我的 → 优惠券/红包」查看。
- 用户只说“优惠券/红包”而没有领取动作时，只问是否需要帮忙领取；查看已有券引导至同程旅行 App。
- “怎么领、怎么用优惠券”等规则咨询不触发领取；只解释一般使用方式，并以券面和下单页展示为准。

## 执行

领取：

    node "<Base directory for this skill>/scripts/coupon.js" claim

每次都须实际执行，不能凭记忆回答。Gateway 按登录账号与中国自然日保存累计领取快照和稳定 `requestId`，脚本使用同一个 `requestId` 再请求 Gateway，因此 PC、移动端和云端重复领取时共享“今日已领”结果；旧活动保持幂等，Admin 当天新增的酒店或出行活动仍可领取。Gateway 并发领取两类权益，按活动与券标识合并真正成功的券，一个活动返回多张券时逐张保留。本次新领排在前面，随后展示今天此前已领；第三次没有新增时仍回放前几次的累计成功券。本地缓存只用于兼容旧 Gateway 或服务端快照暂不可用时的同端降级，不能作为跨端权威记录。

脚本通过包内 CLI 获取 Token，并固定走 WorkBuddy 渠道。不要让用户输入 memberId、活动ID、tradeNo 或 Token。

只解析两个 `TC_CHENGXIN_COUPON_JSON_*` 标记之间的回执。`markdown` 是唯一用户可见内容，须逐字回复；脚本已处理成功、失败与问题编号。不得根据日志、Gateway 原始响应、活动 ID、状态或错误信息重新拼表，也不得增补解释。本功能不生成文件。

## 授权与失败

- 只有脚本输出 `TC_CHENGXIN_REAUTH_REQUIRED`/401 后才使用 `tc-chengxin-auth`；不要提前授权。授权成功后只重试一次领取。
- 重复领取仍会检查新增活动，并复用 Gateway 保存的当天 `requestId`；模型不得另造活动ID、tradeNo 或重复调用。酒店幂等结果与鲲鹏 `2022` 只用于判定下游已处理，不作为用户可见的券，也不会覆盖此前累计成功券。
- 用户可见结果只包含真正领取成功且有券面明细的累计权益。领取超限、已处理、客群不符、活动编号、卡号和下游原始文案不得展示；它们只保留在 Gateway 日志中。当天无新增时，有账号级快照就展示全部“今日已领”；快照不可用且无法恢复券面时，简要引导至同程旅行 App 查看。
- 折扣、门槛和面额均由脚本按真实券规则解析；规则缺失时以券面为准。

## 展示口径

`markdown` 固定为四列表格：`状态 / 优惠券或红包 / 优惠内容 / 有效期`。“优惠券或红包”列只加粗券名，不添加“住宿/出行”前缀；本次新领、今日已领和同活动多张券均在一张表内。不得在表外另列、只报数量、只展示住宿权益或省略出行权益，也不得改列、改成长段或 HTML。PC 与移动端共用此口径。

表格后只保留一个“💡 使用提示”区，简述住宿券、出行券、继续查询条件和 App 入口，最后注明“具体适用范围和最终价格以下单页为准”。不得宣称已自动抵扣或展示券后价。
