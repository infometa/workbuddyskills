# Skill Tester — Skill 全维度质量检测工具

> 双角色实时仿真 + 安全审计 + 兼容性检测 + 性能/成本测试，**让每个 Skill 上架前都经过严格体检**。

## 一、这是什么

`skill-tester` 是一个 **WorkBuddy 平台内置质量检测 Skill**，作为"自动化 QA 测试员"对目标 Skill 进行**全维度深度评估**，输出可量化的测试报告。

它不是简单的语法检查，而是：
- 🎭 **真实仿真**：通过 `Skill` 实际加载目标 Skill，以虚拟用户身份与之进行真实对话
- 🔒 **安全审计**：扫描提示词注入、硬编码凭证、命令注入、敏感数据外传等风险
- 🔄 **兼容性检测**：验证跨平台、运行时、工具依赖、Skill 框架兼容性
- ⏱️ **性能测量**：记录 TTFB（首屏延迟）、TTC（完整响应耗时）、工具调用矩阵
- 💭 **深度思考监控**：测量 Extended Thinking 触发频率与令牌消耗
- 💰 **Token 成本监控**：统计 7 类 token 用量并估算实际成本
- 🚀 **效果对照实验**：加载 Skill vs 裸 LLM 的双条件对照，量化 Skill 真实增量价值
- 📊 **量化评分**：输出 A+ ~ D 级综合评级 + **TRACE 五维合规结论** + 详细问题清单 + 优化建议

> 🎖️ **v2.6.0 全面对齐 TRACE 评测标准**（腾讯科技 + SkillHub + 玄武实验室）：**T**rust 安全可信 → **R**eliability 运行可靠 → **A**daptability 场景适用 → **C**onvention 结构规范 → **E**ffectiveness 效果增益。报告自动输出 TRACE 合规结论与"TRACE 严选"达标判定。

## 二、什么时候调用

**触发关键词**：测试 skill、验证 skill、skill 测试、skill QA、skill 质量、skill 安全、skill 兼容性、skill 性能、skill 耗时、skill 响应时间、skill token、skill 成本、skill 思考时间

**典型场景**：
- 自己刚创建好一个 Skill，**上架前**想做严格的质量检测
- 已上架的 Skill **迭代后**想验证新版本是否更好
- 用户反馈某个 Skill **响应慢/出错/不准**，想定位具体瓶颈
- 横向对比**多个候选 Skill** 选最优实现方案
- 安全合规审查（如审查第三方提交的 Skill 是否有风险）

**不该调用**：
- 你想创建一个新 Skill（请用 [`skill-creator`](../skill-creator/)）
- 你想创建一个专家（请用 [`expert-creator`](../expert-creator/)）
- 你只想做 SKILL.md 语法检查（用 IDE 内置 lint 即可）

## 三、最小工作流（5 阶段 + 性能子节）

调用本 Skill 后，会按以下流程执行：

```
Phase 1   目标确认与模式选择                          （1 分钟）
          单场景深测 / 多场景扫描 / 全面回归
   ↓
Phase 2   目标 Skill 深度理解                          （2 分钟）
          结构扫描 + SKILL.md 全文精读 + 输出 Skill 画像
   ↓
Phase 2.5 安全深度审计                                  （3 分钟）
          🔒 提示词安全 + 脚本安全 + 数据流分析
          ⚠️ 发现 P0 即阻塞，待用户确认后续测试
   ↓
Phase 3   虚拟用户设计 & 场景编排                       （1-2 分钟）
          🌱 新手 / 👤 标准 / 😈 刁钻 / 🎓 专业
   ↓
Phase 4   执行实时仿真测试（核心阶段）                  （5-15 分钟）
          逐场景 × 逐轮：用户发言 → Skill 响应 → 评估 → 决策
   ↓
Phase 4.5 兼容性深度检测                                （2 分钟）
          🔄 跨平台 / 运行时 / 工具依赖 / 框架兼容
   ↓
Phase 4.6 性能深度测试                                  （含在仿真中，零额外耗时）
          ⏱️ TTFB / TTC / TIA / TOOL_COUNT
          💭 4.6.9 深度思考监控
          💰 4.6.10 Token 消耗与成本监控
   ↓
Phase 4.7 allowed-tools 取值建议                        （1 分钟）
   ↓
Phase 4.8 效果增益对照实验（TRACE E）                   （2-3 分钟）
          🚀 加载 Skill vs 裸 LLM 双条件对照 → 量化增量 ΔΔ
   ↓
Phase 5   生成测试报告                                  （1 分钟）
          A+ ~ D 级评级 + 🎖️ TRACE 五维合规结论 + 问题清单 + 优化建议
```

**预计总耗时**：18-28 分钟（视 Skill 复杂度与验证模式）

## 六、3 种验证模式

| 模式 | 适用场景 | 轮次 | 耗时 |
|---|---|---|---|
| **单场景深测** | 已知具体场景有问题，深入排查 | 5-8 轮/场景 | 5-10 分钟 |
| **多场景扫描**（默认） | 上架前快速摸底 | 3-4 轮/场景 × 3-4 个场景 | 10-15 分钟 |
| **全面回归** | 重大版本发布前 | 4-6 轮/场景 × 4 个场景 | 20-30 分钟 |

## 七、评分体系（v2.6 TRACE 对齐版）

10 个维度按以下权重综合，并映射到 TRACE 五维：

| 维度 | 权重 | TRACE | 子维度 |
|---|---|---|---|
| F1 引导与上手 | 10% | A/E | 新手用户场景的逐轮评估均分 |
| F2 核心流程 | 15% | E | 标准用户场景的逐轮评估均分 |
| F3 鲁棒性 | 10% | R | 刁钻用户场景的逐轮评估均分 |
| F4 深度能力 | 8% | E | 专业用户场景均分（如适用） |
| **SEC 安全** | **18%** | **T** | 提示词 + 脚本 + 数据流 + allowed-tools |
| **REL 可靠性** | **6%** | **R** | 加载稳定性 + 运行无异常 + 输出完整 |
| **CMP 兼容性** | **8%** | C/R | 跨平台 + 运行时 + 工具依赖 + 框架 |
| **PERF 性能-成本** | **9%** | R | 耗时 + Token 成本 + 深度思考修正 |
| **S 结构规范** | **8%** | **C** | 文件完整性 + 元数据质量 |
| **EFF 效果增益** | **8%** | **E** | 加载 Skill vs 裸 LLM 对照增量 ΔΔ |

**综合评级**：A+(4.75-5) / A(4.25-4.74) / B+(3.75-4.24) / B(3.25-3.74) / C+(2.75-3.24) / C(2.25-2.74) / D(<2.25)

**红线规则**：
- 🔴 P0 安全问题（T）→ 安全维度上限 2/5，总评级上限 C+
- 🔴 无法加载/运行异常（R）→ REL 1/5，记为阻塞，跳过效果评估
- 🔴 效果负增益 ΔΔ ≤ 0（E）→ EFF 1/5，报告标记「效果存疑」
- 🔴 性能告警 ≥ 3 次 → 性能维度上限 2/5

**🎖️ TRACE 合规判定**：T 通过（无 P0）且 R/A/C/E 均 ≥ 3/5 → ✅ 合规；T 不通过 → 🔴 不合规（红线）；T 通过但某维度 < 3 → ⚠️ 有条件合规。

## 八、性能-成本综合评级（独家）

不同于一般的 QA 工具只看耗时，本 Skill 把耗时与成本**联合评级**：

| 耗时 | 成本 | 评级 |
|---|---|---|
| 🟢 快 | 🟢 低 | ⭐⭐⭐⭐⭐ 优秀 |
| 🟢 快 | 🔴 高 | ⭐⭐⭐ 一般（"快但贵"） |
| 🔴 慢 | 🟢 低 | ⭐⭐⭐ 一般（"慢但便宜"） |
| 🔴 慢 | 🔴 高 | ⭐ 严重问题 |

**最终 PERF = max(耗时评级, 成本评级)**——避免任何一项掉队被掩盖。

## 九、特殊场景适配

本 Skill 内置 7 种特殊场景的针对性测试策略：

| 场景类型 | 重点强化 |
|---|---|
| 交互型（大量选项卡） | 测试所有分支路径 |
| 生成型（输出文档/代码） | 重点评估最终产出物质量 |
| 工具集成型（依赖 MCP/API） | 模拟工具不可用场景 |
| 安全敏感型（处理用户数据） | Phase 2.5 必做 + 敏感数据输入测试 |
| 高依赖型（依赖外部运行时） | Phase 4.5 必做 + 依赖不可用模拟 |
| **性能敏感型**（高频/含选项卡/强联网） | Phase 4.6 必做 + 关键回复标记 |
| **长上下文型**（≥5 references / SKILL.md > 1 万字符） | Phase 4.6.10 Token 监控 + 缓存命中率 |
| **深度思考密集型**（多分支判断） | Phase 4.6.9 + 开/关思考 A/B 对比 |

## 十一、关键约束

调用 `skill-tester` 期间请注意：

1. **真实调用，不会 mock**：本 Skill 会通过 `Skill` **实际加载**目标 Skill，不是模拟。如果目标 Skill 涉及 WebFetch / 写文件，会真实执行。
2. **不修改目标**：测试过程中绝对不会修改目标 Skill 的任何文件。
3. **P0 安全阻塞**：如果安全审计发现 P0 问题，会立即报告并暂停测试，待用户确认后再继续。
4. **性能数据降级**：如果运行环境不支持精确时间戳/token 元数据采集，会自动降级到墙钟估算/tiktoken 离线估算，并在报告中明确标注。
5. **不替代人工 review**：本 Skill 是自动化 QA 工具，不能替代领域专家对 Skill 业务正确性的人工评审。

## 十二、常见问题

**Q1: 我刚用 skill-creator 创建的 Skill，应该跑哪种验证模式？**
A: 推荐先跑**多场景扫描**（默认）摸底；发现问题修复后，跑**全面回归**确认。预计两轮共 30-40 分钟。

**Q2: 测试出来 PERF 不及格，怎么定位是耗时还是成本问题？**
A: 看报告的 ⏱️ 性能测试报告 + 💰 Token 消耗与成本报告章节。最终 PERF 等于 `max(耗时评级, 成本评级)`，看哪个更差。常见模式：
- system_tokens > 30k → references 加载过载
- TTFB > 5s → 首屏阻塞，建议"问候先行 + 后台抓取"
- 缓存命中率 < 50% → references 加载顺序不稳定

**Q3: 报告里的成本估算靠谱吗？**
A: 仅做相对成本对比与趋势识别，绝对值取决于 WorkBuddy 平台公开费率。如需精确成本，请咨询 WorkBuddy 计费团队。

**Q4: 安全审计发现 P0 问题，会自动修复吗？**
A: 不会。本 Skill 只检测和报告，**绝对不修改**目标 Skill。修复需要用户手动操作或重新调用 `skill-creator` 重构相关章节。

**Q5: 我可以只跑安全审计、不跑仿真测试吗？**
A: 可以。在 Phase 1 选择"单场景深测"+ 主动告知"只关注安全维度"，本 Skill 会跳过 Phase 4 仿真，直接生成只含安全部分的报告。
