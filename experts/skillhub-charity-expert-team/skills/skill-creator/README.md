# Skill Creator — 专家团内部技能编写工具

> SkillHub 公益专家团内部工具，由解决方案专家（帅帅/SY）调用，将用户需求转化为符合 WorkBuddy 规范的完整 Skill 包。

## 一、这是什么

`skill-creator` 是专家团内部的技能生成工具，由解决方案专家在收到主理人委托后调用。它不是面向终端用户的独立产品，而是专家团工作流（Phase 2）中的核心执行工具。

> 💡 PDF §3.1 核心原则：**Skill 是纯文本的提示词工程，不需要写代码**。本工具帮你把这件事做对。

调用它，你不需要：
- ❌ 手写 SKILL.md frontmatter（5+ 必填字段 + 4 推荐字段）
- ❌ 担心正文字数 / 中文友好 / 能力边界等准入要求
- ❌ 自己设计安全基线、references 结构
- ❌ 反复查阅 PDF 准入标准
- ❌ 逐项询问用户——本工具基于任务卡信息**自动推导生成**，不逐字段发问用户（详见 SKILL.md「调用模式说明」）

它会：
- ✅ 基于任务卡的用户需求摘要 + 已确认设计方向，**自动推导填充**所有必要信息（6+1 个 Phase）
- ✅ 自动生成完整目录结构（`SKILL.md` + `README.md` + `GUIDE.md` + `CASES.md` + `Prompt.md` + `references/`，5 文件为必需项）
- ✅ 自动注入默认安全基线（API 密钥不硬编码、敏感信息脱敏等）
- ✅ 中文优先填充所有面向用户的字段
- ✅ 提供质量验证清单逐项确认

## 二、什么时候调用

**触发方式**：由专家团主理人委托解决方案专家调用

**典型场景**：
- 专家团收到用户「帮我创建 XX 技能」请求后
- 用户描述的技能需求需要转化为标准 SKILL.md
- 旧版 Skill 需要按规范重构

**不该调用**：
- 你想创建一个能调度多个 Skill 的"AI 专家"（请用 [`expert-creator`](../expert-creator/)）
- 你想测试一个已有 Skill 的质量、安全、性能（请用 [`skill-tester`](../skill-tester/)）

## 三、最小工作流（6+1 Phase）

调用本 Skill 后，会按以下流程自动推导生成（**非逐项询问用户**，缺失关键信息才交主理人确认）：

```
Phase 0    前置准备：固定按 PDF v2026.4 标准，输出目录取自任务卡
   ↓
Phase 1    基础元数据自动推导：name / display_name / description /
           category / version / author
   ↓
Phase 2    能力边界与触发词自动推导（✅ 能做什么 / ❌ 不做什么）
           ★ PDF §3.3 第 1 条最佳实践
   ↓
Phase 3    核心约束 + 安全要求自动推导
           API 密钥处理 / 权限声明 / 降级策略
   ↓
Phase 4    工作流程拆分自动推导
           ★ PDF §3.3 第 2 条最佳实践，3-6 阶段
   ↓
Phase 5    references / scripts / 示例自动推导
           ★ PDF §3.3 第 3-4 条
   ↓
Phase 5.5  配套文档生成（红线·必做）：README.md / GUIDE.md /
           CASES.md / Prompt.md，均基于 SKILL.md 自动映射展开
   ↓
Phase 6    汇总确认 + 生成 Skill 包 + 30+ 项质量验证
```

## 四、产出物

调用结束后，你会得到一个完整的目录结构（**5 个文件为红线必需项，缺一不可**）：

```
{your-skill-name}/
├── SKILL.md                  # ★ 必需：元数据 + 指令正文
├── README.md                 # ★ 必需：技术说明文档（面向开发者/审核者）
├── GUIDE.md                  # ★ 必需：使用指南（面向终端用户）
├── CASES.md                  # ★ 必需：2-3 个实践案例
├── Prompt.md                 # ★ 必需：≥5 条示例提示词
├── references/                #   按需：API 文档、模板、知识库等
└── scripts/                   #   按需：辅助脚本
```

> `icons/` 由图标设计专家在 Phase 2.5 独立完成，不在本工具产出范围内。参照标准结构：`charity/skills/公益文书助手/`。

## 五、调用方式

本工具由专家团内部调用，不面向终端用户：

```
主理人（星星）→ 委托方案专家（帅帅）→ 方案专家激活 skill-creator
```

方案专家在收到主理人任务卡后，自动加载本 Skill 开始自动推导生成流程。

## 六、关键约束（PDF §4.1）

`skill-creator` 会自动确保产出物满足以下准入标准：

| 准入项 | 要求 | 自动保证方式 |
|---|---|---|
| **元数据完整性** | name/description/category/version/author 5 项必填 | Phase 1 自动推导填充 |
| **正文 ≥ 200 字** | SKILL.md 指令正文不少于 200 字 | 模板默认 800-1500 字 |
| **中文友好** | 面向中文用户的描述和指令以中文为主 | 字段值默认中文 |
| **能力边界清晰** | 开头有"✅ 能做什么 / ❌ 不做什么" | Phase 2 自动推导填充 |
| **API 密钥不硬编码** | 通过环境变量或 MCP 配置引入 | 默认安全基线注入 |
| **权限说明** | 涉及文件读写、网络请求需声明 | Phase 3 自动推导填充 |
| **拆分步骤** | 复杂任务分清晰多步 | Phase 4 自动推导，至少 3 步 |
| **示例（input → output）** | 至少 1 组 | Phase 5 自动推导填充 |
| **配套文档齐全** | README/GUIDE/CASES/Prompt.md 均需生成 | Phase 5.5 自动映射展开 |

## 九、常见问题

**Q1: 我的 Skill 不属于内置 10 个 category，怎么办？**
A: 可以从最相近的选一个，由主理人确认即可。

**Q2: SKILL.md 里能用 `tools: [...]` 字段吗？**
A: 可以（这是 Skill 字段，不是 Expert 字段）。使用 `allowed-tools` 逗号分隔形式。

**Q3: API 密钥真的不能写到 SKILL.md 里吗？**
A: 真的不能。应写"通过环境变量引入"或"通过 MCP 配置"。
