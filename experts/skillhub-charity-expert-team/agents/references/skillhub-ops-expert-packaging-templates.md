# 运维专家 · 打包物料模板参考

> 本文件是 `skillhub-ops-expert.md` 步骤 3（生成 metadata + 打包）与步骤 6（回报结论）的模板细节下沉，避免主文档被大段模板占满。Skill 与 Agent 型专家两种产出物类型共用同一套材料包固定文件名（`metadata.md`/`social-value-report.md`/`test-report.md`），仅内容来源不同，见下文各节标注。

## 一、metadata.md 生成模板

```markdown
# 提交元数据

## 软著权确认
- 署名权归属：{活动运营专家回传的机构名称}
- 使用权授予：腾讯技术公益（腾讯 SSV）
- 用户确认时间：{活动运营专家回传软著确认结果的时间，若无精确时间可留空}
- 开源许可：MIT

## 创作者信息
- 机构名称：{活动运营专家回传的机构名称}
- 姓名：{活动运营专家回传的姓名}
- 手机号：{活动运营专家回传的手机号，缺失时填"未提供"}

## 提交对象
- 产出物类型：{Skill / Agent 型专家}
- 名称：{技能名 / 专家名}
- 版本：{版本号，初次交付为 1.0.0}
- requirement_id：{若源自 Phase 0「领取建设中需求」，填对应 requirement_id；否则填"无"}
```

字段全部来自主理人任务卡上下文摘要（活动运营专家回传的软著确认结果+用户信息），不向用户额外提问，也不自行编造缺失字段——缺失项如实填"未提供"/"无"。

## 二、材料目录文件重命名规则

材料目录内固定需要三个文件，命名**不因产出物类型改变**：

| 材料目录内固定文件名 | Skill 模式来源 | Agent 专家模式来源 |
|---|---|---|
| `metadata.md` | 步骤 3.1 生成 | 同左，生成规则不变 |
| `social-value-report.md` | 复制自任务卡给的 `social-value-report-{技能名}-{日期}.md` | 复制自任务卡给的 `social-value-report-{专家名}-{日期}.md`（同一套命名规则，"技能名"替换为"专家名"） |
| `test-report.md` | 复制自任务卡给的 `test-report-{技能名}-{日期}.md`（skill-tester 报告） | 复制自任务卡给的 `审查报告-{plugin-name}.md`（`expert-reviewer` 报告），**同样重命名为 `test-report.md`** |

复制时用 `cp` 到材料目录并改名，不修改原报告文件内容，也不删除原文件（保留在报告目录留档）。

## 三、步骤 6 回报结论模板

```
📦 打包提交结论：{技能名称 / 专家名称}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
产出物类型：{Skill / Agent 型专家}
版本：v{版本号}

提交结果：{动态填充，三种真实凭证任一，缺凭证严禁填"成功/完成"}
  - MCP 直传成功：submission_id={submission_id}，get_submission_status 复核状态={review_pending/review_approved}
  - 问卷通道提交：脚本返回 status={success}，截图路径={绝对路径}
  - 本地兜底导出：产物路径={绝对路径}
  - 未完成：当前卡在 {具体子步骤}，尚未完成提交

后续：{动态填充}
  - 提交成功 → "已成功提交，接下来进入平台人工审核流程"（严禁说"已上架"）
  - 问卷通道 → 额外提示"处理时效可能变长"
  - 未完成 → 说明卡点与下一步建议（重试/换通道/需要用户介入）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

「提交结果」「后续」两个字段按实际情况动态填充，其余结构保持不变；不得因为产出物类型是 Agent 专家就额外增删字段（提交通道、凭证要求、措辞规范三者均与 Skill 模式一致）。
