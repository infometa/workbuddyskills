# Starter、任务目标、工作深度与研究预算

> 本文件执行 ADR-006。工作深度只改变研究强度和批次节奏，不得生成固定候选数、候选上限或完成条件。

## Starter

| Starter | 触发 | 首值 |
|---|---|---|
| `start_targeting_task` | 直接要求找企业 | `ParkBrief`、任务目标、首张有效卡或当前合格批次；用户确认优先标准时才输出优先批次 |
| `audit_public_material` | 只要求核验、解释或总结公开链接/材料 | 材料边界、可证主张、冲突、未知与任务验收；不自动找企业 |
| `material_to_leads` | 明确要求从公开链接或材料发现企业 | 材料边界、候选线索与证据缺口；只有园区适配任务确实需要时才生成园区条件卡 |
| `audit_existing_list` | 提供企业名单并要求去重、核验或判断 | 输入逐项回执、主体闭合和审计结论；不要求完整园区画像 |
| `resolve_entities` / `audit_candidate_evidence` | 只要求主体消歧或候选证据复核 | 实体关系或主张证据结论；不自动生成新名单或组合 |
| `targeted_campaign` | 指定产业链、区域、载体或对象 | 搜索策略、硬约束、目标与覆盖要求 |
| `continue_campaign` | 当前会话存在受信任务绑定，或跨会话由用户导入 `ResumeCapsule` 并重验证 | 从真实未满足依赖或已验证游标继续；不假设线性层级 |
| `switch_park` | 明确换园区 | 旧园区语义失效、新园区卡 |

上述是常见入口，不是封闭枚举。`routeSelected` 只选择一个便于用户理解的主入口，不表示固定优先级，也不得覆盖其他明确意图；`routeFacets` 必须保留本次请求中全部可组合意图，无法无损归类时可使用 `custom:*`。例如，用户提供材料并要求审计名单时，可同时保留“材料核验”和“名单审计”，再按真实产物依赖选择所需 Skill。否定范围优先于关键词，也优先于“检测到已有名单/材料”这类存在性信号：不能把“解释本区域研发补贴政策，不要找企业”路由为找企，也不能在用户明确说“不审计旧名单”或“不使用这份材料”时强行加入相反任务。

## 任务目标

每轮建立可修订的 `TaskGoal`：

- 企业任务中，用户给明确企业数：保留“恰好、至少、至多、区间”等原始关系；
- 企业任务中，用户不给企业数：用用户明确或确认的关键链节、角色、区域或其他可核验覆盖要求判断；
- 用户同时给数量和覆盖：两者都满足才完成；
- 政策、材料、园区条件或一般事实任务：用结构化 `taskDeliverableRequirements` 和 `TaskAssessment` 判断，不创建企业数量或资格条件；
- 目标仍有阻断未知时不宣布完成或市场短缺；
- 园区规模、空置面积、阶段或团队能力不能自动换算为全国统一企业数。

## 可选工作深度

以下档位便于沟通和记录，不是封闭枚举；任务需要时可定义任务专用深度，但只能改变研究强度与批次节奏。

### quick

- 目标：最快形成本任务首个可用结果和当前可见交付；企业任务可以是首张有效卡或当前合格批次，用户没有确认优先标准时不暗示业务排序；
- 只保留会改变候选池、硬约束或主路线的最小阻断信息集合；能合并时合并，但不以固定问句数量牺牲正确性；
- 按当前主张选择直接、可回读且能减少关键未知的查询与来源，不套固定来源顺序；
- 不削弱实体、硬约束、目标适配和证据底线。

### standard

- 目标：覆盖本次目标声明的主要查询方向、反证和替补；
- 分批交付并持续更新累计进度；
- 适用于需要覆盖主要查询方向、反证和替补的任务，但不自动成为默认路线。

### deep

- 目标：锚点、复杂工程条件或高价值产业链的深度攻坚；
- 加强集团关系、项目状态、来源冲突和反证；
- 提供价值主张、伙伴路径和会谈核验问题；
- 不因深度模式扩大 V1 数据或权限边界。

## 可组合任务目录

以下是可扩展目录，不是园区原型到唯一任务的映射。一次任务可按用户目标组合所需项，不设固定个数：

| 任务方向 | 典型问题 | 首要结果 |
|---|---|---|
| 快速去化 | 哪些企业能承接具体空间并进入核验 | 单元适配和短周期账户 |
| 产业补链 | 哪些企业能满足明确链节缺口 | 链节缺口与企业池 |
| 锚点攻坚 | 哪些对象可带来品牌、订单、研发或总部牵引 | 深度账户与定制核验 |
| 专业孵化 | 哪些团队适合入孵、激活、毕业或迁移 | 分阶段候选与承接条件 |
| 续租扩租 | 哪些公开对象可能形成扩展或替补路径 | 公开候选与核验框架 |
| 低效盘活 | 哪些需求场景值得验证，何时止损 | 多场景验证和停止条件 |
| 跨区域复制 | 总部与本地节点怎样分工 | 城市进入与网络客户 |
| 渠道伙伴 | 哪条关系路径最能减少当前未知 | 伙伴地图、去重和责任边界 |
| 稳定资产 | 如何降低集中度并准备替补 | 信用、集中度与替补框架 |
| 企业服务 | 哪些客户任务可能激活或付费 | 客户任务与验证假设 |
| 开放创新 | 是否有真实需求、场景和采购路径 | 挑战题、候选与验证门 |

园区类型、规模和阶段仅用于提供证据化上下文，不能直接决定唯一任务组合或渠道。

## 批次策略

```text
deliveryBatchSize
firstVisibleBatchSize
batchSizeSource
```

批大小可来自用户明确要求、园区团队处理能力、宿主展示限制或非规范性的本地处理选择，并允许用户调整。来源为用户或宿主时必须绑定相应输入/回执；没有回执不得自报。批次只决定何时展示，不改变总任务目标。

## 研究预算

```text
mode
timeBudgetMinutes
maxQueries
maxRetriesPerSource
sourceMode
budgetEffect = pause_checkpoint_not_market_shortfall
```

达到用户时限、查询预算或重试预算时保存游标并暂停；关键来源不可回读时说明缺口。只有冻结目标范围内形成穷尽证明，才能使用“已停止但仍有未覆盖范围”。

## 速度口径

真实报告记录开始、首个可用结果、首个用户可见交付和任务终态中实际发生的时间，并同时记录模型、推理强度、网络、来源模式、并发、查询/Token/重试预算和停止规则。企业任务可另记录首张有效卡或首个候选批次，但它们不是所有任务的固定速度口径。

包内不提供固定家数的性能参考。只有独立评测配置明确预注册样本定义后，才能记录相应速度观测；该配置不能成为用户任务目标、名单上限、任务完成、市场短缺或自动续作条件。合成示例必须标为 `not_measured`，评测数组为空。
