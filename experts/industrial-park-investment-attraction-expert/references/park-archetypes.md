# 园区分型与演进参考

## 使用方式

把本文件作为 `ParkBrief` 的可选上下文目录，不要把园区硬塞进单一类别。先记录可观察事实，再保留确有解释价值的类型标签；最终任务、客户策略和渠道由用户目标、硬约束、覆盖要求及候选证据共同决定，类型标签不能直接强制映射。

## 可扩展园区上下文目录

以下因素常有价值，但不是固定满表。只记录本任务适用的因素，并可增加任务特有因素；缺失非阻断信息不妨碍开工。

| 维度 | 需要判断 |
|---|---|
| O 治理与付费者 | 民营运营商、国企市场团队、开发区、高校、链主、资管、合资平台 |
| A 运营原型 | 众创、孵化、加速、开放创新、技术平台、产业园、稳定资产、网络运营 |
| S 规模 | 单楼、单园、城市园区群、跨城平台、全国网络 |
| D 阶段 | 筹开、开园爬坡、模式验证、集群形成、成熟、更新、资本就绪 |
| P 战略 | 去化、现金流、补链、锚点、创新、服务增收、资产资本化 |
| R 资源 | 空间、链主、订单、场景、技术平台、人才、高校、基金、政府、跨城网络 |
| C 载体 | 办公、研发、小试、中试、实验室、洁净室、厂房、仓储、定制空间、土地 |
| B 存量经营 | 空置、租金、收缴、租期、租户结构、服务收入、NOI、资源负荷 |
| G 区域产业 | 城市产业、人才、交通、能源、监管、上下游、竞园、跨区域协作 |
| T 数据与权限 | V1 使用当前会话和公开资料 |
| M 市场化能力 | 收入模式、定价权、客户选择权、招商预算、续租责任、数据成熟度 |
| J 监管辖区 | 土地/载体用途、能耗、环保、安全、保税、跨境等属性 |

## 典型原型的可核验假设

下列条目只能帮助发现“还要核验什么”，不能直接产生目标企业、资格条件、业务优先级、客户策略或渠道。只有相应事实已在本轮 `ParkBrief / TaskGoal` 中由用户明确或确认，才可成为规范性条件；否则保留为待证假设。

### 众创空间与灵活办公

- 可观察条件：是否确有可交付的小单元、灵活期限、基础服务及合法注册条件；
- 可搜索线索：新设团队、人才扩张、从高校或平台转化等，但线索本身不证明空间需求；
- 待核问题：付费主体、实际面积、使用期限、注册合规和续租条件；
- 只有用户把相应条件写入本轮目标后，才据此筛选；“众创空间”名称不能自动指定早期团队或活动渠道。

### 孵化器与孵化基地

- 可观察条件：导师、技术平台、基金、客户或毕业承接空间中哪些资源真实存在、由谁负责、怎样使用；
- 可搜索线索：技术成果、团队、融资、订单、注册或试验需求，但不得由“初创”标签推定入孵适配；
- 待核问题：企业当前任务是否需要园区已证实可兑现的资源，以及怎样判断激活、毕业或迁移；
- 只有本轮目标明确要求相应阶段或服务时，入孵、毕业或园内迁移才进入完成条件。

### 加速器与开放创新平台

- 可观察条件：挑战题、需求方、预算或采购责任、场景和验证路径是否真实存在；
- 可搜索线索：产品、同类案例、交付能力和合规，但不能据此自称具备采购意向；
- 待核问题：谁决定、用什么标准验证、验证后如何承接；
- 没有已确认的需求授权时，只能记录开放创新假设，不能自动发起征集或把报名数写成招商成果。

### 科技园与研发型产业园

- 可观察条件：研发空间、人才、技术平台、上下游和属地规则中哪些与本轮任务有关；
- 可搜索线索：研发招聘、技术项目、融资或区域合作，但公开事件不等于迁址或入园意愿；
- 待核问题：品牌、研发主体、销售主体和实际用房主体是否为同一法人，以及实际载体需求；
- 只有用户确认研发或链节条件是本轮目标时，才能据此筛选或排序。

### 中试与先进制造园

- 可观察条件：园区实际可提供的用途、层高、荷载、公用工程、排放、安全、洁净、物流和交付边界；
- 可搜索线索：产能扩张、订单、设备采购、项目备案、环评和招聘，但线索不自动成为入园需求；
- 待核问题：企业实际用房主体、项目状态、工程参数和时点；
- 只有写入本轮硬约束的条件才具有否决权；不适用或尚未确认的工程项不能被模板自动设为资格门。

### 稳定资产与存量园

- 可观察条件：空置、租约集中、到期分布、现金流或替补需求中哪些问题被园区本轮提出；
- 可搜索线索：公开信用、区域扩张或搬迁事件，但不能替代租约和财务数据；
- 待核问题：面积、租期、价格、信用、服务需求和资产风险中哪些真正影响本轮决策；
- V1 没有私有租约数据时，只能准备公开候选与核验框架，不能自动把 NOI、续租或集中度设为业务目标。

### 城市园区群与跨城网络

- 可观察条件：跨城空间、客户关系、产业节点、统一服务和总部/本地责任是否真实可用；
- 可搜索线索：企业跨区域布局、总部—基地分工或成长迁移，但不能推定目标城市需求；
- 待核问题：法定主体、总部、区域中心、生产基地和销售办事处的关系及实际承接园区；
- 不把单园经验复制成网络任务；只有用户明确跨园或跨城目标时，相关条件才进入组合。

## 阶段观察与可选问题

阶段标签只描述观察，不产生唯一主任务，也不规定必须按表中顺序演进。一个园区可同时有多个状态，用户可以选择与表中完全不同的任务。

| 可观察状态 | 可提出并等待用户确认的问题 | 不应自动推定 |
|---|---|---|
| 筹开或预开园 | 是否需要验证载体需求、产品定位、种子客户或渠道 | 必须找锚点或必须先做大名单 |
| 开园爬坡 | 本轮更关心去化、价格、适配、账户还是渠道验证 | “爬坡”自动等于数量优先 |
| 模式验证 | 哪个客户问题、获客路径或服务假设需要验证或停止 | 必须聚焦某个预设细分 |
| 集群形成 | 是否存在已确认链节缺口、需求方或共享平台任务 | 产业标签自动生成补链目标 |
| 成熟稳定 | 是否需要续租、扩租、替补、集中度或其他经营任务 | 自动把资产指标设为资格条件 |
| 更新重启 | 是否应先验证需求、改造假设或退出条件 | 固定“先找客户再改造”的唯一顺序 |
| 跨城或资本准备 | 哪些单元可复制，哪些必须属地重建 | 自动寻找网络客户或复制品牌 |

## 市场化检验

仅对本轮策略确实适用的部分，记录相应问题；下面是可扩展目录，不是固定六问，也不是开工前置门：

1. 谁付费，为什么现在付费；
2. 园区对客户选择、价格和资源配置有多大权力；
3. 企业进入后如何激活、续租、扩租或毕业；
4. 哪些资源可真实兑现，谁负责；
5. 招商、运营和资产结果如何闭环；
6. 什么条件下停止某渠道、某客群或某产品。
