# 园企适配、批次与完成判断

> 本文件执行 ADR-006。历史上的固定候选数量、固定维度满表和“入口即资格门”规则已废止，不得继续作为当前验收依据。

## 先过资格底线

企业进入合格池前检查本任务适用的资格底线；以下是常见关系，不是按数量凑齐的固定四项：

1. 法定主体可区分并已去重；
2. 没有已证实的园区硬约束失败；
3. 与本次任务的目标条件相符；
4. 被冻结规则引用为资格或交付关键项的判断有可回读公开证据。“关键”只能从 `TaskGoal / ParkBrief` 引用关系派生，不能由候选自填。

渠道、公开入口、核验话术和发送条件属于行动准备度，不是企业资格。暂时没有公开入口的高适配企业仍可合格，但要标明行动准备待补。证据页与行动入口必须分开：项目、备案、环评、新闻或招聘页面默认只支持对应事实，只有与同一主体、建议渠道和具体用途闭合的入口才可进入行动准备。

## 适用项代替固定满表

从本次 `TaskGoal`、硬约束和覆盖要求中生成判断项。以下只是常用目录，不是必填清单：

| 判断方向 | 可能要回答的问题 |
|---|---|
| 产业或链节 | 企业实际业务是否满足本次链节或角色要求 |
| 载体与工程 | 研发、中试、制造、物流和合规条件是否可能匹配 |
| 企业阶段与信号 | 是否有可核验的成长、扩张、研发或供应链任务 |
| 资源交换 | 园区资源能否解决企业当前任务，企业能否贡献客户、技术、人才或产业关系 |
| 区域协同 | 人才、供应链、客户、交通和政策是否有可解释协同 |
| 商业承接 | 空间、周期、服务和运营能力是否可承接 |
| 证据质量 | 主体、来源、时效、直接性与冲突是否足够 |
| 反证与未知 | 哪些事实会否决资格或改变优先级 |

本任务不适用的判断项可明确写“不适用”；未知不能伪装成通过。用户已明确或确认优先标准时，对外可使用“优先 / 可考虑 / 待观察”；否则只表达资格与证据状态，并声明显示顺序不代表业务优先级。业务排序只读取已回显的本次标准、结构化判断与证据，不读取候选自报分数，也不能解释为招商成功概率。

## 当前批次与有条件的优先批次

当前批次先满足资格与证据底线。只有用户明确或确认以下哪类标准重要时，才形成业务优先批次：

- 资格底线全部通过；
- 对当前目标或未覆盖要求贡献高；
- 来源直接、新鲜、可回读；
- 反证充分披露且仍可管理；
- 下一步能显著减少最大不确定性。

批大小由用户要求、园区团队处理能力、宿主展示能力或非规范性的本地处理选择决定；声明为用户或宿主来源时必须绑定相应输入/回执，不能由业务 payload 自报。用户未确认优先标准时，采用透明、稳定、可复算的展示顺序，并明确它不代表业务优先级。批次交付后保留累计去重数量、覆盖进度和续作游标；批次大小不改变任务目标。

## 累计企业组合

- 同一法定主体只计一次；
- 一个主体可承担多个角色；
- 合格对象可跨多个批次累计，不设产品级上限；
- 数量关系只来自用户明确表达：`exact` 是目标也是上限；`at_least` 是完成下限；`between` 有完成下限和不可越过的上限；`at_most` 只有同时存在正向覆盖条件时才可冻结；`none` 只按覆盖判断；
- 系统不自动生成“1—30 家”之类范围，也不把“至少、至多、区间”静默改成“恰好 N”；
- 关键证据不足对象放观察池，不计入合格数量；
- 硬失败对象放排除池并写明证据；
- 角色或链节只有进入任务覆盖要求时才是完成条件，否则只作诊断；
- 不用硬配额凑数，也不因首批已经可用而提前结束整个任务。

覆盖组合使用可审计的全局求解；不能用一次贪心选择在存在上限内可行组合时误报覆盖不足。相同家数的可行组合只有在用户明确或确认优先标准后才作业务优先比较；否则采用透明稳定的展示顺序。组合计算保护触发时保存进度并暂停，不得生成短缺终态。

## 相对任务目标判断状态

- `completed`：冻结目标中本任务适用的数量关系、覆盖、资格、逐项评估、交付要求和验收标准均满足；
- `in_progress`：目标未满足，仍有明确可执行方向；
- `paused`：用户暂停、时间窗、预算检查点、搜索不可用、工具故障或目标信息缺失；
- `stopped_with_gap`：目标未满足，且任务冻结时已绑定的可枚举有界全集已经逐项评估，并形成可重算的穷尽证明；开放网页搜索不具备该终态资格；
- `superseded`：目标或关键约束被新版本取代。

暂停不是短缺。批次完成是否等于任务完成，只由冻结的 `TaskGoal` 决定，不能自动判为完成或未完成。时间或查询预算到点只能暂停并保存进度，不能单独证明市场不存在更多企业。

## 穷尽证明

只有要使用 `stopped_with_gap` 时，才要求：

1. 明确仍未满足的目标要求；
2. 回连任务冻结时已经绑定的可枚举全集、来源版本、查询条件、逐项内容摘要、分页/游标闭合、总量和受信回执，不得在终态临时缩小范围；
3. 证明该封闭来源宇宙已经逐项处理；开放搜索的“查询饱和”或边际价值判断本身不能证明穷尽；
4. 列出仍未解决的证据缺口；
5. 证明该有界全集内没有未评估对象或可继续方向；时间、预算、工具或组合计算保护到点只形成暂停。

禁止通过降低证据标准、重复主体或把观察池混入合格池来消除未覆盖范围。

真实用户绑定全集可以为 0：纯“逐项审计这份空名单”可完成 0 项；若任务同时要求推荐正数量企业，则只能报告该目标仍有缺口或暂停，不能伪造占位对象，也不能把空输入解释成市场短缺。

## 来源消融

关键来源删除、失效或被反驳时：

1. 找出受影响主张；
2. 把主张支持状态退回；
3. 重新执行资格底线；
4. 重新判断受影响适用项；
5. 重新计算批次、累计组合和目标进度；
6. 披露变化原因。

## 下一核验建议

核验建议针对最大不确定性，例如：

- 核验用户时间窗内是否有新增研发、中试或生产空间任务；
- 确认实际用房主体、区域和决策窗口；
- 核验工程参数、能耗、环评和安全边界；
- 确认园区资源能否对接到企业真实业务任务；
- 通过公开商务路径确认需求，而不是假定意愿。

没有公开入口时，建议可以是“继续查找由主体维护的公开合作路径”，但不得因此取消企业资格。
