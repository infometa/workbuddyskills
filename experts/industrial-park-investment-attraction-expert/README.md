# 产业园招商专家

- 产品名称：**产业园招商专家**
- 中文品牌：**福帮手**
- 英文品牌：**FBSir**

产业园招商专家由福帮手 FBSir 提供，面向市场化园区运营商，仅用公开资料快速找到满足本次条件的企业。版本 `26.7.27` 先确认这次要解决什么、需要覆盖到哪里，再分批交付并按用户明确的数量关系或覆盖要求继续；不把“至少、至多、区间”偷换成“恰好 N”，也不自动生成宽区间。只有用户明确提出或确认优先标准时才称“业务优先”；否则显示顺序不代表业务优先级。证据不足时明确“还需核验”并保留进度，已证明失败则明确“不满足本次条件”。只有任务冻结时已经绑定的可枚举有界全集逐项核验后仍无法满足目标，才形成终止性的未覆盖结论；开放网页搜索、时间到、预算到点或组合计算未完成都只能暂停，任何情况都不拿弱企业凑数。

## 首版能力

- 把园区位置、产业方向、空间载体、发展阶段、资源和经营目标整理成一页条件卡；缺少非关键信息时采用明确假设继续，不让用户填写长表。
- 从公开网页或用户提供的公开材料发现候选企业。
- 可独立核验、解释和整理政策、园区材料、研究结论或一般公开事实；此类任务按交付要求验收，不虚构园区、企业或候选组合。
- 区分法定主体、品牌、集团、子公司、分支机构和生产基地并去重。
- 把每项判断与公开来源绑定，同时记录支持信息、不利信息、待确认项和来源冲突。
- 每家都核对法定主体、园区硬条件、与本次目标的适配和公开证据，再决定是否进入合格池；公开入口和渠道属于后续行动准备，不决定企业是否合格。
- 给出逐家“满足本次条件 / 还需核验 / 不满足本次条件”的自然语言结论、适配理由、不利信息与待确认项；获客路径和核验动作只在本任务需要且有依据时给出。只有用户明确或确认优先标准时才给业务优先级和推进顺序，否则使用稳定显示顺序并明确其不代表推荐程度。暂时没有公开入口时只说明行动准备缺口，不删除已满足本次条件的企业。
- 记录本任务首个可用结果和首个用户可见交付的真实用时；企业任务可另记录首张有效候选和首个可见批次。包内不预设任何固定家数的测速样本、分钟阈值或百分位承诺。正式性能样本和目标必须由独立评测配置预注册并注入，且永不成为业务目标、上限、完成或短缺条件；没有真实计时或宿主可见回执时直接说“本轮未记录耗时”。

普通聊天先给结论和本次任务最有用的结果；企业任务才给名单，政策或材料任务直接给相应结论与证据。不展示内部路线码、机器字段、英文枚举或结果层级。只有用户明确要求 JSON、Schema、调试信息或技术审计时，才提供这些技术细节。

## 明确边界

首版的企业事实、资格判断和完成判断仅使用当前会话输入与公开资料，不读取私有文件或凭据，不依赖连接器，不写入 CRM、邮箱、日历、长期记忆或其他外部系统。长期记忆是宿主回执驱动的可选只读增强：业务 JSON 自称“已读取、已隔离”不算证明；只有外部宿主回执逐项绑定能力、园区、偏好摘要和用户本轮确认后，才可使用绑定当前园区的偏好上下文。没有可连接回执时状态为“未知”并忽略。该偏好不得跨园区复用，不得进入企业证据、入选/排除或任务完成判断。任何对外联络内容都只是草稿；执行必须由用户在包外单独确认。没有实时公开检索且没有公开材料时，只交付检索任务包，不生成企业事实或虚构引用。

包内资产与本地测试不能证明 WorkBuddy 已上架运行、实时检索一定可用、市场审核通过、用户采用或招商业务结果。

## Roadmap 与本版取舍

长期记忆写入、未确认的用户画像、跨园区记忆复用、私有文件/CRM、连接器外联、持续监控和真实漏斗学习是后续授权能力，不是26.7.27遗漏。本版只允许“宿主已证明可用且园区隔离 + 用户本轮确认”的只读偏好上下文，并生成去敏回执；宿主能力未知或任何条件不满足时，完全按当前会话降级。`ProgressCard` 只描述当前会话进度；`ResumeCapsule` 是用户持有、可复制并需重新校验的续作资产，不代表系统暗中保存了长期记忆，也不凭自身哈希证明来源真实性。

## 单写者 Skill

当前 `skill-routing-contract` 声明以下五个 Skill；清单和顺序由合同、Agent、插件清单和实际目录共同校验，不由验证器写死数量。

1. `park-brief-builder`：唯一写入园区约束卡和任务目标 `TaskGoal`。
2. `public-target-research`：唯一写入候选发现集。
3. `entity-evidence-audit`：唯一写入任务适用的实体、来源、主张、知识记录和证据账本；非企业任务不创建实体。
4. `fit-portfolio`：只读冻结的 `TaskGoal`，唯一写入候选判断、组合批次、目标评估、任务状态与有证据的未覆盖范围；不得创建或改写目标。只有用户明确或确认优先标准时才写业务排序。
5. `artifact-renderer`：只渲染既有结果，不改变企业、证据或排名。

## 快速入口

- 快速找企业：公开检索可用时先交付首张有效卡和当前合格批次；没有用户确认的优先标准时，显示顺序不代表业务优先级。
- 公开材料核验：只解释、核验或整理材料时直接交付证据化结论，不自动找企业。
- 公开材料转线索：仅在用户明确要求时，从材料发现企业线索。
- 现有名单审计：逐项消歧、核验、评估或补证，不先启动新一轮找企。
- 定向招商战役：围绕指定产业链环节、区域和载体条件筛选。
- 继续当前任务：同一会话直接使用仍可见且已校验的状态；跨会话或导入场景才使用用户持有的恢复胶囊，并重新核对包版本、上下文、任务目标和证据快照。
- 切换园区：使上一园区派生的候选、证据和排名失效后重新开始。

## 包结构

- `.codebuddy-plugin/plugin.json`：版本和专家身份唯一人工真源。
- `agents/`：单一公开 Agent 入口与运行编排。
- `skills/`：五个单写者工作流。
- `contracts/`：产品、运行、首值、证据、适配、动作和发布合同。
- `schemas/`：机器可校验的数据对象。
- `references/`：全国园区类型、政策监管路由、趋势创新、市场化园区模式、可扩展获客渠道目录、任务模式、公开来源、实体证据与质量降级。
- `examples/`：合成示例，不代表真实企业或线上运行结果。
