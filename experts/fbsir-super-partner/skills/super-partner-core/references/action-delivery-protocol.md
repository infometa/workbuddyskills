# 行动交付协议

本参考只在用户需要持久化成品、任务跟踪、回看提醒、跨会话续接或宿主执行时按需读取。没有对应宿主能力时，继续在对话中交付完整成品，不阻断首值。

## 能力路由

| 意图 | 可用时的最小宿主能力 | 强制边界 |
|---|---|---|
| 读取用户指定材料或续接历史 | 只读文件、会话搜索或网页检索 | 保留来源；搜索不到就说明未知 |
| 保存本轮成品 | 新建本地文件或文档 | 用户已要求持久化；默认新文件；写后回读 |
| 修改已有本地成品 | 可逆编辑、检查点或备份 | 先有恢复点，再修改并展示差异 |
| 创建可跟踪任务 | 当前宿主提供的任务能力 | 先展示任务名、负责人、截止和完成定义；返回任务 ID |
| 创建回看提醒 | 当前宿主提供的提醒或自动化能力 | 属于持久状态变化，先展示时间和提醒正文并取得批准；返回计划 ID |
| 外部发送、发布、部署或付款 | 当前宿主提供的外部写能力 | 目标、完整载荷和影响必须与当次批准绑定；执行后查询终态 |

不要在回答中假装某个具体工具存在。只有当前会话真实暴露并返回结果的能力，才能进入`已执行`回执。

## 行动结构

一个业务动作可以包含预检、执行和验证，但不能偷偷扩大为第二个业务动作。建议结构：

- `启动条件`：可省略；一旦写出，必须是“如果……那么……”的一条明确条件，不能藏入第二个动作。
- `2 分钟启动版`：现在即可完成的一个原子起步动作。
- `完成定义`：由什么可观察事实判断完成。
- `72 小时裁决`：指标、基线、阈值、证据源、裁决时间、达到后和未达到时。

材料红队应区分：

- `限制性信念`：主观判断，先质疑，不冒充事实。
- `可验证假设`：可通过一个信号或实验判断，直接进入 72 小时裁决。

## 可选安全脚本

当宿主真实提供受控 Python 执行能力，且用户明确要求把行动交付保存到工作区时，可使用相邻脚本 `../scripts/materialize_action_delivery.py`。它只接受工作区内普通 JSON 文件，只新建普通 Markdown 文件，不覆盖既有文件，不联网，并在写后回读输出 SHA-256 回执。Windows 备用数据流（ADS）、保留设备名、控制字符路径和指向工作区外的路径都会被拒绝；独占新建失败时不会删除其它进程刚创建的文件。

调用前先向用户展示目标路径；调用后仍需由宿主工具结果绑定真实 `callId`，不能只引用脚本标准输出声称成功。

跨平台最小调用形式（相对路径统一以`--workspace-root`为基准）：

```text
python "<脚本路径>/materialize_action_delivery.py" --workspace-root "<工作区>" --input "action-delivery.json" --output "行动交付.md"
```

可复制输入模板（把时间替换为带时区的 RFC3339；两个起点不得晚于系统当前时间，截止仍须未过期）：

```json
{
  "schemaVersion": "fbsir-super-partner-action-delivery/v1",
  "lensId": "brainstorm",
  "artifact": {
    "type": "客户访谈邀约",
    "title": "三天客户问题验证行动",
    "body": "你好，我正在验证一项帮助小团队减少交付返工的轻量服务。想占用你十五分钟，只聊最近一次最费时间的返工，不推销产品。你本周哪天方便？如果不方便，也可以直接回复最常见的返工环节，我会据此整理一份可执行的改进清单。"
  },
  "executionStatus": "delivered",
  "action": {
    "owner": "用户",
    "action": "向一位近期客户发送上述邀约",
    "target": "该客户的常用私聊渠道",
    "startedAt": "2026-07-16T11:00:00+08:00",
    "deadline": "2026-07-16T23:00:00+08:00",
    "completionDefinition": "消息成功发出并保留原始发送记录",
    "twoMinuteStart": "复制邀约并填入客户称呼"
  },
  "outcome72h": {
    "metric": "明确回复人数",
    "baseline": "当前为 0 人",
    "threshold": "至少 1 人回复痛点或愿意继续沟通",
    "evidenceSource": "客户私聊原始消息线程",
    "windowStartedAt": "2026-07-16T11:00:00+08:00",
    "deadline": "2026-07-18T23:00:00+08:00",
    "onReached": "预约一次十五分钟访谈",
    "onNotReached": "更换目标客户或开场句后只再测一轮"
  },
  "evidence": {
    "facts": ["用户需要在三天内验证需求。"],
    "inferences": ["直接邀约比继续设计方案更快获得真实信号。"],
    "unknowns": ["目标客户是否正面临紧迫问题。"]
  }
}
```

`action.trigger`是普通交付状态下唯一可选字段；使用时写清前置条件，不得藏入第二个动作。若`executionStatus`为`awaiting_approval`，则必须额外提供`approvalPreview`，且只包含`target / effect / payload / impactBoundary`四项；脚本会把它渲染为独立的`待你批准`段，缺少完整目标、效果、载荷或影响边界时拒绝生成。

脚本会验证镜片、成品正文、24 小时动作起点/截止、2 分钟启动版、72 小时窗口起点/指标/带数量单位的基线和阈值/证据源/期限，以及事实/推断/未知。输入字段不得注入`本轮魔镜`、行动合同保留标题或`状态：已执行`等控制行。它使用系统 UTC，不接受调用方覆盖校验时间；成功回执为`fbsir-super-partner-action-materialization-receipt/v2`。这个本地落地脚本只能生成`已交付 / 待授权 / 未执行`；`已执行`必须由真实宿主调用、同目标回读和绑定回执产生，脚本拒绝代填。

`待授权`输入示例（与上方模板同级增加）：

```json
{
  "approvalPreview": {
    "target": "client@example.test",
    "effect": "仅发送一封报价邮件",
    "payload": "主题：90 分钟培训方案诊断测试席位\n正文：测试价 299 元；回复‘看看示例’即可。",
    "impactBoundary": "批准后只向该收件人发送这一封，不追加附件、抄送或其它动作"
  }
}
```
