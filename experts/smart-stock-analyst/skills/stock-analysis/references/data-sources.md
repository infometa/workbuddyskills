# 多数据源与 Fallback 机制

本文档说明分析系统支持的数据源、优先级策略和降级逻辑，帮助理解数据来源和可靠性。

## 二、Fallback 优先级策略

### A股数据源优先级

```
实时行情：TickFlow → Tencent → AkShare → Pytdx → Efinance
历史K线：TickFlow → AkShare → Tushare → Baostock → YFinance
基本面：Tushare → AkShare → YFinance
板块数据：AkShare → Tencent → Efinance
```

### 港股数据源优先级

```
实时行情：TickFlow → Longbridge → Tencent → YFinance
历史K线：TickFlow → Longbridge → YFinance
基本面：Longbridge → YFinance
```

### 美股数据源优先级

```
实时行情：TickFlow → Longbridge → YFinance → Finnhub
历史K线：TickFlow → Longbridge → YFinance → AlphaVantage
基本面：YFinance → AlphaVantage → Finnhub
```

### 日股/韩股/台股

```
实时行情：TickFlow → YFinance
历史K线：TickFlow → YFinance
基本面：YFinance
```

## 三、Fallback 触发条件

| 条件 | 行为 |
|------|------|
| 主数据源超时（>10秒） | 切换到次优数据源 |
| 主数据源返回空数据 | 切换到次优数据源 |
| 主数据源报错（4xx/5xx） | 切换到次优数据源 |
| API 配额耗尽 | 跳过该数据源，使用下一个 |
| 所有数据源均失败 | 标记数据缺失，降低置信度 |

---

## 四、数据质量标记

当使用非首选数据源或数据不完整时，分析结果中需标注数据质量：

| 标记 | 含义 | 对置信度的影响 |
|------|------|-------------|
| `primary` | 使用首选数据源 | 无影响 |
| `fallback` | 使用了降级数据源 | 置信度不可为"高" |
| `stale` | 数据超过 1 小时未更新 | 置信度不可为"高" |
| `partial` | 数据不完整（部分字段缺失） | 置信度不可为"高" |
| `estimated` | 部分数据为估算值 | 置信度不可为"高" |
| `missing` | 关键数据缺失 | 置信度降为"低" |
| `fetch_failed` | 数据获取失败 | 相关分析维度跳过 |

---

## 五、数据来源声明规则

每次分析的输出中应包含数据来源说明：

```
📡 数据来源
- 行情数据：{数据源名称}（{更新时间}）
- 新闻搜索：{数据源名称}（{搜索时间}）
- 基本面：{数据源名称}（{报告期}）
- 数据质量：{primary/fallback/partial}
```

## 六、数据时效性要求

| 数据类型 | 最大可接受延迟 | 超时处理 |
|---------|-------------|---------|
| 实时行情 | 盘中 15 分钟 / 盘后无限制 | 标注延迟时间 |
| 日K线 | 当日收盘后 2 小时 | 使用前一日完整数据 |
| 新闻 | 24 小时内 | 标注新闻时间 |
| 基本面 | 最近一期财报 | 标注报告期 |
| 板块数据 | 当日盘中 30 分钟 | 使用前一日数据 |

---

## 七、单一数据源失败不阻塞分析

**核心原则**：单一数据源的失败不应拖垮整个分析流程。

- 行情数据失败 → 尝试所有备选源，全部失败则报告无法分析
- 新闻数据失败 → 跳过情报面分析，标注"新闻数据不可用"
- 基本面数据失败 → 跳过基本面维度，技术面权重上调
- 板块数据失败 → 跳过板块对比，独立分析个股

只有当**行情数据**（价格和成交量）完全不可获取时，才应拒绝分析并告知用户。
